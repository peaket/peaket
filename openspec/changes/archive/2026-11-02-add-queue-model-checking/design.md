# 설계: 규칙 모델 검사 도구와 대기열·입장 제어 명세

## 맥락

- 정본: docs/verification.md §2.1(명세 넷과 지킬 약속, 작은 범위)·§2.2(도구와 실행, CI)·§2.3(결과를 읽는 법)·§2.6(검사 기록), V-T1, ADR-0057 결정 2.
- 도구는 정본이 정했다: Quint(Apache-2.0)로 쓰고, `quint run`으로 반례를 빨리 찾고, 전수 검사는 `quint verify --backend=tlc`로 한다. 저장 위치는 저장소 뿌리의 `specs/`다.
- 이 PC: Windows 11, Java 없음, pnpm 12 실행 파일이 응용 프로그램 제어에 막힘(PROGRESS OPEN[12]), Docker 있음(소유자 결정 2026-10-31로 로컬 Docker 사용 허용).
- 탐색에서 본 것(Quint 0.33.1 `dist/src`): `quint verify --backend=tlc`는 Apalache 묶음의 `apalache.jar` 안 TLC(`tlc2.TLC`)를 `java`로 띄운다. Apalache 묶음(0.62.4)과 Rust 평가기(v0.7.1, `quint run`의 기본 실행기)는 처음 쓸 때 GitHub에서 해시 확인 없이 받아 `QUINT_HOME`(기본 `~/.quint`)에 둔다. 자리가 차 있으면 다시 받지 않는다.

## 결정

1. **도구 판·해시 고정(추천 적용 2026-11-02).** Quint는 따로 작업 공간 `tools/spec-check/`의 잠금 파일로 고정한다(뿌리 작업 공간에 넣지 않는다: 시험·빌드 의존이 아니고, 무거운 Java 도구와 함께 쓰는 검사 도구라서다. `loadtest/poc/bench`와 같은 방식). Apalache 묶음과 평가기는 `fetch-tools.mjs`가 공식 GitHub 릴리스에서 받아 압축 파일은 릴리스 자산 다이제스트로, 푼 것은 고정한 SHA-256(Apalache는 `apalache/` 폴더의 모든 파일로 만든 폴더 해시: Quint가 띄우는 `bin/apalache-mc`와 TLC가 든 `lib/apalache.jar` 포함, 평가기는 `quint_evaluator`)으로 확인한 뒤 `QUINT_HOME`에 둔다. 받아 둔 것도 검사할 때마다 다시 본다(`tools/local/tools.mjs`와 같은 생각, 코드 리뷰 2026-11-02). 셋 다 게시 뒤 3일이 지난 판이다(`minimumReleaseAge`와 같은 기준).
2. **쓰지 않는 의존성 빼기(추천 적용 2026-11-02).** Quint 0.33.1은 `@octokit/request`를 선언만 하고 쓰지 않는다(`dist`에 주석 한 줄). 그 아래 `@octokit/endpoint` 9.0.6이 `trustPolicy: no-downgrade`에 걸린다. 신뢰 정책 예외를 두지 않고 `overrides`로 설치에서 뺀다.
3. **로컬은 컨테이너, CI는 러너.** 로컬은 `tools/spec-check/Dockerfile`(Temurin 21 JRE 다이제스트 + 서비스 뼈대와 같은 Node 다이제스트 + 잠금 파일 설치 + 고정 해시 도구)로 돌린다. CI는 ubuntu 러너에서 `actions/setup-java`(Temurin 21)와 같은 스크립트로 돈다. 판단은 스크립트(`spec-check.mjs`)가 하고 워크플로는 부르기만 한다(`tools/ci`와 같은 원칙).
4. **검사 목록과 판정.** `specs/specs.json`에 명세마다 범위·관련 ADR·불변식·검사 모듈을 적는다. 검사 모듈은 '지켜짐'(hold) 또는 '반례'(violate, 노린 불변식 하나)를 기대한다. 지켜짐은 TLC가 끝까지 돌고 위반이 없어야, 반례는 노린 불변식이 깨져야 통과한다. 반례를 기대하는 모듈은 노린 불변식 하나만 검사해 그 불변식의 가장 짧은 반례(TLC 너비 우선)를 남긴다. 지켜짐을 기대하는 검사가 없는 명세는 목록에서 거절한다.
5. **CI 주기(정본 §2.2의 [가정]을 확정, 추천 적용 2026-11-02).** PR: 명세·검사 도구·그 워크플로가 바뀌면 형식 검사와 검사 모듈마다 시뮬레이션 1만 회(걸음 40, 고정 시드, 스레드 하나). 같은 커밋은 같은 결과를 낸다. 전수 검사: 주 1회(월요일 03:00 KST)와 명세 목록이 적은 관련 ADR이 바뀐 PR. 결과 파일은 내려받을 묶음으로 남기고, 저장소의 결과 파일은 사람이 `full --write`로 고쳐 커밋한다(CI가 저장소에 쓰지 않는다). 반례는 TLC가 찾은 가장 짧은 경로를 TLC 출력 그대로(`<모듈>.tlc.txt`), 기계가 읽는 동작 기록은 같은 불변식의 반례를 고정 시드 시뮬레이션으로 다시 찾아(`<모듈>.itf.json`) 남긴다. Quint의 TLC 연결은 `--out-itf`를 쓰지 않기 때문이다(Quint 0.33.1 `dist/src/verify.js`, 코드 리뷰 2026-11-02). TLC 첫 줄의 판 문자열은 판 번호가 아니라 실행 시각이라(`TLC2 Version 2026.11.01.162232` 꼴) 결과 파일에는 묶음 판(Apalache 0.62.4)을 적는다.
6. **명세의 모형(정본의 동작을 걸음으로).** 한 Lua 안의 일은 한 걸음, 서로 다른 슬롯에 걸친 일은 걸음을 나눈다. 대기열 Redis는 회차 슬롯 샤드 하나와 사람마다 샤드 하나를 두고, 복제본은 주 노드의 '어느 지난 시점' 상태(복제는 순서대로 가므로 앞부분만 남는다)로 둔다. 리더 쓰기는 'Lease 재확인 → (멈출 수 있음) → 세대 확인 Lua' 두 걸음이다. 줄인 것과 뺀 것은 `specs/queue.qnt` 머리에 적는다.
7. **진행성('serving이 멈추지 않으면 앞사람부터 입장 자격을 얻는다')은 이 변경에서 검사하지 않는다.** 앞사람부터는 serving 하나와 번호의 크기로 정해져 모형에서 따로 깨질 길이 없고, '결국 입장 자격'은 공정성 가정을 적은 시간 논리 검사가 필요하다(docs/verification.md §2.3). TLC의 진행성 검사는 상태 그래프 전체를 들고 있어 안전성 검사보다 훨씬 무겁다. 범위를 줄인 진행성 모듈은 모델 기반 시험(wbs 2.3.4) 전에 더한다(넘김).
8. **찾은 틈은 숨기지 않는다.** 정본 그대로의 모듈(`queue_canon`)은 ②의 반례가, OPEN[13]의 추천안만 더한 모듈(`queue_canon_batch_dup`)은 ⑤(1인 1순번, POL-002)의 반례가 나온다. 소유자가 정하기 전까지 목록에 '반례가 남는 모듈'로 두고, 두 추천안을 더한 모듈(`queue_proposed`: RB-05가 끝날 때까지 번호를 내지 않음, 묶음에 넣은 뒤 선점 값을 묶음 기록으로 바꿈)을 '지켜져야 하는 모듈'로 둔다. 정해지면 정본을 고치고 모듈을 하나로 합친다(PROGRESS OPEN[13]·OPEN[14]). ⑤는 정본 §2.1 표에 없지만, 정본이 '대기표 두 장은 장애 전환으로만 생긴다'고 보는 것(ADR-0056 맥락·재검토 조건)을 검사하려고 더했다(코드 리뷰 2026-11-02).

## 대안

| 대안 | 고르지 않은 까닭 |
| --- | --- |
| 뿌리 작업 공간에 Quint를 개발 의존성으로 | 뿌리 설치(`pnpm install`)마다 검사 도구가 따라오고, 이 PC에서는 pnpm이 막혀 잠금 파일을 고칠 수 없다. 따로 작업 공간이면 컨테이너 안 pnpm으로 잠금 파일을 만들 수 있다 |
| Quint가 처음 쓸 때 받게 둠 | 해시 확인이 없다. 받는 판은 Quint 판이 정하지만 받은 바이트는 확인하지 않는다 |
| Apalache(기호 실행) 전수 검사 | 정본이 TLC를 함께 적었고, TLC는 작은 범위의 모든 상태를 지문으로 센다. Apalache는 걸음 수 한도 안의 검사라 '탐색한 상태 수'를 남기지 못한다 |
| 반례가 남는 정본 모듈을 목록에서 빼기 | 틈이 문서에서 사라진다. 반례를 기대하는 모듈로 두면 정본을 고칠 때까지 CI가 그 반례를 계속 보여 준다 |

## 위험과 한계

- 모형은 코드가 아니다. 이름이 같은지와 동작 기록 재생은 wbs 2.3.4(V-T40)가 본다.
- 작은 범위 밖의 버그는 남는다(작은 범위 가설은 경험칙, §2.3). TLC 지문 충돌 확률은 결과 파일에 남긴다.
- 추천안 모듈은 'RB-05 전에는 번호를 내지 않는다'를 즉시 아는 것으로 줄였다. 실제로는 queue-svc가 회차 슬롯의 주 노드가 바뀐 것을 알아채야 한다(알아채는 법은 OPEN[13]의 추천).
