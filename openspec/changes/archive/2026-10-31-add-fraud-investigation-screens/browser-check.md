# 브라우저 확인: add-fraud-investigation-screens

- 날짜: 2026-10-31
- 커밋: 커밋 전 작업 트리(가지 `develop`, 기준 `02be077`). 이번 지시로 커밋·보관하지 않는다.
- 브라우저: **Claude in Chrome은 못 함(연결 없음)**. `list_connected_browsers`가 두 번(구현 중, 대조 뒤) 빈 목록이었다. OPEN[06]의 기본값대로 그 사실을 적고, 이 PC의 Playwright(Python 판, Chromium 151)로 같은 시나리오를 봤다. 앞선 퍼블리싱(`add-screen-publishing`·`align-screens-with-canon`)은 내장 브라우저로 대신했다. Chrome이 연결된 턴에 아래 표를 다시 누른다.
- 환경: 로컬 개발 서버 셋(관제 3002, 소비자 웹 3000, 포렌식 3005), 목업 데이터(합성, 고정 값). 서버 없이 그리는 퍼블리싱이라 API 요청은 없다.
- **디자인 캔버스 보드 없음**: SCR-070·071과 세 변형(SCR-069 조사·연구 원천, SCR-046 사건 요약, SCR-042 부정 예매 소명)은 보드가 없어 d5 §5.24·§7.7·§7.17~§7.19 그림을 기준으로 봤다.
- 방법: 확인 스크립트(저장소 밖, 결정 12)를 **화면을 만들기 전에 먼저 돌려 실패를 보고**(관제 SCR-070·071 133건 가운데 130건 실패, SCR-046 93건 실패, SCR-042 184건 실패. SCR-069는 원천 모델 시험을 먼저 실패시킨 뒤 만들었다), 만든 뒤 다시 돌렸다. 주소마다 `h1` 개수, 가로 넘침(`scrollWidth − innerWidth`), 정본 고정 문구, 없어야 할 글(원문 IP 꼴, 점수·가중치 숫자, 합성 전용 단추), 콘솔 오류를 쟀다. 화면 캡처는 저장하지 않고 눈으로 봤다(SCR-070·071 데스크톱 1440, SCR-071 휴대폰 375, SCR-069 조사 원천 1440, SCR-042 휴대폰 375).

## 함께 본 것(화면 담당 에이전트, 같은 날 Playwright)

- SCR-046: 역할·지정을 골라 본 경우와 기존 상태가 그대로인지 14건.
- SCR-069: 상태 고르기 링크에 `source`가 남는지, 세 원천의 새 상태.
- SCR-042: 360 다크, 기존 apl-0001·0002 화면이 그대로인지, 링크 주소(`/my/tickets`, `/help/inquiries/new`).

## 실패와 확인 못 함

- 실패: 없음(처음 186건 + 추가 12건, 리뷰 뒤 173건 + 리뷰 항목 21건 + 대화상자 확인).
- 확인 못 함: Claude in Chrome(연결 없음, 위). 화면 낭독기 완주·실기기(OPEN[06], 사람 확인). 키보드만으로 모든 상태 다니기는 IP 원문 열기 대화상자 한 곳만 봤다. SCR-069의 [표로 보기]는 기존 보드처럼 아직 동작하지 않는다(design.md '구현하며 정한 것').
