# 설계: 부정 거래 조사 화면 설계와 퍼블리싱

## Context

- 화면의 내용(요소·문구)은 docs/planning/04 §3의 SCR-042·046·069·070·071 행과 관제 IA §1.3, 흐름 F-14가 정본이다. 데이터·규칙은 docs/features/forensic-replay.md(§2 리플레이 화면, §6.2 권한, §6.7 조사 갈래)와 docs/features/control-tower.md §9.2, 칸 단위 가림은 docs/security/authz-matrix.md §4.1·§4.3, 계약은 docs/api/openapi.yaml(태그 `investigations`)이다.
- 앞선 퍼블리싱(ADR-0170, 보관한 `add-screen-publishing`·`align-screens-with-canon`)은 디자인 캔버스 보드를 시각 기준으로 옮겼다. 키트 CSS는 `@peaket/ds`, 상태는 `?state=`, 앱마다 `/preview` 목록, 관제·포렌식은 창 폭으로 보드별 배치(`board-d/t/m`)를 고른다.
- **SCR-070·071은 디자인 캔버스 보드가 없다.** 캔버스는 소유자가 요청할 때만 고친다(메모 규칙). 그래서 이 변경은 d5에 먼저 와이어프레임을 그리고, 그 그림과 키트 부품(`.widget`·`.kv`·`.stat`·`.table`·`.badge`·`.banner`·`.dialog` 등)으로 화면을 그린다. SCR-069·046·042는 보드가 있지만 이번에 더하는 변형(조사·연구 원천, 사건 요약, 부정 예매 소명)은 보드에 없다.
- 감독 루프(Sidabari4Loop)가 같은 `develop`에서 BUILD_ORDER를 진행한다. 이번에는 소유자 지시로 커밋·보관을 하지 않고 대조와 브라우저 확인까지만 한다. 기록 문서(BUILD_ORDER·PROGRESS·00-summary·review·wbs·adr·planning)는 고치지 않는다.
- 화면 앱에는 시험 도구(시험 실행기·화면 시험 라이브러리)가 아직 없다. 시험 도구는 FND-030(wbs 0.2.1 ①)의 몫이다.

## Goals / Non-Goals

**Goals**

- 세 화면(SCR-070·071과 SCR-069의 세 원천)과 두 변형(SCR-046 사건 요약, SCR-042 부정 예매 소명)을 d5에 세 크기로 그리고, 같은 모양을 목업 데이터로 퍼블리싱한다.
- 정본의 보안 규칙이 화면에도 보이게 한다: 메뉴는 지정 조사관에게만, IP는 가린 값만(원문은 사유를 적고 연 뒤 화면 메모리에만), 승인자는 사건 요약만, 두 원천을 한 화면에 섞지 않음, 점수·가중치는 어디에도 없음.
- 새 화면은 배치마다 마크업을 세 벌 두지 않고 한 벌의 반응형 마크업으로 그린다.

**Non-Goals**

- 캔버스 보드, 데이터 연결(조사 API 클라이언트, 실시간), 재인증 실제 흐름, 실제 그래프 배치·그리기 엔진(Canvas·WebGL), 실제 리플레이 파일 받기.
- 파트너의 기획사 보고 화면·경로(결정 11), 알림 모듈 문서(docs/features/notify.md)의 부정 예매 알림(결정 10).

## Decisions

### 1. 문서를 먼저 고치고 그 그림대로 그린다

보드가 없으므로 d5 와이어프레임이 시각 기준이다. 순서는 d5(배치·상태·문구) → d2(부품) → d3(부품·상태·접근성) → 코드다. 화면 문구는 docs/planning/04의 문구 초안을 그대로 쓰고, 정본에 없는 문구는 d5에 '(추천 적용 2026-10-31)'로 적는다. 대안(코드를 먼저 그리고 문서를 맞추기)은 보드 없는 화면의 기준이 코드가 되어 버려 버렸다.

### 2. 새 화면은 한 벌의 반응형 마크업

앞선 관제 화면은 보드 셋을 옮기느라 배치마다 마크업이 따로였다(보관한 변경의 '남은 빚'). 새 화면은 옮길 보드가 없으니 처음부터 한 컴포넌트에서 배치(`useLayout`: 휴대폰 768 미만·태블릿 768~1279·데스크톱 1280 이상)로 열 수와 순서만 바꾼다. 데스크톱은 12열(왼쪽 8열 | 오른쪽 4열), 태블릿은 한 단(목록 → 상세), 휴대폰은 한 단 카드 목록이다(d5 §3.9). 휴대폰에서 하지 않는 일은 버튼을 숨기지 않고 그 자리에 안내 카드를 둔다("이 작업은 태블릿이나 데스크톱에서 합니다. 휴대폰에서는 볼 수만 있습니다" [ 링크 복사 ]). 대화상자 상태(사건 만들기, IP 원문 열기, 계정 빼기, 소명 요청 확인)는 휴대폰 배치에 없으므로 `BoardGaps`로 기본 상태에 잇고 휴대폰 상태 고르기 목록에서 뺀다.

### 3. 지정 부정 거래 조사관을 목업 호스트 상태에 둔다

- 정본: 메뉴는 `FRAUD_INVESTIGATOR` 지정이 있는 commander·`cs_lead`에게만 그리고(control-tower §9.2 '누가 여는가'), 지정은 토큰이 아니라 `GET /v1/ops/auth/sessions/me`로 알아 온다. 법정 조치 아래에 둔다(같은 절 머리).
- 퍼블리싱: 호스트 상태 `session`에 `designations`를 더하고, `?designation=investigator|pseudonym|none`으로 골라 본다(`?role=`처럼 이동해도 남는다). 메뉴 함수 `navFor(role, designations)`가 지정과 역할을 함께 본다.
- 목업 사람(지어낸 이름): 조사관 도윤(`cs_lead`, `FRAUD_INVESTIGATOR`), 조사관 예린(commander, `FRAUD_INVESTIGATOR`, 사건 목록의 다른 담당), 승인자 수진(commander, 지정 없음, 기존 목업), 가명정보 취급자 태오(commander, `PSEUDONYM_HANDLER`).
- 조사 화면은 역할·지정을 고르지 않았으면 도윤의 화면으로 그린다(앞선 화면이 보드의 사람을 쓰는 것과 같다). 역할을 골랐는데 조사관 지정이 없으면(viewer·operator·`cs_agent` 포함) '권한 없음(지정 없음)'을 그린다. 정본 문구는 "이 화면을 볼 권한이 없습니다"(forensic-replay §2.2)다.
- 기본 세션(수진)에는 지정이 없어서, 지정을 고르지 않으면 다른 화면의 메뉴에 '부정 거래 조사'가 없다. 정본대로다. `/preview`의 '역할 바꿔 보기' 옆에 '지정 바꿔 보기'를 둔다.

### 4. 목업 데이터

- `apps/console-host/src/entities/fraud-case/`에 `model.ts`(계산과 이름표)와 `fixtures.ts`(합성 값)를 둔다. 회차는 기존 목업 LUMEN 1회차(10/25(일) 18:00 KST, 판매 시작 10/14(수) 20:00, 1인 한도 4)다. 기준 시각(지금)은 10/19(월) 14:20 KST다.
- 취소 마감 = 공연 시작 − 26시간 = 10/24(토) 16:00 KST(POL-046 ⑤). 소명 기한 기본값 = max(요청 + 24시간, min(요청 + 3일, 취소 마감 − 6시간))(forensic-replay §6.7.5). 남은 시간 표시: 12시간 넘으면 보통, 12시간 이하 warning, 2시간 이하 danger, 지나면 '지남'(control-tower §9.2 '취소 마감 알림'의 12·2시간).
- IP는 가린 값(IPv4 /24, IPv6 /48)만 둔다. 'IP 원문 열림' 상태의 원문 하나도 문서용 대역(RFC 5737 `203.0.113.0/24`, IPv6 `2001:db8::/32`)이고, ASN은 문서용 번호(RFC 5398, 64496~64511)다. 계정 ID·가명은 지어낸 값이다. 외부 게시물 주소는 `*.example`이다.
- 점수 원값·가중치는 목업에도 두지 않는다(범주만).

### 5. 연결 그래프는 목업 그림(CMP-080)

사건 CASE-2610-0007(계정 9, 결제 수단 연결값 하나·기기 둘·연락처 하나·IP 둘·ASN 하나)을 고정 좌표 SVG로 그린다. 점은 종류마다 모양과 색을 함께 달리한다(색만으로 구분하지 않는다). 그림은 `role="img"`와 한 문장 요약을 두고, 같은 내용을 [표로 보기] 표로 준다. 점 고르기는 퍼블리싱에서 `?state=`로 보인다. 실제 배치 엔진·대량 점 그리기는 데이터 연결 단계의 몫이다. 대안(ds에 실제 그래프 부품을 지금 만들기)은 배치 엔진·라이브러리 선택(새 의존성, ADR 필요)이 따라와 이 변경에서 뺐다.

### 6. 부품은 d2에 번호를 주고, 작은 둘만 ds에 만든다

- 새 번호: CMP-080 LinkGraph, CMP-081 CaseStatusBadge(사건 상태·계정 소명 결과·점수 범주를 글자와 색으로), CMP-082 ReplaySourceBadge, CMP-083 StepBaselineChart. 마감까지 남은 시간은 CMP-040 DeadlineBadge에 '취소 마감' 쓰임(12·2시간)을 더해 새 번호를 만들지 않는다. 승인자 사건 요약은 CMP-060 ApprovalPanel의 `fraud-action` 변형, 부정 예매 소명은 CMP-063 AppealForm의 `fraud` 변형이다.
- `@peaket/ds`에 CMP-081 `CaseStatusBadge`와 CMP-082 `ReplaySourceBadge`를 만든다(두 앱 이상이 쓰거나 규칙이 붙은 작은 부품). CMP-080·083은 목업 그림이라 앱 안에 둔다. CMP-063 `fraud` 변형은 ds의 기존 부품에 더한다.

### 7. 리플레이 원천은 `?source=`로 골라 본다

정본은 '연 길이 원천을 정한다'(forensic-replay §4.2·§6.8)이다. 퍼블리싱에서는 연 길 대신 `?source=조사|연구`(없으면 합성)로 고른다. 조사 원천은 SCR-071 [리플레이 열기]가 `?source=조사&event=&case=`로 새 탭(`rel="noopener"`)을 연다. 원천마다 바뀌는 것:

| 자리 | 합성 | 조사 | 연구 |
| --- | --- | --- | --- |
| 원천 배지(CMP-082, 늘 보임) | 합성 데이터 | 조사 | 연구 |
| 머리 단추 | 시나리오·시드·다시 만들기·파일 불러오기·내려받기·공유 주소 | 회차·사건·시간창, '조사용 기록 · 이 탭에만 있고 내려받지 않습니다', ( 관제 콘솔 › ) | 회차·시간창, '가명 기록 · 30분 동안 쓰지 않으면 지워짐', ( 관제 콘솔 › ) |
| 교차 필터 | 구역·결과·사건 종류·봇 등급(합성 정답)·네트워크 유형 | 구역·결과·사건 종류·묶음(묶음 계정·나머지) | 구역·결과·사건 종류 |
| 후보 패널 | CMP-079 산점도, 정밀도·재현율과 그 경고, 기기 묶음 | CMP-083 단계별 시간 대 정상 기준선, 묶음 안 기기 묶음 | '입장 확정 → 첫 홀드' 한 축 분포 막대(CMP-079 한 축) |
| 고정 문구 | "후보 찾기용입니다. 봇 판정은 표본 검토(SCR-067)와 정해진 규칙(POL-006)으로 합니다." | "후보 찾기용입니다. 조치는 사건 작업대에서 소명과 승인을 거쳐 합니다(POL-046)." | 합성과 같다 |
| 더하는 상태 | — | 받는 중, 원천 만료, 권한 없음(지정 없음) | 받는 중, 원천 만료, 권한 없음(지정 없음) |

예전 상태 이름 '권한 없음(2단계)'은 '2단계'가 없어졌으므로 '권한 없음(지정 없음)'으로 바꾼다.

### 8. SCR-046은 부정 예매 조치 상태 넷을 더한다

'부정 예매 조치'(승인자 수진, 사건 요약 읽기 전용), '부정 예매 조치 · 요청자 본인'(도윤, 승인 단추 비활성과 이유, 작업대 링크 보임), '부정 예매 조치 · 열 수 없음'(가명정보 취급자 태오 또는 `cs_lead`: 상세가 없는 업무와 같은 404라 요약도 승인 단추도 없다), '부정 예매 조치 · 취소 마감 지남'(만료, 실행하지 않음). 사건 요약 칸은 `fraudCaseSummary`의 칸만 보인다(계정 ID·가명·IP·연락처·그래프 없음). 승인자에게 조사관 지정이 없으면 ( 사건 작업대 › )를 보이지 않는다. 세 배치 보드에 공용 패널 하나(`FraudActionPanel`)를 넣어 마크업이 세 벌이 되지 않게 한다.

### 9. SCR-042는 부정 예매 소명 상태 넷을 더한다

'부정 예매 소명'(작성), '제출됨 · 부정 예매', '결과 · 부정 예매 소명 인정', '결과 · 부정 예매 소명 불인정'. 사유 범주(하나 이상), 기한(남은 시간), 양도가 잠긴 티켓, "결정될 때까지 이 표들의 양도가 잠깁니다. 입장은 그대로 할 수 있습니다", "돈이 오가지 않은 가족·지인 대리 예매는 부정 예매가 아닙니다"를 보인다. 점수·가중치·근거 신호·다른 계정은 보이지 않는다(authz-matrix §4.1 마지막 행). 목업 건은 `apl-0003`이다.

### 10. 부정 예매 알림은 d5 §9.1에 한 줄만

SCR-042로 들어오는 길(소명 요청 알림)이 d5 §9.1 알림 표에 없다. 받는 사람·시점·여는 화면을 forensic-replay §6.7.5('알림')대로 한 줄 더하고 채널은 양도 회수 예고와 같게 이메일로 둔다(추천 적용). 알림 모듈 문서(docs/features/notify.md)의 발송 종류 표는 다음 단계에 넘긴다.

### 11. 파트너 기획사 보고 화면은 이 변경에서 정하지 않는다

forensic-replay §6.7.7은 '파트너가 같은 집계를 읽는 화면·경로는 FRN-050에서 정한다'고 적었다. 그러나 그 경로는 계약(openapi)에 새 파트너 경로를 더하는 일이라 계약 우선 규칙상 계약을 먼저 고쳐야 하고, 소유자가 이번 범위로 준 목록에 없다. 추천안(파트너 SCR-027 정산 리포트에 '부정 예매 조치 집계' 탭, 파트너 경로 하나)을 보고에 적고 다음 단계에 넘긴다.

### 12. 시험: 계산은 시험을 먼저, 화면은 확인 스크립트를 먼저

- 화면 앱에는 시험 도구가 없고 이 변경은 의존성을 더하지 않는다. 그래서 Node 24의 내장 시험 실행기(`node --test`, 타입 지우기로 `.ts`를 그대로 읽는다)로 입력과 출력이 분명한 계산과 이름표를 먼저 시험한다(config.yaml tasks 규칙이 허용하는 '입력과 출력이 분명한 계산'). 시험 파일은 `*.test.mjs`라 앱의 `tsc`·번들에 들어가지 않는다. 각 앱 `package.json`에 `test` 스크립트(`node --test`)를 더한다. 정식 시험 도구(FND-030)가 들어오면 옮긴다.
  - 관제: 취소 마감·소명 기한 기본값·남은 시간 표시·구매 대 한도 글자, 상태·신호·사유 범주 이름표가 openapi 열거값을 모두 덮는지, 목업의 IP가 모두 가린 값인지(`[ASVS v5.0.0-14.2.6]`).
  - 포렌식: 원천 고르기와 원천별 고정 문구·보일 자리.
  - 소비자 웹: 부정 예매 사유 범주 이름표와 잠긴 티켓 안내 글.
- 화면은 E2E 시험을 쓰지 않는다(ADR-0167 결정 6). 대신 화면을 만들기 전에 확인 스크립트(Playwright, 이 PC의 Python 판, 저장소에 넣지 않음)를 먼저 써서 실패를 보고, 화면을 만든 뒤 통과를 본다. 확인 항목은 주소마다 `h1` 하나, 가로 넘침 없음, 정본 고정 문구, 원문 IP가 기본 화면에 없음, 메뉴가 지정에 따라 나오고 사라짐이다. 결과는 browser-check.md에 적는다.

### 13. 브라우저 확인

대조 뒤 peaket-browser-check 절차로 한다. Claude in Chrome 연결이 없으면 OPEN[06] 기본값대로 '못 함(연결 없음)'과 까닭을 적고, 결정 12의 Playwright(Chromium 151)로 같은 시나리오를 본다(앞선 퍼블리싱은 내장 브라우저로 대신했다).

## Risks / Trade-offs

- **보드 없이 그린 화면이 나중 보드와 다를 위험** → d5 그림을 기준으로 삼고, 보드를 그리면(소유자 요청 때) 다른 곳을 목록으로 맞춘다. design.md와 browser-check.md에 '보드 없음'을 적는다.
- **목업이 보안 규칙을 흐리게 보일 위험**(예: 원문 IP가 목업에 남음) → 원문은 'IP 원문 열림' 상태 하나에만, 문서용 대역으로 둔다. 시험이 목업 문자열의 원문 IP를 센다.
- **`?designation=`이 운영에 남을 위험** → 퍼블리싱 층(`features/preview-host`)에만 두고, 데이터 연결 단계에서 `sessions/me`로 바꾼다(ADR-0170의 걷어 내기와 같다).
- **루프와 같은 작업 트리** → 이번에는 커밋하지 않는다. 루프가 고치는 기록 문서는 건드리지 않는다.
- **큰 보드 파일(SCR-046·069) 손질** → 공용 패널을 따로 두고 보드에는 조건 줄만 더해 변경을 작게 한다.

## 구현하며 정한 것과 정본과 다른 곳(2026-10-31)

- **보드 없음**: SCR-070·071과 세 변형(조사·연구 원천, SCR-046 사건 요약, SCR-042 부정 예매 소명)은 디자인 캔버스 보드가 없다. d5 §5.24·§7.7·§7.17~§7.19 그림과 키트 부품으로 그렸다. 캔버스는 고치지 않았다(소유자가 요청할 때만).
- **시험 위치**: `node --test` 스크립트를 관제·포렌식·소비자 웹과 `@peaket/ds`(CMP-081 이름표) 넷에 더했다. 시험 파일은 `*.test.mjs`라 `tsc`·번들에 들어가지 않는다. 관제 14건, 포렌식 24건, 소비자 웹 9건, ds 4건. 처음 실행은 모두 모듈이 없어 실패했다.
- **목업 수**: 후보 묶음 8, 조치한 표 17장, 소명 인정 2/18계정으로 정해 d5 §7.18 그림을 같은 값으로 고쳤다. 사건 작업대의 외부 게시물은 이 회차 게시물 둘(이 묶음과 맞은 좌석 0)로 그렸다(묶음 A에 게시물 대조 신호가 없어서).
- **사건 작업대 상태는 단계 그림이다**: 사건마다 기본 상태는 그 사건의 상태이고, 다른 단계 상태를 고르면 그 사건의 목업 시각(소명 요청·조치 요청·실행)으로 그린다. 위 상태 바 시계도 그 단계의 시각이다. 그래서 CASE-2610-0007의 '결정 대기'처럼 목록의 지금 상태와 다른 그림을 볼 수 있다(퍼블리싱 한계).
- **조치 요청 비활성 이유**: 소명을 보내기 전에는 "소명을 요청하고 기한이 지난 뒤에 요청할 수 있습니다", 기한 전에는 "소명 기한이 지난 뒤에 요청할 수 있습니다"로 나눠 d5에 적었다.
- **연결 그래프**: 점을 누르는 고르기는 화면 안 상태(주소에 남지 않음)이고, IP 점을 고른 그림만 `?state=점 고름(IP)`로 다시 연다. 범례·표의 모양은 그림과 같은 작은 SVG다.
- **취소 마감 배지(CMP-040 cancel-deadline)**: ds에 DeadlineBadge 부품이 아직 없어(키트 `badge` 클래스로 그려 왔다) 관제 `entities/fraud-case`의 `CancelDeadlineBadge`로 두었다. SCR-070·071·046이 함께 쓴다. 표 안에서는 짧은 글('5일 1시간 남음', 화면 낭독기에는 '취소 마감까지'를 붙여 읽음), 머리에서는 문장으로 보인다.
- **SCR-046 재인증**: 부정 예매 조치의 [승인] 단추는 기존 '실행 직전 재인증 — commander' 상태(양도 회수 대화상자)로 가지 않고, 패널 안에서 그 조치의 재인증 대화상자를 연다(내용이 섞이지 않게). 승인 자격이 없는 세션(`?role=cs_lead`·operator, `?designation=pseudonym`)이 승인자 상태를 열면 '열 수 없음'으로 그린다(서버 404와 같은 뜻). 사건 요약에는 openapi `FraudCaseSummary`에 없는 점수 범주를 보이지 않는다.
- **SCR-069**: 원천 링크(합성·조사·연구)는 개발 서버에서만 보이는 고르기다. 조사 원천의 묶음 필터는 다른 필터처럼 [전체]를 처음 값으로 더했다. 조사·연구의 타임라인 눈금은 합성과 같은 T+00:00~T+10:00이다(머리의 시간창과 다르다, 목업 한계). 조사 원천 '후보 고름'은 기준선 그림의 칸 하나(#3 · 입장 확정 → 첫 홀드)를 고른 그림이다. 받는 중은 본문 자리에 진행 막대 카드를 둔다. 권한 없음의 머리에는 배지와 관제 콘솔 링크만 둔다(회차·사건 번호를 보이지 않는다). 배지 모양은 조사(빨강·방패), 연구(보라·가린 눈), 합성(기존 노랑)이다. 기준선 그림은 기존 산점도처럼 요약 설명을 달았고 [표로 보기]는 기존 보드처럼 아직 동작하지 않는다(d2 CMP-083은 그림을 숨기고 표를 주라고 적었다. 데이터 연결 단계에서 표를 붙인다). 파일 거절 이유 한 줄, 운영 탭용 복사 방식 띠, 후보 패널 제목, 받는 중 아래 글, 기준선 설명 글은 정본에 없던 문구라 추천 적용이다. 범위 밖의 작은 정리로, 다크가 처음인 이 앱의 상태 고르기 패널 테마 링크를 `baseTheme="dark"`로 고치고 쓰지 않던 보드 상태 상수를 지웠다.
- **SCR-042**: <답변 기다림>은 제출 전에만, 작성 화면에도 처리 일정 줄, 인정 결과에는 '양도 잠금을 푼 티켓 2장' 목록을 두었다(d5 §5.24에 반영). 사유 범주 배지는 여러 개라 목록(`ul`)으로 묶었다. 사건 ID는 팬이 볼 수 있는 칸이지만 d5 그림에 없어 데이터로만 둔다. 남은 시간은 다른 변형과 같은 사안 카드의 시계 배지다. openapi `FraudAppealView`에는 공연 이름·좌석 글이 없어(`eventId`·`lockedTicketIds`만) 데이터 연결 때 팬 자신의 티켓·공연 정보와 합쳐야 한다.
- **목업 ID**: 사건 ID(`CASE-2610-0007`)·묶음 ID는 읽기 쉬운 지어낸 값이다. openapi는 UUID다.

## 코드 리뷰 뒤 고친 것(2026-10-31, 결함 14건)

시험을 먼저 고치거나 더해 실패를 본 뒤 고쳤다. 계산 시험은 `node --test`(관제 18·포렌식 27·웹 9·ds 5건), 화면은 저장소 밖 확인 스크립트(리뷰 항목 21건, 처음 16건 실패 → 0건)다.

- **취소 마감 단계**: 색 단계를 보이는 시간 값(내림한 시간)으로 정한다. 12시간 30분 남음은 '12시간 남음'과 warning, 2시간 30분은 '2시간 남음'과 danger다(d2 CMP-040에 반영).
- **연결 그래프 표**: [표로 보기] 표에 묶음 안 계정 행과 고르기 단추를 넣어, 키보드·화면 낭독기로 계정을 골라 [묶음에서 빼기]에 닿는다. 열 이름은 '이어진 점'이다.
- **SCR-046 목록**: 부정 예매 조치 줄과 '전체' 수(4·5)는 그 요청을 받을 수 있는 세션(요청한 조사관, 승인 자격자)에만 그린다. '요청자 본인' 변형도 세션을 보고, 요청한 조사관이 아니면 '열 수 없음'이다.
- **SCR-069 사건 따라가기**: 주소의 `?case=`·`?event=`를 읽어(꼴이 맞을 때만) 머리·받는 중 글·관제 링크에 쓴다. 권한 없음 화면의 관제 링크는 대시보드다(사건 번호를 드러내지 않는다).
- **SCR-071**: 정상 종료는 소명·조치 자리 대신 '정상 종료' 칸이고, 근거 없음(C2)과 모든 계정 소명 인정(C4)의 문구와 사건 기록을 나눴다. 태블릿·휴대폰 순서를 ① ② ④ ⑤ ⑥ ③ ⑦ ⑧로 맞췄다. 휴대폰의 숨긴 단추 자리(소명 판단, 요청 철회)에 안내 카드를 더했다. 메모와 '이 묶음과 맞은 좌석' 수는 사건 목업(`memos`·`postMatches`)에서 읽는다(CASE-2610-0004는 게시물 좌석 2개).
- **SCR-070**: 사건 만들기 대화상자는 누른 줄의 묶음을 보인다(`?cluster=`). 마감 임박 경고 아이콘은 숨김 글자 "결정되지 않은 사건"으로 뜻을 전한다.
- **ASVS 14.3.3**: 화면 고르기(사건 상태 칩·정렬)는 화면 메모리에만 두는 구현에 맞춰 문장을 고쳤다.
- **시험 강화**: 열거값 시험은 docs/api/openapi.yaml에서 읽어 비교한다(관제·ds·웹). 원문 IP 시험은 목업 값과 화면 코드 파일 글을 함께 보고, IPv6 원문과 `/24`가 붙은 원문(끝이 0이 아닌 값)도 잡는다. 점 ID 시험은 겹치지 않음·꼴·표시값 글자가 들어가지 않음·선의 끝을 본다. 포렌식 원천 시험은 넘긴 사건·회차와 잘못된 값 거르기를 본다.
