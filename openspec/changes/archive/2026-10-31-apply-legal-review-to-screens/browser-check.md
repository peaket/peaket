# 브라우저 확인: apply-legal-review-to-screens

- 날짜: 2026-10-31
- 커밋: 커밋 전 작업 트리(가지 `develop`, 기준 `a92695b`)
- 브라우저: **Claude in Chrome**(Chrome 156, 소유자가 연결해 둔 시험용 프로필, `list_connected_browsers`에 한 대). 이 변경에서 처음으로 Chrome으로 눌렀다.
- 환경: 로컬 개발 서버 넷(소비자 웹 3000, 파트너 3001, 관제 3002, 포렌식 3005). 목업 데이터는 합성 고정 값이다. 서버 없이 그리는 퍼블리싱이라 API 요청이 없다.
- 기준: 디자인 캔버스 보드에 없는 변형이라 d5 §5.11·§5.14·§5.17·§5.23·§5.24·§5.30·§6.10·§7.7·§7.17~§7.19·§9.2의 글자를 그대로 대조했다(FRN-080 커밋 `a92695b`의 줄).
- 방법: 주소를 열고 페이지 스크립트로 `h1` 개수, 가로 넘침(`scrollWidth − innerWidth`), d5 문장, 없어야 할 글을 쟀다. 단추는 실제로 눌러 보고 결과를 읽었다. 콘솔 오류는 앱마다 다시 연 화면에서 봤다.
- **폭**: Chrome 창이 작게 접혀 있어(바깥 160×28) `resize_window`가 듣지 않았다. 그래서 창 안 폭이 1920인 상태로만 눌렀다. 폭 360·768·1280·1440은 작업자들의 확인 스크립트를 마지막 코드로 다시 돌려 대신했다(Playwright, 저장소 밖). 결과는 웹 541건, 관제·포렌식 660건, 파트너 전부 실패 0이다. 화면 캡처도 창이 접혀 있어 두 번 시간 초과가 났고, 한 장(SCR-042 조치 결과에서 [이의 내기]를 누른 뒤)만 눈으로 봤다.

## 실패와 확인 못 함

- 실패: 없음.
- 확인 못 함: Chrome 창 폭 바꾸기와 화면 캡처는 창이 접혀 있어 하지 못했다. 폭별 모양은 위 확인 스크립트 결과로 대신했다. 소유자가 Chrome 창을 펼쳐 두면 다음 화면 단계에서 폭별로 다시 누른다.
- 사람 확인 목록(PROGRESS 턴 규칙): 화면 낭독기로 SCR-042 받은 사람 변형과 SCR-046 대상 줄의 체크 칸 이름('계정 1 · 표 3장 · 소명 불인정')을 끝까지 읽어 보기, 태블릿 실기에서 SCR-070 가릴 자리 상자 그리기.
