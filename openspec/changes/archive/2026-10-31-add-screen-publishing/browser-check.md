# 브라우저 확인: add-screen-publishing

- 날짜: 2026-10-31
- 커밋: 커밋 전 작업 트리(가지 `feature/0.6.4-screen-publishing`, 기준 `aac3787`)
- 브라우저: **Claude in Chrome은 못 함(연결 없음)**. `list_connected_browsers`가 빈 목록이었다(두 번 확인). OPEN[06]의 기본값대로 그 사실을 적고, 대신 Claude 데스크톱 앱의 내장 브라우저로 같은 시나리오를 봤다. Chrome이 연결된 턴에 아래 표를 다시 누른다.
- 환경: 로컬 개발 서버 여섯(웹 3000, 파트너 3001, 관제 3002, 스캐너 3003, 대기실 3004, 포렌식 3005), 목업 데이터(합성, 고정 값). 서버 없이 그리는 퍼블리싱이라 API 요청은 없다.
- 방법: 앱마다 화면 목록(`/preview`)의 경로를 같은 출처 iframe에 차례로 열고, 폭마다 `h1` 개수, 가로 넘침(`scrollWidth − clientWidth`), 빈 화면 여부를 쟀다. 기본 상태만 쟀다. 상태별 확인은 화면 담당 에이전트들이 같은 방법으로 했다(아래 '함께 본 것').

## 함께 본 것(화면 담당 에이전트, 같은 날 내장 브라우저)

- 소비자 웹: 통합 정리 뒤 162개 주소(상태 포함) × 320·768·1280에서 가로 넘침 0·`h1` 1개, 본인확인 창 → 결과 대화상자 → Esc로 초점이 원래 버튼에 돌아옴.
- 파트너: 87개 주소(모든 상태·다크·실무자) 200, 폭 320 가로 스크롤 없음.
- 관제: 99개 상태 × 1400·900·320, 서랍·대화상자·`?role=` 메뉴, 화면 조각 받기 실패를 일부러 일으켜 SCR-059 모양 확인.
- 대기실: 모든 상태 × 320·768·1280, 콘솔 오류 없음.

## 실패와 확인 못 함

- 실패: 없음.
- 확인 못 함: Claude in Chrome(연결 없음, 위). 화면 낭독기 완주·실기기(OPEN[06], 사람 확인), 키보드만으로 모든 상태 다니기는 하지 않았다. 다크 모드는 관제(기본 다크)만 폭마다 쟀고, 다른 앱의 `?theme=dark`는 화면 담당이 상태 목록으로만 열어 봤다.
