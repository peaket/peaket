# 제안: 결제 규칙 모델 검사 명세(wbs 0.9.3, BUILD_ORDER FND-150)

## Why

docs/verification.md §2.1은 결제 규칙을 명세 `payment`로 쓰고 작은 범위의 모든 순서를 기계로 검사하라고 한다(ADR-0057). 지킬 약속은 ① 주문당 승인된 결제 1건 이하(이중 결제 0) ② 결제 접수 뒤 결제사 바뀜 0 ③ 승인 없는 발권 0 ④ 회차 취소 확정·CS 확인 없는 승인 뒤 환불 0이고, 결국 일어나야 할 일은 '승인된 주문은 발권되거나 취소·환불로 끝나고, 결과 모름은 해소되며, 접수하지 않은 주문은 만료로 끝난다'이다. 승인 응답 유실(결과 모름), 서비스 재시작, 웹훅 중복·지연, 결제사 전환, 발권 실패와 보상이 섞이면 타이밍에 따라서만 드러나는 틈이 생길 수 있어 부하 시험보다 먼저 규칙 단계에서 본다. BUILD_ORDER FND-150은 '승인된 주문은 발권 또는 환불로 끝남'을 완료 기준에 넣었으므로, 0.9.1·0.9.2가 미뤄 둔 진행성 검사를 이번에 검사 도구에 더한다.

## What Changes

- **명세** `specs/payment.qnt`: 결제 시도 생성(결제사 선택, 이전 시도 대체), 결제창 인증, 결제 접수(활성 시도·결제사 대조, 결제사 고정), 판매 예약, 승인 명령(payment-svc 결제 원장, 주문 ID로 멱등), 승인 호출(CONFIRM_SENT 표시, 결제사 처리, 응답·시간 초과로 결과 모름), 승인 기한, 결과 모름 해소 조회, 서비스 재시작, 결과 반영(사건·당기기), 발권과 발권 재시도, 발권 기한 넘김·CS 확인, 보상(회차 취소 확정·CS 확인 뒤 결제 취소), 발권된 주문의 회차 취소 환불, 결제 시도·주문의 만료, 결제사 전환.
- **불변식**: §2.1의 ①~④와, 정본이 적은 약속 하나를 더 본다: ⑤ 과금 없음으로 끝난 주문(FAILED·EXPIRED)에 결제사 승인이 남지 않는다(payment §3 FAILED 뜻, §8 결제-발권 불일치의 끝 상태 쪽).
- **진행성**: 공정성 가정(시스템 동작마다 약한 공정성, 시간은 흐름)을 단 시간 논리 속성을 TLC로 검사한다. 검사 도구에 진행성 검사(`temporal`)를 더한다(시험부터). 시뮬레이션(`quint run`)은 진행성을 보지 않으므로 PR 검사에서는 건너뛰고 전수 검사에서만 돈다.
- **변형**(검사가 살아 있는지, V-T1): 결제사 고정, 결제 원장의 주문당 1건, 결과 모름을 가정하지 않음, 웹훅 본문을 믿지 않음, 승인 뒤 앞으로 다시 하기(ADR-0106), 발권 재시도를 하나씩(①은 둘을) 끈 모듈.
- **찾은 것을 묻는다**: 정본 그대로에서 깨지는 약속이 나오면 막는 추천안을 더한 모듈을 '지켜져야 하는 모듈'로 두고 정본 그대로의 모듈은 '반례가 남는 모듈'로 둔 채 PROGRESS의 미해결로 묻는다(FND-130·FND-140과 같은 방식).

## Impact

- 정본: docs/verification.md §2.1(범위 확정)·§2.2(진행성 실행)·§2.3·§2.6(검사 기록)·V-T1, docs/features/payment.md §11 머리말, ADR-0015·0044·0057·0106 상태 줄, specs/README.md, wbs 0.9.3, BUILD_ORDER(넘기는 것), 00-summary·consistency-review R 번호.
- ID: ADR-0015·0044·0057·0106·0107·0140, V-T1, V-T40(동작 이름), P-T1·P-T3·P-T15·P-T24·P-T27·P-T30·P-T39, POL-013·036, NFR-006, WBS 0.9.3.
- 코드: `specs/payment.qnt`, `specs/specs.json`, `specs/results/payment*`, `tools/spec-check/spec-check.mjs`·시험.
- CI: 워크플로는 바뀌지 않는다. `specs_full` 범위는 검사 목록의 `adrs`를 읽으므로 결제 ADR이 바뀌어도 전수 검사가 돈다.
- 보안: 화면·API·데이터가 없는 검사 도구 변경이다(ASVS 추적 표는 FND-130과 같이 docs/security/asvs/delivery.md 15.2.4의 범위 안).
