# D4. 핸드오프 체크리스트

- **독자와 용도**: 제품 디자이너가 프로토타입 UI 시안을 프론트엔드 개발자에게 핸드오프하기 전, 그리고 프론트엔드 개발자가 구현을 완료하고 코드 리뷰를 요청하기 전에 동일한 기준표를 바탕으로 상호 교차 점검하기 위해 활용한다. 체크리스트 항목은 표준 핸드오프 템플릿에 본 프로젝트의 핵심 디자인 원칙(`design/d1-brief.md`) 및 운영 정책(`planning/03-policies-glossary.md`)에서 도출된 필수 요건들을 결합하여 구성하였다.
- **원문 출처**: 설계서 13장(WCAG 2.2 AA 웹 접근성, 명도 대비, 색상 및 시각 패턴 병행), 9장(모션 접근성), 7장(폼 입력 UX 규칙), 6장(디자인 토큰 단일 소스 원칙), `POL-004`·`006`·`013`·`024`(대고객 고지 문구).
- **기준 기획 버전**: v1.0. 점검 세부 항목은 누락된 핸드오프 기준을 체계화한 것이므로 전체에 [보완] 표기를 적용한다.

## 1. 모든 화면 공통 체크리스트

| # | 점검 항목 | 구체적 통과 기준 |
| --- | --- | --- |
| 1 | 5대 표준 상태 및 화면별 특수 상태가 모두 설계되었는가 | 기본(Default), 로딩(Loading), 빈 화면(Empty), 에러(Error), 권한 없음(Forbidden)의 5대 UI 상태와 화면별 특수 라이프사이클 상태(stale, soon, expired, degraded, offline)가 사전에 완벽히 정의되어 있어야 한다. |
| 2 | 모든 시각 속성(색상, 간격, 타이포그래피)이 토큰으로 바인딩되었는가 | 원시 색상 하드코딩 0건, 임의 픽셀(px) 인라인 스타일링 0건을 달성해야 하며, 오직 `tokens.json`에 정의된 시맨틱 토큰(space, size, typography)만을 참조해야 한다. |
| 3 | 본문 텍스트 명도 대비 기준을 충족하는가 | 일반 본문 텍스트는 4.5:1 이상, 대형 텍스트(24px 이상 또는 19px 이상 볼드)는 3.0:1 이상의 명도 대비를 라이트 및 다크 모드 양쪽에서 모두 충족해야 한다. 토큰 값 수정 시 `design/d2 §5`의 상대 휘도 계산표를 재검증하여 반영해야 한다. |
| 4 | 핵심 그래픽 UI 요소 명도 대비 기준을 충족하는가 | 폼 테두리선, 아이콘, 키보드 포커스 링, 조작 가능한 좌석 요소는 배경 대비 3.0:1 이상의 명도 대비를 충족해야 한다. |
| 5 | 마우스 클릭 및 모바일 터치 타깃 영역이 충분한가 | 모든 대화형 인터랙션 요소는 최소 24×24px 이상의 클릭 영역을 가져야 하며, 모바일 주요 액션 버튼(좌석 홀드, 결제하기, 바코드 스캔, 로비 입장)은 최소 44×44px 이상의 터치 타깃을 확보해야 한다. |
| 6 | 키보드 포커스 탐색 순서와 시각적 포커스 링이 유효한가 | DOM 트리 구조 순서와 화면의 시각적 읽기 순서가 일치해야 하며, 키보드 Tab 이동 시 포커스 링이 선명하게 노출되어야 한다. 모달 다이얼로그는 포커스 트랩(Focus Trap) 및 닫기 후 트리거 요소 복귀를 충족해야 한다. |
| 7 | 모든 사용자 행동을 키보드만으로 완주할 수 있는가 | 마우스 드래그 앤 드롭 인터랙션(가격 등급 순서 재배치, 파트너 좌석맵 편집 등)에 대해 동등한 기능의 키보드 조작 대안(위/아래 방향키 또는 조작 버튼)이 제공되어야 한다. |
| 8 | 보조기기 스크린리더 레이블이 누락 없이 제공되는가 | 아이콘 단독 버튼에 명시적 `aria-label`이 선언되어 있어야 하며, 동적 라이브 영역(로비 카운트다운은 30초 간격, 대기열의 앞 인원·진행 막대는 합쳐서 1분에 한 번(ADR-0063), 좌석 홀드 타이머는 만료 1분 전 시점에만 낭독)의 알림 빈도가 제어되어야 한다. |
| 9 | 시스템의 움직임 축소 설정을 충실히 반영하는가 | `prefers-reduced-motion: reduce` 설정 감지 시 모든 공간 이동 애니메이션이 부드러운 불투명도(opacity) 전환으로 자동 대체되어야 하며, 모션 조작 속성은 오직 `transform`과 `opacity`로만 한정해야 한다. |
| 10 | 안내 문구가 용어 사전 및 UX 라이팅 가이드라인을 준수하는가 | 기획 문서(`planning/03-policies-glossary.md`)의 공식 용어 사전과 `design/d2 §4` 라이팅 규칙을 준수해야 한다. 특히 무작위 셔플 및 하이브리드 대기열 공연에서 '선착순'이라는 기만적 표현이 0회여야 한다. |
| 11 | 법정 의무 고지 문안이 원형 그대로 정확히 수록되었는가 | 대기열 정렬 방식 법정 고지(`POL-004`), 부정구매·부정판매 형사처벌·과징금 법정 고지(`POL-024` 라목), 부정 게시물 노출 제한 고지(다목), 통신판매중개자 고지와 판매자 정보(`POL-037`)가 글자 그대로 수록되어야 한다. 법정 고지는 안내 모달로만 숨기지 않고 본문에 늘 보여야 한다(공연 상세의 정렬 방식·판매 조건 요약·라목 고지·판매자 줄. 대기열은 화면 아래 '순번 안내 ›' 시트에 전문, ADR-0063). 자동화된 시스템 결정 안내(`POL-006`)는 고정 문안이 없으므로 필수 내용(자동으로 확인된 사실, 설명 요청·재검토 신청 권리)이 빠짐없이 들어갔는지 확인한다(문구는 planning/04 SCR-009). |
| 12 | 에러 메시지가 표준 2단계 구조를 갖추었는가 | 모든 오류 문구는 '[무엇이 문제인가] + [어떻게 해결하는가]'의 구조를 갖추어야 하며, 과금이 없는 실패(payment §4에서 0원으로 끝난 실패)의 안내문에는 "요금은 청구되지 않습니다"가 결합되어야 하고, 결과 불명·자동 취소 안내에는 쓰지 않는다(`design/d2 §4`). |
| 13 | 신규 UI 컴포넌트가 디자인 시스템(D2)에 공식 등록되었는가 | 신규 컴포넌트에 CMP 식별자가 부여되고 Storybook 스토리(모든 상태 및 variant 망라)가 등록되었으며, Storybook 접근성 애드온(`addon-a11y`) 검사를 오류 없이 통과해야 한다. |
| 14 | 다크 모드 및 라이트 모드 환경이 완벽히 검증되었는가 | 중앙 관제 콘솔은 상시 다크 모드 환경에서 검증되어야 하며, 소비자 웹 및 파트너 콘솔은 라이트 모드와 다크 모드 양대 환경 모두에서 시각적 결함이 없음을 입증해야 한다. |
| 15 | 4개 다국어(ko, en, ja, zh) 환경에서 텍스트 오버플로우가 없는가 | 한국어, 영어, 일본어, 중국어 번역 적용 시 고정 폭 지정으로 인한 버튼 및 배지 텍스트 잘림 현상이 없어야 하며(내용 너비 기반 가변 확장), 날짜와 통화 표기는 표준 `Intl` API 포맷을 따라야 한다. |
| 16 | SEED Design 기반 컴포넌트를 우선적으로 재사용하였는가 | `design/d2 §1.1` 대응표의 'SEED 순수 활용' 및 'SEED 기반 피켓 커스텀 확장' 항목에 명시된 컴포넌트는 독자 구현 대신 `@seed-design/react`를 기반으로 구성해야 한다. 브랜드 역할색과 텍스트 색상은 피켓 토큰으로 오버라이드하되(`ADR-0040`), 당근 브랜드 리소스 사용은 0건이어야 한다. |
| 17 | 반응형 브레이크포인트에서 불필요한 가로 스크롤이 발생하지 않는가 | 지정된 브레이크포인트(360, 768, 1024, 1440px) 전 구간에서 비정상적인 가로 스크롤이 발생하지 않아야 한다(파트너 및 관제 콘솔도 360px부터 같다. 1280×800은 데스크톱 기본 밀도, ADR-0061). 모바일 대기실 화면은 `100dvh`를 충족해야 한다. |

## 2. 화면 유형별 추가 점검

| 대상 화면군 | 상세 점검 요건 |
| --- | --- |
| 대기실 (`SCR-007`, `SCR-008`) | 오픈 전 로비 상태에서 순번으로 오인될 수 있는 임의의 숫자가 노출되지 않아야 한다. 내 앞 대기 인원수는 반올림 없는 정확한 실수치로 표시되고, 내 번호와 현재 입장 번호는 보이지 않아야 한다(ADR-0060 결정 2). 다른 기기·탭에서 이미 참가했으면 처음 기기에서 계속하라는 안내와 기존 참가를 취소하고 다시 참가하는 확인 대화상자(오픈 뒤는 새 순번)가 있어야 한다(ADR-0060 결정 1). 배터리 15% 이하 저전력 모드 진입 시 모든 애니메이션이 비활성화되어야 한다. 좌석 자동 배정 공연의 희망 조건 카드(CMP-057)는 키보드만으로 입력·수정할 수 있어야 하며 저장 여부를 시각 표시와 텍스트로 함께 알려야 한다. 대기열 기본 화면은 앞 인원·진행 막대·예상 시간·대기 취소 네 가지뿐이고 등급별 매진 현황이 없어야 한다. 진행 막대는 0~100% 안이고 처음 앞 인원이 0이면 100%, 더 오래된 대기 상태 파일로 앞 인원이 늘어 보이면 실제 값대로 물러나야 하고, 같은 탭 새로고침에는 처음 앞 인원(세션 저장소)이 남아야 하며, 모션 축소·저전력에서는 효과 없이 값만 바뀌고 `aria-valuetext`가 "앞에 N명, 약 M분 남음"이어야 한다. '순번 안내 ›' 시트에 POL-004 문구와 POL-024 라목 고지가 접히지 않고 있어야 한다(ADR-0063). 그 회차의 판매 종료(공연 시작 24시간 전) 뒤에는 대기 화면이 ended("판매 시간이 끝났습니다")로 바뀌고 폴링이 멈춰야 하며, 사전 셔플 공연의 만료 화면도 다른 공연과 같은 [다시 줄 서기] 문구여야 한다(ADR-0064). 번들 크기는 Gzip 기준 JavaScript 50KB 이하, CSS 10KB 미만을 엄격히 유지해야 한다. |
| 좌석 선택 (`SCR-010`) | 좌석 6대 상태가 색상, 시각 패턴, 텍스트의 3중 신호로 명확히 구별되어야 한다(처음 그림의 점유 좌석은 '선택 불가', 휠체어석은 다른 상태와 함께 그리는 속성, seat-hold §2). 주문서 생성 전 무활동 4분 [가정]에 경고 대화상자(`role="alertdialog"`, 초점은 [ 계속하기 ])가 떠야 한다(ADR-0060 결정 7). 비활성 좌석(타인 홀드, 기판매, 판매 불가)은 WCAG 1.4.11 비활성 예외 조항을 적용받되 빈 좌석과의 뚜렷한 명도 차이를 확보해야 한다(`design/d2 §5`). 스크린리더 대안 컴포넌트인 SeatList를 통해 좌석 탐색부터 홀드까지 단독 완주가 가능해야 한다. 처음 그림은 전체 배치(구역 색·상태)이고 확대·축소는 휠·핀치 말고도 [+]·[−]·[전체 보기]로 할 수 있어야 하며(WCAG 2.5.7), 좌석이 보이는 구역만 실시간 채널을 구독해야 한다(ADR-0063). 홀드 경합 패배 시 인접 대체 좌석을 추천해야 하며, 좌석 홀드 시간 1회 연장 컨트롤을 제공해야 한다. 판매 종료(공연 시작 24시간 전) 뒤 새 홀드가 410 `sale-ended`면 판매 종료 배너가 뜨고, 이미 고른 좌석은 남은 시간 안에 결제로 이어질 수 있어야 한다(ADR-0064). |
| 주문 및 결제 (`SCR-011`, `SCR-012`) | 결제창 렌더링 영역은 두 결제사(토스페이먼츠·포트원)의 Cross-Origin Opener Policy(COOP) 가이드를 충실히 따라야 하고, CSP는 두 결제사 SDK와 결제창 출처만 허용하며 결제창 복귀 주소의 결제 값은 읽은 즉시 주소창에서 지워야 하며(ADR-0044), 좌석맵 라우트의 엄격한 COOP/COEP 헤더가 결제 라우트에 간섭하지 않도록 아키텍처 격리를 확인해야 한다. 과금이 없는 결제 실패에는 무과금 안심 고지가 결합되어야 한다(결과 불명은 "중복 청구는 발생하지 않습니다"). 결제사 전환 뒤 다시 시도할 때는 다른 결제 대행사로 결제한다는 안내(CMP-027 `pg-switched`)를 보여야 한다. |
| 마이 티켓 월렛 (`SCR-013`) | 완전 오프라인 비행기 탑승 모드 환경에서도 모바일 단말기 로컬에서 Dynamic QR 코드가 정상 생성 및 갱신되는지 확인해야 한다. QR 이미지 대체 텍스트에 티켓 ID를 명시하고 PWA 홈 화면 추가 바로가기 안내를 제공해야 한다. |
| 중앙 관제 콘솔 (`SCR-029` ~ `SCR-032`) | 모든 모니터링 패널에 SLO 임계 기준선이 명시되어야 한다. 단일 위젯에서 예외가 발생하더라도 독립 Error Boundary를 통해 격리되어 나머지 위젯이 정상 렌더링되어야 한다. 운영 명령 하달 시 '사유 입력 → dry-run 시뮬레이션 → (위험 명령만) 재인증 → (2인 명령만) 2인 승인과 승인자 재인증 → 전파 ack' 파이프라인이 명령 종류대로 구현되어야 한다(control-tower §4). 임계 기준선 초과 상태는 색상뿐만 아니라 명확한 텍스트로도 표현되어야 한다. |
| 게이트 스캐너 (`SCR-034`) | 검표 판정 결과가 화면 전체 면적의 50% 이상을 차지하는 대형 색상으로 노출되어야 하며, 야외 직사광선 환경에서도 식별 가능한 최고 명도 대비를 확보해야 한다. 입장 거부 사유는 직관적인 단일 텍스트 행으로 제한하고 기기 햅틱 진동 및 비프음을 병행해야 한다. 관람객의 성명 및 연락처는 일체 노출하지 않아야 한다. |
| 현장 스태프 기기 승인 (`SCR-036`) | 현장 단말기 승인을 위한 8자 확인 코드(4자씩 하이픈)가 일회용 QR과 함께 대형 텍스트로 노출되고 스크린리더로 온전히 읽혀야 한다. 단말기 고유 명칭이 표시되어야 하며 유효시간 만료 시 새 코드로 자동 갱신되어야 한다. 아이디·비밀번호 칸이 없고 '아이디·비밀번호 없이 휴대폰으로 승인합니다' 설명과 세 단계 안내, 상태(대기·승인 거부·만료·등록 안 된 기기)가 글자로 보여야 한다(ADR-0066). |
| 초대 수락·스캐너 승인 (`SCR-050`, `SCR-051`) | 초대 수락은 수집·이용 동의와 파트너 제공 동의가 따로 체크되어야 수락 버튼이 켜지고, 수집·이용 동의 카드는 고지 네 항목(개인정보 보호법 §15②), 파트너 제공 동의 카드는 다섯 항목(§17②)을 보여야 한다. 스캐너 승인은 확인 코드를 스캐너 화면과 대조하라는 문구와 기기 이름이 승인 버튼보다 먼저 보여야 한다(ADR-0051). |
| 근무 준비·현장 관리 (`SCR-033`, `SCR-052`) | 기기 배치가 없으면 스캔으로 넘어가지 않아야 하고, 퇴장 모드는 색과 글자로 함께 구분되어야 한다. 현장 관리의 오프라인 상태에서는 배치 변경·부스 허용 버튼이 비활성이어야 한다. |
| 예매 취소 및 회원 탈퇴 (`SCR-038`, `SCR-017`) | 공정거래위원회 기준에 따른 잔여일수별 공제율 근거와 환급 예상액이 최종 실행 버튼보다 먼저 시각적 및 청각적으로 제시되어야 한다. 실행 버튼 레이블에 구체적 환급 금액이 명시되어야 하며, 입장 개시 후 취소 신청 시 입장 기록 마감(offline-gate §7.3) 뒤 환급 확정 안내를 고지해야 한다. |
| 판매자 정보·중개자 고지 (`SCR-001`, `SCR-002`, `SCR-011`, `SCR-012`, `SCR-013`, `SCR-015`, `SCR-055`) | 청약 확인 단계와 예매 확인서의 고지 글씨가 판매자 표시와 같거나 커야 한다(토큰 고정). 고지가 약관 링크나 하단 작은 글씨로만 처리되지 않았는지 확인한다. 공연 상세는 본문의 판매자 줄('판매자: {상호}'와 중개자 고지 한 줄)이 늘 보이고 7항목은 [판매자 정보] 모달에서 키보드로 열려야 하며, 결제 직전(`SCR-011`) 본문에는 7항목 정보 상자가 접히지 않고 늘 보여야 한다(청약 전 제공, 전자상거래법 §20②, ADR-0063). |
| 양도 받기·소명·배상 계좌 (`SCR-041`~`SCR-043`) | 받는 사람 화면에 결제 금액과 결제자 연락처가 보이지 않아야 한다. '결제자만 취소·환불' 고지가 수락 버튼보다 먼저 보이고 읽혀야 한다. 계좌번호 입력값이 브라우저 저장소, 분석 스크립트, URL에 남지 않아야 한다. |
| CS 처리함·승인 업무·회차 취소·판매 승인·정산 지급 (`SCR-045`~`SCR-049`) | 요청자 본인 화면에서 승인 버튼이 비활성화되고 이유가 읽혀야 한다. 기한 배지가 시간과 영업일 단위를 텍스트로 구분해야 한다. 승인 업무 실행(`SCR-046`)과 회차 취소 확정(`SCR-047`) 직전 재인증과 '되돌릴 수 없음' 확인이 있어야 한다. 가려진 개인정보는 열람 사유를 입력한 뒤에만 보여야 한다. |
| 콘솔의 휴대폰·태블릿 배치 (파트너·관제 콘솔 전 화면) | 휴대폰 배치에서 `design/d5 §3.9` 범위 밖의 일이 숨겨지지 않고 '태블릿이나 데스크톱에서 합니다' 안내 카드와 [ 링크 복사 ]로 바뀌어야 한다. 휴대폰 승인자 화면은 요청자·사유·파라미터·dry-run 결과를 줄이지 않고 보이고, 승인 버튼 바로 위에 승인 대상을 한 줄로 다시 적어야 한다. 휴대폰에서는 개인정보 가림 해제 버튼이 없어야 한다. 태블릿에서는 데스크톱과 같은 일을 모두 할 수 있어야 한다. 메뉴 서랍은 포커스를 가두고 닫으면 메뉴 버튼으로 초점이 돌아가야 한다(ADR-0061). |
| 계좌 입력 화면 (`SCR-020`, `SCR-021`, `SCR-038`, `SCR-043`, `SCR-060`) | 계좌번호는 저장하지 않고 결제사 요청에 바로 넘기며, 이후에는 은행과 끝 4자리만 보여야 한다. 입력값이 브라우저 저장소, 분석 스크립트, URL에 남지 않아야 한다(`design/d5-screen-blueprint.md` §3.7). |
| 외부 분석 스크립트 금지 화면 (`design/d5-screen-blueprint.md` §3.8) | 결제(`SCR-011`), 양도 받기, 취소, 계좌 입력, 소명, 문의, 초대 수락(`SCR-050`), 스캐너 승인(`SCR-051`), 내 현장 배정(`SCR-061`), 스캐너 화면 전부에 외부 분석 스크립트가 실리지 않아야 한다(asvs 14.2.3). |
| 폼 입력 전체 공통 | 모든 입력 필드에 고유 ID를 부여하여 레이블 및 `aria-describedby` 힌트/에러와 엄격히 결합해야 한다. 제출 실패 시 최상단 에러 요약 컴포넌트를 띄우고 첫 오류 필드로 포커스를 자동 이동해야 한다. 법정 필수 항목은 텍스트로 "(필수)"를 명시하고 적절한 `inputmode` 및 `autocomplete` 속성을 선언해야 한다. |
| 앱 셸·전역 화면 (CMP-065, SCR-059) | 네 앱 모두 로그인한 화면이면 어디서나 로그아웃에 닿아야 한다(ASVS 7.4.4). 오류 화면은 원인 내부 정보를 보이지 않아야 한다. 대기실(`SCR-007`·`SCR-008`·`SCR-018`)의 집중 셸은 대기실 번들 예산 안이어야 한다. 세션 종료 사유별 문구가 있어야 한다(`design/d5-screen-blueprint.md` §3). 파트너·관제 셸은 유휴 만료 2분 전 [가정] 경고(`role="alertdialog"`, [ 계속 사용 ])가 있어야 하고, 유휴로 세션이 끝나면 다시 로그인한 뒤 원래 화면으로 돌아와야 한다(ADR-0060 결정 7, POL-019). |
| 재인증·알림 권한 (CMP-064, CMP-068) | 재인증 토큰이 5분을 넘으면 다시 요청해야 하고, 소셜 로그인 버튼은 제공자 가이드(색·문구·같은 비중)를 따라야 한다. 웹 푸시 권한은 사용자가 버튼을 누른 뒤에만 요청해야 한다. |
| 주문 내역·고객센터·약관 (`SCR-055`~`SCR-057`) | 예매 상세에 '공연일 10일 이내 취소 시 기준에 따른 공제 후 환불'이 보이고 예매 확인서의 고지 글씨가 판매자 표시와 같거나 커야 한다. 분쟁 접수 뒤 3·10영업일 기한이 글자로 보여야 한다. 문의 화면은 첨부를 받지 않고 외부 분석 스크립트를 싣지 않아야 한다. |
| 새 소비자·파트너 화면 (`SCR-054`, `SCR-058`, `SCR-061`, `SCR-062`, `SCR-063`) | 관심 공연·알림 화면은 오프라인일 때 저장 대기와 연결 뒤 저장을 글자로 알려야 한다(FR-019). 외부 브라우저 전환 안내는 Android·iOS·Windows·Mac의 문구를 나누고 Edge를 빠뜨리지 않아야 한다(NFR-019, ADR-0063). 내 현장 배정은 스태프 셸이고 외부 분석 스크립트를 싣지 않아야 한다. 파트너 공연 목록·개요는 판매 승인 상태·반려 사유와 재승인 배너를 글자로 보여야 한다(FR-052). |
| 새 관리 화면 (`SCR-064`~`SCR-068`) | 가린 개인정보는 열람 사유를 입력한 뒤에만 보이고 열람이 접속기록에 남아야 한다. 권한 밖 버튼은 비활성 이유를 읽어야 한다. 봇 표본 검토 화면에 개인 식별 정보와 판정 가중치가 없어야 한다. 홈 구성 탭(`SCR-068`)은 판매 승인된 공연만 고를 수 있고, 배너 대체 텍스트가 비면 게시가 막히며, 게시·변경이 감사 로그에 남아야 한다(`POL-043`). |
| 표시 가격 (`SCR-001`, `SCR-003`, `SCR-015`) | 가격이 처음 보이는 화면(검색 결과·상품 목록·홈 카드와 굿즈 띠 배너)에 필수 비용을 포함한 총금액이 보여야 한다. 택배만 되는 굿즈는 '배송비 포함 ₩총액'이 앞에 오고 상품가·배송비가 작게, 현장 수령(무료)도 되는 굿즈는 상품가와 '택배 배송비 ₩n 별도(현장 수령 무료)'가 함께 보여야 한다. 티켓은 예매 수수료가 없어 카드 가격이 곧 총금액이다(전자상거래법 §21의2①1호, 전자상거래 소비자보호 지침 12. 가·나, `POL-016`·`POL-032`, ADR-0063). |
| 홈 (`SCR-001`) | NOL의 로고·이미지·문구·배지 이름·아이콘 그림·색 사용이 0건이고 시각은 피켓 토큰이어야 한다(`design/d1 §3`, ADR-0063). 자동으로 넘어가는 배너에 [일시정지]가 있고 포커스·마우스가 올라가면 멈추며 모션 축소면 자동으로 넘기지 않아야 한다(WCAG 2.2.2). 섹션 하나가 비면 그 섹션만 숨겨야 한다. 장르별 랭킹에 기준 글('어제 판매 매수 기준, 매일 오전 10시 갱신')이 있고, '지금 판매 중'의 남은 기간에 깜빡임·재촉 배지가 없어야 한다. 비로그인이면 찜한 공연 줄이 없어야 한다. |
| 공연 상세·관람 후기 (`SCR-002`, `SCR-016`) | 상세 이미지마다 대체 텍스트가 있고 이미지에만 있는 정보가 설명 글에도 있어야 한다(WCAG 1.4.5). [상세정보 더보기]는 `aria-expanded`이고 섹션 바로가기는 `nav`와 `aria-current="location"`이어야 한다. [후기 쓰기]는 자격이 없어도 숨기지 않고 누르면 이유를 보여야 한다. 후기 작성자는 닉네임 첫 글자와 '**', 관람 회차로만 보이고 이메일·전화번호·실명이 없어야 한다. 별점은 별 아이콘과 '5점 만점에 N점' 글자를 함께 둬야 한다. 모달은 제목 연결·포커스 가둠·Esc·뒤로 가기 닫기를 지키고 모달 위에 모달을 겹치지 않아야 한다(`POL-042`, ADR-0063). 후기 사진마다 대체 텍스트가 있고 QR이 찍힌 사진은 올리기에서 거절해야 하며, 신고 모달과 보내기 전 확인 모달은 같은 자리에서 바꿔 열어야 한다(겹치지 않음, `POL-044`, ADR-0066). 공연 카드의 아이콘 버튼(찜·오픈 알림 종)은 44px·`aria-label`이고 종 토글은 `aria-pressed`여야 한다(ADR-0066). |
| 검색 (`SCR-003`) | 소비자 웹의 검색 입력이 전역 머리 검색창 하나뿐이어야 한다(화면 안 두 번째 입력 0개). 연관 검색어 창은 ARIA combobox(listbox·option·`aria-activedescendant`)이고 ↑↓·Enter·Esc로 조작되며, 페이지 번호의 현재 페이지에 `aria-current="page"`가 있어야 한다(ADR-0063). |
| 본인확인 흐름 (`SCR-006`) | 본인확인기관 창은 사용자가 버튼을 누른 동작 안에서만 열리고 서버 응답 뒤 자동으로 열리지 않아야 한다. 결과(완료·창 닫음·기관 장애·다른 계정·만 14세 미만·부스 대조 불일치·동의 없음·팝업 차단)가 부르는 화면 위 대화상자로 보이고, 복귀 화면 `/verify/return`은 진행 표시만 보인 뒤 `next` 화면으로 돌아가야 한다(ADR-0063). |
| 좌석맵 에디터 (`SCR-022`) | 배치 층과 좌석 층을 오갈 수 있고 미리보기가 팬 화면처럼 전체 → 확대로 보여야 한다. 도형 꼭짓점과 좌석 위치를 끌지 않고 숫자 입력으로도 바꿀 수 있어야 한다(WCAG 2.5.7). 구역 도형 밖 좌석은 경고하고 저장은 막지 않아야 한다(ADR-0063). 도구 막대 네 단계([① 배치 그리기] [② 좌석 채우기] [③ 좌석 다듬기] [미리보기])가 현재 단계를 알리고, 템플릿 고르기 대화상자와 좌석 겹침 경고(저장은 막지 않음)가 글자로 보여야 한다(ADR-0066). |

## 3. 핸드오프 산출물 요건

- 각 화면별 시안 링크(`design/d3-screens.md`의 '시안' 열). 지금은 `design/d5-screen-blueprint.md` 와이어프레임 절을 가리키고, 그림 시안이 생기면 같은 칸에 더한다.
- 지원해야 하는 5대 상태별 UI 디자인 프레임(기본, 로딩, 빈 화면, 에러, 권한 없음).
- 화면별 디자인 토큰 적용 매핑표 (어떤 시맨틱 토큰이 사용되었는지 명시).
- 인터랙션 및 모션 명세 노트 (적용된 `motion.duration` 및 `easing` 토큰명 기재).
- 웹 접근성 명세 노트 (키보드 탭 탐색 순서, WAI-ARIA 역할, 스크린리더 낭독 레이블).
- UI 텍스트 카피 대조표 (용어 사전 및 법정 고지 문안과의 100% 일치성 검증 결과).
