# D3. 화면별 UI 명세

- **독자와 용도**: 제품 디자이너가 프로토타입 시안을 만들고, 프론트엔드 엔지니어가 화면 컴포넌트를 조립하고 구현할 때 보는 상세 명세다. 화면의 비즈니스 목적, 주요 요소, 이벤트 동작, 고지 문구는 기획 문서(`planning/04-ia-flows-screens.md`)가 하나뿐인 원본이다. 이 문서는 각 화면을 어떤 그리드 레이아웃, 디자인 시스템 컴포넌트(CMP), UI 상태, 웹 접근성 규칙으로 보여 줄지를 정한다.

## 0. 공통 규칙

- **반응형 그리드 시스템** (`ADR-0040`): 모바일은 4열 그리드(여백 16px = `space.semantic.global-gutter`), 태블릿은 8열 그리드(거터 24px), 데스크톱은 12열 그리드(거터 24px, 여백 32px)를 쓴다. 최대 콘텐츠 너비는 소비자 웹 1040px, 공연 탐색과 좌석맵 캔버스 1280px, 홈(SCR-001) 본문 1240px다(ADR-0063, 토큰 `layout.home-content-max-width`). 파트너 콘솔은 SEED 대시보드 중밀도(12열, 1040px)를 따르고, 관제 콘솔은 고밀도 풀스크린(100% 폭)을 쓴다. 두 콘솔의 휴대폰(본문 1열)·태블릿(8열) 배치와 휴대폰에서 하는 일의 범위는 `design/d5 §3.9`를 따른다(`ADR-0061`). 아래 표의 '브레이크포인트' 열에는 화면마다 다른 점만 적는다.
- **키보드 포커스 탐색 순서**: 화면에 보이는 순서와 DOM 구조 순서를 엄격히 맞춘다. 모달 다이얼로그에는 포커스 트랩(Focus Trap)을 건다. 좌석맵 화면에서는 Canvas 요소 자체를 `aria-hidden="true"`로 숨긴다. 대신 화면 낭독기(화면의 글자를 소리로 읽어 주는 프로그램)를 위한 대안 컴포넌트인 SeatList가 같은 탭 순서 자리에 오도록 배치한다.
- **키보드 인터랙션 표준**: 화면 안의 모든 조작 요소는 Tab, Enter, Space, 방향키, Esc 키만으로 조작할 수 있어야 한다. 단축키는 중앙 관제 콘솔에서만 제공한다(예: `?` 키를 누르면 도움말 모달을 연다) [가정].
- **모션 트랜지션 가이드**: 모든 애니메이션은 디자인 토큰(색·글자 크기·간격 같은 디자인 값에 이름을 붙여 정해 둔 것)의 `motion.duration`과 `easing` 토큰만 쓴다. OS에서 움직임 축소(`prefers-reduced-motion: reduce`) 설정이 감지되면, 모든 위치 이동·크기 변형 애니메이션을 부드러운 불투명도(opacity) 전환으로 자동으로 바꾼다.
- **프로토타입 시안 참조**: 각 명세 표의 '시안' 열은 전체 화면설계서 `design/d5-screen-blueprint.md`의 와이어프레임 절을 가리킨다. 와이어프레임은 배치·화면 이동·상태 전환을 정하고, 그림 시안(디자인 캔버스)은 따로 있고, 공유 주소를 정하면 같은 칸에 링크를 더한다. 상태 이름은 이 문서와 d5가 같은 것을 쓰고, 응답 코드별 문구는 d5 §9.2에 모았다. 브랜드 방향성은 `design/d1 §3`이 정한다(2026-10-13, ADR-0059).
