# @peaket/ds

PEAKET 디자인 시스템 패키지다. 디자인 토큰(`docs/design/tokens.json`)에서 만든 CSS 변수·Tailwind 4 테마·TS 상수, 디자인 캔버스의 키트 CSS(`src/styles/kit.css`, 캔버스 `peaket.css`를 옮긴 것), 공용 부품(CMP)과 퍼블리싱 도우미를 둔다. 게시하지 않고 앱이 `workspace:`로 잇는다(ADR-0165). 정본은 docs/design/d2-design-system.md다.

- 색 모드: `@peaket/ds/color-mode-script`의 `colorModeScript(mode)`가 붙인 SEED 판의 색 모드 스크립트 글자를 준다. 앱은 그것을 같은 출처 파일로 싣는다(소비자 웹 `public/seed-color-mode.js`, `pnpm --filter @peaket/web color-mode`). 키트 다크 변수는 `.pk.dark`와 운영체제 다크(`:root[data-seed-color-mode="system"][data-seed-user-color-scheme="dark"] .pk`)에 함께 걸린다(HOT-291).
- 토큰 빌드: `pnpm --filter @peaket/ds tokens`(만들기) · `tokens:check`(tokens.json과 다르면 실패). `src/gen/`의 다섯 파일 — `tokens.css`(--peaket-* 변수), `theme.css`(Tailwind 테마), `tokens.ts`(Canvas용 TS 상수), `kit-tokens.css`(키트 변수 `.pk`·`.pk.dark`), `queue-room-tokens.css`(대기실 경량 CSS용 같은 블록) — 은 손으로 고치지 않는다.
- 제3자 고지: `THIRD-PARTY-NOTICES.txt`는 붙인 SEED 판의 NOTICE·LICENSE를 그대로 옮긴 고지 파일이다(ADR-0040 결정 7). `notices`로 만들고 `notices:check`(시험에도 있다)로 판과 같은지 본다. SEED 판을 올리면 다시 만든다. 앱 배포에 함께 싣는 일은 HOT-390이 한다.
- 토큰 검사: `pnpm --filter @peaket/ds test`가 생성물 차이(`tokens:check`), 토큰 형식 검사(FE-T45: DTCG 이름·형식·별칭·확장 키, SEED 대응 이름과 중단점, SEED 색 모드 선택자), d2 §5 대비표 계산(FE-T44)을 돈다. 문제 목록만 보려면 `tokens:lint`. 규칙은 `scripts/token-rules.mjs`, 정본 읽기는 `scripts/token-canon.mjs`다.
- 스타일 파일: `styles/index.css`가 SEED base 층 판(`@seed-design/css/base.layered.css`, 스스로 `seed-base` 층에 든다) → tokens.css → theme.css → kit-tokens.css → kit.css → ds.css 순서로 싣는다. 피켓 토큰이 `components` 층이라 같은 이름의 `--seed-*` 변수를 덮는다. 붙인 SEED 판은 `@seed-design/css` 3.1.0이다(BAS-170). `ds.css`는 키트에 없는 ds 보조 규칙(`pk-skip-link` 등)이다. 대기실 경량 페이지는 `@peaket/ds/queue-room.css` 하나만 싣는다(키트 부분집합, 맨 앞에서 queue-room-tokens.css를 싣는다).

## CSS 싣기

앱이 가장 먼저 싣는 CSS 파일에 이 순서 그대로 둔다. 층 순서 선언이 맨 앞이어야 한다(d2 §1 'CSS 층 순서').

```css
@layer theme, base, seed-base, seed-components, components, utilities;
@import "tailwindcss";
@import "@peaket/ds/styles.css";
@source "../../../packages/ds/src"; /* 앱 CSS 파일 위치에서 packages/ds/src까지의 상대 경로 */
```

- Vite·webpack 앱의 진입점(`main.tsx`)은 이 첫 CSS를 다른 무엇보다 먼저 가져온다. 부품을 먼저 가져오면 그 부품 CSS의 층이 가장 약한 층이 된다(FE-T36 PoC).
- Next.js 앱은 `next.config.ts`의 `turbopack.resolveAlias`에 `seedLayeredAlias(import.meta.dirname)`(`@peaket/ds/seed-layered-alias`)를 준다. SEED recipe를 층 판으로 돌리는 표다(Turbopack은 내보내기 조건 `seed-layered`를 고르지 못한다). Vite는 `resolve.conditions`, webpack은 `resolve.conditionNames`에 `seed-layered`를 넣는다.
- 화면의 맨 바깥(`<body>`)에 `class="pk"`를 붙인다. 다크는 `class="pk dark"`다. 키트의 모든 색 변수(`--surface`, `--text`, `--primary` …)와 바탕 정리 규칙은 `.pk` 아래에서만 돈다.
- 키트 클래스(버튼 `btn btn-primary`, 카드 `card`, 배지 `badge badge-success`, 칩 `chip`, 입력 `input`, 표 `table`, 탭 `tabs`, 배너 `banner`, 셸 `wh`·`ps`·`cs`·`ss`, 아이콘 `ic ic-<이름>`, 배치 도우미 `row`·`col`·`grow`·`between`·`center`·`wrap`, 글자 `t-xs`~`t-display`·`fw-m`·`fw-b`·`muted`·`num`·`ellipsis`, `sr-only`, 뼈대 `skel` 등)는 디자인 캔버스 보드와 이름이 같다. 보드를 옮길 때 클래스를 그대로 쓴다. 전체 목록은 `src/styles/kit.css`의 절 제목(1~21절)을 본다.
- 색은 키트의 의미 변수(`var(--primary)` 등)나 Tailwind 테마 색만 쓴다. 원시 색(hex)은 쓰지 않는다(포스터 그림·제공자 버튼만 키트가 예외로 둔다).
- Tailwind 유틸은 반응형 배치(`md:`·`lg:`·`xl:` — 중단점은 SEED 값 768·1280·1440, `sm`은 480)와 키트에 없는 간격에 쓴다. SEED 부품 요소에는 Tailwind 유틸을 겹치지 않는다(d2 §1의 Turbopack 대비책).

## Storybook(부품 이야기, BAS-180)

- Storybook은 뿌리와 따로 둔 작업 공간 `tools/storybook`이다(자기 잠금 파일. 뿌리에 두면 Babel 7·semver 6이 화면 앱 의존성에 섞인다). 그 폴더에서 `pnpm install --frozen-lockfile` 뒤 `pnpm run dev`(개발 서버 6006) · `pnpm run build`(정적 빌드 `storybook-static/`, git에 넣지 않는다) · `pnpm run typecheck`(이야기 파일 타입 검사. ds의 tsc는 이야기 파일을 뺀다). 사용 통계 전송·새 판 확인·새 소식 알림은 끈다(`tools/storybook/.storybook/main.ts`). 개발 서버의 관리 화면은 새 소식 내용을 storybook.js.org에서 받아 올 수 있다. 운영 배포에는 올리지 않는다.
- 이야기는 부품 폴더의 `*.stories.tsx`에 상태마다 하나를 둔다(d4 #1·#13). 도구 막대의 '테마'로 라이트·다크를 고른다(`body.pk`·`body.pk.dark`, 주소에 `&globals=theme:dark`).
- 검사: 시각 회귀 FE-T40(`tools/web-checks/visual/ds-stories.spec.mjs`, 기준 이미지는 `node lib/docker.mjs visual --update-snapshots`), 접근성 FE-T18(모든 이야기 axe, `tools/web-checks/ds/a11y.spec.mjs`, Storybook 화면에서는 `addon-a11y` 패널), 동작(`tools/web-checks/ds/behavior.spec.mjs`). 컨테이너에서 `node lib/docker.mjs ds`.
- 새 부품이나 상태를 더하면 이야기를 더하고 기준 이미지를 다시 만든다. 부품 속을 바꿀 때는 바꾸기 전 구현으로 기준 이미지를 먼저 만든다(ADR-0192).

## SEED React를 쓰는 방식(ADR-0192)

- 모양은 캔버스 키트를 따르고, 속은 손으로 짠 동작보다 나은 것이 있는 부품만 SEED 동작 부품(모양 없는 headless 부품)으로 바꾼다. 지금은 Dialog·DangerConfirm이 `@seed-design/react-dialog` 2.0.2를 쓴다(바깥 내용 숨기기, 초점 가두기, 겹친 층 닫기 차례, 스크롤 잠금).
- 판은 출처 증명 있는 것만 받는다: `react-dialog`는 정확한 판 2.0.2, 그것이 요구하는 `react-dismissible-layer`는 뿌리 `pnpm-workspace.yaml`의 `overrides`로 1.0.1이다(docs/devops.md §4.4 예외 표, ADR-0191). 판을 올릴 때 그 표를 다시 본다.
- 스타일 부품 `@seed-design/react`는 아직 붙이지 않았다. 처음 붙이는 단계는 ADR-0192 결정 5를 먼저 한다.

## 퍼블리싱 도우미(`@peaket/ds/Preview`)

```tsx
import { resolvePreviewState, resolvePreviewTheme, StateSwitcher, PreviewCatalog } from '@peaket/ds/Preview';

const STATES = ['기본', '로딩', '오프라인'] as const; // 캔버스 보드 data-props의 state 열거값 그대로
const state = resolvePreviewState(searchParams, STATES, '기본'); // Next.js 페이지의 searchParams, 또는 location.search
const theme = resolvePreviewTheme(searchParams); // ?theme=dark
<StateSwitcher path="/events/evt-1" states={STATES} current={state} keep={{ theme: theme === 'dark' ? 'dark' : undefined }} renderLink={(p) => <Link {...p} />} />
```

- `PreviewCatalog`는 `/preview` 화면 목록이다(`appName`, `screens: PreviewScreen[]`, `otherApps`, `renderLink`).
- 데이터를 잇는 단계에서 상태 고르기와 목업을 걷어 낸다(ADR-0170).

## 토큰 대조(2026-10-31)

키트 1절의 손으로 쓴 변수 값을 tokens.json과 하나씩 맞춰 보고, 대응표(`scripts/build-tokens.mjs`의 `KIT_VARS`, 키트 변수 → tokens.json 경로)로 만든 `gen/kit-tokens.css`로 바꿨다. kit.css 1절에는 변수 아닌 루트 속성만 남았다.

- 의미 색(surface·border·text·primary·link·success·warning·danger·info-subtle·focus-ring·seat·slo·heat)·그림자·모서리: 라이트·다크 모두 캔버스 값과 tokens.json 값이 같았다. 이름만 다른 것: `--seat-held` = `seat.held-by-others`, `--r-*` = `radius.*`.
- 의미 토큰이 없어 원시 팔레트 경로에 이은 것(값은 같음): `--fill-weak`·`--fill-weak-strong`·`--on-danger`·`--inverse`·`--on-inverse`·`--switch-off`.
- 처음에 tokens.json에 없던 `--scrim`(라이트 rgba(0,0,0,.48) · 다크 .64)과 `--heat-ink`(var(--text))는 소유자 결정(2026-10-31 '추천대로 진행')으로 의미 토큰 `scrim`(`#0000007a`·`#000000a3`, 8자리 16진수라 투명도가 0.2%p 안쪽으로 다름. SEED `bg.overlay`도 이 값으로 덮는다)과 `heat.ink`(`text`의 별칭)로 넣었다. 이제 키트 변수는 모두 tokens.json에서 나온다.
- 글꼴: 정본 순서 그대로이고 캔버스 전용 'Noto Sans KR'을 뺐다. 앱이 Pretendard를 자체 호스팅해야 Windows에서 캔버스와 비슷하게 보인다(d2 §1). 고정폭은 정본(`'JetBrains Mono', ui-monospace, monospace`)대로 SFMono-Regular·Menlo·Consolas 대체 글꼴이 빠졌다.

## 부품

부품은 `@peaket/ds/<폴더 이름>`으로 하나씩 가져온다(`exports`의 `"./*"`). 겉모양은 캔버스 키트 클래스와 디자인 시스템 보드(`Main.dc.html`)·화면 보드의 마크업을 그대로 낸다. 속을 SEED 동작 부품으로 바꾸는 것은 위 'SEED React를 쓰는 방식'대로 같은 API를 지키며 한다(ADR-0192).

- `'use client'` 부품(상태·이벤트를 가진 것)도 서버 컴포넌트에서 그릴 수 있지만, 함수 props(onClick 등)는 클라이언트 부품에서만 넘긴다. 나머지 부품은 서버 컴포넌트에서도 쓴다.
- 앱 라우터 링크(Next.js `Link`)는 `as`·`linkAs`로 넣는다(ButtonLink·Link·Chip·ListItem·TabNav·LogoWordmark). 셸·RoundPicker·AccountLinkPrompt·AlertPanel·ScannerStatusStrip은 링크를 그리는 함수 `renderLink`(`(p) => <Link {...p} />`, 없으면 `<a>`)로 받는다.
- 상태 미리보기용: 입력 부품의 `showFocus`(보드의 '포커스' 모양 `.is-focus`), Dialog·SearchField의 `open`, Countdown의 `running={false}`.
