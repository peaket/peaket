# deploy/data — 데이터 계층 기준

F-09-3(HOT-430)의 기계가 읽는 데이터 계층 기준과 생성 파일이다. **동결 로컬 트랙**이라 `develop`·`release/1.0.0`에 합치지 않고, 출시 환경 값·마이그레이션·릴리스 플래그에 넣지 않는다(ADR-0386 결정 4·5).

## 원천과 생성

- 원천: `deploy/data/peaket-data.yaml`
- 생성: `deploy/data/generated/` 아홉 파일. **손으로 고치지 않는다.**
  - `pgbouncer.ini`·`pgbouncer-userlist.template`
  - `schema-registry.properties`
  - `msk-configurations.yaml`
  - `redis-parameter-group.yaml`·`aurora-parameter-group.yaml`
  - `role-defaults.sql`
  - `topics.yaml`
  - `msk-iam.yaml`

```bash
node tools/ci/data-platform.mjs check   # 원천과 생성 파일 대조
node tools/ci/data-platform.mjs write   # 생성 파일을 원천에서 다시 쓴다
node tools/ci/data-platform.mjs render  # 화면에만 출력
```

`check`는 끝 코드 0(같음), 1(검사 위반·드리프트), 2(파일·인자 오류)다. 생성 파일 머리글은 `generated by tools/ci/data-platform.mjs --write (do not edit)`이다.

## 소비자와 경계

- **F-09-1(Terraform·스테이징 스택)**: 이 원천·생성 파일을 읽어 실제 Aurora·ElastiCache·MSK·Schema Registry를 프로비저닝한다. 이 기능은 AWS provider·스택을 만들지 않는다.
- **F-09-4(TLS·KMS·MSK 역할·비밀 교체)**: `msk-iam.yaml`의 역할 짝과 `pgbouncer.ini`의 TLS 설정을 실제 IAM·Secrets Manager·교체 함수로 옮긴다. 교체 함수 3종·KMS 키 정책·실제 MSK 재인증은 F-09-4 몫이다.
- **F-09-2(마이그레이션·역할)**: `role-defaults.sql`은 F-09-2가 서비스 역할을 만들고 GRANT한 **뒤에** 적용한다. 역할 생성·GRANT는 이 파일에 없다.
- **F-09-10(오토스케일)**: `aurora.pools.*.clientBudget.source`는 `F-09-10`이다. 이 기능은 DB 연결 예산 식(PgBouncer 복제 3 × `default_pool_size` + 예비)과 80% 상한만 검사하고, 파드 최대 복제 수(`maxPods`)를 고정하지 않는다.
