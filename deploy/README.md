# deploy/

배포 상태가 들어갈 자리다. 어느 환경에 무엇을 띄울지(공용 Helm 차트, 배포 단위 기본 값, 환경 값과 이미지 다이제스트, 클러스터 애드온, Kyverno 정책, ArgoCD 프로젝트, 변경 동결 달력)를 적는다. ArgoCD는 `develop` 가지의 이 폴더만 읽는다.

- 구조와 규칙: [docs/devops.md](../docs/devops.md) §5.2(구조)·§5.3(승격), 결정: ADR-0169
- 처음 채우는 작업: wbs 0.4.4. 지금 있는 것(2026-11-01, wbs 0.4.1, openspec 변경 `add-local-cluster-and-relay-deployment`):

| 자리 | 담는 것 |
| --- | --- |
| `charts/peaket-service/` | 공용 서비스 차트의 시작. 서비스 Deployment·Service(관리 포트의 준비 `/ready`·생존 `/livez`, 파드 이름 `PEAKET_POD`, 서비스 계정 토큰 없음, preStop 5초)와 서비스별 Outbox 릴레이 `<서비스>-outbox-relay` Deployment(복제 2, 같은 이미지·다른 시작 명령, 한 파드씩 바꾸기)와 그 Lease(차트가 미리 만든다) 하나의 읽기·고치기만 다루는 Role. 이미지 태그는 `PEAKET_ENV` local·ci에서만, 다른 환경은 다이제스트만 받는다. 켜서 쓰는 CPU HPA(`service.autoscaling`)와 앱·관리 포트 NetworkPolicy(`service.networkPolicy`)는 v0 배포에서 더했다(2026-11-03, wbs 1.1.4). 나가는 연결 허용 목록(`service.networkPolicy.egress`)은 값이 있을 때만 켜진다(추천 적용 2026-11-09, BUILD_ORDER PRF-192). `service.leaderLease`에 이름을 준 서비스만 그 Lease(차트가 미리 만든다)의 읽기·고치기 Role과 토큰을 받는다(추천 적용 2026-11-09, BUILD_ORDER PRF-202). 이름 목록도 받고(한 파드가 여러 Lease를 잡는 합본), 앱 포트 밖 포트(`service.extraPorts`)와 더 붙일 볼륨(`service.volumes`·`volumeMounts`, 릴레이는 `outboxRelay.volumes`·`volumeMounts`)을 받는다(BUILD_ORDER PRF-215). Rollout·PDB·KEDA ScaledObject·ExternalSecret·우선순위 클래스(`service.rollout`·`service.pdb`·`service.keda`·`externalSecret`·`service.priorityClassName`)는 BUILD_ORDER BAS-140(묶음 BAT-080)이 더했다: 기본값은 꺼짐이라 local·CI는 지금처럼 Deployment 하나를 낸다 |
| `workloads/<배포 단위>/values.yaml` | 배포 단위 기본 값(docs/devops.md §5.2). `payment-svc`는 결제사 출구(공인 주소 443)를 둔다(추천 적용 2026-11-09, BUILD_ORDER PRF-192). `queue-svc`(앱 8080·업무 gRPC 50051·제어 50061·지표 9464, 비밀은 `secretEnvFrom`)와 `purchase-svc`(입장 토큰 공개키 묶음 주소 `PEAKET_ADMISSION_JWKS_URL`·발급자 `PEAKET_ADMISSION_ISSUER`·좌석맵 판 폴더 `PEAKET_SEATMAP_DIR`)는 BUILD_ORDER BAT-057이 더했다(ADR-0288 결정 8). `identity-svc`(앱 8080·업무 gRPC 50051·관리 9464, 토큰 키 세 벌의 ExternalSecret·`identity-outbox-relay`)와 `realtime-gw`(앱 8080·관리 9464·복제 2·종료 유예 30초 [가정]·좌석 Redis ACL 비밀)는 BUILD_ORDER BAS-140(묶음 BAT-080)이 더했다. 정적 시험은 `node --test "deploy/workloads/test/*.test.mjs"`이고, 메시 생성기(`mesh-policies.mjs --check`)가 포트·업무 gRPC 주소를 원천과 견준다 |
| `gateways/` | 게이트웨이 다섯(gw-queue·gw-fan·gw-partner·gw-ops·gw-scanner)의 Gateway·HTTPRoute와 Envoy Gateway v1.10 정책(`ClientTrafficPolicy`·`SecurityPolicy`·`EnvoyExtensionPolicy`·`EnvoyProxy`), 공통 Lua(원본 확인·토큰 `typ`·gw-fan 구매 경로의 입장 토큰 확인, 키 목록은 ConfigMap `peaket-admission-jwks`를 프록시 환경 값으로, BAT-057), 손으로 쓴 YAML(docs/infra.md §4.1 'Envoy 게이트웨이의 첫 구현', BUILD_ORDER HOT-400). 정적 시험은 `node --test "deploy/gateways/test/*.test.mjs"`(CI 잡에 잇기는 BAT-055 구현 ⑤). 로컬 kind에는 `node tools/local/cluster.mjs gateways`가 백엔드만 대역으로 바꿔 올린다. API 호스트 다섯의 HTTPRoute는 생성 파일 `<게이트웨이>.routes.yaml`이다(손으로 고치지 않는다, BUILD_ORDER HOT-410) |
| `gateways/routes/` | API 호스트 HTTPRoute의 원천(적용 대상 아님). 규칙마다 맡는 경로(PathPrefix·Exact)만 적고, `node tools/ci/gateway-routes.mjs --write`가 `docs/api/openapi.yaml`과 이것으로 경로·메서드 단위 라우트(`gateways/<게이트웨이>.routes.yaml`)를 만든다. `--check`가 생성 대조를 한다(tools-check, docs/infra.md §4.1 '경로별 메서드 생성기'·'생성 대조') |
| `gateways/controller/` | Envoy Gateway 컨트롤러 설정 `envoy-gateway.yaml`(EnvoyGateway 객체 하나: Lua 확장, 전역 레이트 리밋 백엔드 Redis TLS, 레이트 리밋 서비스 복제 2·키 접두사 `rl:`). 적용 대상이 아니고 설치 파일의 설정 자리에 넣는다(docs/infra.md §4.1 '전역 레이트 리밋 걸기') |
| `platform/mesh/` | 서비스 메시(Istio 앰비언트, ADR-0082)의 매니페스트와 포트별 허용 정책(ADR-0285, BUILD_ORDER HOT-420). 원천 `port-allow.yaml`(포트별 허용 표의 기계 판, 적용 대상 아님)에서 `node tools/ci/mesh-policies.mjs --write`가 `policies.yaml`(운영 오버레이: 노드 프록시 인가 정책 `<워크로드>-ports`, 웨이포인트 `<워크로드>-waypoint`, 업무 gRPC Service `<워크로드>-grpc`, 웨이포인트 인가 정책 `<워크로드>-waypoint-callers`)과 `meshless-networkpolicies.yaml`(메시 없는 로컬·CI·데모의 NetworkPolicy)을 만든다(생성 파일, 손으로 고치지 않는다). 손으로 쓴 메시 바탕은 `namespaces.yaml`(앰비언트 등록 라벨)·`peer-authentication.yaml`(메시 전체 STRICT)·`istiod-values.yaml`(최소 TLS 1.3, 신뢰 도메인)·`cacerts.yaml`(중간 CA ExternalSecret, 값 없음)이다. 정적 시험은 `platform/mesh/test/`, kind 시험은 `node tools/local/cluster.mjs mesh-netpol` 뒤 `tools/local/e2e/mesh-netpol.e2e.mjs` |
| `projects/` | ArgoCD AppProject(가상 팀 아홉, 이름 `peaket-<팀>`)와 ApplicationSet(환경마다 하나, 이름 `peaket-<환경>`). ApplicationSet은 `develop`의 `deploy/envs/<환경>/*`를 Git 디렉터리 생성기로 읽고, `flags/`는 뺀다. 자동 동기화(prune·selfHeal), HTTPRoute `ignoreDifferences`(BUILD_ORDER BAS-140, 묶음 BAT-080, docs/devops.md §5.2, ADR-0169) |
| `policies/` | 클러스터 애드온 우선순위 클래스 `peaket-control`(100000 [가정])·`peaket-addon`(10000 [가정])과 `data`·`observability`의 ResourceQuota 틀. 할당량 숫자는 [가정]이고 Karpenter NodePool limits가 생기는 BAT-076에서 그 한도의 80%로 맞춘다(ADR-0078 결정 8) |
| `platform/observability/alerts/` | realtime-gw 경보 규칙 `realtime-gw.yaml`: `realtime_gw_degraded == 1`(0m, SEV2), 버퍼 1초 연결 비율 5% [가정]·30초(SEV2, G-06), Degraded가 아닐 때만 우는 묶음 대기 p99 150ms 경보(BAT-053이 넘긴 것, ADR-0298) |
| `envs/local/` | 로컬 kind 환경 값. v1 측정 무대의 세 릴리스(`v1-bundle.yaml`: 한 프로세스 합본 복제 3·Lease 둘·서비스별 환경 파일 Secret, `v1-purchase-relay.yaml`·`v1-payment-relay.yaml`: 같은 이미지의 릴레이, `node tools/local/cluster.mjs v1`, BUILD_ORDER PRF-215)와 v0 배포의 두 릴리스(`v0-monolith.yaml`: CPU HPA 1~4·70%, 앱 포트는 입구만 / `v0-gateway.yaml`: HTTPS 8443, IP 레이트 리밋, docs/infra.md §3 'v0 배포'), realtime-gw(`v1-realtime-gw.yaml`: 로컬 태그·복제 2, 좌석 Redis 주소·입장 토큰 공개키는 Secret v1-realtime-gw, `node tools/local/cluster.mjs realtime-gw --image <이름:태그>`, BUILD_ORDER BAS-140). 올리는 법은 `node tools/local/cluster.mjs v0` |
| `local/` | 로컬·CI kind 클러스터 정의(`kind.yaml`)와 클러스터 안의 시험용 저장소: Strimzi Kafka 3.9.1(`kafka.yaml`), PostgreSQL 18(`postgres.yaml`), 계정 없는 AWS 흉내 서버(`aws.yaml`), v0 배포의 Valkey 8.1(`valkey.yaml`)과 PG 시뮬레이터(`pg-simulator.yaml`). 로컬 관측 최소(Prometheus·Grafana, `observability.yaml`)와 템플릿 대시보드(`dashboards/<서비스>.json`, `tools/local/dashboards.mjs`가 만든다, docs/observability.md §3). 띄우는 법은 [tools/local/README.md](../tools/local/README.md) |

- 승격 PR 자동화는 `tools/ci/promote-plan.mjs`(후보 다이제스트 목록으로 `deploy/envs/<환경>/<서비스>.yaml`의 `image.digest`만 고치는 계획·검사·본문)와 `.github/workflows/promote.yml`(가지 `promote/<환경>-<태그>`, 데모 자동 병합·운영 사람 병합)이다. 같은 다이제스트만 쓰고 다시 빌드하지 않는다(docs/devops.md §5.3, ADR-0169, BUILD_ORDER BAS-140).
