# 위협 모델: 신뢰 경계별 STRIDE

- **독자와 용도**: 기능을 설계·구현하는 엔지니어와 보안 검토자가, 데이터가 신뢰 경계(믿는 정도가 다른 두 구역 사이의 선)를 넘는 곳마다 어떤 공격을 생각했고 어디서 막으며 무엇이 남는지 볼 때 참조한다. ASVS 추적 표(웹 보안 기준을 만드는 비영리 단체 OWASP의 웹 앱 보안 검증 항목 목록 ASVS 5.0.0을 기능별로 판정한 표, `docs/security/asvs/`)의 v5.0.0-13.1.4 '위협 모델에 따라' 판정이 이 문서를 근거로 삼는다.
- **범위**: [docs/infra.md](../infra.md) §2 데이터 흐름도의 경계 0~5와, 그 그림에 없는 전달 경로(코드가 저장소에서 운영 클러스터까지 가는 길, [docs/devops.md](../devops.md) §3~§5)와 사람의 운영 접근(관리 도구·쿠버네티스 API·SSM·긴급 접근, docs/devops.md §10)이다. 운영 설계 기준으로 쓰고, 포트폴리오 실행(로컬·CI·데모)이 다른 곳은 그 행에 적는다.
- **방법**: STRIDE로 경계마다 위협을 여섯 갈래로 나눠 빠진 것이 없는지 본다. S는 위장(남인 척하기), T는 변조(데이터를 몰래 바꾸기), R은 부인(한 일을 안 했다고 우기기), I는 정보 노출, D는 서비스 거부(서비스를 못 쓰게 만들기), E는 권한 상승(받지 않은 권한 얻기)이다. 표마다 '대응'에는 정본의 장치와 그것을 판정한 ASVS 행이나 절을, '남는 위험'에는 대응이 막지 못하는 것을 적는다. 막는 것과 남는 것을 함께 적고, 완전히 막는다고 쓰지 않는다.
- **문서 상태**: 2026-10-28에 처음 썼다(추천 적용 2026-10-28, 기술 검토 중간-065). 2026-10-29 상위 설계 문서와 대조해(review R-166) 빠진 외부 연동·엣지·관제 입구 행과 '사람의 운영 접근' 경계(§9, ADR-0147 결정 1)를 더했다. 2026-10-30에 봇 탐지 상세 설계(docs/features/bot-defense.md)가 만든 새 경계 넘기 둘(엣지가 붙인 ASN(인터넷 사업자·데이터센터마다 받은 네트워크 번호) 헤더와 ASN 분류표가 판정에 들어가는 길, 허니팟(사람에게 보이지 않게 숨긴 링크로 화면을 훑는 자동화 봇을 가려내는 장치)의 기록 입구)을 §3·§4에, 관리 계정 비밀번호의 유출 목록 대조(docs/security/auth-controls.md §4.3)를 §7에 더했다(추천 적용 2026-10-30). 새 기능의 ASVS 추적 표를 쓸 때(docs/architecture.md §8.2), 신뢰 경계나 외부 연동이 바뀌는 ADR을 쓸 때, 분기마다 [가정] 다시 본다. 경계를 새로 만들면 표를 더한다. 2026-10-31에 사후 포렌식의 부정 거래 조사 갈래(ADR-0171)가 만든 새 경계와 위협(원문 IP를 싣는 조사 사본이 Kafka로 가는 길, 조사 저장소와 조사 화면, 조사관 권한 남용, 승인자 우회, 두 갈래 연결, 증거 위·변조, 우선 구매 권리 ID, 양도 잠금 우회)을 §11에, 그 키를 §10에 더했다(추천 적용 2026-10-31, BUILD_ORDER FRN-040).

## 1. 경계 지도

| 경계 | 무엇이 있나 | 들어오는 것을 얼마나 믿나 |
| --- | --- | --- |
| 0. 사용자 기기 | 브라우저·PWA(설치형 앱처럼 쓰는 웹 앱), 게이트 스캐너 | 믿지 않는다. 모든 입력을 서버가 다시 검증한다 |
| 1. 엣지 | CDN(사용자 가까운 곳에 파일을 복사해 두고 대신 응답하는 전송망) CloudFront, WAF(악성 요청을 걸러 내는 웹 방화벽), 엣지 함수 | 바깥 요청을 받는 첫 관문. 캐시와 정적 응답만 스스로 판단한다 |
| 2. 게이트웨이 | 클라이언트 종류별 입구 서버 `gw-fan`·`gw-queue`·`gw-partner`·`gw-ops`·`gw-scanner` | 토큰을 검증한 요청만 안으로 넘긴다. 넘기는 내부 헤더는 게이트웨이가 다시 쓴다 |
| 3. 서비스 메시 | 업무 서비스와 작업자. 서비스 메시(서비스끼리의 통신을 앱 대신 처리하는 층, 운영 설계는 Istio 앰비언트)가 서로 인증서를 확인하는 암호화 통신 mTLS로 감싼다 | 메시 신원으로 '어느 서비스가 불렀나'를 안다. 사용자 권한은 앱이 따로 본다 |
| 4. 데이터 저장소 | Aurora(PostgreSQL), Redis 셋, Kafka(MSK), ClickHouse, 접속기록 저장소, 감사 로그 | 서비스별 사용자로만 붙는다. 저장은 KMS(암호 키를 보관하고 대신 써 주는 클라우드 서비스)로 암호화한다 |
| 5. 외부 | 결제사(토스페이먼츠·포트원), 본인확인 기관, 소셜 로그인 제공자, 사람 확인(Turnstile), 유출 비밀번호 목록(Have I Been Pwned의 범위 조회 `api.pwnedpasswords.com`, docs/security/auth-controls.md §4.3), 발송 대행, 브라우저 푸시 서비스(FCM·Mozilla·Apple·Microsoft의 웹 푸시 수신 서버, docs/features/notify.md §3.4), 송금 대행(배상 지급), 파트너 웹훅 수신처, 공연예술통합전산망(KOPIS), 공개 난수 비콘(drand), 공개 타임스탬프(OpenTimestamps), 오류 수집(Sentry 클라우드, EU), 신고기관·수사기관 | 계약한 상대지만 우리 통제 밖이다. 받은 결과는 서명이나 조회 API로 다시 확인한다 |
| 전달 경로 | GitHub Actions, 이미지 레지스트리(운영 ECR, 포트폴리오 GHCR), Sigstore, GitOps 저장소, ArgoCD, 클러스터 입장 정책 Kyverno | 서명과 출처 증명(어느 커밋을 어떤 빌드가 만들었는지 서명한 기록)이 맞는 산출물만 클러스터에 들인다 |
| 부정 거래 조사 갈래(경계 2~4를 가로지른다, §11) | 노드 에이전트 수집기의 조사 사본 갈래, Kafka 토픽 `investigation.requests`, 조사 적재 작업자 `inv-ingest`, ClickHouse 조사 저장소 `inv`, ops-svc 조사 모듈과 ops DB의 사건 표, 증거 버킷(S3), 관제 콘솔의 조사 화면(SCR-069~071) | 실명 계정·원문 IP가 한곳에 모이는 길이라 가장 좁게 믿는다. 쓰기와 읽기를 신원 하나씩으로 묶고, 사람은 지정 조사관만 읽으며, 연구 갈래(가명정보)와 잇지 않는다 |
| 사람의 운영 접근 | 관리 도구(Grafana·ArgoCD·Alertmanager), 쿠버네티스 API, SSM 세션 관리자(서버에 SSH 없이 붙는 AWS 기능), 긴급 접근 역할, 비상 접근 계정 | SSO(한 번 로그인으로 여러 도구에 들어가는 방식)와 MFA(두 가지 이상의 수단으로 확인하는 로그인)를 거친 사람만 들인다. 사람에게 늘 주어진 운영 쓰기 권한은 없다 |

## 2. 경계 0: 사용자 기기

| 갈래 | 위협 | 대응(위치) | 남는 위험 |
| --- | --- | --- | --- |
| S | 남의 세션 쿠키·입장 토큰을 훔쳐 그 사람인 척한다 | 쿠키는 `HttpOnly`·`Secure`·`SameSite=Strict`와 이름 접두사(docs/features/identity.md §3, asvs/auth.md V3·V7). 구매 세션 쓰기는 기기에서 만든 키로 요청에 서명해야 받는다(소지 증명, ADR-0050 결정 8). 입장 토큰은 처음 쓸 때 한 구매 세션에 묶인다(docs/api/guidelines.md §7) | 화면에 스크립트를 끼워 넣는 공격(XSS)이 성공하면, 키를 꺼내지는 못해도 그 화면 안에서 요청을 보낼 수는 있다. CSP(페이지가 실행할 스크립트의 출처를 정하는 브라우저 규칙)와 출력 규칙(docs/frontend.md §5.14)으로 줄인다 |
| S | 위조 스캐너가 입장을 처리한다 | 스캐너는 관리 기기에 등록한 기기 키의 DPoP 증명(요청마다 그 키로 서명, RFC 9449)과 그 키에 묶인 현장 스태프 토큰을 함께 쓴다. 하드웨어 키가 필요한 운영 환경은 mTLS 기기 인증서가 선택지다(ADR-0051, asvs/offline-gate.md, 기술 검토 중간-057) | 기기를 통째로 빼앗기면 기기가 폐기될 때까지 쓸 수 있다. 기기 키는 소프트웨어 키라 루팅 기기에서 옮길 수 있다. 배정 해제, 요청마다 하는 기기 상태 확인과 즉시 폐기로 줄인다 |
| T | 브라우저에 둔 대기표·순번·도착 시각을 고쳐 앞줄로 간다 | 순번과 대기표·도착 시각 쿠키는 서버나 엣지 함수가 서명하고(secrets-and-keys '대기표 서명 키'·'도착 시각 쿠키 서명 키'), 입장 확정 때 서버가 다시 확인한다(docs/features/queue-admission.md) | 정상 기기 여러 대로 줄을 여러 번 서는 것은 1인 1순번(ADR-0056)과 봇 방어가 줄일 뿐 모두 잡지는 못한다 |
| T | 스크립트 없이 끼워 넣은 HTML의 `style` 속성으로 결제 버튼 위에 가짜 요소를 겹쳐 화면을 속인다 | 출력 규칙과 서식 글 구조 문서(docs/frontend.md §5.14), Trusted Types(브라우저가 위험한 문자열을 화면 코드로 넣지 못하게 하는 규칙, 보고 모드), 스타일은 `style-src-attr`로 속성만 받는다(ADR-0111) | 스크립트 없는 화면 위장은 남는다. 바깥 주소로 보내는 것은 `img-src`·`font-src`가 막는다(docs/frontend.md §6.3) |
| T·E | 버전 없는 외부 스크립트(Turnstile, 토스페이먼츠 SDK v2)가 바뀌어 결제·사람 확인 화면에서 돈다 | 그 화면에만 늦게 싣고, nonce(응답마다 새로 만드는 한 번용 값)를 붙인 적재기로 싣는다(외부 스크립트 결정 표 docs/frontend.md §5.14, ASVS 3.6.1) | 무결성 해시(SRI)를 걸 수 없어 결제사·Cloudflare 쪽에서 바뀐 스크립트는 막지 못한다 |
| T·E | 다른 가상 팀이 따로 빌드·배포한 원격 위젯 코드(`peaket`의 `apps/widgets/<원격 이름>`, ADR-0165)가 관제 콘솔 문서 안에서 돈다 | `remotes.json`의 sha384 무결성 값, 계약 주판(`contractMajor`), 전역 값 금지, Trusted Types 정책 `peaket-remote`(docs/frontend.md §4.5·§5.14, ADR-0079 결정 16) | 서명된 판 안에 든 악성 코드는 코드 리뷰와 공급망 검사로만 줄인다 |
| R | 결제·양도·취소를 하고 나서 안 했다고 한다 | 법정 접속기록(로그인·진입·주문·결제, POL-025)과 주문·결제 원장, 동의 기록(docs/security/data-classification.md) | 기기를 함께 쓰는 가족처럼 같은 계정 안의 다른 사람은 가리지 못한다 |
| I | 공용 PC나 잃어버린 기기에서 개인 데이터가 보인다 | 로그아웃 정리 루틴과 탭 사이 알림(docs/frontend.md §5.14.4), 저장 허용 목록(§3.12), 월렛에는 표시 값만 둔다 | 로그아웃하지 않은 공용 PC와 월렛에 기본으로 남기는 입장 키(asvs/offline-gate.md 14.3.1 위험 수용) |
| D | 봇이 대기열·좌석 요청을 쏟아 사람이 못 들어온다 | 사람 확인과 사전 검증, 1인 1순번, 레이트 리밋, CDN 정적 대기 파일(ADR-0039, asvs/bot-defense.md V2.4) | 사람과 구별되지 않는 봇은 남는다. 오탐·미탐 비율은 측정으로만 안다. 출시 전 사람 오탐은 공개 자료 기준이고, 실제 사람 기준은 출시 뒤 첫 온세일의 그림자 실행과 마감 단계 R2(오픈 + 7일)의 표본 검토로 안다(ADR-0112·0174) |
| E | 브라우저에서 숨은 관리 기능이나 남의 주문 ID를 불러 권한 밖 데이터를 본다 | 서버가 역할·스코프와 소유자·테넌트를 확인한다(남의 ID를 넣어 보는 IDOR 막기, docs/security/authz-matrix.md §3·§5: 모든 작업의 허용 역할 칸 `x-peaket-roles`와 doc-check `roles` 검사, 테넌트 표의 행 보안 정책, 시험 AZ-T1~AZ-T14, asvs/auth.md V8, docs/architecture.md §8.1 A01) | 소유자 확인을 빠뜨린 새 API. 기능별 ASVS 표의 V8 행과 계약 시험으로 줄인다 |

## 3. 경계 1: 엣지

| 갈래 | 위협 | 대응(위치) | 남는 위험 |
| --- | --- | --- | --- |
| S | 원본 서버 주소로 바로 요청해 CDN·WAF를 건너뛴다 | 원본 NLB는 사설 서브넷의 CloudFront VPC 원본이라 공인 주소가 없고, CloudFront 서비스 관리 보안 그룹에서 오는 연결만 받으며, 게이트웨이가 원본 확인 헤더를 한 번 더 본다(ADR-0053 결정 9와 상태 줄, docs/infra.md §9, 추천 적용 2026-10-28, 기술 검토 낮음-009). 스캐너 경로는 CloudFront를 거치지 않고 기기 키 DPoP 증명으로 받는다(mTLS는 운영 선택지, 기술 검토 중간-057) | 원본 확인 헤더 값이 새면 우회할 수 있다. 값을 정기적으로 바꾼다(secrets-and-keys 'CloudFront 원본 확인 헤더 값') |
| S | DNS(도메인 이름을 IP 주소로 바꿔 주는 이름 풀이) 응답을 위조하거나 레코드를 가로채 사용자를 가짜 사이트로 보낸다 | AWS의 DNS 서비스 Route 53 공개 호스팅 영역에 두고, DNS 변경도 인프라를 코드로 적은 것(IaC)의 계획을 검토한 뒤 적용한다. HSTS(`includeSubDomains`)로 브라우저가 HTTPS로만 붙게 한다(docs/infra.md §9, ADR-0144 결정 8) | 이름 풀이 응답에 서명하는 DNSSEC는 v1에서 쓰지 않는다(받아들인 위험, ADR-0144 결정 8). 파트너 계약이나 보안 심사가 요구하면 다시 본다 |

| T | 공개 텔레메트리 경로 `/_t/*`(화면 성능 지표·CSP 위반 보고·오류)에 지어낸 값을 보낸다 | 본문 64KiB 상한, WAF의 IP당 속도 제한 [가정], 형식 검사, 표본. 브라우저 지표로는 사람을 호출하거나 자동 조치하지 않고, CSP 위반 급증은 SEV3(장애 심각도 등급. 숫자가 작을수록 심각하다) 티켓만 만든다(docs/observability.md §11) | 지어낸 값이 대시보드의 숫자를 흔들 수 있다. 상한·속도 제한·표본으로 줄일 뿐 막지는 못한다 |
| R | 엣지에서 막은 요청을 나중에 따질 근거가 없다 | WAF 로그를 서울 S3에 남긴다(docs/infra.md §9, docs/observability.md §9). CloudFront 표준 로그는 지금 쓰지 않는다(ADR-0127) | WAF 로그에는 원문 IP와 경로가 있어 개인정보로 다룬다(`Cookie`·`Authorization` 헤더는 가린다, ADR-0139, 시험 V-T42). 계정 ID는 없어 계정 단위로 잇지는 못한다 |
| I | 캐시된 대기 파일·셔플 결과에서 다른 사람의 정보가 보인다 | 대기 파일과 셔플 결과는 쿠키 없이 내고 사람을 알 수 없는 값만 싣는다(docs/api/guidelines.md §9) | 순번 구간 같은 공개 값으로 대기 규모는 알 수 있다(의도한 공개) |
| I | `sendBeacon`·CSP 보고가 같은 출처 쿠키를 함께 실어 텔레메트리 수집기로 간다 | 게이트웨이가 `/_t/*`에서 `Cookie`·`Authorization` 헤더를 지운 뒤 수집기로 넘긴다. 화면은 `fetch`에 `credentials: 'omit'`을 주어 보낸다(docs/observability.md §11, ADR-0076) | 게이트웨이 설정에서 헤더 지우기가 빠지면 쿠키 값이 수집기로 간다. 이 경로의 시험 ID는 아직 없다 |
| D | 대량 요청(DDoS)이나 캐시를 피하는 요청으로 원본을 쓰러뜨린다 | AWS Shield Standard, WAF 속도 규칙, 대기열 파일 캐시와 대체 원본(docs/infra.md §4.1·§9) | 캐시 키를 계속 바꾸는 요청은 원본까지 간다. 캐시 키에 넣는 값을 허용 목록으로 묶어 줄인다. 대기열 파일 배포(`queue-files`)에는 웹 ACL(배포에 붙이는 WAF 규칙 묶음)이 없어 한도 사용률 경보로만 본다(docs/infra.md §9 WAF 규칙표). CloudFront·DNS 전체 장애에는 넘어갈 다른 CDN이 없어 판매를 멈춘다(RB-40, ADR-0144 결정 10, 받아들인 위험) |
| S·T | 시청자가 `CloudFront-Viewer-ASN` 헤더를 꾸며 통신사 대역인 척하거나, ASN 분류표(ASN을 호스팅·프록시·그 밖으로 나눈 파일)를 바꿔 봇 판정의 네트워크 신호와 축소 운영의 IP 한도를 비켜 간다(새 경계 넘기: 엣지·S3가 만든 값이 판정에 들어간다) | ASN은 IP로 찾지 않고 CloudFront가 원본 요청 정책으로 붙인 헤더만 쓴다(대기열 API 배포와, 로그인 판정이 지나는 공연 페이지 배포의 앱 서버 로그인 경로, docs/infra.md §4.1, 로그인 경로는 추천 적용 2026-10-30). 게이트웨이는 원본 확인 헤더가 맞은 요청에서만 이 값을 넘긴다. 분류표는 trust-svc 작업 역할만 S3에 쓰고 trust-svc·queue-svc 파드는 읽기만 하며, 판 번호를 붙여 시작 때와 1시간 [가정]마다 읽는다. 읽지 못하거나 깨진 판이면 마지막으로 읽은 판을 쓰고, 7일 [가정] 넘게 새 판이 없으면 SEV3다(docs/features/bot-defense.md §3.1, B-T7, 추천 적용 2026-10-30) | 시청자가 보낸 같은 이름의 헤더를 CloudFront가 덮어쓰는지는 원문에서 찾지 못했다 [확인 필요]. 헤더가 없거나 분류표에 없는 ASN은 '그 밖'으로 보므로, 꾸민 헤더로 얻는 것은 호스팅 대역 신호를 지우는 데까지다. 그 신호는 가중합의 한 점수기일 뿐이고 사람 확인·본인확인·1인 1순번이 남는다 |
| E | 엣지 함수의 서명 키를 얻어 도착 시각·최초 방문 쿠키를 지어낸다 | 서명 키는 Secrets Manager에 두고 엣지 함수 배포에만 넣는다(secrets-and-keys) | 엣지 함수 코드나 키가 새면 그 회차의 줄 순서가 흔들린다. 키 교체 절차로 줄인다 |

## 4. 경계 2: 게이트웨이

| 갈래 | 위협 | 대응(위치) | 남는 위험 |
| --- | --- | --- | --- |
| S | 위조하거나 다른 대상의 토큰(JWT, 서명된 정보 묶음 형식의 토큰)을 낸다 | ES256 서명·만료·`typ`·`iss`·`aud`를 검증하고 게이트웨이마다 자기 대상의 키만 믿는다(ADR-0050 결정 9, docs/features/identity.md §3, asvs/auth.md V9) | 서명 키가 새면 위조 토큰이 통한다. 키는 KMS에 두고 교체 절차를 둔다(§10) |
| S | 다른 사이트에서 샌 아이디·비밀번호로 파트너·관제 로그인을 대입한다(크리덴셜 스터핑) | 웹 ACL의 IP 평판과 로그인 경로 속도 규칙, 출발지·계정 단위 계수와 사람 확인, 시간 잠금·보호 잠금과 비밀번호 연속 실패 누계 100, 유출 비밀번호 대조, TOTP 필수와 위험 작업의 패스키, 전체 실패율 경보(docs/security/auth-controls.md §2·§3, 추천 적용 2026-10-30) | IP를 계속 바꾸는 느린 대입과 실시간 중계 피싱은 남는다. 이메일을 아는 공격자는 계정을 잠가 새 로그인을 번거롭게 할 수 있다(auth-controls §3.7) |
| S | 허용 IP 밖에서 관제 콘솔·`ops-api`에 닿거나, `X-Forwarded-For`를 꾸며 허용 IP인 척한다 | 관제 배포에 연결한 웹 ACL의 맨 앞 규칙이 시청자 IP를 허용 목록으로 거르고, gw-ops가 원본 확인 헤더와, 사용자가 꾸민 헤더가 아니라 CloudFront가 붙인 시청자 주소 `CloudFront-Viewer-Address`로 한 번 더 본다. 운영자는 MFA와 재인증을 거친다(docs/infra.md §9, ADR-0144 결정 2, docs/features/control-tower.md C-T21) | 등록한 사내망·VPN(회사망으로 들어오는 암호화 터널) 출구가 뚫리면 허용 IP 검사는 통과한다. 관리 계정 MFA와 접속기록 점검으로 줄인다 |
| T | 바깥에서 `X-User-Id` 같은 내부 헤더나 추적 헤더(`traceparent`·`baggage`)를 넣어 신원이나 추적을 조작한다 | 게이트웨이가 바깥 헤더(`X-User-Id`·`X-User-Role`·`X-Tenant-Id` 등)를 지우고 토큰 값으로 다시 쓴다. 역할과 테넌트는 헤더로 넘기지 않고 서비스가 요청마다 identity에서 받으므로(ADR-0172) 꾸민 역할 헤더는 판정에 쓰이지 않는다(asvs/frontend.md·catalog-review.md 4.1.3, docs/security/authz-matrix.md §3.1, 시험 AZ-T4). 추적 문맥은 라우팅·추적 전에 지우고 새 trace를 시작한다(docs/observability.md §6 '신뢰 경계의 추적 문맥', 기술 검토 중간-066) | 게이트웨이 설정 실수로 헤더 정리가 빠지는 것. 정책 시험과 V-T31로 줄인다 |

| I | 오류 응답에 내부 정보(스택, 내부 주소)가 나온다 | 오류는 Problem 형식(RFC 9457)으로만 답하고 스택을 숨긴다(docs/api/guidelines.md §2, 각 ASVS 표 V16.5) | 업무 오류 문구가 존재 여부를 흘리는 경우(예: 가입 여부). 문구 키 검토로 줄인다 |
| D | 요청 폭주로 게이트웨이나 뒤쪽 서비스가 멈춘다 | 로컬 레이트 리밋, 동시 요청·대기 큐 상한과 503 + `Retry-After`, 경로별 시간 초과(ADR-0009, docs/architecture.md §5) | 정상 사용자도 503을 받는다. 대기열이 앞에서 들어오는 수를 줄인다. 계정 단위 전역 한도는 판정을 받지 못하면 열림(통과)이라, 그동안은 파드별 로컬 한도(파드 수 × 한도)만 남고 열림이 이어지면 SEV3로 알린다(docs/architecture.md §4 '전역 레이트 리밋 서비스'). gw-ops는 처음부터 로컬 한도만 쓴다(ADR-0145 결정 1) |
| S·D | 허니팟 기록 입구(소비자 웹과 같은 출처의 `/_t/` 아래 숨긴 링크 주소 → gw-fan → trust-svc 허니팟 기록 처리기)에 바깥 요청을 보낸다. 다른 사이트가 사용자 브라우저로 그 주소를 부르게 해 남에게 적중을 붙이거나, 주소를 퍼부어 trust-svc를 바쁘게 한다(새 경계 넘기: 브라우저 입력이 trust-svc에 바로 닿는다) | `Sec-Fetch-Site: same-origin`이고 미리 가져오기(`Sec-Purpose: prefetch`, `Next-Router-Prefetch`)가 아닌 요청만 적중으로 세고, 응답은 늘 204·빈 본문이다(ADR-0065 결정 9). gw-fan은 이 경로에서 팬 액세스 토큰이 있으면 검증해 pid(본인확인으로 만든 사람 식별값)만 내부 헤더로 넘기고, 쿠키 원문은 `/_t/*` 규칙대로 지운다. 토큰이 없거나 틀리면 로그인하지 않은 적중으로 지표만 센다. 적중은 차단이 아니라 다음 판정의 추가 검증이고, 사람 확인을 다시 통과하면 원래 순번으로 돌아간다(FR-020). `/_t/*`의 본문 상한·WAF IP당 속도 제한 [가정]을 같이 받는다(docs/features/bot-defense.md §7, 추천 적용 2026-10-30) | 같은 출처에 스크립트를 끼워 넣는 공격(XSS)이 성공하면 같은 출처 요청으로 그 사람에게 적중을 붙일 수 있다(CSP로 줄인다). 링크를 미리 여는 확장 프로그램 같은 사람 쪽 접촉이 섞여, 적중은 확정 라벨이 아니라 정밀도를 표본으로 잰다. `Sec-Fetch-*`를 보내지 않는 스크립트는 기록되지 않는다(Q-T40) |
| E | 다른 사이트가 사용자 몰래 쓰기 요청을 보내게 한다(CSRF) | 쿠키로 인증하는 쓰기 요청의 `Origin` 확인(없거나 다르면 403, Envoy Gateway 내장 CSRF 필터, ADR-0065 결정 5, 기술 검토 낮음-139, asvs 각 표 3.5.1) | 사전 요청 없는 T=0 두 호출은 본문의 사전 검증 토큰에 기댄다(docs/api/guidelines.md §9) |

## 5. 경계 3: 서비스 메시(내부)

| 갈래 | 위협 | 대응(위치) | 남는 위험 |
| --- | --- | --- | --- |
| S | 한 서비스가 다른 서비스인 척하거나, 게이트웨이를 건너뛰고 서비스 포트를 직접 부른다 | 메시 전체 STRICT mTLS(ADR-0082)와 포트별 허용 표: 업무 gRPC(서비스끼리 함수를 부르듯 호출하는 통신 방식)는 웨이포인트(서비스마다 둔 요청 단위 대리인)만, REST는 그 경로의 게이트웨이만, 내부 포트는 정한 신원만(docs/architecture.md §5, D-T36, 기술 검토 중간-071) | 포트폴리오 실행은 메시가 없어 신원 대신 파드 라벨로 거른다(NetworkPolicy, docs/verification.md §5.1) |
| T | 메시 안에서 운영 명령이나 원장을 몰래 바꾼다 | 운영 명령은 감사 체인(키를 건 해시 체인, 5분 앵커)과 공개 체크포인트로 고치면 드러나게 한다(ADR-0053·0075). 비상 런북은 서로 다른 두 운영자의 KMS 서명이 있어야 돈다. 예외로 판매 일시정지(명령 3)의 정지 묶음은 commander 한 명의 서명으로 돌고, 판매 재개 묶음과 비상 셔플(RB-35)은 서로 다른 commander 두 명이 서명한다(ADR-0053 결정 11, ADR-0095). | R | 운영자가 명령을 내리고 나서 부인한다 | 명령마다 요청자·승인자·재인증·서명이 감사 로그에 남는다(docs/features/control-tower.md, asvs/delivery.md V16) | 한 사람이 두 역할을 하는 1인 기간에는 2인 승인이 형식에 그친다(docs/devops.md §15) |
| I | 로그·요청 기록·Baggage(서비스 사이로 함께 전파하는 이름표 값)에 개인정보가 섞여 나간다 | 로그·추적에는 키를 건 가명 참조값만 쓴다(ADR-0053 결정 1, docs/observability.md §7). 외부 호출에는 Baggage·추적 헤더를 싣지 않는다(docs/observability.md §6) | 개발자가 새 필드에 원문을 넣는 실수. 공용 로거의 마스킹과 리뷰로 줄인다 |
| D | 한 서비스의 장애나 느림이 다른 서비스로 번진다 | 서킷 브레이커와 벌크헤드, 재시도 예산, 시간 초과 기본값(ADR-0009·0070, docs/architecture.md §5) | 공유 저장소(같은 Aurora 클러스터)가 느려지면 묶인 서비스가 함께 느려진다 |
| E | 탈취한 파드가 그 파드에 없는 권한(다른 서비스의 DB, AWS 자원)을 쓴다 | 서비스별 DB 사용자와 Pod Identity(파드에 주는 AWS 권한) 최소 권한(docs/security/secrets-and-keys.md 관리 규칙 1). 꾸민 이미지로 터질 수 있는 이미지 디코딩은 DB 자격 증명이 없는 `image-worker`에서만 한다(asvs/catalog-review.md 15.2.5, 기술 검토 중간-068) | 탈취한 파드는 자기 권한 안의 일은 할 수 있다. 권한을 서비스 단위로 더 쪼개지는 않는다 |

## 6. 경계 4: 데이터 저장소

WAF 로그는 보안 담당 역할만 읽고 그 읽기를 AWS 작업 기록 CloudTrail에 남긴다(docs/observability.md §9, ADR-0078 결정 6, 기술 검토 낮음-160) | 기본 조직 'PEAKET 관측'의 로그 저장소 Loki와 요청 기록 저장소 Tempo는 엔지니어 Editor(편집 역할) 모두가 본다. 로그·추적에 가명 참조값만 싣는 것으로 줄인다 |

| R | 결제사·파트너와 금액이나 지급을 두고 다툰다 | 결제·정산 원장과 대사, 지급 내역 조회(docs/features/settlement.md) | 결제사 화면에서 사람이 한 일(포트원 콘솔 지급)은 조회 주기만큼 늦게 안다(ADR-0108) |

| I | 오류 수집 도구(Sentry)로 가는 오류 사건에 개인정보가 섞여 나라 밖(EU)으로 간다 | 브라우저·서버 SDK의 수집 설정을 잠근다(사용자 IP·요청 본문 끔, 쿠키·헤더·쿼리 문자열 거름, 로그와 같은 마스킹, 사용자 식별값은 가명 `accountRef`만). 브라우저 오류는 같은 출처 터널 `/_t/err`로 보내 이용자 IP가 Sentry에 가지 않는다. 설정이 먹는지는 V-T39로 본다(data-classification '국외 이전 목록' 국-07, ADR-0067·0139) | 개발자가 새 맥락 필드에 원문을 넣는 실수. 공용 마스킹과 리뷰로 줄인다. | I | 관리 계정 비밀번호를 유출 목록과 대조하며 비밀번호 정보가 바깥(Have I Been Pwned)으로 간다 | 비밀번호를 UTF-8로 바꾼 SHA-1의 앞 5자만 `https://api.pwnedpasswords.com/range/{앞 5자}`로 보내고, 돌아온 목록은 identity-svc 안에서 맞댄다. `Add-Padding: true`로 응답을 800~1,000줄로 채워 응답 크기로 접두어를 짐작하지 못하게 한다. 비밀번호·SHA-1·앞 5자는 로그·트레이스에 남기지 않는다. 이 호출은 identity-svc에서만 나간다(docs/security/auth-controls.md §4.3 3·10, 추천 적용 2026-10-30) | 앞 5자(16진수)는 SHA-1 값을 16^5(약 105만) 칸 가운데 하나로 좁히는 정보다. 상대는 요청한 시각과 우리 쪽 나가는 주소(서버들이 공인 주소 하나를 나눠 쓰며 밖으로 나가는 NAT의 주소)를 안다. 상대 목록이 틀리면 정상 비밀번호를 막거나 샌 비밀번호를 받을 수 있다 |
| D | 유출 목록 API가 느리거나 멈춘다 | 비밀번호를 정할 때 2초 [가정] 안에 답이 없으면 그 비밀번호를 받지 않고 503과 `Retry-After`로 다시 하게 한다(초대 링크는 24시간이라 다시 할 시간이 있다). 로그인 때의 다시 보기는 건너뛰고 다음 로그인에 한다(auth-controls §4.3 9) | 멈춘 동안 새 관리 계정이 비밀번호를 정하지 못해 초대 수락이 늦어진다. 그동안 로그인한 계정의 유출 여부는 다음 확인까지 모른다 |
| E | 파트너가 등록한 웹훅 주소로 서버가 내부 주소를 부르게 한다(서버가 내부 주소로 요청을 보내게 만드는 공격 SSRF) | `https`·포트 443 [가정]만 등록받고(ADR-0050 결정 6), 연결할 때마다 이름을 해석한 IP가 공인 대역인지 다시 본다. 리디렉션은 어디로든 따르지 않는다(3xx는 실패, docs/api/guidelines.md §8, V-T34) | 막는 규칙에 빠진 주소 표기나 대역은 남는다. 세부 규칙과 시험은 웹훅 설계(docs/api/guidelines.md §8)를 따른다 |
| E | 웹 푸시 구독 주소로 발송 워커가 내부 주소나 엉뚱한 바깥 주소를 부르게 한다(SSRF). 구독 주소는 브라우저가 준 값이라 등록 요청을 꾸며 아무 주소나 넣을 수 있다(새 경계 넘기: 사용자가 준 주소로 서버가 나간다) | 등록할 때 `https`·포트 443이고 호스트가 푸시 서비스 허용 목록(FCM·Mozilla·Apple·Microsoft)에 있어야 받고, 아니면 422 `push-service-not-allowed`다. 구독 주소는 1,024자 [가정]까지이고 암호화 키의 길이도 본다. 보낼 때는 연결마다 이름을 해석한 IP가 공인 대역인지 다시 보고 그 IP로 바로 붙으며, 리디렉션은 따르지 않는다(파트너 웹훅과 같은 HTTP 클라이언트). 이 바깥 연결은 발송 워커 `core-notify-sender`만 하고, 그 파드만 '공인 주소의 TCP 443만' 나가는 정책을 받는다(docs/features/notify.md §3.4·§4.4·§13, docs/infra.md §9, V-T34, 추천 적용 2026-10-30) | 허용 목록에 든 푸시 서비스 호스트라면 그 호스트의 아무 경로로나 요청을 보낼 수 있다(그 서비스가 받는 요청만 된다). 목록의 일부 호스트(Microsoft, Samsung Internet·Whale)는 [확인 필요]라, 빠진 브라우저는 웹 푸시를 못 받고 이메일로 받는다. EKS 네트워크 정책이 `except`를 어떻게 다루는지는 확인 필요라 첫 방어선은 발송 클라이언트의 연결 시점 IP 검사다 |

## 9. 사람의 운영 접근

사람이 운영 환경에 닿는 길이다. 관리 도구(Grafana·ArgoCD·Alertmanager), 쿠버네티스 API, SSM 세션 관리자, 긴급 접근 역할, 비상 접근 계정을 한 경계로 묶는다. 산출물이 지나는 전달 경로(§8)와는 공격 면이 달라 표를 나눈다(추천 적용 2026-10-29, ADR-0147 결정 1). 통제의 정본은 docs/devops.md §10이다.

| 갈래 | 위협 | 대응(위치) | 남는 위험 |
| --- | --- | --- | --- |
| S | 훔친 SSO·VPN 자격으로 관리 도구에 들어온다 | 관리 도구는 VPN으로만 닿는 내부 로드 밸런서 뒤에 두고 HTTPS만 받으며, 로그인은 SSO와 MFA로 한다(docs/devops.md §10.1, ADR-0089). 관제 콘솔은 이 길이 아니라 관제 배포의 허용 IP와 gw-ops로 들어온다(§4 S) | MFA까지 뚫리면 그 역할의 권한 안에서는 움직일 수 있다. 역할을 가상 팀별 최소 권한으로 나누고(docs/devops.md §10.1 표) 접근 기록을 월 점검한다 |
| T | 사람이 운영 클러스터를 직접 바꾼다 | 사람에게 늘 주어진 쓰기 권한이 없고, 변경은 GitOps로만 한다. 긴급 접근 역할을 맡는 순간 CloudTrail 이벤트로 SEV2 경보가 나고 세션을 기록하며, 72시간 [가정] 안에 GitOps 상태를 실제와 맞춘다(docs/devops.md §10.2) | 긴급 접근 세션 안의 변경은 사후 검토로만 찾는다 |

| D | IAM Identity Center가 멈추거나 잘못 설정돼, 또는 VPN이 멈춰 사람이 운영에 들어오지 못한다 | VPN이 멈추면 SSM 세션 관리자의 원격 호스트 포트 포워딩으로 사설 엔드포인트에 닿는다. IAM Identity Center가 막히면 비상 접근 계정(IAM 사용자 둘, RB-37)을 쓴다(docs/devops.md §10.1·§10.2, ADR-0102) | 비상 접근 계정도 쓸 수 없으면(봉인물 분실 등) 들어오지 못한다. 분기마다 [가정] 로그인만 해 보는 점검으로 미리 찾는다(RB-37) |

## 11. 부정 거래 조사 갈래(추천 적용 2026-10-31, ADR-0171)

판매가 끝난 뒤 실제 기록으로 부정 예매(약관이 정한 매크로·대기열 우회·보안문자 우회·명의 대여·매수 제한 회피, POL-046)를 묶어 찾고, 사람이 소명과 2인 승인을 거쳐 취소·이용 제한을 정하는 길이다(docs/features/forensic-replay.md §6.7). 이 길은 실명 계정·주문·결제와 원문 IP를 한곳에 모으므로, 경계 2~4의 표와 따로 적는다. 연구 갈래(봇 판정 규칙을 개선하려고 가명 사건으로 가설을 세우고 다시 재생하며 분석하는 길, ADR-0173 결정 8, 추천 적용 2026-10-31)와 잇지 않는 것이 이 표 전체의 전제다(ADR-0171 결정 2).

### 11.1 조사 사본이 Kafka로 가는 길(새 경계 넘기)

노드 에이전트 수집기(노드마다 도는 로그 수집 프로그램)가 게이트웨이 접근 로그에서 회차 경로 줄만 골라, 원문 IP·ASN·TLS 지문 JA4·WAF 라벨·토큰의 계정 ID와 pid·여정 ID를 Kafka `investigation.requests`(텔레메트리 클러스터, 보존 3일 [가정])로 보낸다(docs/observability.md §7). 지금까지 원문 IP는 노드에서 법정 접속기록 DB로만 바로 갔는데, 이제 메시지 저장소에도 머문다.

| 갈래 | 위협 | 대응(위치) | 남는 위험 |
| --- | --- | --- | --- |
| S | 시청자가 `CloudFront-Viewer-JA4-Fingerprint`·`CloudFront-Viewer-ASN`·`x-amzn-waf-bot-labels`를 꾸며 남의 기기·망처럼 보이게 하거나 묶음을 흐린다 | 원본 확인 헤더가 없는 요청에서는 게이트웨이가 이 헤더를 지워 기록·내부 헤더에 싣지 않는다(B-T18 ④, Q-T61 ③). JA4와 끝단 라벨은 실시간 판정에 쓰지 않고 묶음의 근거 신호로만 쓴다(docs/features/bot-defense.md §3.3) | 원본 확인 헤더 값이 새면 꾸민 값이 들어간다(§10 그 헤더 행). 봇이 진짜 브라우저 TLS를 흉내 내면 JA4는 사람과 같다 |
| S·T | 다른 워크로드가 토픽에 가짜 요청 기록을 넣어 남을 묶음에 끼워 넣거나 기록을 지우게 한다 | 토픽 접근 권한으로 쓰기는 수집기 조사 사본 갈래의 MSK 역할만, 읽기는 `inv-ingest` 역할만 갖는다(secrets-and-keys '데이터 저장소 접속 자격 증명'). 조사 저장소의 적재 사용자는 INSERT만 한다 | 수집기는 노드의 모든 로그를 읽는 DaemonSet이라, 수집기가 뚫리면 그 노드의 기록을 지어낼 수 있다. 기록 고정(§11.5) 전에 들어온 거짓 행은 해시로 드러나지 않는다 |

### 11.4 두 갈래 연결(재식별)

| 갈래 | 위협 | 대응(위치) | 남는 위험 |

| I | 한 사람이 두 갈래를 머릿속으로 잇는다 | 한 계정에 조사관과 가명정보 취급자 지정을 함께 두지 않고, 다른 종류를 90일 [가정] 안에 거둔 계정에도 주지 않는다(냉각 기간). 가명정보 취급자였던(90일 안) commander는 조치를 승인하지 못한다. 동시 지정 요청은 행 잠금으로 막는다(authz-matrix §3.7). 책임자의 확인(internal-management-plan.md §2.2)은 보조다 | 90일이 지난 뒤의 바꿔 갖기와, 지정 기록을 고칠 수 있는 DB 관리자의 우회는 남는다(authz-matrix §8) |
| I | 조사관이나 후보 계산이 행동 요약(입력 간격·포인터 이동의 요약)을 계정끼리 견주어 같은 사람인지 알아본다. 그러면 행동 요약이 특정 개인을 알아보는 생체인식 특징정보(민감정보)가 된다 | 행동 요약은 세션 하나의 자동화 판단과 '매크로·봇' 사유의 근거로만 쓰고, 연결·묶음 잇기·묶음 점수에 넣지 않는다. 계정끼리 견주는 질의와 묶음 계정의 값을 나란히 견주는 보기를 두지 않는다(data-classification '화면별 행동 요약의 조사 사본' 행, 법률 확인 34번, FX-T24, 추천 적용 2026-10-31, ADR-0173 결정 5) | 조사관이 두 사건 화면을 따로 열어 눈으로 견주는 것은 막지 못한다. 조사관 의견 양식의 규칙과 교육으로 줄인다 |
| I | 사람 단위 라벨이 판정 규칙 평가를 거쳐 분석 실버로 흘러간다 | 부정 예매 출처의 라벨(`FRAUD_ACTIONED`·`FRAUD_APPEAL_ACCEPTED`)은 trust-svc가 `telemetry.trust-verdicts`로 내지 않는다(B-T20 ⑦, A-T24) | — |
| I | 라벨 키를 가진 신원이 휴대폰 번호를 하나씩 넣어 연락처 가명을 되돌린다 | 라벨마다 KMS 키를 따로 두고 키 정책으로 받는 서비스를 묶는다: `contact`는 identity-svc만, `pay`는 payment-svc만, `device`는 기기 가명을 실제로 계산하는 trust-svc·identity-svc만. purchase-svc는 `contact` 키를 받지 못하고 `ComputeContactRef`(identity-svc, 신원마다 초당 상한)로만 값을 받는다. 라벨 키 요청 수가 평소의 3배 [가정]를 넘으면 SEV2다(secrets-and-keys '조사용 가명 키') | 그 라벨 키를 가진 서비스가 뚫리면 그 라벨은 KMS 없이 대입으로 되돌릴 수 있다(`contact`는 identity-svc, `device`는 무작위 값이라 대입이 어렵다). purchase-svc가 뚫리면 상한 안에서 `ComputeContactRef`를 대입에 쓸 수 있다. 파드 침해를 노출로 보고 그 라벨 키를 회전하는 것으로만 줄인다 |

### 11.5 증거 위·변조와 파기

| 갈래 | 위협 | 대응(위치) | 남는 위험 |
| --- | --- | --- | --- |
| T | 내부자가 기록 고정 뒤 조사 저장소의 행을 바꾸거나 지운다 | 고정 판마다 표별 해시와 판 사슬을 남기고(`fraud_snapshot`), 같은 값을 관제 감사 기록(키를 건 해시 체인)과 공개 체크포인트에 남긴다. 열린 사건 회차는 하루 한 번 [가정] 다시 계산해 다르면 SEV2와 보안 사고 기록이고 내보내기를 막는다(FX-T14) | 고정하기 전에 들어온 거짓 행이나 바뀐 행은 해시가 증명하지 못한다 |
| T | 증거 묶음 파일을 바꾸거나 지우거나, 봉인한 뒤 다시 봉인하거나, 분쟁·수사 보존을 일찍 끝내 지운다 | 증거 버킷의 객체마다 법적 보존과 버킷 기본 보존(준수 모드 30일 [가정])을 건다. ops-svc는 넣기·읽기만, 법적 보존 풀기와 지우기는 파기 작업 신원만 한다(docs/infra.md §9 '증거 버킷'). 분쟁·수사 보존의 끝은 조사관이 요청하고 요청자가 아닌 commander가 재인증해 확인해야 기록되고, 그 뒤 30일 [가정]이 지나야 파기한다(authz-matrix §6). 묶음 해시와 관리 연속성 기록은 관제 감사 기록에도 남고, 하루 한 번 [가정] 다시 계산한다 | 파기 작업 신원이 뚫리면 준수 모드 30일이 지난 묶음은 지울 수 있다. 그 일은 CloudTrail S3 데이터 이벤트와 관리 연속성 기록의 빠진 `DISPOSED`로 드러난다. 짠 두 사람은 보존을 일찍 끝낼 수 있다 |
| D | 증거 저장소 KMS 키를 끄거나 지워 증거를 읽지 못하게 한다 | 끄기·삭제 예약은 두 사람과 SEV1이고, 삭제 대기는 30일이며, 보존 중인 묶음이 있으면 하지 않는다(secrets-and-keys '증거 저장소 KMS 키') | 30일 대기 안에 알아채지 못하면 잃는다 |
| R | 누가 증거를 열람·반출했는지 부인한다 | 관리 연속성 기록(이전 행 해시를 잇는 덧붙이기 기록)과 관제 감사 기록, 관리 계정 접속기록 | 키 없는 해시 사슬이라, ops DB 쓰기 권한을 가진 사람은 사슬을 통째로 다시 만들 수 있다. 감사 기록의 같은 사건과 맞춰 보는 것이 그것을 드러낸다 |
| I | 기관 제출로 요청 범위 밖의 계정·항목을 내보낸다 | 기관 제출은 요청자가 아닌 commander가 승인한 자료 요청(APPROVED)과 겹치는 부분만 담고, 기획사 보고는 집계만 담는다(docs/features/forensic-replay.md §6.7.7). 고소·고발용 내보내기(`COMPLAINT`)에는 개인정보 칸이 없다(법률 확인 35번, 추천 적용 2026-10-31, ADR-0173 결정 6) | 승인 범위 자체가 넓으면 그만큼 나간다(FR-034 점검표가 본다) |

### 11.6 팬 쪽 경로: 소명, 우선 구매 권리, 양도 잠금

| 갈래 | 위협 | 대응(위치) | 남는 위험 |
| --- | --- | --- | --- |
| S | **우선 구매 권리 ID 탈취**: 남의 권리 ID로 판매 종료 뒤에도 대기 없이 들어와 좋은 좌석을 산다(권리 ID가 1회용 열쇠 구실을 한다) | queue-svc는 세션 계정의 사본에서만 권리를 찾아, 남의 ID는 없는 것과 같은 404다. 권리 ID는 본문으로만 보내고 주소·로그에 싣지 않는다(authz-matrix §3.2, Q-T62) | 권리를 받은 계정 자체를 빼앗기면 그 사람인 척 살 수 있다(팬 계정 보호의 한계, §2 S) |
| E | 권리로 받은 입장 토큰으로 다른 좌석을 잡거나 여러 번 산다 | 홀드 Lua가 같은 계정·같은 권리의 우선 구매 보류 좌석만 바꾸고, 결제를 마친 권리(USED)는 홀드·주문이 409다(S-T37) | — |
| T | **양도 잠금 우회**: 잠그기 직전에 넘기기, 잠근 뒤 산 표로 넘기기, 알림을 먼저 받고 넘기기 | 잠금과 진행 중 양도 요청의 철회가 한 트랜잭션이고, 이미 보유자가 바뀐 표와 잠근 뒤 발권한 표도 잠긴다. 돌려주기는 막지 않는다. 표가 결제자에게 돌아갈 뿐 퍼지지 않고, 돌아온 표는 잠긴 채 남기 때문이다(추천 적용 2026-10-31, ADR-0173 결정 3). 알림은 잠금이 모두 반영된 뒤 보낸다. 잠금과 양도 수락은 같은 티켓 행을 잠가 먼저 커밋된 쪽이 이긴다(authz-matrix §3.5, asvs/forensic-replay.md 15.4.2) | 계정 로그인 정보를 넘기는 장외 거래, 결제자가 예매를 취소하고(환급) 다시 사는 것은 막지 않는다(취소는 막지 않는 것이 정책이다, POL-046 ③). 잠금은 소명 요청 + 14일 [가정]에 풀리므로, 판단이 그보다 늦은 사건의 표는 퍼질 수 있다(그때도 이용 제한과 신고는 남는다, ADR-0173 결과) |
| S·T | 남의 사건에 소명·이의를 내 그 사건의 판단을 흔든다 | ops-svc가 낸 계정이 그 사건의 소명 요청 대상인지, 조치 계정의 이의 창 안인지 보고, 아니면 '대상 아님'으로 닫는다(authz-matrix §3.2, R-T32) | 사건 ID를 아는 것만으로는 아무것도 바뀌지 않는다 |
| I | 팬 화면의 소명 요청이 조사 내용(다른 계정, 점수, 근거)을 흘려 봇 운영자가 규칙을 피해 간다 | 팬에게는 사유 범주·기한·잠긴 표만 주고, 점수·가중치·연결 값·다른 계정은 주지 않는다(POL-046 ⑦) | 사유 범주와 조치 시점만으로도 규칙을 짐작할 수는 있다 |
