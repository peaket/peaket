# 비밀과 암호 키 목록

- **독자와 용도**: 비밀 값과 암호 키를 쓰는 서비스 엔지니어와 플랫폼 운영자가, 항목마다 보관 위치·사용 주체·순환 및 폐기 정책을 확인할 때 참조한다.
- **문서 목적**: 시스템 전체에서 다루는 모든 기밀 자격 증명(Secrets)과 암호화 키를 찾아 목록에 올리고, 보관 위치와 허가된 사용 주체를 안전하게 통제한다. OWASP(웹 보안 기준을 만드는 비영리 단체)의 웹 앱 보안 검증 항목 목록인 ASVS `v5.0.0-11.1.1`·`11.1.2`·`13.3.1`·`13.3.2`를 따른다.
- **아키텍처 원칙**: `docs/architecture.md` §8.3 '보안 기본 규칙'(원문 설계서 섹션 0)에 적힌 '모든 기밀 자격 증명은 애플리케이션 코드베이스 외부에 격리 보관한다'는 기본 원칙을 엄격히 지킨다.
- **법적 근거 및 규제 준수**: 개인정보보호위원회 공식 가이드라인은 API(프로그램끼리 요청과 응답을 주고받는 창구) 접근 키 같은 프로그램 연동용 자격 증명을 두고 "비밀번호로 직접 간주하지는 않으나, 이에 준하는 안전한 기술적 관리방안을 수립하여 운용해야 한다"고 밝힌다(「개인정보의 안전성 확보조치 기준 안내서」 2025.11., 82쪽). 이 문서가 그 규제 요건을 충족하는 공식 관리 체계 역할을 한다.

## 관리 규칙

1. 모든 기밀 자격 증명(API 키, 데이터베이스 패스워드 등)은 AWS Secrets Manager에 보관한다. 암호화 키는 AWS KMS(Key Management Service, 암호 키를 안전하게 보관하고 대신 써 주는 클라우드 서비스)의 고객 관리 키(CMK)로 봉인한다. AWS가 운영해 주는 쿠버네티스(컨테이너로 만든 앱을 여러 서버에서 실행하고 관리하는 플랫폼)인 EKS 환경에서는 External Secrets Operator로 비밀을 파드(쿠버네티스에서 앱이 실행되는 가장 작은 단위)의 환경변수와 볼륨에 안전하게 넣는다. 서비스별 IAM 역할은 EKS Pod Identity로 묶어(IRSA는 Pod Identity를 지원하지 않는 곳에만, ADR-0054) 서비스마다 최소 권한 원칙을 강제한다.
2. 소스코드, 컨테이너(앱과 실행 환경을 한 묶음으로 만든 실행 단위) 빌드 이미지, CI/CD 산출물(아티팩트), 애플리케이션 로그, 에러 스택 트레이스, 브라우저 클라이언트 번들(브라우저가 내려받는 자바스크립트 묶음)에 기밀값을 절대 하드코딩하거나 노출하지 않는다.
3. 로컬 개발 환경에서는 Git에 커밋되지 않는 로컬 파일 `.env`와, 변수 이름(키)만 적힌 템플릿 `.env.example`만 쓴다. Secrets Manager 연동이 필요한 로컬 개발 파이프라인은 LocalStack 모의 환경으로 재현한다.
4. pre-commit 훅과 CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 빌드 파이프라인에 gitleaks 검사를 강제로 넣어, 커밋과 배포 단계에서 비밀이 드러나는 것을 미리 막는다. 유출이 의심되는 자격 증명은 지체 없이 폐기하고 재발급한다.
5. 암호화 키의 전체 수명주기(생성, 배포, 사용 권한, 주기적 순환, 안전한 파기)는 NIST SP 800-57 Part 1 권고안을 따른다. 키마다 정기 교체 주기는 아래 목록의 마지막 열에 정했다(추천 적용, 2026-10-13, ADR-0050). 이 주기는 NIST SP 800-57 Part 1의 표와 원문을 대조하지 못해 자체 기준이다. 대조는 구현 전에 한다.
6. 판매가 열리는 시각 앞뒤로 접속이 몰리는 온세일 윈도우(오픈 10분 전부터 오픈 60분 뒤까지)에는 키를 교체하지 않는다(POL-028). 대형·중형 온세일의 변경 동결 창(오픈 90분 전부터)도 피한다. 자동 교체 일정(Secrets Manager 교체 창)은 정비 시간(매일 04:00~06:00 KST [가정, Phase 4 운영 리허설에서 확정])에 맞춘다(POL-041, docs/devops.md §8.3).
7. 키는 '키 사용 범위'에 적은 곳에만 쓴다(ASVS `v5.0.0-11.1.2`).
8. 이 문서의 목록이 암호 목록이다. 키·비밀·알고리즘·인증서를 더하거나 바꾸는 ADR과 PR은 같은 변경에서 목록을 고친다. 분기마다 [가정] KMS·Secrets Manager·ACM의 실제 목록과 대조해 빠진 것과 쓰지 않는 것을 정리한다(ASVS `v5.0.0-11.1.2`, 추천 적용 2026-10-26).

## 키 사용 범위

각 키는 위 표의 '용도' 열에 적은 일에만 쓴다(ASVS `v5.0.0-11.1.2`). 특히 다음은 하지 않는다.

| 키 묶음 | 쓸 수 있는 곳 | 쓸 수 없는 곳 |
| --- | --- | --- |
| 토큰 서명 키(팬 액세스, 관리, 현장 스태프, 입장 토큰) | 자기 토큰 종류의 서명. 게이트웨이는 자기 대상의 공개키만 신뢰한다 | 다른 대상의 토큰 서명, 데이터 암호화, 다른 서비스와 개인키 공유 |
