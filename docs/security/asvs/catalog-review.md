# ASVS 추적 표: 공연 탐색·관람 후기·홈 구성

- **독자와 용도**: 공연 탐색·관람 후기·홈 구성 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 홈 피드(배너·오픈 예정·지금 판매 중·테마·공연장, 장르별 랭킹 파일)와 관제 콘솔 [홈 구성](배너·테마 저장, 배너 이미지 올리기, SCR-068), 공연 검색(페이지 번호, 결과 0건 제안, 관련 공연)과 머리 검색창의 자동완성(SCR-003, [docs/features/search.md](../../features/search.md), ADR-0094), 공연 상세(SCR-002)의 상세정보 섹션(파트너가 올린 공연 설명 글과 포스터·상세 이미지 표시, 프로그램끼리 요청과 응답을 주고받는 창구인 파트너 공연 이미지 올리기 API 포함)과 안내 모달, 관람 후기(자격 확인·요약·목록·쓰기·고치기·지우기·통보 차단, SCR-016), 후기 사진(올리기, 확장자·매직 바이트·디코딩·악성 코드 검사, 다시 인코딩한 파생본 2종, 사진 설명. QR 코드·바코드 거르기는 2026-10-28에 뺐다, 기술 검토 낮음-158), 후기 신고(사유 8종·자세한 내용·권리 침해 본인 요청과 결과 받을 곳·신고 확인 모달·횟수 제한, 신고기관 바로가기), 운영자 후기 조치(관제 콘솔 CS 처리함 SCR-045의 조치 없음·임시조치·노출 차단·해제, 신고자·글쓴이 통지, 후기 자리 공시), 좌석맵 템플릿 목록·상세 읽기와 [템플릿에서 만들기](SCR-022), 찜한 공연·알림 신청 상태 조회, 본인확인 창 흐름(SCR-006)의 브라우저 출처 분리(창 메시지, 복귀 주소, 다른 호스트 이동), 파트너의 공연 등록·회차 더하기(공연 정보·공연장과 아티스트의 새 이름 요청·다른 이름·회차 일정·정렬 설정·배정 방식·1인 한도, SCR-021)와 팬의 찜(공개 공연, 계정당 1,000개 [가정]). 후기 사진·신고·조치와 템플릿은 2026-10-19에 더했다(소유자 요청과 추천 적용, ADR-0066). 공연 등록·회차 더하기·찜은 2026-11-05에 더했다(추천 적용, ADR-0198).
- **보안 검증 기준**: OWASP(웹 보안 기준을 만드는 비영리 단체)의 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 따르고, 목표 레벨은 Level 2다. 인코딩·삽입 방지(V1), 검증과 업무 로직(V2), 웹 프런트엔드(V3), API와 웹 서비스(V4), 파일 처리(V5), 인가(V8), 데이터 보호(V14), 보안 로그와 오류 처리(V16)의 L1·L2 항목을 모두 판정한다. Level 3은 골라 채택한 8개만 싣는다. 로그인·세션·토큰(권한이나 상태를 증명하려고 주고받는 서명된 문자열)과 본인확인 결과 저장은 [계정·인증 추적 표](auth.md)를 따른다. 좌석맵 가져오기 파일 처리와, 바뀐 좌석만 담은 작은 메시지인 좌석 델타를 보내는 WebSocket(연결을 열어 둔 채 서버와 브라우저가 주고받는 통신 방식)은 이 표 범위 밖이다([좌석 추적 표](seat-hold.md)가 판정한다). 좌석맵 배치본의 소유·테넌트 규칙과 [템플릿에서 만들기]는 이 표에서 판정한다(소유·테넌트 규칙은 V2·V8). 템플릿은 PEAKET이 만들어 배포 때 넣는 읽기 전용 자료다. 그래서 새 추적 표를 만들지 않는다(ADR-0066). CS 처리함 자체(건 목록·기한·승인 업무)는 [양도·취소·환불 운영 추적 표](transfer-refund.md), 고객 문의는 [고객 문의 추적 표](support.md)를 따른다. 암호(V11)·보안 통신(V12)·설정(V13)·안전한 코딩(V15)은 이 기능이 새로 정하는 것이 없다. 다만 이미지 처리 작업의 격리는 이 기능이 정하므로 선별 L3의 15.2.5로 이 표에서 판정한다(추천 적용 2026-10-28, 기술 검토 중간-068). 그래서 다른 추적 표(payment.md·settlement.md)와 같은 플랫폼 공통 설정을 따르고, 여기서 다시 판정하지 않는다.
- **아키텍처 설계 근거**: [ADR-0063](../../adr/0063-screen-redesign-owner-feedback.md), [ADR-0066](../../adr/0066-screen-feedback-12-items.md)(후기 사진·신고·조치, 좌석맵 템플릿), [ADR-0062](../../adr/0062-open-items-delegated-decisions.md) 결정 38(공연 이미지 기준), [ADR-0093](../../adr/0093-production-entity-place-artist-units.md)(공연·공연장·아티스트·다른 이름), [ADR-0094](../../adr/0094-search-redesign-autocomplete-read-model-search-port.md)(검색 설계), [docs/api/openapi.yaml](../../api/openapi.yaml)(`catalog`·`reviews` 태그, `/v1/review-images`, `/v1/reviews/{reviewId}/reports`, `/v1/ops/reviews/{reviewId}/moderation`, `/v1/partner/seatmap-templates*`, `POST /v1/partner/productions/{productionId}/seatmap`(템플릿에서 만들기), `/v1/ops/home-layout*`, `/v1/partner/productions/{productionId}/images*`, `/v1/search*`, `/v1/identity/verifications*`), [docs/api/guidelines.md](../../api/guidelines.md) §3·§9, [docs/data.md](../../data.md) §2(`review`, `review_image`, `content_report`, `takedown_action`, `venue` TEMPLATE, `home_banner`, `home_theme`, `production`, `place`, `artist`, `search_alias`, `search_document`, `search_term`), docs/planning/03 POL-024·POL-042·POL-044, [docs/features/identity.md](../../features/identity.md) §5, [docs/features/control-tower.md](../../features/control-tower.md) §3 명령 9·10과 §10, [docs/features/analytics.md](../../features/analytics.md) §8.5, [docs/security/data-classification.md](../data-classification.md)
- **문서 상태 및 일정**: 항목 선정을 마쳤고 구현 직전 단계다(2026-10-14 수립, ADR-0063 반영). 요구사항 문구는 OWASP ASVS 저장소 `v5.0.0` 태그의 5.0/en 장 파일(V1·V2·V3·V4·V5·V8·V14·V16) 원문과 대조했다(2026-10-14). 법률 행의 조문은 국가법령정보센터 원문으로 확인했다(2026-10-14). 소비자 웹 핵심 화면(wbs 2.10.1)과 후기(wbs 7.3.1) 작업을 시작하기 전에 다시 판정한다. 2026-10-15 쿠키(브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 작은 값) 이름 접두사 결정(추천 적용, docs/features/identity.md §3)으로 3.3.1을 적용으로 바꾸고, 3.3.3의 근거를 고쳤다. 2026-10-19 후기 사진·후기 신고·운영자 후기 조치·[템플릿에서 만들기]를 더해 V1·V2·V3·V4·V5·V8·V14·V16과 법률 행을 다시 판정했다(ADR-0066). 판정 항목은 그대로다. 요구사항 요약은 이 표에 이미 원문과 대조해 둔 문구를 썼다. 1.3.11은 신고 결과를 계정 이메일로도 알리게 되어 적용으로 바꿨다. 선별 L3에는 14.2.7(자동 파기)을 더했다. 새 법률 행의 조문은 2026-10-19에 국가법령정보센터 원문으로 확인했다. 2026-10-23에 요구사항 요약 칸을 ID마다 ASVS 5.0.0 원문 기준 한 문장으로 맞췄다(ADR-0087 결정 30). 2026-10-27 검색 재설계(ADR-0093·0094)로 검색 행(1.2.1·1.2.4·1.2.9·1.3.3·1.3.9·1.3.12·2.1.1·2.1.3·2.4.1·8.1.1·14.2.3·14.2.5·16.1.1·16.2.5·16.3.3·16.5.2)을 다시 판정했다. 판정 항목과 적용 여부는 그대로이고, 구현 위치와 사유를 새 설계(자동완성 메모리 사전, LIKE 이스케이프, 검색 전용 연결 묶음, 검색어 없는 품질 사건)에 맞췄다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `web`: 소비자 웹(웹 화면을 만드는 프레임워크 Next.js) 홈·상세·검색 화면, 후기 모달(사진 올리기·사진 보기, 신고·신고 확인 모달), 머리 검색창(자동완성), 본인확인 복귀 화면 `/verify/return`
  - `console`·`partner`: 관제 콘솔 [홈 구성] 탭과 CS 처리함(SCR-045)의 후기 조치, 파트너 콘솔 공연 등록 이미지 올리기와 좌석맵 에디터(SCR-022)의 템플릿 고르기·템플릿에서 만들기
  - `core-svc`: catalog 모듈(홈 피드, 검색·관련 공연(검색 읽기 모델, 읽기 전용 복제본), 자동완성(메모리 사전), 공연·공연장·아티스트·다른 이름, 홈 구성 반영, 이미지 받기(원본을 격리 버킷에 넣고 이미지 작업을 맡김)·결과 반영·파생본 게시, 좌석맵 템플릿 읽기와 템플릿에서 만들기), review 모듈(자격 확인, 금칙어, 같은 내용 숨김, 통보 차단, 후기 사진 받기·결과 반영·파생본 게시, 신고 접수, 신고 처리 조치 반영), notify 모듈(신고 결과·조치 통지)
  - `image-worker`: 이미지 처리 작업(core-svc와 같은 코드의 다른 진입점으로 띄운 별도 배포). 공연 이미지·홈 배너·후기 사진의 디코딩, 화소 검사, 악성 코드 검사 결과 확인, 다시 인코딩과 메타데이터 지우기를 여기서만 한다. DB 자격 증명이 없다(5.4.3, 추천 적용 2026-10-28, 기술 검토 중간-068)
  - `ops-svc`: 홈 구성 권한·감사 로그, 법정 통보 처리, 신고 건(CS 처리함)과 후기 조치의 권한·사유·감사 로그
  - `identity-svc`: 본인확인 시작·결과 경로, `ticket-svc`: 후기 자격용 결제자 티켓 조회
  - `gw-*`: API 게이트웨이(클라이언트 종류별로 앞에 둔 입구 서버), `CDN`: AWS의 CloudFront 배포(공연 페이지·`api`)
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 리포트로 갱신한다. 태그를 붙일 수 있는 검사는 자동 시험, 정적 정책 검사(conftest·Kyverno 정책 시험 등), doc-check 규칙, 설정 검사다. 운영 설계로만 있는 행은 결과를 '설계 검사'로 적고, 운영을 띄우지 않는 동안은 통과로 세지 않는다(docs/architecture.md §8.2 4, 추천 적용 2026-10-28, 기술 검토 낮음-089).
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남긴 기록인 ADR 작성 필수)으로 구분한다.
