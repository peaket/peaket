# ASVS 추적 표: 양도·취소·환불 운영

- **독자와 용도**: 양도·취소·환불 운영 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 양도 요청·수락·거절·철회·돌려주기, 결제자만 하는 예매 취소와 환불 계좌 입력, 회차 취소 요청·귀책 판정·2인 확정·일괄 환불 작업, 주최 측 귀책 배상 지급, CS 처리함, 승인 업무(예외 환불, 계정 탈취 양도 회수), 취소·양도 남용 제한과 소명(예매 제한이나 양도 회수 대상이 된 팬이 사정을 설명하는 절차), 공연 판매 승인과 판매자 정보·중개자 고지, 공연예술통합전산망 전송
- **보안 검증 기준**: OWASP(웹 보안 기준을 만드는 비영리 단체)가 만든 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 따르고, 목표 레벨은 Level 2다. 업무 로직(V2 전 절), 웹 프런트엔드(V3 전 절, 양도·양도 받기·예매 취소·소명·계좌 입력 화면과 파트너·관제 콘솔의 회차 취소·판매 승인·승인 업무·CS 처리함 화면), 인가(V8 전 절), 자체 완결형 토큰(권한이나 상태를 증명하려고 주고받는 서명된 문자열. V9 전 절, 양도·취소에 쓰는 팬 재인증 토큰), 암호(V11 전 절, 양도·취소 때의 기기 키 폐기와 교체. ADR-0053으로 추가), 데이터 보호(V14 전 절), 안전한 코딩(V15.1~V15.3), 보안 로그와 오류 처리(V16 전 절)의 L1·L2 항목을 모두 판정한다. Level 3은 골라 채택한 3개만 싣는다. 관리 계정 로그인과 재인증, 브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 쿠키의 이름과 속성은 [계정·인증 추적 표](auth.md)를 따른다. 결제사 취소 API 호출과, 일이 생기면 결제사가 우리 주소를 불러 알려 주는 웹훅은 [주문·결제 추적 표](payment.md)를 따른다. 응답 보안 헤더와 게이트웨이의 출처 검사 같은 공통 설정은 [전달 파이프라인 추적 표](delivery.md)를 따른다.
- **아키텍처 설계 근거**: [docs/features/transfer-refund.md](../../features/transfer-refund.md), [ADR-0045](../../adr/0045-intermediary-legal-status.md), [ADR-0046](../../adr/0046-cancel-transfer-refund-approvals.md), [ADR-0001](../../adr/0001-fan-social-login-single-factor.md), [docs/features/payment.md](../../features/payment.md), [docs/features/offline-gate.md](../../features/offline-gate.md), [docs/security/data-classification.md](../data-classification.md)
- **문서 상태 및 일정**: 항목 선정을 마쳤고 구현 직전 단계다(2026-10-13 수립). 요구사항 원문은 OWASP ASVS `v5.0.0_release` 원문과 대조했다(2026-10-13). V3 절은 OWASP ASVS 저장소 `v5.0.0` 태그의 V3 원문과 대조해 더했다(2026-10-15). Phase 5 양도·취소 작업 착수(wbs 5.2.1) 전에 다시 판정한다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `ticket-svc`: 양도 요청·수락·돌려주기·회수와 키 교체
  - `purchase-svc`: 예매 취소 Saga(여러 서비스에 걸친 일을 단계별로 처리하고, 중간에 실패하면 앞 단계를 되돌리는 방식)와 일괄 환불 작업
  - `payment-svc`: 결제사 취소와 송금 포트
  - `ops-svc`: 승인 업무, CS 처리함, 감사 로그
  - `core-svc`: 판매 승인, 판매자 정보, 공연예술통합전산망 전송
  - `gw-*`: 클라이언트 종류별로 앞에 둔 입구 서버인 API(프로그램끼리 요청과 응답을 주고받는 창구) 게이트웨이
  - `web`: 소비자 웹 양도(SCR-014)·양도 받기(SCR-041)·예매 취소(SCR-038)·소명 제출(SCR-042)·배상금 계좌 입력(SCR-043)·환불 계좌 입력(SCR-060) 화면
  - `partner`·`console`: 파트너 콘솔 판매 승인 요청(SCR-021)·회차 취소 요청(SCR-044), 관제 콘솔 CS 처리함(SCR-045)·승인 업무(SCR-046)·회차 취소 판정(SCR-047)·판매 승인(SCR-048)
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 리포트로 갱신한다.
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남긴 기록인 ADR 작성 필수)으로 나눈다.
