# ASVS 추적 표: 분석 저장소와 공연 리포트

- **독자와 용도**: 분석 저장소와 공연 리포트 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: Kafka(이벤트를 순서대로 쌓아 두고 여러 곳에 나눠 주는 메시지 시스템) 이벤트·기준 자료·운영 기록·비용·SLO(팀이 정한 목표) 결과의 원본 적재와 가명 처리, dbt 변환(브론즈 → 실버 → 골드)과 마감(R0~R3, 동결), 지표 사전과 결정 규칙 판정, 공연 리포트 만들기·내려받기, 결정 기록, 파트너 판매 요약 리포트, Iceberg 아카이브를 다룬다. 실시간 관제 화면 자체는 관제 콘솔 추적 표(예정)의 대상이다.
- **보안 검증 기준**: 웹 보안 기준을 만드는 비영리 단체 OWASP가 만든 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 쓰고, 목표 레벨은 Level 2다. 인코딩과 정화(V1), 업무 로직(V2), 웹 프런트엔드(V3.2·V3.3·V3.4·V3.5·V3.7. 공연 리포트·결정 기록 화면, 파트너 판매 요약 화면, 리포트 파일 내려받기), API와 웹 서비스(V4), 파일 처리(V5), 인가(V8), 암호(V11), 보안 통신(V12), 설정(V13), 데이터 보호(V14), 안전한 코딩(V15), 보안 로그와 오류 처리(V16)의 L1·L2 항목은 빠짐없이 판정한다. Level 3은 골라서 채택한 4개만 싣는다. 관리 계정 로그인·세션(V6·V7)과 관리 쿠키(브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 작은 값)는 [계정·인증 추적 표](auth.md)를 따른다. V3 행 가운데 콘솔 전체에 걸리는 응답 헤더(페이지가 실행할 수 있는 스크립트의 출처를 정하는 브라우저 규칙인 CSP, `frame-ancestors`, Referrer-Policy)는 docs/architecture.md §6.3 '화면별 CSP'와 [전달 파이프라인 추적 표](delivery.md)를 따른다. 비교 대시보드(Grafana: 지표와 로그를 그래프로 보여 주는 도구)의 브라우저 설정은, 지표·로그·요청 기록으로 시스템 안을 들여다보는 관측 플랫폼의 설정이므로 여기서 판정하지 않는다. V9·V10·V17은 이 기능에 해당하지 않는다.
- **아키텍처 설계 근거**: [docs/features/analytics.md](../../features/analytics.md), [ADR-0052](../../adr/0052-analytics-medallion-star-schema-close-stages.md), [ADR-0042](../../adr/0042-analytics-store-and-decision-rules.md), [docs/security/data-classification.md](../data-classification.md), [docs/security/secrets-and-keys.md](../secrets-and-keys.md)
- **문서 상태 및 일정**: 항목은 다 골랐고, 구현 직전 단계다(2026-10-13 수립, ADR-0052 반영). 요구사항 원문은 OWASP ASVS `v5.0.0_release` 원문과 대조했다(2026-10-13). 요구사항 요약은 2026-10-23에 ID마다 ASVS 5.0.0 원문 기준 한 문장으로 맞춰, 다른 추적 표의 같은 ID와 같은 문장이다(ADR-0087 결정 30). 개인정보 보호법(법률 제21445호)과 시행령(대통령령 제36671호)은 2026-09-11 시행본 원문과 대조했다. 분석 작업(wbs 4.3.2~4.3.7)을 시작하기 전에 구현 위치를 확정한다. V3 절은 2026-10-15에 OWASP ASVS 저장소 `v5.0.0` 태그의 V3 장 원문과 대조해 더했다. 2026-10-20에는 ADR-0071로, 흘러드는 이벤트를 실시간으로 계산하는 스트림 처리 엔진인 Flink의 실행 기반(관리 화면 잠금, 잡별 ClickHouse 사용자, 버전 고정)과 관제 실시간 잡(`ops-rt`)을 구현 위치에 더했다(docs/streaming.md). 2026-10-27에는 ADR-0099로 Flink를 빼고 TypeScript 스트림 작업자 기준으로 고쳤고, 1.3.8은 해당 없음으로 바꿨다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `peaket-data`: 스트림 작업자(Kafka 토픽을 계속 읽어 저장소에 쓰는 TypeScript 서비스)인 원본 적재 작업자(`analytics-ingest`)와 관제 실시간 적재 작업자(`ops-rt`), 심장 박동 발행기(`rt-pulse`), dbt 프로젝트(`analytics`), 마감 실행기(`close-runner`, 컨테이너 앱을 여러 서버에서 실행하고 관리하는 플랫폼인 쿠버네티스의 CronJob). 작업자의 공용 소비 규칙과 실행 기반은 docs/streaming.md §2에 있다
  - `ops-svc`: 공연 리포트 만들기와 API(프로그램끼리 요청과 응답을 주고받는 창구), 결정 기록, 가명정보(추가 정보 없이는 누구인지 알 수 없게 바꾼 정보) 처리 기록, 관제 콘솔 GraphQL
  - `core-svc`·`ops-svc` 내보내기: 회차 기준 자료와 운영 기록을 분석 수집 버킷(AWS의 파일 저장소인 S3)에 쓴다
  - ClickHouse 분석 DB(대량 이벤트 집계에 강한 분석용 데이터베이스): `bronze`·`silver`·`gold`·`rt`, 주체별 사용자와 역할
  - `gw-ops`·`gw-partner`: API 게이트웨이(클라이언트 종류별로 앞에 둔 입구 서버)
  - `console`·`partner`: 관제 콘솔의 공연 리포트(SCR-029 ④)·결정 기록 화면, 파트너 콘솔의 판매 요약(SCR-027)
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정)에서 돌린 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 보고서로 갱신한다.
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남기는 기록인 ADR을 반드시 쓴다)으로 나눈다.
