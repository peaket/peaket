# ASVS 추적 표: 알림·찜·오픈 알림 구독

- **독자와 용도**: 알림 발송, 찜, 오픈 알림·취소표 알림 구독, 파트너 웹훅 발송을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 오픈 알림·취소표 알림의 신청과 끄기(SCR-001·002·018·054), 찜(공연 단위), 웹 푸시 구독 정보(브라우저가 준 구독 주소·암호화 키)의 등록·해제와 서비스 워커의 푸시 받기·알림 누르기, 발송 원장(알림과 파트너 웹훅의 '보낼 일'과 결과를 적어 두는 core DB 표: 낱건 작업과 대량 발송 조각)과 발송 워커(웹 푸시·이메일, 대행 계약 뒤 알림톡·문자), 밤 시간·광고성 정보 규칙과 한 번 누름 수신 거부, 파트너 웹훅(일이 생기면 PEAKET이 파트너가 등록한 주소를 불러 알려 주는 방식) 발송의 서명·SSRF 막기·재시도·실패 보관과 관리 API(SCR-025)를 다룬다. 알림 문구 변수 규칙(발송 작업 행에 받는 주소·전화번호·본문 같은 개인정보를 넣지 않는 규칙)도 포함한다. 파트너 웹훅의 나가는 연결은 [정산 지급 추적 표](settlement.md)도 같은 ID로 판정해 두었다(기술 검토 중간-061). 두 표는 같은 규칙(docs/api/guidelines.md §8 '파트너 웹훅(발송)')을 가리킨다.
- **보안 검증 기준**: 웹 보안 기준을 만드는 비영리 단체 OWASP가 만든 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 쓰고, 목표 레벨은 Level 2다. 인코딩·삽입 방지(V1), 검증과 업무 로직(V2), 웹 프런트엔드(V3), API(프로그램끼리 요청과 응답을 주고받는 창구)와 웹 서비스(V4), 인가(V8), 암호(V11), 보안 통신(V12), 설정(V13), 데이터 보호(V14), 안전한 코딩(V15), 보안 로그와 오류 처리(V16)의 L1·L2 항목은 빠짐없이 판정한다. 웹 푸시 본문 암호화와 VAPID 서명, 웹훅 서명, 브라우저와 파트너가 주는 바깥 주소로 보내는 연결이 있기 때문이다. Level 3은 골라서 채택한 6개만 싣는다. 이 기능은 파일을 받지 않으므로 파일 처리(V5)는 판정하지 않는다. 로그인·세션·토큰(V6·V7·V9·V10)과 쿠키 이름은 [계정·인증 추적 표](auth.md)를, 응답 보안 헤더와 게이트웨이(클라이언트 종류별로 앞에 둔 입구 서버)의 출처 검사 같은 공통 설정은 [전달 파이프라인 추적 표](delivery.md)를 따른다.
- **아키텍처 설계 근거**: [docs/features/notify.md](../../features/notify.md), [ADR-0053](../../adr/0053-crypto-hardening-pseudonyms-webhooks-stores-runbook-audit.md) 결정 4, [ADR-0062](../../adr/0062-open-items-delegated-decisions.md) 결정 28·52, [ADR-0089](../../adr/0089-leftover-values-senior-engineer-decisions.md) 결정 8·9, [ADR-0109](../../adr/0109-delivery-jobs-in-postgres-drop-bullmq-cache-redis-key-classes-noeviction.md), [ADR-0139](../../adr/0139-personal-data-cross-border-transfer-register.md) 결정 6·9·10, [ADR-0155](../../adr/0155-notify-three-stage-open-alert-chunked-broadcast-webhook-rules.md), [docs/api/openapi.yaml](../../api/openapi.yaml)(`/v1/events/{eventId}/subscriptions`, `/v1/subscriptions`, `/v1/wishes`, `/v1/productions/{productionId}/wish`, `/v1/push-subscriptions`, `/v1/subscription-opt-outs/{optOutToken}`, `/v1/partner/webhooks*`, `webhooks.partnerEvent`), [docs/api/guidelines.md](../../api/guidelines.md) §8·§9, [docs/data.md](../../data.md) §2 ⑥·§6, [docs/security/data-classification.md](../data-classification.md)('Web Push 구독 정보', '오픈 알림·취소표 알림 신청', '관심 공연 찜하기 내역', '알림 발송 기록', 국외 이전 목록 국-09), design/d5 §9.1
- **문서 상태 및 일정**: 항목은 다 골랐고, 구현 직전 단계다(2026-10-30 수립, ADR-0154 결정 3). 요구사항 요약은 이 저장소의 다른 추적 표가 원문과 대조해 둔 문구를 그대로 썼다(ID마다 한 문장, ADR-0087 결정 30). 다른 표에 없던 4.1.5 하나만 OWASP ASVS 저장소 `v5.0.0` 태그의 V4 원문(`5.0/en/0x13-V4-API-and-Web-Service.md`)을 2026-10-30에 받아 대조했다. 법률 행의 정보통신망법 §50과 같은 법 시행령 §61·§62의2·§62의3은 2026-10-30 국가법령정보센터 법령 본문으로 확인했다. 알림 모듈 구현(wbs 5.6.1)을 시작하기 전에 다시 판정한다. 이메일 대행사를 정하면(review/open-items.md 57번) 13.2.1·13.2.4를 다시 판정한다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `web`: 소비자 웹(웹 화면을 만드는 프레임워크 Next.js)의 알림 토글(SCR-001·002·018), 관심 공연·알림 신청(SCR-054 `/my/likes`), 웹 푸시 권한 안내(CMP-068), 서비스 워커(브라우저 뒤에서 오프라인 동작과 캐시를 맡는 스크립트)의 푸시 받기·알림 누르기
  - `partner`: 파트너 콘솔 웹훅 연동(SCR-025)
  - `core-svc`: notify 모듈(신청·찜·웹 푸시 구독 API, 대량 발송 계획, 발송 원장), 발송 워커 `core-notify-sender`(웹 푸시·이메일)와 `core-webhook-dispatcher`(파트너 웹훅)
  - `identity-svc`: 받는 사람 조회(이메일·언어·본인확인 여부·계정 상태)
  - `gw-*`: API 게이트웨이(`gw-fan`, `gw-partner`)
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정)에서 돌린 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 보고서로 갱신한다. 태그를 붙일 수 있는 검사는 자동 시험, 정적 정책 검사(conftest·Kyverno 정책 시험 등), doc-check 규칙, 설정 검사다. 운영 설계로만 있는 행은 결과를 '설계 검사'로 적고, 운영을 띄우지 않는 동안은 통과로 세지 않는다(docs/architecture.md §8.2 4, 추천 적용 2026-10-28, 기술 검토 낮음-089).
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남기는 기록인 ADR을 반드시 쓴다)으로 나눈다.
