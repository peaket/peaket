# ASVS 추적 표: 전달 파이프라인과 운영 플랫폼(CI·공급망·GitOps·배포·운영 접근·운영 진단)

- **대상 기능 범위**: 코드가 저장소에서 운영 환경까지 가는 길과 그 길을 받치는 플랫폼 설정이다. 공용 CI 워크플로, 산출물 증명(SBOM·서명·출처 증명), 의존성 관리와 취약점 조치 기한, GitOps 승격과 클러스터 입장 정책(Kyverno), 배포와 마이그레이션 실행, 변경 동결 달력, 인프라 코드, 사람의 운영 접근과 감사 기록, 비용 가드레일, 응답 보안 헤더(CloudFront 응답 헤더 정책과 게이트웨이 공통 정책)와 게이트웨이의 CORS·출처 검사, 프런트엔드 공용 린트, 운영 진단(진단 증거의 수집·저장소, 프로브, 시간 초과 기본값, ADR-0070). 각 서비스의 업무 기능은 기능별 추적 표(auth, payment, settlement, transfer-refund, offline-gate, bot-defense, analytics, queue-admission, catalog-review, support)가 맡고, 이 표는 그 표들이 '공통'이나 'CI'로 미룬 항목의 실제 구현 위치를 정한다.
- **보안 검증 기준**: OWASP ASVS 5.0.0, 목표 레벨 Level 2. 웹 프런트엔드(V3)의 공통 설정, 설정(V13), 데이터 보호(V14, 운영 진단 증거 범위), 안전한 코딩과 구조(V15), 보안 로그와 오류 처리(V16)의 L1·L2 항목을 전수 판정한다. Level 3는 위험이 큰 7개 항목만 골라 채택한다. 요구사항 원문은 OWASP ASVS `v5.0.0_release` 태그의 `0x22-V13-Configuration.md`, `0x24-V15-Secure-Coding-and-Architecture.md`, `0x25-V16-Security-Logging-and-Error-Handling.md`와 대조했다(2026-10-13). V14와 V13·V15·V16의 운영 진단 행은 같은 태그의 `0x23-V14-Data-Protection.md`와 함께 다시 대조했다(2026-10-20, ADR-0070). V3는 OWASP ASVS 저장소 `v5.0.0` 태그의 V3 원문과 대조했다(2026-10-15). 기능별 추적 표의 V3 행이 '공통'으로 미룬 응답 헤더·출처 검사·린트는 이 표가 판정하고, 쿠키 이름과 속성은 [계정·인증 추적 표](auth.md)가 판정한다.
- **아키텍처 설계 근거**: [docs/devops.md](../../devops.md), [ADR-0054](../../adr/0054-delivery-pipeline-change-freeze-and-safe-deploys.md), [docs/infra.md](../../infra.md) §4.1·§7·§9, [docs/architecture.md](../../architecture.md) §4·§6.3, [ADR-0008](../../adr/0008-client-specific-thin-gateways.md), [docs/security/secrets-and-keys.md](../secrets-and-keys.md), [docs/observability.md](../../observability.md) §5·§9, [ADR-0070](../../adr/0070-incident-response-evidence-probes-timeouts-throughput-soak.md), [docs/security/data-classification.md](../data-classification.md)
- **문서 상태 및 일정**: 항목 선정 완료, 구현 직전 단계(2026-10-13 수립, ADR-0054 반영. 2026-10-20 운영 진단 반영, ADR-0070. 같은 날 git flow 가지 규칙과 릴리스 봇 권한 반영, ADR-0074). 공용 워크플로·보안 검사 게이트·가지 규칙 검사·릴리스 워크플로(wbs 0.1.2·0.1.4), 마이그레이션 실행기(0.3.4), 운영 진단 기본값(0.3.6), GitOps·입장 정책·접근 통제(0.4.4), 진단 증거 저장소·증거 수집기(4.1.1), 변경 동결 달력(4.4.3), 프런트엔드 배포(2.10.4), CloudFront 배포와 응답 헤더 정책(2.11.2) 구현 때 테스트 결과를 채운다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `.github`: 조직 공용 재사용 워크플로(`ci-node`, `security-scan`, `build-image`, `migration-check`, `contract-check`, `iac-check`, `gitops-check`, `promote`)
  - `peaket-gitops`: Kyverno 정책, ArgoCD AppProject·ApplicationSet, 공용 Helm 차트, 변경 동결 달력 파일, Envoy Gateway 공통 정책(보안 응답 헤더, CORS, 출처 검사)과 라우트
  - `peaket-infra`: AWS 계정·조직 정책·IAM(OIDC 역할, Identity Center 권한 세트), GitHub 조직 설정, CloudFront 배포와 응답 헤더 정책
  - `peaket-frontend`: 프런트엔드 모노레포의 공용 ESLint 설정, 앱(web·partner·관제 콘솔)이 보내는 화면 보안 헤더
  - `peaket-platform`: 마이그레이션 실행기, OpenFeature 감싸개, 공용 린트·Semgrep 규칙, HTTP 클라이언트 기본값, 공용 시작 코드(프로브 세 종류, 진단 주석 수집, Node 실행 옵션, DB·Redis 시간 초과 기본값)
  - `freeze-calendar`: 변경 동결 달력과 자동 중단(플랫폼 네임스페이스)
  - `evidence-collector`: 경보 웹훅을 받아 DB·Redis 순간 상태를 진단 증거 저장소에 올리는 증거 수집기(플랫폼 네임스페이스)
- **테스트 결과**: 손으로 적지 않는다. CI 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 파싱한 리포트로 갱신한다.
- **미적용 사유 분류**: 해당 없음, Phase 이연, 위험 수용(ADR 작성 필수)으로 구분한다.

## V3 웹 프런트엔드 보안(V3.2 의도치 않은 해석, V3.3 쿠키, V3.4 브라우저 보안 헤더, V3.5 브라우저 출처 분리, V3.7 기타 브라우저 보안)

응답 보안 헤더는 두 곳에서 붙인다. CloudFront를 거치는 응답(S3 원본의 정적 자산과 대기열 파일 포함)은 배포·캐시 동작마다 단 응답 헤더 정책이, CloudFront를 거치지 않는 `gw-scanner`를 포함한 게이트웨이 응답은 게이트웨이 공통 정책(architecture §4 '공통 인프라 정책')이 붙인다. 응답 헤더 정책의 원본 값 재정의를 끄면 원본이 보낸 헤더를 그대로 두고 원본에 없을 때만 정책의 값을 붙인다(CloudFront 응답 헤더 정책 문서, 2026-10-15 확인). 그래서 화면마다 다른 CSP·Referrer-Policy는 앱이 보내고, 모든 응답에 같아야 하는 HSTS와 `nosniff`는 정책 값으로 덮어쓴다.
