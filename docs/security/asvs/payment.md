# ASVS 추적 표: 주문·결제

- **독자와 용도**: 주문·결제 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 주문을 만든 뒤의 결제 흐름 전체다. 결제 시도 시작과 결제사 선택(공연별 지정, 장애 때 전환, 플랫폼 기본값), 결제창 연동(PEAKET이 연동하는 결제사인 토스페이먼츠의 주문서형 결제와 포트원의 결제창), 결제 접수와 결제사별 접수 계약, 승인·조회·취소·환불, 결제사 웹훅(일이 생기면 상대 서버가 우리 주소를 불러 알려 주는 방식) 수신, 일일 대사, 결제사별 동시 입장 목표 상한(ADR-0029, ADR-0036, ADR-0044).
- **보안 검증 기준**: 기준은 웹 보안 기준을 만드는 비영리 단체 OWASP가 만든 웹 앱 보안 검증 항목 목록 ASVS 5.0.0이고, 목표 레벨은 Level 2다. V2 전 절, V3 전 절(L1·L2가 있는 V3.2~V3.5·V3.7)과, 결제 흐름에 직접 걸리는 절(V8.2, V11.2·V11.3·V11.5, V12.2·V12.3, V13.1~V13.3, V14.1~V14.3, V15.1·V15.3, V16.2·V16.3·V16.5)의 L1·L2 항목을 빠짐없이 판정한다. Level 3은 골라 채택한 4개만 싣는다. 사용자 로그인과 세션, 쿠키(브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 작은 값)의 이름과 속성은 [계정·인증 추적 표](auth.md)에서 판정한다. 대기열의 자동화 방지는 [봇 방어 추적 표](bot-defense.md)에서 판정한다. 응답 보안 헤더, 그리고 클라이언트 종류별로 앞에 둔 입구 서버인 게이트웨이의 출처 검사 같은 공통 설정은 [전달 파이프라인 추적 표](delivery.md)에서 판정한다. 좌석 홀드(결제하는 동안 다른 사람이 가져가지 못하게 좌석을 잠시 잡아 두는 것)는 Redis(메모리에 데이터를 두는 빠른 저장소)에서 Lua로 처리하며, 그 이중 예약 방지는 [좌석 추적 표](seat-hold.md)에서 판정한다. 이 표는 여러 서비스에 걸친 일을 단계별로 처리하고 중간에 실패하면 앞 단계를 되돌리는 결제 Saga 안에서 좌석 확정 행(`seat_sale`)까지 판정한다. 로그 저장소 보호(V16.4) 같은 공통 항목은 플랫폼 공통 추적 표에서 다룬다.
- **아키텍처 설계 근거**: [docs/features/payment.md](../../features/payment.md), [ADR-0015](../../adr/0015-tosspayments-two-phase-approval.md), [ADR-0029](../../adr/0029-pg-adapter-toss-default-portone-compatible.md), [ADR-0036](../../adr/0036-external-limits-estimates.md), [ADR-0044](../../adr/0044-dual-pg-selection-and-switchover.md), [docs/security/data-classification.md](../data-classification.md), [docs/security/secrets-and-keys.md](../secrets-and-keys.md).
- **문서 상태 및 일정**: 항목 선정을 마쳤고 구현 직전 단계다(2026-10-13 작성, ADR-0044 반영). 요구사항 원문은 OWASP ASVS `v5.0.0_release` 원문과 대조했다(2026-10-13). V3 절은 OWASP ASVS 저장소 `v5.0.0` 태그의 V3 원문과 대조해 빠진 V3.2·V3.3·V3.5 행을 채웠다(2026-10-15). Phase 2 결제 작업 시작(wbs 2.7.1) 전에 다시 판정한다. 승인 실행기 착수 때 다시 판정했다(2026-11-09, BUILD_ORDER PRF-181): 새 외부 연동은 없고(결제사 호출 경로는 앞서 판정했다) 판정이 바뀐 행은 없으며, 구현 위치에 2.2.3·2.3.3·2.3.4·14.2.7·16.2.5·16.3.4·16.5.2·16.5.3을 더했다. UNKNOWN 해소 착수 때 다시 판정했다(2026-11-09, BUILD_ORDER PRF-182): 새 외부 연동은 없고(단독 조회는 같은 결제사 경로다) 판정이 바뀐 행은 없으며, 같은 여덟 행의 구현 위치에 단독 조회 몫을 더했다. 결제사 호출 보호 착수 때 다시 판정했다(2026-11-09, BUILD_ORDER PRF-183): 새 외부 연동은 없고 판정이 바뀐 행은 없으며, 구현 위치에 2.3.2·2.4.1·13.2.6·15.1.3·16.2.5·16.3.4·16.5.2를 더했다. 포트원 어댑터 착수 때 다시 판정했다(2026-11-09, BUILD_ORDER HOT-140): 결제사 호출 경로는 앞서 판정한 것이고 판정이 바뀐 행은 없으며, 구현 위치에 2.2.1·2.2.3·2.3.2·11.2.1·12.3.1·13.2.2~13.2.5·13.3.1·14.2.7·15.3.2·16.2.5·16.5.3을 더했다. 계약 시험 묶음과 결제 수단 연결값 착수 때 다시 판정했다(2026-11-09, BUILD_ORDER HOT-145): 새로 나가는 호출은 토스 스모크의 공개 시험 키 호출뿐이고 판정이 바뀐 행은 없으며, 구현 위치에 2.2.1·11.2.1·13.3.1·14.2.4·16.2.5·16.5.2를 더했다. 2026-10-20 3차 점검에서 가상계좌 번호(ADR-0062)의 필드 암호화(ADR-0073 결정 26)를 판정에 넣어 V11.3 세 행을 더하고 고시 제7조 제2항 행을 적용으로 바꿨으며, 주문·결제 접속기록 보존 법률 행을 더했다(추천 적용 2026-10-20, ADR-0073).

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다. `purchase-svc`는 booking 모듈(주문, 결제 시도, Saga), `payment-svc`는 결제사 선택기·어댑터·웹훅·대사, `gw-*`는 API 게이트웨이, `web`은 소비자 웹 결제 화면(SCR-011, 결제창 복귀 상태 포함)과 결제 결과 화면(SCR-012)이다.
- **테스트 결과**: 손으로 적는 것은 금지한다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트 모음의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 자동으로 만든 리포트로 갱신한다. 태그를 붙일 수 있는 검사는 자동 시험, 정적 정책 검사(conftest·Kyverno 정책 시험 등), doc-check 규칙, 설정 검사다. 운영 설계로만 있는 행(예: CloudFront 응답 헤더 정책, ACM 공인 인증서)은 결과를 '설계 검사'로 적고, 운영을 띄우지 않는 동안은 통과로 세지 않는다(docs/architecture.md §8.2 4, 추천 적용 2026-10-28, 기술 검토 낮음-089).
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남긴 기록인 ADR 작성 필수)으로 나눈다.

- 14.2.1: 피켓 API(프로그램끼리 요청과 응답을 주고받는 창구)는 결제 값을 본문으로만 받는다. 하지만 결제창에서 돌아오는 주소에는 결제사 규약에 따라 결제 키와 결제 토큰(권한이나 상태를 증명하려고 주고받는 문자열)이 쿼리로 실린다. 위험 수용과 완화는 ADR-0044 결정 9에 적었다.
- 3.5.5: 결제창(다른 출처의 프레임·창)과의 통신은 두 결제사의 브라우저 SDK가 맡는다. SDK가 창 메시지를 받는지, 받는다면 출처와 형식을 확인하는지는 아직 확인하지 않았다.
- 13.2.1: 결제사 API는 결제사가 발급한 바뀌지 않는 키(토스페이먼츠 시크릿 키, 포트원 API 시크릿)만 받는다. Secrets Manager에 두고 1년마다 바꾸며, 노출이 의심되면 바로 다시 발급하고, 토스 키는 호출 IP를 NAT 고정 EIP로 제한해 위험을 줄인 뒤 받아들인다(위험 수용, ADR-0088).
