# ASVS 추적 표: 고객 문의

- **독자와 용도**: 고객 문의 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 고객센터(SCR-056)의 문의하기(`/help/inquiries/new`: 문의 유형 11개, 관련 주문, 제목, 내용, 첨부 없음, 동의 체크 없는 개인정보 처리 고지), 내 문의 내역(`/help/inquiries`: 상태 칩, 새 답변 표시), 문의 상세(`/help/inquiries/[id]`: 분쟁 유형의 진행 경과·결과 기한, 문의·진행 경과·답변 기록, 추가 문의, 닫힌 문의)를 다룬다. 문의를 CS 처리함 건(`INQUIRY`, 분쟁 유형은 `DISPUTE`, 미성년자 계약 취소는 `MINOR_CONTRACT_CANCEL`)으로 잇는 일, 관제 콘솔 CS 처리함(SCR-045)의 답변 보내기·진행 경과 남기기·문의 닫기, 답변 알림, 문의 기록의 3년 보존과 파기도 포함한다(추천 적용 2026-10-19, ADR-0066).
- **보안 검증 기준**: 웹 보안 기준을 만드는 비영리 단체 OWASP가 만든 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 쓰고, 목표 레벨은 Level 2다. 인코딩·삽입 방지(V1), 검증과 업무 로직(V2), 웹 프런트엔드(V3), API(프로그램끼리 요청과 응답을 주고받는 창구)와 웹 서비스(V4), 인가(V8), 데이터 보호(V14), 보안 로그와 오류 처리(V16)의 L1·L2 항목은 빠짐없이 판정한다. Level 3은 골라서 채택한 2개만 싣는다. 이 기능은 첨부 파일을 받지 않으므로 파일 처리(V5)는 판정하지 않는다. 로그인·세션·쿠키(브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 작은 값) 이름과 관리 계정 재인증은 [계정·인증 추적 표](auth.md)를 따른다. CS 처리함의 건 목록·기한·승인 업무는 [양도·취소·환불 운영 추적 표](transfer-refund.md)를 따른다. 응답 보안 헤더와 게이트웨이(클라이언트 종류별로 앞에 둔 입구 서버)의 출처 검사 같은 공통 설정은 [전달 파이프라인 추적 표](delivery.md)를 따른다. 암호(V11)·보안 통신(V12)·설정(V13)·안전한 코딩(V15)은 이 기능이 새로 정하는 것이 없어서, 플랫폼 공통 설정을 따르고 여기서 다시 판정하지 않는다.
- **아키텍처 설계 근거**: [ADR-0066](../../adr/0066-screen-feedback-12-items.md) 결정 5, [docs/api/openapi.yaml](../../api/openapi.yaml)(`support` 태그의 `/v1/inquiries*`, `/v1/ops/cases/{caseId}/replies`, `PATCH /v1/ops/cases/{caseId}`), [docs/api/guidelines.md](../../api/guidelines.md) §3·§4·§9, [docs/architecture.md](../../architecture.md) §3.1(support 모듈과 CS 처리함 연결)·§6.3(문의 화면), [docs/data.md](../../data.md) §2(`inquiry`, `inquiry_message`, `cs_case`)·§6, [docs/security/data-classification.md](../data-classification.md)('고객 문의' 행, 법률 질문 24번), planning/03 POL-038, design/d5 §5.30
- **문서 상태 및 일정**: 항목은 다 골랐고, 구현 직전 단계다(2026-10-19 수립, ADR-0066 반영). 요구사항 요약은 이 저장소의 [공연 탐색·관람 후기·홈 구성 추적 표](catalog-review.md)(V1·V2·V3·V4·V8·V14·V16의 L1·L2 전 항목, 2026-10-14 원문 대조)와 [양도·취소·환불 운영 추적 표](transfer-refund.md)(선별 L3 14.2.7)에서 이미 원문과 대조해 둔 문구를 그대로 썼다. 이 표를 쓰면서 ASVS 원문을 다시 열어 보지 않았다. 요약 문구는 2026-10-23에 ID마다 ASVS 5.0.0 원문 기준 한 문장으로 맞췄고(ADR-0087 결정 30), 판정의 원문 대조는 고객 문의(wbs 5.8.4)를 시작하기 전에 다시 판정할 때 한다. 법률 행 가운데 전자상거래법 시행령 §6①은 2026-10-19 국가법령정보센터 원문으로 확인했다. 전자상거래법 §20③·시행령 §25의2, 개인정보 보호법 §23①, 「개인정보의 안전성 확보조치 기준」 §7②6호는 양도·취소·환불 운영 추적 표에 있는 같은 법률 행의 문구를 따랐다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `web`: 소비자 웹(웹 화면을 만드는 프레임워크 Next.js)의 고객센터 `/help`, 문의하기 `/help/inquiries/new`, 내 문의 내역 `/help/inquiries`, 문의 상세 `/help/inquiries/[id]`
  - `console`: 관제 콘솔 CS 처리함(SCR-045)의 문의 건 상세·답변 보내기·진행 경과 남기기·문의 닫기
  - `core-svc`: support 모듈(문의 접수·조회·추가 문의, 기록 저장, 닫힘·파기 작업, 관련 주문 확인), notify 모듈(답변 알림)
  - `ops-svc`: CS 처리함 건 등록과 답변·진행 경과·닫기의 권한·감사 로그
  - `gw-*`: API 게이트웨이(`gw-fan`, `gw-ops`)
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정)에서 돌린 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 보고서로 갱신한다.
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남기는 기록인 ADR을 반드시 쓴다)으로 나눈다.
