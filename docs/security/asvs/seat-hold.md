# ASVS 추적 표: 좌석 선택·홀드·실시간 좌석 전파

- **독자와 용도**: 좌석 기능(purchase-svc의 inventory 모듈, realtime-gw, 소비자 웹 좌석 화면, 파트너 좌석맵 가져오기)을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: [docs/features/seat-hold.md](../../features/seat-hold.md) 전체다. 좌석 스냅샷(어느 시점의 전체 좌석 상태를 찍어 둔 것)과 구매 세션 시작, Soft Hold Lua(좌석 Redis에서 여러 좌석을 한 번에 검사하고 잡는 스크립트. Redis는 메모리에 데이터를 두는 빠른 저장소다)와 자동 배정 Lua, 1인당 매수 한도, 홀드(결제하는 동안 다른 사람이 가져가지 못하게 좌석을 잠시 잡아 두는 것)의 TTL(정해 둔 유효 시간. 지나면 지워진다)·연장·만료·멈춤, 판매 확정(Hard Sale, PostgreSQL의 PENDING·SOLD와 1인 한도 조건부 갱신), 좌석 델타(바뀐 좌석만 담은 작은 메시지) 전파, 좌석맵 파일과 확대 표시, 파트너 좌석맵 가져오기 파일 해석(SVG·JSON·CSV)을 다룬다. 회차 판매 상태 판정과 좌석 Redis 장애 조치(세대·준비 표시)도 포함한다.
- **보안 검증 기준**: OWASP(웹 보안 기준을 만드는 비영리 단체)가 만든 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 따르고, 목표 레벨은 Level 2다. 인코딩·삽입 방지(V1), 검증과 업무 로직(V2), 웹 프런트엔드(V3), API(프로그램끼리 요청과 응답을 주고받는 창구)와 웹 서비스(V4), 파일 처리(V5), 인가(V8), 안전한 통신(V12), 설정(V13), 데이터 보호(V14), 안전한 코딩과 아키텍처(V15), 보안 로그와 오류 처리(V16)의 L1·L2 항목을 빠짐없이 판정한다. Level 3은 동시성 절(V15.4) 4개와 위험 구성 요소 격리(15.2.5, 좌석맵 해석 작업 `seatmap-worker`, open-items 70번 ②로 2026-10-30에 더함) 1개만 골라 싣는다. 구매 세션 소지 증명(서버 ECDH 키, 요청 인증 키, 일련번호)의 자체 완결형 토큰(V9)과 암호(V11)는 [대기열 추적 표](queue-admission.md)가 판정한다(ADR-0053). 이 표는 다시 판정하지 않고 가리키기만 한다. 입장 토큰(권한이나 상태를 증명하려고 주고받는 서명된 문자열)의 서명·만료 확인도 그 표의 V9가 판정한다. 로그인·세션·쿠키(브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 작은 값)는 [계정·인증 추적 표](auth.md)(V6·V7·V10 포함), 좌석 자동 배정의 희망 조건 검증과 대기열의 자동화 방지는 [봇 방어 추적 표](bot-defense.md), 주문 생성 뒤의 결제 흐름은 [결제 추적 표](payment.md), 좌석맵 배치본의 소유·테넌트 규칙과 템플릿은 [공연 탐색·후기 추적 표](catalog-review.md), 브라우저 쪽 이진 해독·Worker 메시지는 [프런트엔드 추적 표](frontend.md), 응답 보안 헤더와 게이트웨이(클라이언트 종류별로 앞에 둔 입구 서버)의 출처 검사 같은 공통 설정은 [전달 파이프라인 추적 표](delivery.md)를 따른다.
- **아키텍처 설계 근거**: [docs/features/seat-hold.md](../../features/seat-hold.md), [ADR-0007](../../adr/0007-service-boundaries-by-load-availability-runtime.md), [ADR-0014](../../adr/0014-soft-hold-hard-sale.md), [ADR-0053](../../adr/0053-crypto-hardening-pseudonyms-webhooks-stores-runbook-audit.md), [ADR-0063](../../adr/0063-screen-redesign-owner-feedback.md), [ADR-0065](../../adr/0065-web-frontend-security-after-asvs-v3.md), [ADR-0103](../../adr/0103-control-as-state-startup-sync-broadcast-topics-compacted-settings.md), [ADR-0121](../../adr/0121-seat-redis-failover-defer-purchase-drop-db-hold-path.md), [ADR-0124](../../adr/0124-purchase-session-proof-threat-table-theft-test-revert-condition.md), [docs/data.md](../../data.md) §2·§3, [docs/api/openapi.yaml](../../api/openapi.yaml)(`seats` 태그, `seatmap-imports`), [docs/api/asyncapi.yaml](../../api/asyncapi.yaml)(`ws.seat-delta`), [docs/frontend.md](../../frontend.md) §4.4·§5.14, [docs/security/data-classification.md](../data-classification.md), docs/planning/03 §2.3·§3
- **문서 상태 및 일정**: 항목 선정을 마쳤고 구현 직전 단계다(2026-10-30 수립, ADR-0154 결정 3). 원문 설계서에 없던 문서라 전체가 [보완]이다. 요구사항 요약은 이 저장소의 다른 ASVS 추적 표에서 원문과 대조해 둔 같은 ID의 문장을 그대로 쓴다(ADR-0087 결정 30). 그 표들에 없던 V15.4의 L3 셋(15.4.1·15.4.3·15.4.4)은 OWASP ASVS 저장소 `v5.0.0` 태그의 `0x24-V15-Secure-Coding-and-Architecture.md` 원문과 대조했다(2026-10-30). 판정하면서 찾은 설계 빈틈 다섯 가지(구매 세션의 회차 묶기, 판매 제외석·없는 좌석 거절, 해제·연장의 소유 확인, 좌석 구독 요청 검사, 좌석맵 가져오기 파일 처리)는 docs/features/seat-hold.md §2·§3·§7·§10에 '(추천 적용 2026-10-30)'으로 더했다. Phase 2 좌석 작업(wbs 2.5) 시작 전에 다시 판정한다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `purchase-svc`: inventory 모듈(스냅샷, 홀드·해제·연장·만료 Lua, 자동 배정 Lua, 판매 확정의 PENDING·SOLD와 1인 한도 조건부 갱신, 회차 판매 상태 판정, 비트맵 다시 만들기, 홀드 원장 적재 소비자)과 구매 세션 확인
  - `realtime-gw`: 좌석 델타 WebSocket(연결을 열어 둔 채 서버와 브라우저가 주고받는 통신 방식). 구독 받기, 묶음 보내기, 좌석 Redis 샤드 Pub/Sub 구독
  - `좌석 Redis`: 좌석 클러스터(ElastiCache Valkey, 회차 해시 태그 `{event:E}` 슬롯)
  - `gw-fan`: 팬 API 게이트웨이(입장 토큰 서명·만료 확인, 로컬 레이트 리밋(일정 시간에 받는 요청 수의 상한), WebSocket 첫 연결 확인)
  - `apps/web`: 좌석 화면 `/booking/[eventId]/seats`(SCR-010, 좌석 Worker와 OffscreenCanvas, CMP-021 SeatMap, CMP-022 SeatList)
  - `core-svc`: catalog 모듈(좌석맵 배치본 저장, 좌석맵 가져오기 결과의 다시 검사, 좌석맵 파일 게시). 가져오기 파일은 해석하지 않고 `seatmap-worker`에 맡긴다
  - `seatmap-worker`: 좌석맵 가져오기 해석 작업(core-svc와 같은 이미지의 별도 배포). SVG·JSON·CSV 해석을 여기서만 한다. DB·Kafka·Redis 자격 증명과 AWS 권한이 없고, 저장소를 쓰지 않으며, 나가는 통신이 막혀 있다(소유자 결정 2026-10-30, open-items 70번 ②, seat-hold §10)
  - `apps/partner`: 파트너 좌석맵 에디터(SCR-022)
  - `CDN`: 공연 페이지 배포의 좌석맵 파일(원본 S3). CDN은 사용자 가까운 곳에 파일을 복사해 두고 대신 응답하는 전송망이다
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 보고서로 갱신한다. 태그를 붙일 수 있는 검사는 자동 시험, 정적 정책 검사(conftest·Kyverno 정책 시험 등), doc-check 규칙, 설정 검사다. 운영 설계로만 있는 행은 결과를 '설계 검사'로 적고, 운영을 띄우지 않는 동안은 통과로 세지 않는다(docs/architecture.md §8.2 4, 추천 적용 2026-10-28, 기술 검토 낮음-089). 그런 행은 구현 위치 끝에 '(운영 설계만)'을 붙인다(ADR-0147 결정 5).
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남긴 기록인 ADR 작성 필수)으로 나눈다.

## 법률 요구사항

좌석 선택·홀드에 직접 걸리는 보안·개인정보 법률 조항은 없어 행을 두지 않는다. 1인당 매수 한도(POL-011)는 판매 정책이고 법정 의무가 아니다. 매크로 부정구매 방지 의무(공연법 제4조의2 제2항)는 [봇 방어 추적 표](bot-defense.md), 주문·결제 기록 보존은 [결제 추적 표](payment.md), 대기열 진입 접속기록 보존은 [대기열 추적 표](queue-admission.md)의 법률 행이 맡는다. 좌석맵의 웹 접근성(대체 좌석 목록 SeatList, NFR-020)은 보안 통제가 아니라 접근성 요구로 seat-hold §10과 S-T18에서 관리한다.
