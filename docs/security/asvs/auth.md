# ASVS 추적 표: 계정·인증

- **독자와 용도**: 계정·인증 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 팬 소셜 로그인·회원가입·회원탈퇴, 파트너와 운영자의 관리자 로그인(다중 인증 MFA 강제), 분산 세션 관리, 마이페이지 계정 설정과 기기 제어 화면.
- **보안 검증 기준**: OWASP(웹 보안 기준을 만드는 비영리 단체)가 만든 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 따르고, 목표 레벨은 Level 2다. Level 1과 Level 2 통제 항목을 모두 판정한다. Level 3 항목은 프로젝트에서 골라 채택한 것만 싣는다.
- **검토 장별 구성**: V3 웹 프런트엔드 보안(로그인 화면과 인증 쿠키), V6 인증, V7 세션 관리, V8 인가, V9 자체 완결형 토큰, V10 OAuth·OIDC(다른 서비스 계정으로 로그인하게 하는 표준·그 위에 사용자 정보를 더한 로그인 표준) 연동, V11 암호화, V12 보안 통신, V13.3 비밀 관리, V14 데이터 보호. V13의 나머지 절(13.1·13.2·13.4)은 시스템 공통 설정이라 플랫폼 공통 추적 표에서 판정한다.
- **아키텍처 설계 근거**: [docs/features/identity.md](../../features/identity.md)(원문 설계서 섹션 6 '계정·인증'), [ADR-0001](../../adr/0001-fan-social-login-single-factor.md), [ADR-0011](../../adr/0011-token-lifecycle-and-login-responsibilities.md)(토큰 수명주기 및 로그인 책임 분립).
- **문서 상태 및 이력**: 선정을 마쳤고 구현 직전 단계다(2026-10-06 처음 수립, 2026-10-08 V9와 V10.3 재판정 완료, 2026-10-09 관리자 비밀번호 해시 방식을 PBKDF2-HMAC-SHA256으로 확정해 6.5.2·11.2.1·11.4.2와 고시 제7조 제1항 갱신 완료, 2026-10-15 V3 웹 프런트엔드 보안 절 추가와 쿠키 이름 접두사 결정(추천 적용), 2026-10-28 소셜 로그인을 앱 서버의 얇은 OIDC 클라이언트로 바꾸고 파트너 로그인을 gw-partner 경로로 옮겨 V3·7.1.3·10.1.2·13.3.1의 구현 위치를 고침(추천 적용, ADR-0119)).

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용(적용되는 계정 유형을 함께 적는다), 미적용으로 나눠 적는다.
- **구현 대상 컴포넌트**: 전체 마이크로서비스의 예정 위치를 적는다. `identity`는 identity-svc, `web BFF`는 소비자 웹의 Next.js(웹 화면을 만드는 프레임워크) 앱 서버가 가진 소셜 로그인 경로(얇은 OIDC 클라이언트: 로그인 시작·콜백·로그아웃)를 가리킨다(추천 적용 2026-10-28, ADR-0119. 지난 설계는 Auth.js 라우트 핸들러였고, PoC I-T51에서 그쪽으로 돌아가면 이 표의 Auth.js 판정을 되살린다).
- **테스트 결과**: 손으로 적는 것은 금지한다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트 러너가 `[ASVS v5.0.0-x.y.z]` 태그를 파싱해 자동으로 만든 리포트로 채운다. 태그를 붙일 수 있는 검사는 자동 시험, 정적 정책 검사(conftest·Kyverno 정책 시험 등), doc-check 규칙, 설정 검사다. 운영 설계로만 있는 행은 결과를 '설계 검사'로 적고, 운영을 띄우지 않는 동안은 통과로 세지 않는다(docs/architecture.md §8.2 4, 추천 적용 2026-10-28, 기술 검토 낮음-089).
- **미적용 사유 분류**: 해당 없음, IdP(로그인을 대신 처리해 주는 신원 제공자) 위임, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남긴 기록인 ADR 작성 필수)으로 나눈다.

CSP(페이지가 실행할 수 있는 스크립트의 출처를 정하는 브라우저 규칙) 항목(3.4.3)은 파트너·관제 콘솔의 CSP도 docs/architecture.md §6.3 '화면별 CSP'에 정해져 있어(추천 적용 2026-10-15, ADR-0065 결정 4) 적용이다. 운영 설계로만 있는 4건(12.1.3·12.3.3·12.3.4·13.3.2)은 서비스 메시와 EKS Pod Identity처럼 포트폴리오의 로컬 실행에는 없는 장치로만 지키는 행이다. 구현 위치 끝에 '(운영 설계만)'을 붙이고, 결과는 '설계 검사'로 세어 운영을 띄우지 않는 동안은 통과로 세지 않는다. 다른 추적 표는 시험을 시작할 때 같은 표시를 맞춘다(추천 적용 2026-10-29, ADR-0147 결정 5).

## 아키텍처 재판정 메모 (2026-10-09)

- 현장 스태프 기기 승인 로그인 아키텍처(FR-046, ADR-0030)를 정했으므로, 구현 시작 전 다음 영역을 자세히 다시 판정한다: V6 인증(RFC 8628 기기 승인 흐름, 확인 코드 대조로 피싱 막기, 이중 소지 기반 인증 요소), V7 세션 관리(현장 스태프 세션 토큰의 유효 기간, 오프라인 스캐너의 자체 타이머 만료, 현장 스태프 권한 해제의 실시간 전파), V8 인가(배정 회차와 게이트 범위의 인가, `gate_lead`의 수동 검표 판정 권한), V9 자체 완결형 토큰(대상 독자 `aud: "scanner"`, 기기 mTLS 인증서 지문에 묶기).
- 이 추적 표의 기능 범위를 현장 게이트 도메인으로 넓혀 함께 다룰지, 게이트 스캐너 전용 독립 추적 표(`docs/security/asvs/offline-gate.md`)를 새로 만들지는 Phase 5를 시작할 때 최종 확정한다(docs/architecture.md §8.2 절차를 따른다). 2026-10-13 현장 입장 검토에서 독립 추적 표를 새로 만들었다(아래 메모).
- 회원 탈퇴 수명주기(POL-033과 docs/planning/03 §1.5: 연계정보 HMAC 즉시 영구 파기, 결제한 미사용 티켓을 취소·환급한 뒤 탈퇴 확정, 받은 티켓은 결제자에게 돌려주기, 보낸 양도 요청 철회와 받은 양도 요청 거절, 결제 결과나 가상계좌 지연 환급을 기다릴 때 탈퇴 유예 202. 추천 적용 2026-10-14, ADR-0062)는 위 `v5.0.0-7.4.2`(세션 종료)와 개인정보 보호법 제21조 행(파기)으로 판정한다. 유예 중에는 로그인·환불 계좌 입력·알림만 허용하고 새 예매·주문·양도 요청은 409로 막는다. 그래서 세션 종료와 파기는 탈퇴가 끝날 때 한다. 돌려주기·철회가 양도 수락과 겹칠 때 티켓 행 잠금으로 한쪽만 성공하는지, 유예 중에 요청이 막히는지는 구현 때 시험으로 확인한다(identity I-T43).
- 여러 소셜 계정 연결과 계정 병합 파이프라인(FR-048, ADR-0038)을 정했으므로, 구현 전 다음 통제를 반영한다: V6.8(여러 IdP의 식별성을 서로 독립되게 보장, 6.8.1), V10.5.2(바뀌지 않는 `sub` 기준으로 식별하고 이메일 식별자 오용 막기), V7(흡수된 계정의 활성 세션을 즉시 만료하고 전파), V8(계정 병합 제안은 본인 세션에서만 조회·확정하도록 인가), 민감 작업 전 소셜 재인증 강제. 연결을 제안할 때 타인 계정이 있는지 캐내는 시도를 막으려고 정보 노출을 최소로 줄이는 정책도 판정에 넣는다.

## 아키텍처 재판정 메모 (2026-10-13)

- 현장 게이트 도메인(스캐너 기기 등록, 현장 스태프 초대 수락, 기기 승인 로그인, 스캐너 세션, 스캔 판정·업로드, 현장 예외 절차)은 `docs/security/asvs/offline-gate.md`에서 판정한다(ADR-0051). 위 2026-10-09 메모의 V6·V7·V8·V9 재판정 항목은 그 문서로 옮겼다. 그 사이 바뀐 것: 권한 해제는 15분 거부 목록 대신 서버가 요청마다 세션 상태를 확인한다(ASVS 7.4.1, 8.3.2). `gate_lead`의 수동 검표(티켓 번호 직접 입력)는 없애고 예외 통과로 바꿨다. 초대 토큰과 기기 승인 확인 코드는 URL 조각(`#`)에만 싣는다(ASVS 14.2.1).
- 이 문서(auth)의 판정 범위는 그대로다. 팬 기기(휴대폰) 쪽 초대 수락과 기기 승인 화면(SCR-050·051)의 소셜 로그인 세션은 이 문서의 V7 판정을 따른다.
