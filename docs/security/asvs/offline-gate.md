# ASVS 추적 표: 현장 입장(회전 QR 월렛·게이트 스캐너·현장 스태프)

- **독자와 용도**: 현장 입장(회전 QR 월렛·게이트 스캐너·현장 스태프) 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 스캐너 기기 등록·폐기, 현장 스태프 초대·수락, 스캐너 기기 승인 로그인과 현장 스태프 세션, 근무 준비와 기기 배치, 목록·변경분 동기화, 오프라인 입장 판정과 스캔 기록 업로드, 서버 입장 판정과 이상 표시, 부스 재발급과 예외 통과, 입장 기록 마감, 월렛의 입장용 휴대폰 등록과 회전 QR
- **보안 검증 기준**: 기준은 웹 보안 기준을 만드는 비영리 단체 OWASP가 만든 웹 앱 보안 검증 항목 목록 ASVS 5.0.0이고, 목표 레벨은 Level 2다. 업무 로직(V2 전 절), 웹 프런트엔드(V3.2·V3.3·V3.4·V3.5·V3.7. 스캐너 PWA, 월렛, 초대 수락·스캐너 승인 화면, 이 범위의 파트너·관제 화면), 인증 중 기기 승인에 걸리는 절(V6.1·V6.3·V6.5·V6.6), 세션(V7 전 절), 인가(V8 전 절), 필요한 정보를 서명된 문자열 안에 담은 자체 완결형 토큰(V9 전 절), 다른 서비스 계정으로 로그인하게 하는 표준인 OAuth(V10.1~V10.4. 이 경로는 그 위에 사용자 정보를 더한 로그인 표준인 OIDC를 쓰지 않아 V10.5~V10.7은 대상이 아니다), 암호(V11 전 절), 통신(V12 전 절), 설정(V13 전 절), 데이터 보호(V14 전 절), 안전한 코딩(V15.1~V15.3), 보안 로그와 오류 처리(V16 전 절)의 L1·L2 항목을 빠짐없이 판정한다. Level 3은 골라 채택한 5개만 싣는다. 팬 소셜 로그인·재인증과 관리 계정, 팬·관리 쿠키(브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 작은 값)는 [계정·인증 추적 표](auth.md)를, 취소·양도는 [양도·취소·환불 추적 표](transfer-refund.md)를 따른다.
- **아키텍처 설계 근거**: [docs/features/offline-gate.md](../../features/offline-gate.md), [docs/features/identity.md](../../features/identity.md) §6.1, [ADR-0025](../../adr/0025-rotating-qr-device-key-signature.md), [ADR-0030](../../adr/0030-gate-staff-event-scoped-role-device-approval.md), [ADR-0050](../../adr/0050-crypto-corrections-and-key-management.md), [ADR-0051](../../adr/0051-gate-process-end-to-end.md), [docs/security/secrets-and-keys.md](../secrets-and-keys.md), [docs/security/data-classification.md](../data-classification.md)
- **문서 상태 및 일정**: 항목 선정을 마쳤고 구현 직전 단계다(2026-10-13 작성). 요구사항 원문은 OWASP ASVS `v5.0.0_release` 원문과 대조했다(2026-10-13). auth.md에 '예정'으로 적혀 있던 현장 스태프 로그인 재판정(V6·V7·V8·V9)을 이 표가 맡는다. Phase 5 스캐너·현장 스태프 작업(wbs 5.4·5.5)을 시작하기 전에 다시 판정한다. 본 개발 전에 위험한 부분만 먼저 만들어 확인하는 시험인 기기 인증서 PoC(wbs 5.4.3)에서 대안 B(기기 키와 DPoP)로 바뀌면 V10·V12 행과 V3.5 행을 다시 판정한다. V3 절은 2026-10-15에 OWASP ASVS 저장소 `v5.0.0` 태그의 V3 장 원문과 대조해 더했다. 같은 날 ADR-0065 결정 1·10으로 설치형 앱처럼 쓰는 웹 앱인 스캐너 PWA의 호스트(`scanner.peaket.example`)와, 기기 인증만 요구하는 세 경로의 JSON·`Origin` 확인을 설계에 반영해 3.5.1·3.5.2·3.5.4의 근거 위치를 실제 문서로 옮겼다(교차 출처 요청에 기기 인증서가 실리는지는 PoC 5.4.3).

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `apps/scanner`: 스캐너 PWA(오프라인 판정, 스캔 큐, 변경분, 근무 준비, 현장 관리)
  - `apps/web`: 월렛(입장용 휴대폰 등록, 회전 QR, 부스 재발급 요청), 초대 수락·스캐너 승인 화면
  - `identity-svc`: 초대·수락, 기기 승인, 현장 스태프 토큰과 세션, 부스 본인확인 대조
  - `ticket-svc`: 기기 키, 목록·변경분, 스캔 수신과 입장 판정, 이상 표시, 부스 허용, 입장 기록 마감, 스캐너 기기 기록
  - `ops-svc`: 스캐너 기기 관리 화면, CS 처리함, 감사 로그, 관제 입장 탭
  - `gw-scanner`: mTLS(양쪽이 서로 인증서를 확인하는 TLS) 종료, 현장 스태프 토큰 검증, 토큰과 기기의 결속 확인, 스캐너 API(프로그램끼리 요청과 응답을 주고받는 창구) 응답 헤더(CloudFront를 거치지 않는다)
  - `gw-fan`·`gw-partner`·`gw-ops`, `CDN`: 월렛·휴대폰 화면과 파트너·관제 화면의 게이트웨이(클라이언트 종류별로 앞에 둔 입구 서버)와 CloudFront(AWS의 CDN) 배포(공통 응답 헤더)
  - 관리 앱: Android Enterprise 기기 관리(인증서 발급·갱신, 대안 B에서는 쓰지 않는다)
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 리포트로 갱신한다.
- **미적용 사유 분류**: 해당 없음, Phase 이연, 위험 수용(아키텍처 결정과 그 이유를 남긴 기록인 ADR 작성 필수)으로 나눈다.
