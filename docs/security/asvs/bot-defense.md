# ASVS 추적 표: 봇 방어

- **독자와 용도**: 봇 방어 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 사람 확인(Cloudflare Turnstile), trust-svc의 실시간 위험 점수 계산과 추가 검증 큐 격리, 허니팟 상호작용 감지, 새 판정 규칙의 그림자 실행(Shadow Execution), 탐지 품질과 오탐률(사람을 봇으로 잘못 잡는 비율) 실측(K6), 좌석 자동 배정 공연의 희망 조건 미리 입력과 차례 직전 직접 확인(ADR-0043).
- **보안 검증 기준**: OWASP(웹 보안 기준을 만드는 비영리 단체)가 만든 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 따르고, 목표 레벨은 Level 2다. 봇 방어에 직접 관련된 V2.1, V2.3, V2.4, V16 통제 항목과, 브라우저 쪽 통제인 사람 확인 위젯·허니팟·행동 신호·최초 방문 쿠키(브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 작은 값)의 V3 L1·L2 19개를 모두 판정한다. Level 3 권고 항목은 이 시스템에 골라 채택한 것만 싣는다. 로깅 인프라 보호(V16.2·V16.4)는 플랫폼 공통 추적 표(asvs/delivery.md)에서 다룬다. 일반 입력값 검증(V2.2)은 입력을 받는 기능별 표(payment·offline-gate·transfer-refund·settlement·analytics·catalog-review·support)에서 판정한다. 다만 좌석 자동 배정의 희망 조건처럼 봇 방어 흐름에 직접 들어가는 입력은 이 표에서 함께 판정한다(V2.2.1~2.2.3, ADR-0043). 수량이 한정된 자원의 이중 예약 방지(V2.3.3·2.3.4)는 좌석 추적 표(예정, 00-summary §9)와 결제 추적 표에서 판정한다.
- **아키텍처 설계 근거**: [docs/features/queue-admission.md](../../features/queue-admission.md) §7·§11, [ADR-0006](../../adr/0006-ticket-buyer-identity-verification-before-queue.md), [ADR-0012](../../adr/0012-queue-ordering-hybrid-shuffle-default.md), [ADR-0039](../../adr/0039-bot-detection-evaluation-protocol.md), [ADR-0041](../../adr/0041-fifo-speed-bot-countermeasures.md), [ADR-0043](../../adr/0043-auto-seat-preferences-before-turn.md), [docs/features/seat-hold.md](../../features/seat-hold.md) §3.
- **문서 상태 및 일정**: 항목 선정을 마쳤고 구현 직전 단계다(2026-10-11 수립, 2026-10-12 ADR-0043 반영, 2026-10-15 V3 웹 프런트엔드 보안 절 추가. 같은 날 ADR-0065 결정 9로 최초 방문 쿠키(`__Host-peaket_fv`)·행동 신호 전송 경로·허니팟 기록 조건을 설계에 정해 3.3.1~3.3.4·3.5.1·3.5.3을 적용으로 바꿨다). Phase 3를 시작할 때(할 일을 잘게 나눈 작업 목록인 WBS의 3.2.1) 마지막으로 다시 판정한다. 2026-10-20 ADR-0071로 판정 피처 일부(회차별 기기 공유 수, 호스팅·프록시 대역 진입 수)는 trust-svc가 Redis(메모리에 데이터를 두는 빠른 저장소)에서 바로 계산하기로 정했다. 또 Flink(흘러드는 이벤트를 실시간으로 계산하는 스트림 처리 엔진) `trust-reassess`의 대기 중 재평가(그림자 시작, 격리 상한)와 행동 신호 원시 적재를 2.4.1·2.4.2·16.3.3·16.3.4와 법률 행에 더했다(docs/streaming.md §5).

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 대상 컴포넌트**: 전체 마이크로서비스의 예정 위치를 적는다. `trust-svc`는 위험 점수와 추가 검증 큐, `queue-svc`는 로비와 사전 검증, `gw-*`는 API(프로그램끼리 요청과 응답을 주고받는 창구) 게이트웨이(클라이언트 종류별로 앞에 둔 입구 서버. 인증, 공통 정책, 안쪽 서비스로 넘기기를 맡는다) 계층, `web`·`apps/web`은 소비자 웹 화면, `CDN`은 CloudFront(AWS의 CDN) 배포다.
- **테스트 결과**: 손으로 적는 것은 금지한다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트 스위트의 `[ASVS v5.0.0-x.y.z]` 태그를 파싱해 자동으로 만든 리포트로 갱신한다.
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남긴 기록인 ADR 작성 필수)으로 나눈다.

## V3 웹 프런트엔드 보안(V3.2 의도치 않은 해석, V3.3 쿠키, V3.4 브라우저 보안 헤더, V3.5 브라우저 출처 분리, V3.6 외부 자원 무결성, V3.7 기타 브라우저 보안)

이 절은 사람 확인 위젯(CMP-047)을 싣는 소비자 웹 화면(공연 상세의 사전 검증, 로비 SCR-007, 추가 검증 SCR-009), 허니팟 요소·경로, 행동 신호 수집, 최초 방문 쿠키(ADR-0060 결정 11)를 판정한다. 관리 계정 로그인 화면(SCR-020·028)은 [계정·인증 추적 표](auth.md)가, 대기열 API·파일의 헤더와 CORS(다른 주소에서 온 요청을 브라우저가 허용할지 정하는 규칙)는 [대기열 추적 표](queue-admission.md)가 판정한다. 요약 문장은 OWASP ASVS 저장소 `v5.0.0` 태그의 V3 원문과 대조했고(2026-10-15), [공연 탐색·후기 추적 표](catalog-review.md)의 같은 요구 문장을 그대로 쓴다.

## 비즈니스 및 운영 메모

- 그림자 실행(Shadow Execution)과 표본 수동 검토는 모델 성능을 평가하려고 실제로 재는 수단이고, 직접 막는 통제가 아니다. 그래서 ASVS 통제 항목에 억지로 맞춰 넣지 않고, 위 측정 요구사항으로 따로 관리한다. 개인정보 처리는 POL-006과 data-classification의 행동 신호 규정을 엄격히 지킨다.
- 허니팟의 숨은 요소는 보조기기 사용자의 오작동을 막으려고 브라우저 접근성 트리(Accessibility Tree)에서 완전히 숨긴다(NFR-020). 화면 낭독기(화면의 글자를 소리로 읽어 주는 프로그램)가 닿을 수 있는 UI 요소를 허니팟으로 잘못 쓰면 심각한 오탐이 생기기 때문이다.
- 알려진 설계 한계(타인 명의 대여·도용 방어의 한계, 실서비스 환경의 탐지율 하한이 추정값인 점, 3단계 정교한 봇 목표치를 나중에 세우는 점, 장외 거래 감지 한계, 서킷 브레이커 작동 때의 탐지율 완화)는 docs/features/queue-admission.md §7과 planning/01 §5.2에 적어 두었다. ASVS 항목을 '적용'으로 판정하더라도 이 한계는 분명히 알고 관리한다.
