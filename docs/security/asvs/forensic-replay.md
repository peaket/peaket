# ASVS 추적 표: 포렌식 리플레이

- **독자와 용도**: 포렌식 리플레이 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 포렌식 리플레이(SCR-069, FR-071)는 지난 온세일(판매가 열리는 시각 앞뒤로 접속이 몰리는 기간)의 좌석 상태 변화와 홀드(결제하는 동안 다른 사람이 가져가지 못하게 좌석을 잠시 잡아 두는 것)·결제 흐름을 시간 순서로 다시 보는 기능이다. 구역·시간·결과로 거르고, 봇 후보를 찾아본다. 1단계는 합성 데이터만 쓰는 브라우저 데모 앱 `apps/forensics`(서버 없음)다. 2단계(출시 뒤 선택)는 관제 콘솔에서 분석 저장소의 가명 사건 기록을 회차·시간창 단위로 내려받아 다시 보는 연결이다.
- **보안 검증 기준**: OWASP ASVS 5.0.0(웹 보안 기준을 만드는 비영리 단체가 낸 웹 앱 보안 검증 항목 목록), 목표 레벨 Level 2다. 이 기능과 직접 관련된 V1, V2, V3, V4, V5, V8, V14, V16의 L1·L2 108개를 모두 판정하고, L3 5개를 골라 채택한다. 같은 저장소(`peaket-frontend`)의 공통 통제인 V11(브라우저 암호)·V13(설정)·V15(안전한 코딩과 공급망)은 [asvs/frontend.md](frontend.md)의 판정을 그대로 따르고, 앱 목록에 `forensics`를 더했다. 2단계의 서버·로그 쪽 공통 통제는 [asvs/analytics.md](analytics.md)·[asvs/auth.md](auth.md)를 따른다.
- **아키텍처 설계 근거**: [docs/features/forensic-replay.md](../../features/forensic-replay.md), [ADR-0080](../../adr/0080-forensic-replay-synthetic-demo-first.md), [ADR-0079](../../adr/0079-frontend-radio-detailed-design.md), [docs/frontend.md](../../frontend.md) §5.19, [docs/features/analytics.md](../../features/analytics.md) §11, POL-006.
- **문서 상태 및 일정**: 항목을 골랐고, 구현 직전 단계다(2026-10-21 수립, ADR-0080). 1단계는 wbs 7.7.1~7.7.3에서 구현과 시험 결과를 채운다. 요구사항 요약은 2026-10-23에 ID마다 ASVS 5.0.0 원문 기준 한 문장으로 맞췄다(ADR-0087 결정 30). '(2단계)'로 시작하는 구현 위치는 2단계를 시작할 때 이 표를 다시 판정한 뒤 만든다(2단계는 할 일을 잘게 나눈 작업 목록인 WBS 밖이고, 출시 뒤 선택이다).

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다. 이름은 아래 이름 가운데 하나를 쓴다.
  - `forensics`: 포렌식 리플레이 앱(1단계 데모, 정적 파일과 Worker), `forensics/gen`: 합성 시나리오를 만드는 Worker
  - `host`: 1단계 공개 위치(응답 헤더를 정할 수 있는 정적 호스팅, ADR-0080 결정 2)
  - `ops-svc`·`gw-ops`·`ops-api`·`console`: 2단계 내보내기 API(프로그램끼리 요청과 응답을 주고받는 창구), 관제 게이트웨이(콘솔 요청이 처음 닿는 입구 서버), 관제 게이트웨이가 받는 API 호스트(`ops-api.peaket.example`, openapi `servers`), 관제 콘솔 주소 아래 따로 여는 2단계 페이지(`/forensics`, 추천 적용 2026-10-21)
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 리포트로 갱신한다. 시험 ID는 docs/features/forensic-replay.md §8의 FX-T 번호다. 태그를 붙일 수 있는 검사는 자동 시험, 정적 정책 검사(conftest·Kyverno 정책 시험 등), doc-check 규칙, 설정 검사다. 운영 설계로만 있는 행은 결과를 '설계 검사'로 적고, 운영을 띄우지 않는 동안은 통과로 세지 않는다(docs/architecture.md §8.2 4, 추천 적용 2026-10-28, 기술 검토 낮음-089).
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 이유를 남기는 기록인 ADR 작성 필수)으로 나눈다.
