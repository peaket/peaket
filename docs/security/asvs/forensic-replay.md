# ASVS 추적 표: 사후 포렌식(포렌식 리플레이·부정 거래 조사)

- **독자와 용도**: 사후 포렌식 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 사후 포렌식은 온세일(판매가 열리는 시각 앞뒤로 접속이 몰리는 기간)이 끝난 뒤 실제 기록으로 봇·매크로 부정 예매를 찾고, 사람이 소명과 2인 승인을 거쳐 취소·이용 제한을 정하는 기능이다(FR-071~074, POL-046, [ADR-0171](../../adr/0171-post-sale-forensics-in-launch-scope.md)). 데이터 원천은 셋이고 이 표는 원천마다 따로 판정한다.
  - **조사 갈래**: 지정 부정 거래 조사관이 조사 저장소 `inv`(실명 계정에 이어지는 회차 기록)와 운영 DB로 후보 묶음(한 사람이나 한 조직이 쓰는 것으로 보이는 계정 모음)을 조사하고, 소명 요청(양도 잠금), 조치 요청(승인 업무 `FRAUD_ACTION`), 증거 묶음과 내보내기를 다룬다. 화면은 SCR-070·071, 조사 원천 리플레이(SCR-069), 승인 업무(SCR-046)의 사건 요약이다.
  - **연구 갈래**: 가명정보(추가 정보 없이는 누구인지 알 수 없게 바꾼 정보) 취급자가 분석 저장소 실버의 회차 가명 사건을 내려받아, 봇 판정 규칙을 개선하려고 가명 사건으로 가설을 세우고 다시 재생하며 분석하는 길이다. 그림자 실행은 이 갈래가 아니다(봇 판정 서비스의 운영 처리, ADR-0173 결정 8, 추천 적용 2026-10-31). 개인 조치에 쓰지 않는다.
  - **시험·시연 원천**: 합성 시나리오(프로그램이 만든 가짜 데이터)와 부하 시험 기록만 쓰는 브라우저 앱 `apps/forensics`(서버 없음)다.
- **보안 검증 기준**: OWASP ASVS 5.0.0(웹 보안 기준을 만드는 비영리 단체가 낸 웹 앱 보안 검증 항목 목록), 목표 레벨 Level 2다. 이 기능과 직접 관련된 V1, V2, V3, V4, V5, V8, V11, V12, V13, V14, V15, V16의 L1·L2 157개를 모두 판정하고, L3 10개를 골라 채택한다. 관리 계정 로그인·세션·재인증·쿠키(V6·V7·V9·V10)는 [계정·인증 추적 표](auth.md), 승인 업무의 공통 흐름(요청·승인·반려·철회·만료·실행)은 [양도·취소·환불 운영 추적 표](transfer-refund.md), 신고기관·수사기관 자료 요청의 등록·추출·제출(FR-034)은 [관제 추적 표](control-tower.md), 브라우저 앱 공통 통제(V11 브라우저 암호, V13 설정, V15 공급망의 화면 쪽)는 [프런트엔드 추적 표](frontend.md)를 따른다. 조사용 기록을 모으는 쪽(게이트웨이·대기열·구매·결제·판정의 수집 보강, 조사 적재)은 [봇 방어 추적 표](bot-defense.md)·[분석 추적 표](analytics.md)가 판정한다(2026-10-31 BUILD_ORDER FRN-040에서 더했다).
- **아키텍처 설계 근거**: [docs/features/forensic-replay.md](../../features/forensic-replay.md), [ADR-0171](../../adr/0171-post-sale-forensics-in-launch-scope.md), [ADR-0080](../../adr/0080-forensic-replay-synthetic-demo-first.md), [ADR-0079](../../adr/0079-frontend-radio-detailed-design.md), [ADR-0046](../../adr/0046-cancel-transfer-refund-approvals.md), [docs/frontend.md](../../frontend.md) §5.19, [docs/features/analytics.md](../../features/analytics.md) §11, docs/planning/03 §3('부정 거래 조사'·'부정 예매 조치'·'증거 묶음 보존·내보내기' 행), POL-006, POL-046, POL-038 ⑪, [docs/security/data-classification.md](../data-classification.md) 법률 확인 30~37번.
- **문서 상태 및 일정**: 항목을 골랐고, 구현 직전 단계다. 2026-10-21에 1단계(합성 데모)·2단계(출시 뒤 선택)로 세웠고(ADR-0080), 2026-10-31에 사후 포렌식이 출시 범위의 필수 기능이 되어(소유자 승인, ADR-0171) 조사·연구·시험 세 원천으로 다시 판정했다(BUILD_ORDER FRN-020). 예전 '(2단계)' 행은 연구 갈래 행이 되었고, 조사 갈래 행과 V11·V12·V13·V15의 서버 쪽 행을 새로 더했다. 요구사항 요약은 이 저장소의 다른 ASVS 추적 표가 원문과 대조해 둔 같은 ID의 문장을 그대로 쓴다(ADR-0087 결정 30). 새로 고른 L3 다섯(1.2.10·2.3.5·8.4.2·14.2.8·15.4.2)도 다른 표에 이미 있는 문장이다. 이 판정에서 찾은 설계 빈틈(외부 게시물 주소를 서버가 부르지 않기, 수집본의 원본과 보기용 사본 나누기, 연결 그래프의 칸 가림, 양도 잠금과 양도 수락의 경합)은 docs/features/forensic-replay.md §6.7에 '(추천 적용 2026-10-31)'로 넣었다. 데이터 분류·키 목록·권한 문서의 새 행은 FRN-040에서 더하므로 그 행을 가리키는 칸은 '부분 적용'으로 두었다. 2026-10-31 FRN-040에서 그 행들(data-classification의 조사 행과 처리방침 문구 초안, secrets-and-keys의 `inv-ref-key`·증거 저장소 KMS 키·해시 판, authz-matrix §3.7·§4.1, internal-management-plan §2.2·§4.2)을 더하고 부분 적용 넷(11.1.1·11.1.2·14.1.1·14.1.2)을 적용으로 다시 판정했다. 8.1.2·13.3.2와 법률 행의 구현 위치도 그 행에 맞췄다. 2026-10-31 FRN-050(화면 설계와 퍼블리싱, OpenSpec 변경 `add-fraud-investigation-screens`)에서 화면 쪽 줄을 다시 보고 14.3.1·14.3.3에 연 IP 원문을 화면 메모리에만 두는 것을 보탰다. 목업 퍼블리싱이라 위치 이름 `console`은 `apps/console-host`의 `pages/investigations`·`pages/investigation-case`·`pages/cs-approvals`(사건 요약)와 `entities/fraud-case`, `forensics`는 `apps/forensics`(원천 배지·원천별 후보 패널)를 가리킨다. 서버 연결과 시험 태그는 데이터 연결 단계에서 단다. 목업의 IP는 가린 값과 문서용 대역뿐이고 이를 `node --test` 시험(`[ASVS v5.0.0-14.2.6]`)이 본다. 2026-10-31 FRN-080에서 법률 확인 30~37번의 자체 법률 조사(ADR-0173, 법률 자문이 아니다)를 반영해 행을 다시 보았다: 처리 근거 제6호와 이익형량 기록, 승인자의 실질 관여(판단 이유 필수, 범위 줄이기, 사건 요약을 연 뒤에만 승인, 한꺼번에 승인 없음), 양도 잠금 14일 [가정] 상한과 돌려주기 허용, 받은 사람(`HOLDER`)의 사본, 고소·고발용 내보내기 `COMPLAINT`, 증거 묶음 목록의 요약, 행동 요약을 계정끼리 견주지 않음, 적정성 검토 전 연구 내보내기 403, 외부 게시물 최소화, 조사 저장소 보존 기준(그 회차 공연일 + 30일 [가정], 파기 작업 `inv-partition-purge`). 법률 행 둘(제20조, 제23조)을 더했다(추천 적용 2026-10-31, ADR-0173). 2026-10-31 FRN-090(화면 반영, OpenSpec 변경 `apply-legal-review-to-screens`)에서 FRN-080의 화면 줄을 퍼블리싱 화면에 옮기며 화면 쪽 행을 다시 보았고 판정은 바뀌지 않았다. 승인 화면(`console`의 `pages/cs-approvals`)의 판단 이유 칸·대상 줄 빼기·요약을 열기 전 [승인] 비활성과 한꺼번에 승인하는 칸이 없음(2.3.5), 외부 게시물 등록(`pages/investigations`)의 확인 칸 셋과 가릴 자리 고르기는 화면의 안내이고, 강제는 서버의 409·422다(8.3.1). 소비자 웹(`apps/web`)의 받은 사람 변형(SCR-042 `HOLDER`)은 결제자의 사유 범주·이용 제한·우선 구매를 싣지 않는다(authz-matrix §4.1). 목업 퍼블리싱이라 시험 태그는 데이터 연결 단계에서 단다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다. 이름은 아래 이름 가운데 하나를 쓴다.
  - `forensics`: 리플레이 앱(SCR-069, 세 원천이 함께 쓰는 정적 앱과 Worker. Worker는 화면과 따로 도는 브라우저 안 작업 스레드다). 시험·시연 빌드와 관제 콘솔 아래 운영 빌드가 있다. `forensics/gen`: 합성 시나리오를 만드는 Worker
  - `host`: 시험·시연 빌드의 공개 위치(응답 헤더를 정할 수 있는 정적 호스팅, ADR-0080 결정 2)
  - `console`: 관제 콘솔의 부정 거래 조사 화면(SCR-070·071), 승인 업무(SCR-046)의 사건 요약, 콘솔 주소 아래 따로 여는 리플레이 페이지(`/forensics`)
  - `ops-svc`: 조사 모듈(후보 묶음·사건·소명 요청·조치 요청·외부 게시물·증거 묶음·내보내기), 연구 갈래 내보내기, 배경 작업(기록 고정, 후보 만들기, 증거 묶음 검증·파기)
  - `gw-ops`·`ops-api`: 관제 게이트웨이(콘솔 요청이 처음 닿는 입구 서버)와 그 게이트웨이가 받는 API(프로그램끼리 요청과 응답을 주고받는 창구) 호스트(`ops-api.peaket.example`)
  - `ticket-svc`: 티켓의 양도 잠금(`ticket.fraud_lock_case_id`, `SetTransferLock`, 409 `transfer-locked`)
  - `support`: core-svc support 모듈(팬의 소명·이의 접수, `/v1/appeals`의 대상 종류 `FRAUD_CASE`)
  - `inv`: ClickHouse(대량 이벤트 집계에 강한 분석용 데이터베이스)의 조사 저장소. 쓰기는 조사 적재 작업자(DB 사용자 `inv_ingest`), 읽기는 `ops-svc`의 `inv_reader`, 보존이 끝난 회차 파티션 지우기는 파기 작업 `inv-partition-purge`의 `inv_purger`다(결과 기록은 ops DB `ops_purge_writer`, 추천 적용 2026-10-31, ADR-0173)
  - `증거 저장소`: 증거 묶음과 외부 게시물 수집본을 두는 비공개 S3(아마존의 파일 저장소) 버킷
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 리포트로 갱신한다. 시험 ID는 docs/features/forensic-replay.md §8의 FX-T 번호다. 태그를 붙일 수 있는 검사는 자동 시험, 정적 정책 검사(conftest·Kyverno 정책 시험 등), doc-check 규칙, 설정 검사다. 운영 설계로만 있는 행은 결과를 '설계 검사'로 적고, 운영을 띄우지 않는 동안은 통과로 세지 않는다(docs/architecture.md §8.2 4, 추천 적용 2026-10-28, 기술 검토 낮음-089). 그런 행은 구현 위치 끝에 '(운영 설계만)'을 붙인다(ADR-0147 결정 5).
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 이유를 남기는 기록인 ADR 작성 필수)으로 나눈다. '부분 적용' 행은 남은 몫을 미적용 사유 칸에 같은 분류로 적는다.
