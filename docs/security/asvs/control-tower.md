# ASVS 추적 표: 관제 콘솔의 운영 명령·법정 조치·보안 사고·접속기록 점검

- **독자와 용도**: 관제 콘솔(Control Tower)의 운영 명령과 법정 업무를 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: [docs/features/control-tower.md](../../features/control-tower.md)의 네 묶음이다.
  - 운영 명령: 명령 카탈로그 1~12(POL-021 B), 명령 수명주기와 2인 승인, dry-run(실행 전 예상 영향 미리 보기), 직접 제어 채널(제어 전용 gRPC. gRPC는 서비스끼리 함수를 부르듯 빠르게 호출하는 통신 방식이다)과 설정 제어 사건 `control.settings`, 받는 쪽의 제어 상태와 판 번호(그 범위·종류에서 늘어나기만 하는 수), 비상 런북(장애가 났을 때 따라 하는 절차서) CLI와 서명 묶음, 자동 제어와 사람 제어의 우선순위, 사후 검토 보고서, 감사 로그(이벤트 소싱, 키를 건 해시 체인, 앵커, 공개 체크포인트)와 인시던트(대응이 필요한 장애나 보안 사건) 리플레이, 경보 받기(Alertmanager 웹훅)와 판단 위젯·SSE 흐름(서버가 브라우저로 한 방향으로 계속 보내는 흐름)(§1~§8, §12)
  - 법정 조치: 신고기관·수사기관 통보 문서 등록과 게시물 노출 차단(명령 10), 같은 내용 차단, 법적 자료 요청서 검증·자료 추출·제공 대장(§9)
  - 보안 사고 등록과 신고·통지: 의무별 기한, 통지 문안과 보내는 규칙(§9, §9.1)
  - 접속기록 점검: 매일 이상 탐지와 월 정기 점검(§9)
- **보안 검증 기준**: OWASP(웹 보안 기준을 만드는 비영리 단체)가 만든 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 따르고, 목표 레벨은 Level 2다. 인코딩·삽입 방지(V1), 검증과 업무 로직(V2), 웹 프런트엔드(V3), API(프로그램끼리 요청과 응답을 주고받는 창구)와 웹 서비스(V4), 파일 처리(V5), 인가(V8), 암호(V11), 안전한 통신(V12), 설정(V13), 데이터 보호(V14), 안전한 코딩과 아키텍처(V15), 보안 로그와 오류 처리(V16)의 L1·L2 항목을 빠짐없이 판정한다. Level 3은 골라 채택한 4개만 싣는다. 관리 계정 로그인·세션·재인증·쿠키(브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 작은 값)(V6·V7·V9·V10)는 [계정·인증 추적 표](auth.md), 정산 화면(SCR-049)은 [정산 추적 표](settlement.md), CS 처리함·승인 업무·회차 취소는 [양도·취소·환불 운영 추적 표](transfer-refund.md), 홈 구성(SCR-068)은 [공연 탐색·후기 추적 표](catalog-review.md), 공연 리포트·결정 기록은 [분석 추적 표](analytics.md), 포렌식 리플레이는 [포렌식 리플레이 추적 표](forensic-replay.md), 관제 콘솔 원격 위젯의 브라우저 쪽 통제는 [프런트엔드 추적 표](frontend.md), 응답 보안 헤더·게이트웨이(클라이언트 종류별로 앞에 둔 입구 서버)의 출처 검사·사람의 운영 접근 같은 공통 설정은 [전달 파이프라인 추적 표](delivery.md)를 따른다. 파트너 실시간 판매 현황(§11)은 이 표의 범위가 아니다.
- **아키텍처 설계 근거**: [docs/features/control-tower.md](../../features/control-tower.md), [ADR-0049](../../adr/0049-onsale-alert-windows-and-ops-metrics.md), [ADR-0053](../../adr/0053-crypto-hardening-pseudonyms-webhooks-stores-runbook-audit.md) 결정 11·12, [ADR-0075](../../adr/0075-public-audit-anchor-signed-merkle-checkpoints.md), [ADR-0095](../../adr/0095-sale-pause-single-commander-and-two-person-approval-demo.md), [ADR-0102](../../adr/0102-control-plane-direct-grpc-dedicated-pool-ops-db-audit-chain-worker-break-glass.md), [ADR-0103](../../adr/0103-control-as-state-startup-sync-broadcast-topics-compacted-settings.md), [ADR-0143](../../adr/0143-settings-commands-pg-switch-over-grpc-applied-version-outbox.md), [ADR-0149](../../adr/0149-command-audit-actor-pseudonym-reference-and-3-year-mapping.md), planning/03 §1.1(POL-021 B)·§2.6·§3, [docs/api/openapi.yaml](../../api/openapi.yaml)(`ops` 태그의 `/v1/ops/commands*`, `/v1/ops/compliance/*`, `/v1/ops/live`), [docs/api/proto/](../../api/proto/README.md)(`peaket.control.v1.ControlReceiver`), [docs/security/data-classification.md](../data-classification.md), [docs/security/secrets-and-keys.md](../secrets-and-keys.md), [docs/data.md](../../data.md) §4·§6
- **문서 상태 및 일정**: 항목 선정을 마쳤고 구현 직전 단계다(2026-10-30 수립, ADR-0154 결정 3). 원문 설계서에 없던 문서라 전체가 [보완]이다. 요구사항 요약은 이 저장소의 다른 ASVS 추적 표에서 원문과 대조해 둔 같은 ID의 문장을 그대로 쓴다(ADR-0087 결정 30). 그 표들에 없던 L3 둘(4.1.5·8.4.2)은 OWASP ASVS 저장소 `v5.0.0` 태그의 `0x13-V4-API-and-Web-Service.md`·`0x17-V8-Authorization.md` 원문과 대조했다(2026-10-30). 법률 행의 조문은 2026-10-30 국가법령정보센터 Open API(요청 머리 `Referer: https://www.law.go.kr/`를 붙이면 받는다)로 원문과 다시 대조했다(아래 '법률 요구사항' 첫 문단). 판정하면서 찾은 설계 빈틈 네 가지(경보 링크 허용 목록, 관제 AWS 권한 범위, 요청서·제출 파일 처리, 조회 역할의 칸 가림)는 docs/features/control-tower.md §5·§8·§9에 '(추천 적용 2026-10-30)'으로 더했다. 1인 기간의 접속기록 점검(자기 기록은 다른 commander만 점검하는데 commander가 한 명뿐이면 월 점검을 마칠 수 없다)은 정본(planning/03 §3 '자기 기록 제외')과 다른 예외가 필요해 고치지 않고 통합 담당에게 제안했다. Phase 4 관제 작업(wbs 4.4.1) 시작 전에 다시 판정한다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `console`: 관제 콘솔(`apps/console-host`와 원격 위젯). SCR-029 온세일 대시보드, SCR-030 운영 명령 제어 센터(CMP-036 CommandCard), SCR-031 감사 로그·인시던트 리플레이, SCR-032 법정 조치 관리
  - `ops-svc`: 명령 접수·dry-run·2인 승인·전달·ack·감사 원장, 감사 체인 작업자, 법정 조치(통보·차단 기록·자료 요청·대장), 보안 사고·신고·통지 기록, 접속기록 이상 탐지와 점검, SSE 흐름 둘, Alertmanager 웹훅 받기
  - `gw-ops`: 관제 게이트웨이(허용 IP 재확인, 원본 확인 머리, `Origin`, 관리 계정 쿠키)
  - `받는 쪽`: `admission-ctrl`·`purchase-svc`·`queue-svc`·`payment-svc`의 제어 포트(`ControlReceiver/ApplyControl`)와 `control.settings`를 읽는 각 서비스
  - `런북 Job`: `ops-breakglass` 네임스페이스의 비상 런북 Job(`peaket-runbook`)
  - `core-svc`: review 모듈(명령 10의 노출 차단과 같은 내용 차단), notify 모듈(보안 사고 통지 발송)
  - `CDN`: 관제 배포(웹 ACL의 허용 IP)와 `console` 배포의 응답 헤더 정책. CDN은 사용자 가까운 곳에 파일을 복사해 두고 대신 응답하는 전송망이다
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 보고서로 갱신한다. 태그를 붙일 수 있는 검사는 자동 시험, 정적 정책 검사(conftest·Kyverno 정책 시험 등), doc-check 규칙, 설정 검사다. 운영 설계로만 있는 행은 결과를 '설계 검사'로 적고, 운영을 띄우지 않는 동안은 통과로 세지 않는다(docs/architecture.md §8.2 4, 추천 적용 2026-10-28, 기술 검토 낮음-089). 그런 행은 구현 위치 끝에 '(운영 설계만)'을 붙인다(ADR-0147 결정 5).
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남긴 기록인 ADR 작성 필수)으로 나눈다.

## 법률 요구사항

조문과 기한은 2026-10-30 국가법령정보센터 Open API로 원문과 다시 대조했다. 대조한 판은 공연법(법률 제21582호, 2026-10-29 시행)과 같은 법 시행령(대통령령 제36615호, 2026-08-28 시행), 통신비밀보호법(법률 제21989호, 2026-10-02 시행), 전기통신사업법(법률 제21503호)과 같은 법 시행령(대통령령 제36735호까지 반영, 2026-10-01 시행), 정보통신망법(법률 제21988호, 2026-10-02 시행)과 같은 법 시행령 공포본(대통령령 제36735호, 2026-10-01 시행), 개인정보 보호법(법률 제21445호, 2026-09-11 시행)과 같은 법 시행령(대통령령 제36671호, 2026-09-11 시행)이다. 정보통신망법 시행령은 국가법령정보센터의 '현행' 통합본(대통령령 제36728호, 2026-10-02 시행)에 제36735호의 조문(§58의8·§58의9·§60의16)이 2026-10-30에도 들어 있지 않아, 연혁 목록의 제36735호 판으로 대조했다. 대조 결과 바꾼 것은 넷이다: 공연법 시행령의 조치 결과 제출(제2호 사목)을 더했고, 통신비밀보호법의 법원 허가 단서(긴급하면 요청 뒤 허가)와 연 2회 보고(제13조 제8항)를, 전기통신사업법 시행령의 보고·통보 기한(제53조 제2항)을 더했으며, 개인정보 보호법의 유출 신고 조항을 제34조 제4항으로 바로잡았다(2026-03-10 개정으로 가능성 통지 제2항이 생겨 신고가 제4항으로 밀렸다).
