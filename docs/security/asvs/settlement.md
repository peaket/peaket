# ASVS 추적 표: 정산 지급(결제사 지급대행)

- **독자와 용도**: 정산 지급(결제사 지급대행) 기능을 구현하거나 검토하는 엔지니어와 보안 검토자가, ASVS 5.0.0 항목마다 적용 여부·구현 위치·시험 결과·미적용 사유를 확인할 때 참조한다. 구현 전에 이 표를 먼저 쓴다(docs/architecture.md §8.2).
- **대상 기능 범위**: 회차 종료 뒤 결제사별 회차 정산서와 매주 상품 정산서(굿즈·부가 상품, 추천 적용 2026-10-14, ADR-0062)의 계산·통지·이의·확정, 결제사 지급대행(결제사가 PEAKET 대신 파트너 정산 계좌로 판매 대금을 보내는 서비스) 등록(PEAKET이 연동하는 결제사인 토스페이먼츠의 셀러 등록, 포트원의 파트너 등록, 예금주 확인), 지급 요청과 상태 동기화(토스페이먼츠 지급대행 API와 서명 웹훅, 포트원 콘솔 일괄 지급과 지급 내역 조회), 지급 보류(고객 신원 확인 절차인 KYC, 정산 계좌 변경, 이의), 정산서 수기 조정과 정산 계좌 변경 승인, 지급 뒤 환불·카드 이의제기 회수, 파트너 정산 화면(SCR-027, 상품 빌더 SCR-023의 [상품 정산] 탭)과 관제 콘솔 정산 지급 화면(SCR-049). 파트너가 등록한 주소로 판매·취소·정산 사건을 보내는 파트너 웹훅 발송(FR-025)의 나가는 연결도 이 표가 판정한다(추천 적용 2026-10-28, 기술 검토 중간-061. 알림·웹훅 전용 추적 표를 따로 두는 대신 파트너 쪽 외부 연결을 이미 판정하는 이 표에 더했다).
- **보안 검증 기준**: OWASP(웹 보안 기준을 만드는 비영리 단체)가 만든 웹 앱 보안 검증 항목 목록인 ASVS 5.0.0을 따르고, 목표 레벨은 Level 2다. 업무 로직(V2), 웹 프런트엔드(V3, 파트너 정산 화면·정산 계좌 변경과 관제 콘솔 정산 지급 화면), API와 웹 서비스(V4), 인가(V8), 암호(V11), 보안 통신(V12), 설정(V13), 데이터 보호(V14), 안전한 코딩(V15), 보안 로그와 오류 처리(V16)의 L1·L2 항목을 모두 판정한다. 인코딩과 삽입 방지(V1)도 L1·L2 항목을 모두 판정한다. 이의 설명·수기 조정 근거 같은 자유 입력, DB 조회, 결제사 응답 해석, 정산서·명단 CSV·XLSX·PDF 내려받기, 파트너 웹훅 발송(1.3.6 SSRF)이 있기 때문이다(추천 적용 2026-10-28, 기술 검토 낮음-090). Level 3은 골라 채택한 5개만 싣는다(1.2.10 CSV·수식 삽입은 2026-10-28에 더했다). 파트너 로그인과 재인증, 브라우저가 사이트별로 저장했다가 요청마다 함께 보내는 쿠키의 이름과 속성은 [계정·인증 추적 표](auth.md)를 따른다. 결제 승인·취소와 결제 웹훅은 [주문·결제 추적 표](payment.md)를, 팬 배상 송금은 [양도·취소·환불 추적 표](transfer-refund.md)를, 응답 보안 헤더와 게이트웨이의 출처 검사 같은 공통 설정은 [전달 파이프라인 추적 표](delivery.md)를 따른다.
- **아키텍처 설계 근거**: [docs/features/settlement.md](../../features/settlement.md), [ADR-0047](../../adr/0047-settlement-payout-via-pg-agency.md), [ADR-0044](../../adr/0044-dual-pg-selection-and-switchover.md), [ADR-0045](../../adr/0045-intermediary-legal-status.md), [ADR-0046](../../adr/0046-cancel-transfer-refund-approvals.md), [docs/features/payment.md](../../features/payment.md)
- **문서 상태 및 일정**: 항목 선정을 마쳤고 구현 직전 단계다(2026-10-13 수립, ADR-0047 반영). 요구사항 원문은 OWASP ASVS `v5.0.0_release` 원문과 대조했다(2026-10-13). V3 절은 OWASP ASVS 저장소 `v5.0.0` 태그의 V3 원문과 대조해 더했다(2026-10-15). 결제사 규격은 토스페이먼츠 지급대행 가이드·API 참조·웹훅 이벤트 문서와 포트원 API 명세 v1.16.0을 따른다(2026-10-13 확인). 정산 지급 작업 착수(wbs 7.2.3) 전에 다시 판정한다.

**작성 및 판독 가이드**

- **적용 여부**: 적용, 부분 적용, 미적용 중 하나로 적는다.
- **구현 위치**: 예정 위치를 적는다.
  - `payment-svc`: settlement 모듈(정산서, 지급, 파트너에게서 돌려받을 돈인 미수금), 결제사 지급 어댑터(토스페이먼츠 지급대행, 포트원 플랫폼), 지급 웹훅(일이 생기면 결제사가 우리 주소를 불러 알려 주는 방식) 검증
  - `core-svc`: 판매 승인과 결제사 등록 연결, 판매자 정보
  - `ops-svc`: 승인 업무, CS 처리함, 감사 로그, 관제 콘솔 REST·SSE(GraphQL은 2026-10-28 ADR-0100으로 뺐다)
  - `gw-*`: 클라이언트 종류별로 앞에 둔 입구 서버인 API(프로그램끼리 요청과 응답을 주고받는 창구) 게이트웨이
  - `partner`·`console`: 파트너 콘솔 정산 리포트(SCR-027)·상품 정산(SCR-023 [상품 정산] 탭)·정산 계좌 변경(SCR-020 설정), 관제 콘솔 정산 지급(SCR-049)·CS 처리함(SCR-045)·승인 업무(SCR-046) 화면
- **테스트 결과**: 손으로 적지 않는다. CI(코드를 올릴 때마다 자동으로 검사하고 빌드하는 과정) 테스트의 `[ASVS v5.0.0-x.y.z]` 태그를 읽어 만든 리포트로 갱신한다. 태그를 붙일 수 있는 검사는 자동 시험, 정적 정책 검사(conftest·Kyverno 정책 시험 등), doc-check 규칙, 설정 검사다. 운영 설계로만 있는 행은 결과를 '설계 검사'로 적고, 운영을 띄우지 않는 동안은 통과로 세지 않는다(docs/architecture.md §8.2 4, 추천 적용 2026-10-28, 기술 검토 낮음-089).
- **미적용 사유 분류**: 해당 없음, 나중 Phase로 미룸, 위험 수용(아키텍처 결정과 그 이유를 남긴 기록인 ADR 작성 필수)으로 나눈다.
