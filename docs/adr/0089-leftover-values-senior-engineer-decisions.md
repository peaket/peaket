# ADR-0089: 4차 점검에서 남긴 값 정하기 — 요청 한도, 시간 초과, 의존성 고정, 관리 도구 접속, 대사, 환급 계좌, 접속기록, 데이터 분류, 비밀 목록, heat 팔레트, CloudFront 지표(2026-10-26)

- **상태**: 채택 (2026-10-26. 소유자 요청 "남긴 것들은 합리적으로 시니어 개발자 관점에서 정해주세요"에 따라, ADR-0088 '남는 한계'와 4차 점검 3부(review R-101)가 남긴 빈칸을 정했다. 모두 추천 적용이다. 추천 적용은 소유자가 방향을 승인하고 세부를 맡긴 부분에서 제안해 적용한 값으로, 바꾸고 싶으면 언제든 바꾼다. 같은 요청의 "글자 깨진건 고쳐주시고요"에 따른 ADR-0011 본문 복원은 결정이 아니라 일회성 예외 처리라 review R-102에 적었다. 질문 48은 소유자 결정을 기다린다) 2026-10-27(ADR-0099): Flink를 빼서 결정 3의 Gradle 부분(잠금 파일·의존성 검증·`exclusiveContent`)은 쓸 곳이 없어졌다. dbt의 `uv.lock` 고정과 npm 레지스트리 고정은 그대로다. 2026-10-28(기술 검토 높음-21, 소유자 승인 '추천안 동의'): 결정 7의 로그인 접속기록 줄에 파드마다 늘어나기만 하는 일련번호 `seq`를 싣고, 대조 잡이 빈 번호를 세어 하나라도 있으면 SEV2로 알린다. 줄은 '잃지 않는 갈래'(읽은 위치 저장·디스크 큐·끝없는 재시도)로 간다. 로그인 줄에 대조 차이가 거듭 나오면 identity-svc만 Outbox 경로로 바꾼다(결정 7 되돌릴 조건과 같은 방향, docs/observability.md §7). 2026-10-28(기술 검토 낮음-171, 소유자 승인 '추천안 동의'): 결정 4의 '공개 엔드포인트는 허용 대역으로만 연다'를 '사설 엔드포인트만 두고 공개 엔드포인트는 끈다'로 바꾼다(검토의 둘째 안, 추천 적용). 검토한 대안 절이 든 이유('GitHub 호스트 러너만 쓰는 CI와 처음 설치를 막아서')는 같은 결정의 'CI는 쿠버네티스 API를 부르지 않고 클러스터 안 설치는 ArgoCD가 하며 Terraform은 AWS API만 쓴다'와 맞지 않았다. 사람의 접속은 VPC로 이어진 VPN이나, SSM 세션 관리자의 원격 호스트 포트 포워딩(`AWS-StartPortForwardingSessionToRemoteHost`)으로 사설 서브넷의 중계 인스턴스를 거쳐 사설 엔드포인트에 닿는다. ArgoCD를 처음 올리는 일과 긴급 접근·비상 런북 Job 만들기도 이 길로 하므로 VPN이 멈춰도 막히지 않는다. 그래서 되돌릴 조건의 '자체 호스트 러너를 들이면 공개 엔드포인트를 끈다'는 이미 이루어졌다(docs/devops.md §10.1). 2026-10-30(ADR-0154·0160): '남는 한계'의 굿즈 주문 본문은 요청 본문과 판매자 제공 동의 칸을 넣어 풀었고, 웹 푸시 구독·찜 엔터티는 이미 docs/data.md에 있었다. 2026-10-30(open-items 13번): '남는 한계'의 Mimir 시간 초과는 소스로 확인했다. Mimir 3.2.3의 query-frontend는 querier로 보낼 요청을 새로 만들며 `timeout`을 빼므로, 클라이언트가 35초에 끊는 규칙을 그대로 둔다(docs/observability.md §14, docs/architecture.md §5).

## 맥락

- 4차 점검 3부(ADR-0088)는 정본에 값이 없어 다음을 남겼다: 리포트·결정 기록 API의 요청 한도, 분석 저장소 호출의 시간 초과·재시도, Gradle·PyPI 의존성의 저장소 고정, 관리 도구와 원격 접속의 전송 암호화를 한곳에 모은 규칙, 자정 대사와 자정 오픈의 겹침, 환급 계좌 화면(SCR-060)의 API 경로, ADR-0062~0065 범위가 빠진 WBS 작업 설명, 데이터 분류표의 동의·구독·예매 제한 행, 비밀 목록의 평가 기간 Datadog 키·발송 대행·공연예술통합전산망 자격 증명 행, 좌석맵 heat 팔레트, 로그인 접속기록을 접속기록 DB에 넣는 경로, CloudFront 지표를 Prometheus·Mimir로 가져오는 경로.
- 고르는 기준(시니어 개발자 관점): ① 이미 있는 장치와 규칙을 다시 쓴다. 새 토픽·새 서비스·새 저장소를 늘리지 않는다. ② 실패해도 안전한 쪽을 고른다. 돈이 나갈 계좌를 정하는 작업에는 재인증을 두고, 법정 기록은 잃지 않는 길로 보낸다. ③ 측정 전 값은 [가정]으로 두고 확정할 WBS 작업을 적는다. ④ 정본 한 곳에 적고 나머지 문서는 그곳을 가리킨다.
- 외부 사실(ClickHouse 설정·쿼터, `@clickhouse/client`, dbt-clickhouse, Prometheus·Mimir 시간 초과, AWS SDK 재시도, Gradle·pip·uv·Renovate, EKS 엔드포인트, SSM 세션 관리자, CloudFront 지표와 한도, YACE)은 2026-10-26에 각 공식 문서로 확인했다.

## 결정

### 가. 요청 처리와 의존성

1. **리포트·결정 기록 API의 요청 한도**: 분석 저장소를 읽는 리포트 조회는 계정당 30회/분, 결정 기록 쓰기는 계정당 10회/분 [가정, Phase 4 4.3.6에서 확정]이다(docs/api/guidelines.md §6). 그 뒤에서 화면이 부르는 ClickHouse 읽기 사용자는 읽기 전용 설정 프로필로 쿼리마다 실행 시간 10초·메모리 2GiB를 넘지 못하게 하고, 쿼터로 1분에 쿼리 300개(Grafana용은 120개)를 넘으면 거절한다(docs/features/analytics.md §11). `readonly=1`이면 쿼리가 설정을 바꿀 수 없어, `max_execution_time`에만 `CHANGEABLE_IN_READONLY` 제약을 걸어 더 짧게 끊을 수 있게 한다. 쿼터는 서버마다 따로 센다.
2. **분석 저장소 호출의 시간 초과와 재시도**: docs/architecture.md §5 '시간 초과 기본값' 표에 네 행을 더한다. ClickHouse 리포트 조회는 서버 10초·클라이언트 12초에 재시도 없음, 마감 변환(dbt)은 문장마다 300초·회차당 20분에 다음 실행이 처음부터 다시 만들고 같은 회차가 3번 연달아 실패하면 간격을 30분·60분으로 늘린다. Mimir 조회는 클라이언트 35초에 두 번까지 다시 묻는다(지수 백오프와 무작위 흔들기). S3는 AWS SDK 표준 재시도 모드·최대 3번 시도를 설정에 못박고, 끝내지 못한 멀티파트 업로드는 수명 규칙으로 지운다.
3. **Gradle·PyPI 의존성 고정**: `peaket-data`의 Gradle은 잠금 파일·의존성 검증 파일(SHA-256)을 두고, 저장소 내용 필터(`exclusiveContent`)로 `io.peaket` 그룹은 GitHub Packages에서만, 나머지는 Maven Central에서만 받는다. dbt 이미지의 Python 의존성은 해시가 든 `uv.lock`으로 고정하고 PyPI 하나만 쓴다(`--extra-index-url` 금지). Renovate의 3일 대기를 두 생태계에도 걸고, Renovate가 보지 못하는 전이 의존성은 uv의 `--exclude-newer`로 막는다(docs/devops.md §4.4).
4. **관리 도구와 원격 접속의 전송 암호화**: Grafana·ArgoCD·Alertmanager는 허용 IP·VPN으로만 닿는 내부 로드 밸런서 뒤에서 HTTPS(TLS 1.2 이상)와 SSO·MFA만 받는다. 쿠버네티스 API는 사설 엔드포인트를 켜고 공개 엔드포인트는 허용 대역으로만 연다. CI(GitHub 호스트 러너)는 쿠버네티스 API를 부르지 않고, 클러스터 안 설치는 ArgoCD가 한다. 노드는 SSH 대신 SSM 세션 관리자로만 들어가고, 세션 기록이 남지 않는 포트 포워딩은 CloudTrail과 대상 쪽 감사 기록으로 남긴다(docs/devops.md §10.1).

### 나. 돈과 기록

5. **대사 배치와 온세일**: 매일 자정 대사는 대형·중형 온세일 윈도우(T-10분~T+60분)에 걸리면 윈도우가 끝난 뒤 시작한다. 실행 중에 그런 윈도우가 시작되면 결제사 조회의 동시 호출을 1개로 낮춘다 [가정]. 늦어도 04시 [가정]에는 시작해 06시 정산서 계산 전에 끝낸다. 소형 온세일은 미루지 않는다(회차 취소 일괄 환불과 같은 기준, docs/features/payment.md §8, FR-041).
6. **지연 환급 계좌 경로와 재인증**: 환급을 미뤘던 취소의 계좌는 `POST /v1/cancellations/{cancellationId}/account`로 받는다(SCR-060). 배상금 계좌(`POST /v1/compensations/{compensationId}/account`, SCR-043)와 같은 꼴이다. 계좌는 저장하지 않고 결제사 취소 요청에 바로 넘긴다. 돈이 나갈 계좌를 정하는 작업이라 두 경로 모두 소셜 재인증(5분 1회용 토큰)을 거친다(POL-019 재인증 목록에 더함). 남의 취소 건이면 존재를 드러내지 않게 404로 답한다.
7. **로그인 접속기록 경로와 관리 계정 사본**: 로그인·재인증·로그아웃·토큰 갱신은 게이트웨이를 거치지 않는 호출(웹 앱 서버가 identity-svc를 안쪽으로 부르는 팬 로그인)이 있다. 그래서 identity-svc가 사건마다 접속기록 줄(JSON 한 줄)을 표준 출력에 쓰고, 에이전트 수집기가 이 줄만 골라 게이트웨이 접근 로그와 같은 법정 사본 갈래로 접속기록 DB에 보낸다. 일반 로그(Loki)에는 보내지 않는다(docs/observability.md §7). 관리 계정의 줄은 ops-svc가 매일 00:10 감사 체크포인트 전에 접속기록 DB에서 읽어 감사 저장소에 덧붙이고 최소 2년 둔다. 이 읽기는 행 정책으로 관리 계정 줄만 보이는 전용 사용자로 한다(docs/features/control-tower.md §7).
8. **데이터 분류표의 세 행**: 법정 보존 기간이 따로 없는 기록은 그 기록이 딸린 기록과 같은 수명으로 두거나 쓰임이 끝나면 지우고, 새 법률 해석을 만들지 않는다(POL-027 목록 수는 그대로다). ① 법적 동의 기록: 가입 때의 동의(이용약관, 개인정보 수집·이용, 휴대폰 번호 수집)는 identity `consent`에 두고 탈퇴 때 지운다(선택 동의는 철회 때). 예매의 판매자 제공·판매 조건 동의, 굿즈 택배의 판매자 제공 동의, 현장 스태프의 두 동의는 각 주문 원장·굿즈 주문·배정 원장에 고지 문안의 판(`consent_version`)으로 두어 그 기록과 함께 보존하고 지운다(주문은 5년, 배정은 회차 종료 1년). ② 오픈 알림·취소표 알림 신청(`notification_subscription`, core 논리 DB): 끄면 바로 지운다. 오픈 알림 신청은 그 회차의 오픈 시각이 지나면(오픈 30분 전 구독 수를 수요 예측이 남긴 뒤) 지우고, 끝난 취소표 알림 신청과 남은 신청은 그 회차의 공연 종료 예정 시각에 지운다. 탈퇴하면 바로 지운다. 근거는 알림 발송 기록과 같은 개인정보 보호법 §15①4호다. ③ 예매 제한 기록(`booking_restriction`): 제한이 끝나거나 탈퇴한 날부터 3년 뒤 지운다(승인 업무·소명 본문과 같은 전자상거래법 시행령 §6①4호). 연계정보·pid는 넣지 않는다. docs/data.md에 `consent`·`notification_subscription` 엔터티와 세 기록의 `consent_version` 칸을 더했다.
9. **비밀 목록의 세 행**: ① Datadog API 키·애플리케이션 키는 wbs 4.8.2의 14일 체험에만 쓴다. API 키는 평가 전용으로 따로 만들고, 애플리케이션 키는 Datadog 서비스 계정이 갖게 해 조회 범위만 준다. 정기 교체 없이 체험이 끝나기 전 둘 다 폐기하고, 판정이 Datadog이면 운영 키를 새 행으로 올린다. 합성 데이터만 보낸다(한국 리전이 없다, ADR-0067). 키 사용 범위 표에 운영 환경·실제 이용자 데이터를 막는 행을 더했다. ② 발송 대행 자격 증명(이메일·알림톡·문자)은 대행사를 정하면(이메일은 wbs 5.6.1, 알림톡·문자는 wbs §7의 선정·계약) 이름을 바꾼다. 시험용과 실제 발송용을 나누고, 범위는 발송·결과 조회만, 교체는 1년(외부 연동 비밀 규칙)이다. IAM 역할로 인증하는 서비스면 정적 비밀을 두지 않는다. ③ 공연예술통합전산망 전송 자격 증명은 운영기관이 연동 규격과 함께 준다(wbs 7.3.3. 그 전에는 시뮬레이터라 비밀이 없다). 교체는 1년이고 core-svc 1일 전송 작업만 쓴다. 셋 다 Secrets Manager에 두고, 노출이 의심되면 RB-26으로 바로 폐기한다.

### 다. 화면·관측·일정

10. **좌석맵 heat 팔레트**: 좌석 상태와 SLO가 쓰지 않는 파랑 한 색의 명도 3단계를 PEAKET 확장 팔레트로 둔다(라이트 #E0F1FF·#A9D2FE·#6DB0F4, 다크 #192D41·#1A4268·#1D5B92, design/tokens.json). 면은 늘 글자나 표 보기와 함께 쓰는 보조 표시이고, 면 위 글자는 `text`만 쓴다(대비 6.43:1 이상, design/d2 §5). 전체 배치의 등급 면은 가격이 높은 등급부터 heat.3·heat.2·heat.1을 칠하고 넷째 등급부터는 칠하지 않는다. 구역별 남은 좌석 히트맵은 남은 비율 50% 이상·10% 이상·10% 미만으로 heat.1·heat.2·heat.3을 칠한다 [가정, 디자인 시안에서 확정].
11. **CloudFront 지표 경로**: CloudWatch(us-east-1)의 CloudFront `Requests` 1분 합계를 관측 클러스터의 YACE(prometheus-community의 CloudWatch 내보내기 도구)가 가져오고, Prometheus가 긁어 Mimir에 남긴다. 기록 규칙 `cloudfront:quota_usage:ratio`(배포별 1분 요청 수 ÷ 60 ÷ 승인 한도)를 SEV3 경보, R0 SLO 스냅샷, 회차 사실 F11이 함께 쓴다(docs/observability.md §8 지표 출처 표).
12. **WBS 작업 설명**: ADR-0062·0063·0065·0083·0085 범위가 빠진 작업 39개의 설명에 범위를 짧게 더하고 근거 열에 ADR 번호를 넣었다. 일수는 이미 wbs §6에 들어 있어 바뀌지 않는다(436일). wbs.csv가 md와 달랐던 5.4.3·5.4.6의 점검 항목 수(넷 → 다섯)도 맞췄고, 7.7.2·7.7.3의 근거 열에 ADR-0080을 더했다.

## 검토한 대안

- 결정 1: 일반 REST 한도(로그인 사용자당 60회/분)를 그대로 쓰는 안. ClickHouse 조회는 한 번이 무거워 낮췄다.
- 결정 2: 리포트 조회도 자동으로 다시 시도하는 안. 같은 무거운 쿼리를 겹쳐 보내 과부하를 키워 택하지 않았다.
- 결정 3: 사설 프록시 저장소로 모든 의존성을 받는 안. 운영 부담과 비용이 커서 포트폴리오 범위에 맞지 않는다.
- 결정 4: EKS 공개 엔드포인트를 완전히 끄는 안. GitHub 호스트 러너만 쓰는 CI(docs/devops.md §4.5)와 처음 설치를 막아서, 허용 대역으로 좁히는 쪽을 골랐다.
- 결정 5: 대사 실행 시각을 다른 시각(예: 03시)으로 옮기는 안. 요구사항(FR-041)의 '매일 자정'을 바꾸지 않고 겹칠 때만 미루는 쪽을 골랐다.
- 결정 6: 취소 요청 때 계좌를 미리 받아 두는 안. 계좌를 저장하지 않는다는 원칙(POL-014, ADR-0050 결정 3)과 맞지 않는다.
- 결정 7: 로그인 사건용 Kafka 토픽을 새로 두는 안. 토픽·계약·소비자가 늘어서 이미 있는 법정 사본 갈래를 다시 썼다. 관리 계정 사본은 identity-svc가 ops-svc를 바로 부르는 안도 있었지만, 하루 한 번 당겨 오는 쪽이 로그인 경로에 의존을 더하지 않는다.
- 결정 8: 모든 동의를 identity `consent` 한 표에 두는 안. 주문은 탈퇴 뒤에도 5년 분리 보관하고 월 파티션째 지우므로, 다른 논리 DB에 둔 동의의 수명을 따로 맞춰야 해서 택하지 않았다. 동의 기록을 일괄 5년 두는 안은 법정 기간이 없어(개인정보 보호법 §21①) 택하지 않았다. 예매 제한을 pid로 묶어 다시 가입한 계정에도 잇는 안은 탈퇴자의 연계정보를 남기지 않는 원칙(POL-033, ADR-0087 결정 18)과 맞지 않는다. 오픈 알림 신청을 알림을 보내자마자 지우는 안은 알림이 오픈 30분 전보다 일찍 나가면 수요 예측의 구독 수가 줄어 택하지 않았다.
- 결정 9: Datadog 키를 다른 외부 비밀처럼 1년 교체로 두는 안. 14일만 쓰는 키라 폐기 시점을 정하는 쪽이 맞다.
- 결정 10: 등급마다 다른 색(범주 팔레트)을 두는 안. 상태색과 겹치기 쉽고 등급에는 가격 순서가 있어 한 색의 명도 단계로 했다.
- 결정 11: CloudWatch 지표 스트림으로 밀어 넣는 안. 배포 셋·지표 하나에는 구성이 과하다. 공식 cloudwatch_exporter는 README가 유지보수자가 없다고 밝혀 YACE를 골랐다.

## 결과와 트레이드오프

- 고친 곳: 문서 41개(이 ADR 포함)에 고칠 문장 263건(에이전트 제안 183건, 직접 작성 80건). REST는 경로 167개·작업 183개, 오류 응답은 269개 가운데 265개가 Problem이다. 가정 표시는 9곳 늘었다(측정 전 값 4곳과 이 ADR 본문 5곳). WBS 일수(436일)와 FR·NFR·POL 수는 그대로다.
- 결정 6은 환급·배상 계좌 입력에 재인증 한 단계를 더한다. 결정 7의 관리 계정 사본은 하루 늦게 감사 저장소에 들어간다(그 사이에는 접속기록 DB에 있다). 결정 11의 사용률은 1분 평균이라 초 단위 순간 최고를 놓칠 수 있다. 결정 5는 정산서 계산 전에 대사를 끝내려고 미루는 데 상한(04시)을 둔다.

## 되돌릴 조건

- 결정 1: Phase 4 측정에서 정상 사용이 한도에 걸리면 올린다.
- 결정 3: Gradle에 전이 의존성 대기 장치가 생기거나 사설 프록시 저장소를 들이면 그쪽으로 바꾼다.
- 결정 4: 자체 호스트 러너를 들이면 공개 엔드포인트를 끈다.
- 결정 7: 접속기록 DB의 행 정책을 쓸 수 없으면 identity-svc가 Outbox로 ops-svc에 보내는 쪽으로 바꾼다.
- 결정 8: 법률 검토(wbs 7.4.1)가 동의 기록이나 예매 제한 기록의 보존 기간을 따로 정하면 그 값으로 바꾼다.
- 결정 9: 발송 대행사와 전산망 연동 규격이 정해지면 형식·범위·교체 주기를 그 규격대로 고친다.
- 결정 10: 디자인 시안에서 단계 구분이 약하면 명도 간격을 넓힌다.
- 결정 11: 초 단위 순간 최고가 필요하면 CloudFront 실시간 로그로 바꾼다.
