# ADR-0185: NFR-002 입장 임박 대기자의 차례 반영 목표를 p99 3초로 바꾼다(소유자 결정, 2026-11-04)

- **상태**: 채택(2026-11-04, 소유자 결정 "둘 다 추천대로", docs/review/open-items.md 104번 ①). ADR-0110 결정 2('NFR-002는 목표 p99 2초를 그대로 두고 입장 임박 구간의 설계를 바꾼다')의 목표 값만 바꾼다. 설계(만료 맞춤 `Expires`, 0.5초 폴링, 낡은 값 허용 없음)는 그대로다
- **관련**: NFR-002, Q-T47, ADR-0110, [docs/features/queue-admission.md](../features/queue-admission.md) §4, [docs/planning/02-requirements.md](../planning/02-requirements.md) §3.1·§3.2, docs/review/open-items.md 41번·104번, BUILD_ORDER PRF-085·HOT-340
- **관련 ID**: NFR-002, Q-T47

## 맥락

- NFR-002는 입장이 임박한 대기자(예상 대기 1분 이내, 보이는 탭)의 차례 반영을 p99 2초로 약속했다. ADR-0110은 그 2초를 단계 예산(생성 1초 + 캐시 0.1초 + 폴링 0.6초 + 왕복·그리기 0.3초)으로 나누고, 로컬 측정 Q-T47의 통과 기준을 CDN 계층 몫 0.2초를 남긴 p99 1.8초 [가정]로 두었다.
- 2026-11-03 Q-T47(BUILD_ORDER PRF-085)은 p99 2.48초(0.3초 늦은 생성 2.22초)로 넘었다. 원인은 캐시 계층이다. nginx는 `Expires`를 초 단위로 받아 그 초가 끝날 때까지 캐시를 살려, 매초 경계에 만드는 파일과 캐시의 다시 받기가 같은 경계에서 겹치고 캐시가 옛 파일을 1초 가까이 더 든다(ADR-0110 '측정', 따로 한 측정으로 확인). 같은 까닭으로 'Expires 뒤에 옛 파일을 다시 쓰지 않는다'도 깨졌다(가장 늦은 것 999ms·998ms).
- 길은 넷이었다(open-items 104번): ① 목표를 p99 3초로 ② 직접 선택 공연에도 차례 직전 직접 확인 ③ 입장 임박 구간 파일 주소에 생성 초 ④ `Expires`를 생성한 그 초로.

## 결정

1. **NFR-002의 입장 임박 대기자 차례 반영 목표를 p99 3초로 바꾼다(소유자 결정)**: 순번 조회 가용성 99.95%와 일반 대기자의 설계 식은 그대로다. 3초는 '다음 파일 생성 1초 + 캐시가 만료를 초 단위로 다뤄 더 드는 몫 최대 1초 + 폴링 대기 0.6초 + 캐시·왕복·그리기 0.4초'로 나눠 지킨다.
2. **로컬 판정(Q-T47)**: 차례 반영 지연 p99 2.8초 [가정] 이하(3초에서 로컬에서 재지 못하는 CDN 계층 몫 0.2초를 남긴다). 생성이 늦은 경우, 캐시가 `Expires` 뒤에 옛 파일을 내는 시간은 캐시의 만료 시계 한 단위(nginx 1초)에 시계 흔들림 0.2초를 더한 1.2초 미만이어야 한다(낡은 값 허용을 끈 것이 지켜지는지 본다. 켜 두면 옛 파일이 몇 초씩 남아 넘는다. 재 보니 최대 999ms·998ms라 한 단위 그대로는 1~2ms 차이라서 흔들림 폭을 둔다). 같은 측정(2026-11-03)을 이 기준으로 다시 판정하면 통과다: p99 2.48초·2.22초 ≤ 2.8초, 옛 파일 가장 늦은 것 999ms·998ms < 1.2초.
3. **설계는 바꾸지 않는다**: 입장 임박 구간의 만료 맞춤(`Expires` = 다음 생성 시각, `Cache-Control: public`, 낡은 값 허용 없음)과 0.5초 폴링을 그대로 둔다. 화면(HOT-340)에 바꿀 것이 없다. 운영 RUM 목표(`queue_reflect_seconds` p99)와 관측 SLO도 3초로 맞춘다.

## 검토한 대안

| 대안 | 문제 |
| --- | --- |
| ② 직접 선택 공연에도 차례 직전 직접 확인 | 원본 요청과 입장 확정 요청이 는다(ADR-0110이 기각한 까닭과 같다) |
| ③ 입장 임박 구간 파일 주소에 생성 초를 넣는다 | 캐시가 옛 파일을 들 수 없지만, CloudFront 계층 동작(41번)을 모르는 채 주소 규칙·화면·원본 경계 처리를 바꾼다 |
| ④ `Expires`를 생성한 그 초로 준다 | nginx는 다음 경계에 정확히 만료했지만 표준(RFC 9111)대로면 받자마자 낡은 응답이라 CloudFront가 아예 캐시하지 않을 수 있다(원본으로 몰림) |

## 결과와 트레이드오프

- 약속이 1초 느슨해진다. 차례가 온 사람이 알아채기까지 최악 1초쯤 더 걸려, 그동안 예매 입장 자리가 비는 시간이 는다. 늦게 알아챈 사람은 15분 유예가 받으므로 입장 기회를 잃지는 않는다.
- 공신력 있는 기준이 없는 자체 기준이라(§3.1 4번) 느슨하게 바꾼 사유와 재검토 조건을 아래에 둔다(§3.1 2번).

## 되돌릴 조건

- 선택 보정 `cloud-cdn`에서 CloudFront 계층이 `Expires`에 정확히 만료하는 것으로 나오면(41번) p99 2초로 다시 조이는 안을 본다.
- 운영 RUM `queue_reflect_seconds` p99가 3초를 넘으면 ②·③을 다시 본다.
