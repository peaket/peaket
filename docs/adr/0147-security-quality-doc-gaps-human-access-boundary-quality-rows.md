# ADR-0147: 상위 설계와 하위 문서 대조에서 나온 보안·품질 문서 보완(추천 적용 묶음, 2026-10-29)

- **상태**: 채택 (2026-10-29. 소유자 요청 "이제 /docs 경로에 있는 설계문서들의 내용이 그 아래 경로인 /api, /features, /quality, /security 에 온전히 잘 반영되어있는지 검토해주고 미진한 부분은 보완 다해주세요."에 따른 대조 점검(review R-166)의 판단이다. 방향은 소유자 요청이고, 세부는 모두 추천 적용이다.)
- **관련**: ADR-0054(전달 경로), ADR-0089(관리 도구 접근), ADR-0099(스트림 작업자), ADR-0102(비상 접근), ADR-0112(봇 평가), ADR-0141(MSK), [docs/security/threat-model.md](../security/threat-model.md), [docs/quality/quality-requirements.md](../quality/quality-requirements.md), [docs/perf-ledger.md](../perf-ledger.md) §7

## 맥락

위협 모델과 품질 명세가 상위 설계 문서(devops·infra·verification·observability)를 다 옮기지 못했고, 어디에 둘지 정해야 하는 것이 있었다.

## 결정

1. **위협 모델에 '사람의 운영 접근' 경계를 따로 둔다**: 관리 도구, 쿠버네티스 API, SSM, 긴급 접근 역할, 비상 접근 계정을 한 경계로 묶고 STRIDE로 다룬다. 전달 경로(§8, 산출물이 지나는 길)와는 다른 공격 면이라 섞지 않는다.
2. **Renovate는 자체 실행한다**: GitHub 재사용 워크플로와 GitHub 앱 설치 토큰으로 돌린다. 호스팅판을 쓰면 모든 저장소에 쓰기 권한을 가진 외부 서비스가 하나 더 생기기 때문이다. asvs/delivery의 외부 통신 목록에 npm·PyPI·Renovate·OpenSSF Scorecard·LocalStack 인증을 적는다.
3. **봇 판정 기준값은 Secrets Manager 매개변수로 둔다**: `peaket-trust` 저장소는 공개라 판정 기준값과 가중치를 코드에 두지 않는다. trust-svc만 읽는 매개변수로 두고, secrets-and-keys 목록에 행을 둔다(분기마다 실제 목록과 대조할 때 지워지지 않게). 암호 키가 아니라는 것은 '종류' 칸에 적는다.
4. **`trust-reassess`의 통제는 asvs/analytics 한 표에 모은다**: 스트림 작업자 셋의 실행 기반 판정이 이미 그 표에 있기 때문이다. ClickHouse `trust_raw_writer`, 세션·캐시 Redis RBAC 사용자(`tr:ra:` 접두사만), 작업자별 MSK 전용 역할과 원시 표 30일 보존을 적는다.
5. **ASVS 표의 '운영 설계만' 표시**: 운영 환경에서만 확인할 수 있는 행은 구현 위치 끝에 '(운영 설계만)'을 붙이고, 결과는 '설계 검사'로 센다. 지금은 모든 행이 미실행이라 auth 표부터 적용하고, 다른 표는 시험을 시작할 때 맞춘다.
6. **품질 명세에 빠진 목표 행을 더한다**: 값은 새로 정하지 않고 NFR·K를 가리키기만 한다.
   - QR-RE-4 복구성(NFR-015): AZ 장애 PostgreSQL RPO 0·RTO 5분, Redis RTO 30초, 리전 장애 RPO·RTO 24시간.
   - QR-RE-5 명령 전파(NFR-008, K8): p99 3초, 성공률 99.9%.
   - QR-PE-5 좌석 상태 전파(NFR-004, K4): p99 300ms, 판 번호 틈 스스로 메우기 99.9%.
   - QR-PE-6 관제 실시간 표 반영(NFR-009): p95 5초 미만, 누락률 0.1% 미만.
   - QR-PE-7 여정 지연 SLO 묶음(NFR-002·005·006·011).
   - QR-SE-2 봇 탐지(NFR-022, K6): 1·2단계 등급별 95% 이상, 사람 오탐 단측 95% 상한 0.5% 이하.
   - QR-RE-1에는 측정 지점(인그레스 게이트웨이 서버 쪽, 엣지 502·504 포함, ADR-0144)을 더한다.
7. **품질 명세의 증거 수준**: 표에 열을 더하지 않는다. 표 위에 한 줄로 'docs/perf-ledger.md §7 KPI별 증거 수준 표를 따른다'를 둔다. QR-PE-1은 '랩 측정으로 판정(K5), 실제 사용자 측정은 운영 뒤라 포트폴리오에서는 설계만'으로 고친다.
8. **PoC의 시험 ID 자리**: 엣지 함수 서명·비용 PoC와 로비 사람 확인 검증 부하 PoC는 queue-admission의 Q-T56·Q-T57로 둔다. 기능 문서가 없는 게이트웨이 차단 상한 PoC와 메시 웨이포인트 PoC는 verification의 V-T43·V-T44로 둔다.

## 검토한 대안

- 사람 접근을 전달 경로 표에 섞기: STRIDE 갈래가 겹치고 범위가 흐려진다.
- 품질 명세에 증거 수준 열 두기: 정본이 두 곳이 된다(문서 한 흐름 원칙).

## 결과와 트레이드오프

- 위협 모델과 품질 명세가 길어지지만, 상위 설계의 통제와 목표를 한 곳에서 찾을 수 있다.
