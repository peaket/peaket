# ADR-0235: 팬 계정 요약과 가입 마무리의 서버 구현, 그리고 세션이 끝난 까닭을 갱신 응답으로 알리는 길

- **상태**: 채택(2026-11-09, 추천 적용). BUILD_ORDER BOT-047. ADR-0202 결정 1·5와 ADR-0203의 서버 몫을 맡는다.
- **관련**: ADR-0202(팬 계정 요약), ADR-0203(가입 마무리), ADR-0209(로그인 수단이 바뀌면 다른 세션 끝내기), ADR-0143(Outbox), [docs/features/identity.md](../features/identity.md) §8 '팬 계정 요약·세션 종료 사유·가입 마무리의 첫 구현', [docs/frontend.md](../frontend.md) §3 '세션이 끝났을 때', [docs/design/d5-screen-blueprint.md](../design/d5-screen-blueprint.md) §3.5
- **관련 ID**: FR-001, FR-002, POL-019, POL-023, SCR-004, SCR-005, I-T77, I-T78, I-T79, I-T80, I-T81, I-T82

## 맥락

- 계약은 있는데 서버가 없어서 화면은 가짜 API로만 돌았다. 경로는 넷이다: 팬 계정 요약 `GET /v1/identity/me`, 가입 마무리, 닉네임 확인, 가입 취소.
- 로그인 화면(SCR-004)은 세션 종료 사유(`?ended=`)를 받아 안내한다. 그런데 사유를 화면에 알려 주는 길이 없었다. 토큰 갱신 실패(401)는 이유를 싣지 않았다.
- `consent`(동의 기록) 표와 닉네임 중복 키는 정의만 있고 만들어지지 않았다.
- 세션 행에는 끝난 시각만 있고 끝난 까닭은 없다. 끝난 까닭은 세션 종료 사건(Outbox, 보낼 사건을 DB 표에 먼저 적어 두는 방식)으로만 나간다.
- 처음 로그인 때 만든 계정이 가입을 마치지 않은 채로 남을 수 있다. 언제 치울지 정해 두지 않았다(ADR-0203 '결과').

## 결정

1. **세션 종료 사유는 세션 행에 남기고, 갱신 401의 오류 본문으로 알린다.**
   - 세션 행에 `terminated_reason`을 더한다. 세션을 끝내는 트랜잭션(여러 쓰기를 한꺼번에 반영하거나 되돌리는 DB 작업 단위)에서 끝난 시각과 함께 적는다.
   - 갱신(`POST /v1/identity/access-tokens`)이 401이면 오류 이름은 그대로 `refresh-token-invalid`이고, 사유를 알 수 있을 때만 확장 칸 `ended`를 싣는다.
   - 칸은 쿠키의 토큰이 끝난 세션의 지금·바로 앞 토큰일 때만 채운다. 토큰이 없거나 모양이 틀리거나 모르는 값이면 칸이 없다. 유휴·절대 만료로 끝난 세션도 칸이 없다. 그래서 사유로 남의 세션을 떠볼 수 없다.
   - 사유는 화면이 받는 팬 사유 일곱만이다: LOGOUT·ADMIN_FORCE·REFRESH_REUSE·DEVICE_LIMIT·MERGED·DELETE·LOGIN_METHOD_CHANGED. 재사용을 찾아낸 바로 그 응답도 REFRESH_REUSE를 싣는다.
   - 칸 이름은 로그인 화면의 주소 값과 같은 `ended`다.
   - 갱신이 탈퇴·병합된 계정의 세션을 끝낼 때는 계정 상태대로 DELETE·MERGED로 적는다. 지금까지는 병합된 계정도 DELETE로 적었다.
2. **화면은 갱신이 거절됐을 때 사유를 기억해, 로그인 화면으로 보낼 때 싣는다.**
   - `refreshOnce`가 401 본문의 `ended`를 허용 목록으로 걸러 그 문서의 메모리에 둔다.
   - 갱신 거절 뒤 로그인 화면으로 보내는 곳은 `loginHrefAfterRefresh(next)`로 `/login?next=&ended=` 주소를 만든다. 사유는 한 번 쓰면 지운다.
   - 셸 머리의 계정 요약은 비로그인으로 그리기만 하고 로그인 화면으로 보내지 않는다(ADR-0202 결정 2 그대로). 공개 화면을 보던 사람을 끌어내지 않는다.
   - 다만 그 요약이 비로그인으로 끝난 뒤 그 문서가 로그인 화면으로 보내면(가입 완료 화면의 비로그인 처리) 사유를 함께 싣는다.
3. **팬 계정 요약의 네 칸은 각자의 출처에서 읽는다.**
   - `nickname`: 계정 행의 닉네임. 가입 전이면 null이다.
   - `signupCompleted`: `age_verified`가 참이고 동의에 TERMS·PRIVACY_REQUIRED가 모두 있을 때 참이다.
   - `verified`: 토큰의 `ticket:buy`와 같은 출처(계정 클레임 포트)다. 그래서 정리 중인 계정이나 이용 제한을 이은 계정은 토큰과 같이 false다.
   - `hasStaffAssignment`: 포트로 둔다. `staff_assignment` 표를 만드는 단계(BUILD_ORDER GAT-210) 전까지는 늘 false다.
   - 부른 세션이 이미 끝났으면 401이다(원격 로그아웃 뒤 남은 15분의 토큰으로 읽지 못하게). 읽기만 하므로 행을 잠그지 않는다.
4. **가입 마무리의 저장(ADR-0203 결정 1·2 구현).**
   - 동의 네 종류를 `consent` 표에 적는다. 고지 문안의 판은 동의마다 그 문안이 있는 문서의 시행일이다. 이용약관은 `/policy/terms`, 개인정보 동의 둘은 `/policy/privacy`의 시행일(지금 2026-11-01)이고, 마케팅은 문서가 없는 가입 화면 문구라 같은 날로 둔다 [가정]. 동의 시각은 서버 시각이다.
   - 닉네임의 중복은 키로 본다. 키는 전각·반각처럼 모양만 다른 글자를 한 모양으로 맞추고(유니코드 NFKC 정규화) 대소문자를 없앤 값이다. 이 키 `account.nickname_key`에 UNIQUE를 건다. 같은 닉네임이 겹치면 키 잠금(`pg_advisory_xact_lock`)으로 하나씩 처리해 뒤쪽이 409 `nickname-taken`을 받는다.
   - 회원 코드는 가입 마무리에서 매긴다. 꼴은 `XXX-XXXX` 7자 [가정]이다. 글자는 0과 O, 1과 I·L처럼 헷갈리는 것을 뺀 32글자 표기(Crockford base32)를 쓴다(d5 SCR-017 예시 `PK7-42Q9`와 같은 꼴). 겹치면 새로 뽑는다.
   - 휴대폰 번호는 동의가 있을 때만 `account.phone`에 둔다. 본인확인으로 확인한 번호가 아니므로 조사용 연락처 가명(`account_contact_ref`의 PHONE)은 쓰지 않는다.
5. **닉네임 확인의 요청 한도는 세션마다 1분에 30번 [가정]이다.** 세션·캐시 Redis `id:nick:{세션 ID}`(1분)로 센다. Redis에 닿지 못하면 통과시킨다. 확인은 참고일 뿐이고 확정은 가입 마무리의 409이기 때문이다. 넘으면 429 `nickname-check-limited`와 `Retry-After`다.
6. **가입 취소(UNDER_14)는 계정을 정리 중으로 바꾸고 그 계정의 세션을 모두 끝낸다(사유 DELETE).** 응답이 팬 쿠키 둘을 지운다. 가입을 이미 마쳤으면 409 `signup-already-completed`다. 끝내기 뒤의 정리는 만 14세 미만 정리와 같이 정비 `withdrawal-finish`가 한다. 만 14세 미만으로 정리 중인 계정의 가입 마무리는 401이 아니라 403 `under-14`다. 본인확인 경로와 같은 답이고, 화면은 로그인 화면 대신 '만 14세 미만' 안내를 보인다.
7. **가입을 마치지 않은 계정은 정비가 치운다.** 만든 지 30일 [가정]이 지났고, 살아 있는 세션이 없고, 가입을 마치지 않았고, 본인확인 기록이 없는 ACTIVE 계정을 탈퇴와 같은 길로 지운다(하루 한 번, `signup-incomplete-purge`). 본인확인을 시작하는 경로는 가입 완료를 보지 않으므로 본인확인을 마친 가입 전 계정이 있을 수 있다. 그 계정은 지우지 않는다. 이 길로 지우면 pid를 잃고 대기열 키도 지우지 못한다. 본인확인 여부를 모르면 지우지 않는다. 한 계정이 실패해도 나머지를 끝까지 다룬다. 세션의 절대 만료가 30일이라 살아 있는 세션이 없는 쪽이 조건이다. 탈퇴 사건은 내지 않는다. 본인확인을 마치지 않아 사람 식별값(pid)이 없기 때문이다.
8. **게이트웨이 경로는 넘긴다.** gw-fan이 아직 없으므로(BUILD_ORDER HOT-400) 이 네 경로의 게이트웨이 설정은 HOT-400이 한다.
9. **병합의 대표 계정: 둘 다 본인확인 전이면 가입을 마친 계정이다(POL-034를 고침).** 가입 전 계정으로 로그인해 가입을 마친 계정을 합치면, 지금까지는 로그인한 쪽이 대표라 가입을 마친 계정의 닉네임·동의·회원 코드가 사라졌다.
   - 두 계정의 가입 여부가 같으면 지금처럼 지금 로그인한 계정이다.
   - 본인확인을 마친 쪽이 대표라는 규칙이 먼저다. 그래서 본인확인을 마친 가입 전 계정이 가입을 마친 계정을 흡수하는 경우는 남는 한계다.
   - 제안 뒤 가입 여부가 바뀌어 대표가 달라지면 본인확인 때와 같이 확정은 404이고 다시 제안한다.

## 결과

- 정본: identity §8(새 절)·§10.1·§12(I-T77~82), openapi(Problem `ended`, 경로 설명, `nickname-check-limited`), data.md(`session.terminated_reason`, `account.nickname_key`, Redis 키, §5 경합), frontend.md §3, asvs/auth.md를 고쳤다. 마이그레이션은 0029다.
- 쿠키를 지니고 있던 사람은 세션이 끝난 까닭을 로그인 화면에서 본다. 토큰이 없는 사람은 지금처럼 아무 사유도 받지 않는다.
- 값이 없는 칸(`ended` 없음)은 옛 응답과 같으므로 계약 깨짐이 아니다.
- 대가:
  - 사유 기억은 그 문서의 메모리뿐이다. 공개 화면에서 비로그인으로 그린 뒤 다른 문서로 옮겨 로그인하면 사유 안내는 없다.
  - 닉네임 확인 한도는 Redis가 끊긴 동안 풀린다. 닉네임은 비밀이 아니고 가입 마무리의 확정이 남는다.
  - 처음 로그인만 하고 떠난 계정의 이메일은 최대 30일 [가정] 남는다. 본인확인을 마친 가입 전 계정은 그 뒤에도 남는다.

## 다른 선택지

| 길 | 고르지 않은 까닭 |
| --- | --- |
| 세션 종료 사유를 응답 헤더로 알린다 | 화면이 오류 본문을 이미 읽을 수 있고, 교차 출처에서 헤더는 노출 설정이 따로 필요하다 |
| 사유를 `/login` 주소에 서버가 실어 보낸다 | 갱신은 화면 스크립트가 부르는 API 호출이라 서버가 이동을 주도하지 않는다 |
| 사유를 세션 종료 사건 저장소에서 찾아 답한다 | 갱신마다 다른 저장소를 읽어야 한다. 세션 행에 칸 하나면 같은 행을 읽는 데서 끝난다 |
| 닉네임 확인 한도를 파드 메모리로 센다 | 파드 수만큼 한도가 늘고 재시작하면 잊는다 |
| 가입 전 계정을 지우지 않고 둔다 | 동의 없이 받은 이메일이 끝없이 남는다(개인정보 최소화) |
