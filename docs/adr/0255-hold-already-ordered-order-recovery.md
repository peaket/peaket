# ADR-0255: 같은 구매 세션의 409 `hold-already-ordered`는 주문 ID를 함께 돌려준다

- **상태**: 채택(2026-11-09, 추천 적용). BUILD_ORDER HOT-358이 넘겨받은 일(HOT-355, ADR-0228).
- **관련**: ADR-0228, [docs/features/payment.md](../features/payment.md) §2 '주문 생성의 첫 구현', docs/api/guidelines.md §4·§12
- **관련 ID**: ASVS v5.0.0-8.2.2

## 맥락

주문 생성 응답을 잃으면 화면은 주문 ID를 모른다. 같은 본문이면 같은 멱등 키로 처음 201을 다시 받지만, 새로고침으로 키를 잊었거나 예매자 입력을 고쳐 다시 보내면 새 키가 되어 409 `hold-already-ordered`만 받는다. 그러면 결제를 이어 갈 길이 없고, 홀드도 끝까지 묶인다.

## 결정

1. 409 `hold-already-ordered`의 확장 칸 `orderId`에 그 홀드의 주문 ID를 싣는다. 싣는 조건은 주문의 계정과 구매 세션이 요청과 같을 때뿐이다. 다르면 칸을 뺀다(다른 사람의 주문 ID를 알리지 않는다). 이 응답은 홀드 확인(`h:{holdId}`와 Hash 소유)을 지난 뒤에만 나간다.
2. 화면은 `orderId`가 있으면 그 주문으로 결제를 잇고, 없으면 지금처럼 '다른 곳에서 진행 중' 안내를 보인다.
3. 조회는 `purchase_order.hold_id` 유일 인덱스 한 번이다.

## 고르지 않은 안

- **멱등 키를 탭 저장소에 두고 다시 쓰기**: 예매자 입력을 고치면 지문이 달라 422가 된다. 입력 고치기를 막을 수는 없다.
- **`GET /v1/orders?holdId=` 조회 API를 더하기**: 한 경우만을 위한 경로가 늘고, 소유 확인을 다시 만들어야 한다.

## 결과

응답을 잃어도 같은 구매 세션 안에서는 주문을 되찾아 결제로 간다. 예매자 입력을 고쳐 다시 눌렀어도 처음 만든 주문의 값으로 이어지므로, 화면은 이어 갈 때 입력을 다시 받지 않는다.
