# ADR-0269: K7 결제 확정은 20초 드레인 뒤 실제 시간으로 판정한다

- **상태**: 채택(2026-11-13, 소유자 승인 "K7 끝 경계 드레인 추가"). R-511.
- **관련**: [docs/verification.md](../verification.md) §3.9·§3.10, [docs/review/plans/BAT-033.md](../review/plans/BAT-033.md), [docs/review/measurements/BAT-033-k7-finish.md](../review/measurements/BAT-033-k7-finish.md)
- **관련 ID**: P-T1, P-T47, NFR-006, K7

## 맥락

- BAT-033/R-496은 본구간 마지막 3초 안에 시작한 반복을 `payment_p99_3000ms` 초과에서 뺐다. 끝에서 잘린 PENDING을 숨기지 않으려는 방법이었지만, 실제로 3초를 넘긴 드레인 결제까지 함께 뺄 수 있다.
- 2026-11-13 K7 진단(BAT-039, R-510)에서 `payment_confirm_ms` p99는 2,925.9ms로 3초 안이었지만 공식 `payment_p99_3000ms`는 405/9,812(4.13%)였다. 그중 PENDING 332(3.38%)가 대부분이었고, 16초 지연군은 55(0.56%)였다.
- 2026-11-13 R-511 드레인 진단에서도 PENDING 278(3.09%)가 남았다. `payment-status` 호출은 10,076건으로 결제 8,901건보다 1,175건 많았고, 278건이 4회를 다 썼다면 나머지는 결제당 1.04회꼴이다. 4회 고정 루프가 3초 전에 비끝 답으로 끝내 p99 3초를 재기 전에 포기했을 수 있다.
- 본구간이 끝난 뒤 새 결제를 멈추고 진행 중인 결제를 실제 시간으로 판정하는 드레인이 필요하다.

## 결정

1. main 시나리오에 k6 `gracefulStop: '20s'`를 둔다. 본구간 100초가 끝나면 새 반복을 시작하지 않고, 시작 가드와 접수 가드로 드레인 중 새 결제도 시작하지 않는다.
2. 드레인 중 끝난 결제는 접수 시작→끝 상태의 실제 시간으로 판정한다. 3,000ms 이하면 통과, 넘으면 위반이다.
3. 20초가 지나도 끝나지 않은 결제는 위반이다. `payment_started - payment_finished`를 `payment_drain_unfinished`로 남기고 `over_target`·`payment_outcomes PENDING`에 더한다.
4. 기존 3초 끝 경계 제외(`PAYMENT_END_GUARD_MS`·`paymentEndTruncated`·`payment_end_truncated*`)를 없앤다. `payment_drain_finished*`·`payment_drain_unfinished`로 대체한다.
5. 16초 지연군 0.5%는 p99.5에 남는다. `payment_confirm_ms` p99 <3초 목표와 공식 ≤1% 점검을 분리해 본다.
6. 끝 상태가 아닌 빠른 답(기다림 표가 참·멈춤 등)으로 끝내지 않는다. 빠른 비끝 답이면 100ms 쉬었다 다시 묻고, 접수 시작 후 최소 3,000ms까지 묻는다. 3,000ms가 지나도 끝 상태가 아니면 그때 위반으로 세고 멈춘다. 전체 상한은 드레인 20초와 맞춘다. 3초 전에 포기한 결제는 `payment_pending_before_3s`로 남긴다.

## 결과

- 공식 점검은 끝에서 잘린 PENDING을 더 이상 면제하지 않는다. 드레인 안에 끝난 결제는 실제 시간으로, 20초를 넘긴 결제는 위반으로 센다.
- PENDING은 더 이상 4회 고정 루프 때문에 3초 전에 끝나지 않는다. 3초가 지나도 비끝인 결제만 PENDING으로 남는다.
- K7 측정 창은 본구간 뒤 최대 20초 늘어난다.
- 0.5% 지연군은 p99.5에 남고, 공식 ≤1% 점검에는 0.5% 여유만 남는다.

## 되돌릴 조건

- 드레인 20초가 실제 결제 확정 시간보다 짧아 정상 결제를 위반으로 세면, 드레인 길이를 늘리는 결정을 소유자와 한다.
- 20초 드레인 뒤에도 PENDING이 많으면 제품 미확정인지 측정 창 문제인지 나눠 본다. `payment_pending_before_3s`가 0이 아니면 측정 방법 문제다.
