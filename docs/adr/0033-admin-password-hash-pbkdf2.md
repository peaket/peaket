# ADR-0033: 백오피스 관리자 계정의 비밀번호 일방향 암호화 알고리즘으로 PBKDF2-HMAC-SHA256 채택 (Argon2id 대체)

- **상태**: 채택 (2026-10-09 수립. 국내 개인정보보호 컴플라이언스 기준과의 부합을 위해 기존 argon2id 결정을 공식 대체). ADR-0050(2026-10-13)이 근거를 바로잡는다. 600,000회는 OWASP와 ASVS 부록 C의 값이고 NIST SP 800-63B-4는 반복 횟수를 정하지 않는다. 'Modular Crypt Format(PHC 포맷)'은 PHC 문자열 형식, 고시는 현행 제2026-9호다. 같은 ADR이 KMS HMAC 페퍼(관리 계정 ID 결합)를 더하고 결과의 '완벽히 충족'을 뺀다
- **관련 문서**: docs/architecture.md §8.3(보안 기본 규칙, 이전 결정 argon2id를 대체), docs/security/data-classification.md 항목 10, docs/security/asvs/auth.md 6.5.2·11.2.1·11.4.2, docs/features/identity.md §6, POL-020, POL-027
- **관련 ID**: FR-021, FR-028, POL-020, POL-027, NFR-016

## 맥락
- 피켓에서 일반 팬 사용자는 OAuth 2.0 소셜 로그인만을 사용하므로 데이터베이스에 비밀번호를 저장하지 않는다. 비밀번호는 파트너사 및 내부 플랫폼 운영자의 관리자 계정에만 존재하며, 모든 관리자는 TOTP 2차 인증과 IP/VPN 접근 제어가 의무 적용된다.
- 기존 초기 설계에서는 최신 메모리 하드 암호화 알고리즘인 `Argon2id`를 지정하였으나, '개인정보의 안전성 확보조치 기준(개인정보보호위원회 고시 제2023-6호) §7①'에서 규정한 '안전한 일방향 암호화 알고리즘'에 법리적으로 부합하는지 명확한 규제 해석이 필요했다(POL-027).
- 2026년 10월 규제 및 보안 표준 분석 결과:
  - 개인정보보호위원회 공식 안내서(2025.11)의 권장 예시에는 SHA-224/256/384/512 등 SHA 계열만이 나열되어 있으며 Argon2는 명시되지 않았다.
  - 국가정보원 및 KISA KCMVP(암호모듈검증체계) 검증대상 목록에는 키 유도 함수 `PBKDF(HMAC)`가 공식 등재되어 있으나 Argon2는 부재하다.
  - OWASP Password Storage Cheat Sheet 및 NIST SP 800-63B 디지털 신원 가이드라인은 FIPS-140 규정 준수가 요구되는 환경에서 PBKDF2에 최소 600,000회 이상의 반복 횟수(Iteration)와 HMAC-SHA-256을 조합할 것을 공식 권고하고 있다.

## 결정
1. 관리자 비밀번호 및 비상 복구 코드는 `PBKDF2-HMAC-SHA256` 알고리즘을 사용하여 해시화 저장한다.
2. 암호화 매개변수는 암호학적으로 안전한 16바이트 이상의 무작위 솔트(Salt)와 OWASP 권고 기준인 **600,000회 이상의 반복 카운트**를 적용하며, Modular Crypt Format(PHC 포맷)으로 식별자, 반복 횟수, 솔트, 해시값을 결합 저장한다.
3. 추후 반복 카운트 상향 조정이나 알고리즘 전환이 필요할 경우, 관리자가 로그인에 성공하는 시점에 백그라운드에서 신규 파라미터로 자동 재해싱(Re-hashing)하여 사용자 개입 없는 무중단 마이그레이션을 지원한다.
4. 'PBKDF2-HMAC-SHA256이 개인정보보호 고시상의 안전한 알고리즘에 해당한다'는 해석 근거를 컴플라이언스 문서(POL-027)에 공식 명기한다.

## 검토한 대안
| 대안 | 기각 사유 및 한계점 |
| --- | --- |
| 기존 argon2id 고수 | GPU 기반 크래킹에 대한 암호학적 저항력은 월등하나, 국내 공공 가이드라인 및 KCMVP 목록에 근거가 미비하여 외부 보안 감사 시 규제 미준수 지적 위험이 상존한다. |
| 단순 SHA-256 + 솔트 단일 해시 | 정부 안내서의 단순 예시에는 부합하나, 해시 연산 속도가 지나치게 빨라 GPU 무차별 대입 공격에 무방비로 노출되므로 현대 엔지니어링 표준(OWASP)에 부적합하다. |
| bcrypt | 72바이트 입력 길이 제한(Truncation)으로 인해 긴 패스프레이즈나 한글 UTF-8 조합 비밀번호의 후반부가 무시되는 심각한 암호 결함이 존재한다. |

## 결과와 트레이드오프
- 국내 개인정보보호법 컴플라이언스와 글로벌 OWASP 보안 표준을 동시에 완벽히 충족한다.
- 고반복 횟수(600,000회) 적용으로 인해 인증 시 단일 스레드 CPU 연산 시간이 수백 ms 소요되므로, Node.js libuv 워커 스레드풀의 고갈 여부를 실시간 프로메테우스 지표로 면밀히 모니터링해야 한다.
