# ADR-0373: 7일 안에 완성하려고 범위를 잘라 동결하고 절차를 가볍게 한다(2026-11-23)

- **상태**: 채택(2026-11-23, 소유자 결정). 완성 기한은 2026-11-30이었고, 같은 날 소유자가 2026-12-03으로 늦췄다("12월 3일 까지는 괜찮아요. 그 안에 일괄 환불(F-07-8) 처리하도록 하세요"). [ADR-0354](0354-feature-vertical-slices-after-cutover.md)의 기능 표 상태 값에 `동결`을 더한다. [ADR-0372](0372-tdd-frozen-tests-no-post-impl-review.md)의 시험 리뷰는 A등급 기능에만 남긴다. [ADR-0171](0171-post-sale-forensics-in-launch-scope.md)의 사후 포렌식 플랫폼은 이번 완성 범위에서 뺀다. 결정 3의 A등급 줄에 구현 리뷰를 더한 것은 [ADR-0381](0381-agrade-post-impl-review.md)이다(2026-11-23).
- **관련**: [docs/BUILD_ORDER.md](../BUILD_ORDER.md) '기능 단위 계획' 표, [docs/architecture.md](../architecture.md) §8.6, [docs/lanes/coord.md](../lanes/coord.md)
- **관련 ID**: 없음(범위와 진행 절차만 바꾼다)

## 맥락

- 2026-11-23 기준 기능 표에 남은 기능은 91개(완료 3, 막힘 5)이고, 어림 일수를 더하면 약 263일 치다. 갈래 다섯이 7일 동안 할 수 있는 양은 많아야 35~50일 치다.
- 같은 날 소유자: "솔직히 말할게. 지금 이 프로젝트를 7일 안에 완성을 해야해. 그래서 선택과 집중을 해야할거 같어." 감독이 범위를 자르는 안을 올렸고, 소유자가 다음을 정했다.
  - "포렌식 플랫폼은 안만들어도돼요."
  - 핵심 셋 말고 더 할 영역으로 현장 입장·정산·지급대행·관측·경보를 골랐다. CS·법정 의무는 고르지 않았다.
  - 절차는 'A등급만 시험 리뷰'(감독 추천)를 골랐다.
  - "분석 적재 파이프라인은 TDD없이 그냥 진행해서 빠르게 하면 안될까요?" — 감독이 동결하려던 분석 적재를 되살리되 빠른 길로 한다.

## 결정

### 1. 완성의 정의(2026-12-03까지)

1. **팬 핵심 흐름이 실제 서버로 끝까지 된다.** 대기열 → 입장 → 좌석 잡기 → 결제 → 발권 → 월렛.
2. **"100만 명이 한꺼번에 몰려도 멈추지 않는다"를 숫자로 보인다.** 부하 시험과 100만 외삽(F-08-2), 장애 주입(F-08-8), 시험 뒤 불변식 검사(오버셀·이중 결제 0건)를 한다.
3. **관제는 최소로 한다.** 판매 일시정지·입장 조절·결제사 전환 명령이 동작하고(F-02-1·F-02-2와 그 나눈 몫), 콘솔이 실제 데이터로 뜬다(F-03-1~F-03-3, F-03-4의 명령 화면, F-04-1).
4. **소유자가 고른 영역**: 현장 입장(F-05-2~F-05-6), 정산·지급대행(F-07-6~F-07-8, F-07-8 일괄 환불은 기한 안에 꼭 한다), 관측·경보(F-01-1, F-01-3~F-01-7), 분석 적재(F-04-3~F-04-8, 결정 3의 빠른 길).
5. **데모 영상과 안내**(F-08-7)를 마지막에 만든다.
- 진행 중인 기능(F-01-2, F-02-1, F-02-2, F-03-1, F-03-2, F-04-2, F-05-1, F-06-7)은 끝낸다.
- 측정 셋(F-08-2·F-08-7·F-08-8)의 선행 칸에 있는 기능이 동결되면 그 선행은 보지 않는다. 측정에 로컬 클러스터가 꼭 필요하면 F-09-8 가운데 클러스터를 다시 띄우는 몫만 한다.

### 2. 동결

- 기능 표의 `상태`에 `동결`을 더한다. 뜻은 '7일 완성 범위 밖, 시작하지 않는다'이다. 기능 행과 정본은 지우지 않는다. 완성 뒤 다시 열 때 `대기`로 되돌린다.
- 동결하는 기능:
  - 포렌식 플랫폼: F-04-9~F-04-19
  - CS·법정 의무: F-06-1, F-06-3, F-06-4, F-06-5(F-06-6은 `막힘` 그대로)
  - 관제 명령·콘솔의 나머지: F-02-3, F-02-4, F-03-5, F-03-6. F-03-4는 명령 화면만 하고 감사·리플레이·법정 조치 화면은 동결한다.
  - 현장 입장의 나머지: F-05-8, F-05-9
  - 커머스·파트너 화면: F-07-2, F-07-3, F-07-4, F-07-9, F-07-10, F-07-11, F-07-12
  - 출시·측정의 나머지: F-08-1, F-08-3~F-08-6, F-08-9~F-08-15
  - 클라우드 기반: F-09 전부(결정 1의 F-09-8 몫은 빼고)
  - 탐색·콘텐츠: F-10-1, F-10-2. 봇 방어 측정: F-11-1~F-11-3
  - 기능 표 밖: FIX-problem-ctor(오류 이름 전수 대조), FIX-roles-tdd(역할 확인 도구의 시험 먼저 차례, 가지 `feature/coord-FIX-roles-tdd`에 시험 초안을 남긴다)
- 동결한 기능에 닿는 장부 항목은 완성 판정에서 빼고, 완성 보고에 '동결로 미검증'으로 수를 따로 적는다.
- 진행 중인 기능이 동결한 기능의 몫을 넘겨받았으면(예 F-02-5의 몫이 F-03-5로 감) 그 몫도 동결된다. 결정 1의 명령 셋이 끝까지 동작하는 데 꼭 필요한 몫만 남긴다.

### 3. 절차

- **A등급(돈·좌석·대기 순번)**: ADR-0372 그대로다. 계획 → 시험 → 시험 리뷰 → 시험 고정 → 구현 → 게이트.
- **B·C등급**: 계획 → 시험 → 구현 → 시험 통과면 합친다. 시험 리뷰는 하지 않는다. 시험 담당과 구현 담당은 나누고, 구현 담당은 시험을 고치지 못한다(ADR-0372 결정 3).
- **분석 적재(F-04-1, F-04-3~F-04-8)는 빠른 길로 한다**(소유자 요청). 시험 먼저와 역할 나누기 없이 한 담당이 구현하고 시험한다. 기능마다 완료 정의의 동작을 실제로 돌려 보이고, 돌린 명령과 결과 숫자를 계획 파일에 남긴다. 기존 시험·타입 검사·린트는 통과해야 한다.
- **합치기를 막지 않는 것**(7일 동안):
  - 역할 확인(`roles-check.mjs`)의 차례·구성 실패. 꼬리말 `Role`·`Batch`·`Agent-Session`은 이력을 읽으려고 계속 단다.
  - 장부 `--require`의 빈칸. A등급만 막고, B·C는 빈칸 수를 계획 파일에 적는다.
  - 기록 맞추기(`records.mjs`): 감독이 모아서 한다.
  - ADR: 정본의 결정을 바꿀 때만 쓴다. 작은 세부는 계획 파일에 '(추천 적용, 날짜)'로 적는다.
- 브라우저 확인은 마지막 날 한 번 한다. 새로 찾은 범위는 coord '범위 늘어남'에 한 줄만 적고 하지 않는다.
- 막는 게이트로 남는 것: 그 기능의 시험 통과, 타입 검사, 린트, 계약 생성물 일치(`gen:check`), develop CI의 node 잡.

## 결과

- 좋아지는 점: 남은 일이 7일 안에 들어올 크기로 준다. 시험 리뷰·기록·ADR이 합치기를 막지 않아 대기가 준다.
- 잃는 점:
  - 포렌식(사후 조사·증거 묶음·리플레이)이 없다. ADR-0171이 필수로 정한 부분이 이번 완성에 들어가지 않는다.
  - CS·법정 의무 화면, 커머스·파트너 화면, 클라우드 기반이 없다.
  - B·C 기능의 시험은 다른 눈의 리뷰를 받지 않는다. 분석 적재는 시험 먼저도 역할 나누기도 없다.
  - 장부의 빈칸이 남는다. 완성 보고에 동결로 미검증인 수를 따로 적어 숨기지 않는다.
- 갈래가 여섯이 되어 Docker와 기계 부하가 늘어난다. 통합 시험은 Docker 잠금을 지킨다.

## 고른 안과 버린 안

- (고름) 핵심 셋 + 소유자가 고른 영역 + 분석 적재 빠른 길, 나머지 동결.
- (버림) 다 하기: 263일 치라 7일에 들어오지 않는다.
- (버림) 지금 TDD 그대로: 소유자가 'A등급만 시험 리뷰'를 골랐다.
