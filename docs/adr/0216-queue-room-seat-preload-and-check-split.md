# ADR-0216: 대기실의 좌석 자원 미리 받기 규칙을 정하고, 세 엔진 검사와 QueuePanel 비교는 나눈다

- **상태**: 채택(2026-11-05, 추천 적용). BUILD_ORDER HOT-345 ①.
- **관련**: [docs/frontend.md](../frontend.md) §5.1 '차례와 입장'·§1.5·§2.5·§4.2.2·FE-T3·FE-T4·FE-T6·FE-T15·FE-T40, [docs/security/asvs/seat-hold.md](../security/asvs/seat-hold.md) v5.0.0-1.2.2, openapi `QueueState.seatmapLayoutPath`·`AdmissionResult.seatmapLayoutPath`, ADR-0207, ADR-0211 결정 1
- **관련 ID**: SCR-008, FE-T10, FE-T15

## 맥락

- HOT-342(ADR-0211 결정 1)가 이 단계로 넘긴 것은 다섯 가지다.
  - 좌석 자원 미리 받기
  - BAS-210의 세 엔진 브라우저 검사(FE-T3·FE-T15·FE-T4)
  - HOT-341의 여러 탭 세 엔진 검사(FE-T6)
  - BAS-170의 React `QueuePanel`과 대기실 셸 시각 비교(FE-T40)
  - 같은 출처 검사 틀
- 정본을 모아 보니 0.5일 안에 할 수 없었다.
  - 견줄 React `QueuePanel`(CMP-015)이 ds에 아직 없다.
  - 운영 빌드로 같은 출처를 만드는 검사 경로가 없다.
  - Playwright는 경로를 가로채면 CORS 사전 요청에 스스로 답해, 사전 요청 수(FE-T3)를 서버에서 세야 한다.
- 미리 받기에도 빈칸이 있었다.
  - `/_q/seat-preload.json`은 이름만 있다. 만드는 쪽·모양·캐시가 없다.
  - 언제·어느 탭이 받는지가 없다.
  - 경로를 어떻게 검사하는지가 없다.
  - 좌석 화면의 요청과 HTTP 캐시가 맞게 하는 요청 모드가 없다.

## 결정

1. **나눔**
   - HOT-345 ①: 좌석 자원 미리 받기, 그리고 대기실 fetch 층의 시간 초과 듣기 정리(FE-T15의 단위 부분)
   - HOT-347: 같은 출처 검사 틀(운영 빌드의 경로 나눔, 가짜 API의 사전 요청 기록)과 세 엔진 FE-T3·FE-T15·FE-T4
   - HOT-348: 세 엔진 FE-T6
   - HOT-349: ds `QueuePanel`(CMP-015)과 이야기 네 상태, 대기실 셸과의 FE-T40 비교
   - `/_q/seat-preload.json`을 만드는 일은 좌석 화면을 잇는 HOT-350으로 넘긴다. 좌석 화면 자산이 그때 정해진다.
2. **언제 받는가**
   - 예상 대기가 60초 [가정] 안으로 들어오면 받는다. 팬 토큰을 미리 갱신하는 때와 같다.
   - 리더 탭(보이는 탭)만 받는다. HTTP 캐시는 탭끼리 나눠 쓰므로 한 탭으로 충분하다.
   - 같은 경로는 페이지마다 한 번만 받는다(다시 줄 서기·다른 탭의 대기표로 대기를 다시 돌아도). 경로가 바뀌면(좌석맵 판이 바뀜) 다시 받는다.
   - 차례가 온 뒤(serving ≥ 내 순번)에는 받지 않는다. 입장 확정·좌석 화면 이동과 대역폭을 다투지 않게 한다.
   - 실패해도 다시 받지 않는다. 좌석 화면이 어차피 받는다.
3. **무엇을 받는가**
   - 대기 상태 파일의 `seatmapLayoutPath`가 가리키는 좌석맵 파일. 자동 배정 공연도 서버가 경로를 주면 받는다.
   - `/_q/seat-preload.json` `{v: 1, assets: string[]}`이 있으면 거기 적힌 좌석 화면 자산. 404이거나 꼴이 틀리면 건너뛴다.
4. **경로 검사(ASVS 1.2.2)**
   - 좌석맵은 `/v1/events/{이 회차 ID}/seatmap-layouts/{판 번호}.json` 꼴의 같은 출처 경로만 받는다(판 번호는 계약의 정수 `layoutVersion`). www 출처의 S3 정적 파일이다(docs/frontend.md §2.5·§4.2.2 1번).
   - 자산은 `/_next/static/…` 아래의 `.js`·`.css`만 받는다.
   - 그 밖의 값(다른 출처, `..`, 쿼리)은 버린다.
5. **요청 모드**
   - 모든 요청에 `priority: "low"`를 준다. 이 칸을 모르는 엔진은 무시하고 보통 우선순위로 받는다.
   - 좌석맵은 좌석 화면 Worker와 같은 `credentials: 'omit'`으로 받아 같은 캐시 항목을 쓴다.
   - 자산은 `same-origin`으로 받는다.
   - `seat-preload.json`은 빌드마다 바뀌므로 `cache: 'no-cache'`로 다시 확인한다.
6. **시간 초과 듣기 정리(FE-T15)**
   - `AbortSignal.any`가 없는 엔진의 대체 경로는 요청이 끝나면 두 신호에 단 듣기를 지운다(api-client `signal.ts`와 같은 규칙).
7. **개발·검사**
   - 가짜 API가 좌석맵 경로에 자리 파일(immutable)을 낸다. 실제 파일은 HOT-350이고, 바꿀 때는 판 번호를 올린다(같은 경로로 바꾸면 이미 받은 브라우저가 옛 파일을 캐시에서 쓴다).
   - 소비자 웹 개발 서버와 대기실 개발 서버가 그 경로를 가짜 API로 넘긴다.

## 결과

- 차례 1분 전쯤 좌석맵 파일이 HTTP 캐시에 들어가, 입장 뒤 좌석 화면이 그 판을 캐시에서 읽는다. 판이 같으면 다시 받지 않는다(§4.2.2 1번).
- 남는 한계:
  - 좌석 화면 자산 목록은 HOT-350 전까지 없다(404라 건너뛴다).
  - 실제 서버의 대기 상태 파일은 `seatmapLayoutPath`를 아직 싣지 않는다(HOT-010).
  - 세 엔진 검사와 QueuePanel 비교는 HOT-347~349 전까지 단위 시험·기존 시각 회귀만 덮는다.

## 다른 선택지

- 입장 확정 응답의 `seatmapLayoutPath`로 받기: 그때는 이미 좌석 화면으로 가는 중이라 미리 받는 뜻이 없다. 그 값은 판 비교에만 쓴다(§4.2.2).
- 모든 탭이 받기: 같은 파일을 탭 수만큼 받는다. HTTP 캐시가 같아 리더 하나로 충분하다.
- `<link rel="prefetch">`: Safari가 지원하지 않는다(§5.1). 그래서 `fetch`로 캐시를 채운다.
