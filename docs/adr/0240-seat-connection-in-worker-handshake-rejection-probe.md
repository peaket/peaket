# ADR-0240: 좌석 연결은 Worker가 맡고, 핸드셰이크 거절은 HTTP로 다시 확인한다

- **상태**: 채택(2026-11-09, 추천 적용. wbs 2.6.4 세부는 추천 적용이라는 승인 2026-10-21·2026-10-28을 따른다). BUILD_ORDER HOT-100.
- **관련**: [docs/frontend.md](../frontend.md) §3.3·§3.5·§4.4.1, [docs/features/seat-hold.md](../features/seat-hold.md) §7, ADR-0110, ADR-0117, ADR-0221, ADR-0227
- **관련 ID**: FE-T11, NFR-004, ASVS v5.0.0-4.4.1

## 맥락

- 좌석 형식 해독과 델타 판정은 HOT-110에 있고, 연결을 맺고 지키고 다시 맞추는 쪽이 없었다. 서버(realtime-gw, HOT-090)는 아직 없어 가짜 서버로 만든다.
- 정본은 4401이면 다시 붙지 않는다고 적었지만, 게이트웨이가 핸드셰이크에서 토큰을 거절하면 브라우저에는 닫힘 코드가 1006으로만 보인다(HTTP 401을 스크립트가 읽을 수 없다, WebSocket 표준). 이 PoC에서 세 엔진 모두 확인했다. 그대로면 토큰이 무효인 사람이 만료 시각까지 계속 다시 붙는다.
- 4403은 원인이 셋인데(회차·토큰 불일치, 구역 색인, 프레임 형식) 화면은 어느 것인지 구분할 수 없다.

## 결정

1. **세 층으로 나눈다**: 연결(`packages/seatmap/src/connection.ts`), 시계(`clock.ts`), 다시 맞추기(`delta-sync.ts`)는 Worker에서 돈다. 화면 상태는 메인 스레드의 XState 기계(`apps/web … connection-machine.ts`)가 Worker의 알림을 받아 그린다(§3.5). 소켓·타이머·시계·난수는 주입해 가짜 서버로 시험한다.
2. **연결을 잇는 일은 HOT-357이다**: 이번 단계는 부품과 시험까지다. Worker 메시지, 구독 구역 고르기(1초 머묾), 화면 표시는 realtime-gw가 생긴 뒤 HOT-357이 잇는다.
3. **핸드셰이크 거절**: 한 번도 열리지 못한 닫힘이 3번 [가정] 이어지면 HTTP로 토큰을 확인한다(`probeAuth`, 스냅샷 경로를 그대로 쓴다). 401·403이면 `ended`이고, 그 밖에는 계속 다시 붙는다.
4. **4403**: 좌석맵 파일과 스냅샷을 다시 받고 한 번만 새로 붙는다(§4.4.1 표의 구역 색인 경우). 다시 4403이면 끝낸다. 나머지 두 원인도 끝나므로 어느 경우든 다시 붙기를 되풀이하지 않는다.
5. **실패 횟수는 10초 [가정] 붙어 있어야 지운다**: 열리자마자 닫거나 프레임 하나를 답하고 닫기를 되풀이하는 서버에 짧은 간격으로 몰리지 않게 한다. 여는 중에 10초 [가정] 답이 없으면 포기한다.
6. **닫힘 코드 값**: 1012는 0~5초, 4429는 10초에 0~5초 무작위 [가정]을 더한다. 그 밖은 0.5초부터 두 배씩 늘리는 전체 지터(상한 10초)다. 서버가 보낸 1000도 화면이 켜져 있으면 다시 붙는다.
7. **깨진 프레임은 버리고 알린다**: 연결을 끊어도 같은 프레임이 다시 올 뿐이다. 오류 수집에 남긴다.
8. **다시 맞추기**: 스냅샷을 기다리는 구역의 델타는 구역마다 64개 [가정]까지 둔다. 넘치면 오래된 것부터 버리고 다시 얹을 때 갭이면 한 번 더 묻는다. 실패는 1초부터 두 배씩(상한 5초 [가정]) ±20% 지터로 다시 묻고, `Retry-After`를 하한으로 지키며 한 페이지에서 분당 60회를 넘지 않는다(ADR-0117). 401·403과 좌석맵 판 불일치는 멈추고 `onFatal`로 알린다. 스냅샷이 새 세대면 다른 구역도 다시 맞춘다. 요청 중에 세대가 오르거나 다시 붙으면 끝난 뒤 한 번 더 묻는다.
   - 스냅샷의 점유는 무엇 때문인지 모르는 값이라, 이미 아는 다른 분 선택·판매는 지키고 내 좌석은 다른 분 선택으로 둬 내 표시가 남게 한다.
9. **만료 판정은 서버 시각으로 한다**: 왕복을 잰 뒤에는 그 값을 먼저 쓰고, 그 전에는 보정 시계(§3.3)를 쓴다. 기기 시계로 재면 빠른 기기가 첫 연결에 끝난다.
10. **`BatchInterval`은 연결 직후 한 번 보낸다**: 바뀔 때만 보내면 Degraded 중에 다시 붙은 화면이 평시로 보인다. 다시 붙으면 화면은 Degraded를 지우고 서버의 첫 값을 기다린다. 정본을 고쳤고 서버 몫은 HOT-090이다.
11. **지표 이름**(§4.4.1이 wbs 2.6.4로 미룬 것): 닫힘 코드와 열렸는지를 `onClose(code, opened)`로 넘긴다. 텔레메트리 표시값은 `ws_reconnects`와 `seat_delta_e2e_ms`를 쓰고, 4403·4429 수는 HOT-357에서 표시값 `ws_close_4403`·`ws_close_4429` [가정]로 보낸다.

## 결과

- 세대·갭·재요청 규칙과 닫힘 코드별 동작이 서버 없이 시험된다(FE-T11).
- 하위 프로토콜로 토큰을 싣는 방식은 세 엔진에서 된다(이 단계 PoC). 1KB 넘는 토큰도 지나간다.

### 확인하지 못한 것

- **게이트웨이 쪽 PoC**: Envoy Gateway가 `Sec-WebSocket-Protocol`에서 토큰을 읽어 검증하는지는 게이트웨이와 realtime-gw가 없어 재지 못했다(HOT-090에서 잰다). 안 되면 첫 메시지 인증(`auth: 'first-message'`, type 17)으로 바꾸며, 그 길도 만들어 두었다.
- iOS 실기기의 OffscreenCanvas는 소유자 확인 목록(`tools/web-checks/seatmap-pkg/OWNER-CHECK.md`)에 남아 있다.

## 다른 선택지

| 길 | 고르지 않은 까닭 |
| --- | --- |
| 핸드셰이크에서 거절하지 않고 받은 뒤 4401로 닫게 한다 | 토큰이 없는 연결까지 게이트웨이와 realtime-gw가 받아 첫 방어선의 뜻이 약해진다(§4.4.1, asvs seat-hold 4.4.2) |
| 1006이 나면 만료까지 계속 다시 붙는다 | 토큰이 무효인 사람이 화면에 머무는 동안 핸드셰이크를 계속 보낸다 |
| 연결을 메인 스레드에 둔다 | 델타 해독과 상태 배열이 Worker에 있어 프레임마다 스레드를 건너게 된다(§5.2) |
