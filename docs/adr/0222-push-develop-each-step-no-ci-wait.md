# ADR-0222: 갈래가 단계마다 develop을 원격에 푸시하고 CI를 기다리지 않는다

- **상태**: 채택(2026-11-06, 소유자 결정 "기다리지 않고 푸시". 감독 세션이 푸시를 소유자 몫으로 둔 까닭과 단계마다 푸시할 때의 기다림·비용을 설명한 뒤 소유자가 골랐다)
- **관련**: R-201(단계 단위로 맡기기, 2026-10-30), ADR-0074(git flow), ADR-0189·ADR-0190(갈래 셋과 단계 비용), [docs/architecture.md](../architecture.md) §8.5·§8.6, [docs/devops.md](../devops.md) §2.2.5·§3.3·§3.4, docs/PROGRESS.md '턴 규칙'

## 맥락

- R-201(2026-10-30)은 AI가 단계 하나를 커밋까지 맡되 원격 푸시는 멈추고 묻는 일로 두었다. 그때는 원격 저장소가 없었다. 2026-11-03 원격(`peaket/peaket`, 공개)이 생긴 뒤에도 규칙 세트는 소유자 계정만 우회하게 걸고, 갈래는 PR 없이 `develop`에 바로 커밋하며 푸시는 소유자가 시킬 때만 했다.
- 그래서 문서가 PR마다 돌게 정한 CI(단위·통합 시험의 깨끗한 Linux 실행, kind 위 E2E, 이미지 빌드, 계약 깨짐·보안 검사, devops §3.3)가 단계마다 돌지 않았다. 2026-11-06에는 원격 `develop`이 이 PC보다 101커밋 뒤였다. 이 PC의 관문은 갈래가 돌리는 시험뿐이라, 2026-11-05에 Docker가 멈추자 관문이 닫혔다.
- 원격 실행 기록(2026-11-03~05)으로 잰 `develop` 푸시 CI는 9~25분, PR CI는 10~43분이다. `ci.yml`은 같은 가지의 새 푸시가 오면 돌던 실행을 취소한다(`cancel-in-progress`). 공개 저장소의 표준 러너는 무료다.

## 결정

1. **단계마다 푸시**: 갈래는 단계를 `develop`에 커밋하면 곧바로 `git push origin develop`으로 올린다. 갈래 셋이 같은 저장소의 `develop` 참조를 함께 쓰므로 어느 작업 폴더에서 올려도 같다. 단계 중간의 미완 상태는 올리지 않는다.
2. **CI를 기다리지 않는다**: 푸시한 뒤 CI 결과를 기다리지 않고 다음 단계로 간다. 다음 단계를 시작할 때 직전 `develop` CI 결과를 본다(`gh run list --repo peaket/peaket --branch develop --workflow ci --limit 3`). 실패면 그것부터 고친다. 다시 돌려 통과하는 흔들리는 시험이면 실패한 잡만 다시 돌리고(`gh run rerun <실행 ID> --failed`), 그 시험을 그 갈래의 구간 끝 정리 목록에 적는다. 취소된 실행은 다음 실행이 같은 내용을 덮으므로 실패로 보지 않는다.
3. **여전히 묻는 것**: `develop` 밖 원격 가지·태그 푸시, 강제 푸시와 원격 기록 덮어쓰기, 공개 게시, 계정·저장소 만들기, 비용, 되돌리기 어려운 일, 보안 규칙에 걸리는 일. 푸시가 거절되면(빨리 감기가 아님 등) 강제로 밀지 않고 멈춘다.
4. **1인 기간의 가지 규칙**: 원격이 생긴 뒤에도 1인 기간에는 작업 가지·PR 없이 `develop`에 바로 쌓는다(2026-11-03 소유자 선택, 규칙 세트는 소유자 계정 우회). 이 결정은 거기에 '단계마다 푸시'를 더한다. 사람이 늘어 PR 규칙을 걸 때 다시 정한다.

## 결과

- 단계마다 원격 CI가 돈다. 기다리지 않으므로 단계 시간은 푸시 몇 초와 다음 단계 시작 때의 확인만큼 는다.
- 갈래들이 CI 한 번(9~25분)보다 자주 올리면 앞 실행이 취소되어 마지막 상태만 끝까지 검사된다. 그때는 어느 단계가 깨뜨렸는지 가리기 어렵다. 취소가 잦아 끝까지 도는 실행이 드물면 푸시를 몇 시간에 한 번으로 묶는 쪽으로 다시 정한다.
- 공개 저장소라 올린 내용은 되돌리기 어렵다. 커밋된 비밀은 노출로 보고 폐기·재발급한다(architecture §8.3, devops RB-26).
- 매주 월요일 예약 실행이 그때의 원격 `develop`에서 출시 후보를 자르므로 만들던 기능도 들어간다. 정본대로 미완 기능은 릴리스 플래그(꺼짐) 뒤에 둔다(architecture §8.5).
