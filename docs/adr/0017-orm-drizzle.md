# ADR-0017: ORM은 Drizzle

- **상태**: 대체됨 (2026-10-05 설계서 25장에 기록, 2026-10-08 ADR로 옮김). 선택 근거는 ADR-0034(2026-10-09)가 보완했다. 같은 날 ADR-0035가 TypeORM으로 대체했다가 ADR-0037이 Drizzle 결정을 되살렸고, 지금 유효한 결정은 ADR-0037이다
- **관련**: 설계서 25장, 21장(잠금·인덱스·파티셔닝), docs/data.md
- **관련 ID**: NFR-003, NFR-025(불변식), FR-010·011

## 맥락
- 초고부하 트랜잭션 핫패스(Hot-path)에서는 `FOR UPDATE SKIP LOCKED`, 복합 CTE, 정렬 잠금, 파티션 프루닝(Partition Pruning) 등 고도화된 SQL 제어 기능을 개발자가 직접 완전히 통제할 수 있어야 한다.
- 고수준 ORM 프레임워크가 쿼리를 임의 변환하거나 과도한 엔티티 매핑 오버헤드를 유발하면 결제 확정 예산 중 PG 밖 1초(NFR-006)를 지키기 어렵다.
- 기술 스택 후보군으로는 TypeORM, Prisma, Drizzle이 검토 대상에 올랐다.

## 결정
- 경량 TypeScript ORM인 Drizzle을 1차 채택한다. Drizzle은 원시 SQL 형태가 투명하게 보존되어 핫패스 쿼리를 직관적으로 제어할 수 있으며, 런타임 추상화 계층이 극히 얇아 고성능 처리에 유리하다.
- SQL 인젝션 공격은 타입 안전 파라미터 바인딩 메커니즘을 통해 완벽히 방어한다.
- 본 결정은 이후 ADR-0034로 근거가 구체화되고, ADR-0035의 TypeORM 일시 전환을 거쳐, ADR-0037에서 Drizzle로 최종 확정되었다.

## 검토한 대안
| 대안 | 문제 |
| --- | --- |
| Prisma | 쿼리 엔진의 바이너리 오버헤드, 복잡한 잠금 구문(`FOR UPDATE SKIP LOCKED`) 제약, 번들 크기 증가 |
| TypeORM | 데코레이터 메타데이터 오버헤드 및 액티브 레코드 패턴의 암시적 쿼리 생성으로 정밀한 핫패스 최적화 제약 |

## 결과와 트레이드오프
- 데이터베이스 스키마의 단일 진실 공급원(SSOT)은 마이그레이션 파일로 관리되며, docs/data.md는 논리적 데이터 구조와 아키텍처 결정 사항만을 기술한다.
- 트레이드오프: 생태계 성숙도와 고수준 관계 매핑 추상화 수준이 Prisma에 비해 얇아 일부 보일러플레이트 코드가 증가할 수 있다.
