# ADR-0139: 개인정보 국외 이전 목록을 정본으로 두고, 지점마다 근거와 줄이는 방법을 정한다(2026-10-28)

- **상태**: 채택 (2026-10-28. 2026-10-19 ADR-0067을 정할 때 '개인정보 국외 이전 점검'을 따로 하기로 남겼다(review R-76). 2026-10-28 그 점검 보고(점검표 36개 지점, 수정안, 줄일 곳, 확인 필요 15건)를 본 소유자가 "추천대로 반영"이라고 정했다. 방향(국외 이전 목록을 두고 처리방침에 공개)은 소유자 승인이고, 지점마다 고른 근거·값·규칙은 추천 적용이다. 법령은 2026-10-28 국가법령정보센터 원문, 외부 서비스 사실은 같은 날 각 회사 공식 문서로 확인했다) 2026-10-29(소유자 결정, ADR-0152): 결정 4의 Slack 저장 위치는 '운영으로 넘어갈 때 Business+로 시작하고 첫 운영 경보 전에 데이터 레지던시를 서울로 켠다'로 정했다(review/open-items.md 60번). 회원 프로필 등은 지역 밖일 수 있어 국-10의 국외 이전 고지는 그대로다. 같은 날 2인 승인 대기 알림이 IRM으로도 가지만, 알림 글은 대기 수와 콘솔 링크뿐이라 이전 항목은 늘지 않는다.
- **관련**: ADR-0012(결정 3 사람 확인), ADR-0031(환경·리전 재해 복구), ADR-0032(온콜·알림·상태 도구), ADR-0044(결정 10 결제 처리 위탁 공개), ADR-0060(결정 13 알림 채널), ADR-0067(결정 4·6 오류 도구와 국외 이전 판정), ADR-0083(결정 6 ticket 교차 리전 복제본), ADR-0115(분석 아카이브 복제), POL-023, POL-027, [docs/security/data-classification.md](../security/data-classification.md) '국외 이전 목록', wbs 7.4.1·4.8.2

## 맥락

- **법의 틀**: 개인정보 보호법 §28의8①(2026-09-11 시행본, 2027-03-09 시행 개정본도 문언이 같다)은 개인정보를 나라 밖으로 **제공**(나라 밖 제3자가 조회만 하는 것 포함)·**처리위탁**(일을 맡김)·**보관**(저장)하는 것을 '국외 이전'이라 부르고 원칙적으로 막는다. 예외는 다섯이다: 1호 별도 동의, 2호 법률·조약, 3호 정보주체와의 계약 체결·이행에 필요한 처리위탁·보관(가목: §28의8② 다섯 항목을 처리방침에 공개, 나목: 서면 등으로 알림), 4호 인증, 5호 개인정보보호위원회의 동등성 인정. 3호는 처리위탁·보관만 덮고 **제공은 덮지 않는다**. 처리방침에는 국외 이전의 근거와 다섯 항목(이전 항목, 나라·시기·방법, 받는 자의 명칭·연락처, 받는 자의 이용 목적·보유 기간, 거부 방법·절차·효과)을 적는다(시행령 §31①2호). 이전할 때는 안전성 확보 조치, 고충처리·분쟁해결 조치 같은 보호조치를 하고 받는 자와의 계약에 반영한다(§28의8④, 시행령 §29의10). 가명정보도 대상이다(§28의7이 §28의8을 빼지 않는다). 위반하면 전체 매출액 3% 이하 과징금(§64의2①7호), 보호조치를 하지 않으면 3천만 원 이하 과태료(§75②14호)다.
- **개인정보보호위원회 안내**: 국외 이전만 다루는 안내서는 없다(2026-10-28 안내서 게시판 목록). 「개인정보 처리방침 작성지침」(2026.4. 개정) Ⅲ-10이 적는 법을 정한다: 국외 이전을 제3자 제공·위탁과 구분해 적고, 여러 나라면 모두 적고, 재이전도 적는다. '백업 등을 위해 해외 서버 등에 분산 저장'을 국외 보관의 예로 들고, 3호를 근거로 한 예시 문안(목적 '재난·재해 대비 국가 간 데이터 백업', 거부 효과 '서비스 이용 불가, 탈퇴로 거부')을 준다. 동등성 인정은 2025년 9월 유럽연합 27개국과 유럽경제지역 3개국(노르웨이·리히텐슈타인·아이슬란드)에 처음 내렸다(개인정보위 누리집 '동등성 인정 현황'). 영국은 2026년 10월 검토를 시작했다. 일본·미국·싱가포르는 대상이 아니다. 개인정보위 누리집은 국외의 사업자가 정보주체에게서 **직접 수집**하는 것은 국외 이전이 아니라고 설명한다.
- **문서의 빈칸**: 국외 이전을 다룬 곳은 Sentry 클라우드(ADR-0067), Datadog 평가(합성 데이터만), Algolia(채택 안 함)뿐이었다. 다음은 다루지 않았다.
  - 도쿄(AWS ap-northeast-1, 일본) 재해 복구 사본: ticket DB 상시 복제본, Aurora 일 스냅샷 사본(서비스 DB의 개인정보 거의 전부, 7일), S3 백업 복제(원문 IP가 든 법정 접속기록 포함), 분석 아카이브 복제, 파기 감사 사본, 리전 재해 때의 복구 처리
  - 이용자 브라우저가 직접 해외로 보내는 곳: Cloudflare Turnstile(IP·TLS 지문·User-Agent·검사 신호), Web Push(구독 주소·Topic·보낸 시각과 길이)
  - 미국 리전(us-east-1)에 강제로 쌓이는 로그: CloudFront용 WAF 로그를 CloudWatch Logs·Firehose로 받는 경우, CloudFront Functions의 `console.log`. WAF 로그에는 요청 헤더 목록이 들어가 가리지 않으면 쿠키 속 액세스 토큰까지 남는다
  - 온콜·협업 도구(Grafana Cloud IRM, Slack, GitHub, Healthchecks.io)에 가는 직원 연락처와, 인시던트 기록에 이용자 정보가 섞일 위험
  - 해외 기획사에 예매자 명단을 주거나 파트너가 해외에서 조회하는 경우(국외 제공)
  - 처리방침 수탁자 목록: 결제사만 적혀 있었다
- **확인한 외부 사실(2026-10-28)**
  - Sentry 클라우드의 저장 위치는 미국(아이오와)과 EU(독일 프랑크푸르트) 중 조직을 만들 때 고르고 바꿀 수 없다. 사용자 계정·조직 설정·크론 체크인 등 일부는 고른 위치와 상관없이 미국에 저장될 수 있다. 한국은 없다.
  - Grafana Cloud 스택 리전에 한국은 없고 가장 가까운 곳은 도쿄다. IRM 데이터의 저장 위치는 공식 문서에서 찾지 못했다. 전화·문자는 Twilio가 보낸다. Synthetic Monitoring 공개 프로브에는 서울이 있다.
  - Slack은 데이터 레지던시를 쓰지 않으면 미국에 저장한다. Business+·Enterprise 요금제에서 서울을 고를 수 있다(메시지·파일·검색 색인. 프로필·멤버십은 지역 밖일 수 있다).
  - GitHub.com은 미국에 저장한다. 데이터 레지던시 지역에 한국은 없다.
  - Healthchecks.io는 독일 Hetzner 서버에서 처리·저장하고, 고객과 처리 위탁 계약(DPA)을 맺지 않으며 API에 개인정보를 넣지 말라고 한다.
  - Cloudflare는 Turnstile 신호를 봇 차단에서는 처리자로, 탐지 성능 개선에서는 스스로 관리자로 처리한다고 밝힌다. 한국 이용자 부록의 이전 나라는 15개국이고, Turnstile은 처리 지역 제한 기능(Regional Services)과 호환되지 않는다.
  - AWS WAF: CloudFront용 웹 ACL은 us-east-1에 만들고, CloudWatch Logs 로그 그룹은 웹 ACL과 같은 리전, Firehose는 us-east-1이어야 한다. S3 대상의 리전 조건은 문서에 없다. 로그 필드에 헤더 목록이 있다. CloudFront Functions 로그는 어느 엣지에서 실행해도 us-east-1에 남는다. CloudFront 표준 로그 v2는 다른 리전 S3로 보낼 수 있다.
  - Web Push 본문은 RFC 8291로 종단 암호화되지만, 헤더(TTL·Urgency·Topic), 보낸 시각과 길이, 어느 서버가 어느 구독에 보내는지는 푸시 서비스가 본다(RFC 8030 §8.1, RFC 8291 §7).
  - 토스페이먼츠는 해외 결제수단을 쓸 때만 미국·싱가포르로 보내고, 포트원은 일본·미국·싱가포르 회사에 국외 처리위탁을 한다(각 사 처리방침). 이동통신 3사·NICE평가정보·KCB의 처리방침에는 본인확인 관련 국외 이전 항목이 없다.

## 결정

1. **국외 이전 목록의 정본**: docs/security/data-classification.md '국외 이전 목록' 절을 정본으로 둔다. 처리방침의 국외 이전 절과 수탁자 목록은 이 절에서 만든다(wbs 7.4.1). 새 외부 서비스·리전을 쓰기 전에 이 목록에 행을 먼저 올린다(추천 적용 2026-10-28).
2. **도쿄 재해 복구 사본은 국외 보관으로 공개한다**: ticket DB 상시 복제본, Aurora 일 스냅샷 사본, S3 백업과 분석 아카이브 복제, 파기 감사 사본, 리전 재해 때의 복구 처리는 §28의8①3호 가목으로 처리방침에 공개한다. 받는 자는 AWS, 나라는 일본, 목적은 서울 리전 전체 장애에 대비한 보존과 복구, 거부 효과는 서비스 이용 불가(탈퇴로 거부)다. 작성지침의 예시와 같은 유형이라 '확인됨'으로 본다. AWS 계약(데이터 처리 부록)이 §29의10 보호조치를 담는지는 법률 검토에서 확인한다(추천 적용 2026-10-28).
3. **오류 도구를 클라우드로 정하면 EU 조직으로 만든다**: ADR-0067 결정 6의 판정이 Sentry 클라우드로 나오면 EU(프랑크푸르트) 저장 위치로 조직을 만든다. 근거는 5호(동등성 인정)이고, 처리방침에는 근거와 다섯 항목을 적는다. 미국 저장 위치는 쓰지 않는다. Sentry가 미국에 두는 계정·설정 정보와 하위 처리자는 재이전(§28의11)이라 Sentry 처리방침 링크로 알린다(추천 적용 2026-10-28).
4. **온콜·협업 도구에는 이용자 식별값을 쓰지 않는다**: 경보 라벨 규칙(docs/observability.md §9)에 더해, Grafana Cloud IRM 인시던트 기록, Slack 인시던트 채널, GitHub Issues에도 이용자 계정 ID·이메일·전화번호·주문번호를 쓰지 않고 관제 콘솔 링크만 붙인다. 직원 연락처는 업무용 번호·메일만 등록하고, 온콜에 배정할 때 국외 처리위탁(나라, 받는 자, 항목, 목적, 보유 기간)을 서면으로 알린다(3호 나목, 시행령 §29의7. 근로·용역 계약 이행으로 보는 것은 해석). Healthchecks.io에는 사람 연락처를 넣지 않고 IRM·Slack 웹훅으로만 알린다. Slack 서울 데이터 레지던시(Business+ 이상)를 쓸지는 운영으로 넘어갈 때 소유자가 정한다(review/open-items.md 60번) (추천 적용 2026-10-28).
5. **Turnstile은 국외 처리위탁으로 공개한다**: 봇 차단에서 Cloudflare는 처리자이므로 3호 가목으로 공개한다(공정한 예매와 계정 보호가 계약 이행에 필요하다고 보는 것은 해석). 서버 검증(Siteverify)에는 `remoteip`를 보내지 않는다. Cloudflare가 관리자로서 같은 신호를 탐지 개선에 쓰는 부분이 PEAKET의 국외 제공인지는 확인 필요(POL-027)다(추천 적용 2026-10-28).
6. **Web Push는 법률 검토 전까지 보수적으로 공개한다**: 이용자 브라우저의 푸시 서비스 운영사(구글·모질라·애플·마이크로소프트)를 받는 자로 처리방침에 적는다. Topic에는 대상 ID 원문 대신 무작위 값이나 키를 건 해시(HMAC) 값을 쓰고, 본문은 RFC 8291로 암호화하며, VAPID `sub`에는 팀 메일을 쓴다(추천 적용 2026-10-28).
7. **나라 밖으로 '제공'하지 않는다**: 지금은 국내 파트너만 받는다 [가정]. 파트너 계약에 '예매자·배송 명단은 국내에서만 처리·조회한다'를 넣는다. 해외 기획사 공연을 받게 되면 예매 때 국외 제공 별도 동의(1호, 다섯 항목을 미리 알림)를 더한다(추천 적용 2026-10-28).
8. **개인정보가 드는 로그는 서울에 둔다**: CloudFront용 WAF 로그는 서울 S3 버킷으로 받고 CloudWatch Logs·Firehose(us-east-1 강제)는 쓰지 않는다. `Cookie`·`Authorization` 헤더를 가리고, 가림이 로그의 헤더 목록에 실제로 먹는지는 시험(V-T42)으로 본다. 서울 S3로 받을 수 없으면 소유자가 국외 보관 공개와 로그 끄기 중에서 정한다(review/open-items.md 50번). CloudFront 표준 로그를 켜면 서울 S3로 받고 쿠키 로깅을 끈다. 운영 엣지 함수는 `console.log`로 식별값·쿠키를 쓰지 않는다(추천 적용 2026-10-28).
9. **수탁자 목록**: 처리방침에 AWS(서울 리전도 국내 처리위탁), 결제사와 쓰는 하위 결제사, 본인확인기관, 알림 발송 대행, Cloudflare(사람 확인), 오류 도구(클라우드일 때)를 수탁자로 적는다. 재수탁자와 수탁자의 국외 재이전(토스페이먼츠 해외 결제수단, 포트원 국외 처리위탁)은 그 수탁자의 처리방침 링크로 알린다(§26②, 작성지침). 직원 정보만 맡는 온콜·협업 도구 운영사(Grafana Labs, Slack, GitHub)는 결정 4의 서면 고지로 알린다(추천 적용 2026-10-28).
10. **업체 고르는 기준**: 알림 발송 대행(review/open-items.md 57번)과 본인확인 업체(58번)의 비교 기준에 '국외 재이전 여부'를 넣는다(추천 적용 2026-10-28).
11. **이미지 서명 신원**: 컨테이너 이미지 서명은 CI 워크플로 신원으로만 한다. 사람 계정으로 서명하면 이메일이 공개 투명성 로그(Rekor)에 영구히 남기 때문이다(추천 적용 2026-10-28).

## 결과와 트레이드오프

- 처리방침(wbs 7.4.1)을 쓸 때 국외 이전 절과 수탁자 목록을 정본 목록에서 그대로 만든다. 새 서비스를 들이면 목록부터 고친다.
- 오류 도구가 클라우드로 정해지면 EU 조직으로 만들어야 하므로, 판정(wbs 4.8.2) 전에 미국 조직을 만들지 않는다.
- 온콜·인시던트 기록에서 이용자를 가리킬 때 콘솔 링크를 거쳐야 해 한 번 더 누른다.
- WAF 로그를 서울 S3로만 받으므로 CloudWatch Logs Insights로 바로 조회하지 못하고, S3를 읽는 도구(예: Athena)로 본다.

## 되돌릴 조건

- 법률 검토(wbs 7.4.1)에서 운영 도구(Turnstile·IRM·Slack·GitHub)의 국외 처리위탁이 3호로 덮이지 않는다고 정하면, 해당 도구를 국내 대안으로 바꾸거나 별도 동의를 받는다.
- 개인정보위가 일본·미국 등에 동등성 인정을 하면 해당 지점의 근거를 5호로 바꾼다.
- AWS가 서울 밖 리전을 거치지 않는 WAF 로그 경로를 문서로 확인해 주거나 반대로 막으면 결정 8을 다시 본다.

## 남는 한계

- 사람 규칙(인시던트 기록에 이용자 식별값을 쓰지 않음)은 완전히 막지 못한다. 월 접속기록 점검(FR-064) 때 표본을 본다.
- Web Push의 보낸 시각과 길이, Turnstile 신호의 처리 위치, Grafana IRM의 저장 위치는 PEAKET이 고를 수 없다.
- 도쿄 사본에는 봇 행동 신호와 원문 IP가 든 접속기록이 7일 남는다(위 대안 표의 마지막 행).
- 확인 필요 항목(POL-027, 3건): Turnstile 개선 목적 처리의 성격, 직원 연락처 국외 처리위탁을 서면 고지로 처리할 수 있는지, Web Push가 국외 이전인지. 운영 도구(사람 확인·온콜·협업 도구)를 3호로 보는 것은 해석(POL-027)이고, 출시 전 법률 검토에서 함께 본다.
