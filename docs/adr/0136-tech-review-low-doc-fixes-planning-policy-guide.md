# ADR-0136: 기술 검토 낮음 항목의 문서 수정 묶음 4 — 기획·정책·용어·guide(2026-10-28)

- **상태**: 채택 (2026-10-28. 기술 검토(review/tech-review.md)의 낮음 항목(영역: 기획(개요·요구사항), 정책·용어·IA, guide/ 대조)에 소유자가 "나머지 건수들은 모두 추천안에 동의합니다. 그렇게 모두 수정해주세요."라고 정했다. 방향은 소유자 결정(추천안 승인)이고, 검토가 안을 고르지 않은 곳의 선택과 값 같은 세부는 추천 적용이다. 측정 전 값은 [가정]으로 표시했다) 2026-10-31(ADR-0174, 소유자 결정): 낮음-122의 '사람 표본에 확장 프로그램 층'은 판정용 사람을 모으지 않기로 해 바뀐다. 링크를 미리 여는 확장 프로그램을 켠 브라우저를 모의 사람 시나리오로 돌려 허니팟 오탐 경로를 회귀 시험으로 보고, 허니팟의 실제 정밀도는 출시 뒤 표본 검토로 잰다(ADR-0174 결정 4).
- **관련**: review/tech-review.md(낮음-112·낮음-113·낮음-114·낮음-115·낮음-116·낮음-117·낮음-118·낮음-119·낮음-120·낮음-121·낮음-122·낮음-123·낮음-124·낮음-125·낮음-126·낮음-127·낮음-128·낮음-129·낮음-130·낮음-131·낮음-132·낮음-133·낮음-134·낮음-174·낮음-175·낮음-176·낮음-177·낮음-178·낮음-179·낮음-180·낮음-181·낮음-182·낮음-183·낮음-184·낮음-185·낮음-186·낮음-187), review/consistency-review.md R-154, 00-summary.md §6·질문 61, 같은 날 새 ADR-0100~0126(새 결정이 필요한 항목)

## 맥락

2026-10-27 기술 검토 2판은 설계의 모든 기술·기법을 시니어 개발자 관점에서 따져 높음·중간·낮음 항목으로 냈다. 2026-10-28 소유자가 남은 항목을 모두 추천안대로 고치라고 정했다. 새 결정이 필요한 항목은 따로 ADR(0100~0126)을 썼고, 이 ADR은 정본 문서를 고쳐 반영한 낮음 항목 37건의 문제와 결정을 한곳에 모은다. 검토 문서에서는 이 항목들의 본문을 지우고 이 ADR을 가리키는 한 줄만 남겼다(지운 본문은 git 이력에 있다).

## 결정

항목마다 검토의 추천 수정을 따랐다(소유자 승인). 검토가 안을 여럿 내고 고르지 않은 곳은 고른 안과 이유를 적었고 '추천 적용'으로 표시했다. 정본에는 `(추천 적용 2026-10-28, 기술 검토 <번호>)`로 표시했다.

#### 낮음-112 6대 약속 표에 증명 방식 표시가 없다
- **문제**: 6대 약속 표에 증명 방식 표시가 없다
- **결정**: 경영진 요약의 약속 표에 정본 범주로 증명 방식 칸을 더한다(소유자 승인).

#### 낮음-113 남은 결정 4안건의 범위가 드러나지 않는다
- **문제**: 남은 결정 4안건의 범위가 드러나지 않는다
- **결정**: 경영진 요약의 네 안건에 포트폴리오 일정 영향 여부를 붙이고, 공개 범위 안건에 배치도 공개 위험과 다시 볼 조건을 적는다(소유자 승인, 판정은 추천 적용).

#### 낮음-114 화면 낭독기 '완주율 100%'의 시험 조건이 없다
- **문제**: 화면 낭독기 '완주율 100%'의 시험 조건이 없다
- **결정**: 완주율 100%를 'TalkBack을 더한 낭독기 조합 셋 × 3대 시나리오 × 3회 [가정] 모두 완주'로 정하고, 개발자 수동 시험임을 표시한다(소유자 승인, 조합의 브라우저와 회차 수는 추천 적용).

- **문제**: K9 '60초 확장'의 전제와 '노드 기동 문서 인용'의 출처가 비어 있다
- **결정**: K9의 60초를 '노드가 미리 있을 때 파드 확장'으로 한정하고, 노드 기동은 문서 인용(없으면 확인 필요)과 T-40분 프리워밍으로 다룬다(소유자 승인).
- **바꾼 문서**: planning/01 §3.1 K9, planning/02 NFR-023, docs/verification.md §5.3

#### 낮음-116 전환율 83%를 '보증'한다고 쓴다
