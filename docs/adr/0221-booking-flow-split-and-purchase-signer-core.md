# ADR-0221: 좌석·결제·결과 화면(HOT-350)을 열셋으로 나누고, 구매 세션 서명기 핵심을 먼저 만든다

- **상태**: 채택(2026-11-06, 추천 적용). BUILD_ORDER HOT-360 ①.
- **관련**: [docs/frontend.md](../frontend.md) §3.5·§3.6·§3.12·§4.1·§4.2.2·§4.2.3·§5.3·§5.17 FE-T7, [docs/security/asvs/frontend.md](../security/asvs/frontend.md) V11, [docs/api/openapi.yaml](../api/openapi.yaml) `PurchaseSeq`·`PurchaseMac`·`ClientEphemeralKey`·`AdmissionResult.serverEcdhPublicKey`, `packages/platform/src/purchase-auth.ts`, ADR-0050 결정 8, ADR-0079 결정 6, ADR-0124, ADR-0216
- **관련 ID**: SCR-010, SCR-011, SCR-012, FE-T6, FE-T7

## 맥락

- HOT-350(2.25일)은 SCR-010~012 세 화면이다. 결제사 결제창, 결제창 복귀 착지, 넘겨받은 일 다섯 묶음도 함께 들어 있다. 넘겨받은 일은 HOT-110·HOT-120의 좌석맵 엔진 잇기, PRF-110의 `seatmapLayoutPath`, HOT-343의 자동 배정 `auto`, HOT-345의 좌석 화면 자산 목록이다.
- 정본을 모아 보니 6일 넘게 걸린다. 서버가 아직 없는 길도 셋이다.
  - 홀드 다시 읽기·연장·해제: HOT-070
  - 실시간 좌석 델타: realtime-gw, HOT-090
  - 결제 시도 `POST …/payments`: PRF-190
- 차례도 막힌다. 좌석 화면의 첫 스냅샷 요청은 입장 토큰을 처음 쓰는 요청이다.
  - 이 요청에 클라이언트 임시 공개키(`X-Client-Ephemeral-Key`)가 필수다. 서버는 이 키로 구매 세션의 요청 인증 키를 합의한다.
  - 그런데 키 쌍을 만들고 요청 인증 키를 지니는 일은 HOT-360(구매 세션 서명기)에 있다. HOT-360은 BUILD_ORDER에서 HOT-350 뒤에 있다.
  - 좌석 화면을 먼저 이으면 공개키를 보낼 수 없거나, 보내고 키를 버려 홀드에 서명하지 못하게 된다.
- 서명기에도 정본의 빈칸이 있다.
  - `@peaket/api-client`에는 요청마다 머리를 한 번만 만든다. 구매 세션 쓰기는 시도마다 일련번호·MAC을 새로 만들어야 하는데, 시도마다 부르는 자리가 없다(BAS-210이 넘김).
  - 서명할 작업을 화면이 고르게 하면 빠뜨릴 수 있다.
  - 시험 벡터는 서버 패키지 안(`packages/platform/test/vectors`)에만 있다.
  - FE-T7의 도구 행은 Vitest 브라우저 모드다. 그런데 그 공급자(`@vitest/browser-playwright`)는 작업 공간에 없다.

## 결정

1. **나눔과 차례**(갈래 2, 위에서부터 한다)
   - **HOT-360 ①**(이 단계): 구매 세션 서명기 핵심. 키 합의·키 유도, `peaket-purchase` 저장, `ps:{jti}` 잠금 아래의 일련번호, MAC, api-client의 시도마다 붙는 서명 머리, 공용 시험 벡터, 세 엔진 FE-T7.
   - **HOT-350 ①**: 좌석 화면에 실제 좌석맵 엔진을 잇는다.
     - 입장 저장값을 읽는다.
     - 첫 스냅샷을 서명기의 공개키로 보낸다.
     - 확대·축소 버튼과 안내를 둔다. 끌기·휠·핀치로 움직이고, 회차 가격표의 등급 차례를 쓴다.
     - 좌석맵 판이 다르면 좌석맵 파일을 다시 받는다.
     - 가짜 API에 실제 배치와 이진 스냅샷을 둔다.
     - 좌석 화면의 목업과 상태 고르기를 걷어 낸다.
   - **HOT-351**: 입장 확정 응답의 `seatmapLayoutPath`를 서버(queue-svc)가 싣는다.
   - **HOT-352**: 좌석 화면 자산 목록 `/_q/seat-preload.json`을 빌드가 만든다. 대기실이 미리 받은 좌석맵 파일을 좌석 Worker가 캐시에서 읽는지 본다.
   - **HOT-353**: 좌석 고르기와 홀드. 예매 흐름 기계의 `selecting`·`holding`·`held`를 둔다.
     - 서명한 홀드를 보낸다.
     - 409는 되돌리고 추천을 보인다. 422·423·410·401을 다룬다.
     - 자동 배정 `auto`와 `auto-assign-not-supported`를 다룬다.
     - 바텀 시트와 카운트다운, [예매 그만두기](구매 세션 나가기)를 둔다.
   - **HOT-361**: 구매 세션 401의 갈래와 복제 탭 세 엔진(FE-T6의 나머지).
     - 401에서는 키를 지우고 '예매 시간이 끝났습니다'를 보인다. 15분 안이면 대기실로 다시 들어간다.
   - **HOT-354**: 접근성 좌석 목록(CMP-022)과 목록 열기 메시지(§4.7 `sectionState`·`stateChanged`)
   - **HOT-355**: 결제 화면(SCR-011)의 주문 생성(`POST /v1/orders`, 서버가 계산한 금액, 동의)
   - **HOT-362**: 결제창 복귀 착지와 결제 접수, 결제창 이동 통일(HOT-360이 넘긴 것).
     - 쿠키 없는 정적 셸이 결제 값을 읽고 지운다. 서명한 `payment-acceptance`를 보내고, 새로고침에 대비한다.
     - 가짜 API의 복귀 주소로 본다.
   - **HOT-363**: 결과 화면(SCR-012)과 결제 결과 기계(wbs 2.10.7의 '결과 확인 상태 기계', `payment-status` 롱 폴링, `issueDelayed`, 상태별 문구)
   - **HOT-356**: 홀드 다시 읽기·연장·해제와 '방금 놓은 좌석' 30초(대기: HOT-070)
   - **HOT-357**: 실시간 구역 구독·델타·연결 상태 기계·Degraded·시계 맞추기(대기: HOT-090)
   - **HOT-358**: 결제 시도와 결제사별 결제창(대기: PRF-190)
     - 토스·포트원 SDK를 결제 화면에서만 동적 import한다. 데모 시뮬레이터 결제창을 둔다.
     - SDK 창 메시지 규칙에서 frontend §5.3('받지 않는다')과 payment·ASVS 3.5.5가 엇갈린다. 이 엇갈림을 이 단계의 ADR로 정한다.
   - 대기가 붙은 셋은 서버 단계가 `develop`에 들어오면 한다. 그 전에는 건너뛰고 다음 단계로 간다(PROGRESS 턴 규칙).
2. **서명기는 `@peaket/api-client/purchase`에 둔다.** `crypto.subtle`만 쓰고 새 패키지를 들이지 않는다(ASVS 11.2.1). 알고리즘·HKDF `info`·키 길이는 이 모듈의 상수 한 곳에서 고른다(ASVS 11.2.2).
3. **키 수명**(§5.3 그림대로)
   - 입장 토큰을 처음 쓰기 전에 `openPurchaseSession`을 부른다. 직접 선택은 첫 스냅샷 전, 자동 배정은 첫 홀드 전이다.
   - `jti`는 입장 토큰(JWT)의 본문에서 서명을 확인하지 않고 읽는다. 서명은 서버가 확인한다.
   - 브라우저는 ECDH P-256 키 쌍을 만든다. 개인키는 추출 불가다.
   - 입장 확정 응답의 서버 공개키(JWK)와 합의해 공유 비밀 32바이트를 얻는다. 서버 `purchaseRequestKey`와 같은 식으로 요청 인증 키를 만든다.
     - 식: HKDF-SHA256, salt는 `jti`의 UTF-8, info는 `PEAKET-purchase-v1`
     - 결과: HMAC-SHA256 키, `length: 256`, 추출 불가, 서명에만 쓴다
   - ECDH 개인키는 합의 뒤 버리고 저장하지 않는다.
   - IndexedDB `peaket-purchase`(판 1)의 `sessions`(키 `jti`)에 네 값을 둔다. 공개키는 비압축 점의 base64url이다.
     - 요청 인증 키
     - 일련번호 0
     - 만료
     - 보낸 클라이언트 공개키(§3.12 표에 더한다)
   - 입장 토큰은 저장하지 않는다. 서명기는 화면이 입장 저장값(`peaket.admission.{eventId}`)에서 읽어 넘긴 토큰을 메모리에만 둔다.
   - 만료는 입장 확정 응답의 `purchaseSessionExpiresAt`이다. 없으면 입장 토큰의 `exp`를 쓴다.
   - 이 만료는 기기 시계로 재므로 세션을 거절하는 데 쓰지 않는다. 계약이 이 값을 '표시에만 쓰고 판단은 서버가 한다'고 정했다. 시계가 빠른 기기도 첫 열기와 결제 뒤 복귀 화면의 다시 열기가 된다. 세션이 끝났으면 서버가 401로 알린다.
   - 같은 `jti`의 항목이 살아 있으면 새로 만들지 않고 그것을 쓴다. 그래서 첫 스냅샷 전후에 새로고침해도 같은 공개키를 다시 보낸다. 서버는 다른 키를 401로 거절한다.
   - 앱이 시작할 때(서명기를 처음 열 때) 만료하고 여유 24시간 [가정]이 지난 항목을 지운다. 시계가 빠른 기기에서 살아 있는 세션의 키를 지우지 않기 위해서다. 세션 끝·로그아웃에는 그 항목이나 DB를 지운다(§3.12).
   - 서버 공개키가 없거나 합의에 실패하면 서명기를 만들지 않는다. 화면은 그 구매 세션을 시작하지 못한 것으로 다룬다(HOT-353·361).
4. **순서 보장**
   - 서명 요청 하나 전체를 Web Locks `ps:{jti}` 안에서 보낸다. 자동 재시도를 포함하고, 응답이나 시간 초과까지다.
   - 시도마다 IndexedDB 트랜잭션 하나에서 일련번호를 읽고 1 올린 뒤, 그 번호로 MAC을 만든다.
   - Web Locks가 없는 브라우저는 그 페이지 안의 차례 줄로 대신한다. 다른 탭과의 차례는 서버가 일련번호로 거른다.
5. **api-client가 서명할 작업을 계약으로 고른다.**
   - 생성기는 매개변수에 `PurchaseSeq`가 있는 작업에 `purchaseSigned`를 단다.
   - 그 작업은 `RequestOptions.purchase`(서명기)가 없으면 보내지 않고 거절한다(TypeError). 빠뜨리면 401이 아니라 개발 중에 바로 드러나게 한다.
   - 시도마다 머리 셋을 새로 단다.
     - `X-Admission-Token`
     - `X-Purchase-Seq`
     - `X-Purchase-Mac`: 보낸 주소의 경로 + 쿼리, 처음 한 번 만든 본문 바이트로 만든다
   - 자동 재시도는 같은 멱등 키로 1회만 한다(§4.1 '자동 재시도'). 잠금을 쥔 채 기다리므로 기다림이 10초 [가정]를 넘으면 다시 보내지 않고 화면에 올린다.
   - 401 `purchase-seq-reused`만 새 번호로 한 번 다시 보낸다. 자동 재시도 횟수와 따로 센다(§5.3 '401').
   - 다른 401 갈래와 다시 보낸 뒤의 `purchase-seq-reused`는 오류로 그대로 올린다. 화면에서는 모두 세션 끝이다(`purchaseUnauthorizedAction`).
6. **시험 벡터를 계약 옆 공용 위치로 옮긴다.** 새 위치는 `docs/api/vectors/purchase-request-mac.v1.json`이다(BUILD_ORDER HOT-360, R-226). 서버 시험(`packages/platform`)과 화면 시험(`packages/api-client`)이 같은 파일을 읽는다.
7. **FE-T7은 두 층에서 본다.**
   - Node 단위 시험(Node의 `crypto.subtle`)이 벡터를 본다. 벡터는 MAC 입력, HKDF 키 바이트(시험에서만 추출 가능으로 만든다), 경우별 MAC이다.
   - Node 단위 시험은 합의 왕복도 본다. 서버 쪽 `purchaseRequestKey`와 같은 키가 나와야 한다.
   - 세 엔진(Chromium·WebKit·Firefox)은 `tools/web-checks`의 Playwright 검사가 본다.
     - 같은 벡터
     - 추출 불가 키를 IndexedDB에 두고 다시 연 페이지에서도 같은 MAC이 나오는지, 내보내기는 거절되는지
     - 두 탭이 같은 `jti`로 동시에 보낼 때 일련번호가 겹치거나 거꾸로 받히지 않고, 서버가 동시에 처리한 요청이 늘 하나인지(잠금이 응답까지 이어지는지)
     - IndexedDB 지우기(세션 끝·만료 여유·로그아웃)와 잠금 기다림 취소
   - Vitest 브라우저 모드는 쓰지 않는다. 공급자 패키지를 새로 들여야 하고, 같은 Web API를 이미 있는 Playwright 틀로 볼 수 있다. FE-T13·FE-T28처럼 같은 도구 행의 다른 시험이 필요해지면 그때 함께 다시 본다.

## 결과

- 좌석 화면(HOT-350 ①)은 서명기가 만든 공개키로 첫 스냅샷을 보낸다. 홀드(HOT-353)부터는 `purchase` 하나만 넘기면 서명된다.
- 서명할 작업을 화면이 빠뜨리면 보내기 전에 거절된다.
- 새 판의 서명 규칙(HKDF `info` v2)은 이 모듈의 상수와 벡터 파일만 바꾸면 된다.
- 서명기가 빠질 때(ADR-0124, S-T16 결과)는 `purchase` 모듈과 `peaket-purchase` 저장, 벡터를 지운다. 생성기의 `purchaseSigned`도 지운다.
- 소비자 웹의 로그아웃 정리 루틴(§5.14.4 2번)은 아직 없다(대기실 경량 페이지만 있다). 그 루틴이 생기면 `peaket-purchase`를 지운다. 여기서는 서명기가 지우는 함수(`clearPurchaseSessions`)만 둔다.

## 검토한 다른 안

- **HOT-350 차례대로 좌석 화면부터 잇기**: 공개키를 보낼 수 없어 첫 스냅샷이 400이다. 키를 만들고 버리면 홀드부터 서명할 수 없다. 고르지 않았다.
- **서명할 작업을 화면이 머리로 넘기기**: 시도마다 새 번호를 만들 수 없고 빠뜨리기 쉽다. 고르지 않았다.
- **ECDH 개인키도 저장해 다시 합의하기**: 요청 인증 키 하나면 되고, 남는 비밀이 늘어난다(ASVS 11.1.1, 공유 비밀은 두 주체까지). 고르지 않았다.
- **Vitest 브라우저 모드 들이기**: 위 결정 7의 이유로 지금은 미뤘다.
