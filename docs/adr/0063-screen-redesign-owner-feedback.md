# ADR-0063: 화면 개편 — 홈 구성, 공연 상세의 상세정보·관람 후기, 본인확인 흐름 등(2026-10-14)

- **상태**: 채택 (2026-10-14. 소유자가 디자인 시안을 보고 일곱 가지를 요청했고, 확인 질문에 홈은 'NOL 레이아웃을 따라 함', 본인확인은 '별도 화면 없앰(권장)', 나머지 다섯은 '적은 대로 진행(권장)'으로 답했다. 소유자가 고른 방향은 소유자 결정이고, 세부 값·문안·데이터 구조는 추천 적용으로 소유자 검토 대상이다.) 2026-10-14 소유자 결정(ADR-0064): 결정 11의 '판매 종료는 공연 시작 시각'을 '공연 시작 24시간 전'으로 바꾸고, 사전 셔플 공연도 판매 종료까지 판다(오픈 뒤 진입 410을 없앰, K25에서 그 문제를 뺌). 2026-10-19 ADR-0066: 후기 화면 표기를 '후기'로 하고 사진·일반 신고를 더했으며, 좌석맵 에디터 두 층을 네 단계(배치 그리기·좌석 채우기·좌석 다듬기·미리보기)와 템플릿 10종으로 구체화했다(두 층 결정은 그대로). 2026-10-19(ADR-0066 결정 2): 오픈 예정 카드의 [오픈 알림 받기]는 공연명을 담은 종 아이콘 토글로 바뀌었다. 2026-10-26: 등급 면 색으로 빌리는 데이터 시각화 팔레트 heat.1~3의 값과 칠하는 순서를 정했다(design/tokens.json, design/d2 CMP-024, ADR-0089). 2026-10-27(ADR-0093·0094): 입력 중 후보 창의 이름을 '자동완성'으로 바꿨다('연관 검색어'는 검색 기록으로 만드는 기능에만 쓴다). 홈·검색·랭킹 카드(`EventCard` → `ProductionCard`)와 찜은 공연 단위, 홈 공연장 줄과 검색 공연장 필터는 공연장 `placeId`, 후기 목록·요약은 공연의 모든 회차를 모은다. 자동완성의 Redis 캐시는 없애고 서버 메모리 사전으로 답한다. `/search`는 정적 셸과 noindex로 바꿨다.
- **관련**: ADR-0040(SEED Design 토대, NOL 약관), ADR-0045(통신판매중개자), ADR-0051(현장 입장), ADR-0059·0060(화면 설계), ADR-0061(콘솔 휴대폰·태블릿), ADR-0062(미정 항목 추천 적용), FR-002, FR-003, FR-007, FR-009, FR-016, FR-023, POL-004, POL-016, POL-024, POL-032, POL-037, POL-042(관람 후기, 새로), POL-043(홈 구성, 새로), NFR-019, NFR-020, CMP-071~073(새로), SCR-001·002·003·006·008·010·011·015·016·022·058·068

## 맥락

- 소유자 피드백(2026-10-14) 일곱 가지: ① 홈(SCR-001)은 기획 요구사항을 지키되 NOL 티켓 메인 화면 구성을 따른다 ② 공연 상세(SCR-002)에 상세정보(보통 이미지) 섹션이 없다. 기대평은 빼고 관람 후기만 두며, 후기는 공연이 끝난 직후부터 그 공연 예매자만 쓴다. 상세 화면에 후기 2개를 미리 보이고 전체는 모달로, [리뷰 쓰기] 버튼을 알맞은 곳에 둔다. 예매 안내사항·취소 및 환불 안내사항·판매자 정보는 제목을 누르면 모달로 연다 ③ 검색(SCR-003)에 검색창이 머리와 본문에 겹친다(머리 하나로 충분), 페이지 번호가 없다, 연관 검색어 창을 디자인하지 않았다 ④ 본인확인(SCR-006)은 본인확인기관 창이 열리므로 별도 화면이 필요 없지 않은가 ⑤ 외부 브라우저 안내(SCR-058)가 Safari·Chrome만 말한다. Windows 기본 브라우저인 Edge도 지원하게 보강한다 ⑥ 대기열(SCR-008)에 정보가 너무 많다. 내 앞 대기 인원, 진행 막대(더 인터랙티브하게), 남은 예상 시간, 대기 취소만 둔다 ⑦ 좌석 선택(SCR-010)이 무대 전체 배치와 좌석 선택을 동시에 보인다. 전체 배치를 화면 가득 보이고 확대하면 그 위치의 좌석을 고르게 하며, 좌석맵 에디터(SCR-022)도 맞춘다.
- NOL 서비스 이용약관(2026-09-29 시행본, 2026-10-14 원문 확인) 제23조(이용자의 의무)④는 사전 서면 허가 없이 자동화 수단이나 수동 프로세스로 서비스의 콘텐츠를 모니터링·복제·수집·확인·정리·사용하는 행위(제15호)와 사전 서면 승인 없이 회사의 브랜딩, 페이지 레이아웃이나 디자인을 사용·복제·전시·미러링하는 행위(제20호)를 금지한다. ADR-0040은 이 때문에 NOL 토큰 추출을 하지 않았고, design/d1 §3은 레퍼런스를 일반 패턴 참고로만 쓰게 했다. 이 위험을 소유자에게 알렸고, 소유자는 홈 화면 구성을 따르고 그 위험을 감수하기로 했다(2026-10-14).
- 공연법 시행령 §3의3(2026-08-28 시행, 2026-10-14 원문 확인)은 입장권 판매 화면에 부정구매·부정판매 관련 게시물의 신고 기능(각 호 나목)과 노출 제한 미리 알림(각 호 다목), 처벌 고지(각 호 라목)를 요구한다. 지금 정본은 기대평·관람 후기 영역에 신고 버튼과 노출 제한 고지(POL-024 다목)를 두고 있었다.
- 지원 브라우저는 이미 NFR-019(Chrome·Safari·Samsung Internet·Edge·Whale 최신 2개)에 Edge가 들어 있었고, 어긋난 것은 SCR-058의 안내 문구였다.

## 결정

### 1. 홈(SCR-001) — NOL 메인 화면 구성을 따른다(소유자 결정)

- 따르는 것은 섹션 순서·배치·크기 비율뿐이다. NOL의 로고·이미지·문구·배지 이름·아이콘 그림·색은 쓰지 않고, 시각은 피켓 디자인 시스템(SEED 토큰, 인디고)을 그대로 쓴다. 구성 메모는 사람이 공개 화면을 보고 말로 적었고, 자동 수집이나 스크린샷 저장은 하지 않았다. 피켓 기획에 없는 기능(포인트 적립·결제 혜택, 할인·타임딜, 영상 클립, 쿠폰 탭)은 넣지 않거나 피켓 기능으로 바꾼다.
- 섹션(위에서 아래로): 전역 머리(유일한 검색 입력) → 큰 배너 슬라이드(본문 폭 1240 안쪽, 높이 약 400, 'n / N'과 [일시정지], 5초 [가정] 자동 넘김, 포커스·마우스가 올라가면 멈춤) → 장르 바로가기 타일 한 줄 → 오픈 예정(가로 카드 줄, [오픈 알림 받기]) → 찜한 공연(로그인한 경우) → 장르별 랭킹 → 지금 판매 중(마감 임박 순, 3열 가로형 카드) → 굿즈 스토어 띠 배너 → 테마 추천 → 공연장(원형 이니셜, 로고 이미지 없음) → 바닥글(지금 그대로). 휴대폰·태블릿은 같은 순서를 쌓고 가로 줄은 가로 스크롤로 보인다(추천 적용).
- 배너와 테마는 운영 콘솔 SCR-068에 새 탭 [홈 구성]을 두어 운영자(operator) 한 사람이 판매 승인된 공연 가운데 골라 순서와 노출 기간을 정하고 감사 로그를 남긴다. 배너 이미지는 운영자가 올린 가로형 이미지(1240×400 이상 [가정])와 대체 텍스트다. 배너·테마 자리는 돈을 받고 팔지 않는다. 유료 노출은 이번 범위 밖이며, 도입하려면 새 ADR로 정한다(추천 적용).
- 장르별 랭킹은 분석 저장소의 확정 판매 기준 '어제 판매 매수' 순이고 매일 10:00 [가정]에 다시 계산해 정적 파일로 CDN에 낸다. 판매 승인된 공연만 넣고, 매진·판매 종료 공연은 '매진' 배지와 함께 남긴다. 섹션에 기준('어제 판매 매수 기준, 매일 오전 10시 갱신')을 적는다(추천 적용).
- 자동으로 넘어가는 배너에는 일시정지 수단을 둔다(WCAG 2.2 SC 2.2.2, NFR-020). 로딩·빈 상태·오류와 100만 동시 접속 때 캐시 규칙은 지금 SCR-001 규칙을 따른다(섹션마다 스켈레톤, 빈 섹션만 숨김).

### 2. 공연 상세(SCR-002) — 상세정보 섹션과 안내 모달(소유자 요청, 세부는 추천 적용)

- 데스크톱은 2단(왼쪽 본문, 오른쪽 고정 예매 패널)이고, 본문 위에 스크롤을 따라 붙는 섹션 바로가기 탭(공연 정보·상세정보·판매 조건·장소·후기)을 둔다.
- 상세정보 섹션을 새로 둔다. 파트너가 공연 등록(SCR-021 1단계)에서 올린 설명 글과 상세 이미지(0~10장)를 이어 보이고, 처음에는 1,200px [가정]까지만 보인 뒤 [상세정보 더보기]로 펼친다. 이미지마다 대체 텍스트를 받고, 이미지에만 있는 정보는 설명 글로도 적게 한다(WCAG 2.2 SC 1.1.1·1.4.5, ADR-0062 결정 38의 이미지 기준).
- 본문 아래에 단추 셋(예매 안내사항·취소·환불 안내사항·판매자 정보)을 두고 누르면 모달로 자세한 내용을 연다. 예매 안내사항은 접는 항목(예매 전 확인, 대기실과 순번, 가상계좌 결제, 모바일 티켓과 입장용 휴대폰, 양도, 부정구매·부정판매 처벌)으로, 취소·환불 안내사항은 POL-032 공제표·취소 방법과 기한·환급 수단과 기한·회차 취소와 연기·미성년자 계약 취소로, 판매자 정보는 신원정보 7항목과 공연용 중개자 고지(POL-037)로 채운다. 문장은 정본(POL·FR·design/d5)에서 가져온다.
- 법정 고지는 모달에만 숨기지 않는다. 정렬 방식 표준 문구(POL-004), 부정구매·부정판매 처벌·과징금(POL-024 라목), 핵심 판매 조건 요약과 공연일 10일 이내 취소 시 공제 안내(POL-032 사전 고지), 판매자 줄('판매자: {상호}'과 중개자 고지 한 줄)은 본문에 늘 보이고, 모달은 더 자세히 보는 곳이다.

### 3. 관람 후기(FR-016, SCR-016) — 기대평을 없애고 후기만 둔다(소유자 결정, 세부는 추천 적용)

- 쓰는 자격: 그 회차의 공연 종료 예정 시각(`ends_at`)이 지난 뒤, 그 회차 티켓을 결제한 계정만 쓴다. 취소·환불된 티켓만 가진 계정은 쓰지 못하고, 양도받은 사람은 쓰지 않는다. 한 계정은 한 회차에 후기 하나를 쓰고 고치거나 지울 수 있다. 쓰는 기한은 두지 않는다.
- 내용: 별점 1~5(필수)와 본문 10~1,000자(문자 단위 grapheme) [가정]. 작성자는 닉네임 첫 글자와 '**', 관람 회차 일시로만 보이고 이메일·전화번호·실명은 보이지 않는다.
- 상세 화면에는 평균 별점·후기 수와 최근 후기 2개 미리보기, [후기 n개 전체보기], 섹션 머리 오른쪽 [후기 쓰기]를 둔다. 전체보기는 후기 전체 모달(정렬 최신·별점 높은·낮은 순, '더 보기', 후기마다 암표·매크로 신고, 본인 후기 수정·삭제), [후기 쓰기]는 후기 쓰기 모달(별점, 본문, POL-024 다목 노출 제한 고지, [등록])을 연다. 자격이 없으면 버튼을 숨기지 않고 누를 때 이유를 대화상자로 알린다. SCR-016은 별도 페이지가 아니라 SCR-002 위의 모달 둘이 되고, 모달 상태는 주소(`?reviews=all`, `?review=new`)에 남긴다.
- 신고 버튼, 노출 제한 고지, 금칙어 차단, 같은 내용 자동 숨김, 운영 명령 10(블라인드)은 후기에 그대로 적용한다(공연법 시행령 §3의3 각 호 나목·다목). 별점이 낮다는 이유로 숨기지 않는다.

### 4. 검색(SCR-003)(소유자 요청, 세부는 추천 적용)

- 검색 입력은 전역 머리의 검색창 하나다. 본문의 검색창을 없애고, 휴대폰은 머리의 검색 아이콘을 누르면 이 화면 위쪽이 머리 검색창으로 바뀐다.
- 연관 검색어 창(머리 검색창 아래 드롭다운): 입력 전 포커스 때 이 기기의 최근 검색어(하나씩 지우기·전체 지우기), 2자 [가정]부터 연관 검색어 최대 8개 [가정](공연·아티스트·공연장 구분, 일치한 부분 굵게, 공연이면 작은 포스터와 오픈 일시), 맨 아래 '전체 결과 보기'. ARIA combobox 패턴(listbox·option·aria-activedescendant), ↑↓·Enter·Esc, 이전 요청 취소.
- 결과는 페이지 번호로 나눈다(한 페이지 20개 [가정], 현재 페이지 `aria-current="page"`, 주소 `?q=&page=`).

### 5. 본인확인(SCR-006) — 별도 화면을 없앤다(소유자 결정)

- 본인확인이 필요한 화면의 [휴대폰 본인확인] 버튼이 사용자 동작 안에서 본인확인기관 창을 바로 연다. 목적 문구는 그 버튼 위 한 줄로 부르는 화면에 둔다.
- 결과(완료·창 닫음·실패·기관 장애·다른 계정의 본인·만 14세 미만·부스 대조 불일치·동의 없음)는 부르는 화면 위의 토스트나 대화상자로 보인다. 문구는 지금 design/d5 §5.6 상태 표를 그대로 쓴다.
- 기관이 새 창 대신 페이지 이동으로 처리하는 경우만 짧은 복귀 화면 `/verify/return`(진행 표시만)을 두고, 결과를 받으면 원래 화면으로 돌아가 그 위에 결과를 띄운다. SCR-006 ID는 '본인확인 흐름(기관 창·결과 대화상자·복귀 화면)'으로 남긴다(화면 ID 수는 그대로).

### 6. 외부 브라우저 안내(SCR-058) — Edge를 포함한다(소유자 요청)

- 안내 문구를 기기별 기본 브라우저로 바꾼다: iPhone·iPad는 Safari, Android는 Chrome이나 삼성 인터넷, Windows는 Edge나 Chrome, Mac은 Safari나 Chrome(Whale도 됨). 기기를 알아내면 그 기기 줄을 먼저 굵게 보인다. Windows·Mac의 PC용 메신저 안 브라우저에서는 기본 브라우저(Edge 등)로 여는 방법과 [주소 복사]를 보인다. 같은 'Safari나 Chrome만' 표현이 있는 다른 문서도 고친다. 지원 범위(NFR-019)는 바뀌지 않는다.

### 7. 대기열(SCR-008) — 기본 화면은 네 가지만(소유자 요청, 세부는 추천 적용)

- 기본 화면은 내 앞 대기 인원, 진행 막대, 남은 예상 시간, [대기 취소]뿐이다.
- 진행률 = (처음 받은 앞 인원 − 지금 앞 인원) ÷ 처음 받은 앞 인원(0~100%로 자르고, 처음 앞 인원이 0이면 100%). 새 값이 오면 이전 값에서 부드럽게 채우고, 막대 위 '나' 표시가 움직이며, 숫자가 굴러가듯 바뀐다. 앞 인원이 늘어 보이면(예: 다른 엣지에서 더 오래된 대기 상태 파일을 받은 경우) 막대도 실제 값대로 물러난다. 추가 검증 복귀자는 빠진 번호를 다시 채우지 않으므로 다른 사람의 앞 인원을 늘리지 않는다. `prefers-reduced-motion`이면 효과 없이 값만 바꾼다. `role="progressbar"`와 `aria-valuetext`를 두고 화면 낭독기 알림은 1분에 한 번이다. 처음 앞 인원은 브라우저가 처음 받은 값을 탭의 세션 저장소에 두고 쓴다. 같은 탭에서 새로 고치면 남지만, 탭을 닫았다 다시 열거나 다른 탭·기기에서 열면 그때 값이 새 기준이 되어 0%부터 시작한다.
- 나머지(운영 공지, 일시정지, 순서를 정하는 중, 곧 입장, 만료, 다른 기기에서 취소, 연결 확인 중, 구매가 어려울 수 있음, 추가 검증, 이미 입장)는 생길 때만 띄운다. 등급별 매진 현황은 뺀다. 좌석 자동 배정 공연의 희망 조건은 한 줄 요약과 [바꾸기]로 줄인다.
- 순번 정렬 방식 표준 문구(POL-004)와 처벌 고지(POL-024 라목)는 화면 아래 '순번 안내 ›'가 여는 시트로 옮긴다. 두 고지는 공연 상세(SCR-002)에서 판매 전에 이미 늘 보이므로 미리 알리는 요건은 그대로 충족한다고 본다(해석).

### 8. 좌석 선택(SCR-010)과 좌석맵 에디터(SCR-022) — 전체 배치에서 확대해 고른다(소유자 요청, 세부는 추천 적용)

- 기본은 무대와 구역 배치 전체를 화면 가득 보이고, 구역마다 등급 색과 남은 좌석 정도(많음·적음·매진)를 칠한다. 휠·핀치·[+]·구역 누르기로 확대하면 일정 배율(구역이 화면 폭의 1/3 이상으로 보일 때 [가정])부터 그 범위 구역의 좌석이 나타나 고를 수 있고, 축소하면 다시 구역 색으로 합쳐진다. 미니맵과 [전체 보기]를 둔다. 실시간 좌석 상태는 좌석이 보이는 구역만 구독한다(지금 구역 단위 채널). 오른쪽 선택 패널, 등급 칩·연석 찾기, 접근성 대안 목록(구역 → 열 → 좌석), 자동 배정 공연은 지금 그대로다.
- 좌석맵 에디터는 배치 층(무대·구역 도형: 사각형·다각형·부채꼴, 구역 이름·등급·입장 게이트·라벨 위치)과 좌석 층(구역을 확대해 행·좌석 배치: 행 수·좌석 수·간격·곡률·번호 매기기, 좌석 속성)으로 나누고, 미리보기는 팬 화면처럼 전체에서 확대로 보인다. 가져오기(SVG·JSON·CSV)는 도형과 좌표를 함께 받는다.
- 데이터: 공연장에 캔버스 크기와 무대 도형, 구역에 공연장 좌표계 다각형·라벨 위치, 좌석에 x·y 좌표를 둔다. 좌석맵 정적 파일(CDN)에 구역 도형과 좌석 좌표를 함께 싣고 상태 변화는 지금처럼 구역별 델타로 보낸다.
- 좌석맵 소유 단위: 공연장 배치는 틀이고, 파트너가 좌석맵을 만들 때 틀을 복제해 그 공연용 배치본(배치 버전)을 만든다. 편집은 그 배치본에만 미친다. 판매 승인 뒤 바꾸면 재승인 대기(지금 규칙)이고, 오픈 뒤에는 도형·좌표·좌석 추가·삭제를 바꾸지 않고 좌석 판매 중지 같은 기존 좌석 속성 규칙만 허용한다(추천 적용).

### 9. 장르 목록(추천 적용)

- 홈 장르 타일·검색 필터·장르별 랭킹·공연 등록은 같은 장르 목록(콘서트·뮤지컬·연극·클래식·페스티벌·팬미팅·기타)을 쓴다. 프로토타입 파트너 공연 등록의 목록과 같다. 홈 장르 타일은 이 7개에 굿즈 스토어·공연장·전체 장르(장르 필터 없는 검색)를 더한 10칸이다(휴대폰 5×2).

### 10. 판매자 신원정보와 표시 가격(추천 적용)

- 공연 상세는 판매자 줄과 [판매자 정보] 모달(소유자 요청)로 두고, 결제 직전 화면(SCR-011) 본문에 판매자 신원정보 7항목을 접지 않은 작은 정보 상자로 늘 보인다. 전자상거래법 §20②(2026-07-21 시행본, 2026-10-14 원문 확인)는 통신판매중개업자가 신원정보를 '청약이 이루어지기 전까지' 소비자에게 제공하도록 하므로, 모달만 두는 배치가 충족하는지 따질 필요 없이 청약 직전 본문에서 제공한다.
- 전자상거래법 §21의2①1호와 전자상거래 소비자보호 지침(고시 제2025-8호) 12.가·나(2026-10-14 원문 확인)는 가격이 처음 보이는 화면(검색 결과·상품 목록·사진과 가격이 함께 있는 초기 화면)에서 필수 비용을 포함한 총금액을 보이게 하고, 배송비도 필수 비용에 넣되 추가 비용이 없는 기본 선택지가 있으면 그보다 비싼 선택지의 비용은 뺀다. 티켓은 예매 수수료가 없으므로(POL-032) 홈·검색 카드의 티켓 가격이 곧 총금액이다. 굿즈 목록과 홈 굿즈 배너에 가격을 보이면 택배만 되는 상품은 배송비를 포함한 총액을 앞에 두고, 현장 수령(무료)도 되는 상품은 상품가와 '택배 배송비 별도(현장 수령 무료)'를 함께 보인다. 이 규칙은 개편 전 굿즈 목록에도 빠져 있던 것이다.
- 장르별 랭킹의 기준 문구는 법정 의무가 아니라 프로젝트 선택이다. 위 법과 지침에 판매 순위의 기준 고지 의무는 없다(지침의 '노출 기준 설명'은 가격비교 정보 제공 항목이다). 랭킹은 공연·날짜별 판매 매수 집계만 읽고 개인 단위 행은 읽지 않는다. 검색 정렬 '인기'는 최근 7일 확정 판매 매수 [가정]이다.

### 11. 그 밖의 세부(추천 적용)

- 홈 본문은 최대 1240px이고, 화면이 좁으면 바깥 여백 32px를 지키고 본문을 줄인다(1280 화면에서 1216px, design/d1 §4).
- 회차의 판매 종료는 새 칸을 두지 않고 그 회차의 공연 시작 시각으로 본다. '지금 판매 중'의 남은 판매 기간은 그 공연의 마지막 회차 시작 시각까지다 [가정].
- 전체 배치에서 좌석이 보이지 않는 구역의 많음·적음·매진은 5초마다 갱신하는 구역 요약 스냅샷으로 받는다(docs/features/seat-hold §7). K5(좌석맵 프런트 성능)의 첫 그림은 전체 배치도와 구역 상태이고, 확대해 좌석이 나타나는 동작도 주요 인터랙션 경로에 넣는다.
- 대기열 화면의 앞 인원과 진행 막대 낭독은 한 live 영역에서 1분에 한 번으로 합친다(그동안 앞 인원 낭독은 30초였다).
- 온세일 윈도우(오픈 10분 전~60분 뒤)는 배포 동결·관제 집중·R0 리포트 기준의 운영 구간이고 판매를 끝내지 않는다. 판매와 대기열은 그 회차의 판매 종료(공연 시작 시각)나 매진까지 같은 대기실·대기열 경로로 이어지고, 앞에 대기자가 없으면 바로 입장한다. 대기열의 '판매 종료'는 그 회차 판매 종료 때다. 그동안 design/d5 §5.8과 queue-admission이 윈도우 종료를 판매 종료처럼 적어 홈의 '지금 판매 중'과 부딪쳤다. 대기열 키는 대기가 끝날 때 지우고 남은 키는 판매 종료 TTL로 파기한다. 판매 기간 동안 남는 것은 입장한 사람 표시(`q:adm`)뿐이라 회차당 많아야 구매자 수만큼이다. 사전 셔플 공연은 오픈 뒤 새 진입을 받지 않는 규칙(410)을 그대로 두고, 그 공연의 남은 좌석·취소표 판매 경로는 열린 확인 항목 K25(판매 단계와 오픈)에서 정한다.
- 후기 목록은 같은 공연의 모든 회차를 모아 보이고, 쓰기 모달은 쓸 수 있는 회차가 둘 이상이면 회차를 고르게 한다(자격은 회차 단위).

## 검토한 대안

| 대안 | 고르지 않은 이유 |
|---|---|
| 홈을 NOL 구성이 아닌 일반 패턴 참고로만 짠다(ADR-0040·design/d1 §3의 원래 규칙) | 약관 위험이 가장 낮지만, 위험을 알린 뒤 소유자가 NOL 구성을 따르기로 골랐다. |
| 기대평을 남긴다 | 소유자가 후기만 두라고 했다. 관람 전 글이라 내용을 확인할 근거가 없다. |
| 후기 자격을 입장 기록(스캔) 기준으로 한다 | 양도받아 관람한 사람도 쓸 수 있지만, 입장 기록은 현장 기기 동기화 뒤에야 확정되고(ADR-0051) 결제자와 관람자 가운데 누가 쓰는지 정해야 해 범위가 커진다. v1은 결제자 기준으로 하고 되돌릴 조건에 적는다. |
| 후기를 별도 페이지로 둔다 | 소유자가 모달을 요청했다. 주소에 모달 상태를 남겨 공유·뒤로 가기는 지킨다. |
| 본인확인 전용 화면을 남긴다 | 소유자 결정. 기관 창이 열리므로 중간 화면은 단계만 늘린다. 페이지 이동형 기관만 복귀 화면이 필요하다. |
| 대기열에 지금 정보를 모두 남긴다 | 소유자 요청. 법정 고지는 상세 화면에 늘 있고 대기열에서는 시트로 볼 수 있다. |
| 좌석맵을 배경 이미지와 클릭 영역으로 만든다 | 좌석 좌표가 데이터에 없으면 확대 표시, 구역별 구독, 연석 찾기 표시를 할 수 없다. |

- 남는 한계: NOL 약관 위험(소유자 감수), 양도받아 관람한 사람은 후기를 쓰지 못함, 랭킹은 어제 기준이라 오늘 오픈한 공연은 다음 날 10시에 반영됨, 진행 막대의 처음 값은 탭마다 따로라 다른 탭·기기에서는 0%부터, 좌석이 보이지 않는 구역의 상태는 최대 5초 늦음, 사전 셔플 공연의 오픈 뒤 남은 좌석 판매 경로는 K25에서 정한다, 판매 기간 동안 남는 대기열 키는 영구 백업이 없어 잃으면 입장한 사람이 다시 줄을 설 수 있다(매수 한도는 DB가 지킴).

## 되돌릴 조건

- NOL(야놀자)이 이의를 제기하거나 법률 검토(wbs 7.4.1)가 위험을 크게 보면 홈을 일반 패턴 구성으로 되돌린다(배너·랭킹·테마 같은 기능은 남기고 배치만 바꾼다).
- 양도받아 관람한 사람의 후기 요청이 많으면 후기 자격을 입장 기록 기준으로 넓히는 새 ADR을 낸다.
- 측정(Phase 2 부하 시험, 사용성 점검)으로 [가정] 값(배너 5초, 상세정보 1,200px, 후기 글자 수, 연관 검색어 2자·8개, 페이지 20개, 좌석이 나타나는 배율, 랭킹 갱신 시각)을 바꾼다.

## 소유자가 따로 볼 것

- 홈의 NOL 구성은 약관 제23조④ 제20호(페이지 레이아웃의 사용·복제)에 걸릴 수 있다. 소유자가 감수하기로 했지만 공개 포트폴리오로 낼 때 다시 본다.
- 후기는 결제자만 쓴다. 양도받아 관람한 사람은 쓰지 못한다.
- 대기열 화면에서 등급별 매진 현황을 뺐다. 팬은 차례가 온 뒤 좌석 선택 화면에서 매진을 안다.
