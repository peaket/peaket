# ADR-0228: 결제 화면은 결제창보다 먼저 주문을 만들고, 미리보기는 개발 서버에만 남긴다

- **상태**: 채택(2026-11-09, 추천 적용). BUILD_ORDER HOT-355.
- **관련**: [docs/frontend.md](../frontend.md) §3.12·§4.1·§5.3, [docs/design/d5-screen-blueprint.md](../design/d5-screen-blueprint.md) §5.11, [docs/features/payment.md](../features/payment.md) §2, ADR-0221, ADR-0224, ADR-0225
- **관련 ID**: SCR-011

## 맥락

- 결제 화면은 목업이었다. 서명한 `POST /v1/orders`로 주문을 만드는 실제 화면이 필요하다. 결제사 위젯(HOT-358)은 서버 단계(PRF-190)를 기다린다.
- 정본에 빈칸이 있었다.
  - 동의 문안의 판(`consentVersion`)을 화면이 어디서 얻는지 없다. 서버는 환경 값으로 지금 판을 정한다.
  - '저장된 정보 자동 입력'을 줄 API가 없다. 팬 계정 요약(`GET /v1/identity/me`)에 이름과 번호가 없다.
  - 주문을 만든 뒤 결제창이 없는 동안 화면이 무엇을 보이는지 없다.

## 결정

1. **화면의 흐름**: 탭 저장소의 입장 저장값과 홀드로 `GET /v1/holds/{holdId}`를 다시 읽어 서버가 정한 좌석과 금액을 보이고, [결제하기]가 서명한 주문을 만든다. 금액은 화면에서 계산하지 않는다.
2. **동의 문안의 판은 화면 코드의 상수다**(`ORDER_CONSENT_VERSION`). 문안이 화면 코드에 있으므로 판도 같이 둔다. 서버 환경 값 `PEAKET_ORDER_CONSENT_VERSION`과 같게 배포한다. 어긋나면 서버가 422 `consent-version-outdated`로 답하고, 화면은 체크를 지우고 다시 동의받는다.
3. **예매자 이름과 번호는 빈 칸으로 시작한다**. 이 값을 주는 API가 생기면 채운다. 이름과 번호는 저장소에 두지 않는다(§3.12). 동의 체크는 `peaket.checkout.{holdId}`, 만든 주문 ID는 `peaket.checkout.{holdId}.order`에 둬 새로고침해도 주문을 겹쳐 만들지 않는다.
4. **실패는 `orderOutcome`으로 가른다**(openapi `createOrder` 응답표).
   - 이름 없는 401은 토큰을 한 번 갱신하고 같은 멱등 키로 다시 보낸다. 이름 있는 401과 그 밖의 403은 키와 저장값을 지우고 대기실로 간다(§5.3 '401').
   - 403 `identity-verification-required`는 결제 버튼 자리를 [휴대폰 본인확인]으로 바꾸고, 403 `booking-restricted`는 서버가 홀드를 풀었으므로 저장한 홀드를 지우고 안내한다.
   - 404는 홀드 만료 대화상자, 409는 '다른 탭에서 진행 중', 410·423은 안내와 결제 막기, 422는 다시 동의다.
5. **멱등 키는 본문에 묶는다**. 같은 본문을 다시 보내면 같은 키, 예매자나 동의가 바뀌면 새 키다. 서버는 같은 키의 다른 본문을 422로 막는다.
6. **주문을 만든 뒤 결제창이 없는 동안**은 '주문이 접수되었습니다'만 보이고 결제 버튼을 막는다. 결제 시도와 위젯은 HOT-358이다.
7. **미리보기**: 아직 잇지 않은 상태의 퍼블리싱 그림(`?state=`)은 개발 서버에만 남긴다(ADR-0224 결정 2와 같다). 운영 묶음에는 들지 않는다. 본문(`CheckoutForm`)은 실제 화면과 미리보기가 함께 쓴다.
8. **가짜 API**: `GET /v1/holds/{id}`, 서명을 확인하는 `POST /v1/orders`, `order=normal|no-id|restricted|hold-gone|other-tab|paused|sale-ended|consent-outdated|down`.

## 결과

- 좌석 → 홀드 → 주문까지 실제 화면으로 이어진다. 결제창과 결과는 HOT-358·362·363이다.
- **넘긴 것(HOT-358)**: 응답을 받지 못한 채 새로고침하고 다시 입력하면 새 멱등 키라 409 `hold-already-ordered`가 된다. 지금은 '다른 탭에서 진행 중'과 주문 내역 링크로 나간다. 결제 시도를 이을 때 그 409에서 주문을 찾는 길을 정한다.
- 결제 화면의 Lighthouse 행은 입장값과 홀드를 넣고 잰다. 홀드를 읽을 서버가 없어 '불러오지 못함'까지의 시간이다(회귀 방지).

## 검토한 다른 안

- **좌석 화면의 [결제하기]에서 바로 주문 만들기**: 예매자와 동의를 받기 전이라 본문을 채울 수 없다.
- **동의 문안의 판을 서버에서 받기**: 지금 판을 주는 API가 없고, 문안이 화면에 있어 판만 서버에서 받아도 어긋남을 막지 못한다.
