# ADR-0133: 기술 검토 낮음 항목의 문서 수정 묶음 1 — 범위·아키텍처·인프라·DevOps·API 계약(2026-10-28)

- **상태**: 채택 (2026-10-28. 기술 검토(review/tech-review.md)의 낮음 항목(영역: 부록·범위(직접 검토), 아키텍처·인프라, DevOps·API 계약)에 소유자가 "나머지 건수들은 모두 추천안에 동의합니다. 그렇게 모두 수정해주세요."라고 정했다. 방향은 소유자 결정(추천안 승인)이고, 검토가 안을 고르지 않은 곳의 선택과 값 같은 세부는 추천 적용이다. 측정 전 값은 [가정]으로 표시했다) 2026-10-29(ADR-0144 결정 1): 낮음-009의 'NLB 둘(CloudFront용 사설 하나·스캐너용 공개 하나)'은 NLB 셋(팬·파트너 원본, 관제 원본, 스캐너)으로 읽는다. 2026-10-29(원문 확인): 낮음-020 — Envoy Gateway CORS 안내서가 'SecurityPolicy CORS는 대상 라우트가 OPTIONS를 받아야 동작한다'고 적어, 메서드를 좁힌 라우트의 사전 요청은 404다. 생성 규칙의 OPTIONS를 유지한다. 낮음-023 — Envoy Gateway는 `responseOverride` 본문을 Envoy 치환 형식 문자열로 넘기므로(PR #6297, 소스) `%TRACE_ID%`를 먼저 D-T43에서 본다(docs/api/guidelines.md §2). 2026-11-01(BUILD_ORDER FND-110, openspec 변경 add-local-cluster-and-relay-deployment): 낮음-010의 LocalStack 계정·토큰은 소유자 결정(2026-10-31, 외부 서비스 계정을 만들지 않음)에 따라 만들지 않고, 결정의 '막히면' 갈래대로 계정 없는 AWS 흉내 서버(moto 5.2.5)로 바꿨다. 쓰는 기능은 kind에서 확인했고, 포크 PR 건너뛰기 표시는 비밀이 필요한 단계를 위해 `tools/ci/fork-guard.mjs`로 두었다(docs/infra.md §3, docs/devops.md §4.5).
- **관련**: review/tech-review.md(낮음-001·낮음-002·낮음-003·낮음-004·낮음-005·낮음-006·낮음-007·낮음-008·낮음-009·낮음-010·낮음-011·낮음-012·낮음-013·낮음-014·낮음-015·낮음-016·낮음-017·낮음-018·낮음-019·낮음-020·낮음-021·낮음-022·낮음-023·낮음-024·낮음-025·낮음-026·낮음-027·낮음-028·낮음-029·낮음-030·낮음-031·낮음-032), review/consistency-review.md R-151, 00-summary.md §6·질문 61, 같은 날 새 ADR-0100~0126(새 결정이 필요한 항목)

## 맥락

2026-10-27 기술 검토 2판은 설계의 모든 기술·기법을 시니어 개발자 관점에서 따져 높음·중간·낮음 항목으로 냈다. 2026-10-28 소유자가 남은 항목을 모두 추천안대로 고치라고 정했다. 새 결정이 필요한 항목은 따로 ADR(0100~0126)을 썼고, 이 ADR은 정본 문서를 고쳐 반영한 낮음 항목 32건의 문제와 결정을 한곳에 모은다. 검토 문서에서는 이 항목들의 본문을 지우고 이 ADR을 가리키는 한 줄만 남겼다(지운 본문은 git 이력에 있다).

## 결정

항목마다 검토의 추천 수정을 따랐다(소유자 승인). 검토가 안을 여럿 내고 고르지 않은 곳은 고른 안과 이유를 적었고 '추천 적용'으로 표시했다. 정본에는 `(추천 적용 2026-10-28, 기술 검토 <번호>)`로 표시했다.

### 아키텍처·인프라

#### 낮음-003 §9.2·§9.5의 샤드 분산 가정과 결론이 맞지 않는다
- **문제**: §9.2·§9.5의 샤드 분산 가정과 결론이 맞지 않는다
- **결정**: 해시 태그는 샤드를 고르지 않으므로 '흩어진다'는 근거를 지우고, Aurora 용량은 쓰기량으로 적는다. 좌석 샤드는 겹친 최악을 PoC 통과 기준으로 두고, 실패하면 큰 회차 배치 규칙을 새 ADR로 정한다(추천 적용).
- **바꾼 문서**: docs/architecture.md §9.2·§9.4·§9.5, docs/data.md §3, docs/features/seat-hold.md

#### 낮음-004 홀드 지연 예산의 'Lua 실행 7ms' 뜻과 샤드 하나의 처리량 상한이 적혀 있지 않다
- **문제**: 홀드 지연 예산의 'Lua 실행 7ms' 뜻과 샤드 하나의 처리량 상한이 적혀 있지 않다
- **결정**: 7ms는 대기를 포함한 Redis 왕복이고, 스크립트 실행 시간 p99 0.1ms·회차 샤드 CPU 50%를 PoC 통과 기준으로 둔다(값은 [가정], 추천 적용).
- **바꾼 문서**: docs/architecture.md §7·§9.4, docs/features/seat-hold.md §8·§12

#### 낮음-005 씬 게이트웨이 분리를 BFF로 설명한 용어 혼동
- **문제**: 씬 게이트웨이 분리를 BFF로 설명한 용어 혼동

#### 낮음-006 용어·표기 묶음(지연 큐 Outbox, 버전 벡터, Shared-Nothing, Motion·Workbox)

#### 낮음-009 CloudFront 원본 보호에 'VPC 원본' 비교가 없다
- **문제**: CloudFront 원본 보호에 'VPC 원본' 비교가 없다

- **남는 한계**: 스캐너 NLB는 인터넷에 열려 있다(DPoP와 게이트웨이 한도가 지킨다), NLB 하나만큼 비용이 는다(ADR-0053 상태 줄에 적음). planning/01 §5.2에는 더하지 않았다

- **결정**: SBOM은 릴리스 산출물로도 남기고 조회 스크립트로 운영 다이제스트에서 찾는다. 계약 차이는 형식마다 한 도구(oasdiff·AsyncAPI CLI·buf·로컬 레지스트리)로 보고 '깨짐'을 정의한다. 마이그레이션 뒤 `RECONNECT`는 그 DB PgBouncer의 모든 파드에 보낸다(추천 적용).
- **바꾼 문서**: devops §3.1·§4.4·§7.2, api/guidelines §1.

#### 낮음-020 HTTPRoute 메서드 제한의 생성 방법과 CORS 사전 요청 상호작용을 정한다
- **문제**: HTTPRoute 메서드 제한의 생성 방법과 CORS 사전 요청 상호작용을 정한다
- **결정**: HTTPRoute의 경로·메서드는 계약 openapi에서 생성하고 `gitops-check`가 차이를 막는다. 교차 출처 경로에는 OPTIONS를 함께 넣어 사전 요청이 CORS 정책에 닿게 하고, 실제 동작은 D-T42로 확인한다(추천 적용).
- **바꾼 문서**: asvs/delivery 3.5.3, architecture §4, devops §3.1·§14.

#### 낮음-021 포트원 행의 '계약 테스트(Pact)'를 어댑터 계약 시험으로 바로잡는다
- **문제**: 포트원 행의 '계약 테스트(Pact)'를 어댑터 계약 시험으로 바로잡는다
- **결정**: 외부 결제사에는 Pact를 쓰지 않고 세 어댑터에 같은 어댑터 계약 시험(P-T16)을 돌린다고 적는다(추천 적용).
- **바꾼 문서**: api/guidelines §8.

#### 낮음-022 게이트웨이 로컬 레이트 리밋이 파드 수만큼 느슨해진다는 점을 한도 계산에 적는다
- **문제**: 게이트웨이 로컬 레이트 리밋이 파드 수만큼 느슨해진다는 점을 한도 계산에 적는다
- **결정**: 로컬 한도의 실효 상한이 파드 수에 비례함을 한도 계산과 시험 기대값에 쓰고, 정확한 기기당 한도는 뒤층(1인 1순번·trust-svc·입장 토큰)이 맡는다고 적는다(추천 적용).
- **바꾼 문서**: api/guidelines §6, queue-admission §3.

#### 낮음-023 작은 표기·빈칸 넷(RFC 번호, Deprecation 형식, traceId 응답 헤더, 게이트웨이 Problem의 요청별 값)
- **문제**: 작은 표기·빈칸 넷(RFC 번호, Deprecation 형식, traceId 응답 헤더, 게이트웨이 Problem의 요청별 값)
- **결정**: 구조화 필드는 RFC 9651, `Deprecation`은 RFC 9745 형식으로 적는다. 응답 추적 헤더는 `X-Trace-Id`로 정하고 공개 캐시 응답에는 싣지 않는다. 게이트웨이가 만든 Problem은 고정 본문(`type`·`status`·`title`)이고 요청별 값은 헤더로 잇는다(추천 적용).
- **바꾼 문서**: api/guidelines §1·§2·§4·§9, infra §9, devops §14(D-T43).

#### 낮음-024 파트너 판매 현황 SSE를 1분 주기 조회로 바꿀지 판단한다
- **문제**: 파트너 판매 현황 SSE를 1분 주기 조회로 바꿀지 판단한다
- **결정**: 1분마다 바뀌는 전체 상태라 SSE 대신 1분 주기 REST 조회(`live-snapshot`, 다음 집계 시각에 맞춰 묻기, 숨긴 탭 5분 [가정])로 바꾸고 asyncapi 채널을 없앤다. 1분보다 짧은 지연을 약속할 때 SSE를 다시 본다(추천 적용).
- **바꾼 문서**: openapi, asyncapi, frontend §4.4.3·§4.4.6 외, control-tower §11·C-T20, architecture §3, ADR-0027·0079·0091·0100 상태 줄.

#### 낮음-025 Kafka 채널에 클러스터를 묶고, 키 순서 보장의 범위를 정확히 적는다
- **문제**: Kafka 채널에 클러스터를 묶고, 키 순서 보장의 범위를 정확히 적는다
- **결정**: 채널마다 MSK 클러스터를 적고, 회차 키가 지키는 순서를 '한 생산자의 같은 주문·좌석'으로 좁혀 적는다. 생산자가 둘인 trade.seats는 순서를 기대지 않고 펜싱·판 번호로 거른다. 인기 회차 한 파티션의 소비 처리량은 ST-T17로 잰다(추천 적용).
- **바꾼 문서**: asyncapi, streaming §7·§10.

#### 낮음-026 사건 메시지의 중복 제거 키와 판 정보를 정리하고, 설정 값에 모양을 준다
- **문제**: 사건 메시지의 중복 제거 키와 판 정보를 정리하고, 설정 값에 모양을 준다
- **결정**: 중복 제거 키를 eventKey 하나로 하고 OrderEvent.idempotencyKey와 모든 Avro 메시지의 schemaVersion을 첫 등록 전에 뺀다. SettingChanged.value는 키별 레코드의 유니온으로 바꿔 호환 검사가 값 모양 변화를 잡게 한다(추천 적용).
- **바꾼 문서**: asyncapi, avro *.avsc·README, analytics §3.4, streaming §5, ADR-0052 상태 줄.

#### 낮음-027 asyncapi.yaml의 중복 키를 지우고 YAML 중복 키 검사를 doc-check에 넣는다
- **문제**: asyncapi.yaml의 중복 키를 지우고 YAML 중복 키 검사를 doc-check에 넣는다
- **결정**: 중복 키를 지우고, 계약 YAML(openapi·asyncapi·buf.yaml)의 중복 키를 doc-check가 잡게 한다(추천 적용).
- **바꾼 문서**: asyncapi(RumSample). doc-check는 메인 세션.

#### 낮음-028 결제창 준비 응답의 결제사 값을 결제사별 메시지로 형을 주고, 시각 형을 하나로 맞춘다
- **문제**: 결제창 준비 응답의 결제사 값을 결제사별 메시지로 형을 주고, 시각 형을 하나로 맞춘다
- **결정**: 결제창 준비 응답의 결제사 값을 결제사별 메시지로 형을 주고(proto oneof, openapi oneOf), 문자열 시각을 Timestamp로 맞춘다(추천 적용).
- **바꾼 문서**: proto payment·core·control·README §3, openapi.

#### 낮음-029 제어 평면 TCP 채널의 메시지 모양과 버전을 정한다
- **처리**: 이미 반영됨(ADR-0102·ADR-0103, 1차)
- **문제**: 제어 평면 TCP 채널의 메시지 모양과 버전을 정한다
- **결정**: 이미 반영됨. ADR-0102의 제어 gRPC(control.proto)와 ADR-0103의 판 번호가 이 항목을 푼다.
- **바꾼 문서**: 없음.

#### 낮음-030 고치기 작업의 동시 수정 규칙을 하나로 정한다
- **문제**: 고치기 작업의 동시 수정 규칙을 하나로 정한다
- **결정**: 여러 사람이 고치는 자원은 응답의 강한 `ETag`와 PUT·PATCH의 필수 `If-Match`로 막고, 다르면 412·없으면 428로 답한다. 본문 판으로 409를 내던 좌석맵·홈 구성도 이 규칙으로 바꾸고, 자기 상태 셋만 예외로 둔다(추천 적용).
- **바꾼 문서**: api/guidelines §9·§12, openapi(PUT·PATCH 13개, components), infra §9, frontend §5.6.

#### 낮음-031 경로마다 게이트웨이 호스트를 묶고, 보안 요구를 기계가 확인할 수 있게 적는다
- **문제**: 경로마다 게이트웨이 호스트를 묶고, 보안 요구를 기계가 확인할 수 있게 적는다
- **결정**: 경로의 게이트웨이는 openapi의 접두사 규칙 표(`x-peaket-gateways`)와 경로 `servers`로 정하고, 인증은 전역 기본(팬 쿠키)과 공개 작업의 `security: []`로 적어 빠진 작업을 기계로 찾는다. 계정 연결 임시 쿠키를 인증 방식에 더한다(추천 적용. 태그별 servers는 태그와 게이트웨이가 일대일이 아니어서 쓰지 않았다).
- **바꾼 문서**: openapi, api/guidelines §10.

#### 낮음-032 guidelines §12의 명세 숫자를 손으로 적지 말고 검사기가 세게 한다
- **문제**: guidelines §12의 명세 숫자를 손으로 적지 말고 검사기가 세게 한다
- **결정**: guidelines는 기준만 적고, 명세의 숫자는 doc-check `api` 검사가 보고로 낸다(추천 적용).
- **바꾼 문서**: api/guidelines §12.
