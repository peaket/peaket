# ADR-0001: 팬 계정은 소셜 로그인 단일 요소 인증 + 보완 통제

- **상태**: 채택 (2026-10-06). 2026-10-26(4차 점검 3부): 보완 통제 표의 '민감 작업 전 제공자 재인증' 대상은 POL-019의 목록(티켓 양도와 결제자에게 돌려주기, 예매 취소, 티켓 재발급과 입장 시작 뒤 첫 입장용 등록, 로그인 수단 추가·해제, 계정 병합, 연락처 변경, 회원 탈퇴)으로 읽는다(planning/03 POL-019, docs/features/identity.md §7).
- **관련**: 설계서 섹션 6 '계정·인증', `docs/security/asvs/auth.md`, ADR-0006(입장권 구매자 본인확인)
- **관련 ID**: FR-001, FR-017, POL-019, NFR-016, SCR-004, SCR-017
- **대상 요구사항**: ASVS `v5.0.0-6.3.3`(L2), `v5.0.0-6.8.4`(L2)

## 맥락

ASVS 5.0.0의 6.3.3(L2)은 애플리케이션 접근 시 다중 인증 또는 복합 단일 요소 인증 조합을 요구하며, 이를 완화할 경우 타당한 근거와 보완 통제를 문서화하도록 명시한다. 또한 6.8.4(L2)는 외부 IdP의 인증 강도가 요구될 때 IdP가 제공한 메타데이터(`acr`·`amr`·`auth_time`)를 검증하고, 해당 정보가 없으면 가장 낮은 인증 강도로 간주하는 대체 방식을 문서화하도록 규정한다.

PEAKET 팬 계정은 카카오·네이버·구글 소셜 로그인 체계만 채택하며 자체 비밀번호를 보관하지 않는다. 외부 제공자 측 2단계 인증 활성화 여부는 사용자 개별 선택 사항이므로, PEAKET 플랫폼 차원에서 다중 인증을 일괄 강제할 수 없다.

## 결정

1. 팬 계정은 외부 제공자 인증을 단일 요소로 간주한다. 제공자가 인증 강도 메타데이터를 전달하더라도 감사 로그에 기록만 수행하며, 접근 허용 판정에는 반영하지 않는다.
2. 일반 팬 사용자에게 다중 인증을 강제하지 않는 대신, 하단의 다층 보완 통제를 체계적으로 구축한다.
3. 파트너 및 플랫폼 운영자 계정은 본 결정의 적용 대상이 아니며, 다중 인증(MFA) 적용이 필수이다.

## 보완 통제

| 통제 | 막는 위험 |
| --- | --- |
| 기기 바인딩, 계정당 대기열 1개 | 탈취한 계정으로 여러 기기에서 대기열 진입 |
| trust-svc 위험 점수(새 기기·IP/ASN·행동 신호) | 탈취 계정과 매크로 계정의 자동화 사용 |
| 민감 작업 전 제공자 재인증(양도, 연락처 변경, 제공자 연결 변경) | 세션 탈취 후 티켓 가로채기 |
| 새 기기 로그인 알림(ASVS 6.3.5, L3 항목을 채택) | 계정 탈취를 사용자가 늦게 알아차림 |
| '로그인한 기기' 화면에서 세션 확인·종료 | 탈취된 세션의 장기 사용 |
| 팬 계정에는 비밀번호·결제수단을 저장하지 않음(카드 정보는 토스 결제위젯에서만 입력) | 계정 탈취 시 피해 범위 |
| 입장권 예매 전 본인확인(연계정보로 1인 1계정·1인 1순번, ADR-0006) | 대량으로 만든 계정이나 탈취한 계정으로 순번·추첨권 늘리기 |

## 결과

- 팬 자체 비밀번호를 관리하지 않으므로 ASVS V6.2(비밀번호), V6.4(비밀번호 재설정) 항목은 팬 계정 범위에서 제외된다.
- 계정 보안 체계의 일부가 외부 제공자의 보안 수준에 종속된다. 제공자 계정이 탈취되면 PEAKET 세션 역시 위협받을 수 있으나, 그에 따른 피해 규모는 보완 통제를 통해 엄격히 제한한다.
- 6.3.3 요구사항은 팬 계정에 대해 '위험 수용'으로 추적 표에 공식 기록한다.
- 본인확인 절차는 인증 강도 자체를 격상하지 않는다. 로그인은 지속적으로 단일 요소로 유지되며, 본인확인은 실제 소유자 식별을 위해 예매 진입 전 1회 수행하는 독립적 행정 절차이다(공연법 시행령 §3의3 1호 가목, 2026-10-08 추가).

## 재검토 조건

- 양도 사기나 계정 탈취 신고가 판매 티켓 1만 장당 1건을 초과할 때
- 패스키(Passkey)를 팬 계정의 선택적 2차 인증 수단으로 도입할 엔지니어링 여력이 확보될 때
- 시스템 전반의 ASVS 목표 레벨을 L3로 상향 조정할 때
