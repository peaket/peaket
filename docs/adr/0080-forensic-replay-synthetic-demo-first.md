# ADR-0080: 포렌식 리플레이를 두 단계로 줄여 넣는다 — 1단계 합성 데이터 브라우저 데모, 2단계 운영 연결은 출시 뒤 선택(2026-10-21)

- **상태**: 채택 (2026-10-21. 소유자가 기획서 '티케팅 시공간 트래픽 포렌식 & 좌석 리플레이 스튜디오'를 보이며 "아래 기획설계를 현재 이 프로젝트에 넣는것은 어떤지 한번 고려해주세요"라고 물었고, 정본·데이터·법·브라우저 지원 기준과 대조한 검토 보고(그대로는 넣지 않고 줄여 두 단계로)를 본 뒤 "Please record the forensic replay as a new ADR in the recommended reduced form (synthetic-data browser demo first, the production hookup as an option) and apply it to the docs, WBS and canvas."로 승인했다. 범위(두 단계)는 소유자 승인이고 결정 하나하나의 세부는 추천 적용이다. 외부 사실은 2026-10-21에 원문으로 확인했다.) 2026-10-21(추천 적용, 소유자 질문 "포렌식 리플레이는 기존 플랫폼에 통합하는게 좋을까요?"에 대한 답을 본 뒤 반영 요청): 2단계 화면은 관제 콘솔 화면 묶음 안의 경로나 원격 위젯이 아니라 콘솔 주소 아래 따로 여는 페이지(`/forensics?event=`, 새 탭)로 둔다. 같은 `apps/forensics`를 운영 모드로 빌드해 console 배포 S3 `/forensics/`에 올리고, 운영자 쿠키·관리자 IP 제한·역할 확인·재인증·감사 기록은 콘솔 것을 그대로 쓰며, 관제 셸과 실시간 연결은 싣지 않는다. 헤더는 관제 묶음 C에 COEP `require-corp`를 이 경로에만 더해 공유 메모리를 쓴다. 이유는 빌드 구조 차이(webpack·원격 위젯 대 Vite), 실시간 관제 화면 보호, 공유 메모리다. 세부는 docs/features/forensic-replay.md §6.8이다. 2026-10-28(기술 검토 중간-092, 소유자 승인 '추천안 동의'): 결정 8의 '같은 시드면 같은 바이트'를 엔진이 달라도 지키도록, 생성기는 정수 연산·사칙연산·결과가 하나로 정해진 `Math` 함수(`Math.sqrt`·`Math.imul` 등)만 쓰고, 로그·지수가 필요한 분포는 빌드 때 만든 역누적분포 표로 만든다. ECMA-262가 `Math.log`·`Math.exp`·`Math.pow`와 삼각 함수의 계산 방법을 구현에 맡기기 때문이다. FX-T1은 Chromium·WebKit·Firefox 세 엔진에서 SHA-256이 같은지 본다(docs/features/forensic-replay.md §5.3·§8). 2026-10-28(기술 검토 중간-093, 소유자 승인 '추천안 동의'): 결정 4·7의 2단계 내보내기에서 행동 요약값·기기 묶음·네트워크 유형·ASN 열을 비워 내고 사건만 낸다(검토의 안 (나), 추천 적용). 실버의 회차 가명 사건과 trust-svc 원시 표를 이을 키가 없고, 이으면 '운영 DB·trust-svc 원천과 잇지 않는다'와 '분석 저장소는 행동 신호를 싣지 않는다'는 규칙과 부딪치기 때문이다. `an_forensic_reader`는 실버만 읽고, 봇 후보 패널은 2단계에서 '입장 확정 → 첫 홀드' 한 축으로 본다. 행동 요약을 실버에 싣는 안 (가)는 가명정보 범위를 넓혀 다시 알아볼 위험을 키우고, 2단계를 열지 않는 안 (다)는 충돌하지 않는 사건 재생까지 막아 고르지 않았다. 착수 조건 4의 새 ADR이 이 결정을 이어받고, 사건만으로 찾지 못한 봇 유형이 실제로 나오면 그 ADR에서 (가)를 법률 검토와 함께 다시 본다(docs/features/forensic-replay.md §4.1·§4.2·§6.3·§6.6, docs/features/analytics.md §3.1·§11, docs/security/asvs/forensic-replay.md, docs/security/asvs/analytics.md 13.2.2, docs/security/data-classification.md). 2026-10-28(기술 검토 낮음-165, 소유자 승인 '추천안 동의'): 1단계 후보 패널의 '합성 정답 기준 정밀도·재현율' 바로 아래에 고정 문구 "합성 데이터의 정답으로 잰 값입니다. 봇을 이 특징으로 만들었기 때문에 높게 나오며, 실제 봇 탐지 성능을 뜻하지 않습니다."를 늘 둔다. 봇을 등급표대로 만들고 같은 특징으로 찾으므로 그 값은 생성 가정의 결과다. 실제 탐지 성능(NFR-022)은 ADR-0039·0048의 표본 검토로만 재고, 이 값을 성능 장부·포트폴리오 설명에 탐지 성능으로 옮기지 않는다(docs/features/forensic-replay.md §2.1·§5.3·FX-T9, design/d5 SCR-069). 2026-10-28(기술 검토 낮음-049~052, 소유자 승인 '추천안 동의'): 결정 6의 1단계는 공유 메모리 시계 없이 복사 방식 하나로 만들고, FX-T5·FX-T6에서 필터 반영 p95 50ms·프레임 p95 20ms [가정]을 못 맞출 때만 공유 시계를 더한다. 그래서 공개 위치의 COEP는 '있으면 좋다'로 낮춘다(asvs/forensic-replay 3.4.8). 결정 7의 좌석 상태 체크포인트는 1초 고정이 아니라 전체가 32MB [가정]를 넘지 않는 간격(30분·10만 석이면 6초)으로 만들고, §7에 한도 시나리오의 힙 상한을 둔다. 결정 4의 2단계 내보내기 쿼리에 `output_format_arrow_compression_method = 'none'`·`output_format_arrow_low_cardinality_as_dictionary = 0`을 붙이고, 받기 GET은 `Content-Disposition` 없이 `Sec-Fetch-Mode: navigate`를 거절해 메모리에만 둔다. 결정 8·9의 프리셋에 봇 등급표 3단계로 만든 셋째 프리셋 '사람 흉내 봇'을 더해, 산점도로 가를 수 없는 경우를 보인다(docs/features/forensic-replay.md §2.1·§3.3·§3.4·§5.1·§6.3·§6.5·§6.8·§7·§8).
- **관련**: ADR-0039(봇 탐지 평가), ADR-0048(봇 평가 표본과 등급표), ADR-0052(분석 저장소와 가명정보), ADR-0057(상시 데모 없음), ADR-0061(세 크기), ADR-0065(행동 신호는 요약값만), ADR-0067(관제 콘솔과 관측 도구의 경계), ADR-0079(프론트엔드 상세 설계), POL-006, POL-027

## 맥락

- **기획서가 원한 것**: 오픈 직후 5~10분의 수백만 사건과 5만 석 좌석 상태 변화를 브라우저 메모리(DuckDB-WASM, SharedArrayBuffer)와 저수준 그래픽(OffscreenCanvas, WebGPU)으로 동기화해, 지연 없는 다차원 필터링, 1ms 단위 리플레이, 봇 군집 탐지를 하는 포렌식 콘솔. 반응 속도 × 마우스 엔트로피 산점도, IP C클래스 군집, 데모 시나리오 생성기를 포함한다.
- **정본과 겹치는 것**: 감사 로그·인시던트 리플레이(SCR-031), 봇 판정 표본 검토(SCR-067, FR-049), 관제 구역 히트맵(SCR-029), 좌석맵 Worker·격자 색인·바뀐 좌석 덧칠(ADR-0079 결정 9).
- **데이터가 있는 것과 없는 것**(2026-10-21 정본 확인)
  - 있음: `HoldAttempt`(결과 HELD·CONFLICT·LIMIT·ERROR, 구역, 재시도, 지연, 시각), `slv_seat_change`, `slv_queue_entry`, `slv_payment_attempt`, `slv_trust_label`, 행동 요약값(포인터 이동 엔트로피 등, 공연 상세에서 잼, 30일), 네트워크 유형·ASN.
  - 없음: `HoldAttempt`의 좌석 번호(구역까지만), 사람이 좌석을 '보고 있음', 좌석 화면의 마우스 궤적, 분석 저장소의 IP(IP는 법정 접속기록에만, POL-025).
  - 접근: 실버(사건 단위)는 가명정보 취급자만 읽고, 실버 대량 조회는 보안 이벤트다. 특정 개인을 알아보는 처리는 금지다(개인정보 보호법 §28의5, analytics §11).
- **기술 사실**(2026-10-21 확인)
  - DuckDB-WASM: npm `latest` 태그가 개발판 1.33.1-dev57.0(2026-06-22), 마지막 정식 1.32.0(2025-12-16). `duckdb-eh.wasm` 원본 35.9MB, brotli 약 7.1MB.
  - apache-arrow(JS) 21.2.0(2026-07-21), 전체 최소화 판 192.6KB(gzip 약 51.5KB).
  - WebGPU는 Baseline이 아니다(Chrome 144, Chrome Android 121, Safari 26, Firefox 표 없음, web-features 3.43.0). 공유 메모리·OffscreenCanvas·WebGL2는 Baseline이다. Long Animation Frames는 Chromium만, `scheduler.yield`는 Safari에 없다.
  - 공유 메모리는 교차 출처 격리(COOP·COEP)가 있어야 쓴다.
  - Arrow IPC 파일은 앞뒤 매직 `ARROW1`, ClickHouse는 Arrow·Parquet 입출력을 지원한다.
- **이 프로젝트의 사정**: 상시 데모가 없어(ADR-0057) 누구나 눌러 보는 시연이 비어 있다. 1인 일정이 이미 429일이다.

## 결정

1. **그대로 넣지 않고 두 단계로 줄여 넣는다(소유자 승인)**
   - 1단계: 합성 데이터만 쓰는 브라우저 데모. 2단계: 관제 콘솔에서 분석 저장소의 가명 사건 기록을 다시 보는 운영 연결, 출시 뒤 선택.
   - 이름은 '포렌식 리플레이', 화면은 SCR-069, 요구사항은 FR-071이다.
2. **1단계는 서버 없는 정적 앱이다(추천 적용)**
   - `peaket-frontend`의 `apps/forensics`(Vite 8 + React 19.3). 개인정보를 다루지 않는다. 부하 시험 실행 기록(합성 사용자)을 같은 파일 형식으로 불러올 수 있다.
   - 공개 위치는 응답 헤더(CSP, COOP·COEP, `nosniff`, HSTS, `frame-ancestors`)를 정할 수 있는 정적 호스팅이어야 한다. 어디에 둘지는 출시 준비 때 소유자가 정한다. 정하지 못하면 녹화 영상과 재현 스크립트로 보인다(ADR-0057과 같은 방식).
3. **2단계는 착수 조건 넷을 채운 뒤에만 연다(추천 적용)**
   - ① 가명정보를 봇 방어 규칙 개선에 쓰는 것이 처리 목적(§28의2) 안인지 법률 검토(POL-027 확인 필요에 1건 더함) ② 보안 추적 표의 '(2단계)' 행 재판정 ③ `HoldAttempt`에 좌석 번호를 더하는 계약 보강 ④ 이를 담은 새 ADR.
   - WBS에 넣지 않는다(추정 8~12일).
4. **2단계 결과는 규칙 개선에만 쓰고 개인 조치에 쓰지 않는다(추천 적용)**
   - 다음 회차 판정 규칙을 고치고 그림자 실행으로 사람 오탐을 잰 뒤 채택한다(ADR-0039). 특정 개인을 알아보거나 조치하지 않는다(§28의5). 그래서 자동화된 결정(§37의2) 절차가 이 화면에 생기지 않는다.
   - 가명정보 취급자(개인정보 보호책임자가 지정한 commander)만 쓴다. 회차·시간창(오픈 뒤 30분 [가정]) 단위로 사유를 적어 내보내고, 감사 기록과 가명정보 이용 내역에 남긴다. 열은 허용 목록뿐이고 IP·원본 pid·기기 원문은 없다. 브라우저 메모리에만 두고 30분 [가정] 유휴면 지운다.
   - 내보내기 API(`POST /v1/forensics/exports`, `GET …/{exportId}`)는 초안으로 두고 2단계 착수 때 openapi에 넣는다.
5. **좌석맵 렌더러를 공용 패키지로 올린다(추천 적용)**
   - 열 배열·격자 색인·그리기 Worker를 `packages/seatmap`으로 옮겨 소비자 웹 좌석 화면과 포렌식 앱이 같이 쓴다. 앱끼리 가져오지 않는 규칙(docs/frontend.md §2.2) 때문이다.
6. **무거운 기술은 줄인다(추천 적용)**
   - DuckDB-WASM을 쓰지 않는다. 열 배열과 비트마스크 교차 필터(바뀐 차원만 다시 계산, 히스토그램 증분 갱신)로 한다.
   - WebGPU를 쓰지 않는다. 좌석맵은 OffscreenCanvas 2D, 산점도는 WebGL2이고 없으면 2D 표본으로 그린다.
   - 공유 메모리와 `Atomics` 시계는 교차 출처 격리가 있을 때만 쓰고, 없으면 메시지와 `Transferable`로 같은 결과를 낸다.
   - 긴 작업은 공용 `MessageChannel` 나누기 함수로, 부하 조절은 Chromium에서만 Long Animation Frames로 한다.
7. **사건 모델과 파일 형식을 정한다(추천 적용)**
   - 사건 종류 여섯(`ADMIT`·`HOLD_TRY`·`HOLD_END`·`PAY_TRY`·`SALE`·`PAY_FAIL`)과 열 14개를 Arrow IPC 파일(`peaket-forensics-v1`)에 담는다. 검증 규칙과 한도(사건 300만·파일 200MB·좌석 10만 [가정])는 docs/features/forensic-replay.md §4다.
   - 검증이 하나라도 실패하면 아무것도 그리지 않는다. 일관성이 깨진 사건만 버리고 버린 수를 보인다.
8. **합성 시나리오 생성기를 정한다(추천 적용)**
   - 프리셋 둘(인기 콘서트 5만 석·봇 30% [가정], 스포츠 플레이오프 3만 석·봇 10% [가정]). 봇은 봇 등급표 12칸(docs/perf-ledger.md §10)대로 움직인다. 사람의 반응 시간·엔트로피 분포는 설명용 가정이다.
   - 시드 고정 의사난수라 같은 시드면 같은 바이트다. 정답이 있어 후보 영역의 정밀도·재현율을 보인다.
9. **화면과 부품을 정한다(추천 적용)**
   - SCR-069: 좌석 리플레이(레이어 상태·경합·이탈), 타임라인, 교차 필터, 봇 후보 산점도, 상태 띠. 세 크기(ADR-0061)이고 휴대폰은 리플레이 보기만이다.
   - 새 부품 CMP-079 ScatterBrush(점 산포도와 영역 고르기). CMP-021 SeatMap에 `replay` 변형, CMP-039 AuditTimeline에 `scrub` 변형(구간 고르기)을 더한다.
   - 후보 패널에 늘 "후보 찾기용입니다. 봇 판정은 표본 검토(SCR-067)와 정해진 규칙(POL-006)으로 합니다"를 둔다. 좌석 '탐색 중' 상태와 IP 군집은 어느 단계에도 두지 않는다.
10. **성능 목표와 시험을 정한다(추천 적용)**
    - 목표는 모두 [가정]이다: 100만 사건 생성·색인 3초 안, 필터 반영 p95 50ms, 재생 p95 프레임 20ms, INP 200ms, 10분 재생 힙 증가 5% 이하. 기획서의 '0ms·GC 0회·16.6ms'는 보장이 아니라 목표 범위로 바꿨다.
    - 시험 FX-T1~FX-T10(docs/features/forensic-replay.md §8).
11. **일정에 넣는다(추천 적용)**
    - wbs 7.7(Phase 7, 출시 준비 산출물): 7.7.1 합성 생성기·사건 형식·좌석 상태 재구성 2일, 7.7.2 리플레이 화면(타임라인·교차 필터·세 크기) 3일, 7.7.3 봇 후보 패널·표 보기·성능 측정·정적 묶음 2일.

## 검토한 대안

| 대안 | 판단 |
| --- | --- |
| 기획서 그대로 넣기 | 기각. '탐색 중'·좌석별 경합·IP 군집 데이터가 없고, 실버 대량 내려받기는 가명정보 규칙과 부딪히며, WebGPU는 지원 기준 밖이다 |
| 넣지 않기 | 기각. 상시 데모가 없는 프로젝트에서 서버 없이 눌러 보는 시연과 프론트엔드 깊이를 보일 기회를 버린다 |
| DuckDB-WASM으로 인브라우저 SQL | 기각. 압축 뒤 약 7.1MB이고 정식판이 2025-12 뒤 없다. 정해진 차원 집계에는 비트마스크로 충분하다 |
| WebGPU로 그리기 | 기각. Baseline이 아니다. 산점도 수십만 점은 WebGL2로 그린다 |
| 처음부터 관제 콘솔 원격 위젯으로 | 기각. 서버·권한·법률 검토가 먼저 필요해 1단계 시연이 늦어진다 |
| SCR-031 리플레이만 늘리기 | 기각. 서버 없이 보일 수 없고 좌석 공간 맥락이 없다 |

## 결과와 트레이드오프

- **좋은 점**: 서버·개인정보 없이 누구나 눌러 보는 시연이 생긴다. 좌석맵 렌더러를 패키지로 올려 두 화면이 같이 쓴다. 2단계는 데이터 원천만 바꾸면 된다.
- **남는 한계**
  - 1단계는 합성 데이터라 실제 온세일을 증명하지 않는다. 사람 분포는 설명용 가정이다.
  - 공개 위치를 아직 정하지 않았다. 헤더를 정할 수 없는 곳이면 공유 메모리·`frame-ancestors`를 쓸 수 없다.
  - 2단계는 법률 검토 결과에 따라 열리지 않을 수 있다. 좌석 단위 경합은 계약 보강 전까지 구역 단위다. 행동 요약값 30일·사건 90일 보존 밖의 회차는 다시 볼 수 없다.
  - 서비스 사이 사건 순서는 밀리초 시각으로 정하지 않는다.
  - 이 한계들은 planning/01 §5.2와 guide/17에 적었다.
- **반영 수치(2026-10-21)**
  - ADR 79 → 80, FR 70 → 71(FR-071), SCR 68 → 69(SCR-069), CMP 78 → 79(CMP-079), 용어 2개(포렌식 리플레이, 합성 시나리오), POL-027 확인 필요 11 → 12, 시험 FX-T1~FX-T10, REST 경로·작업 수 그대로(2단계 API는 초안)
  - WBS 3개 작업 +7일(429 → 436일): 7.7.1 2, 7.7.2 3, 7.7.3 2
  - 검토 기록 R-89, 질문 38, 디자인 캔버스 SCR-069 세 크기 보드(v57, 새 쪽 ⑨, 렌더 확인은 하지 않음)

## 되돌릴 조건

- wbs 7.7.3 측정에서 비트마스크 교차 필터가 목표에 크게 못 미치고 임의 질의가 꼭 필요하면 인브라우저 SQL(DuckDB-WASM 정식판)을 새 ADR로 다시 본다.
- WebGPU가 Baseline Widely available이 되면 산점도·좌석맵 그리기를 다시 본다.
- 법률 검토에서 가명정보 쓰임이 처리 목적 밖이면 2단계를 열지 않고 1단계만 둔다.
- 공개 위치를 정할 수 없으면 1단계는 녹화 영상과 재현 스크립트로만 보인다.
