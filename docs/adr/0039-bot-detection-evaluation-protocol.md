## 맥락
- 소유자 질문(2026-10-11): "매크로 봇의 부정행위를 얼마나 잘 잡아내는지 어떻게 평가하는가, 공신력 있는 방식이 있는가." 조사 결과 탐지율을 보증하는 공인 인증이나 공식 수치 기준은 국내외에서 확인하지 못했다. 대신 아래 자료가 각각 한 부분씩을 정해 준다(2026-10-11 원문 확인).

- 기존 계획(planning/01 §3 K6, NFR-022, wbs 1.2.2·3.7.1)에 있던 것: 합성 봇 차단율 95% 이상, 사람 오탐률 0.5% 이하, Playwright 매크로 봇과 녹화한 사람 세션의 라벨 데이터셋, 혼동 행렬, 속도형·물량형 두 종류, 정렬 방식별 봇 성공률(Q-T1), 봇 점유율의 하한 추정, 스테이징 한정 윤리 규칙(POL-026), 자동화된 결정 공개(POL-006).
- 빠져 있던 것: 표본 수와 신뢰 구간 기준, 봇 등급과 OAT 유형 대응, 적응 라운드, 실서비스 하한 추정 수단, 사람 세션의 기기·망 다양성, 봇 방어 기능의 ASVS 추적 표, 봇 1장 비용 지표.
- 실제 운영 트래픽에는 정답 라벨(Ground Truth)이 존재하지 않으므로, 단일 벤더의 마케팅성 '99.9% 차단' 수치를 맹신할 수 없으며 수학적 신뢰 구간과 공격자의 전략 변화를 반영한 다단계 검증이 필수적이다.
- 용어: 문서에 제품 이름 'Turnstile'이 기능 이름처럼 쓰여 읽기 어렵다는 소유자 지적(2026-10-11). planning/01은 '보안문자(Turnstile)'라고 적었으나, 보안문자는 글자를 읽어 입력하는 방식이고 Turnstile은 브라우저 안의 짧은 비대화형 검사로 판별하며 위험할 때만 체크 상자를 띄운다(Cloudflare 문서). 영어 turnstile은 개찰구라는 뜻이라 공연장 입장(오프라인 게이트)과도 혼동된다.

## 결정
1. **합성 봇 등급 체계 및 계층별 목표.** 합성 봇을 목적 4유형과 정교함 3단계의 매트릭스로 세분화하고 등급마다 따로 보고한다. 유형은 물량형(OAT-005 Bulk purchase, OAT-021), 속도형(OAT-006, OAT-013), 계정 대량 생성형(OAT-019. 1인 1계정 본인확인을 우회하는 명의 대여 포함), 대기열 새치기형(OAT-005 Queue jumping: 토큰 재사용·절차 건너뛰기)이다. 정교함은 1단계 요청만 보내는 원시 HTTP 스크립트, 2단계 브라우저 자동화(사람 확인 풀이 시도 포함, OAT-009), 3단계 사람 입력을 녹화해 재생·변형하는 봇이다. 1단계 및 2단계는 등급마다 탐지율 95% 이상을 달성해야 하며, 3단계 인간 모사 봇은 실측값과 '봇 1장 비용' 지표를 기록하고 목표치는 첫 측정 뒤 확정한다 [가정, Phase 3 3.7.1에서 확정]. 합성 봇은 피켓 자신의 시험 환경에서만 구동한다(POL-026).
2. **수학적 표본 설계 및 신뢰 구간.**
   - 탐지율은 Wilson 95% 신뢰 구간과 함께 기록하며, 판정 기준은 점추정치 95% 이상이다. 봇 세션은 등급마다 1,000개 이상을 투입한다(탐지율 95%에서 구간 폭 약 ±1.4%p).
   - 일반 사용자 오탐률(False Positive Rate)은 Clopper-Pearson 단측 95% 신뢰 구간 상한으로 판정하며 상한이 0.5% 이하여야 통과한다. 오탐 0건일 때 상한은 1 − 0.05^(1/n)이므로 사람 세션 600개 이상이 필요하다(600개면 약 0.50%). 오탐률 자체를 ±0.2%p 정밀도로 추정하려면 약 4,800개가 필요하므로, 그 전에는 '상한'으로만 표기한다.
   - 사람 세션은 녹화 재생만이 아니라 실제 입력 세션을 섞고, 기기 3종·망 2종 이상에서 수집한다. 참여자의 동의를 받으며 개인정보는 합성 데이터만 사용한다(POL-026).
3. **적대적 적응 라운드 3회 평가.** 같은 예산(시간·요청 수) 안에서 공격자 측이 이전 라운드 결과를 보고 탐지 회피 전략을 수정하는 라운드를 3회 연속 실시하고, 회차마다 등급별 탐지율과 하락폭을 기록한다. 라운드 사이의 탐지 규칙 변경은 허용하되 변경 내용을 같은 장부에 남긴다. 1회 측정만으로는 '탐지한다'고 말하지 않는다.
4. **실서비스 트래픽의 하한(Lower Bound) 표기 원칙(FR-049).** 프로덕션 환경에는 정답 라벨이 없으므로 아래 수단으로 센 값을 엄격한 '탐지 하한'으로만 공표한다.
   - 사후 라벨: 추가 검증 실패, 부정구매 신고, 본인확인 중복 시도.
   - 허니팟 신호: 사람이 보거나 누를 수 없게 숨긴 요소·경로를 두고, 접촉한 세션을 봇으로 확정 라벨하여 위험 점수에 반영한다. 숨긴 요소는 접근성 트리에서도 제외하여 키보드·스크린리더 사용자가 닿지 않게 한다(NFR-020).
   - 허용 세션 표본 검토: 공연 종료 후 정상 통과 세션 중 무작위 표본을 CS가 행동 신호로 심층 검토하여 미탐지 비율을 신뢰 구간과 함께 추정한다. 표본은 공연당 200건 [가정, Phase 3 3.7.1에서 확정]. 봇 탐지 목적 안에서 행동 신호 보존 기간(30일) 안에 수행하고 세션 ID와 판정만 남긴다(POL-006).
   - 그림자 실행(Shadow Execution): 신규 판정 규칙·모델은 기존 규칙이 집행하는 동안 같은 세션에 판정만 기록한다. 두 판정이 갈린 세션을 사후 라벨과 대조해 오탐·미탐 변화를 확인한 뒤 집행으로 승격한다. 집행은 기존 규칙이 계속 담당하므로 그림자 실행 때문에 추가로 통과하는 봇은 없다.
5. **봇 1장 비용 지표.** 합성 시험에서 봇이 티켓 1장을 획득하기까지 소모한 본인확인 계정 수, 요청 수, 시간을 원본으로 기록하고, 금액 환산은 가정한 단가를 명시하여 함께 기록한다. 1인 1계정과 휴대폰 본인확인이 구조적 상한을 만들고 탐지가 그 위의 비용을 높인다는 사실을 이 지표로 입증한다. 기존의 '요청 수 증가 배수' 지표는 이 지표의 일부가 된다.
6. **보고 규칙.** 등급별 표, 라운드별 표, 신뢰 구간, 실측·외삽·설계 목표·하한의 구분(docs/perf-ledger.md §7)을 준수한다. 측정 1회는 장부 폴더 하나이며, 혼동 행렬을 `confusion.csv`로 두고 manifest의 `k6_eval`에 등급·라운드·표본 수·구간을 기록한다(docs/perf-ledger.md §2). 사람 확인 통과율은 봇 탐지 지표로 사용하지 않는다.
7. **ASVS 추적 표.** 봇 방어 기능의 ASVS 추적 표를 `docs/security/asvs/bot-defense.md`로 두고(2.1.3, 2.3.1, 2.3.2, 2.4.1, 2.4.2, 6.1.1, 16.1.1, 16.3.3, 16.3.4), Phase 3 착수 전(wbs 3.2.1) 재판정한다.
8. **용어 표준화: '사람 확인'.**
   - 기능과 흐름을 말할 때는 '사람 확인'이라고 부르며 화면 문구도 동일하다. 특정 상용 제품명인 'Turnstile'을 일반 명사처럼 사용하지 않는다.
   - 제품을 가리켜야 하는 곳(기술 스택 표, 외부 서비스 목록, C4 외부 시스템, 비밀 키, 한도, 참고 자료 제목)과 각 문서에서 처음 나오는 곳에는 'Cloudflare Turnstile'을 함께 적는다. 용어 사전이 '사람 확인'을 정의한다.
   - 코드 이름은 공급자 중립으로 `human_check`·`HumanCheck`를 쓴다(예: API 필드 `humanCheckToken`, 컴포넌트 CMP-047 `HumanCheckBox`, trust-svc 첫 처리기 `HumanCheck`). 공급자를 교체해도 이름이 유지된다.
   - 고치지 않는 것: 이전 ADR 본문, 00-diagnosis, docs/appendix-learning-map.md 원문, review의 지난 기록.

## 검토한 대안
| 대안 | 기각 사유 및 한계점 |
| --- | --- |
| 외부 벤더의 봇 보고서 수치를 인용 | 정의와 모집단이 달라 비교할 수 없고, 피켓의 탐지 성능을 말해 주지 않는다. |
| 인증 취득 | 봇 탐지율을 인증하는 제도를 찾지 못했다. |
| 단순 CAPTCHA 통과율을 봇 방어 지표로 인용 | 컴퓨터 비전 및 LLM을 활용한 최신 봇의 풀이 성공률이 사람보다 높다는 연구 결과(USENIX Security 2023)가 있어 방어 지표로서의 신뢰성이 없다. |
| 실서비스 전수 라벨링 | 정답지가 없다. 사후 라벨은 일부만 드러내므로 하한으로만 쓴다. |
| 실제 운영 트래픽에서 대조군을 위해 일부 세션의 집행을 해제 | 놓친 봇의 실제 피해를 볼 수 있지만, 해제한 만큼 봇이 더 통과해 봇 점유율 목표(5%)를 깰 수 있다. 표준 시나리오에서 1%만 해제해도 대기열의 봇이 약 4,750 늘어 점유율이 약 4.8%에서 5.6%로 오른다. 대신 기존 규칙이 집행하는 그림자 실행과 표본 검토를 쓴다. |
| 용어를 '보안문자'나 '캡차'로 | 둘 다 글자·그림을 맞히는 방식을 떠올리게 해 Turnstile의 동작과 다르다. '자동입력 방지'는 정확하지만 길다. '사람 확인'은 기능이 하는 일을 그대로 말한다. |

## 결과와 트레이드오프
- 얻는 것: K6를 단일 숫자가 아니라 등급·라운드·신뢰 구간이 있는 표로 말할 수 있고, 실서비스 수치는 과장 없이 하한으로 말한다. 평가 방법이 OWASP·ISO·NIST 자료와 연결되어 근거를 댈 수 있다. 문서를 처음 읽는 사람이 '사람 확인'을 바로 이해한다.
- 대가
  - WBS가 3.5일 늘어난다(1.2.2 +1, 3.2.3 신설 1.5, 3.7.1 +1).
  - 사람 세션 600개 이상을 모아야 오탐률 주장을 할 수 있다. 모이기 전에는 '측정 전'으로 둔다.
  - 그림자 실행은 판정 연산을 두 번 수행한다. 로비 단계라 T=0 경로 밖이지만 trust-svc 용량 산정에 반영한다.
  - 표본 검토는 CS 시간이 들고 개인정보 처리 목적 안에서만 수행해야 한다(POL-006).
  - 코드 이름 변경으로 API 필드(`turnstileToken` → `humanCheckToken`)와 컴포넌트 이름(CMP-047)이 바뀐다. 구현 전이라 비용은 문서 수정뿐이다.
- 되돌릴 조건
  - 적응 라운드 3회에서 2단계 탐지율이 95% 아래로 떨어지면 trust-svc 신호 구성을 새 ADR로 다시 정한다.
  - 표본 검토로 추정한 미탐지 비율의 구간이 너무 넓어 판단에 쓸 수 없으면 표본 수를 늘린다.
  - 문체부·KISA 등이 매크로 탐지의 공식 평가 기준을 내면 그 기준을 채택하고 이 ADR을 보완한다.
