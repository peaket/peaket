# ADR-0066: 화면 피드백 12건 — 페이지별 보드, 후기 사진·신고, 문의 화면, 좌석맵 템플릿(2026-10-19)

- **상태**: 채택 (2026-10-19. 소유자가 디자인 캔버스를 보고 12가지를 요청·질문했다. 요청한 것은 소유자 요청으로, 세부는 추천 적용으로 정했다. 결정 하나하나가 소유자 검토 대상이다. 법령은 2026-10-19 국가법령정보센터 원문으로 확인했다)
- **관련**: ADR-0032(외부 상태 페이지), ADR-0051(현장 입장 과정), ADR-0053(웹훅 서명), ADR-0061(콘솔 휴대폰·태블릿), ADR-0062 결정 38(공연 이미지 기준), ADR-0063(화면 개편), POL-024, POL-042, FR-016, FR-023, FR-025, FR-057

## 맥락

- 소유자 요청(2026-10-19, 요지): ① SCR-015 굿즈 카드의 [장바구니 담기]를 장바구니 아이콘으로 바꿔 글자 묶음 안 오른쪽에 두고, 비슷한 카드 버튼도 성격에 맞게 고친다 ② SCR-016은 후기만 담으니 제목을 '후기'로, 기대평 쓰기를 없애고, 사진을 올리게 하고, '암표·매크로 신고'를 일반 [신고]로 바꿔 사유 버튼·자세한 사유·유의사항이 있는 모달과 전송 전 확인 모달을 둔다 ③ SCR-056의 [문의하기]가 가는 문의하기·내 문의 내역 페이지가 없다 ④ SCR-059는 판매 일시 중단 말고 다른 상태도 보이게 하고, '서비스 상태' 링크가 무엇이고 필요한지 묻는다 ⑤·⑪ 현장 스태프가 스캐너에 로그인하는 과정과 화면이 무엇인지, SCR-051은 언제 나오는지 묻고 그 과정을 명확하게 완성하라고 한다 ⑥ 좌석맵 에디터는 큰 틀의 배치를 그리고 모양을 조절한 뒤 그 안에 좌석 수대로 배치하고 위치를 다듬는 방식이어야 하고, 국내에서 흔한 공연장은 좌석 템플릿을 가져다 쓰게 하라고 한다(기획·설계·디자인 모두) ⑦ SCR-037 [현장 운영]이 무엇을 하는지 묻는다 ⑧ SCR-027 판매 요약·예매자 명단·다운로드 이력 ⑨ SCR-023 상품 목록·굿즈 주문 현황을 각각 그려 달라고 한다 ⑩ SCR-025 웹훅은 어디에 쓰는지, 기획이 있는지 묻는다 ⑫ 파트너 콘솔 '내 계정'·'판매자 정보'·'정산 계좌' 페이지가 필요하지 않느냐고 묻는다.
- 조사 결과: ⑧·⑨·⑪·⑫로 '없다'고 한 화면 상당수(예매자 명단, 상품 목록, 굿즈 주문 현황, 스캐너 로그인 SCR-036, 내 계정·정산 계좌)는 보드 안의 숨은 상태로만 있었다. 캔버스는 보드의 기본 상태만 보이고, 다른 상태는 보드마다 Tweaks를 열어야 보인다. 다운로드 이력, 판매자 정보(데스크톱·태블릿), 문의 세 페이지, 신고 모달, 후기 사진, 좌석맵 그리기 세부와 템플릿은 정말로 없었다. 기대평은 ADR-0063에서 이미 없앴고 2026-10-19 다시 찾아 남은 곳이 없었다.
- 법령(2026-10-19 원문 확인): 공연법 시행령 §3의3 1호·2호 나목은 게시물을 '신고기관'(법 §4의3①)에 신고할 수 있는 기능을 요구한다. 정보통신망법 §44의2(시행 2026-10-02)는 권리를 침해받은 자의 삭제 요청(통지 수단 지정), 지체 없는 조치와 신청인·정보게재자 통지, 게시판 공시, 판단이 어려울 때 30일 이내 임시조치, 약관에 절차 명시를, §44의3은 임의의 임시조치를 둔다. 전기통신사업법 §22의5①(시행 2026-10-01)은 조치의무사업자가 신고로 인식한 불법촬영물등을 지체 없이 삭제·접속차단하게 하고, 시행령 §30의6은 전년도 매출 10억 원 이상이거나 하루 평균 이용자 10만 명 이상이고 별표 3의2 서비스를 하는 사업자에게 기술적·관리적 조치를 둔다. 전자상거래법 시행령 §6①4호는 소비자 불만·분쟁 처리 기록을 3년 보존하게 한다.

## 결정

1. **한 페이지 = 한 보드(추천 적용)**: 원본 보드 하나에 상태를 그리고, 탭·페이지·주요 모달 상태는 원본 사본에 `state` 기본값만 바꾼 보기용 보드로 원본 행 아래에 놓는다. 보기용 보드는 스크립트로 다시 만들고 사람이 고치지 않는다(고칠 때는 원본). 대상은 SCR-016·020·022·023·027·036·037·051·056·059(셸 넷 포함).
2. **카드 안 아이콘 버튼(소유자 요청, 배치 세부는 추천 적용)**: 굿즈 카드는 글자 묶음을 두 칸 격자로 하고 1행 [이름 | 장바구니 아이콘 버튼 44px]을 두며 가격·배송비·판매자는 아래에서 두 칸을 다 쓴다. 옵션이 있는 상품은 옵션 시트를 연다. 같은 꼴인 홈 오픈 예정 카드의 [오픈 알림 받기]는 종 아이콘 토글(`aria-pressed`, 신청되면 채운 종)로 바꾼다. 머리의 장바구니 아이콘도 `ic-cart`로 맞춘다.
3. **후기 이름과 사진(소유자 요청, 세부는 추천 적용)**: 화면 표기는 '후기'다. 한 후기에 사진 3장 [가정], 공연 이미지와 같은 형식·크기 기준, 서버가 다시 인코딩하고 메타데이터를 지우며 원본은 파생본을 만든 뒤 지운다. QR 코드·바코드가 보이는 사진은 받지 않는다. 사진 설명(대체 텍스트)은 선택이다. 사진 보기는 같은 모달 안에서 한다.
4. **일반 [신고](소유자 요청, 세부는 추천 적용)**: 사유 8종(암표·부정판매, 매크로·부정 예매 프로그램, 욕설·비방·혐오, 개인정보 노출·명예훼손, 음란물·불법 촬영물, 광고·도배, 공연과 관계없는 내용, 기타), 자세한 내용 500자 [가정], 유의사항 6줄, 확인 모달. 한 번에 대화상자 하나(신고·확인 모달은 앞 모달 자리를 바꿔 연다). 암표·매크로 사유와 목록 위 안내에 신고기관(한국콘텐츠진흥원) 온라인 암표신고센터 바로가기를 남겨 공연법 시행령 §3의3 나목 조치를 유지한다(POL-024 나목의 '간주'는 그대로, 위치만 바뀜). 개인정보 노출·명예훼손을 '본인'이 신고하면 정보통신망법 §44의2 삭제 요청으로 받아 통지 수단을 고르게 하고, 판단이 어려우면 30일 이내 임시조치하고 신청인·글쓴이에게 알리며 후기 자리에 공시한다. 불법 촬영물 신고는 확인할 때까지 바로 가린다. 같은 후기는 계정당 한 번, 하루 10건 [가정], 결과 알림 3영업일 [가정], 신고 기록 1년 [가정] 보관.
5. **문의 화면(추천 적용)**: `/help/inquiries/new` 문의하기(유형 11개, 관련 주문, 제목, 내용, 첨부 없음), `/help/inquiries` 내 문의 내역(상태 칩, 새 답변 표시, 페이지 번호), `/help/inquiries/[id]` 문의 상세(분쟁 기한, 기록, 추가 문의, 답변 뒤 14일 [가정] 지나면 닫힘). 담당자는 '피켓 고객센터'로 보인다. 문의는 core-svc의 새 support 모듈이 갖고 CS 처리함 건(ops-svc)과 잇는다. 기록은 소비자 불만·분쟁 처리 기록으로 3년 보존한다(일반 문의를 이 기록으로 보는 것은 해석).
6. **시스템 안내(추천 적용)**: SCR-059의 모든 상태를 보기용 보드로 둔다. '서비스 상태' 링크는 클러스터 밖 공개 상태 페이지(ADR-0032)라 남기되 '복구 소식 보기 ↗'로 이름을 바꾸고 "피켓이 멈춰도 열리는 별도 안내 페이지" 설명을 붙인다. 판매 일시 중단에만 둔다.
7. **현장 스태프 로그인(추천 적용)**: 과정은 그대로다(초대 SCR-037 → 수락 SCR-050 → 배정 SCR-061 → 스캐너 SCR-036 QR → 스태프 본인 휴대폰 SCR-051 승인 → SCR-033 → SCR-034, 휴대폰이 없으면 현장 책임자의 대리 승인). SCR-036에 '아이디·비밀번호 없이 내 휴대폰으로 승인' 설명과 세 단계를 넣고, 상태를 세 크기에 같게 맞추고(새 코드로 바뀜, 승인 거부됨, 대리 승인, 기기 등록 포함), SCR-051에 화면이 열리는 때와 대리 승인 화면을 더하고, 스캐너 페이지 첫 행에 흐름 보드(세 레인·여덟 단계)를 둔다.
8. **좌석맵 에디터 네 단계(소유자 요청, 도구 세부는 추천 적용)**: [① 배치 그리기] [② 좌석 채우기] [③ 좌석 다듬기] [미리보기]. ①은 도형 손잡이(크기·회전·꼭짓점·반지름·각도)·안내선·치수·좌우 대칭 복제, ②는 구역에 좌석 수(또는 행 × 좌석)를 넣으면 도형 안에 자동으로 놓고 들어간 수를 알린다, ③은 고른 좌석의 이동·줄 맞추기·간격·통로 만들기·지우기·번호 다시 매기기. 좌석 겹침 경고를 더한다. 자동 채우기 계산은 에디터가, 저장 때 검사는 서버가 한다.
9. **좌석 템플릿 10종(소유자 요청, 목록은 추천 적용)**: 실내 아레나(엔드·돌출·센터), 돔 구장, 종합운동장, 대극장(3층), 중극장(2층), 소극장, 콘서트홀(합창석), 평면 블록. 기본 좌석 수는 [가정]이고 목표 좌석 수와 변형(무대 형태·피트 등)을 고른 뒤 그 공연의 배치본으로 복제한다. 템플릿은 흔한 모양을 본뜬 출발점이고 실제 공연장의 배치도가 아니다. 특정 공연장 이름과 남의 배치도는 쓰지 않는다. 스탠딩(정리번호) 구역은 ADR-0051대로 범위 밖이라 플로어는 지정석이다. 템플릿은 저장소 정적 자료로 배포 때 넣고 파트너는 읽기만 한다.
10. **현장 운영·정산·상품 페이지(추천 적용)**: SCR-037 [현장 운영]에 목적 설명·시간 띠·요약 타일을 더한다. SCR-027 [다운로드 이력](명단 내려받기 기록, 파트너 관리자만, 접속기록 2년)을 새로 그리고, 판매 요약·예매자 명단을 다듬는다. SCR-023 탭 넷(상품 목록·굿즈 주문 현황·배송·반품 처리·상품 정산)을 각 페이지로 보인다.
11. **웹훅의 목적(추천 적용)**: FR-025에 목적과 쓰임새(매출·회계 반영, 사내 메신저 알림, 자사 공지 갱신, 정산 입금 확인)를 적고 SCR-025 맨 위에 설명 상자를 둔다. 본문에 개인정보가 없어 팬 관리에는 쓸 수 없고, 파트너 서버가 PEAKET에 물어보는 서버용 API는 없다(Phase 이연). 우선순위는 그대로 Could다.
12. **파트너 설정 페이지(추천 적용)**: 내 계정·판매자 정보·정산 계좌·팀 계정을 설정 메뉴 3열 + 본문 9열 페이지로 그린다. 판매자 정보 보기와 변경 요청 API를 더한다. 상호·대표자 변경은 공연의 판매 재승인이 아니라 PEAKET 운영자가 판매자 정보를 다시 확인하는 것이고(planning/03 §2.14, POL-039, ADR-0062), 확인이 끝날 때까지 지금 정보가 보인다. 파트너 계정 보안 설정 API는 d5 §1.6에 남긴다.

## 검토한 대안

| 대안 | 고르지 않은 이유 |
| --- | --- |
| 숨은 상태를 그대로 두고 Tweaks 사용법만 안내 | 소유자가 이미 여러 번 '없다'고 봤다. 캔버스에서 바로 보이지 않으면 검토할 수 없다 |
| 페이지마다 따로 그린 독립 보드 | 같은 화면이 두 곳에 생겨 고칠 때 어긋난다. 원본 하나 + 스크립트 사본이 정본을 하나로 지킨다 |
| `<dc-import>`로 원본을 불러 쓰는 얇은 보드 | 사본이 필요 없지만 이 캔버스에서 렌더링을 확인한 적이 없어 보드가 오류로 보일 수 있다 |
| 신고를 피켓 신고로만 받고 암표 신고기관 링크를 없앰 | 시행령 §3의3 나목은 신고기관에 신고하는 기능을 요구한다 |
| 신고 확인을 신고 모달 위에 겹친 모달로 | d2 §3.4의 '모달 위에 모달을 겹치지 않는다' 규칙과 어긋나고 초점 가둠이 둘이 된다 |
| 실제 국내 공연장 배치도를 템플릿으로 | 공연장이 준 공식 자료와 허락이 필요하고, 다른 예매처·공연장의 배치도를 베끼면 이용 조건과 저작권 문제가 생긴다 |
| 스탠딩 구역 템플릿 | 정리번호 입장은 ADR-0051에서 범위 밖이다 |
| '서비스 상태' 링크를 뺌 | 리전 장애 때 앱 밖에서 복구 상황을 알릴 길이 없어진다. 대신 쉬운 이름과 설명을 붙였다 |

## 결과와 트레이드오프

- 캔버스: 보기용 보드와 흐름 보드가 늘어 보드 수가 커지고 게시를 두 번에 나눠야 한다(한 번 255개 상한). 보기용 보드는 원본을 고친 뒤 다시 만들어야 한다.
- 남는 한계: 사진의 QR 거르기는 일부만 보이거나 흐린 코드를 놓칠 수 있다. 사진에는 금칙어 검사가 듣지 않아 신고로 보완한다. 불법 촬영물 사전조치 의무와 조치의무사업자 해당 여부는 확인 필요다. 템플릿은 실제 공연장과 달라 파트너가 고쳐야 한다. 웹훅만으로는 자세한 판매 정보를 받을 수 없다.
- 반영 수치(2026-10-19): FR 68 → 70(FR-069 고객 문의, FR-070 게시물 신고), POL 43 → 44(POL-044), CMP 73 → 78(CMP-074~078), REST 경로 150 → 163·작업 163 → 178(이 ADR의 14개와 운영자 CS 건 상세 1개), asyncapi 채널 `support.cases-requested`, ASVS 추적 표 10 → 11(asvs/support), POL-027 해석 25 → 26·확인 필요 8(목록 기준으로 다시 셈), WBS 360 → 369.5일(7.3.1·5.8.4 +1.5, 2.9.2 +5, 7.2.1·7.2.5·0.10.2 +0.5), review R-75, 디자인 캔버스 보드 217 → 390(보기용 172·흐름 보드 1, 버전 37), 프로토타입(홈 종 토글·후기 사진·신고)

## 되돌릴 조건

- 소유자가 '서비스 상태' 링크를 빼라고 하거나, 신고 사유·유의사항·보존 기간을 바꾸라고 하면 그대로 고친다.
- 법률 검토(wbs 7.4.1)에서 신고 기능이나 불법 촬영물 조치 기준이 달라지면 POL-024·POL-044를 고치고 새 ADR로 남긴다.
- 실제 공연장과 좌석 자료 제공 계약이 생기면 공연장 템플릿(실제 배치도)을 새 ADR로 더한다.
