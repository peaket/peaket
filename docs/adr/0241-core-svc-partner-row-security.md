# ADR-0241: core-svc의 파트너 경로를 전용 DB 사용자와 행 보안으로 막는다

- **상태**: 채택(2026-11-09, 추천 적용. authz-matrix §5.3의 행 보안은 추천 적용 2026-10-30이다). BUILD_ORDER HOT-172.
- **관련**: [docs/security/authz-matrix.md](../security/authz-matrix.md) §3.3·§5.3, ADR-0083, ADR-0198 결정 2·8
- **관련 ID**: AZ-T5, FR-021, ASVS v5.0.0-8.4.1

## 맥락

- 파트너 경로는 조회 조건으로 자기 테넌트만 읽지만(1차), 쿼리 하나에서 조건이 빠지면 다른 파트너의 공연이 나온다. 2차 방어인 행 보안이 없었다.
- 공연 등록의 오픈 간격 판정은 다른 파트너의 공개 회차 오픈 시각을 봐야 한다. 행 보안을 켜면 파트너 사용자는 그 행을 볼 수 없다.

## 결정

1. **DB 역할 둘**: 마이그레이션이 로그인할 수 없는 그룹 역할 `core_app`(팬·관제 경로)과 `core_partner`(파트너 경로)를 만든다. 비밀번호가 있는 로그인 사용자는 비밀 관리가 만들어 이 역할에 넣는다. 두 역할 모두 `BYPASSRLS`가 없고 표 소유자가 아니다.
2. **연결 묶음 둘**: 파트너 경로의 쓰기(공연 등록·회차 더하기)는 `PEAKET_PARTNER_DATABASE_URL`의 풀로만 간다. 값이 없으면 서비스가 시작하지 않는다. 팬·관제 경로는 지금처럼 `PEAKET_DATABASE_URL`을 쓴다.
3. **정책**: `production`·`event`에 행 보안을 켠다. `core_partner`는 `promoter_id = nullif(current_setting('app.tenant_id', true), '')::uuid`인 행만 보고 쓴다(읽기·쓰기 같은 조건). `core_app`은 전체를 읽는다(쓰기 정책 없음).
4. **권한은 코드가 쓰는 만큼만**: `core_partner`는 `production`·`event`를 읽고 넣으며, `production`은 `sale_review`·`pending_revision` 두 칸만 고친다(스스로 판매 승인을 올리거나 판매자를 바꾸지 못한다). `place`·`artist`는 읽기만, `production_artist`·`search_alias`는 넣기만 한다(판매자 연락처, 승인 전 공연 별칭을 읽지 못한다). `core_app`은 전체 읽기와 `wish`의 넣기·지우기뿐이고, 쓰기가 생기면 그 단계의 마이그레이션이 더한다. `idempotency_record`는 등록 재시도에 필요해 읽기·쓰기를 주며 값은 만든 ID뿐이다.
5. **오픈 간격은 정의자 권한 함수로 읽는다**: `public_open_times(from, to, exclude)`는 공개 공연 회차의 오픈 시각 한 칸만 돌려준다. `search_path`를 `pg_catalog, pg_temp`로 고정하고 표 이름에 스키마를 붙여(임시 표로 대상을 바꿔치지 못하게) `core_partner`에게만 실행 권한을 준다. 보기(view)는 소유자 권한으로 돌아도 칸을 더 드러내기 쉽고, 파트너에게 표 조회 권한을 넓히지 않아도 되는 함수를 골랐다.
6. **Outbox 파티션과 마이그레이션은 소유자 권한으로 돈다**: 표를 만드는 일이라 앱 사용자에게 주지 않는다. `outbox`는 테넌트 표가 아니다. 소유자는 슈퍼유저가 아니어도 된다(`CREATEROLE`만 있으면 된다).
7. **시작할 때 접속 사용자를 본다**: 소유자·슈퍼유저이거나 두 역할을 겸하면(정책은 OR로 합쳐진다) 행 보안이 조용히 꺼지므로 서비스가 시작하지 않는다. 이미 있는 역할이 `BYPASSRLS`이면 마이그레이션이 멈춘다.

## 결과

- 파트너 쿼리에서 테넌트 조건이 빠져도 다른 파트너의 행이 나오지 않는다. 테넌트를 걸지 않은 트랜잭션은 0건이다.
- 등록 통합 시험을 실제 권한의 사용자로 돌려, 빠진 권한이 있으면 시험이 실패한다.
- 풀이 하나 늘어난다. 파트너 경로는 핫패스가 아니어서 풀 크기는 4 [가정]로 둔다. 비용은 wbs 3.6.1에서 잰다(§5.3).

### 넘긴 것

- 운영 DB의 로그인 사용자 생성과 비밀 등록은 core-svc를 배포하는 단계가 한다(BAS-060 실행기와 함께).
- core-svc의 다른 테넌트 표(`product` 등)는 그 표를 만드는 단계가 같은 방식으로 켠다.

## 다른 선택지

| 길 | 고르지 않은 까닭 |
| --- | --- |
| 한 사용자로 접속하고 `SET ROLE`로 바꾼다 | 앱이 역할을 바꿀 권한을 쥐게 되어, 코드 실수 하나로 2차 방어가 사라진다 |
| `FORCE ROW LEVEL SECURITY`로 소유자까지 막는다 | 마이그레이션과 정의자 함수가 소유자 권한에 기대므로 함께 막힌다. 앱을 소유자가 아니게 두는 것으로 충분하다 |
| 파트너에게 다른 테넌트 회차의 조회 권한을 정책으로 연다 | 오픈 시각 말고 다른 칸(판매 상태 등)까지 함께 열린다 |
