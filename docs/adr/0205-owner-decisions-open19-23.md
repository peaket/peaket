# ADR-0205: 2026-11-05 소유자 결정 다섯 — 흔한 비밀번호 목록, 패스키 확인 라이브러리, 같은 종류 로그인 수단 병합, 흡수 계정의 기기 행, 봇 시뮬레이터 미룸

- **상태**: 채택(2026-11-05, 소유자 결정 "추천안대로". 갈래 3 세션이 docs/PROGRESS.md '미해결' OPEN[19]~[23]의 추천을 설명했고, 소유자가 다섯 모두 추천안으로 정했다. 같은 답으로 정한 OPEN[18]은 갈래 2 몫이라 갈래 2가 따로 반영한다)
- **관련**: ADR-0165(목록의 판은 출시와 함께 고정), ADR-0048·ADR-0174(봇 평가), [docs/security/auth-controls.md](../security/auth-controls.md) §4.1, [docs/features/identity.md](../features/identity.md) §2.1·§6·§9.1, [docs/data.md](../data.md) `device`, [docs/devops.md](../devops.md) §4.4(공급망 규칙)
- **관련 ID**: POL-020, POL-034, I-T14, I-T31, I-T32, I-T53, ASVS v5.0.0-6.2.4, BUILD_ORDER BOT-110·BOT-122·BOT-042·BOT-045·BAS-250·BOT-170

## 맥락

- 구간 1을 하며 갈래 3이 소유자에게 물은 것이 다섯 남아 있었다. 둘은 파일·패키지를 받는 일이라 소유자 허락이 필요했다(OPEN[19]·[20]). 둘은 정본이 정하지 않은 병합 규칙이었다(OPEN[21]·[22]). 하나는 이 세션이 만들 수 없는 단계였다(OPEN[23]).
- 추천안의 원문은 이 결정을 반영하기 전 커밋의 docs/PROGRESS.md '미해결'에 있다.

## 결정

1. **흔한 비밀번호 목록(OPEN[19])**: 관리 계정 비밀번호의 L1 목록을 공개 보안 자료 모음 SecLists(MIT 사용 허가)의 `xato-net-10-million-passwords-1000000.txt`(흔한 것부터 정렬한 100만 개)에서 만든다.
   - 판은 커밋 `00f80ec9cc39bed63ee40cf6805a6b1b77e87644`(2026-10-31)로 고정하고, 받은 파일의 SHA-256을 목록 파일 머리에 적는다.
   - 넣는 것: 원본 전체에서 15자 이상인 것(10,908개)과, 길이와 상관없이 가장 흔한 10만 줄 [가정]. 대조가 구분 글자를 지운 사본으로 하기 때문이다. 짧은 흔한 비밀번호에 점·공백을 끼워 15자를 채운 것도 막는다(새 맥락 리뷰 2026-11-05). 모두 110,834개다.
   - 만들기는 `services/identity-svc/scripts/build-common-passwords.mjs`가 한다. 받는 일은 사람이 손으로 하고, 스크립트는 SHA-256이 다르면 멈춘다.
2. **패스키 확인 라이브러리(OPEN[20])**: 관리 계정 패스키의 WebAuthn 확인(등록 증명·서명 확인)은 `@simplewebauthn/server`에 맡긴다.
   - 출처 증명이 있는 판으로 고정하고 identity-svc에만 더한다. 공급망 규칙(게시 뒤 3일, 신뢰 증거가 약해지지 않는 판)을 그대로 받는다.
   - 직접 만들지 않는다. 위조를 막는 확인은 검증된 구현에 맡긴다.
   - 설치와 세부 설계는 BOT-122에서 한다.
3. **같은 종류 로그인 수단(OPEN[21])**: 두 계정에 같은 종류의 다른 로그인 수단이 있으면 병합을 막는다.
   - 막는 사유는 `SAME_PROVIDER_KIND`이고, 화면이 그 종류를 말하도록 `sameKindProviders`를 함께 준다.
   - 사용자는 두 계정 가운데 한쪽에서 그 수단을 해제한 뒤 다시 합친다. 로그인 수단 '종류마다 하나' 규칙과 종류 단위 해제를 그대로 둔다.
4. **흡수 계정의 기기 행(OPEN[22])**: 병합 확정 트랜잭션에서 흡수 계정의 기기 행을 대표 계정으로 옮긴다.
   - 대표 계정에 같은 기기가 이미 있으면 흡수 쪽 행을 지운다. 같은 기기는 기기 가명이나 옛 판 가명이 겹치는 것이다.
   - 키 회전 이음 기간이면 새 판 가명을 남긴다.
   - 같은 사람의 기기라 다음 로그인에서 새 기기 알림이 가지 않고, 조사 연결과 로그인한 기기 목록이 대표 계정에 모인다. 대표 계정이 탈퇴하면 함께 지워진다.
5. **봇 시뮬레이터(OPEN[23])**: BAS-250을 미룬다.
   - K6 측정(BOT-170) 전에 소유자가 만들 길(직접 만들기나 다른 도구)을 정한다.
   - BAS-250이 끝나지 않으면 BOT-170은 앞선 단계 대기로 건너뛴다.

## 결과

- 정본: auth-controls §4.1 L1과 asvs/auth.md 6.2.4, identity §2.1·§6·§9.1, data.md `device`, data-classification(기기 가명 보존), openapi `MergeProposal`, planning/03 POL-034·T9, planning/04, d5 §5.22를 고쳤다. BUILD_ORDER BOT-122·BOT-140·BOT-170·BAS-250 줄에 결정을 적었다.
- 시험: I-T14(목록 판·개수, 구분 글자를 끼운 흔한 비밀번호), I-T31·I-T32(같은 종류 수단, 기기 행 옮기기)를 메모리 저장소와 PostgreSQL에서 본다.
- 대가:
  - 목록 파일이 약 1MB이고, 시작할 때 약 11만 개의 대조 사본을 만든다.
  - 병합을 막는 경우가 하나 늘어, 같은 종류 수단이 겹친 사용자는 한 번 더 해제해야 한다.
  - 옛 웹은 새 막는 사유를 모르므로 서버와 웹을 함께 낸다.

## 다른 선택지

| 선택지 | 판단 |
| --- | --- |
| 목록을 15자 이상만 | 버림. 구분 글자를 지운 사본으로 견주므로 `p.a.s.s.w.o.r.d`가 통과한다(새 맥락 리뷰 2026-11-05) |
| WebAuthn 확인을 직접 만들기 | 버림. 코드 약 200줄과 소프트웨어 인증기 시험이 필요하고, 위조 방지 확인의 보안 검토 부담이 크다 |
| 같은 종류 수단을 둘 다 두고 해제를 수단 단위로 | 버림. 해제 경로·로그인 수단 목록·'종류마다 하나' 규칙을 모두 바꿔야 한다 |
| 흡수 계정의 기기 행을 지우기 | 버림. 조사 적재가 병합 전에 읽지 못한 연결을 잃고, 다음 로그인에 새 기기 알림이 간다 |
| 흡수 계정에 기기 행을 그대로 두기 | 버림. 언제 지울지를 따로 정해야 하고, 대표 계정이 탈퇴해도 남는다 |
| 봇 시뮬레이터를 범위를 줄여 다시 시도 | 버림. 다시 막힐 수 있고, 줄인 범위로는 ADR-0048의 12칸 등급표를 채우지 못해 측정 의미가 약해진다 |
