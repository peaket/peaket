# ADR-0097: 학습 지도 부록을 설계 근거로 쓰지 않고 없앤다 — 기술을 고른 이유와 일부러 쓰지 않은 기술은 정본에 두고, OWASP Top 10 대응 표는 architecture §8.1로 옮긴다(2026-10-27)

- **상태**: 채택 (2026-10-27. 기술 검토(review/tech-review.md)의 높음-03 '학습 지도(부록)가 설계 근거처럼 쓰이고, 오버엔지니어링 비판 대응 문장이 사실과 다르다'에 소유자가 "'학습 지도(부록)'를 대안 기각 근거로 내세우는 역효과에 대해 동의합니다. 이거는 처음에 프로젝트를 기획할때 요구했던 부분이긴 한데 어느정도만 활용되었으면 끼워맞출 필요 없습니다. 색인에 맞춰 끼워맞추고 기술을 억지로 욱여넣는거보다 중요한건 합리적으로 이 기술을 선택한 이유를 면접관에게 설명할수 있어야 하는것입니다. 그래서 색인 문서도 최종적으로는 없애는게 맞습니다. 동의안대로 가겠습니다."라고 정했다. 부록을 없애고 학습 목록에 끼워 맞추지 않는다는 방향은 소유자 결정이고, 옮길 곳, 표의 칸, 약속했던 확인 실험의 처리는 추천 적용이다). 2026-10-27(ADR-0098): 같은 날 원문 설계서도 archive/에서 지워 git 태그 `archive-original`에만 남겼다. 본문이 말하는 'archive/의 원문'과 '원문 §11~13'은 그 태그에서 읽는다.
- **관련**: 원 요구 조건 1(review/consistency-review.md §8), planning/01 §5.2, [docs/architecture.md](../architecture.md) §6.1·§8.1·§11, ADR-0004, ADR-0018, ADR-0019, ADR-0021, ADR-0067, ADR-0068, ADR-0090, ADR-0096, review/open-items.md 5번, 00-summary §7 질문 48, [review/tech-review.md](../review/tech-review.md)(높음-03, 중간-065)

## 맥락

- **부록이 무엇이었나**: docs/appendix-learning-map.md는 원문 설계서 §11~13(학습 로드맵 1~33장의 항목을 시스템 어디에 썼는지 잇는 색인과 '의도적 기각' 목록)과 §9 '면접 답변 문장'을 원문 그대로 보존한 부록이었다(00-summary §2 '부록 보존'). 원문 보존 문서라 고치지 않아 왔다.
- **사실과 다른 대응 문장**: planning/01 §5.2의 '오버엔지니어링(과설계) 비판' 대응은 '모든 기술 스택과 아키텍처를 들일 때마다 정량적 ADR과 부하 테스트 측정 근거를 제시한다'고 적었다.
  - MongoDB, 저장소 여러 개, Module Federation, 판매 정책 DSL, Kafka 클러스터 셋 같은 선택에는 측정 계획이 없다.
  - 같은 칸이 '일부러 채택하지 않은 대안 목록'으로 이 부록을 들었다. 부록은 학습 목록을 채운 색인이라, 면접관에게는 '학습 목록을 채우려고 기술을 넣었다'는 인상을 준다.
- **정본과 어긋난 내용**: 부록 313행을 정본과 대조하면 정본에서 바뀐 행이 약 20개, 정본에 없는 행이 약 60개다(기술 검토 부록 A의 '부록 대조'). 본문에 상태 표시가 없어 정본과 다른 것이 사실로 읽혔다. 예: SWR·Jotai·Redux, GSAP, Terminus 헬스체크, Cassandra와 CockroachDB '실험', 좌석 상태의 HOT 주장.
- **정본이 부록을 근거로 가리킨 곳**:
  - architecture §8.1 OWASP Top 10 행은 항목별 대응을 부록 31장 표로 넘겼다.
  - architecture §6.1 기술 스택 표의 '관련 결정 기록' 칸에 학습 목록 장 번호(16장·20장·23장·26장)가 결정 기록처럼 적혀 있었다.
  - architecture §11 아래 '작성 예정 과제'의 Bigtable·Dataflow·GFS/HDFS는 학습 목록 항목을 채우려는 과제였다.
  - 옛 ADR이 기각 근거로 약속한 확인 실험 넷(ADR-0004 Cassandra와 ClickHouse 비교, ADR-0019 Aphrodite·Fela PoC, ADR-0021 CockroachDB 두 가지)은 학습 목록 항목을 다루려고 약속한 것이다. ADR-0004 결정 3은 '학습 목록 25장의 Cassandra 항목은 … 비교하는 실험으로 다룬다'고 적었다. 넷 모두 일정이 없다(review/open-items.md 5번, 질문 48).
  - 시험 표 몇 개의 '연결 요구사항' 칸과 인프라·데이터 표의 '근거' 칸에도 장 번호가 요구사항처럼 적혀 있었다.

## 결정

1. **부록을 없앤다(소유자 결정).** docs/appendix-learning-map.md를 지운다.
   - 원문 §11~13과 §9는 archive/의 원문 설계서와 git 이력에 남는다.
   - ADR 본문, 00-diagnosis.md, review의 지난 기록은 쓴 그대로 둔다. 거기 남은 부록 경로는 문서 점검 도구의 허용 목록에 넣어 오류로 보지 않는다(ADR-0090의 docs/arc42.md와 같다).
   - 부록에만 있던 영문 용어는 199개다(원문 대조 `--coverage`, 2026-10-27). 대부분 학습 항목을 보이려고 든 코드 예시 이름(`useQueue`, `CapacityVisitor` 등)과 언어 기능 이름이다. 도구 이름 일부(Testcontainers, supertest, Piscina, undici, immer 등)는 정본이 정하지 않은 것이다. 이런 도구가 필요하면 그 기능을 설계할 때 정본에서 정하고, 부록에 있었다는 사실은 근거로 쓰지 않는다. 원문 링크 70개는 모두 다른 문서에 남는다.
   - §9 '면접 답변 문장'은 옮기지 않는다. 목표 숫자의 정본은 planning/02 NFR 표와 docs/observability.md §12다.
2. **기술을 고른 이유는 정본에만 두고, 만드는 범위와 측정 근거를 숨기지 않는다(소유자 결정, 칸은 추천 적용).** architecture §6.1 기술 스택 표에 두 칸을 더한다.
   - '포트폴리오 범위': 만든다(로컬·CI·데모에서 돈다), 일부만, 설계만(코드와 정적 검사까지) 중 하나와 그 내용.
   - '측정 근거': 그 선택을 측정으로 판정하는 시험(K, PoC, 비교 측정)이 있으면 그 이름, 없으면 '없음(문서 근거)'.
   - '관련 결정 기록' 칸의 학습 목록 장 번호는 지우고 ADR로만 적는다. ADR이 없으면 '없음'이다.
3. **일부러 쓰지 않거나 미룬 기술은 architecture §6.1의 표로 둔다(추천 적용).**
   - ADR이 있는 것만 넣는다. 학습 목록에만 있던 항목(Bigtable·Dataflow·GFS/HDFS)은 넣지 않고, architecture §11 아래 '작성 예정 과제'에서도 지운다. PEAKET이 쓰는 AWS에 없는 서비스이거나 직접 운영할 이유가 없는 분산 파일 시스템이라, 따로 쓰지 않는 이유를 댈 후보가 아니었다.
   - 약속했던 확인 실험 넷은 하지 않는다. 학습 목록 항목을 채우려던 실험이라 소유자 원칙에 따라 일정에 넣지 않는다. 그 기술들의 기각 근거는 각 ADR 맥락에 적힌 문서 근거(지원 범위, 라이선스, 쓰기 지연, 운영 부담)이고, 표에는 '문서 근거로 기각'으로 적는다. review/open-items.md 5번과 질문 48을 닫는다.
4. **OWASP Top 10:2025 대응 표를 architecture §8.1 아래로 옮긴다(추천 적용).**
   - 칸의 장치는 정본에 있는 것으로 바꿔 쓴다. 부록 표의 helmet(보안 헤더), npm audit, Syft, sanitize-html·DOMPurify, STRIDE는 정본에 없는 도구다. 보안 헤더는 ADR-0065, 의존성 검사와 SBOM은 docs/devops.md §4, 사용자 입력 출력은 텍스트로만 그리는 규칙과 CSP·Trusted Types로 적는다.
   - A06(안전하지 않은 설계)의 위협 모델링은 정본에 없다. 표에는 '위협 모델 문서는 아직 없다(review/tech-review.md 중간-065)'로 적는다.
   - '대응 ASVS 5.0 장' 칸은 그대로 옮긴다.
5. **planning/01 §5.2 '오버엔지니어링(과설계) 비판' 대응을 사실대로 고친다(소유자 결정, 문장은 추천 적용).**
   - 기술마다 고른 이유와 대안은 ADR로 남기고, 측정으로 판정할 선택에는 바꿀 조건을 함께 둔다.
   - 어느 선택에 측정 근거가 있는지, 무엇을 만들고 무엇을 설계만 하는지는 architecture §6.1 표에 그대로 적는다. 일부러 쓰지 않은 기술도 같은 절에 둔다.
   - 서비스 분리 효과는 세 구성 비교로 보이고, v1 합격은 목표 절대값으로 판정한다(ADR-0096).
   - 측정 근거가 없는 선택은 문서 근거로만 설명한다는 한계를 영향 칸에 적는다.
6. **장 번호를 요구사항이나 근거로 쓴 칸을 고친다(추천 적용).** 시험 표의 '연결 요구사항'(identity I-T14, payment P-T15, seat-hold S-T11), 인프라·데이터 표의 '근거' 칸(infra §4 admission-ctrl·EKS 워커 노드 풀, data §5 리더 중복 행), design/d1 원칙 4의 장 번호를 정본 ID나 시험 ID로 바꾼다. 문서 머리의 '원문 출처', 제목의 '(원문 N장)', 참고 자료 목록의 장 번호는 원문 위치를 알려 주는 표시라 그대로 둔다.
7. **정본 반영.**
   - docs/architecture.md: §6.1(두 칸, 장 번호, 일부러 쓰지 않은 기술 표), §8.1(OWASP 행과 새 표), §11(0097 행, 작성 예정 과제).
   - planning: planning/01 §5.2, planning/03 §5 문서 쓰기 규칙의 적용 범위 문장.
   - 정본의 칸: docs/features/identity.md I-T14, payment.md P-T15, seat-hold.md S-T11, docs/infra.md §4, docs/data.md §5, design/d1-brief.md §2.
   - 기록: 00-summary §2(문서 지도, 읽는 사람별 표, 부록 문단), review/consistency-review.md §8 원 요구 조건 1, review/open-items.md 5번.
   - 도구: tools/doc-check/check_all.py(허용 목록에 부록 경로, 절 참조 별칭 'appendix'와 부록 제외 줄 삭제).
   - ADR-0004·ADR-0018·ADR-0019·ADR-0021은 상태 줄에만 적는다.

## 검토한 대안

| 대안 | 기각 이유 |
| --- | --- |
| 부록을 두고 끝에 정본 상태 표만 더한다(기술 검토의 처음 추천) | 소유자가 '색인 문서도 최종적으로는 없애는 게 맞다'고 정했다. 상태 표를 두어도 학습 목록을 채운 색인이라는 성격은 그대로다 |
| 부록을 고쳐 정본과 맞춘다 | 313행을 정본에 맞춰 계속 고쳐야 하고, 정본과 같은 내용을 두 곳에 두게 된다 |
| 부록을 archive/로 옮긴다 | 같은 내용이 이미 원문 설계서 §11~13에 있다. archive/는 고치지 않는 원문만 둔다 |
| 약속했던 확인 실험을 일정에 넣는다 | 학습 목록을 채우려던 실험이다. 기각 근거는 문서로 충분하고, 측정 예산(5만 원)과 측정 순서에서 우선순위가 낮다 |
| '일부러 쓰지 않은 기술' 표에 학습 목록 항목(Bigtable 등)도 넣는다 | 고를 후보가 아니었던 기술을 기각했다고 적으면 같은 역효과가 난다 |

## 결과와 트레이드오프

- 면접에서 기술마다 '왜 골랐나, 무엇과 견줬나, 무엇을 만들었나, 무엇으로 재나'를 정본 한 곳(architecture §6.1과 각 ADR)에서 답한다. 측정 근거가 없는 선택도 숨기지 않는다.
- 학습 목록에 끼워 맞추려던 과제(확인 실험 넷, Bigtable 등의 정리)가 일정과 문서에서 빠진다.
- 대가:
  - 원문 학습 매핑(어느 장의 항목을 어디에 썼나)을 새 문서에서 찾을 수 없다. 필요하면 archive/의 원문 §11~13을 본다.
  - 부록에만 있던 영문 용어 199개가 새 문서에서 사라진다. 그래서 원문 대조(`--coverage`)의 '새 문서에 없는 영문 용어' 경고가 5개에서 188개로 늘었다(이 ADR 본문이 그중 몇 이름을 다시 적어 199개보다 적다).
  - ADR 본문과 지난 기록에 지운 경로가 남는다(허용 목록으로 처리).

## 되돌릴 조건

- 학습 목록의 어느 항목을 쓰지 않은 이유를 면접에서 따로 설명해야 할 일이 생기면, 그 항목만 고를 후보였는지부터 보고 ADR로 남긴다. 부록 같은 색인은 다시 만들지 않는다.

## 남는 한계

- 측정 근거가 없는 선택(예: MongoDB, Module Federation, 판매 정책 DSL)은 문서 근거로만 설명한다. 그 가운데 다시 볼 것은 기술 검토의 높음-05~08, 중간-010~026에 있다.
- 위협 모델 문서가 없어 OWASP A06 행은 비어 있는 부분을 그대로 적는다(중간-065).
