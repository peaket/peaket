# ADR-0040: 오픈소스 디자인 시스템 SEED Design을 기반으로 한 UI 토대 구축 및 브랜드 독자 자산 결합

- **상태**: 채택 (2026-10-11 수립, 소유자 선택. 브랜드 결정(design/d1 §3, 추천 적용 2026-10-09)의 서비스명·인디고 브랜드 색·로고는 그대로 유지한다) 2026-10-13 전수 점검(2026-10-14 2차): 맥락의 '00-summary §7 질문 16'은 §7 추가 요청 표의 NOL·SEED 행(번호 없음)이다. 브랜드 역할 중 빠졌던 stroke.brand-solid 덮어쓰기를 tokens.json `border-primary`로 더했다. 2026-10-14: 소유자 결정으로 홈(SCR-001)은 NOL 티켓 메인 화면의 섹션 구성을 따른다(ADR-0063 결정 1, 약관 위험은 소유자가 감수). 시각 토대(SEED)와 브랜드는 그대로이고 NOL의 로고·이미지·문구·색은 쓰지 않는다. 약관 조항은 제23조(이용자의 의무)④ 제15호·제20호다(2026-09-29 시행본, 2026-10-14 원문 확인). 2026-10-26(4차 점검 3부): 결정 4의 라운드 눈금 밖에 홈 배너 슬라이드 전용 20px(`radius.banner`, ADR-0073)을, 결정 5의 최대 폭에 홈 본문 1240px(ADR-0063)을 더했다. 파트너·관제 콘솔의 휴대폰(본문 1열)·태블릿(8열) 배치는 ADR-0061을 따른다(design/d1 §4, design/d2 §1). 2026-10-26: 맥락의 '기능은 Ticketmaster를 본뜨되'는 그때 소유자 요청의 말이다. 지금 문서는 Ticketmaster를 설계 때 참고한 사례로만 적는다(planning/01 §1.4, review R-103). 2026-10-28(기술 검토 중간-096, 소유자 승인 '추천안 동의'): 결정 5의 브레이크포인트 값을 피켓 값(360/768/1024/1440)에서 SEED 값(480/768/1280/1440)으로 바꾼다. SEED 부품의 반응형 속성과 SEED가 미리 만든 CSS의 매체 질의가 SEED 값에서 바뀌어(매체 질의는 CSS 변수로 덮어쓸 수 없다), 이름이 같은 Tailwind 중단점과 360~479·1024~1279px에서 어긋났기 때문이다. 360은 휴대폰 시안 폭으로만 남는다(design/d1 §4, design/tokens.json). 2026-10-28(기술 검토 중간-097·099, 소유자 승인 '추천안 동의'): 결정 1을 이행하는 SEED CSS 싣기(쓰는 부품의 recipe만, 층 판, 층 순서 하나)와 토큰 파일 형식 표기(DTCG 이전 초안의 문자열 값, 이름에 점 없음)를 design/d2 §1에 정했다.
- **관련 문서**: design/d1-brief.md §3·§4, design/d2-design-system.md §1·§2·§5, design/d3-screens.md §0, design/tokens.json, planning/01-overview.md §1·§6, docs/architecture.md §6, wbs 0.6.1·0.6.2
- **관련 ID**: NFR-012, NFR-019, NFR-020, NFR-024, CMP-001~056

## 맥락
- 티켓 예매 플랫폼은 티켓마스터 수준의 고도화된 기능성을 제공하면서도 국내 사용자에게 친숙한 모바일 우선의 세련된 시각 경험을 제공해야 한다.
- 소유자 요청(2026-10-11): 기능은 Ticketmaster를 본뜨되 화면 디자인은 야놀자(NOL) 티켓 스타일로 바꾸고, 토큰 추출 도구로 NOL의 디자인 토큰을 뽑아 기본 스타일로 삼자는 제안이었다. 확인 결과 NOL 서비스 이용약관 제15호(사전 서면 허가 없는 자동화·수동 수집 금지)와 제20호(브랜딩·페이지 레이아웃·디자인의 사용·복제 금지)에 어긋나고 추출 도구의 이용 정책에도 어긋나므로 추출하지 않았다(review R-37, 00-summary §7 질문 16). 소유자가 선택지 B '공개 라이선스 디자인 시스템 기반'을 선택했다(2026-10-11).
- 후보와 확인한 사실(2026-10-11, GitHub API·npm 레지스트리·저장소 원문):

| 후보 | 라이선스 | 상태 | 성격 |
| --- | --- | --- | --- |
| SEED Design(당근) | Apache-2.0. NOTICE가 로고·상호·캐릭터 같은 브랜드 리소스는 상표라 별도 제한 | 저장소 갱신 2026-10-10, `@seed-design/css` 3.0.2·`@seed-design/react` 3.0.0(2026-10-08), 문서 seed-design.io | 모바일 소비자 앱 디자인 언어. 토큰(색·타이포·간격·라운드·그림자·모션)과 컴포넌트 100여 종, 라이트·다크 테마, Tailwind 4 테마 플러그인 |
| Bezier(채널톡) | Apache-2.0 | `@channel.io/bezier-react` 3.6.6 | 업무용 메신저 제품 중심 |
| Montage(원티드) | MIT | 저장소 갱신 2026-10-10 | 채용 서비스 웹 |

- SEED의 성격 중 피켓과 맞는 것: 모바일 우선의 한국어 소비자 제품, 역할 기반 색 토큰과 적응형 팔레트(라이트·다크 값이 다른 팔레트), 4px 간격 스케일, Pretendard를 포함한 글꼴 스택, 접근성 문서(터치 영역 44px, 색만으로 전달 금지, 움직임 축소). 맞지 않는 것: 대비 기준이 WCAG가 아니라 APCA(본문 Lc 75, 그 밖 Lc 60)라서 SEED의 전경색 일부가 WCAG 2.2 AA(최소 4.5:1)에 미달한다. 당근의 브랜드 색(carrot)이 기본 브랜드 역할에 고정되어 있다. 데스크톱 대시보드는 레이아웃 지침만 있고 데이터 테이블·차트 컴포넌트가 없다.

## 결정
1. **토대.** 프론트엔드 UI 컴포넌트 패키지(`@peaket/ds`)의 기초 토대로 `@seed-design/css`의 토큰 체계와 `@seed-design/react` 컴포넌트 라이브러리를 채택한다. 피켓 토큰(design/tokens.json)은 SEED 토큰 값을 옮겨 적고 `$extensions.seed`에 원본 토큰 이름을 남긴다. 값의 출처는 SEED 저장소 `packages/rootage/__generated__`(색 토큰 갱신일 26-06-15)이며, SEED 판이 오르면 같은 경로에서 다시 옮긴다.
2. **브랜드 정체성의 독자화.** 브랜드 역할(`fg.brand`, `bg.brand-solid`, `bg.brand-solid-pressed`, `bg.brand-weak`, `stroke.brand-solid`)은 SEED의 carrot 대신 피켓 고유의 인디고 팔레트로 오버라이드한다. 당근의 로고·상호·캐릭터는 사용하지 않으며 carrot 팔레트도 사용하지 않는다. 휠체어석 자홍은 피켓 확장 팔레트로 남긴다.
3. **웹 접근성 WCAG 2.2 AA 재측정(NFR-020).** SEED의 전경 역할 중 명도 대비 4.5:1에 미달하는 색상 토큰은 한 단계 더 짙은 팔레트로 보정한다. 라이트 테마의 성공·경고·위험 문구색은 SEED 700 대신 800 단계, 포커스 링은 SEED blue-600(2.84:1) 대신 피켓 indigo-500(5.11:1)을 사용한다. 계산표는 design/d2 §5에 둔다.
4. **타이포그래피·간격·라운드·그림자·모션은 SEED 스케일을 그대로 상속한다.** 글자 크기는 SEED t2·t4·t5·t7·t9·t12·t14를 피켓 xs~display에 대응시키고 줄 높이는 같은 번호의 SEED 값을 쓴다. 두께는 regular·medium·bold. 글꼴 스택은 SEED `--seed-font-family`이며 Windows를 위해 Pretendard 가변 서브셋을 자체 호스팅한다(원문 6장 유지). 간격은 SEED dimension(4px 기반)과 의미 간격(global-gutter 16, component-default 12, nav-to-title 20, screen-bottom 56). 라운드 4/8/12/16/24px, 그림자 3단계, 모션 150/200/300ms와 SEED enter·exit·easing 곡선.
5. **레이아웃.** 소비자 웹 콘텐츠 최대 폭 1040px(공연 탐색·좌석맵은 1280px), 데스크톱 거터 24px·여백 32px, 파트너·관제는 SEED 대시보드 레이아웃(중밀도 12열 1040px, 관제 패널은 고밀도 전체 폭). 브레이크포인트 값은 피켓 것(360/768/1024/1440, 추천 적용)을 유지한다.
6. **컴포넌트.** SEED에 있는 표준 UI 요소(버튼, 입력, 선택, 체크박스, 스위치, 탭, 칩, 바텀 시트, 다이얼로그, 경고 다이얼로그, 콜아웃, 스낵바, 배지, 스켈레톤, 상단 내비게이션, 수량 선택, 날짜·시간 선택, 페이지네이션)는 그대로 쓰거나 그 위에 변형만 더한다. 도메인 특화 부품(좌석맵 캔버스, 좌석 리스트, 대기 패널, 카운트다운, 회전 QR, 스캔 결과, 관제 위젯·명령 카드·차트, 데이터 테이블)은 SEED 토큰으로 직접 구축한다. 대응표는 design/d2 §1.1.
7. **배포 의무.** 앱 번들에 SEED를 포함하므로 Apache-2.0 제4조에 따라 라이선스 사본과 NOTICE의 귀속 고지를 제3자 고지 파일에 싣는다(wbs 0.6.2).
8. **레퍼런스 규칙은 그대로.** 다른 회사 사이트의 자동 추출·레이아웃 복제는 하지 않는다(design/d1 §3). SEED를 쓴다는 사실을 당근과의 제휴·보증으로 읽히게 표현하지 않는다(NOTICE).

## 검토한 대안
| 대안 | 기각 사유 및 한계점 |
| --- | --- |
| NOL 화면에서 토큰 추출(타사 상용 사이트 역공학) | 약관 제15호·제20호와 추출 도구의 이용 정책에 어긋나며 지식재산권 분쟁 위험이 크다. |
| 관찰만으로 피켓 고유 값 정의(선택지 A) | 합법이지만 값이 전부 추정이라 시안 전까지 근거가 약하다. 소유자가 B를 선택했다. |
| 처음부터 모든 UI 토큰과 부품을 밑바닥 개발 | 100여 종에 달하는 기초 UI 컴포넌트와 접근성(A11y) 인터랙션을 구축하는 데 막대한 개발 공수가 든다. |
| Bezier·Montage | 업무용 메신저·채용 서비스 중심이라 티켓 소비자 흐름(모바일 상세·바텀 시트·수량 선택)과 거리가 있다. |
| SEED 색을 그대로 쓰고 대비 기준도 APCA로 변경 | NFR-020과 원문 13장이 WCAG 2.2 AA라서 기준을 바꾸면 요구사항을 고쳐야 한다. 색 몇 개를 진하게 바꾸는 쪽이 변경이 작다. |
| SEED의 carrot을 브랜드 색으로 사용 | 당근 제품처럼 보이고 NOTICE의 '오인하게 하는 사용'에 가까워진다. |

## 결과와 트레이드오프
- 얻는 것: 검증된 토큰·컴포넌트 100여 종과 라이트·다크 테마를 바로 쓰고, 디자인 토대의 출처와 라이선스를 문서로 댈 수 있다. 토큰 파이프라인(wbs 0.6.1)은 SEED 토큰 위에 피켓 확장만 얹으면 된다. 독자적인 인디고 브랜딩과 WCAG 2.2 AA 접근성을 양립시킨다.
- 대가
  - 업스트림 SEED 판이 오를 때 토큰 값과 컴포넌트 API를 추적해야 한다. 토큰은 `$extensions.seed` 이름으로 대조하고, 컴포넌트는 Changesets로 묶어 올린다.
  - SEED는 모바일 앱 언어라 파트너·관제의 데이터 테이블·차트는 여전히 피켓이 직접 만든다.
  - 대비 기준 차이로 피켓이 덮어쓴 색이 있어, SEED 컴포넌트의 기본 색과 피켓 문구색이 한 화면에서 다를 수 있다. 문구색은 피켓 토큰만 쓰는 규칙(d2 §1)으로 막는다.
  - 소유자가 처음 원한 '야놀자 느낌'과는 다르다. 모바일 우선·흰 바탕·둥근 카드·바텀 시트 같은 국내 소비자 앱의 공통 패턴은 SEED에도 있다.
- 되돌릴 조건
  - SEED가 라이선스를 바꾸거나 1년 이상 갱신이 멈추면 토큰 값을 피켓 저장소로 복사한 채 컴포넌트만 교체한다.
  - 시안 단계에서 SEED 컴포넌트의 접근성 결함(axe 위반)이 반복되면 해당 컴포넌트만 피켓 구현으로 바꾼다.
