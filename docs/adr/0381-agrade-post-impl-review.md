# ADR-0381: A등급 코드 기능은 구현 뒤에 리뷰를 한다(2026-11-23)

- **상태**: 채택(2026-11-23, 소유자 결정). [ADR-0372](0372-tdd-frozen-tests-no-post-impl-review.md) 결정 3의 '구현 뒤의 리뷰는 하지 않는다'를 A등급 코드 기능에 한해 바꾼다. [ADR-0373](0373-seven-day-completion-scope-and-light-process.md) 결정 3의 A등급 줄에 구현 리뷰를 더한다. ADR-0372의 검증(틀린 구현 검사) 없앰, B·C 기능의 절차(ADR-0373 결정 3), 역할을 서로 다른 에이전트가 맡는 규칙([ADR-0270](0270-independent-agents-per-role-test-first.md) 결정 1)은 그대로다.
- **관련**: [docs/architecture.md](../architecture.md) §8.6, `tools/ci/roles-check.mjs`(자동 검사는 다음 기능), 계획 `docs/review/plans/FIX-agrade-impl-review.md`
- **관련 ID**: 없음(진행 절차만 바꾼다)

## 맥락

- ADR-0372 '결과'는 잃는 점 둘을 적었다. 틀린 구현 검사가 없어 시험이 실제로 결함을 잡는지 구현으로 확인하지 않는다. 구현 코드를 읽는 리뷰가 없어 시험이 덮지 않는 곳(보안 설정, 로그의 개인정보, 성능)의 결함은 구간 마무리(SEG)에서야 잡힌다.
- 돈·좌석·대기 순번에서는 그 잃는 점이 사고로 이어진다. 자기 리뷰가 놓친 높음 결함 23건이 웨이브 6 독립 감사에서 나왔다(ADR-0270 맥락). 시험이 통과하는데 구현이 틀린 결함도 거듭 나왔다(§8.6 4 '자주 놓친 결함'의 BAT-020·BAT-022·BAT-195).
- 2026-11-23 소유자가 네 가지를 골랐다. ① A등급 코드 기능만 구현 뒤 리뷰(구현 리뷰)를 되살리고 B·C 기능은 ADR-0372·ADR-0373 그대로 둔다. ② 까닭은 위의 잃는 점이 A 대상에서는 사고로 이어지기 때문이다. ③ A등급 표시는 계획 커밋 꼬리말(커밋 메시지 끝의 `키: 값` 줄) `Batch-Grade: A`로 하고 기능 표 등급 칸을 자동으로 읽지 않는다. 꼬리말이 없는 진행 중 기능이 갑자기 막히지 않게 하려는 것이다. ④ `roles-check.mjs`의 자동 검사는 이번에 하지 않는다. FIX-roles-tdd가 같은 파일을 고치는 중이라 겹치면 충돌한다. 그 전에는 감독이 합치기 전에 손으로 확인한다.

## 결정

말 풀이: '구현 리뷰'는 구현이 고정된 시험을 통과한 뒤, 구현을 맡지 않은 리뷰 담당이 구현 코드의 바뀐 부분을 읽고 결함을 찾는 일이다. '시험 리뷰'는 ADR-0372 결정 2의 구현 전 리뷰다.

### 1. 대상과 차례

- 대상은 A등급 코드 기능뿐이다. A등급 표시는 계획 커밋 꼬리말 `Batch-Grade: A`다.
- 기능 표(`docs/BUILD_ORDER.md` '기능 단위 계획')의 등급이 A인 코드 기능과, 장부 범위에 A등급 대상(§8.6 3의 표) 항목이 든 기능은 계획 커밋에 `Batch-Grade: A`를 꼭 단다. 빠졌으면 합치지 않고 계획 커밋을 더해 단다(결정 9의 손 확인). 기능 표 밖의 고침은 꼬리말로만 정한다. 도구는 기능 표 등급 칸을 읽지 않는다(소유자 결정 ③).
- B·C 기능은 ADR-0372·ADR-0373 그대로다.
- A등급 코드 기능은 **계획 → 시험 → 시험 리뷰 → (지적 반영) → 시험 고정 → 구현 → 구현 리뷰 → (지적 반영) → 고친 곳 다시 보기 → 게이트 → 기록·합치기**로 한다.
- 구현 리뷰는 구현 담당이 고정된 시험을 모두 통과시키고 계획 파일 '시험 결과' 절을 적은 뒤에 시작한다. 시험이 실패하는 구현은 리뷰하지 않는다.
- 게이트(§8.6 4의 8)는 구현 리뷰의 지적 반영이 끝난 뒤 한 번만 돈다. 합치기 직전의 통합 시험 전체를 두 번 돌리지 않으려는 것이다.
- 한 바퀴만 돈다. 지적을 고친 뒤 리뷰 담당은 고친 곳만 다시 본다(시험 리뷰와 같다).
- 정방향 기능(`Batch-Order: impl-first`)이 A등급이면 이미 시험이 있으므로 같은 차례로 구현 리뷰를 한다. 시험만 기능(`Batch-Kind: test-only`)과 문서 기능에는 `Batch-Grade`를 달지 않는다. 구현이 없기 때문이다.

### 2. 리뷰 담당이 받는 것과 받지 않는 것

- 받는 것: 구현의 바뀐 부분(`git diff <시험 고정 커밋>..<구현 끝 커밋>`. 시험 고정 커밋은 구현 전 마지막 시험 리뷰 커밋이다. 고정된 시험 파일은 읽기만 한다), 지시서, 계획 파일 전체(시험 리뷰 절·'실패 확인'·'시험 결과' 포함), 장부(`node tools/ci/ledger.mjs --batch <기능>`), 지시서가 가리킨 정본(`docs/` 아래 명세 문서)의 줄 범위, 그 기능의 ASVS 추적 표(보안 검증 기준 ASVS의 요구마다 적용 여부와 근거를 적은 표, `docs/security/asvs/<기능>.md`).
- 받지 않는 것: 구현 담당의 설명·보고·대화, 감독이 요약한 코드 설명. 담당끼리는 파일로만 넘긴다(§8.6 '역할 나누기').
- 할 수 있는 것: 읽기, 이미 있는 시험과 읽기 전용 명령(시험 실행, 쿼리 계획 보기 등)을 돌리기.
- 하지 않는 것: 코드·시험·정본을 고치지 않는다. 바꾸는 파일은 계획 파일 '리뷰' 절의 '구현 리뷰' 하위 절과 담당 표의 자기 줄뿐이다. 틀린 구현을 넣어 보는 검사(옛 검증)는 하지 않는다. ADR-0372 결정 3의 검증 없앰은 그대로다.
- 구현 리뷰 담당은 같은 기능의 시험 리뷰 담당과 다른 새 세션으로 띄운다. 시험 리뷰의 결론에 끌려가지 않게 하려는 것이다. 모델과 생각 강도는 §8.6 '읽는 양 줄이기'를 따른다.

### 3. 결과를 적는 계획 파일 절

- A등급 코드 기능의 계획 파일은 `## 리뷰` 절 아래에 하위 절 `### 시험 리뷰`와 `### 구현 리뷰`를 둔다. 따로 `## 구현 리뷰` 절을 두지 않는다. 지금 `roles-check.mjs`는 리뷰 커밋이 '리뷰' 절(하위 제목 포함)을 바꿔야 리뷰 커밋으로 세므로, 하위 절이면 지금 도구로도 센다.
- 지적 번호는 시험 리뷰가 `RV-NN`, 구현 리뷰가 `IR-NN`이다. 리뷰 반영 커밋의 `Finding:` 값과 재현 시험 이름(예 `F-07-8 IR-01 ①`)에 그대로 쓴다.
- '구현 리뷰' 하위 절에는 지적 표(번호·등급(높음·중간·낮음)·종류(보안·통과 기준·그 밖)·자리(파일:줄)·내용·정본 근거), '확인했으나 문제 없음' 목록(결정 5의 관점마다 한 줄), '판정'(합쳐도 되는지 한 줄), 지적 반영 뒤의 '다시 보기'(고친 곳만)를 둔다.

### 4. 커밋 역할과 꼬리말

- 구현 리뷰 커밋도 `Role: review`다. 새 역할 값을 만들지 않는다. 지금 `roles-check.mjs`는 역할 목록 밖의 `Role` 값을 실패로 잡는다.
- 시험 리뷰와 구현 리뷰는 꼬리말 `Review-Of: test|impl`로 가른다. 리뷰 커밋에만, 한 커밋에 하나, 값은 소문자 그대로 단다. `Batch-Grade: A` 기능의 리뷰 커밋에는 꼭 달고, 그 밖의 기능에는 달지 않는다.
- `Batch-Grade: A`는 계획 커밋에만, 한 커밋에 하나, 값은 대문자 `A` 그대로 단다(`Batch-Order`·`Batch-Kind`와 같은 방식). B·C 값은 두지 않는다. 꼬리말이 없으면 A가 아닌 것으로 본다.
- 두 꼬리말은 꼬리말 덩이에서 `Role` 바로 뒤에 둔다(예 `Role: review` 다음 줄 `Review-Of: impl`).
- 지금 `roles-check.mjs`는 모르는 꼬리말 키를 읽지 않고 넘어가므로(`readTrailers`, 2026-11-23 확인) 두 꼬리말을 달아도 지금 검사가 깨지지 않는다.

### 5. 구현 리뷰가 보는 것

정본 값은 옮겨 적지 않고 자리만 가리킨다. 리뷰 담당은 관점마다 지적이나 '확인했으나 문제 없음' 한 줄을 남긴다.

1. **판정 기준과 구현의 대조**: 장부 범위 항목마다 정본 판정 기준을 구현이 실제로 지키는지 본다. 시험이 값을 덜 단언해 통과해도 구현이 틀릴 수 있는 곳을 먼저 본다.
2. **A 대상 불변식**(늘 참이어야 하는 조건): §8.6 3 위험 등급 표의 A 행과 그 기능 장부 범위의 정본. 같은 좌석이 두 사람에게 팔리는 오버셀, 이중 결제, 대기 순번의 건너뜀·겹침이 생길 길이 있는지, 시험 뒤 불변식 검사 도구 `services/invariant-checker`가 세는 항목과 어긋나지 않는지 본다.
3. **동시 실행·되돌림·장애 경로**: §8.7 실패 목록 셋(경합은 `docs/data.md` §5, 외부 호출은 `docs/api/guidelines.md` §8·§8.1·§5, 자원 한도는 `docs/verification.md` §4·§4.1)의 동작을 구현이 따르는지, 트랜잭션(여러 변경을 한꺼번에 반영하거나 한꺼번에 취소하는 DB 작업 단위) 경계와 Outbox(보낼 이벤트를 같은 트랜잭션으로 DB 표에 먼저 적어 두고 나중에 보내는 방식) 쓰기가 한 트랜잭션인지, 되돌림이 건드린 키·행을 모두 되돌리는지 본다.
4. **멱등**(같은 요청이 여러 번 와도 한 번 처리한 것과 결과가 같은 성질): `docs/api/guidelines.md` §4와 그 기능 정본. 재시도·중복 이벤트·순서가 바뀐 이벤트에서 결과가 같은지 본다.
5. **시험이 덮지 않는 곳**: 보안 설정(§8.3, 그 기능 ASVS 추적 표의 적용 행), 로그·오류 응답의 개인정보(`docs/planning/03-policies-glossary.md` §1.2 POL-023 개인정보 처리 표), 쿼리·Lua(Redis 안에서 다른 요청이 끼어들지 못하게 한 번에 도는 짧은 스크립트) 성능(인덱스, 한 요청의 쿼리 수, Lua가 훑는 키 수. Lua·빠른 경로를 바꿨으면 §8.6 4의 7 비교).
6. **'자주 놓친 결함'**(§8.6 4): 목록의 모양마다 이 구현에 해당하는지 본다. 특히 겹친 가드, 부르는 쪽이 판정 결과를 실제로 쓰는지, 시간 한도·상수, 시작 파일 조립.

### 6. 지적 처리

- 그 기능에서 고치는 것은 높음·보안·통과 기준(판정 기준을 어김) 지적뿐이다(ADR-0331 결정 5). 중간·낮음 지적은 갈래 정리 목록(`docs/lanes/lane<N>-cleanup.md`)에 한 줄씩 넘긴다.
- 고치는 차례는 버그와 같다(§8.6 5, ADR-0372 결정 3). 시험 담당이 재현 시험을 먼저 쓰고 실패를 본다(`Role: review-fix`, `Fix-By: test`, `Finding: IR-NN`) → 시험 리뷰 담당이 그 재현 시험만 짧게 본다(`Role: review`, `Review-Of: test`) → 구현 담당이 고친다(`Role: review-fix`, `Fix-By: impl`, `Finding: IR-NN`) → 구현 리뷰 담당이 고친 곳만 다시 본다(`Role: review`, `Review-Of: impl`).
- 시험으로 재현할 수 없는 지적(설정 값, 쿼리 계획, 로그 문구처럼 시험이 단언하기 어려운 것)은 구현 리뷰 담당이 계획 파일 '구현 리뷰' 하위 절의 그 지적에 '시험 없음'과 까닭 한 줄을 적는다. 구현 담당은 리뷰 반영 커밋(`Role: review-fix`, `Fix-By: impl`)이 아니라 구현 커밋(`Role: impl`)으로 바로 고치고, 커밋 본문에 `IR-NN 시험 없음: <까닭>`을 적는다. 지금 `roles-check.mjs`의 '리뷰 반영은 지적마다 시험 먼저' 규칙에 걸리지 않게 하려는 것이다. 감독은 기록 커밋 본문에 예외로 적는다. 시험으로 재현할 수 있으면 이 예외를 쓰지 않는다.
- 다시 보기에서 새 높음·보안·통과 기준 지적이 나오면 같은 차례를 한 번 더 한다. 세 바퀴째가 필요하면 감독이 멈추고 소유자에게 묻는다.

### 7. 진행 중인 A 기능에 쓰는 때

- 이 결정은 이 문서 기능이 `develop`에 합쳐진 때부터 쓴다.
- 새로 시작하는 A등급 코드 기능은 첫 계획 커밋에 `Batch-Grade: A`를 단다.
- 이미 시작했지만 아직 `develop`에 합치지 않은 A등급 코드 기능(구현 전·구현 중·구현 끝 모두)은 합치기 전에 구현 리뷰를 한다. 그 기능의 계획 담당(같은 역할이면 새 세션도 된다)이 계획 커밋 하나를 더한다. 새 세션이면 계획 파일 담당 표에 그 세션의 plan 줄을 더한다. 그 커밋은 계획 파일 '리뷰' 절에 `### 시험 리뷰`(이미 있는 시험 리뷰 내용을 그 아래로 옮긴다)와 `### 구현 리뷰`('구현 리뷰 담당이 채운다' 한 줄)를 두고, 꼬리말 `Batch-Grade: A`를 단다.
- 이미 한 시험 리뷰 커밋에 `Review-Of`를 소급해 달지 않는다(커밋을 고쳐 쓰지 않는다). 그 뒤의 리뷰 커밋부터 단다.
- `Batch-Order`와 달리 `Batch-Grade`는 구현 뒤의 계획 커밋에 달아도 된다. 일을 늦게 무겁게 하는 표시라 차례를 피하는 데 쓸 수 없기 때문이다.
- 이미 `develop`에 합친 A 기능은 소급해 구현 리뷰를 하지 않는다. 구간 마무리의 관점별 새 맥락 리뷰(§8.6 4의 5)가 맡는다.

### 8. 완성 기간(ADR-0373)과의 관계

- 2026-11-23~12-03 동안에도 A등급 코드 기능은 구현 리뷰를 한다. ADR-0373 결정 3의 A등급 줄에 구현 리뷰가 더해진다. B·C 기능과 분석 적재 빠른 길은 그대로다.
- 완성 기간에 구현 리뷰 때문에 A 기능의 합치기를 막는 것은 셋이다: 등급 꼬리말(결정 1)이 빠짐, 구현 리뷰가 없음, 높음·보안·통과 기준 지적이 열려 있음. 등급 꼬리말 확인은 '구현 리뷰가 없음'을 가리지 않으려는 것이다.
- 손 확인 항목 가운데 꼬리말 꼴, 세션, 담당 표, 계획 파일 절은 `roles-check.mjs`가 기간 중에도 막는 종류라 손 확인에서도 기간 중에 막는다. 기간 중 기록 커밋 본문에 적기만 하는 것은 `roles-check.mjs`가 보지 않는 ADR-0381만의 항목(구현 리뷰 커밋의 차례, `IR-NN` 지적의 시험 먼저 처리)뿐이다. 2026-12-04부터는 손 확인 항목을 모두 막는다.
- 넷째 날(2026-11-26)의 빼는 차례(ADR-0373 결정 4)는 그대로다. 기한이 모자라도 감독이 구현 리뷰를 빼지 않고, 빼야 하면 소유자에게 묻는다. `roles-check.mjs`의 차례·구성 실패가 합치기를 막지 않는 것은 완성 기간뿐이다(ADR-0373 결정 3).

### 9. 역할 확인

- 구현 리뷰의 자동 검사(`roles-check.mjs`)는 FIX-roles-tdd를 `develop`에 합친 뒤의 다음 기능으로 한다. 같은 `tools/ci/roles-check.mjs`·`roles-check.test.mjs`를 고치므로 먼저 하면 충돌한다.
- 그 전에는 감독이 A등급 코드 기능을 합치기 전에 손으로 보고 기록 커밋 본문에 적는다. 어긴 항목은 결정 8대로 다룬다. 완성 기간에는 결정 8이 기록만 한다고 정한 항목(구현 리뷰 커밋의 차례, `IR-NN` 지적의 시험 먼저 처리)만 어겨도 기록에 적고 합치며, 나머지는 하나라도 어기면 합치지 않는다. 2026-12-04부터는 모두 막는다. 보는 항목은 §8.6 '역할 나누기'의 '합치기 전 역할 확인'에 둔다.
- 자동 검사가 생기면 손 확인 항목 가운데 도구가 보는 것을 지우고, 도구가 보지 않는 것(지적 등급 판단, 정리 목록 넘김, '시험 없음' 예외)만 남긴다.

## 결과

- 좋아지는 점: A 기능의 구현 결함이 합치기 전에 걸러진다. 시험이 덮지 않는 보안 설정·로그의 개인정보·성능 문제가 구간 마무리 전에 보인다.
- 잃는 점: A 기능마다 리뷰 대기 한 번과 지적 반영 한 바퀴가 늘어, 완성 기간의 A 기능 일정이 길어진다. 자동 검사가 생기기 전에는 감독의 손 확인에 기댄다. 틀린 구현 검사는 여전히 없어, 시험이 결함을 잡는지 구현으로 확인하지 않는다.

## 고른 안과 버린 안

- (고름) A등급 코드 기능만 구현 리뷰를 하고, 계획 커밋 꼬리말로 표시하며, 자동 검사는 다음 기능으로 한다.
- (버림) 모든 코드 기능에 구현 리뷰를 되살린다: 소유자가 A등급만 골랐다.
- (버림) 기능 표 등급 칸을 도구가 자동으로 읽는다: 꼬리말이 없는 진행 중 기능이 갑자기 막힌다.
- (버림) 이번에 `roles-check.mjs`도 고친다: FIX-roles-tdd와 같은 파일이라 충돌한다.
- (버림) 새 역할 값 `impl-review`: 지금 도구가 목록 밖의 역할을 실패로 잡는다.
