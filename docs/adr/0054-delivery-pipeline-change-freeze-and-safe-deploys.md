## 맥락

- DevOps 설계는 infra §3(환경 4종)·§5(프리워밍과 배포 동결)·§7(CI/CD 그림 한 장과 규칙 다섯 줄)·§8(무중단 배포 원칙)·§9(공급망 한 줄)·§10(런북 목록), observability(SLO·경보·Game Day), ADR-0016(저장소)·0031(환경과 리전 장애)·0032(온콜 도구)에 흩어져 있었다. '무엇을 쓰는가'(GitHub Actions, ArgoCD, Argo Rollouts, Kyverno, Terraform, Karpenter)는 정해져 있었지만 '어떻게 바꾸고 내보내고 되돌리는가'는 없었다.
- **그대로 구현하면 사고로 이어지는 결함 7건**
  1. 배포 동결이 ArgoCD 동기화 창(고정 크론)으로만 적혀 있는데 오픈 시각은 공연마다 다르다. 창을 누가 만드는지 없었다. 또 창이 T-10분에 시작하므로 그 전에 시작한 카나리(분석 수십 분)가 오픈 뒤에도 진행된다. T-30분 점검에 '진행 중 배포 없음'이 없다.
  2. 배포가 아닌 변경이 동결을 우회한다. 관리형 서비스 유지보수 창(서울 기본값: Aurora는 22:00~06:00(KST) 안 임의 30분, ElastiCache는 21:00~05:00 안 임의 60분이라 저녁 오픈과 겹칠 수 있다), Karpenter의 노드 통합·교체·만료, 비밀 자동 교체, 인스턴스 교체가 따르는 Terraform 변경, 클러스터 애드온 갱신, 기능 공개 설정이 POL-028 '배포 금지'에 들어가지 않는다.
  3. admission-ctrl(활성 리더 1)과 realtime-gw(WebSocket)는 트래픽 비율 카나리로 배포할 수 없다. 리더 교체 횟수와 재연결 폭주 대책이 없다. Argo Rollouts에는 리더 선출 워크로드에 대한 안내가 없고, 트래픽 라우팅이 없으면 비율을 복제본 수로 근사한다(2026-10-13 문서·소스 확인).
  4. 프론트엔드 배포가 없다. Next.js 앱 서버가 배포 구성도에 없고, 옛 정적 자산 보존(버전 불일치), 여러 파드의 캐시 공유, 관제 콘솔 MF 원격의 버전, 지갑·스캐너 PWA의 갱신 시점이 정해지지 않았다. 스캐너가 입장 시간에 새 서비스 워커로 바뀌면 오프라인 판정 코드가 입장 도중 바뀐다.
  5. DB 마이그레이션 규칙이 없다. 카나리와 되돌리기 동안 두 버전이 같은 DB를 쓰므로 N-1 호환(확장·축소)이 필요한데 규칙이 없었다. Drizzle 마이그레이터는 대기 중인 마이그레이션 전부를 한 트랜잭션으로 실행하고(0.45 계열·1.0 RC 소스 확인), PostgreSQL은 `CREATE INDEX CONCURRENTLY`를 트랜잭션 블록 안에서 실행하지 못한다. 잠금 대기 제한, 백필, 실행 주체·시점도 없었다.
  6. Redis Lua 스크립트와 키 형식, Kafka 이벤트 스키마의 배포 순서, Flink 상태의 버전 호환 규칙이 없다(Avro BACKWARD만 있었다).
  7. 되돌리기 규칙이 없다. '자동 롤백'만 있고, 동결 중 되돌리기 허용 여부와 승인, ArgoCD 동기화 창이 수동 동기화와 롤백까지 막는다는 사실(소스 확인)이 반영되지 않았다.
- **상세 설계 공백 12건**: 저장소 유형별 CI 단계와 필수 검사(보안 검사 게이트는 Phase 3 3.6.1에 있어 Phase 0~2 코드가 검사 없이 쌓인다), GitOps 저장소 구조와 환경 승격 흐름(그림에는 'Renovate·Changesets가 매니페스트를 갱신'한다고 적혀 있는데 Changesets는 패키지 버전 도구다), 공급망(출처 증명, 액션 고정, 토큰 최소 권한, 취약점 조치 기한(ASVS 15.1.1 L1), 새 패키지 대기, 서명 검증 조건), 설정·기능 플래그의 구분, IaC 저장소 구조·상태 분리·계정 구조·드리프트 점검, 사람의 운영 접근(SSO·긴급 접근·운영 DB 직접 접근), 플랫폼 수명주기(EKS 지원 기간, 노드·애드온 갱신), 비용 가드레일(예산 경보, 측정 환경 자동 삭제 보장), DORA 5종의 산출 방법, 배포·마이그레이션·비밀 유출·CI 장애 런북과 Game Day, 문서 저장소와 공용 워크플로 저장소(wbs 0.1.3은 '문서 리포'를 말하지만 리포 12개에 없다), 저장소 공개 범위.
- **문서 간 어긋남 2건**: ① infra §3의 상시 데모 환경(AWS 단일 AZ 최소 구성)은 노드·DB를 빼고도 EKS 제어 평면(시간당 0.10달러)·NAT 게이트웨이(0.059달러)·NLB(0.0225달러)만으로 월 약 133달러(730시간, 1,400원/달러 가정 약 18.6만 원)라, 소유자 지출 상한(2026-10-10 '최대 5만 원')을 약 8일 만에 넘는다(서울 리전 가격 목록 2026-10-13 조회). 이 ADR은 환경 호스팅을 정하지 않고 질문 24로 올린다. ② infra §9는 서비스 권한을 IRSA로 적었는데 AWS는 리눅스 EC2 노드에서 EKS Pod Identity를 권한다(문서 확인).
- **외부 원문 확인(2026-10-13 열람, docs/devops.md §16)**
  - 실천 근거: DORA 지표 가이드(2026-01-05 갱신)와 역량 문서(작은 묶음, 트렁크 기반 개발, CI 피드백 상한 약 10분, 배포 자동화, DB 변경 관리, 변경 승인 간소화: 외부 승인 위원회는 성과를 낮추고 변경 실패율을 낮추지 않는다), SRE Book 8장(밀폐 빌드, 정책 강제)·SRE Workbook 16장(카나리: 대조군 비교, 한 번에 하나, SLI 상위 지표, 4xx 제외, 집계 간격 ≤ 카나리 시간, 평시 카나리는 부하 결함을 놓칠 수 있음), OpenGitOps 1.0.0 네 원칙, Martin Fowler 'ParallelChange', AWS Well-Architected 운영 우수성 OPS05-BP08~10·OPS06-BP01~04.
  - 제품 사실: ArgoCD 동기화 창(deny가 allow보다 우선, 수동 동기화·롤백도 막음, `manualSync`만 수동 예외, 자동 동기화 앱의 롤백 API 거부), Argo Rollouts(분석 실패 시 중단, `abort`는 상태만 바꿈, `rollbackWindow`는 v1.4부터 창 안 되돌리기의 단계·분석 생략, Gateway API 트래픽 플러그인은 argoproj-labs 0.x이고 Envoy Gateway 조합 시험됨·미러링 단계는 무시), Karpenter(중단 예산은 자발적 중단만 막고 만료는 막지 못함, `expireAfter: Never` 허용, 예산 크론은 UTC), Kyverno(ClusterPolicy는 v1.19에서 폐기 예정·v1.20 제거 예정, 후속은 CEL 기반 ImageValidatingPolicy), Next.js `deploymentId`(버전 차이면 전체 새로고침, 배포별 라우팅은 하지 않음), 쿠버네티스 종료 흐름(종료와 엔드포인트 제거가 동시, preStop `sleep` 1.34 GA), GitHub 요금 등급(무료 등급 비공개 저장소에는 브랜치 보호·규칙 세트·환경이 없고 출처 증명은 Enterprise Cloud), 출처 증명(기본 SLSA Build L2, 공용 재사용 워크플로로 L3), SLSA 1.2, 액션 SHA 고정 정책(2025-08-15), tj-actions 탈취(CVE-2025-30066)·Trivy 액션 탈취(CVE-2026-33634, 2026-03-19), Sigstore(Rekor 공용 인스턴스 가용성 목표 99.5%), Drizzle 단일 트랜잭션 마이그레이션, Squawk 규칙, PostgreSQL `lock_timeout`·`NOT VALID`, Aurora·ElastiCache·MSK 유지보수(MSK는 창을 고를 수 없고 브로커를 하나씩 재시작하며 최대 약 2분 동안 p99 최대 약 2초), EKS 지원 기간(표준 14개월, 연장 지원 시간당 0.60달러), Terraform S3 잠금 파일(1.10 도입·1.11 정식), Linkerd(2.15부터 오픈소스 안정판 아티팩트 없음), Next.js 여러 인스턴스의 캐시(공유 `cacheHandler`·`cacheHandlers`가 필요하고 `revalidateTag()`는 부른 인스턴스만 무효화하므로 처리기가 `refreshTags()`로 공유 상태를 읽어야 함), Confluent Schema Registry(BACKWARD는 직전 판만 대조하고 소비자를 먼저 올림), kafkajs(마지막 릴리스 2023-02-27, 협력적 재조정 없음), pnpm(v10부터 의존성 설치 스크립트 기본 차단, `minimumReleaseAge`는 v10.16 도입·분 단위), CISA의 npm 웜 경보(2025-09-23), Valkey 스크립트 캐시(장애 조치 뒤 NOSCRIPT), NLB 대상 등록 해제 지연(기본 300초), WebSocket 닫기 코드 1012(IANA 등록).

## 결정

1. **원칙.** 변경은 작게 자주, 같은 산출물로, 선언형으로 내보낸다. 사람 승인 대신 자동 검사와 동료 검토로 통제하고, 배포와 공개를 나누며(릴리스 플래그), 온세일 중에는 운영 변경을 멈춘다. 코드 병합은 멈추지 않는다(트렁크는 늘 열림).
2. **저장소.** 리포를 12개에서 14개로 늘린다: `peaket-docs`(이 문서 묶음, 문서 점검 CI)와 조직 공용 `.github`(재사용 워크플로). 공개 저장소를 기본으로 하고, 합성 봇 시뮬레이터가 있는 `peaket-loadtest`만 비공개로 둔다(POL-026). 봇 탐지 임계값·가중치는 코드가 아니라 비공개 설정으로 둔다. 근거는 무료 등급에서 공개 저장소만 브랜치 보호·규칙 세트·환경 보호 규칙·코드 스캐닝·출처 증명을 쓸 수 있고 호스트 러너 사용이 무료라는 점이다. GitHub 조직 설정(규칙 세트, 환경, 액션 허용 목록, 토큰 기본 권한)은 Terraform으로 관리한다.
3. **CI.** 모든 저장소는 `.github`의 재사용 워크플로를 호출한다. 트렁크 기반(작업 가지는 몇 시간~1일), 스쿼시 병합, Conventional Commits 1.0.0, 라이브러리는 SemVer 2.0.0, 서비스는 커밋 SHA와 이미지 다이제스트로 식별한다. PR 검사는 10분 안 [가정, 0.1.2에서 측정]. 보안 검사 게이트(gitleaks CLI, Semgrep, 공개 저장소 CodeQL, 의존성·이미지·IaC 검사)를 Phase 0으로 앞당긴다(wbs 0.1.4). gitleaks는 MIT인 CLI를 쓴다(공식 액션 v2 이후는 독자 사용권이고 조직 저장소에 사용권 키가 필요).
4. **공급망.** 이미지마다 CycloneDX SBOM, cosign 키 없는 서명, SLSA 출처 증명(공용 재사용 워크플로로 빌드해 Build L3 목표)을 만든다. 서드파티 액션은 전체 SHA로 고정하고 허용 목록만 쓴다. 워크플로 토큰은 읽기 전용이 기본이다. 새 패키지 버전은 3일 [가정] 기다려 받는다. 취약점 조치 기한은 치명 7일, 높음 30일, 중간 90일, 낮음은 분기 정기 갱신이고, 수정본이 없으면 만료 30일의 예외 기록을 둔다(ASVS 15.1.1·15.2.1, POL-041). 클러스터 입장 검증은 Kyverno CEL 정책(ImageValidatingPolicy)으로 서명 신원과 출처 증명을 확인하되, 검증이 공용 투명성 로그의 가용성에 묶여 온세일 확장을 막지 않게 하는 방법(서명 묶음의 오프라인 확인 또는 검증 캐시)을 PoC로 정한다(wbs 0.4.4). PoC가 실패하면 승격 단계 검증과 승격된 다이제스트 허용 목록으로 바꾼다.
5. **환경과 승격.** 한 번 만든 다이제스트만 승격한다. main 병합 → 이미지 빌드·서명 → GitOps 저장소에 승격 PR(데모 자동 병합) → ArgoCD 동기화 → 카나리 분석 → 배포 기록. 운영 승격은 데모 카나리 통과·데모 체류 1시간 [가정]·운영 28일 오류 예산 잔여·동결 창 밖·조치 기한 초과 없음을 필수 검사로 확인한다. 한 환경에서 동시에 진행하는 카나리는 하나다. 상시 데모의 호스팅은 질문 24에서 정하고, 승격 흐름은 호스팅과 무관하다.
6. **설정 세 종류.** 정적 설정은 배포로, 운영 매개변수는 관제 명령(감사·승인)으로, 릴리스 플래그는 GitOps 파일과 OpenFeature(flagd 파일 모드, 프로세스 안 평가)로 바꾼다. 운영 중 바꿔야 하는 값은 관제 명령으로 만들고 플래그를 운영 스위치로 쓰지 않는다. 플래그는 소유자와 만료일이 있고 100% 공개 뒤 30일 [가정] 안에 지운다.
7. **워크로드별 배포 전략**(docs/devops.md §6.1 표). 게이트웨이 뒤 무상태 서비스는 Gateway API 경로 가중치 카나리(5% → 25% → 50% → 100%, 단계마다 5분 분석, 상한 40분 [가정, 4.6.2에서 확정])이고, 플러그인이 맞지 않으면 복제본 비율 카나리로 대신한다. 분석은 카나리와 안정판의 서버 오류 비율·p99·포화·불변식 위반 0건과 절대 SLO를 본다. admission-ctrl은 리더 인지 롤링(종료 때 Lease를 바로 놓음)이고, 알고리즘 변경은 Lease에 참여하지 않는 그림자 계산으로 먼저 본다. realtime-gw는 한 파드씩 롤링하며 닫기 코드 1012와 무작위 지연 재연결로 비운다. Kafka는 BACKWARD 호환이므로 소비자를 먼저 배포한다. Flink는 세이브포인트 업그레이드다. 프론트엔드 정적 자산은 배포별 경로에 추가만 하고 30일 [가정] 보존하며, `deploymentId`는 커밋 SHA다. 스캐너 PWA는 근무 준비 때만 새 버전을 적용하고 입장 시간에는 보류한다.
8. **되돌리기.** 카나리 중이면 `abort`, 완료된 배포는 Git 되돌리기와 `rollbackWindow`(최근 3개 리비전 [가정]) 빠른 복귀다. 스키마는 되돌리지 않고 앱만 되돌린다(N-1 호환이 전제). 결정부터 이전 버전 100%까지 5분 이내를 목표로 한다 [가정, Game Day G-18에서 확정].
9. **데이터 변경.** 앞으로만 간다(운영에 down 마이그레이션 없음). 모든 스키마 변경은 실행 중 버전(N-1)과 새 버전(N)에 함께 맞아야 하고, 호환되지 않는 변경은 확장 → 이전 → 축소로 배포 2회 이상에 나눈다. 마이그레이션은 서비스 이미지의 별도 명령으로 ArgoCD PreSync 잡에서 돌고, 자체 실행기가 Drizzle이 만든 SQL 파일을 읽어 표시된 파일만 트랜잭션 밖에서 실행한다. 문장마다 `lock_timeout` 3초 [가정]와 재시도, 실행 잠금(advisory lock), DDL·DML 역할 분리, Squawk 검사, 직전 스키마·N-1 시험을 둔다. 무거운 변경과 백필은 정비 시간에 한다. Redis 키·Lua는 의미를 제자리에서 바꾸지 않고 새 키로 확장·축소한다.
10. **변경 동결 창(POL-028 확장).** 대형·중형 온세일(architecture §9.5의 규모 구분)은 T-90분부터 T+60분까지 모든 운영 변경(앱·게이트웨이·엣지 함수·설정·릴리스 플래그·DB·인프라·애드온·노드 자발 교체·키 정기 교체)을 시작하지 않고, T-45분에 끝나지 않은 롤아웃을 자동 중단하며, T-30분 점검에서 진행 중 변경 0건을 필수로 확인한다. 소형 온세일은 핫패스 묶음(gw-queue, gw-fan, queue-svc, admission-ctrl, purchase-svc, payment-svc, realtime-gw, identity-svc, 소비자 웹 앱 서버, 엣지 함수)과 핫패스 노드 풀만 T-50분부터 T+60분까지 막고 T-15분에 자동 중단한다. 시작 금지 시각은 '진행 중 변경 0건 시점 − 카나리 상한 40분 − 여유'로 정했다.
11. **변경 동결 달력.** `freeze-calendar`(플랫폼 네임스페이스의 CronJob)가 ops-svc의 승인된 회차·오픈 시각·규모 등급을 10분마다 읽어 앞으로 7일의 창을 GitOps 저장소 `calendar/freeze.json`에 봇 PR로 쓰고, 이 파일에서 ArgoCD AppProject deny 창(`manualSync: true`)과 Karpenter NodePool 중단 예산(`nodes: "0"`, UTC 크론)을 렌더링한다. 같은 이미지의 가드 루프가 1분마다 자동 중단을 집행한다. ops-svc를 읽지 못하면 파일을 바꾸지 않고(이미 걸린 7일 창 유지), 30분 넘게 갱신되지 않으면 SEV2, 2시간 넘게 낡으면 운영 승격을 막는다(닫힘 실패). 운영 수동 동기화 권한은 commander만 가진다.
12. **정비 시간과 관리형 유지보수.** 정비 시간은 매일 04:00~06:00(KST) [가정, Phase 4 운영 리허설에서 확정]이다. 무거운 DB 변경, 장애 조치를 부르는 인프라 교체, 노드 이미지 교체(Karpenter drift는 그 밖의 시간에 중단 예산 0), 애드온·EKS 올리기, 비밀 자동 교체를 여기서 한다. Aurora·ElastiCache 유지보수 창은 기본값으로 두지 않고 수요일 04:00(KST)부터 지정한다. 오픈 시각이 수요일 03:00~06:30(KST)에 걸리면 오픈 간격 규칙 검사와 같은 자리에서 막는다. MSK는 창을 고를 수 없어 AWS Health 예정 이벤트를 구독하고 브로커 CPU 60% 이하 권고를 따르며 남는 위험을 기록한다. 핫패스 노드 풀은 `expireAfter: Never`로 강제 만료를 끄고 drift로만 바꾼다.
13. **긴급 변경.** 동결 창 안에서는 진행 중 카나리 중단(자동), 이전 다이제스트로 되돌리기, 릴리스 플래그 끄기, 관제 명령만 허용한다. 새 코드(핫픽스)·스키마·인프라 변경은 창이 끝난 뒤 한다. 되돌리기 PR에는 `emergency-change` 라벨과 인시던트 번호가 있어야 동결 게이트를 지나고, commander가 수동 동기화하며, 포스트모템이 필수다(RB-23).
14. **인프라 코드.** `peaket-infra`는 모듈과 '계정/환경/구성 요소'별 스택으로 나누고, 상태는 S3 백엔드에 구성 요소마다 따로 두며 S3 잠금 파일(`use_lockfile`)을 쓴다. AWS Organizations 3계정(관리, 비운영, 운영)과 조직 정책(허용 리전 밖 거부, 루트 사용 거부, 감사 끄기 거부)을 둔다. PR마다 plan·IaC 보안 검사·비용 차이를 붙이고, 교체가 있는 plan은 `allow-replace` 라벨이 있어야 적용한다. 매일 드리프트를 점검한다. EKS는 표준 지원(14개월) 안에 머물며 새 버전이 나오면 3개월 [가정] 안에 데모 → 스테이징 → 운영 순으로 올린다.
15. **사람의 접근.** IAM 사용자와 장기 키를 두지 않고 IAM Identity Center(MFA)와 EKS 접근 항목으로 권한 세트를 쿠버네티스 그룹에 묶는다. 운영 클러스터에 사람의 상시 쓰기 권한은 없다. 긴급 접근 역할을 맡는 순간 SEV2 경보와 사후 검토가 따른다. 운영 DB 직접 접근은 원칙적으로 없고, 긴급 조회는 SSM 세션·IAM DB 인증·pgaudit 기록으로 하며 관리자 접속기록(NFR-017)과 월 점검(FR-064) 대상이다. 서비스 권한은 EKS Pod Identity로 주고 IRSA는 지원하지 않는 곳에만 쓴다.
16. **비용 가드레일.** AWS Budgets(경보만, 무료) 월 예산과 50·80·100%·예측 경보, 비용 이상 탐지, 측정 스택의 `ttl` 태그 필수(기본 6시간 [가정])와 매시 자동 삭제, 시작 전 '예상 비용 × TTL ≤ 남은 예산' 확인, 측정 1회 비용의 성능 장부 기록(K9)을 둔다. 예산 금액은 질문 24의 결정을 따른다.
17. **운영 준비와 검증.** 변경을 표준·일반(위험 큼, 정비 시간과 변경 계획)·긴급으로 나눈다(POL-041). 새 서비스는 첫 운영 배포 전에 운영 준비 검토 목록을 통과한다. 런북 7종(RB-23~29)과 Game Day 3종(G-18 나쁜 배포 자동 중단, G-19 동결 창 위반 시도와 달력 장애, G-20 입장 정책 검증 의존 장애 중 확장)을 더해 런북 29종·Game Day 20종이 된다. DORA 5종은 dora.dev 정의대로 GitHub·ArgoCD 알림·인시던트 라벨에서 주 1회 계산하고 목표를 두지 않는다(NFR-023). 출시 전에는 데모 환경 값으로 표시한다.
18. **관련 정정.** ADR-0010 메시 PoC(wbs 0.5.2) 비교 항목에 '오픈소스 판 갱신 주기와 고정 방법'을 더한다(Linkerd는 2.15부터 오픈소스 안정판 아티팩트를 내지 않고 주간 edge 판만 낸다). Kyverno 정책은 처음부터 CEL 형식으로 쓴다. infra §7 그림의 매니페스트 갱신 주체를 승격 PR로 고친다. Schema Registry 호환 모드를 BACKWARD에서 BACKWARD_TRANSITIVE로 바꾼다. BACKWARD는 직전 판하고만 대조하는데, 분석 재적재처럼 보관 7일 안의 옛 메시지를 최신 스키마로 다시 읽는 소비자가 있기 때문이다(docs/api/guidelines.md §1).
19. **위험 구성 요소.** kafkajs는 마지막 릴리스가 v2.2.4(2023-02-27)이고 협력적 재조정을 지원하지 않는다. ASVS 15.1.2의 '계속 유지되는 저장소' 조건에 걸리므로 위험 구성 요소로 표시하고, PoC(wbs 0.5.1)에서 KafkaJS 호환 API를 가진 Confluent 공식 클라이언트(`@confluentinc/kafka-javascript`)와 처리량·재조정·OTel 계측을 비교해 새 ADR로 정한다. npm 공급망은 pnpm 10.26 이상의 설치 스크립트 허용 목록(`allowBuilds`)과 `minimumReleaseAge`(4,320분 = 3일)로 막고, 자체 호스트 러너를 두지 않는다(2025년 npm 웜 'Shai-Hulud'와 그 2차 확산이 토큰 탈취와 자체 호스트 러너 등록을 썼다).
20. **범위와 새 식별자.** docs/devops.md(상세 설계)와 docs/security/asvs/delivery.md(전달 파이프라인 ASVS 추적 표)를 새로 두고, POL-041(변경 관리와 배포), 용어 9개(변경 동결 창, 변경 동결 달력, 정비 시간, 카나리 배포, 확장·축소 변경, 릴리스 플래그, 승격, 긴급 변경, 출처 증명), 테스트 포인트 D-T1~D-T17, 쉬운 설명서 16편을 더한다. WBS는 0.1.1·0.1.2·0.4.2·0.5.1·4.7.1·5.4.1을 늘리고 0.1.4·0.3.4·0.4.4·2.10.4·4.2.3·4.4.3·4.6.2를 새로 둔다(합계 +17.5일).

## 대안

| 대안 | 기각 사유 |
| --- | --- |
| 동결을 ArgoCD 고정 크론 창으로만(지금 문서) | 오픈 시각이 공연마다 다르고, 창 시작 전에 시작한 카나리가 오픈 뒤에도 진행되며, 관리형 유지보수·노드 교체·키 교체·플래그는 동기화 창이 막지 못한다 |
| 모든 온세일에 T-90~T+60 전체 동결 | 3년차 소형 온세일은 연 4,500회(하루 약 12회)라 창이 하루 대부분을 덮어 배포가 밤으로 몰리고 묶음이 커진다(작은 묶음 원칙에 반함). 소형은 핫패스 묶음만 막는다 |
| 소형 온세일은 동결하지 않음 | 지금 POL-028(T-10~T+60 배포 금지)보다 약해진다. 소형 회차의 오류 예산은 몇 건 수준이라 카나리 실패 한 번도 회차 예산을 넘긴다 |
| 동결 중 핫픽스 허용 | 새 코드는 카나리 분석을 다시 거쳐야 하고 그동안 온세일 트래픽이 시험 대상이 된다. 되돌리기와 관제 명령으로 충분하지 않은 경우만 온세일 뒤에 한다 |
| 모든 서비스 블루그린 | 핫패스 파드 수만큼 자원이 두 배로 필요하고, 단일 리더·WebSocket에는 역시 맞지 않는다 |
| 마이그레이션을 앱 기동 때 실행 | 카나리 파드마다 실행이 겹치고, 실패가 앱 기동 실패로 번지며, 잠금 대기가 핫패스 쿼리를 막는다 |
| Drizzle 기본 마이그레이터만 사용 | 대기 중 마이그레이션 전부를 한 트랜잭션으로 돌려 `CREATE INDEX CONCURRENTLY`를 실행할 수 없다 |
| 운영 DB 스키마 되돌리기(down) | 되돌리는 동안 새 버전이 쓴 데이터가 사라지거나 옛 버전과 맞지 않는다. N-1 호환이면 앱만 되돌리면 된다 |
| ArgoCD Image Updater로 이미지 자동 갱신 | 변경이 Git PR로 남지 않아 검토·동결 게이트·감사가 갈라진다. 승격 PR은 다이제스트와 변경 목록을 함께 남긴다 |
| Pact 브로커 자체 호스팅 또는 PactFlow 무료 등급 | 브로커는 PostgreSQL이 필요해 상시 비용이 들고, PactFlow 무료 등급은 통합 2개라 소비자·제공자 쌍이 모자란다. 계약 저장소에 Pact 파일을 두고 제공자 CI가 검증한다 |
| 비공개 저장소 기본 | 무료 등급에서 브랜치 보호·규칙 세트·환경 보호 규칙·출처 증명이 없고, 호스트 러너 분(월 2,000분)을 넘으면 과금된다. 비공개로 하려면 유료 등급이 필요하다 |
| Kyverno ClusterPolicy `verifyImages` | v1.19에서 폐기 예정이고 v1.20에서 제거 예정이다 |
| 리전·계정 하나에 모든 환경 | 운영 데이터와 측정 자원이 같은 권한 경계에 놓인다. 조직 계정은 추가 요금이 없다 |

## 결과

- **얻는 것**: 온세일 동안 운영 변경이 '설계상' 아니라 '장치로' 멈춘다(동기화 창, 노드 중단 예산, 승격 게이트, 관리형 유지보수 창, 자동 중단, T-30 점검). 모든 운영 이미지가 어디서 어떻게 빌드됐는지 증명되고, 카나리가 SLI로 자동 판정되며, 스키마 변경이 되돌리기를 막지 않는다. 배포·마이그레이션·비밀 유출·CI 장애에 런북이 생긴다. ASVS V13·V15·V16의 전달 파이프라인 항목이 추적 표로 판정된다.
- **대가**
  - WBS +17.5일(Phase 0 +9, Phase 2 +1, Phase 4 +7, Phase 5 +0.5). Phase 0이 길어진다.
  - 공용 워크플로·동결 달력·마이그레이션 실행기를 직접 유지해야 한다.
  - 3년차에는 소형 온세일 창이 겹쳐 핫패스 배포가 대략 21:00~09:00으로 몰린다(docs/devops.md §8.5의 가정 계산).
- **남는 한계**(planning/01 §5.2, docs/devops.md §15, 쉬운 설명서 16편)
  - 1인 기간에는 2인 승인·동료 검토·commander 결정이 모두 한 사람의 자기 확인이다. GitHub는 작성자가 자기 PR을 승인할 수 없어 필수 승인 수를 0으로 두고 필수 검사로 대신한다.
  - 카나리는 평시 트래픽에서만 돈다. 부하에서만 드러나는 결함은 축소 성능 시험과 측정 캠페인이 맡고, 데모 환경은 합성 트래픽으로 판정력을 보탠다.
  - 서명과 출처 증명은 '어디서 어떻게 빌드됐나'를 증명할 뿐 코드와 의존성이 안전함을 증명하지 않는다. 2026-05-11 'Mini Shai-Hulud' 공격에서는 탈취한 OIDC 토큰으로 유효한 출처 증명이 만들어졌다(SLSA 블로그). 새 버전 3일 대기는 그 안에 드러나는 악성 버전만 거른다.
  - MSK 유지보수 시점은 고를 수 없다. 온세일 중 브로커 재시작이 겹치면 최대 약 2분 동안 p99가 최대 약 2초 늘 수 있다(AWS 문서). 거래 경로는 Outbox 재시도와 멱등 소비로 흡수하지만 관제 지표 지연은 남는다.
  - Gateway API 트래픽 플러그인은 0.x다. 깨지면 복제본 비율 카나리로 돌아가며 판정 정밀도가 떨어진다.
  - Next.js 앱 서버 카나리 중에는 다른 버전 파드에 닿은 사용자가 전체 새로고침될 수 있다. 대기실·구매 경로는 Next.js를 거치지 않고 온세일 중에는 배포하지 않으므로 평시 탐색 화면에 한정된다.
  - 운영 환경을 실제로 돌리지 않으므로 운영 승격·긴급 접근·관리형 유지보수 대응은 데모·스테이징 리허설로만 검증된다.
- **되돌릴 조건**
  - 핫패스 배포 가능 시간이 하루 8시간 아래로 줄면 동결 단위를 줄이는 설계(셀 분리, 공연 단위 카나리)를 새 ADR로 검토한다.
  - 카나리 자동 중단이 한 달에 3회 [가정] 넘게 헛판정이면 분석 기준을 다시 잡는다.
  - 서명 검증 PoC가 온세일 확장 시간(K9 60초)을 해치면 승격 단계 검증과 다이제스트 허용 목록으로 바꾼다.
  - 가상 팀이 실제 팀이 되면 필수 승인 수를 1 이상으로 올리고, 동결 중 긴급 변경에 두 번째 승인자를 둔다.
