# ADR-0036: 확인 불가능한 외부 한도의 엔지니어링 추정치 수립 및 금전 안전 보장 원칙

- **상태**: 채택 (2026-10-09 수립. ADR-0015 및 ADR-0029에 미정으로 남았던 외부 의존성 제약 사항을 확인·추정으로 공식 보완) ADR-0044(2026-10-13)가 결정 1 표 포트원 API 호출 한도 행의 전제 '포트원 채널은 호환·계약 테스트용이라 피크를 받지 않는다'를 대체한다. 포트원이 결제사인 공연은 결제사별 동시 입장 목표 상한(채널 상한 ÷ 0.06 TPS/명)으로 받는다. 2026-10-28(기술 검토 중간-027, 소유자 승인 '추천안 동의'): 결정 3과 위 줄의 '승인 한도 ÷ 0.06 TPS/명'은 두 갈래로 바꾼다. 첫 물결은 serving 전진 속도 상한 = 승인 한도 ÷ 결제 비율(처음 1.0 [가정]), 정상 상태는 동시 입장 상한 = 승인 한도 × 평균 체류(180초) ÷ 결제 비율 × 안전 계수(0.5 [가정])다. 추정 300 TPS면 토스는 초당 300번호·2.7만 명이라 결제사가 합산 5,000명을 묶지 않는다. 합산 5,000명은 좌석·결제 계층 용량으로 정한 값이고, 1~3년 전망의 1만~1.5만(NFR-021)은 결제 한도 협의가 아니라 그 계층의 부하 시험이 전제다. 한도 협의와 채널 추가는 첫 물결 속도를 높인다. 포트원 채널 하나(초당 50건)는 초당 50번호·4,500명이다(docs/architecture.md §9.5, docs/features/queue-admission.md §5).
- **관련 문서**: ADR-0015, ADR-0029, ADR-0031, docs/architecture.md §9.1·§9.4·§9.5, docs/features/payment.md §2.1·§5·§9, docs/api/guidelines.md §4, design/d1-brief.md §3
- **관련 ID**: FR-011, FR-041, NFR-005, NFR-006, NFR-021, POL-013, POL-027

## 맥락
- 결제 및 도메인 설계 과정에서 외부 연동과 관련된 5가지 미확정 제약 사항이 식별되었다: 토스페이먼츠 운영 승인 한도(TPS), 포트원 수동 승인 유효 기한, 포트원 웹훅 서명 헤더 규격, 포트원 API 호출 한도, 그리고 서비스 명칭 'PEAKET' 및 '피켓'의 상표권 선점 여부.
- 소유자 지시(2026-10-09): 확인할 수 없으면 어림잡아 추정한다. 현재 프로젝트는 포트폴리오 및 아키텍처 검증 단계이므로 토스·포트원 문의에 필요한 가맹점 계약을 체결하여 비공개 운영 수치를 확인하는 것이 불가능하다(운영 환경 미가동, ADR-0031).
- 따라서 확인 불가능한 외부 수치 때문에 아키텍처 결정을 무한정 유보하는 대신, 합리적인 엔지니어링 추정치를 공식 수립하고 **추정치가 빗나가더라도 시스템의 금전적 무결성(이중 결제 0건, 과금 없는 실패)은 절대적으로 보장되는 안전장치**를 마련한다.
- 2026-10-09에 다시 확인한 것:

| 항목 | 찾은 것 | 찾지 못한 것 |
| --- | --- | --- |
| 토스 운영 승인 한도 | 테스트 환경은 API별 분당 100건 | 운영 환경의 호출 한도 수치 |
| 포트원 수동 승인 기한 | 수동 승인 API는 가능한 한 즉시 호출하라고 권하고, 타임아웃은 PG마다 다르며 오래 기다리면 승인이 실패할 수 있다고 적음 | PG별 기한 수치 |
| 포트원 웹훅 서명 헤더 | 포트원 문서가 Standard Webhooks 스펙을 따른다고 밝힘. 공식 JS 서버 SDK가 `webhook-id`·`webhook-timestamp`·`webhook-signature` 세 헤더를 읽고, 헤더가 없거나 시각 차이가 5분을 넘으면 거부함 | 없음 |
| 포트원 API 호출 한도 | 포트원 문서의 PG 한 곳(키움페이) 유의사항이 비인증 결제 API를 초당 50건 이하로 권함 | 포트원 API 자체의 한도 |
| 상표 | 없음 | KIPRIS 검색 결과. 이 작업 환경에서는 검색 제출이 허용되지 않아 수행하지 못함 |

## 결정
1. 포트원 웹훅 서명 헤더는 공식 SDK 분석을 통해 확인된 규격(`webhook-id`, `webhook-timestamp`, `webhook-signature`)을 확정 사용한다. 나머지 4개 미확정 항목은 아래 추정치를 공식 수립하고 POL-027에 '추정'으로 명시한다.

| 항목 | 추정치 | 근거 | 추정이 틀렸을 때 |
| --- | --- | --- | --- |
| 토스 운영 승인 한도 | 가맹점 하나에 피크 300 TPS(사전 협의 전제) | 운영 한도는 문서에 없어 가맹점 계약에서 정하는 값으로 본다. 이 설계가 필요로 하는 값(결제 피크 300 TPS, NFR-005)을 그대로 추정치로 두고, 틀린 경우는 결정 2·4가 받는다 | 상한을 넘는 승인은 큐에서 기다리고, 승인 기한 10분을 넘기면 과금 없이 만료된다 |
| 포트원 수동 승인 기한 | 인증 뒤 10분 | 수치가 공개된 국내 PG 사례가 토스 10분뿐이다. 이 흐름은 인증 직후 승인을 호출하므로 첫 호출은 몇 초 안에 끝난다 | 실제 기한이 더 짧으면 늦은 재시도만 실패하고 과금 없이 끝난다 |
| 포트원 API 호출 한도 | 채널 하나에 초당 50건 | 포트원 문서에 있는 PG 권장치(키움페이, 초당 50건 이하)를 상한 사례로 쓴다 | 포트원 채널은 호환·계약 테스트용이라 피크를 받지 않는다. 429·5xx를 받으면 지수 백오프한다 |
| 상표 | 포트폴리오 기간에는 'PEAKET'·'피켓'을 바꾸지 않아도 된다 | 'PEAKET'은 만든 단어다. '피켓'은 일반 단어라 같은 이름의 선등록 상표가 있을 수 있다. 포트폴리오 기간에는 상업 운영이 없다(ADR-0031) | 실서비스 전에 이름을 바꿔야 할 수 있다 |

2. PG 어댑터의 능력 플래그(ADR-0029 결정 2)에 채널 호출 상한을 더하고, 어댑터 내부의 토큰 버킷(Token Bucket) 레이트 리미터가 이를 강제한다. 토스 300 TPS, 포트원 초당 50건, PG 시뮬레이터는 시험마다 정한다. 상한을 넘는 승인은 같은 멱등키로 재시도 큐에서 기다리고(승인 기한 안에서만, POL-013), 확정 지연이 완화 SLO(확정까지 p99 60초)를 넘으면 신규 결제 진입을 잠시 막는다(payment §9). PG가 HTTP 429를 반환하면 그 채널의 상한을 낮춘다. 기한을 초과한 건은 PG에 승인을 요청하지 않고 좌석을 자동 반환한다(과금 없는 만료).
3. 합산 동시 입장 상한은 '승인 한도 ÷ 0.06 TPS/명'(docs/architecture.md §9.5)에 추정 한도를 넣은 5,000이다. 1~3년 전망의 1만~1.5만(NFR-021)은 토스와 한도를 협의로 늘리거나 결제 채널을 더한 뒤 적용한다.
4. 추정이 틀려도 안전한지는 시험으로 확인한다. Phase 2 장애 주입(wbs 2.12.2)에서 PG 시뮬레이터 상한을 300 TPS와 비관 사례 100 TPS로 두고, 승인 대기열이 10분 기한 안에 비는지, 이중 결제 0건인지, 기한을 넘긴 승인이 과금 없이 끝나는지 검증한다(payment P-T22).
5. 포트원 웹훅은 세 헤더를 필수로 받고(OpenAPI에 표시), 검증은 지금처럼 서버 SDK에 맡긴다. 중복 제거 키는 지금처럼 이벤트 종류·`paymentId`·`timestamp`다.
6. 상표는 포트폴리오 기간에 이름을 그대로 쓰고, KIPRIS 검색은 브랜드 자산 작업(wbs 0.6.3)에 남긴다. 상업 서비스 론칭 전에 출원 여부를 정한다.
7. 실제 값이 확인되면 추정을 바꾼다. 토스·포트원은 가맹점 계약이나 기술지원 답변, 상표는 KIPRIS 검색 결과가 그 계기다.

## 검토한 대안
| 대안 | 기각 사유 및 한계점 |
| --- | --- |
| 외부 답변이 확인될 때까지 '확인 필요'로 유보 | 포트폴리오 기간에는 가맹점 계약이 없어 끝내 확인되지 않는다. 합산 동시 입장 상한·채널 호출 상한 같은 핵심 설계 값이 계속 미정으로 남는다. |
| 성장 전망까지 받는 낙관적 추정(토스 900 TPS) | 근거가 없다. 틀리면 결제 확정이 10분 기한을 넘겨 판매를 잃고, 실제 운영에서 대규모 429 오류와 결제 타임아웃 실패를 유발한다. |

## 결과와 트레이드오프
- 설계 값(합산 동시 입장 상한, 채널 호출 상한, 포트원 승인 기한)이 정해져 Phase 0~2 작업이 외부 답변을 기다리지 않는다.
- 대가: 추정이 틀리면 결제 확정이 느려지거나(토스 한도가 더 낮을 때) 성장 전망의 상한 확대가 늦어진다. 이중 결제 0건과 기한 초과 무과금은 추정과 관계없이 지킨다.
- 되돌릴 조건: 실제 값이 확인되면 결정 1의 표를 바꾸고 POL-027의 표시를 '확인됨'으로 바꾼다.
