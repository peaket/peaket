# ADR-0025: 오프라인 회전 QR 코드 검증을 위한 비대칭 기기 키 서명 채택 (대칭키 TOTP 배제)

- **상태**: 채택 (2026-10-05 설계서 §6 '오프라인 입장 전략'에 최초 수립, 2026-10-08 아키텍처 결정 레코드(ADR)로 공식 이관). ADR-0050(2026-10-13)이 결정 2와 결과 첫 줄의 '보안 저장소·Secure Enclave/Keystore' 주장을 정정한다. WebCrypto 키는 스크립트가 꺼낼 수 없을 뿐 브라우저 프로필에 저장되는 소프트웨어 키다. 같은 ADR이 결정 7의 '완벽히 방어'를 '줄인다'로 고치고 재발급 제한(입장 시작 전 재인증·24시간 1회, 입장 시작 뒤 현장 부스)을 더한다. ADR-0051(2026-10-13)이 결정 2의 키 생성 시점을 월렛 접속이 아니라 '이 휴대폰을 입장용으로 등록' 버튼으로 바꾸고(입장 시작 뒤 첫 등록은 재인증), 결정 3의 QR에 형식 버전과 키 번호(keyId)를 더하며(QR v1), 결정 6의 1분 변경분은 화면이 켜진 동안 앱 타이머로 받고 다른 스캐너의 입장 기록도 함께 받게 하며, 결정 8의 동시 스캔 보고 대상을 그 구역 현장 책임자와 파트너로 바꾼다(관제는 감시)
- **관련 문서**: 설계서 §6(오프라인 입장 전략), §10(암호화 아키텍처 K10), 33장(버전 벡터 합의), docs/features/offline-gate.md, docs/security/secrets-and-keys.md(기기 키 관리)
- **관련 ID**: FR-012, FR-013, FR-035, FR-036, POL-017, POL-018, NFR-010, SCR-013, SCR-034

## 맥락
- 수만 명이 밀집하는 대형 공연장 환경에서는 LTE/5G 통신망 포화나 전파 음영으로 인해 게이트 스캐너의 실시간 중앙 서버 통신이 완전히 두절될 가능성이 매우 높다. 따라서 티켓 검표 시스템은 외부 네트워크 연결이 끊긴 상태에서도 독립적으로 작동하는 '오프라인 우선(Offline-First)' 구조여야 한다.
- 동시에 스크린샷 캡처본 공유나 화면 녹화를 통한 티켓 불법 복제 및 이중 입장을 원천 차단하기 위해, 티켓마스터 SafeTix와 같이 일정 주기마다 동적으로 갱신되는 동적 회전 QR 코드를 구현해야 한다.
- 초기 대안으로 검토된 대칭키 기반 TOTP(시간 기반 일회용 비밀번호) 알고리즘은 현장 검증 스캐너 기기 내부에도 암호화 대칭키를 직접 저장해야 하므로, 스캐너 단말기 분실이나 덤프 시 전체 티켓 위조가 가능해지는 치명적인 보안 취약점을 내포하고 있다.

## 결정
1. 대칭키 TOTP 방식을 배제하고, W3C WebCrypto API 기반의 비대칭 디지털 서명 체계(ECDSA P-256)를 공식 채택한다.
2. 예매 완료 후 사용자가 티켓 월렛에 접속할 때, 브라우저의 보안 저장소 내부에서 외부 추출이 불가능한(Non-exportable) ECDSA P-256 키쌍을 생성하고, 공개키(Public Key)만을 중앙 티켓 서비스(`ticket-svc`)에 전송하여 등록한다.
3. 월렛 화면의 회전 QR 코드는 `티켓 식별자(UUID) + 타임스탬프(Unix Epoch) + 기기 개인키 디지털 서명` 페이로드로 구성되며, 15초 주기로 자동 재계산되어 화면에 갱신 렌더링된다.
4. 현장 게이트 스캐너 단말기는 사전에 중앙 서버로부터 동기화받은 '티켓 ID → 공개키 매핑 테이블'과 '폐기 목록(CRL)'만을 보관한다. 검표 시 스캐너는 QR 코드의 서명을 보관 중인 공개키로 순수 로컬 오프라인 검증만 수행하므로, 스캐너 단말기를 물리적으로 탈취당하더라도 티켓을 위조할 수 있는 비밀 정보가 일절 노출되지 않는다.
5. 단말기 간 시계 오차(Clock Drift)는 ±30초 허용 범위를 두며, 사용자가 마지막으로 온라인 상태였을 때 측정한 서버-단말기 시간 편차 오프셋을 서명 타임스탬프에 자동 반영하여 보정한다.
6. 티켓의 공식 양도 및 취소 재발급 시에는 구 키를 즉시 폐기 목록에 등재하고 수신자의 신규 기기 공개키를 재등록한다. 스캐너는 '티켓 ID → 공개키' 목록과 폐기 목록으로 검증만 하며, 입장 시작 전 전체 목록을 받고 온라인일 때 1분마다 변경분을 받는다.
7. iOS Safari ITP(Intelligent Tracking Prevention)로 인한 7일 후 IndexedDB 자동 초기화 위험은 PWA 홈 화면 추가 유도, `navigator.storage.persist()` 영구 저장소 권한 요청, 공연 전날 리마인더 알림, 그리고 현장 부스 비상 키 재발급 절차를 마련하여 완벽히 방어한다.
8. 네트워크가 단절된 복수 게이트 간의 동시 스캔 이중 입장 방지는 물리적 게이트 구역(Zone)별 좌석 범위 격리로 1차 차단하고, 스캐너 네트워크 복구 시 버전 벡터(Version Vector) 기반 이벤트 로그 동기화를 통해 동시 스캔 이상을 감지하여 보안 관제 센터로 즉시 보고한다.

## 검토한 대안
| 대안 | 기각 사유 및 한계점 |
| --- | --- |
| TOTP 기반 대칭키 회전 방식 | 검증을 수행하는 수십 대의 오프라인 스캐너 단말기마다 암호화 비밀키를 로컬에 보관해야 하므로, 현장 단말기 1대만 도난·분실되더라도 해당 키로 무제한 위조 티켓을 생산할 수 있는 보안 붕괴 위험이 있다. |
| 온라인 전용 중앙 검증 방식 (v0) | 대형 콘서트장 네트워크 트래픽 포화 시 게이트 스캐너가 타임아웃에 빠져 수만 명의 관람객 입장이 전면 중단되는 대형 운영 사고가 발생한다. |

## 결과와 트레이드오프
- 검증 단말기에는 오직 공개키만 보관되므로 하드웨어 탈취 위협으로부터 완벽한 보안성을 보장하며, 개인키는 사용자의 기기 하드웨어 보안 영역(Secure Enclave/Keystore) 밖으로 절대 유출되지 않는다.
- 허용 시계 오차(±30초) 구간 동안에는 캡처된 스크린샷이 물리적으로 유효할 수 있는 미세한 공격 창이 존재하므로, 월렛 화면에 동적 회전 워터마크 애니메이션과 렌더링 시각 인디케이터를 시각적 보조 수단으로 함께 배치한다.
