# ADR-0329: 화면 앱 구조를 공용 ESLint 규칙으로 막는다(층 방향·조각 공개 파일·이름·경로 파일) (2026-11-21)

- **상태**: 채택(2026-11-21, 소유자 인터뷰로 정하고 같은 날 소유자가 "채택으로" 확인). 규칙·기준선·시험은 a79a82834로 커밋했다.
- **관련**: [docs/frontend.md](../frontend.md) §2.2 '층 의존'·'조각 공개 파일'·'이름'·'Next.js 경로 폴더', [docs/architecture.md](../architecture.md) §6.5 '아키텍처 구조', [docs/quality/quality-requirements.md](../quality/quality-requirements.md) QR-MA-2, `packages/config/eslint/web-boundaries.mjs`·`web-boundaries-baseline.json`·`web-boundaries.test.mjs`
- **관련 ID**: QR-MA-2, 기술 검토 낮음-098

## 맥락

- 화면 앱 셋(소비자 웹·파트너 콘솔·관제 콘솔)은 FSD 층(`_app` → `_pages` → `widgets` → `features` → `entities` → `shared`)으로 나뉜다. 정본은 층 방향을 Steiger `fsd/forbidden-imports` 하나로 막는다고 적었지만, 저장소 어디에도 Steiger가 설치·실행되지 않아 **실제로는 아무것도 막지 않았다**(2026-11-21 조사). 그 사이 거꾸로 가져오기와 같은 층 조각끼리 가져오기가 운영 코드에 4곳 생겼다.
- 서비스 안 구조(받는 층 → 유스케이스 → 도메인, 다른 모듈은 `index.ts`로만)는 `service-layers.mjs`가 ESLint로 이미 막는다. 화면 앱만 기계 검사가 비어 있었다.
- 조각 공개 파일(`index.ts`)을 거치지 않는 가져오기는 정본에 규칙이 없었다. 실제 코드는 대부분 공개 파일을 쓰지만, 서버 전용(`server/`)·브라우저 전용(`browser.ts`) 파일과 첫 화면 예산 때문에 늦게 싣는 `import()`는 일부러 공개 파일을 피한다.
- 파일·폴더 이름은 정본에 규칙이 없지만 세 앱이 모두 같은 관례를 지킨다(`.ts` 465개·폴더 178개 소문자-하이픈, `.tsx`는 대문자 시작 324개·소문자-하이픈 묶음 67개, 2026-11-21 셈).
- 받는 값 타입은 작은 부품에서 그 자리 객체 타입으로 적는 곳이 499곳이고, 이름 붙인 타입 가운데 32곳이 `Props`·`FormProps`처럼 부품 이름과 다르다.
- Next.js `app/` 경로 파일은 '다시 내보내기만'이 정본이지만 13개 파일(로그인·연결·재인증 처리기 등)이 코드를 직접 담는다.

## 결정

1. **층 방향은 ESLint `peaket-web-boundaries/layer-direction` 하나로 막는다.** 위 층은 아래 층을 가져오고, 아래 층이 위 층을 가져오거나 같은 층의 다른 조각끼리 가져오면 막는다. 타입만 가져오기도 의존이므로 막는다. Steiger는 들이지 않고 정본의 Steiger 문장을 이 규칙으로 바꾼다. 같은 규칙을 두 도구로 막지 않는다는 원칙(기술 검토 낮음-098)은 그대로다.
2. **아래 층의 조각은 공개 파일로만 가져온다(`no-slice-internals`).** 공개 파일은 `index.ts(x)`, `browser.ts`, `server/` 아래다. 공개 파일이 없는 조각은 폴더 전체가 공개다. 타입만 가져오기와 늦게 싣는 `import()`는 막지 않는다: 앞은 실행 때 사라지고, 뒤는 공개 파일로 모으면 첫 화면 묶음에 실려 JS 예산(docs/frontend.md §5.8 '성능 예산 표')을 깬다. 시험·이야기 파일과 관제 콘솔 미리보기(`app/preview`, ADR-0170 ?state=)는 보지 않는다. 미리보기는 화면마다 상태 예시를 모으는데, 그것을 공개 파일에 넣으면 운영 묶음에 미리보기 자료가 실린다.
3. **이름 표기를 지금 관례로 굳힌다(`file-naming`).** `.ts`·`.mjs`와 폴더는 소문자-하이픈, `.tsx`는 대문자 시작(부품 하나) 또는 소문자-하이픈(부품 묶음). 첫 점 앞만 보고, 프레임워크가 정한 이름은 건너뛴다.
4. **이름 붙인 받는 값 타입은 `부품이름Props`로 짓는다(`props-type-naming`).** 그 자리 객체 타입과 여러 부품이 함께 쓰는 공용 이름(`PageProps`·`RouteProps`·`StepProps`)은 받는다. 그 자리 타입까지 막는 안은 정상 코드 499곳을 막아 고르지 않았다.
5. **경로 파일은 다시 내보내기와 경로 설정 글자 값만 둔다(`route-reexport-only`).** Next.js가 경로 파일에서 직접 읽어야 하는 `dynamic`·`revalidate`·`instant` 같은 설정은 글자·수·참거짓 값으로 둘 수 있다.
6. **들이기 전 위반은 기준선에 까닭과 함께 두고 줄이기만 한다.** `web-boundaries-baseline.json`에 63줄(층 방향 4, 공개 파일 14, 타입 이름 32, 경로 파일 13)을 둔다. 줄이 늘거나 이미 고친 줄이 남으면 `web-boundaries.test.mjs`가 막는다. 줄 안 주석으로 끄지 않는다(docs/devops.md §4.4 '보안 린트'와 같은 방식).

## 결과

- 화면 앱의 새 거꾸로 가져오기·조각 안쪽 가져오기·이름 어긋남·경로 파일 코드는 `pnpm lint`에서 막힌다. 들일 때 전체 린트(4,258개 파일)는 오류 0이었다.
- 서비스 쪽 규칙(`service-layers.mjs`·`service-security.mjs`)은 바꾸지 않았다. 새 규칙은 `apps/{web,partner,console-host}`의 `src`와 `app/` 경로 파일만 본다.
- 기준선 63줄은 따로 정리한다. 줄마다 고치는 길(아래 층으로 내리기, 공개 파일에 더하기, 처리기를 `src/_app`·`server/`로 옮기기, 타입 이름 바꾸기)을 까닭 칸에 적었다.
- 남는 한계: 가져오기는 상대 경로와 `@/` 별칭만 해석한다. 이름 규칙은 린트가 보는 파일만 보고(이미지·CSS 제외), 잘못된 폴더 하나 아래 파일마다 알린다. 공용 받는 값 이름 목록은 손으로 관리한다.
- 되돌릴 조건:
  - Steiger를 CI에 실제로 들이면 결정 1을 Steiger로 옮기고 `layer-direction`을 끈다(두 도구로 막지 않는다).
  - FSD 공식 규칙이 서버·브라우저 진입 파일 이름을 따로 정하면 결정 2의 공개 파일 목록을 그 이름으로 맞춘다.
  - 기준선이 줄지 않고 한 분기 넘게 남으면, 줄마다 예외로 남길지 고칠지 다시 정한다.

## 다른 선택지

| 길 | 고르지 않은 까닭 |
| --- | --- |
| 정본대로 Steiger를 설치한다 | 새 도구·새 CI 잡이 필요하고, 조각 공개 파일·이름·경로 파일 규칙은 따로 또 만들어야 한다. 설정 패키지에 같은 꼴의 ESLint 규칙이 이미 있다 |
| `no-restricted-imports` 글롭으로 막는다 | 조각의 공개 파일 유무와 `@/` 별칭·상대 경로를 함께 판단하지 못한다. 층마다 패턴이 늘어 `service-layers.mjs`보다 복잡해진다 |
| 처음부터 경고로만 켠다 | 정본(devops §4.4)에 경고 단계가 없고, 경고는 새 위반도 막지 못한다 |
| 그 자리 객체 타입까지 이름을 강제한다 | 정상 코드 499곳이 걸려 기준선이 566줄이 된다. 작은 부품의 그 자리 타입은 이 프로젝트의 관례다 |
