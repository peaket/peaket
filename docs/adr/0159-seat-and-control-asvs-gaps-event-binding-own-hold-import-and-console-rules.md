# ADR-0159: 좌석·관제 보안 추적 표를 판정하며 찾은 빈틈을 막는다 — 입장 토큰의 회차 묶기, 자기 홀드만, 서버의 좌석 확인, 구독 상한, 가져오기 파일과 관제 링크·원본 파일 규칙(2026-10-30)

- **상태**: 채택 (2026-10-30. 소유자가 ADR-0154 결정 3으로 좌석·관제 보안 추적 표를 지금 쓰기로 정했다. 판정하며 막은 빈틈의 방법은 모두 추천 적용이다. 큰 판단 일곱은 고치지 않고 review/open-items.md에 남겼다. 정본은 docs/security/asvs/seat-hold.md, asvs/control-tower.md, docs/features/seat-hold.md §2·§3·§7·§10, docs/features/control-tower.md §5·§8·§9다.)
- **관련**: ADR-0053(구매 세션 소지 증명), ADR-0065(웹 보안 기본값), ADR-0149(감사 기록의 사람 칸), ADR-0154, POL-021 B(운영 명령 카탈로그), [docs/security/asvs/seat-hold.md](../security/asvs/seat-hold.md), [docs/security/asvs/control-tower.md](../security/asvs/control-tower.md), [docs/security/authz-matrix.md](../security/authz-matrix.md)

## 맥락

ASVS 5.0.0 Level 2 항목을 좌석(143개)과 관제(157개)에 대해 하나씩 판정했다. 그러다 설계에 다음 빈틈이 있음을 찾았다.

- **대기열 우회**: 게이트웨이와 purchase-svc는 입장 토큰의 서명·만료·재사용·세션만 보고, 토큰의 회차를 주소의 회차와 대조하지 않았다. 한가한 회차의 입장 토큰으로 인기 회차의 좌석을 잡을 수 있었다.
- **남의 홀드**: holdId로 좌석을 찾는 방법과 소유 확인이 정해져 있지 않았다(남의 ID로 남의 홀드를 바꾸는 BOLA 빈틈).
- **판매 제외석**: 판매 제외석은 비트맵에서 0이라 화면만 막았고, API를 직접 부르면 잡을 수 있었다.
- **구독 범위**: 서버는 클라이언트가 '보이는 구역만' 구독하는지 알 수 없었다. 고친 클라이언트가 모든 구역을 구독하면 전송량 상한을 깰 수 있었다.
- **가져오기 파일**: 다른 추적 표들이 좌석맵 가져오기 파서 판정을 좌석 추적 표로 미뤘는데, 파서 설정이 어디에도 없었다.
- **관제 화면**:
  - 경보 링크가 `javascript:` 주소여도 운영자 화면에 그대로 뜰 수 있었다.
  - ops-svc의 AWS 권한 범위가 없었다.
  - 요청서·공문 원본의 올리기·내려받기 규칙이 없었다.
  - 조회만 하는 역할(CS, viewer)이 수사 대상자 식별값을 볼 수 있었다.

## 결정

1. **입장 토큰을 회차에 묶는다**: gw-fan이 주소의 회차 ID와 입장 토큰의 `event`가 같은지 본다. 다르면 403이고, WebSocket이면 4403으로 닫는다. purchase-svc는 구매 세션에 회차를 적고 요청마다 대조한다.
2. **서버가 좌석을 먼저 확인한다**: 홀드 Lua를 부르기 전에 없는 좌석, 다른 회차 좌석, 판매 제외석, 중복을 422로 거절한다.
3. **자기 홀드만 풀고 늘린다**: holdId를 구매 세션 상태와 좌석 홀드 Hash에 적고, 해제·연장은 그 세션의 목록에서만 찾는다. 남의 것과 없는 것은 같은 404다.
4. **좌석 구독을 검사한다**: 구독 메시지의 범위·중복을 검사한다(4403). 연결마다 구독은 16개 [가정]까지, 바꾸기는 초당 2번 [가정]까지다(넘으면 4429). 정한 프레임 길이만 받고, 시계 맞추기는 초당 1번 [가정]이다.
5. **좌석맵 가져오기 파일 규칙**:
   - 한 파일 10MB [가정]이고, 압축 파일은 받지 않는다.
   - SVG는 DTD와 외부 엔터티를 끄고 `<!DOCTYPE`이 있으면 거절한다.
   - 정한 도형 요소·속성만 읽는다.
   - 상한은 좌석 5만 석, 구역 500개 [가정], 도형 하나의 꼭짓점 1,000개 [가정], CPU 5초 [가정]이다.
   - 원본은 저장하지 않는다.
6. **하나만 받는 쿼리 매개변수가 두 번 오면 400이다**: HTTP 파라미터 오염 공격 판정(ASVS 15.3.7)의 규칙이다.
7. **관제 경보 링크**: `runbookUrl`과 대시보드 링크는 `https`이고 정한 호스트일 때만 링크로 보이고, 아니면 글자로 보인다. ops-svc는 경보에 든 주소를 부르지 않는다.
8. **ops-svc의 AWS 권한**: 관제용 IP 집합 갱신과 대기열 배포의 전환 설정으로만 좁힌다.
9. **요청서·공문 원본은 PDF만 받는다**:
   - 확장자와 첫 바이트 `%PDF-`가 함께 맞아야 받고, 한 파일 20MB [가정]까지다.
   - 격리 버킷에서 악성 코드 검사가 '위협 없음'일 때만 내려받게 하고, 걸리면 내려받기를 막고 SEV2로 알린다.
   - 콘솔 안에서 열지 않고, 첨부와 서버가 정한 파일 이름으로만 내려준다.
10. **조회만 하는 역할의 칸 가림**: CS의 기관 요청 조회, viewer·CS의 보안 사고 조회에는 대상자 식별값, 제출 파일, 통지 대상 목록을 빼고 건 요약만 보인다.
11. **관제 글 칸**: 2,000자 [가정]까지이고, 포스트모템 초안 Markdown에 넣는 사람 글은 마크다운 문법 문자를 이스케이프한다.

12. **주문·결제 경로도 자기 것만이다(2026-10-30 마지막 정리)**: 이 경로들의 주소에는 회차가 없으므로 회차 대조(결정 1) 대신, 본문의 holdId나 주소의 orderId가 그 구매 세션의 것이 아니면 404로 답한다(결정 3과 같은 규칙, docs/features/seat-hold.md §2).

## 검토한 대안

- **purchase-svc만 회차를 확인하기**: WebSocket 경로가 빠진다. 기각.
- **판매 제외석 비트를 켜 두기**: 가용 계산식과 다시 만들기 절차를 함께 바꿔야 한다. 기각.
- **남의 홀드에 403으로 답하기**: 그 홀드가 있다는 사실을 알린다. 기각.
- **연결 수 상한만 두기**: 연결 하나로 모든 구역을 구독할 수 있다. 기각.
- **경보 링크를 모두 글자로만 보이기**: 런북을 여는 데 시간이 든다. 기각.
- **요청서 원본을 사진처럼 다시 쓰기**: 법정 원본 보존과 맞지 않는다. 기각.
- **조회 권한 자체를 없애기**: planning/03 §3의 권한과 어긋난다. 기각.

## 결과와 트레이드오프

- 대기열을 건너뛰는 길과 남의 홀드를 건드리는 길이 닫힌다. 회차 대조는 게이트웨이에서 요청마다 한 번 더 비교하는 비용이다.
- 고치지 않고 남긴 큰 판단 일곱이 있다. 이 가운데 1·2·3은 위험 표(planning/01 §5.2)에도 올리고, 모두 review/open-items.md 67~70번에 남긴다.
  1. 홀드를 풀자마자 다시 잡아 좌석을 최대 45분 붙잡는 것
  2. 수사기관 제공 자료에 commander 승인 단계가 없는 것
  3. 1인 기간에 접속기록 자기 점검을 끝낼 수 없는 것
  4. 수사기관 제출 파일의 보관 기간
  5. ops-svc가 멈추면 만료된 WAF 차단을 거둘 곳이 없는 것
  6. 좌석맵 SVG 해석을 DB 자격이 없는 별도 작업으로 떼는 것
  7. 평소 제어 gRPC에 메시지 서명이 없는 것

## 되돌릴 조건

- 구독 상한(16개·초당 2번)이 정상 화면 이동에서 4429를 내면 상한을 다시 잰다(좌석 화면 시험).
- 회차 대조가 게이트웨이 지연 예산을 넘으면 purchase-svc 쪽 대조로 옮기고 WebSocket은 연결 때 한 번 본다.
