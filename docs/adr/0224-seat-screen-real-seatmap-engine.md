# ADR-0224: 좌석 화면을 실제 좌석맵 엔진에 잇고, 아직 잇지 않은 상태의 미리보기를 개발 서버에만 남긴다

- **상태**: 채택(2026-11-09, 추천 적용). BUILD_ORDER HOT-350 ①.
- **관련**: [docs/frontend.md](../frontend.md) §4.2.2·§4.4.2·§4.7·§5.2, [docs/design/d5-screen-blueprint.md](../design/d5-screen-blueprint.md) §5.10, [docs/security/asvs/seat-hold.md](../security/asvs/seat-hold.md), ADR-0063, ADR-0170 결정 3, ADR-0216, ADR-0221
- **관련 ID**: SCR-010

## 맥락

- 좌석 화면(SCR-010)은 목업과 `?state=`로 그린 퍼블리싱 화면이었다. `@peaket/seatmap` 엔진(HOT-110·HOT-120)은 시연 페이지에서만 돌았다.
- 잇는 일은 ADR-0221의 여러 하위 단계로 나뉜다. 이 단계는 지도(첫 그림·확대·이동)만 잇는다. 그래서 정본에 없는 것을 정해야 했다.
  - 목업과 `?state=`는 데이터를 잇는 단계가 지운다(ADR-0170 결정 3). 그런데 홀드·자동 배정·배너 그림은 뒤 단계가 잇는다.
  - '스냅샷 주소가 같은 출처인지 확인'(HOT-120이 넘긴 말)이 무슨 뜻인지 없다. 스냅샷은 API 호스트라 문서와 같은 출처가 아니다.
  - 스냅샷 판이 다를 때 어디서 새 파일을 받는지 없다.
  - 스냅샷·파일 실패를 화면이 어떻게 가르는지 없다. 엔진의 오류 메시지는 글자뿐이었다.
  - 대기실은 만료 전 입장 저장값을 보면 좌석 화면으로 되돌려 보낸다. 서버가 401로 끝낸 세션이면 두 화면이 끝없이 왕복한다.
  - 지도 구역 글자에 파일의 등급 ID(`tier-s`)가 그대로 나왔다.

## 결정

1. **화면 구조**
   - 경로는 요청마다 셸이다(§5.2). 서버는 회차 값을 읽지 않고 `SeatsLive`(클라이언트)를 낸다. 그래서 없는 회차도 첫 응답은 200이고, 판단은 입장 저장값과 스냅샷이 한다.
   - 화면은 탭 저장소의 입장 저장값을 읽고, 구매 세션 키를 연 뒤(ADR-0221) 좌석맵 Worker에 파일과 스냅샷을 맡긴다.
   - 좌석맵 패키지·서명기·회차 요약 호출은 늦게 가져온다(첫 JS 예산 §5.8).
   - 캔버스는 효과 안에서 만든다. OffscreenCanvas로 넘긴 캔버스는 다시 넘길 수 없어서 다시 시도와 Strict Mode마다 새로 만든다.
2. **미리보기는 개발 서버에만 남긴다.** `?state=` 그림은 `SeatsPreview`로 옮기고 `process.env.NODE_ENV === 'development'`일 때만 불러온다. 운영 묶음에 들지 않는다. 뒤 단계(HOT-353·354·356·357)가 각자 잇는 상태를 지우고, 마지막 단계가 파일을 지운다.
3. **주소**
   - 좌석맵 파일은 입장 확정 응답의 경로가 이 회차의 같은 출처 경로이고 판 번호가 1~2^32−1일 때만 쓴다(`seatmapLayoutUrl`).
   - 스냅샷 주소는 서버가 준 값을 쓰지 않고 설정한 API 출처(`NEXT_PUBLIC_API_ORIGIN`)로 만든다. HOT-120이 넘긴 '같은 출처 확인'은 이 두 규칙으로 정한다.
4. **판이 다를 때**: 스냅샷의 `layoutVersion`이 받은 파일과 다르면 같은 경로 꼴의 그 판 파일을 자격 증명 없이 한 번만 다시 받는다. 그래도 다르면 오류로 끝낸다(§4.4.2).
5. **오류**
   - 엔진의 `error`에 `source`(`layout`·`snapshot`), `status`, 문제 유형 `problem`, `retryAfter`(초)를 싣는다. 파일·스냅샷 요청에는 읽기 시간 제한 10초를 둔다.
   - 스냅샷의 이름 없는 401은 팬 쿠키 만료일 수 있다. 서버는 입장 토큰 거절도 같은 모양으로 낸다. 그래서 §4.1대로 토큰을 한 번 갱신하고 다시 받고, 또 401이면 끝이다. 이름 있는 401과 403은 바로 '예매 시간이 끝났습니다'다.
   - `Retry-After`가 있는 503·429는 그 시각을 하한으로 위로만 흩어 세 번 [가정]까지 스스로 다시 받는다. 그 밖은 [다시 시도]다.
   - 첫 그림 뒤의 메시지 검사 오류 하나로는 지도를 잃지 않는다. 요청 실패만 화면을 바꾼다.
   - 입장 저장값이 없을 때도 예매 시간 끝으로 본다. 키를 열지 못하면(토큰 모양·서버 공개키) 세션 무효 화면이다.
   - 두 화면 모두 입장 저장값과 구매 세션 키를 지우고 2.5초 [가정] 뒤 대기실로 옮긴다(기록을 바꿔 뒤로 가기로 돌아오지 않는다). 지우지 않으면 대기실이 좌석 화면으로 되돌려 보낸다.
6. **끌기·휠·핀치**: 메인 스레드의 작은 몸짓 판별기(`createGesture`, 8px [가정])가 주 버튼·터치의 끌기·핀치·누르기를 가르고, 엔진에 `pan`·`zoomBy`·`pointer`를 보낸다. `pan`은 엔진이 배치 밖 빈 곳이 보이지 않게 묶는다. 엔진은 이 메시지가 몰려도 프레임마다 한 번만 그린다(§3.5). 캔버스는 `touch-action: none`이고, 전체 보기에서 더 축소할 수 없는 휠은 페이지 스크롤로 둔다.
7. **가격표**
   - 회차 공개 요약에서 `tierRank`와 등급 이름 `tierNames`를 만들어 엔진에 넘긴다(지도의 구역 글자가 'R석'이 된다).
   - 첫 그림을 요약 때문에 늦추지 않는다(§5.2 첫 그림 예산). 요약이 오면 `tiers` 메시지로 지도를 고친다. 엔진이 생기기 전에 오면 만들 때 쓴다.
   - `view`에 `maxZoom`을 더해 [+]를 막는다.
8. **가짜 API**: 실제 배치 판 2·3(1,440석, 구역 여섯, 마지막 구역 매진)과 이진 스냅샷(`seatSnapshot=expired|down|newer`), JWT 모양 입장 토큰(jti·exp)을 낸다. 판 1은 ADR-0216의 8석 자리 파일로 남긴다.

## 결과

- 좌석 화면이 실제 좌석맵을 Worker로 그리고 확대·이동·고르기가 된다. 고른 좌석의 홀드와 요약은 HOT-353, 접근성 목록은 HOT-354, 실시간은 HOT-357이다.
- 이 사이 화면 낭독기·키보드 사용자에게는 지도 대체가 없다(키보드로는 확대 버튼만 쓸 수 있다). HOT-354까지의 빈틈이다.
- 입장 확정 응답에 경로를 싣는 서버 쪽은 HOT-351이다. 그 전까지 실제 서버로는 [다시 시도] 화면이 뜬다.

## 검토한 다른 안

- **`?state=`를 지금 모두 지우기**: 뒤 단계가 볼 그림과 문구가 사라진다. 고르지 않았다.
- **Worker에 끌기 카메라 값을 그대로 보내기(`camera`)**: 메인 스레드가 묶음 규칙을 다시 계산해야 한다. 고르지 않았다.
- **대기실이 만료 판단을 서버에 물어보기**: 서버 호출이 늘고 대기실 경량 페이지를 바꿔야 한다. 끝난 쪽(좌석 화면)이 저장값을 지우는 쪽이 작다.
