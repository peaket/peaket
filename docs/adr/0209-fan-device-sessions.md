# ADR-0209: 팬의 로그인한 기기는 기기마다 한 줄로 보이고, 로그인 수단이 바뀌면 다른 세션을 모두 끝낸다

- **상태**: 채택(2026-11-05, 추천 적용, BUILD_ORDER BOT-044). 같은 날 새 맥락 리뷰로 결정 4(지금 기기 줄)·5(사건 쓰기 차례)를 고쳤다.
- **관련**: ADR-0001(팬 단일 요소 인증의 보완 통제), ADR-0011(토큰 수명주기), ADR-0050(재인증 토큰 5분 한 번), ADR-0081(목록 나누기), ADR-0143 결정 3(Outbox는 마지막 쓰기), ADR-0171 결정 4(기기 가명), [docs/features/identity.md](../features/identity.md) §4·§8 '로그인한 기기와 다른 세션 끝내기의 첫 구현', [docs/security/asvs/auth.md](../security/asvs/auth.md) 7.4.3·7.5.2
- **관련 ID**: FR-017, POL-019, SCR-017, SCR-040, I-T74, I-T75, I-T76, ASVS v5.0.0-7.4.3, ASVS v5.0.0-7.5.2

## 맥락

- 팬은 계정 설정(SCR-017)의 '로그인한 기기'에서 살아 있는 세션을 보고 다른 기기를 원격으로 로그아웃한다(FR-017, POL-019). 세션은 로그인 한 번에 하나씩 생기는 서버 쪽 기록이다.
- 지금까지 이 칸은 목업이었다. 정본에 빈칸이 넷 있었다.
  - 화면에 보일 기기 이름을 어디서 얻을지 정하지 않았다. identity는 기기 가명(`device_ref`)만 두고, 로그인 때 받는 브라우저 정보(User-Agent, 브라우저가 스스로 알리는 이름표 글)는 버린다.
  - 같은 브라우저에서 다시 로그인하면 앞 세션이 끝나지 않고 남는다. 세션을 그대로 늘어놓으면 한 기기가 여러 줄이 되고 목록 길이도 정해지지 않는다(ADR-0081은 나누지 않는 목록에 상한을 요구한다).
  - 지금 쓰는 기기를 이 경로로 끝내려 할 때, 남의 세션 ID를 보낼 때의 답이 없었다.
  - ASVS 7.4.3(인증 요소를 바꾼 뒤 다른 세션 끝내기)이 팬에게는 미충족이었다. 로그인 수단 추가·해제가 다른 세션을 끝내지 않았다(BOT-041이 넘긴 것).

## 결정

1. **화면용 기기 이름**: 로그인 때 identity가 받은 User-Agent에서 '브라우저 · 운영체제'의 거친 이름만 뽑아 세션 행(`session.device_label`)에 둔다.
   - 낱말은 정해진 목록에서만 고른다. 브라우저는 Chrome·Safari·Firefox·Edge·Samsung Internet·Whale·Opera·카카오톡·네이버 앱, 운영체제는 iPhone·iPad·Android·Windows·macOS·ChromeOS·Linux다.
   - 브라우저 계열은 정규 로그 줄의 `client`와 같은 판별(`packages/platform` `browserFamily`)을 쓴다. 판별 규칙이 두 곳에서 어긋나지 않게 한 곳에 둔다. 그 판별이 모르는 앱 안 브라우저(카카오톡·네이버 앱)만 identity가 먼저 본다.
   - 둘 다 모르면 비우고(null) 화면은 '알 수 없는 기기'로 보인다. 하나만 알면 그것만 보인다.
   - User-Agent 원문과 판 번호는 저장하지 않는다. 원문은 지금처럼 법정 접속기록 줄에만 간다.
   - 세션이 끝나면 같은 트랜잭션(여러 쓰기를 한꺼번에 반영하거나 한꺼번에 되돌리는 DB 작업 단위)에서 지운다. 유휴 만료로 끝난 세션의 값은 매일 정비(`session-label-expired`)가 그 세션의 절대 만료 뒤에 지운다. 그래서 늦어도 로그인 + 30일 + 하루 안에 사라진다 [가정].
2. **마지막 활동**: 세션 행의 `last_active_at`이다. 로그인과 토큰 갱신(회전) 때 지금 시각으로 쓴다.
   - 액세스 토큰이 15분이라 활동하는 동안은 15분마다 고쳐진다. 그래서 실제 마지막 활동과 최대 15분 차이가 난다.
   - 이 칸이 생기기 전 세션은 마지막 회전 시각이나 로그인 시각으로 대신한다.
3. **목록은 기기마다 한 줄**: `GET /v1/identity/sessions`는 이 계정의 살아 있는 세션을 기기 행(`device_id`)으로 묶는다.
   - 기기 행이 없는 세션(로그인 때 기기 가명을 못 구함)은 혼자 한 줄이다. 기기 한도(POL-019 5대)와 같은 묶음 규칙이라 줄은 늘 5개 이하다.
   - 한 줄의 칸은 대표 세션 ID, 기기 이름, 마지막 활동(묶음의 가장 늦은 값), 지금 이 기기 여부, 같은 기기의 다른 로그인 수(`otherSessions`)다.
   - 대표 세션은 지금 세션이 들어 있으면 지금 세션이고, 아니면 마지막 활동이 가장 늦은 세션이다.
   - 차례는 지금 이 기기가 맨 앞이고, 나머지는 마지막 활동이 늦은 순이다. 응답은 캐시하지 않는다(`no-store`).
   - 부른 세션이 이미 끝났으면 401이다(원격 로그아웃 뒤 토큰이 남은 15분 동안 목록을 보지 못하게).
4. **원격 로그아웃**: `DELETE /v1/identity/sessions/{sessionId}`는 그 세션과 같은 기기의 살아 있는 세션을 모두 끝낸다. 지금 세션은 끝내지 않는다.
   - 소셜 재인증 토큰(`X-Reauth-Token`, 같은 세션·`FAN_SENSITIVE`, 5분 한 번)을 받아야 한다(POL-019 재인증 목록의 '다른 기기의 로그인 세션 끝내기'). 없거나 맞지 않으면 403 `reauth-required`다.
   - 지금 이 기기 줄을 보내면 지금 세션만 남기고 같은 기기의 다른 로그인을 끝낸다(2026-11-05 새 맥락 리뷰 중간 1에서 바꿈. 처음에는 409로 막았다). 같은 브라우저 저장소의 기기 값으로 로그인한 세션이 '지금 이 기기' 줄에 숨어 보이지도 끄지도 못하는 일을 막으려는 것이다. 목록의 `otherSessions`가 그 수이고, 화면은 그 수가 0보다 클 때만 [이 기기의 다른 로그인 끝내기]를 보인다.
   - 다른 계정의 세션, 끝난 세션, 없는 ID, 끝낼 다른 로그인이 없는 지금 기기 줄은 모두 같은 404 `session-not-found`다. 재인증을 확인한 뒤에야 보므로 재인증 없이는 세션 ID를 떠보지 못한다. 대상은 그 계정의 살아 있는 세션 가운데서만 찾고, 남의 세션 행은 잠그지 않는다(같은 리뷰 낮음 4).
   - 지금 세션 자체는 화면의 로그아웃(앱 서버 `POST /logout`)으로 끝낸다. 쿠키를 지우는 길이 하나로 남는다.
   - 404는 트랜잭션을 되돌려 재인증 토큰을 쓰지 않은 것으로 둔다. 목록을 다시 받고 같은 토큰으로 다른 기기를 끝낼 수 있다.
   - 끝낸 세션마다 세션 종료 사건(`control.sessions-terminated`, 이유 `LOGOUT`)을 같은 트랜잭션의 마지막 쓰기로 Outbox(보낼 사건을 DB 표에 먼저 적어 두었다가 릴레이가 Kafka로 보내는 방식)에 적는다. 끝난 세션의 화면 문구는 d5 §3.5의 '다른 기기에서 이 기기를 로그아웃했습니다'다.
   - 동시 세션 상한과의 관계: 원격 로그아웃은 줄 수와 세션 수를 줄이기만 한다. 상한을 넘을 때 오래 쉰 기기를 끄는 규칙(로그인 때)은 그대로다.
5. **로그인 수단이 바뀌면 다른 세션을 모두 끝낸다(ASVS 7.4.3)**: 그 일을 한 세션 말고 그 계정의 살아 있는 세션을 같은 트랜잭션에서 끝낸다. 새 종료 이유 `LOGIN_METHOD_CHANGED`를 쓴다.
   - 바뀌는 때는 넷이다. 설정의 추가(`LINKED`)와 해제, 계정 병합 확정(대표 계정에 흡수 계정의 수단이 옮겨 온다), 가입 때 연결 제안의 연결이다.
   - 병합에서 제안한 쪽이 흡수 계정이면 그 세션은 지금처럼 `MERGED`로 끝나고, 대표 계정의 세션은 모두 `LOGIN_METHOD_CHANGED`로 끝난다.
   - 가입 때 연결 제안의 연결에서는 그 로그인으로 막 만든 세션이 '그 일을 한 세션'이다. 그 로그인이 기기 한도를 넘어도 따로 '5대를 넘어'로 끄지 않고, 다른 세션을 모두 `LOGIN_METHOD_CHANGED`로 한 번에 끝낸다(같은 리뷰 낮음 3).
   - 이미 연결된 수단(`ALREADY_LINKED`), 같은 종류가 있어 잇지 않음, 다른 계정이라 병합 제안으로 감, 재인증 실패는 끝내지 않는다. 바뀐 것이 없기 때문이다.
   - 세션 종료 사건은 연결·해제 사건(`identity.login-methods-changed`)·병합 사건보다 먼저 적는다. 사건 쓰기는 모두 트랜잭션의 마지막 문장이다(ADR-0116 결정 3). 병합 확정은 흡수 계정의 `MERGED`와 대표 계정의 `LOGIN_METHOD_CHANGED`를 세션 상태를 모두 고친 뒤 한 번에 적는다(같은 리뷰 낮음 3).
   - 화면 SCR-040의 결과 문구에 '다른 기기에서는 모두 로그아웃했습니다'를 붙인다. 끝난 기기의 문구는 '로그인 수단이 바뀌어 이 기기에서 로그아웃되었습니다. 다시 로그인해 주세요'다.
   - 사유를 asyncapi `SessionTerminated.reason`과 Avro(Kafka 메시지 모양을 기계가 읽게 적은 형식) 열거 끝에 더한다. 모르는 옛 읽는 쪽은 `UNRECOGNIZED`로 읽는다.
6. **운영 신호**: `identity_other_sessions_ended_total{cause}`(cause `remote_logout`·`login_method_changed`)로 끝낸 세션 수를 센다. 경보는 두지 않는다 [가정].

## 결과

- 정본: identity §3·§4·§2.1·§8·§9.1·§10.1·§12, data.md(`session` 칸 둘과 인덱스 하나, §5 경합), openapi(경로 둘, 스키마 `FanDeviceSession`, 오류 이름 `session-not-found`. 처음 둔 409 `current-session`은 같은 날 뺐다), asyncapi·Avro(`LOGIN_METHOD_CHANGED`), proto 주석(User-Agent 쓰임), d5 §3.5·§5.17·§5.21·§5.22, POL-019, frontend.md §3.12 저장소 표, data-classification(기기 이름 행), asvs/auth.md를 고쳤다. 마이그레이션은 0028이다.
- 시험: I-T74(목록·원격 로그아웃), I-T75(로그인 수단을 바꾼 뒤 다른 세션 끝내기), I-T76(기기 이름 뽑기와 지우기)을 메모리 저장소와 PostgreSQL에서 본다. 화면은 node 시험으로 흐름을 본다.
- 계약 깨짐 예외: 원격 로그아웃의 재인증 머리와 세션 ID 모양(uuid)을 `docs/api/breaking/openapi-ignore.txt`에 이유와 함께 적었다. v0.2.0까지 이 경로를 구현한 서비스도 부르는 화면도 없었다. 예외가 늘어 PR에 `breaking-approved` 라벨이 필요하다.
- 대가:
  - 다른 기기를 여럿 끄려면 기기마다 재인증을 다시 받는다(토큰은 한 번만 쓴다). 기기가 5대 이하라 견딜 만하다고 본다 [가정]. '다른 기기 모두 로그아웃'(한 번의 재인증)은 쓰는 모습을 본 뒤 다시 본다.
  - 404로 되돌린 재인증 토큰은 남은 5분 동안 같은 작업 묶음(`FAN_SENSITIVE`)의 다른 작업(탈퇴, 로그인 수단 해제·추가, 계정 병합 확정)에도 통한다. 작업 묶음을 작업마다 나누지 않은 지금 규칙(docs/security/authz-matrix.md §6)의 남는 한계다. 같은 사람이 같은 세션에서 방금 다시 로그인해 받은 토큰이라 받아들인다(같은 리뷰 낮음 5).
  - 로그인 수단을 바꾸면 휴대폰 같은 다른 기기도 로그아웃되어 다시 로그인해야 한다. 드문 일이고 계정 탈취를 끊는 쪽을 골랐다.
  - User-Agent는 브라우저가 스스로 알리는 값이라 꾸밀 수 있다. 기기 이름은 사람이 기기를 알아보는 보조 정보이고, 통제에 쓰지 않는다(identity §7 '기기 식별값의 한계'와 같다).

## 다른 선택지

| 선택지 | 판단 |
| --- | --- |
| User-Agent 원문을 세션에 두고 화면에서 풀기 | 버림. 판 번호까지 남아 기기를 좁히는 값이 되고(개인정보 최소화), 화면이 받는 글이 길고 꾸밀 수 있다 |
| 기기 이름을 웹 앱 서버가 뽑아 gRPC(서비스끼리 부르는 원격 호출 방식) 칸으로 넘기기 | 버림. 규칙이 두 곳에 생기고 계약(proto)이 늘어난다. identity가 이미 원문을 받는다 |
| 세션마다 한 줄 | 버림. 같은 브라우저의 남은 세션이 여러 줄로 보이고 목록 길이에 상한이 없다 |
| 지금 세션도 이 경로로 끝내기 | 버림. 쿠키를 지우는 로그아웃 길이 둘이 된다 |
| 지금 기기 줄은 409로 막기(처음 결정) | 버림(2026-11-05 새 맥락 리뷰 중간 1). 같은 기기의 다른 세션이 그 줄에 숨어 보이지도 끄지도 못한다 |
| 로그인 수단을 바꾼 뒤 끌지 물어보기(ASVS 문장 그대로 '선택') | 버림. 묻는 창 하나가 더 생기고, 탈취된 세션을 남겨 두는 답을 고를 수 있다. 관리 계정의 비밀번호 바꾸기(`PASSWORD_CHANGED`)도 묻지 않고 끈다 |
| 마지막 활동을 요청마다 적기 | 버림. 모든 요청이 identity DB에 쓰기를 더한다. 토큰 갱신 때만 적어 15분 차이를 받아들인다 |
