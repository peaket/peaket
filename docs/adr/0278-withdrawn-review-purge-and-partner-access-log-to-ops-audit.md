# ADR-0278: 탈퇴 계정 후기는 파기하고 15분 뒤 한 번 더 정리하며, 파트너 명단 접속기록은 ops 감사 저장소로 옮긴다(2026-11-16)

- **상태**: 채택(2026-11-16, 소유자 결정 R-651 'OPEN[36]~[47] 모두 추천대로' 가운데 OPEN[42]·[43]·[44]). 세부는 추천 적용(2026-11-16, 계획 [W8-audit2a](../review/plans/W8-audit2a.md)·[W8-audit2b](../review/plans/W8-audit2b.md)). 2026-11-15 R-617이 정한 '후기 익명화(본문·평점은 남김)'와 2026-11-16 W7-audit A2-19가 정한 'core `attendee_export_audit`에 접속기록'을 바꾼다.
- **관련**: [docs/features/identity.md](../features/identity.md) §8 '후기 파기', [docs/data.md](../data.md) §2 '후기 파기'·'관리 계정 개인정보 열람·내려받기 기록', [docs/streaming.md](../streaming.md) §2.6, [docs/api/asyncapi.yaml](../api/asyncapi.yaml) `audit.data-accessed`, [docs/features/settlement.md](../features/settlement.md) §9, [docs/features/control-tower.md](../features/control-tower.md) §7, [docs/review/plans/W7-audit.md](../review/plans/W7-audit.md) §5, ADR-0086 ⑧, ADR-0116, ADR-0142, ADR-0214 결정 7
- **관련 ID**: FR-017, FR-027, FR-064, POL-023, I-T83, J-T26 ⑤⑥, C-T19 ①~⑤, ASVS v5.0.0-14.2.7·16.2.1·16.4.2

## 맥락

- 탈퇴한 회원의 관람 후기를 두고 정본끼리 어긋났다. docs/features/identity.md §8(R-617)은 "본문·평점은 법정 보존·분쟁 대응을 위해 남기고 계정·주문 참조만 끊는다"였고, docs/data.md §6 '관람 후기'·data-classification '관람 후기'·planning/03 권한표·ADR-0086 ⑧은 파기였다. 후기 본문을 남길 법정 근거는 정본에 없고(법정 차단 조치 증적은 `takedown_action`이 3년 따로 둔다), 본문에는 작성자나 다른 사람의 개인정보가 섞여 들 수 있다(W7-audit 웨이브 끝 보안 리뷰 S2).
- core-svc는 탈퇴 사건을 받자마자 후기를 정리한다. 탈퇴 전에 받은 액세스 토큰(최대 15분)으로 그 뒤에 쓴 후기는 그 계정의 사건이 다시 오지 않아 영영 남는다(동시 실행 리뷰 K3). 같은 사건을 읽는 queue-svc는 같은 까닭으로 `withdrawnAt` + 15분에 처리한다(ADR-0214 결정 7).
- 파트너 예매자 명단 보기·내려받기 접속기록은 core 논리 DB의 보통 표 `attendee_export_audit`였다. 정본의 관리 계정 접속기록 저장소는 ops-svc 감사 저장소 `admin_data_access`(해시 체인, FR-064 매일·매월 점검이 읽는 곳)인데, core 표에는 고친 것을 찾아낼 장치가 없고 점검이 읽지 않았다. 고시 제8조는 접속기록의 점검과 위·변조 방지를 요구한다(보안 리뷰 S1).

## 결정

1. **탈퇴 계정 후기는 파기한다(OPEN[42])**: 본문·별점·내용 지문·작성자 표시를 비우고 상태를 DELETED로 바꿔 공개 목록·요약에서 뺀다. 계정·주문 참조는 그 후기 ID로 바꿔 끊는다. 대상은 그 계정의 모든 후기(보이는 것, 가린 것, 작성자가 이미 지운 것)다. 작성자가 지울 때도 같은 칸을 비운다(ADR-0086 ⑧ 그대로). 칸 목록과 마이그레이션 나눔(별점·지문의 NOT NULL을 풀고 살아 있는 행 CHECK는 `NOT VALID`로, 파기 행 CHECK는 다음 출시)은 docs/data.md §2 '후기 파기'다.
2. **탈퇴 + 15분 뒤 한 번 더 파기한다(OPEN[44])**: 탈퇴 사건을 처리하는 트랜잭션에서 파기와 함께 '다시 정리 예약'(`review_withdrawal_recheck`, 계정 ID·예약 시각)을 쓴다. 예약 시각은 min(`withdrawnAt`, 처리 시각) + 16분이다(토큰 최대 15분에 처리 중이던 쓰기 요청이 끝날 여유 1분 [가정]). core-svc 소비자 파드의 반복이 60초 [가정]마다 때가 된 예약을 `FOR UPDATE SKIP LOCKED`로 잠가 다시 파기하고 예약을 지운다.
3. **파트너 명단 접속기록은 ops 감사 저장소로 사건을 보내 옮긴다(OPEN[43])**: core-svc가 명단 보기 한 페이지·내려받기 한 번마다 사건 `DataAccessed`(토픽 `audit.data-accessed`, 키 행위자 계정 ID)를 명단·파일을 주기 전에 같은 트랜잭션의 core Outbox에 쓴다(Outbox를 쓰지 못하면 주지 않는다). ops-svc가 자기 그룹으로 받아 `admin_data_access` 행과 감사 체인 기록을 한 트랜잭션에 쓴다. 사건의 `eventKey`가 행 ID라 다시 받아도 한 행이고, 같은 `eventKey`에 다른 내용이면 보류한다. FR-064 점검은 기간 [시작, 끝)의 행을 읽는다.
4. **체인 기록에는 행 해시만 싣는다**: 감사 체인 기록(`ADMIN_DATA_ACCESS_RECORDED`)의 내용은 행의 정규화 JSON SHA-256 하나다. 접속지·커서 원문을 체인에 복사하지 않고, 체인 검증의 원본 대조가 지금 행으로 해시를 다시 계산해 고친 행을 찾는다.
5. **core `attendee_export_audit`은 더 쓰지 않는다**: 이전 판 코드가 배포 창 동안 쓰도록 표와 권한을 남기고 다음 출시 마이그레이션이 지운다. 운영 전이라 옮길 행이 없다. 접속기록 사건에는 행위자의 표시 이름을 싣지 않는다(식별자는 계정 ID).

## 버린 대안

- **후기를 익명화해 남김(R-617)**: 남길 법정 근거가 정본에 없고 정본 넷과 어긋난다. 본문·사진에 든 개인정보가 남는다.
- **15분 뒤 정리 대신 게이트웨이의 끝난 세션 막기(HOT-400)를 기다림**: 그 전까지 후기가 계정 참조를 가진 채 남고, HOT-400이 생겨도 사건과 쓰기의 순서가 바뀌는 경우를 덮지 못한다.
- **15분 늦춤을 사건 처리 자체를 미뤄서 함(queue-svc 방식)**: 첫 파기가 15분 늦어진다. 결정은 '한 번 더'다.
- **15분 늦춤을 relay 정비 일로 함**: platform 정비 반복은 하루 한 번 일만 다룬다(10분마다 깨어나도 하루 한 번 성공하면 끝). 고치면 다른 서비스의 정비 지표 규칙이 흔들린다.
- **core가 ops 내부 API를 바로 부름**: 명단 보기의 가용성이 ops-svc(독립 제어 평면)에 묶인다. Outbox는 core 트랜잭션 하나로 기록을 지키고, ops가 멈춰도 사건이 쌓였다 나간다.
- **core 표에 해시 체인과 월 점검 읽기를 붙임**: 감사 저장소가 둘이 되고, FR-064 점검이 두 곳을 읽어야 한다.
- **기한을 정해 위험을 받아들임**: 법정 점검·위변조 방지 의무를 미룬다.
- **체인에 행 원문을 그대로 실음**: 행을 보존 기한 뒤 지워도 접속지 원문이 체인에 남는다.

## 결과

- 탈퇴한 계정의 후기가 바로, 그리고 15분 뒤 한 번 더 파기된다. 작성자 지우기도 정본(ADR-0086 ⑧)과 맞는다.
- core-svc에 처음으로 Outbox에 쓰는 모듈이 생기고, `core_partner`가 `outbox`에 넣기만 한다. ops-svc에 소비자 그룹 하나와 `admin_data_access` 표가 생긴다.
- 접속지 IP·계정 ID가 core Outbox(3일 [가정])·Kafka(7일)·ops 보류 표를 지난다. 이 사본도 접속기록과 같은 보호를 따른다(docs/security/data-classification.md '관리자 시스템 접속기록').
- 남는 한계: 탈퇴 사건이 보류되면 파기와 예약이 없다(W7-audit 리뷰 S7). 체인의 키 건 해시(mac)·체인 작업자·ops DB 역할 나누기는 BUILD_ORDER OPS-270, FR-064 매일 탐지 일의 서버 몫은 W8-audit2b 계획이 더할 새 단계(OPS-275, 갈래 2)다. 지운 행의 해시를 대입으로 맞춰 볼 수 있는 것은 행 지우기 일이 생길 때 다시 본다.

## 되돌릴 조건

- 법률 검토(wbs 7.4.1)가 후기 본문을 분쟁 대응용으로 보존해야 한다고 보면 결정 1을 다시 정한다(파기 칸 가운데 본문만 보존 전용 스키마로 옮기는 등).
- 다시 정리 반복이 core API 파드의 DB 연결을 눈에 띄게 빼앗거나(밀린 예약이 늘거나), 액세스 토큰 수명이 15분에서 바뀌면 결정 2의 시각·자리를 다시 본다.
- ops-svc 소비 지연으로 접속기록이 FR-064 매일 탐지에 늦게 드는 일이 하루를 넘으면 결정 3의 길을 다시 본다.

## 확인

- W8-audit2a가 끝나면 I-T83 ①~⑦의 결과를, W8-audit2b가 끝나면 J-T26 ⑤⑥·C-T19 ①~⑤의 결과를 여기에 적는다.
