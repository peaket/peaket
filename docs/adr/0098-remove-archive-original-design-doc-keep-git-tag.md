# ADR-0098: 원문 설계서(archive/)를 지우고 git 태그 `archive-original`로만 남긴다 — 원문은 판단 근거로 쓰지 않는다(2026-10-27)

- **상태**: 채택 (2026-10-27. 소유자가 "전체 문서들이 계속 원문 학습 지도를 토대로 판단을 하려고 하는 경향이 있는데 archive로 보낸 문서는 이제 필요없지 않나요? 다른 문서들이 이미 내용을 대체하고 있잖아요. … archive를 이제 삭제해도 되지 않을까요?"라고 물었다. 검토 의견(review/tech-review.md §12.2)을 본 뒤 "archive/는 git 태그를 달고 지워 주세요. 원문 링크 68개는 글자로 바꾸고, CLAUDE.md에서 고칠 문장은 먼저 보여 주세요."라고 정했다. 지우는 것, 태그, 링크를 글자로 바꾸는 것은 소유자 결정이고, 태그 이름과 점검 도구 처리 같은 세부는 추천 적용이다. CLAUDE.md는 소유자가 문장을 확인한 뒤 고친다). 2026-10-27: 소유자가 제안 문장을 확인하고 "CLAUDE.md 3번째 줄의 원문 설계서 문장을 제안한 문장(학습 목록 문장 포함)으로 고쳐 주세요."라고 해, CLAUDE.md의 원문 문장을 '원문 설계서는 2026-10-27에 지웠고 git 태그 `archive-original`에만 남아 있다. 원문과 학습 목록(1~33장)은 판단 근거로 쓰지 않고, 기술을 고른 이유는 ADR과 정본 문서로만 댄다'로 고쳤다(결정 6 끝남).
- **관련**: ADR-0074, ADR-0084, ADR-0090, ADR-0097, 00-summary §2·§7 질문 59, [review/open-items.md](../../review/open-items.md) 38번, [review/tech-review.md](../../review/tech-review.md) §12.2, tools/doc-check

## 맥락

- **무엇이 있었나**: archive/에는 2026-10-08에 동결한 원문 설계서 파일 하나가 있었다. 고치지 않는 원문이고, 새 문서가 말하는 '설계서 §N'과 '원문 §N'의 원본이었다.
- **새 문서가 이미 대신한다**: 원문의 외부 링크 70개는 모두 새 문서에 있다(원문 대조 `check_all.py --coverage`, 2026-10-27). 원문 문장을 어디로 옮겼는지는 00-diagnosis §3 매핑표에 있다.
- **원문을 가리키던 곳**:
  - 문서 19개의 머리 '원문 출처' 줄에 원문으로 가는 링크 68개가 있었다.
  - CLAUDE.md, 00-summary §2, planning/03 §5에 '원문은 동결했으며 고치지 않는다'는 규칙이 있었다.
  - 문서 점검의 `--coverage`가 archive/ 폴더를 읽었다.
- **소유자가 본 문제**: 문서들이 원문(학습 지도)을 토대로 판단하려는 경향이 있다. 그 경향은 근거 칸의 장 번호와 '원문 이어받음'으로 남은 결정에서 나왔다. 장 번호는 ADR-0097로 고쳤다.

## 결정

1. **원문 설계서를 지운다(소유자 결정).**
   - 지우기 전 마지막 커밋(develop 4e7b1ce)에 주석을 단 git 태그 `archive-original`을 달았다. 태그 안의 원문은 작업 폴더의 파일과 같은 내용이다(blob 92be0d2).
   - 원문은 이 태그로만 꺼낸다. 예: `git show "archive-original:archive/PEAKET(피켓) — 100만 동시접속 티케팅 + 관제 시스템 프로젝트 설계서.md"`.
   - 이 태그는 릴리스 태그(`vX.Y.Z`, ADR-0074)가 아니다. 같은 커밋에는 ADR-0097로 지운 학습 지도 부록도 들어 있다.
2. **원문 링크 68개는 링크를 떼고 글자로 둔다(소유자 결정).** '[설계서 §8 <용량 산정>](…archive…)'은 '설계서 §8 <용량 산정>'이 된다. 제목과 본문의 '(원문 §N)'·'설계서 §N' 글자는 그대로 둔다. 이 글자들의 원본이 태그에 있다는 것은 00-summary §2에 적는다.
3. **원문은 판단 근거로 쓰지 않는다(소유자 결정).** ADR-0097의 원칙(학습 목록에 끼워 맞추지 않는다)을 원문 전체로 넓힌다. 새 판단은 정본 문서와 ADR의 근거로만 한다. '원문 이어받음'으로 남은 결정은 기술 검토 항목으로 근거를 새로 댄다.
4. **문서 점검 도구(추천 적용).** `--coverage`는 archive/ 폴더가 없으면 git 태그 `archive-original`에서 원문을 읽는다. 태그가 없는 복제본에서는 '원문 없음' 경고만 낸다. 경고의 위치 표시는 'archive L…'에서 '원문 L…'로 바꿨다.
5. **고치지 않는 것.** ADR 본문, 00-diagnosis.md, review의 지난 기록에는 archive/를 가리키는 글자가 남는다(링크는 없다). 소유자 도구 tools/reader/(build.py·manifest.json)는 소유자가 정리한다.
6. **CLAUDE.md.** '재구성 전의 원문 설계서는 `archive/`에 동결했으며 고치지 않습니다' 문장은 소유자가 바꿀 문장을 확인한 뒤 고친다.
7. **정본 반영.**
   - 00-summary: §1 머리, §2(보관 행, 원문 설계서 대조자 행, 원문 설명 문단), §7 질문 3·59, §8 유지보수 규칙.
   - planning/03 §5 문서 쓰기 규칙의 적용 범위 문장.
   - 문서 19개의 '원문 출처' 줄(링크 68개).
   - tools/doc-check(check_all.py, README).
   - 기록: review/open-items.md 38번, review/tech-review.md §12.2, review/consistency-review.md §1·R-116, docs/architecture.md §11.
   - ADR-0097은 상태 줄에만 적는다.

## 검토한 대안

| 대안 | 기각 이유 |
| --- | --- |
| 그대로 두고 CLAUDE.md에 '판단 근거로 쓰지 않는다'만 적는다 | 할 일은 적지만, 원문을 근거로 다시 끌어오는 일을 규칙으로만 막는다. 소유자가 지우기로 정했다 |
| 태그 없이 지운다 | git 이력에는 남지만 커밋 번호를 찾아야 꺼낼 수 있다. 태그 이름으로 바로 꺼내게 한다 |
| 원문 링크를 태그 주소로 바꾼다 | 원격 저장소가 없어 열리는 주소가 없다. 글자로 두면 출처 표시는 남는다 |
| `--coverage`를 없앤다 | 원문을 옮겨 쓰는 일이 다시 생기면 쓸 수 있고, 태그에서 읽게 하는 데 코드 몇 줄이면 된다 |

## 결과와 트레이드오프

- 저장소에서 원문이 사라져, 새 판단이 원문에 기대는 길이 줄어든다. 저장소의 문서는 planning·design·docs·review·wbs와 해설서 guide만 남는다.
- 대가:
  - 원문을 보려면 git 명령이 필요하다.
  - 원격 저장소가 없어서 태그는 이 PC의 저장소에만 있다. 원격 저장소를 만들면 태그도 함께 올린다(`git push <원격 이름> archive-original`).
  - '원문 출처' 줄의 글자는 남지만 바로 열리지 않는다.

## 되돌릴 조건

- 원문을 자주 봐야 하는 일이 생기면 `git checkout archive-original -- archive/`로 되살린다. 되살려도 판단 근거로는 쓰지 않는다.

## 남는 한계

- ADR 본문과 지난 기록은 archive/를 가리키는 글자를 그대로 둔다.
- '원문 이어받음'으로 남은 결정의 근거를 새로 대는 일은 이 결정으로 끝나지 않는다(review/tech-review.md 높음-05~08 등).
