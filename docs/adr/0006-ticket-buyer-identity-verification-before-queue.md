# ADR-0006: 입장권 구매자 본인확인은 모든 정렬 방식에서, 순번을 받기 전에

- **상태**: 채택 (2026-10-08). ADR-0050(2026-10-13)이 pid를 'KMS 비대칭 키'가 아니라 별도 KMS HMAC 키(대칭)로 다시 해시한 값으로 바로잡고, 연계정보 키 버전 조회와 pid 저장 규칙을 더한다. ADR-0055(2026-10-13)가 결정 6의 재확인 시점(주문 생성 때 한 번)과 identity-svc가 응답하지 못할 때의 판정(토큰의 본인확인 표시)을 보완한다 2026-10-14: SCR-006은 별도 화면이 아니라 본인확인 흐름(부르는 화면의 버튼이 여는 기관 창, 결과 대화상자, 페이지 이동형 기관만 쓰는 복귀 화면)이 되었다(ADR-0063 결정 5). 본인확인 시점과 규칙은 그대로다. 2026-10-26(4차 점검 3부): 결정 5의 '오픈 알림 카카오톡/푸시'는 웹 푸시·이메일로 읽는다(FR-004, design/d5 §9.1. 알림톡은 ADR-0060 결정 13대로 정해진 알림에만 발송 대행 계약 뒤 쓴다). 결과의 '완벽히 충족한다'는 '간주한 사항'(계정당 1회 연계정보 바인딩을 법정 본인확인의 충분조건으로 봄)을 전제로 한 판단이다. '물리 차단된다'는 같은 사람이 여러 계정으로 순번을 늘리는 것을 막는다는 뜻이고, 명의를 빌린 계정(ADR-0050 결정 5)과 탈퇴 뒤 중복 확인 키를 지운 사람이 같은 공연에 다시 줄 서는 경우(ADR-0087 결정 18)는 남는다(docs/features/identity.md §5).
- **관련**: 설계서 섹션 0 '준수 기준'(공연법), 섹션 6 '계정·인증'·'암표 방지 법정 조치', 섹션 7(정렬 방식), ADR-0001(팬 소셜 로그인), ADR-0005(입장 확정), `docs/security/data-classification.md` 13~15번
- **관련 ID**: FR-002, FR-005, FR-006, FR-020, POL-001, POL-002, POL-024, NFR-016, NFR-018, SCR-006

## 맥락

- **법률이 모든 구매자에 대한 본인 확인을 강제한다.** 공연법 제4조의2제2항 및 동법 시행령 제3조의3제1호가목(2026-08-28 시행)은 정보통신망을 통해 입장권을 판매하는 사업자에게 구매자 본인 확인 의무를 규정했다. 시행령 부칙 제3조에 따라 기존 판매자는 시행 후 1개월 이내에 관련 조치를 완비해야 한다.
- **초기 설계는 셔플 모드 공연에만 본인확인을 요구했다.** FIFO 순차 선착순 공연 및 하이브리드 모드의 오픈 후 도착자는 본인확인 없이도 예매가 가능한 결함이 존재했다.
- **법령은 구체적 확인 방식·시점·재인증 주기를 명시하지 않았다.** 시행령 원문 및 문화체육관광부 공식 보도자료/Q&A(2026-08-28)에서도 세부 규정이 위임되지 않았다.
- **대기열 정렬 방식에 따라 암표 봇의 공격 기법이 상이하다.** 셔플 모드에서는 계정 수량(추첨권 수)이 공격 수단이며, FIFO에서는 물리적 진입 속도가 무기이다. 본인확인 절차는 계정 수량을 실제 자연인 인원수로 엄격히 수렴시킨다.
- **유효 입장 자리는 첫 예매 API 요청 시점에 원자적으로 배정된다(ADR-0005).** 미인증 다계정이 대기 순번을 발급받게 되면 입장 자리까지 불필요하게 점유한 뒤 결제 단계에서야 걸러지는 심각한 지연 병목이 초래된다.

## 검토한 대안

| 대안 | 문제 |
| --- | --- |
| 1. 셔플 모드 한정 본인확인(초기 설계) | 법정 의무 위반 소지 발생. FIFO 공연 및 오픈 후 일반 도착자가 검증 대상에서 누락됨 |
| 2. 결제 단계 진입 시 본인확인 | 결제 직전 확인으로 법정 최소선은 맞출 수 있으나, 미인증 다계정이 대기열 순번과 입장 자리를 독점 선점한 후 이탈하며 외부 KCB/NICE 호출이 결제 시점에 폭주함 |
| 3. 회원가입 시 전원 의무 본인확인 | 단순 공연 탐색 및 알림 수신만 이용하는 일반 방문자의 연계정보(CI)까지 과도하게 수집하여 개인정보 최소 수집 원칙에 위배됨 |
| 4. 매 공연 예매 시마다 본인확인 | 매 티케팅마다 본인인증 부하가 발생하고 티켓 오픈 직전 외부 PG/인증사 트래픽이 폭주함. 법령상 공연별 반복 인증을 요구하는 법적 근거 부재 |
| **5. 대기 순번 발급 전 계정당 1회 + 결제 시 자격 상태 재검증 (채택)** | 최초 예매 시도 사용자의 진입 퍼널이 1단계 증가함. 티케팅 오픈 전 사전 인증 안내 UI/UX로 완충 |

## 결정

1. **모든 티켓팅 진입 경로에서 대기 순번 발급 전에 본인확인을 필수 완결한다.** 입장권 구매자는 대기열 정렬 정책(셔플·하이브리드·FIFO)과 무관하게 대기 순번을 부여받기 전에 본인확인을 완료해야 한다. 세일 오픈 전 대기실 진입과 오픈 후 선착순 대기열 진입에 동일한 규칙을 관철한다.
2. **원칙적으로 계정당 1회 수행한다.** 통신사 휴대폰 본인확인을 통해 수신한 연계정보(CI)의 일방향 암호화 HMAC 값을 계정에 귀속시켜 1인 1계정 정책을 확립한다.
3. **트래픽 집중 진입 경로에서는 암호화 서명만 무상태 검증한다.** 본인확인 완료 여부는 identity-svc가 발급하는 JWT 액세스 토큰 내 구매 권한 클레임(`ticket:buy`)으로 증명된다. 오픈(T=0)를 포함한 고부하 진입 경로에서는 API 게이트웨이가 토큰 서명과 권한만 로컬 검증하며(ADR-0008), 외부 인증사 통신 I/O를 핫패스에 절대 배치하지 않는다.
4. **엄격한 1인 1순번 규칙을 강제한다.** 대기열 순번 중복 발급 검증 키는 단순 계정 ID가 아니라 연계정보에서 안전하게 유도한 고유 자연인 식별자(`pid`. CI HMAC을 전용 KMS 비대칭 키로 재해싱하여 토큰에 탑재, ADR-0011)를 기준으로 한다. queue-svc는 진입 검증 시 identity-svc와 동기 통신하지 않고 토큰 내 `pid` 클레임을 원자적으로 조회한다.
5. **사전 인증 경로를 다각도로 제공하며, 미인증자는 진입 시점에 즉시 안내한다.** 순번 발급 전이라면 언제든 사전 인증이 가능하다. 제공 경로는 계정 설정(상시), 회원가입 완료 화면(선택 권유), 공연 상세 페이지(실시간 상태 배지 및 '지금 본인확인' CTA), 오픈 알림 카카오톡/푸시(미인증자 전용 링크)이다. 사전 미인증 사용자가 대기실/대기열 진입을 시도할 경우 즉시 본인확인 인증창으로 리다이렉트한다. 오픈 후 최초 인증을 마친 사용자는 인증 완료 시점의 실도착 순서에 따라 대기 순번을 부여받는다.
6. **최종 결제 트랜잭션 시 상태를 재확인한다.** 주문서 작성 및 결제 승인 시 주문 계정의 본인확인 유효 자격을 철저히 재검증한다.
7. **재인증 절차는 추가 검증 큐 격리 대상에 한해 조건부로 발동한다.** 신규 기기 접속, 계정 탈취 의심 등 이상 징후는 trust-svc 위험 점수(Risk Score)에 누적 반영되며, 고위험군으로 판정된 계정은 추가 검증 큐(설계서 섹션 7 결정 5)로 우회되어 정밀 인간 검증(Turnstile 등) 및 휴대폰 본인확인을 재수행한다. 핫패스 진입 경로 자체에는 외부 본인확인 I/O를 두지 않으므로(결정 3) 단순 신규 기기 접속이라는 단일 사유만으로 진입 시점에 일괄 재인증을 요구하지 않는다. 계정당 1회 인증으로 법적 효력이 충분한 것으로 전제하므로(하단 간주 사항) 정기적 만료 재인증은 적용하지 않는다.
8. **공연법 적용 예외 대상인 티켓 상품에도 동일한 1인 1순번 규칙을 일관 적용한다.** 문체부 Q&A 가이드라인에 따라 일반 팬미팅 등은 공연법 적용 대상에서 제외될 수 있으나, 플랫폼 거버넌스 단순성과 공정성을 확보하기 위해 모든 유료 입장권 티케팅에 단일 룰을 적용한다. 단, 일반 굿즈/MD 상품은 입장권이 아니므로 기존 커머스 정책(계정당 수량 제한 및 이상 결제 탐지)을 유지한다.

## 결과

- **공연법 시행령 법정 의무(가목)를 모든 티케팅 판매 파이프라인에서 완벽히 충족한다.**
- **셔플 추첨 방식의 최대 취약점인 '다계정을 동원한 확률 왜곡'이 실제 자연인 수량으로 물리 차단된다.** 공격자가 취할 수 있는 잔여 수단은 타인 명의 도용 및 불법 대여로 좁혀진다. 암표 재판매 목적의 명의 대여/도용 행위는 공정한 예매 절차를 방해한 부정구매로 형사처벌 대상이며, 법정 접속기록 데이터베이스를 통해 사법기관에 소명 자료를 제공한다.
- **연계정보(CI) 수집·관리 대상이 전체 예매 사용자로 확장된다.** 이에 따라 연계정보 이용기관 준수 의무 및 기술적·관리적 보호조치(정보통신망법 §23의6)를 철저히 이행한다.
- 트레이드오프: 최초 예매 사용자의 진입 퍼널에 인증 단계가 추가된다. 세일 개시 후 인증을 시작할 경우 인증 소요 시간만큼 대기 순번이 후순위로 밀릴 수 있다.
- 트레이드오프: 외부 본인확인 대행사(KCB/NICE 등)에 전산 장애가 발생할 경우, 사전 미인증 사용자의 신규 진입이 일시 차단된다. 단, 사전 인증을 완료한 대다수 정상 사용자는 전혀 영향을 받지 않는다.

## 간주한 사항 (프로젝트 아키텍처 원칙, 2026-10-08)

공연법 시행령 원문 및 주무부처 Q&A에서 본인 확인의 기술적 방식과 유효 주기를 구체화하지 않았으므로, 엔지니어링 실행을 위해 다음 사항을 합리적 기준으로 전제한다.

- 계정당 1회 연계정보(CI) 바인딩을 법률이 요구하는 '구매하는 자에 대한 본인 확인'의 충분조건으로 간주한다.
- 인증 수단은 공인 통신사 휴대폰 본인확인 단일 체계로 일원화한다.

## 재검토 조건

- 주무관청(문화체육관광부 등)이 본인 확인의 세부 절차, 기술 표준, 갱신 주기를 행정고시 또는 유권해석으로 제정할 때
- 오픈 후 현장 본인확인 시도로 인한 순번 밀림 CS 불만이 시스템 허용 임계치를 초과할 때(섹션 7 검증 지표)
- 차명 계정 대여 및 대규모 명의 도용 패턴이 고도화될 때
