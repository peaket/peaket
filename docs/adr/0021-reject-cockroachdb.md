# ADR-0021: CockroachDB 도입 검토 및 실험 후 기각 결정

- **상태**: 채택 (2026-10-05 설계서 §13, 25장, 33장에 최초 수립, 2026-10-08 아키텍처 결정 레코드(ADR)로 공식 이관). 실험 수치는 작성 예정. 2026-10-26(4차 점검 3부): 결정 3의 실험 2개(좌석 홀드 경합 벤치마크, 3리전 리전 장애 생존 측정)는 WBS와 docs/architecture.md §9.4 PoC 목록에 없어 아직 일정이 없다. 포트폴리오 기간의 클라우드 측정은 ADR-0057 결정 11의 선택 보정 두 가지뿐이다. 2026-10-27(ADR-0097): 결정 3의 실험 두 가지와 '33장 합의 학습'은 하지 않는다. 학습 목록 항목을 채우려던 일이라, 학습 목록에 끼워 맞추지 않는다는 소유자 원칙에 따라 일정에 넣지 않는다. 기각 근거는 맥락의 단일 리전·쓰기량·3리전 요건·라이선스이고, docs/architecture.md §6.1 '일부러 쓰지 않거나 미룬 기술' 표에 '문서 근거로 기각'으로 적었다. 2026-10-28(기술 검토 낮음-137, 소유자 승인 '추천안 동의'): 제목의 '실험 후 기각'은 '문서 분석으로 기각'으로 읽는다. 상태 줄 첫머리의 '실험 수치는 작성 예정'과 결과의 '실험 수치를 이 ADR에 첨부한다(작성 예정)'는 없어진 약속이고, 결정 3의 'Raft range 복제는 33장 합의 학습에 쓴다'도 하지 않는다. 2026-11-01(정합 점검, ADR-0177 해설서 검토 네 번째 묶음): 맥락의 '주문·결제 원장 RPO 24시간 이내'는 잴 때까지의 지금 값으로 읽는다. 대사 배치를 만들 때(wbs 2.7.4) 대형 온세일 하루치 결제 사건을 결제사 거래 조회로 맞추는 시간을 재고, 그 시간이 복구 목표 안에 들지 않으면 교차 리전 스냅샷을 4시간 [가정]마다로 줄인다(ADR-0152 결정 4, docs/infra.md §6).
- **관련 문서**: 설계서 §13(기술 스택), 25장(NewSQL 특성), 33장(합의 알고리즘), ADR-0014, ADR-0028, ADR-0031
- **관련 ID**: NFR-003, NFR-015, NFR-021

## 맥락
- 피켓은 단일 리전(AWS 서울)을 기반으로 서비스되며, 양도 및 거래 쓰기 트래픽의 규모는 수평 분산 데이터베이스 없이도 PostgreSQL 단일 Writer로 감당 가능한 수준이다(ADR-0028).
- CockroachDB로 리전 장애를 견디려면 데이터베이스 리전이 최소 3개 필요하고, 분산 합의(Raft)로 쓰기 지연이 가장 가까운 리전 왕복 시간만큼 늘어난다([CockroachDB 문서](https://www.cockroachlabs.com/docs/stable/multiregion-survival-goals)).
- 2024년 11월부터 무료 Core가 없어지고 매년 갱신하는 Enterprise Free 라이선스로 바뀌어([InfoQ](https://www.infoq.com/news/2024/09/cockroachdb-license-concerns/)) 장기적인 라이선스 리스크가 생겼다.

## 결정
1. 프로덕션 운영 환경의 주문 및 판매 원장 데이터베이스로는 CockroachDB를 채택하지 않고, Aurora PostgreSQL을 단일 리전 주 데이터베이스로 사용한다.
2. 수평 확장이 필요한 상황은 분산 DB 도입 대신 셀 단위 확장(ADR-0028)으로 해결한다.
3. CockroachDB는 PoC 실험 2개로만 활용한다: 좌석 홀드 경합 벤치마크(Redis·PostgreSQL·CockroachDB), 3리전 클러스터에서 리전 장애 생존 시 쓰기 지연과 장애 동작 측정. Raft range 복제는 33장 합의 학습에 쓴다.

## 검토한 대안
| 대안 | 기각 사유 및 한계점 |
| --- | --- |
| CockroachDB를 주문·판매 원장에 전면 도입 | 3리전 구성 강제, 쓰기 지연 가산, 라이선스 비용 대비 이득이 없다. |

## 결과와 트레이드오프
- Aurora PostgreSQL 단일 리전 다중 AZ 구성 + 셀 단위 확장(ADR-0028)으로 단순하고 성능이 예측 가능한 트랜잭션 환경을 확보한다. 실험 수치를 이 ADR에 첨부한다(작성 예정).
- 크로스 리전 자동 액티브-액티브 장애 조치는 지원되지 않으므로, 리전 전체 장애 시에는 ADR-0031의 절차(판매 중단 → 일일 교차 리전 스냅샷 기반 복원, 주문·결제 원장 RPO 24시간 이내, RTO 24시간 이내, infra §6·RB-18)를 따른다.
