# ADR-0032: 관리형 무료 티어 조합을 활용한 온콜·알림·외부 상태 페이지 도구 체인 채택

- **상태**: 채택 (2026-10-09 수립, 소유자 위임으로 추천안 채택. 2026-10-19 ADR-0066: 소비자 웹 '판매 일시 중단' 화면의 상태 페이지 링크 이름을 '복구 소식 보기'로 바꾸고 "피켓이 멈춰도 열리는 별도 안내 페이지" 설명을 붙였다(결정은 그대로).)
- **관련 문서**: docs/observability.md §4·§5·§10, docs/infra.md §10, POL-022
- **관련 ID**: POL-022, NFR-023, FR-029

## 맥락
- 원문은 온콜(On-call) 호출, 메신저 알림, 인시던트 티켓 연동, 외부 상태 페이지(Status Page), 데드맨 스위치(Dead Man's Switch)가 있어야 한다고만 하고 구체적인 도구를 정하지 않았다.
- 관측 스택(Prometheus, Alertmanager, Grafana)이 클러스터와 함께 죽어도 사람을 부르고 대외 공지를 할 수 있어야 하므로, 호출·데드맨·상태 페이지는 클러스터 밖의 독립 서비스에 있어야 한다.
- 2026-10-09 확인:
  - Grafana OnCall OSS는 2025-03-11 유지보수 모드에 들어가 2026-03-24 보관(archive) 처리됐다.
  - Grafana Cloud 무료 등급은 IRM(온콜 일정·알림·인시던트) 월 활성 사용자 3명까지다. Synthetic Monitoring은 월 API 점검 10만 회, 브라우저 점검 1만 회다.
  - Healthchecks.io 무료 등급은 점검 대상 20개다.
  - Upptime은 GitHub Actions로 5분마다 점검하고 정적 상태 페이지를 만든다.

## 결정
클러스터 외부 독립성을 보장하고 도구 비용을 0원으로 두기 위해 관리형 무료 등급 도구를 역할별로 조합한다.

| 역할 | 도구 | 이유 |
| --- | --- | --- |
| 호출·온콜 일정·인시던트 | Grafana Cloud IRM(무료 등급) | Grafana·Alertmanager와 바로 이어지고 1인(가상 팀 3명 이하)에 무료 한도로 충분 |
| 메신저 | Slack(일반 알림 채널 `#alerts`, SEV1 인시던트 채널 `#war-room`) | 알림 연동이 가장 흔함 |
| 티켓 | GitHub Issues | 코드·포스트모템 액션 아이템과 같은 곳에서 관리 |
| 데드맨 스위치 | Healthchecks.io(무료 등급) | Alertmanager Watchdog 알림을 ping URL로 받고 끊기면 운영자에게 알림 |
| 외부 합성 점검 | Grafana Synthetic Monitoring(무료 등급) | 온세일 1분·평시 5분 주기가 무료 한도 안(observability §10) |
| 상태 페이지 | Upptime(GitHub Pages) | 클러스터 밖 정적 호스팅이라 장애 중에도 열림 |

## 검토한 대안
| 대안 | 기각 사유 및 한계점 |
| --- | --- |
| Grafana OnCall OSS 클러스터 내부 자체 호스팅 | 2026-03-24 보관 처리됐고, 클러스터 안에 두면 관측 스택과 함께 죽어 대역 외 호출 목적에 어긋난다. |
| PagerDuty 등 유료 온콜 | 요금 페이지를 확인하지 못했다(2026-10-09 조회 실패). 개인 예산에서는 무료 조합으로 충분하다. |
| 상태 페이지를 앱 안에 호스팅 | 장애 중에 상태 페이지까지 함께 접속이 안 될 수 있다. |

## 결과와 트레이드오프
- 운영 도구 비용 0원으로 클러스터 밖 호출·감시·공지를 갖춘다.
- 대가: 무료 한도(IRM 3명, Synthetics 월 10만·1만 회, Healthchecks 20개)를 넘으면 유료 등급이나 다른 도구로 옮겨야 한다. Upptime의 점검 주기(5분)는 온세일 감시에 느리므로 온세일 감시는 Synthetic Monitoring이 맡는다.
- 되돌릴 조건: 가상 팀이 실제 팀이 되어 온콜 인원이 3명을 넘으면 IRM 유료 등급 또는 다른 온콜 도구를 새 ADR로 고른다.
