# ADR-0134: 기술 검토 낮음 항목의 문서 수정 묶음 2 — 데이터·보안·스트림·관측·대기열·좌석·결제·봇(2026-10-28)

- **상태**: 채택 (2026-10-28. 기술 검토(review/tech-review.md)의 낮음 항목(영역: 데이터·검색·보안 문서, 스트림·분석·포렌식, 관측·검증·관제, 대기열·좌석·결제·봇)에 소유자가 "나머지 건수들은 모두 추천안에 동의합니다. 그렇게 모두 수정해주세요."라고 정했다. 방향은 소유자 결정(추천안 승인)이고, 검토가 안을 고르지 않은 곳의 선택과 값 같은 세부는 추천 적용이다. 측정 전 값은 [가정]으로 표시했다)
- **관련**: review/tech-review.md(낮음-033·낮음-034·낮음-035·낮음-036·낮음-037·낮음-038·낮음-039·낮음-040·낮음-042·낮음-044·낮음-045·낮음-046·낮음-047·낮음-048·낮음-049·낮음-050·낮음-051·낮음-052·낮음-053·낮음-054·낮음-055·낮음-056·낮음-057·낮음-058·낮음-059·낮음-060·낮음-061·낮음-062·낮음-063·낮음-064·낮음-065·낮음-066·낮음-067·낮음-068·낮음-069·낮음-070·낮음-071·낮음-072), review/consistency-review.md R-152, 00-summary.md §6·질문 61, 같은 날 새 ADR-0100~0126(새 결정이 필요한 항목)

## 맥락

2026-10-27 기술 검토 2판은 설계의 모든 기술·기법을 시니어 개발자 관점에서 따져 높음·중간·낮음 항목으로 냈다. 2026-10-28 소유자가 남은 항목을 모두 추천안대로 고치라고 정했다. 새 결정이 필요한 항목은 따로 ADR(0100~0126)을 썼고, 이 ADR은 정본 문서를 고쳐 반영한 낮음 항목 38건의 문제와 결정을 한곳에 모은다. 검토 문서에서는 이 항목들의 본문을 지우고 이 ADR을 가리키는 한 줄만 남겼다(지운 본문은 git 이력에 있다).

## 결정

항목마다 검토의 추천 수정을 따랐다(소유자 승인). 검토가 안을 여럿 내고 고르지 않은 곳은 고른 안과 이유를 적었고 '추천 적용'으로 표시했다. 정본에는 `(추천 적용 2026-10-28, 기술 검토 <번호>)`로 표시했다.

### 데이터·검색·보안 문서

#### 낮음-033 trust 키의 회차 해시 태그를 빼고, 기기 공유 수는 정확히 센다
- **문제**: trust 키의 회차 해시 태그를 빼고, 기기 공유 수는 정확히 센다
- **결정**: trust 키(판정 피처 `tr:devshare`·`tr:asnhost`, 재평가 `tr:ra:dev`·`tr:ra:fp`)는 해시 태그를 기기 가명·ASN·지문에 둔다. 같은 Lua에서 함께 쓰는 회차 단위 키에만 회차 태그를 붙이는 §1 규칙과 맞춘다. 기기 공유 수는 HyperLogLog 대신 Set으로 정확히 센다(원소 상한 20개 [가정], 추천 적용).
- **바꾼 문서**: data §3, streaming §2.3·§5.5·§5.8, queue-admission §7, data-classification, ADR-0071·0099 상태 줄.

#### 낮음-034 data.md §1의 Kafka 클러스터 수가 '둘'로 남아 있다
- **문제**: data.md §1의 Kafka 클러스터 수가 '둘'로 남아 있다
- **결정**: 데이터 토픽 클러스터는 둘(거래·제어, 텔레메트리)이고, ADR-0077의 관측 전용 셋째는 docs/observability.md §1에서 다룬다. 운영 MSK는 모두 셋이다(소유자 결정 ADR-0077의 반영 누락을 고친 것).
- **바꾼 문서**: docs/data.md §1.

#### 낮음-035 일관성 표의 표기를 바로잡고 WAIT 결정 상태를 맞춘다
- **문제**: 일관성 표의 표기를 바로잡고 WAIT 결정 상태를 맞춘다
- **결정**: data §4의 둘째 칸을 '일관성 요구(강함·최종적)'로 바꾸고 CP·AP를 뺀다. 홀드·1인 매수 한도·한정 굿즈 재고는 '빠른 판정(Redis 원자 연산) + 최종 확정(PostgreSQL 제약)'이다. 홀드의 `WAIT`는 seat-hold §13대로 쓸지를 PoC로 정하고, 써도 강한 일관성이 되지 않는다(Redis 문서, 추천 적용).
- **바꾼 문서**: docs/data.md §4.

#### 낮음-036 '받은 후보 안에서 거르기' 규칙이 중간 일치·초성 전환에서 후보를 놓친다
- **문제**: '받은 후보 안에서 거르기' 규칙이 중간 일치·초성 전환에서 후보를 놓친다
- **결정**: 앞선 입력이 이미 두 글자(한글은 두 음절) 이상이고 입력 종류가 같으며 거른 결과가 0건이 아닐 때만 거른다(셋째 조건은 추천 적용). 골든 세트(SR-T12)에 입력을 한 글자씩 늘리는 순서 경우를 넣는다.
- **바꾼 문서**: search §4.5·§12, frontend 요청 줄이기 표, d5 자동완성 행, ADR-0094 상태 줄.

#### 낮음-037 '내부 mTLS 필수'가 포트폴리오 실행(메시 없음)과 범위를 나누지 않는다
- **문제**: '내부 mTLS 필수'가 포트폴리오 실행(메시 없음)과 범위를 나누지 않는다
- **결정**: P1 행과 법률 질문 7의 내부 mTLS는 운영 설계(ADR-0082)라고 적고, 포트폴리오 실행은 실제 개인정보가 없는 합성 데이터라 메시 없이 돈다고 verification §8을 가리킨다.
- **바꾼 문서**: docs/security/data-classification.md.

#### 낮음-038 Sentry `dataCollection` 설정이 기대는 SDK 최소 판을 적는다
- **문제**: Sentry `dataCollection` 설정이 기대는 SDK 최소 판을 적는다
- **결정**: 수집 설정 잠금이 기대는 Sentry JavaScript SDK를 10.57.0 이상(브라우저·서버 같은 판)으로 정하고, docs/devops.md §4.4 '설정이 기대는 최소 판'에서 CI가 지킨다. 가짜 수신기로 설정이 먹는지 V-T39로 본다(추천 적용).
- **바꾼 문서**: data-classification Sentry 행, observability §11, devops §4.4, verification §9, ADR-0067 상태 줄.

#### 낮음-039 NIST SP 800-57 표와 대조한 결과를 적고, 정기 교체가 없는 키를 편차로 남긴다
- **문제**: NIST SP 800-57 표와 대조한 결과를 적고, 정기 교체가 없는 키를 편차로 남긴다
- **결정**: 교체 주기를 NIST SP 800-57 Part 1 Rev.5 표 1과 대조해 결과를 적고(주기가 있는 키는 모두 권장 기간 안), 정기 교체를 두지 않는 키는 이유와 보완 통제를 한 표에 모은다. 페퍼 키는 '2년 안'. KMS 옛 키 재료의 풀기 기간은 남는 편차로 적는다(추천 적용).
- **바꾼 문서**: docs/security/secrets-and-keys.md 관리 규칙 5·페퍼 행·새 소절.

#### 낮음-040 PgBouncer 판을 고정한다(트랜잭션 풀링의 prepared statement는 1.21부터)
- **문제**: PgBouncer 판을 고정한다(트랜잭션 풀링의 prepared statement는 1.21부터)
- **결정**: PgBouncer를 1.26.1 이상으로 엔진 판 줄에 고정하고(기능 하한 1.24, 1.26.1은 `auth_file` SCRAM 인증 결함 수정), 이미지는 판 이름표와 다이제스트로 고정한다(추천 적용).
- **바꾼 문서**: data §1·§5.2, devops §4.4·§7.2, infra-handover PgBouncer 행, ADR-0086 상태 줄.


### 스트림·분석·포렌식

#### 낮음-042 수집 버킷 파일(기준 자료·운영 기록·비용·SLO)을 누가 어떻게 싣는지 정해지지 않았다
- **문제**: 수집 버킷 파일(기준 자료·운영 기록·비용·SLO)을 누가 어떻게 싣는지 정해지지 않았다
- **결정**: 개인정보가 없는 수집 버킷 파일은 마감 실행기가 ClickHouse `s3()` 표 함수로 브론즈에 싣는다(크기 상한·열 구조·모르는 칸 거절, 적재 기록, 미적재 SEV3, 전용 사용자 `an_intake`, 추천 적용). 스트림 작업자는 파일을 읽지 않고 S3 권한을 뺀다.
- **바꾼 문서**: analytics §3.2·§11, streaming §2.3·§6.1, asvs/analytics 13.2.2.

#### 낮음-044 같은 규모 회차가 적을 때 '직전 회차 하나'를 기준선으로 쓰지 않는다
- **문제**: 같은 규모 회차가 적을 때 '직전 회차 하나'를 기준선으로 쓰지 않는다
- **결정**: 같은 규모 확정 회차 수로 기준선 모양을 셋으로 나눈다(3회 미만 없음, 3~9회 범위·약함, 10회 이상 중앙값·사분위). 직전 회차 하나와는 견주지 않고, 약한 기준선으로는 되돌리기 어려운 결정을 미루는 것이 기본이다(추천 적용).
- **바꾼 문서**: analytics §6.4·§10.2·§14, observability §13, planning/01 §3.2·§5.2, guide/15.
- **남는 한계**: planning/01 §5.2 기존 행의 문장을 고쳤다(새 줄 없음)

#### 낮음-045 결정 규칙의 '걸림'을 점 추정이 아니라 구간으로 판정한다
- **문제**: 결정 규칙의 '걸림'을 점 추정이 아니라 구간으로 판정한다
- **결정**: 비율 규칙은 95% Wilson 구간으로 판정하고(전체 밖 걸림, 품으면 경계, 전체 안 안 걸림) F12에 '경계'를 더한다. 경계는 검토를 열지 않는다(추천 적용). 비율이 아닌 규칙은 그대로다.
- **바꾼 문서**: analytics §5.2·§6.2·§6.4·§8.2·§10.2·§12, planning/01 §3.2, planning/02 FR-068, planning/04 SCR-029, d5 SCR-029.

#### 낮음-046 시각 순서 검사에 서비스 사이 시계 차이 허용 오차를 둔다
- **문제**: 시각 순서 검사에 서비스 사이 시계 차이 허용 오차를 둔다
- **결정**: 서로 다른 서비스가 찍은 시각은 노드 시계 오프셋 경보 값의 두 배(40ms)까지 앞뒤가 바뀌어도 맞는 것으로 보고, 같은 서비스가 같은 토픽에 낸 단계는 Kafka 위치로 견준다(추천 적용).
- **바꾼 문서**: analytics §7.

#### 낮음-047 골드를 익명정보로 보는 근거에 작은 칸 처리를 더한다
- **문제**: 골드를 익명정보로 보는 근거에 작은 칸 처리를 더한다
- **결정**: 사람에 대한 판단이 차원으로 든 골드 사실은 세션 5 [가정] 미만 칸을 '기타'로 합친 뒤 쓴다(추천 적용). 합친 골드가 익명정보인지는 법률 검토(확인 필요, POL-027)이고, 아니면 가명정보로 돌려 90일 보존한다.
- **바꾼 문서**: analytics §5.2·§11, data-classification, POL-027.

#### 낮음-048 포트폴리오에는 비용 원천이 없다는 점을 한계에 적는다
- **문제**: 포트폴리오에는 비용 원천이 없다는 점을 한계에 적는다

- **남는 한계**: analytics §14에 더함(planning/01 §5.2의 '사후 분석과 결정 규칙의 한계' 행이 이미 포트폴리오 합성 데이터 한계를 적어 새 줄은 더하지 않았다)

#### 낮음-049 1단계는 공유 메모리 시계 없이 복사 방식 하나로 시작한다
- **문제**: 1단계는 공유 메모리 시계 없이 복사 방식 하나로 시작한다

#### 낮음-050 좌석 상태 체크포인트 간격을 메모리 상한으로 정한다
- **문제**: 좌석 상태 체크포인트 간격을 메모리 상한으로 정한다

#### 낮음-051 2단계 내보내기의 형식 설정과 '메모리에만' 원칙을 맞춘다
- **문제**: 2단계 내보내기의 형식 설정과 '메모리에만' 원칙을 맞춘다

#### 낮음-052 정밀도·재현율이 생성기 가정의 값임을 보이고, 사람을 흉내 내는 봇 프리셋을 둔다
- **문제**: 정밀도·재현율이 생성기 가정의 값임을 보이고, 사람을 흉내 내는 봇 프리셋을 둔다

### 관측·검증·관제

#### 낮음-053 브라우저 계측 라이브러리 셋의 역할이 겹치고, 브라우저 span을 내보내는지 불분명하다
- **문제**: 브라우저 계측 라이브러리 셋의 역할이 겹치고, 브라우저 span을 내보내는지 불분명하다
- **결정**: 브라우저 span을 내보내지 않고 OTel 브라우저 SDK를 뺀다. `traceparent`는 작은 함수가 같은 출처 요청에만 만들고, 실패한 요청의 trace-id를 Sentry 태그로 실어 서버 span 링크를 찾는다. Sentry는 자기 추적 헤더를 붙이지 않는다(추천 적용).
- **바꾼 문서**: observability §2·§11·§14, frontend §5.8·§5.14.5·§5.16, ADR-0079 상태 줄

#### 낮음-054 fast-check 모델과 Quint 명세를 잇는 장치가 없다

#### 낮음-057 DORA 지표를 25010 유지보수성(모듈성·재사용성)에 대응시켰고, 운영 배포가 없는 포트폴리오에서의 뜻이 없다
- **문제**: DORA 지표를 25010 유지보수성(모듈성·재사용성)에 대응시켰고, 운영 배포가 없는 포트폴리오에서의 뜻이 없다
