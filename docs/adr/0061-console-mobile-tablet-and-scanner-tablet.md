# ADR-0061: 파트너·관제 콘솔의 휴대폰·태블릿 지원과 스캐너 태블릿

- **상태**: 채택 (2026-10-14. 소유자 결정: 화면 디자인 시안을 보고 "나머지 다른 앱도 모두 디자인을 만들어주세요"라고 요청했고, 지원 범위를 묻는 질문(모두 3가지 크기·태블릿까지만·지금 그대로)에 '모두 3가지 크기'를 골랐다. 화면별 휴대폰 범위, 셸 배치, 브라우저 목록, 시험, WBS 일수는 이 결정에 따라 정했다(추천 적용, 2026-10-14)) 2026-10-14 추천 적용(ADR-0062 결정 4): 결과 절의 휴대폰 승인자 안내 문안은 design/d5 §3.9에 정했다. 2026-10-14 추천 적용(ADR-0062·0063): 휴대폰 범위에 SCR-023 반품 도착 확인·상품 정산 이의, SCR-020·028 내 계정 보안 설정 변경(재인증)이 더해졌다(design/d5 §3.9. 2026-10-20 3차 전수 점검에서 상태 줄에 적음, 소유자 검토 대상).

## 맥락

- NFR-019와 design/d1 §4는 파트너·관제 콘솔을 데스크톱(1280×800 이상)으로만 정했다(추천 적용, 2026-10-09). 원문 설계서의 사용 맥락(파트너 실무자의 업무용 데스크톱, 관제실의 다크 모드 데스크톱)을 따른 것이다. 게이트 스캐너는 관리형 Android 휴대폰의 세로·가로였다.
- 2026-10-14 화면 디자인 시안(소비자 웹은 휴대폰·태블릿·데스크톱, 콘솔은 데스크톱, 스캐너는 휴대폰)을 본 소유자가 다른 앱도 모두 세 크기로 만들라고 했다.
- 콘솔을 휴대폰에서 쓰는 장면은 실제로 있다. 공연 당일 현장에 있는 파트너는 입장 현황을 보고 스태프 권한을 해제하고 기기 배치를 바꾼다. 자리를 비운 2인 승인 상대는 운영 명령의 두 번째 승인을 해야 한다. 스캐너를 잃어버리면 운영자가 바로 폐기해야 한다. 반면 좌석맵 편집, 공연 등록, 위험 명령 요청, 개인정보 원문 열람은 작은 화면에서 잘못 누르거나 확인을 건너뛰기 쉽고 공공장소에서 남의 눈에 띈다.

## 결정

1. **세 크기를 지원한다.** 파트너·관제 콘솔은 sm 360~767(휴대폰), md 768~1023(태블릿), lg 1024 이상(데스크톱)에서 쓴다. 1280×800은 데스크톱 기본 밀도의 기준으로 남기고, 1440 이상은 xl 고밀도다. 게이트 스캐너는 관리형 Android 휴대폰(세로·가로)에 관리형 Android 태블릿(md 768 세로)을 더한다. 스캐너의 데스크톱 배치는 두지 않는다. 카메라를 든 채 검표하는 단말이 전제이고, 큰 화면의 입장 감시는 관제 대시보드 입장 탭과 파트너 현장 운영이 맡는다.
2. **태블릿은 데스크톱과 기능이 같고 배치만 바뀐다.** 왼쪽 내비는 메뉴 서랍으로 접고, 표는 가로 스크롤 상자에 넣고, 위젯 격자는 2열로 줄인다. 좌석맵 에디터는 캔버스를 전체 폭으로 두고 계층 트리와 좌석 속성을 시트로 연다.
3. **휴대폰은 일의 종류로 범위를 정한다.**
   - 파트너: 보기, 공연 당일 현장 운영(SCR-037 전부: 초대·재발송·권한 해제·기기 배치·준비 점검·이상 표시 확인), 정산 이의 제기와 정산서 내려받기. 공연 등록·수정, 좌석맵·판매 정책·상품·웹훅 편집, 정산 계좌 변경과 판매자 정보 변경 요청, 회차 취소 요청, 예매자 명단 열람·다운로드는 태블릿 이상에서 한다.
   - 관제: 보기, 이미 요청된 일의 승인·반려(운영 명령의 두 번째 승인, 승인 업무, 회차 취소 제2 승인. 재인증 포함), 안전 쪽 조치(관리 계정 세션 강제 종료, 스캐너 기기 즉시 폐기, 일괄 환불 일시정지). 운영 명령의 요청·실행·되돌리기, Go/No-Go 판정과 결정 기록, 회차 취소 판정, 판매 승인, 법정 조치 실행, 개인정보 가림 해제, 원본 로그 내보내기, 봇 표본 판정, 공지 작성·발송, 계정 초대·역할 변경은 태블릿 이상에서 한다.
   - 휴대폰에서 범위 밖의 일은 버튼을 숨기지 않고 "이 작업은 태블릿이나 데스크톱에서 합니다" 안내 카드와 [ 링크 복사 ]로 대신한다. 화면별 범위는 design/d5 §3.9 표가 정본이다.
4. **이 제한은 화면 장치이고 보안 통제가 아니다.** 서버는 화면 크기나 User-Agent를 믿지 않는다. 권한은 지금처럼 서버의 역할(planning/03 §3)·재인증·2인 승인이 막는다. 휴대폰 제한은 작은 화면의 잘못 누름, 확인 건너뛰기, 공공장소 노출을 줄이려는 것이다.
5. **접속 통제는 그대로 둔다.** 관제는 허용 IP·사내 VPN(휴대폰도 VPN 프로필로 접속)과 TOTP 필수(POL-020), 관리 계정 기기 2대 한도(POL-019)를 그대로 쓴다. 휴대폰을 쓰는 사람은 데스크톱 1대와 휴대폰 1대로 한도를 채운다. TOTP를 휴대폰에서 등록할 때는 같은 기기의 카메라로 QR을 찍을 수 없으므로 설정 키 복사 경로를 둔다.
6. **브라우저.** 콘솔의 휴대폰·태블릿은 iOS·iPadOS Safari 16.4 이상과 Android Chrome·Samsung Internet 최신 2개 버전, 데스크톱은 지금처럼 Chrome·Edge·Whale 최신 2개 버전이다. 콘솔은 인앱 브라우저를 지원하지 않고 외부 브라우저로 열라고 안내한다(SCR-059의 지원하지 않는 브라우저 변형).
7. **시험.** Playwright에 휴대폰(390×844)·태블릿(820×1180) 뷰포트 프로젝트를 더해 파트너·관제의 주요 흐름과 휴대폰 범위 밖 안내를 매 PR마다 확인하고, 실기(iOS Safari·iPadOS Safari·Android Chrome) 수동 점검을 메이저 릴리스마다 한다(NFR-019). 성능은 NFR-012가 이미 모바일과 데스크톱을 따로 잰다. 접근성(NFR-020)은 휴대폰 배치에서 터치 영역(design/d2)과 확대 200% 때 가로 스크롤 없는 재배치를 본다.
8. **일정.** WBS에 4.5.4(관제 2일), 5.8.5(CS·승인·팬 조회 화면 1일), 5.4.6(스캐너 태블릿 1일), 7.2.6(파트너 2일)를 더하고 7.5.1에 실기 점검 0.5일을 더한다. 합계 +6.5일(316.5일 → 323일)이다. 프로토타입(wbs 0.10)은 데스크톱 크기로 만들었고 이번 범위에 넣지 않는다.

## 검토한 대안

| 대안 | 기각 사유 |
| --- | --- |
| 태블릿까지만 지원 | 공연 당일 현장의 파트너와 자리를 비운 승인자의 장면을 놓친다. 소유자가 고르지 않았다 |
| 휴대폰에서도 데스크톱과 같은 기능 | 위험 명령 요청, 좌석맵 편집, 개인정보 열람이 작은 화면에서 잘못 누름과 노출을 늘린다 |
| 휴대폰 제한을 서버에서 강제(User-Agent·화면 폭 판별) | 클라이언트가 보내는 값이라 바꿀 수 있어 통제가 되지 못하고, 잘못 판별하면 태블릿·작은 노트북 사용자를 막는다 |
| 관제 전용 네이티브 앱 | 앱 배포·서명·기기 관리가 새로 생긴다. 같은 웹 앱의 반응형 배치로 장면을 덮는다 |
| 스캐너 데스크톱 배치 | 카메라를 든 검표 단말이라는 전제와 맞지 않는다. 큰 화면의 입장 감시는 관제 입장 탭과 파트너 현장 운영에 있다 |

## 결과와 트레이드오프

- 화면 수는 68개 그대로이고 배치가 는다. 파트너 13개·관제 17개 화면(SCR-059 변형 포함)에 휴대폰·태블릿 배치를, 스캐너 6개 화면에 태블릿 배치를 더한다. 2026-10-14 디자인 시안에 보드 66개를 더한다.
- 휴대폰에서는 운영 명령을 요청하지 못하므로, 휴대폰만 가진 commander는 명령 11(입장 제어 자동화 긴급 정지)을 낼 수 없다. 이때는 태블릿·데스크톱을 쓰는 다른 운영자나 런북 CLI(두 운영자 서명)를 쓴다.
- 휴대폰으로 로그인·재인증하면서 같은 휴대폰의 인증 앱으로 TOTP를 넣으면, 로그인한 기기와 두 번째 요소가 한 기기에 모인다. 휴대폰을 잃으면 두 요소를 함께 잃는 위험이 남는다. 화면 잠금, 관리 계정 유휴 1시간(POL-019), 원격 강제 종료(SCR-064)로 위험을 줄일 뿐 없애지는 못한다. 휴대폰으로 승인하는 사람에게는 인증 앱을 다른 기기에 두라고 안내한다.
- 휴대폰에서 개인정보 가림을 풀지 않아도 운영 지표와 건 요약(가린 값과 가명 참조값)은 보인다. 공공장소 노출은 그만큼 남는다.
- 화면 크기 제한은 데스크톱 모드 요청 같은 방법으로 우회할 수 있다. 우회한 사람도 서버의 권한·재인증·2인 승인을 그대로 거친다.
- 프론트엔드 일정이 6.5일 늘고 [가정], 뷰포트 프로젝트만큼 E2E 시간이 늘어난다.

## 되돌릴 조건

- 실기 점검이나 운영 회고에서 휴대폰 승인이 잘못 누름이나 확인 건너뛰기로 이어진 사례가 나오면 휴대폰 승인을 다시 막고 이 ADR의 상태 줄에 적는다.
- 관제 사용자가 휴대폰에서 실제로 하는 일이 보기뿐이면 결정 3의 승인 범위를 줄인다.
- 휴대폰 범위 밖으로 둔 일 가운데 현장에서 급히 필요하다고 드러난 일(예: 회차 취소 요청)은 그 화면만 범위를 넓히고 d5 §3.9 표와 이 ADR의 상태 줄을 함께 고친다.
