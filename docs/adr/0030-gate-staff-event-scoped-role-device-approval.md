# ADR-0030: 현장 게이트 검표 요원을 위한 회차 한정 역할(RBAC) 및 기기 승인 로그인(RFC 8628) 채택

- **상태**: 채택 (2026-10-09 수립). ADR-0051(2026-10-13)이 보완·정정한다: 결정 1에 초대 수락 조건(휴대폰 본인확인, 검증된 이메일이 초대 이메일과 같음, 동의 두 개)과 URL 조각에만 싣는 초대 토큰을 더하고, 결정 2의 4자리 확인 코드를 8자(RFC 8628 §6.1 문자 집합)로 바꾸며 게이트 구역은 승인 화면이 아니라 기기 배치가 정한다. 해제는 종료 세션 목록 대신 서버가 요청마다 세션 상태를 확인하고, 대리 승인은 일반 스태프 권한으로만 한다. 결정 6의 티켓 번호 수동 조회는 현장 책임자의 예외 통과(좌석 표시로 찾고 사유를 남김)로 바꾼다. 결과 첫 줄의 '2요소 인증 효과·부담 제로화·책임성 영구 확보'는 '기기 인증서는 기기를 증명하고 사람 쪽은 휴대폰의 소셜 로그인 한 요소이며, 계정 관리 부담을 줄이고 스캔마다 계정 ID로 추적한다'로 정정한다
- **관련 문서**: ADR-0011(토큰 수명주기 관리), ADR-0025(회전 QR 코드), docs/features/identity.md §6.1, docs/features/offline-gate.md §6, docs/security/asvs/auth.md, [RFC 8628](https://www.rfc-editor.org/rfc/rfc8628)
- **관련 ID**: FR-035, FR-036, FR-046, POL-018, POL-031, SCR-033, SCR-034, SCR-036, SCR-037

## 맥락
- 초기 설계안에서는 게이트 스캐너 단말기만을 mTLS 기기 인증서로 식별하고, 실제 단말기를 조작하는 현장 인력 계정의 관리는 미래 과제로 유보되어 있었다. 이로 인해 관람객을 입장시킨 작업자의 실명 책임 추적이 불가능하였으며, 카메라 오작동이나 스마트폰 방전 시 예외 입장을 승인하는 '수동 판정 권한'을 단말기별로 차등 제어할 수 없었다.
- 그러나 현장 스태프는 콘서트 당일 하루만 투입되는 단기 아르바이트 인력이 대부분이므로, 모든 현장 스태프에게 정식 백오피스 관리 계정(이메일, 영구 비밀번호, TOTP 앱 등록)을 발급하는 것은 극심한 운영상 오버헤드를 초래한다.
- 또한 현장 단말기는 야외에서 장갑을 착용한 채 교대 사용하는 공용 산업용 기기이므로, 번거로운 키패드 비밀번호 입력을 강제할 수 없다.

## 결정
1. 파트너(공연 기획사)는 공연 회차 단위로 24시간 유효한 1회용 초대 이메일을 발송하고, 현장 스태프가 본인의 기존 PEAKET 일반 계정으로 이를 수락하면 해당 회차에 한정된 임시 권한(`gate_staff` 또는 `gate_lead`)을 동적으로 부여한다.
   - 부여된 권한의 유효 시간은 원칙적으로 입장 시작 3시간 전부터 공연 종료 후 2시간까지로 자동 제한된다.
2. 스캐너 단말기 로그인은 OAuth 2.0 Device Authorization Grant(RFC 8628) 표준 워크플로를 적용한다:
   - mTLS 인증서를 탑재한 등록 스캐너 기기가 서버로부터 검증 코드를 발급받아 화면에 QR 코드와 4자리 확인 코드를 띄운다.
   - 현장 스태프는 본인의 스마트폰 카메라로 QR 코드를 촬영하여 로그인한 모바일 웹 승인 창에서 기기 명칭, 게이트 번호, 공연 회차, 확인 코드를 대조한 후 '승인' 버튼을 누른다.
   - 스캐너 단말기는 백그라운드 롱 폴링을 통해 본인 인증이 완료된 현장 스태프 세션 토큰을 수신하여 즉시 검표 모드로 전환된다. 별도의 비밀번호나 PIN 입력은 요구되지 않는다.
3. 현장 스태프 세션 토큰은 `identity-svc`의 ES256 개인키로 서명되며 수신자(`aud=scanner`), 대상 회차, 역할을 포함하고, 해당 스캐너 단말기의 TLS 인증서 지문(Fingerprint)에 강력히 바인딩된다.
4. 오프라인 네트워크 단절 환경에서도 유효성을 검증할 수 있도록 스캐너 로컬 캐시에 세션 만료 시각을 보관하며, 토큰 유효 시간이 경과하면 스캐너가 자체적으로 세션을 강제 종료한다.
5. 모든 티켓 스캔 이벤트 로그에는 단말기 식별자뿐만 아니라 조작한 현장 스태프의 식별자(`staff_account_id`)를 불변 필드로 반드시 남긴다. 단, 개인정보 보호를 위해 스캐너 화면에는 관람객의 이름이나 전화번호 등 민감 식별자를 표출하지 않는다.
6. 관람객 스마트폰 파손 시 티켓 번호 수동 조회 승인, 강제 상태 번복 등의 고위험 예외 처리는 오직 관리자 역할인 `gate_lead` 권한 소지자에게만 허용된다.

## 검토한 대안
| 대안 | 기각 사유 및 한계점 |
| --- | --- |
| mTLS 기기 인증서만 단독 사용 | 부정 입장이나 오류 발생 시 단말기를 잡고 있던 실제 현장 스태프를 역추적할 수 없으며, 일반 현장 스태프와 현장 팀장의 예외 승인 권한 분리가 불가능하다. |
| 현장 스태프 전원에게 정규 백오피스 관리자 계정 발급 | 단기 인력 수백 명의 사전 회원가입 및 TOTP 설정 지원에 과도한 운영 비용이 낭비되며, 현장 공용 기기에서 패스워드 탈취 위험이 크다. |
| 회차별 공용 마스터 PIN 번호 공유 | 구두나 쪽지로 PIN이 공유되어 보안 책임성이 전무해지며, 1명이라도 유출 시 현장의 모든 단말기를 즉시 재설정해야 하는 치명적 취약점이 발생한다. |

## 결과와 트레이드오프
- 공용 스캐너 기기 소지와 개인 휴대폰 소지라는 2요소 인증(2FA) 효과를 자연스럽게 달성하면서, 단기 인력의 계정 관리 부담을 제로화하고 모든 검표 행위의 책임성을 영구 확보한다.
- 현장 스태프 개인 명의의 스마트폰 및 기본 계정 로그인이 전제되어야 하며, 스마트폰 배터리가 방전된 비상시에는 현장 책임자(`gate_lead`)가 대리 승인하여 책임 로그를 이관해야 한다.
- 파트너가 역할을 해제하면 종료 세션 목록과 1분 변경분으로 스캐너에 알린다. 오프라인 스캐너에는 해제가 늦게 반영된다(최대 역할 유효 끝까지).
