# ADR-0339: 명령 4(대역 차단)의 2인 승인 조건과 보호 대역 목록을 정한다(2026-11-21)

- **상태**: 채택(추천 적용, 2026-11-21, BAT-355 계획). [ADR-0136](0136-tech-review-low-doc-fixes-planning-policy-guide.md) 낮음-129가 '값·목록은 4.4.1에서 확정하고 그때 ADR'로 남긴 것을 정한다. 목록 값은 [가정]이고 출시 준비 때 다시 본다(결정 4). 소유자 결정이 아니다.
- **관련**: [docs/features/control-tower.md](../features/control-tower.md) §3 명령 4 행과 '명령 4의 2인 조건과 보호 대역 목록의 첫 구현' 문단, [docs/planning/03-policies-glossary.md](../planning/03-policies-glossary.md) POL-021, [docs/security/asvs/control-tower.md](../security/asvs/control-tower.md) 2.2.1·2.3.5, [ADR-0340](0340-ops-command-lifecycle-dry-run-expiry-revert-actor-refs.md)(dry-run 기록), `docs/review/plans/BAT-355.md`
- **관련 ID**: OPS-260, ASVS v5.0.0-2.2.1·2.3.5

## 맥락

- 명령 4(ASN·IP 대역 차단)는 1인 승인이다. 다만 ASN(인터넷에서 한 사업자가 쓰는 주소 묶음의 번호) 단위 차단, IPv4 /16보다 넓은 대역, IPv6 /48보다 넓은 대역, 보호 대역 목록(국내 통신사의 ASN·대역, 주요 클라우드의 공개 대역)에 걸리는 차단은 2인 승인이다(control-tower §3). 값과 목록은 Phase 4 4.4.1(OPS-260)에서 정하기로 했다.
- 지금 ops-svc는 명령 4를 늘 2인으로 다룬다(`services/ops-svc/src/modules/commands/domain/command.ts`의 `approvalModeOf`). 좁은 대역 하나를 막는 데도 두 사람과 패스키 재인증이 들어 공격 중 대응이 늦고, 정본과 다르다.
- 통신사·클라우드의 대역 목록은 수천 줄이고 자주 바뀐다 [추정]. 지금은 그 목록을 받아 오는 도구도, 운영 계정도 없다.

## 결정

1. **2인 조건**: 명령 4의 `params`는 대역 목록 `cidrs`(IPv4·IPv6 CIDR 표기), ASN 목록 `asns`(1~4294967295 정수), 만료 시각 `expiresAt`(필수, 지금보다 늦고 지금 + 24시간 이하)이다. 아래 가운데 하나라도 맞으면 그 명령 전체가 2인이다(control-tower §4 T4).
   - ASN 항목이 하나라도 있다.
   - IPv4 접두 길이가 16보다 짧다(/15 이하). /16은 1인이다.
   - IPv6 접두 길이가 48보다 짧다(/47 이하). /48은 1인이다. IPv4를 담은 IPv6 표기(`::ffff:a.b.c.d/n`)는 IPv4로 바꿔 본다(접두 길이는 n − 96).
   - 대역이 보호 목록의 CIDR 항목과 겹친다. 어느 쪽이 다른 쪽을 품어도 겹침이다(넓은 차단이 보호 대역을 품는 경우와, 보호 대역 안의 좁은 차단 둘 다).
   그 밖은 1인(T5)이다. 2인이면 위험 명령이라 접수·승인에 재인증(`act=OPS_COMMAND`, `factors`에 passkey)이 필요하고, 1인이면 필요 없다(control-tower §3 '위험 명령 재인증의 첫 구현').
2. **입력 검사**: 표준 해석기로 읽는다. 호스트 비트가 0이 아닌 대역(예 `10.0.0.1/8`), 접두 길이 0, 빈 목록 둘, 같은 항목 두 번, 항목 합계 100개 [가정] 초과, 만료 시각이 없거나 범위 밖이면 저장 전에 거른다. 꼴이 틀리면 422 `invalid-command`, 만료·개수가 한계 밖이면 422 `command-out-of-range`(ADR-0340 결정 9)다.
3. **목록 꼴과 자리**: 보호 목록은 ops-svc 코드 안의 데이터 파일 하나(`services/ops-svc/src/modules/commands/domain/protected-ranges.ts`)다. 항목은 `{ kind: 'ASN' | 'CIDR', value, category: 'KR_CARRIER' | 'CLOUD', label, source }`이고 목록 판 `version`(날짜)이 있다. 운영 명령으로 바꾸지 못한다(운영자가 목록을 줄여 2인을 피하지 못하게, control-tower §6 1번의 정적 안전 한계와 같은 까닭). 아래 결정 4의 첫 목록은 이 ADR이 정한 값이고, 그 뒤의 원본은 파일이다. 파일을 바꾸면 이 ADR '목록 판' 줄에 판과 까닭 한 줄을 더한다. dry-run 결과(ADR-0340 결정 2)에 걸린 항목 `protectedRangeHits`(분류·라벨)와 목록 판을 싣는다.
4. **첫 목록(판 2026-11-21) [가정]**:
   - ASN, 국내 통신사: AS4766(KT), AS9318(SK브로드밴드), AS3786·AS17858(LG유플러스), AS9644(SK텔레콤).
   - ASN, 클라우드: AS16509·AS14618(AWS), AS15169·AS396982(Google), AS8075(Microsoft), AS13335(Cloudflare).
   - ASN 차단은 결정 1로 이미 늘 2인이라, ASN 항목은 dry-run의 '보호 대역에 걸림' 표시와 보안 사건(결정 5)에만 쓰인다.
   - CIDR 항목: 첫 판은 비운다. 통신사·클라우드 대역을 받아 오는 길(클라우드의 공개 대역 문서, 인터넷 주소 등록 기관 자료)과 갱신 주기는 출시 준비 때 정한다(정할 곳: 구간 5 운영 데이터 준비, BAT-355 계획 '정할 것'). 시험은 시험용 목록을 넣어 겹침 판정을 본다.
5. **보안 사건**: 보호 목록에 걸린 차단 요청은 정규 로그의 보안 사건 한 줄 `ops_block_protected_range`(명령 ID, 요청자 역할, 걸린 항목의 분류·라벨)를 남긴다. 사람 이름·계정 ID는 싣지 않는다.

## 검토한 대안 (트레이드오프)

| 대안 | 이런 점이 낫다 | 이런 점이 걸린다 | 판단 |
| --- | --- | --- | --- |
| A. 크기 규칙 + 코드 안 목록(이 결정) | 외부 의존이 없고 시험으로 경계를 볼 수 있다 | 첫 판은 CIDR 목록이 비어 크기 규칙만 일한다 | 고른다 |
| B. 명령 4를 늘 2인(지금 코드) | 단순하다 | 좁은 차단에도 두 사람·패스키가 들어 공격 중 대응이 늦고 정본과 다르다 | 쓰지 않는다 |
| C. 차단할 때 바깥 ASN 조회 서비스로 소속을 본다 | 목록을 고칠 일이 없다 | 관제 명령 경로에 외부 의존이 생기고, 조회가 멈추면 판정을 못 한다 | 쓰지 않는다 |
| D. 목록을 DB 표에 두고 운영 명령으로 고친다 | 배포 없이 바꾼다 | 운영자가 목록을 줄여 2인을 피할 수 있다 | 쓰지 않는다 |

## 결과

- 좁은 대역 차단은 1인·재인증 없이, 넓은 대역·ASN·보호 대역 차단은 2인·패스키 재인증으로 나간다. 명령 4의 실제 집행(AWS WAF API)은 OPS-310, 만료 거두기는 OPS-290 몫이다.
- 대가: ops-svc에 CIDR 해석·겹침 판정과 목록 파일이 생긴다.
- 남는 한계: CIDR 보호 목록을 채우기 전에는 통신사 대역 안의 /16보다 좁은 IPv4 차단(IPv6는 /48 이하)이 1인이다.

## 되돌릴 조건

- 1인 차단이 사람을 잘못 막은 사례(효과 줄 SEV2 '차단이 사람을 막고 있을 수 있음', control-tower §3)가 나오면 크기 기준을 좁힌다.
- CIDR 목록을 받아 오는 도구가 생기면 결정 4의 CIDR 첫 판을 바꾸고 판을 올린다.
