# ADR-0232: 셔플 결과 파일의 객체 저장소, 머클 루트 먼저 공시, 시드 공개와 셔플 검증 정보

- **상태**: 채택(2026-11-09, 추천 적용). BUILD_ORDER HOT-050, wbs 2.4.2.
- **관련**: POL-004, POL-005, FR-005, FR-006, FR-038, ADR-0041, ADR-0050(결정 7), ADR-0058, ADR-0110, ADR-0171, ADR-0182, ADR-0223(결정 9), ADR-0231, [docs/features/queue-admission.md](../features/queue-admission.md) §2·§5, [docs/data.md](../data.md) §3, [docs/infra.md](../infra.md) §4.1, [docs/design/d5-screen-blueprint.md](../design/d5-screen-blueprint.md) §5.19.

## 맥락

HOT-040은 로비와 묶음의 셔플 결과를 로컬 폴더에 쓰고, 커밋(추첨에 쓸 비밀 시드의 해시를 먼저 공개한 값)과 라운드만 공시했다. 라운드는 drand(여러 기관이 함께 정해진 주기로 공개 난수를 내는 서비스)의 회차이고, 그 회차의 난수를 비콘이라 부른다. 결과를 공개 범위로 내보내고 '누구나 다시 계산할 수 있다'를 지키려면 정본에 없는 세부를 정해야 한다.

- 결과 파일은 객체 저장소(S3, 파일을 키로 읽고 쓰는 저장소)의 어디에 어떤 머리로 쓰는가.
- 정본의 파일 수 '약 1,000개'와 구현의 4,096개가 다르다.
- 머클 루트(참가자 목록 전체를 값 하나로 요약한 해시)는 지금 결과를 게시할 때 함께 쓴다. POL-005는 T=0에 공표한다고 정했다.
- 시드 공개(오픈 60분 뒤)는 누가 하는가. KMS(암호 키를 안전하게 보관하고 대신 써 주는 클라우드 서비스) 권한은 queue-svc가 봉인, admission-ctrl이 풀기로 나뉜다(HOT-041).
- 셔플 검증 정보 API의 응답 모양과 내 순번을 브라우저에서 다시 계산하는 방법.

AWS S3 SDK를 받지 않으므로(소유자 결정 대기 OPEN[24]·[25]) 이 단계는 포트(코드가 바깥 저장소를 부르는 약속)와 시험 대역까지 한다.

## 결정

1. **결과 파일은 객체 저장소 포트에 쓴다.** 어댑터 `ObjectStoreResultFiles`가 키와 머리를 정하고, 실제 저장은 `ResultObjectStore.put`이 한다.
   - 키는 `queue/fallback/v1/queues/{회차 ID}/{shuffle-results|batch-results}/{앞 세 자리}.json`이다. CloudFront(AWS의 CDN. CDN은 사용자 가까운 곳에 파일을 복사해 두고 대신 응답하는 전송망이다)의 S3 원본은 원본 경로 + 요청 경로를 키로 쓰므로 요청 경로와 같아야 한다(ADR-0223 결정 9와 같은 원본 경로 `/queue/fallback`). 회차 ID가 키 앞부분에 있어 접두사가 회차마다 갈린다. ADR-0058 결정 5의 `queue/{eventId}/shuffle/…`는 이 키로 바꾼다.
   - 머리는 `application/json; charset=utf-8`과 `Cache-Control: public, max-age=60` [가정]이다.
   - 동시에 쓰는 수는 64개 [가정]이다. 접두사마다 초당 PUT 3,500건 안에 든다.

2. **결과 파일은 4,096개 [가정]로 통일한다.** 파일을 고르는 값은 토큰 해시의 16진 앞 세 자리라 4,096개로 나뉜다. ADR-0058 결정 6의 '1,000개'는 십진 어림이다. 100만 명이면 파일마다 약 244건, 약 19 KB [추정]이고 한 사람이 받는 양은 약 36 KB에서 줄어든다. 분산 창 8초의 전송은 약 19 Gbps [추정](ADR-0058 후속 변경)다.

3. **참가자가 한 명 이상인 구간은 파일 4,096개를 모두 쓴다(비어 있으면 `{}`).** 404가 '셔플 전'이라는 뜻(openapi)과 어긋나지 않게 하려는 것이다. 빈 앞자리가 404면 브라우저는 '아직 전'과 '내 앞자리에 아무도 없음'을 가르지 못한다. 참가자 0명으로 닫힌 구간은 공개할 결과가 없어 파일을 쓰지 않고, 검증 정보의 `fileCount`가 0이다.

4. **결과 파일 경로의 CDN 원본은 S3 하나다.** 대기열 파일 배포의 다른 경로는 gw-queue가 주 원본이고 S3가 대체 원본이지만, 결과 파일은 S3에만 있으므로 gw-queue를 거치면 한 단계만 늘어난다. S3 버킷 정책에 이 접두사의 `s3:ListBucket`을 함께 준다. 이 권한이 없으면 없는 키가 404가 아니라 403이 된다. local·ci·demo는 객체 저장소가 없어 queue-svc가 같은 경로로 폴더(`PEAKET_BATCH_RESULT_DIR`)를 읽어 준다(같은 머리, 없으면 1초 캐시 404).

5. **머클 루트는 목록을 고정하고 복제를 확인한 뒤, 비콘을 기다리기 전에 공시한다.** 게시는 ① 복제 확인 → ② 참가자 읽기와 머클 루트 계산 → ③ `batch_done`의 `root:{구간}`·`rootAt:{구간}`을 비어 있을 때만 쓰기 → ④ 비콘 대기다.
   - `rootAt`은 파드 시계가 아니라 저장소 시각(Redis `TIME`)이다. 공시 라운드의 예정 시각보다 늦게 쓰였으면(리더가 죽었다가 라운드 뒤에 처음 돈 경우) '목록을 비콘 전에 고정했다'는 증거가 되지 못하므로 그 구간의 게시를 멈춘다(`stop:{구간}`의 이유 `late_root`, SEV1, RB-35).
   - 공시한 루트와 게시 때 다시 센 루트가 다르면 그 구간의 게시를 멈춘다(이유 `members_changed`, SEV1, RB-35). 게시한 뒤 다시 쓰기에서 루트가 다르면 지금처럼 예외(`BatchMembersChanged`)이고 그 구간만 다시 부르지 않는다. 다른 구간의 게시는 막지 않는다.
   - 참가자 목록과 루트는 ②에서 만든 것을 게시 끝까지 메모리에 둔다. 큰 묶음의 `SSCAN`(큰 집합을 조금씩 나눠 읽는 Redis 명령)과 머클 계산을 두 번 하지 않으려는 것이다. 리더를 잃으면 비우고, 다음 리더가 다시 읽는다.

6. **게시할 때 비콘 값과 서명을 공시 기록에 남긴다.** `q:{event:E}:shuffle`의 `beacon:{구간}`(16진)·`sig:{구간}`(16진)이다. 비어 있을 때만 쓰고, 게시 표시보다 먼저 쓴다. `Beacon` 포트는 값과 서명을 함께 준다.

7. **시드 공개는 admission-ctrl 리더가 한다.** `오픈 + 60분` 뒤, 그 구간을 게시한 뒤에만 봉인을 풀고 커밋과 대조한 다음 `seed:{구간}`·`seedAt:{구간}`(16진·밀리초)을 비어 있을 때만 쓴다. 게시하지 못한 구간과 멈춘 구간(게시 뒤 멈춘 경우 포함)은 공개하지 않는다. 멈춘 구간은 RB-35의 판단 전에 시드가 나가면 비상 셔플의 결과를 누구나 미리 알게 되기 때문이다. 리더는 5초 [가정]마다 본다. queue-svc는 봉인을 풀 수 없고, 응답에 봉인 값을 싣지 않으며, 공개 시각 전에는 `seed` 칸이 있어도 내지 않는다.

8. **셔플 검증 정보 `GET /v1/queues/{eventId}/shuffle-proof`는 공시 기록을 그대로 읽는 공개 응답이다.** 회차 일정과 `q:{event:E}:shuffle`·`batch_done`을 읽어 구간(`lobby`·`batch`)별로 커밋·공시 시각·체인·라운드·라운드 예정 시각·알고리즘 판·머클 루트·참가자 수·첫 번호·비콘 값과 서명·게시 시각·결과 경로·공개된 시드·멈춤 사유를 낸다. 값이 아직 없는 칸은 빼고, 로비를 끈 회차의 `lobby`와 묶음을 끈 회차의 `batch`는 `null`이다. 없는 회차는 404 `queue-not-found`다. `Cache-Control: public, max-age=5` [가정]이고 쿠키를 쓰지 않는다.

9. **내 순번 다시 계산은 브라우저에서 WebCrypto(브라우저에 들어 있는 암호 기능)로 한다.** `@peaket/shuffle`은 Node.js `crypto`에 묶여 있어 브라우저에서 돌 수 없고, 저장소 밖 패키지도 받지 않는다. 그래서 같은 규격을 브라우저 코드로 한 벌 더 쓰고(apps/web `shuffle-proof/model/recompute.ts`), 파이썬 참조 구현이 만든 기준값(`packages/shuffle/test/vectors.json`)과 시험으로 맞춘다.
   - 참가자 목록은 그 구간의 결과 파일을 모아 만든다. 다시 계산하기 전에 네 가지를 대조하고, 하나라도 틀리면 '일치'로 내지 않는다: 시드 = 공시한 커밋(`SHA-256("PEAKET-shuffle-v1" ‖ 회차 ‖ 시드)`), 비콘 값 = `SHA-256(서명)`, 머클 루트 = 파일의 참가자로 다시 센 값, 머클 루트 공시 시각 ≤ 라운드 예정 시각. 머클 루트만 보면 운영자가 비콘을 본 뒤 원하는 순서가 나오는 시드를 골라 파일을 만들어도 드러나지 않는다.
   - BLS 서명 검증 라이브러리는 아직 없다(OPEN[27]). 화면은 서명 자체를 확인하지 않았다고 그대로 적는다.
   - 계산은 Web Worker(화면과 따로 도는 백그라운드 실행기, CSP 묶음 A의 `worker-src 'self'` 안)에서 하고, 진행률과 취소가 있다. 시작 전에 받을 크기를 알린다(100만 명이면 약 77MB·4,096요청 [추정]). Worker를 만들 수 없는 브라우저는 화면 쪽에서 돈다. 파일은 Worker가 직접 받지 않고 화면 쪽 `fetch`로 받아 넘긴다. Worker의 요청에는 페이지 CSP의 `connect-src`가 걸리지 않고(자기 스크립트 응답의 CSP를 따른다), 정적 자산 응답에는 CSP 머리가 없기 때문이다. JSON 풀기와 계산은 Worker에서 한다.
   - 전체 토큰 해시는 서버로 보내지 않는다. 받을 파일을 고르는 앞 세 자리만 파일 주소로 나간다(12비트라 사람을 가리지 못한다).

10. **커밋 공시를 감사 기록 포트에 남긴다(POL-005).** queue-svc는 커밋을 처음 쓴 호출에서 `ShuffleDisclosures.committed`를 부른다(회차, 구간, 커밋, 체인, 라운드, 알고리즘 판, 공시 시각). 지금 어댑터는 정규 로그 줄 `shuffle_commit_disclosed`다. 불변 감사 저장소(ops-svc)에 잇는 일은 그 저장소를 만드는 단계의 몫이고, 그 전까지 값 자체의 정본은 바뀌지 않는 `q:{event:E}:shuffle` 기록이다.

11. **로비의 늦은 게시를 묶음과 같게 판단한다.** 로비 공개 예정 시각은 `round:lobby`의 예정 시각 + 5초 [가정]이고(ADR-0231 결정 8과 같은 값), 게시 시각이 그보다 늦으면 첫 전진 문을 게시 + 21초로 늦춘다. 공시 기록이 없으면(참가자 0명) 늦었다고 보지 않는다.

12. **게시가 실패하면 2초 [가정] 뒤에 다시 하고, 사람별 결과는 되풀이해 쓰지 않는다.** 사람별 결과까지 쓴 뒤 결과 파일에서 실패했으면 만든 파일 내용을 메모리에 두고 다음 호출은 파일 쓰기부터 한다. 객체 저장소가 멈췄을 때 `SSCAN`·봉인 풀기·셔플·수백만 건의 Redis 쓰기를 되풀이하지 않으려는 것이다. 들고 있는 결과는 만든 때의 닫힌 구간 표시와 지금 값이 같고 그 구간이 멈추지 않았을 때만 쓴다. 돌던 사이에 리더를 잃으면 결과를 들고 남지 않고 게시 표시도 쓰지 않는다. 멈춘 구간은 리더가 5초 [가정]에 한 번만 다시 본다(RB-35로 풀리면 이어서 게시한다). 첫 전진 문은 게시 표시가 없으면 닫혀 있다. 객체 저장소의 PUT 하나가 실패하면 새 PUT을 시작하지 않고, 진행 중인 PUT이 끝난 뒤 던진다. PUT 마감(5초 [가정])은 실제 어댑터(HOT-012)의 의무다.

## 대안

- **결과 파일 경로도 gw-queue를 주 원본으로 두고 queue-svc가 S3를 읽어 준다**: 파일이 S3에만 있어 원본 요청 한 단계와 코드가 늘고, 404 재시도가 그대로 원본에 온다.
- **머클 루트를 게시 때만 쓴다(지금 동작)**: 비콘이 나온 뒤에야 루트가 드러나 운영자가 비콘을 본 뒤 참가자 목록을 바꿔도 드러나지 않는다. POL-005의 T=0 공표와도 다르다.
- **결과 파일을 앞자리별로 나누지 않고 전체 하나로 낸다**: 한 사람이 약 77 MB를 받게 된다.
- **`@peaket/shuffle`을 브라우저에서 돌게 바꾼다**: 패키지를 WebCrypto로 옮기면 게시(동기 계산)가 비동기 해시 호출 200만 번이 되어 느려진다. 서버는 동기 계산이 맞다.

## 결과

- 로비·묶음 결과가 객체 저장소 포트로 나가고, 셔플 검증 화면이 실제 공시 기록으로 그려진다. 운영에서 켜려면 실제 S3 어댑터(BUILD_ORDER HOT-012), KMS 봉인·drand 어댑터(HOT-041), CloudFront 경로·404 캐시 설정(HOT-450)이 필요하다.

### 되돌릴 조건

- 100만 명 규모의 측정(Q-T6)에서 머클 루트 공시(`SSCAN` 약 1초 + 머클 계산 약 2.4초 [추정])가 공시 라운드보다 늦으면 결정 5 때문에 그 구간이 멈춘다. 라운드 여유(목록 고정 뒤 3초 [가정], 실제 3~6초)를 늘리거나 루트 계산을 나눈다. 이 값을 재기 전에는 100만 명 회차를 열지 않는다.
- 브라우저 재계산이 큰 회차에서 너무 무거우면 '내 순번만 머클 경로로 검증'(결과 파일에 내 잎에서 루트까지의 경로를 함께 싣는다. 내가 목록에 들었는지는 파일 하나로 확인하고, 순서 재계산은 공개 스크립트에 맡긴다)으로 바꾼다. 2026-11-11 소유자 결정 "추천안대로"(open-items 107번)로 이 길을 정했다. 결과 파일에 잎→루트 머클 경로를 넣고, 전체 순서 재계산은 `packages/shuffle/reference/shuffle.py`에 맡긴다(docs/features/queue-admission.md §2, docs/design/d5 §5.19).

### 남는 한계

- 머클 루트 공시의 시각은 우리 저장소 시각이다. 저장소를 조작할 수 있는 운영자가 시각을 고치는 것까지는 외부에서 확인할 수 없다.
- 감사 저장소에 잇기 전까지 커밋 공시 기록은 로그 줄이다.
