# ADR-0091: 콘솔이 켜져 있는 동안의 성능을 정한다 — 화면별로 늦게 싣기, 안 보이는 위젯의 구독 멈춤, Canvas 그래프와 보관 상한, 장시간 시험(2026-10-27)

- **상태**: 채택 (2026-10-27. 소유자 질문 "파트너 콘솔이나 운영 관제 콘솔은 많은 데이터를 클라이언트에 실시간으로 전달하잖아요. 근데 그러면 프론트에 부담이 좀 있을거 같은데 코드 스플리팅이나 레이지 로딩같은 처리는 설계가 안되어있나요?"에 답하며 문서를 대조해 빈칸 다섯과 문서 사이 어긋남 하나를 찾았다. 소유자 요청 "빠진 다섯 가지와 d2 §3.3 어긋남을 frontend.md에 보강하고, 결정은 새 ADR로 남겨 주세요. 숫자는 추천값(잠정)으로 정해 주세요."에 따라 아래처럼 정했다. 모두 추천 적용이다. 추천 적용은 소유자가 방향을 승인하고 세부를 맡긴 부분에서 제안해 적용한 값으로, 바꾸고 싶으면 언제든 바꾼다. 숫자는 모두 [가정]이고 wbs 7.5.2 측정 캠페인에서 바꾼다.) 2026-10-27(ADR-0092): 관제 콘솔의 상태 저장소는 Zustand다. 맥락의 `alerts` 슬라이스는 Zustand 호스트 저장소의 슬라이스로 읽는다(docs/frontend.md §3.1·§3.10). 2026-10-28(ADR-0100, 소유자 승인 '추천안 동의'): 결정 3의 멈춤 규칙(무엇을 언제 멈추나)은 그대로이고 수단만 바꾼다. graphql-ws 구독마다 `complete`를 보내는 대신, 보이는 위젯 목록이 바뀌면 1초 묶어 SSE 위젯 흐름을 새 목록으로 다시 연다. 경보·명령 확인·자동 제어 상태는 늘 여는 SSE 흐름으로 숨긴 동안에도 받는다(docs/frontend.md §5.7). 2026-10-28(기술 검토 낮음-172, 소유자 승인 '추천안 동의'): 검토한 대안의 uPlot 기각 이유 '1년 넘게 새 판이 없다'와 되돌릴 조건의 'Chart.js가 1년 넘게 새 판을 내지 않으면'은 한 라이브러리에만 쓴 기준이었다. 이제 모든 의존성에 같은 기준을 쓴다: 어느 배포 태그든(베타 포함) 마지막 게시가 12개월보다 오래되면 위험 구성 요소 표에 올리고 대안과 바꿀 조건을 적는다. 안정판만 오래되고 다음 판을 12개월 안에 내는 라이브러리는 올리지 않는다(예: RxJS 7.8.2는 2025-02-22, 9.0.0-beta.1은 2026-10-09). 관제 콘솔의 RxJS 어댑터는 같은 날 작은 함수 둘로 바뀌었고(기술 검토 낮음-097), 백엔드는 NestJS의 동반 의존성으로만 RxJS를 쓴다(docs/devops.md §4.4, docs/frontend.md §5.14.5). 2026-10-28(기술 검토 낮음-097, 소유자 승인 '추천안 동의'): 결정 3의 구독 묶기 수단 RxJS `share`(`resetOnRefCountZero` 10초 타이머)를 호스트 스트림 어댑터의 작은 함수 `shareByKey`(구독자 수를 세고 0이 되면 10초 뒤 닫음)로 읽는다. 멈춤 규칙과 10초는 그대로다(docs/frontend.md §3.1·§5.7). 2026-10-28(기술 검토 낮음-098, 소유자 승인 '추천안 동의'): 결정 2의 늦게 싣는 부분 가운데 끌어 놓기 목록(`@hello-pangea/dnd`)은 없앤다. 순서 바꾸기는 위로·아래로 버튼만 쓰고, 늦게 싣는 부분은 에디터·시뮬레이터·그래프 셋이다(같은 날 기술 검토 낮음-100으로 서식 글 편집기를 더해 넷이 된다, docs/frontend.md §5.6). 2026-10-28(기술 검토 낮음-024, 소유자 승인 '추천안 동의'): 결정 3의 '파트너 판매 현황 SSE는 숨긴 탭에서도 연결을 그대로 둔다'를, 1분 주기 조회로 바꾸면서 '숨긴 탭은 5분 [가정]마다 묻고 다시 보이면 바로 한 번 묻는다'(이 ADR의 조회 주기 늘리기 규칙)로 바꾼다(docs/frontend.md §4.4.3). 2026-10-29(소유자 결정, ADR-0152): '남는 한계'의 '2인 승인 요청은 관제 푸시 팝업으로만 온다'는 승인 권한자의 온콜 앱 푸시를 더해 메웠다(review/open-items.md 34번, docs/observability.md §5).

## 맥락

- **부담은 두 종류다**
  - 처음 열 때의 무게: 브라우저가 처음 내려받아 실행하는 코드의 양이다. 코드 분할(코드를 화면·기능별로 쪼개 필요한 만큼만 보내는 것)과 늦게 싣기(당장 쓰지 않는 부분은 쓸 때 불러오는 것, 지연 로딩)가 줄인다.
  - 켜 둔 동안의 무게: 데이터가 계속 들어올 때 화면을 다시 그리는 횟수와 쌓이는 메모리다. 코드 분할로는 줄지 않는다. 갱신을 묶어 그리기, 안 보이는 것은 멈추기, 들고 있는 양에 상한 두기, 긴 목록은 보이는 줄만 그리기가 줄인다.
- **실제 데이터 양**: 파트너 콘솔의 실시간 판매 현황은 SSE(서버가 브라우저로 한 방향으로 계속 보내는 통신)로 1분에 한 번 전체 숫자를 받는다(ADR-0079 결정 11). 관제 콘솔은 초당 3만 건의 원천 사건을 받지 않고, Flink(흘러드는 사건을 실시간으로 계산하는 도구)가 1초 단위로 합친 숫자를 위젯마다 GraphQL 구독(서버가 값이 바뀔 때마다 밀어 주는 요청)으로 받는다(control-tower §2, ADR-0071). 그래서 부담은 네트워크보다 화면 다시 그리기와, 하루 종일 켜 두는 화면의 메모리에 생긴다.
- **이미 있던 것**: 관제 위젯은 따로 빌드·배포되는 원격 모듈이고 `load()`로 필요할 때 실린다(docs/frontend.md §4.5). 첫 화면 JS 예산(관제 호스트 250KB·원격마다 80KB, 파트너 경로마다 250KB, 좌석맵 에디터는 늦게 싣는 덩어리 300KB, §5.8), 위젯 갱신을 250ms 단위로 묶기(RxJS `auditTime`, §5.7), 위젯이 쓰는 칸만 받는 영속 쿼리(§4.6), 회차별 Socket.IO 방(§4.4.4), 표의 커서 페이지와 가상 스크롤(design/d2 CMP-031)이 있었다.
- **비어 있던 것**
  1. 관제 콘솔 화면 16개(SCR-028~032·045~049·053·064~068)를 화면마다 따로 싣는 규칙이 없었다. 따로 실리는 것은 위젯뿐이었다.
  2. 파트너 콘솔에서 무엇을 늦게 실을지가 예산 표의 '에디터는 늦게 싣는 덩어리'뿐이었다. 시뮬레이터·끌어 놓기 라이브러리·그래프와 방법(`next/dynamic`)이 없었다.
  3. 안 보이는 위젯(대시보드의 고르지 않은 탭, 접은 위젯, 숨긴 브라우저 탭)의 구독을 멈추는 규칙이 없었다. 좌석맵에는 '보이는 구역만 구독' 규칙이 있다(seat-hold §7, ADR-0063).
  4. 시계열 그래프(CMP-033)를 SVG로 그릴지 Canvas로 그릴지, 어떤 라이브러리를 쓸지, 선 하나에 점을 몇 개까지 브라우저 메모리에 둘지 없었다. 경보 목록(`alerts` 슬라이스)에도 상한이 없었다.
  5. 콘솔의 켜 둔 동안 성능 시험이 없었다. Lighthouse CI 대표 주소에 콘솔이 없고, memlab(브라우저 메모리 누수를 찾는 도구) 대상은 좌석맵과 포렌식뿐이며, 장시간 운영 목표(NFR-027)는 서버만 대상이다. 조작 반응 목표(INP 200ms, NFR-012)는 콘솔에도 걸려 있다.
  6. design/d2 §3.3은 관제 위젯의 오류 격리를 `useSuspenseQuery`·`QueryErrorResetBoundary`(TanStack Query 라이브러리의 기능)로 적었는데, 관제 콘솔의 서버 데이터 도구는 urql이다(ADR-0079 결정 31).
- **고르는 기준**: ① 규칙은 원격 위젯을 만드는 팀마다 지키게 하기보다 호스트 한 곳에서 강제한다. ② 운영자가 꼭 알아야 하는 신호(경보·명령 확인·자동 제어 상태)는 멈추지 않는다. ③ 측정 전 값은 [가정]으로 두고 시험으로 지킨다. ④ 새 의존성은 공급망 규칙(docs/frontend.md §5.14.5)으로 고른다.
- **확인한 사실**(2026-10-27 원문과 레지스트리)
  - Next.js 늦게 싣기 안내(2026-03-10 갱신판): 서버 컴포넌트는 기본으로 코드가 나뉜다. 늦게 싣기는 클라이언트 컴포넌트에 쓰며 `next/dynamic` 또는 `React.lazy()`와 Suspense로 한다. `ssr: false`는 클라이언트 컴포넌트 안에서만 쓸 수 있다.
  - React Router 8.5.0(2026-10-19): 데이터 라우터(`createBrowserRouter`)의 경로 객체 `lazy`로 첫 묶음 크기를 줄인다.
  - Module Federation 런타임 `preloadRemote`(`@module-federation/enhanced/runtime`, 2.9.2): 원격의 진입 파일·내보낸 모듈·동기·비동기 자원을 미리 받고, 하나라도 실패하거나 시간이 넘으면 거절된 Promise를 돌려준다.
  - RxJS 7.8.2 `share`의 `resetOnRefCountZero`: 구독자 수가 0이 될 때 원천 구독을 끊을지 정하고, 알림 함수를 주면 늦춰서 끊을 수 있다.
  - graphql-ws 프로토콜: 한 연결에서 작업마다 ID를 쓰고, 클라이언트가 `Complete`를 보내면 그 구독만 멈춘다.
  - Chart.js 4.6.1(2026-10-22, MIT, 의존성 `@kurkle/color` 하나): Canvas로 그리고, 쓰는 컨트롤러·요소·축·플러그인만 등록하면 묶음에서 나머지가 빠진다. 점 줄이기(Decimation) 플러그인은 선 그래프·x축 `linear`나 `time`·`parsing: false`일 때 쓰고, 방식은 `lttb`와 `min-max`(꼭짓점을 지키며 픽셀마다 점 최대 4개)이며 기본 시작 기준은 캔버스 폭의 4배다. 성능 안내는 `parsing: false`·`normalized: true`·애니메이션 끄기(끄면 선 그래프가 Path2D 캐시를 쓴다)·축 최소·최대 지정이다. 시간 축(`time`)은 날짜 라이브러리와 어댑터가 더 필요하다. Canvas 내용은 화면 낭독기가 읽지 못하므로 `role`·`aria-label`이나 대체 내용을 붙여야 한다.
  - 크기(jsDelivr 배포 파일을 받아 gzip -9로 잰 값, 2026-10-27): Chart.js 4.6.1 전체 UMD 69.2 KiB, uPlot 1.6.32 21.5 KiB(마지막 게시 2025-03-14), ECharts 6.1.0 전체 359.3 KiB·`simple` 판 164.9 KiB, `@hello-pangea/dnd` 18.0.1 UMD 28.6 KiB.
  - Chrome: 메모리 절약(기본으로 켜짐)은 쓰지 않는 탭을 비활성화하고 다시 열면 새로 불러온다. '항상 활성 상태로 유지할 사이트' 목록과 기업 정책 `TabDiscardingExceptions`(Chrome 108부터)로 뺄 수 있다. Chrome 133부터 에너지 절약 모드는 5분 넘게 숨겨지고 소리가 없으며 CPU를 많이 쓰는 탭을 얼린다(사건 처리가 멈췄다가 다시 보이면 이어서 처리한다).

## 결정

### 가. 처음 싣는 코드

1. **관제 콘솔은 화면마다 따로 싣는다.** 관제 호스트는 React Router 8 데이터 라우터의 경로 `lazy`로 화면 16개를 화면마다 따로 싣는다. 첫 화면 묶음에는 셸(위 상태 바·메뉴·경보 패널)과 로그인·대시보드 틀만 넣는다. 대시보드 위젯은 원래대로 원격이다.
   - 예산: 호스트 첫 화면 250KB는 그대로 두고, 화면으로 처음 이동할 때 더 받는 JS를 화면마다 80KB [가정] 이하로 둔다(gzip).
   - 미리 받기: 대시보드를 처음 그린 뒤 2초 [가정]가 지나면 명령 화면(SCR-030) 덩어리를 낮은 우선순위로 받는다. 비상 때 첫 클릭이 내려받기를 기다리지 않게 하려는 것이다. 그다음 다음 단계 탭(T-30분 점검 → T=0 → 판매 중 → 종료 후. 입장 탭은 공연 당일)의 원격을 `preloadRemote`로 미리 받는다. 메뉴 항목에 포인터가 올라가거나 초점이 가면 그 화면의 `lazy`를 미리 부른다.
   - 미리 받기가 원격 무결성 확인(`createScript` 훅, ADR-0079 결정 16)을 거치는지는 wbs 4.5.5 PoC에서 함께 확인한다. 거치지 않으면 원격은 미리 받지 않는다.
   - 실패: 화면 덩어리를 받지 못하면 그 화면 자리만 "화면을 불러오지 못했습니다 [다시 시도]"로 바꾸고 셸과 경보 패널은 그대로 둔다. 배포 식별자가 바뀌었으면 "새 버전이 있습니다 [새로고침]"을 함께 보인다.
2. **파트너 콘솔은 무거운 부분을 쓸 때 싣는다.** 경로 사이는 Next.js App Router가 나누고, 한 경로 안의 무거운 클라이언트 부분은 클라이언트 컴포넌트 파일 안에서 `next/dynamic`으로 싣는다. 늦게 싣는 것과 예산은 아래와 같다.
   - 좌석맵 에디터 캔버스·에디터 Worker·도구(SCR-022): 에디터 경로에서 계층 트리와 뼈대를 그린 뒤, `ssr: false`. 300KB(그대로).
   - 판매 정책 시뮬레이터(DSL AST 평가기를 `@peaket/validation/dsl` 하위 진입점으로, SCR-024): [시뮬레이션]을 열 때. 30KB [가정].
   - 끌어 놓기 목록(`@hello-pangea/dnd`, CMP-050): 그 목록이 나오는 단계에 들어올 때. 40KB [가정].
   - 그래프·히트맵(Chart.js, CMP-033·034, SCR-023·026·027): 숫자 타일을 먼저 그린 뒤. 60KB [가정].
   - 경로 첫 JS 250KB는 그대로다. 첫 화면 덩어리에 위 넷이 들어가면 CI가 실패한다(FE-T25).

### 나. 켜 둔 동안의 부담

3. **안 보이는 위젯은 구독을 멈춘다. 멈춤은 호스트가 한다.**
   - 위젯은 `ConsoleServices.graphql.subscribe`를 효과(`useEffect`) 안에서 열고 정리 함수에서 닫는다. 그리는 중에 구독하지 않는다. 호스트는 위젯 자리마다 따로 만든 `ConsoleServices`를 넘기고, 그 안에서 멈추고 다시 연다. 위젯은 자기가 보이는지 따지지 않는다.
   - 같은 영속 쿼리·변수의 구독은 호스트가 하나로 묶어 나눠 준다(RxJS `share`). 마지막 구독자가 떠나도 10초 [가정] 동안 열어 두었다가 닫는다(`resetOnRefCountZero`에 10초 타이머). 탭을 오가며 확인해도 구독을 닫았다 여는 일이 반복되지 않는다.
   - 구독을 닫는 때: ① 대시보드에서 고르지 않은 탭의 위젯(그리지 않으므로 10초 뒤 닫힌다) ② 브라우저 탭이 30초 [가정] 넘게 숨겨졌을 때(호스트가 위젯 구독과 주기 조회를 모두 멈춘다) ③ 회차를 바꿀 때(이전 회차 구독은 10초를 기다리지 않고 바로 닫고 방을 옮긴다).
   - 접은 위젯: 구독은 그대로 두고 머리(제목·상태 점·핵심 숫자 한 줄)만 그린다. 휴대폰의 접힌 위젯 목록(design/d5 §3.3)과 같은 모양이라, 핵심 숫자는 계속 바뀌어야 하기 때문이다. 이를 위해 `WidgetProps`에 `collapsed`를 더한다.
   - 화면 밖으로 스크롤된 위젯: 구독은 그대로 두고(위젯마다 초당 1건 안팎이라 작다) 그리기만 멈춘다. 호스트가 `IntersectionObserver`로 보이는지 보고, 안 보이는 동안은 마지막 값만 들고 있다가 보이면 넘긴다.
   - 멈추지 않는 것: Socket.IO 연결(`alert`·`command:ack`·`presence`), 위 상태 바가 쓰는 `control`·`autoActions` 구독, 세션·유휴 처리. 탭을 숨긴 동안 SEV1·SEV2 경보나 내 승인 대기가 있으면 탭 제목 앞에 수를 붙인다(예: `(SEV1 1 · 승인 1) 관제`).
   - 다시 보일 때: 닫았던 구독을 다시 연다. 그래프 위젯은 최근 15분 창을 영속 쿼리로 한 번 받아 채운다. 첫 값이 올 때까지는 마지막 값을 'n초 전'과 함께 보인다(5초가 넘으면 경고 색, 기존 신선도 규칙). graphql-ws는 구독마다 `complete`로 닫으므로 연결은 다시 맺지 않는다.
   - 파트너 콘솔: 숨긴 탭에서도 SSE는 유지한다(1분에 한 번이라 작다). 현장 운영의 10초 조회는 숨긴 동안 60초 [가정]로 늘리고, 다시 보이면 바로 한 번 묻는다.
   - 관제 PC: 관제 PC의 Chrome은 기업 정책 `TabDiscardingExceptions`(또는 설정의 '항상 활성 상태로 유지할 사이트')에 콘솔 주소를 넣어, 숨긴 콘솔 탭이 비활성화되어 새로 불리지 않게 한다. 숨긴 동안 위젯을 멈추면 CPU를 덜 써서 에너지 절약 모드가 탭을 얼릴 조건에서 멀어진다. 얼리지 않는다고 장담하지는 못한다(남는 한계).
4. **그래프는 Canvas로 그리고, 브라우저가 들고 있는 양에 상한을 둔다.**
   - CMP-033 TimeSeriesChart는 Chart.js 4로 Canvas 2D에 그린다. 선·막대 컨트롤러와 요소, `LinearScale`, 채우기(`Filler`)·점 줄이기(`Decimation`)·툴팁 플러그인만 등록한다. x축은 `linear`(밀리초)로 두고 눈금 글자는 `Intl.DateTimeFormat`으로 쓴다. 시간 축은 날짜 라이브러리와 어댑터를 더 실어야 해서 쓰지 않는다.
   - 실시간 갱신은 `animation: false`, `parsing: false`, `normalized: true`, 축의 최소·최대 지정, `chart.update('none')`로 한다. 점이 캔버스 폭의 4배(플러그인 기본값)를 넘으면 `min-max` 방식으로 줄인다(꼭짓점을 지킨다).
   - 라이브러리는 `@peaket/ds`의 `TimeSeriesChart` API 뒤에 숨긴다. Chart.js가 1년 넘게 새 판을 내지 않거나 예산을 넘으면 직접 그리는 작은 모듈로 바꿀 수 있게 하려는 것이다. 관제에서는 `chart.js`를 공유 싱글턴에 더해(처음 그래프를 그릴 때 한 번 받는다) 원격마다 따로 싣지 않는다.
   - 접근성: `<canvas role="img" aria-label="{요약}">`을 두고, 기존 표 보기 전환(CMP-033)을 그대로 둔다.
   - CMP-034 HeatmapGrid는 DOM 격자로 그리고 값이 바뀐 칸만 다시 그린다. 구역이 400개 [가정]를 넘으면 표 보기로 연다.
   - 보관 상한: 관제 그래프 한 선은 최근 15분(1초 점 900개) [가정]만 고리 버퍼(정해진 크기를 돌려 쓰며 오래된 값부터 덮어쓰는 배열)에 두고, 더 긴 기간은 '자세히 보기 ↗'(Grafana)로 본다(ADR-0067). 그래프 한 장의 선은 6개 [가정]까지다. 파트너 분당 판매는 SSE가 최근 180분 [가정]만 싣는다(SSE 형식 초안 변경, wbs 0.2.3). 경보 목록은 걸린 경보 전부와 풀린 지 60분 [가정] 안의 것을 합쳐 500건 [가정]까지 두고, 풀린 것 가운데 오래된 것부터 버린다. 지난 경보는 감사 로그(SCR-031)와 Grafana에서 본다. 경보 목록이 50줄 [가정]을 넘으면 가상 스크롤로 그린다. 운영 빌드에는 상태 저장소의 개발 도구 연결을 넣지 않는다(FE-T21).

### 다. 지키는 장치

5. **콘솔의 켜 둔 동안 성능을 시험으로 지킨다.**
   - FE-T25 덩어리 나눔(PR): 관제 첫 화면 묶음에 다른 화면 덩어리가 없고 화면 덩어리가 80KB 이하인지, 파트너 첫 화면 묶음에 에디터·시뮬레이터·끌어 놓기·그래프가 없는지 빌드 산출물의 덩어리 목록으로 본다.
   - FE-T26 안 보이는 위젯(PR): 가짜 GraphQL·Socket.IO 서버와 가짜 시계로 탭 전환·위젯 접기·브라우저 탭 숨김·회차 바꾸기를 만들고, 열린 구독 수(떠난 탭은 10초 뒤, 숨긴 탭은 30초 뒤 위젯 구독 0), 접은 위젯은 머리만 그리는지, 경보·명령 확인 수신 유지, 탭 제목의 수, 다시 보일 때의 재구독·창 채우기·신선도 표시를 본다.
   - FE-T27 장시간·스트림 부하(측정 캠페인 wbs 7.5.2): Playwright로 판매 중 탭을 열고, 가짜 스트림(위젯마다 초당 1건, 1분 동안 경보 초당 20건 [가정])을 4시간 [가정] 흘리며 탭과 회차를 20번 [가정] 바꾼다. 통과 기준은 처음 30분 뒤 JS 힙(가비지 수거 뒤)의 시간당 증가 5% [가정] 이하, DOM 노드 수가 늘지 않음, 평상 구간 긴 작업 0, 탭 전환과 명령 화면 열기 INP 200ms(데스크톱 프로필과 CPU 4배 태블릿 프로필), memlab 탭 순환 시나리오 누수 0, 그래프 점 수가 상한 안이다. 파트너 판매 현황은 8시간 [가정] SSE로 같은 힙·DOM 기준을 본다.
   - Lighthouse CI 대표 주소에 관제 대시보드 데모와 파트너 판매 현황 데모(가짜 API)를 더한다.

### 라. 문서 어긋남

6. **design/d2 §3.3의 관제 위젯 오류 격리 문장을 정본에 맞춘다.** 위젯마다 오류 경계(CMP-035)가 그 칸만 오류 카드로 바꾸고, [다시 시도]는 그 위젯의 쿼리만 다시 실행한다고 고친다(관제 콘솔의 서버 데이터 도구는 urql이다, docs/frontend.md §3.1). docs/appendix-learning-map.md 본문의 같은 말은 쓴 그대로 두는 문서라 고치지 않는다.

## 검토한 대안

- **관제 화면도 원격 모듈로 쪼개기**: 원격은 서비스 팀이 위젯을 따로 배포하려는 장치다. 화면은 호스트 팀이 만들므로 경로 `lazy`로 충분하고, 원격이 늘면 무결성 확인과 계약 판 관리만 늘어난다.
- **위젯이 스스로 보이는지 따져 구독을 멈추기**: 원격 저장소가 여럿이라 팀마다 지키는지 확인하기 어렵다. 호스트가 `ConsoleServices` 안에서 하면 한 곳에서 강제하고 FE-T26 하나로 본다.
- **숨긴 탭에서도 모든 구독 유지**: 숨긴 콘솔이 CPU를 계속 쓰면 노트북·태블릿 배터리를 쓰고, Chrome 에너지 절약 모드가 탭을 얼릴 조건(CPU를 많이 쓰는 숨긴 탭)에 가까워진다.
- **숨기면 바로 멈추기**: 위젯의 '자세히 보기 ↗'가 Grafana를 새 탭으로 여는 일이 잦아(ADR-0067) 돌아올 때마다 다시 받게 된다. 30초 유예를 둔다.
- **화면 밖 위젯도 구독 멈추기**: 스크롤할 때마다 구독을 닫고 여는 일이 생긴다. 위젯 데이터가 작아 그리기만 멈춘다.
- **접은 위젯도 구독 닫기**: 휴대폰은 위젯을 접힌 목록으로 시작하고 접힌 줄에 핵심 숫자를 보인다(design/d5 §3.3). 구독을 닫으면 그 숫자가 멈추므로, 그리기만 머리로 줄인다.
- **그래프 라이브러리**: SVG로 그리는 라이브러리(예: Recharts)는 선·점이 DOM 요소라 900점 × 6선을 초마다 다시 그리면 DOM 일이 커진다. uPlot은 가장 작지만(21.5 KiB) 마지막 게시가 2025-03-14라 1년 넘게 새 판이 없고, 막대·채우기 같은 것을 직접 만들어야 한다. ECharts 6은 기능이 많지만 `simple` 판만 164.9 KiB라 원격 예산(80KB)과 맞지 않는다. 직접 그리기는 가장 작고 공급망 위험이 없지만 축·눈금·툴팁·크기 변경·고해상도 화면 처리를 모두 만들어야 해서, Chart.js가 멈출 때의 대체로 둔다.
- **그래프를 Worker(OffscreenCanvas)에서 그리기**: Chart.js가 지원하지만 툴팁처럼 DOM을 쓰는 플러그인이 동작하지 않고 크기 변경을 직접 해야 한다. 위젯마다 초당 한 번 그리므로 메인 스레드로 시작하고, FE-T27에서 긴 작업이 나오면 다시 본다.
- **온세일 70분 전체를 1초 점으로 들고 있기**: 선마다 4,200점이고 그래프가 늘수록 커진다. 관제 그래프는 판단용 최근 창만 들고, 원인 분석은 Grafana로 보낸다는 원칙(ADR-0067)과도 맞다.

## 결과와 트레이드오프

- 관제 첫 화면이 화면 수에 따라 커지지 않는다. 숨긴 콘솔이 쉬어 CPU와 배터리를 아끼고, 하루 종일 켜 두는 화면의 메모리를 시험으로 지킨다.
- 대가: 숨겼다가 돌아오면 위젯 숫자가 1초 안팎 늦게 채워진다(그동안 마지막 값과 'n초 전'). 관제 그래프는 최근 15분만 보인다. 의존성 Chart.js가 하나 늘어난다(3일 대기·잠금 파일·SBOM 같은 공급망 규칙을 따른다). 탭을 숨긴 동안 탭 제목에 경보·승인 대기 수가 보인다(관리자 IP로 제한한 배포의 화면이다).
- 고친 곳: docs/frontend.md(§2.3·§3.2·§3.10·§4.4.3~§4.4.6·§4.5·§5.6·§5.7·§5.8·§5.9·§5.17·§6.1~§6.4), design/d2(§3.3, CMP-033·034), design/d5(§3.3, §6.9, §7.2), docs/features/control-tower.md(§11·§12), docs/architecture.md(§6.2·§6.5), ADR-0079 상태 줄, wbs(4.5.5 +1.5일, 7.5.2 +1일, 436 → 438.5일), planning/00·01(ADR 수·일정, §5.2 새 행), guide/12·17, review/open-items.md(34번, 25번에 덧붙임), review R-109, 00-summary.

## 되돌릴 조건

- FE-T27에서 숨겼다 돌아온 뒤 첫 값까지 2초 [가정]를 넘는 일이 잦으면, 30초 유예를 늘리거나 숨긴 동안 그래프 창만 가끔 받는 방식으로 바꾼다.
- Chart.js가 1년 넘게 새 판을 내지 않거나 그래프 덩어리 예산(60KB)을 넘으면 직접 그리는 모듈로 바꾼다.
- 위젯 데이터가 초당 1건보다 훨씬 많아지면(예: 좌석 단위 실시간) 화면 밖 위젯도 구독을 멈춘다.
- Canvas 그리기가 긴 작업을 만들면 Worker(OffscreenCanvas) 그리기를 새 ADR로 정한다.

## 남는 한계

- 브라우저가 숨긴 탭을 얼리면(Chrome 에너지 절약 모드) 경보와 2인 승인 요청도 탭이 다시 보일 때까지 처리되지 않는다. 경보의 1차 통로는 온콜 알림이지만, 2인 승인 요청은 지금 관제 푸시 팝업으로만 온다(design/d5 §9.1). 온콜 채널로도 보낼지는 정하지 않았다(review/open-items.md 34번).
- 관제 PC의 브라우저 설정(탭 비활성화 예외)은 사람이 해야 한다. 빠진 PC에서는 숨긴 탭이 돌아올 때 새로 불린다(주소의 회차·탭과 세션은 남는다).
- 장시간 시험은 가짜 스트림과 실험실 기기로 한다. 실제 온세일의 경보 폭주 모양과 다를 수 있다.
- 크기 숫자는 배포 파일 전체를 잰 값이라, 필요한 부분만 등록한 실제 덩어리 크기는 wbs 7.5.2에서 다시 잰다.
