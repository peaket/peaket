# ADR-0281: 구현을 먼저 하고, 독립 시험 담당이 뒤에 시험을 쓴다(2026-11-16)

- **상태**: 채택(2026-11-16, 소유자 결정 "다음 웨이브 부터는 TDD 말고 구현 -> 테스트 정방향으로 가는게 좋겠네요. 다만 독립적으로 에이전트를 쓰는거는 기존과 동일하고요(실패하는 테스트 작성하는 등 테스트 통과후 리뷰 이런것들은 기존과 동일)"). ## 맥락

- 웨이브 7(2026-11-16)은 ADR-0270대로 시험 담당이 구현 전에 시험과 빈 뼈대를 쓰고 실패를 본 뒤 구현 담당이 통과시켰다. 독립 리뷰는 갈래 1·2의 웨이브 끝에서 높음을 셋씩 잡았다.
- 시험을 먼저 쓰려면 시험 담당이 공개 인터페이스를 미리 정해 빈 뼈대를 만들어야 했다. 바탕(클러스터 접속 정보 등)이 구현 몫이라 실패를 볼 수 없는 시험이 생겼고(BAT-055 kind 38개), 구현을 둘로 나누거나 정책 객체를 지운 클러스터를 따로 띄워야 했다.
- 같은 날 소유자가 다음 웨이브부터 구현 → 시험 차례(정방향)로 바꾸고, 담당을 서로 다른 에이전트로 나누는 것, 실패하는 시험으로 증명하는 것, 시험이 통과한 뒤 리뷰하는 것은 그대로 두라고 정했다.

## 결정

1. **묶음 안 차례(정방향)**: 계획 → 정본 빈칸 → 구현 → 시험(독립 시험 담당) → 시험 통과 → 대조 리뷰 → 지적 반영 → 검증 → 게이트·기록. 웨이브 끝 비싼 검사(ADR-0267)와 갈래 1·2의 묶음마다 비싼 검사(PROGRESS 턴 규칙)는 그대로다.
2. **시험 담당은 구현을 따라 쓰지 않는다.** 시험 담당은 계획의 시험 목록·정본·지시서로 시험을 쓴다. 구현의 공개 인터페이스(함수·API·이벤트의 모양)는 읽어도 되지만, 단언 값은 정본에서 가져오고 코드가 하는 일을 옮겨 적지 않는다. 시험 담당은 제품 코드를 바꾸지 않고, 구현 담당은 시험 파일을 바꾸지 않는다(ADR-0270 결정 1 그대로).
   - 새 시험이 구현에서 실패하면 시험 담당이 계획 파일 '시험 결과' 절에 적는다. 계획 담당이 정본으로 가린다: 구현 결함이면 구현 담당이 고치고(`Fix-By: impl`), 시험 결함이면 시험 담당이 고친다('시험 이의'). 리뷰는 시험이 모두 통과한 뒤에 시작한다.
3. **실패하는 시험으로 증명하는 것은 그대로다.** 모든 행동 시험은 한 번은 실패를 본다.
   - 시험 담당은 새 시험을 구현 전 트리(묶음 가지의 기준 커밋)에서 돌려, 새로 생긴 동작을 보는 시험이 실패하는 것을 계획 파일 '실패 확인' 절에 적는다. 실행조차 안 되는 실패(파일을 못 읽음, 바탕이 없음)는 세지 않는다.
   - 구현 전 트리에서 실패를 볼 수 없는 시험(이미 있던 동작, 바탕이 구현 몫)과 처음부터 통과한 시험은 검증 담당의 틀린 구현(A등급은 항목마다, B등급은 표본)으로 실패를 본다. 실패를 본 적 없는 시험은 지금처럼 완료 근거로 세지 않는다.
   - 리뷰·검증·게이트가 찾은 결함은 지금처럼 시험 담당이 재현 시험을 먼저 써서 실패를 보고 구현 담당이 고친다(§8.6의 5).
4. **적용 시점**: 이 ADR이 develop에 들어온 뒤 계획 커밋을 처음 만드는 묶음부터다. 이미 시험 먼저로 계획·시험 커밋이 있는 묶음(BAT-060, BAT-415, BAT-420, W8-audit2a 등)은 그 차례대로 끝낸다.
5. **역할 확인(roles-check)**: 정방향 묶음은 계획 커밋에 `Batch-Order: impl-first`를 단다. 그 묶음에서는 '첫 시험 커밋이 첫 구현 커밋보다 먼저'를 보지 않고 대신 다음을 본다: 첫 리뷰 커밋이 첫 시험 커밋 뒤에 있다, 시험 커밋(리뷰 반영의 `Fix-By: test` 포함)은 시험 파일과 문서만 바꾼다(빈 뼈대가 필요 없으므로), 마지막 검증 커밋이 마지막 코드 고침 뒤에 있다(R-653 그대로). 꼬리말이 없는 묶음은 지금처럼 시험 먼저로 본다. 스크립트 고침은 갈래 1이 웨이브 8 안에서 하고, 고치기 전에 합치는 정방향 묶음은 감독이 같은 항목을 손으로 본다.

## 결과

- 시험 담당이 인터페이스를 미리 추측하지 않아도 되고, 바탕이 구현 몫인 시험도 구현 뒤 바로 돌릴 수 있다.
- 시험이 구현을 따라 쓰일 위험이 커진다. 정본에서 단언 값을 가져오는 규칙, 구현 전 트리에서의 실패 확인, 검증 담당의 틀린 구현, 독립 리뷰로 막는다.

## 되돌릴 조건

- 정방향 첫 두 웨이브에서 검증 담당의 틀린 구현을 시험이 놓치는 비율이 웨이브 7(시험 먼저)보다 뚜렷이 높으면 시험 먼저로 돌아갈지 소유자에게 묻는다.

## 확인

- 웨이브 8·9가 끝나면 묶음마다 틀린 구현을 놓친 비율, 리뷰 높음 수, 묶음당 시간을 웨이브 7과 견주어 여기에 적는다.
