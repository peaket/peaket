# ADR-0199: 화면을 먼저 잇고 서버가 생기기 전에는 계약 모양의 가짜 API로 띄운다 — 홈 데이터 경로와 이미지 파생본 주소

- **상태**: 채택(2026-11-05). 순서는 소유자 결정이다(2026-11-05, "화면 먼저 (추천)"). 세부는 추천 적용이다(wbs 2.10.1 세부는 추천 적용이라는 승인 2026-10-14·2026-10-28). BUILD_ORDER HOT-300.
- **관련**: ADR-0063(홈 구성), ADR-0093(공연 카드), ADR-0170(화면 퍼블리싱), ADR-0193(응답 때 해시), ADR-0196(api-client 생성물), [docs/frontend.md](../frontend.md) §2.5·§5.14.1, [docs/data.md](../data.md) §1 'S3 공개 정적 객체', [docs/api/openapi.yaml](../api/openapi.yaml) `getHome`·`getHomeRankings`·`listWishes`·`listSubscriptions`·`ProductionCard`·`HomeFeed`
- **관련 ID**: FR-003, FR-004, FR-019, POL-043, SCR-001, FE-T21

## 맥락

- 홈(HOT-300)이 읽는 홈 피드 API(`GET /v1/home`)를 만들 단계가 BUILD_ORDER에 없었다. 그 서버가 기대는 검색 읽기 모델(HOT-270)과 홈 구성 표(OPS-410)는 뒤에 있다. 랭킹 파일 게시는 OPS-230이고, 찜 목록(`GET /v1/wishes`)은 GAT-260, 알림 신청은 알림 단계가 만든다.
- 퍼블리싱한 화면(ADR-0170)은 목업 값과 `?state=`로 그려졌다. 데이터 단계는 그 화면에 데이터를 잇고 목업을 걷어 낸다.
- 공연 카드의 `posterUrl`과 배너의 `imageUrl`은 주소 하나다. 그런데 정본은 파생본(폭 320·640·960·1,280px × AVIF·WebP)을 `<picture>`와 사용자 로더로 고르게 한다(docs/frontend.md §5.14.1). 그래서 주소 하나에서 파생본 주소를 만드는 규칙이 필요한데, 그 규칙이 없었다.

## 결정

1. **화면을 먼저 잇는다(소유자 결정 2026-11-05)**:
   - 화면 단계는 서버를 기다리지 않는다. `@peaket/api-client` 생성 함수로 계약 경로를 부른다.
   - 서버를 맡을 단계는 BUILD_ORDER에 적는다. 홈 피드 서버는 새 단계 HOT-305다(검색 읽기 모델 HOT-270·홈 구성 OPS-410 뒤).
   - 뒤의 화면 단계(상세·검색 등)도 같은 방식으로 간다.
2. **개발·브라우저 확인은 계약 모양의 가짜 API로 띄운다**:
   - `apps/web/scripts/mock-api.mjs`는 로컬 전용 HTTP 서버다(127.0.0.1에만 묶는다). 화면이 쓰는 경로마다 고정 자료(`apps/web/scripts/mock-api/*.json`)를 낸다.
   - 상태(빈 피드·랭킹 밀림·비로그인 등)는 `/__mock/state`로 바꿔 화면 상태를 본다. 파생본 이미지 주소에는 자리 그림(SVG)을 낸다.
   - 고정 자료가 계약 Zod(`@peaket/contracts` 생성물)를 지나는지는 web 시험이 본다. 그래서 계약이 바뀌면 고정 자료도 함께 고친다.
   - MSW 처리기(`@peaket/api-client/mocks`)는 무작위 값이라 화면 확인에 쓰지 않고, 시험·이야기(Storybook)에만 쓴다.
   - 화면 앱의 운영 코드는 `@peaket/api-client/mocks`·`msw`·`@faker-js/faker`를 가져오지 않는다(린트가 막는다, ADR-0196). 운영 묶음에 MSW 글자가 없는지는 FE-T21이 본다.
3. **홈의 데이터 경로**:
   - 홈 피드는 서버가 빌드 때와 ISR 때 `'use cache'` 함수에서 부른다(`cacheLife` 60초, `cacheTag('home')`, docs/frontend.md §2.5). 홈은 요청 값을 읽지 않아 빌드 때 그려진다.
   - 서버 API 주소(`PEAKET_API_ORIGIN`)가 없으면 부르지 않고 빈 피드로 그린다. 그러면 섹션이 숨는다(SCR-001 '섹션 비어 있음'). CI 빌드처럼 원본이 없는 곳을 위한 것이다. 빌드가 아닌 실행 중에 주소가 없으면 배포 설정 누락이라 경고 기록을 남긴다. 운영 배포는 이 값을 넣는다.
   - 주소가 있는데 원본이 실패하면 던진다. ISR 다시 만들기라면 Next.js가 마지막 정상 화면을 계속 낸다(SCR-001 '에러'). 첫 빌드라면 빌드가 실패해 드러난다. 그래서 홈 피드 서버(HOT-305)가 생기기 전의 환경에는 이 값을 넣지 않는다.
   - 랭킹 파일·찜·알림 신청 상태는 브라우저가 따로 받는다.
     - 랭킹 파일은 같은 출처의 정적 파일이다. 기준일이 2일 [가정] 넘게 지나면 그 섹션을 숨긴다.
     - 찜 목록이 401이면 비로그인으로 보고 찜한 공연 줄을 숨긴다. 서버는 쿠키로 로그인 여부를 정하지 않는다(docs/frontend.md §2.5 '알림·외부 링크 착지 규칙').
   - 서버 쪽 API 주소는 `PEAKET_API_ORIGIN`이다(앱 서버가 gw-fan을 부르는 주소). 서버 클라이언트는 쿠키·요청 머리를 싣지 않는다.
   - 브라우저 클라이언트는 앱이 쓰는 호스트(`api`·`queue`·`queue-files`·`www`)를 모두 담아 한 번 만든다. `setOrvalClient`는 `apps/web/src/shared/api`만 부른다(린트). 화면마다 따로 꽂으면 먼저 꽂은 쪽 설정에 다른 화면의 호스트가 빠진다.
   - 팬 요청이 401이면 토큰을 한 번 갱신하고(창끼리 잠금 `peaket.refresh`) 다시 보낸다. 그래도 401일 때만 비로그인이다(docs/frontend.md §4.1 '401').
4. **이미지 파생본 주소**:
   - `ProductionCard.posterUrl`과 `HomeFeed.banners[].imageUrl`은 그 이미지 파생본 묶음의 기준 주소다.
   - 파생본 하나는 `{기준 주소}/{폭}.{avif|webp}`다. 폭은 320·640·960·1,280 [가정]이다.
   - 화면은 AVIF를 먼저, WebP를 대체로 둔 `<picture>`를 그린다. srcset은 이 폭 단계에서 바로 만든다. 처음에는 `getImageProps()`로 만들었지만, 클라이언트 부품에서 이미지 설정 코드가 첫 화면 JS에 실려 예산(§5.8)을 넘어 바꿨다. `next/image`의 사용자 로더(같은 이름 규칙)는 남겨 `next/image`를 쓰는 곳도 `/_next/image`를 쓰지 않게 한다.
   - 이미지 출처(운영 `https://img.peaket.example` [가정], `security-headers.mjs` `PROD_ORIGINS.img`)는 CSP `img-src`에 넣는다. 환경마다 다른 값은 `PEAKET_CSP_ORIGINS`의 `img`로 바꾼다. 화면은 계약이 준 기준 주소를 그대로 쓰므로 따로 이미지 출처 변수를 두지 않는다.
   - 파생본을 이 이름으로 게시하는 일은 이미지 단계(HOT-190)가 한다.
5. **배너 글자 칸**: d5 §5.1은 배너의 핵심 문구를 이미지 안 글자로 넣지 않고 [홈 구성]의 제목 칸으로 받아 HTML 글자로 보이게 한다. 그런데 계약과 data.md에는 그 칸이 없었다. 그래서 `HomeFeed.banners[]`에 `title`·`subtitle`을, [홈 구성] 배너 입력과 `home_banner`에 같은 두 칸(제목 40자·부제 80자 [가정])을 더한다. 요청 본문에 필수 칸을 더하면 계약이 깨지므로 둘 다 선택 칸이다. 칸이 없으면 화면은 이미지와 대체 텍스트만 보인다.

## 결과

- 홈 화면이 서버 없이도 개발·확인·CI 빌드에서 돈다. 서버 단계가 끝나면 화면 코드를 고치지 않고 진짜 응답을 받는다.
- 가짜 API의 응답이 계약에서 나오므로, 계약이 바뀌면 생성물 시험이 가짜 API도 함께 바꾸게 한다.
- 운영 빌드의 첫 홈은 원본이 없으면 장르 타일과 바닥글만 보인다. 원본이 생기면 60초 안에 채워진다.

## 다른 선택지

| 길 | 고르지 않은 까닭 |
| --- | --- |
| 서버를 먼저 만든다(검색 읽기 모델·홈 구성·홈 피드) | 소유자가 화면 먼저를 골랐다. 화면이 며칠 밀리고, 다른 화면 단계도 같은 선행 작업을 기다린다 |
| 개발 서버 안에서 MSW(`msw/node`)로 가로챈다 | 앱 시작 코드가 목업을 가져와야 해서 운영 코드와 섞인다. 따로 띄운 가짜 API는 운영 묶음에 들어갈 길이 없다 |
| 가짜 API가 생성된 MSW 처리기를 그대로 돌린다 | 값이 무작위라 같은 화면을 다시 볼 수 없고, 생성물이 TS 원본(확장자 없는 가져오기)이라 Node만으로는 돌릴 수 없다 |
| 배너 글자를 이미지에 넣는다 | 확대·고대비·번역에서 글자가 사라지고(WCAG 2.2 SC 1.4.5), d5 §5.1과 다르다 |
| 카드마다 파생본 주소 목록을 계약에 싣는다 | 응답이 커지고(카드마다 8개 주소) 폭 단계를 바꿀 때 계약이 깨진다. 기준 주소 하나와 이름 규칙이면 된다 |
