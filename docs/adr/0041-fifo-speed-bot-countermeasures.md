# ADR-0041: 선착순(FIFO) 오픈 시점의 속도형 매크로 무력화 대책 (동시 도착 구간 무작위 셔플 및 좌석 자동 배정 옵션)

- **상태**: 채택 (2026-10-11 수립, 소유자 승인. ADR-0012 대기열 정렬 정책을 보완하여 오픈 순간의 밀리초 속도 경쟁을 구조적으로 무력화. ADR-0012의 결정은 그대로다). ADR-0043(2026-10-12)이 결정 3의 좌석 자동 배정을 보완한다(희망 조건 사전 입력, 차례 도래 자동 요청, 차례 직전 직접 확인). ADR-0050(2026-10-13)이 묶음 셔플의 커밋 시점(오픈 10분 전까지 공연 상세 화면)과 머클 잎·결과 파일 키(pid가 아니라 사전 검증 토큰 해시), 비콘 라운드 대기 규칙을 정한다. R-56(2026-10-13): 제목과 상태의 '무력화'는 처음 N초(기본 2초) 안에 도착한 요청끼리의 속도 차이를 없앤다는 뜻이다. N초 뒤에는 도착 순서가, 좌석을 고르는 단계에서는 입력 속도가 여전히 차이를 만든다(자동 배정 공연의 좌석 선택 쪽은 ADR-0043이 줄인다). ADR-0056(2026-10-13)이 묶음 셔플 뒤 순번 카운터 전진을 묶음마다 한 번만, 리더 세대를 확인해 하게 한다 ADR-0058(2026-10-13): 묶음 결과 파일도 셔플 결과와 같은 분산 조회 규칙을 쓴다(202 응답에 결과 공개 예정 시각과 분산 창).
- **관련 문서**: ADR-0012, ADR-0002(순번 발급), ADR-0005(입장 확정), ADR-0014(좌석 2단계 일관성), docs/features/queue-admission.md §2·§3·§11, docs/features/seat-hold.md §3·§12, planning/04 SCR-010·SCR-021, docs/api/openapi.yaml, docs/data.md §2
- **관련 ID**: FR-006, FR-010, FR-022, FR-050, POL-003, POL-004, POL-011, POL-035, NFR-001, K1, K4, K5, K6

## 맥락
- 소유자 질문(2026-10-11): "빨리 누르는 매크로로 오픈되었을 때 선착순으로 빠르게 표를 가져가는 일이 빈번한데, 대비하는 대책은 없는가." 소유자가 2026-10-11 네 가지 제안을 승인했다(00-summary §7 질문 17).
- 피켓의 기본 대기열 정렬 정책인 하이브리드 셔플은 티켓 오픈 시각 이전 대기자들을 암호학적 난수로 공정하게 무작위 재정렬하므로 물리적 속도 경쟁이 무의미하다.
- 그러나 파트너가 관행상 선택할 수 있는 선착순(FIFO) 방식과 하이브리드 오픈 직후에 유입되는 사용자 경로는 도착 순이라, 밀리초(ms) 단위의 패킷 전송 속도 경쟁이 남아 빠른 매크로 프로그램이 유리하다는 구조적 취약점이 있었다. 사람 확인은 오픈 전에 미리 통과시키고(사전 검증 토큰), 1인 1순번·기기 바인딩·매수 한도가 이득을 줄이지만 속도 경쟁 자체는 막지 못했다(queue-admission Q-T1이 'FIFO는 속도형 봇에 취약'을 기록하기로 되어 있었음).

## 결정
1. **동시 도착 구간 묶음(오픈 후 도착 경로 공통) 및 공정 셔플.**
   - 티켓 오픈 시점부터 N초(초기값 2초 [가정, Phase 2 부하 시험에서 확정]) 안에 도착한 진입 요청은 같은 시각에 온 것으로 간주하여 한 묶음(배치)으로 수집한다.
   - 구간이 끝나면 `admission-ctrl` 리더가 로비 셔플과 같은 commit-reveal 방식(시드 해시 사전 공개, 참가자 머클 루트, 공개 난수 비콘, 종료 후 시드 공개)으로 묶음 안 순서를 무작위로 정하고 결과 파일을 CDN에 게시한다. 구간 뒤 도착자는 묶음 뒤에 도착 순으로 선다. 선착순 공연은 묶음이 1번부터, 하이브리드 공연은 로비 인원 뒤부터 번호를 받는다.
   - 구간 안의 화면은 순번 없이 "공정한 순서를 정하는 중"만 보인다(POL-004). 1인 1순번 선점(pid)은 묶음 전에 그대로 수행한다.
2. **사전 검증 토큰의 최초 발급 시각 규칙.** 사전 검증 토큰은 오픈 전후 언제나 발급하되 최초 발급 시각을 갖고, 만료 전 조용한 갱신에서도 최초 발급 시각을 유지한다. 묶음에는 최초 발급 시각이 오픈 시각 이전인 토큰만 들어간다. 오픈 뒤 발급된 토큰으로 구간 안에 도착하면 묶음 뒤에 도착 순으로 선다. 봇도 오픈 전에 기기마다 사람 확인을 거쳐야 묶음에 들어갈 수 있고, 사람 확인 호출은 오픈 순간의 경로에서 계속 빠져 있다.
3. **좌석 자동 배정(AUTO) 선택지 신설(FR-050, POL-035).** 공연별 판매 정책에 좌석 배정 방식 `PICK`(좌석맵에서 직접 고름, 기본)과 `AUTO`(등급·매수만 고르고 시스템이 같은 등급의 연석을 배정)를 둔다. AUTO는 입장 뒤 좌석 고르기 속도 경쟁과 좌석맵 경합 부하를 없애고, 스크린리더 사용자에게는 접근성 대안이 된다. 배정은 같은 등급 안에서 파트너가 정한 선호 순(기본은 무대 가까운 순)으로 가장 앞의 연석이고 [가정, 시안에서 확정], 후보 좌석을 같은 Lua 홀드로 잡으며 경합에 지면 다음 후보로 최대 3회 [가정] 재시도한다. 매수 한도·홀드 TTL·결제 흐름은 같다. 자동 배정 사실과 규칙은 판매 조건에 미리 고지한다.
4. **선착순 선택 시 파트너 경고.** 파트너가 공연 등록 위저드에서 선착순을 고르면 "선착순은 빠른 매크로에 취약합니다. 오픈 직후 동시 도착 구간 묶음이 적용되며, 추첨(하이브리드)을 권장합니다"라는 경고를 보이고 기본값은 하이브리드로 둔다. 선착순 공연의 고지 문구에는 묶음 규칙을 넣는다(POL-004).
5. **측정.** Q-T1의 봇 유형별 성공률에 '묶음 적용 전후'를 더하고(Q-T23), 토큰 발급 시각 규칙(Q-T24), 자동 배정의 경합·연석(seat-hold S-T19)을 시험한다. 구간 길이 N은 부하 시험에서 '묶음 셔플이 끝나는 시간 + 네트워크 지연 분포'로 정한다.

## 검토한 대안
| 대안 | 기각 사유 및 한계점 |
| --- | --- |
| 오픈 시각을 예고 없이 수 초간 불규칙하게 지연 | 속도 경쟁의 기준점만 뒤로 밀릴 뿐 없어지지 않고, 공정성 원칙 1(숨기지 않는다)에 어긋나 사용자 불신을 초래한다. |
| 오픈 순간 경로에 사람 확인을 강제 | 20만 명이 동시에 외부 사람 확인 서버를 호출하여 T=0 병목이 된다(ADR-0012 결정 3의 이유). 사전 검증 토큰 규칙으로 같은 효과를 낸다. |
| 선착순 자체를 폐지 | 대관처 규정이나 기획사 계약 관행상 선착순을 요구하는 파트너의 선택권을 잃는다. 경고와 기본값으로 유도한다. |
| 자동 배정을 모든 공연에 강제 | 좌석을 고르는 경험이 사라진다. 공연별 선택지로 둔다. |
| 구간 안 순서를 도착 시각 쿠키로 보존 | 밀리초 경쟁을 그대로 남긴다. 묶음 안은 무작위여야 속도가 소용없다. |

## 결과와 트레이드오프
- 얻는 것: 선착순 공연에서도 밀리초 속도 경쟁이 사라지고, 봇은 오픈 전에 기기마다 사람 확인을 거쳐야 한다. 자동 배정 공연은 좌석맵 전파·렌더 부하(K4·K5)도 줄어든다.
- 대가
  - 구간 동안 모든 도착자가 순번을 N초 늦게 받는다(셔플 계산 완료 대기). 셔플 1회가 더 늘어 queue-svc·admission-ctrl 구현이 커진다(wbs 2.2.1 +1일).
  - 자동 배정은 배정 규칙·후보 선택·재시도가 새로 생긴다(wbs 2.5.4 1.5일). 선호 순을 정하지 않은 파트너에게는 무대 가까운 순이 기본이라 민원이 생길 수 있다.
  - 오픈 직전에 처음 온 사람은 토큰을 오픈 뒤에 받아 묶음에 못 들어간다. 공연 상세·알림에서 '미리 사람 확인'을 안내한다.
- 되돌릴 조건
  - 부하 시험에서 묶음 셔플이 N초 안에 끝나지 않으면 N을 늘리거나 구간을 두 묶음으로 나눈다.
  - Q-T23에서 선착순의 속도형 봇 성공률이 묶음 뒤에도 하이브리드보다 뚜렷이 높으면 선착순 선택지를 닫는 것을 다시 검토한다.
