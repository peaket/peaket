# ADR-0212: 대기실의 자동 배정 희망 조건·차례 직전 직접 확인·차례 알림을 잇는 데 필요한 빈칸을 채운다

- **상태**: 채택(2026-11-05, 추천 적용). BUILD_ORDER HOT-343.
- **관련**: [docs/frontend.md](../frontend.md) §3.12 `peaket.autoassign.{eventId}`·§5.1 '차례와 입장', [docs/features/queue-admission.md](../features/queue-admission.md) §4 '차례 직전 직접 확인', [docs/design/d5-screen-blueprint.md](../design/d5-screen-blueprint.md) §5.7 ⑧·⑩, §5.8 ⑥·⑧·tier-sold-out, d2 CMP-057·CMP-068, ADR-0043, ADR-0208
- **관련 ID**: SCR-007, SCR-008, Q-T25

## 맥락

- HOT-341(ADR-0208 결정 1)이 자동 배정 공연의 희망 조건·차례 직전 직접 확인과 [차례 알림 받기]를 이 단계로 넘겼다. 그때까지 대기실은 ⑧ 희망 조건과 ⑩·⑥ [차례 알림 받기]를 그리지 않았다.
- 정본을 모아 읽으니 빈칸이 있었다.
  - 희망 조건의 저장 꼴(칸 이름·판)과, 처음 열었을 때의 기본값이 없다. 등급 목록과 매수 상한을 어디서 읽는지도 없다.
  - 차례 직전 직접 확인은 '첫 시도는 예상 도래 시각에 맞춘다'뿐이고, 여러 탭·숨긴 탭에서 누가 보내는지는 §5.1 '여러 탭'에만 있다.
  - [차례 알림 받기]를 누른 뒤 무엇을 언제 알리는지(알림음·브라우저 알림·탭 제목)와, 웹 푸시 구독 등록 경로가 아직 없다는 점이 정리되지 않았다(알림 서비스는 BUILD_ORDER GAT-250).

## 결정

1. **희망 조건(CMP-057 preference)**
   - 저장: `peaket.autoassign.{eventId}` = `{v: 1, firstTierId, count, wheelchair, secondTierId?, allowSplit, savedAt}`. 등급 ID는 공연 공개 요약 `priceTiers`의 `tierId`, 매수 상한은 `perPersonLimit`이다. 꼴이 틀리거나 그 회차에 없는 등급이면 버리고 기본값을 쓴다.
   - 기본값: 1순위는 첫 등급, 매수 1, 휠체어석 아님, 2순위 없음, 분리 허용 아님. 저장된 값이 없으면 '저장됨' 표시를 하지 않는다.
   - 로비 카드는 바꿀 때마다 바로 저장하고 '저장됨'을 보인다. 대기열 ⑧ 줄의 [바꾸기]는 시트를 열고 [희망 조건 저장하기]로 저장한다. 2순위는 1순위와 같을 수 없다.
   - 지우는 때: 로그아웃(ADR-0208 결정 7이 이미 지운다), 판매 종료(대기 상태 파일 `ENDED`와 진입·입장 확정의 410 `sale-ended`), 배정 확정(좌석 단계, HOT-350).
   - 이 값은 서버로 보내지 않는다. 입장 뒤 좌석 화면이 홀드 요청의 `auto`로 보낸다(HOT-350, 서버는 wbs 2.5.4 전까지 400 `auto-assign-not-supported`).
2. **등급 매진 줄(tier-sold-out)**: 대기 상태 파일 `soldOutTiers`에 1순위 등급이 있으면 ⑧ 줄이 "1순위 등급이 매진되었습니다. 2순위 등급을 골라 두세요" + [바꾸기]다(d5 §5.8). 대기 화면 기본 영역에는 등급 현황을 보이지 않는다(ADR-0063).
3. **차례 직전 직접 확인(자동 배정 공연만, ADR-0043)**
   - 공연 공개 요약의 `seatAssignment`가 `AUTO`이고, 이 탭이 리더(보이는 탭)이고, 예상 대기가 10초 [가정] 안이면, 예상 도래 시각(지금 + 앞 인원 ÷ 속도)에 입장 확정을 보낸다.
   - `NOT_YET`이면 `retryAfterMs` 뒤 지터 없이 다시 보낸다. 이 값은 예상 도래까지 남은 시간이라 차례에 가까울수록 1초보다 작을 수 있으므로, 브라우저가 1초 하한을 지킨다(시도 간격 1초 이상, queue-admission §4). 그 하한 동안은 대기 화면이고 [지금 입장]도 깨지 않는다(ADR-0208 결정 6).
   - 차례 전 직접 확인은 화면을 '입장 중'으로 바꾸지 않는다(대기 화면·⑧ 줄·열린 시트를 그대로 둔다). `ADMITTED`·`SOON`이 오면 그때 바뀐다.
   - 다시 연 탭이 공연 공개 요약(좌석 배정 방식)을 처음에 못 받으면 늘려 가며 다시 받는다.
   - 직접 선택 공연에는 하지 않는다. 숨긴 탭은 보내지 않는다(§5.1 '여러 탭').
4. **[차례 알림 받기](CMP-068)**
   - 누르면 시트가 왜 필요한지 설명하고, [알림 켜기]를 누른 동작 안에서만 알림 권한을 먼저 묻고(동작의 유효 시간 안에) 오디오를 연다(Web Audio, 열리기를 기다리지 않는다). 상태는 `role="status"`로 알린다: 묻는 중 "알림 권한을 묻는 중입니다", 허용 "차례가 가까워지면 알림과 알림음으로 알려 드립니다", 거부 "알림 권한이 없어 탭 제목과 알림음으로 알려 드립니다", 미지원 "이 브라우저는 알림을 지원하지 않아 탭 제목과 알림음으로 알려 드립니다". iOS·iPadOS에서 홈 화면 앱이 아니면 누르기 전에 시트에서 홈 화면에 추가하는 방법을 먼저 안내한다(iOS는 그 앱에서만 알림이 된다). 다시 연 시트는 마지막 결과를 그대로 보인다.
   - 켜 둔 상태는 저장하지 않는다(§3.12에 없는 값). 페이지를 다시 열면 다시 누른다.
   - 알리는 때: 예상 대기가 60초 [가정] 안으로 들어오거나 곧 입장·차례 도래 유예가 되면 한 번, 짧은 알림음(0.3초)을 내고, 탭이 숨겨져 있고 권한이 있으면 브라우저 알림을 띄운다(같은 회차 표지로 겹치지 않게). 알림을 누르면 그 탭으로 돌아온다(보이는 탭이 리더가 되어 입장 확정을 보낸다). 다시 줄을 서면 다시 알린다.
   - 탭 제목 카운트다운은 버튼과 관계없이 한다: 탭이 숨겨져 있고 예상 대기가 5분 [가정] 안이면 제목 앞에 남은 시간(`(약 N분)`, 60초 안이면 `(N초)`)을 붙인다. 남은 시간은 폴링할 때마다 고친다(숨긴 탭은 5초 이상 간격).
   - 웹 푸시(서버가 보내는 알림)는 구독 등록 경로(`POST /v1/push-subscriptions`)와 알림 서비스(GAT-250)가 생기면 잇는다. 그때까지 '웹 푸시'는 이 탭이 띄우는 브라우저 알림으로 대신한다.

## 결과

- 자동 배정 공연의 대기에서 희망 조건을 고르고 저장하며, 차례 직전에 직접 확인한다. 차례가 가까우면 알림음·브라우저 알림·탭 제목으로 알린다.
- 남는 한계: 탭을 닫으면 알림이 없다(웹 푸시 전). 브라우저 알림은 안드로이드 크롬에서 `new Notification`을 막아 탭 제목·알림음만 쓴다. 직접 확인 창(10초)은 [가정]이고 Q-T25 부하 시험에서 정한다.

## 다른 선택지

- 켜 둔 알림 상태를 저장해 다시 열어도 유지: 오디오는 사용자 동작 없이 다시 열 수 없어 알림음이 나지 않는다. 그래서 저장하지 않고 다시 누르게 했다.
- 희망 조건을 서버에 미리 보내기: 대기 중 요청이 늘고(100만 명), 계약(ADR-0043)이 차례가 올 때 홀드 요청에 싣기로 정했다.
