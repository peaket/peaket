# ADR-0162: 수사기관 제공 자료는 commander 승인 뒤에만 추출·제출하고, 1인 기간 자기 점검은 시연에서만 허용하며, 만료 차단은 따로 뗀 작업이 거두고, 정산 화면 권한과 법정 조치 조회를 정한다(소유자 결정, 2026-10-30)

- **상태**: 채택 (2026-10-30. 소유자가 review/open-items.md 68·69·72·74번과 70번 ①·③의 추천을 "A B C 는 추천대로 해주시고요"라고 정했다. 방향은 소유자 결정이다. 승인 흐름의 상태와 기한, 시연 표시 방식, 정리 작업의 권한·주기, 조회 경로의 모양은 추천 적용이다.)
- **관련**: ADR-0102(비상 접근), ADR-0149(감사 기록의 사람 칸), ADR-0157(권한 표), ADR-0158(내부 관리계획), ADR-0159(관제 빈틈), POL-021 B(명령 4 차단), POL-038 ⑦(수기 조정 요청), [docs/features/control-tower.md](../features/control-tower.md) §4·§5·§9, [docs/features/settlement.md](../features/settlement.md) §9, [docs/security/authz-matrix.md](../security/authz-matrix.md), [docs/security/internal-management-plan.md](../security/internal-management-plan.md)

## 맥락

- 권한 표(planning/03 §3)는 수사기관 요청 처리의 최종 승인을 commander에게 주었다. 하지만 관제 설계(control-tower §9)에는 승인 단계가 없어 operator 혼자 자료를 추출하고 제출할 수 있었다(ADR-0159에서 찾음).
- 자기 접속기록은 스스로 점검할 수 없다(C-T24). 그런데 1인 기간에는 commander가 한 명뿐이라 월 점검을 끝낼 수 없다.
- 명령 4의 WAF 차단은 만료되면 ops-svc가 거두었다. 그래서 ops-svc가 멈추면 만료된 차단을 거둘 곳이 없었다.
- 평소 제어 gRPC에는 메시지 서명이 없고 메시 신원만 본다.
- 정산 화면에서 두 가지가 비어 있었다. 관제 역할이 정산 계좌를 보는지, CS가 정산 화면에 드는지다.
- 법정 조치 화면(SCR-032)의 목록·상세 조회 경로가 없었다.

## 결정

1. **수사기관 제공 자료는 commander 승인 뒤에만 추출·제출한다(소유자 결정, 68번)**
   - 흐름:
     - operator 이상이 범위를 좁혀(항목·기간만, 대상자는 더할 수 없음) 사유와 재인증으로 추출을 요청한다.
     - 요청자가 아닌 commander가 패스키 재인증으로 승인한다.
     - 시스템이 추출한다.
     - 제출을 기록한다. 제출 기록의 SHA-256이 승인 때 만든 파일과 다르면 422다.
   - 승인 대기는 24시간 [가정] 또는 제출 기한 가운데 이른 때 만료된다. 2인 명령의 10분은 실시간 제어용이라 날 단위 기한의 기관 요청에는 짧다(추천 적용).
   - 거부는 두 갈래다. REVISE(범위를 고쳐 다시 요청)와 DECLINE(제공하지 않음)이다.
   - 보존 기간은 제공한 날부터 다시 센다(통신비밀보호법 제13조 제8항). 제출 파일 사본의 보관 기간은 [확인 필요]로 법률 검토에 넘긴다.
   - 경로는 `…/data-requests/{requestId}/extraction-requests`·`approvals`·`rejections`·`submission`이다(docs/api/openapi.yaml).
2. **1인 기간의 접속기록 점검은 운영 시작 조건을 유지하고, 시연에서만 자기 점검을 허용한다(소유자 결정, 69번)**
   - 점검자 2명 이상이 운영 시작 조건이다(docs/security/internal-management-plan.md §2 제1호).
   - 데모 환경의 ops-svc만 본인 종결을 받고, 종결 기록에 `self_review_demo`를 남겨 화면에 표시한다.
   - 데모 표시를 켠 ops-svc는 스테이징·운영에서 배포 정책 검사(Kyverno)가 막는다(C-T60).
3. **만료된 WAF 차단은 따로 뗀 작업 `waf-block-expirer`가 거둔다(소유자 결정, 70번 ①)**
   - 배치: ops-svc와 같은 이미지의 다른 진입점으로 띄우는 CronJob이다. 관제 노드 풀에서 1분 [가정]마다 돌고, 서비스 계정은 따로 둔다.
   - 권한: ops DB의 명령 4 읽기 전용 보기 하나와, IP 집합 하나의 조회·갱신만 갖는다.
   - 동작:
     - 만료됐고 아직 살아 있는 다른 차단에 들지 않으며 명령 기록에 있는 대역만 뺀다.
     - AWS WAF의 IP 집합 갱신은 목록을 통째로 바꾸고 잠금 토큰이 다르면 실패하므로, 다시 읽어 한 번 더 한다(2026-10-30 원문 확인).
     - ops-svc는 대역이 빠진 것을 확인한 뒤 명령 상태를 자동 만료로 적는다.
   - 경보: 마지막 성공이 5분 [가정]보다 오래되면 SEV2다.
4. **평소 제어 gRPC 메시지 서명은 더하지 않는다(소유자 결정, 70번 ③)**: 남는 위험은 ops-svc 신원을 빼앗기면 명령을 보낼 수 있다는 것이다. 제어 경로가 신뢰 경계를 넘게 되면 다시 본다.
5. **정산 화면의 권한(소유자 결정, 72번)**
   - 관제 역할(viewer·operator·commander)은 파트너 정산 계좌를 은행 이름과 끝 4자리만 본다.
   - CS 담당자는 정산 화면(SCR-049)과 정산 조회 경로에서 403이다.
   - CS 처리함의 정산 건 가운데 CS에게 보이는 것은 '정산 이의' 하나다. 그 건에는 정산서의 금액 항목·상태·이의 내용만 붙는다. 지급·대사·KYC 건은 관제 역할만 본다.
   - 이의 없는 수기 조정은 승인 업무 화면(SCR-046)에서 정산서 ID로 요청한다(POL-038 ⑦을 지키려는 것이다, 추천 적용).
6. **법정 조치의 목록·상세 조회(소유자 결정, 74번)**
   - 경로: 통보·자료 요청·보안 사고의 목록과 상세 GET 여섯이다.
   - 응답의 `view`로 SUMMARY(건 요약)와 FULL(원문)을 가른다.
   - 목록 정렬은 기한 순(기본)과 최근 순이고, 상태 필터를 둔다.
   - viewer가 통보·자료 요청을 부르면 403이다. 자료 요청 상세를 열면 접속기록에 남는다.

7. **함께 정한 것(2026-10-30 후속 정리, 추천 적용)**
   - 재인증 작업 묶음 '수사기관 자료'를 따로 둔다. 승인 업무 묶음을 같이 쓰면 환불 승인용 토큰을 5분 안에 자료 추출 승인에 쓸 수 있다(docs/features/identity.md §3).
   - 제출 파일은 PDF·CSV·XLSX [가정]이고, 내려받기의 Content-Type은 저장한 `mediaType` 그대로다. CSV·XLSX는 수식 첫 글자를 정화하는 공용 내보내기 함수로 만든다(ASVS 1.2.10).
   - 만료 차단 정리 작업은 읽기 전용 보기 `waf_block_expiry_v`와 DB 사용자 `waf_block_expirer`를 쓰고, 나가는 통신은 ops DB, WAF API(us-east-1), Pod Identity 에이전트, 클러스터 DNS뿐이다.
   - CS 처리함의 정산 건은 `CsCaseDetail.statementDispute`로 정산 이의만 싣고, CS 담당자 목록에서 지급·대사·KYC 건을 빼며 그 상세는 404로 답한다.

## 검토한 대안

- **68번: 승인 업무(POL-038)를 그대로 쓰기**: 승인 업무는 환불·양도 같은 거래 예외용이라 법정 제출 기한과 범위 좁히기를 담지 못한다. 기각.
- **68번: 제출 단계에서만 승인받기**: 승인 전에 추출 파일이 생긴다. 기각.
- **69번: 데모 승인자 계정이 대신 종결하기**: 사람 둘이 있는 것처럼 보이게 하는 것이라 시연의 정직성에 맞지 않는다. 기각.
- **70번 ①: 만료 시간마다 IP 집합을 따로 두기**: DB 권한은 필요 없지만 IP 집합 수 한도와 규칙 수가 늘어난다. 기각.
- **70번 ③: 메시지 서명 더하기**: 키 관리와 검증이 서비스마다 늘고, 같은 클러스터 안의 메시 신원으로 막는 위험과 차이가 작다. 기각(조건부로 다시 본다).
- **72번: CS도 정산 화면을 보기**: 지급·KYC 정보까지 보게 된다. 기각.

## 결과와 트레이드오프

- 수사기관 제공은 commander가 있어야 끝난다. 그래서 1인 기간에는 시연으로만 보인다.
- 만료 차단 정리는 ops-svc 장애와 무관해진다. 대신 정리 작업이 ops DB 보기 하나를 읽는다.
- CS는 정산 이의만 다루고, 나머지 정산 문의는 관제 역할에게 넘긴다.

## 되돌릴 조건

- 법률 검토에서 제출 파일 보관 기간이나 긴급 요청 절차가 달라지면 결정 1을 고친다.
- 제어 경로가 클러스터 밖이나 다른 계정으로 넘어가면 결정 4를 다시 본다.
