# ADR-0105: 결제사 장애로 멈춘 새 결제 진입을 확인 호출과 시험 재개로 다시 열고, commander가 손으로 풀 길을 둔다(2026-10-28)

- **상태**: 채택 (2026-10-28. 기술 검토(review/tech-review.md)의 높음-14 '결제 신규 진입 정지의 자동 해제 조건이 정지 때문에 생기지 않는 신호에 기대고, 사람이 푸는 길이 없다'에 소유자가 "나머지 건수들은 모두 추천안에 동의합니다. 그렇게 모두 수정해주세요."라고 정했다. 방향은 소유자 결정(추천안 승인)이고, 기준값과 같은 세부는 추천 적용이다)
- **관련**: NFR-006, POL-013, POL-021, POL-022, POL-029, ADR-0009(두 층 서킷 브레이커), ADR-0044(결제사 선택·전환), ADR-0056(리더 세대로 늦은 쓰기 막기), ADR-0069 결정 1·7(제어 입력 없음, 결제 확정 소요), ADR-0078 결정 2(자동 조치의 끝내는 조건), ADR-0085(정지 동안 홀드 멈춤), ADR-0095(멈춤은 1인, 재개는 2인), ADR-0103(제어 상태), [docs/features/payment.md](../features/payment.md) §9·§11·§12, [docs/architecture.md](../architecture.md) §3.3·§5, [docs/features/control-tower.md](../features/control-tower.md) §3·C-T44, [docs/infra.md](../infra.md) RB-07, [docs/observability.md](../observability.md) §3·§4·§5·§12·§14, [docs/data.md](../data.md) §1·§2, docs/api/proto/peaket/payment/v1/payment.proto, planning/03 POL-013·§1.1 명령 6, planning/01 §5.2, design/d5 §7.2, [review/tech-review.md](../review/tech-review.md)(높음-14)

## 맥락

- payment-svc는 결제사 장애 때 새 결제 진입을 잠시 멈춘다(docs/features/payment.md §9). 결제 시도 시작은 503(새 결제 일시 정지)을 받고, 화면은 결제 버튼을 막는다.
  - 시작 조건은 결제사 서킷 브레이커(계속 실패하는 호출을 잠시 끊어 장애가 번지지 않게 하는 장치) 열림이나, 결제 확정 소요 p99(백 건 중 아흔아홉 건이 이 시간 안에 끝난다는 뜻) 5초 초과다. 결제 확정 소요는 승인 요청을 시작해 결과가 정해질 때까지의 시간이고, 같은 멱등키(같은 요청을 여러 번 보내도 한 번만 처리되게 하는 열쇠) 재시도와 결과 모름 조회를 포함한다(ADR-0069 결정 7).
  - 채널 호출 상한 때문에 확정이 완화 목표(p99 60초)보다 늦어져도 멈춘다.
- ADR-0078 결정 2는 다시 여는 조건을 '그 결제사의 서킷이 닫혀 있고 결제 확정 소요 p99가 5초 아래로 5분 이어짐'으로 정했다. 이 조건은 정지 때문에 생기지 않는 신호에 기댄다.
  - 정지 중에는 새 결제가 없다. 남는 표본은 재시도 큐(승인 기한 10분 안에서 같은 멱등키로 다시 묻는 대기열)에 든 결제뿐이다. 이 결제들은 장애 동안 기다린 시간이 확정 소요에 들어가 p99가 5초를 크게 넘는다.
  - 승인 기한이 지나 큐가 비면 표본이 0이 된다. 빈 결과는 0으로 읽지 않으므로(ADR-0069) 조건은 참이 될 수 없다.
  - payment-svc가 쓰는 opossum 서킷은 열린 뒤 정해진 시간이 지나면 반 열림(시험 삼아 한 번 통과시키는 상태)이 되고, 그다음 호출 한 번의 성패로 닫을지 다시 열지 정한다(opossum README, 2026-10-28 확인). 호출이 없으면 닫히지 않는다.
- 끝내는 조건 표(docs/architecture.md §5)에는 사람이 정지를 푸는 명령이 없다. 대체 결제사가 없는 공연은 결제사가 회복해도 판매가 끝날 때까지 결제가 막힐 수 있다. 그동안 주문서까지 온 팬의 홀드(결제하는 동안 좌석을 잠시 잡아 두는 것)는 남은 시간이 멈춰, 그 구매 세션의 최대 체류 시각까지 좌석이 묶인다(ADR-0085).
- SRE Workbook 5장의 '요청이 적은 서비스' 절은 실제 사용자 신호가 모자라면 인공 트래픽(확인용 요청)으로 신호를 만들라고 한다. 같은 절은 인공 요청이 성공해도 실제 사용자가 겪는 문제를 가릴 수 있다고 경고한다(2026-10-28 원문 확인).

## 결정

1. **다시 여는 판단은 정지 중에도 생기는 신호로 한다(소유자 승인)**. 정지 중에는 확인 호출로 결제사가 답하는지 보고, 그다음 새 결제의 일부만 받는 시험 재개로 실제 승인 경로를 본 뒤 모두 연다.
   - 두 단계로 나눈 이유는 맥락의 경고 때문이다. 확인 호출은 실제 결제를 건드리지 않지만 승인 API가 아니라 조회 API를 본다. 시험 재개는 승인 경로를 보지만 실제 팬을 실패에 노출한다.
   - 그래서 결제사가 분명히 죽어 있는 동안에는 확인 호출만 하고, 결제사가 답하기 시작한 뒤에만 팬 일부로 승인을 확인한다. 서킷 브레이커의 반 열림을 결제 진입 단위로 한 번 더 두는 셈이다.
2. **확인 호출(추천 적용)**:
   - 정지 중인 결제사마다 1초에 1건 [가정] 결제 단건 조회(어댑터의 `query()`, docs/features/payment.md §2.1)를 보낸다. 대상은 결제가 없는 고정 확인 번호다.
   - 토스페이먼츠는 없는 결제를 조회하면 404 `NOT_FOUND_PAYMENT`를, 포트원 V2는 404 `PAYMENT_NOT_FOUND`를 돌려준다(토스페이먼츠 에러 코드 문서, 포트원 V2 OpenAPI `getPayment`, 2026-10-28 확인). 그래서 이 응답을 정상 응답으로 센다. 실제 결제를 조회하지 않으므로 구매자 정보를 받아 오지 않는다.
   - 확인 호출의 기한은 1초 [가정]다(승인 호출의 시간 초과와 따로 둔다). 기한 안의 정상 응답이 성공이다. 5xx, 시간 초과, 연결 실패, 429(한도 초과), 인증 오류는 실패다.
   - 확인 호출은 그 결제사의 서킷을 거친다. 서킷이 열린 동안에는 결제사에 가지 않으므로 세지 않는다. 반 열림일 때의 확인 호출이 시험 호출이 되어, 성공하면 서킷이 닫힌다.
   - 판정자(결정 8)의 서킷이 닫혀 있고, 확인 호출 성공률이 99% [가정] 이상인 상태가 3분 [가정] 이어지면 시험 재개로 넘어간다.
   - 1초 1건은 분당 60건이라, 토스페이먼츠 테스트 환경의 API별 분당 100건 한도 안이다(docs/features/payment.md §2.1).
3. **시험 재개(추천 적용)**:
   - 새 결제 시도 시작의 5% [가정]를 무작위로 받는다. 나머지는 지금처럼 503과 `Retry-After`를 받는다.
   - 받은 결제의 첫 승인 호출(재시도 큐 건은 빼고) 20건 [가정]이 모이면 판정한다. 결제사가 5초 [가정] 안에 결론(승인 또는 거절)을 낸 비율이 95% [가정] 이상이면 모두 연다. 아니면 정지로 돌아가 확인 호출부터 다시 한다.
   - 카드 한도 초과 같은 거절은 결제사가 정상으로 답한 결론이라 실패로 세지 않는다. 시간 초과, 5xx, 결과 모름은 실패다.
   - 10분 [가정] 안에 20건이 모이지 않으면(판매 끝 무렵처럼 결제가 적을 때), 그때까지 실패가 기준을 넘지 않았고 확인 호출이 계속 정상이면 모두 연다.
   - 시험 재개 동안에도 그 회차는 일시 정지 중으로 본다. 그래서 ADR-0085의 홀드 멈춤은 모두 열 때까지 이어지고, `GetNewPaymentPause`도 그 회차를 계속 돌려준다.
4. **채널 호출 상한 때문에 멈춘 경우(추천 적용)**: 결제사는 정상이고 우리 쪽 대기가 길어진 것이라, 확인 호출과 시험 재개를 쓰지 않는다. 그 채널의 대기 건수 ÷ 채널 상한(초당 건수)으로 계산한 예상 대기가 10초 [가정] 아래로 1분 [가정] 이어지면 다시 연다. 429를 받아 낮춘 채널 상한은 지금처럼 그 회차 동안 유지한다(ADR-0078 결정 2).
5. **재시도 큐 건은 시작·해제 판정에서 뺀다(소유자 승인, 라벨 이름은 추천 적용)**: 결제 확정 소요 히스토그램에 경로 라벨을 붙인다. `payment_confirm_resolution_seconds{pg, path}`이고, path는 `direct`(재시도 큐에 들어가지 않고 끝남)와 `retry_queue`(재시도 큐에서 끝남)다.
   - 정지의 시작 조건과 RB-07 결제사 전환 검토의 p99는 `direct`만 본다. 큐 건의 긴 확정 소요가 다시 연 직후 정지를 또 부르지 않게 하려는 것이다.
   - NFR-006 Degraded의 결제 확정 p99 60초는 두 경로를 합쳐 잰다. 팬이 겪는 시간에는 큐에서 기다린 시간도 들어가기 때문이다.
6. **다시 연 뒤의 시작 조건(추천 적용)**: 다시 연 뒤에는 연 시각 뒤에 끝난 결제(`direct`)만으로 p99를 본다. 서킷 열림은 지금처럼 바로 본다. 정지 전의 표본으로 다시 멈추지 않게 하려는 것이다.
7. **commander가 손으로 푼다(소유자 승인, 승인 강도는 추천 적용)**:
   - 명령 6(Degraded Mode 전환)의 해제로 그 결제사의 새 결제 진입을 바로 모두 연다. commander 1인이 사유를 적고 재인증한다. 확인 호출 중에도 시험 재개 중에도 쓸 수 있다. 감사 로그와 운영 사건 줄(`ops_event`)에 남는다.
   - 연 뒤에도 결정 6의 시작 조건은 그대로 살아 있다. 결제사가 아직 실패하면 다시 멈춘다.
   - 1인으로 두는 이유: 잘못 풀어도 다시 멈추는 조건이 살아 있어 피해가 한 번의 탐지 시간으로 묶인다. 돈의 안전(이중 결제 0건)은 좌석을 먼저 잡고 승인하는 2단계 결제와 멱등키가 지킨다. 반대로 늦게 풀면 그 결제사를 쓰는 회차의 결제가 모두 막힌다. 판매 재개(명령 3 되돌리기, 2인, ADR-0095)는 이중 결제 의심 같은 사고 뒤에 다시 여는 것이라 위험의 방향이 다르다.
   - 쓰는 때: 확인 호출 경로만 고장 나 자동 판정이 막혔을 때, 정지가 잘못 걸렸을 때, 결제사가 회복을 공지했는데 시험 재개를 기다릴 수 없을 때.
8. **정지 상태는 한곳에 두고 한 곳이 정한다(추천 적용)**:
   - 시작·단계·해제는 payment-svc 파드 가운데 쿠버네티스 Lease(정해진 시간 동안만 유효한 권한. 갱신하지 않으면 다른 파드가 가져간다)로 뽑은 하나(정지 판정자)가 정한다. 확인 호출도 판정자만 보낸다. 파드마다 정하면 같은 팬이 요청마다 다른 답을 받고, 확인 호출도 파드 수만큼 늘어나기 때문이다.
   - 판정자는 상태(결제사, 채널 상한 정지면 채널, 단계, 시작 시각, 사유, 행위자, 판 번호)를 payment DB `payment_entry_pause`에 쓴다. 읽은 판 번호가 그대로일 때만 쓰므로, Lease를 잃은 옛 판정자의 늦은 쓰기는 거절된다(ADR-0056과 같은 생각).
   - 모든 payment-svc 파드는 이 행을 1초 [가정]마다 읽어 결제 시도 시작과 `GetNewPaymentPause` 응답에 쓴다. 명령 6 해제는 받은 파드가 같은 판 조건으로 이 행을 쓴 뒤 ack한다. 제어를 메시지가 아니라 저장한 상태로 다루는 원칙(ADR-0103)과 같다.
   - 시작의 입력은 모든 파드가 내는 서킷 상태(`payment_pg_circuit_open{pg, pod}`)와 직접 경로 확정 소요다. 판정자는 이것을 클러스터 Prometheus의 제어 입력 긁기 작업(5초 [가정], docs/observability.md §4 '긁기·평가·알림 간격')으로 읽는다. 준비된 파드의 절반 이상에서 서킷이 열리면 시작한다 [가정].
   - Prometheus 입력이 없거나 30초보다 낡으면(제어 입력 없음, ADR-0069) 판정자는 자기 파드의 서킷만으로 시작을 정하고, 단계를 앞으로 옮기지 않는다(다시 열지 않는다). 그때 여는 길은 결정 7이다.
   - 시험 재개로 받은 결제는 payment DB `payment_entry_trial`에 주문 ID를 남기고, 첫 승인 호출의 결과를 같은 행에 적는다. 판정자는 이 표로 센다.
9. **보이는 것(추천 적용)**:
   - 지표: `payment_new_entry_pause_stage{pg}`(0 열림, 1 확인 호출, 2 시험 재개), `payment_pg_probe_total{pg, outcome}`, `payment_entry_trial_total{pg, outcome}`. 라벨은 결제사와 결과만 쓴다. 열림도 0으로 내보내, 값이 없으면 '모름'으로 읽는다.
   - 관제 콘솔 '걸린 자동 조치' 위젯은 단계와 막대(확인 호출 n분/3분, 시험 결제 n/20건)를 보이고, 사람이 푸는 길로 명령 6 해제를 함께 보인다(design/d5 §7.2).
   - 정지가 15분 [가정] 넘게 풀리지 않으면 인시던트 선언 기준(POL-022 'SEV2가 15분 넘게 풀리지 않음')에 걸린다. 새 경보는 두지 않는다.
10. **시험(추천 적용)**: payment P-T43이 확인 호출·시험 재개·수동 해제·상한 대기 해제와 재시도 큐 라벨을 보고, control-tower C-T44 ②가 '재시도 큐가 빈 뒤 회복'을 본다.

| 지금 조건(서킷 닫힘 + p99 5초 아래 5분)을 그대로 둔다 | 정지 중의 표본은 재시도 큐 건뿐이고, 큐가 비면 0이다. 조건이 참이 될 수 없다 |
| 확인 호출만으로 모두 연다 | 조회 API가 살아도 승인 경로가 아플 수 있다. 인공 요청의 성공이 실제 문제를 가린다(Workbook 5장) |
| 정지 직후부터 시험 재개(5%)만 한다 | 결제사가 분명히 죽어 있는 동안에도 팬을 실패에 노출한다. 실패한 승인은 재시도 큐로 가서 큐가 길어진다 |
| 정해진 시간(예: 10분) 뒤에 무조건 다시 연다 | 회복을 보지 않고 연다. 결제사가 아직 실패하면 열고 멈추기를 되풀이한다 |
| 자동 해제 없이 사람만 연다 | 결제사 장애는 짧고 자주 온다. 매번 사람을 기다리면 그동안 그 결제사의 결제가 모두 막힌다 |
| 수동 해제를 2인 승인으로 한다 | 결정 7의 이유. 다시 멈추는 조건이 살아 있어 잘못 연 피해는 짧고, 늦게 연 피해는 길다 |
| 확인 호출로 실제 결제(최근 승인 건)를 조회한다 | 응답에 구매자 정보가 섞여 온다. 없는 번호의 404로도 결제사 API가 답하는지는 본다 |
| 파드마다 자기 서킷으로 정지를 정한다 | 파드마다 정지가 엇갈려 같은 팬이 요청마다 다른 답을 받는다. 확인 호출도 파드 수만큼 는다 |

## 결과와 트레이드오프

- **좋은 점**
  - 결제사가 회복하면 확인 호출 3분과 시험 재개를 거쳐 저절로 다시 열린다. 대체 결제사가 없는 공연도 판매 끝까지 막히지 않는다.
  - 다시 열 때 실제 승인 경로를 먼저 작은 규모로 보므로, 열자마자 다시 멈추는 흔들림이 준다.
  - 자동 판정이 막혀도 commander가 바로 연다.
  - 재시도 큐 건을 판정에서 빼서, 장애 뒤의 긴 확정 소요가 시작과 해제를 흐리지 않는다.
- **대가**
  - 회복 뒤 다시 열 때까지 최소 3분과 시험 재개 시간(첫 승인 20건이 모일 때까지. 팬이 결제창에서 인증하는 시간이 들어가 보통 몇 분)이 걸린다. 그동안 홀드는 멈춰 있다.
  - 시험 재개 동안 먼저 결제하는 사람은 무작위로 정해진다.
  - payment-svc에 Lease 판정자와 작은 표 둘, 지표 셋이 생긴다.
- **반영 수치(2026-10-28)**: WBS 2.7.5에 판정자·확인 호출·시험 재개·수동 해제·상태 표를 더한다(2.75일 → 3.5일 [가정]). 콘솔 위젯의 단계 표시는 콘솔 작업 안에서 한다.

## 되돌릴 조건

- G-05와 P-T43에서 확인 호출은 정상인데 시험 재개가 거듭 실패하면(조회 경로와 승인 경로가 자주 엇갈리면), 확인 호출을 결제사가 주는 다른 확인 방법으로 바꾸거나 확인 호출 단계를 줄이는 것을 다시 본다.
- 결제사가 계약에서 정지 중 확인 호출을 막거나 상태 확인 API를 따로 주면 그것으로 바꾼다(review/open-items.md 39).
- 시험 재개의 20건이 자주 10분을 넘겨 모이거나, 시험으로 받은 팬의 실패가 많으면 5%와 20건을 바꾼다.

## 남는 한계

- 확인 호출은 조회 API만 본다. 승인 경로만 아픈 장애는 시험 재개에서야 드러나고, 그때 시험으로 받은 팬 일부는 실패를 겪는다(과금은 없다).
- 결제사가 회복해도 다시 열 때까지 몇 분이 걸린다. 그동안 주문서까지 온 팬의 홀드는 멈춰 있고(ADR-0085), 새로 주문하려는 팬은 기다린다.
- 시험 재개의 5%는 무작위라, 오래 기다린 팬이 먼저 결제한다는 보장은 없다.
- 판정자가 바뀌는 동안(Lease 기간) 단계 판단이 잠시 멈춘다. 상태는 DB에 있어 이어진다.
- Prometheus 입력이 없으면 판정자 파드 하나의 서킷만 보고 멈추고, 그동안 자동으로는 다시 열지 않는다. 그때는 commander가 연다.
- 채널 비활성으로 생긴 503(ADR-0085 '남는 한계')은 이 ADR의 대상이 아니다. 설정을 고치거나 명령 6으로 대체 결제사로 돌려야 풀린다.
