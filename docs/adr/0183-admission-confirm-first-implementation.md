# ADR-0183: 입장 확정의 첫 구현 — 확인·1인 1순번 키·입장 Lua 세 단계, 지금 목표, 다시 시도 시간, 입장 토큰(추천 적용, 2026-11-03)

- **상태**: 채택(2026-11-03, 추천 적용. 입장 확정의 규칙(1인 1순번 재확인, 곧 입장 대기열의 번호 순, 15분 유예, 입장 토큰 클레임)은 ADR-0005·0056·0062·0104·0122·0171과 정본 §6에 있던 것이고, 정본에 방법이나 숫자가 없던 것만 아래에 적었다) 2026-11-09(ADR-0226): 결정 4의 'AIMD의 현재 목표도 이 칸이다'를 나눈다. `targetNow`는 결제사·합산 나누기까지 끝난 실제 목표이고, AIMD의 자기 목표는 `aimdTarget`이다. 입장 확정이 `targetNow`를 읽는 것은 그대로다
- **관련**: FR-008, POL-002, POL-008, POL-009, Q-T9, Q-T10, Q-T11, Q-T28, Q-T31, Q-T60, ADR-0005, ADR-0050, ADR-0056, ADR-0062, ADR-0104, ADR-0122, ADR-0171, ADR-0181, ADR-0182, [docs/features/queue-admission.md](../features/queue-admission.md) §5·§6, [docs/data.md](../data.md) §3, docs/api/openapi.yaml(입장 확정), [docs/observability.md](../observability.md) §5, `specs/queue.qnt`(`admit`), BUILD_ORDER PRF-110, wbs 2.3.3

## 맥락

- queue-svc에는 사전 검증과 진입(대기표 발급)만 있고 입장 확정이 없다. admission-ctrl 리더(PRF-090·100)는 `slots`·`soon`·`soon_at`·`call_req`를 읽어 빈자리와 오는 중을 세지만 아무도 쓰지 않는다.
- 사람 키(`q:adm`·`q:dup`, 해시 태그 `{pid}`)와 회차 키(`{event:E}`)는 해시 슬롯이 달라 한 Lua로 묶지 못한다. 정본은 '입장 자리를 잡기 전에 `q:adm`을 확인하고 비었으면 채운다'고만 하고, 자리가 없어 `SOON`이 될 때 그 값을 어떻게 할지는 없다.
- 정본에 없던 것: 입장 확정이 빈자리를 셀 때 쓰는 '지금 목표'(리더만 안다), `retryAfterSeconds`의 '최근 자리가 비는 속도'와 `NOT_YET`의 `retryAfterMs`를 세는 법, 응답을 잃은 재시도에 자리를 두 번 주지 않는 법, 빠진 번호·잘못된 대기표의 응답 이름, 입장 토큰의 첫 사용 기한을 싣는 곳, 예상 대기 오차의 '처음 보인 예상 대기'를 서버가 아는 법, `admission_soon_wait_seconds`의 처음 `SOON` 시각을 두는 곳.

## 결정

1. **세 단계와 마무리(추천 적용)**: 입장 확정은 ① 회차 슬롯 확인 Lua(읽기만: 판매 상태, 빠진 번호·추가 검증, 건너뛴 구간 세대, 차례 전, 차례 시각과 15분) ② 사람 슬롯 `q:adm` Lua ③ 회차 슬롯 입장 Lua(빈자리·곧 입장) ④ 사람 슬롯 마무리 순서로 한다. ①에서 걸리는 대기표(만료·빠진 번호·차례 전)는 `q:adm`을 건드리지 않는다. 명세 `admit`의 '회차 확인 → 사람 키 → 기록'과 같은 순서다. 명세는 2026-11-04 이 네 호출과 곧 입장 뒤의 되돌리기를 동작으로 나눴다(`admitCheck`·`admitClaim`·`admitSlot`·`admitSettle`·`admitRelease`, ADR-0184).
2. **`q:adm` 값과 다시 받기(추천 적용, 2026-11-03 새 맥락 리뷰로 고침)**: `q:adm` 값은 `{대기표 해시}:{요청 표지}`다(요청마다 새로 만드는 값). 비었으면 채우고(NEW), 같은 대기표면 통과(SAME), 다른 대기표면 409 `DUPLICATE_ADMISSION`이고 이 번호의 빠진 번호 비트를 켠다. 대기표가 받은 자리의 jti는 회차 슬롯 `q:{event:E}:slot_of`(대기표 해시 → jti)에 둔다. 입장 Lua는 그 자리가 만료 전이면 같은 jti로 입장 토큰을 다시 주고, 첫 사용 기한을 지금 + 5분으로 올리며(새 토큰의 `iat`와 맞춘다), 입장 수·처음 요청은 다시 세지 않는다. 같은 대기표의 요청이 동시에 와도 회차 슬롯 Lua 하나가 가르므로 자리는 하나다(처음 안처럼 jti를 사람 슬롯에서 읽으면 두 요청이 둘 다 자리를 잡았다). 자리가 만료·회수됐으면 새 jti로 다시 잡는다(그 jti의 구매 세션이 이미 열렸다 끝났으면 같은 jti로는 새 구매 세션을 열 수 없어서다). 15분이 지났어도 이 대기표의 자리가 살아 있으면 만료로 보지 않는다(입장한 뒤 응답을 잃은 재시도).
3. **`SOON`이면 새로 채운 값을 지운다(추천 적용, 리뷰로 고침)**: ③이 `SOON`이고(또는 그 뒤가 대기열 Redis 장애로 끝나고) ②가 NEW였으면 ④에서 값이 이 요청의 표지 그대로일 때만 지운다. 입장하지 않은 사람의 `q:adm`이 남으면, 곧 입장 대기열에서 빠진 뒤 15분이 지나 410을 받을 때 `rejoinAllowed`가 false가 되고 진입 ①이 `already-admitted`로 막기 때문이다. ADMITTED면 ④가 값이 없거나 같은 대기표일 때 이 요청의 표지로 다시 쓰고 `q:dup`을 지운다. 같은 대기표의 다른 요청이 `SOON` 되돌리기로 값을 지웠어도 되살리고, 늦게 온 되돌리기는 표지가 달라 지우지 못한다. 같은 사람의 두 번째 대기표는 ②에서 첫 대기표의 값을 보는 동안 409를 받는다.
4. **지금 목표(추천 적용)**: 리더가 `ADVANCE` 주기마다 쓰는 목표를 `q:{event:E}:ctl`의 `targetNow`에 남기고, 입장 Lua가 같은 값을 읽는다(없으면 처음 값 5,000). 빈자리 = `targetNow` − 만료 전 자리 수다. AIMD(HOT-030)의 현재 목표도 이 칸이다. 일시 매진(`ALL_HELD`)에는 리더가 새로 부르지 않을 뿐, 이미 불린 사람의 입장 확정은 평소대로 받는다.
5. **다시 시도 시간(정본 식, 속도는 추천 적용)**:
   - `retryAfterSeconds` = ⌈(곧 입장 대기열에서 내 앞 수 + 1 − 빈자리) ÷ 최근 10초 입장 속도⌉를 1~5초로 자른다. 자리가 찬 동안의 새 입장은 비워진 자리만큼이라, 입장 속도를 '자리가 비는 속도'로 쓴다. 입장 속도는 `q:{event:E}:admits`(1초 칸 16개를 돌려 쓰는 Hash, 값 `{초}:{수}`)에서 지난 10초를 더한다. 속도가 0이면 5초다.
   - `NOT_YET`의 `retryAfterMs` = ⌈(내 번호 − serving) ÷ 최근 10초 serving 속도⌉를 1~60초 [가정]로 자른다. 속도는 `serving_log`의 끝 11칸에서 10초 전(또는 그보다 앞)의 마지막 칸과 지금 serving으로 센다. 속도가 0이면 60초다. 직접 선택 공연도 차례 전 요청은 입장 자리를 주지 않고 `NOT_YET`으로 답한다.
6. **처음 요청과 도착 지연(정본 결정 2·6의 방법, 리뷰로 고침)**: 번호마다 한 번만 센다. 회차 슬롯의 번호 비트맵 `q:{event:E}:req`(수명 판매 종료)가 0일 때 켜고 센다('NEW이고 곧 입장 대기열에 없을 때'라는 처음 안은 곧 입장에서 빠진 뒤 다시 온 요청을 두 번 셌다). `ZRANGE calls 내 번호 +inf BYSCORE LIMIT 0 1`로 찾은 전진의 시각이 차례 시각 칸(`serving_log`)과 같은 초일 때만 그 전진으로 본다. 60초가 지나 그 전진 기록이 지워졌으면 뒤 전진을 잘못 고르지 않게 세지 않는다(그 번호는 이미 비율 창 밖이다). 건너뛴 구간의 옛 세대 번호도 세지 않는다. 센 때 '지금 − 그 전진 시각'을 `admission_arrival_delay_seconds`로 낸다.
7. **응답 이름과 차례 전 입장 지표(추천 적용)**: `queue_admit_before_turn_total`은 ADMITTED인데 번호가 입장 Lua가 본 serving보다 클 때 오른다. 입장 Lua가 같은 확인으로 이미 막으므로 늘 0이고, 그 확인이 빠지는 코드 퇴행을 잡는 감시다. 대기표 MAC·회차·계정이 틀리면 403 `queue-ticket-invalid`, 15분 만료는 410 `queue-ticket-expired`(v0와 같은 이름, `rejoinAllowed`), 빠진 번호(추가 검증 중·통과가 아닌)와 건너뛴 구간의 새 세대 번호는 410 `queue-ticket-removed`, 본문에 대기표·참가 토큰·권리 ID가 하나도 없으면 400이다. 차례 시각 기록이 없으면(장애로 잃음) 만료를 세지 않는다.
8. **입장 토큰(정본 클레임, 싣는 법은 추천 적용)**: ES256 JWT, 머리 `typ` `admission+jwt`·`kid`, 클레임 `iss`·`sub`(계정)·`aud` `purchase`·`jti`·`sid`·`event`·`jny`·`iat`·`exp`(= `iat` + 최대 체류 45분). 첫 사용 기한은 클레임을 더하지 않고 purchase-svc가 `iat` + 5분으로 본다. 서명은 Node 표준 암호 모듈로 한다(서비스에 새 의존성을 깔지 않는다, 서명 형식은 RFC 7515 그대로라 받는 쪽은 어느 라이브러리로든 검증한다). 키는 환경 값의 개인 JWK다(OPEN[10] 추천 적용, docs/security/secrets-and-keys.md).
9. **곧 입장 처음 시각(추천 적용)**: `q:{event:E}:soon_first`(Hash, 필드 = 해시, 값 = 처음 `SOON` 시각 ms)를 둔다. `SOON` 때 비었을 때만 쓰고, ADMITTED 때 읽어 `admission_soon_wait_seconds`를 낸 뒤 지운다. 리더가 낡은 곧 입장 항목을 뺄 때도 함께 지운다.
10. **예상 대기 오차(추천 적용)**: 입장 확정 본문에 선택 칸 `firstEtaSec`(브라우저가 처음 보인 예상 대기, 초)·`firstEtaAtMs`(그때의 보정된 서버 시각)를 둔다. 그 대기표가 처음 자리를 잡을 때 (차례 시각 − `firstEtaAtMs`) ÷ `firstEtaSec`을 `queue_eta_error_ratio`에 넣는다. 관측용이라 받는 층이 모양을 묻지 않고(브라우저의 작은 결함이 입장을 400으로 막지 않게), 숫자가 아니거나 범위 밖(예상 0 이하·하루 넘음, 시각이 미래이거나 이틀보다 앞)이면 버린다. 클라이언트 값이라 위조로 분포를 흐릴 수 있는 것은 받아들인다(판정에 쓰지 않는다).
11. **구매 세션 사건(정본, 갱신 조건은 추천 적용)**: `PurchaseSessionStarted`면 그 jti 자리가 남아 있을 때만 점수를 최대 체류 시각으로 올리고(`ZADD XX GT`), `PurchaseSessionEnded`면 뺀다. 5분 첫 사용 기한으로 이미 회수된 자리를 늦게 온 시작 사건이 되살리지 않게 한다.

## 검토한 대안

| 대안 | 기각 사유 |
| --- | --- |
| `q:adm`을 입장 Lua 뒤(ADMITTED일 때만) 채운다 | 같은 사람의 두 대기표가 동시에 오면 둘 다 자리를 잡고, 늦은 쪽의 자리를 되돌리는 보상 쓰기가 필요하다. 정본도 '자리를 잡기 전에'다 |
| `SOON`이어도 `q:adm`을 그대로 둔다 | 입장하지 않은 사람이 곧 입장에서 빠진 뒤 만료되면 다시 줄 서지 못한다(`rejoinAllowed` false, 진입 `already-admitted`) |
| 리더가 '자리가 비는 속도'를 재서 `ctl`에 둔다 | 리더 Lua가 자리 회수(만료·구매 세션 종료)를 다 보지 못해(종료 사건은 queue-svc가 받는다) 따로 세야 한다. `SOON`은 드물고 값은 1~5초로 잘리므로 입장 속도로 충분하다 |
| 입장 토큰에 첫 사용 기한 클레임을 더한다 | `iat` + 5분과 같은 값이고, 받는 쪽 규칙이 하나 는다 |
| 입장 토큰 서명에 jose를 queue-svc에 깐다 | 지금 이 PC에서 의존성 설치가 막혀 있고(pnpm이 Windows 앱 제어에 막힘), ES256 서명은 Node 표준 모듈로 몇 줄이다 |

## 결과와 트레이드오프

- 입장 확정 한 건은 대기열 Redis를 3~4번 부른다(확인·`q:adm`·입장·마무리). 회차 키가 둘(`slot_of`: 입장한 대기표마다 한 칸, `req`: 번호 비트맵) 는다. 입장 확정은 초당 약 28건이라 부담이 작다. `SOON`·만료·중복은 드물다.
- 확인 Lua와 입장 Lua 사이에 판매 상태가 바뀌면 그 한 건은 바뀌기 전 상태로 처리된다. 입장 Lua는 serving과 빠진 번호 비트만 다시 본다.
- 남는 한계: ②가 NEW로 채운 뒤 ④ 전에 파드가 멈추면 `SOON`인 사람의 `q:adm`이 남는다. 그 사람이 다시 오면 같은 대기표라 통과하지만, 곧 입장에서 빠진 채 만료되면 다시 줄 서지 못한다.

## 되돌릴 조건

- 입장 확정 처리 지연 p99가 예산을 넘으면 확인 Lua와 입장 Lua를 하나로 합친다(`q:adm`을 입장 Lua 뒤로 옮기고 중복이면 보상 쓰기).
- `SOON` 다시 시도 간격이 실제 자리 비는 속도와 크게 어긋나면(곧 입장 대기 p99가 5초를 넘으면) 리더가 자리 회수 수를 세는 쪽으로 바꾼다.
