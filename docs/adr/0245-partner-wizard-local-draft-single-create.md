# ADR-0245: 공연 등록 위저드는 입력을 브라우저에 임시저장하고 판매 정책 단계에서 한 번에 등록한다

- **상태**: 채택(2026-11-09, 추천 적용. 서버가 없는 화면은 계약 모양 가짜 API로 띄운다는 소유자 결정 ADR-0199를 따른다). BUILD_ORDER HOT-184.
- **관련**: [docs/design/d5-screen-blueprint.md](../design/d5-screen-blueprint.md) §6.4, ADR-0118, ADR-0198, ADR-0199, ADR-0242, ADR-0244
- **관련 ID**: SCR-021, FR-022, POL-004, POL-030, POL-035, POL-041

## 맥락

- d5는 위저드 1단계부터 자동 임시저장을 그렸는데, `POST /v1/partner/productions`는 회차가 하나 이상 있어야 하고 공연을 고치는 서버 경로(`PATCH`)는 아직 없다.
- 등록 본문에는 1단계(공연 정보), 2단계(회차), 4단계(정렬·배정·1인 한도)의 값이 모두 들어간다. 3단계(좌석맵)는 공연 ID가 있어야 열린다.
- 파트너 콘솔에는 아직 API 클라이언트와 로그인 연결이 없다(게이트웨이 경로는 BOT-132).

## 결정

1. **임시저장은 브라우저에 한다**: `/events/new`의 입력은 `localStorage`에 1초 [가정] 뒤, 단계를 옮길 때, 화면을 떠날 때 저장한다. 공연 정보만 들어가고 개인정보는 없다. 등록에 성공하면 지운다. 같은 브라우저의 다른 탭은 저장을 따라오고, 다른 탭이 등록했거나 지웠으면 입력을 멈춰 같은 공연이 두 번 등록되지 않게 한다.
2. **등록은 4단계 끝에서 한 번이다**: 1·2·4단계를 모아 한 요청으로 보낸다. 3단계는 "등록한 뒤에 좌석맵을 만듭니다"로 안내하고 다음으로 넘어가게 한다. 이렇게 해야 정렬·배정 값을 고치는 서버 경로 없이 한 번에 저장한다.
3. **단계를 넘을 때 그 단계를 검사한다**: 서버 판정(오픈 간격·정비 시간·일정)은 등록 때 돌아오고, 그 회차의 오픈 시각 칸에 오류를 보이고 2단계로 돌아간다.
4. **시각은 한국 시각으로 입력받아 `+09:00`을 붙여 보낸다**: 기기 시간대가 달라도 같은 시각이다.
5. **멱등 키**: 같은 본문을 다시 보내면 같은 키이고, 입력을 고치면 새 키다(ADR-0225의 홀드와 같은 방식). 키는 임시저장과 함께 두어 새로고침 뒤에도 같고, 저장소를 못 쓰면 메모리에 둔다. 등록 요청 중에는 입력을 잠근다. 응답을 못 받았거나 서버 오류면 등록됐는지 모른다고 알리고 내용을 바꾸지 말고 다시 누르게 한다.
6. **폼 라이브러리를 쓰지 않는다**: 단계 전체가 하나의 임시저장 값이고 검사는 순수 함수로 시험한다. React Hook Form을 더해 얻는 이득보다 파트너 번들과 의존성이 늘어나는 비용이 크다. 입력 칸이 많은 다른 파트너 화면은 그 단계에서 정한다.
7. **미리보기는 그대로 둔다**: `?state=`가 있으면 지금의 퍼블리싱 화면을 그리고, 없으면 실제 위저드를 그린다.
8. **보드가 필수로 표시한 칸은 화면에서 막는다**: 아티스트·관람 연령·러닝타임·기획사·제작사·입장 시작은 계약에서는 선택이지만 보드(SCR-021)는 필수로 표시한다. 한 번에 등록하므로 빈 칸을 남길 까닭이 없어 화면이 막는다. 계약의 선택은 그대로 두고(다른 호출과 나중의 고치기 경로), ADR-0244 결정 1의 '필수 여부는 판매 승인 요청이 본다'는 서버의 마지막 검사로 남는다.

## 결과

- 파트너가 공연 정보·회차·정렬 방식을 입력해 등록할 수 있다. 아직 게이트웨이 경로와 로그인 화면 연결이 없어 실제 환경에서는 BOT-132 뒤에 동작한다. 지금은 가짜 API로 확인했다.
- 공연 설명(HOT-185)과 이미지(HOT-190), 가격 등급·좌석맵(HOT-210~240), 판매자 정보·승인 요청(LCH-080)은 각 단계가 잇는다.

### 넘긴 것

- 등록한 공연을 고치는 화면(`/events/[id]/edit`)은 수정 서버 경로가 생기는 단계가 잇는다.
- 같은 브라우저에서 파트너 계정을 바꾸면 임시저장이 남는다. 로그아웃 정리는 로그인 연결 단계가 한다.
- 401은 로그인 화면으로 보낸다. 토큰 갱신은 BOT-132 뒤 로그인 연결 단계가 더한다.

## 다른 선택지

| 길 | 고르지 않은 까닭 |
| --- | --- |
| 2단계 끝에서 먼저 등록하고 4단계는 고치기로 보낸다 | 고치는 서버 경로가 없다 |
| 서버에 임시저장 경로를 새로 만든다 | 임시저장 표와 정리 작업이 늘어나고, 이번 범위에서 얻는 것이 적다 |
| 회차 없이도 등록되게 계약을 푼다 | 회차 없는 공연이 생겨 판매 승인·검색의 조건이 복잡해진다(ADR-0198) |
