# ADR-0088: 4차 전수 정합성 점검 3부의 추천 적용 — 병합 차단·재인증·인증 기록, 바뀌지 않는 외부 키, 월렛 QR 무늬(2026-10-26)

- **상태**: 채택 (2026-10-26. 소유자 요청 "저번에 못했던 부분 계속 진행"에 따라, 4차 전수 정합성 점검(ADR-0087) 1·2부가 읽지 못한 문서를 3부로 읽었다. 정본이 분명한 어긋남은 정본 쪽으로 고쳤고(review R-101), 정본에 값이 없거나 같은 순위의 두 정본이 다르게 말한 것만 이 ADR에 추천 적용으로 정했다. 추천 적용은 소유자가 방향을 승인하고 세부를 맡긴 부분에서 제안해 적용한 값으로, 바꾸고 싶으면 언제든 바꾼다)
- **관련**: ADR-0004, ADR-0011, ADR-0019, ADR-0021, ADR-0023, ADR-0025, ADR-0044, ADR-0051, ADR-0054, ADR-0058, ADR-0077, ADR-0079, ADR-0080, ADR-0087

## 맥락

- 4차 점검 1·2부(2026-10-23, ADR-0087, review R-99·R-100)는 주간 사용 한도 때문에 다음 문서를 읽지 못한 채 멈췄다: design/d5 §0~§4·§7, guide/ 18편, ASVS(웹 앱 보안 검증 항목 목록) 추적 표 11개의 구현 위치, ADR-0001~0073 본문, wbs.md·wbs.csv, 00-summary·review의 현재 절, 부록(docs/appendix-learning-map.md)의 도입부와 'ADR 대응' 표.
- 3부에서는 맡은 문서를 처음부터 끝까지 읽는 점검 에이전트 17개를 돌렸다. ASVS 표는 요구사항 요약을 원문 기준으로 넓힌 뒤(ADR-0087 결정 30) 구현 위치가 새 요소를 덮지 못하던 72곳을 함께 보았다.
- 지적은 337건이었다. 대부분은 나중 결정을 따라가지 못한 옛 문장(특히 guide/와 옛 ADR), 넓힌 ASVS 요약에 비해 비어 있는 근거, 개수 숫자였다. ADR 본문은 고치지 않고 상태 줄에 읽는 법을 더했다(00-summary §1). 아래는 정본만으로 정할 수 없어 고른 것이다.

## 결정

### 가. 계약과 요청 처리

1. **입장 중인 회차의 티켓이 있으면 계정 병합을 막는다**: 병합 차단 조건에 '어느 계정이든 입장 시작부터 입장 기록 마감 사이에 있는 회차의 티켓이 있는 경우'를 더한다. 입장 중에는 티켓 소유자와 입장 키를 바꾸지 않기 때문이다(ADR-0051 결정 10). openapi 병합 제안의 차단 사유(`blockers`) 값에 `ENTRY_STARTED`를 더한다. 티켓 작업이 이미 쓰는 409 코드와 같은 이름이다(docs/features/identity.md §2.1, planning/03 POL-034).
2. **파트너·관제의 이미지 올리기도 `X-Requested-With` 헤더를 요구한다**: 파일을 여러 부분으로 나눠 보내는 형식(multipart)의 업로드는 모두 이 헤더를 필수로 둔다는 판정(asvs/catalog-review 3.5.1)에 맞춰, 후기 사진에만 있던 헤더를 공연 이미지 올리기(`POST /v1/partner/events/{eventId}/images`)와 홈 배너 이미지 올리기(`POST /v1/ops/home-layout/banner-images`)에도 둔다.
3. **주문 생성·결제 시도·결제 접수는 JSON이 아닌 본문에 415를 낸다**: `POST /v1/orders`, `POST /v1/orders/{orderId}/payments`, `POST /v1/orders/{orderId}/payment-acceptance`에 415 Problem 응답을 더한다(asvs/payment 3.5.2). 그래서 openapi의 4xx·5xx 응답은 264개가 되고, 그 가운데 260개가 Problem 본문을 선언한다. 예외 4개는 그대로다(docs/api/guidelines.md §12).
4. **HTTP/2 요청의 길이 대조**: 요청 경계를 판정하는 공통 행(asvs/settlement 4.2.1)에 'HTTP/2 요청의 `Content-Length`가 실제 본문 데이터(DATA 프레임) 길이의 합과 다르면 거부한다'를 더한다. Envoy·CloudFront가 기본으로 이렇게 하는지는 PoC(wbs 2.11.2)에서 확인한다.
5. **Fastify를 쓰지 않는 서비스의 응답·요청 검증**: NestJS 기본 Express 어댑터를 쓰는 서비스는 응답 DTO(응답에 실을 칸을 정한 객체)의 허용 필드만 직렬화하고, 공용 검증 파이프가 같은 이름의 매개변수가 겹쳐 오면 거부한다(asvs/delivery 15.3.1·15.3.7, ADR-0023).
6. **결제사 응답과 지급 웹훅은 쓰는 필드만 스키마로 검사한다**: 지급 건 상태·금액·`refPayoutId`, 셀러 상태처럼 PEAKET이 읽는 필드만 검사하고 나머지는 결제사 규격에 맡긴다(asvs/settlement 2.1.1, docs/features/settlement.md §10).

### 나. 인증·기록·비밀

7. **다른 기기의 로그인 세션을 끝내기 전에 재인증한다**: POL-019 재인증 목록에 '다른 기기의 로그인 세션 끝내기(SCR-017 로그인된 기기 관리)'를 더한다. 같은 화면에서 현장 스캐너 세션을 끝낼 때도 소셜 재인증을 거친다(identity §4, asvs/auth·offline-gate 7.5.2).
8. **로그인·재인증 기록에 인증 방식과 쓴 인증 요소를 남긴다**: 성공·실패와 함께, 팬은 소셜 제공자를, 관리 계정은 비밀번호와 TOTP나 패스키를 적는다(identity §9). ASVS 16.3.1 행들은 판정 절이 없는 asvs/auth.md 대신 identity §9를 가리킨다.
9. **암호 목록을 갱신하는 규칙**: secrets-and-keys의 목록이 암호 목록(쓰는 키·비밀·알고리즘·인증서의 목록)이다. 키·비밀을 더하거나 바꾸는 ADR·PR은 같은 변경에서 목록을 고치고, 분기마다 [가정] KMS·Secrets Manager·ACM의 실제 목록과 대조한다(ASVS 11.1.2).
10. **인코딩만 된 값과 로그의 분류**: Base64·JWT 본문처럼 인코딩만 된 값은 풀었을 때의 내용으로 등급을 매긴다. 로그 속 민감 데이터는 2단계 마스킹 뒤에 저장하고, Grafana 권한으로 볼 사람을 나눈다(data-classification, ASVS 14.1.1·14.1.2).
11. **GitHub 조직 권한 변경 기록의 3년 보존**: GitHub 조직 감사 로그는 화면에 최근 180일만 남으므로, 조직 웹훅(member·organization·team 사건)을 받아 운영 감사 저장소(S3 Object Lock)에 사본을 남겨 3년 보존을 지킨다(devops §10.4, asvs/delivery).
12. **바뀌지 않는 외부 키는 위험을 줄인 뒤 받아들인다**: 단기 토큰을 지원하지 않는 외부 서비스의 정적 키가 대상이다. 외부 SaaS 토큰(Infracost API 키, Slack 웹훅 주소, Grafana 주석 토큰, Healthchecks.io 핑 주소)과 결제사 키(토스페이먼츠 시크릿 키, 포트원 API 시크릿)다. 환경 비밀이나 Secrets Manager에 두고, 범위를 그 기능만으로 좁히고, 1년마다 바꾸고, 노출이 의심되면 바로 폐기한다. 토스 키는 호출 IP를 NAT 고정 EIP로 제한한다. 그래서 ASVS 13.2.1은 asvs/delivery·payment·settlement 모두 '부분 적용'이다. 전달 표가 근거로 들던 ADR-0054에는 이 위험 수용이 없어 이 ADR에 둔다.

### 다. 화면·운영·일정

13. **월렛 QR 둘레의 움직이는 무늬와 지금 시각**: ADR-0025의 결과대로, 정적 캡처본과 구별되도록 QR 둘레에 계속 움직이는 무늬와 지금 시각을 함께 그린다(design/d2 CMP-029). 움직임 줄이기 설정(`prefers-reduced-motion`)이면 무늬는 멈추고 시각만 매초 바꾼다.
14. **입력 신호 끊김 지표의 라벨**: `admission_control_input_stale{event_id,input}`로 둔다. 입력 신호 상태를 회차별 키에 두므로 회차를 함께 적는다(docs/features/queue-admission.md, docs/observability.md §3·§5).
15. **CloudFront 배포별 한도 사용률의 최대값을 남긴다**: R0 SLO 스냅샷과 회차 사실 F11에 이 값을 넣어 한도 증액 요청의 근거로 쓴다(ADR-0058 결정 7, docs/features/analytics.md §3.2·§5.2).
16. **포트원 결과를 리디렉션으로 받지 못하면 포트원을 고르지 않는다**: 결제창 결과는 기기와 관계없이 리디렉션으로 받는다(ADR-0079 결정 7). 그래서 P-T33에서 리디렉션으로 결제 토큰이 오지 않으면, 모바일에서만 끄는 예전 대비책 대신 능력 플래그로 포트원 자체를 고르지 않고, ADR-0079 되돌릴 조건대로 포트원의 결과 받기 방식을 다시 본다(docs/features/payment.md §2.2·§11, ADR-0044 상태 줄).
17. **WBS 상위 행의 상태**: 하위 작업을 모아 적는다. 모두 완료면 완료, 하나라도 진행이나 완료가 있으면 진행, 아니면 예정이다(wbs/wbs.md §1).
18. **앱 개수의 표기**: 프론트엔드 앱은 4개로 세고, 포렌식 리플레이 데모 앱(`apps/forensics`, ADR-0080)은 따로 적는다. docs/frontend.md 머리말의 '앱 넷과 포렌식 리플레이 데모'와 같다(planning/00·planning/01·review §8).

## 검토한 대안

- 결정 1: 병합은 허락하고 입장 중인 티켓만 옮기지 않는 안도 있었다. 그러면 한 사람의 티켓이 두 계정에 나뉘어 남고 입장이 끝난 뒤 다시 옮기는 단계가 필요해 택하지 않았다.
- 결정 7: 정책을 바꾸지 않고 ASVS 7.5.2를 관리 계정만 '부분 적용'으로 두는 안도 있었다. 5분 재인증 토큰 흐름이 이미 있어 더하는 비용이 작아 넣었다.
- 결정 12: 결제사 키는 '적용'으로 두는 안도 있었다. 13.2.1이 바뀌지 않는 API 키를 쓰지 않을 것을 요구하므로, 같은 처지인 외부 SaaS 토큰(전달 표)과 같은 판정으로 맞췄다.
- 결정 13: 무늬를 넣지 않고 ADR-0025 상태 줄에 '두지 않는다'를 적는 안도 있었다. ADR-0025가 캡처본 악용을 줄이는 보조 수단으로 약속했고 그리는 비용이 작아 넣었다.
- 결정 16: 결제 토큰이 주소에 실려도 포트원을 쓰는 안은 결제사 전환 대체 경로를 지키지만, 결제 토큰이 주소·브라우저 기록·서버 로그에 남는 범위가 넓어져 택하지 않았다.
- 결정 18: 데모 앱을 다섯째 앱으로 세는 안도 있었다. 데모는 서버 없이 합성 데이터만 쓰는 시연이라 제품 앱과 범위가 달라 따로 적었다. guide/17의 '앱 다섯 개'는 저장소의 앱 폴더 수라 그대로 둔다.

## 결과와 트레이드오프

- 고친 곳: 문서 112개(이 ADR 포함)에 고칠 문장 584건(에이전트 제안 524건, 직접 작성 60건). 옛 ADR 47개의 상태 줄에 읽는 법을 더했고, guide/ 18편이 ADR-0062 이후 결정을 따라왔다. REST 경로·작업 수는 그대로(166개·182개)이고, 오류 응답은 264개 가운데 260개가 Problem이다.
- ASVS 표: payment·settlement의 13.2.1이 '부분 적용'이 되어 적용 확정이 82건·112건이다.
- 결정 7은 다른 기기 로그아웃에 재인증 한 단계를 더한다. 결정 12는 정적 키의 위험을 없애지 않고 줄여서 받아들인다. 결정 16은 P-T33이 실패하면 그 공연에서 결제사 하나가 멈출 때 바꿀 곳이 없어진다(ADR-0044의 대체 결제사 전환을 쓸 수 없다).

## 되돌릴 조건

- 결정 1: 입장 기록 마감 전 병합 요청이 잦아 고객 지원 부담이 크면, 입장 중인 티켓을 남겨 두는 부분 병합을 검토한다.
- 결정 9: 분기 대조 주기 [가정]은 첫 분기를 운영한 뒤 소유자가 정한다.
- 결정 12: 결제사나 SaaS가 단기 토큰(예: OAuth 클라이언트 자격 증명으로 받는 짧은 토큰)을 지원하면 그쪽으로 바꾸고 '적용'으로 되돌린다.
- 결정 13: 사용성 시험에서 무늬가 QR 인식이나 읽기를 방해하면 시각 표시만 남긴다.
- 결정 16: 포트원이 결과를 주소 쿼리 없이 넘길 수 있게 되면 다시 고른다.

## 남는 한계

- 정본에 값이 없어 이번에 정하지 않은 것: 리포트·결정 기록 API의 레이트 리밋 값(asvs/analytics 2.1.3), 분석 저장소 호출(ClickHouse·Mimir·S3)의 시간 초과와 재시도 간격, Maven(Flink)·PyPI(dbt) 의존성의 레지스트리 고정 규칙, 관제·관측 도구(Grafana·ArgoCD·쿠버네티스 API)와 운영자 원격 접속의 전송 암호화를 한 곳에 모은 규칙, 자정 대사 조회가 자정에 여는 공연의 온세일과 겹칠 때의 규칙(docs/features/payment.md §8).
- 2부에서 남긴 것도 그대로다: data-classification의 동의·구독·예매 제한 행, Datadog 평가 키 등 비밀 행, 좌석맵 heat 팔레트, 로그인 접속기록을 접속기록 DB에 넣는 경로. 환급 계좌 화면(SCR-060)의 REST 경로도 아직 없다.
- wbs 작업 설명에 ADR-0062~0065 범위가 빠진 작업이 여럿 남았다. 범위와 일수는 wbs §6에 있고, 이번에는 지적된 두 작업(2.2.2·4.5.3)만 고쳤다.
- CloudFront 지표(CloudWatch)를 Prometheus·Mimir로 가져오는 경로가 없어, 결정 15의 값을 R0 스냅샷에 넣는 방법은 wbs 4.1.1에서 정한다.
- ADR-0011 본문에 깨진 글자(제어 문자)가 있다. 상태 줄에 읽는 법만 적었고, 본문을 되돌리려면 R-92와 같은 소유자의 일회성 예외 허락이 필요하다.
- 옛 ADR이 약속한 기각 근거 실험 4건(ADR-0004 Cassandra·ClickHouse 비교, ADR-0019 Aphrodite·Fela PoC, ADR-0021 CockroachDB 두 가지)은 일정에 없다. 상태 줄에 사실만 적었고, 넣을지는 00-summary 질문 48로 소유자에게 묻는다.
