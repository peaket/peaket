# BAT-610 브라우저 확인

- **무엇**: BAT-610(LCH-050·LCH-060, R-556)의 파트너 화면을 운영 빌드로 눌러 본 기록이다(2026-11-14 heavy gate).
- **환경**: Windows, Docker 없음. `apps/partner` 운영 빌드(`next build`, `NEXT_PUBLIC_PARTNER_API_ORIGIN=http://127.0.0.1:4012`)를 `next start -p 4201`로 띄우고, `tools/web-checks/partner-api/server.mjs`를 `PARTNER_ORIGIN=http://127.0.0.1:4201`로 띄웠다.
- **도구**: Playwright Chromium 1280×900. 확인 스크립트는 저장소 밖 임시 파일로 돌렸고, 아래 결과만 남긴다.
- **가짜 API**: 상품·웹훅·배송 항목·정산서·예매자·다운로드 이력. 재인증 `POST /v1/partner/auth/reauthentications`는 `factors`에 passkey를 넣은 `DONE`을 준다. 명단 내려받기는 `X-Reauth-Token`이 없으면 403 `reauth-required`다.

- 콘솔 오류는 의도한 403 두 번과 404 한 번뿐이었다. 화면을 막는 오류는 없었다.
- 403·404는 확인을 위해 Playwright `page.route`로 만든 응답이다.

## 브라우저 확인 중 고친 것

- **CSV가 문자열로 와서 다운로드가 안 되던 문제**: `api-client`는 `text/csv`를 문자열로 돌려준다. `asBlob`으로 문자열을 Blob으로 감싸 배송·예매자 명단 다운로드를 고쳤다.
- **웹훅 비밀 1회 화면에서 재발급으로 넘어가지 못하던 문제**: [비밀을 확인했습니다]로 1회 표시를 닫고 바로 재발급할 수 있게 했다.
- **웹훅이 둘 이상일 때 첫 주소만 보이던 문제**: 주소 선택과 [새 웹훅 추가]를 넣었다.
- **초안 상품을 고치면 게시되던 문제**: `DRAFT`·`HIDDEN` 상태를 유지한다.
- **실무자가 송장·반품 거절을 못 하던 문제**: 계약 권한(`partner_admin`·`partner_member`)에 맞춰 실무자도 송장 등록·반품 확인·거절을 하게 하고, 배송 명단 내려받기만 관리자로 남겼다.
- **예매자 명단 회차 ID**: 공연 ID가 아니라 선택한 회차 ID(`perf-…`)로 명단·이력을 부르게 했다.
