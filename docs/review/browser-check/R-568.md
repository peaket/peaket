## 누른 것

- `/commands`: 명령 목록 3건, 승인 대기 `EVENT_CANCEL` 상세의 `params`를 확인했다.
- **승인**: 승인 대기 명령에서 `승인`을 눌러 상태가 `성공`으로 바뀌고 시도 1회·`result`가 보이는 것을 확인했다.
- **반려**: 가짜 API를 다시 띄워 승인 대기 상태로 돌린 뒤 `반려` → 사유 입력 → `반려 확정`을 눌러 상태가 `반려됨`이 되는 것을 확인했다.
- **재시도**: 실패 `SCALE_CHANGE`를 골라 `다시 시도`를 눌러 상태가 `성공`, 시도 2회, `lastError`가 사라지고 `result`가 보이는 것을 확인했다.
- **감사 체크포인트**: 탭에서 체크포인트 1건을 보고 `검증`을 눌러 `통과`를 확인했다. `?role=commander`로 다시 열어 사유를 적고 `체크포인트 만들기`를 눌러 2건이 되는 것을 확인했다.
- **5초 폴링**: 네트워크 기록에서 `GET /v1/ops/commands?limit=100`이 약 5초 간격(…717.9, …722.9, …727.9, …732.9, …737.9)으로 반복되는 것을 확인했다.
- 콘솔 오류는 없었다(React DevTools 안내와 React Router `HydrateFallback` 경고만).

- 브라우저는 **가짜 ops API**만 불렀다. 실제 관리자 쿠키·identity 경로를 브라우저에서 열지 않았다.
- 실제 ops-svc HTTP 경로는 `services/ops-svc/test/command-execution-http.test.ts`(메모리 저장소)와 `services/ops-svc/test-int/command-execution.int.test.ts`(실제 PostgreSQL 18 + 가짜 core-svc/purchase-svc HTTP)가 확인했다. 여기서 2인 승인·요청자≠승인자, `SCALE_CHANGE`→core-svc, `EVENT_CANCEL`→purchase-svc, `DISPATCHED`→`SUCCEEDED`/`FAILED`, 재시도, 체크포인트 루트·사슬·검증, 내부 사건 eventKey 멱등을 봤다.
