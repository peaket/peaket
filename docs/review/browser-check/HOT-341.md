# 브라우저 확인: HOT-341 ① 대기실 로비 경로·여러 탭·차례 도래 유예·로그아웃

- 날짜: 2026-11-05
- 커밋: 이 기록과 같은 커밋(HOT-341 ①)
- 브라우저: Claude in Chrome(Chrome, Windows, 시험용 프로필)
- 환경
  - 계약 모양 가짜 API(127.0.0.1:4010)에 로비 경로를 더했다: 로비 참가, 로비 참가 취소, 셔플 결과 파일, 참가 토큰으로 입장 확정. 상태는 `/__mock/state`의 `queueOpenIn`(오픈까지 남은 초)·`queueLobby`·`queueShuffle`과 기존 대기열 칸으로 바꾼다.
  - 대기실 개발 서버(`pnpm --filter @peaket/queue-room dev`, localhost:3004). 사람 확인은 개발용 시뮬레이터(0.8초 뒤 토큰)다. 캡차는 풀지 않는다.
  - 회차는 가짜 API 고정 자료의 뮤지컬 별빛 정원(`0b8f1f2e-…4e04`)이다.
- 범위: SCR-007(d5 §5.7), SCR-008(d5 §5.8 '차례 도래 유예'·invalid), docs/frontend.md §3.4·§5.1 '여러 탭'·§5.14.4, ADR-0208

## 브라우저 시험으로 본 것

- 상태 기계(`test/lobby.test.mjs` SCR-007, `test/tabs.test.mjs` FE-T6·SCR-008, 가짜 시계·공유 저장소·가짜 Web Locks·가짜 BroadcastChannel): 로비 참가 응답 전부(201·REQUIRED·401·403 두 가지·428·409 두 가지·429·503·위젯 실패), boot 일정, 셔플 지연·취소, 다시 참가, 오프라인, 리더 하나, 리더 숨김 뒤 넘김, 모든 탭 숨김, 방송 끊김, 숨긴 채 차례, 두 탭 진입 409, stored 방송, 차례가 온 시각 세 출처.
- 카운트다운(`test/countdown.test.mjs` FE-T42): 늦게 깨기·숨김 2분·기기 시계 바뀜·낭독 3번.
- 로그아웃(`test/logout.test.mjs`): 지우는 키·남기는 키·월렛 고를 때만·웹 푸시 서비스 워커는 남김·서버 응답 처리.

## 새 맥락 리뷰 뒤 다시 본 것

- 리뷰가 찾은 것(대기표가 다른 탭끼리 서로를 끝내거나 저장소를 지움, `NOT_YET` 하한을 [지금 입장]이 깸, 로그아웃 뒤 다른 탭이 저장소를 다시 채움, 로비 일정 다시 받기 없음, 끝 상태 탭이 리더 잠금을 쥠 등)은 재현 시험(`test/ticket-identity.test.mjs`, `test/lobby.test.mjs` 끝 셋)을 먼저 쓰고 고쳤다.
- 고친 뒤 Chrome에서:
  - 두 탭이 같은 대기표로 기다릴 때 한 탭에서 [대기 취소] → 다른 탭이 '다른 기기에서 이 대기를 취소했습니다'로 멈추고 `queue-poll` 잠금을 놓는다(잠금 0개).
  - 그 뒤 다른 탭이 새로 진입해 새 대기표를 저장하자 멈춘 탭도 그 대기표로 다시 대기한다('앞에 245명').
  - 한 탭에서 로그아웃 → 그 탭은 웹 홈, 같은 회차를 연 다른 탭은 `peaket.session` logout을 받아 로그인 화면(`/login?next=/queue/…`)으로 간다.
  - 로비 참가(카운트다운·확인 완료)는 그대로다. 콘솔 오류 없음.

## 확인 못 함

- 리더 탭을 숨기기·모든 탭 숨기기: 확장이 다루는 탭은 배경에 있어도 `visibilityState`가 `visible`로 보여 숨김을 만들 수 없다. 상태 기계 시험(FE-T6)이 본다. 세 엔진 브라우저 시험은 HOT-342의 대기실 브라우저 검사에서 더한다.
- 오프라인 배너·저전력: 확장으로 네트워크를 끊거나 배터리 값을 바꿀 수 없다. 상태 기계 시험(SCR-007 오프라인)이 본다.
- 실제 Turnstile 위젯: 개발 서버는 시뮬레이터를 쓴다(외부 사이트를 열지 않는다).
- 비고: [지금 입장]을 누른 탭과 리더가 같은 대기표로 각각 입장 확정을 받아 두 탭 모두 좌석 화면으로 갔다(가짜 API는 queue-svc처럼 같은 대기표에 ADMITTED를 다시 준다). 사람이 직접 누른 동작이라 막지 않았다(ADR-0208 결정 6).
- 서버 로그아웃이 503으로 실패하면 그 탭의 상태 기계는 멈춘 채다(저장소는 이미 지웠다). 대화상자 안의 다시 시도로 끝낸다.
