# 브라우저 확인 대본: GAT-090·GAT-110 화면 몫(BAT-421)

- **상태**: 자리만 잡았다. 시험·검증 담당이 실제 확인 뒤 결과·스크린샷·콘솔 오류·요청 기록을 채운다. 이 문서는 아직 '통과'가 아니다.
- **범위**: SCR-038 예매 취소(web), SCR-044 회차 취소·연기 요청(partner), SCR-047 회차 취소 판정·일괄 환불(console). ADR-0328의 취소 POST 재인증·Origin 경로, 202 세 상태, `progress.accountPending`을 본다.
- **환경(채울 것)**: 작업 폴더, 세 앱 빌드/개발 서버 주소, gw-fan·gw-partner·gw-ops와 서비스 기동 방식, 시드 계정·공연·티켓, 브라우저(확장 이름·판), 날짜.

## 준비

- [ ] `pnpm --filter @peaket/validation build` 뒤 세 앱을 빌드했는가(web은 `@peaket/validation/refund-account`을 쓴다).
- [ ] 관제·파트너는 관리자 세션, 팬은 소셜 로그인 세션과 결제자 본인 티켓을 준비했는가.
- [ ] 시험용 티켓 하나는 카드 결제, 하나는 가상계좌 결제인가(계좌 칸이 참일 때만 보이는지 보려면 둘 다 필요).
- [ ] 재인증 확인기(identity 공개키·좌석 Redis `reauth:jti`)와 `PEAKET_IDENTITY_FAN_JWKS_URL`·`PEAKET_IDENTITY_ISSUER`가 켜져 있는가.

## SCR-038 `/my/tickets/{ticketId}/cancel`

- [ ] 티켓 상세·견적이 실제 API(`GET /v1/tickets/{id}`, `GET …/cancellation-quote`)로 채워지고 좌석·결제 금액·공제·환급액이 보인다.
- [ ] 카드 결제 티켓에는 계좌 칸이 없다. 가상계좌 결제 티켓은 재인증 전에는 계좌 칸이 없고, 재인증에서 돌아온 뒤에만 보인다.
- [ ] 견적 `refundAccountRequired` 참이면 재인증 `purpose=ticket-cancel-refund-account`, 거짓이면 `ticket-cancel`이 `/reauth/{provider}` 양식에 실린다(개발자 도구 요청 본문).
- [ ] 재인증에서 돌아오면 `POST /reauth/token`이 200이고, 그 뒤에만 `POST /v1/tickets/{id}/cancellation`이 나간다. 요청 머리에 `X-Reauth-Token`·`Idempotency-Key`가 있고 구매 서명 머리(`X-Purchase-Seq`·`X-Purchase-Mac`)는 없다.
- [ ] 계좌번호는 요청 본문에만 있고 `sessionStorage`·`localStorage`·주소·콘솔 로그에 없다.
- [ ] 202 `REFUNDED`는 '환급 완료', `REQUESTED`는 '환급 보류', `REFUND_PENDING`+`refundAccountRequired` 참은 '환급 대기'와 SCR-060 안내 문구만, 거짓은 '환급 지연 · 자동 재시도'로 보인다. 카드 끝 4자리는 어디에도 없다.
- [ ] 403 `reauth-required`는 d5 §9.2 문구와 새 재인증 버튼이고, 같은 본문·같은 키로 다시 보낸다. 503 `reauth-unavailable`은 새 재인증을 받는다. 422 `refund-account-required`는 계좌가 필요한 상태로 바뀐다. 409 `transfer-pending`은 [요청 보기], `entry-started`는 '공연이 시작되어 취소할 수 없습니다', `event-cancelled`는 일괄 환불 안내다.
- [ ] 콘솔 오류 0, 화면 HTML에 서버 `title`·`detail` 원문 없음.

## SCR-044 `/events/{productionId}/cancellation`

- [ ] 실제 공연 UUID로 열면 `getPartnerProduction`의 회차가 선택지에 보이고 목업 공연명이 나오지 않는다.
- [ ] 연기 요청은 KST 벽시계를 ISO로 바꾸고, 지금 시작보다 이르거나 빈 값이면 칸 오류다. 취소 요청에는 `newStartsAt`이 실리지 않는다.
- [ ] 확인 대화상자 뒤에만 `POST /v1/partner/events/{eventId}/cancellation`이 나가고 `Idempotency-Key`가 있다. 같은 본문을 다시 보내면 같은 키다.
- [ ] 202 뒤 상태가 `REQUESTED`(판정 대기)이고, 서버 상태를 바꾸면 `JUDGED`(재판정 대기) → `PENDING_APPROVAL`(확정 대기(2인 승인)) → `RUNNING`(확정 · 환불 진행 중 n%) → `COMPLETED`로 다시 읽는다. 반려면 반려 사유와 [다시 요청]이 보인다.
- [ ] 진행률은 `refundProgress`의 total·done·failed 합계만이고, `dryRun`·결제사별 몫·판정자·내부 판정 사유가 화면에 없다.
- [ ] 실무자(`?role=member`가 아니라 실제 partner_member 세션)가 요청하면 403 `partner_member` 문구가 뜨고 그 방문 동안 버튼이 꺼진다.
- [ ] 409 `event-cancellation-active`는 기존 요청 안내, `event-ended`는 종료 안내, 404는 '찾을 수 없습니다', 422 `postponement-date-invalid`는 바뀐 일시 칸 오류다.

## SCR-047 `/cancellations/{requestId}`

- [ ] 요청 ID가 없거나 404면 진행 중 요청 목록(`REQUESTED,JUDGED,PENDING_APPROVAL,RUNNING,PAUSED`)에서 고를 수 있다.
- [ ] 상세가 실제 API로 채워지고 ① 파트너 요청(회차·종류·사유·증빙·귀책 의견), ② 판정 폼, ③ 미리보기, ④ 2인 확정, ⑤ 진행률이 보인다.
- [ ] commander 판정 저장 뒤 응답의 `dryRun`으로 대상 주문·환급 총액·배상 대상/총액·결제사별 주문·예상 소요가 보인다. 모르는 키를 그대로 JSON으로 찍지 않는다.
- [ ] 확정은 `PENDING_APPROVAL`에서만 활성이고, 누르면 admin 재인증(비밀번호·TOTP → 패스키) 창이 뜬다. 끝나면 `POST …/approvals`에 `X-Reauth-Token`이 실린다. 토큰 없이 부르는 길이 없다.
- [ ] 판정자 본인은 403 `approver-ineligible` 문구를 본다. 409 `judgement-required`·`preview-required`·`already-approved` 문구가 구분된다.
- [ ] 진행률은 `done/total`(내림)이고 `failed`를 분자에 넣지 않는다. `accountPending`은 '계좌 대기 n건'으로 따로 보이고, `total = done+failed+accountPending`이면 완료 표시다.
- [ ] 일시정지·재개 버튼은 이유 글과 함께 비활성이다. viewer·CS는 읽기 전용 안내가 보이고 쓰기 버튼이 없다.
- [ ] 파트너 사유·판정 사유·팬 통지 사유는 텍스트로만 보이고 HTML로 해석되지 않는다.
