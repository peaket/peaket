# 브라우저 확인: BOT-040 가입 때 계정 연결 제안과 소유권 증명

- 날짜: 2026-11-04
- 커밋: 이 기록과 같은 커밋(BOT-040)
- 브라우저: **Claude in Chrome 못 함(연결 없음)**. BOT-010과 같은 까닭으로 Playwright(1.58.2, Chromium 156 headless shell)로 실제 클릭을 해 대신 눌렀다(docs/review/browser-check/BOT-010.md). 다음에 Chrome이 연결된 턴에 다시 누른다.
- 환경: BOT-036과 같은 로컬 스택(갈래 3 전용 포트). identity DB에 마이그레이션 0011(account.email_verified)을 적용했다. identity는 로컬이라 세션·캐시 Redis 없이 연결 제안을 프로세스 메모리에 둔다(경고 로그). 모의 OIDC 제공자는 저장소의 것을 그대로 띄우되, 카카오·구글 사용자의 sub와 이메일을 시나리오마다 바꾸는 조종 포트를 붙인 작은 감싸개로 띄웠다(저장소 밖, 같은 검증 이메일을 두 제공자에 주려고).
- 범위: SCR-039(docs/design/d5 §5.21), docs/features/identity.md §2.1 '가입 때 연결 제안의 첫 구현', I-T29, I-T30, FR-048(새 계정 만들기).
- 다시 누름: 새 맥락 리뷰를 고친 뒤(대상 계정 잠근 뒤 상태 확인, 카카오 이메일 검증 여부를 사용자 정보로 읽음, 연결 화면의 로그인은 계정 다시 고르기) 새 시험 사람으로 다섯 시나리오를 다시 눌렀다. 모의 제공자의 카카오 ID 토큰에서 이메일 검증 칸을 뺐는데도 카카오 계정이 검증 이메일로 만들어졌다(사용자 정보 경로). 아래 표는 다시 누른 결과다.

- 다루지 않은 것: 10분 만료는 시계를 돌릴 수 없어 화면으로 기다리지 않았다(단위 시험이 본다). 세션·캐시 Redis에 둔 제안은 통합 시험(test-int/link-proposal.int.test.ts, 실제 Valkey)이 본다. 닫기는 제안을 지우지 않는다(10분 만료).
- 캡처: 남기지 않았다. 값은 페이지 글과 DB로 읽었다.
