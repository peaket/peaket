# 브라우저 확인: BOT-047 팬 계정 요약·세션 종료 사유·가입 마무리(SCR-004·005·017·040)

- 날짜: 2026-11-09
- 커밋: 가지 `feature/2.1.1-fan-me`의 커밋 전 작업 트리(바탕 7fd38fea)
- 브라우저: **Claude in Chrome: 쓰지 않음(연결된 Chrome이 시험용 프로필인지 확인할 수 없음) → Playwright로 대신**. Playwright(1.64.1, Chromium 156.0.8078.4 headless shell)로 실제 클릭과 키보드 입력을 했다. 모든 브라우저 문맥은 CSP를 끄지 않았다(`bypassCSP` 없음). 다음에 시험용 프로필이 확인된 턴에 다시 누른다.
- 환경: 운영 빌드(`node seed-css/build.mjs web`, 운영 빌드만 `PEAKET_BUILDS=prod`), 서버는 `seed-css/apps.mjs`의 web(4101, 앞에 캐시 화면 해시 서버, 안쪽 Next.js 5101)과 가짜 API(`apps/web/scripts/mock-api.mjs`). 4010은 다른 세션의 가짜 API가 쓰고 있어 건드리지 않고 제 것을 4310에 띄웠다. 빌드 뒤 웹·패키지 소스가 바뀌지 않은 것을 봤다. 합성 데이터는 가짜 API의 고정 자료다. 대조(`node tools/ci/trace-check.mjs`)는 이 확인에서 돌리지 않았다.
  - 대역 넷:
    1. 빌드에 넣은 팬 API 출처는 운영 기본값(`api.peaket.example`)이다. 이 주소는 Playwright route가 받아 가짜 API로 넘겼다. 인터넷으로 나간 요청은 없다(대역에 없는 바깥 요청을 막고 세는 칸이 모든 장면에서 0).
    2. `GET /v1/identity/sessions`·`GET /v1/identity/providers`는 가짜 API에 없어 대본이 답했다. 가짜 API 상태가 비로그인이면 401이고 아니면 합성 목록이다.
    3. '겹치는 요청' 장면은 진짜 서버의 경합을 흉내 냈다: 첫 거절이 쿠키를 지워 뒤따른 갱신에는 `ended`가 없고, 갱신 답을 250ms 늦춘다.
    4. 5031 장면은 `fan=closing`인데 요약만 '가입 전'으로 대역했다(아래 관찰 3).
- 범위: SCR-004(d5 §5.4, §3.5 세션 종료 안내), SCR-005(d5 §5.5), SCR-017(d5 §5.17), SCR-040(d5 §5.22), 본인확인 흐름 시작(d5 §5.6), 셸 머리·공연 상세 ⑦(d5 §3.1·§5.2), docs/features/identity.md §8 '팬 계정 요약·세션 종료 사유·가입 마무리의 첫 구현', ADR-0202·0203·0235, I-T78 ④의 화면 쪽. 서버 시험(I-T77~I-T82)은 여기서 보지 않았다.

## 실패와 확인 못 함

1. **만 14세 미만 안내의 '홈으로'가 보조 버튼이 아니라 글자 링크다(실패, 낮음, 모양만)**.
   - 재현 단계: 가짜 API `fan=pending`으로 `/signup/consent?next=/`를 열고 [만 14세 미만입니다] → [가입 취소]를 누른다(또는 `fan=closing`으로 제출한다).
   - 본 것: `홈으로 ›` 글자 링크(`link-more` + 화살표). 누르면 `/`로 가는 동작과 문구는 정본과 같다.
   - 정본과 다른 점: d5 §5.5 상태 표 '만 14세 미만'은 `[ 홈으로 ]`이고, d5 머리의 표기 표에서 `[ 이름 ]`은 보조 버튼, `( 이름 › )`가 링크다.
   - 한계: 이 코드는 HOT-323부터 있던 것이고(`SignupForm.tsx`, 커밋된 판에도 같다) BOT-047이 바꾼 곳이 아니다. 화면을 만들 때 본 캔버스 보드와는 견주지 못했다. 재현 시험은 쓰지 않았고 코드는 고치지 않았다.

### 관찰(정본에 어긋난 것은 아니다)

1. **공연 상세마다 콘솔에 CSP 알림 한 줄(이 단계 밖)**: `The Content-Security-Policy directive 'frame-src' contains the keyword 'none' alongside with other source expressions…`. 원인은 사람 확인을 싣는 화면의 CSP가 `frame-src 'none' https://challenges.cloudflare.com`로 합쳐지는 것이다(`packages/config/headers/security-headers.mjs` 35행, `headers.test.mjs` 97행이 이 모양을 못 박는다). 브라우저는 `'none'`을 무시하고 사람 확인 출처만 허용하므로 동작은 의도와 같고 CSP 위반은 아니다. 이 단계에서 바꾼 파일이 아니다.
2. **`POST /login/kakao` 500**: 서버 로그 `PEAKET_WEB_ORIGIN이(가) 없다`. 로컬에 제공자 설정을 주지 않아서 생긴 것으로, 결함이 아니다. 그래서 로그인 경로 서버의 `next` 재검사와 '다시 로그인하면 원래 화면으로 돌아옴'은 눌러 보지 못했다(폼의 `returnTo` 값까지만 봤다).
3. **가짜 API의 `fan=closing`은 요약이 `signupCompleted: true`**라 가입 화면을 그대로 열면 곧바로 `next`로 간다(장면 5032). 진짜 서버의 '가입 전에 정리 중인 계정'은 false가 되므로 5030(열린 뒤 바뀜)·5031(요약 대역)로 봤다. 가짜 API 쪽 편의 문제이고 화면 결함은 아니다.

### 모든 시나리오 공통 요청 오류

- 비로그인·세션 끝남 장면의 401은 모두 기대한 것이다: `GET /v1/identity/me`·`/sessions`·`/providers`·`/wishes`·`/subscriptions`·`/booking-restrictions/me`, `POST /v1/identity/access-tokens`·`/verifications`·`/signup-cancellations`.
- `GET http://127.0.0.1:4101/v1/home/rankings.json` 404는 홈마다 나온다. 랭킹 파일은 www 출처의 정적 파일이고 이 로컬 구성에는 없다(가짜 API에만 있다). 기대한 것.
- `net::ERR_ABORTED`(`/identity/sessions`, `/identity/access-tokens`, `rankings.json`)는 읽지 않은 401 본문을 버리거나 페이지를 떠날 때 끊긴 것이다.
- 콘솔의 'Failed to load resource' 줄은 모두 위와 표에 적은 것에서 나왔다.

### 다루지 않은 것

- Claude in Chrome으로 다시 누르기(위 '브라우저' 줄).
- 실제 identity-svc·gw-fan·쿠키. 요약·갱신 응답 모양은 가짜 API와 대역이다. `Set-Cookie`로 팬 쿠키가 지워지는 것은 브라우저에서 보지 않았다(I-T81의 몫).
- SCR-005 [지금 본인확인]의 기관 창 흐름(모의 기관을 띄우지 않았다, 대본 범위 밖).
- SCR-017의 원격 로그아웃, SCR-040의 연결·해제·합치기(다른 단계에서 본 흐름).
- 390폭은 메뉴 시트만 봤다. Firefox·WebKit은 E2E 몫이다.
- 검사 대본은 저장소 밖 세션 scratchpad의 `stack/check-b47.mjs`(서버 `stack/b47-servers.mjs`, 전체 기록 `stack/b47-full.log`)이다. 정본 문구는 대본에 옮겨 적지 않았다. 캡처는 저장소에 넣지 않았다.
