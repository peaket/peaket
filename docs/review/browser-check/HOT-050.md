# 브라우저 확인: HOT-050 추첨 결과 파일과 검증 페이지(SCR-019)

- 날짜: 2026-11-09(같은 날 고친 뒤 다시 누름, 아래 '다시 누른 결과')
- 커밋: 가지 `feature/2.4.2-shuffle-results`의 커밋 전 작업 트리(바탕 8aa5e2e8)
- 브라우저: **Claude in Chrome: 쓰지 않음(연결된 Chrome이 시험용 프로필인지 확인할 수 없음) → Playwright로 대신**. Playwright(1.64.1, Chromium 156.0.8078.4 headless shell)로 실제 클릭과 키보드 입력을 했다. 모든 브라우저 문맥은 CSP를 끄지 않았다(`bypassCSP` 없음). 다음에 시험용 프로필이 확인된 턴에 다시 누른다.
- 환경: 운영 빌드(`node seed-css/build.mjs web`, 운영 빌드만 `PEAKET_BUILDS=prod`), 서버는 `seed-css/apps.mjs`의 web(4101, 앞에 캐시 화면 해시 서버, 안쪽 Next.js 5101)과 가짜 API(`apps/web/scripts/mock-api.mjs`, 4010). 빌드에 넣은 대기열·파일 출처는 운영 기본값(`queue.peaket.example`·`queue-files.peaket.example`)이고, 이 주소는 Playwright route가 브라우저 안에서 대신 답했다. 인터넷으로 나간 요청은 없다(대역에 없는 바깥 요청을 막고 세는 칸이 모든 시나리오에서 0).
  - 대역 셋: ① `GET …/shuffle-proof`는 시나리오 2~5에서 가짜 API로 넘겼다(`queueOpenIn`으로 일정을 옮김). 나머지는 합성 응답이다. ② 결과 파일 4,096개는 `packages/shuffle`(dist)로 실제로 맞게 만든 값이다(시드·커밋·서명·SHA-256(서명)인 비콘·머클 루트·셔플 순서). 합성 회차는 로비 40명·묶음 12명, 큰 회차는 2만 명이다. ③ 팬 API(`api.peaket.example`)는 `tools/web-checks/csp/pages.mjs`의 `stubFanApi`와 같은 503이다(화면이 부르는 계정 요약이 인터넷으로 나가지 않게).
  - 대조(`node tools/ci/trace-check.mjs`)는 이 확인에서 돌리지 않았다.
- 범위: SCR-019(docs/design/d5-screen-blueprint.md §5.19 상태 표와 본문), ADR-0232 결정 7·8·9, docs/features/queue-admission.md '내 순번 다시 계산(SCR-019)'. Q-T6은 서버 쪽 측정 시험이라 여기서 보지 않았다.
- 판정은 화면 글을 찍어 정본과 사람이 견줬고, 글이 아닌 것(Worker, CSP, 요청 주소, 넘침, 포커스)은 대본이 숫자로 봤다. 전체 43장면을 마지막에 한 번 더 돌려 대본 판정에 어긋남이 없었다.
- **다시 누름(2026-11-09)**: 아래 1~5를 고친 작업 트리(바탕은 같은 8aa5e2e8, 커밋 전)로 웹을 다시 운영 빌드하고, 같은 서버·대역·브라우저(Playwright 1.64.1, Chromium 156.0.8078.4, CSP 끄지 않음)로 눌렀다. 빌드 뒤 소스가 바뀌지 않은 것을 봤다. 고친 곳만이 아니라 대본 전체(46장면, 게시 뒤 멈춤 세 장면을 더함)를 돌렸고 대본 판정에 어긋남이 없었다. 결과는 아래 '다시 누른 결과' 표다.

| 6. ⑥ 진행률·[계산 취소]·입력 바꾸기 | 통과 | 진행 글이 지난번과 같은 차례로 늘어남. 취소하면 글과 버튼이 사라지고 Worker가 끝나며 파일 요청이 멈춤(4,096개 전). 계산 중 입력을 바꿔도 같음. 끝난 뒤 입력을 바꾸면 결과가 지워지고 [다시 계산해 확인]이 돌아옴 | 취소 때 진행 중이던 파일 요청의 `net::ERR_ABORTED`(취소 신호로 끊은 것, 기대한 것). 공통만 |
| 7. ⑥ 불일치·오류(회귀) | 통과 | 시드 커밋·비콘 값·머클 루트·루트 늦음·순번 변조·모양 틀림·파일에 없음·파일 하나 500 모두 지난번과 같은 결과 | 파일 500(일부러 만든 것). 공통만 |
| 묶음 구간과 라운드·게시 시각의 초(d5 §5.19) | 통과 | 묶음 구간 `11/9(월) 04:11:02~04:11:04`, 라운드 `8,000,000 · 04:11:05`, 결과 게시 `11/9(월) 04:11:07`처럼 초까지 보임 | 공통만 |
| 파일 없음의 제목·돌아가기 링크(d5 §5.19 '파일 없음') | 통과 | 404·503·연결 실패·없는 회차에서 h1 '셔플 검증'과 '공연 상세로 돌아가기'(주소 `/events/{id}`) 아래에 안내와 [다시 시도]. 시드 배지는 없음 | 일부러 만든 404·503·연결 실패. 공통만 |

| 12. 390px·키보드(회귀) | 통과 | 가로 넘침 없음. 입력 → Tab [다시 계산해 확인] → Enter로 시작. 버튼이 사라져 포커스는 body로 가지만 다음 Tab이 [계산 취소]로 감 → Enter로 취소, Worker 끝남. 취소 뒤 Shift+Tab으로 [다시 계산해 확인]에 감 | 공통만 |

모든 시나리오에서 콘솔에 CSP 위반이 없었고 잡히지 않은 예외(pageerror)도 없었다.

## 실패와 확인 못 함

1. **게시 뒤에 멈춘 구간의 사유가 안 보인다(실패, 대본에 더한 조합)**.
   - 재현 단계: `GET …/shuffle-proof` 응답의 `lobby`에 `publishedAt`을 두고 `seed`를 빼고 `stopped: { reason: 'members_changed', at: … }`를 더해 `/events/{id}/shuffle-proof`를 연다. 묶음도 같다.
   - 본 것: ③에 drand 값·서명·결과 파일 주소만 있고 <공개됨>이다. 멈췄다는 글이 어디에도 없고, ⑤는 '오픈 60분 뒤 원본 시드를 공개합니다', ⑥은 공개 시각이 지났는데도 '원본 시드를 공개한 뒤(…) 다시 계산할 수 있습니다'로 남는다.
   - 정본과 다른 점: d5 §5.19 '멈춤'은 ③에 멈췄다는 글과 사유 한 줄을 보인다고 적고, §5.19 본문은 ③과 ⑧을 구간마다 판단한다고 적는다. ADR-0232 결정 7은 '게시 뒤 멈춘 경우'도 멈춘 구간으로 세어 시드를 내지 않는다. 그런데 `ShuffleProofBody.tsx`의 ③·⑧은 게시 여부를 먼저 보고 그때는 `stoppedNote`·`batchStoppedNote`를 그리지 않는다(`v.pub ? … : v.stoppedNote ? …`).
   - 한계: 이 조합은 대역으로 만들었다. 서버가 실제로 어느 길로 게시 표시와 멈춤 표시를 함께 쓰는지는 끝까지 따라가지 않았다(시드 공개 코드 `reveal-shuffle-seeds.ts`는 이 경우를 먼저 거른다). 고치지 않았다. 게시 전 멈춤의 시드 안내도 같은 글이다: 공개하지 않을 구간에 '공개합니다'로 적힌다.
   - **고침과 다시 누름**: ③·⑧이 게시 값과 사유를 함께 보이고, 멈춘 구간의 시드 칸과 모든 구간이 멈춘 때의 ⑥이 '공개하지 않습니다'로 바뀌었다. 2026-11-09에 CSP를 켠 채 로비·묶음 둘 다, 로비만, FIFO의 게시 뒤 멈춤과 게시 전 멈춤을 다시 눌러 통과했다(위 '다시 누른 결과'). 조합을 대역으로 만든 한계는 그대로다.
2. **시각에 초가 없어 2초 묶음이 안 보인다(관찰, 낮음)**. 실제 화면의 묶음 구간은 `11/9(월) 03:52~03:52`로 찍히고 라운드·게시 시각도 분까지다(`dateTimeText`·`timeText`). 캔버스 값을 옮긴 미리보기 자료(`entities/shuffle-proof/model.ts`)는 `20:00:00~20:00:02`처럼 초가 있다. d5 문장에는 초 표기가 정해져 있지 않아 실패로 세지 않았다.
   - **고침과 다시 누름**: d5 §5.19에 초까지 보인다고 적혔고, 다시 눌러 묶음 구간·라운드·게시 시각의 초를 봤다.
3. **파일 없음 화면에 머리가 없다(관찰, 낮음)**. 실제 화면은 불러오는 중과 파일 없음일 때 h1과 돌아가기 링크가 없다(눌러서 확인, h1 0개). `ShuffleProofPage.tsx`의 미리보기 길은 같은 상태에서 머리를 그린다(코드로만 봤다. 개발 서버는 띄우지 않았다). d5는 그 상태의 글만 정한다.
   - **고침과 다시 누름**: d5 '파일 없음'에 제목과 돌아가기 링크가 들어갔고, 다시 눌러 파일 없음에서 h1과 링크를 봤다. 불러오는 중에는 지금도 머리가 없다(d5가 정하지 않음).
4. **'다시 계산 중'의 자리(관찰, 낮음)**. d5는 [다시 계산] 자리에 글이 나온다고 적는데, 실제로는 버튼이 비활성으로 남고 글은 그 아래 role=status에 나온다.
   - **고침과 다시 누름**: 계산 중에는 버튼이 사라지고 그 자리에 진행 글과 [계산 취소]가 나오는 것을 세 폭에서 봤다. 그 때문에 Enter로 시작하면 포커스가 body로 가지만, 다음 Tab이 [계산 취소]로 이어져 키보드 조작은 막히지 않는다.
5. **Worker 안에는 페이지 CSP가 닿지 않는다(관찰)**. Worker 스크립트 응답에 CSP 머리가 없어, Worker 안의 `fetch`는 페이지의 connect-src로 막히지 않는다. 그래서 '위반 0'은 `worker-src 'self'`로 Worker가 뜬다는 증거이고, Worker의 파일 요청이 connect-src 안에 있다는 증거는 아니다. 주소가 connect-src의 queue-files와 같은 것은 따로 봤다.
   - **고침과 다시 누름**: Worker가 파일을 직접 받지 않고 화면 쪽 `fetch`로 받아 넘긴다. 다시 눌러 파일 요청이 모두 화면 쪽 호출인 것(4,691 / 4,691), 일치 경로가 끝나는 것, CSP 위반 0을 봤다. Worker 스크립트 응답에 CSP 머리가 없는 것은 그대로지만 Worker는 이제 파일 요청을 하지 않는다. Worker 안의 다른 요청을 막는 시험은 하지 않았다.
6. **입력칸에서 Enter는 계산을 시작하지 않는다(관찰)**. 폼이 제출을 막아 아무 일도 없다. Tab으로 버튼에 가면 된다. 정본에 정해진 동작은 없다.
7. **모든 시나리오 공통 요청 오류**: `GET https://api.peaket.example/v1/identity/me` 503(`stubFanApi`와 같은 대역, 일부러 만든 것). 공연 상세로 간 시나리오는 같은 대역의 `subscriptions`·`wishes`·`review-summary` 503. 콘솔의 'Failed to load resource' 줄은 모두 이것과 표에 적은 기대한 404·500·503·연결 실패에서 나왔다. 합성 회차와 `evt-lumen-1025`에서는 돌아가기 링크 미리 받기가 404다(`/events/{id}?_rsc=…`, 가짜 API에 없는 회차). 다시 누를 때는 파일 없음 화면에도 돌아가기 링크가 생겨 같은 404가 그 화면에서도 나오고, 취소·입력 바꾸기 때 진행 중이던 파일 요청이 `net::ERR_ABORTED`로 끊긴다(취소 신호로 끊은 것).
8. **다루지 않은 것**:
   - Claude in Chrome으로 다시 누르기(위 '브라우저' 줄).
   - 실제 queue-svc·admission-ctrl·S3와 CDN을 거치는 길. 응답 모양은 대역과 가짜 API다. 결과 파일의 값만 규격대로 실제로 맞다.
   - Firefox·WebKit(엔진 차이는 E2E 몫). Worker를 만들 수 없는 브라우저의 화면 쪽 대체 길은 돌지 않았다.
   - 복사 버튼 누르기, '내 앞자리 결과 파일 내려받기' 누르기(주소만 봄).
   - 100만 명 규모의 다시 계산(2만 명까지 약 5초). 받을 크기 글만 봤다.
   - BLS 서명 검증(OPEN[27], 화면도 안 한다고 적음).
9. 검사 대본은 저장소 밖 세션 scratchpad의 `stack/check-h50.mjs`(서버는 `stack/h50-servers.mjs`, 첫 번째 누름의 대본은 `stack/check-h50-1차.mjs`)다. 정본 문구는 대본에 옮겨 적지 않았다. 캡처는 저장소에 넣지 않았다.
