## 실패와 확인 못 함
- Claude in Chrome: 연결이 없어 누르지 못했다. 다음 연결 턴에 홈·설정·로그인 세 화면을 다시 연다.
- 처음 만든 `proxy.ts`는 캐시 화면 요청의 손님 CSP 머리를 지우지 않아, 손님이 고른 nonce가 캐시 화면 HTML에 들어갔다. 재현 시험(고치기 전 빌드에서 실패)을 먼저 쓰고 고쳤다.
- 새 맥락 리뷰가 찾은 것: 처음 앞 서버는 모든 인라인 스크립트를 해시해 끼워 넣은 스크립트도 허용 목록에 넣었고, GET이 아닌 HTML에는 CSP를 달지 않았다. Next.js·React 모양(설치된 실행 파일과 같은 도우미 정의)만 해시하고 메서드와 상관없이 HTML에 달게 고쳤다(재현 단위 시험). 루트 Suspense는 소프트 404를 만들어 뺐다.
- Playwright WebKit의 응답 가로채기는 한글 본문의 글자를 바꿔, 빌드 때 해시를 가로채 거는 PoC 시험 하나는 WebKit에서 건너뛴다. 실제 응답의 해시는 WebKit에서도 위반 0이다.

## Chrome 다시 확인(2026-11-05)

- 브라우저: Claude in Chrome(Chrome, Windows, 시험용 프로필). 위에서 '다음에 Chrome이 연결된 턴에 다시 누른다'고 한 것을 이 날 눌렀다.
- 환경: 소비자 웹 운영 빌드(2026-11-05 다시 빌드)를 `apps/web/server/start.mjs --port 4101 --inner-port 5101`로, 서버 쪽 원본은 가짜 API.

| 시나리오(근거 ID) | 결과 | 본 것 |
| --- | --- | --- |
| 운영 헤더로 여러 화면 열기(FE-T35, ADR-0193) | 통과 | 홈·공연 상세·검색·설정·로그인·가입·약관이 스타일과 함께 그려진다. 캐시 화면 `/`는 응답 때 해시 CSP, 요청 화면은 nonce CSP. 외부 스크립트 6개에 integrity |
| CSP 집행 | 통과 | 페이지에 끼운 인라인 스크립트가 실행되지 않았다 |
| 위반 수 | 브라우저 시험으로 갈음 | 확장이 CSP 위반을 콘솔로 보이지 않는다. 같은 날 `csp` 설정을 돌렸다: 이 PC Chromium·WebKit 68 통과, Firefox(설치한 정식 판, BiDi) 24 통과·19 건너뜀(다크 흉내 2, 나머지는 Chromium만 도는 시험), 판을 고정한 컨테이너(CI와 같은 이미지)의 세 엔진 93 통과. 팬 API는 시험에서 일시 장애(503)로 답하게 바꿨다(없는 주소로 요청을 내보내지 않는다, `csp/pages.mjs`) |
| 컨테이너에서 찾은 것 | 실패 → 고침 | 컨테이너는 이 PC의 서버를 `http://host.docker.internal`로 연다. 보안 맥락(https·localhost)이 아니라 `crypto.subtle`이 없어, 공연 상세의 로비 버튼 계산이 던지고 페이지 오류가 났다(세 엔진). HOT-311 기록에 적고 고쳤다 |

- 도구 한계(이 날 확인):
  - 확장은 페이지가 `window.open`으로 연 팝업 창을 다루지 못한다(확장이 맡은 탭 묶음 밖이다). 팝업 길은 Playwright(Chromium)로 같은 서버를 눌렀다.
  - 확장의 콘솔 읽기는 CSP 위반을 보이지 않는다(페이지에 끼운 인라인 스크립트가 막혔는데 메시지가 없었다). 위반 수는 브라우저 시험이 센다.
  - 확장의 요청 목록은 가짜 API의 204 응답(토큰 갱신)을 503으로 보였다. 가짜 API 쪽 기록은 204였다.
  - `resize_window`는 최대화된 창을 줄이지 못했다. 화면 크기별 모양은 Playwright 기록을 그대로 둔다.
