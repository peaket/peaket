# 브라우저 확인: BOT-055 숨긴 링크와 좌석 화면 행동 요약(SCR-002·SCR-007·SCR-010)

- 날짜: 2026-11-09
- 커밋: 가지 `feature/3.2.1-bot055-signals`의 커밋 전 작업 트리(바탕 f7d7b9a8)
- 브라우저: **Claude in Chrome: 쓰지 않음(연결된 Chrome이 시험용 프로필인지 확인할 수 없음) → Playwright로 대신**. Playwright 1.64.1, Chromium 156.0.8078.4 headless shell로 실제 클릭과 키보드 입력을 했다. CSP(허용 출처 규칙)는 끄지 않았다.
- 환경: 운영 빌드(`node seed-css/build.mjs web`, `PEAKET_BUILDS=prod`), 웹 서버 4101, 가짜 API(`apps/web/scripts/mock-api.mjs`) 4310. 허니팟(사람 눈에 보이지 않게 숨긴 링크로, 그 링크를 부른 세션에 표시를 남기는 장치)의 경로는 합성 값 `/_t/synthetic-check-path`를 웹 서버 환경 값으로 줬고, '값 없음' 장면은 그 값 없이 서버를 다시 띄웠다. 대기실은 같은 합성 값을 `VITE_PEAKET_HONEYPOT_PATH`로 넣어 저장소 밖 폴더에 빌드하고 `tools/web-checks/lib/same-origin.mjs`의 틀로 4131에서 냈다.

- 좌석 화면 진입: 대기실을 지나지 않고, 가짜 API와 같은 모양의 입장 저장값을 탭 저장소에 넣어 열었다. 좌석은 지도를 확대한 뒤 마우스로 실제로 눌렀다.
- 범위: docs/features/bot-defense.md §4.8·§7, B-T8·B-T17·Q-T40의 화면 몫, ADR-0249 결정 3·7, d5 SCR-002·SCR-007·SCR-010. 대조(`node tools/ci/trace-check.mjs`)는 이 확인에서 돌리지 않았다.
- 판정은 글이 아닌 것(개수, 계산된 스타일, Tab 순회, 접근성 트리, 요청 본문, CSP)을 대본이 숫자로 봤고, 화면 모습은 캡처를 사람이 봤다. 캡처는 저장소에 넣지 않았다.

## 실패와 확인 못 함

이 단계의 실패는 없다. 제품 코드는 고치지 않았다.

### 이 단계 밖에서 본 것

1. **좌석 화면을 열 때마다 CSP 위반 이벤트 1건(`script-src eval`, 새로 적음).** 콘솔에는 찍히지 않고 `securitypolicyviolation` 이벤트로만 보인다. 화면 동작은 막히지 않는다.
   - 재현: ① 운영 빌드를 띄운다. ② 탭 저장소 `peaket.admission.{회차}`에 입장 저장값을 넣는다. ③ 문서 시작 전에 `document.addEventListener('securitypolicyviolation', …)`를 건다. ④ `/booking/{회차}/seats`를 연다. ⑤ `script-src eval enforce …/_next/static/chunks/2d25s9vksynd1.js:1:25005`가 1건 잡힌다.
   - 원인: 그 묶음의 zod 4가 평가 가능 여부를 `try { Function("") }`로 시험한다(`jitless` 설정이 없음). 이번 단계의 추적기 묶음에는 `pointerEntropy`가 있고 이 묶음에는 없다. 이번 단계가 고치지 않은 패키지(`packages/seatmap`·`packages/api-client`)에서 오는 것으로 보이지만, 바탕 커밋을 빌드해 견주지는 않았다.
   - 운영에서 이 위반이 CSP 보고(`/_t/csp`)로 나가 보고를 부풀리는지는 로컬에서 보지 못했다.
2. **공연 상세마다 콘솔에 frame-src 알림 1건.** `frame-src`에 `'none'`과 다른 출처가 함께 있다는 알림이다. 사람 확인 묶음이 값을 더하면서 생긴다. `docs/review/browser-check/BOT-047.md`에 이미 적혀 있고, 이번 단계는 `packages/config`를 고치지 않았다.

### 다루지 않음

- 사전 검증 응답의 최초 방문 쿠키: 엣지 함수 몫이라 로컬에서 보지 못한다(ADR-0249 결정 1, HOT-012).

### 확인 못 함

- 허니팟 적중의 뒤쪽(게이트웨이 연결, 204, `tr:hp:{pid}`, B-T8 ①~⑤): 로컬에 gw-fan이 없어 그 경로가 404다. 브라우저에서는 링크와 나가는 머리까지만 봤고, 처리기는 trust-svc 시험이 본다.
- 행동 요약의 서버 쪽(`bs` 칸 `HSETNX`, `BehaviorSignal` 발행, B-T19): 가짜 API라 보지 못했다. purchase-svc 시험이 본다.
- B-T17 여정 ID: 입장 토큰과 서버가 다루는 값이고 화면이 보내는 칸이 아니라 브라우저에서 볼 것이 없다.
- 대기실의 값 없음 빌드: 따로 빌드하지 않았다. `apps/web/queue-room/test/hidden-link.test.mjs`가 본다.
- 로비 참가에 성공한 뒤의 로비 화면: 사람 확인 스크립트(외부 주소)를 막아 참가 전 안내 상태에서만 봤다. 숨긴 링크는 상태 분기 앞에서 붙는다.
- 좌석 화면의 '목록으로 보기'로 고른 경로와 자동 배정 공연의 홀드: 누르지 않았다. 이번에 본 것은 지도에서 마우스로 고른 경로다.
- `page.accessibility.snapshot()`: 이 Playwright에 없어 CDP 전체 접근성 트리와 ARIA 스냅샷으로 대신했다.
- Firefox·WebKit: 돌리지 않았다(Chromium만).
