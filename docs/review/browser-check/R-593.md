## SCR-030 관제 명령

- `/commands?role=commander`: 명령 3건(판매 중지 승인 대기, 규모 변경 실패, 판매 재개 성공), SSE 상태 `실시간`, 상세 `params`를 확인했다.
- **승인**: 판매 중지 `SALE_STOP` 승인 대기 명령에서 `승인`을 눌러 상태가 `성공`, 시도 1회, 승인자 `admin-9`, `result { applied: true }`가 보이는 것을 확인했다.
- **감사 체크포인트**: 탭에서 1건(구간 1–10, 사유 `판매 중지 감사`)을 보고 `검증`을 눌러 `검증 통과`를 확인했다.
- 콘솔 오류는 없었다(콘솔 오류 0, 페이지 오류 0).

## SCR-048 판매 중지

- `/sale-reviews/prd-lumen-2026?role=commander&state=...`에서 디자인 보드의 판매 중지 상태 셋을 확인했다.
- **판매 중지 요청**: 사유 코드(필수)·사유(필수), `요청한 분이 아닌 commander가 승인 업무에서 승인하면 공개와 새 판매가 멈춥니다. 승인 전까지 공개와 판매는 계속됩니다`를 확인했다.
- **판매 중지 승인 대기**: 요청 시각·요청자·사유, `승인 업무에서 보기`, 급하면 명령 3으로 판매만 먼저 멈추라는 안내를 확인했다.
- **판매 중지됨**: `공개와 검색에서 빠졌고 새 판매가 막혔습니다. 이미 판매한 티켓은 유효하고, 정산 지급은 보류됩니다`, 회차별 판매 중지, `정산 지급 보류 2건`을 확인했다.
- 이 화면은 `상태 · 개발용` 전환기가 있는 **디자인 보드 미리보기**다. 실제 `POST /v1/ops/sale-reviews/{productionId}/...`·core-svc `RecordSaleReviewResult`·payment-svc `SALE_SUSPENDED` 정산 보류에 연결되지 않았다.

## 실제 API 확인 범위

- 브라우저는 **가짜 ops API**만 불렀다. 실제 관리자 쿠키·identity 경로를 브라우저에서 열지 않았다.
- R-593의 `SetBookingRestriction` 수신은 queue-svc·purchase-svc test-int가 실제 Valkey 8.1·gRPC로 확인했다(판 번호 가드·옛 판 무시·`q:rst`/`s:rst`·`until` 제거·INVALID_ARGUMENT).
- ops-svc 앵커 경계는 test-int가 설정 없음 503 `anchor-unavailable`·가짜 저장소 참조/검증을 확인했다.
- SCR-048의 실제 판매 중지 집행(core 비공개·검색·홈·오픈 예약 멈춤, payment 정산 보류)은 아직 구현되지 않아 막힌 것으로 기록한다.
