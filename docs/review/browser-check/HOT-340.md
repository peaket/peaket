# 브라우저 확인: HOT-340 ① 대기실 오픈 뒤 경로 데이터 잇기

- 날짜: 2026-11-05
- 커밋: 이 기록과 같은 커밋(HOT-340 ①)
- 브라우저: Claude in Chrome(Chrome, Windows, 시험용 프로필)
- 환경
  - 계약 모양 가짜 API(127.0.0.1:4010)에 대기열 경로를 더했다: 진입, 묶음 결과 파일, 대기 상태 파일, 입장 확정, 대기 취소. 상태는 `/__mock/state`의 `queue`·`queueEntry`·`queueAdmit`·`queueAhead`·`queueRate`·`queueBanner`·`queueSeats`·`queueReset`로 바꾼다.
  - 대기실 개발 서버(`pnpm --filter @peaket/queue-room dev`, localhost:3004)
  - 사전 검증 토큰은 공연 상세가 쓰는 단계(HOT-342) 전이라, 대기실 출처의 localStorage `peaket.queue.{eventId}`에 손으로 두고 열었다.
  - 회차는 가짜 API 고정 자료의 뮤지컬 별빛 정원(`0b8f1f2e-…4e04`)이다.
- 범위: SCR-008(d5 §5.8), SCR-018(d5 §5.18), docs/frontend.md §3.4·§3.12·§5.1, ADR-0207

## 브라우저 시험으로 본 것

- 상태 기계(`test/controller.test.mjs`, SCR-008, 가짜 시계): 토큰 없음 → 공연 상세, 진입 201·202·429·503·409 두 가지·410 두 가지·403·404·409 `queue-not-open`, 다시 열었을 때 batching·waiting부터, 판매 상태, 연속 실패 3회 → 연결 확인 중, 숨긴 탭은 입장 확정을 보내지 않고 보이면 곧바로 보냄, `NOT_YET`이면 그 시각 전에 다시 보내지 않음, `SOON` 뒤 `ADMITTED`, `VERIFYING`·403 세 가지·409·410 네 가지, 401 갱신, 대기 취소, 다시 줄 서기.
- 시각 회귀(FE-T40, 판을 고정한 컨테이너 Chromium·WebKit): 대기열 호출을 가로채 waiting·soon·paused·stale을 실제 상태 기계로 만든다. 처음에는 waiting·paused·stale이 퍼블리싱 기준 이미지와 같았고 '곧 입장'만 계약 범위(1~5초) 밖의 12초를 5초로 바꿨다. 새 맥락 리뷰 뒤 동작하지 않는 [차례 알림 받기]와 계정 메뉴(로그아웃)를 데이터 연결 화면에서 숨겨(HOT-341) 네 상태 16장을 다시 찍었다.

## 새 맥락 리뷰 뒤 다시 본 것

- 고친 뒤 Chrome에서: 계정 메뉴·[차례 알림 받기]가 보이지 않고, 대기 → 곧 입장 → 입장 확정 → 좌석 화면까지 이어진다.
- 상태 기계 시험에 더한 재현: 공개키 없는 ADMITTED, 401 뒤 갱신 일시 장애, 실패 뒤 전체 지터, 서버 하한을 탭 전환이 깨지 않음, '곧 입장' 깜박임 없음, 진입 401·400·415, 대기 취소 실패 뒤 이어 감, 입장 뒤 [뒤로], 410 저장소 정리.

## 확인 못 함

- 연결 끊김(offline): 확장으로 네트워크를 끊을 수 없다. 상태 기계 시험이 `online()` 거짓을 본다.
- 여러 탭·차례 도래 유예·로비 경로: HOT-341.
- 좌석 화면이 입장 토큰을 읽는 것: 개발에서는 대기실(3004)과 좌석 화면(3000)의 출처가 달라 sessionStorage를 나누지 않는다(운영은 같은 www 출처). 좌석 화면 단계가 본다.
