## 실패와 확인 못 함

- **찾아서 고친 것**: SCR-034 상태 띠의 `대기 1` 링크가 `?live=1`을 잃고 `/sync`로 가 SCR-035가 퍼블리싱 값(`업로드 대기 12건`, `#48291`)을 보였다. SCR-035의 `[스캔 화면으로 돌아가기]`도 `/scan`으로 가 실제 연결 판정 화면을 잃었다. 고치기 전 임시 대본에서 `/sync`·`12건`을 확인했고, `61dee4f79`에 재현 시험을, `7bdab70b5`에 화면 이동 고침을 넣었다. 고친 뒤 `/sync?live=1`(대기 1건)·`/scan?live=1`(이미 입장)로 이어졌고, 같은 시험이 통과한다.
- **확인 못 함(까닭)**:
  - 관제 SCR-053 기기 둘 등록·파트너 SCR-037 같은 구역 입장/퇴장 배치·SCR-051 승인: 이 무대에 세 화면과 ops-svc·partner·identity-svc가 없다. 대본의 서버 응답만 스캐너 API 대역으로 만들었다.
  - 실제 휴대폰 월렛의 15초 회전 QR과 실제 카메라 프레임: 실기·카메라가 없어 QR v1을 시험이 서명하고 `BarcodeDetector`·`getUserMedia`를 대역으로 바꿨다. 실제 카메라의 인식률·초점·노출과 기기 저장소(실기 PWA 설치·비행기 모드)는 확인하지 못했다.
  - 실제 ticket-svc의 `POLICY`·`PLACEMENT` 변경분과 서버 입장 판정: 60초 변경분·퇴장 전환은 `page.route` 응답으로 만들었다. 실제 서버 쪽은 `services/ticket-svc/test-int/scanner-f054.int.test.ts`·`scanner-pass-only.int.test.ts`가 본다.
  - 두 기기의 동시 오프라인 통과 뒤 서버 `중복 입장` 표시(GAT-160): 서버 통합 시험 몫이라 이 화면 확인에서 판정하지 않았다.
- **남은 위험(이번에 고치지 않은 정리 목록)**:
  - IR-09(상태 띠가 실제 값을 다 쓰지 않음): 오프라인인데 띠가 `온라인`으로 남고, 구역은 fixture `동문 구역`, 역할은 fixture 현장 책임자다. 이번 대본의 구역이 `동문`이라 값이 우연히 같았을 뿐, `서문` 배치에서는 띠 구역이 틀릴 수 있다. 판정·큐·입장 상태는 실제 값으로 동작했다.
  - IR-10(변경분 2분 배지)은 이번 대본에서 60초 변경분을 한 번만 돌려 확인하지 않았다. 단위 시험 `scan-live.test.ts`가 경계를 본다.
  - 앱 결함으로 400이 나는 묶음은 최대 간격으로만 미뤄진다(계획 §9 그대로). 1단계 거부는 서버 거부율에 없다(F-05-10 텔레메트리 전까지).
