# 브라우저 확인: HOT-352 좌석 화면 자산 목록과 좌석 Worker의 캐시 읽기

- 날짜: 2026-11-09
- 커밋: 이 기록과 같은 커밋(HOT-352)
- 브라우저: Claude in Chrome(Chrome, Windows, 시험용 프로필)
- 환경: 계약 모양 가짜 API(127.0.0.1:4010), 소비자 웹 개발 서버(3000)와 대기실 개발 서버(3004)를 같은 출처로 띄웠다. 앞 인원 3명·속도 0.2명/초로 공연 상세 → 대기열 → 좌석 화면을 실제로 지나갔다.
- 범위: SCR-008 미리 받기와 SCR-010 첫 그림, ADR-0216 결정 3·5, docs/frontend.md §5.1·§5.2

| 시나리오(근거 ID) | 결과 | 본 것 | 콘솔·요청 오류 |
| --- | --- | --- | --- |
| 미리 받은 좌석맵 파일을 좌석 Worker가 캐시에서 읽는다(SCR-008, SCR-010) | 통과 | 처음 여는 회차에서 가짜 API 기록의 좌석맵 파일 GET은 입장 확정 전 1번뿐이고, 좌석 화면이 그려진 뒤에도 늘지 않는다. 스냅샷 GET은 입장 뒤 1번 | 없음 |

## 브라우저 밖 시험

- 빌드 결과 목록의 파일이 모두 `.next/static`에 있고, 좌석 경로 HTML이 싣는 JS·CSS의 부분 집합이다(HTML에만 있는 것은 폴리필과 오류 경계 묶음).
- 목록의 모양과 대기실 검사(`preloadAssets`)는 `apps/web/scripts/seat-preload.test.mjs`가 본다.

## 확인 못 함

- 운영 배포의 `/_q/seat-preload.json` 올리기는 배포 단계가 생기면 본다. 개발 서버에는 이 파일이 없어 대기실이 건너뛴다.
