# 브라우저 확인: BOT-044 팬의 로그인한 기기와 다른 세션 끝내기

- 날짜: 2026-11-05
- 커밋: 이 기록과 같은 커밋(BOT-044). 누를 때는 가지 `feature/3.1.3-fan-devices`의 커밋 전 작업 트리(바탕 4e066039)였다.
- 브라우저: **Claude in Chrome: 연결은 있었으나 시험용 프로필인지 확인하지 못해 쓰지 않음 → Playwright로 대신**. Playwright(1.58.2, Chromium 156 headless shell)로 실제 클릭을 해 눌렀다. 다음에 시험용 프로필이 확인된 턴에 다시 누른다. 지금 빌드의 CSP `form-action 'self'`가 로그인·재인증의 제공자 이동을 막아(아래 '실패와 확인 못 함' 2), 표의 시나리오는 브라우저 문맥의 CSP를 끄고(`bypassCSP`) 눌렀다. 막힘은 CSP를 켠 문맥에서 따로 눌러 확인했다(표 맨 아래 줄).
- 환경: BOT-043과 같은 로컬 스택. identity DB에 마이그레이션 0027·0028(세션의 화면용 기기 이름·마지막 활동)까지 적용하고, 지금 작업 트리로 platform·contracts·identity와 웹을 다시 빌드했다. 웹은 `PEAKET_CSP_ORIGINS`의 `api`를 게이트웨이 대역 주소로 두고 띄웠다. 게이트웨이 대역(`apps/web/scripts/local-fan-gateway.mjs`)은 검사 대본 안에서 띄워 시나리오 5에서 끊었다 이었다. 모의 OIDC 제공자는 BOT-040의 감싸개(시나리오마다 sub·이메일을 바꾸는 조종 포트, 저장소 밖)로 띄웠다. 시험 사람은 실행마다 새 합성 sub다. 기기는 브라우저 문맥마다 하나이고, User-Agent를 셋으로 나눴다(Chrome·Windows, Safari·iPhone, 어느 낱말에도 맞지 않는 글).
- 범위: SCR-017 ② 로그인한 기기(docs/design/d5 §5.17), SCR-040 연결·해제·합치기 완료 문구(§5.22), SCR-039 연결 성공(§5.21), SCR-004 세션 종료 안내(§3.5), docs/features/identity.md §8 '로그인한 기기와 다른 세션 끝내기의 첫 구현', I-T74, I-T75.

## 실패와 확인 못 함

1. **이 기기의 다른 로그인(실제 클릭)**: 로그인 화면에서 [제공자 로그인]을 누르면 기기 값이 서버에 가지 않는다.
   - 재현 단계: 새 브라우저 문맥에서 `/login?next=/my/settings` → [카카오 로그인] → 쿠키만 지운다(localStorage `peaket.device`는 남긴다) → 다시 [카카오 로그인] → `/my/settings`.
   - 정본과 다른 점: d5 §5.17 '이 기기의 다른 로그인'(지금 이 기기 줄의 `otherSessions` > 0이면 안내와 버튼), docs/features/identity.md §8의 목록(기기 행으로 묶어 기기마다 한 줄), I-T74 ①⑤. 실제로는 로그인 시작 `POST /login/{provider}`의 `deviceId`가 늘 빈 값이라 세션에 기기 행이 없다. 같은 브라우저로 다시 로그인한 세션이 다른 기기처럼 따로 한 줄로 보이고, [이 기기의 다른 로그인 끝내기]는 나오지 않는다.
   - 원인 짐작(확인은 재현 시험으로): 로그인 화면의 폼 `onSubmit`이 진행 중 표시(`apps/web/src/_pages/login/ui/LoginProviders.tsx`의 `setPressed`, 140d11cb HOT-321)를 그리며 다시 그린다. 그때 `DeviceIdInput`의 숨은 칸(`defaultValue=""`, 값은 효과에서 `.value`로 채움)이 빈 값으로 돌아가는 것으로 보인다. 숨은 칸은 `value`가 기본값 속성과 같다. submit 이벤트 없이 보내면 값이 실리고 기기 행이 생긴다(위 '대역 제출' 줄). 연결 제안 화면(SCR-039)의 숨은 폼 로그인도 기기 행이 생겼다. 이 DB에서 마지막으로 생긴 기기 행은 2026-11-04 23:25(KST, BOT-043 확인)다.
   - 영향 [짐작, 확인 안 함]: 기기 행으로 묶는 다른 규칙(기기 5대 한도의 셈, 새 기기 알림)도 로그인 화면으로 들어온 세션은 기기 행 없이 돈다.
   - 이 단계의 코드(BOT-044)가 아니라 로그인 화면 쪽 회귀로 보인다. 고치지 않았다. 재현 시험은 단위 단계에 쓸 수 있다(로그인 폼을 다시 그린 뒤 숨은 칸의 값).
2. **CSP `form-action 'self'`가 소셜 제공자 이동을 막는다(이 단계 밖)**.
   - 재현 단계: 지금 빌드의 웹을 CSP를 켠 채 Chromium으로 연다. `/login`에서 [카카오 로그인]을 누른다. 또는 로그인한 상태로 `/my/settings`에서 다른 기기 [로그아웃] → [카카오로 다시 로그인하고 계속]을 누른다.
   - 본 것: 콘솔에 "Sending form data to '…/login/kakao'(또는 '/reauth/kakao') violates … form-action 'self'"가 뜨고 제공자로 가지 않는다. 앱 서버의 303(제공자 인가 주소)이 막히는 것이다.
   - 정본과 다른 점: docs/frontend.md §5.14.1은 로그인 화면과 재인증을 시작하는 화면의 form-action에 세 소셜 제공자 인가 출처를 더한다고 적는다. 그런데 `packages/config/headers/security-headers.mjs`·`apps/web/src/_app/security/page-headers.ts`에는 그 출처를 넣는 자리가 없다. 그래서 `/login`·`/login/link`·`/my/settings`·`/my/settings/providers`가 `form-action 'self'`뿐이다(정본 주석은 '연동 때 확정'). `/login/link`는 경로 표만 봤고 누르지 않았다.
   - 영향: 이 단계의 원격 로그아웃, 이 기기의 다른 로그인 끝내기, 로그인 수단 추가·해제는 모두 이 재인증을 지난다. 그래서 실제 브라우저에서는 끝까지 가지 않는다. 원격 로그아웃은 버튼이 처리 중에 멈추고 안내가 없다.
   - 원인은 소비자 웹 CSP(3d28b92d)다. BOT-043 확인(2026-11-04)은 그 전이었다. 고치지 않았다.
3. **모든 시나리오 공통 요청 오류**:
   - 셸이 화면마다 부르는 `GET /v1/identity/me`가 404다. identity-svc에 아직 그 경로가 없다(BUILD_ORDER BOT-047). 콘솔의 'Failed to load resource' 줄은 모두 이 404와 위의 기대한 401·404·502·연결 거부에서 나왔다. 잡히지 않은 예외(pageerror)는 없었다.
   - 204·202 응답(토큰 갱신, 원격 로그아웃 `DELETE`, 로그인 수단 해제, 합치기 확정)은 Playwright가 응답을 받은 뒤 `requestfailed net::ERR_ABORTED`로도 알린다. 따로 줄을 찍어 응답 204가 먼저 온 것을 확인했고, 화면은 성공으로 이어졌다(본문 없는 응답의 도구 표시다). 401 뒤 로그인 화면으로 옮길 때 끊긴 요청도 같은 표시다.
4. **다루지 않은 것**:
   - 화면에서 누르지 않은 것: 원격 로그아웃 5xx의 '지금은 로그아웃할 수 없습니다…' 토스트, 재인증 만료·이미 쓴 토큰(403)의 재인증 창 문구, 그사이 끝낼 것이 없어진 '끝낼 다른 로그인이 없습니다'(404 `others`). 흐름 시험(`apps/web/src/features/device-sessions/flow.test.mjs`의 I-T74 결과 문구·403·404 분류)이 본다.
   - 현장 스캐너 세션 줄과 그 안내는 이 API에 없다(BUILD_ORDER GAT-230).
   - 게이트웨이가 끝난 세션의 액세스 토큰을 수 초 안에 거부하는 것은 HOT-400이다. 이 확인에서는 identity 경로(목록 401·갱신 401)로만 봤다.
5. 캡처: 남기지 않았다. 값은 페이지 글, 요청 본문, DB(세션·Outbox `control.sessions-terminated`의 reason)로 읽었다. 검사 대본은 저장소 밖(세션 scratchpad의 `stack/check-b44.mjs`, CSP 확인은 `stack/check-b44-csp.mjs`)이다.
