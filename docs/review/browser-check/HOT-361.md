# 브라우저 확인: HOT-361 구매 세션 401의 갈래

- 날짜: 2026-11-09
- 커밋: 이 기록과 같은 커밋(HOT-361)
- 브라우저: Claude in Chrome(Chrome, Windows, 시험용 프로필)
- 환경: 계약 모양 가짜 API(127.0.0.1:4010, `hold=` 네 상태), 소비자 웹 개발 서버(3000, 이 PC에서 Turbopack의 PostCSS 프로세스가 0xc0000142로 뜨지 못해 webpack으로 띄웠다). 입장 저장값은 JWT 모양 토큰과 가짜 API의 서버 공개키로 탭 저장소에 넣었다
- 범위: SCR-010(d5 §5.10 '구매 세션 끝', docs/frontend.md §5.3 '401')

| 시나리오(근거 ID) | 결과 | 본 것 | 콘솔·요청 오류 | 캡처 |
| --- | --- | --- | --- | --- |
| `purchase-session-ended`(SCR-010) | 통과 | 좌석을 고르고 홀드하면 경고 영역에 '예매 시간이 끝났습니다', 입장 저장값·홀드 저장값 비움, IndexedDB의 그 jti 키 사라짐, 3초 안에 대기실로 옮기고 대기표가 없어 공연 상세로 갔다 | 콘솔 오류 없음 | 없음 |
| `purchase-signature-invalid`(SCR-010) | 통과 | 같은 안내, 입장 저장값 비움, POST 1번 401 | 콘솔 오류 없음 | 없음 |
| `admission-token-invalid`(SCR-010) | 통과 | 같은 안내, 입장 저장값 비움 | 콘솔 오류 없음. 요청 기록은 이동으로 지워져 못 봄 | 없음 |
| `purchase-seq-reused` 두 번(SCR-010) | 통과 | 번호를 건너뛰어 한 번 다시 보내 POST 2번 401, 그 뒤 같은 안내, 입장 저장값 비움 | 콘솔 오류 없음 | 없음 |

## 실패와 확인 못 함

- 화면 캡처: 좌석맵이 뜬 탭에서 Chrome 캡처가 30초 시간 초과로 실패해 글과 저장소 값으로 봤다.
- 복제한 탭의 일련번호 역전 0(FE-T6)은 화면이 아니라 서명기를 세 엔진에서 돌리는 검사(tools/web-checks/purchase)로 봤다. 운영 빌드의 화면은 빌드에 넣은 API 출처를 불러 가짜 API에 닿지 않는다.
