# 브라우저 확인: R-562 웹 예산·CLS 회귀 수정

- 날짜: 2026-11-14
- 커밋: R-562(같은 기록을 남기는 커밋)
- 브라우저: Playwright Chromium(운영 빌드), 뷰포트 412×823
- 환경: `apps/web` 운영 빌드(`pnpm --filter @peaket/web build`) 뒤 `node apps/web/server/start.mjs --port 4101 --inner-port 5101`, 가짜 API 4010
- 범위: SCR-013 `/my/tickets`, FR-012·POL-018, ADR-0025·0051, offline-gate §2·§3, O-T13

| 시나리오(근거 ID) | 결과 | 근거 |
| --- | --- | --- |
| 기기 키 등록(FR-012) | 통과 | '이 휴대폰을 입장용으로 등록'을 누른 뒤 QR과 `기기 키 <11자> · 이 기기에만 등록됨`이 보인다. 이 가지에는 ticket-svc device-keys 서버 경로가 없어 `registration=LOCAL`이다 |
| 15초 회전(O-T13) | 통과 | 16초 뒤 QR 모듈 클래스 배열이 달라졌다(회전 true) |

| 콘솔·페이지 오류 | 없음 | 페이지 오류 0. 오프라인 API 실패만 있다 |

## 확인 중에 찾아 고친 것

- 동적 QR 조각이 서비스 워커 제어 전에 받아지면 첫 방문 뒤 오프라인에서 빠질 수 있었다. 워커 등록 뒤 이 화면이 받은 스크립트를 `CACHE_URLS`로 보내 캐시하게 고쳤다.
- QR 로딩 카드가 짧았다가 등록 안내 카드로 커지며 CLS가 났다. 첫 HTML에 같은 높이(400px)의 등록 안내를 그리고, `DeviceQr`의 모든 상태를 400px로 맞췄다.
- 오프라인 배너가 늦게 나타나며 QR을 밀었다. 배너 자리를 40px로 늘 잡고 한 줄로 잘랐다.

## 남는 것

- 이 가지는 BAT-430 이전이라 서버 공개키 등록은 `LOCAL`이다. 서버 등록·폐기는 BAT-430(R-561) 가지에서 이어진다.
- `navigator.onLine`은 서버를 끈 상태에서도 true일 수 있어 배너는 실제 네트워크 절단에서 확인했다.
