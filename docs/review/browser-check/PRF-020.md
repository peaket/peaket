# 브라우저 확인: PRF-020 소셜 로그인(얇은 OIDC 클라이언트)과 팬 재인증

- 날짜: 2026-11-03
- 커밋: 이 기록과 같은 커밋(PRF-020)
- 브라우저: **Claude in Chrome 못 함(연결 없음)**. `list_connected_browsers`가 빈 목록이었다. BSL-070처럼 Claude 데스크톱 앱의 내장 브라우저(Chromium)로 대신 눌렀다. 창이 가려져 그림을 그리지 않을 때 좌표 클릭이 시간 초과로 실패해, 네이버·구글 버튼은 같은 버튼을 페이지 스크립트로 눌렀다(`button.click()`, 폼 제출은 같다). 다음에 Chrome이 연결된 턴에 같은 시나리오를 다시 누른다(PROGRESS 턴 규칙).
- 환경: 로컬 실행(병렬 세션 전용 이름·포트). identity DB PostgreSQL 18 컨테이너(`lane2-idpg`), identity-svc(`dist/main.js`, 업무 gRPC 18951), 모의 OIDC 제공자(`apps/web/scripts/mock-oidc.mjs`, 18900), 소비자 웹(`next build` 뒤 `next start`, `http://localhost:18300`, `PEAKET_ENV=local`). 팬 토큰 키와 앱 서버 비밀은 실행마다 새로 만들었다. 실행 방법은 apps/README.md '소셜 로그인을 로컬에서 돌려 보기'.
- 범위: SCR-004 로그인 버튼(docs/design/d5 §5.4), docs/features/identity.md §2 '웹 앱 서버 경로와 첫 구현 범위'·§3·§7.1 '재인증 흐름과 토큰', FR-001, I-T71, I-T72, I-T54 ①.

- 다루지 않은 것: 실패 쪽(바꾼 state·nonce·issuer, 오래된 `auth_time`, 계정 불일치, 다른 출처)은 모의 제공자의 동작을 바꿔야 해서 자동 시험(`apps/web/src/features/social-login/server/login-routes.test.mjs`)이 본다. 이 확인에서는 누르지 않았다.
- 캡처: 창이 가려져 화면 캡처가 시간 초과로 실패해 남기지 못했다. 값은 페이지의 DOM·응답 본문, identity DB, 지표로 읽었다.
- 사람 확인이 필요한 것은 없다(로그인 버튼의 모양은 바뀌지 않았다).
- 새 맥락 리뷰 뒤 다시 본 것(같은 날): 리뷰가 찾은 것(돌아갈 주소 `safeNext()` 규칙, 액세스 토큰 쿠키 수명, 고위험 재인증 목적, 재인증 실패 경로, `Origin: null`, 봉인 쿠키 키 ID, 동시 로그인 잠금, 연결 오류 상태 코드)을 재현 시험부터 고친 뒤, 화면 모양은 바뀌지 않아 브라우저를 다시 열지 않고 같은 로컬 스택(웹은 127.0.0.1에만 열었다)에 쿠키 모음 스크립트로 끝까지 보냈다: 카카오 첫 로그인 → `/signup/consent?next=%2Fmy%2Ftickets`, 쿠키 둘(액세스 쿠키 `Max-Age` 1209599초 = 리프레시와 같음), 재인증 결과 `FAN_SENSITIVE`·고위험 확인됨 `FAN_HIGH_RISK`, `Origin: null` + `Sec-Fetch-Site: same-origin` 로그아웃 303과 identity 세션 종료.
