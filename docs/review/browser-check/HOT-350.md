# 브라우저 확인: HOT-350 ① 좌석 화면 실제 좌석맵 엔진

- 날짜: 2026-11-09
- 커밋: 이 기록과 같은 커밋(HOT-350 ①)
- 브라우저: Claude in Chrome(Chrome, Windows, 시험용 프로필)
- 환경: 계약 모양 가짜 API(127.0.0.1:4010, 좌석맵 판 2·3과 이진 스냅샷), 소비자 웹 개발 서버(3000)와 운영 빌드(4101). 입장 저장값은 JWT 모양 토큰과 가짜 API의 서버 공개키로 탭 저장소에 넣었다.
- 범위: SCR-010 지도(ADR-0224), docs/frontend.md §4.2.2·§4.4.2·§5.2

| 시나리오(근거 ID) | 결과 | 본 것 | 콘솔·요청 오류 |
| --- | --- | --- | --- |
| 첫 그림(SCR-010) | 통과 | 무대와 구역 여섯, 구역 글자는 회차 가격표 이름(요약이 오면 고친다), 가장 비싼 구역이 가장 진한 색, '구역을 확대하면…' 안내, 머리에 공연명·회차·공연장 | 없음(라우트 경고는 `instant = false`로 없앴다) |
| 구역 누르기·[+]·[−]·[전체 보기](SCR-010) | 통과 | 구역을 누르면 그 구역으로 확대되고 좌석·미니맵과 좌석 범례가 보인다. 전체 보기 상태에서 [−]·[전체 보기]는 막힌다 | 없음 |
| 좌석 고르기(SCR-010) | 통과 | 좌석을 누르면 '내 선택' 체크로 바뀐다 | 없음 |
| 끌기·휠(SCR-010) | 통과 | 끌면 지도가 옮겨지고 고른 좌석이 그대로다. 휠로 축소된다 | 없음 |
| 스냅샷의 판이 다름(§4.4.2) | 통과 | `seatSnapshot=newer`에서 첫 그림이 그려진다. 다시 받는 흐름은 엔진 시험이 본다 | 없음 |
| 스냅샷 503(SCR-010, §4.4.2) | 통과 | `Retry-After`를 지켜 스스로 세 번 더 받은 뒤(가짜 API 기록 GET 4번) '좌석맵을 불러오지 못했습니다'와 [다시 시도], 눌러서 지도가 다시 그려진다 | 없음 |
| 이름 없는 401(§4.1) | 통과 | 토큰을 한 번 갱신하고(`POST …/access-tokens` 1번) 스냅샷을 한 번 더 받은 뒤(GET 2번) 예매 시간 끝으로 대기실로 옮긴다 | 없음 |
| 오른쪽 클릭(SCR-010) | 통과 | 좌석이 골라지지 않는다 | 없음 |
| 스냅샷 401(SCR-010, §5.3) | 통과 | '예매 시간이 끝났습니다' 뒤 입장 저장값을 지우고 대기실로 옮긴다. 대기실이 좌석 화면으로 되돌려 보내지 않는다 | 없음 |
| 운영 빌드 CSP(worker-src 'self') | 통과 | 4101의 좌석 화면에서 Worker 스크립트를 받고 스냅샷 요청이 나간다. CSP 위반 콘솔 없음. 좌석맵 파일은 운영에서 CDN 정적 파일이라 이 서버에는 없어 [다시 시도]로 끝났다 | 없음 |

## 확인 못 함

- 실제 서버의 입장 확정 응답에는 아직 좌석맵 경로가 없다(HOT-351).
- 핀치는 터치 기기가 없어 몸짓 판별기의 단위 시험으로 본다.
