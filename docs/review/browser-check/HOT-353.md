# 브라우저 확인: HOT-353 좌석 고르기와 홀드

- 날짜: 2026-11-09
- 커밋: 이 기록과 같은 커밋(HOT-353)
- 브라우저: Claude in Chrome(Chrome, Windows, 시험용 프로필)
- 환경: 계약 모양 가짜 API(127.0.0.1:4010, 서명을 실제로 확인한다), 소비자 웹 개발 서버(3000). 입장 저장값은 JWT 모양 토큰과 가짜 API의 서버 공개키로 탭 저장소에 넣었다.
- 범위: SCR-010(d5 §5.10, docs/frontend.md §3.6·§4.2.2), ADR-0225

| 시나리오(근거 ID) | 결과 | 본 것 | 콘솔·요청 오류 |
| --- | --- | --- | --- |
| 좌석 고르기(SCR-010) | 통과 | 좌석 둘을 고르면 체크로 바뀌고 아래 띠에 'B구역 7열 11번, B구역 7열 12번', 금액, '남은 한도'가 보인다. 고를 수 없는 배율에서는 고르지 않는다 | 없음 |
| 서명한 홀드(SCR-010, §5.3) | 통과 | [좌석 홀드하기] → 가짜 API가 브라우저 서명기의 MAC·일련번호를 확인하고 201. 머리에 '홀드 6:57', 띠에 '2매 홀드'와 [결제하기], 탭 저장소에 `peaket.hold.{eventId}` | 없음 |
| 경합 패배 409(SCR-010) | 통과 | '이 좌석은 방금 다른 분이 선택했습니다. 가까운 좌석: A-5-5, A-5-6', 고른 좌석과 지도 표시가 풀린다 | 없음 |

## 브라우저 밖 시험

- 예매 흐름 기계의 모든 상태·전이(`@xstate/graph`), 한도·일시 정지·판매 종료·세션 끝·만료, 실패 → 이벤트(apps/web/src/_pages/seats/model/booking-machine.test.mjs)
- 서명 검증·모드별 Problem(apps/web/scripts/mock-api.test.mjs)

## 확인 못 함

- 운영 서버의 홀드는 HOT-070까지의 경로만 있다. 자동 배정은 서버 단계(HOT-080) 전이라 화면 흐름을 가짜 API 시험으로만 본다.
