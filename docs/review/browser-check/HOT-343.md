## 브라우저 밖 시험

- `apps/web/queue-room/test/autoassign.test.mjs`: 희망 조건 저장 꼴·기본값·그 회차에 맞지 않는 값 버리기(SCR-008), 탭 제목 카운트다운(5분·60초), 알림은 켠 뒤 한 번(60초·유예), 판매 종료면 희망 조건을 지움, 차례 직전 직접 확인(Q-T25: 예상 도래 시각에 보내고 `NOT_YET`이면 `retryAfterMs` 뒤 지터 없이, 직접 선택 공연·숨긴 탭은 하지 않음).
- 가짜 API(`scripts/mock-api/queue.test.mjs`): `queueSoldOutTiers`가 대기 상태 파일 `soldOutTiers`로 나온다.

## 확인 못 함

- [알림 켜기]: 누르면 브라우저가 알림 권한 창을 띄운다. 권한을 주는 것은 소유자 몫이라 누르지 않았다. 알림음·브라우저 알림·탭 제목은 단위 시험(alertDue·titlePrefix)과 코드 검토로 본다.
- 직접 확인의 `NOT_YET`: 가짜 API는 속도가 정확해 예상 도래 시각이 곧 차례라, 브라우저에서 이른 시도를 보지 못했다(Q-T25 상태 기계 시험이 본다).
- 탭 제목 카운트다운: 확장 탭은 배경이어도 보이는 상태로 잡혀 숨김을 만들 수 없다.

## 새 맥락 리뷰 뒤 고친 것

- 차례 전 직접 확인이 화면을 잠깐 '입장 중'으로 바꾸던 것, `NOT_YET`의 다시 보내기 간격이 1초보다 짧을 수 있던 것, 다시 연 탭이 좌석 배정 방식을 못 받으면 직접 확인을 하지 않던 것, 입장 확정 410 `sale-ended`에서 희망 조건을 지우지 않던 것: 재현 시험(`test/autoassign.test.mjs`)을 먼저 더하고 고쳤다.
- [알림 켜기]: 권한 요청을 오디오보다 먼저 부르고, 묻는 중 상태를 알리며, 초점이 있는 버튼은 `aria-disabled`로 둔다. 다시 연 시트는 마지막 결과를 보인다. 알림을 누르면 그 탭으로 돌아온다. 권한 창 때문에 브라우저에서는 누르지 않았다.
- 시트 저장 뒤 초점: 위 표의 '대기열 [바꾸기] 시트에서 저장'이 다시 본 결과다.
