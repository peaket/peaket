## 실패와 확인 못 함

1. **위젯 흐름이 첫 구독 15초 뒤부터 늘 '받지 못함'이다(FE-T28 ②, ADR-0360 결정 9)**
   - 재현: 메모리 ops-svc + Prometheus HTTP 대역으로 `GET /v1/ops/events/{id}/live?widgets=queue-admission-rate.summary`를 curl로 50초 열면 처음 약 15초는 `ratio` 값 프레임이고, 그 뒤 모든 프레임이 `{"error":"source-unavailable"}`다. 대역 Prometheus에 찍힌 요청은 초당 5건이 정확히 그 시점에 멈춘다(ops-svc가 보내지도 않음). 같은 때 위젯 조회 REST는 값을 준다. 화면에서는 두 원격 위젯이 '받지 못함'으로 바뀌고, 그 뒤 연 두 번째 탭도 같은 (회차, 키) 계산을 나눠 받아 처음부터 '받지 못함'이다.
   - 원인 추정(코드 읽기, 고치지 않음): `services/ops-svc/src/modules/live/application/widget-feed.ts` `subscribe()`가 첫 구독자의 SSE 요청 처리 안에서 `setInterval`(1초 계산 타이머)을 만든다. 타이머 콜백은 그 요청의 요청 문맥(남은 시간)을 물려받고, `packages/platform/src/http-client.ts`는 `requestContext()`의 `deadline.budgetFor(cap)`이 0 이하이면 보내기 전에 `deadlineExceeded`를 던진다. 요청 마감 상한은 `DEFAULT_MAX_DEADLINE_MS = 15_000`이라 15초 뒤 모든 계산이 실패하고 `WidgetFeed`가 `source-unavailable`로 바꾼다. 실제 Prometheus여도 보내기 전에 막히므로 같다.
   - 시험이 놓친 까닭(추정): 통합 시험 `test-int/ops-live.int.test.ts`의 위젯 조립 (나)는 가짜 시계(`fakeClock`)를 써서 남은 시간이 줄지 않는다.
   - 다음: 브라우저 확인 절차대로 고치기 전에 가장 낮은 단계(실제 시계로 15초 넘게 구독하는 단위 또는 통합 시험)에서 실패를 먼저 본다. 고친 뒤 이 줄만 다시 누른다.
2. **'n초 전'이 늘어나는 모습**: 위젯 흐름은 실패 프레임도 1초마다 보내 신선도 표시가 늘 '0초 전'이다. 흐름이 멈춘 상태(무소식)를 만들지 않아 n이 커지는지는 보지 못했다.
3. **`Last-Event-ID`로 다시 받았는지**: 내장 브라우저 도구가 요청 머리를 보여 주지 않아, 다시 붙은 뒤 빠진 명령이 다시 보내기로 왔는지 REST 다시 읽기로 왔는지 가르지 못했다(통합 T1 ①-4가 서버 쪽을 본다).
4. **실제 신원·DB 길**: 시드 운영자 로그인, gw-ops의 JWT → 머리 바꾸기, identity 역할 조회, PostgreSQL 알림 표 트리거 길은 이번에 지나지 않았다(메모리 저장소와 신원 대역). 그 길은 통합 시험(T1·T7·T9, 실제 PostgreSQL 18)이 본다.
5. **파트너 Word 붙여넣기**: 위 표대로 확인 못 함.

## 범위 밖 관찰(판정하지 않음)

- 머리 줄의 사용자 표시('commander · 수진')는 operator 신원 탭에서도 같게 보인다. 셸 고정 자료로 보이며 이 기능 범위(흐름·위젯·헤더) 밖이다.
- `/commands`에서 '접속 운영자' 숫자가 탭마다 달랐다(대시보드에서 넘어온 탭은 2를 그대로, 새로 연 탭은 0). 접속자는 회차별이라 회차 없는 화면의 표시 규칙은 정본을 따로 보지 않았다.

## 정리

- 띄운 서버(ops-svc 4185, 가짜 Prometheus 4184, 콘솔 미리보기 4187·4188, 파트너 4189)와 브라우저 탭을 모두 닫았다. 무대 스크립트·두 번째 빌드는 세션 임시 폴더에만 두었다.
- 이번에 만든 빌드 산출물 `services/ops-svc/dist`·`apps/partner/.next`는 지웠다. `apps/console-host/dist`는 원래 있던 폴더를 `PEAKET_OPS_API_ORIGIN=http://localhost:4187` 빌드로 덮은 채 남아 있다(git 무시 대상).
- Docker를 쓰지 않아 차례 잠금은 잡지도 놓지도 않았다. 캡처는 대화 안 화면 갈무리뿐이고 저장소에 넣지 않았다.
