# 브라우저 확인: BOT-090 추가 검증 큐·이의 제기·추가 검증 화면(SCR-009)·통과자의 입장

- 날짜: 2026-11-10
- 커밋: c6114c28(작업 트리에 아직 커밋하지 않은 BAT-200 고침이 있는 상태로 봤다. 세 서비스와 `packages/contracts`의 빌드 결과는 확인 전에 다시 만들었다)
- 브라우저: Chrome 156(Claude in Chrome, Windows), 시험용 프로필
- 환경: 로컬 실제 스택(저장소 밖 `stack-up.mjs`): 웹 개발 서버 3000, 게이트웨이 대역, queue-svc·trust-svc·identity-svc 실제 프로세스, Valkey 둘·PostgreSQL 컨테이너, 사람 확인 서버 검증 대역(siteverify), 모의 본인확인기관. 시드는 도우미가 실행마다 새로 만든 시험 계정(identity gRPC `CreateSession`)과 첫 본인확인(모의 기관), 회차 설정 `bot090-a1`~`a7`이다. 로그인 쿠키는 도우미가 `Set-Cookie`로 넣어 토큰을 옮겨 적지 않았다. 추가 검증 진입은 실제 사전 검증으로 만들었다(검증 대역이 사전 검증 토큰을 실패로 답함 → trust-svc `CHALLENGE`, 사유 `HUMAN_CHECK` → 대기실 진입 201 `verification: REQUIRED`). CS 인정·기각은 ops-svc 자리에서 queue-svc gRPC `ResolveVerificationAppeal`을 불렀다.
- 범위: SCR-009(d5 §5.9), §5.8 '이의 기각' 행, B-T10 ①③④, B-T11, Q-T34 ②~⑥, I-T56 ①③, ASVS bot-defense·delivery 3.2.2·3.7.2·3.4.3

## 콘솔·요청 오류 모아 보기

- 콘솔 오류: SCR-009·SCR-008에서는 없음. 시드용으로 연 `/policy/privacy`에서 Next.js 개발 전용 진단(`instant-shell-url-data`, `/policy/[slug]`) 두 번. 이 단계와 무관하다.
- 실패한 `/v1/` 요청: `GET /v1/events/{E}` 404(화면을 열 때마다, 합성 회차가 가짜 API에 없음), 일부러 만든 400(금지 글자)·503 넷(trust-svc 끊김)·410(기각 뒤 입장 확정). 그 밖은 없음.

## 실패와 확인 못 함

- 실패: 없음.
- 확인 못 함: 창 기능이 붙은 진짜 팝업 창 안의 조작. 확장이 탭 묶음 밖 창을 다루지 못해 새 탭으로 바꿔 봤다(첫 시도의 팝업은 "본인확인 창에서 진행해 주세요" 대기까지만 봄).
- 확인 못 함: 실제 Turnstile 위젯. 로컬은 위젯 대역(`sim.verify.*` 토큰)이고 캡차는 풀지 않았다.
- 확인 못 함: 강제 CSP. 개발 서버는 보고 모드뿐이라 운영 빌드의 강제 헤더는 CI(FE-T35·FE-T30) 몫이다.
- 확인 못 함: 360 폭을 창 크기로 보기. 창 크기가 바뀌지 않아 iframe으로 대신 봤다.
- 화면 밖이라 보지 않음: B-T10 ①의 건 요청 한 건, ③의 trust-svc `LABELED_HUMAN`, ④의 'trust 라벨 없음'(통합 시험 몫). I-T56 ④(identity-svc 멈춤 503)는 하지 않았다.
- 참고(판정 밖): `frame-src 'none' https://challenges.cloudflare.com`처럼 `'none'`이 다른 출처와 함께 남는다. CSP는 이때 `'none'`을 무시하므로 동작은 같다. 공용 설정 `packages/config/headers/security-headers.mjs`의 사람 확인 더하기 모양이고 `headers.test.mjs`도 이 모양을 기대한다.
- 참고(판정 밖): 기각 뒤 화면에도 집중 셸의 닫기 링크 이름이 '닫고 공연 상세로 가기(대기는 유지됩니다)'로 남는다. 이 대기 참여는 끝났으므로 글이 맞지 않다. d5 §5.9가 정한 글이 아니라 판정하지 않았다.
