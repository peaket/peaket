## 실패와 확인 못 함
- Claude in Chrome: 연결 없음(위).
- 본인확인 기관 창 끝까지(성공·결과 대화상자 여러 가지): 가짜 API에 본인확인 경로가 없다. 기관 창 흐름은 `flow.test.mjs`(I-T45, 이번에 앞일·돌아갈 주소 시험을 더함)와 BOT-010의 모의 기관이 본다.
- 개발 서버 콘솔의 `/signup/consent`·`/verify/return` 'URL data during prerendering' 경고: 페이지 경로 파일에 `instant = false`를 달았다. 하지만 콘솔에 남은 메시지가 그 전 것인지 가르지 못했다(같은 묶음 이름). 운영 빌드에는 영향이 없다.

## Chrome 다시 확인(2026-11-05)

- 브라우저: Claude in Chrome(Chrome, Windows, 시험용 프로필). 위에서 '다음에 Chrome이 연결된 턴에 다시 누른다'고 한 것을 이 날 눌렀다.
- 환경: 계약 모양 가짜 API(127.0.0.1:4010, 본인확인 경로를 더함), 정본 모의 기관(`services/identity-svc/scripts/mock-idv.mjs`, 127.0.0.1:4020), 소비자 웹 개발 서버(`next dev --port 3000`).

- 관찰(정리 목록): 가입 화면 머리는 가입을 마치지 않은 로그인 계정에도 [로그인]을 보인다(퍼블리싱 그대로 `<AppShell guest>`). d5 §5.5는 셸을 '일반(머리만)'으로만 정해, 공연 상세처럼 '계정 메뉴 회원'으로 보일지 정하지 않았다.
- 도구 한계(이 날 확인):
  - 확장은 페이지가 `window.open`으로 연 팝업 창을 다루지 못한다(확장이 맡은 탭 묶음 밖이다). 팝업 길은 Playwright(Chromium)로 같은 서버를 눌렀다.
  - 확장의 콘솔 읽기는 CSP 위반을 보이지 않는다(페이지에 끼운 인라인 스크립트가 막혔는데 메시지가 없었다). 위반 수는 브라우저 시험이 센다.
  - 확장의 요청 목록은 가짜 API의 204 응답(토큰 갱신)을 503으로 보였다. 가짜 API 쪽 기록은 204였다.
  - `resize_window`는 최대화된 창을 줄이지 못했다. 화면 크기별 모양은 Playwright 기록을 그대로 둔다.
