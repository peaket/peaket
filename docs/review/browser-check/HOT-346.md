## 실패와 확인 못 함

- B3 경계: 가짜 API의 `detailSale=presale-now`는 일반 예매 시작을 상태를 정한 순간 + 1시간으로만 준다. '1분 전 고정 자료'가 없어 판매 자격 판정의 경계는 보지 못했다. 같은 다시 고르기 장치는 B5 보탬(오픈 뒤 진입 403의 창 끝)에서 봤다.
- 근거(기록 담당 `l2w7-record`, 2026-11-16): 확인 못 함 1(B3 1분 전 경계)은 단위 시험 RV6(`apps/web/src/_pages/event-detail/model/sale.test.mjs`, `[R040-2][Q-T36 ⑧] 오픈 전 로비 403으로 켠 명단 밖 알림 …`: 오픈 1분 전 로비, 일반 예매 시작 1ms 전 비활성 '대기열 들어가기'와 이유 글, 시작 시각에 새로고침 없이 버튼이 돌아옴)이 덮는다. 같은 다시 고르기 장치는 브라우저에서 B5 보탬으로 봤다.
- B5 '오픈 전 로비 403 뒤 일반 예매 시작까지 머묾': 로비 403으로 켠 창은 오픈 시각이 든 PRESALE 끝(오픈 + 1시간)까지라, 로비가 열려 있는 회차에서는 60분 넘게 머물러야 한다. 이번에는 보지 않았다(RV6이 단위 시험으로 본다).
- 휴대폰 폭: Chrome 창은 폭 538보다 좁아지지 않아 375 폭은 보지 못했다. 538 폭(휴대폰 배치, 아래 고정 띠가 보임)으로 봤다.
- 탭 숨김: 확장 도구는 탭을 실제로 배경으로 보내지 못한다(새 탭을 만들어도 시험 탭이 보이는 상태로 남았다). B8의 숨김·보임은 위처럼 흉내 냈다.

## 관찰(실패 아님, 감독 참고)

- B1 첫 글이 "팬클럽 선예매 선예매 대상입니다"로 '선예매'가 두 번 나온다. 가짜 API 명단 이름이 '팬클럽 선예매'이고 ADR-0272 결정 3의 틀이 "{명단 이름} 선예매 대상입니다"라 코드는 틀 그대로다. d5 §5.2 예("팬클럽 선예매 대상입니다" + "…보낸 팬클럽 선예매 명단에")는 같은 이름에서 첫 글에만 '선예매'를 한 번 쓴다. 정본 둘이 어긋난다(틀을 고칠지 명단 이름 관례를 정할지는 계획 몫).
- B6 취소표 알림을 처음 켤 때 뜨는 알림 권한 안내 시트의 제목·설명이 오픈 알림 글("오픈 알림을 이 기기로 보냅니다", "로비가 열리기 전에 알림을 보냅니다")이다. 정본(d5 CMP-068, ADR-0272 결정 2)은 취소표 알림 시트 글을 따로 정하지 않았다.
- 개발 서버라 개인 값 요청(찜·알림 목록·후기 요약)이 효과 두 번 실행으로 두 번씩 나갔다. 운영 빌드에서는 생기지 않는 개발 모드 동작이다.
