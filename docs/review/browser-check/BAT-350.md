## 확인 중에 찾아 고친 것

- **높음: 오프라인 새로고침이 502를 받았다.** 처음에는 `/my/tickets` 문서를 `NetworkFirst`로 캐시했는데, 원본/프록시가 502를 돌려주면 `NetworkFirst`가 그 502를 그대로 반환해 캐시 셸로 넘어가지 않았다. `/my/tickets` 문서를 `StaleWhileRevalidate`(캐시 셸 우선·뒤에서 갱신)로 바꾸고 5xx를 네트워크 실패로 보는 `rejectServerErrors` 플러그인을 더해, 서버가 내려가도 캐시 셸과 QR이 열리게 고쳤다.
- **중간: 서비스 워커 범위가 `/`로 너무 넓었다.** 월렛 밖 화면까지 제어할 수 있어 범위를 `/my/tickets`로 좁혔다. `Service-Worker-Allowed`도 `/my/tickets`로 좁혔다.

## 확인 못 함·남은 것

- `navigator.onLine`은 서버만 내려간 상태에서도 true다. 그래서 서버 장애만으로는 오프라인 배너가 뜨지 않는다(캐시 셸·QR은 정상). 실제 네트워크 단절은 배너로 확인했다.
- 새 판이 열린 티켓 화면에 바로 적용되지 않게 하는 `skipWaiting`·새 판 안내는 아직 없다. `docs/frontend.md` §2.7과 맞추는 후속이 필요하다.
- `/~offline`을 직접 열면 서비스 워커 범위 밖이라 캐시가 닿지 않는다. `/my/tickets` 문서의 대체 응답으로는 정상 동작한다.
- 데스크톱 안내의 '그래도 이 기기에 등록'은 아직 토스트다. 실제 등록은 모바일 QR 영역의 `DeviceQr` 카드다.
- 서버 공개키 등록(ticket-svc `device-keys`)이 없어 키는 `LOCAL`로만 남는다.
