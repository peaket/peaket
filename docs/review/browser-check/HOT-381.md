## 실패와 확인 못 함

- **본문 바로가기 초점이 보이지 않음(실패, 기존)**: 셸의 링크(`packages/ds/src/components/WebShell/WebShell.tsx:271`)는 `sr-only focus:not-sr-only …`인데, 키트의 `components` 층 `.sr-only`(`packages/ds/src/styles/kit.css:67`)가 `clip: rect(0 0 0 0)`를 걸고 Tailwind v4의 `focus:not-sr-only`는 `clip-path`만 풀고 `clip`은 풀지 않는다. 그래서 초점을 받아도 잘린 채다. `develop`(`760f465b`)에도 같은 클래스·같은 규칙이 있어 이 묶음이 만든 것은 아니고, 띠에 가린 초점(2.4.11)이 아니라 초점 보임(2.4.7)·CMP-065 문제다. 파트너 셸(`PartnerShell.tsx:139`)·파트너 인증 틀(`AuthFrame.tsx:23`)도 같은 꼴이라 같은 결함일 수 있다(보지 않았다). 재현: 운영 빌드 아무 소비자 웹 화면 → Tab 한 번 → `getComputedStyle(document.activeElement).clip`이 `rect(0px, 0px, 0px, 0px)`, 화면 왼쪽 위에 링크가 없다. 고치기 전에 재현 시험(예: `keyboard.spec` 또는 ds 시험에서 초점 받은 바로가기의 `clip`·보이는 크기)을 먼저 둔다. HOT-381 범위에 넣을지는 감독이 정한다.
- **결제 하단 띠(확인 못 함)**: 운영 빌드에서 홀드를 만들 길이 없어 띠가 그려지지 않는다. 소스 검사가 덮는다.
- **크기를 정한 시나리오의 Chrome 확인(확인 못 함 → Playwright로 대신)**: 시험용 Chrome 창이 최소화되어 있어 `resize_window`가 창 안 크기를 바꾸지 못했고(1920×945 그대로) 화면 캡처도 시간 초과였다. 400% 확대 단축키도 확장이 보낼 수 없다. 그래서 320·640 폭과 256·320·321 높이는 Playwright Chromium으로 봤다. 다음에 창이 열린 상태에서 Chrome으로 다시 누를 수 있다.
- 좌석맵 상자 안의 두 방향 밀기(캔버스 끌기)는 누르지 않았다(B3의 안쪽 몫, 재배치 잡 `reflow.spec`이 예외 상자를 본다).

## 관찰(실패 아님, 감독 참고)

- 관제 `/dashboard` 320×256: 가로로 미는 단계 탭 줄(`div.tabs.tabs-scroll`)의 마지막 탭 '종료 후'에 Tab으로 오면 탭 줄이 그쪽으로 밀리지 않아 탭은 오른쪽 끝 약 12px(초점 테두리 한 줄)만 보인다. 다 가려지지는 않아 2.4.11 최소 기준은 넘지만, 소비자 웹 탭 줄에 넣은 스크롤 여백(`adbf4885`)과 같은 손질이 관제 탭 줄에는 없다.
- 공연 상세 응답 CSP가 `frame-src 'none' https://challenges.cloudflare.com`이라 Chromium이 "'none'은 혼자 써야 한다"는 콘솔 오류를 내고 `'none'`을 무시한다(사람 확인 출처를 더하는 `packages/config/headers/security-headers.mjs:35`가 기본 `'none'` 뒤에 붙임). 결과적으로 사람 확인 출처만 허용되어 뜻한 동작과 같아 보이지만, 콘솔 오류가 남는다. HOT-381 범위 밖.
- 월렛 워커는 첫 설치 때 바로 열린 화면을 맡는다(`controller`가 처음부터 있음). 정리 목록의 BAT-170 R170-5와 같은 것이다. 또, 확인용으로 주소만 다른 등록을 넣은 뒤 화면이 원래 주소로 다시 등록하는 사이 잠깐 `active`가 비고 `waiting`만 있는 상태가 보였다(바로 다음 [새로고침]에서 정상 활성화). 실제 흐름에서는 생기지 않는 확인용 조작에서 본 것이다.
- Chrome에서만 Tab 순회 끝에 크기 0의 `div`(바깥 요소를 읽지 못함) 하나가 초점을 받았다. Playwright에서는 없어 Chrome 확장이 넣은 요소로 본다.
- 운영 빌드 첫 시도에서 Next.js가 "알려진 보안 취약점이 있는 판"이라며 업그레이드 권고로 빌드를 한 번 멈췄다(`next build`의 업그레이드 안내, 다시 돌리면 이어진다). 이 확인에서는 판을 바꾸지 않았다. Next.js 판 올리기는 소유자·감독이 정할 일이다.
