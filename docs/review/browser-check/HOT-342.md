# 브라우저 확인: HOT-342 ① 공연 상세 사전 검증 → 대기실

- 날짜: 2026-11-05
- 커밋: 이 기록과 같은 커밋(HOT-342 ①)
- 브라우저: Claude in Chrome(Chrome, Windows, 시험용 프로필)
- 환경
  - 계약 모양 가짜 API(127.0.0.1:4010)에 사전 검증 경로를 더했다. 상태는 `/__mock/state`의 `queuePreverify`·`queueOpenIn`과 기존 대기열 칸으로 바꾼다. 팬은 `fan=member`(본인확인 완료)다.
  - 소비자 웹 개발 서버(3000)가 대기실 경로·`/_q/*`를 대기실 개발 서버(3004)로 넘겨 같은 출처로 흉내 낸다(ADR-0211 결정 5). 그래서 `/queue/{id}`도 3000에서 열린다.
  - 사람 확인은 개발용 시뮬레이터(0.8초 뒤 토큰)다. 캡차는 풀지 않는다.
- 범위: SCR-002(d5 §5.2 '사전 사람 확인'·'오픈 뒤 진입'·'진입 혼잡'·'본인확인 필요'), SCR-008, ADR-0211

## 새 맥락 리뷰 뒤 다시 본 것

- 리뷰가 찾은 것(진입 403 `preverify-invalid` 뒤 두 화면을 오감, 조용한 갱신을 숨긴 탭에서 건너뛰고 실패하면 멈춤, 자동 다시 시도의 지터가 1초 카운트다운에 묻힘, 이미 줄 선 팬도 사람 확인을 다시 거침, 저장 실패를 무시함, 갱신이 입장 뒤 키를 되살림 등)은 흐름을 화면과 떼어(`features/preverify/flow.ts`) 재현 시험을 먼저 쓰고 고쳤다. 계약에 없는 428 응답은 가짜 API에서 걷었다(queue-svc는 사람 확인 실패에도 토큰을 준다).
- 흐름·대화상자·위젯·API 호출을 첫 그리기 뒤 늦게 싣게 나눴다. 공연 상세 첫 JS(운영 빌드, gzip)가 203.1kB(처음 구현)에서 167.3kB가 됐다(기준선 199.3kB).
- 고친 뒤 Chrome에서: [대기열 들어가기] → 대화상자 → 시뮬레이터 → 대기실 '앞에 296명'. 대기표가 저장된 뒤 공연 상세로 돌아와(사전 검증은 만료) [대기열 들어가기]를 누르면 사전 검증 요청 없이 바로 대기실로 간다.

## 브라우저 밖 시험

- `apps/web/src/features/preverify/model.test.mjs`(SCR-002): 회차 키 병합 저장, 만료·갱신·진입 가능 판단, 201 본문 읽기, 오류 → 화면 동작(HTTP 날짜 Retry-After 포함), 행동 신호 요약 v1(정수 칸, 1시간 뒤 멈춤), 공연 상세가 쓴 값을 대기실 저장소가 그대로 읽는지.
- `apps/web/src/features/preverify/flow.test.mjs`(SCR-002): 진입 흐름, 이미 줄 선 팬, 실제 다시 시도 시각, 닫기, 저장 실패·위젯 불러오기 실패·본인확인 전, 숨긴 탭의 조용한 갱신, 갱신 실패 뒤 다시·조작 필요하면 멈춤, 입장 뒤 키를 되살리지 않음.
- 대기실(`queue-room/test/controller.test.mjs`): 진입 403 `preverify-invalid`면 사전 검증 칸을 지운다.
- 가짜 API(`scripts/mock-api/queue.test.mjs`): 사전 검증 본문·응답이 계약 Zod를 지나고, 갱신이 최초 발급 시각을 잇고, 상태 바꾸기대로 403·404·503(Retry-After, 회차마다 한 번)·401, 사람 확인 토큰 없이도 201(계약에서 선택), 모르는 회차 404.

## 확인 못 함

- 조용한 갱신(만료 2분 전): 15분을 기다려야 해 누르지 않았다. 시간 계산은 단위 시험(`needsRefresh`)이 본다.
- 휴대폰 크기의 히어로 카드: 확장으로 창 크기를 바꾸지 못했다(창이 최대화 상태). 데스크톱 패널의 카드로 봤다.
- 실제 Turnstile 위젯: 개발 서버는 시뮬레이터를 쓴다.
