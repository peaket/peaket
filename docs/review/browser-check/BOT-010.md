# 브라우저 확인: BOT-010 본인확인 모의 기관과 기관 창 흐름

- 날짜: 2026-11-04
- 커밋: 이 기록과 같은 커밋(BOT-010)
- 브라우저: **Claude in Chrome 못 함(연결 없음)**. `list_connected_browsers`가 빈 목록이었다. Claude 데스크톱 앱의 내장 브라우저는 창이 가려져(보기 영역 0×0) 좌표 클릭을 할 수 없었다. 팝업은 사용자가 누른 동작이 있어야 열리므로 스크립트 클릭(`button.click()`)으로는 대신할 수 없다. 그래서 턴 규칙대로 Playwright(1.58.2, Chromium 156 headless shell)로 실제 클릭을 해 대신 눌렀다. 다음에 Chrome이 연결된 턴에 같은 시나리오를 다시 누른다(docs/PROGRESS.md 턴 규칙).
- 환경: 로컬 실행(갈래 3 전용 이름·포트). identity DB PostgreSQL 18 컨테이너(`lane3-idpg`, 18432), identity-svc(`dist/main.js`, 앱 18381·gRPC 18383, 시험 어댑터 `PEAKET_TEST_VERIFICATION_MODE` POPUP → ④만 REDIRECT로 다시 띄움), 모의 기관(`services/identity-svc/scripts/mock-idv.mjs`, 18920), 게이트웨이 대역(`apps/web/scripts/local-fan-gateway.mjs`, 18930), 모의 OIDC 제공자(`apps/web/scripts/mock-oidc.mjs`, 18910), 소비자 웹(`next build` 뒤 `next start`, `http://localhost:18310`, `NEXT_PUBLIC_API_ORIGIN=http://localhost:18930`). 키와 비밀은 실행마다 새로 만들었다. 실행 방법은 apps/README.md '휴대폰 본인확인을 로컬에서 돌려 보기'.
- 부르는 화면: 공연 상세 `/events/evt-lumen-1025?state=본인확인 필요`(SCR-002의 데이터 연결은 BUILD_ORDER HOT-310이라, 버튼이 보이는 상태 미리보기에서 눌렀다. 버튼은 실제 흐름이다). 계정은 모의 제공자의 카카오·네이버·구글 시험 사용자 셋이다.
- 범위: SCR-006 본인확인 흐름(docs/design/d5 §5.6), SCR-002의 [휴대폰 본인확인], docs/features/identity.md §5 '모의 기관과 기관 창 흐름', I-T45 ①~⑥, I-T6, FR-002.

- 새 맥락 리뷰 뒤 다시 본 것(같은 날): 리뷰가 찾은 것(COOP로 열린 팝업이 닫힌 것으로 보일 때의 늦은 메시지, 창끼리 토큰 갱신 잠금, 복귀 화면 COOP `unsafe-none`, 게이트웨이 대역·모의 기관의 머리·Host 검사 등)을 재현 시험부터 고친 뒤, 다시 빌드한 같은 스택에서 ①②③⑤⑥과 다른 계정·기관 장애를 다시 눌러 모두 통과했다. 복귀 화면 응답에 `Cross-Origin-Opener-Policy: unsafe-none`이 붙는 것도 보았고, 이번 실행의 기관 값 8개도 로그 0건이었다. ④는 바뀐 곳이 그 길에 없어 다시 누르지 않았다.
