# LCH-190 접근성 수동 시나리오 3종 확인 목록

- **무엇**: 소비자 웹의 예매 3시나리오(좌석 선택·결제·양도)를 화면 낭독기 3조합(NVDA·VoiceOver·TalkBack)으로 완주하는 사람 확인 목록이다(docs/frontend.md §5.11, NFR-020, FE-T18, 기술 검토 낮음-114).
- **누가**: 소유자(사람 확인). 이 묶음(BAT-580)은 목록과 자동 검사만 만든다. VoiceOver는 기기를 구할 때까지 미실행으로 적는다(ADR-0237).
- **정본**: 판정 기준은 NFR-020·docs/frontend.md §5.11, 화면 규칙은 docs/design/d4 §1이다. 이 문서는 검토 기록이고 규범이 아니다.

## 1. 조합과 횟수

| 조합 | 기기·브라우저 | 낭독기 | 상태 |
| --- | --- | --- | --- |
| A | Windows 11 + Chrome | NVDA 최신 | 미실행(소유자 몫) |
| B | iPhone + Safari | VoiceOver | 미실행(기기를 구할 때까지, ADR-0237) |
| C | Android + Chrome | TalkBack 최신 | 미실행(소유자 몫) |

- 조합마다 시나리오 3개를 각각 3회 [가정] 완주한다. 한 번이라도 끊기면 그 조합·시나리오는 실패다.
- VoiceOver 몫은 기기가 없어 지금은 100%로 쓰지 않는다(ADR-0237, open-items 108번).

## 2. 시나리오

1. **좌석 선택**: 공연 상세 → 사전 사람 확인 → 대기실 → 좌석 화면 → [목록으로 보기] → 구역·열·좌석 펼치기 → 2석 고르기 → 홀드.
2. **결제**: 홀드된 좌석에서 결제 화면 → 주문 내용·금액 확인 → 결제 수단 고르기 → 결제창 복귀 → 결과 화면(시뮬레이터, 실제 결제 없음).
3. **양도**: 마이 티켓 → 양도할 티켓 → 받는 사람·연락처 입력 → 확인 → 양도 완료 안내.

## 3. 접근성 이름 3종

| 종류 | 확인 | 통과 기준 |
| --- | --- | --- |
| 아이콘만 있는 버튼 | 닫기·더보기·알림·확대/축소·계정 메뉴 | `aria-label`이 동작과 대상을 담고, 화면에 보이는 글자가 있으면 그 글자도 이름에 들어간다(WCAG 2.5.3) |
| 링크 | 정책·도움말·회차·외부 안내 | 링크 이름이 목적지를 말하고, "여기"·"더 보기"만으로 끝나지 않는다. 새 창이면 이름에 알린다 |
| 입력 칸 | 로그인·양도 받는 사람·신고 사유·검색 | `label`/`aria-labelledby`로 이름이 붙고, 힌트·오류는 `aria-describedby`로 이어지며, 오류 요약이 해당 칸으로 초점을 옮긴다 |

- axe의 `label-content-name-mismatch`(실험 규칙)와 `aria-prohibited-attr`를 켜서 자동 검사가 보는 부분은 FE-T18이 맡는다.

## 5. 자동 검사가 덮는 것

- `apps/web/src/_pages/seats/model/seat-list.test.mjs`: 좌석 목록 tree·방향키·낭독 이름.
- `tools/web-checks/ds/a11y.spec.mjs`: ds 부품 axe.
- `tools/web-checks/csp`, `reflow`(FE-T31): CSP·재배치.
- 좌석 화면 axe·키보드 완주는 FE-T18의 브라우저 확인 몫이다.

## 6. 이 묶음에서 하지 않은 것

- 브라우저 수동 3종(iOS Safari·iPadOS Safari·Android Chrome)과 콘솔 휴대폰·태블릿 실기는 WBS 7.5.1에 있지만, 이 묶음의 BUILD_ORDER 범위는 접근성 수동 시나리오 3종과 i18n이다. 소유자 실기 확인 목록으로 남긴다.
