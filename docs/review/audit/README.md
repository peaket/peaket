# 웨이브 6 독립 감사

## 목적
`v0.2.0`(2026-11-04, `6bcea3c7`) 이후 `develop`까지 합쳐진 모든 작업을, 구현에 참여하지 않은 새 에이전트가 독립적으로 검토한다. 새 기능은 이 감사가 끝날 때까지 시작하지 않는다(소유자 결정 2026-11-15).

## 독립성
- 감사 에이전트는 해당 영역의 구현 커밋을 만든 세션이 아니다.
- 감사자는 코드를 수정하지 않는다(읽기 전용). 변이 담당만 격리 worktree에서 코드를 잠시 바꾼 뒤 원복한다.
- 기존 리뷰·측정·ledger·CI 초록을 그대로 믿지 않고, 코드·계약·시험·마이그레이션을 직접 대조한다.
- 확인된 결함과 추정을 구분한다. 추정은 `확신도: 낮음`으로 표시한다.

## 범위
- `git log --oneline v0.2.0..develop`의 모든 커밋, 배치, R 번호.
- 영역 감사 7: payment 정산·지급·KYC(A1), partner export·webhook·상품 정산·미수금(A2), purchase priority·refund·예매 제한(B1), queue admission·예매 제한·판매 상태(B2), ops 명령·감사·SSE·제어·앵커·지급 승인(B3), scanner·오프라인 게이트(C1), identity 기기 승인·세션·platform 인증(C2).
- 관점 리뷰 4: 보안(SEC), 정합·멱등·동시성(CONS), 시험·증거(TEST), 운영·마이그레이션(OPS).
- 변이 5: payment 돈(M1), purchase(M2), queue(M3), ops(M4), scanner/identity(M5).
- 커버리지·계약 1(COV): 배치·R 번호 누락 0, OpenAPI/AsyncAPI/proto/생성물 일치.

## 심각도
- **높음**: 돈·좌석·대기 순번·권한·개인정보·감사 무결성이 실제로 깨질 수 있거나, 재현 가능한 보안 결함. 배포 전 수정.
- **중간**: 특정 조건에서 정합·운영·복구가 깨지거나, 고위험 경로의 시험이 비어 있거나, 문서와 코드가 어긋남. 웨이브 안 수정 또는 명시적 후속.
- **낮음**: 문서·이름·관측성·편의 개선. 후속 기록.

## 발견 형식
```md
### [높음|중간|낮음] <ID>: <한 줄 제목>
- 영역/배치: ...
- 위치: `path:line`
- 증거: 코드·시험·계약·명령 결과
- 왜 문제인가: 사용자·돈·좌석·권한·운영에 미치는 영향
- 재현/확인: 가능하면 명령과 결과
- 제안 수정: 최소 수정안
- 확신도: 높음|중간|낮음
```

## 운영
- 감사·관점·커버리지는 읽기 전용 worktree(`D:\ticketpass-audit-ro1`~`ro3`)에서 한다.
- 변이는 격리 worktree(`D:\ticketpass-audit-mut1`~`mut5`)에서 하고, 끝나면 원복한다.
- Docker는 슈퍼바이저가 허용한 변이 하나만 쓴다.
- 보고서는 감독 세션의 `audit/` 폴더에 모으고, 중복을 제거해 `findings.md`에 옮긴다.
- 높음·중간 결함만 구현 담당이 고치고, 고친 뒤 다른 감사자가 확인한다.
- 감사가 끝나면 `coverage.md`에서 “검토되지 않은 배치 0”을 확인한 뒤 웨이브 7로 넘어간다.
