- **약화·삭제 없음.** `git diff b31786ea^ b31786ea -- "*.test.ts"`는 전부 추가이며 삭제 라인 0. 기존 시험 이름·기대값 변경 없음. `skip`/`todo` 추가 없음.
- `scanner-gate-regression.test.ts`는 `MemoryScannerGateStore`의 `scans`·`flags`·`changes`를 직접 읽고 `pages === 3` 같은 페이지 수를 단언한다. 어댑터 구현에 다소 붙지만, C1-03/04/05의 대상이 메모리 저장소 재판정·커서라서 행동 계약으로 볼 수 있다. 페이지 수 단언은 페이지 크기 변경 시 깨질 수 있는 경미한 취약점.
- `scanner-device-audit.test.ts`는 `assertJkt`를 `vi.mock`하고 어댑터가 그 함수를 호출했는지 단언한다. “어댑터가 도메인 검증을 거친다”는 M5V §4 요구를 고정하려는 의도가 주석에 있으나, 어댑터가 동등한 인라인 검증으로 리팩터링되면 깨지는 구현 결합이다. 의도적 결합으로 판단하며, 계약 시험과 분리해 두는 편이 낫다.
- identity 시험은 `store.sessions`, `w.assignments.sessions`, `w.store.byHash` 같은 메모리 하네스 내부를 읽는다. “세션을 만들지 않는다/코드가 PENDING으로 남는다”를 확인하는 데 필요하며, 실제 gRPC/DB 계층 시험은 아니다.
- platform 시험은 상태 코드와 `www-authenticate` 문자열, 문제 유형을 단언한다. 전부 외부 계약이다.

## 6. 남은 공백

1. **platform 영역의 수정 전 실패 없음.** R-609의 platform 변경이 타입 추가뿐이라 `8436d9db^`에서 4건 모두 통과한다. “각 영역 1개 이상 수정 전 실패”를 엄격히 요구하면 이 영역은 미충족이다.
2. **identity M5-08도 회귀 고정.** `OUTSIDE_STAFF_HOURS`·validFrom 경계는 R-566 동작이라 수정 전에 통과한다.
3. **apps/scanner 표본은 수집 단계 실패.** 수정 전에는 `reloginRequired` 등 export 자체가 없어 모듈 로드가 실패한다. 함수별 행동이 수정 전에 틀렸다는 증거는 아니며, 커서·jkt 변이로 보완했다. DPoP iat 보정(C1-07)은 변이로 직접 확인하지 않았다.
4. `ticket-cancel-refund-after-close.test.ts`와 `audit-r622-contract.test.ts`는 시험 주석 스스로 “수정 전에도 통과하는 회귀 고정”이라고 밝힌다. R-622의 수정 전 실패 집계에 넣으면 과대 계상이다.
5. **opsAlert 미주입 경로 미시험.** `ScannerDevices`에서 `opsAlert`가 없을 때 `alert`로 내려가는 `else` 분기는 신규 시험에 없다(opsAlert 성공·실패·경계만 있음).
6. **기기 단독 업로드 + 배치 없음 조합 미시험.** C1-02의 “배치 없음 403”은 스태프 세션 경로만 확인한다. `sessionEventId === undefined` 기기 단독 경로와 `shifts`가 함께 있을 때의 403은 별도 시험이 없다.
7. **음수 시계 오차 경계 미시험.** `TIME_UNCERTAIN`은 `+2분`/`+2분+1ms`만 보고 `-2분`/`-2분-1ms`는 보지 않는다(코드는 `Math.abs`).
