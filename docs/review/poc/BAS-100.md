# BAS-100 PoC: 엣지 함수·셔플 100만·Turnstile 검증 지연

- **무엇**: wbs 0.5.3의 PoC 결과다(docs/BUILD_ORDER.md BAS-100, FR-038). 엣지 함수는 AWS 계정이 없어 문서 확인과 로컬 경로 함수 시험으로 했고, 셔플 100만과 Turnstile 검증 지연은 이 PC에서 작은 표본으로 쟀다.
- **정본**: 엣지 함수 선택·배포는 docs/infra.md §4·§9, 셔플은 docs/features/queue-admission.md §2·§3, Turnstile은 docs/features/bot-defense.md·docs/features/queue-admission.md Q-T57이 정본이다. 이 문서는 검토 기록이고, 수치는 로컬 PoC라 운영 값이 아니다.
- **하지 않은 것**: AWS 실제 배포·무료 범위 함수 시험, 100만 명 부하, Q-T57 로비 부하 시험, CloudFront·S3 요금 청구 확인. 이는 계정이 생기는 HOT-012·BAT-185와 구간 측정 몫이다.

## 1. 엣지 함수: CloudFront Functions vs Lambda@Edge

| 항목 | CloudFront Functions | Lambda@Edge | 이 서비스에서의 판단 |
| --- | --- | --- | --- |
| 실행 위치 | 시청자 요청·응답(엣지) | 시청자·원본 요청·응답 | 대기실 경로 바꾸기와 도착 시각 쿠키는 시청자 요청이면 된다 |
| 런타임 | JavaScript ES 5.1 + ES6~12 일부, 런타임 2.0 | Node.js | 경로 문자열 판정은 ES 5.1로 충분하다 |
| 암호 | `crypto` 모듈의 `createHash`·`createHmac`(md5·sha1·sha256) | Node.js `crypto` 전체(RSA·EC 포함) | 도착 시각 쿠키 HMAC-SHA256은 CloudFront Functions로 된다 |
| 저장소 | KeyValueStore(KVS) 읽기 | 환경 변수·외부 호출 | 매진 플래그·서명 키를 KVS에서 읽는 지금 설계와 맞다 |
| 시간 한도 | 1ms(계산) | 시청자 5초·원본 30초 | 경로 판정·HMAC은 1ms 안이다. 긴 작업은 원본 서비스 몫이다 |
| 원본 트리거 | 없다 | 있다 | 원본 NLB가 VPC 원본이라 원본 요청·응답 트리거를 쓸 수 없다(docs/infra.md §9) |
| 로그 | us-east-1에 남는다 | 실행 리전에 남는다 | 쿠키·식별자를 로그에 남기지 않는 규칙과 함께 본다 |
| 비용 | 요청 수가 적고 무료 범위가 넓다 [가정, 배포 때 요금표 확인] | 요청+실행 시간 과금 | 경로 판정·쿠키 발급은 CloudFront Functions가 싸다 |
| 배포 | 함수 게시·연결이 단순하다 | 리전별 복제·게시가 필요하다 | 변경 동결·되돌리기가 단순한 쪽이 낫다 |

**결정(권고)**: 대기실 경로 바꾸기와 도착 시각 쿠키는 **CloudFront Functions(런타임 2.0)**로 한다. Lambda@Edge는 원본 요청·응답 트리거나 RSA/EC 서명 검증이 필요할 때만 다시 본다. 지금 정본의 엣지 함수 업무(도착 시각 쿠키, 완전 매진 응답, 대기실 셸 경로)는 모두 시청자 요청이고 HMAC-SHA256으로 충분하다.

**로컬 PoC**: `apps/web/queue-room/edge/queue-room-viewer-request.js`가 `/queue/{id}`, `/{en,ja,zh}/queue/{id}`, `/shop/{id}/queue`를 `/_q/shell.{locale}.html`로 바꾼다. `apps/web/queue-room/test/edge.test.mjs`가 로케일 넷·상품 대기·비대상 경로·쿼리 문자열 보존을 본다(4개 시험 통과). 실제 CloudFront 연결은 AWS 계정이 생기는 HOT-012·BAT-185에서 한다.

## 2. 셔플 100만

**스크립트**: `node tools/poc/shuffle-1m/shuffle.mjs` (씨앗 20261113, Node 24, 이 PC). Fisher–Yates로 0..999,999를 섞고, 참가 토큰 해시 앞 세 자리(4,096개 [가정])로 결과 파일을 나눠 JSON으로 직렬화했다. Redis 파이프라인·drand·S3 게시는 넣지 않았다.

| 값 | 측정 |
| --- | --- |
| 순열 유효 | 참(true) |
| 섞기 | 45.2ms |
| 해시·묶음 나누기 | 865.9ms |
| 4,096개 JSON 직렬화 | 212ms |
| 합계(로컬) | 1,123ms |
| 결과 파일 수 | 4,096 |
| 전체 직렬화 크기 | 14,892,986바이트(약 14.9MB) |
| 가장 큰 파일 | 4,519바이트 |
| 가장 작은 파일 | 2,984바이트 |
| 힙 사용(측정 시점) | 109.6MB |

**해석**: 로컬에서 순열·묶음·직렬화는 1.1초 안이고, 파일 하나는 5KB 미만이다. 정본의 "drand 라운드 뒤 5초 안에 4,096개 게시" [가정]을 로컬 계산만으로는 증명하지 못한다. 남은 몫은 Redis 파이프라인 쓰기, S3 4,096객체 게시, 네트워크·CDN 전파, 100만 명 조회 분산이다. 이 PoC는 그 앞단의 계산·파일 모양이 5초 예산에 들어올 여지가 있다는 것만 보인다.

**남는 한계**: 파일 형식은 `[해시, 순번]` 배열이고 정본의 `해시 → 순번` 지도와 완전히 같지 않다. 운영 형식·압축·샤드 수는 queue-admission §2의 PoC에서 확정한다.

## 3. Turnstile 검증 지연

**스크립트**: `node tools/poc/turnstile-latency/siteverify.mjs 20`. Cloudflare가 공개한 시험 키와 더미 토큰(`XXXX.DUMMY.TOKEN.XXXX`)으로 siteverify를 20번 불렀다. 시험 키 값은 [Cloudflare 테스트 문서](https://developers.cloudflare.com/turnstile/troubleshooting/testing/)에 공개된 `1x…AA` 값이고, 저장소에는 한 덩어리 비밀처럼 보이지 않게 나눠 적었다. 시험 키는 늘 통과하므로 **챌린지 풀이 시간은 빠지고** 네트워크·검증 API 시간만 잰다.

| 값 | 측정 |
| --- | --- |
| 성공/오류 | 20 / 0 |
| 최소 | 8.9ms |
| p50 | 15.5ms |
| p95 | 20.7ms |
| p99 | 71.7ms |
| 최대 | 71.7ms |

**해석**: 이 PC에서 검증 API 한 번은 p99 71.7ms로, 정본의 trust-svc 판정 데드라인 800ms [가정] 안이다. 다만 이는 표본 20건의 로컬 네트워크 값이고, 로비 개방 순간 초당 1,700~3,500건을 넣는 Q-T57 부하 시험이 아니다. 실제 챌린지 풀이 시간·Cloudflare 측 제한·국내 네트워크 지연은 Q-T57에서 잰다. 지금 설계(로비 T-10분 개방, 지연이 보이면 T-15분으로 앞당김, ADR-0147 결정 8)를 바꾸지 않는다.

## 4. 남은 일

- **엣지 함수 실제 배포**: AWS 계정·CloudFront 배포·KVS·함수 게시는 HOT-012·BAT-185. 배포 때 요금표와 무료 범위를 확인하고, 시청자가 같은 이름의 머리를 보낼 때 CloudFront가 덮어쓰는지 확인한다(docs/infra.md §4 '확인 필요').
- **셔플 운영 파이프라인**: drand 라운드 수신, Redis 파이프라인, S3 4,096객체 게시, CDN 전파를 넣고 5초 예산을 잰다(queue-admission §2, Q-T6).
- **Turnstile 부하**: Q-T57에서 로비 개방 몰림·검증 p99·검증 보류 비율을 잰다. 시험 키가 아닌 실제 사이트 키로 챌린지 풀이 시간을 포함한다.
