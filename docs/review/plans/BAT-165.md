- **무엇**: 묶음을 시작할 때 계획 담당이 만든 작업 목록이다(docs/architecture.md §8.6 4의 1, ADR-0256 결정 10). 검토 기록이고 규범이 아니다. 정본 값은 옮겨 적지 않고 자리만 가리킨다. 정본과 다르면 정본이 이긴다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane2`, 가지 `wave/lane2-BAT-160-165`, 출발점 `origin/develop` `434cb126`(R-495). 웨이브 2 커밋은 R-497부터 쓴다(R-496은 갈래 1 몫). 2026-11-12 작성.
- **등급**: 묶음은 B다(docs/BUILD_ORDER.md:68). 검색은 공개 읽기이고 결제·좌석·권한을 바꾸지 않는다.
- **이 계획과 함께 정본에 쓴 것**: ADR-0268(검색 읽기 모델을 뷰로 두는 1차 구현과 순위 결정), docs/data.md `search_document` 칸, docs/security/asvs/catalog-review.md 16.5.2의 검색 응답 캐시 머리 위치, docs/BUILD_ORDER.md BAT-165 범위, docs/review/ledger-notes.md의 다른 단계·측정·사람 확인 줄.

## 1. 묶음 나누기와 BAT-160

**결정**: 웨이브 2에서 BAT-160(HOT-260·HOT-200)은 시작하지 않고 BAT-165(HOT-270·HOT-280)를 먼저 한다.

- **BAT-160이 막힌 까닭**: HOT-200은 새 `image-worker` 배포, S3 어댑터(격리·준비·공개 버킷), 악성 코드 검사기, 이미지 코덱 의존을 요구한다. 지금 `develop`에 `image-worker` 배포와 `@aws-sdk/client-s3`가 없고, 이 묶음의 싼 게이트 범위 밖에서 인프라를 새로 세워야 한다. HOT-260만 해도 묶음의 절반이라 BAT-160을 완료로 적지 않는다.
- **BAT-165를 고른 까닭**: 선행 HOT-171(공연 등록·회차)·HOT-180(검색 정규화 패키지)·HOT-312(검색 결과 화면)가 이미 `develop`에 있다. HOT-270의 검색 포트·읽기 모델·자동완성 사전과 HOT-280의 순위·쪽·0건 제안·관련 공연을 core-svc 안에서 끝낼 수 있다.
- **더 나눌 때**: 1차는 `search_document`를 뷰로 둔다. 공연 수가 늘어 뷰 스캔이 느려지면 materialized view·증분 동기화를 후속 묶음으로 나눈다(ADR-0268 되돌릴 조건).

## 3. 구현

1. **도메인**(`services/core-svc/src/modules/catalog/domain/search.ts`): `SearchDocument`·`SearchQuery`·`SearchOutcome`·`SearchSuggestions`, `SearchIndex` 포트. `searchDocuments`는 등급 → 판매 상태 → 관심도 → 이름 → ID 순으로 정렬하고, 장르·공연장·아티스트·기간·상태 필터, 20개씩 50쪽(1,000건 상한), 0건 `didYouMean`·`relaxedTotal`, 관련 공연(같은 아티스트 → 같은 공연장 → 다가오는 인기)을 만든다. `suggestDocuments`는 공연 5·아티스트 2·공연장 1 몫을 먼저 채우고 빈 몫을 다른 종류로 채운다.
2. **유스케이스**(`application/search.ts`): `SearchCatalog`. 검색은 매번 `SearchIndex.documents()`를 읽고, 자동완성 사전은 판(`version`)이 같고 10초 [가정] 안이면 메모리 사본을 쓴다.
3. **어댑터**: 메모리(`MemorySearchIndex`)는 `MemoryCatalogRepository`의 공연·회차·이미지·찜에서 문서를 만든다. PostgreSQL(`DrizzleSearchIndex`)은 `search_document` 뷰를 읽고 `search_version`의 판을 쓴다.
4. **마이그레이션**(`0009_search.sql`): `search_version`(한 줄)·`search_term`(자리) 표와 `search_document` 뷰. 뷰는 `production`·`event`·`place`·`artist`·`production_artist`·`search_alias`·`production_image`·`wish`를 모아 항상 지금 값을 보여 준다. 판매 승인 공연만 넣고 `SUSPENDED`는 뺀다. 판매 상태는 시각으로 `UPCOMING`·`ON_SALE`·`ENDED`를 만들고, `SOLD_OUT`은 purchase-svc `event_sale` 사본이 생길 때까지 만들지 않는다.
5. **HTTP**(`inbound/search.controller.ts`): `GET /v1/search`·`GET /v1/search/suggestions`. 인증 없음, 계약 스키마가 검색어·필터·쪽을 먼저 검사한다. `Cache-Control`에 `stale-if-error`를 단다.
6. **정규화 패키지**: `packages/search-normalize`가 `convertQwertyToHangul`을 내보내고 core-svc가 한/영 변환에 쓴다. `noConvert=true`면 변환하지 않으며, 변환으로 찾았으면 응답 `query.converted`에 원문과 바꾼 값을 싣는다.
7. **조립**: `catalog.module.ts`에 `SEARCH_INDEX` 제공자(운영 Drizzle·시험 메모리)와 `SearchController`를 더하고, `index.ts`가 새 공개 이름을 내보낸다.

## 7. 무거운 게이트로 남긴 것(웨이브 끝)

- **test-int**: 실제 PostgreSQL 18에서 `0009_search.sql` 뷰·`search_version`·`search_term` 마이그레이션과 `DrizzleSearchIndex` 읽기. SR-T7(문자 분류·조각 비교)·SR-T15(읽기 복제본·사전 판)가 여기서 증명된다.
- **측정**: SR-T13(k6 검색 p95, 검색 전용 연결 묶음, 요청 한도).
- **브라우저 확인**: SR-T10(한글 조합 중 Enter·Esc), SR-T14(`/search` noindex·sitemap 제외).
- **CDN·게이트웨이**: ASVS 2.4.1·14.2.5·16.3.3(IP별 레이트 리밋, 경로별 캐시 표, 503 기록). 1차 코드는 공개 읽기와 `Cache-Control`만 둔다.

- **4관점 리뷰·변이**: 아직 돌리지 않았다.
