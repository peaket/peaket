## 1. 범위와 선행 확인

**선행 확인**: HOT-370의 상태표·폴러·시계·탭 조정·텔레메트리 lite는 `apps/web/queue-room`에 이미 있다(HOT-340·341·343·345·347~349·352). HOT-130의 SeatList tree·방향키·가상 스크롤·낭독 이름은 `apps/web/src/_pages/seats`에 이미 있고, 자동 배정 화면·실패 갈래도 `SeatsLive.tsx`·`SeatsPreview.tsx`에 있다. 그래서 새로 만들지 않고 **빠진 빌드 체계와 확인 목록**만 채웠다.

**한 것**:
1. **로케일 셸 넷**(HOT-370): `shell.{ko,en,ja,zh}.html`을 Vite 빌드 입력에 넣고, 개발 서버·검사 서버가 경로의 로케일을 골라 셸로 바꾼다. 화면 문구 전체의 다국어는 다국어 단계에서 잇는다.
2. **S3 `/_q/` 업로드 목록**(HOT-370): `scripts/upload-manifest.mjs`가 셸 `max-age=0, must-revalidate`, `assets/*` 1년 immutable, `preview.html`·소스 맵 제외를 표시한다.
3. **CloudFront Function 경로 PoC**(HOT-370): `edge/queue-room-viewer-request.js`가 `/queue/{id}`·`/{en,ja,zh}/queue/{id}`·`/shop/{id}/queue`를 로케일 셸로 바꾼다. AWS 계정이 없어 로컬 함수 시험만 했다.
4. **S-T18 확인 목록**(HOT-130): `docs/review/manual-a11y/S-T18.md`에 NVDA·TalkBack·VoiceOver 조합, 시나리오 11항목, 3회 완주 기록 틀을 만들었다. 사람 확인은 소유자 몫이다.
5. **SeatList·자동 배정 화면 확인**(HOT-130): 기존 시험에 ASVS 태그를 붙이고, 좌석 화면 저장소 검사(14.3.3)를 더했다.

**막힌 몫(후속·다른 단계로 적음)**:
- **실제 CloudFront 함수 게시·S3 업로드**: AWS 계정이 생기는 HOT-012·BAT-185.
- **S-T19 1,000건 동시 자동 배정**: purchase-svc의 자동 배정 Lua·Redis·부하 측정 몫이다. 이 묶음은 화면과 실패 갈래만 시험한다.
- **S-T18 사람 확인**: NVDA·TalkBack은 소유자, VoiceOver는 기기를 구할 때까지 미실행(ADR-0237).
- **화면 문구 다국어**: 로케일 셸은 만들었지만 화면 문구 자체는 다국어 단계 몫이다.
