# BAT-179 계획(Next.js 16.4.3 → 16.4.5 보안 판 올림)

- **무엇**: `apps/web`과 `apps/partner`가 쓰는 Next.js를 16.4.3에서 16.4.5로 올린다. 두 앱의 `package.json`이 선언하는 최소 판을 `^16.4.5`로 올리고 `pnpm-lock.yaml`을 다시 만든다. 제품 코드·설정·화면은 바꾸지 않는다.
- **쉬운 말**: Next.js는 화면을 만드는 프레임워크다. 지금 쓰는 16.4.3에는 다른 사용자의 캐시 내용이 섞일 수 있는 보안 결함 두 가지가 있다. 16.4.5는 그것을 고친 판이다. 판을 올리면 빌드 끝에 보안 경고로 한 번 멈추던 일도 없어진다. 화면과 동작은 지금과 같아야 한다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane2`, 가지 `feature/lane2-BAT-179`, 출발 `develop` `f6d046087`. 2026-11-20 계획 담당이 썼고 제품·시험 코드는 쓰지 않았다. 읽은 것: `docs/lanes/lane2.md` 8~10줄, `docs/BUILD_ORDER.md` 88~101줄, `docs/frontend.md` §5.18(1,657~1,681줄)·§6.4(1,882줄), `docs/devops.md` §3.1 `ci-web.yml` 행(207줄)·§4.4(최소 출시 대기·신뢰 정책)·§6.6(543~552줄), `apps/web/package.json`·`apps/partner/package.json`·`apps/console-host/package.json`, `pnpm-lock.yaml`의 next 항목, `apps/web/next.config.ts`·`apps/partner/next.config.ts`, `apps/web/server/csp-hash-server.mjs`·`start.mjs`·`cache-handler.mjs`·`use-cache-handler.mjs`, `packages/config/next/server-actions-key.mjs`, `packages/platform/src/telemetry-app-server.ts`, `.github/workflows/ci-web.yml`·`security-scan.yml`, `tools/ci/vuln-deadline.mjs`·`vuln-exceptions.json`, npm 레지스트리의 `next@16.4.3`·`next@16.4.5` 문서와 GitHub 권고 두 건.
- **등급**: C(짧은 고리, ADR-0283 결정 2). 판과 잠금 파일만 바꾸고 돈·좌석 홀드·대기 순번에 닿지 않는다. 단계는 `-`, 장부 범위는 `-`, WBS는 0.5일 [가정]이다.
- **차례**: 계획 → 시험(T1) → 구현 → 리뷰 → 검증 → 기록. 이 파일은 역할마다 자기 절만 쓴다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.

## 감독에게

1. **Next.js 앱은 둘뿐이다.** `apps/web`과 `apps/partner`만 `dependencies.next`를 가진다. `apps/console-host`는 webpack 5 + React Router 8이고, `apps/web/queue-room`·`apps/scanner`·`apps/forensics`는 Vite다. 그래서 이 묶음이 고치는 `package.json`은 둘이고, 관제·스캐너·포렌식·대기실은 판이 바뀌지 않는다.
2. **새 판 3일 대기는 이미 지났다.** 16.4.5는 npm에 2026-11-03T18:38:39Z에 게시됐고(레지스트리·GitHub 릴리스), 오늘은 2026-11-20이다. `pnpm-workspace.yaml`의 `minimumReleaseAge: 4320`(3일)에 걸리지 않으므로 예외를 더할 일이 없다. `trustPolicy: no-downgrade`도 내려가는 판이 아니라 걸리지 않는다. 설치가 이 두 규칙에 막히면 예외를 억지로 더하지 말고 멈춰 보고한다.
3. **이 묶음은 빨간 CI를 초록으로 바꾸는 일이 아니다.** 두 권고는 모두 중간(CVSS 6.3)이고, `tools/ci/vuln-deadline.mjs`는 치명·높음만 PR을 막는다. 지금 `security-scan / dependencies`는 이 두 건 때문에 실패하지 않는다. 이 묶음의 값은 ① `pnpm audit`에서 next 권고 2건을 없애고 ② 16.4.3이 빌드 끝에 내던 `SecurityFatalError`(같은 명령을 다시 돌려야 넘어가던 것)를 없애는 것이다. 16.4.5 릴리스 본문에는 권고가 7건 실려 있지만, 지금 이 잠금 파일에 잡히는 next 권고는 2건뿐이다.
4. **지금 코드에는 두 권고의 악용 조건이 바로 성립하지 않는다.** 저장소 전체에 `unstable_cache`와 `next/root-params` 사용이 0건이다. 첫 권고는 `unstable_cache()` 호출이, 둘째 권고는 root param을 읽는 안쪽 `'use cache'`가 필요하다. 그래도 권고가 있는 판을 잠금 파일에 두지 않는다는 공급망 규칙(`docs/devops.md` §4.4)과 빌드 알림 때문에 올린다. 이 판단은 "지금 안전하니 미룬다"가 아니다.
5. **진짜 위험은 Next.js 내부 모양에 기댄 코드다.** `apps/web/server/csp-hash-server.mjs`는 설치된 Next.js의 `dist/compiled/next-server/app-page*.runtime.prod.js`에서 React 스트리밍 도우미 문자열을 정규식으로 뽑고, `apps/web/server/start.mjs`는 `next/dist/bin/next`와 `required-server-files.json`을 읽는다. `packages/config/next/server-actions-key.mjs`는 `encryption-utils.js`의 키 읽기를, `packages/platform/src/telemetry-app-server.ts`는 `__NEXT_PRIVATE_ORIGIN`을 본다. 패치 판에서 이 모양이 바뀌면 조용히 깨질 수 있어 P3·P4(기존 `test:build`·`boot`·`csp`)가 본다.
6. **정본 위치를 바로잡는다.** `docs/frontend.md`에는 §6.6이 없다(§6.1~§6.4뿐). Next.js 자체 호스팅·정적 자산·`deploymentId` 규칙의 §6.6은 `docs/devops.md`다. 이 계획은 `docs/frontend.md` §5.18(빌드·배포·동결)과 `docs/devops.md` §6.6(프론트엔드·PWA·엣지)을 읽었다. 두 정본 모두 판 번호를 박지 않아 문장을 고칠 것이 없다. `docs/security/secrets-and-keys.md` 34줄과 `packages/config/next/server-actions-key.mjs` 2줄에 남은 '16.4.3에서 확인'은 날짜가 붙은 기록이라 이 묶음에서 고치지 않는다. 16.4.5에서 키 읽기 코드가 달라지면 P3의 시작 시험이 잡고, 그때 정본을 고친다.

## 계획

### 1. 지금 상태

- **선언과 설치**: `apps/web/package.json`·`apps/partner/package.json` 모두 `"next": "^16.4.3"`이다. 잠금 파일의 두 작업 공간 항목도 `specifier: ^16.4.3`·`version: 16.4.3`이고, 설치된 `node_modules/next`도 두 앱 모두 16.4.3이다.
- **잠금 파일의 next 항목**: `next@16.4.3`, `@next/env@16.4.3`, `@next/swc-*@16.4.3` 여덟(SWC 바이너리), 그리고 `@serwist/turbopack@9.5.13`의 peer 묶음이 `next@16.4.3`을 가리킨다. `@serwist/turbopack`의 peer 범위는 `next >=14.0.0`이라 16.4.5와 맞는다. 16.4.5의 의존성은 16.4.3과 같고 `@next/env`·SWC 바이너리만 16.4.5로 바뀐다(레지스트리 문서). 그래서 잠금 파일 차이는 next 주변으로 좁아야 한다.
- **지금 잡히는 권고**(2026-11-20 이 PC, `pnpm audit --json`): 중간 5건. 그중 next 2건이 `GHSA-mfr8-8qww-v76h`(CVE-2026-119790)와 `GHSA-vc7v-qv4w-wrv8`(CVE-2026-119351)이고 둘 다 `patched >=16.4.5`다. 나머지 3건은 esbuild·glob·minimatch의 기존 중간 권고로 이 묶음 범위 밖이다. 치명·높음은 0건이다.
- **두 권고의 조건**: 첫째는 `'use cache'` 함수를 `unstable_cache()`로도 부를 때 root param이 다른 캐시가 섞이는 문제다. 둘째는 Cache Components에서 바깥 `'use cache'`가 root param을 키에 넣지 못하는 문제다. 저장소에 `unstable_cache`·`next/root-params` 사용이 없어 지금 코드가 그 조건을 만들지는 않는다. 다만 16.4.3은 권고가 있는 판이고, 빌드가 보안 알림으로 멈추는 원인이라 올린다.
- **빌드 알림**: 설치된 16.4.3의 `dist/lib/upgrade/nudge.js`가 `SecurityFatalError`를 던진다. BAT-178 기록(`docs/review/plans/BAT-178.md` 173·265·279줄)에서 운영 빌드가 앱마다 한 번 멈추고 같은 명령을 다시 돌려야 넘어갔다고 적었다. 16.4.5에서 이 알림이 사라지는지가 P3의 판정이다. 다시 나타나면 설치된 판을 레지스트리 권고와 견주고 멈춰 보고한다(억지로 재시도하지 않는다).
- **내부 결합**: 위 '감독에게 5'의 네 곳이 Next.js 내부 파일·환경 값에 기댄다. 판이 바뀌면 가장 먼저 깨질 수 있는 곳이고, 새 시험을 만들지 않고 기존 운영 빌드·시작·CSP 시험이 본다.

### 2. 바른 동작

1. **설치된 판**: `@peaket/web`과 `@peaket/partner`가 같은 Next.js 16.4.5(또는 그보다 높은 같은 판)를 쓴다. 저장소 어디에도 next 관련 16.4.0~16.4.4가 남지 않는다.
2. **선언**: 두 앱의 `dependencies.next`가 `^16.4.5`로 같다. 잠금 파일의 작업 공간 항목도 같은 최소 판을 적는다.
3. **설치 재현**: `pnpm install --frozen-lockfile`이 통과하고 작업 트리가 바뀌지 않는다. 즉 잠금 파일과 `package.json`이 어긋나지 않는다.
4. **동작·빌드 그대로**: 타입 검사·단위 시험·린트가 지금과 같이 통과한다. 운영 빌드가 첫 시도에 `SecurityFatalError` 없이 끝나고, standalone 산출물·서버 시작 확인·공유 캐시·CSP 해시 서버·SRI가 지금과 같이 동작한다.
5. **보안 알림 해소**: `pnpm audit --json`에서 next 권고가 0건이 된다. `auditConfig`·`ignoreGhsas`·`pnpm.overrides`·`vuln-exceptions.json`으로 권고를 숨기지 않는다.
6. **화면 그대로**: `web / budgets`(첫 JS·Lighthouse·CSP·정적 자산)·`web / visual`·`web / reflow`가 초록이고, 한도 값(월렛 LCP 7,255ms와 BAT-176 임시 알림 포함)은 바꾸지 않는다.

### 3. 고치는 방법 비교

| 후보 | 좋은 점 | 문제 | 결론 |

- **정한 것**: 두 앱의 `next`를 `^16.4.5`로 올리고 `pnpm install`로 잠금 파일을 다시 만든다. `next.config.ts`·`proxy.ts`·캐시 처리기·CSP 해시 서버는 고치지 않는다.
- **공개 인터페이스**: 없다. 의존성 범위와 잠금 파일만 바뀐다.
