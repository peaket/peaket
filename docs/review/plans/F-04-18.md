# F-04-18 계획 — CMP-079 봇 후보 산점도·2D 대체·원천별 패널·성능(동결 로컬)

- **무엇**: 기능 표 F-04-18(LCH-230)의 동결 로컬 트랙 계획이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **등급**: B. 이번 동결 기간(2026-11-23~12-03)의 가벼운 절차(ADR-0373)에서는 B·C 기능의 시험 리뷰를 생략하지만, 감독이 이 기능에 한해 **계획 → 시험 → 시험 리뷰(새 세션) → 반영 → 구현 → 기록**을 지시했다. 이번 턴은 계획·시험·기준 트리 실패 확인·게이트·푸시에서 멈추고 시험 리뷰를 기다린다. 구현은 시험 리뷰 뒤에 시작한다.
- **동결 로컬 범위**: v1 출시 범위 밖이다(ADR-0373 결정 2, ADR-0386 결정 4·5, `docs/release/v1-scope.md` F-04-18). `freeze/lane6-F-04-18` 가지와 `D:/ticketpass-freeze-F-04-18` 워크트리에서만 개발하고 `develop`·`release/1.0.0`에 합치지 않는다. 출시 마이그레이션·릴리스 플래그·`deploy/` 값을 건드리지 않는다.
- **바탕**: `cc1398783`(`origin/freeze/lane6-F-04-17`, F-04-17 완료 포함, 2026-11-27). F-04-17이 만든 `ReplayMain`·`ReplayFilters`·`ReplayTimeline`·`SeatReplay`·`crossfilter`·`table`·`session`을 입력으로 쓴다. 이미 있던 F-04-9 생성기·F-04-16 운영 빌드·replay-export도 그대로 쓴다.
- **정본**: `docs/features/forensic-replay.md` §2.1~§2.3·§3.1~§3.6·§4.1~§4.4·§7.1·§8(FX-T5·FX-T9), `docs/security/asvs/forensic-replay.md`(v5.0.0-1.1.2·1.4.1·1.4.2·1.4.3·3.5.5·3.7.1·14.3.3), `docs/frontend.md` §5.2·§5.8·§5.19, `docs/design/d5-screen-blueprint.md` §7.17, `docs/lanes/lane6.md`, ADR-0080·0171·0173·0372·0373·0386.
- **감독 지시문과 정본의 차이**: 지시문의 'Worker·공유 시계'는 정본 §3.1·§3.3이다. 이번에는 **복사 방식 Worker 하나만** 만들고 공유 시계는 더하지 않는다. §3.3의 '더할 조건'은 FX-T5 측정에서 복사 방식이 목표를 못 맞추고 원인이 메시지 전달로 확인될 때인데, 이번 동결 로컬 턴에는 그 측정이 없다(미실행). '2D 대체'는 정본 시험 FX-T7이 아니라 이 기능의 화면 수용 기준 UI-11로 닫는다. 장부 범위는 기능 표가 정한 FX-T5·FX-T9 두 판정이다.

## 1. 이 기능이 끝내는 것과 넘기는 것

### 1.1 끝내는 것

1. **후보 모델(순수)**: 사건 열에서 세션 점(`first_hold_ms`·`entropy`)을 만들고, 영역 고르기(`[x0,x1)`·`[y0,y1)`), 합성 정답 기준 정밀도·재현율, 기기 묶음(같은 묶음이 10ms [가정] 안에 서로 다른 좌석 시도), 고른 세션의 좌석 목록, 연구 원천 한 축 24칸 [가정] 분포, 원천별 고정 문구를 계산한다.
2. **원천별 후보 패널**: 합성은 CMP-079 산점도(가로 `first_hold_ms` 로그, 세로 `entropy`), 연구는 같은 자리에 한 축 분포 막대, 조사는 CMP-083 '단계별 시간 대 정상 기준선'을 그린다. 패널 제목·축 설명·고정 문구는 원천에 맞춘다. 조사 원천은 계정별 행동 값을 나란히 견주지 않는다(ADR-0173 결정 5).
3. **2D 대체**: WebGL2가 없으면 산점도를 2D로 그리고 최대 2만 점 [가정]을 일정 간격으로 골라 그린다. "이 기기는 표본으로 그립니다"를 보인다. 고르기·정밀도·재현율은 표본이 아니라 전체 세션으로 센다.
4. **고르기 연결**: 산점도 영역·연구 분포 구간·조사 기준선 칸을 고르면 그 세션이 `HOLD_TRY`·`SALE`한 좌석이 좌석맵에 색과 굵은 테두리로 점등된다. 고르기를 지우면 점등도 지운다.
5. **정밀도·재현율과 고정 경고**: 합성 원천에서만 고른 영역의 세션 수·정밀도·재현율을 보이고, 바로 아래에 정본 §2.1의 생성 가정 경고를 늘 둔다. 연구·조사 원천에는 정답이 없어 `panelSections`가 거짓이라 보이지 않는다.
6. **기기 묶음 목록**: 합성·조사 원천에서 기기 묶음 번호·세션 수·해당 시도 수를 보인다. 연구 원천에는 없다.
7. **표로 보기**: 후보 패널의 그림마다 같은 집계를 표로 보는 `[표로 보기]`를 둔다. 표 값은 그림과 같은 `candidateModel`·`selectionStats`·`histogram`에서 `candidateTableRows`·`histogramRows`로 만든다.
8. **복사 방식 Worker**: 후보 점·기기 묶음·영역 집계를 데이터 Worker가 계산한다. 메인은 후보 계산용 열 **복사본**을 `candidate` 메시지로 전송 목록에 넘기고, Worker는 `candidate-done`(점 x·y 쌍, 세션, 봇, `panel`, `bursts`, `histogram`, 합계)·`error`만 돌려준다. 정해진 종류·판 번호·형이 아닌 메시지는 버린다. 메인의 좌석 재생용 원본 열은 그대로 두고, 좌석 점등은 메인에서 `seatsOfSessions`로 계산한다. Worker가 없거나 실패하면 같은 순수 함수로 메인 스레드에서 계산한다.
9. **성능 띠와 판정 함수**: 이 기기에서 잰 필터 반영 p95·프레임 p95·긴 작업 수와 복사 방식 여부를 상태 띠에 보인다. 판정 함수는 정본 §7.1의 50ms·20ms 경계를 쓰고, 측정이 없으면 `null`·`—`로 합격하지 않는다. 실제 성능 수치는 이 기능에서 주장하지 않는다.
10. **정본 반영**: §2.1에 후보 패널의 그림·고르기·값 정의를, §3.3에 후보 Worker와 공유 시계를 더하지 않는 결정을 적었다. 기능 표 장부 범위를 FX-T5·FX-T9로 좁혔다. FX-T5는 판정 함수·경계만 자동 시험으로 두고, 실제 기준 기기 측정은 notes `측정`으로 미실행을 남긴다.
11. **교차 필터 연결**: `ReplayMain`이 필터 상태를 들고 `ReplayFilters`·`CandidatePanel`에 같은 값을 넘긴다. 후보 패널은 `maskToKeep(selectionMask(...))`로 같은 조건의 점·기기 묶음·정밀도를 다시 센다.

## 2. 정본 빈칸과 이번에 정한 것(추천 적용 2026-11-27, F-04-18)

- **정본 반영**: 아래 1~3은 이번 계획 커밋에서 `docs/features/forensic-replay.md` §2.1·§3.3에 **먼저** 적었다. 이 계획은 그 정본을 가리키고, 정본과 다르면 정본이 이긴다.

1. **후보 패널 정의**: 산점도 축·축 밖 값, 정밀도·재현율의 분모(후보 패널에 그려진 전체 봇 세션), 영역의 반열림 구간, 사람 흉내 봇 프리셋의 1,000세션·+10%p [가정], 연구 분포 24칸, 기기 묶음 10ms, 2D 표본 2만 점, 점등 좌석을 §2.1에 적었다.
2. **Worker와 공유 시계**: 후보 계산을 데이터 Worker가 맡고 메시지 종류·판 번호·형을 검사하며, 공유 시계는 이번 구현에서 더하지 않는다는 것을 §3.3에 적었다. 메인은 후보 계산용 열 **복사본**만 전송 목록으로 넘기고, 메인의 좌석 재생용 원본 열은 그대로 둔다. Worker 응답은 점(x·y 쌍)·세션·봇·기기 묶음·히스토그램·원천별 `panel`을 담는다.
3. **장부 범위**: 기능 표 F-04-18의 장부 범위를 `FX-T5, FX-T9`로 좁혔다(§8.6 3). FX-T5는 판정 함수·경계만 자동 시험으로 두고 실제 측정은 notes `측정`으로 미실행을 남기며, FX-T9은 시험으로 닫는다. `docs/features/forensic-replay.md` 경로를 범위에서 빼서 이 기능과 닿지 않는 FX-T1~T4·T6~T8·T10~T24가 딸려 오지 않게 했다.
4. **정밀도·재현율의 분모**: 재현율 분모는 '후보 패널에 그려진 세션 가운데 봇 세션 수'다. 첫 홀드가 없어 점이 없는 봇은 고를 수 없으므로 분모에서 뺀다. §2.1에 적었다.
5. **연구 분포 칸**: 10ms~10s를 10배마다 8칸씩 나눈 24칸이다(d5 §7.17 목업의 24칸과 같다). 10ms 미만은 첫 칸, 10s 이상은 마지막 칸에 넣는다. 경계 값은 `10^(1+i/8)`ms다.
6. **기기 묶음 경계**: '10ms 안'은 양 끝을 포함한다(`t2 - t1 <= 10`). 같은 좌석만 시도한 묶음은 세지 않는다. 묶음 번호 0(없음)은 보지 않는다.
7. **사람 흉내 봇 시험 규모**: 단위 시험은 프리셋과 같은 분포·시드 규칙으로 3,000세션(좌석 1,200·창 120초·봇 30%)을 만든다. 실제 3만 세션 프리셋 생성은 단위 시험에서 하지 않는다. 시험은 16×16 분위 경계로 만든 영역 가운데 세션 1,000개 이상인 곳을 모두 본다(§7.3).
8. **2D 표본 방식**: 표본 수 `min(전체, 20000)`, 고르는 자리 `floor(i × 전체 ÷ 표본수)`다. 처음 점은 늘 포함하고 마지막 점은 전체 길이 안이다. 표본은 그리기에만 쓰고, 영역 집계·정밀도·재현율·좌석 점등은 전체 점으로 한다. 시험은 2.5만 점을 모두 덮는 영역의 집계가 2.5만인지 본다.
9. **공유 시계 없음**: `SharedArrayBuffer`·`Atomics`를 만들지 않는다. 상태 띠의 공유 시계 값은 `clockModeLabel(SHARED_CLOCK_ENABLED)`로만 보이고, `SHARED_CLOCK_ENABLED`는 거짓이라 늘 '복사 방식'이다. 교차 출처 격리가 켜져도 공유 시계를 만들지 않는다.
10. **FX-T5 수치 없음**: 30k/s·100만·K1/K2/K7 0 같은 수치를 이 기능의 결과로 적지 않는다. 성능 띠의 값은 실제로 잰 값이 없으면 `p95`가 null이고 화면은 `—`를 쓴다. `0`으로 합격하지 않는다.
11. **조사 원천 행동 값**: 조사 원천 후보 패널은 단계 시각·기기 묶음만 보이고, 세션별 `entropy`를 계정끼리 나란히 놓거나 정렬하지 않는다(ADR-0173 결정 5, d5 §7.17).
12. **계약**: `docs/api/openapi.yaml`·`packages/contracts`·`packages/api-client`를 고치지 않는다. F-04-16이 쓴 `getOpsFraudCaseReplayExport`·`getOpsResearchExport`를 그대로 쓴다.
13. **교차 필터 연결**: `ReplayMain`이 `ReplayFilter` 상태를 들고 `ReplayFilters`·`CandidatePanel`에 같은 값을 넘긴다. 후보 패널은 `maskToKeep(selectionMask(columns, keep, filter), columns.t_ms.length)`로 계산한다. 정본 §2.1의 '고르기는 모두 연결된다'를 후보 패널까지 잇는다.
14. **표 값**: 그림과 표는 같은 `candidateModel`·`selectionStats`·`histogram`에서 나온다. `candidateTableRows`·`histogramRows`를 순수 함수로 두고, 화면은 그 값만 그린다. 합성에서만 정밀도·재현율을 보이고 연구·조사는 `panelSections`가 거짓이다.

## 3. 계약과 생성물(이번 단계는 고치지 않는다)

- 새 경로·스키마·Problem type 없음. `gen:check`는 계약과 생성물이 같은지만 본다. 이번 단계에 바뀌는 계약은 0줄이다.
- 새 의존 없음. `apache-arrow`는 F-04-17이 더했다. Worker는 Vite의 `new Worker(new URL(...), { type: 'module' })`를 쓰고 새 패키지를 더하지 않는다.
- `deploy/`·마이그레이션·릴리스 플래그·`pnpm-lock.yaml`은 0줄이다.

- `candidatePanelKind`: `SYNTHETIC`→`scatter`, `RESEARCH`→`distribution`, `INVESTIGATION`→`baseline`.
- `candidateNotice`: 조사 원천은 `"후보 찾기용입니다. 조치는 사건 작업대에서 소명과 승인을 거쳐 합니다(POL-046)."`, 연구·합성은 `"후보 찾기용입니다. 봇 판정은 표본 검토(SCR-067)와 정해진 규칙(POL-006)으로 합니다."`다.
- `precisionNotice`: `"합성 데이터의 정답으로 잰 값입니다. 봇을 이 특징으로 만들었기 때문에 높게 나오며, 실제 봇 탐지 성능을 뜻하지 않습니다."`다.
- `mimicPrecisionLimit(ratio)`는 `ratio + 0.1`이다.
- `sessionPoints`는 `keep[i] === 1`인 행만 보고 세션마다 하나를 만든다. `first_hold_ms > 0`인 값 가운데 가장 이른(최소) 값을 쓰고, `entropy`는 같은 세션에서 NaN이 아닌 첫 값, `botTier`는 가장 큰 값, `deviceGroup`은 0이 아닌 첫 값, `member`는 하나라도 1이면 참이다. 세션 번호 오름차순으로 돌려준다. `first_hold_ms`가 0인 세션은 넣지 않는다.
- `candidatePoints`는 `entropy !== null`인 점만 만든다. `x`는 `firstHoldMs`, `y`는 `entropy`, `bot`은 `botTier > 0`이다.
- `selectPoints`는 `x0 <= x < x1`이고 `y0 <= y < y1`인 점만 돌려준다. `bounds`가 뒤집혔거나 같으면 빈 배열이다.
- `selectionStats`의 정밀도는 `bots / sessions`, 재현율은 `bots / totalBots`다. 분모가 0이면 0이다. `totalBots`는 `candidateModel`이 그려진 점의 봇 수로 넘긴다.
- `distributionHistogram`은 기본 10ms·10s·24칸이다. `firstHoldMs <= 0`이거나 NaN인 점은 세지 않는다. 10ms 미만은 첫 칸, 10s 이상은 마지막 칸에 넣는다. `edges[i] = 10 ** (1 + i / 8)`(i=0~24)이다.
- `deviceBursts`는 `keep=1`·`device_group>0`·`seat != 0xFFFFFFFF`인 `HOLD_TRY`만 본다. 같은 묶음 안에서 `|t2-t1| <= windowMs`(기본 10)이고 좌석이 다른 짝이 하나라도 있으면 그 두 행을 '해당 시도'로 센다. `attempts`는 해당 시도 행 수, `sessions`는 그 행들의 세션 수, `firstAtMs`·`lastAtMs`는 그 행들의 최소·최대 시각이다. 묶음 번호 오름차순이다.
- `seatsOfSessions`는 고른 세션의 `HOLD_TRY`·`SALE` 좌석을 중복 없이 오름차순으로 돌려준다. `0xFFFFFFFF`는 뺀다.
- `candidateModel`: `SYNTHETIC`은 점·기기 묶음, `RESEARCH`는 분포(점 없음, 기기 묶음 없음), `INVESTIGATION`은 기준선(점·분포 없음, 기기 묶음)이다. `totalSessions`는 `sessionPoints` 길이, `totalBots`는 점의 봇 수다(연구·조사는 점이 없어도 `sessionPoints`의 `botTier>0`을 센다).
- `panelSections`: `SYNTHETIC`은 `{precision:true, deviceGroups:true, histogram:false, baseline:false}`, `RESEARCH`는 `{precision:false, deviceGroups:false, histogram:true, baseline:false}`, `INVESTIGATION`은 `{precision:false, deviceGroups:true, histogram:false, baseline:true}`다.
- `candidateTableRows`: 합성은 `세션`·`봇 세션`·`기기 묶음`을, `stats`가 있으면 `고른 세션`·`정밀도`·`재현율`을 더한다. 연구는 `세션`·`분포 칸`, 조사는 `세션`·`기기 묶음`을 낸다. 비율은 `Math.round(x * 10000) / 10000`이다.
- `histogramRows`: 칸마다 `{fromMs: edges[i], toMs: edges[i+1], sessions: bins[i]}`를 낸다. 표 값은 같은 히스토그램에서만 나온다.
- `maskToKeep`: `Uint32Array` 비트마스크의 비트 i가 1이면 `keep[i]=1`, 아니면 0인 길이 `rowCount` 배열을 만든다. `rowCount` 밖 비트는 무시한다.

### 4.2 차트 런타임(`apps/forensics/src/lib/replay/chart-runtime.ts`, 순수)


- `renderPlan(total, webgl2)`: `total <= 0`이면 `count=0`·`stride=1`이다. WebGL2가 있으면 `mode='webgl2'`·`count=total`·`stride=1`, 없으면 `mode='2d-sample'`·`count=min(total, 20000)`·`stride=total/count`(total이 2만 이하면 1)다.
- `samplePoints`는 `mode==='webgl2'`이거나 `count >= points.length`이면 받은 배열을 그대로 돌려준다. 아니면 `points[Math.floor(i * points.length / count)]`를 `i=0..count-1`만큼 모은다.
- `webgl2Available`은 `canvas`가 null이거나 `getContext`가 던지면 거짓, `getContext('webgl2')`가 null이 아니면 참이다. `map2dLabel()`은 `'이 기기는 표본으로 그립니다'`다.
- `logPosition(value, min=10, max=10000)`은 `(log10(value) - log10(min)) / (log10(max) - log10(min))`을 0~1로 자른다. 값이 유한하지 않거나 `min <= 0`·`max <= min`이면 `NaN`이다. `linearPosition(value, min=0, max=1)`은 같은 방식으로 자르고 유한하지 않으면 `NaN`이다. `scatterPosition(x,y)`는 `{u: logPosition(x), v: linearPosition(y)}`다. 축 밖 값은 가장자리 0·1로 그리되, 고르기·집계는 실제 값으로 한다.
- `SHARED_CLOCK_ENABLED`는 `false`다. 이 기능은 공유 시계를 더하지 않는다. `clockModeLabel(false)`는 `'복사 방식'`, `true`는 `'공유 메모리 켜짐'`이다. 화면은 늘 `clockModeLabel(SHARED_CLOCK_ENABLED)`를 쓴다.
- `candidateRequest`는 열 16개와 `keep`을 `slice()`로 복사하고, 복사본 버퍼 17개를 `transfer`에 담아 돌려준다. 메인의 원본 배열은 바꾸지 않는다. 보낸 쪽은 `postMessage(message, transfer)` 뒤 복사본을 다시 읽지 않는다.
- `decodeWorkerMessage`는 `kind`가 `candidate`·`candidate-done`·`error` 가운데 하나이고 `version`이 0 이상 정수일 때만 받는다. `candidate`는 `source` 셋, 열 16개가 모두 같은 길이의 형식 배열, 같은 길이의 `Uint8Array` `keep`을 요구한다. `candidate-done`은 `panel` 셋, `points.length === sessions.length * 2`, `bots.length === sessions.length`, 정수 `totalSessions`·`totalBots`, `bursts`의 다섯 수 필드, `histogram`이 null이거나 `edges.length === bins.length + 1`인 형식 배열일 때만 받는다. `error`는 200자 이하 문자열만 받는다. 그 밖은 null이고, 모르는 키는 무시한다.
- `candidateDoneBuffers`는 `points`·`sessions`·`bots`와 히스토그램이 있으면 `bins`·`edges`의 버퍼를 중복 없이 돌려준다. Worker는 이 목록을 `postMessage`의 전송 목록으로 넘긴다.
- `tick` 메시지와 차트 Worker는 이 기능에서 만들지 않는다. 재생 시각을 차트 Worker에 프레임마다 보내는 일은 뒤 몫이다(계획 §13.2).

## 8. 실패 시나리오와 엣지 케이스

1. **점이 없음**: 모든 세션의 `first_hold_ms`가 0이면 산점도는 비고, 세션 수·정밀도·재현율은 0이다. NaN을 내지 않는다.
2. **엔트로피 없음**: 합성에서 `entropy`가 NaN인 세션은 산점도 점에서 빠지고, 재현율 분모에서도 빠진다. 연구 원천은 엔트로피가 없어도 분포에는 들어간다.
3. **영역 경계**: `x0`·`y0`와 같은 점은 들고, `x1`·`y1`과 같은 점은 뺀다. 뒤집히거나 같은 영역은 빈 영역이다.
4. **분모 0**: 고른 영역에 세션이 없으면 정밀도 0, 그려진 봇이 없으면 재현율 0이다.
5. **사람 흉내 봇**: 세션 1,000개 미만 영역은 정밀도 검사에서 뺀다. 1,000개 이상 영역이 하나도 없으면 시험은 실패한다(시드·규모가 규칙을 못 만든 것).
6. **기기 묶음 경계**: 정확히 10ms는 포함, 11ms는 제외한다. 같은 좌석만 시도한 묶음은 0건이다. `device_group=0`은 보지 않는다.
7. **좌석 없음**: `seat=0xFFFFFFFF`인 `HOLD_TRY`는 점등·기기 묶음에서 뺀다.
8. **같은 세션 여러 행**: `sessionPoints`는 세션 하나를 한 번만 만들고, `first_hold_ms`는 가장 이른 값, `botTier`는 가장 큰 값, `deviceGroup`은 첫 0 아닌 값, `member`는 하나라도 1이면 참이다.
9. **버린 사건**: `keep=0` 행은 점·기기 묶음·좌석·기준선 어디에도 들어가지 않는다.
10. **연구 원천**: 점·기기 묶음·정밀도·재현율이 없고 한 축 분포만 있다. 교차 필터에 봇 등급이 있어도 후보 패널의 정답 계산에는 쓰지 않는다.
11. **조사 원천**: 봇 등급·엔트로피를 계정끼리 견주는 그림·표를 두지 않는다. 기준선은 `member=0` 여정의 1·50·99 백분위다.
12. **WebGL2 없음**: 2D 표본으로 그리고 안내를 보인다. 컨텍스트 생성이 던져도 2D로 간다. 표본 수는 2만을 넘지 않는다.
13. **Worker 없음·실패**: `new Worker`가 던지거나 `error` 메시지가 오면 메인 스레드의 `candidateModel`로 같은 값을 만든다. 모르는 메시지·판 번호가 다른 메시지·형이 틀린 메시지는 버린다.
14. **전송 버퍼**: 메인은 후보 계산용 열 복사본과 `keep` 복사본만 전송 목록으로 넘기고 원본은 그대로 둔다. Worker 응답의 점·세션·봇·히스토그램 버퍼도 전송 목록으로 넘긴다. 공유 메모리(`SharedArrayBuffer`)는 만들지 않는다.
15. **성능 값 없음**: 실제 측정이 없으면 `p95`는 null이고 상태 띠는 `0`이 아니라 `—`를 보이며 `filterOk`·`frameOk`는 거짓이다.
16. **표본과 집계**: 2D 표본은 그리기에만 쓰고, 영역 고르기·정밀도·재현율·좌석 점등은 전체 점으로 한다. 2.5만 점 영역의 집계는 2.5만이다.
17. **큰 입력**: 300만 행·10만 석에서도 표본 수는 2만이고, 배열을 복사해 두 배로 만들지 않는다. 실제 힙·프레임은 `미실행`이다.
18. **화면 이탈**: Worker를 `terminate()`하고, 고른 영역·점등·모델을 지운다. 저장소·URL·로그에 남기지 않는다.
19. **교차 필터**: 구역·결과·사건 종류를 바꾸면 `maskToKeep`가 만든 `keep`으로 후보 점·기기 묶음·정밀도를 다시 센다. 필터를 지우면 원래 집계로 돌아온다.

## 13. 미룬 것과 남는 위험

1. **FX-T5 실제 측정**: 기준 기기·GPU·브라우저·Worker 실측은 `미실행`이다. 이 기능은 판정 함수·2D 표본·복사 방식 구조만 시험으로 고정하고, 수치를 주장하지 않는다. 실제 측정은 동결 해제 뒤 구간 측정 창으로 넘긴다.
2. **FX-T6**: 복사 방식 성능 비교는 기능 표 장부 범위 밖이다. 공유 시계는 더하지 않았고, §3.3의 '더할 조건'은 측정 전이라 성립하지 않는다.
3. **FX-T7**: 2D 대체는 UI-11로 구현·시험하지만 장부 판정은 FX-T7이 아니다(기능 표 F-04-18 판정 칸에 없다). 동결을 풀 때 기능 표 범위를 다시 본다.
4. **실제 렌더링**: WebGL2 인스턴스 그리기·Canvas 2D·Worker 실행은 브라우저에서 확인하지 않았다. 소스 배선과 순수 모델까지다.
5. **axe·화면 낭독기**: 후보 패널의 표 보기·키보드 영역 고르기·axe 위반 0은 브라우저 확인 단계다. 이 기능은 `role`·`aria-label`·표 모델까지다.
6. **좌석 배치**: 리플레이 파일에 좌석 기하가 없어 좌석 번호 격자에 점등한다. 회차 좌석맵 판 연결은 F-04-18 뒤 정리 목록이다.
7. **사람 흉내 봇 시험 규모**: 단위 시험은 3,000세션 축소판이다. 실제 3만 세션 프리셋 생성·브라우저 표시는 `미실행`이다.
8. **F-04-19**: 연구 내보내기 `POST`·감사·`pseudonymization_log`·`an_forensic_reader`·용량 외삽은 이 기능이 부르지 않는다.
9. **`deploy/`**: S3 `/forensics/` 경로·CloudFront 캐시·COEP 값은 여전히 연결하지 않았다. 실제 배포에서 COEP가 빠질 수 있다.
10. **조사 원천 행동 값**: 세션 하나를 골랐을 때의 상세 행동 값은 F-04-17 화면에 아직 없다. 이 기능은 계정끼리 견주는 보기를 두지 않는 것까지만 고정한다.
11. **표본의 시각 정확성**: 2D 표본은 그리기만 하고 집계는 전체로 하므로 값은 정확하지만, 화면에서 점이 겹쳐 보일 수 있다. 실제 GPU 점 수·겹침은 브라우저 확인 몫이다.
12. **차트 Worker·재생 tick**: 이 기능은 후보 Worker만 만든다. 재생 시각을 차트 Worker에 프레임마다 보내는 일과 공유 시계는 뒤 몫이다. `tick` API를 이 기능에서 만들지 않아 죽은 API가 없다.
13. **교차 필터 연결**: `ReplayFilters`의 필터 상태를 `ReplayMain`으로 올리는 작은 리팩터가 구현에 든다. F-04-17의 화면 시험은 상태 위치를 보지 않아 그대로 통과해야 한다.
