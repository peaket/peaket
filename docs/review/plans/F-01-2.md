## 감독에게

막는 물음은 없다. 아래 1·2는 추천대로 계획을 세웠다. 다르게 정하면 이 계획과 ADR-0356을 고친다.

1. **[결정 요청, 범위 밖] 브라우저 Sentry SDK를 맡을 기능이 없다.** observability.md:635와 frontend.md §5.16 '오류 도구'는 대기실 경량 페이지를 뺀 앱에 브라우저 SDK를 싣고 같은 출처 터널 `/_t/err`로 보낸다고 정했지만, 어느 WBS 단계·기능에도 이 일이 없다. V-T39가 서버와 브라우저를 한 행으로 묶고 있어 ①②③으로 나눴다(이 커밋).
   - (가) **(추천)** F-01-2는 서버(V-T39 ①)와 최소 판 검사(③)만 한다. ②는 ledger-notes에 '다른 단계, 미정'으로 두고(이 커밋), 감독이 화면 영역 기능(예: F-08의 프론트 성능 기능이나 F-03 콘솔 기능)에 붙이거나 새 기능으로 더한다. 첫 JS 예산(frontend.md §5.8 '관측 라이브러리의 몫')을 함께 재야 해 화면 기능이 맞다.
   - (나) F-01-2에 브라우저 SDK를 넣는다: `apps/web`·`apps/partner`·관제 콘솔·스캐너와 `/_t/err` 터널, 첫 JS 예산을 이 기능에서 다룬다. +1.5~2일 [가정]이라 5일 상한에 닿아 기능을 나눠야 한다.
2. **[확인] 오류 요약 가져오는 방식은 정했고, 확인은 넘긴다.** WBS 4.1.3의 '무료 등급 API 범위 확인'과 'GlitchTip API 범위 확인·C-T30 연결 시험 대상 판단'은 Sentry 계정이나 서버 설치가 필요하다. ADR-0356 결정 6으로 방식(ops-svc가 Sentry 호환 웹 API를 1분 [가정]마다 읽음)만 정하고, 확인은 OPS-520(F-08-15, 문서 인용 판정)에, 어댑터와 C-T30은 OPS-380(F-03-3)에 넘긴다. F-08-15·F-03-3 기능 행의 비고에 한 줄씩 더해 달라(기록 커밋에서 감독 몫).
3. **[알림] OPS-040·OPS-050 체크와 넘기는 것.** 이 기능은 배포 쪽을 만들지 않는다(ADR-0331 결정 9, ADR-0332 결정 5). 기록 커밋에서 두 단계 줄을 체크하고, INF-020 줄 끝에 넘겨받은 것(SSO 신원 공급자 연결, 조직·팀 적용의 운영 방식, Loki 데이터 소스와 온세일 주석 실제 표시, Mimir 모놀리식 배치)을, INF-040에 V-T47 ⑥을 적어 달라(BAT-215와 같은 꼴).
4. **[알림] 생성 파일 경로가 바뀐다.** 대시보드 파일이 `deploy/local/dashboards/<폴더>/<이름>.json`으로 내려간다(ADR-0356 결정 1). 생성 파일 편집을 막는 훅 규칙(`tools/claude-hooks/edit-rules.mjs:12`)은 구현 담당이 같은 구현 커밋에서 하위 폴더까지 막게 고친다. CLAUDE.md의 '로컬 대시보드(`node tools/local/dashboards.mjs`)' 문구는 그대로 맞으므로 고치지 않는다.
5. 새 ADR은 0356 하나(0357·0358은 갈래 1의 다음 기능 몫으로 비워 둔다). 마이그레이션 없음.

### 3. 바른 동작과 근거(값은 정본에서 읽는다)

- **대시보드**: 첫 행 네 신호와 둘째 행은 지금 생성기 그대로(observability.md:264). 대상은 architecture.md §3.1 표의 첫 칸, 폴더는 CODEOWNERS의 `/services/<서비스>/` 줄의 팀(가장 아래 맞는 줄), `example-svc`·`v0-monolith`은 `/services/` 기본 줄의 팀. 온세일 공용 대시보드의 주석 셋은 observability.md:125, 운영 사건 줄은 §7의 `ops_event` 행. 화면 고침 저장 안 함은 :601.
- **조직**: 조직 둘·데이터 소스 배치·역할은 :598~602. 제한 조직의 데이터 소스는 PostgreSQL 쿼리 문장(읽기 전용 모니터링 계정, ADR-0067)뿐이다(:600). 로컬에는 Loki·Tempo·Pyroscope·Mimir가 없으므로 로컬 프로비저닝에는 Prometheus와 제한 조직의 PostgreSQL만 싣고, 운영 판의 나머지 데이터 소스는 같은 파일에 운영 판으로 적되 로컬 ConfigMap에서 뺀다 [추천]. 구현 담당이 그 가르는 방법(파일 둘 또는 환경 표시)을 '구현 메모'에 적는다.
- **보존·원격 쓰기**: 테넌트와 보존 값은 :573. 5분 집계 기록 규칙의 평가 간격은 :330. 골라 보내기는 ADR-0077·ADR-0356 결정 3. 28일 예산 규칙은 만들지 않는다(OPS-090).
- **서버 SDK 잠금**: 끄는 값·거름·마스킹·`accountRef`는 :635. 최소 판·같은 판은 devops.md:306. 마스킹 함수는 `packages/platform/src/log.ts`의 `redactDeep`(§7과 같은 가림). `accountRef`는 요청 상태의 `refs.accountRef`(`request-log.ts:45`). 보내는 범위·빈 DSN·종료 2초 [가정]·OpenTelemetry 겹치지 않기는 ADR-0356 결정 4. 받는 곳이 멈춰도 앱을 기다리게 하지 않는다(:642). 추적 전파 헤더를 바깥 호출에 싣지 않는 규칙(guidelines §8 첫 문단, V-T31 ③)은 SDK를 켠 뒤에도 그대로다. Sentry SDK의 HTTP·fetch 자동 계측은 바깥 요청에 `sentry-trace`·`baggage`를 실으므로 켜지 않는다.
- **최소 판 검사**: 읽는 줄은 devops.md:305~307, 판 비교는 숫자 마디(ADR-0356 결정 5).

### 10. 자주 놓친 결함(docs/architecture.md:1168~1182에서 고름, 시험·구현 지시문에 넣는다)

- 허용·거부 목록은 목록 밖 값마다 거부를 본다: 본문·쿠키·쿼리·IP 넷을 따로 단언하고, 데이터 소스 배치는 기본 조직의 데이터 소스와 대시보드 두 길 모두 본다.
- 판 번호는 두 자리 마디(9 → 10, 57 → 100)까지 넣어 글자 비교 결함을 잡는다. 시험 값은 코드 상수가 아니라 정본에서 적는다(보존 값, 최소 판).
- 판정 함수만 보지 말고 부르는 쪽을 본다: `capture`만이 아니라 `createService`로 띄운 서비스의 실제 5xx 경로, 검사 함수만이 아니라 CLI 끝 코드.
- 빈 결과가 통과로 새지 않게 한다: 대상 서비스 0개, 수신 사건 0개, 읽은 잠금 파일 0줄이면 실패다.
- 시작 조립(`createService` 안 SDK 켜기)은 시험 조립과 따로 띄워 본다(identity-svc를 DSN만 바꿔 띄우는 통합 시험 하나, 무거우면 정리 목록).

### 12. 범위 밖과 막힘

- **막힘(외부 계정)**: Sentry 조직과 실제 DSN(ADR-0139 결정 3, OPS-520 판정 뒤), Sentry 무료 등급 API 범위 확인(계정 필요, OPS-520), Grafana SSO 신원 공급자 연결(IAM Identity Center 같은 계정, INF-020). 이 기능은 가짜 수신기와 가짜 Grafana API로 대신 본다.
- **구간 5(INF-020·INF-040)**: 실제 Grafana·Mimir·Loki에 올린 확인(V-T47 ⑥), 조직·팀 적용의 운영 방식, Mimir 모놀리식 배치와 테넌트 보존 확인(ADR-0120), 온세일 주석의 실제 표시, 운영 판 데이터 소스 연결.
