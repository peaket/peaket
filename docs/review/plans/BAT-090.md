# BAT-090 계획 — 자동 좌석 배정(HOT-080) + 구매 세션 소지 증명 마무리(BOT-100)

- 작성: 2026-11-13
- 묶음: BAT-090(HOT-080·BOT-100, 갈래 1, 구간 2, **A등급**, 4.75일)
- 장부 범위: `S-T16`, `S-T19`, `S-T20`, `docs/features/seat-hold.md`, `docs/security/asvs/seat-hold.md`
- 선행: FND-100·PRF-110·PRF-136·PRF-137 모두 `develop`에 있음(`[x]` 확인). BAT-157의 판매 정책 평가(BAT-051)는 `salePolicy` 원천이 없어 보류라 이 묶음과 분리한다.
- 웨이브: `wave/lane1-BAT-090`, `origin/develop` `3d4c4943`에서 시작. R-518.

## 1. 목표

- HOT-080: 자동 배정 희망 조건(`auto`)을 받아 1순위 연석 → (분리 허용 시) 1순위 분리 → 2순위 연석 → 2순위 분리 차례로 같은 Lua에서 찾아 홀드한다. 후보가 없으면 아무 좌석도 잡지 않고 409 `manual-selection-required`다.
- BOT-100: 서버 ECDH 키 교체(옛 키 함께 허용)와 구매 세션 탈취 재현·판정을 넣는다. 1ms 측정은 무거운 게이트로 미룬다.

## 2. 구현

### HOT-080

- `domain/auto.ts`: `AutoCondition`·`AutoAssignResult`·`AutoCandidateGroup`·`AutoCandidateList`, 멱등 지문 `autoFingerprint`, 희망 조건 검사 `autoConditionProblem`, 후보 만들기 `autoCandidatesOf`(구역 차례·구역 안 거리 차례, 휠체어 필터, 연석/분리/2순위).
- `adapters/auto-hold-lua.ts`: 페이지의 후보 묶음을 한 Lua에서 비트·`rel`·보유 수로 보고, 처음 맞는 묶음을 홀드한다. `auto_cur` 커서, 멱등 기록 `seats`·`assign`, Stream HELD·구역 델타·펜싱·만료·보유 수를 직접 선택과 같은 규칙으로 쓴다.
- `SeatStore.holdAuto`·`autoCursor`의 Redis(`redis-seat-store.ts`)·메모리(`memory-seat-store.ts`) 구현.
- `SeatMapAuto` 포트와 `LayoutSeatMap`·`MemorySeatMap` 구현(후보 목록은 판마다 한 번 캐시).
- `HoldSeats` auto 경로: 설정·판매 종료·희망 조건 검사 → 커서부터 4페이지 → `holdAuto` → 201 `assignResult`/`seatIds` 또는 409 `manual-selection-required`. 시도 기록 `mode: 'AUTO'`.
- 자동 배정 공연은 스냅샷을 받지 않으므로 첫 홀드 요청이 본문 `clientEphemeralPublicKey`로 구매 세션을 연다(`StoredPurchaseSessions.openFirstUse` → `OpenPurchaseSession`).
- 오류: `AUTO_AND_SEATS`(400), `AUTO_TIER_UNKNOWN`(400), `AUTO_CONDITION_INVALID`(422), `MANUAL_SELECTION_REQUIRED`(409). OpenAPI 문제 유형 `auto-condition-invalid`·`invalid-auto-condition`을 더한다.

### BOT-100

- `ServerEcdhKey`에 옛 키(`PEAKET_PURCHASE_ECDH_KEY_PREV`)와 `sharedSecrets`를 더한다. kid가 같으면 시작하지 않는다.
- `StoredPurchaseSessions.resolve`가 현재·옛 키의 요청 인증 키를 모두 넘기고, `verifyPurchaseRequest`가 그 가운데 하나라도 맞으면 통과한다.
- `test/purchase-session-theft.test.ts`: jti를 훔쳐도 키가 없으면 MAC 불일치, 같은 서명 재전송은 replay, 옛 키로 서명한 요청은 통과, 공격자 키는 거절을 단위 시험으로 고정한다.
- 1ms 측정은 `heavy gate go` 뒤로 미룬다.
