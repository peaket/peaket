## 1. 목표

- HOT-080: 자동 배정 희망 조건(`auto`)을 받아 1순위 연석 → (분리 허용 시) 1순위 분리 → 2순위 연석 → 2순위 분리 차례로 같은 Lua에서 찾아 홀드한다. 후보가 없으면 아무 좌석도 잡지 않고 409 `manual-selection-required`다.
- BOT-100: 서버 ECDH 키 교체(옛 키 함께 허용)와 구매 세션 탈취 재현·판정을 넣는다. 1ms 측정은 무거운 게이트로 미룬다.

## 2. 구현

- `adapters/auto-hold-lua.ts`: 페이지의 후보 묶음을 한 Lua에서 비트·`rel`·보유 수로 보고, 처음 맞는 묶음을 홀드한다. `auto_cur` 커서, 멱등 기록 `seats`·`assign`, Stream HELD·구역 델타·펜싱·만료·보유 수를 직접 선택과 같은 규칙으로 쓴다.
- `SeatStore.holdAuto`·`autoCursor`의 Redis(`redis-seat-store.ts`)·메모리(`memory-seat-store.ts`) 구현.
- `SeatMapAuto` 포트와 `LayoutSeatMap`·`MemorySeatMap` 구현(후보 목록은 판마다 한 번 캐시).

## 4. 알려진 차이·다음

- 후보 목록은 지금 판에서 메모리로 만든다. `s:{event:E}:auto:{tier}:{n}` Redis 목록과 `s:{event:E}:auto_back:{tier}` 돌아온 좌석 우선은 LCH-080 판매 열기·해제 경로를 붙일 때 더한다(지금은 `auto_cur`가 목록을 한 바퀴 돌아 돌아온 좌석도 찾는다).
- **S-T16 ② 1ms는 미달**이다. 반복 측정에서 전체 p99 9.7101ms, Redis 제외 3.8070ms, MAC만 1.1281ms였다. 요청 파싱·타이밍 비교·할당을 줄이고 세션 조회를 파이프라인·로컬 캐시로 줄이는 후속 작업이 필요하다.
- **S-T19 문자 그대로 1,000건 동시는 미달**이다. 로컬 단일 Valkey 100ms 마감에서 전부 503이었다. 100 동시×10묶음은 1,000/1,000 성공·중복 0으로 통과했다. 실제 1,000 동시를 판정하려면 다중 샤드·연결 풀·입장 제어가 있는 무대가 필요하다.
- 503 마감 뒤 완료된 Lua의 홀드는 남을 수 있다. 같은 멱등 키 재시도가 `IDEM_REPLAY`로 흡수하지만, 새 키로 재시도하면 좌석이 묶인 채 남는다. API 문서에 재시도 규약을 명시한다.
- BAT-050은 HOT-160 발권만, BAT-052(HOT-090)는 새 서비스 선행으로 보류, BAT-051은 LCH-080 전 보류.
