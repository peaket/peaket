# 작업 계획: W11-rtgw-flake(realtime-gw Degraded 시험의 벽시계 한도 넘김)

- **무엇**: 갈래 2 PR #32 CI(실행 44401816769, `node / node` 잡)에서 `services/realtime-gw/test/degraded.test.ts:178` 'S-T14 ① RF-T6 …'이 `Error: Test timed out in 5000ms`로 실패했다(vitest 기본 시험 한도). 판정 단언이 아니라 계산이 느린 러너에서 벽시계 5초를 넘긴 것이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane4-flake`(가지 `feature/lane4-W11-rtgw-flake`, 출발점 `origin/develop` `a1900dc6`). 시험은 `pnpm --filter @peaket/realtime-gw test`(단위, vitest).
- **등급·차례**: C, 시험만 묶음(`Batch-Kind: test-only`): 계획 → 시험(실패 확인을 같은 커밋) → 리뷰 → 검증 → 기록. 제품 코드(`services/realtime-gw/src/`)는 고치지 않는다.
- **정본(바꾸지 않음)**: ADR-0298, `docs/features/seat-hold.md` §12 S-T14 ①~③의 경계(256KiB·64KiB·1MiB, 51/50·26/25ms, a × 100 > n)·창 수(18·30)·차례 수(30)·바이트. 시나리오(RF-T1~T14)는 BAT-053 계획 '리뷰 반영 계획' 표.

## 계획

### 1. 원인 분석(잰 값)

- 잰 방법: 작업 폴더에서 `npx vitest run test/degraded.test.ts --reporter=json`을 세 번(이 PC, 32스레드) 돌려 시험별 `duration`을 읽었다. CI 값은 실패한 잡 기록의 시험별 시간이다. 단계별 몫은 시험 파일을 임시로 복사해 `publish`(시험 쪽 메시지 만들기 + 허브가 받아 쌓기)·`h.hub.tick()`(박자)·`intervals`/`deltaCount`(보낸 프레임 전부 해독)를 `performance.now()`로 감싸 쟀다(복사본은 지웠다).

- 파일 전체: 로컬 약 1.1초, CI 14,282ms(시험 24개). CI는 같은 시험이 로컬보다 **약 11~25배** 느렸다(RF-T9 2,416/225 ≈ 11배, RF-T6 5,783/229 ≈ 25배). turbo가 여러 꾸러미 시험을 한 러너에서 함께 돌리기 때문으로 본다.
- 원인: RF-T6은 박자 수가 아니라 **박자마다 3,400좌석 메시지를 새로 만들고(좌석 배열 3,400개 + JSON 약 40KB) 허브가 그것을 받아 쌓는 일**이 시간의 9할이다. RF-T4는 연결 100개의 보낸 프레임을 `intervals`로 **전부 해독**하는 데 4할을 쓴다. RF-T9·RF-T1은 메시지 수(박자마다 10개)가 크다.

### 2. 고칠 시험과 방법

- 손댈 파일은 `services/realtime-gw/test/degraded.test.ts` 하나다(시험 담당). `test/hub-fixtures.ts`는 다른 시험 파일(`hub.test.ts` 등)도 쓰므로 고치지 않는다. 꼭 고쳐야 하면 '시험 이의'로 올린다.
- **바꾸지 않는 것**: 판정 경계·창 수·차례 수·바이트(위 '정본'), 시나리오의 박자 시각·박자 수·창 수·연결 수·박자마다 메시지 수·메시지마다 좌석 수(RF-T6의 3,400좌석 = 10,208B, 300KiB/s, 한 번 더하는 300KiB), 단언 값(`degradedChanges`의 `batches`·`overEnter`·`overExit`·`ticks`, n·a·b, 게이지 값)과 시험 이름. 메시지 수나 박자를 줄이면 n(창의 묶음 수)과 M24(되돌림 표본을 박자마다 봄)를 잡는 '차례가 아닌 박자의 큰 버퍼'가 바뀌므로 줄이지 않는다.
- ① 계산량 줄이기(먼저 한다)

- ② 벽시계 한도 명시(①을 한 뒤에도 모자랄 때만, 그 시험에만): ①을 한 뒤 로컬 중앙값(JSON 보고서 다섯 번)이 **80ms 이상**인 시험에만 `test(이름, 몸, 30_000)`처럼 셋째 인자로 한도 30,000ms를 준다(`test.each`는 같은 자리). 30,000ms는 CI 최대 관측 5,783ms(한도에 끊긴 값)의 5배쯤이고, 25배 배율이면 로컬 1,200ms까지 견딘다. 파일·설정 전체 한도(`testTimeout`)는 올리지 않는다(다른 시험의 멈춤을 늦게 알게 되므로). 한도를 준 시험 옆에 '가짜 시계로 박자 N개를 돌려 느린 CI 러너에서 5초를 넘은 적이 있다(W11-rtgw-flake)'는 주석을 단다.

### 3. 실패 확인 방법(느린 조건 흉내)

- 로컬은 CI보다 11~25배 빨라 기본 한도로는 실패가 나지 않는다. 그래서 **한도를 줄여 느린 러너를 흉내 낸다**.
  1. 고치기 전(`a1900dc6` 그대로): `npx vitest run test/degraded.test.ts -t "RF-T6" --testTimeout=<X>`를 다섯 번. X는 고치기 전 RF-T6 최솟값의 0.7배쯤(지금 재면 약 160ms)으로 정해 적는다. 다섯 번 모두 `Test timed out in <X>ms`로 실패해야 한다. RF-T4(X는 그 시험 최솟값의 0.7배)도 같은 꼴로 본다.
  2. ①만 한 뒤(②를 넣기 전): 같은 X로 다섯 번 모두 통과해야 한다. 통과하지 못하면 ① 효과가 그만큼이 못 되는 것이니, 고치기 전·후 중앙값(JSON 보고서 다섯 번씩)을 표로 적고 ②로 간다.
  3. ②를 넣은 뒤: `npx vitest run test/degraded.test.ts --testTimeout=50`(일부러 아주 작게)에서 한도를 준 시험은 통과하고(시험별 한도가 설정 한도를 이긴다는 확인), 한도를 주지 않은 시험만 넘김으로 떨어짐을 본다. 그다음 기본 설정 `pnpm --filter @peaket/realtime-gw test`로 꾸러미 시험 전체가 통과해야 한다.
- 덧붙여 해 볼 것(필수 아님): 이 PC 스레드 수만큼 `node -e "for(;;){}"`를 띄워 CPU를 막고 기본 한도로 파일을 다섯 번 돌려 시간을 적는다(실패 재현을 기대하지는 않는다. 배율만 적는다). 띄운 것은 끝나고 모두 끈다.

## 실패 확인

- 시험 담당(w11fl-test-8b16)이 이 PC(32스레드)에서 했다. 고치기 전은 머리 `275e2d38`의 `degraded.test.ts`(시험 파일은 출발점 `a1900dc6`과 같다)를 임시로 보관해 두고 바꿔 끼워 돌렸다(끝나고 고친 파일로 되돌려 `git diff`로 확인).
- 명령: 지시의 `pnpm --filter @peaket/realtime-gw test -- -t "RF-T6" --testTimeout=<X>`는 pnpm이 `--`를 vitest에 그대로 넘겨 `-t`가 먹지 않았다(5번 모두 꾸러미 86개가 기본 한도로 돌아 통과). 그래서 `--` 없이 `pnpm --filter @peaket/realtime-gw test -t "<이름>" --testTimeout=<X>`로 돌렸다(그 시험 하나만 돌고 85개는 건너뜀).
- X: 계획대로 '고치기 전 최솟값의 0.7배'를 파일 전체 실행(JSON 보고서 다섯 번)의 최솟값으로 잡았다. RF-T6 222ms → **X = 155**, RF-T4 88ms → **X = 62**. 그런데 `-t`로 한 시험만 돌리면 그 시험이 첫 시험이라 데워지지 않아 훨씬 느리다(따로 잰 한 시험만 실행 시간, JSON 다섯 번: RF-T6 고치기 전 715~2,052ms·중앙값 923 → ① 뒤 140~347·146, RF-T4 고치기 전 379~825·628 → ① 뒤 200~364·263). 그래서 한 시험만 실행 기준 X(RF-T6 500, RF-T4 265)로도 덧붙여 돌렸다. 이 X들은 아래 둘째 표이고, 그때 PC에 다른 세션 부하가 있어 흔들렸다.

- 덧붙여 해 볼 것(CPU 막기)은 하지 않았다. 대신 다른 세션 부하가 있던 때의 재기('시험 결과' 둘째 표)가 느린 러너의 배율 꼴을 보여 준다.

## 시험 결과
