# 기능 계획: F-08-7(관제 데모 영상·안내·RFC 정리·블로그 목차)

- **진행**: 계획 끝(2026-11-24). 다음은 검수 대본(시험) → 구현(영상·문서) → 검수 → 기록. 이 커밋은 계획만이고 영상·RFC 본문·블로그 글·제품 코드는 쓰지 않았다.
- **무엇**: BUILD_ORDER '기능 단위 계획' F-08-7(갈래 5, 등급 C, LCH-350, WBS 1.50일, 단계 줄 `LCH-350 wbs 7.6.1`)의 작업 목록이다. 판정 문장은 "관제 데모 영상·안내·RFC 정리·블로그 목차가 나온다"이고, 장부 범위는 `-`다(11-24 `node tools/ci/ledger.mjs --batch F-08-7` → 항목 0·빈칸 0). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **쉬운 말**: 이 기능은 코드를 만드는 일이 아니라 **보여 주고 설명하는 일**이다. ① 실제 화면을 돌려 관제 장면을 영상으로 남기고 ② 새로 온 사람이 저장소에서 첫걸음을 뗄 수 있는 안내를 쓰고 ③ 이미 있는 RFC 초안 3건을 지금 정본과 대조해 낡은 곳을 고치고 ④ 앞으로 쓸 블로그 10편의 목차를 정리한다. 여기서 'RFC'는 구현 전에 방향과 한계를 같은 말로 맞추는 설명서 초안이고, '블로그 목차'는 글을 쓰는 것이 아니라 무엇을 어떤 근거로 쓸지 차례를 정하는 표다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane5-F-08-7-plan`, 가지 `feature/lane5-F-08-7-plan`, 기준 `origin/develop` `073dc18c3`. 그 뒤 origin/develop이 `c3175c7b5`(월렛 첫 JS 기준선 시험) 한 커밋 앞섰고 이 기능과 닿지 않는다. 계획 담당은 Docker·kind·demo·영상 촬영을 하지 않았다.
- **차례(ADR-0373 결정 3, C등급)**: 계획 → 검수 대본(시험) → 구현(영상·문서) → 검수 → 기록. 시험 리뷰·구현 리뷰·틀린 구현 표본은 없다(ADR-0372·ADR-0331 결정 4). C등급은 화면 비교(시각 회귀)와 문서 점검으로 증명한다. 시험 담당과 구현 담당은 나누고 구현 담당은 시험(검수 대본)을 고치지 못한다.
- **한 줄 결론**: 네 산출물 모두 제품 코드를 바꾸지 않아 자동 시험이 붙지 않는다. 그래서 수용 기준을 **명령 실행 기록·장면표·정본 대조표·숫자 카드**로 바꿔 검수한다. 1.5일 가운데 촬영 0.5일, 문서 셋 0.75일, 검수·기록 0.25일로 잡고, 12-02 아침에 선행 입력이 비어 있으면 §8 규칙대로 범위를 줄인다.

## 2. 감독에게

1. **안내 문서의 자리와 이름(정할 것)** — 추천은 `docs` 폴더에 `onboarding.md`를 새로 두는 것이다(예정). `docs/00-summary.md` §2는 독자별 지도라 새로 온 사람의 첫날 순서를 담기에는 넓다. 다른 안을 고르면 그 자리를 이 계획에 적고 doc-check 경로를 맞춘다.
2. **영상의 형태(정할 것)** — 추천은 **촬영본 + 장면 대본·내레이션 문안**까지다. 편집·자막·음성 녹음·게시는 소유자 몫으로 남긴다(외부 게시는 소유자 결정, `docs/architecture.md` §8.6 '맡기기'). 1.5일 안에 편집까지 하면 문서 셋이 밀린다.
3. **영상 범위(정할 것)** — 추천은 S7(관제)을 필수로, S1(팬 흐름)을 10~20초 도입으로, S9(회차 취소·배상)는 시간이 남을 때만 넣는 것이다. F-07-8이 넘긴 SCR-047 확정→진행률 장면은 S9에 들어간다.
4. **영상 파일 보관·게시(정할 것)** — 추천은 저장소에 영상 파일을 커밋하지 않고(큰 이진 파일·개인정보·제3자 표시 위험), 저장 위치·길이·SHA-256·장면표만 측정 기록에 남기는 것이다. 게시·공유는 소유자가 한다.
5. **RFC 정리의 뜻(정할 것)** — 추천은 기존 초안 3건의 정본 대조·갱신과 README 상태 갱신까지다. 새 RFC를 더 쓰지 않는다(1.5일 범위).
6. **블로그 목차의 자리(정할 것)** — 추천은 `docs/blog/README.md`의 표를 10편 목차로 넓히고(이미 10편 표가 있다) 각 행에 근거·정본 자리·상태·순서를 더하는 것이다. 별도 파일을 만들지 않는다.
7. **WBS 7.6.1의 다섯째 산출물 'ADR 점검'** — F-08-7 줄의 판정 문장에는 없다. 추천은 안내 문서에 "ADR 읽는 길" 한 절( `docs/architecture.md` §11 목록과 실제 347건의 차이는 목록으로만 남김)을 두고, 전수 색인 정리는 하지 않는 것이다. 기능 표에 넣으려면 감독이 F-08-7 줄을 고친다.
8. **선행이 늦을 때(정할 것)** — 12-01 확인에서 F-08-2·F-08-8 보고서나 데모 S1·콘솔 장면이 비면, 12-02 아침에 §8 규칙대로 범위를 줄인다. 그래도 "네 산출물"을 다 채워야 하면 기한을 넘기므로 감독이 12-01에 판단한다.

## 3. 범위

### 3.1 하는 것

- **관제 데모 영상**: 실제 로컬 데모 무대에서 S1(팬 흐름, 도입)과 S7(T=0 관제)을 재생해 화면을 녹화하고, 장면표(시각·화면 번호·무엇을 보여 주는가·판정 check)와 내레이션 문안을 쓴다. S9(회차 취소·배상)는 시간이 남을 때만 넣는다. 영상에 쓰는 숫자는 §6.3 숫자 카드로 제한한다.

- **RFC 정리**: 초안 3건(온세일 핫패스·봇 방어·관제)을 지금 정본과 대조해 바뀐 사실·링크·상태를 고치고, README 표의 상태를 갱신한다. 새 결정·새 숫자를 만들지 않는다.
- **블로그 목차**: `docs/planning/01-overview.md` §3.3의 10편(M0 1·M1 1·M2 3·M3 1·M4 2·M5 1·M6 1)을 제목·질문·근거·정본 자리·상태·순서·분량으로 정리한다. 초안 2편(M0·M1)과 나머지 8편의 상태를 구분한다.

## 5. 산출물과 수용 기준

- **개인정보**: 데모 계정은 합성이다. 영상에는 합성 이름·가상 티켓만 나오고, 실제 개인정보·연락처·결제수단·비밀 값은 쓰지 않는다(`docs/planning/03-policies-glossary.md` POL-023, `docs/verification.md` §7, V-T7 ⑥ '비밀·토큰을 출력·측정에 싣지 않는다').
- **라이선스**: 폰트·아이콘은 저장소 것이고, 화면에 우연히 나오는 제3자 표시는 클로즈업하지 않는다. 외부 음악·이미지·영상을 넣지 않는다.
- **화면 노출**: 브라우저 개발자 도구·주소창의 토큰·다른 갈래의 시험 화면·비밀 환경 값이 나오지 않게 한다. 데모 전용 배너·가짜 API 표시는 사실대로 나와도 된다.

## 9. 완료의 정의

1. 네 산출물이 정해진 자리에 있다: 영상 파일+장면표+대본, 안내 문서, RFC 3건 수정+README, 블로그 10편 목차+README.
2. §5의 A1~A8·B1~B9·C1~C7·D1~D7이 모두 통과했거나, 미통과·미확인은 까닭과 함께 적혀 있고 통과로 세지 않았다.
3. `python tools/doc-check/check_all.py` 오류 0, `node tools/local/demo.mjs plan --check` 통과, `play --scenarios S1,S7` 통과.
4. 숫자 카드 밖의 숫자가 영상·블로그·RFC에 없다(대조 기록).
5. 개인정보·비밀·제3자 표시 금지 목록이 0이다(기록).
6. 12-01 선행 확인 기록과 12-02 아침 결정(줄이기 포함)이 이 파일에 있다.
7. 담당 표에 계획·시험·구현 세션과 시각이 다르게 적혀 있다. C등급이라 시험 리뷰·구현 리뷰·틀린 구현 검사는 없다.
8. `docs/lanes/lane5.md`에 계획·구현·검수 사실 한 줄이 있고, LCH-350 단계 줄은 기록 커밋에서 갈래 5가 체크하며, 기능 표 상태 칸은 감독이 맞춘다.
9. 영상 파일은 저장소에 커밋하지 않았고, 저장 위치·길이·SHA-256·장면표가 측정 기록에 있다.

## 10. 남는 위험

- **측정 결과 의존**: F-08-2·F-08-8 보고서가 11-28에 늦거나 V-T4가 판정되지 않으면 영상·블로그의 핵심 숫자가 빠진다. 그때는 '100만'을 말하지 않는 것이 맞지만, 포트폴리오 산출물의 설득력은 떨어진다.
- **콘솔·rt 의존**: 갈래 2의 F-03-4와 갈래 6의 rt 사슬이 12-01에 확인되지 않으면 관제 영상의 핵심 장면(명령·ack·실시간 표)이 빠진다. 데모는 팬 흐름만 남는다.
- **영상 품질**: 재생기 영상은 계정·맥락별 webm이라 한 편으로 이어지지 않는다. 편집·내레이션은 소유자 몫이라, 이 기능만으로는 "올릴 수 있는 완성 영상"이 아니라 "촬영본과 대본"이다. 감독이 편집까지 원하면 일정이 늘어난다.
- **문서 구조 결정**: 안내 문서의 자리·이름을 감독이 다르게 정하면 링크·doc-check를 다시 맞춰야 한다.
- **ADR 색인**: WBS 7.6.1의 'ADR 점검'을 하지 않으면 아직 남은 항목이다. 안내 문서의 한 절로만 다루므로 전수 색인은 여전히 비어 있다.
- **날짜 고정 시험**: 12-02·03에 CI 통합 시험이 빨개질 수 있다. 이 기능은 문서만이라 막지 않지만, 같은 날 검수 기록에 CI 빨강이 섞이면 원인을 구분해 적어야 한다.
- **개인정보·라이선스**: 합성 데이터라도 화면에 이름·QR·금액이 나온다. 게시 전 소유자 확인이 필요하고, 제3자 표시가 클로즈업되면 다시 찍어야 한다.

## 11. 검수 명령과 장부·시험 ID가 없는 자리

| 무엇 | 명령·자리 | 이 기능에서 |
| --- | --- | --- |
| 장부 | `node tools/ci/ledger.mjs --batch F-08-7` | 항목 0·빈칸 0(11-24 확인). 게이트가 아니라 기록이다 |
| 시험 ID | 없음 | trace-check를 부르지 않는다. 판정 문장이 시험 ID를 갖지 않는다 |
| 문서 점검 | `python -I -X utf8 tools/doc-check/check_all.py` | 오류 0이 게이트다 |
| 데모 장면 | `node tools/local/demo.mjs plan --check` | S1~S9 정의와 d5 §10.6 대조 |
| 데모 재생 | `node tools/local/demo.mjs play --scenarios S1,S7` | 결과 통과·check 통과가 A1~A3 |
| 안내 문서 명령 | 새 PowerShell에서 순서대로 | B7 |
| 새 세션 확인 | 안내만 보고 demo S1 | B8 |
| 숫자·PII·라이선스 | §6.3 카드·§8 금지 목록과 대조 | A5·A6·C3·C7 |

- C등급이라 틀린 구현 표본·구현 전 실패 확인은 하지 않는다(ADR-0331 결정 4). 시험 담당은 §5의 기준을 검수 대본으로 옮기고, 기준 트리에서 실행 가능한 검사(doc-check·`plan --check`·링크)를 돌려 지금 상태를 적는다. 산출물이 없어 확인할 수 없는 항목은 "구현 전 확인 불가"로 적는다.
- 브라우저 확인은 따로 하지 않는다. 영상이 화면 증거이고, 영상 검수(A2·A3)가 그 몫을 한다.
