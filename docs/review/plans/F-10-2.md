## 감독에게

막는 물음은 없다. 1~3은 확인, 4~5는 알림이다.

1. **[확인] 동결 로컬 범위.** F-10-2는 v1 출시 범위 밖이다(ADR-0386). 이 계획은 로컬 설정·단위 시험·Docker 통합 시험까지다. `deploy/`에 image-worker의 **동결 무대 값**과 정책 시험용 IRSA 정책 문서를 더하지만, 출시 환경 값·Argo CD·Helm 릴리스·Terraform·실제 AWS 계정은 건드리지 않는다. `docs/release/v1-scope.*`의 분류는 바꾸지 않는다(BUILD_ORDER 상태 `동결` 그대로).
2. **[확인] 장부 범위를 좁힌다.** F-10-2 줄의 `docs/frontend.md`는 화면 변경이 없어 범위에서 뺀다. `docs/security/asvs/catalog-review.md` 전체(212항목) 대신 image-worker가 닿는 행 16개만 남긴다. 지시서에 적힌 기능 설계서 이름의 파일은 저장소에 없다. 실제 정본은 `docs/security/asvs/catalog-review.md`와 `docs/data.md`다.
3. **[확인] 마이그레이션 번호 0050.** core-svc는 0047까지 있고, 다른 동결 가지가 0048(`wish_list_read`·`ops_sale_review_linkage`)·0049(`search_card_badges`·`event_pg_assignment`)를 이미 쓴다. 겹치지 않게 **0050_image_job**으로 정한다. ADR-0386 결정 5대로 출시 마이그레이션 목록에 넣지 않고, 출시 뒤 `develop`에서 다시 번호를 매긴다.
4. **[알림] F-10-1 경계.** 이 기능은 image-worker와 공연 이미지 경로, 그리고 후기 사진·배너가 쓸 **종류별 처리 규격**까지 만든다. `POST /v1/review-images`, `/v1/ops/home-layout/banner-images`, 후기 사진 목록·붙이기, 홈 피드·검색은 F-10-1 몫이라 만들지 않는다. F-10-1이 이 포트와 키 규칙을 그대로 쓴다.
5. **[알림] 계약 설명 변경.** 원본보다 넓은 폭은 만들지 않으므로 `derivatives`가 여덟 개보다 적을 수 있다. 스키마 모양은 그대로이고 설명 문장만 바뀐다. 구현 커밋에서 `gen`을 돌려 생성물을 함께 커밋한다.

## 계획

### 1. 범위

- **E1 image-worker 실행 파일**: core-svc 패키지의 다른 진입점(`src/image-worker/main.ts`, 운영 명령 `node dist/image-worker/main.js`). DB·Kafka·Redis 자격 증명이 있으면 뜨지 않고, AWS S3 자격 증명은 받는다. gRPC `peaket.image.v1.ImageService.ProcessImage` 하나를 연다. 파드마다 동시 처리 1, 이미지 하나당 처리 시한 30초 [가정], 디코더 화소 상한 4,000만 [가정].
- **E2 이미지 처리**: 격리 원본을 읽어 검사 태그를 확인하고, JPEG·PNG·WebP만 디코딩한다. 긴 변 20,000px·4,000만 화소를 넘으면 **디코딩 전에** `TOO_LARGE`로 거절한다. 통과하면 sharp(libvips) API로 다시 인코딩하며 EXIF·GPS·XMP 등 메타데이터를 지운다. 셸 명령을 부르지 않는다. 공연 이미지·홈 배너는 폭 320·640·960·1,280px [가정] 가운데 **원본 폭 이하**만 AVIF·WebP로 만들고, 후기 사진은 목록 240px·보기 긴 변 1,280px [가정] WebP만 만든다. JPEG 파생본은 만들지 않는다. 원본 키로 멱등하다.
- **E3 S3 객체 저장소**: `ImageObjectStore`의 S3 어댑터. 격리 원본 쓰기·지우기, 준비 위치 읽기·크기 보기·지우기, 공개 위치 쓰기·지우기를 한다. 키는 서버가 만든 이미지 ID와 정한 접두사만 받는다. 공개 파생본에 `Content-Type`, `Cache-Control: public, max-age=31536000, immutable`, `Content-Disposition: inline; filename="{이미지 ID}.{확장자}"`를 붙인다. 격리·준비 위치는 비공개다.
- **E4 이미지 작업 원장**: `image_job` 표(마이그레이션 0050)와 작업 워커. 공연 이미지 올리기는 원본을 격리 위치에 넣고 작업을 적은 뒤 결과를 기다린다. 작업 워커가 `FOR UPDATE SKIP LOCKED`로 집어 gRPC로 맡기고 결과를 DB에 반영한다. 처리 시한 30초를 넘기면 다시 맡기고, 검사 결과가 아직 없으면 60초 [가정] 뒤 다시 맡긴다. 10번 [가정]을 넘으면 `DEAD`로 두고 요청은 503이다. 포스터 교체·삭제 뒤 남은 옛 파생본 정리와 공연 이미지에서 빠진 준비 위치 객체 정리도 같은 원장의 `CLEANUP` 작업으로 맡긴다.
- **E5 모의 악성 코드 검사기**: `tools/local/mock-malware-scanner.mjs`. moto S3의 새 객체를 훑어 `GuardDutyMalwareScanStatus` 태그를 붙인다. EICAR 시험 문자열이 있으면 `THREATS_FOUND`, 없으면 `NO_THREATS_FOUND`. 한 번 돌리기(`--once`)와 계속 돌리기(`--watch` [가정])를 받는다. image-worker는 이 태그가 `NO_THREATS_FOUND`일 때만 디코딩한다.
- **E6 D-T35 배포·정책 문서**: `deploy/workloads/image-worker/values.yaml`(DB·Kafka·Redis Secret 없음, 비루트·읽기 전용 루트 파일 시스템은 공용 차트가 이미 건다, 동시 처리 1, 자원 상한, 나가는 통신은 S3 VPC 엔드포인트 하나)와 `deploy/workloads/image-worker/irsa-policy.json`(격리 버킷 읽기, 준비 위치 쓰기만). 정적 시험이 ①②③을 막는다.
- **E7 core-svc 연결**: 공연 이미지 올리기·고치기·지우기의 `ImageProcessing` 포트를 요청 안 gRPC 호출에서 작업 원장 어댑터로 바꾼다. 파생본 키 검사를 **원본 폭 이하의 정확한 집합**으로 바꾸고, 응답 `derivatives`도 그 집합만 싣는다. 게시 전 준비 위치 파생본의 크기·앞부분 검사는 그대로 둔다. 화면 코드는 바꾸지 않는다.
- **일수**: 구현 1.0일 [가정](E1·E2 0.35, E3 0.15, E4 0.25, E5 0.1, E6 0.1, E7 0.05), 시험 0.5일로 1.50일 안팎이다. BUILD_ORDER의 1.50과 같다.

### 3. 바른 작업과 근거(값은 정본에서 온다)

- **파생본 폭·형식**(`docs/data.md` §1, `docs/frontend.md` §5.14.1, ADR-0257 결정 1): 공연 이미지·홈 배너는 320·640·960·1,280px [가정] × AVIF·WebP. 후기 사진은 240px·긴 변 1,280px [가정] × WebP. **원본보다 넓은 폭 칸은 만들지 않는다**(HOT-200 줄). 예: 폭 1,200px 원본은 320·640·960만, 폭 1,240px 배너도 1,280을 만들지 않는다. 후기 사진 1,600×1,200은 240·1,280 둘 다 만든다. 파생본 키는 `{준비|공개}/{종류}/{이미지 ID}/{폭}.{형식}`이다.
- **검사 태그**(`docs/security/asvs/catalog-review.md` 5.4.3, D-T35): 운영은 GuardDuty S3 악성코드 보호가 객체에 붙이는 결과 태그를 읽는다. 태그 이름은 `GuardDutyMalwareScanStatus`, 값은 `NO_THREATS_FOUND`·`THREATS_FOUND`·`UNSUPPORTED`·`ACCESS_DENIED`·`FAILED`다(추천 적용, 2026-11-26, F-10-2 계획). `NO_THREATS_FOUND`만 디코딩한다. `THREATS_FOUND`는 `REJECTED(MALWARE)`. 태그가 없거나 그 밖의 값은 `SCAN_PENDING`으로 답하고 작업을 60초 [가정] 뒤 다시 맡긴다. 열 번 [가정]을 넘으면 `DEAD`이고 요청은 503이다(fail-closed, 16.5.3).
- **이미지 형식·크기**(`docs/data.md` §2 `production_image`, `docs/api/openapi.yaml` 이미지 경로, ADR-0062 결정 38): JPEG·PNG·WebP만, 한 장 10MB, 긴 변 20,000px·4,000만 화소 상한. SVG·GIF·압축 파일은 받지 않는다. 앞부분(매직 바이트)과 디코딩이 맞지 않으면 `UNSUPPORTED_TYPE`. 화소 상한은 헤더를 읽어 **디코딩 전에** 본다.
- **메타데이터 제거**(ASVS 14.2.8, ADR-0062 결정 38): 다시 인코딩할 때 EXIF·GPS·XMP를 지운다. sharp의 `withMetadata()`를 쓰지 않고, 회전 정보는 `rotate()`로 화소에 반영한 뒤 지운다.
- **S3 머리**(ASVS 3.2.1·4.1.1·5.4.1, `docs/data.md` §1): 공개 파생본은 `Content-Type: image/avif|image/webp`, `Cache-Control: public, max-age=31536000, immutable` [가정], `Content-Disposition: inline; filename="{이미지 ID}.{확장자}"`. 원본은 공개하지 않고, 격리·준비 위치는 `private, no-store` [가정]. 파생본 이름은 서버가 만든 ID와 폭·형식뿐이라 덮어쓰지 않는다(immutable). 그래서 공개 위치 쓰기는 `If-None-Match: *`로 하고 같은 키가 이미 있으면 덮어쓰지 않고 실패한다. 확장자와 Content-Type이 맞지 않으면(예 `.avif`에 `image/webp`) 쓰지 않는다.
- **격리**(ASVS 15.2.5, D-T35): image-worker는 DB·Kafka·Redis 자격 증명이 없다. AWS 권한은 격리 버킷 `GetObject`와 준비 위치 `PutObject`·`AbortMultipartUpload`뿐이다. 비루트(1000)·읽기 전용 루트 파일 시스템·`allowPrivilegeEscalation: false`·모든 capability 제거·seccomp `RuntimeDefault`는 공용 차트가 이미 건다. 나가는 통신은 S3 VPC 엔드포인트 하나(`10.20.0.0/16` [가정], 443)이고 공인 HTTPS는 열지 않는다. 동시 처리 1, 메모리·CPU 상한을 둔다(5.2.1). `source_key`는 `quarantine/(production|banner|review)/{UUID}` 꼴만 받고 그 밖은 gRPC `INVALID_ARGUMENT`로 거절하며 S3를 부르지 않는다(5.3.2). 처리 한 건마다 `image_process` 로그 한 줄에 `active`(그때 처리 중인 수)·`status`·`durationMs`를 남긴다(16.1.1).
- **작업 원장**(HOT-200 줄, ADR-0148 결정 8, ADR-0257 결정 2): 작업 표 이름은 정본에 없다. `image_job`으로 정한다(추천 적용, 2026-11-26, F-10-2 계획).
  - 칸: `id`(uuid PK), `source_key`(text, **UK**, 원본 키로 멱등), `kind`(PRODUCTION·HOME_BANNER·REVIEW_PHOTO·CLEANUP), `status`(PENDING·SCANNING·RETRYING·DONE·DEAD), `attempts`(int, 0 이상), `next_attempt_at`(timestamptz), `lease_until`(timestamptz), `result_status`(ACCEPTED·REJECTED·DELETED), `width`·`height`(int), `derivative_keys`(jsonb), `reject_reason`(text), `created_at`·`updated_at`(timestamptz).
  - 집기: `FOR UPDATE SKIP LOCKED`, `lease_until`이 지난 행만, `next_attempt_at`이 된 행만.
  - 재시도: `SCAN_PENDING` 60초 [가정], 처리 무응답·데드라인 5초 [가정], `attempts` 10회 [가정]에서 `DEAD`. 기다리는 동안 `reject_reason`에 `SCAN_PENDING`·`UNAVAILABLE`을 넣어 요청이 `Retry-After` 60과 30을 가른다.
  - 요청은 작업을 적고 결과를 최대 30초 [가정] 기다린다. 검사 대기로 끝나면 503 `Retry-After: 60`, 무응답·DEAD면 503 `Retry-After: 30`이다. 작업은 지우지 않고 워커가 이어 간다.
  - `CLEANUP` 작업은 `source_key`가 `cleanup/{종류}/{이미지 ID}`이고 `derivative_keys`에 지울 공개 키를 담으며, 워커가 공개 위치에서 지운다. 공연 이미지 교체·삭제 뒤 옛 파생본과 `staging`에 남은 객체를 맡는다.
- **마이그레이션 0050**: `services/core-svc/migrations/0050_image_job.sql`, `meta/_journal.json`에 idx 50, `when`은 0047보다 큰 값. 파일 번호와 idx가 같아야 한다(`migrations-journal.test.ts`). 다른 동결 가지의 0048·0049와 겹치지 않게 0050을 쓴다(ADR-0386 결정 5). 출시 마이그레이션 목록에는 넣지 않는다.
- **모의 검사기**: `tools/local/mock-malware-scanner.mjs`. `--endpoint`·`--bucket`·`--once`(또는 `--watch`)를 받고, 태그가 없는 객체만 읽어 EICAR 문자열이 있으면 `THREATS_FOUND`, 없으면 `NO_THREATS_FOUND`를 붙인다. 이미 태그가 있으면 건드리지 않는다(멱등). AWS SDK 없이 Node `fetch`와 S3 REST(`?tagging`, `?list-type=2`)로 moto와 말한다. 운영 GuardDuty를 대신하는 로컬 대역임을 머리 주석에 적는다.

### 5. 공개 인터페이스(시험 담당이 이 모양으로 시험을 먼저 쓴다. 구현은 이 이름을 그대로 쓴다)

- **gRPC**: `docs/api/proto/peaket/image/v1/image.proto` 그대로. `ProcessImage(source_key, kind)` → `ACCEPTED`(keys·width·height)·`REJECTED`(reason)·`SCAN_PENDING`. 계약 변경 없음.
- **core-svc 포트**: `ImageProcessing.process({sourceKey, kind, timeoutMs})` 그대로. `ImageObjectStore` 그대로.
- **파생본 계획**: `derivativeNames(width: number, kind?: ImageKind): string[]` — `width`는 공연·배너는 원본 폭, 후기 사진은 원본 긴 변이다. 테스트는 `kind`를 생략한 공연 이미지 기본값·`'HOME_BANNER'`·`'REVIEW_PHOTO'`를 쓴다. `derivativeKeysMatch(imageId: string, keys: string[], width: number, kind?: ImageKind): boolean`.
- **작업 상태**: `nextImageJobState({status, attempts, outcome, now}): {status, nextAttemptAt, attempts, resultStatus?}`. `outcome`은 `'ACCEPTED' | 'REJECTED' | 'SCAN_PENDING' | 'UNAVAILABLE' | 'CLEANUP_DONE'`. 거절 사유는 상태 함수가 아니라 작업 기록(`reject_reason`)이 갖는다. `DONE`·`DEAD`면 `nextAttemptAt`을 두지 않는다(지운다).
- **작업 원장**: `DrizzleImageJobStore(database)`가 `enqueue(record, now)`, `find(sourceKey)`, `leaseDue(now, limit, leaseMs)`, `save(record)`를 제공한다. `ImageJobWorker({store, processing, objects, clock, logger})`가 `runOnce(now?)`로 한 바퀴를 돌려 `{claimed, done, retrying, dead}`를 돌려준다. `ImageJobProcessing({store, clock, waitMs})`가 `ImageProcessing`을 구현해 작업을 적고 결과를 기다린다.
- **S3 저장소**: `new S3ImageObjectStore({bucket, region, endpoint?, client?})`가 `ImageObjectStore`를 구현한다. `endpoint`가 있으면 path-style이다. 공개 위치는 `If-None-Match: *`로 덮어쓰지 않고, 확장자와 Content-Type이 맞지 않으면 쓴다. `client`는 시험이 moto를 가리킬 때만 쓴다.
- **모의 검사기**: `node tools/local/mock-malware-scanner.mjs --endpoint <url> --bucket <name> --once`.
- **image-worker 동시 처리**: `createImageQueue({concurrency, timeoutMs})`의 `run(fn)`이 동시 처리 수와 한 건 시한을 지킨다. `concurrency`는 1만 받는다(0·2 이상이면 시작 실패).
- **image-worker 환경 값**: `PEAKET_GRPC_PORT`(필수), `PEAKET_GRPC_HOST`(기본 0.0.0.0), `PEAKET_IMAGE_S3_ENDPOINT`·`PEAKET_IMAGE_S3_REGION`·`PEAKET_IMAGE_BUCKET`(필수), `AWS_ACCESS_KEY_ID`·`AWS_SECRET_ACCESS_KEY`(moto/로컬만), `PEAKET_IMAGE_CONCURRENCY`(기본 1, 1이 아니면 시작 실패), `PEAKET_IMAGE_TIMEOUT_MS`(기본 30000), `PEAKET_IMAGE_MAX_PIXELS`(기본 40000000), `PEAKET_LOG_LEVEL`.
- **image-worker가 받으면 안 되는 이름**: `PEAKET_DATABASE_URL`, `PEAKET_PARTNER_DATABASE_URL`, `PEAKET_OPS_DATABASE_URL`, `PEAKET_SEARCH_DATABASE_URL`, `PEAKET_MAINTENANCE_DATABASE_URL`, `PEAKET_KAFKA_BROKERS`, `PEAKET_REDIS_*`, `DATABASE_URL`, `KAFKA_*`, `REDIS_*`(빈 값도 이름이 있으면 거절). AWS 이름은 허용한다.
- **시험용 고정 값**: 태그 이름 `GuardDutyMalwareScanStatus`, 값 `NO_THREATS_FOUND`·`THREATS_FOUND`. 재시도 60초·5초, 최대 10회, 처리 시한 30초, 화소 상한 40,000,000, 긴 변 20,000. 시험은 코드 상수를 가져오지 않고 이 정본·계획 값을 적는다.

### 6. 정본 빈칸(계획 커밋에서 정한다. 모두 '추천 적용, 2026-11-26, F-10-2 계획')

- S3 공개 파생본의 `Cache-Control: public, max-age=31536000, immutable`, `Content-Disposition: inline; filename="{이미지 ID}.{확장자}"`, 격리·준비 위치 `private, no-store`. `docs/data.md` §1에 적는다.
- `image_job` 표의 이름·칸·상태·재시도 값. `docs/data.md` §2 ERD에 적는다. 정본에 표 이름이 없다는 사실은 그대로 남긴다. 작업 앱 역할은 `core_app`이고, 마이그레이션이 `SELECT·INSERT·UPDATE·DELETE`를 준다.
- image-worker의 IRSA 서비스 어카운트 주석(`eks.amazonaws.com/role-arn`)과 버킷 ARN은 `arn:aws:s3:::peaket-image/quarantine/*`·`arn:aws:s3:::peaket-image/staging/*` [가정]로 둔다. 공용 차트는 `serviceAccountAnnotations` 값을 그대로 싣는다.
- S3 VPC 엔드포인트 CIDR은 `10.20.0.0/16` [가정]이고 `internal` egress의 유일한 항목이다.
- 검사 태그 이름·값과 '태그 없음/실패는 SCAN_PENDING, 10회 뒤 DEAD' 규칙. 위 §3에 적고 `docs/data.md` §1 이미지 행에 태그 이름만 가리킨다.
- 마이그레이션 번호 0050과 그 근거(다른 동결 가지 0048·0049).
- 파생본 폭 줄이기와 계약 설명. `docs/api/openapi.yaml` 설명을 구현 커밋에서 고친다.
- 모의 검사기의 `--watch` 간격은 1초 [가정]. 시험은 `--once`만 쓴다.

### 10. 범위 밖과 막힘

- **F-10-1**: `POST /v1/review-images`(후기 사진 올리기·목록·붙이기·24시간 파기), `POST /v1/ops/home-layout/banner-images`, 홈 피드·검색·자동완성·후기·신고·조치. 이 기능은 image-worker의 `IMAGE_KIND_REVIEW_PHOTO`·`IMAGE_KIND_HOME_BANNER` 규격과 저장 키만 준비한다.
- **화면**: `apps/web`·`apps/partner`·`apps/console-host`는 바꾸지 않는다. `derivatives`가 6개일 수 있는 응답을 화면이 이미 `srcset` 후보로 받는지 확인만 하고, 바꿀 것이 있으면 F-10-1·F-10-2 후속으로 넘긴다.
- **실제 AWS**: GuardDuty S3 악성코드 보호, EventBridge, S3 VPC 엔드포인트, IRSA 실제 연결, Terraform 버킷은 F-09-4(동결)와 운영 설계 몫이다. 이 기능은 로컬 moto와 정책 문서·정적 시험까지다.
- **배포**: `deploy/envs/*`의 출시 환경 값, Helm 릴리스, Argo CD, 카나리, `release-scope` 분류는 건드리지 않는다. image-worker를 로컬 kind 무대에 넣는 일은 F-10-2 후속(화면·데모가 필요할 때)으로 미룬다.
- **성능 측정**: 1.5일 기능이라 부하 측정은 하지 않는다. 동시 처리 1·시한 30초·화소 상한은 단위/통합 시험과 정적 값으로 증명한다.
