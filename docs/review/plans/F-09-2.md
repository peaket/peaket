# 기능 계획: F-09-2(BAS-050·BAS-060 — 마이그레이션 도구 판정·실행기·Squawk·릴리스 플래그)

- **무엇**: 기능 F-09-2(docs/BUILD_ORDER.md:139)의 작업 목록이다(docs/architecture.md §8.6 4의 1·2, ADR-0354). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다. 정본 값은 옮겨 적지 않고 자리(문서:줄, 이 커밋 기준)만 가리킨다.
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-09-2`, 가지 `freeze/lane1-F-09-2`, 출발점 `origin/develop` `75771324e`(2026-11-27). 지시서 `node tools/ci/brief.mjs --batch F-09-2`(같은 커밋, 범위 209항목·빈칸 44). 2026-11-27 계획 담당 `lane1-freeze-F-09-2-opencode`(deepseek-v4.1-flash)가 썼다. **동결 로컬 한 덩이**라 이번 푸시 묶음에서 계획 커밋과 시험 커밋을 함께 쌓았고, 구현은 하지 않았다(감독에게 4·'검증').
- **등급과 차례**: B(docs/BUILD_ORDER.md:139). ADR-0373 결정 3의 B 차례는 **계획 → 시험 → 구현**이고 시험 리뷰·구현 뒤 리뷰·검증은 없다. 다만 이 작업은 감독 지시로 **계획·시험을 마치고 새 세션 리뷰 준비에서 멈춘다.** 구현 담당은 시험 파일을 고치지 못한다(ADR-0372 결정 3). 이 계획 커밋에는 `Batch-Order`를 달지 않는다(시험 먼저).
- **동결 로컬 범위**: ADR-0386 결정 4·5. `develop`·`release/1.0.0`에 합치지 않고, 출시 마이그레이션 목록·출시 환경 플래그(`deploy/envs/{demo,staging,prod}/flags/`)에 넣지 않는다. 이 가지에서만 실행기·검사 도구·로컬 플래그를 만든다. AWS·Aurora 실제 연결, 운영 DB 실행, 30k/s·100만·K1/K2/K7 수치 주장은 이 기능에서 하지 않는다(소유자 자원·측정 창 몫).

## 감독에게

막는 물음은 1 하나다. 나머지는 추천대로 계획과 정본에 적었다. 다르게 정하면 이 계획과 그 정본 줄을 고친다.

1. **[결정 요청] F-09-2의 장부 범위를 10개로 좁힌다.** 지금 행의 범위(`D-T37, D-T44, docs/infra.md, docs/devops.md, docs/data.md, docs/security/asvs/delivery.md, SR-T11 ②, frontend:v5.0.0-3.4.4`)는 209항목·빈칸 44다. 그 가운데 셋은 이 기능이 닿지 않는다.
   - `D-T37`(WAF 규칙표 정적 검사, docs/devops.md:953·docs/infra.md:578)은 CloudFront·WAF 배포 구성 검사다. F-09-4(CloudFront/WAF, 동결) 몫이고 F-09-2 행에도 F-09-4 행에도 들어 있다.
   - `SR-T11 ②`(CDN 캐시 정책이 쿠키를 키에서 뺀다, docs/features/search.md:305)는 HOT-450의 CloudFront 캐시 정책 몫이다. 장부도 이미 '다른 단계(HOT-450)'다.
   - `frontend:v5.0.0-3.4.4`(`X-Content-Type-Options: nosniff`, delivery.md:58)는 CloudFront 응답 헤더 정책과 게이트웨이 공통 정책이 붙인다. F-09-4 몫이고, 장부는 이미 `deploy/gateways/test/gateways.test.mjs`로 자동 시험이다.
   - 그래서 이 행의 `장부 범위`를 `D-T8, D-T9, D-T10, D-T44, delivery:v5.0.0-13.2.2, delivery:v5.0.0-16.3.4`로 바꾼다(§2). D-T37·SR-T11 ②·3.4.4는 F-09-4 행에 그대로 남아 있어 장부에서 사라지지 않는다. F-09-4는 동결이라 지금 시작하지 않는다.
2. **[확인] D-T44 판정은 'Drizzle SQL 파일 + 자체 실행기'다.** Atlas와 node-pg-migrate는 ① 파일마다 트랜잭션·② 트랜잭션 밖 표시·④ 실행 잠금을 문서상 채우지만, ③ 문장마다 `lock_timeout`을 걸고 5회 다시 시도하는 일과 ⑤ DDL 역할로 PgBouncer를 거치지 않고 붙는 일을 도구가 보장하지 않는다(§3.1). Atlas의 무료 사용 조건도 확인 전이다. 실제 PostgreSQL에서 세 안을 돌리는 PoC는 **Docker·DB를 쓸 수 있는 구현 차례**에 하고, 결과를 D-T44 표와 ADR-0054 상태 줄에 적는다. 그전까지 이 판정은 `[가정]`이며 D-T44 ③⑤는 `미실행`이다.
3. **[확인] 릴리스 플래그는 로컬·CI에만 둔다.** ADR-0386 결정 5대로 v1에는 릴리스 플래그가 없다. 이 기능은 `deploy/envs/local/flags/peaket.json`(빈 정의)과 파일 모드 평가기만 만들고, demo·staging·prod에는 플래그 파일을 만들지 않는다. `tools/ci/release-flags.mjs --local-only`가 그 경계를 검사한다. 운영 중 바꾸는 값은 계속 관제 명령이다(docs/devops.md §5.4).
4. **[알림] 이번 턴은 Docker·kind·AWS를 쓰지 않았다.** 그래서 PostgreSQL 통합 시험(`packages/platform/test-int/migrations.int.test.ts`)은 파일만 쓰고 `미실행`이다. 다음 구현·검증 차례에 Docker 잠금을 잡고 돌린다. 실행기 단위 시험은 가짜 연결로, 검사 도구 시험은 임시 폴더와 가짜 Squawk 실행 파일로 돈다.
5. **[알림] 파일이 겹치는 곳.** `tools/ci/README.md`·`.github/workflows/tools-check.yml`·`ci.yml`·`tools/ci/changes.mjs`는 다른 기능도 만진다. 이 기능은 `migration-check` 잡 한 줄과 README 한 줄만 더하고, 나중에 합치는 쪽이 다시 쌓으며 맞춘다. `docs/BUILD_ORDER.md`는 F-09-2 행의 장부 범위·비고만 고친다.
6. **[알림] 남는 몫은 소유자 자원이 아니다.** 출시 환경 플래그 배포와 실제 Aurora 연결은 F-09-1·F-09-4·INF-020/040(동결)과 소유자 몫이다. 이 기능은 실행기·검사·로컬 플래그까지다.

## 계획

### 1. 범위

- **P1 도구 판정(D-T44, BAS-050)**: 세 안을 문서로 견주고 'Drizzle SQL 파일 + 자체 실행기'를 고른다. 실제 PostgreSQL PoC의 실행 절차(다섯 시나리오)를 정해 구현 차례에 돌린다. 새 패키지·도구 이미지를 더하지 않는다(Atlas·node-pg-migrate는 쓰지 않는다).
- **P2 공용 실행기(BAS-060)**: `packages/platform/src/migrations.ts`에 `readMigrationFiles`·`planMigrations`·`runMigrations`·`assertDirectDatabaseUrl`·`roleStatements`를 둔다. 서비스 `scripts/migrate.mjs` 여섯(core·identity·ops·payment·purchase·ticket)은 이 실행기를 부르는 얇은 껍데기로 바꾼다. `v0-monolith`는 비교용이라 바꾸지 않는다.
- **P3 마이그레이션 검사(BAS-060)**: `tools/ci/migration-check.mjs`(check·squawk·n1·roles)와 `.github/workflows/migration-check.yml`, `ci.yml` 연결, `tools/ci/` 아래 `squawk-exceptions.json`. Squawk는 `PEAKET_SQUAWK` 실행 파일이 있으면 그것을, 없으면 끝 코드 2다(Docker를 기본으로 띄우지 않는다. CI 잡이 고정 이미지나 실행 파일을 준비한다).
- **P4 역할·정비(BAS-060이 넘겨받은 몫)**: 서비스별 `db/roles.sql`(앱 DML·`<서비스>_outbox_relay`·정비 역할)을 실행기가 적용한다. 마이그레이션 뒤 `ensureOutboxPartitions`·`ensureMonthlyPartitions` 훅을 같은 연결에서 부른다. `order_event` 앱 역할에서 UPDATE·DELETE를 뺀다(ADR-0113 결정 2). 정비 역할의 부모 표 `ANALYZE`·보존 나눠 지우기·`REINDEX CONCURRENTLY`·`pgstattuple`은 서비스 설정으로 정한다.
- **P5 릴리스 플래그(BAS-060)**: `packages/platform/src/flags.ts`(OpenFeature + flagd 파일 모드 감싸개, 네트워크 호출 없음, 실패하면 꺼짐)와 `deploy/envs/local/flags/peaket.json`(빈 정의), `tools/ci/release-flags.mjs`(스키마·소유자·만료일·기본 꺼짐·로컬 한정 검사). 배포 순서는 확장 → 마이그레이션(PreSync) → 앱(플래그 꺼짐) → 플래그 켜기다.
- **P6 정본·차트(BAS-060)**: docs/devops.md §7.2·§7.3, docs/data.md §2, delivery.md 13.2.2·16.3.4를 고친다. `deploy/charts/peaket-service/templates/migration-job.yaml`(ArgoCD PreSync, 서비스와 같은 이미지·다른 명령, DDL 역할 주소)과 values를 더한다.
- **어림**: 구현 2.25일 [가정](P1 0.25, P2 0.75, P3 0.5, P4 0.5, P5 0.25)과 시험 0.75일로 약 3.0일이다. 4일 안이라 나누지 않는다. 구현이 시작 뒤 2일을 넘으면 P4(역할·정비)를 새 행으로 넘긴다(파일이 겹치지 않는다).

### 3. 바른 동작과 근거(값은 정본에서 읽는다)

- **3.1 D-T44 판정(2026-11-27, [가정])**: 요구 다섯은 docs/devops.md:948 그대로다. ① 보통 DDL 파일마다 트랜잭션 ② 트랜잭션 밖 표시를 한 `CREATE INDEX CONCURRENTLY` 파일 ③ 다른 트랜잭션이 잠금을 쥔 표의 DDL이 `lock_timeout`에 걸려 5회 다시 시도한 뒤 실패 ④ 같은 DB에 잡 두 개를 동시에 띄우면 하나만 돌고 다른 하나는 기다리거나 실패 ⑤ DDL 역할로 PgBouncer를 거치지 않고 붙기.
  - Atlas: `--tx-mode file`과 `-- atlas:txmode none`으로 ①②는 채운다. advisory 잠금은 `--lock-timeout`(기본 10초)이다. ③의 문장별 `lock_timeout`·5회 재시도와 ⑤의 연결 경로 보장은 문서에 없다. 무료 사용 조건도 확인 전이다.
  - node-pg-migrate(9.0.0, MIT): `--no-single-transaction`·`pgm.noTransaction()`으로 ①②, advisory 잠금으로 ④를 채운다. ③⑤는 문서에 없다.
  - 자체 실행기: 다섯을 모두 코드로 채운다(§3.2). 그래서 'Drizzle SQL 파일 + 자체 실행기'를 고른다. Drizzle은 `drizzle-kit generate`로 SQL만 만든다(ADR-0037 결정 6).
  - 실제 PostgreSQL 비교는 Docker가 필요한 구현 차례에 한다: 임시 DB에 같은 묶음(①~⑤)을 세 안으로 돌리고, ③은 다른 세션이 `LOCK TABLE`을 쥔 채, ④는 두 프로세스를 동시에 띄워, ⑤는 PgBouncer 주소와 직접 주소를 각각 줘 본다. 결과는 D-T44 행과 ADR-0054 상태 줄에 적는다. 이번 턴은 `미실행`이다.
- **3.2 실행기 계약**(`packages/platform/src/migrations.ts`):
  - **읽기·순서**: `migrations/*.sql`을 이름 숫자 순으로 읽는다. `NNNN_이름.sql` 꼴이 아니거나 번호가 겹치면 `BAD_FILE_NAME`·`DUPLICATE_NUMBER`. `.down.sql`은 `DOWN_NOT_SUPPORTED`(앞으로만 간다, devops.md:598). `meta/_journal.json`이 있으면 tag 목록이 파일 이름 순서와 정확히 같아야 한다(`JOURNAL_MISMATCH`). 없으면(ops·ticket 같은 손으로 쓴 폴더) 숫자 순서만 본다.
  - **표시**: 첫 줄이 정확히 `-- peaket:no-transaction`인 파일만 트랜잭션 밖이다. 표시가 둘째 줄 이하이면 트랜잭션 파일로 본다(D-T9). 트랜잭션 밖 파일은 `--> statement-breakpoint`로 나눈 문장을 하나씩 실행하고, `BEGIN`·`COMMIT`이 들어 있으면 거절한다. 트랜잭션 밖 파일은 다시 돌려도 안전해야 한다(`IF NOT EXISTS` 등).
  - **기록 표**: `peaket_migration(name text primary key, checksum text not null, applied_at timestamptz not null default now())`. 파일 본문의 SHA-256을 적는다. 이미 적용한 이름의 체크섬이 다르면 `CHECKSUM_DRIFT`(전진 금지), DB에만 있는 이름이면 `UNKNOWN_APPLIED`, 적용 순서가 파일 순서의 앞부분이 아니면 `OUT_OF_ORDER`.
  - **잠금**: 시작할 때 `SET lock_timeout = '3000ms'` 뒤 `SELECT pg_try_advisory_lock(0x5045414b, 0x4554)`를 잡는다. 못 잡으면 100·200·400·800·1600ms [가정] 간격으로 5회 다시 시도하고, 그래도 못 잡으면 `LOCK_BUSY`로 잡을 실패시킨다(④). 끝낼 때 `pg_advisory_unlock`을 부른다.
  - **문장 시간 제한**: 트랜잭션 파일은 `BEGIN` → `SET LOCAL lock_timeout = '3000ms'` → `SET LOCAL statement_timeout = '30000ms'` → 파일 SQL → 기록 INSERT → `COMMIT`. `55P03`(lock_not_available)이면 `ROLLBACK`하고 같은 간격으로 5회 다시 시도한 뒤 `LOCK_TIMEOUT`으로 실패한다(D-T10). `57014`(statement_timeout)는 다시 시도하지 않고 `STATEMENT_TIMEOUT`이다. 트랜잭션 밖 파일은 세션 `SET lock_timeout`·`SET statement_timeout`으로 같은 제한을 걸고, 실패한 문장만 다시 시도한다.
  - **드라이런**: 연결 없이 `readMigrationFiles`·`planMigrations`만 하고 `[dry-run] <파일> (<transaction|no-transaction, N문장>)`을 로그에 남긴다. `BEGIN`·INSERT·훅을 부르지 않는다.
  - **훅**: 대기 파일을 모두 적용한 뒤에만 `afterMigrate()`를 한 번 부른다. 서비스는 여기서 `ensureOutboxPartitions` → `ensureMonthlyPartitions` 순서로 부른다(FND-080·FND-090이 넘긴 몫). 실패·드라이런·대기 0이면 부르지 않는다.
  - **연결**: 서비스 스크립트는 `PEAKET_MIGRATION_DATABASE_URL`(DDL 역할)과 `PEAKET_MAINTENANCE_DATABASE_URL`(정비 역할)만 읽는다. `PEAKET_DATABASE_URL`(앱 DML·PgBouncer)은 읽지 않는다. `assertDirectDatabaseUrl`이 `pgbouncer`가 들어간 주소를 거절한다(⑤).
  - **역할**: `roleStatements(service, spec)`이 `<서비스>_outbox_relay`에 `SELECT`(Outbox)와 `UPDATE (sent_at)`만 주고, 정비 역할에 부모 표 `ANALYZE`·보존 나눠 지우기·`REINDEX CONCURRENTLY`·`pgstattuple` 권한을 주며, 앱 역할에서 `order_event`의 UPDATE·DELETE를 뺀다(ADR-0113 결정 2, R-224·R-225·R-227). 서비스별 `db/roles.sql`은 이 함수가 만든 문장을 담고, 실행기가 마이그레이션 뒤에 적용한다(멱등).
- **3.3 검사 도구**(`tools/ci/migration-check.mjs`):
  - `check`: 파일 이름·번호·journal·첫 줄 표시·트랜잭션 밖 문장 허용 목록(`CREATE INDEX CONCURRENTLY`·`DROP INDEX CONCURRENTLY`·`REINDEX … CONCURRENTLY`)을 본다. 표시 없는 파일의 동시 인덱스는 막는다(D-T9).
  - `squawk`: 바뀐 마이그레이션(`--base` 또는 `--files`)만 Squawk에 넘긴다. 규칙은 devops.md:629의 위험 패턴(동시 생성이 아닌 인덱스, 트랜잭션 안의 동시 인덱스, NOT NULL 열 추가, 열 삭제, `NOT VALID` 없는 제약, `lock_timeout` 없는 문장)이다. 파티션 부모의 `CREATE INDEX … ON ONLY`는 `tools/ci/` 아래 `squawk-exceptions.json`에 저장소 기준 경로·규칙·까닭·만료를 적어 예외로 둔다. 실행 파일이 없거나 결과를 읽지 못하면 끝 코드 2다(통과로 보지 않는다).
  - `n1`: 바뀐 파일에서 `DROP COLUMN`·`RENAME COLUMN`·`SET NOT NULL`·좁히는 `ALTER COLUMN TYPE`·`NOT VALID` 없는 제약을 찾으면 막는다(확장 → 이전 → 축소, devops.md:600~606). 같은 배포에 축소가 들어가면 N-1 통합 시험이 실패한다(D-T8). `ADD COLUMN … NOT NULL DEFAULT`와 `ADD CONSTRAINT … NOT VALID`는 통과한다. 실제 N-1 앱 시험은 구현 차례의 통합 시험이다.
  - `roles`: 서비스별 `db/roles.sql`과 실행기 `roleStatements`의 결과를 본다(§3.2 마지막 줄).
  - 끝 코드: 0 통과, 1 위반(파일마다 `막음: <경로>: <까닭>`), 2 인자·파일·도구 오류. 결과를 읽지 못하면 2다.
- **3.4 릴리스 플래그**(`packages/platform/src/flags.ts`, `tools/ci/release-flags.mjs`):
  - 정의 파일은 flagd 파일 모드 꼴(`{"flags":{...}}`)이고, 플래그마다 `state`·`variants {on:true, off:false}`·`defaultVariant:"off"`·`metadata.owner`·`metadata.expiresAt`(YYYY-MM-DD)가 있어야 한다. 기본값이 꺼짐이 아니면 검사기가 막는다. 만료일이 지난 플래그는 경고하고, 100% 공개 뒤 30일 [가정] 안에 코드와 함께 지운다(docs/devops.md:498).
  - 평가는 OpenFeature 서버 SDK + flagd 파일 공급자로 프로세스 안에서 한다. 공급자·파일이 깨지면 코드의 기본값(꺼짐)으로 동작하고 던지지 않는다(docs/devops.md:499). 네트워크를 부르지 않는다.
  - 경로는 `deploy/envs/local/flags/peaket.json` 하나다. `--local-only`는 demo·staging·prod에 플래그 파일이 있으면 막는다(ADR-0386 결정 5). 출시 환경 플래그는 동결을 푼 뒤 새 ADR·manifest 변경과 함께 만든다.
  - **배포 순서**: ① 확장(NULL 허용 열·새 표)을 PreSync 마이그레이션으로 넣고 ② N-1·N 앱이 함께 도는 동안 플래그는 꺼짐 ③ 새 경로를 켜고 ④ 이전·축소는 다음 배포다. 차트의 마이그레이션 Job은 `argocd.argoproj.io/hook: PreSync`라 동기화·롤아웃보다 먼저 돈다(docs/devops.md:610). 잡이 실패하면 동기화가 실패해 롤아웃이 시작되지 않는다.
- **3.5 차트**: `deploy/charts/peaket-service/templates/migration-job.yaml`은 서비스와 같은 이미지·다른 명령(`node scripts/migrate.mjs`), `backoffLimit: 0`, `activeDeadlineSeconds: 600` [가정], `hook-delete-policy: BeforeHookCreation`, 서비스 계정 토큰 없음, `PEAKET_MIGRATION_DATABASE_URL`·`PEAKET_MAINTENANCE_DATABASE_URL`만 Secret에서 받는다. `PEAKET_DATABASE_URL`과 `pgbouncer` 문자열은 넣지 않는다. values `migration.enabled`(기본 true)·`migration.secretName`.
- **3.6 정본 고침**: 도구 판정·실행기 계약·검사 CI를 docs/devops.md §7.2·§7.3에, 실행기 위치·파티션 훅을 docs/data.md §2에, 역할 분리·실패 로그를 delivery.md 13.2.2·16.3.4에 적는다. 값은 옮겨 적지 않고 위치만 가리킨다.

### 7. 차례·어림·동결 로컬

- 차례: 계획(이 커밋) → 시험(이 커밋) → **새 세션 리뷰(멈춤)** → 리뷰 반영 → 구현(P1→P2→P3→P5→P4→P6, P4가 늦으면 감독에게) → 게이트 → 기록.
- 어림: P1 0.25·P2 0.75·P3 0.5·P4 0.5·P5 0.25 = 2.25일 [가정], 시험 0.75일. 3.0일.
- 동결 로컬: 이 가지에서만 커밋·푸시한다. `develop`·`release/1.0.0`·`main`에 합치거나 체리픽하지 않는다. 출시 마이그레이션·출시 플래그에 넣지 않는다. 실제 Aurora·AWS·Docker는 이번 턴에 쓰지 않는다.

### 8. 실패 시나리오와 완료의 정의

- **실패 시나리오**: ① 두 실행이 동시에 시작(④) ② 다른 트랜잭션이 표를 잡음(D-T10) ③ 파일 중간 실패(트랜잭션 파일은 전부 롤백, 트랜잭션 밖 파일은 적용된 문장이 남으므로 재실행 안전 필요) ④ 적용 뒤 파일 체크섬 바뀜 ⑤ DB에만 있는 파일·순서 뒤집힘 ⑥ 드라이런이 쓰기를 함 ⑦ 표시 없는 동시 인덱스(D-T9) ⑧ 축소 변경이 같은 배포에 들어감(D-T8) ⑨ Squawk 실행 파일 없음·결과 못 읽음(닫힌 실패) ⑩ 플래그 파일 깨짐·공급자 실패(꺼짐) ⑪ 만료 플래그 ⑫ 출시 환경에 플래그·동결 마이그레이션 ⑬ 마이그레이션 Job 실패 뒤 롤아웃 시작 ⑭ PgBouncer 주소로 DDL 실행.
- **완료의 정의(구현·기록 차례에 확인)**:
  1. `pnpm --filter @peaket/platform test` 통과(마이그레이션·플래그 단위).
  2. Docker 잠금을 잡고 `pnpm --filter @peaket/platform test:integration` 통과(마이그레이션 통합).
  3. `node --test tools/ci/migration-check.test.mjs tools/ci/release-flags.test.mjs` 통과.
  4. `node tools/ci/migration-check.mjs all`이 저장소에서 0, Squawk 실제 실행 0(도구가 없으면 `미실행`으로 적고 통과로 세지 않는다).
  5. `node tools/ci/release-flags.mjs --check --local-only` 0.
  6. `node tools/ci/ledger.mjs --batch F-09-2 --require` 빈칸·ID만 0.
  7. `pnpm lint`, `python -I -X utf8 tools/doc-check/check_all.py`, `node tools/ci/release-scope.mjs --check` 통과.
  8. 실제 PostgreSQL 세 안 비교(PoC) 결과를 D-T44 표와 ADR-0054 상태 줄에 적었다(또는 Docker를 못 쓰면 `미실행`과 까닭).
  9. 동결 로컬 경계(출시 환경 플래그·출시 마이그레이션 없음)를 `release-scope --release`와 `release-flags --local-only`로 확인했다.

### 9. 남는 위험·외부 자원

- 실제 Aurora·PgBouncer·Squawk 이미지·Atlas 유료 조건은 소유자 자원·계정이 필요하다. 이 기능은 로컬·CI 무대까지만 확인하고, 운영 배포는 F-09-1·F-09-4·INF-020/040(동결) 몫이다.
- `pgstattuple` 확장이 없으면 부푼 인덱스 확인을 건너뛴다(정본 동작). 확장 설치는 정비 역할 권한과 함께 배포 환경에서 확인한다.
- 실행기 자체가 운영 DB를 바꾸는 가장 위험한 코드다(devops.md:612). 구현 뒤 실제 PostgreSQL 통합 시험과 리뷰를 통과하기 전에는 출시 경로에 넣지 않는다.
- N-1 앱 시험(D-T8)의 실제 실행은 서비스 통합 시험 묶음이 필요해 이번 턴에는 정적 검사만 있다. 구현 차례에 서비스 하나(identity)로 먼저 끝까지 돌린다.
