- 만든 때: 2026-11-11, `origin/develop` `7585da9c`에서 가지 `feature/BAT-028-hot-path-optimization`.
- 정본: [docs/verification.md](../../verification.md) §3.8~§3.10, [docs/observability.md](../../observability.md) §3·§8, [docs/features/seat-hold.md](../../features/seat-hold.md) §2~§5, [docs/perf-ledger.md](../../perf-ledger.md), [BAT-027 보고서](../measurements/BAT-027-hot-path-instrumentation.md).
- 소유자 결정: 2026-11-11 OPEN[36] **D + A + B 묶음**. D(측정 방법) → A(HTTP 입구·출구 계측) → B(인증 세션 재사용)를 한 배치로 한다.

## 1. D — 측정 방법

- K2 좌석 홀드의 기본 예열을 30초에서 **60초**로 늘린다(v1 seat-hold만. K1·K7·v0는 30초 그대로).
- 모든 발생기가 준비(setup: 사전 검증·진입·입장·구매 세션 열기)를 마친 뒤 **같은 절대 시각**에 예열을 시작한다.
  - 실행 도구가 `WARM_START_AT_MS`를 정해 발생기에 넘기고, 각 k6 `setup()`은 준비가 끝나면 그 시각까지 기다린다.
  - 실행 도구는 그 시각까지 기다렸다가 `loadStartMs`를 잡고 곁작업·판정 창을 연다. 준비가 늦은 발생기는 그 발생기만 늦게 시작하며, 그 사실은 발생기별 start skew로 남는다.
- `loadtest/runner/args.mjs`의 기본값, `loadtest/run.mjs`의 env·대기, `loadtest/scenarios/v1-seat-hold.js`의 setup 대기를 고친다.
- 시험: v1 seat-hold 기본 예열 60, K1·K7 기본 30, 사용자가 준 `--warm` 우선. k6 시나리오 형식 시험과 BAT-025 계획이 그대로 도는지 확인한다.

## 2. A — HTTP 입구·출구 계측

- 기존 `HotPathMetrics`에 HTTP 구간을 더한다: `http.entry`(onRequest→preHandler: 라우팅·본문 검사), `http.auth`(인증 가드), `http.handler`(preHandler→onSend), `http.problem`(ProblemFilter), `http.log`(정규 로그 줄), `http.serialize`(onSend→onResponse), `http.total`.
- `createService`가 서비스의 `HotPathMetrics`를 받아 `installHttpHooks`·`AuthState`·`ProblemFilter`에 같은 객체를 넘긴다. 라벨은 `service`·`stage`뿐이고 계정·주문·회차 ID는 싣지 않는다.
- 동작 불변: 구간은 관측만 하고, 지표가 던져도 요청을 막지 않는다. `hotPath`를 넘기지 않는 서비스·시험은 기존 경로 그대로다.
- 시험: 데모 서비스에 409 Problem을 내고 `http.entry`·`auth`·`handler`·`problem`·`log`·`serialize`·`total`이 모두 1 이상 기록되는지 본다.
- K2 3회에서 HTTP p99와 각 구간을 견줘 25.58ms가 어디에 있는지 표로 낸다.

## 3. B — 인증 세션 재사용

- 인증 훅(`StoredPurchaseSessions.resolve`)이 이미 읽은 구매 세션 정보를 요청에 붙인다. 받는 층의 `@CurrentPurchaseSessionInfo()`가 그 값을 읽어 `HoldSeats.execute`에 넘긴다.
- `HoldSeats`는 세션이 넘어오면 `sessions.get`(두 번째 Redis GET)을 부르지 않는다. 넘어오지 않으면 기존처럼 부른다.
- 동작을 바꾸지 않기 위해 넘어온 세션에도 다음을 다시 본다:
  - 계정 대조: `session.accountId === command.accountId`가 아니면 `SESSION_NOT_FOUND`.
  - 회차 대조: `session.eventId === command.eventId`가 아니면 `EVENT_MISMATCH`.
  - 최대 체류 경계: 인증이 읽은 `maxStayUntilMs`를 함께 넘겨 홀드 직전 `clock.now() >= maxStayUntilMs`면 `SESSION_NOT_FOUND`. 인증과 홀드 사이의 경계 차이를 없앤다.
- 남의 세션 거절은 인증 훅의 계정·로그인 세션 대조가 그대로 맡는다. 세션이 없거나 만료면 훅이 401로 끝내므로 홀드에 오지 않는다.
- 시험 먼저: 계정 대조, 회차 대조, 최대 체류 경계(양쪽), 남의 세션 거절(HTTP), 세션 없음(기존 fallback), 인증 읽기 실패 503, 홀드 저장소 실패 503. 틀린 구현 검사는 경계와 되돌림(세션 재사용을 끄는 변이) 두 가지로 한다.
- A등급이므로 판정 기준·단언 대조를 전수로 남긴다.

## 4. 재측정

- K2 2,000/s를 CPU 4/replica(3복제 합 12코어)에서 **3회**. 같은 클러스터·같은 방법, D로 예열 60초·발생기 동시 시작.
- 3회 모두 유효(놓침 0·오류 0)이고 p99가 안정적으로 50ms 안이면 K7 ②(3회, 회마다 새 클러스터)와 A/A로 넘어간다.
- K2가 여전히 미달·무효면 더 하지 말고 원인·지표를 보고한다. 정본 목표(2,000/s·p99 50ms)는 바꾸지 않는다.
- 결과는 `docs/review/measurements/BAT-028-hot-path-optimization.md`와 `docs/review/measurements/BAT-028/`에 남긴다. 성능 장부 실행도 포함한다.

## 6. 예상과 위험

- D 2시간, A 3시간, B 4시간, 시험·게이트 3시간, K2 3회 1시간, K7 ② 3회·A/A 3~4시간. 합 1.5~2일 [가정].
- 위험: 예열 60초와 준비 대기로 실행 한 번이 3분 길어진다. K2 3회면 9분 늘어난다.
- 위험: 인증 훅과 홀드 사이의 세션 경계가 달라지면 BOLA·만료 경계가 흔들린다. `maxStayUntilMs`를 함께 넘겨 막고, 경계 시험을 먼저 쓴다.
- 위험: HTTP 구간이 겹쳐 합이 total보다 클 수 있다. `auth`·`problem`은 `handler`의 부분 구간으로 표시하고, 합으로 해석하지 않는다.
- 위험: K2가 유효해도 p99가 50ms를 넘으면 K7·A/A를 하지 않는다. 그때는 HTTP 구간 표와 남은 격차만 보고한다.
