# 기능 계획: F-07-9(파트너 콘솔 휴대폰·태블릿, 중개자 고지, 판매자 정보 — LCH-130·LCH-170)

- **무엇**: 기능을 시작할 때 만든 작업 목록이다(docs/architecture.md §8.6 4의 1, ADR-0256 결정 10, ADR-0354). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-07-9`, 가지 `freeze/lane5-F-07-9`, 출발 `origin/develop` `1d10d6da3`(2026-11-25). 2026-11-26 작성.
- **Batch-Grade: A**. F-07-9는 A등급이다(docs/BUILD_ORDER.md F-07-9 줄). 파트너에게 보이는 판매자 정보와 법정 고지가 틀리면 전자상거래법 §20②·§13③, 통신판매중개자 지위(ADR-0045), 표시광고 책임으로 이어지고, 잘못된 화면 배치는 휴대폰에서 결제·계약 확인을 막을 수 있다. 돈·좌석·대기 순번은 아니지만 **법정 의무와 계약 정보**라 A로 본다.
- **차례(A등급, ADR-0372·ADR-0373·ADR-0381)**: 계획 → 시험(구현 전, 기준 트리 = 이 계획의 마지막 커밋에서 새 동작 시험이 실패하는 것을 봄) → 시험 리뷰(새 세션) → 반영(시험 담당) → 시험 고정 → 구현(고정한 시험만 통과하면 되고, 구현 담당은 시험을 고치지 못함) → 구현 리뷰(새 세션) → 지적 반영 → 고친 곳 다시 보기 → 게이트. **이번에는 계획·시험·기준 실패 확인 뒤 시험 리뷰를 받을 준비에서 멈춘다. 구현은 시험 리뷰 뒤에 시작한다.**
- **정본**: `docs/features/transfer-refund.md` §1·§2.2·§4·§11(R-T14·R-T15), `docs/features/settlement.md` §3·§6·§9·§12(SCR-020·SCR-027 행)·§13(J-T42), `docs/frontend.md` §2.3·§3.9·§5.11·§5.17·§1.6(SCR-020·027)·§6.3, `docs/design/d5-screen-blueprint.md` §3.9·§6.1·§6.10, `docs/security/asvs/settlement.md`(1.2.1·3.2.2·8.2.3·14.2.6), `docs/security/asvs/transfer-refund.md`(1.2.1·3.2.2), `docs/security/authz-matrix.md` §6(I-T53은 경계만), `docs/planning/03-policies-glossary.md` POL-014·016·017·024·032·037·039, ADR-0045·0061·0062·0063·0066·0173·0373·0386.

## 0. 넘겨받은 것과 경계

F-07-9는 F-07-8 뒤에 오는 동결 묶음이고, 원래 LCH-130(파트너 콘솔 전 화면 휴대폰·태블릿)과 LCH-170(중개자 고지·판매자 정보 표시·분쟁 해결 기준 게시)의 남은 몫이다. 앞선 묶음이 만든 화면·문구를 다시 만들지 않고, **비어 있는 모바일 분기와 판매자 고지·정산 주체 표시**만 채운다.

## 3. 이번에 하는 것

차례: I-04(공용 문구·판매자 정보) → I-01(판매 정책) → I-02(상품 폼) → I-03(주문 현황) → I-05(R-T15 시험) → I-06(reflow 전 화면) → I-07(문서·기록). 구현 담당은 시험 고정 뒤에 시작한다.

1. **I-01 판매 정책 라이브 화면의 모바일 배치**(G-01·G-11, AC-02):
   - `LiveSalePolicy.tsx`의 규칙 표를 `.table-wrap`으로 감싸고, `md:hidden` 규칙 카드 목록(`<ul aria-label="등록 규칙 목록">`)을 더한다. 카드에는 규칙 이름·조건 요약·상태를 둔다.
   - '새 규칙' 단추와 편집 폼(`규칙 고치기`·`폼 값을 규칙에 넣기`·`판매 정책 저장`·`JSON 보기`)을 `max-md:hidden`으로 감싸고, 그 자리에 `BigScreenNotice`("규칙 편집과 시뮬레이션은 태블릿이나 데스크톱에서 합니다")를 둔다.
   - 시뮬레이션 카드도 `max-md:hidden`으로 감싼다. 판매 자격 명단은 목록만 보이고, 파일 올리기 칸은 `max-md:hidden` + 안내 카드로 바꾼다.
   - 불러오기·404·오류 상태는 지금처럼 카드로 보이고, 모바일에서도 안내 카드가 사라지지 않는다.

4. **I-04 판매자 정보·중개자 고지 한 곳으로 모으기**(G-04~G-06·G-10, AC-05·AC-06·AC-08):

## 4. 장부 범위

```text
FE-T31, R-T15, settlement:v5.0.0-1.2.1, settlement:v5.0.0-3.2.2, settlement:v5.0.0-8.2.3, settlement:v5.0.0-14.2.6, transfer-refund:v5.0.0-1.2.1, transfer-refund:v5.0.0-3.2.2
```

- BUILD_ORDER F-07-9 줄의 장부 범위를 위 8항목으로 좁힌다(문서 통째 여섯 → 이 기능에 닿는 항목). 상태 `동결`과 `frozen-local` 분류는 그대로다(ADR-0386). `node tools/ci/ledger.mjs --batch F-07-9`: 항목 8개, 자동 시험 7·빈칸 1(R-T15). 시험 커밋에서 R-T15 시험이 생기면 자동 8·빈칸 0이 된다.
- **왜 이 8개인가**: `FE-T31`은 파트너 전 화면 반응형(AC-01), `R-T15`는 결제 직전 판매자 이름·고지·글씨(AC-07), `settlement:v5.0.0-1.2.1`·`3.2.2`와 `transfer-refund:v5.0.0-1.2.1`·`3.2.2`는 판매자 이름·고지를 글자 노드로만 그리는 것(AC-08), `settlement:v5.0.0-8.2.3`은 판매자 정보 필드 수준 접근(계좌 전체·연락처를 권한 밖에 싣지 않음, AC-05), `settlement:v5.0.0-14.2.6`은 정산 계좌를 은행·끝 4자리만 보이는 것(AC-05)이다.
- 장부에 넣지 않는 것: `I-T53`(패스키 재인증은 F-07-7·F-07-13의 몫이고 이 기능은 판매자 정보 표시만 한다), `J-T42`(F-07-7 회귀, 이 기능은 링크만), `J-T24`(F-07-8에서 동결), `settlement:v5.0.0-8.2.2`(정산서·지급 소유권은 이 기능이 안 바꿈), `transfer-refund:v5.0.0-8.2.2/8.2.3`(양도·환급 권한은 이 기능이 안 바꿈).
