# 기능 계획: F-09-8(kind 재가동·야간 실행 복구·kind 장부 재확인)

- **무엇**: 기능 F-09-8(`docs/BUILD_ORDER.md:143`)의 작업 목록이다(`docs/architecture.md` §8.6 4의 1). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다. 정본 값은 옮겨 적지 않고 자리만 가리킨다.
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-09-8`, 가지 `freeze/lane1-F-09-8`, 출발점 `8a7081d94`(2026-11-26 `origin/develop`, `fix(ticket-svc): … (R-T31 ①)`). 작업 트리는 깨끗했다. 2026-11-26T18:41+09:00에 계획을 시작했다.
- **등급과 차례**: B(`docs/BUILD_ORDER.md:143`). ADR-0373 결정 3의 B 차례는 계획 → 시험 → 구현 → 시험 통과면 합친다(시험 리뷰 없음)이나, 이 동결 로컬 트랙은 감독 지시로 **계획 → 시험/복구 절차 → 새 세션 리뷰 → 반영 → 실행·문서 → 기록**으로 한다. 이번 정지점은 **리뷰 준비**다. 리뷰는 계획·시험·구현을 맡지 않은 새 세션이 한다.
- **동결 로컬 범위**(ADR-0386 결정 4·5): `freeze/lane1-F-09-8` 가지만 쌓고 `develop`·`release/1.0.0`에 합치지 않는다. 체리픽하지 않는다. 이 기능의 DB 마이그레이션·릴리스 플래그는 없다. freeze 가지만 원격에 푸시한다.
- **7일 범위**(ADR-0373 결정 1·2, `docs/BUILD_ORDER.md:143` 비고): 측정에 로컬 클러스터가 꼭 필요하면 클러스터를 다시 띄우는 몫만 한다. INF-020의 나머지 배포 묶음(admission-ctrl 차트·리더 Service·`pod-deletion-cost`·`<서비스>-control` Service·`PEAKET_PROMETHEUS_URL`, kind Q-T12·G-09 등)은 **동결**이다. 이 계획은 INF-010·INF-030·INF-040만 한다.
- **정본**: `docs/BUILD_ORDER.md:815`(INF-010)·`:817`(INF-030)·`:818`(INF-040), ADR-0331 결정 9(`docs/adr/0331-trim-per-batch-checks-defer-kind.md:134~155`), ADR-0332(`docs/adr/0332-infra-build-out-segment-five.md:30~52`·`:83`), `docs/devops.md:189`(ci-kind 행)·`:191`(dast-nightly 행)·`:203`(perf-nightly 행)·`:231~262`(§3.3 시험 배치), `docs/infra.md:268~309`(§3 환경 분리·로컬 클러스터·v0), `tools/local/README.md:1~92`·`:164~181`(고정 판), `.github/workflows/ci.yml:92~98`, `ci-kind.yml`, `dast-nightly.yml`, `perf-nightly.yml`, `tools/ci/check-workflows.test.mjs:1160~1212`(BOT-161), `docs/review/ledger-notes.md:346`·`:362`(kind 보류), `docs/review/ledger/README.md`, ADR-0373·ADR-0386.
- **ADR**: 새 ADR은 쓰지 않는다. ADR-0332는 "구간 5에서 되살린다"고 이미 예고했으므로, 기록 차례에 상태 줄에 `일부 되돌림(2026-11-26, INF-030)`을 더한다. 계약(`docs/api/`)·마이그레이션은 바꾸지 않는다. 새 외부 계정·비용은 없다(공개 저장소 Actions 분은 무료).

## 감독에게

막는 물음은 없다. 아래는 추천대로 계획에 적었다. 다르게 정하면 이 계획과 그 정본 줄을 고친다.

1. **[결정 요청] 동결 로컬 범위를 INF-010·INF-030·INF-040으로 좁힌다.** F-09-8 행은 INF-020까지 갖지만, ADR-0373의 7일 범위는 "측정에 클러스터가 꼭 필요하면 다시 띄우는 몫만"이라 한다. INF-020의 OPS-300 배포 몫(admission-ctrl 차트 Lease RBAC·리더 Service·`pod-deletion-cost`·`<서비스>-control` Service·`PEAKET_PROMETHEUS_URL`)과 나머지 배포 묶음은 동결로 두고, F-09-8 행 비고에 그 사실을 기록한다. (추천)
2. **[알림, 소유자 몫] `PEAKET_KIND_IN_CI`는 이 가지에서 켤 수 없다.** 저장소 변수라 소유자가 GitHub 설정에서 `true`로 바꾼다(`docs/BUILD_ORDER.md:815` ①). 이 기능은 `ci.yml`의 조건이 변수를 그대로 보는지 정적으로 확인하고, 켠 뒤의 효과는 develop 병합 뒤에 본다. 변수를 켜지 않은 채 "kind 재가동 완료"로 적지 않는다.
3. **[알림, 한계] 예약(`schedule`)은 기본 가지에서만 돈다.** GitHub은 예약 워크플로를 기본 가지(`develop`)의 최신 커밋에서만 실행한다. freeze 가지에 `on.schedule`을 넣어도 이 가지에서는 실제로 울리지 않는다. 그래서 이 기능의 "야간 실행 복구"는 ① 워크플로 정의 복구 ② 같은 명령을 로컬에서 수동으로 돌린 증거 ③ 병합 뒤 첫 예약 실행을 기다리는 남은 몫으로 나눈다. 합병 전에 예약이 실제로 울렸다고 적지 않는다.
4. **[알림, 한계] Kyverno kind 시험은 Windows 로컬에서 돌릴 수 없다.** `tools/local/e2e/kyverno.e2e.mjs`는 Linux의 `--network host`를 전제한다(계획 `docs/review/plans/BAT-085.md` §kind e2e 무대). 이 PC에서는 `cluster.mjs kyverno --env demo`까지 확인하고 입장 시험은 CI(또는 Linux 환경)로 넘긴다. 넘긴 사실을 측정 기록에 적는다.
5. **[알림] C-T61 ⑦은 이 기능에서 닫지 않는다.** 장부 메모가 `BAT-365`(인프라·관측 배포)와 구간 5를 가리키고, BAT-365는 동결된 INF-020 몫이다. 재확인 표에는 넣되 상태를 `동결(INF-020)`으로 두고 통과로 세지 않는다.
6. **[알림] 병합 뒤 비용·알림이 생긴다.** 세 예약이 다시 돌면 주 1회 kind(약 90분 상한), 매일 DAST·야간 성능이 돈다. 공개 저장소 Actions는 무료지만, DAST·성능 실패는 SEV3 이슈를 연다. 동결을 풀어 develop에 합치는 시점의 소유자 판단이다.
7. **[알림] 클러스터 이름·포트를 분리한다.** 다른 갈래의 kind 클러스터를 지우지 않도록 `PEAKET_CLUSTER=freeze-f098`, `PEAKET_GATEWAY_BASE_PORT=18641`을 쓴다. 기본 이름 `peaket`을 쓰지 않는다(2026-11-21 BAT-086 정리 실수와 같은 사고를 막는다).
8. **[알림] B인데 시험 리뷰를 한다.** ADR-0373 결정 3은 B의 시험 리뷰를 빼지만, 이 트랙은 감독 지시로 새 세션 리뷰를 거친다. 리뷰 담당은 계획·시험·구현에 관여하지 않고, 계획 파일 '리뷰' 절과 담당 표 자기 줄만 고친다.

## 계획

### 1. 범위

- **A. INF-010 kind 재가동(로컬)**
  - A1. `PEAKET_CLUSTER=freeze-f098`, `PEAKET_GATEWAY_BASE_PORT=18641`로 kind 클러스터를 새로 띄우고, `ci-kind.yml`이 도는 순서대로 시험을 돌린다(클러스터 up → 이미지 → AWS 흉내 서버·릴레이 → 관측 → 프로브·진단 → v0 → 게이트웨이 → 메시 NetworkPolicy → Kyverno).
  - A2. 마지막 통과 커밋 `fe21934d`(2026-11-19) 뒤에 쌓인 실패를 가른다. ADR-0332 맥락이 든 후보(Kyverno 입장 시험, 게이트웨이 e2e, 데모 시드)를 먼저 본다. 실패마다 재현 명령·실패 줄·원인·고침(또는 남은 위험)을 측정 기록에 남긴다.
  - A3. `ci.yml`의 kind 잡 조건이 저장소 변수 `PEAKET_KIND_IN_CI`를 그대로 보는지 확인한다. 변수는 켜지 않는다(감독에게 2).
  - A4. 끝나면 이 가지의 클러스터만 `PEAKET_CLUSTER=freeze-f098 node tools/local/cluster.mjs down`으로 지우고, 다른 클러스터·컨테이너가 그대로인지 확인한다.
- **B. INF-030 야간 실행 복구**
  - B1. `ci-kind.yml`에 매주 토요일 03:00 KST(UTC cron `0 18 * * 5`) 예약을 되살린다. 수동 실행(`workflow_dispatch`)과 `workflow_call`은 그대로 둔다. 참고용이라 이슈를 열지 않는다(ADR-0331 결정 9).
  - B2. `dast-nightly.yml`·`perf-nightly.yml`에 매일 03:00 KST(UTC cron `0 18 * * *`) 예약을 되살린다. 수동 실행은 그대로 둔다. DAST는 예약 실패만 SEV3 이슈를 연다(기존 `notify-scheduled-failure` 잡).
  - B3. 같은 명령을 로컬에서 수동으로 돌려 실패를 고친다: DAST는 `tools/local/e2e/dast.e2e.mjs`(High 0), 야간 성능은 `tools/perf-ledger/nightly.py run`·`compare`(D-T40, `loadtest/nightly/config.json`·`threshold.json`). 성능 기준값(`max_ratio`)은 소유자·감독 결정 없이 바꾸지 않는다.
  - B4. 예약은 기본 가지에서만 도는 한계를 문서와 측정 기록에 적는다(감독에게 3).
- **C. INF-040 kind 장부 재확인**
  - C1. 재확인 표(`docs/review/measurements/F-09-8-kind-recheck.md`)를 만든다. 행은 ① ADR-0332 결정 4가 든 이미 통과한 항목(Q-T69 ②, S-T28 ①, D-T50, D-T43, D-T36, D-T11 ②, D-T18 ①·②, D-T19 ③·④, D-T33 ①·②, V-T43, I-T36) ② `ledger-notes`가 `kind 보류`로 적은 항목(V-T47 ⑥, V-T30 ③, C-T61 ⑦) ③ 이 기능이 새로 보는 kind 항목(V-T28 ①의 kind 부분) ④ BUILD_ORDER:818이 넘겨받은 F-01-4의 운영 확인 표 네 줄·Tempo 마이크로서비스 모드와 F-01-5의 로컬 Prometheus `rule_files`·Grafana 주석 링크다.
  - C2. 행마다 명령·판정 근거·상태를 채운다. 상태는 `대기`·`통과`·`실패`·`해당 없음`·`동결` 가운데 하나다. 실행하지 않은 항목을 `통과`로 적지 않는다. `동결`은 까닭(예: C-T61 ⑦은 BAT-365/INF-020)을 적는다.
  - C3. 실행으로 상태가 바뀐 항목만 `docs/review/ledger-notes.md`와 `docs/review/ledger/*.md`를 고친다. 장부 파일은 `node tools/ci/ledger.mjs`로 다시 쓴다(손으로 고치지 않는다). 미검증을 통과로 바꾸려면 그 행의 측정 기록을 가리킨다.
- **범위 밖(동결)**: INF-020의 모든 배포 묶음(admission-ctrl 차트·리더 Service·`pod-deletion-cost`·`<서비스>-control` Service·`PEAKET_PROMETHEUS_URL`, Q-T12·G-09), 실제 `PEAKET_KIND_IN_CI` 변수 설정, develop 병합 뒤 첫 예약 실행, BAT-365의 CronJob 경보(C-T61 ⑦), 운영 Grafana·Mimir·Loki·Tempo 배포 확인(V-T47 ⑥·V-T30 ③의 운영 판).

### 2. 장부 범위

`node tools/ci/ledger.mjs --batch F-09-8`(이 커밋): **항목 0개**(묶음 등급 B). F-09-8 행의 장부 범위가 `-`이고 "장부 없음: 시험·측정으로 본다"이기 때문이다. 그래서 `--require`는 빈 범위로 통과한다. INF-040이 다시 보는 항목은 다른 묶음의 장부 범위에 남아 있으므로, 이 기능은 그 항목의 상태를 바꾸되 F-09-8의 장부 범위를 새로 만들지 않는다. 재확인 결과는 표와 측정 기록으로 남긴다.

### 3. 바른 동작과 근거(값은 정본에서 읽는다)

- **kind 재가동**(`tools/local/README.md:9~13`, `docs/infra.md:279`): 클러스터는 `node tools/local/cluster.mjs up` 하나로 만든다. 사용자의 `~/.kube/config`는 바꾸지 않고 `.cache/peaket-tools/kubeconfig-<이름>`을 쓴다. 이름은 `PEAKET_CLUSTER`, 게이트웨이 포트 시작 값은 `PEAKET_GATEWAY_BASE_PORT`로 바꾼다. 도구는 공식 주소에서 받아 고정 SHA-256과 견주고, 이미지는 다이제스트로 고정한다.
- **ci-kind 순서**(`.github/workflows/ci-kind.yml:41~118`): `up` → `image` → `aws-emulator`·`relay-takeover` → `observability` → `probes` → `diagnose` → (v0 앞 정리) → `v0` → `v0-deploy` → (v0 정리) → `gateways` → 게이트웨이 시험 다섯 → `mesh-netpol` → 메시 시험 → `kyverno --env demo` → Kyverno 입장 시험(파일이 있으면) → `down`. 실패하면 상태·로그·이벤트·`/diag`·helm 값·버킷 목록·moto 로그를 남긴다.
- **kind 잡 조건**(`.github/workflows/ci.yml:92~98`): 저장소 변수 `vars.PEAKET_KIND_IN_CI == 'true'`이고, 바뀐 범위가 `kind`이거나 `develop` 푸시일 때만 `ci-kind.yml`을 부른다. 변수가 없으면 건너뛰고 `ci-summary`는 건너뛴 잡을 통과로 센다. 이 기능은 이 조건을 바꾸지 않는다.
- **예약 시각**(ADR-0331 결정 9, ADR-0332 맥락): ci-kind는 매주 토요일 03:00 KST, DAST·야간 성능은 매일 03:00 KST다. GitHub cron은 UTC라 KST 03:00은 전날 18:00 UTC다. 토요일 03:00 KST는 금요일 18:00 UTC이므로 `0 18 * * 5`, 매일은 `0 18 * * *`다.
- **예약의 뜻**(ADR-0332 결정 1·4): 셋 다 구간 5에서 되살린다. `ci-kind.yml`은 참고용이라 아무것도 막지 않고 이슈도 열지 않는다. DAST는 High(보안 등급 7.0 이상) 0을 막고, 예약 실패만 SEV3 이슈를 연다. 야간 성능은 D-T40의 상대 비교로 `threshold.json`의 `max_ratio`를 넘으면 실패하고 SEV3 이슈를 연다.
- **DAST 로컬 대역**(`tools/local/e2e/dast.e2e.mjs:1~54`): kind에 v0와 게이트웨이 다섯을 올린 뒤 `tools/ci/scan-tools.mjs dast`로 www·api·partner 셋을 ZAP 기준선 점검한다. 미끼가 High를 못 찾으면 대상 점검을 하지 않는다. 결과는 `dast-gate`(SARIF) → `scan-gate --tool zap`(High 7.0 판정)로 간다. ops-api·scanner-api는 뺀다.
- **야간 성능 로컬 대역**(`loadtest/nightly/config.json`, `prepare.mjs`, `tools/perf-ledger/nightly.py`): `prepare`가 kind를 `up --v0-only`로 올리고 v0를 배포하며, 가장 최근 출시 태그(`v0.2.0`, 이 커밋)를 기준판으로 따로 빌드해 `v0-base`에 올린다. `nightly.py run`이 두 판을 번갈아 5번 재고 `compare`가 p99 중앙값 비율을 `threshold.json`과 견준다. 전체 기한(`--deadline-s`)은 잡 상한보다 짧아야 멈춘 k6도 실패로 끝난다.
- **장부 재확인**(`docs/review/ledger/README.md`, `tools/ci/ledger.mjs:22~31`): 장부는 시험 이름과 notes로 상태를 정한다. `--require`는 빈칸·ID만·미검증·다른 단계를 실패로 센다. B 기능이라 빈칸은 합치기를 막지 않지만(ADR-0373 결정 3), 이 기능은 재확인 표로 미검증을 줄이는 것이 목적이다. `측정`·`사람 확인`으로 바꾸려면 근거(측정 기록·확인 목록)가 있어야 한다.

### 10. 완료의 정의

- 워크플로 셋의 `on.schedule`이 정한 cron과 같고, `INF-030 ①~③`이 통과한다.
- 복구 절차 문서가 ci-kind의 모든 무대·e2e 명령과 준비·정리 단계·한계를 담고, `INF-010 ①~③`이 통과한다.
- 재확인 표가 kind 보류·INF-040 항목을 모두 담고, 각 행에 명령·근거·상태가 있으며, `INF-040 ①~②`가 통과한다.
- kind 클러스터를 실제로 띄워 ci-kind 시험을 돌린 기록이 있고, 실패마다 원인·고침·남은 위험이 적혀 있다. 실행하지 못한 시험은 `건너뜀`과 까닭이 있다.
- DAST High 0과 야간 성능 D-T40의 로컬 수동 실행 결과가 기록되어 있다. 실패면 남은 위험과 맡을 곳이 적혀 있다.
- 상태를 바꾼 장부 항목은 측정 기록을 가리키고, `ledger.mjs`로 다시 쓴 장부와 어긋나지 않는다.
- 게이트가 통과하고(구현 전 실패가 정상인 시험은 구현 뒤 통과), `develop`·release에 합치지 않은 채 freeze 가지만 푸시한다.

### 11. 동결 로컬 범위와 한계

- 이 기능의 "완료"는 **로컬 증거**와 **병합 뒤 예약이 돌 정의**까지다. 실제 예약 실행·저장소 변수·develop CI 초록은 병합 뒤 몫이다.
- INF-020의 배포 묶음은 하지 않는다. admission-ctrl 차트·리더 Service·`pod-deletion-cost`·`<서비스>-control` Service·`PEAKET_PROMETHEUS_URL`, Q-T12·G-09는 동결 그대로다.
- 운영 Grafana·Mimir·Loki·Tempo의 실제 응답(V-T47 ⑥), 수집기 셋의 실제 kind 확인(V-T30 ③), CronJob 마지막 성공 경보(C-T61 ⑦)는 이 기능에서 닫지 않는다. 재확인 표에 `동결`·`해당 없음`과 까닭을 적는다.
- `release/1.0.0`·`main`에는 어떤 커밋도 넣지 않는다. 체리픽하지 않는다(ADR-0386 결정 4).

### 12. 정본 빈칸

- 예약 cron의 정확한 UTC 표기: ADR-0331 결정 9가 KST 시각만 정했고 UTC cron은 적혀 있지 않다. KST 03:00 = UTC 18:00(전날)로 옮겨 워크플로·시험에 적는다. 새 결정이 아니라 시간대 변환이라 ADR을 쓰지 않는다.
- 복구 절차 문서의 자리: `docs/`에 `runbooks/` 폴더가 아직 없고 `docs/infra.md:580`이 "런북 목차(예정)"만 둔다. 이 기능이 첫 런북으로 `docs/runbooks/F-09-8-kind-nightly-recovery.md`를 만든다(추천 적용, 2026-11-26). 정본의 런북 목차에 RB 번호를 더하지는 않는다(운영 런북이 아니라 개발·복구 절차다).
- 재확인 표의 상태 값: 장부 상태와 섞이지 않게 `대기`·`통과`·`실패`·`해당 없음`·`동결` 다섯으로 정한다(추천 적용, 2026-11-26). 장부에는 이 값을 쓰지 않고 `ledger.mjs`의 상태만 쓴다.
