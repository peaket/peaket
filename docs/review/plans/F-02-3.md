# 기능 계획: F-02-3(변경 동결 달력 — 규모별 창·ArgoCD/Karpenter 반영·승격 게이트·진행 중 롤아웃 자동 중단)

- **진행**: 구현 끝·게이트 통과(2026-11-24, 동결 범위 로컬 개발). 다음은 **새 세션 구현 리뷰**(ADR-0381)이고, 감독이 새 리뷰 세션을 띄울 때까지 멈춘다.
- **무엇**: BUILD_ORDER '기능 단위 계획' F-02-3(갈래 4, 등급 A, OPS-320, WBS 2.75일, 단계 줄 `OPS-320 wbs 4.4.3`)의 작업 목록이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **동결 범위**: ADR-0373 결정 2로 F-02-3은 v1 완성 범위 밖(`동결`)이다. 이 계획은 `freeze/lane2-F-02-3` 가지(기준 `333da1253`, 최신 `develop`)에서만 진행하고 `develop`·`release`에 합치지 않는다. 기능 표의 상태는 `동결` 그대로 둔다.
- **쉬운 말**: 공연 티켓이 열리는 시각 주변에는 서버·설정·인프라를 바꾸지 않는 '변경 동결 창'이 있다. 큰 공연은 90분 전부터 60분 뒤까지 모든 운영 변경을 막고, 작은 공연은 50분 전부터 60분 뒤까지 사람이 몰리는 길(핫패스)만 막는다. 이 기능은 승인된 공연 일정을 읽어 앞으로 7일의 창을 계산해 GitOps 달력 파일에 쓰고, ArgoCD의 동기화 금지 창과 Karpenter의 노드 중단 예산 0을 만들며, 창 안에서 운영 승격 PR을 막고, 창의 자동 중단 시각(T-45분·T-15분)에 아직 도는 롤아웃을 멈춘다. 긴급 변경은 라벨·인시던트 번호와 '되돌리기·플래그 끄기·오토스케일 정지' 모양일 때만 통과시킨다.
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-02-3`, 가지 `freeze/lane2-F-02-3`, 기준 `333da1253`(2026-11-24 최신 `develop`). 계획 담당은 제품·시험 코드를 쓰지 않았고 시험·Docker를 돌리지 않았다.
- **차례**: A등급 시험 먼저(ADR-0372·ADR-0373·ADR-0381): 계획 → 시험(기준 트리 실패 확인) → 시험 리뷰 → 시험 고정 → 구현 → 게이트 → **새 세션 구현 리뷰**. 구현 리뷰는 이 세션이 하지 않는다.
- **한 줄 결론**: 동결 달력의 순수 계산·렌더·게이트 판정·자동 중단 판정을 새 패키지 `@peaket/freeze-calendar`와 `tools/ci/freeze-gate.mjs`에 모으고, AWS S3·ArgoCD·Karpenter·Argo Rollouts 실제 연결은 포트와 메모리 가짜로 시험한 뒤 구간 5(INF-020, ADR-0331 결정 9)로 넘긴다. 장부 범위는 D-T1~D-T5·D-T26 여섯 항목으로 좁힌다.

## 2. 감독에게(정할 것)

아래는 이 계획이 정한 추천안이다. 방향을 바꾸는 것이 아니면 구현 중에 그대로 쓴다. 감독이 다르게 정하면 계획·시험을 고친다.

1. **장부 범위 좁히기(추천)**: 기능 표 F-02-3 행의 `판정 범위`를 `docs/devops.md, docs/infra.md`에서 `D-T1, D-T2, D-T3, D-T4, D-T5, D-T26`으로 좁힌다. 까닭: §8 전체를 범위로 두면 항목 130개(빈칸 42)라 이 기능과 닿지 않는 D-T6~D-T16·D-T18~D-T25·D-T27~D-T52가 섞인다. D-T17(오픈 시각 제한)은 HOT-030(2.3.2) 오픈 간격 규칙 검사 몫이라 뺀다. `docs/infra.md`는 바탕 문서로 남기고 범위에서 뺀다(장부 항목 0).
2. **실제 클라우드·클러스터 연결은 구간 5(추천)**: S3 일정 읽기·ArgoCD AppProject 창 적용·Karpenter NodePool 예산 패치·Argo Rollouts 중단은 포트와 메모리 가짜(또는 임시 폴더)로 시험한다. 실제 자격 증명·클러스터는 INF-020(구간 5)이다(ADR-0331 결정 9, F-02-1·F-02-2와 같은 처리). 이 기능은 렌더 결과 파일과 적용 포트까지 만든다.
3. **달력 산출물의 자리(추천)**: 봇이 바꾸는 것은 `deploy/calendar/` 아래뿐이다(devops §8.2 봇 쓰기 범위). `deploy/calendar/freeze.json`(창 목록)과 `deploy/calendar/rendered/argocd-windows.json`·`karpenter-budgets.json`(적용할 바라는 상태)을 쓴다. ArgoCD·Karpenter에 실제로 거는 일은 `CalendarApplier`·`NodePoolBudgetApplier` 포트가 맡고, 구간 5에서 실제 어댑터를 붙인다.
4. **`freeze-guard`의 배포 상태 읽기(추천)**: 같은 이미지에서 `calendar`·`guard` 두 명령을 둔다. 가드는 `PEAKET_FREEZE_CALENDAR_FILE`(ArgoCD가 마운트한 ConfigMap) 또는 같은 경로의 파일을 읽는다. 실제 마운트·CronJob·RBAC은 INF-020이다(AWS·kind 없이 시험).
5. **T-30분 점검 연결(추천)**: `deploy/platform/observability/rules/freeze.yaml`에 기록 규칙 `peaket:readiness:freeze_window`(달력 지표 `freeze_window_active`에서)와 `peaket:readiness:deployments`(가드 지표 `freeze_rollouts_in_progress`에서), 경보 `FreezeCalendarStale`(30분, SEV2, RB-28, G-19)를 더한다. ops-svc의 `readiness` 항목 `freeze-window`·`deployments`는 이미 `rule` 원천이라 코드를 고치지 않는다.
6. **긴급 변경의 증명(추천)**: `gitops-check`가 PR 라벨(`emergency-change`)과 본문의 `INC-<숫자>`를 확인하고, 바뀐 파일 모양이 ① 이전에 쓰던 이미지 다이제스트로 되돌리기 ② `deploy/envs/prod/flags/`의 플래그 끄기 ③ KEDA `autoscaling.keda.sh/paused-replicas` 정지 주석 중 하나일 때만 통과시킨다. 통과하면 `freeze_override_total`과 보안 로그 줄(`kind: security`, `event: freeze_override`)을 남긴다. 실제 수동 동기화 권한은 ArgoCD RBAC(구간 5)이다.
7. **D-T17과 오픈 시각 제한**: 이 기능에서 하지 않는다. HOT-030이 만든 오픈 간격 규칙 검사(2.3.2·2.9.1)가 정본 자리이고, 장부에서도 뺀다.
8. **D-T26의 코드 병합·태그**: 게이트는 `deploy/envs/prod`를 바꾸는 승격 PR에만 돈다. `develop`·`main` 병합과 태그, 데모 승격은 막지 않는다(devops §5.3, §8.1 '코드 병합은 막지 않는다'). 시험으로 `env=demo`와 코드 파일만 바뀐 경우를 확인한다.

## 3. 범위

### 3.1 하는 것

- **일정 읽기·검사(`@peaket/freeze-calendar`)**: `ops-calendar/upcoming-onsales.json`(판 번호·생성 시각·승인된 회차의 `eventId`·`opensAt`·`scale`)을 읽어 꼴을 검사한다. 승인되지 않은 회차·모르는 규모·겹친 회차·7일 밖·과거 회차·잘못된 시각은 거절한다. S3 어댑터와 로컬 파일 어댑터를 둔다.
- **창 계산**: 대형·중형은 `startsAt = opensAt − 90분`, `endsAt = opensAt + 60분`, `abortAt = opensAt − 45분`, 범위 `all`. 소형은 `startsAt = opensAt − 50분`, `endsAt = opensAt + 60분`, `abortAt = opensAt − 15분`, 범위 `hotpath`. 창은 UTC ISO로 저장하고, ArgoCD·Karpenter 크론은 UTC 5칸(`분 시 일 월 *`)으로 만든다.
- **렌더**: `freeze.json`(창 목록·판·생성 시각·7일 배포 가능 시간), `rendered/argocd-windows.json`(팀/프로젝트별 deny 창, `manualSync: true`), `rendered/karpenter-budgets.json`(모든 NodePool에 `nodes: "0"`, 같은 크론·기간). 지난 창은 지운다.
- **적용 포트**: `CalendarApplier`(ArgoCD AppProject 창 적용), `NodePoolBudgetApplier`(Karpenter 예산 패치). 시험은 가짜로 호출 횟수·값을 본다. 실제 어댑터는 구간 5.
- **닫힘 실패**: 일정 파일을 못 읽거나 일정 파일의 `generatedAt`이 30분 넘게 낡았으면 `freeze.json`을 바꾸지 않고 종료 코드 0으로 끝낸다(이미 걸린 창 유지). 산출물 파싱 실패·창 계산 불가는 종료 코드 1(운영 경보).
- **승격 게이트(`tools/ci/freeze-gate.mjs`, `gitops-check`가 부름)**: 운영(`prod`) 승격 PR만 본다. ① `freeze.json`이 없거나 2시간 넘게 낡았으면 막는다(닫힘 실패). ② 대형·중형 창 안이면 `deploy/envs/prod/`·`deploy/gateways/`·`infra/`의 모든 운영 값 변경을 막는다. ③ 소형 창 안이면 핫패스 배포 단위(`deploy/envs/prod/`의 queue-svc·purchase-svc·payment-svc·realtime-gw·identity-svc·web·queue-room, `deploy/gateways/`)를 바꾸는 경우만 막는다. ④ 긴급 변경 라벨·인시던트·허용 모양이면 통과하고 감사 로그·지표를 남긴다. ⑤ `demo`·`staging`·`local`·`ci`, 코드 파일만 바뀐 PR은 건너뛴다.
- **자동 중단(`guard`)**: `freeze.json`을 읽고, 지금이 `abortAt ≤ now < endsAt`인 창의 범위에 드는 진행 중 롤아웃을 `abort`한다. 대형·중형은 모든 롤아웃, 소형은 핫패스 워크로드만. 이미 중단·완료된 롤아웃은 건드리지 않고, 같은 실행에서 같은 롤아웃을 두 번 부르지 않는다. 목록·중단 실패는 종료 코드 1.
- **정본·장부**: `docs/devops.md` §8에 구현한 자리(파일 경로·시험 이름·구간 5로 미룬 것)를 한 줄씩 더한다. BUILD_ORDER F-02-3 행의 판정 범위를 2절 1대로 좁히고, 비고에 동결 범위 개발 가지를 적는다. `deploy/calendar/README.md`에 봇 산출물·적용 포트·구간 5 몫을 적는다.

### 정한 세부

- **창 계산**: `WINDOW_MINUTES` 하나에 규모별 앞·뒤·자동 중단 오프셋과 범위를 둔다. 대형·중형 90/60/45분·all, 소형 50/60/15분·hotpath. 크론은 UTC 5칸, 기간은 `150m`·`110m`. 7일 밖은 오픈 시각 기준으로 빼고, 이미 끝난 창은 뺀다.
- **닫힘 실패**: 일정 원천 읽기 실패·`generatedAt` 30분 초과는 산출물을 쓰지 않고 `skipped`로 끝난다. 파싱·쓰기 실패는 던져 종료 1이다.
- **게이트 범위**: `prod`만 보고 `deploy/envs/prod/`·`deploy/gateways/`·`infra/`를 운영 변경으로 센다. 큰 창은 모두, 작은 창은 `HOTPATH_WORKLOADS`와 게이트웨이만. `deploy/calendar/` 봇 PR과 코드 PR은 건너뛴다.
- **신선도**: 30분 초과는 경고, 2시간 초과·달력 없음·깨짐은 막는다(fail-closed). 긴급 변경이어도 달력이 없거나 낡았으면 통과시키지 않는다.
- **긴급 변경**: `emergency-change` 라벨과 본문 `INC-<숫자>`가 모두 있어야 시도로 본다. 되돌리기는 현재 파일의 다이제스트가 `git log <baseRef> -- <파일>` 조상 이력에 있을 때만, 플래그 끄기는 `deploy/envs/prod/flags/`의 `enabled: false`/`value: false`/`off`, 오토스케일 정지는 KEDA `autoscaling.keda.sh/paused-replicas` 주석일 때만 통과한다. 통과는 `audit` 레코드(`kind: security`, `event: freeze_override`)로 돌려주고 `gitops-check`/CLI가 로그에 남긴다.
- **자동 중단**: `abortAt ≤ now < endsAt`인 창만 본다. `Progressing`·`Paused`만, `all`은 모든 롤아웃, `hotpath`는 `HOTPATH_WORKLOADS`. 같은 실행에서 같은 `namespace/name`은 한 번만. 목록·중단 실패는 결과 `failed`와 오류 목록으로 남기고 나머지는 계속 시도한다(다른 롤아웃을 대신 건드리지 않음).
- **T-30 연결**: `peaket:readiness:freeze_window`는 `freeze_window_active`의 10분 최댓값(없으면 0), `peaket:readiness:deployments`는 `freeze_rollouts_in_progress`가 0일 때 1. `FreezeCalendarStale`은 `time() - freeze_calendar_last_render_timestamp > 1800`, SEV2, RB-28, G-19.
- **실제 연결**: S3 일정 읽기만 실제 SDK 어댑터를 두고(로컬은 파일), ArgoCD·Karpenter 적용과 Argo Rollouts 목록·중단은 포트와 로컬 `LoggingAborter`·파일 원천만 둔다. 실제 어댑터·CronJob·RBAC·이미지·지표 노출은 INF-020(구간 5)이다. `freeze_calendar_last_render_timestamp`·`freeze_window_active`·`freeze_rollouts_in_progress`를 내는 배선도 그때 붙인다.
- **시험 이의**: 구현 중 시험 설정 오류(작은 창 시각·KEDA 파일 경로·낡은 달력·타입)를 시험 담당이 고쳤고, `infra/`를 큰 창의 운영 변경으로 더했다(정본 §8.1).
