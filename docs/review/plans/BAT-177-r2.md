# BAT-177-r2 계획·기록(월렛 첫 화면 LCP 두 번째 바퀴: 앞 서버가 정적 파일에 압축을 넘긴다, OPEN[52] (나))

- **무엇**: OPEN[52] (나)의 두 번째 바퀴다. 소비자 웹 앞 서버(`apps/web/server/csp-hash-server.mjs`)가 **모든** 요청에 `accept-encoding: identity`를 붙여 안쪽 Next.js에 보내서, HTML이 아닌 `/_next/static/`의 CSS·JS까지 압축 없이 나간다. 이것이 월렛 LCP를 한도(7,255ms) 위로 밀어 올린다. ① 앞 서버가 `/_next/static/` 요청에만 손님의 `accept-encoding`을 그대로 넘기게 고치고(I1) ② 초안 PR CI에서 월렛 LCP 가운데 값이 7,255ms 이하이면 BAT-176 임시 알림을 지운다(I2). 한도 7,255ms·기준선 5,804ms·`LOAD_MARGIN`·`RUNS`는 그대로다.
- **쉬운 말**: LCP(가장 큰 글·그림이 화면에 그려지기까지의 시간)를 재는 Lighthouse는 느린 휴대폰 회선(초당 1.6메가비트, 왕복 150ms)을 흉내 내며, 받은 **바이트 수**로 시간을 셈한다. 지금 첫 화면 CSS 파일 하나가 압축 없이 약 26만 바이트로 오는데, 압축하면 약 3만 바이트 [가정]다. 그 차이만 흉내 회선에서 1초가 넘는다. 압축을 끈 까닭은 HTML 안 스크립트의 지문(해시)을 압축 전 본문으로 재야 해서다. 그런데 지문이 필요한 것은 HTML뿐이고 CSS·JS 파일은 아니다. 그래서 HTML이 될 수 없는 정적 파일 길(`/_next/static/`)에만 압축을 다시 켠다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane2-base-BAT-177`, 가지 `feature/lane2-BAT-177`, 출발 `origin/develop` `450ab6cd7`. 2026-11-23 계획 담당이 썼고 시험·제품 코드는 쓰지 않았다. 읽은 것: 앞 바퀴 `docs/review/plans/BAT-177.md` 전체, `apps/web/server/csp-hash-server.mjs`·`csp-hash-server.test.mjs`·`start.mjs`, `apps/web/proxy.ts` 123줄(matcher), `apps/web/next.config.ts`(`compress` 설정 없음 = Next.js 기본 켬), `docs/adr/0193-…` 결정 3, `docs/adr/0326-…` 머리, `docs/frontend.md` §5.8(1270줄 'Lighthouse CI')·§5.14.1(1394줄)·§6.2, `docs/devops.md` 209줄(`ci-web.yml` ④), `tools/web-checks/budgets/`(limits·lighthouse.spec·report·js.spec와 그 시험), `tools/web-checks/test/sri.mjs`, `.github/workflows/ci-web.yml` `budgets` 잡, `tools/ci/roles-check.mjs`, 감독이 내려받은 develop CI `budgets-reports` 산출물 5개의 `lighthouse/월렛.json`.
- **등급**: C(앞 바퀴와 같다). 앞 서버의 압축 요청 머리 하나와 검사 도구의 알림 갈래를 바꾼다. 돈·좌석 홀드·대기 순번에 닿지 않는다. HTML의 CSP 해시 길은 바뀌지 않는다. 단계 `-`, 장부 범위 `-`, WBS 0.15일 [가정], 마감 2026-11-30(`WARN_ONLY`의 되돌릴 날).
- **차례**: 정방향(`Batch-Order: impl-first`, ADR-0281 결정 5). 계획 → 구현 I1(앞 서버 고침·ADR 0359) → 시험(T1~T5, 실패 확인) → 초안 PR CI 측정 → (측정 통과 때만) 시험 T-I2(spec 알림 고리 지우기·알림 없음 시험) → 구현 I2(`limits.mjs`·`report.mjs` 알림 지우기·정본 §5.8·devops) → 시험 결과 → 리뷰 → 검증 → 기록(감독). 측정이 7,255ms를 넘으면 T-I2·I2를 하지 않고 감독에게 보고한다.
- 이 파일은 역할마다 자기 절만 쓴다: 계획(아래), 실패 확인·시험 결과(시험), 시험 이의(구현), 리뷰, 검증, 담당 표·기록(감독). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.

## 감독에게

1. **원인은 감독 조사 그대로 받아 썼고, 산출물로 다시 확인했다.** develop CI `budgets-reports` 산출물 5개(14722882424·14726220046·14737206430·14738967258·14749057674)의 `lighthouse/월렛.json`을 읽었다. 가운데 값 7,141 / 8,121 / 8,119 / 7,149 / 8,121ms(한도 7,255). 25회 모두 LCP 요소가 `div.card-flat > img.wallet-qr-skeleton`이고, 가운데 회차 분해는 TTFB 13.7~17.1ms·불러오기 지연 0·불러오기 0·그리기 지연 110.9~132.5ms다(느리게 하지 않은 실제 값). `renderBlocking`에는 늘 `/_next/static/chunks/<해시>.css?dpl=…` totalBytes **263,674**(절감 1,502~1,653ms)와 `/seed-color-mode.js` 3,578B(302~303ms) 둘이 있다. CSS 바이트가 빌드 다섯 개에서 한 바이트도 다르지 않은 것은 압축 없이 원본 크기로 나갔다는 뜻이다. 원인 자리는 `csp-hash-server.mjs` 189줄이다.
2. **새 ADR이 필요하다고 판단했다: ADR 0359**(갈래 2 몫 0359~0361의 첫 번호). ADR-0193 결정 3의 넷째 점(32줄 '해시는 압축 전 본문으로 낸다. 그래서 안쪽 서버에는 압축하지 말라고 보낸다(`accept-encoding: identity`, 압축은 CDN이 한다)')은 범위를 적지 않아 모든 요청을 뜻하고, 이번 고침은 '정적 덩어리는 원 서버(Next.js)가 압축한다'로 **누가 압축하는지**를 바꾼다. 이 저장소는 ADR 본문을 고치지 않고 뒤 ADR과 상태 줄로 바꾼 기록을 쌓는다(`docs/architecture.md` 1623줄). 그래서 짧은 새 ADR로 좁히고, ADR-0193 상태 줄에 한 마디를 단다. 보안 성질(HTML의 응답 때 해시, 압축된 HTML은 해시 없는 막는 CSP)은 그대로라 소유자 결정 없이 '추천 적용, 감독 승인'으로 둘 수 있다고 본다. 감독이 승인하지 않으면 I1 전에 멈춘다.
3. **알림 되돌리기는 측정을 통과한 뒤에만 한다.** I1 + 시험 커밋으로 초안 PR CI `web / budgets`를 돌려 월렛 LCP 다섯 회 가운데 값이 7,255ms 이하일 때만 T-I2·I2를 한다. 넘으면 알림을 남기고 감독에게 보고한다(한도를 바꾸지 않는다). 측정 때 `runs[].lcp.renderBlocking`의 CSS `totalBytes`가 크게 줄었는지(아래 9의 확인 2)를 함께 본다. 줄지 않았으면 고침이 CI에서 효과가 없는 것이므로 판정 전에 원인을 본다.
4. **I2는 시험 담당이 먼저 한다.** 알림 고리(`loadVerdict` 부르기·경고 갈래·`warnLine`)는 시험 파일 `lighthouse.spec.mjs`에 있고 구현 커밋은 시험 파일을 건드리지 않는다(앞 바퀴 계획 §8의 경계). 그래서 T-I2(시험: spec 고리를 지우고 알림 없음 시험을 넣음, 이때 `limits.mjs`에 `WARN_ONLY`가 남아 T6가 실제로 실패) → I2(구현: `limits.mjs`·`report.mjs`·정본) 차례다. roles-check 정방향 규칙(첫 test·첫 impl 사이 차례를 보지 않음)과 맞는다.
5. **마감**: `WARN_ONLY`의 되돌릴 날이 2026-11-30이다. 이 묶음이 그날까지 합쳐지지 않으면 한국 시각 2026-12-01부터 월렛 LCP 판정이 저절로 실패로 돌아온다(그 자체는 정본대로다). 측정이 한도를 넘으면 그 전에 소유자에게 (가)(기준선 다시 잡기)를 다시 물어야 한다(`docs/frontend.md` §5.8 '(나)로 안 풀리면').
6. **`/seed-color-mode.js`(public 파일, 3,578B, 302ms)는 이번에 손대지 않는다.** 지시대로 public 파일은 `identity` 그대로다. 302ms는 대부분 왕복 시간이고 크기 몫은 작다 [가정]. 측정이 7,255를 넘으면 다음 후보로 보고에 적는다(아래 13).
7. **BUILD_ORDER는 손대지 않았다.** 행 문안은 아래 10 끝에 적었다. 감독이 BAT-177 행 아래에 넣는다.
8. **정본은 고치지 않았다.** 고칠 자리와 내용은 아래 10에 적었다. ADR 0359·ADR-0193 상태 줄·§5.14.1은 I1이, §5.8·devops 209줄은 I2가, 진행 기록은 감독이 고친다.

## 계획

### 1. 범위

- **한다**:
  - 앞 서버가 안쪽 Next.js에 보내는 `accept-encoding`을 요청마다 고른다. `GET`·`HEAD`이고 경로가 `/_next/static/`으로 시작하는(아래 4의 판정) 요청만 손님의 값을 그대로 넘기고, 나머지는 지금처럼 `identity`다. 판정은 순수 함수로 빼서 내보낸다.
  - 그 결정을 ADR 0359로 남기고, ADR-0193 상태 줄·`csp-hash-server.mjs` 머리 주석(12줄)·`docs/frontend.md` §5.14.1 문장을 맞춘다(I1).
  - 위 동작을 `node --test` 시험으로 고정한다(`csp-hash-server.test.mjs`).
  - 초안 PR CI 측정이 한도 안이면 BAT-176 임시 알림을 지우고 정본 두 곳을 '되돌렸다'로 고친다(T-I2·I2).
- **그대로 둔다**:
  - HTML이 될 수 있는 모든 요청(화면 주소, RSC 화면 데이터, `/_next/image`, public 파일, 처리기, POST)은 `identity`. 캐시 화면 HTML의 응답 때 해시, 2MiB 상한, 압축된 HTML → 해시 없는 막는 CSP(207·211~223줄), 304·HEAD·RSC 처리(198~203줄), 502·끊김 처리.
  - Next.js 설정(`next.config.ts`의 `compress` 기본값 켬). 앞 서버가 스스로 압축하지 않는다(노드 기본 모듈만, 바이트는 그대로 흘린다).
  - `lighthouse-baseline.json`의 월렛 `lcpMs` 5,804, `LOAD_MARGIN`({ ms: 0.25, cls: 0.02 }), `RUNS` 5, `loadLimit`·`median`·`jsLimit`, 첫 JS 한도(`/my/tickets` 161.6kB), 다른 일곱 화면의 세 지표 판정, 앞 바퀴의 LCP 기록 칸(`runs[].lcp`·`lcpSummary`·`lcpTable`).
  - 월렛 화면 코드(앞 바퀴의 data URI QR 뼈대·`afterLoad`). 화면 모양은 바뀌지 않는다.
- **하지 않는다**:
  - HTML 압축(ADR-0193 그대로, CDN 몫), 앞 서버 스트리밍, critical CSS 인라인, CSS 줄이기, 글꼴 파이프라인.
  - public 파일(`/seed-color-mode.js` 등)·`/_next/image` 압축.
  - 기준선 다시 잡기·한도 넓히기((가)). 넘으면 보고한다.
  - `apps/web/scripts/local-fan-gateway.mjs`(로컬 개발 관문, 87줄 `identity`)는 손대지 않는다. 운영·CI 측정 길이 아니다.
  - 마이그레이션·새 표·새 외부 연동·새 저장소·Docker.

### 2. 현재 상태(출발점 `450ab6cd7`)

- **앞 서버**: `createCspHashServer`(186~260줄)가 189줄에서 `{ ...req.headers, 'accept-encoding': 'identity', 'x-forwarded-host': … }`로 모든 요청을 안쪽에 보낸다. 응답에 틀 머리(`x-peaket-csp-template`)가 없으면 198~203줄에서 머리·본문을 그대로 흘린다. `proxy.ts` 123줄 matcher가 `_next/static`·`_next/image`·자산 확장자를 건너뛰므로 `/_next/static/` 응답에는 원래 틀 머리가 없다. 곧 정적 파일은 지금도 '그대로 흘리기' 길이고, 바뀌는 것은 위로 보내는 머리 하나뿐이다.
- **압축된 HTML 안전 길**: 틀 머리가 있는 HTML에 `content-encoding`이 `identity`가 아니면(207줄) 첫 조각에서 해시 없이 막는 CSP로 머리를 쓰고 흘린다(211~223줄). 시험은 `csp-hash-server.test.mjs` 182~196줄('위 서버에는 압축하지 말라고 보낸다…')로, `/` 요청에 손님 `gzip, br`을 줘도 위 서버가 `identity`를 받고, 위 서버가 gzip HTML을 주면 해시 없는 CSP인지 본다. 이 시험은 경로가 `/`라 고친 뒤에도 그대로 통과해야 한다(회귀).
- **Next.js 압축**: `next.config.ts`에 `compress`가 없어 기본(켬)이다. `next start`와 standalone 서버는 손님이 `gzip`을 받으면 압축할 만한 응답(CSS·JS 등)을 gzip으로 주고 `Vary: Accept-Encoding`을 단다 [가정: Next.js 16.4.3 기본 동작. brotli는 하지 않는다. 구현 담당이 로컬 운영 빌드의 안쪽 포트에 `curl -sI -H 'accept-encoding: gzip' http://127.0.0.1:<안쪽>/_next/static/chunks/<파일>.css`로 `content-encoding: gzip`을 확인해 I1 커밋 본문에 적는다].
- **측정 무대**: `tools/web-checks/seed-css/apps.mjs` 101~110줄이 소비자 웹을 `server/start.mjs --port <p> --inner-port <p+1000>`으로 띄운다. `web / budgets` 잡(ci-web.yml 268줄~)이 그 위에서 `pnpm run budgets`(첫 JS·Lighthouse)와 `pnpm run csp`(CSP·SRI)를 돈다.
- **임시 알림(BAT-176, 앞 바퀴가 되살림)**:
  - `tools/web-checks/budgets/limits.mjs` 51~96줄: `WARN_ONLY`(56~58줄, 월렛 `lcpMs`, until '2026-11-30'), `KST_OFFSET_MS`(60), `DATE_RE`(61), `kstDate`(68~71), `checkWarnEntry`(74~78), `loadVerdict`(86~96).
  - `tools/web-checks/budgets/lighthouse.spec.mjs`: 머리 주석 8~11줄, 20줄 `loadVerdict` 가져오기, 39~43줄 `ghEscape`·`warnLine`, 78~79줄 시계 `now`, 98~105줄 `verdict`·`warnOnly` 모으기, 107줄 기록의 `verdict, warnOnly`, 116~122줄 경고 갈래(`continue`).
  - `tools/web-checks/budgets/report.mjs`: 37~49줄 `metricVerdict`(기록의 `verdict`)·`warnText`, 51~68줄 `lighthouseTable`의 '알림만' 갈래(53줄 주석, 62·64줄).
  - 시험: `limits.test.mjs` 5줄 가져오기(`WARN_ONLY`·`kstDate`·`loadVerdict`), BAT-177 T7 ①~⑥(162~254줄), T9 ①(255~278줄, `loadVerdict`로 판정), T9 ③(280~305줄, 지표 loop의 `continue`가 하나뿐이라고 단언). `report.test.mjs` 147~176줄(`WALLET_WARN`·T7 ①), 177줄~ T9 ②.
  - 정본: `docs/frontend.md` 1270줄 '**다만 월렛 첫 화면의 LCP 하나만은 임시로 …**'부터 '(나)가 할 일: … 알림만 표시를 지운다.'까지, `docs/devops.md` 209줄 ④ 괄호 안 '월렛 첫 화면의 LCP만은 임시로 넘어도 … docs/frontend.md §5.8 'Lighthouse CI''. `docs/observability.md` 630줄은 예외 문장이 없어 알림을 지우면 다시 맞다(R176-4는 문장을 단 적이 없다).

### 4. 공개 인터페이스(시험 담당이 기댄다. 이름은 구현이 이대로 쓴다)

모두 `apps/web/server/csp-hash-server.mjs`에서 내보낸다. 순수 함수이고 던지지 않는다.

- **`STATIC_ASSET_PREFIX = '/_next/static/'`** (문자열 상수, 끝 `/` 포함).
- **`isStaticAssetRequest(method: string | undefined, url: string | undefined): boolean`** — 손님의 압축 요청을 위로 넘겨도 되는 요청인가.
  - `method`가 대문자 `GET`이나 `HEAD`가 아니면 `false`.
  - `url`(요청 대상 글, `req.url` 그대로)이 문자열이 아니면 `false`. `?` 앞을 경로로 본다(쿼리 `?dpl=…`는 판정에 쓰지 않는다).
  - 경로가 `STATIC_ASSET_PREFIX`로 **대소문자까지 정확히** 시작해야 한다. `/_next/static`(끝 `/` 없음), `/_next/staticx/…`, `/_NEXT/static/…`, `//_next/static/…`, `http://h/_next/static/…`(절대 꼴)은 `false`.
  - 경로에 `%`(퍼센트 인코딩 전부), `\`, 빈 마디(`//`), `.`이나 `..` 마디가 있으면 `false`. 접두 뒤가 비었으면(`/_next/static/`만) `false`.
  - 위를 모두 통과하면 `true`. 이 판정은 성능용이다. 틀려서 HTML 요청이 넘어가도 압축된 HTML은 207·211~223줄의 해시 없는 막는 CSP 길로 가므로 보호가 풀리지 않는다(화면이 깨질 뿐, 닫힘 실패). 그래서 거부 목록이 넓어도 된다.
  - [가정] 운영 빌드의 `/_next/static/` 파일 이름에 `%`·`\`가 없다. 구현 담당이 `apps/web/.next/static` 목록에서 확인해 커밋 본문에 적는다.
- **`upstreamAcceptEncoding(req: { method?: string, url?: string, headers: Record<string, string | string[] | undefined> }): string`**
  - `isStaticAssetRequest(req.method, req.url)`가 참이고 `req.headers['accept-encoding']`가 빈 글이 아닌 문자열이면 그 값을 **고치지 않고** 돌려준다.
  - 그 밖은 모두 `'identity'`(손님 값이 없거나, 배열이거나, 빈 글인 정적 요청 포함).
  - 189줄은 이 값을 그대로 위 머리에 넣는다. 다른 손님 머리는 지금처럼 복사한다.
- **응답 쪽 동작(바뀌지 않음, 시험이 기댄다)**: 틀 머리 없는 응답은 위 서버의 상태·머리(`content-encoding`·`vary`·`content-length`/`transfer-encoding` 포함)와 바이트를 그대로 흘린다. 앞 서버는 풀거나 다시 압축하지 않는다. `/_next/static/`이라도 응답이 `text/html` + 틀 머리 + `content-encoding: gzip`이면 해시 없는 막는 CSP(`fill(template, [])`)를 단다.
- I2 뒤 `tools/web-checks/budgets/limits.mjs` 내보내기: `JS_OVER_BUDGET_MARGIN`·`jsLimit`·`RUNS`·`LOAD_MARGIN`·`loadLimit`·`median`만. `report.mjs` 내보내기 이름(`jsTable`·`lighthouseTable`·`lcpTable`·`renderReport`)은 그대로.
- HTTP·gRPC·DB·API 계약 변경 없음.

### 11. 브라우저 확인

**필요하다(가볍게).** 화면 모양은 바뀌지 않지만 첫 화면이 받는 정적 파일의 응답 머리가 바뀐다. Claude 데스크톱의 내장 브라우저(Browser pane)로 보고, 기록은 `docs/review/browser-check/` 폴더에 묶음 ID BAT-177-r2 이름으로 남긴다.

1. 로컬 운영 빌드를 `apps/web/server/start.mjs`(앞 서버)로 띄우고 `/my/tickets`를 연다.
2. 네트워크 요청 목록(`read_network_requests`)이나 페이지 안 `performance.getEntriesByType('resource')`로 `/_next/static/chunks/*.css`·`*.js`의 응답 머리 `content-encoding: gzip`과 전송 크기(`transferSize` < `decodedBodySize`)를 본다.
3. 문서(`/my/tickets` HTML) 응답은 `content-encoding`이 없고 `content-security-policy`에 `'sha256-…'` 해시가 들어 있다(캐시 화면이면). 요청 화면이면 nonce 정책 그대로다.
4. 월렛 화면이 지금과 같이 뜬다: QR 뼈대 그림, 안내 문구, `load` 뒤 QR 자리 바뀜, 콘솔 CSP 위반·오류 0.
5. 다른 캐시 화면 하나(홈 `/` 또는 공연 상세)도 열어 CSP 위반 0, 스타일이 깨지지 않음을 본다(HTML이 압축되어 해시 없는 CSP로 막히는 결함 M8을 눈으로 확인).
6. LCP는 브라우저 확인에서 판정하지 않는다(CI 산출물로 본다).
