# F-03-7 계획(감사·리플레이·법정 조치·나머지 명령 화면, 동결 로컬)

- **무엇**: `docs/BUILD_ORDER.md` '기능 단위 계획' 표의 F-03-7 행(69행)과 단계 줄 `OPS-390`·`OPS-400`(711~712행)의 남은 몫을 동결 로컬에서 진행하는 B 등급 화면 기능의 작업 목록이다(ADR-0373, ADR-0386). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다. 정본 값은 옮겨 적지 않고 자리만 가리킨다.
- **쉬운 말**: 지금 관제 콘솔의 감사(`/audit`)·법정 조치(`/compliance`) 화면은 그림만 있는 미리보기 보드다. 명령 화면도 명령 1·3·6만 실제로 낼 수 있다. 이 기능은 ① 감사 로그·인시던트 리플레이(SCR-031)를 실제 서버 값(명령 원장·감사 체크포인트)으로 읽고 검증 묶음을 내보내며 타임라인을 재생하고, ② 법정 조치(SCR-032)의 통보·자료 요청·보안 사고·접속기록 점검 목록·상세·등록·차단·철회·추출 요청·승인·거부·제출 기록·판단·신고 기록·종결·이상 건 종결을 계약대로 잇고, ③ 나머지 운영 명령(2·4·5·8·9·11·12)의 작성 화면과 명령 4·5 효과 줄, 걸린 자동 조치 표시를 더한다. ④ 자동 조절 복귀 확인(C-T31 ③)은 화면 모델과 대기 알림까지 만들되 서버 확인 경로가 없어 실제 전송은 막고 남은 위험으로 적는다.
- **바탕**: 동결 로컬 가지다(ADR-0386 결정 4). 작업 폴더 `D:/ticketpass-freeze-F-03-7`, 가지 `freeze/lane2-F-03-7`, 출발 `1d10d6da3`(최신 develop, 2026-11-25). `develop`·`release/1.0.0`에 합치지 않고 이 가지 하나만 원격에 둔다. 기능 표 분류는 `frozen-local`이라 v1 릴리스 계약에 들어가지 않는다(`docs/release/v1-scope.json`). 담당 세션 `lane2-freeze-F-03-7-opencode`(계획·시험·구현을 한 세션이 맡는다. 동결 로컬 지시에 따른 예외이며 `roles-check`의 '역할마다 다른 세션'을 통과하지 못한다 — '감독에게' 6).
- **등급·차례**: B. 동결 로컬이라 ADR-0373의 가벼운 차례(계획 → 시험 → 구현 → 시험 통과)를 따르되, 합치기 게이트는 돌리지 않는다. 시험은 구현 전 기준 트리에서 실패를 확인하고 계획 파일 '실패 확인' 절에 남긴다. 시험 파일은 구현 커밋에서 고치지 않는다.
- **범위 결정**: BUILD_ORDER F-03-7 행은 감사·리플레이(SCR-031), 법정 조치(SCR-032, OPS-400), 명령 2·4·5·7~12 작성 화면, 명령 4·5 효과 줄, 자동 조치, 한 글자 단축키·사용성, `/me` 패스키 줄, 명령 3·11 사후 검토 보고서 폼, C-T7 ③ 런북 CLI를 모두 적었다. 이번 동결 로컬 바퀴는 **화면과 모델이 계약·정본으로 닫히는 몫**을 끝낸다. 서버 모듈이 없는 부분(법정 조치 REST, 감사 원장 조회, 자동 조절 복귀 확인)은 계약 모양대로 화면을 만들고 실제 서버 경로를 남은 위험으로 적는다(사용자 지시 2).
- **한 줄 결론**: 새 계약·새 패키지 없이 `apps/console-host` 안에서 ① 감사 화면(명령 원장 + 체크포인트 읽기, 검증 묶음 내보내기, 타임라인 재생), ② 법정 조치 화면(계약 `ComplianceNotice`·`DataRequest`·`SecurityIncident`·access review), ③ 명령 2·4·5·8·9·11·12 작성 모델과 화면, ④ 명령 4·5 효과 줄과 자동 조치 표시를 만든다. 화면 시험은 `node --test`(console-host 단위)와 기존 `tools/web-checks` 무대를 쓰고, Docker·kind는 쓰지 않는다.

## 감독에게

1. **동결 로컬 범위와 서버 상태(2026-11-25 확인)**: `services/ops-svc/src/modules/`에 `compliance` 모듈이 없다. openapi에 법정 조치 경로·스키마는 있으나 서버 구현은 다른 갈래(또는 뒤 바퀴) 몫이다. 감사 원장(명령별 사유·승인자·dry-run·ack)을 행 단위로 읽는 경로도 openapi에 없다(wbs 0.2.3 '감사 로그 조회' 몫). 그래서 이번 화면은 ㉠ 명령 원장(`GET /v1/ops/commands`)을 감사 행의 원천으로 쓰고(명령 감사는 정본 §7이 명령 원장과 감사 체인을 함께 원본으로 둔다), ㉡ 체크포인트·검증·공개 앵커(`/v1/ops/audit-checkpoints*`, `/v1/ops/audit-anchors*`)로 체인 상태를 보이며, ㉢ 명단 다운로드 기록·원본 로그 내보내기는 "원천 연결 전"으로 둔다. 법정 조치 화면은 계약대로 다 잇되 서버가 없어 실제 응답은 대역으로만 확인한다. 이 두 가지를 남은 위험 1·2로 적는다.
2. **명령 7·10·사후 검토 폼**: 명령 7(대기실 공지)은 계약 `Command.params`가 열려 있고(정본 §3은 '미리 승인한 문구 템플릿'만 말한다), 문구 템플릿 ID 목록이 정본에 없다. 명령 10은 `POST /v1/ops/compliance/notices/{noticeId}/takedown`으로만 내야 해서 명령 작성 화면에 두지 않는다. 명령 3·11 사후 검토 보고서 폼은 `POST …/post-review` 계약이 있으나 화면 항목·검증 규칙이 d5에 아직 없다. 셋은 이번 바퀴에서 **자리 안내와 원천 연결 전 표시**만 하고, 다음 몫으로 넘긴다('하지 않는다').
3. **장부 범위**: F-03-7의 장부 범위는 `C-T7 ②, C-T8, C-T31 ③` 셋이다(묶음 등급 B). 이번 시험이 셋을 모두 콘솔 영역 시험으로 채운다. C-T8의 '감사 2건'은 서버 판정이라 화면은 되돌리기 ack와 감사 행 두 줄(실행·되돌림)을 보이는 데까지 한다. C-T31 ③은 서버 확인 경로가 없어 '확인 대기 알림 + 전송 막힘'까지만 한다(남은 위험 3). `--require`는 지금도 빈칸 0이지만, 시험 뒤 다시 확인한다.
4. **정본 고침은 하지 않는다**: 새 결정이 없고, 동결 기능은 v1 계약 밖이다. 다만 `docs/security/asvs/control-tower.md` 1.2.1·3.3.4·8.1.2·14.2.1의 '구현 위치' 칸에 이 화면 글을 더하는 것은 CLAUDE.md 절대 규칙(보안 추적 표 먼저)에 따라 계획 커밋에서 한다. 계약·정본 값은 바꾸지 않는다.
5. **Docker·kind·브라우저 없음**: 사용자 지시 3대로 Docker·kind를 쓰지 않는다. `tools/web-checks`의 기존 console-csp/console-remotes 무대는 손대지 않고 그대로 통과하는지만 본다. 실제 서버가 필요한 시험은 가짜 `fetch` 대역으로 확인하고, 브라우저 확인은 이번 바퀴에서 하지 않는다(동결 로컬, 마지막 날 몫).
6. **역할 확인 예외**: 계획·시험·구현을 한 세션(`lane2-freeze-F-03-7-opencode`)이 맡는다. `tools/ci/roles-check.mjs`는 `Agent-Session`이 역할마다 달라야 한다고 보므로 이 가지는 합치기 전 역할 확인을 통과하지 못한다. 동결 가지이고 합치지 않으므로 게이트에서 빼고 보고에 적는다(지시서가 정한 세션 ID 그대로).

## 계획

### 1. 범위

**한다(화면: `apps/console-host`)**

1. **SCR-031 감사 로그·인시던트 리플레이(`/audit`)**
   - 목록: `GET /v1/ops/commands`(최근 100, `updatedAfter`·`type`·`state`·`eventId` 거르기)를 감사 행으로 바꾼다. 행은 d5 §7.4의 칸(시각·행위자·명령·사유·승인자·dry-run 결과·결과)을 채운다. 행위자는 `requestedBy`, 승인자는 `approvals`, dry-run은 `CommandState.dryRun`, 결과는 `state`·`ackedAt`·`lastError`다. SYSTEM(AUTO_EXPIRED)과 런북 CLI 행위자 구분은 값이 없으면 '—'로 둔다.
   - 필터: 기간(최근 1시간·24시간·7일·전체), 행위자(사람·SYSTEM·런북 CLI), 종류, 검색(명령 ID·사유·회차). 거르기는 화면 안 상태로만 하고 주소에 사유·검색어를 싣지 않는다(ASVS 14.2.1).
   - 체인 상태: `GET /v1/ops/audit-checkpoints` 최신순 + `GET …/{id}/verification`으로 '검증됨'·'대기'·'실패' 배지를 보인다. 공개 앵커는 마지막 공개 체크포인트의 `no`·`publishedAt`·`otsState`로 '확정 대기'·'게시 지연' 띠를 그린다. 체인 변조면 danger 배너와 보안 사고 안내 문구(d5 §7.4).
   - 행 상세: 선택한 명령의 `GET /v1/ops/commands/{id}`(operator·commander만)로 사유·매개변수·승인 기록·dry-run 전문·전달 경로·ack를 보인다. viewer는 상세를 부르지 않는다.
   - 검증 묶음 내보내기: commander가 사유를 적고 `POST /v1/ops/audit-checkpoints/{id}/verification-bundles`를 부른다. 응답(정규화 기록·잎 솔트·포함 증명·체크포인트·서명·공개키)은 화면에서 열지 않고 JSON 파일로 내려받는다. 사유는 500자, 내보내기 기록은 서버가 남긴다. operator·viewer·휴대폰은 막고 까닭을 보인다(C-T39).
   - 원본 로그 내보내기(④)와 명단 다운로드 기록 탭은 계약 경로가 없어 '원천 연결 전' 카드로 두고, 접속기록에 남는 내보내기라는 사실과 준비 중인 경로(wbs 0.2.3)를 적는다.
   - 리플레이: 선택한 기간의 명령 원장 행과 체크포인트를 시간축 사건으로 바꾼다(사건 종류: 체크포인트, 명령 접수, 승인·거부, 전파·ack, 되돌림·만료). 재생·일시정지·처음으로·속도(1×·2×·4×)를 두고, 재생 위치의 사건과 지나온 사건을 보인다. 휴대폰은 플레이어를 그리지 않는다(d5 §3.9). 원천이 명령 원장뿐이라 경보·장애 주입 사건은 '원천 연결 전'으로 표시하고, 없는 사건을 0으로 그리지 않는다.
2. **SCR-032 법정 조치(`/compliance`)**
   - 탭: 통보·자료 요청(한 탭) / 보안 사고 / 접속기록 점검. 탭은 `?tab=`에만 담는다(frontend §2.7). 목록은 커서(`limit` 100, `nextCursor`)와 `sort=DUE_ASC|LATEST`, 상태 거르기.
   - 통보: 목록·상세(`view SUMMARY|FULL`), 등록(기관 종류·기관 이름·접수 시각·기한 H24/H10·게시물 ID·요약), 공문 PDF 올리기(20MB·PDF 검사 상태), 노출 차단(사유 필수, 멱등 키), 통보 철회로 복원(사유 필수, d5 §7.5 대화상자 글), 결과 회신·문서 내려받기. 기한 배지(남은 시간, 2시간 전 danger)와 미조치 SEV2 안내.
   - 자료 요청: 목록·상세, 등록 점검표(법적 근거·목적·범위·기한 + CDR이면 법원 허가서), 최소 범위 추출 요청(항목·기간·사유, 재인증 `AUTHORITY_DATA`, 행 수는 서버 센 값), commander 승인(요청자 본인은 막고 이유 글)·거부(REVISE/DECLINE, 사유)·제출 기록(제출 시각·기관·방법·SHA-256, 불일치 422 글), 제공 대장·보존 안내, 문서 내려받기. 승인 대기 남은 시간과 만료 글.
   - 보안 사고: 목록·상세, 등록(종류·인지 시각·대상 수·민감정보·외부 접근·요약), 의무별 기한·수행 시각, commander 해당 판단(한 번만), 신고·통지 기록(의무·기관·방법·시각·요약), 종결(남은 의무가 있으면 막고 이유), 이용자 통지 문안 미리보기(§9.1 문안 A·A2·A3·B의 필수 칸 검사).
   - 접속기록 점검: commander만 목록·상세, 이상 건 사유·사후조치 기록, 월 점검 완료. 본인 기록 종결은 운영에서 막고(이유 글), 데모 환경(환경 배지 '데모 환경')에서만 '자기 점검(시연)'으로 허용한다.
   - 칸 가림: 응답 `view`가 SUMMARY면 ID·기관·종류·기한·상태만 그린다. viewer는 통보·자료 요청을 부르지 않고(403), 보안 사고만 요약으로 본다. CS 담당자는 통보·자료 요청을 요약으로, 보안 사고를 요약으로 본다. 매개변수로 칸을 더 달라는 요청은 보내지 않는다(ASVS 8.1.2).
   - 휴대폰: 조회·요약만. 등록·차단·철회·추출 요청·승인·거부·제출·판단·종결·점검 완료 단추는 그리지 않고 "등록과 집행은 태블릿이나 데스크톱에서 합니다"를 둔다(control-tower §12).
3. **나머지 명령 작성(SCR-030 확장)**: 명령 2(입장 일시정지, `ADMISSION_PAUSE`), 4(ASN·IP 대역 차단, `BLOCK_ASN_IP`), 5(봇 판정 강도, `BOT_LEVEL`), 8(로그 레벨, `LOG_LEVEL`), 9(비핵심 기능 끄기, `FEATURE_OFF`), 11(자동화 정지, `AUTOMATION_STOP`), 12(결제사 지정, `PG_ASSIGN`)의 작성 값·본문·화면 막힘을 모델로 만들고, 명령 카탈로그 아래 '그 밖의 명령' 접힌 구역에서 작성한다. 명령 1·3·6 화면은 그대로 둔다. 파라미터가 계약으로 닫힌 명령 2·4·5·12는 정확한 칸을 만들고, 8·9·11은 정본 §3의 뜻을 최소 칸으로 옮기되 계약이 열려 있음을 화면에 적는다. 명령 7·10은 '하지 않는다' 2.
4. **명령 4·5 효과 줄**: `ackedAt` 뒤 10분 [가정] 동안 명령 카드와 SCR-030 위 줄에 차단 비율·추가 검증 통과율·이의 제기 수를 실행 전 5분 값과 나란히 보인다. 값이 없으면 '원천 연결 전'으로 두고 0으로 그리지 않는다. 추가 검증 통과율 10%p [가정] 하락 또는 이의 5건 [가정] 초과면 SEV2 안내를 낸다(control-tower §3 '명령 4·5 효과 줄', C-T33). 값 원천(관측 창고)은 이번 몫에 없어 모델과 표시만 한다.
5. **걸린 자동 조치**: 늘 여는 흐름 `autoAction` 사건과 `HostState.autoActions`(console-contract의 `{name,target,state,startedAt}`)를 호스트 저장소에 채우고, 명령 화면 위 줄에 '걸린 자동 조치'와 풀린 지 10분 [가정] 안의 '최근 풀림'을 보인다. 시간 조건은 남은 시간 막대, 조건이 깨지면 0으로 되돌린다(C-T44 ⑦). 본문 모양이 아직 정해지지 않은 사건은 이름·상태만 쓰고 나머지는 '원천 연결 전'이다.
6. **자동 조절 복귀 확인(C-T31 ③)**: `control` 사건이 `no-input`에서 `ok`·`paused`로 돌아오면 '자동 조절 복귀 확인' 대화상자를 띄우는 모델을 만든다. 확인 단추는 서버 경로가 없어 비활성이고 "확인 경로 준비 중"을 보인다. 확인 전 자동 증액이 없다는 것은 서버 판정이라 시험하지 않는다(남은 위험 3).
7. **재인증 확장**: `features/admin-reauth`의 `ReauthAct`에 `AUTHORITY_DATA`(수사기관 자료, openapi `OpsReauthPasswordStep.act`)를 더한다. 법정 조치의 추출 요청·승인만 이 동작을 쓰고, 기존 `OPS_COMMAND`·`APPROVAL`은 그대로다. 패스키 요소 없는 토큰은 계속 버린다.

**그대로**
- 명령 1·3·6의 작성·dry-run·승인·되돌리기(F-03-4), 감사 체크포인트 탭(BAT-465)은 옮기지 않고 새 감사 화면과 같은 함수만 나눠 쓴다. 미리보기 보드(`?state=`)·고정 자료·디자인 보드는 그대로 둔다.
- 서버(`services/**`), 계약(`docs/api/**`, 생성물), 새 패키지, 배포·마이그레이션·플래그, 다른 동결 기능(F-01-8 접속기록 원천, F-02-4 보존, F-04-11 포렌식 리플레이)은 건드리지 않는다.

**하지 않는다(경계 · 다음 몫)**
- 계약에 없는 경로 만들기: 감사 원장 행 조회, 원본 로그 내보내기, 명단 다운로드 기록, 자동 조절 복귀 확인 전송, 자동 조치 본문. 화면은 '원천 연결 전'과 비활성 이유만 둔다.
- 명령 7(문구 템플릿 ID 없음)·명령 10(법정 조치 경로로만)의 작성 카드. 명령 3·11 사후 검토 보고서 폼(계약은 있으나 d5 항목·검증 규칙 없음). 한 글자 단축키·초점 거르기·FE-T18 키보드 시나리오. `/me` 패스키 줄. 여러 회차 고르기. 같은 명령 동시 편집 잠금. 런북 CLI 한 줄(C-T7 ③).

### 6. 정할 것과 추천(작은 세부는 추천 적용, 2026-11-25)

1. **감사 원천(추천 적용)**: 명령 원장을 감사 행의 원천으로 쓴다. 원장 행은 정본 §7이 감사 대상으로 정한 명령 사건이고, 화면이 새 계약을 만들지 않는다. 원장 밖 사건(경보·장애 주입·접속기록)은 '원천 연결 전'으로 두고 0으로 그리지 않는다.
2. **리플레이 원천(추천 적용)**: 명령 원장 + 체크포인트로 만든다. 경보·장애 주입 사건은 원천이 생기면 같은 모델에 사건 종류만 더한다.
3. **검증 묶음 내보내기(추천 적용)**: 감사 화면에서만, commander·데스크톱·태블릿만. 사유는 1~500자(openapi `AuditVerificationBundleRequest`), `seq`는 상세에서 고른 기록이 있으면 그 값, 없으면 체크포인트 첫 seq. 화면이 `Blob`·`URL.createObjectURL`로 내려받고 본문을 렌더하지 않는다.
4. **법정 조치 화면의 쓰기(추천 적용)**: 모든 쓰기는 `Idempotency-Key`를 제출마다 새로 만들고(`Submission` 재사용), 재인증은 추출 요청·승인만 `AUTHORITY_DATA`, 나머지는 서버가 요구하지 않는다. 문서 내려받기는 `getOpsComplianceDocument`의 blob을 `<a download>`로만 내려준다.
5. **명령 8·9의 계약 빈칸(추천 적용)**: `LOG_LEVEL {service, level}`·`FEATURE_OFF {flag}`로 만들고 화면에 '계약 확정 전(서버가 거절할 수 있습니다)' 표지를 단다. 명령 11은 `AUTOMATION_STOP`에 params 없이 보낸다.
6. **효과 줄·자동 조치의 원천(추천 적용)**: 원천(관측 창고·autoAction 본문)이 없으므로 모델과 표시만 하고, 연결 전에는 '원천 연결 전'이다. 자동 조치 본문은 console-contract의 기존 모양(`name`·`target`·`state`·`startedAt`)만 읽는다.
7. **복귀 확인(추천 적용)**: 대화상자는 띄우되 확인 전송은 막는다. 서버 경로가 생기면 그 경로만 잇는다(남은 위험 3).

**소유자 결정이 필요할 수 있는 것**: 없다. 동결 로컬 범위·서버 경로 없음은 이미 정해진 상태이고, 이 계획은 그 안에서 화면을 끝내는 방법만 정한다.
