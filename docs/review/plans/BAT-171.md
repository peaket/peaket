# BAT-171 계획·기록(HOT-381 재배치 첫 실행 실패 고치기와 `web / reflow` 잡 켜기, HOT-391 같은 출처 스크립트 SRI)

- **무엇**: BAT-170 웨이브 끝 게이트(2026-11-16)에서 처음 실제로 돈 재배치 시험 묶음(`web / reflow`: FE-T31 재배치·글자 확대·글자 간격, FE-T18 자동 몫의 초점 가림, SCR-058 인앱 안내, 월렛 워커 브라우저 시험)이 37~39개 실패했고, CSP 시험의 ASVS 3.6.1 '같은 출처 외부 스크립트 integrity 없음'이 26건이었다. 이 묶음은 그 실패를 고치고, 다 통과하면 `web / reflow` CI 잡을 처음 켜고 3.6.1 시험의 건너뛰기를 되돌린다. 재배치(reflow)는 화면을 좁히거나 크게 확대해도 내용이 세로 한 방향으로만 다시 흘러 가로 스크롤 없이 쓸 수 있게 하는 것이고, SRI(하위 자원 무결성)는 스크립트 태그에 파일의 해시를 적어 받은 파일이 바뀌었으면 브라우저가 실행하지 않게 하는 장치다.
- **범위의 원천**: docs/BUILD_ORDER.md:89(묶음 행 비고), :444(HOT-381), :446(HOT-391). 장부 범위는 `FE-T31, frontend:v5.0.0-3.6.1`(판정 기준 docs/frontend.md:1636, docs/security/asvs/frontend.md:113). 지난 묶음 기록은 docs/review/plans/BAT-170.md §17 '웨이브 끝 게이트 뒤 정한 것'과 그 'G-6 바꿈'.
- **바탕**: 작업 폴더 `D:/ticketpass-lane2-b171`, 가지 `feature/lane2-BAT-171`, 출발점 `5ec2d8b0`. 지시서는 `brief.mjs --batch BAT-171`(만든 때 `5ec2d8b0`).
- **등급**: B(docs/BUILD_ORDER.md:89). 돈·좌석 수·대기 순번의 핵심 로직을 바꾸지 않는다(좌석 화면은 바깥 상자 속성만 본다).
- **차례**: 정방향(`Batch-Order: impl-first`, ADR-0281, docs/architecture.md §8.6 '정방향 묶음'). 계획 → 구현 → 독립 시험(구현 전 트리에서 실패 확인) → 리뷰 → 검증 → 브라우저 확인 → 기록. B 묶음 짧은 고리(docs/PROGRESS.md:12): 리뷰 반영 계획 커밋을 따로 두지 않고, 다시 리뷰 대신 검증 담당이 고친 곳을 본다.
- 이 파일은 역할마다 자기 절만 쓴다: 계획(아래 '계획'·'정할 것'), 실패 확인·시험 결과(시험), 시험 이의(구현), 리뷰, 검증, 담당 표·기록(감독).

### 5. 첫 JS 예산

- 공연 상세는 이미 예산을 넘어 '잰 값 + 1kB [가정]'로만 막는 경로다(docs/frontend.md:1256, 기준선 `tools/web-checks/budgets/js-baseline.json`). 그래서 F1·F2 고침은 CSS만으로 되는 길을 먼저 본다. 띠 높이를 재는 코드를 더하면 이미 실리는 예매 부품 안에 두고 새 의존성을 들이지 않는다.
- 확인: 구현 담당이 초안 PR CI의 `web / budgets` 결과(또는 측정 창 뒤 로컬 `node lib/docker.mjs budgets`)에서 공연 상세·검색·좌석·월렛·관제 경로의 첫 JS가 기준선을 넘지 않는지 보고, 값을 구현 커밋 본문에 적는다. 관제는 속성만 더하므로 바뀌지 않아야 한다.

## 정할 것

1. **같은 출처 스크립트 SRI 26건에서 실행 중 적재기가 넣은 덩어리를 어떻게 다룰지(HOT-391, 방향 결정이라 정본에 쓰지 않았다)**: 구현 담당이 1의 F8대로 먼저 가른다. 26건이 모두 응답 HTML에 실린 태그(ㄱ)면 고치기만 하고 이 항목은 닫는다. 실행 중 적재기가 넣은 덩어리(ㄴ)가 있으면 셋 가운데 고른다.
   - (가) **추천**: (ㄱ)은 모두 `integrity`를 단다. (ㄴ)은 같은 출처·같은 빌드의 화면별 덩어리이고 ASVS 3.6.1이 말하는 '외부에 둔 자산'(다른 곳에 올린 자원)이 아니다. ADR-0193 PoC(docs/frontend.md:1815)도 이 한계를 이미 적었고, 그 덩어리는 CSP `'self'`로만 실린다(ADR-0193 결정 6). 그래서 §5.14.2 표에 '같은 출처 화면별 덩어리' 한 줄 결정을 더하고(새 ADR로 ADR-0193 결정 6을 보충한다), T5의 단언을 'HTML에 실린 같은 출처 태그는 모두 integrity, 실행 중 넣은 태그는 같은 빌드의 정적 덩어리 경로(`/_next/static/`)뿐'으로 좁힌다. 비용 작음.
   - (나) 모두 단다: 덩어리 적재기(Turbopack 실행 코드)가 넣는 태그에도 해시를 달게 한다. Next.js 판 올림이나 실행 코드 고치기가 들어 비용이 크고 판 올림마다 깨질 수 있다.
   - (다) 지금 단언을 그대로 두고 건너뛰기를 유지한다. 묶음을 끝낼 수 없어 HOT-391을 체크하지 못한다.
