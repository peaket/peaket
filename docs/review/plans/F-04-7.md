`mtr_event_report`는 회차 한 줄에 다음을 묶는다.

- `metrics`: `(지표, 차원, 값, 분자, 분모, 표본, 기준선 중앙값, 기준선 1사분위, 기준선 3사분위, 확정 여부)` 배열. `mtr_event_metric`·`mtr_baseline_band`를 읽는다.
- `rule_checks`: `(규칙, TRIGGERED|NOT_TRIGGERED|DEFERRED, 보류 사유, 결정 기록 ID)` 배열. F12(`mtr_rule_check`)의 HIT·BORDER·CLEAR·HOLD를 리포트 판정으로 옮긴다.
- `quality_coverage_ok`·`quality_failed_metrics`·`quality_checks`: `mtr_data_quality`의 현재 판 검사 결과.

`partner_sales_gold`는 R3 현재 판의 회차 한 줄에 `sold_seats`·`sold_out_at`·`by_tier`·`sales_curve`·`refunds`·`recommendations`를 묶는다. `by_tier`는 F15의 등급별 판매 좌석·반환 좌석·판매 금액·등급 매진 시각이고, `sales_curve`는 F2의 구역 × 10분 판매 좌석이다. 판매 5건 [가정] 미만 칸은 구역 안에서 합치고 `merged=1`로 표시한다.

## 정본 빈칸과 고른 안

1. 리포트 생성(JSON·Markdown)·API는 ops-svc 몫이다. 이 기능의 데이터 계약은 골드 뷰 두 개다(추천 적용, 2026-11-24). ops-svc는 이 뷰를 자기 쿼리로 다시 계산하지 않는다.
2. 파트너 판매 요약의 등급별 판매·매출은 F15(날짜별 판매)에서, 매진 시각은 F11·`mtr_tier_sold_out`에서, 판매 곡선은 F2(온세일, R2 동결)에서 온다. R2 뒤 판매는 등급별 합계에만 들어가고 곡선에는 없다(analytics §4.3의 한계, 추천 적용 2026-11-24).
3. 작은 칸 합치기(5건 [가정])는 구역 안에서 한다. 작은 칸이 여럿이면 구역의 작은 칸을 한 칸으로 합치고 `merged=1`이다(추천 적용 2026-11-24).
4. `recommendations`는 결정 기록이 생기기 전이라 빈 배열이다. 리포트의 `decisionChecks`도 같은 이유로 빈 배열이다. 결정 기록 CRUD(A-T15·A-T20 ③)는 다음 몫이다.
5. 봇 범주·가명·다른 테넌트 비교·내부 규칙 수치는 뷰에 넣지 않는다(POL-037·040). 테넌트 필터는 API가 세션 테넌트로 강제한다.
6. 판매 곡선의 시간 묶음은 10분이다(오픈 기준 분을 10으로 나눈 몫). 리포트의 축은 오픈 기준 분이다(§8.3).

남은 빈칸 0.

## 남긴 것

- ops-svc의 리포트 JSON·Markdown 생성과 API(`/v1/ops/events/{eventId}/reports`, `/v1/partner/events/{eventId}/report`)는 이 데이터 뷰를 읽는 소비 쪽 몫이다. 이번 기능은 데이터 계약(골드 뷰)까지다.
- 결정 기록(`decision_record`) CRUD와 다음 리포트의 결정 확인 줄(A-T15), 정산 대조 실패로 조사 건 만들기(A-T9 뒷부분), 부정 예매 사후 집계(32번)는 다음 몫이다.
- 파트너 API의 테넌트 필터(자기 테넌트 회차만)는 세션 테넌트와 core 판매 설정을 아는 API 계층이 강제한다(뷰에는 넣지 않았다).
- 동결 아카이브(A-T19)·장르 랭킹(동결)·커버리지(A-T17)·실시간 대비(A-T8)는 계획대로 이번 몫이 아니다.
