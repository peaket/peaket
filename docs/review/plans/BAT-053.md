# 묶음 계획: BAT-053(HOT-091 realtime-gw 전파 Degraded 자동 전환)

- **무엇**: 묶음을 시작할 때 만든 작업 목록이다(docs/architecture.md §8.6 4). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다. 값은 옮겨 적지 않고 자리만 가리킨다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane4`, 가지 `feature/lane4-BAT-053`, 출발점 `origin/develop` `d52945b5`. 구현 전 트리는 `D:/ticketpass-lane4-base`(`d52945b5`, 분리 HEAD, 커밋 안 함). 2026-11-19 계획 담당 `bat053-plan-6b19`가 썼고 시험·제품 코드는 쓰지 않았다.
- **등급·차례**: A(좌석 상태를 나르는 길). 정방향(`Batch-Order: impl-first`): 계획 → 구현 → 시험(구현 전 트리에서 실패 확인) → 리뷰 → 리뷰 반영 → 다시 리뷰 → 검증 → 기록. 짧은 고리는 쓰지 않는다.
- **정본(이 커밋)**: [ADR-0298](../../adr/0298-realtime-gw-degraded-switch-excess-wait-pod-window-connection-buffer.md), docs/features/seat-hold.md 422행('맺은 뒤' 첫 `BatchInterval`)·437행(운영 확인 표 행)·452~458행('자동 전환의 첫 구현')·487행(§9)·570행(§12 S-T14 ①~④)·611행(§13), docs/review/ledger-notes.md 'S-T14 ④'.

## 감독에게

1. **S-T14 ④(완화 SLO p99 1.5초·초과 판매 0건) 판정 측정의 자리**: 서버 시험으로 잴 수 없는 종단 값이라 notes를 '구간 측정'으로 두었다. 측정 창 2의 BAT-095(갈래 5, S-T12 ①과 같은 연결 5,000개 무대) 장부 범위에 `S-T14 ④`를 더할지 정해 달라(다른 갈래 묶음 표).
2. **화면 쪽은 고칠 것이 없다**: `packages/seatmap/src/connection.ts` 217행은 `intervalMs > 100`을 Degraded로 보고, 다시 붙으면 서버의 첫 `BatchInterval`로 다시 정한다. 서버가 보내는 값(100·1000, 리틀 엔디언 u16)과 맞다. 화면의 '지연 표시' 시험은 BAT-182(갈래 2) 몫 그대로다.
3. **경보 규칙**: Degraded 동안 '묶음 대기 p99 150ms' 경보를 `realtime_gw_degraded` 경보로 갈음하는 일은 BAS-140(BAT-080)의 경보 규칙 파일 몫이다. 그 단계 줄에 '넘긴 것'으로 적을지 정해 달라.

## 계획

### 1. 범위

- **하는 것**: `services/realtime-gw` 허브의 묶음 간격을 연결마다 100·1000으로 바꾸는 판정(파드: 넘친 대기 창, 연결: 보내기 버퍼), `BatchInterval` 알림, 1초로 보내기, 게이지 둘과 로그 한 줄, 시작 파일 조립.
- **장부 범위**: `S-T14`(4항목, A). 지금 빈칸 3(①~③)·측정 1(④). 끝나면 자동 시험 3·측정 1.
- **ASVS**: 새 입력·외부 경로·저장소가 없다(보내는 프레임 type 3은 이미 있다). docs/security/asvs/seat-hold.md는 고치지 않는다.

### 2. 바른 동작과 근거

| # | 동작 | 근거 |
| --- | --- | --- |
| B1 | 넘친 대기 = `maxWaitMs` − 쌓기 시작할 때의 간격(0 아래 0). 보낸 묶음만 센다 | seat-hold 453행, ADR-0298 결정 1 |
| B2 | 10초 창의 n·a(>60)·b(>30), 넘음 a×100>n, 괜찮음 b×100≤n, 빈 창은 괜찮음·넘음 아님. 넘음 18개 → Degraded, 괜찮음 30개 → 평시, 다른 창이 끼면 처음부터. 판정은 박자 앞 | 454행, 결정 2·6 |
| B3 | 박자에 버퍼 ≥ 256KiB → 그 연결만 1초. ≤ 64KiB 박자가 30초 이어지면 되돌림. > 1MiB는 1013 그대로 | 455행, 결정 3, ADR-0297 결정 2 |
| B4 | 간격 = 파드 Degraded 또는 버퍼 → 1000, 아니면 100. 바뀐 박자에 `BatchInterval` 한 번, 같으면 안 보냄. 맺은 직후 첫 프레임도 그때 값 | 422·456행, 결정 4, ADR-0240 결정 10 |
| B5 | 1초 연결은 차례에서 1,000ms 이상 지난 첫 박자에 보내고 그 박자가 다음 시작(빈 차례도 넘어감). 세대 바뀜 바로 보내기·4401·1013·하트비트는 박자마다. 박자 차례: 만료 → 1MiB → 간격 → 묶음 → 하트비트 | 457행, 결정 5 |
| B6 | 게이지 `realtime_gw_degraded`·`realtime_gw_buffer_slow_connections`(시작 때 0), 파드가 바뀔 때 로그 `realtime_gw_degraded`(n·a·b) | 458행·437행, 결정 7 |

**공개 인터페이스(시험이 기댄다)**: `StreamHubDeps`에 `onMetric`의 게이지 두 이름(값을 그대로 둔다)과 `onDegradedChange?(e: { degraded: boolean; batches: number; over60: number; over30: number }): void`를 더한다. 시계는 지금 `Clock`(`now`·`monotonicMs`). `tick()` 말고 새 타이머를 두지 않는다. 상수 이름은 구현이 정하되 시험은 상수를 가져오지 않고 정본 값을 적는다.

### 4. 시험 목록(값은 seat-hold 570행)

| ID | 종류 | 단언 | 구현 전 트리 |
| --- | --- | --- | --- |
| S-T14 ① | 허브(가짜 연결의 `bufferedAmount`) | 262,144B 박자에 그 연결만 `BatchInterval` 1000 하나, 262,143B는 없음. 다음 묶음은 1,000ms 박자에 오고 999ms 박자엔 없음. 65,536B 박자가 30,000ms 이어지면 100(29,999ms엔 없음), 65,537B가 끼면 처음부터. 1,048,577B는 1013. 다른 연결은 프레임 변화 없음. 게이지 1 → 0 | 실패(1000이 안 온다) |
| S-T14 ① | 통합(받기를 멈춘 실제 연결) | 퍼붓는 동안 받기를 멈췄다 다시 받으면 `BatchInterval` 1000이 오고, 뒤 묶음 `serverTimeMs` 간격이 1,000ms 안팎, 버퍼가 빈 뒤 30초 근처에 100. 다른 연결은 100. `/metrics`의 게이지 | 실패 |
| S-T14 ② | 허브·창 판정 | 넘친 대기 61ms가 2/100인 창 18개 → 모든 연결에 1000, 게이지 1, 로그 한 번. 17개 + 1/100 창(a×100=n) → 그대로. 60ms 정각은 넘침 아님. 17개 + 빈 창 + 1개 → 그대로. Degraded에서 1초 묶음(`maxWaitMs` 약 1,000)만 오는 창 30개 → 100, 29개는 그대로. 31ms 2/100 창이 끼면 처음부터 | 실패 |
| S-T14 ③ | 허브 | Degraded 중 새 연결 첫 프레임 1000. 간격이 그대로인 박자엔 `BatchInterval` 없음(바뀐 박자에 꼭 하나). 1초 연결도 세대 바뀐 메시지는 바로. `exp` 박자에 4401·15초 하트비트 그대로. 파드+버퍼 연결은 둘 다 풀린 박자에만 100 | 실패(첫 프레임·전환) |
| S-T42 ①⑪ | 기존 통합 | 평시 첫 프레임 100, 읽지 않는 연결 1013이 그대로 통과 | 통과(회귀) |

- 시험 값은 상수와 다르게 고른다(박자 배수가 아닌 시각, 창 경계 − 1ms). '바뀌지 않으면 안 보냄'은 바뀐 박자의 하나와 같이 단언해 구현 전 트리에서 실패하게 한다.
- 통합의 1초 간격·30초 되돌림은 실제 시계라 허용 폭(±50ms [가정])을 시험에 적는다. 경계는 허브 시험이 맡는다.

### 6. 정한 값(추천 적용, 2026-11-19, ADR-0298)

넘친 대기로 판정(망·그리기 어림 140ms → 60ms), 되돌림 30ms·5분, 창 10초, 연결 버퍼 들어감 256KiB·되돌림 64KiB·30초, 파드 판정과 연결 판정을 나눔, 1초 차례 방식. 모두 [가정]이고 S-T12·K4에서 정한다(seat-hold §13 611행).

### 7. 범위 밖

종단 판정 측정(S-T14 ④, '감독에게' 1), 화면 지연 표시(BAT-182), 경보 규칙 파일·대시보드(BAS-140), 연결마다 차례 흩기(몰림을 재 본 뒤), 환경 값으로 기준 바꾸기(두지 않는다).
