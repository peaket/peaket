# F-04-3 계획 — 원본 적재 `analytics-ingest` (빠른 길)

- **무엇**: 기능 표 F-04-3(OPS-200·OPS-205, wbs 4.3.4 ①②) 작업 목록과 결과. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **절차**: 빠른 길(ADR-0373 결정 3, 소유자 요청). 갈래 6이 구현과 시험을 함께 하고, 완료 정의의 동작을 돌려 보인 명령과 숫자를 '시험 결과'에 남긴다.
- **완료 정의**: analytics-ingest가 가명 키·금지 칸 제거·오프셋 대조로 적재한다(docs/BUILD_ORDER.md 기능 표 F-04-3 행).
- **장부 범위**: docs/features/analytics.md, A-T21, docs/streaming.md, docs/security/asvs/analytics.md, A-T18, A-T22, ST-T22.
- **정본**: docs/streaming.md §1·§2·§6(§6.4 `inv-ingest`는 빼고), docs/features/analytics.md §3·§5.5·§7·§11, docs/api/avro/README.md §3.
- **이 출력을 읽는 곳**: 브론즈는 화면이 직접 읽지 않는다. F-04-4(dbt 실버·골드) → F-04-7의 관제 콘솔 공연 리포트(SCR-029 ④)·파트너 판매 요약(SCR-027, 골드 뷰 `partner_sales_gold`), 그리고 F-04-1 관제 실시간 표의 잔여석 계산이 읽는 `bronze.brz_ref_seat_map`(표만 이 기능이 만들고 싣는 것은 마감 실행기 F-04-6).
- **포렌식 몫(동결, 하지 않음)**: §6.4 `inv-ingest`·조사 저장소 `inv`, A-T22의 `inv` 쪽 권한(`inv_reader`·`an_forensic_reader`로 `inv.inv_request` 조회), ClickHouse 두 갈래 권한 분리의 `inv` 몫(OPS-205). 장부에서 이 몫은 빈칸으로 둔다('포렌식, 동결').

## 정본 빈칸과 고른 안

1. 사건 브론즈 칸: 레코드마다 표 하나(`brz_order_event`·`brz_payment_event`·`brz_seat_event`·`brz_event_sale`·`brz_purchase_session`(시작·끝 둘)·`brz_ticket_event`·`brz_settlement_event`·`brz_setting_changed`·`brz_queue_entry`·`brz_hold_attempt`·`brz_trust_verdict`). 칸은 공통 머리(회차·eventKey·레코드·사건 시각·키 판·스키마 ID·Kafka 위치·적재 시각)와 가명·허용 목록을 거친 값 `payload`(JSON 글)다. 원문 보관층이라 계약 판마다 칸을 펼치지 않고 실버(dbt, F-04-4)가 JSON에서 꺼낸다 (추천 적용, 2026-11-23)
2. 사건 시각: 레코드의 `occurredAt`, 구매 세션은 `startedAt`·`endedAt`, 판매 상태는 `changedAt`, 대기 기록은 끝난 시각(`admittedAt`·`removedAt`), 없으면 `enteredAt`. 모두 없으면 Kafka 시각 (추천 적용, 2026-11-23)
3. 회차 ID: 설정 사건은 `scope`가 회차 UUID일 때만(전체 범위는 빈 글), 상품 정산서는 빈 글. 회차가 없는 상품 결제(`PaymentEvent.eventId` null)는 회차 가명을 만들 수 없고 회차 분석 대상이 아니라 건너뛴다(위치는 `brz_offset` SKIPPED `NO_EVENT`) (추천 적용, 2026-11-23)
4. 가명 값 꼴: HMAC-SHA256(회차 키, 식별값) 256비트 전체를 16진수 64자로. 키 판은 local `local-v1`, 운영 `PEAKET_ANALYTICS_KEY_VERSION`(기본 `v1`) (추천 적용, 2026-11-23)
5. 회차 키 원천: 운영은 KMS `GenerateMac`(HMAC_SHA_256, `PEAKET_ANALYTICS_KMS_KEY_ID`), local·ci는 `PEAKET_ANALYTICS_PSEUDONYM_KEY`(base64 32바이트)로 같은 식을 몸 안에서 계산한다. 운영 환경에서 KMS 키 ID가 없으면 시작하지 않는다. 회차 키는 파드 메모리에 2,048 [가정] 회차까지 (추천 적용, 2026-11-23)
6. 금지 칸 이름 목록(대소문자 무시, 중첩 포함): name·fullName·phone·phoneNumber·contact·email·ci·di·ip·ipAddress·userAgent·paymentKey·paymentToken·bankAccount·accountNumber·cardNumber. 보이면 버리고 `analytics_forbidden_field_total{record, field}`로 센다(스키마 위반 경보의 원천) (추천 적용, 2026-11-23)
7. 허용 목록 = `@peaket/contracts/avro`(작업자가 빌드된 계약 판)의 최상위 칸 − 조사 칸 일곱 − `SettingChanged.actor`. 중첩 값의 조사·금지 칸도 지운다. 모르는 열거 기호는 원래 기호 그대로(읽기 `keepUnknownSymbols`) (추천 적용, 2026-11-23)
8. 커버리지 위치 표 `bronze.brz_offset`: 받은 모든 레코드의 (토픽, 파티션, 오프셋, 결과 LOADED·REJECTED·SKIPPED, 까닭). 건너뛴 심장 박동·1초 집계·점검 회차도 위치를 남겨 '고유한 (파티션, 오프셋) 수 = 구간 길이' 대조를 한 표로 한다. 대조는 `analytics-ingest coverage <토픽> <파티션> <처음> <끝>`(빈 구간을 JSON으로, 모자라면 종료 코드 3). 압축 토픽 `control.settings`는 대조에서 뺀다(정본 §6) (추천 적용, 2026-11-23)
9. 다시 적재(OPS-205): `analytics-ingest backfill <끝말>`이 버리는 그룹 `peaket.analytics-ingest.<환경>.backfill-<끝말>`로 가장 이른 곳부터 읽고, 중복 거르기 표시 앞에 `backfill-<끝말>:`을 붙인다(F-04-1 ST-T7에서 본 '같은 표시면 서버가 버림'을 피함). 겹친 행은 실버가 eventKey로 지운다. 오프셋 구간 지정(그 구간만)은 두지 않았다 (추천 적용, 2026-11-23)
10. 스키마 원천: `PEAKET_SCHEMA_REGISTRY_URL`이 있으면 레지스트리, 없으면 local·ci에서만 고정 스키마 ID(`localSchemaIds`, ADR-0357 결정 4)를 거꾸로 찾아 계약 판 스키마를 쓴다 (추천 적용, 2026-11-23)
11. 설정 이름: `PEAKET_ANALYTICS_CLICKHOUSE_URL`(·`_USER` 기본 `bronze_writer`·`_PASSWORD`·`_TOPOLOGY`), `PEAKET_BRONZE_MIGRATIONS_DIR`, `PEAKET_PROBE_EVENT_IDS`. 지표 `analytics_bronze_rows_total{table}`·`analytics_bronze_rejected_total`(1건이라도 SEV3의 원천)과 공용 `stream_*` (추천 적용, 2026-11-23)
12. 기준 자료 표 `brz_ref_event`·`brz_ref_seat_map`은 칸 이름(analytics §3.2) 그대로 이 이전 파일에 만들고, 정렬 키는 `event_id`가 앞이다(관제 잔여석 조회의 `force_primary_key`, F-04-1 계획 '남긴 것'). 싣기는 마감 실행기(F-04-6) (추천 적용, 2026-11-23)
