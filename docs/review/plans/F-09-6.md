## 감독에게

막는 물음은 없다. 아래는 추천대로 계획에 적었다. 다르게 정하면 이 계획과 그 정본 줄을 고친다.

1. **[결정 요청] BAT-046으로 미뤄 둔 관리 계정 초대 수락 서버 경로를 F-09-6이 이어받는다.** ADR-0322 결정 1과 `docs/features/identity.md:412~417`이 “초대 수락 경로와 SCR-064는 BAT-046”으로 남겼지만 BAT-046은 기능 표에 없고, F-07-13(`docs/BUILD_ORDER.md:121`)이 “F-09-6이 관리 계정 쪽 같은 TOTP 등록·복구 코드 유스케이스를 만든다”며 F-09-6을 기다린다. 이 계획은 **서버 경로(`/v1/{partner,ops}/auth/invitation-*` 14개)만** 한다. SCR-064 화면·콘솔 세션 표시는 여전히 화면 기능 몫으로 남긴다. 이 좁힘을 승인해 달라.
2. **[결정 요청] A등급 시험 범위에 초대 수락을 넣는다.** 장부 범위 25항목은 이미 모두 자동 시험이라 `--require`가 통과한다. 그래서 F-09-6의 남은 몫은 장부 항목이 아니라 ① BAT-045 리뷰가 남긴 결함 ② BOT-152의 미구현 서버 경로 ③ DAST 닫힘 실패다. 새 시험은 장부 범위를 넓히지 않고 계획의 `## 시험` 표로 관리한다. 이 판단을 승인해 달라.
3. **[알림, 소유자 몫] 운영 허용 IP·VPN 출구 값은 저장소에 넣지 않는다.** gw-ops 허용 IP는 이미 `PEAKET_OPS_ALLOWED_IPS`(IPv4 CIDR 1~32개) 하나로 사내망과 VPN 출구를 함께 받는다(`docs/infra.md:543`, ADR-0321 결정 3). 별도 VPN 환경 값을 만들지 않는다. local·ci 시험 값만 저장소에 있고 운영 값은 소유자가 채운다.
4. **[알림, 미실행] 실제 IP/VPN·DAST·AWS는 이 계획에서 통과로 세지 않는다.** AWS WAF·보안 그룹·CloudFront 관제 웹 ACL·VPN 출구·WAF 로그 탐지·CloudTrail 경보는 클라우드 계정 뒤라 **미실행**이다. DAST 야간 첫 Linux 실행, 출시 후보 데모·운영 실제 점검, ZAP 인증 점검·Full Scan도 **미실행**이다. 예약 실행은 ADR-0332 결정 1과 F-09-8 몫이라 이 기능은 `on.schedule`을 건드리지 않는다.
5. **[알림, 한계] 새 DB 마이그레이션은 동결 가지 로컬 전용이다.** 초대 수락 단계 상태를 저장하려면 `services/identity-svc/migrations/0039_admin_invitation_acceptance.sql`이 필요하다(이름은 구현 때 비어 있는 번호로 맞춘다). ADR-0386 결정 5대로 출시 마이그레이션 목록·release 가지에 넣지 않고, 동결을 풀 때 번호를 다시 맞춘다. 이번 턴에는 Docker를 쓰지 않으므로 단위·HTTP(메모리 저장소) 시험만 쓰고, 실제 PostgreSQL 통합 시험은 구현 차례에 Docker 잠금을 잡고 더한다.
6. **[알림] 이번 턴은 계획·시험만 한다.** Docker·kind·AWS를 쓰지 않았고, 실제 서버·브라우저도 띄우지 않는다. 기준 트리 실패는 단위·HTTP·정적 시험으로 본다. A등급 시험 리뷰는 이 계획·시험을 쓰지 않은 새 세션이 한다.
7. **[알림] BAT-045 리뷰의 낮은 결함 넷은 이번에 고치지 않고 남긴다.** RV-10(세션 강제 종료 REST 재전송의 `already_done` 노출), RV-11a(세션 브라우저·OS 빈 값), RV-11b(지정 시각을 identity가 아니라 ops가 만듦), RV-11d(승인 목록 `cursor` 무시)는 계약·proto를 넓혀야 하거나 화면 계약과 맞물린다. 이 계획은 RV-12·RV-17·RV-11c만 고치고, 넷은 `docs/lanes/lane1-cleanup.md` 후보로 남긴다.
8. **[알림] 새 A 기능 구현 리뷰를 한다.** 이 계획 커밋에 `Batch-Grade: A`를 단다. 구현이 고정 시험을 모두 통과한 뒤, 구현을 맡지 않은 새 세션이 바뀐 코드를 보고 `IR-NN` 지적을 남긴다(ADR-0381).

#### 1.2 남은 몫(이 기능이 하는 것)

**A. 관리 계정 초대 수락 서버 경로(BOT-152, BAT-046에서 미뤄 둔 몫)**

- A1. `POST /v1/partner/auth/invitation-acceptances`·`/v1/ops/auth/invitation-acceptances`: 초대 링크 토큰(43자 base64url)의 SHA-256으로 INVITED 계정을 찾고, 30분 [가정] 단계 토큰과 가린 이메일·표시 이름·역할·`passkeyRequired`·`next: PASSWORD`를 준다. 없는·지난·쓴·재초대된·다른 콘솔·활성/삭제 계정은 모두 같은 410 `invitation-invalid`다.
- A2. `POST /v1/{partner,ops}/auth/invitation-passwords`: 15~256자, 흔한 비밀번호·서비스/계정 맥락 말·유출 목록 대조(`SetAdminPassword` 재사용). 통과하면 `next: TOTP`, 정책 위반은 422 `password-rejected`(까닭·안내), 길이 밖은 400이다.
- A3. `POST /v1/{partner,ops}/auth/invitation-totp-enrollments`·`…/invitation-totp-confirmations`: 비밀번호 뒤에만 등록을 시작하고(`BeginTotpEnrollment` 재사용), 코드가 맞으면 시드를 확정하고 복구 코드 10개 [가정]를 한 번만 준다(`ConfirmTotpEnrollment` 재사용). 틀린 코드는 5번 [가정]까지 422 `reauth-code-invalid`(남은 수)이고, 그 뒤 단계 토큰이 무효(410)다.
- A4. `POST /v1/{partner,ops}/auth/invitation-passkey-registrations`·`…/invitation-passkeys`: 패스키 등록 옵션과 자격 확인. 세션·재인증 토큰 대신 단계 토큰이 자격이고, RP ID·출처·사용자 확인은 기존 `WEBAUTHN`·`WEBAUTHN_RPS`를 쓴다. `partner_admin`·`operator`·`commander`는 패스키가 필수이고, 나머지 역할은 건너뛸 수 있다(`PASSKEY_REQUIRED_ROLES` 재사용).
- A5. `POST /v1/{partner,ops}/auth/invitation-completions`: 비밀번호·TOTP가 끝났고 필수 역할이면 패스키가 하나 이상일 때만 활성화한다. `recoveryCodesSaved: true`가 없으면 400, 패스키가 없으면 409 `passkey-not-registered`, 앞 단계가 안 끝났으면 409 `invitation-step-out-of-order`다. 한 트랜잭션에서 상태를 ACTIVE로 하고 초대 토큰 해시·단계 토큰·대기 시드를 지운다. 세션은 만들지 않는다(로그인으로 보낸다).
- A6. 다시 시작하면 앞서 저장한 비밀번호·대기 시드·확정 TOTP·복구 코드·패스키를 지우고 처음(비밀번호)부터 한다. 남이 링크로 넣어 둔 값을 이어 쓰지 않게 하려는 것이다. 단계 토큰은 한 초대에 하나이고 30분 [가정]이며, 다른 초대·다른 콘솔에 쓰면 410이다.

**B. BAT-045 리뷰가 남긴 로컬 결함(작은 몫)**

- B1. RV-12: 파트너 계정 초대의 `promoterId`가 실제 파트너사인지 identity를 부르기 전에 확인한다. 없으면 422 `unknown-promoter`, 파트너사 조회가 503이면 503 `promoter-directory-unavailable`이고 identity 호출·감사 기록은 0건이다.
- B2. RV-17: `PUT /v1/ops/admin-accounts/{id}/role`의 같은 `Idempotency-Key`·같은 본문 재전송은 identity 호출과 감사 `SUCCEEDED`가 1회이고, 다른 본문은 422 `idempotency-key-reused`다. 지금은 성공 감사에 `operation`·`idempotencyKey`·`bodyHash`가 없어 `#prior`가 찾지 못한다(`admin-accounts.ts:143~150`).
- B3. RV-11c: commander 역할 변경 승인 감사에 요청자(관리 계정 ID)를 `requestedBy`로 남긴다. 지금은 승인자(`actorAdminAccountId`)만 있어 권한 변경 내역에서 요청자가 보이지 않는다(`role-change-approvals.ts:111~127`).
- B4. RV-13a~d: DAST 판정의 닫힘 실패. ① 결과의 `riskcode`가 없거나 모르는 값이면 High로 보아 막는다 ② 미끼 결과 파일이 없거나 깨졌으면 `DecoyError`(종료 코드 3)로 끝내고 대상 점검을 하지 않는다 ③ `scan-gate --tool zap`의 High/Medium 판정과 같은 규칙·주소 중복 합치기를 시험으로 고정한다 ④ 야간 실패 SEV3 이슈는 실행마다 새로 열지 않고 열린 이슈를 찾아 한 번만 열거나 덧붙인다.

**C. 하지 않는 것(이미 됐거나 범위 밖)**

- gw-ops 허용 IP·VPN 출구의 code: 이미 있다. VPN 출구는 `PEAKET_OPS_ALLOWED_IPS`의 CIDR 한 줄이다. 실제 VPN·AWS 값은 소유자 몫이고 이 계획에서는 **미실행**이다.
- 위험 명령 재인증: 이미 있다. 토큰의 `act=OPS_COMMAND`·패스키·jti·503을 바꾸지 않는다. 시험 이름과 정본 태그도 그대로 둔다.
- 관리 세션 수명(24시간)·유휴(1시간)·동시 2개·잠금·`SESSION_LIMIT` 알림: 이미 있다. 새 시험을 쓰지 않고 기존 시험이 게이트에서 통과하는지 본다.
- AZ-T14·C-T69·auth 태그: 이미 자동 시험이다. 장부 범위를 넓히지 않는다.
- SCR-064 화면, 콘솔 세션 강제 종료 표시, 관리 계정 초대 메일 문구: 화면·문구 기능 몫이다.
- RV-10·RV-11a·RV-11b·RV-11d: 계약·proto를 넓혀야 하거나 화면 계약과 맞물려 이번에는 남긴다(감독에게 7). `docs/lanes/lane1-cleanup.md` 후보로 적는다.
- AWS WAF·보안 그룹·CloudFront 웹 ACL·VPN 출구·WAF 로그·CloudTrail, 실제 DAST 야간 첫 실행, 데모·운영 점검, ZAP 인증 점검·Full Scan: **미실행**이다.

#### 1.3 크기(어림, 모두 [가정])

초대 수락 서버 경로 1.25일, BAT-045 잔여 0.5일, DAST 닫힘 실패 0.5일, 정본·게이트 0.25일 = **2.5일**. 기능 표의 3.25일 안이다.

- **계획 시점 장부**: `node tools/ci/ledger.mjs --batch F-09-6`는 **25항목(자동 시험 25, ID만 0, 빈칸 0, 미검증 0, 다른 단계 0, A 0·B 25·C 0)** 을 낸다. `--require`는 지금도 통과한다. 이 기능은 장부 범위를 넓히거나 줄이지 않는다.
- **새 시험의 자리**: 초대 수락·RV-12·RV-17·RV-11c·DAST 닫힘 실패 시험은 위 25항목 밖의 추가 시험이다. 장부는 시험 이름의 ID로 상태를 정하므로, 새 시험 이름에 `BOT-152`·`BOT-161`을 달아도 위 25항목의 상태를 바꾸지 않는다. 계획의 `## 시험` 표와 `trace-check`가 이 시험들을 따로 센다.
- **완료 판정**: ① 위 25항목이 계속 자동 시험 ② `## 시험` 표의 새 시험이 모두 통과 ③ 게이트 통과 ④ 외부 몫이 `미실행`으로 기록됨. `--require`만으로 F-09-6을 끝으로 적지 않는다.

### 5. 공개 인터페이스(시험 담당이 이 모양으로 시험을 먼저 쓴다)

**HTTP(openapi 그대로, 새 경로·type 없음)**

- `POST /v1/{partner,ops}/auth/invitation-acceptances` → 201 `{ acceptanceStep, expiresInSeconds: 1800, emailMasked, displayName, role, promoterName: null, passkeyRequired, next: 'PASSWORD' }`, 400 `invalid-body`, 410 `invitation-invalid`, 503 `admin-login-unavailable`.
- `POST /v1/{partner,ops}/auth/invitation-passwords` `{ acceptanceStep, password }` → 200 `{ next: 'TOTP' }`, 400 `invalid-body`, 410 `invitation-step-invalid`, 422 `password-rejected`(까닭), 503.
- `POST /v1/{partner,ops}/auth/invitation-totp-enrollments` `{ acceptanceStep }` → 201 `{ otpauthUri }`, 409 `invitation-step-out-of-order`, 410, 503.
- `POST /v1/{partner,ops}/auth/invitation-totp-confirmations` `{ acceptanceStep, code }` → 200 `{ recoveryCodes: string[10], next: 'PASSKEY' | 'COMPLETE' }`, 409, 410, 422 `reauth-code-invalid`(remainingAttempts), 503.
- `POST /v1/{partner,ops}/auth/invitation-passkey-registrations` `{ acceptanceStep }` → 201 `{ registrationId, publicKey, expiresInSeconds }`, 409 `invitation-step-out-of-order`·`passkey-limit`, 410, 503.
- `POST /v1/{partner,ops}/auth/invitation-passkeys` `{ acceptanceStep, registrationId, credential, name? }` → 201 `AdminPasskey`, 409 `passkey-exists`·`passkey-limit`, 410 `invitation-step-invalid`·`passkey-registration-invalid`, 422 `passkey-attestation-invalid`, 503.
- `POST /v1/{partner,ops}/auth/invitation-completions` `{ acceptanceStep, recoveryCodesSaved: true, displayName? }` → 204, 400 `invalid-body`, 409 `passkey-not-registered`·`invitation-step-out-of-order`, 410, 503.
- 초대·단계·비밀번호·TOTP·패스키 응답은 `Cache-Control: no-store`다(완료 204는 계약에 없다). 본문에 초대 토큰·단계 토큰·비밀번호·TOTP 시드·복구 코드 원문(확인 응답 제외)·해시를 싣지 않는다.

**저장(동결 로컬 마이그레이션)**

- `admin_account`에 `invite_step_hash bytea`(SHA-256), `invite_step_expires_at timestamptz`, `invite_step_stage text`(`PASSWORD`·`TOTP_PENDING`·`TOTP_CONFIRMED`·`PASSKEY`), `invite_step_code_failures int`를 더한다.
- 단계 토큰은 초대 토큰과 별개다. 한 계정에 하나이고, 새로 시작하면 덮어쓴다. 완료·재시작·재초대·만료 때 지운다.
- 완료 트랜잭션: 상태 ACTIVE, `invite_token_hash`·`invite_expires_at`·단계 칸·`totp_pending_enc` 지우기. `password_phc`·`totp_seed_enc`·복구 코드·패스키는 남긴다.

**응용 층(시험이 의존하는 이름)**

- `AcceptAdminInvitation.start({ aud, invitationToken })`
- `AcceptAdminInvitation.setPassword({ aud, acceptanceStep, password })`
- `AcceptAdminInvitation.beginTotp({ aud, acceptanceStep })`·`confirmTotp({ aud, acceptanceStep, code })`
- `AcceptAdminInvitation.beginPasskey({ aud, acceptanceStep })`·`finishPasskey({ aud, acceptanceStep, registrationId, credential, name? })`
- `AcceptAdminInvitation.complete({ aud, acceptanceStep, recoveryCodesSaved, displayName? })`
- 실패는 `InvitationAcceptanceError`(code: `INVITATION_INVALID`·`STEP_INVALID`·`STEP_OUT_OF_ORDER`·`PASSWORD_REJECTED`·`CODE_INVALID`·`PASSKEY_REQUIRED`·`PASSKEY_LIMIT`·`ATTESTATION_INVALID`·`EXISTS`)로 돌려주고 받는 층이 Problem으로 바꾼다.

**ops 관리 계정**

- `AdminAccountsDeps.promoters?: { exists(promoterId: string): Promise<boolean> }`(없으면 확인 생략, 운영 배선은 반드시 넣는다).
- `AdminAccounts.invite`는 파트너 역할·`promoterId`가 있을 때 `promoters.exists`를 먼저 부른다. false → 422 `unknown-promoter`, throw → 503 `promoter-directory-unavailable`.
- `AdminAccounts.changeRole`의 성공 감사에 `operation: 'admin-role'`·`idempotencyKey`·`bodyHash`를 남긴다(키가 있을 때).
- `RoleChangeApprovals.approve`의 감사 payload에 `requestedBy: r.requestedBy`를 더한다.

**도구**

- `dast-gate.mjs`의 `SEVERITY_OF_RISK`는 0~3 밖/없음 → 9.0, `toSarif`의 `high`도 1로 센다.
- `scan-tools.mjs`의 `runDast`는 미끼 결과 읽기 오류를 `DecoyError`로 감싼다.
- `scan-gate.mjs --tool zap`은 결과를 규칙·주소로 합쳐 세고 7.0 이상을 막는다.
- `dast-nightly.yml` notify는 고정 제목으로 `gh issue list --state open`을 먼저 보고, 있으면 `gh issue comment`, 없으면 `gh issue create`다.

### 구현 리뷰 고침(IR096)

- **IR096-01(높음, 시험 먼저)**: 시험 ⑩을 200·`{next: DONE}`으로 바꾸고, 초대 수락 계정의 **뒤 재로그인도 200**임을 더했다. 구현은 204 분기·`viaInvitation`·`invitation_accepted_at` 칸·마이그레이션 칸을 지웠다. 정본 openapi가 이긴다.
- **IR096-02(중간, 시험 먼저)**: 재전송 시험을 처음 `If-Match:"1"`로 바꿨다. 구현은 재인증·멱등(`#prior`)을 `If-Match` 검사 앞에 두어 같은 `approvalId`/계정 뷰를 그대로 준다.
- **IR096-03(보안)**: 초대의 파트너사 조회를 `#reauth`·`#prior` 뒤로 옮겼다. 재인증 없는 요청은 조회 0·403, 관제 역할+`promoterId`는 조회 0·422 `promoter-mismatch`, 같은 키 재전송은 조회 장애 뒤에도 처음 201이다. 시험 셋을 더했다.
- **IR096-04(중간)**: 초대 저장소·TOTP 시드 키·패스키 챌린지 장애를 `UNAVAILABLE`→503 `admin-login-unavailable`으로 모았다. `beginTotp`의 `TotpKeyUnavailable`도 410이 아니라 503이다. 장애 주입 시험 넷을 더했다. **잔여 고침**: `setPassword`의 catch를 `instanceof AdminPasswordError`로 좁혀 정해진 `REJECTED`/`UNAVAILABLE`/`NOT_FOUND`만 422/503/410으로 가르고, top-level `code`가 붙은 raw 드라이버 오류(`ECONNREFUSED`·`57P01`)를 포함한 예상 밖 오류는 503으로 보낸다. 시험 고정 `cf3f1bb43`, 구현 `d9ec32c5c`.
- **IR096-05·07·12(가능한 것)**: `complete()`가 `recoveryCodesSaved`를 직접 확인하고, 메모리 저장소의 동기 배열 캐스트를 없애 `async`로 돌려주며(시험은 `await`), `beginTotp`가 주입된 시계를 넘긴다.
- **IR096-08·09·10·11(남은 것)**: 정본 문서 갱신·HTTP-core 어댑터 시험·Drizzle `markRemoved`/`expireInvites` 칸 정리·멱등 키 호출자 범위는 `docs/lanes/lane1-cleanup.md`로 보냈다.

**IR096-05·12 꼬리말 정리(이미 푸시된 커밋은 force 없이 고치지 않는다)**

- `IR096-05`: `complete(aud, step, recoveryCodesSaved, displayName?)`의 유스케이스 확인은 구현 커밋 `887e9d29d`에서 들어갔다. 시험은 HTTP 경로의 `recoveryCodesSaved: false` 400을 고정 시험 `430b25038`이 이미 보고, `e7aec553e`는 503·멱등·로그인 시험만 더했다. 그래서 `887e9d29d`의 `Fix-By: impl`에 `Finding: IR096-05`가 함께 붙었고, 별도 `Fix-By: test` 커밋은 만들지 않았다. 유스케이스를 직접 부르면 409 `invitation-step-out-of-order`인 것은 **낮은 잔여**다(HTTP는 400).
