- **무엇**: 묶음을 시작할 때 계획 담당이 지시서로 만든 작업 목록이다(docs/architecture.md §8.6 4의 1, ADR-0256 결정 10). 검토 기록이고 규범이 아니다. 정본 값은 옮겨 적지 않고 자리(문서:줄)만 가리킨다. 정본과 다르면 정본이 이긴다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane2`, 가지 `feature/BAT-157-sale-policy-eligibility`, 커밋 4fd524ab(원격 develop과 같다). 지시서는 작업 폴더 밖 `brief-BAT-157.md`(같은 커밋)다. 출발점은 docs/review/plans/BAT-155.md §1.2·§4.2·§4.3·§5·§6.1과 갈래 2가 정한 답 다섯(다른 갈래 폴더는 고치지 않음, 사본 쓰는 쪽은 소유자 몫, 평가기는 `@peaket/validation`, 화면은 크기를 보고, services/README.md의 core-svc 환경 값). 2026-11-10 작성.
- **등급**: 묶음은 A다(docs/BUILD_ORDER.md:56). A 항목은 Q-T36 ④⑤⑥과 새 S-T39 ①~⑥이다(평가 함수가 1인 한도와 진입 거름을 정한다). 나머지 ASVS 행은 B다.

## 1. 묶음 나누기(추천: 화면만 뺀다)

**추천**: BAT-157 = HOT-250 ①② 서버 몫(평가 함수, 규칙 저장, 회차 고치기, 공개 요약·팬별 자격, 판매 자격 명단). SCR-024 화면은 새 묶음 **BAT-158**(새 단계, 8장 감독에게 ③)으로 뺀다.

- **근거(크기)**: 서버 몫만으로 새 경로 여섯(규칙 둘·명단 셋·팬 하나)과 `updatePartnerEvent` 통째, 마이그레이션 0008(칸 다섯·표 둘의 칸·행 보안), 평가 함수 넷, gRPC 어댑터 하나, 포트 하나, 정비 일 둘, A 항목 아홉(항목마다 틀린 구현 1~2개)이다. WBS 2.25일(화면 포함)이 이미 빠듯하다.
- **근거(화면)**: SCR-024(docs/design/d5-screen-blueprint.md:2688~2749)는 규칙 종류 셋의 폼, 시뮬레이션, JSON 보기, 명단 올리기, 두 상태다. 서버 계약이 이 묶음에서 처음 생기므로 화면은 그 계약을 받은 뒤 실제 서버에 잇는 편이 '가짜 API로 끝내지 않기'(§8.6 4의 4)에 맞는다. 브라우저 확인도 그 묶음 하나로 모인다.
- **더 나눌 때(구현 중 한 턴에 넘치면)**: ②(판매 자격 명단, Q-T36 ④⑤⑥과 올리기 ASVS 행)를 BAT-158로, 화면을 BAT-159로 미룬다. ①이 먼저다(잠금 시각이 규칙의 `during`에서 나온다).

## 3. 차례

1. 정본 빈칸은 이 계획과 함께 썼다(9장). 구현 중 새 세부가 나오면 ADR-0261에 결정을 더한 뒤 코드를 쓴다. BUILD_ORDER 단계 줄·새 묶음은 감독이 한다(8장).
2. **`@peaket/validation/sale-policy` 먼저**(A, 시험 먼저 쓰고 실패를 본다): S-T39 ①~⑥. 잠금 파일·링크 손질(6장).
3. 마이그레이션 `0008`(+ `migrations/meta`) → drizzle 스키마 → 저장소 어댑터(메모리·Drizzle). 행 보안은 0004·0006·0007과 같은 꼴.
4. 규칙 저장(GET·PUT) → `updatePartnerEvent` → 공개 요약 칸·`PRESALE` 배지 → 팬별 자격.
5. **명단(A, 시험 먼저)**: Q-T36 ⑤(잠금 경계와 잠금 안 다시 보기), ④(파기 경계·사본 수명), ⑥(결과·감사 기록). 그다음 줄 해석 → 변환 포트·gRPC 어댑터 → 저장 → 사본 포트 → 정비 일 둘(relay 조립).
6. 시작 파일 조립(`main.ts`의 변환 어댑터, 사본 포트의 늘 실패하는 어댑터, relay의 정비 일) → services/README.md core-svc 실행 안내의 환경 값(7장 끝).
7. 실제 서버 연결(4장) → 관점 넷 리뷰 → 틀린 구현 검사(5장) → 게이트(7장) → 기록과 커밋. 화면을 바꾸지 않으므로 브라우저 확인은 하지 않는다(BAT-158이 한다). Lua·빠른 경로를 바꾸지 않아 성능 비교도 없다.

## 6. `@peaket/validation`을 core-svc에 잇기(pnpm이 막혀 있을 때)

HOT-180의 3845535c(`packages/search-normalize`를 core-svc에 붙인 커밋)와 같은 꼴이다. 새 외부 패키지는 없다(zod는 이미 잠금 파일에 4.6.7로 있다).

1. `packages/validation/package.json`: `exports`에 `"./sale-policy": { "types": "./src/sale-policy/index.ts", "development": "./src/sale-policy/index.ts", "default": "./dist/sale-policy/index.js" }`(packages/contracts/package.json의 꼴), `scripts.build`(`tsc -p tsconfig.build.json`), `dependencies.zod`(`^4.6.7`). `"."`·`"./safe-json"`은 그대로 둔다(화면과 api-client가 원본을 쓴다).
2. `sale-policy` 아래 파일은 상대 가져오기에 `.js`를 붙이고(`../safe-json.js`) 계약 생성 스키마를 가져오지 않는다(ADR-0261 결정 11).
3. `services/core-svc/package.json`: `dependencies`에 `"@peaket/validation": "workspace:*"`.
4. `pnpm-lock.yaml` importers 두 곳을 손으로 고친다.
   - `services/core-svc:` → `dependencies:`의 `'@peaket/search-normalize':` 뒤에 `'@peaket/validation':` / `specifier: workspace:*` / `version: link:../../packages/validation`.
   - `packages/validation:` → `dependencies:`의 `'@peaket/contracts':` 뒤에 `zod:` / `specifier: ^4.6.7` / `version: 4.6.7`.
5. 링크를 손으로 만든다(PowerShell, 관리자 권한 없이 되는 접합점): `New-Item -ItemType Junction -Path D:\ticketpass-lane2\services\core-svc\node_modules\@peaket\validation -Target D:\ticketpass-lane2\packages\validation`, `New-Item -ItemType Junction -Path D:\ticketpass-lane2\packages\validation\node_modules\zod -Target D:\ticketpass-lane2\node_modules\.pnpm\zod@4.6.7\node_modules\zod`.
6. 빌드 차례: core-svc 형 검사·시험 전에 `packages/validation`에서 `node node_modules/typescript/bin/tsc -p tsconfig.build.json`. CI는 turbo `^build`와 ci-node.yml의 core-svc 통합 시험 앞 빌드(`--filter=@peaket/core-svc^...`)가 잡는다. `pnpm install --frozen-lockfile`이 손 고친 잠금 파일을 받는지는 CI 첫 결과로 본다(다음 묶음 시작 때).
7. 더 가벼운 안은 고르지 않았다: 평가기를 core-svc 안에만 두면 화면(BAT-158)과 purchase-svc(갈래 1 새 단계)가 같은 함수를 쓰라는 정본(docs/design/d5-screen-blueprint.md §6.7)을 어기고, 그때 다시 옮겨야 한다. queue-svc는 평가기를 쓰지 않는다(진입 자격 창은 판매 승인이 계산해 일정 사본에 쓴다, ADR-0261 결정 10).

## 10. OPEN 초안(소유자 결정 몫, 번호는 감독이 매긴다)

OPEN[번호]: 판매 자격 명단의 대기열 사본(`q:{event:E}:elig:{listKey}`, 구성원은 계정 ID)을 누가 대기열 Redis에 쓸지 정해 주세요(2026-11-10 갈래 2, docs/review/open-items.md 102 ⑹). core-svc가 명단을 올릴 때 넘길 데이터(회차·명단 키·판·계정 ID 최대 50만 개·수명 = 판매 기간 끝 + 1일)는 포트 `SaleEligibilityCopy` 뒤에 만들었고(ADR-0261 결정 9, docs/review/plans/BAT-157.md), 정하기 전까지 운영 조립은 늘 실패하는 어댑터라 명단이 진입 대조에 쓰이지 않습니다. (가) core-svc가 대기열 Redis에 직접 쓴다(임시 키에 1만 개씩 넣고 이름 바꾸기, 판이 클 때만, 수명은 파기 시각). 회차 일정 사본 `q:{event:E}:cfg`를 판매 승인이 쓰는 것과 같은 '사본 쓰기' 길입니다. 추천: 이것. 넘기는 길이 하나이고 queue-svc 진입 처리와 섞이지 않으며 갈래 2 안에서 끝납니다. 대가로 core-svc에 대기열 Redis 쓰기 자격 증명(그 키 접두사만, HOT-430의 Redis ACL)과 위협 모델 행이 생깁니다. (나) queue-svc에 내부 gRPC(예 `PutSaleEligibility`, 1만 개씩 나눠 받기)를 두고 queue-svc만 자기 Redis에 쓴다. 쓰기 소유가 한 서비스로 남지만, 갈래 3이 고치는 중인 queue-svc에 새 RPC와 처리기가 들고 50만 건을 나눠 보내야 합니다. (다) queue-svc가 진입 때 core-svc에 묻는다(사본 없음). 진입이 공연 DB에 기대지 않게 한다는 정본(docs/data.md §3 일정 사본 행)과 어긋나 권하지 않습니다. 정해지면 Q-T36 ⑦과 사본 어댑터를 그 길을 만드는 단계((가)는 갈래 2 새 단계 또는 BAT-157 뒤 첫 묶음, (나)는 8.2 ①의 갈래 3 단계)에 둡니다.

## 11. 구현 지시문에 넣을 '자주 놓친 결함'(docs/architecture.md:1129~1141)의 이 묶음 판

- 응답은 정확한 값까지: 올리기 결과의 `applied`·두 수·행 번호 목록 전체·SHA-256(올린 바이트로 계산한 값), 규칙 저장의 판과 `ETag`, 공개 요약 `salePhases`의 시각·한도, 사본 포트가 받은 `expiresAt`·`eventIds`·`accountIds`(정렬해 견줌).
- 지우기는 건드린 것을 모두 본다: 파기 뒤 그 명단의 구성원 0·명단 행 0·다른 명단과 다른 공연은 그대로, 사본 `drop` 호출. 같은 키 다시 올리기는 옛 구성원이 하나도 남지 않는다.
- 경계 양쪽: 잠금 시각 − 1ms와 그 시각, 파기 시각 − 1ms와 그 시각, 오픈 − 1ms와 오픈(정렬 설정 잠금), 창 `from`·`to`의 양쪽, 50만 줄과 50만 1줄, 8MiB와 1바이트 넘음, 행 번호 1,000개와 1,001번째, 규칙 20·21개, 깊이 3·4, 잎 10·11개, 빈 파일·빈 줄만 있는 파일.
- 소유자 대조를 뺀 요청: 다른 테넌트 공연의 규칙·명단, 실무자의 올리기·지우기, 승인 이력 공연에서 실무자의 규칙·회차 고치기, 비로그인 팬 자격.
- 겹친 가드는 하나씩 빼 본다: 앱의 테넌트 조건과 행 보안, 올리기 앞 잠금 확인과 트랜잭션 안 다시 보기(둘 사이에 시계를 옮기는 시험), 계약 생성 Zod와 평가 함수의 같은 검사(예 깊이·명단 키 모양)는 각각을 잡는 시험.
- 시험 값은 상수와 다르게: 회차 1인 한도 4·3과 규칙 한도 2(정본 기본 4와 다른 회차 하나), 잠금 24시간·파기 1일은 시험이 시계를 옮겨 보되 단언 값은 ADR-0261 결정 7의 글로 적는다. 판은 9 → 10을 지나게 올려 글자 비교 결함을 잡는다.
- 시작 파일 조립(`main.ts`의 변환 어댑터 주소, 사본 어댑터, relay의 정비 일 이름)은 시험 조립과 따로 띄워 본다.
- 장애 주입: 변환 50번 가운데 마지막 호출만 실패(아무것도 저장하지 않음), 구성원 넣기 도중 커밋 실패(옛 구성원 그대로), 커밋 뒤 사본 넘기기 실패(200, `copied_version` 그대로).
- 정본 시험 표에 세부를 더할 때는 '연결: …' 앞에 둔다(S-T39·Q-T36 ⑦은 그렇게 썼다).
