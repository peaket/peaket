### 4. 공개 인터페이스(시험 담당은 이 모양의 빈 뼈대만 더한다)

`model/` 파일은 node --test가 바로 불러 보므로 상대 경로 `.ts`만 가져오고(`'../../../shared/lib/kst.ts'`처럼), `@peaket/api-client/model`은 타입으로만 가져온다(`detail.ts`와 같다). 화면 코드(`ui/*.tsx`)는 시계·난수를 직접 부르지 않는다(`ui/no-render-clock.test.mjs`).

- `model/sale.ts`
  - `type SalePhaseKind = 'PRESALE' | 'GENERAL'`, `interface DetailSalePhase { kind; startsAtMs; endsAtMs; limit }`.
  - `toSalePhases(list: EventPublicSummary['salePhases']): DetailSalePhase[]` — 시각 순, 틀린 조각(시각 없음·끝 ≤ 시작·모르는 종류·한도가 1~10 밖) 버림, 10개까지.
  - `interface FanPhase extends DetailSalePhase { eligible: boolean }`, `type FanEligibility = { status: 'none' } | { status: 'known'; phases: FanPhase[]; lists: { name: string; destroyAtMs: number }[] }`, `type FanEligibilityState = { status: 'idle' } | { status: 'loading' } | FanEligibility`.
  - `toFanEligibility(body: unknown): FanEligibility` — 모양이 틀리면 `none`.
  - `needsEligibility(phases: DetailSalePhase[], session: { status: string }, nowMs: number): boolean` — ADR-0272 결정 3 '부르는 때'.
  - `eligibilityJudgeAt(phase: string | undefined, openAtMs: number, nowMs: number): number | undefined` — 결정 3 '판정 시각'. `ended`·`cancelled`·없음은 `undefined`.
  - `type EligibilityGate = null | 'loading' | { reason: string }`.
  - `eligibilityGate(i: { phase: string | undefined; session: { status: string }; phases: DetailSalePhase[]; fan: FanEligibilityState; denied: boolean; openAtMs: number; nowMs: number }): EligibilityGate` — 결정 3 '자격 없음'·'실패'·받는 동안, 결정 4 명단 밖 알림.
  - `saleBoundaryAfter(phases: DetailSalePhase[], nowMs: number): number | undefined` — 결정 3 '다시 고르는 때'.
  - `presaleNotice(i: { fan: FanEligibilityState; sellerName: string; nowMs: number }): { lead: string; notice: string } | null` — 결정 3 '선예매 대상 안내'의 두 글.
  - `SALE_ELIGIBILITY_DENIED_HASH = '#sale-eligibility-required'`, `isDeniedHash(hash: string): boolean`(정확히 같은 값만), `deniedUntilMs(phases: DetailSalePhase[], nowMs: number): number | undefined`(지금이 든 조각의 끝, 없으면 `undefined` = 문서 동안).

### 8. 브라우저 확인 대본(브라우저 확인 폴더(`docs/review/browser-check/`)의 새 `HOT-346.md`(기록 담당이 만든다)에 결과, 스킬 peaket-browser-check)

시험용 Chrome 프로필, 운영 빌드 로컬 서버(웹 4101), 가짜 API(`node apps/web/scripts/mock-api.mjs`), 대기실 빌드. 상태는 `/__mock/state?…`로 바꾼다. 회원은 `fan=member`(본인확인 완료). 정본 화면 자리: d5 §5.2 ⑦ 상태 표(docs/design/d5-screen-blueprint.md:863~890), d2 §3.6(docs/design/d2-design-system.md:162~167), ADR-0272.

- B1 선예매 대상: `detailSale=presale-before&eligibility=eligible`로 판매 전 회차 공연 상세. 회차·오픈 묶음(히어로·데스크톱 패널)의 '선예매' 줄에 결정 3 두 글(명단 이름·시작·한도·판매자·파기 날짜)이 보이고, 휴대폰 폭(375)의 아래 고정 띠에는 없다.
- B2 자격 없음(FE-T18 몫): `eligibility=ineligible`. ⑦이 '로비 입장'(선착순 회차면 '대기열 들어가기') 비활성이고 바로 위에 "이 회차의 선예매 대상이 아닙니다. 일반 예매는 …에 시작합니다"가 보인다. Tab으로 버튼에 닿고 Enter·Space·클릭이 아무 일도 하지 않으며, 버튼의 `aria-describedby`가 그 글을 가리킨다(접근성 트리 확인). 휴대폰·데스크톱 둘 다.
- B3 경계: `detailSale=presale-now&eligibility=ineligible`로 일반 예매 시작 1분 전쯤의 고정 자료를 써서 시작 시각이 지나면 새로고침 없이 [대기열 들어가기]가 살아나는지 본다(가짜 API가 그런 시각을 못 주면 '해당 없음'과 까닭을 적고 T6에 맡긴다).
- B4 자격 모름: `eligibility=down`. 버튼이 평소 모양이고 오류 글이 없다. `fan=guest`면 판매 자격을 부르지 않는다(개발자 도구 네트워크에 `sale-eligibility` 요청 0).
- B5 명단 밖 403(Q-T36 ⑧): `eligibility=eligible`인데 대기실 가짜 API 로비·진입이 403 `sale-eligibility-required`를 주게 두고(가짜 API에 그 상태가 없으면 구현 담당이 `queueLobby`·`queueEntry` 값을 더한다) [로비 입장]·[대기열 들어가기]를 누른다. 대기실이 사람 확인 실패를 보이지 않고 공연 상세로 돌아오며, 주소에 조각이 남지 않고, ⑦이 자격 없음 모양이다. 새로고침하면 다시 평소 버튼이다.
- B6 매진: 판매 중 회차에서 `queue=sold-out`. 등급 배지 모두 <매진>, ⑦이 [ 취소표 알림 받기 ]·( 다른 회차 › ). 토글을 켜고 끄면 신청·끄기 요청이 한 번씩 가고(검사 기록 `/__mock/requests`), `subscribe=limit`이면 실패 글과 되돌림.

- B8 상태 파일 실패: 가짜 API를 상태 파일만 404로(없는 회차 등) 두면 배지가 '판매 중' 고정 글. 오픈 전 회차에서는 `segment-states` 요청이 0이다. 판매 중 회차에서 탭을 숨겼다가 30초 넘어 다시 보이면 요청이 한 번 더 가고, 그 전이면 가지 않는다.

### 10. 감독에게 알릴 것·정할 질문

- **질문 1(첫 JS)**: 공연 상세 첫 JS 한도는 203.3kB이고 지금 202.3kB다. 새 판정 코드(차례·조각·배지)는 첫 그리기에 필요해 늦게 가져올 수 없는 부분이 있다(1kB 안팎 [가정]). 넘으면 구현 담당은 멈추고 보고한다. 그때 (가) 기준선을 올린다(HOT-344처럼 까닭을 `js-baseline.json` 메모에 적음) / (나) 다른 코드를 늦게 가져와 줄인다 가운데 감독이 정한다.
- **질문 2(방향 확인, 추천 적용으로 정본에 씀)**: ADR-0272 결정 1은 새 파일을 만들지 않고 대기 상태 파일 구간 0을 공연 상세의 출처로 썼고, 오픈 전과 오픈 순간에는 읽지 않으며 주기 조회도 하지 않는다. 그래서 화면을 연 채 오픈을 지난 팬은 다시 보일 때까지 '판매 중'을 본다. 방향을 바꾸는 결정은 아니라고 보았지만(ADR-0200·0214가 넘긴 빈칸 채우기), 감독이 다르게 보면 시험을 쓰기 전에 알려 달라.
- 공연 상세가 상태 파일을 부르면 queue-svc 파드가 그 회차 파일 만들기를 켠다(결정 5). 판매 중 회차마다 1초 주기 생성이 늘 켜진 상태가 될 수 있다(켠 회차 1,000개 상한 안). 측정 창(PRF·HOT-460)에서 볼 거리로 갈래 정리 목록 후보에 올린다.

- 가짜 API 대기실 로비·진입에 403 `sale-eligibility-required` 상태가 없으면 구현 담당이 더한다(B5). 대기실 가짜 API(`scripts/mock-api/queue.mjs`)는 갈래 2만 고친다.
