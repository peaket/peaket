### 4. 공개 인터페이스(시험 담당은 이 모양의 빈 뼈대만 더한다)

`model/` 파일은 node --test가 바로 불러 보므로 상대 경로 `.ts`만 가져오고(`'../../../shared/lib/kst.ts'`처럼), `@peaket/api-client/model`은 타입으로만 가져온다(`detail.ts`와 같다). 화면 코드(`ui/*.tsx`)는 시계·난수를 직접 부르지 않는다(`ui/no-render-clock.test.mjs`).

- `model/sale.ts`
  - `type SalePhaseKind = 'PRESALE' | 'GENERAL'`, `interface DetailSalePhase { kind; startsAtMs; endsAtMs; limit }`.
  - `toSalePhases(list: EventPublicSummary['salePhases']): DetailSalePhase[]` — 시각 순, 틀린 조각(시각 없음·끝 ≤ 시작·모르는 종류·한도가 1~10 밖) 버림, 10개까지.
  - `interface FanPhase extends DetailSalePhase { eligible: boolean }`, `type FanEligibility = { status: 'none' } | { status: 'known'; phases: FanPhase[]; lists: { name: string; destroyAtMs: number }[] }`, `type FanEligibilityState = { status: 'idle' } | { status: 'loading' } | FanEligibility`.
  - `toFanEligibility(body: unknown): FanEligibility` — 모양이 틀리면 `none`.
  - `needsEligibility(phases: DetailSalePhase[], session: { status: string }, nowMs: number): boolean` — ADR-0272 결정 3 '부르는 때'.
  - `eligibilityJudgeAt(phase: string | undefined, openAtMs: number, nowMs: number): number | undefined` — 결정 3 '판정 시각'. `ended`·`cancelled`·없음은 `undefined`.
  - `type EligibilityGate = null | 'loading' | { reason: string }`.
  - `eligibilityGate(i: { phase: string | undefined; session: { status: string }; phases: DetailSalePhase[]; fan: FanEligibilityState; denied: boolean; openAtMs: number; nowMs: number }): EligibilityGate` — 결정 3 '자격 없음'·'실패'·받는 동안, 결정 4 명단 밖 알림.
  - `saleBoundaryAfter(phases: DetailSalePhase[], nowMs: number): number | undefined` — 결정 3 '다시 고르는 때'.
  - `presaleNotice(i: { fan: FanEligibilityState; sellerName: string; nowMs: number }): { lead: string; notice: string } | null` — 결정 3 '선예매 대상 안내'의 두 글.
  - `SALE_ELIGIBILITY_DENIED_HASH = '#sale-eligibility-required'`, `isDeniedHash(hash: string): boolean`(정확히 같은 값만), `deniedUntilMs(phases: DetailSalePhase[], nowMs: number): number | undefined`(지금이 든 조각의 끝, 없으면 `undefined` = 문서 동안).

### 8. 브라우저 확인 대본(브라우저 확인 폴더(`docs/review/browser-check/`)의 새 `HOT-346.md`(기록 담당이 만든다)에 결과, 스킬 peaket-browser-check)

시험용 Chrome 프로필, 운영 빌드 로컬 서버(웹 4101), 가짜 API(`node apps/web/scripts/mock-api.mjs`), 대기실 빌드. 상태는 `/__mock/state?…`로 바꾼다. 회원은 `fan=member`(본인확인 완료). 정본 화면 자리: d5 §5.2 ⑦ 상태 표(docs/design/d5-screen-blueprint.md:863~890), d2 §3.6(docs/design/d2-design-system.md:162~167), ADR-0272.

- B1 선예매 대상: `detailSale=presale-before&eligibility=eligible`로 판매 전 회차 공연 상세. 회차·오픈 묶음(히어로·데스크톱 패널)의 '선예매' 줄에 결정 3 두 글(명단 이름·시작·한도·판매자·파기 날짜)이 보이고, 휴대폰 폭(375)의 아래 고정 띠에는 없다.
- B2 자격 없음(FE-T18 몫): `eligibility=ineligible`. ⑦이 '로비 입장'(선착순 회차면 '대기열 들어가기') 비활성이고 바로 위에 "이 회차의 선예매 대상이 아닙니다. 일반 예매는 …에 시작합니다"가 보인다. Tab으로 버튼에 닿고 Enter·Space·클릭이 아무 일도 하지 않으며, 버튼의 `aria-describedby`가 그 글을 가리킨다(접근성 트리 확인). 휴대폰·데스크톱 둘 다.
- B3 경계: `detailSale=presale-now&eligibility=ineligible`로 일반 예매 시작 1분 전쯤의 고정 자료를 써서 시작 시각이 지나면 새로고침 없이 [대기열 들어가기]가 살아나는지 본다(가짜 API가 그런 시각을 못 주면 '해당 없음'과 까닭을 적고 T6에 맡긴다).
- B4 자격 모름: `eligibility=down`. 버튼이 평소 모양이고 오류 글이 없다. `fan=guest`면 판매 자격을 부르지 않는다(개발자 도구 네트워크에 `sale-eligibility` 요청 0).
- B5 명단 밖 403(Q-T36 ⑧): `eligibility=eligible`인데 대기실 가짜 API 로비·진입이 403 `sale-eligibility-required`를 주게 두고(가짜 API에 그 상태가 없으면 구현 담당이 `queueLobby`·`queueEntry` 값을 더한다) [로비 입장]·[대기열 들어가기]를 누른다. 대기실이 사람 확인 실패를 보이지 않고 공연 상세로 돌아오며, 주소에 조각이 남지 않고, ⑦이 자격 없음 모양이다. 새로고침하면 다시 평소 버튼이다.
- B6 매진: 판매 중 회차에서 `queue=sold-out`. 등급 배지 모두 <매진>, ⑦이 [ 취소표 알림 받기 ]·( 다른 회차 › ). 토글을 켜고 끄면 신청·끄기 요청이 한 번씩 가고(검사 기록 `/__mock/requests`), `subscribe=limit`이면 실패 글과 되돌림.
- B7 등급 매진: `queue=on-sale&queueSoldOutTiers=<한 등급 ID>`. 그 등급만 <매진>, 나머지 '판매 중', 버튼은 [대기열 들어가기].
- B8 상태 파일 실패: 가짜 API를 상태 파일만 404로(없는 회차 등) 두면 배지가 '판매 중' 고정 글. 오픈 전 회차에서는 `segment-states` 요청이 0이다. 판매 중 회차에서 탭을 숨겼다가 30초 넘어 다시 보이면 요청이 한 번 더 가고, 그 전이면 가지 않는다.

### 10. 감독에게 알릴 것·정할 질문

- **질문 1(첫 JS)**: 공연 상세 첫 JS 한도는 203.3kB이고 지금 202.3kB다. 새 판정 코드(차례·조각·배지)는 첫 그리기에 필요해 늦게 가져올 수 없는 부분이 있다(1kB 안팎 [가정]). 넘으면 구현 담당은 멈추고 보고한다. 그때 (가) 기준선을 올린다(HOT-344처럼 까닭을 `js-baseline.json` 메모에 적음) / (나) 다른 코드를 늦게 가져와 줄인다 가운데 감독이 정한다.

### 검증 뒤 정한 것(2026-11-16)

검증 담당(커밋 `fd76b4de`, '## 검증')이 남긴 살아남은 둘(V040-28·V040-34)과 참고 하나(V040-42의 멈춤)다.

**V040-34(이유 글의 일반 예매 시각) — 판정: 첫 문장만 내는 지금 동작은 정본이 뜻한 결과가 아니다. 정본을 바로잡았다.** 결정 3 '자격 없음'의 이유 글은 '판정한 조각이 끝나면 언제 살 수 있는지'를 알리려는 것이고, 결정 4의 창은 바로 그 시각(오픈 시각)에 끝난다. 오픈 전에 켠 명단 밖 알림에서 일반 예매가 오픈 시각에 바로 열리면 "…일반 예매는 {오픈 시각}에 시작합니다"가 맞다. 그래서 ADR-0272 결정 3·4에 '시작 시각이 판정 시각과 **같거나 뒤**인 첫 `GENERAL`, 지금이 아니라 판정 시각으로 고른다'를 적었다(추천 적용, 2026-11-16). 판정 시각이 `PRESALE` 안인 보통 경우는 같은 시각에 시작하는 `GENERAL`이 있을 수 없어 결과가 바뀌지 않는다.

- 구현 담당 몫: `model/sale.ts`의 이유 글 고르기(`deniedReason`, 지금 `sale.ts:104`)에서 `startsAtMs > atMs`를 `startsAtMs >= atMs`로 바꾼다. 부르는 쪽이 넘기는 시각은 지금처럼 판정 시각이다.
- 시험 담당 몫(`model/sale.test.mjs`):
  - VV1 `[V040-34][Q-T36 ⑧] 오픈 전에 켠 명단 밖 알림이고 일반 예매가 오픈 시각에 바로 시작하면 이유 글은 "이 회차의 선예매 대상이 아닙니다. 일반 예매는 {오픈 시각 M/D(요일) HH:MM}에 시작합니다"다`. 검증 담당이 적은 조각(PRESALE 오픈 − 1시간 ~ 오픈, GENERAL 오픈 ~ 판매 종료)과 `deniedWindow(…, 오픈, 오픈 − 10분)`, `phase: 'lobby'`·지금 오픈 − 1분의 `eligibilityGate`가 위 글 전체와 같음을 단언한다(지금 코드는 첫 문장만이라 먼저 실패한다). 같은 창으로 지금 = 오픈이면 `null`(창 끝)도 단언한다.
  - VV2 `[V040-34] 이유 글은 지금이 아니라 판정 시각으로 고른다: 오픈 전에는 오픈 시각 뒤 첫 GENERAL이다`. 오픈 전 조각이 섞인 공개 조각(GENERAL 오픈 − 2시간 ~ 오픈 − 1시간, PRESALE 오픈 ~ G, GENERAL G ~ 판매 종료. 계약 밖이지만 `toSalePhases`가 받는 모양)에서 지금 = 오픈 − 3시간, `phase: 'closed'`, 팬 자격의 PRESALE `eligible` false면 이유 글이 G 시각이다(지금 기준으로 고르는 틀린 구현은 오픈 − 2시간을 내 실패한다). 판정 시각이 이미 시작한 GENERAL 안이고 뒤 GENERAL이 없으면(명단 밖 알림, `phase: 'queue'`) 첫 문장만이다.

**V040-28(주소 조각 지우기 빼기) — 정본은 그대로(결정 4 "`history.replaceState`로 주소 조각만 지운다"). 순수 함수로 꺼내고 소스 읽기로 잇기를 막는다.**

- 시험 담당 몫:
  - VV3(`model/sale.test.mjs`) `[V040-28][Q-T36 ⑧] 명단 밖 조각을 지운 주소는 경로와 쿼리를 남기고 조각만 뺀다(다른 조각·대소문자·뒤 글자·빈 조각은 null)`. 예: `{ pathname: '/events/e1', search: '?ref=a', hash: '#sale-eligibility-required' }` → `'/events/e1?ref=a'`, 쿼리 없음 → `'/events/e1'`, T8의 목록 밖 조각마다 `null`.

### 웨이브 끝 리뷰 뒤 정한 것(2026-11-16)

웨이브 끝 보안 리뷰(커밋 `8fd2505c`, docs/review/measurements/W7-lane2-review-security.md의 W7L2-S2, 중간·보안): 누구나 `#sale-eligibility-required` 조각을 붙인 링크로 남의 예매 버튼을 끌 수 있다. 정본 빈틈이라 ADR-0272 결정 4에 '출처 확인' 항목을 더했다(추천 적용, 2026-11-16). 방향은 그대로다(명단 밖 알림을 두고, 켜는 조건만 좁힌다).

- **정한 것**: 대기실이 403을 받고 돌려보내기 직전 같은 탭 sessionStorage `peaket.queue.{eventId}.eligDenied`에 `{"v":1,"at":<기기 시각 밀리초>}`를 한 번 쓴다. 공연 상세는 처음 그린 뒤 그 키를 늘 한 번 읽고 바로 지우며, 조각이 정확히 맞고 이 회차 값의 모양이 맞고 `at`이 지금 − 60초 [가정] 이상 · 지금 + 5초 [가정] 이하일 때만 켠다. 짝이 맞지 않으면(조각만 = 바깥 링크, 표시만, 오래됨·미래·모양 틀림, 저장소를 읽거나 지우지 못함) 켜지 않고 평소대로 고르며, 조각은 어느 경우든 지운다. 새 키는 docs/frontend.md §3.12 저장소 표(:613)에 적었다.
- **구현 담당 몫**
  - 대기실(`apps/web/queue-room/src/live/store.ts`): 가게에 `markEligibilityDenied(): void`를 더한다. `peaket.queue.{eventId}.eligDenied`에 `JSON.stringify({ v: 1, at: now() })`(가게가 받는 `now`, 기기 시계)를 쓰고, 저장소가 없거나 던지면 조용히 넘어간다(지금 `safe(…)`와 같다). 파일 머리의 저장소 목록 주석에도 더한다.
  - 대기실(`controller.ts:189~193` 근처): `isSaleDenied(reply)`인 로비·진입 두 갈래에서 `store.markEligibilityDenied()`를 부른 뒤 `leave(deniedEvent(), sig)`로 간다. 다른 403·4xx는 쓰지 않는다.
  - 공연 상세(`model/sale.ts`): `takeDeniedMarker(i: { kv: { getItem(k: string): string | null; removeItem(k: string): void } | null; eventId: string; loc: { pathname: string; search: string; hash: string }; deviceNowMs: number; phases: DetailSalePhase[]; openAtMs: number }): { cleanUrl: string | null; denied: { untilMs?: number } | null }`를 더한다. 키를 읽고(던지면 없음) 늘 지우며(던지면 켜지 않음), `cleanUrl`은 지금의 `deniedHashCleanUrl(loc)`, `denied`는 짝이 맞을 때만 `deniedWindow(phases, openAtMs, deviceNowMs)`다. 창의 시각 기준은 지금처럼 보정한 시계가 맞으므로 `deniedWindow`에는 보정 시각을 따로 넘겨도 된다(이때 입력에 `readAtMs`를 더한다. 표시의 나이는 기기 시계로, 창은 보정 시계로 잰다).
  - 공연 상세(`ui/sale-live.ts:147~158` `useDeniedMarker`): 효과 안에서 `window.sessionStorage`를 얻어(얻기가 던지면 `null`) `takeDeniedMarker`에 넘기고, `cleanUrl`이 있으면 `history.replaceState(…, cleanUrl)`, `setDenied(denied)`. 기기 시각(`Date.now()`)은 효과 안에서만 읽는다.
- **시험 담당 몫**(바깥 경계: `takeDeniedMarker` → `eligibilityGate` → `bookingCta`를 이어서, 대기실은 가게·컨트롤러를 이어서 본다. 단언 값은 정본 값 60초·5초를 적고 코드 상수를 가져오지 않는다)
