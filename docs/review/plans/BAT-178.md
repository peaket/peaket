# BAT-178 계획(바로가기 초점 고침: CMP-065 본문 바로가기)

- **무엇**: 소비자 웹·파트너의 셸에 있는 본문 바로가기(CMP-065, '본문 바로가기' 링크)가 키보드 초점을 받아도 화면에 보이지 않는 결함을 고친다. 링크를 초점 때 보이게 하는 CSS를 지금의 `sr-only`/`focus:not-sr-only` 조합에서 디에스에 이미 있는 `SkipLink`(`.pk-skip-link`)로 바꾼다. 링크를 누르면 `#main`으로 초점이 옮겨지고 본문 첫 부분이 화면에 들어오는지도 시험으로 고정한다.
- **쉬운 말**: '본문 바로가기'는 키보드만 쓰는 사람이 머리·메뉴를 하나하나 Tab으로 지나지 않고 본문으로 바로 가게 하는 숨은 링크다. 지금은 Tab을 눌러 이 링크에 초점이 가도, 숨기는 규칙(`clip`)이 풀리지 않아 글자가 0×0으로 잘린 채다. 화면 낭독기는 링크를 읽지만 눈으로는 볼 수 없어, 초점이 어디에 있는지 알기 어렵다. 링크를 초점 때 보이게 하는 공용 부품으로 바꾸고, 누른 뒤 초점이 본문으로 옮겨지는지까지 시험한다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane2`, 가지 `feature/lane2-BAT-178`, 출발 `develop` `a4078ff55`. 2026-11-20 계획 담당이 썼고 제품·시험 코드는 쓰지 않았다. 읽은 것: `docs/lanes/lane2.md` 8~11줄, `docs/lanes/lane2-cleanup.md` 154줄, `docs/BUILD_ORDER.md` BAT-176~177 행, `docs/review/browser-check/HOT-381.md` 22·26줄, `docs/frontend.md` §5.11, `docs/design/d2-design-system.md` CMP-065, `docs/design/d4-handoff-checklist.md` #22, `docs/security/asvs/frontend.md` V3 절, `apps/web`의 루트 레이아웃과 셸, `packages/ds`의 `WebShell`·`PartnerShell`·`SkipLink`·`ConsoleShell`·`kit.css`·`ds.css`, `apps/partner`의 `AuthFrame`·`PartnerShell` 사용처, `apps/console-host`·`apps/forensics`·`apps/web/queue-room`의 같은 링크.
- **등급**: C(짧은 고리, ADR-0283 결정 2). 화면에 보이는 초점 모양과 링크 부품만 바꾸고 돈·좌석 홀드·대기 순번에 닿지 않는다. 단계는 `-`, 장부 범위는 `-`, WBS는 0.5일 [가정]이다.
- **차례**: 계획 → 시험(실패 확인) → 구현 → 리뷰 → 검증 → 기록. 이 파일은 역할마다 자기 절만 쓴다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.

## 감독에게

1. **같은 결함이 세 곳이다.** 소비자 웹 `WebShell.tsx`, 파트너 `PartnerShell.tsx`, 파트너 인증 틀 `AuthFrame.tsx`가 모두 `sr-only focus:not-sr-only`를 쓴다. 셋 다 `SkipLink`로 바꾸는 것이 이 묶음의 제품 변경 전부다. 관제 `ConsoleShell`, 포렌식, `console-host` 로그인 화면은 초점 때 클래스를 바꾸는 다른 방식이라 지금도 보인다(아래 1).
2. **`queue-room`은 링크는 보이지만 초점 대상이 아니다.** 대기실 경량 페이지의 `main`에는 `tabindex="-1"`이 없어, 링크를 눌러도 `document.activeElement`가 `main`으로 가지 않는다(브라우저가 '다음 Tab 시작점'만 옮긴다). 이 묶음은 CMP-065 셸 셋만 고치고, 대기실·포렌식 `main`의 `tabindex`는 구간 끝 정리 목록 후보로 둔다(아래 8). 같이 고치기를 원하면 감독이 범위를 넓힌다.
3. **정본은 고치지 않았다.** `docs/frontend.md` §5.11과 디자인 정본은 이미 '본문 바로가기'와 초점 규칙을 말하고 있어 새 문장이 필요 없다. 바꾸는 것은 구현뿐이다. 새 ADR도 쓰지 않는다.

## 계획

### 1. 지금 상태와 원인

- **셸 셋의 마크업**:
  - 소비자 웹: `packages/ds/src/components/WebShell/WebShell.tsx:270~275`가 `<a className="sr-only focus:not-sr-only focus:fixed …" href="#main">본문 바로가기</a>`를 그린다.
  - 파트너: `packages/ds/src/components/PartnerShell/PartnerShell.tsx:138~143`이 같은 꼴이다(`focus:!absolute`).
  - 파트너 인증 틀: `apps/partner/src/_pages/partner-auth/ui/AuthFrame.tsx:22~27`도 같다.
- **숨기는 규칙 두 벌이 엇갈린다**:
  - 키트 `packages/ds/src/styles/kit.css:67`의 `.sr-only`는 `clip: rect(0 0 0 0)`으로 숨긴다. `components` 층이다.
  - Tailwind v4는 `.sr-only` 유틸을 `clip-path: inset(50%)`으로 만들고, `focus:not-sr-only`는 `clip-path`는 풀지만 `clip`은 건드리지 않는다. 빌드 산출물(`apps/web/.next/static/chunks/*.css`)에서 두 규칙과 `focus:not-sr-only`의 속성 목록을 확인했다.
  - 그래서 초점을 받아 `position`·`width`·`height`·`overflow`는 풀려도, 키트의 `clip: rect(0 0 0 0)`이 남아 그려지는 내용이 0×0으로 잘린다. `docs/review/browser-check/HOT-381.md`가 같은 화면에서 `getComputedStyle(activeElement).clip === 'rect(0px, 0px, 0px, 0px)'`로 재현했다.
- **이미 맞는 부품이 있다**: `packages/ds/src/components/SkipLink/SkipLink.tsx`는 `.pk-skip-link`를 쓰고, `packages/ds/src/styles/ds.css:21~58`이 `:not(:focus)`일 때만 1×1로 숨기며 초점 때는 `clip: auto`·`position: fixed`·왼쪽 위 버튼 모양으로 보인다. 스캐너 셸(`ScannerShell.tsx:44`)이 이미 이 부품을 쓴다.
- **초점 대상은 이미 준비돼 있다**: 셸 셋의 `<main id="main" tabIndex={-1}>`(PartnerShell 284~288줄, AuthFrame 28~33줄, 소비자 웹 화면의 `main`)이 있어 링크를 누르면 초점이 옮겨질 수 있다. 소비자 웹은 `apps/web/src/_app/styles/globals.css:38~39`의 `scroll-padding-top`이 고정 머리 높이를 비켜 준다. 파트너·관제 머리는 기본 폭에서 고정·붙박이가 아니다.
- **같은 링크를 쓰는 다른 곳(이번에 고치지 않음)**:
  - 관제 `ConsoleShell.tsx:488~502`는 `onFocus`/`onBlur`로 클래스 자체를 `btn`↔`sr-only`로 바꿔 보인다.
  - 포렌식 `apps/forensics/src/App.tsx:97~110`도 같은 상태 방식이다.
  - `console-host` 로그인 `apps/console-host/src/pages/login/ui/Page.tsx:58~70`은 초점 때 `classList.replace('sr-only', 'btn')`를 한다.
  - 대기실 `apps/web/queue-room/src/styles/page.css:12`의 `.q-skip:focus`는 `clip: auto`를 직접 넣어 링크가 보인다. 다만 `shell.*.html`의 `main`에는 `tabindex="-1"`이 없다(위 감독에게 2).

### 2. 바른 동작

1. **평소**: 링크는 화면에 보이지 않고 문서 흐름을 차지하지 않는다(1×1, 절대 위치).
2. **초점을 받으면**: 링크가 화면 왼쪽 위에 버튼 모양으로 나타난다. 그려진 상자가 1×1보다 크고, 화면 안에 있으며, 고정 머리·배너·대화상자에 가리지 않고, 초점 테두리(킷의 `.pk :focus-visible`)가 보인다.
3. **누르면(Enter)**: 같은 문서 안에서 `#main`으로 이동한다. `document.activeElement`가 `main`이고, `main`의 시작(또는 첫 제목)이 화면 안에 보이도록 스크롤된다. 페이지를 새로 열지 않는다.
4. **초점을 잃으면**: 링크는 다시 숨는다.

접근성 근거는 `docs/frontend.md` §5.11(목표·랜드마크·시험), `docs/design/d2-design-system.md` CMP-065(셸의 본문 바로가기), `docs/design/d4-handoff-checklist.md` #22(초점 가림; 이 결함은 그 형제 기준인 초점 보임이다), `docs/planning/02-requirements.md` NFR-020이다. ASVS는 `docs/security/asvs/frontend.md` V3 절이 CSP·출처 분리 같은 보안 항목이라 이번에 새 행을 만들지 않는다(접근성은 ASVS 통제가 아니라 NFR-020이다).

### 3. 고치는 방법 비교(최소 수정 고르기)

| 후보 | 좋은 점 | 문제 | 결론 |
| --- | --- | --- | --- |
| `kit.css`의 `.sr-only`를 `clip-path`로 바꾼다 | 한 줄로 근본 원인을 없앤다 | 모든 앱의 `sr-only` 글(라벨·라이브 영역·표 캡션 등)이 한꺼번에 바뀐다. 오래된 브라우저의 `clip` 지원을 걷어내는 결정이라 이 묶음 범위를 넘는다 | 쓰지 않는다 |
| `ds.css`에 `.sr-only:focus { clip: auto }`를 더한다 | 세 셸을 한 규칙으로 고친다 | 숨기는 규칙이 여전히 두 벌(`sr-only`·`pk-skip-link`)이고, 초점을 받는 모든 `sr-only` 요소의 뜻을 바꾼다. 공용 부품이 이미 있는데 규칙을 하나 더 만드는 꼴이다 | 쓰지 않는다(대체안) |
| 셸 셋을 `SkipLink`로 바꾼다 | 디에스의 정본 부품을 쓴다. 스캐너에서 이미 같은 방식이다. 숨김·보임이 한 규칙(`.pk-skip-link:not(:focus)`)에 모이고, 버튼 모양·`z-index`·초점 테두리가 함께 온다. 바뀌는 파일이 셋뿐이다 | 셸의 링크 생김새가 지금의 '떠 있는 흰 상자'에서 'primary 버튼'으로 바뀐다(초점 때만 보이므로 화면 흐름에는 영향 없음) | **고른다** |
| `main`에 `tabIndex={-1}`을 더한다 | 초점이 확실히 옮겨진다 | 셸 셋에는 이미 있다. 대기실·포렌식에만 빠져 있다(위 감독에게 2) | 셸 셋은 그대로 두고 시험으로 확인한다 |
| `:focus-visible`만 쓴다 | 마우스 초점과 키보드 초점을 가른다 | 지금의 숨김 규칙은 `:focus` 기준이고, 스크립트·보조기기 초점이 `:focus-visible`과 다르게 잡힐 수 있다. `clip` 문제도 풀지 못한다 | 쓰지 않는다 |
| `scroll-margin-top`을 더한다 | 고정 머리에 가리지 않게 한다 | 소비자 웹은 이미 `scroll-padding-top`이 있고, 파트너·관제 머리는 기본 폭에서 고정이 아니다. 값이 하나 더 생기면 BAT-171이 정리한 '여백은 한 곳' 규칙과 어긋난다 | 쓰지 않는다(시험으로 확인) |

- **정한 것**: 셸 셋의 날 링크를 `SkipLink`로 바꾼다. `kit.css`·`ds.css`·`.pk-skip-link`는 고치지 않는다. 초점 대상 `main`의 `tabIndex`도 그대로 둔다.
- **공개 인터페이스**: `SkipLink`의 `href` 기본값(`#main`)과 글('본문 바로가기')을 그대로 쓴다. 새 prop·새 CSS 클래스는 없다.

### 6. 틀린 구현 표본(검증 담당, 등급 C지만 8개)
