# 기능 계획: F-01-8(OPS-070 — 법정 접속기록 두 갈래·건수 대조·하루 사본·조사 사본과 조사 칸 지우기)

- **무엇**: 기능 F-01-8(docs/BUILD_ORDER.md:53)의 작업 목록이다(docs/architecture.md §8.6 4의 1·2, ADR-0354). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다. 정본 값은 옮겨 적지 않고 자리(문서 절 이름, 이 커밋 기준)만 가리킨다.
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-01-8`, 가지 `freeze/lane1-F-01-8`, 출발점 `333da1253`(최신 `develop`, 2026-11-24). 이 기능은 v1 배포 범위 밖 `동결`이고 이 가지는 감독이 연 동결 범위 로컬 개발 갈래다. **어떤 커밋도 `develop`·`release`에 합치지 않고 이 가지만 원격에 올린다.** 배포(Helm·kind·INF-020·INF-040)는 하지 않는다.
- **등급과 차례**: 기능 표 등급 B(docs/BUILD_ORDER.md:53)이나 장부 범위에 Q-T61 ①~⑤가 있어 A등급 대상(대기 순번)에 닿는다. 이번 동결 몫은 감독 지시대로 **B 절차**로 한다: 계획 → 시험(기준 트리 실패 확인) → 구현 → 시험 통과. 시험 리뷰·구현 리뷰·검증은 하지 않는다(ADR-0373 결정 3). 구현 리뷰가 필요하면 감독이 따로 띄운다. 시험 담당과 구현 담당은 이 갈래에서 같은 세션이 맡되 커밋을 `Role: plan`·`Role: test`·`Role: impl`로 나눈다.
- **동결의 뜻**: 기능 표 상태는 `동결` 그대로 둔다. 정본 행·단계 줄은 지우지 않고, 이 계획 커밋은 행의 비고에 동결 범위 로컬 개발 사실만 한 줄 더한다. 완성 기한(2026-12-03) 뒤 다시 열 때 이 계획의 미완 몫(§11)부터 본다.
- **선행**: F-01-3(끝남, `develop`): 수집기 셋 설정·생성기 `tools/ci/collector-config.mjs`·2차 마스킹 원천 `packages/platform/src/pii-patterns.json`. F-01-1(끝남): 증거 저장소·보존 규칙. F-01-7(끝남): `alert-check`·경보 규칙 검사. F-01-2(끝남): Grafana 조직·대시보드 생성기. 이 기능은 그 위에 얹고, F-01-3의 고정된 시험(`tools/ci/collector-config.test.mjs`, `packages/platform/test-int/collector-*.int.test.ts`)을 깨지 않는다.
- **정본**: docs/observability.md §1 '수집기 구성'의 '설정 원천과 로컬 확인'(에이전트 로그 파이프라인·접근 로그 갈래가 이 판에 없다는 줄), §5 '법정 접속기록 갈래 신호', §7 '게이트웨이 접근 로그 분기'·'법정 사본은 잃지 않는 갈래'·'원문 IP를 두는 곳'·'개인정보 2단계 마스킹 통제'·'수집 금지 대상', §9 보존 표; docs/data.md §1 '시스템 접속기록' 행·§2 '부정 예매 사후 조사의 표'·§6; docs/infra.md §6 'ClickHouse 접속기록 DB' 행·§10 RB-38; docs/security/asvs/delivery.md 16.3.1·16.3.2·16.3.3·16.4.2·16.4.3; docs/security/data-classification.md '시스템 접속기록'·'조사용 요청 기록'·'여정 ID' 행; docs/features/identity.md §9 '법정 접속기록 관리'; docs/features/queue-admission.md §2 '조사용 요청 기록'·Q-T61; docs/verification.md V-T21·V-T22·V-T23; docs/security/secrets-and-keys.md '데이터 저장소 접속 자격 증명'의 접속기록 사용자 넷; ADR-0076 결정 7(접근 로그 갈래·IP 앞부분), ADR-0127(잃지 않는 갈래·하루 사본·SEV2), ADR-0171 결정 1·2·4(조사 사본·두 갈래 분리·조사 칸), ADR-0173 결정 2·7(조사 저장소 보존·파기), ADR-0073 결정 25(일 해시 앵커), ADR-0089·0146 결정 6(접속기록 사용자·보존).

## 감독에게

1. **[결정 완료] 이번 몫은 로컬 전용이다.** `deploy/`의 설정·표·도구·시험만 만들고 클러스터에 적용하지 않는다. INF-020(수집기 DaemonSet·볼륨·권한·NetworkPolicy·Prometheus 긁기)과 INF-040(kind 노드 비우기·이미지 서명·운영 적용)은 하지 않는다. V-T22의 노드 비우기 실행과 V-T23의 kind 몫은 INF-040으로 넘긴다.
2. **[알림] 브라우저 수집 경로 `/_t/rum`·`/_t/csp`는 이 기능에서 하지 않는다.** OPS-070 단계 줄(docs/BUILD_ORDER.md:676)에 있지만 F-01-8 행의 장부 범위에 그 판정이 없고, gateway·WAF·INF-040 배포에 닿는다. 이 계획 §11에 'OPS-070 남은 몫'으로 적었다. 다시 열 때 새 행이나 INF-040으로 나눈다.
3. **[알림] Q-T61 ⑤(진입 부하 p99·버린 줄 수)는 측정 몫으로 남긴다.** `investigation.requests`를 읽는 `inv-ingest`(F-04-10)가 동결이라 실제 적재 E2E와 진입 부하 비교를 이번에 할 수 없다. ①~④는 이 기능의 설정·단위·정적 시험으로 닫고, ⑤는 빈칸으로 두며 장부에 '동결로 미검증'으로 적는다. B라 `--require`를 막지 않는다.
4. **[알림] V-T21·V-T22·V-T23은 로컬 Docker 시험으로 하는 몫과 측정/INF-040 몫을 나눈다.** V-T21은 Docker ClickHouse 5분 정지·복구와 큐·SEV2 규칙을 로컬로 볼 수 있으나 5분 창·10만 건 부하는 측정 창이 필요하다. V-T22의 에이전트 재시작은 Docker로, 노드 비우기는 INF-040. V-T23은 ClickHouse·moto(Object Lock)로 로컬 시험이 가능하나 이번 동결 몫의 시험 시간이 모자라면 구현·정적 검사·단위 시험까지 하고 Docker 시험은 '다음 몫'으로 넘긴다.
5. **[알림] Docker 잠금.** 이 계획·시험·구현은 Docker 없이 된다. Docker 시험을 돌릴 때만 `D:/ticketpass-locks/lock.sh take docker lane1-F-01-8`을 쓰고, 2026-11-26 08:30~11-27 저녁 갈래 4 측정 창에는 잡지 않는다(ADR-0373 결정 4).
6. **[알림] 정본을 고치지 않은 채로 둔 빈칸.** 접근 로그 JSON 칸 이름과 파일 경로는 `docs/infra.md §4.1 '접근 로그'`가 칸 뜻만 적고 이름을 정하지 않았다. 이 계획 §5가 시험·구현의 계약으로 이름을 정한다. 동결이 풀리면 그 절과 `docs/observability.md §7`에 옮겨 적는다.
7. **[알림] 장부 범위는 그대로 12개다.** `node tools/ci/ledger.mjs --batch F-01-8`: 항목 12개, 자동 시험 1, ID만 2(delivery 16.3.1·16.3.2), 빈칸 9. 이번 시험으로 V-T21~V-T23·Q-T61 ①~④·delivery 16.4.3이 자동 시험이 되고, 16.3.1·16.3.2는 identity 줄 시험이 생기면 세부 번호가 붙어 자동 시험이 된다 [기대]. Q-T61 ⑤는 빈칸으로 남는다.

## 계획

### 1. 범위

- **L1 법정 사본 갈래(수집기)**: 노드 에이전트에 게이트웨이 접근 로그·identity 접속기록 줄을 읽는 전용 filelog 수신기 둘을 더한다. 읽은 위치 저장(`file_storage`), 처음부터 읽기(`start_at: beginning`), 회전 파일 읽기(`compression: auto`), ClickHouse 디스크 큐(`sending_queue.storage`)·큐가 차면 읽기 멈춤(`block_on_overflow: true`)·끝없는 재시도(`retry_on_failure.max_elapsed_time: 0`). 이 갈래는 표본으로 줄이지 않는다. 정본: observability §7 '법정 사본은 잃지 않는 갈래' ①②③.
- **L2 건수 대조와 하루 사본**: 5분마다 15분 전 5분 칸을 보는 대조 계산(게이트웨이 원천 요청 수 대비 적재 행 수 0.1% 초과, identity `seq` 빈 번호), 다음 날 03:30 하루 대조·일 해시 앵커, 매일 04:00 전날 파티션 Parquet 사본(행 수+파일 SHA-256, S3 Object Lock 준수 모드, 그 날짜 3개월 보존+7일), 06:00까지 사본이 없으면 SEV2. 정본: observability §5 '법정 접속기록 갈래 신호', §7 ④⑤, infra §6.
- **L3 표·보존·권한**: ClickHouse 접속기록 DB `access_log` 표(`ReplicatedMergeTree`, `PARTITION BY toYYYYMMDD(ts)`, `ORDER BY ts`, 원문 IP 건너뛰기 색인 bloom filter, TTL 3개월 이상), 사용자 `al_ingest`(INSERT만)·`al_admin_reader`(관리 계정 줄만 행 정책)·`al_investigation`(수사 대응 SELECT)·마이그레이션 역할(ALTER/DROP만), 하루 사본 버킷 쓰기/복원 역할 분리. 정본: data §1 '시스템 접속기록', secrets-and-keys '데이터 저장소 접속 자격 증명', delivery 16.4.2.
- **L4 조사 사본 갈래와 조사 칸 지우기**: 같은 Envoy 접근 로그 파일을 읽되 **자기 file_storage를 따로** 둔 셋째 filelog 수신기. 조사 경로(대기열 다섯·구매·양도) 줄만 골라 Kafka `investigation.requests`로 보낸다. zstd 압축, 큐가 차면 새 줄을 버리고(`block_on_overflow: false`) 재시도는 10분 뒤 그만둔다. 버린 줄은 `inv_copy_dropped_total{node}`로 센다. 법정·일반 사본과 운영 로그·트레이스에서는 조사 칸(`ja4`·`asn`·`edgeBotLabels`·토큰의 `sub`·`pid`·`jny`)을 지운다. 정본: observability §7 '게이트웨이 접근 로그 분기', ADR-0171 결정 2·4, docs/features/queue-admission.md §2·Q-T61.
- **L5 identity 접속기록 줄**: identity-svc가 로그인·재인증·로그아웃·토큰 갱신의 성공·실패를 `kind: "legal-access"` 표준 출력 줄로 쓴다. 줄에는 일시(KST 오프셋), 원문 IP, User-Agent, 결과, 제공자, 확인 요소(`factors`), 실패 종류, 작업 묶음 `act`, 요청 ID, 계정 ID, 파드, **파드마다 늘어나기만 하는 `seq`**가 든다. 토큰·비밀번호·쿠키·본문은 싣지 않는다. 정본: docs/features/identity.md §9, delivery 16.3.1·16.3.2.
- **L6 로컬 검증 도구**: 정적 검사 `tools/ci/access-log-config.mjs`(설정·표·권한·작업·줄 계약), 계산 라이브러리 `tools/ci/access-log-reconcile.mjs`(5분 칸·0.1%·seq 빈 번호·일 앵커·Object Lock 머리), 로컬 작업 실행기 `tools/local/access-log-jobs.mjs`(대조·앵커·사본 내보내기/복원, ClickHouse HTTP·S3 호환 서버). 정본 값은 문서에서 읽고 코드에 옮겨 적지 않는다(0.1%·3개월·7일·03:30·04:00·06:00·5분·15분·10분).
- **어림**: 설정·표·도구 구현 2.25일 [가정](L1 0.5, L2 0.5, L3 0.25, L4 0.5, L5 0.25, L6 0.25)과 시험 0.75일로 3일 안팎이다. 동결 갈래에서는 Docker 통합·측정을 빼면 더 짧다.

### 3. 바른 동작과 근거(값은 정본에서 읽는다)

- **수집기 파일 자리**: F-01-3의 운영 판 위에 `deploy/platform/observability/collector/access-log.yaml`을 겹친다. 배포 차례는 `agent.yaml` → `access-log.yaml` → (로컬만) `local/agent.yaml` → (로컬만) `local/access-log.yaml`이다. `agent.yaml`의 '접근 로그 갈래는 OPS-070 몫이라 이 판에 없다' 줄을 'access-log.yaml이 더한다'로 고친다. `tools/ci/collector-config.mjs`의 검사는 `agent.yaml`만 읽으므로 새 파일은 그 검사를 깨지 않는다 [확인: 2026-11-24 코드 읽음].
- **접근 로그 한 줄의 칸(추천 적용 2026-11-24, F-01-8 계획)**: Envoy `EnvoyProxy` 접근 로그 JSON은 `kind`("envoy-access"), `ts`(UTC ISO), `method`, `path`(쿼리 뗌), `status`, `duration_ms`, `client_ip`(원문), `user_agent`, `x_request_id`, `app`, `ja4`, `asn`, `edge_bot_labels`(배열), `sub`, `pid`, `jny`다. infra §4.1 '접근 로그'가 뜻을 정한 칸을 이름만 정한다. 헤더가 없으면 그 칸은 비거나 빠진다.
- **identity 접속기록 줄의 칸(추천 적용 2026-11-24)**: `kind`("legal-access"), `service`("identity-svc"), `ts`(KST 오프셋 ISO), `event`(LOGIN·LOGOUT·REAUTH·REFRESH), `result`(SUCCESS·FAILED), `provider`(kakao·naver·google), `factors`(password·totp·passkey, 팬은 소셜 제공자와 재인증 강도 `strength`), `failure`(password·totp·passkey·locked·session), `act`(관리 재인증 작업 묶음), `client_ip`, `user_agent`, `request_id`, `account_id`, `pod`, `seq`(파드마다 1부터 증가, 빈 값 금지).
- **법정 갈래 필터**: 게이트웨이 파일은 `kind="envoy-access"` 줄만, identity 파일은 `kind="legal-access"` 줄만 남긴다. 변환에서 법정 칸만 남기고 조사 칸을 지운다. 법정 사본에는 표본 처리기를 두지 않는다.
- **일반 갈래**: 같은 접근 로그 줄에서 조사 칸을 지우고 `client_ip`를 IP 앞부분(IPv4 /24, IPv6 /48)으로 바꾼다. 5xx·SLO 초과는 전수, 그 밖은 앱 로그와 같은 문턱(온세일 1%·평시 10%)으로 고른다 [가정]. 일반 갈래는 게이트웨이 수집기를 거쳐 Loki로 간다. 수집기에서 5xx·SLO 초과를 가르는 정확한 문턱은 이 기능에서 정하지 않고, 표본 처리기 설정과 정적 검사(5xx 통과 필터가 표본기 앞에 있음)만 둔다.
- **조사 갈래 거르기**: 조사 경로는 asyncapi `InvestigationRequest.routeKind` 다섯(로비 입장·사전 검증·진입·입장 확정·추가 검증 제출)과 구매·양도 경로다. 경로를 `routeKind`로 바꾸는 표는 `access-log.yaml`의 변환 문장에 둔다. 거르는 자리는 파일 수신기 뒤, Kafka 내보내기 앞이다. 상태 조회·셔플 결과 파일처럼 조사 경로가 아닌 줄은 보내지 않는다. 원본 확인이 맞지 않은 요청의 위조 `ja4`·`asn`·`edge_bot_labels`는 게이트웨이가 지우므로 수집기에 빈 값으로 온다. 수집기는 빈 값을 지어내지 않는다.
- **법정 사본의 칸 지우기**: 법정 사본과 일반 사본 모두 `ja4`·`asn`·`edge_bot_labels`·`sub`·`pid`·`jny`를 지운다. 법정 사본은 POL-025가 요구하는 칸(일시, 원문 IP, 단말 정보, 요청 경로·상태, 요청 ID)만 남긴다. 일반 사본은 조사 칸을 지운 뒤 IP 앞부분만 남긴다.
- **큐·재시도**: 법정 ClickHouse 내보내기는 `sending_queue.storage`=법정 file_storage, `block_on_overflow: true`, `retry_on_failure.max_elapsed_time: 0`, 큐 크기는 노드 하나의 피크 접근 로그 30분 분량 [가정]. 조사 Kafka 내보내기는 `storage`=조사 file_storage(법정과 다른 경로), `block_on_overflow: false`, `max_elapsed_time: 10m`, `compression: zstd`, `encoding: raw_json` [가정]. 같은 묶음이 다시 들어간 중복은 ClickHouse 복제 표의 같은 묶음 거르기가 받고, 남은 중복은 잃는 것보다 낫다.
- **건수 대조**: 5분마다 15분 전 5분 칸을 본다. 원천 요청 수는 게이트웨이별 Envoy 요청 수 지표, 적재 수는 `access_log`의 같은 칸 행 수다. 모자란 비율 = (원천 − 적재) ÷ 원천. 원천이 0이면 '확인할 수 없음'이고 통과가 아니다. 0.1%를 **넘으면** SEV2(`kind` legal, `access_log_shortfall_ratio{source}`). identity 줄은 `seq` 빈 번호가 하나라도 있으면 `access_log_seq_gaps_total` SEV2. 다음 날 03:30에 전날 하루를 같은 방법으로 대조해 원천 수·적재 수·빈 번호 수를 일 해시 앵커에 남긴다.
- **하루 사본**: 매일 04:00 [가정] 전날 파티션을 Parquet 파일 하나로 내보내 접속기록 사본 버킷에 둔다. 파일 이름은 `access_log/YYYY-MM-DD.parquet` [가정]. 행 수와 파일 SHA-256을 일 해시 앵커에 적는다. 버킷은 Object Lock 준수 모드, 저장소 암호화, 쓰기는 내보내기 역할만·읽기는 복원 역할만. 보존은 그 날짜의 3개월 보존이 끝난 뒤 7일 [가정]. 보존 기간 안의 삭제는 버킷이 거부해야 한다. 06:00까지 전날 사본 성공 표시(`access_log_export_last_success_timestamp`)가 없으면 SEV2.
- **표**: `access_log` 표 하나에 게이트웨이·identity 줄을 함께 넣되 `source`(gateway·identity)로 가른다. 칸은 §5에 적는다. `PARTITION BY toYYYYMMDD(ts)`(일 해시 앵커·3개월 보존과 맞춤, 약 92 파티션), `ORDER BY ts`, 원문 IP bloom filter 건너뛰기 색인, TTL 3개월 이상. 관리 계정 줄은 `is_admin`으로 표시하고 `al_admin_reader`의 행 정책이 그 줄만 보이게 한다.
- **권한**: `al_ingest`는 INSERT만, `al_admin_reader`는 관리 계정 줄 SELECT만(행 정책), `al_investigation`은 POL-025 수사 대응 SELECT만(개인 계정), `al_migrator`는 ALTER·DROP·TTL 변경만. 표를 지우거나 TTL을 3개월보다 줄이는 변경은 CI가 막는다. 사본 버킷 쓰기·읽기 역할은 나눈다.
- **끝 코드**: 도구는 `prom-rules.mjs`·`collector-config.mjs` 꼴로 0 통과, 1 위반(`막음: <파일>: <까닭>`), 2 인자 오류·읽을 파일 없음·정본 값 없음.
- **배포 무관**: 이 기능의 산출물은 저장소 파일과 로컬 시험뿐이다. `kubectl`·Helm·kind·Argo CD를 부르지 않는다. Docker는 로컬 시험에만 쓴다.
