## 계획

계획 담당 `l3-b416-plan`(claude-opus-5-5), 2026-11-18. 시험·제품 코드는 쓰지 않았다. 정본 빈칸은 없다(아래 1).

### 1. 정본: 좌석 델타 `changedAtMs`의 단위와 뜻

정본은 epoch 밀리초로 분명히 정해 두었다. 정본을 고칠 것은 없다.

| 정본 | 줄 | 내용 |
| --- | --- | --- |
| docs/data.md | 2638 (`s:{event:E}:sec:{section}` 행) | 메시지는 `1 {seatEpoch} {sectionIndex} {sectionVersion} {changedAtMs} {seatOffset}:{state} …`이고, "`changedAtMs`는 바꾼 Lua의 Redis `TIME`(epoch 밀리초)" |
| docs/adr/0110-latency-budgets-nfr002-nfr004-aligned-expiry-100ms-batches-ms-clock.md | 66~76 (결정 4) | 반영 지연을 밀리초 서버 시각으로 잰다. 홀드 Lua가 Pub/Sub 메시지에 변경 시각(Redis `TIME`, 밀리초)을 싣고, realtime-gw가 묶음 머리에 `u16 maxWaitMs`를 싣는다. 종단 지연 = 그린 시각 − (`serverTimeMs` − `maxWaitMs`) |
| docs/features/seat-hold.md | 399 (순서도), 430 (전파 지연 절) | `SPUBLISH(seatEpoch, seatIndex, state, sectionVersion++, changedAtMs)`. 시작점은 상태가 바뀐 시각(`changedAtMs`, Redis `TIME`) |
| docs/features/seat-hold.md | 541 (S-T12 행) | 종단 p99 300ms 이하(NFR-004)를 "홀드 Lua의 변경 시각, 묶음 대기 포함"부터 잰다 |
| docs/quality/quality-requirements.md | 79 (NFR-004) | 상태 변경(홀드 Lua 반영)부터 다른 화면에 그려질 때까지 p99 300ms 이하 |

뜻: 1970-01-01 UTC부터의 밀리초 정수(지금은 13자리, 10^12대). Redis `TIME`은 `{초, 마이크로초}` 두 글을 주므로 `초 × 1000 + floor(마이크로초 ÷ 1000)`이다. 반올림하지 않고 버린다(다른 Lua 여덟 파일과 같은 식). 글로 낼 때는 지수 표기·소수점 없이 정수 글이다(다른 Lua의 `int(x) = string.format('%.0f', x)`).

결함이 하는 일: 지금 `redis-seat-returns.ts`는 `redis.call('TIME')[1]`(초, 10자리)을 그대로 싣는다. realtime-gw는 그 값을 밀리초로 읽어 `serverTimeMs − changedAtMs`가 수십 년치가 되고, `u16 maxWaitMs`가 상한 65,535에 고정된다. 좌석 상태(비트맵·구역 번호)는 맞으므로 판매가 틀리지는 않지만, NFR-004의 SLI `seat_delta_e2e_ms`, realtime-gw 묶음 대기 경보(리뷰가 든 `realtime_gw_batch_wait_ms`), S-T12 측정이 취소표 델타가 섞일 때마다 오염된다.

### 4. 재현 시험(시험 담당, 구현 뒤에 쓰고 구현 전 트리에서 실패를 본다)

Lua라 Valkey 없이는 돌지 않는다. 재현되는 가장 낮은 단계는 **통합 시험(실제 Valkey)** 이다. 새 파일 `services/purchase-svc/test-int/seat-returns-time.int.test.ts`(또는 `cancellation.int.test.ts`의 `describe('Redis 취소표')` 옆). 구독은 `test-int/valkey.ts`의 `shardSubscriber`, 세대·비트맵은 기존 `cancellation.int.test.ts` 'Redis 취소표'처럼 직접 쓴다. 시험 이름 머리는 `WIR-01`로 단다. `S-T12`는 장부에서 '측정'(HOT-090·갈래 5)이라 이 시험 이름에 달지 않는다(달면 측정 항목을 단위 시험이 덮은 것처럼 읽힌다).

**고정 TIME 사본 만드는 법**: `RETURN_SOLD_LUA.split("redis.call('TIME')")`이 길이 2(TIME 읽기 정확히 한 번)인지 먼저 단언하고, `RETURN_SOLD_LUA.replace("redis.call('TIME')", "({'<초>', '<마이크로초>'})")`로 사본을 만들어 `redis.evalScript(redisScript(사본), keys, args)`로 부른다. **괄호를 꼭 친다**: 고치기 전 코드 `redis.call('TIME')[1]`에서 괄호 없이 `{…}[1]`로 바꾸면 Lua 5.1 문법 오류라 '실행조차 안 되는 실패'가 되고, 괄호를 치면 고치기 전 트리에서 값 단언으로 실패한다.

| 번호 | 시험 이름(제안) | 단언(정확한 값, 메시지 글 전체를 `toBe`로) | 잡는 틀린 구현 |
| --- | --- | --- | --- |
| T1 | `WIR-01 ① TIME을 {1700000000, 999999}로 고정하면 델타의 변경 시각은 1700000000999다(마이크로초 몫을 버린다)` | 메시지 = `1 {epoch} 0 1 1700000000999 3:0` | 초 그대로(원래 결함), ×1000 빠짐, 마이크로초 무시, 1e6 나눔, 반올림·올림, floor 빠짐 |
| T2 | `WIR-01 ② 마이크로초 경계: 0 → …000, 999 → …000, 1000 → …001, 500000 → …500` (표 하나로 네 값) | `{1700000000,'0'}`→`1700000000000`, `'999'`→`1700000000000`, `'1000'`→`1700000000001`, `'500000'`→`1700000000500` | 올림(999 → 1), 0을 채우지 않은 글 이어 붙이기(`t[1]..floor(t[2]/1000)`이면 1000 → `17000000001`), 마이크로초 그대로 더함 |
| T3 | `WIR-01 ③ 초가 2^31을 넘어도(TIME {2147483648, 123456}) 지수·소수 표기 없이 2147483648123이다` | 메시지의 다섯째 칸 = `2147483648123`, `/^\d{13}$/` | 정수 글 아닌 `tostring`·`%d`(32비트) 출력, 소수점 남김 |
| T4 | `WIR-01 ④ 한 번에 두 구역을 되돌리면 두 메시지의 변경 시각이 같은 1700000000999다` | 구역 0·1 메시지 둘, 둘 다 다섯째 칸 `1700000000999`, 다른 칸(세대·구역·구역 번호·`off:0`) 정확히 | TIME을 구역마다 읽기(사본 단언의 split 길이), 칸 차례 바뀜 |
| T5 | `WIR-01 ⑤ 실제 TIME: 변경 시각은 호출 앞뒤 Valkey TIME(ms)의 사이이고 10^12 이상 10^13 미만이다` | 앞뒤로 `TIME` 명령을 불러 `초*1000+floor(µs/1000)`을 계산, `before ≤ changedAtMs ≤ after`, `1e12 ≤ v < 1e13`. 앱 시계(`Date.now()`)는 쓰지 않는다(Docker VM 시계 차, pin-failed-mark.int.test.ts 8줄과 같은 까닭) | 초 그대로(10^9대), 마이크로초 그대로(10^15대) |
| T6 | 기존 `GAT080_취소는_티켓키폐기·…` (cancellation.int.test.ts 374줄) 단언을 `/^1 \d+ 0 1 \d+ 3:0$/`에서 다섯째 칸이 T5처럼 앞뒤 TIME 사이인지로 좁힌다 | 부르는 쪽(취소 Saga → `DrizzleSeatReturns` → `RedisSeatReturnNotices`) 바깥 경계에서 ms인지 | 이 결함을 숨긴 기존 `\d+` 단언(자주 놓친 결함 '정확한 값까지') |

모든 고정 사본 시험에서 비트맵 비트 0, `secver` 증가, `NOT_READY`가 아닌 `OK`도 함께 본다(고정 사본이 다른 경로로 새지 않게).

**실패 확인 트리**: 기준 `5ec2d8b0`에는 `RETURN_SOLD_LUA` export가 없어 T1~T4는 가져오기부터 실패한다(세지 않는 실패). 그래서 실패 확인은 '구현 커밋에서 Lua 고침(①②)만 되돌리고 export(③)는 남긴 트리'에서 본다(커밋하지 않는 임시 트리). T5·T6은 `5ec2d8b0` 그대로에서 실패를 본다.

**단위 시험**: 새 동작을 Valkey 없이 재현할 수 없어 두지 않는다(Lua 글을 정규식으로 보는 시험은 구현 모양만 보고 값을 보지 않아 쓰지 않는다). 단위 시험이 없는 까닭은 이 절이 적은 것으로 갈음한다.

복구 경로의 장애 주입: 이 고침은 복구 경로(세대 키 없음 `NOT_READY`, 다시 만들기)를 바꾸지 않는다. 기존 `GAT080_세대키가_없으면_NOT_READY이고_비트맵을_건드리지_않는다`가 그대로 통과하는지만 본다(해당 없음의 까닭). 규칙 모델(specs/)에는 변경 시각이 없어 모델 검사도 해당 없음.

### 7. 자주 놓친 결함을 이 묶음에 대 본 것(§8.6 '자주 놓친 결함')
