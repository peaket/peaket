## 1. 범위와 선행 확인

**선행 확인**: 소비자 웹에는 아직 전체 화면 i18n 런타임(i18next)과 로케일 접두 라우트가 없었다. WBS 7.5.1의 이 묶음 코드 몫은 **구매 조건 알림 문구와 번역 검토 표시(0.25일)**이고, 나머지는 접근성·브라우저·실기 수동 확인이다(wbs.md 731·852행). 그래서 전체 화면 번역을 억지로 넣지 않고, 그 0.25일 몫을 실제로 동작하는 카탈로그·알림·검사기로 만들었다.

**한 것**:
1. **구매 조건 알림 4언어**(NFR-024, POL-001): `apps/web/src/shared/i18n/messages/{ko,en,ja,zh}.json`에 `identity.domesticPhoneRequired`를 두고, en·ja·zh 로그인 화면과 공연 상세의 구매 버튼 가까이에 한 줄로 보인다. 한국어 화면에는 보이지 않는다.
2. **번역 검토 표시**: 문구마다 `review: machine | native`를 둔다. ko는 `native`, en·ja·zh는 원어민 검토 전이라 `machine`이다.
3. **번역 키 검사기**: `tools/ci/i18n-check.mjs`가 네 로케일 키 목록·빈 문구·review 값·`{자리}` 일치를 검사한다. 루트 `i18n:check` 스크립트를 더했다.
4. **로케일 접두 경로**: `/en/login`·`/ja/login`·`/zh/login`과 `/en/events/{id}`·`/ja/events/{id}`·`/zh/events/{id}`가 같은 화면을 로케일만 달리 그린다. `hreflang` 대안 주소와 로그인 언어 링크의 현재 로케일 표시를 더했다. 한국어는 접두가 없다(ADR-0060 결정 3).
5. **접근성 수동 시나리오 3종**: `docs/review/manual-a11y/LCH-190.md`에 NVDA·VoiceOver·TalkBack × 좌석 선택·결제·양도 × 3회 확인 목록과 접근성 이름 3종(아이콘 버튼·링크·입력 칸)을 만들었다. 사람 확인은 소유자 몫이다.

**막힌 몫(후속·다른 단계로 적음)**:
- **전체 화면 문구의 i18next 연결**: 이번 코드 몫은 구매 조건 알림 한 키다. 전체 화면 번역·네임스페이스·동적 import는 다국어 단계에서 이 카탈로그 모양을 그대로 쓴다.
- **사람 확인**: NVDA·TalkBack은 소유자, VoiceOver는 기기를 구할 때까지 미실행(ADR-0237).
- **브라우저 수동 3종·콘솔 휴대폰·태블릿 실기**: WBS 7.5.1에 있지만 BUILD_ORDER LCH-190 범위 밖이라 소유자 실기 목록으로 남긴다.
- **번역 원어민 검토**: en·ja·zh는 `machine` 표시를 유지한다. 출시 전 점검 목록에 남긴다.
