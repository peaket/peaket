## 1. 범위와 막힌 몫

**한 것(코드 몫)**:
1. **SCR-058 인앱 브라우저 감지·연결**(HOT-380): 알려진 인앱 브라우저(KakaoTalk·Instagram·Facebook·Naver·Line·Band·TikTok·X)를 User-Agent로 알아보고, 대기실 [로비 입장]과 마이 티켓의 입장용 등록 직전에 `/open-in-browser?next=` 안내를 먼저 거친다. `next`는 기존 `safeNext()`로 검사해 열린 이동을 막는다.
2. **FE-T31 재배치·확대·글자 간격 시험 틀**(HOT-380): 320×256(400% 확대)·640×400(200% 확대) 뷰포트, WCAG 1.4.12 글자 간격(1.5·2·0.12·0.16배), 표·좌석맵·에디터·그래프 예외, ko·en 두 로케일의 소비자 웹·파트너·관제 대표 흐름을 도는 Playwright 설정·시험을 더했다. **브라우저 확인은 heavy gate에서 돌린다.**
3. **standalone·배포 식별자**(HOT-390): `apps/web/next.config.ts`에 `output: 'standalone'`과 `deploymentId`를 넣었다. 값은 `PEAKET_DEPLOYMENT_ID` 또는 `GITHUB_SHA`이고, 기존 `server/start.mjs`가 `.next/standalone/apps/web/server.js`를 안쪽 포트에 띄운다.
4. **정적 자산 30일·최근 5빌드 보존 계산**(HOT-390): `tools/web-checks/static/retention.mjs`가 빌드 목록에서 남길 빌드·파일과 지울 파일을 고른다. 해시 파일을 여러 빌드가 함께 쓰면 남긴다.
5. **제3자 고지 업로드 예외**(HOT-390/BAS-180): 정적 업로드 목록이 앱마다 `THIRD-PARTY-NOTICES.txt`를 `.txt`여도 싣고, 같은 이름이 아닌 `.txt`는 계속 뺀다.

**막힌 몫(후속·다른 단계로 적음)**:
- **지갑 PWA 서비스 워커 갱신 보류**: 월렛 서비스 워커 자체가 아직 없다(Serwist PoC wbs 5.1.4). SW의 `waiting`·QR 표시 중 활성화 보류·킬 스위치 시험은 그 PoC 뒤에 본다.
- **MF 원격 목록**: `remotes.json`의 sha384·계약 주판 검사는 `@peaket/console-contract`가 OPS-350으로 넘겼다. 관제 호스트의 실제 Module Federation 적재도 OPS-350이다.
- **공유 캐시 처리기**: Next.js `cacheHandlers`의 Redis 처리기는 Redis 런타임·배포 설정과 함께 봐야 한다. 이 묶음은 `standalone` 산출물과 배포 식별자까지다.
- **S3 수명 주기·CloudFront 헤더**: 30일 보존 계산은 했지만 실제 S3 수명 주기·`nosniff`·서비스 워커 범위 헤더는 배포 단계(HOT-450) 몫이다.
- **SCR-017·018**: `/my/settings`와 대기실 매진 화면은 이미 구현되어 있어 새로 만들지 않았다.
