## 계획

### 1. 범위

- **P1 묶음 실행기(Kafka 없이)**: 파티션별 묶음 닫기, 중복 거르기 표시, 다시 시도 지연, 파티션마다 1개·작업자 전체 한도, 커밋 위치, 거절 위치 모으기, 지표(§2.4·§2.7).
- **P2 Kafka 잇기**: 자동 커밋 끔, 쓰기 뒤 파티션별 커밋, 다시 시도 동안 그 파티션 멈춤, 한도 초과 때 모든 파티션 멈춤, 재조정·종료 때 처리 중 묶음 마치기(§2.4 :87). 클라이언트 필수 설정은 기존 함수로(docs/devops.md:557).
- **P3 Avro 읽기**: 쓴 쪽 스키마로 풀어 레코드 이름으로 나누기, 모르는 열거 기호를 `UNRECOGNIZED`로 바꾸고 세기(원본 적재용으로 원래 기호를 남기는 선택), 거절 분류 셋, 처음 보는 ID의 레지스트리 장애는 다시 시도(§2.6 :131·:132).
- **P4 작업자 배포 값**: `peaket-service` 차트의 작업자 모드. 앱 포트·Service·라우트를 만들지 않고, 들어오는 연결은 관측 네임스페이스에서 관리(지표·상태) 포트로만, Restricted·읽기 전용 루트·서비스 계정 토큰 안 붙임은 기존 도우미 그대로(§2.3 :60·:62). 작업자마다의 값 파일(`deploy/workloads/ops-rt` 등)은 작업자 묶음 몫이다.

### 3. 바른 동작과 근거(값은 정본에서 읽는다)

- **쓰기 뒤 커밋**: 자동 커밋 끔, 쓰기 성공 뒤 파티션마다 '끝 + 1', 다시 뜨면 커밋 위치부터(streaming :77·:83, §2.4 끝 줄).
- **묶음·표시·다시 시도·동시 묶음·거절과 함께 쓰기·재조정 기다림**: 한도는 표 :78~:81(작업자가 옵션으로 넘긴다), 나머지는 :84(이 커밋). 재조정·종료는 :87.
- **읽지 못한 레코드**: 위치만, 데드 레터 토픽 없음(:86). 분류 셋은 :478 `error_class`와 :156 `reason`(이 커밋).
- **레지스트리**: 캐시, 처음 보는 ID 실패는 멈춤·다시 시도, 404만 거절, 조회 한도·실패 캐시 안 함(:131, 끝 문장은 이 커밋).
- **모르는 열거 기호**: `UNRECOGNIZED`로 바꿔 넘기고 세며 버리지 않는다. 원본 적재는 원래 기호(:132, avro README:69).
- **지표·`client.id`**: :156의 여섯, :134.
- **배포 값**: 관리 API 없음(:46), Restricted·읽기 전용 루트(:60), 네트워크 정책 표(:62~:70), ASVS v5.0.0-13.4.5(asvs/analytics.md:195).

// packages/platform/src/batch-consumer.ts (본 이름공간 @peaket/platform)
export type RejectReason = 'DESERIALIZE' | 'UNKNOWN_SCHEMA' | 'MISSING_FIELD';
export interface BatchRecord<T> { topic: string; partition: number; offset: string; timestamp: string; value: T }
export interface RejectedPosition { topic: string; partition: number; offset: string; kafkaTs: string; schemaId: number | null; reason: RejectReason }
export interface ClosedBatch<T> {
  topic: string; partition: number;
  firstOffset: string; lastOffset: string;   // 거절 레코드 포함
  dedupToken: string;                        // dedupToken(topic, partition, firstOffset, lastOffset)
  records: BatchRecord<T>[]; rejected: RejectedPosition[];
}
/** 던지면 같은 묶음을 다시 보낸다. table은 stream_insert_seconds 라벨 */
export interface BatchSink<T> { table: string; write(batch: ClosedBatch<T>): Promise<void> }
export function dedupToken(topic: string, partition: number, firstOffset: string, lastOffset: string): string;
export function retryDelayMs(attempt: number): number;
export const BATCH_WORKER_DEFAULTS: { readonly maxInFlight: number; readonly drainTimeoutMs: number };
/** 파티션 하나의 묶음 상태(가짜 시계). 닫히면 돌려준다 */
export class BatchPartition<T> {
  constructor(o: { topic: string; partition: number; maxRecords: number; maxWaitMs: number; now?: () => number });
  push(item: BatchRecord<T> | RejectedPosition): ClosedBatch<T> | undefined;
  poll(): ClosedBatch<T> | undefined;
  static commitOffset(b: Pick<ClosedBatch<unknown>, 'lastOffset'>): string;
}
export class BatchWorkerMetrics { static for(registry: Registry, worker: string): BatchWorkerMetrics }

### 7. 차례(구현 담당)

1. `batch-consumer.ts`: `BatchPartition`·`dedupToken`·`retryDelayMs`·지표. 가짜 시계로 돌게.
2. `avro-reader.ts`: 포트·헤더(매직 바이트·스키마 ID) 대조·열거 바꾸기·거절 분류. 시험 담당이 가짜 `SchemaSource`로 단위 시험을 쓸 수 있게 한다.
3. `stream-worker.ts` `runBatchWorker`: 기존 `runKeyedConsumer`(:203)의 멈춤·재조정 다루기를 본뜬다.
4. `avsc` 5.7.9를 넣고(§4의 확인 기록) `schema-registry-source.ts`와 `createAvroReader`의 실제 풀기를 잇는다. `corepack pnpm install --frozen-lockfile`이 통과해야 한다.
5. 차트 `worker.enabled`.
6. 플랫폼 build, 쓰는 서비스 typecheck, `pnpm lint`. §5와 다른 이름만 '구현 메모' 절에 적는다.

### 10. 시험·구현 지시문에 넣을 '자주 놓친 결함'(docs/architecture.md:1166~1180에서 고름)

- 정확한 값까지 단언한다(커밋 오프셋, 표시 글, 지연 목록, 지표 값).
- 경계값은 양쪽(건수 한도 − 1과 한도, 시간 한도 − 1ms와 한도, 레지스트리 조회 한도, 0건·모두 거절 묶음).

- 허용·거부 목록은 목록 밖 값마다 본다: 거절은 404 하나뿐, 나머지 응답 각각이 다시 시도.
- 장애 주입은 끊는 자리가 쓰기 뒤·커밋 전까지 닿는지, 끊긴 사례가 실제로 있었는지 단언한다.
- 부르는 쪽(`runBatchWorker`)이 실제로 멈추고 커밋하는지 바깥 경계에서 보고, 싱크가 받은 건수를 단언해 0건이 통과로 새지 않게 한다.

### 구현 의심점(시험 실패, 구현 담당 몫)

- **ST-T16 ① 위반: 레지스트리에 닿지 못한 처음 보는 ID를 실행기가 거절하고 커밋한다.** `runBatchWorker`는 `decode`가 던진 오류를 `isTransientError`로 갈라 거짓이면 `DESERIALIZE`로 거절한다(`packages/platform/src/stream-worker.ts:797`·`:803`). 그런데 `isTransientError`(`packages/platform/src/keyed-consumer.ts:107`)는 `instanceof TransientError`를 보지 않고 이름 목록(`:103` `TransientError`·`TimeoutError`·`AbortError`)·코드·글·원인만 본다. `SchemaUnavailableError`는 이름을 `'SchemaUnavailableError'`로 바꾸고(`avro-reader.ts:19`) 레지스트리 조회는 원인 없이 던져서(`schema-registry-source.ts:124`·`:132`) 일시 실패로 보이지 않는다. 그래서 레지스트리가 닫히면 그 파티션을 멈추지 않고 모두 `DESERIALIZE`로 거절·커밋해, 되살려도 그 레코드를 다시 읽지 않는다(정본 docs/streaming.md §2.4 '읽지 못한 레코드' 줄·§2.6 역직렬화 줄의 '거절하지 않으므로 빠지는 레코드가 없고'). 실패 시험: `avro-reader.test.ts` 'ST-T16 ① 레지스트리 장애 오류는 실행기가 일시 실패로 보는 오류다', `batch-worker.int.test.ts` 'ST-T16 ① 레지스트리가 닫힌 채…'(싱크가 레코드 0·거절 셋인 쓰기를 네 번 받았다). 구현 메모 '일시 실패(`isTransientError`, `SchemaUnavailableError` 포함)만 파티션을 멈춘다'와도 다르다.
- 참고(결함 아님): 작업자 모드 기본 렌더에 PodDisruptionBudget이 없다(정본 §2.2 'PodDisruptionBudget은 1'). 작업자마다의 값 파일 몫(§1 P4·§12)이라 이 묶음 시험에 넣지 않았다.

- **정한 작은 동작**: 운영에 보이는 둘은 정본에 먼저 적었다(docs/streaming.md §2.3 '배포 값'과 §2.4 '실행기 세부', 모두 '추천 적용, 2026-11-22, BAT-220 구현'. 두 줄이 늘어 §2.4 :84 뒤의 줄 번호가 1~2씩 밀렸다). 나머지는 코드 주석과 아래에만:

  - `recordName`은 쓴 쪽 레코드의 전체 이름(`peaket.telemetry.PipelinePulse`)이다. `stream_unrecognized_symbol_total`은 실행기가 `DecodeOutcome.unrecognized`로 센다(`onUnrecognized`는 따로 부르는 고리). 빌드된 계약 판에 그 레코드 이름이 없으면 필수 필드 검사 없이 넘기고, 열거는 이름으로 찾아 본다. `MISSING_FIELD`는 빌드된 판에서 기본값 없는 필드가 쓴 쪽 레코드(이름·별칭)에 없을 때다.
  - 읽기 쪽도 풀어 둔 쓴 쪽 형을 ID마다 캐시(1,000개)하고 같은 ID 동시 조회를 하나로 묶는다. 그래서 원천이 닫혀도 읽은 ID는 풀린다. 조회 원천이 `UnknownSchemaError`·`SchemaUnavailableError` 밖의 예외를 던지면 `SchemaUnavailableError`로 감싼다. 받은 스키마가 avsc로 읽히지 않으면 `SchemaUnavailableError`.
  - 레지스트리 응답: 200이고 `{ schema: <글> }`, `schemaType`이 없거나 `AVRO`, `references`가 비어야 받는다. 그 밖의 상태(3xx 포함)·모양은 `SchemaUnavailableError`. 오류 글에는 스키마 ID와 상태 코드, 연결 실패면 원인 코드(`ECONNREFUSED` 등)만 넣는다(주소·자격 없음). 주소에 사용자 정보·쿼리·조각이 있거나, local·ci 밖(모르는 환경 값 포함)에서 https가 아니거나, Basic 사용자 이름에 `:`가 있으면 `PlatformConfigError`. `byId`에 1~`MAX_SCHEMA_ID` 밖 ID는 `RangeError`(읽기 쪽이 먼저 거른다).
  - 실행기: `eachBatch`(`eachBatchAutoResolve: false`, 받은 레코드만 표시)로 높은 물표를 받아 소비 밀림을 고친다. 닫힌 묶음은 파티션마다 쓰기 하나, 쓰는 중에 또 닫히면 그 파티션을 멈춘다. 거절 위치의 `stream_rejected_total`·위치 로그(`kind: 'stream-rejected'`, 원문 없음)는 그 묶음 쓰기가 성공한 뒤에 남긴다. 재조정·종료 때 열린(닫히지 않은) 묶음은 버리고(커밋하지 않아 다시 받는다) 닫힌 묶음만 한도 안에서 기다린다. 잃은 배정이면 커밋하지 않는다.
  - 남는 위험: 싱크 `write`가 끝나지 않으면 넘기기 한도 뒤에도 동시 묶음 한 칸을 계속 쥔다. 싱크가 자기 시간 한도를 가져야 한다(작업자 묶음 BAT-221 몫).
