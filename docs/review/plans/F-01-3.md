## 감독에게

막는 물음은 1 하나다. 나머지는 추천대로 계획을 세웠다. 다르게 정하면 이 계획과 그 정본 줄을 고친다.

1. **[결정 요청] F-01-3을 둘로 나눈다.** 이 행은 OPS-060(수집기 2단)만 남겼다. OPS-070을 맡을 새 행(이름 제안 F-01-8, 갈래 1, B, 3.00일, 선행 F-01-3)을 더해 달라. 제안하는 장부 범위는 V-T21, V-T22, V-T23, V-T30 ④, Q-T61, delivery:v5.0.0-16.3.1, delivery:v5.0.0-16.3.2, delivery:v5.0.0-16.3.3, delivery:v5.0.0-16.4.3이다. 완료 정의는 "접근 로그 두 갈래와 identity 접속기록 줄이 법정 접속기록 DB에 잃지 않고 들어가 건수 대조를 통과한다"다. 그 행에서 함께 정할 것은 다음과 같다.
   - (가) **(추천) Q-T61(조사 사본 갈래)은 그 새 행에서 동결한다.** Q-T61이 쓰는 `investigation.requests`는 조사 적재 `inv-ingest`(LCH-240, F-04-10)만 읽는데, F-04-10은 ADR-0373 결정 2로 동결됐다. ADR-0373 결정 2의 "동결한 기능의 몫을 넘겨받은 몫도 동결"과 같은 뜻으로 본다. 동결하면 OPS-070은 약 2.25일 [가정]이다. (나) 그대로 하면 로컬 Kafka와 앞단 흉내까지 띄워 3일을 꽉 채운다.
   - V-T22의 노드 비우기 실행과 V-T23 가운데 kind에서만 되는 몫은 INF-040으로 간다. 에이전트 재시작(V-T22 앞 실행)과 V-T21은 Docker로 된다.
   - 단계 줄 OPS-060은 이 기능의 기록 커밋에서 체크하고, OPS-070은 새 행이 끝날 때 체크한다.
2. **[알림] 배포 몫은 INF-020으로 넘긴다**(ADR-0331 결정 9, ADR-0373 결정 1). INF-020 ④가 이미 'OTel 수집기 셋'을 갖고 있다. 기록 커밋에서 그 줄 끝에 넘긴 것을 적어 달라: 이 기능의 설정 파일로 만드는 DaemonSet·Deployment(게이트웨이 복제 3, 클러스터 복제 2)·헤드리스 Service(부하 분산 해석기가 찾는 이름)·쿠버네티스 메타데이터·이벤트·리더 임대 권한·NetworkPolicy, Prometheus가 수집기 셋의 `:8888`을 긁는 설정, 수집기 이미지 서명 확인(ADR-0054). INF-040 줄에는 V-T30 ③(ledger-notes, 이 커밋)을 적어 달라. 수집기 자체 신호 SEV3 규칙(observability.md:445~451)은 F-01-5(OPS-100), 수집기 패널은 F-01-4(OPS-080) 비고에 한 줄씩 더해 달라.
3. **[알림] 생성 파일 자리가 하나 는다.** `deploy/platform/observability/collector/generated/`(꼬리 표본 정책·2차 마스킹 문장)는 `node tools/ci/collector-config.mjs --write`로만 고친다. 생성 파일 편집을 막는 훅 규칙(`tools/claude-hooks/edit-rules.mjs`)은 구현 담당이 같은 구현 커밋에서 이 폴더를 더한다. CLAUDE.md '절대 규칙'의 생성 파일 목록에 한 줄을 더할지는 소유자·감독이 정한다(에이전트는 CLAUDE.md를 고치지 않는다).
4. **[알림] F-01-2가 넘긴 조건(TR012-2·5)을 이 기능이 닫는다.** 2차 마스킹 꼴의 원천을 `packages/platform/src/pii-patterns.json` 하나로 두고, 오류 수집 가림과 수집기가 같은 원천을 읽는다. 표시는 `[REDACTED]` 그대로다. 글 속 계좌 꼴은 숫자 ID와 겹쳐 두지 않고, 예금주 조회 경로의 계좌번호 꼴만 더한다(observability.md:514). 이 기능을 합친 뒤 F-08-15 비고의 넘김 조건 문장을 '정규식 원천과 표시는 F-01-3에서 맞춤'으로 바꿔 달라(기록 커밋에서 감독 몫).

### 3. 바른 동작과 근거(값은 정본에서 읽는다)

- **설정 원천과 겹쳐 읽기**: observability.md:108. 게이트웨이는 `gateway.yaml` → `generated/tail-sampling.yaml` → `generated/pii-masking.yaml` → (로컬만) `local/gateway.yaml` 차례로, 에이전트는 `agent.yaml` → (로컬만) `local/agent.yaml` 차례로 `--config`를 준다. 겹쳐 읽을 때 목록은 통째로 바뀌므로, 로컬 판은 파이프라인의 처리기·내보내기 목록을 통째로 다시 적는다.
- **에이전트**: :109. 추적은 OTLP(노드 안) → 메모리 상한 → 쿠버네티스 메타데이터 → 묶기 → 부하 분산(`routing_key: traceID`). 로그는 컨테이너 표준 출력(filelog, `container` 해석) → 메모리 상한 → 쿠버네티스 메타데이터 → 묶기 → 게이트웨이(OTLP). 접근 로그 두 갈래와 조사 사본은 OPS-070이라 넣지 않는다(:113). 로컬 판: 쿠버네티스 메타데이터를 빼고, 부하 분산은 고정 주소 목록(Docker 네트워크 별칭 `peaket-gw-0:4317`·`peaket-gw-1:4317`), 로그 내보내기는 `peaket-gw-0:4317`.
- **게이트웨이 수집기**: :110. 정책 다섯과 그 차례, 크기 값, 메모리 상한 비율. 드문 경로는 openapi에서 `x-peaket-trace-rare: true`를 단 작업의 경로를 그대로 쓴다(서버 span의 `http.route`는 `routeLabel`이 `{param}` 꼴로 단다, metrics.ts:101). 같은 경로에 드물지 않은 메서드가 있을 수 있으므로 경로마다 하위 정책은 `and`(`http.route` 같음 + HTTP 메서드 같음 + `rate_limiting`)다. 메서드 속성 이름은 지금 서버 span이 싣는 이름을 쓴다(시험 담당이 `telemetry.test.ts` 꼴로 확인해 '시험 결과'에 적는다). 처리기 차례는 메모리 상한 → 꼬리 표본 → 2차 마스킹 → 묶기다(추적). 로그는 메모리 상한 → 2차 마스킹 → 묶기다. 운영 판의 내보내기는 Tempo(관측 전용 Kafka 경유, observability.md §1 '관측 저장소 쓰기 경로')와 Loki이고, 로컬 판은 파일(`/var/lib/otelcol/out/traces.json`·`logs.json`, JSON 줄)이다.
- **클러스터 수집기**: :112. `k8sobjects`(이벤트 감시) → 묶기 → Loki, 리더 선출 확장에 묶음. 쿠버네티스가 없으면 뜨지 않으므로 로컬 판은 없고 정적 검사만 한다.
- **자체 감시**: :111과 §5 :445~451. 셋 모두 `service.telemetry.metrics`가 `0.0.0.0:8888` Prometheus 형식. SEV3 규칙 자체는 F-01-5(감독에게 2).
- **2차 마스킹**: :514. 꼴 다섯(이메일·카드·국제 전화·국내 휴대폰은 :513의 범위 그대로, 예금주 조회 경로의 계좌번호 마디), 표시 `[REDACTED]`, 거는 곳(로그 본문·로그 속성·span 속성·자원 속성의 글 값), IP 속성 셋의 처리(앞부분 꼴 `a.b.c.0/24`·`h:h:h::/48`은 그대로, IPv4는 앞부분으로, 그 밖은 `[REDACTED]`, `ipPrefix` 꼴과 같게, pseudonym.ts:84). RE2는 앞뒤 살피기가 없으므로 지금 `pii-text.ts`의 `(?<!\d)`·`(?!\d)` 경계는 잡은 묶음(`(^|[^0-9])` … `$1`)으로 바꾼다. 이때 한 글자로 붙은 두 값(예: `a@b.kr,c@d.kr`, `01011112222/01033334444`)을 모두 가려야 한다. 한 번 걸어 놓치는 자리가 생기면 같은 문장을 두 번 거는 식으로 맞춘다(방법은 구현 몫, 결과는 시험이 본다).
- **SLO 지연 초과 표시**: :110 ③. 응답을 보내기 직전(`onSend`, 서버 span이 아직 열려 있다)에 요청 시작부터 지난 시간이 그 경로의 SLO 지연(`@LogPolicy`의 `sloLatencyMs`, 없으면 서비스 기본값, request-log.ts:205)을 넘으면 `peaket.slo.exceeded: true`. 넘지 않으면 속성을 달지 않는다. 정규 로그 줄의 지연 초과(onResponse의 `durationMs`)와 경계에서 조금 어긋날 수 있지만, trace를 남긴 요청이 로그 줄을 갖는 쪽(V-T30 ②)은 늘 맞는다.
- **크기 측정**: ADR-0125 결정 2(식·남길 결과)와 V-T30 ①(verification.md:657). 앞 부하(진입을 뺀 몫)는 판정 전 버림 0·오류 trace 100% 남김·메모리가 식 안, 뒤 부하(진입을 넣은 몫)는 버림이 생기는지 기록. PC가 뒤 부하의 속도를 내지 못하면 도달한 속도를 그대로 적는다(통과로 꾸미지 않는다). 결과는 성능 장부(docs/perf-ledger.md §2의 측정 1회 산출물과 §5 요약 행)에 남기고, §1(:110)·§6(:491)의 [가정] 값을 잰 값으로 바꾼다.

### 9. 자주 놓친 결함(docs/architecture.md §8.6 4의 목록에서 고름, 시험·구현 지시문에 넣는다)

- 허용·거부 목록은 목록 밖 값마다 본다: 정책 다섯을 하나씩 빼 보고, 버려야 할 trace 종류(드문 경로의 표시 없는 메서드 포함)를 따로 단언한다. 가림 꼴은 꼴마다, 붙은 두 값까지 본다.
- 빈 결과가 통과로 새지 않게 한다: 결과 파일 0줄, 남은 trace 0개, 드문 경로 0개, 받은 게이트웨이가 하나뿐이면 실패다.
- 판정 함수만 보지 말고 부르는 쪽을 본다: 정규식 함수만이 아니라 실제 수집기를 지난 바이트, 검사 함수만이 아니라 CLI 끝 코드, 표시 함수만이 아니라 서버 span.
- 시험 값은 코드 상수가 아니라 정본에서 적는다(`decision_wait`·`num_traces`, 자원 속성 다섯, 가림 표시).
- 개인정보는 분해한 칸이 아니라 결과 파일 원문 바이트 전체에서 찾는다.
- 같은 규칙을 두 곳에서 지키면 하나를 빼도 다른 쪽이 가린다: 서비스 템플릿의 1차 가림과 IP 앞부분이 이미 값을 지우므로, 수집기 시험은 서비스를 거치지 않고 원문 값을 수집기에 바로 넣는다(V-T49 ③).

- **클라우드·kind 없음(INF-020·INF-040)**: 수집기 셋의 쿠버네티스 배포와 권한, 헤드리스 Service로 찾는 부하 분산, 쿠버네티스 메타데이터·이벤트 수집·리더 선출이 실제로 도는지, Prometheus 긁기, Tempo·Loki로 내보내기, 관측 전용 Kafka의 MSK IAM(observability.md §1, open-items 42번), gw-queue의 머리 표본(V-T30 ③). 감독에게 2.

- **다른 기능**: 수집기 자체 신호 SEV3 규칙(F-01-5 OPS-100), 수집기 패널(F-01-4 OPS-080), 불변식 위반 trace 표시(감독에게 6), 브라우저 Sentry SDK(F-01-2가 넘긴 V-T39 ②, 미정).
