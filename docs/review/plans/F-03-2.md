# F-03-2 계획(OPS-350 관제 원격 위젯 계약·sha384 무결성·대체 카드·원격 빌드 워크플로, OPS-360 콘솔을 켜 둔 동안의 성능 상한)

- **무엇**: `docs/BUILD_ORDER.md` '기능 단위 계획' 표의 F-03-2 행(57행)과 단계 줄 `OPS-350 wbs 4.5.5 ①`(692행)·`OPS-360 wbs 4.5.5 ②`(693행)를 한 번에 끝내는 B 등급 수직 기능의 작업 목록이다(docs/architecture.md §8.6 4의 1·2, ADR-0270 '계획', ADR-0354). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다. 정본 값은 옮겨 적지 않고 자리만 가리킨다.
- **쉬운 말**: F-03-1이 관제 콘솔 호스트에 팀 위젯 원격 둘(대기열 팀·구매 팀이 따로 빌드한 화면 조각)을 이어 붙였지만, 지금은 빌드에 박은 주소 두 개를 그대로 믿고 싣는다. 이 기능은 두 가지를 한다. ① **믿을 수 있게 싣기**: 호스트가 원격 목록 파일(`remotes.json`)을 읽어 계약 판(호스트와 원격이 같은 약속을 쓰는지 나타내는 큰 판 번호)을 맞춰 보고, 파일의 지문(sha384 해시, 내용이 한 글자만 바뀌어도 달라지는 값)이 목록과 같을 때만 실행한다. 안 맞거나 5초 안에 안 오면 한 번 더 받고, 그래도 안 되면 그 칸만 '이 위젯만 불러오지 못했습니다' 카드로 바꾸고 실패 수를 센다. 원격은 팀마다 같은 공용 빌드 절차(워크플로)로 만든다. ② **켜 둔 동안 가볍게**: 하루 종일 켜 두는 화면이라, 보지 않는 위젯(고르지 않은 탭, 숨긴 브라우저 탭, 화면 밖)은 숫자를 받지 않거나 그리지 않고, 그래프는 점 수에 상한을 두며, 첫 화면에는 다른 화면 코드를 싣지 않는다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane2-F-03-2`, 가지 `feature/lane2-F-03-2`, 출발 `feature/lane2-F-03-1` 머리 `677ffd0f3`(F-03-1 구현 커밋, 아직 develop에 없음, 2026-11-23). 계획 담당 `lane2-f032-plan`(claude-opus-5-5). 제품·시험 코드는 쓰지 않았다. 현재 상태를 보려고 관제 운영 빌드를 한 번 돌려 덩어리 크기만 쟀다(아래 2). Docker·브라우저는 쓰지 않았다. 지시서는 `node tools/ci/brief.mjs --batch F-03-2 --out <작업 폴더 밖>`로 뽑는다(이 계획 커밋 뒤 7항목).
- **등급·차례**: B. **정방향**(`Batch-Order: impl-first`, ADR-0281 결정 5)이고 B 짧은 고리다(ADR-0283 결정 2). 차례: 계획 → 구현(정본 빈칸·ADR 포함) → 시험 → 리뷰 → 검증(틀린 구현 표본 10개) → 기록. 판단: §8.6은 2026-11-16부터 정방향이 기본이고 B 기능은 구현 전 트리 실패 확인 없이 틀린 구현 표본으로 실패를 본다(ADR-0331 결정 2·3). 이 기능은 원격 한 파일 빌드·미리 받기 무결성처럼 PoC 결과에 따라 공개 인터페이스(목록 형식, 적재기 함수 모양)가 정해지는 몫이 있어, 시험 먼저로 하면 시험이 두 번 쓰인다.
- **한 줄 결론**: 계약 패키지에는 판 확인 함수 둘만 있고 `remotes.json`·무결성·시간 초과·다시 받기·실패 수·공용 빌드 워크플로가 없다. 원격 빌드는 한 원격이 파일 다섯 개로 나와 진입 파일 하나의 sha384로는 다 덮지 못한다. 위젯 흐름은 1초 묶기만 있고 10초 유예·숨긴 탭 30초·접기·화면 밖·탭 제목 수가 없다. 대시보드 덩어리가 84.1kB(gzip)로 화면 덩어리 예산 80KB [가정]를 이미 넘는다. 새 패키지 의존성 없이 Node 내장(`node:crypto` sha384, `node:zlib`)과 webpack 내장으로 다 되는 길을 추천한다. ops-svc는 고치지 않는다. 크기는 **4.5일 [가정]**(5일 상한 안, '감독에게' 7).

PoC(아래 6-2)가 실패할 때만 후보가 생긴다. 후보와 까닭(모두 devops §4.4 승인 대상, 지금은 더하지 않는다):

## 계획

### 1. 범위

**한다(OPS-350)**
1. `@peaket/console-contract`: 원격 목록 한 항목의 형식(`RemoteListEntry {name, sha, entry, integrity, contractMajor}`)과 검사 함수(이름·sha·`sha384-<base64>` 꼴, `entry`가 `/remotes/<name>/<sha>/remoteEntry.js`와 정확히 같은지), 실패 까닭 이름 목록(`RemoteLoadFailReason`). 판 확인 `isLoadable`은 그대로.
2. 호스트 원격 적재기(`apps/console-host/src/shared/lib/remotes/`): 같은 출처 `/remotes.json`을 읽고 → 항목마다 계약 판을 확인하고(다르면 받지 않음) → `integrity`·`crossorigin="anonymous"`를 붙인 스크립트 요소를 `peaket-remote` 정책으로 만들어 넣고(시간 초과 5초 [가정]) → 실패하면 한 번 다시 → 또 실패하면 그 칸만 대체 카드. `peaket-remote` 허용 목록은 빌드에 박은 주소 대신 **읽은 목록의 정식 주소**(이름·sha로 만든 경로)다. 원격 노출 모듈을 실은 뒤 위젯 정보의 `contractMajor`도 다시 본다.
3. 대체 카드의 [다시 시도]가 그 칸만 다시 싣는다(지금은 눌러도 아무 일이 없다). 문구·모양은 d5 §7.2 '위젯 오류'(지금 `FailCard`).
4. 실패 수 `remote_load_failed_total{remote, reason}`: 콘솔이 같은 출처 `/_t/rum`으로 브라우저 지표 묶음의 `counters` 칸에 싣는다(소비자 웹 검색 품질 수와 같은 꼴, `apps/web/src/widgets/app-shell/model/search-quality-client.ts`). 계약은 asyncapi 브라우저 지표 묶음 `counters`의 이름·라벨 열거에 더한다. 수를 Prometheus 지표로 바꾸는 게이트웨이 수집기는 아직 없다(구간 5, 이 기능 밖).
5. 원격 빌드: 원격을 **한 파일**(`remoteEntry.js` 하나에 노출 모듈·위젯 덩어리까지)로 낸다(아래 6-2). 출력 자리 `dist/remotes/<name>/<sha>/remoteEntry.js`, 빌드 뒤 목록 만들기 스크립트가 sha384를 계산해 `dist/remotes.json`을 쓴다. 원격 하나만 빌드하는 명령(`webpack --config-name remote-<name>`).
6. 공용 원격 빌드 워크플로 `.github/workflows/build-remote.yml`(재사용, 입력 `remote`): 설치 → 원격 폴더 린트 → 그 원격만 빌드 → 크기(gzip 80KB [가정], §5.8 관제 줄) → sha384 → 목록 조각·산출물 올리기. `ci-web.yml`이 원격 폴더·계약 패키지가 바뀌면 두 원격으로 부른다. 콘솔 버킷 올리기는 구간 5('감독에게' 9).
7. 원격 폴더 린트(뿌리 `eslint.config.mjs`, `apps/widgets/**`): `fetch`·`WebSocket`·`EventSource`·`XMLHttpRequest`·`localStorage`·`sessionStorage`·`indexedDB` 직접 쓰기, `window`·`globalThis`·`document`에 값 두기, `@peaket/console-contract`·공유 싱글턴 밖의 `@peaket/*` 가져오기를 막는다(정본 §4.5 '금지', ASVS 3.2.3). ESLint 내장 규칙만 쓴다.
8. 공유 싱글턴: '감독에게' 8대로 좁혀 선언하고, 원격 산출물에 react·계약 패키지 사본이 없는지 본다(devops §6.6 '싱글턴과 버전 범위를 E2E로 검사').
9. FE-T39 마무리: 운영 빌드 + 묶음 C 헤더로 화면 16개와 목록의 원격을 모두 싣고, 목록과 다른 주소를 거절하는지 본다.

**한다(OPS-360)**
10. 위젯 구독 수명(정본 §4.4.5 '구독 수명', §4.5 '구독 수명과 보이기', §5.7 '안 보이는 위젯' 표, ADR-0091 결정 3): 같은 키는 한 흐름(지금 있음), 마지막 구독자가 떠나도 **10초 [가정] 유예** 뒤 목록에서 뺌, **숨긴 브라우저 탭 30초 [가정]**이면 위젯 키를 모두 뺌(구독자는 멈춤 상태로 남김), 다시 보이면 다시 열고 그 키의 위젯 조회(최근 15분 창)를 한 번 불러 구독자에게 넘김, **회차 바꿈은 유예 없이 바로**, 늘 여는 흐름은 건드리지 않음.
11. 접은 위젯: 위젯 머리의 접기(d5 §3.3, 보드 SCR-029-d '접은 위젯')를 실제 값 화면에도 두고 `collapsed`를 넘긴다. 구독은 그대로 둔다. 접힘 상태는 호스트가 이 브라우저에만 남긴다(보드 문구 '이 브라우저에만 남습니다').
12. 화면 밖 위젯: 구독은 두고 그리기만 멈춘다. 호스트 자리가 `IntersectionObserver`로 보고, 안 보이는 동안 마지막 값만 들고 있다가 보이면 한 번 넘긴다. 실시간 값은 자리마다 250ms [가정] 단위로 마지막 값만 넘긴다(§5.7 '신선도').
13. 탭 제목의 수: 숨긴 동안 SEV1·SEV2 경보 또는 내 승인 대기가 있으면 `(SEV1 1 · 승인 1) 관제` 꼴을 앞에 붙인다(§5.7 '멈추지 않는 것', d5 §3.3).
14. 미리 받기(§5.7 '화면별 늦게 싣기', ADR-0091 결정 1): 대시보드를 처음 그린 뒤 2초 [가정]에 명령 화면(SCR-030) 덩어리를 낮은 우선순위로, 그다음 다음 단계 탭의 원격을 **같은 무결성 적재기로** 미리 싣는다. 메뉴에 포인터·초점이 가면 그 화면 덩어리를 미리 부른다. PoC 결과를 정본 §6.3 '확인 필요' 표(1845행)와 ADR-0361에 적는다.
15. 덩어리 나눔(FE-T25): 관제 첫 화면 묶음(로그인·대시보드 틀)에 다른 화면 덩어리가 없고 화면 덩어리마다 80KB [가정] 이하. **대시보드 덩어리(84.1kB)를 예산 안으로** 줄인다(배치별 보드 셋 `board-d`·`board-t`·`board-m`을 배치마다 따로 싣기, 실제 값 화면에서는 퍼블리싱 고정 자료 위젯을 싣지 않기 등, 방법은 구현 담당). 파트너 첫 화면 묶음에 에디터·시뮬레이터·그래프·서식 글 편집기가 없고 파트너·관제 묶음에 끌어 놓기 라이브러리가 없는지도 본다.
16. 그래프 상한(§5.7 '그래프와 들고 있는 양', ADR-0091 결정 4): `@peaket/ds` `TimeSeriesChart`에 실시간 방식(x축 `linear` 밀리초, `parsing: false`, `normalized: true`, `animation: false`, 축 최소·최대, `update('none')`, `Decimation` `min-max`)을 **더하고**(지금의 글자 눈금 방식은 파트너 분당 판매가 쓰므로 그대로), 한 선 900점·한 장 6선 [가정] 고리 버퍼를 같은 부품 뒤에 둔다. 지금 실제 값으로 잇는 위젯 둘(입장 비율·빈자리, 결제사)은 화면 설계(d5)에 그래프가 없어 이 방식을 쓰는 위젯은 원천 기능이 위젯을 더할 때 생긴다(아래 6-9).

**그대로**: ops-svc 전부, 늘 여는 흐름·위젯 흐름의 서버 계약, 위젯 둘의 값 모양·마크업, 퍼블리싱 `/preview`와 고정 자료, 한 앱 빌드 경로(FE-T29가 쓰므로 깨지지 않게만), 헤더 값(`packages/config/headers/security-headers.mjs`, Trusted Types 이름 목록은 원격 이름이 같으면 그대로).

**하지 않는다(경계)**
- F-03-1 몫: 흐름 둘의 서버·화면 연결, 콘솔·파트너 헤더와 정책 이름, FE-T28·FE-T41.
- F-03-3 몫: FE-T29 한 앱 기준선 비교 측정, 대시보드 4단계·Go/No-Go, (제안) 경보 목록 가상 스크롤과 관제 Lighthouse CI 대표 주소.
- 측정 기능 몫: FE-T27 4시간 장시간·memlab.
- 구간 5 몫: 콘솔 버킷 올리기, 운영 `remotes.json` GitOps 자리, CloudFront 응답 헤더 정책, 브라우저 지표를 Prometheus로 바꾸는 수집기, Trusted Types 막는 모드.
- 나머지 위젯 일곱의 실제 값(원천 기능이 `WidgetSource`에 붙인다, ADR-0360 결정 9).

### 4. 공개 인터페이스

- **`remotes.json`**(같은 출처 `/remotes.json`, `Cache-Control: no-cache`): 정본 §4.5의 배열 `[{name, sha, entry, integrity, contractMajor}]` 그대로. 제안 제약: `name`은 호스트가 아는 원격 이름(`queue`·`purchase`), `sha`는 소문자 16진 7~40자, `integrity`는 `sha384-`+base64 64자, `entry`는 정확히 `/remotes/<name>/<sha>/remoteEntry.js`. 틀린 항목은 그 원격만 실패(`list`)로 보고 나머지는 싣는다. 목록 자체를 못 읽으면 원격 칸 모두 실패(`list`).
- **`@peaket/console-contract` 더하는 것(제안)**: `interface RemoteListEntry`, `function parseRemoteList(json: unknown): { entries: RemoteListEntry[]; rejected: { name?: string; why: string }[] }`, `function remoteEntryPath(name: string, sha: string): string`, `type RemoteLoadFailReason = 'list' | 'contract' | 'policy' | 'integrity' | 'network' | 'timeout' | 'container'`.
- **호스트 적재기(제안)**: `loadRemoteWidgets(name, { priority?: 'low' })`(같은 함수가 미리 싣기도 한다), 실패는 `RemoteLoadError{ remote, reason }`로 던진다. 같은 원격의 동시 요청은 하나로 묶고, 실패하면 기억을 지워 [다시 시도]가 새로 받는다.
- **실패 수**: `counters` 항목 `{ name: 'remote_load_failed_total', labels: { remote, reason }, value }`. 한 적재가 마지막에 실패했을 때 한 번 센다(처음 실패 뒤 다시 받아 성공하면 세지 않는다, 제안).
- **위젯 흐름 관리(제안)**: `WidgetStreams`에 유예(`graceMs` 기본 10초)·`setHidden(hidden)`(30초 뒤 모든 키 멈춤)·다시 보일 때 키마다 조회 콜백. 시계·무작위·fetch는 지금처럼 넘겨받는다(Node 시험 실행기로 읽힘).
- **ds**: `TimeSeriesChart`에 선택 속성(예: `realtime: { points, windowMs }`)과 `RingSeries`(한 선 900점, 한 장 6선, 넘으면 오래된 점·선부터 버림). 기존 속성 모양은 그대로.
- **원격 빌드 명령**: `pnpm --filter @peaket/console-host exec webpack --mode production --config-name remote-<name>` 뒤 `node apps/console-host/scripts/remotes-manifest.mjs --remote <name> --sha <커밋 sha>`(제안). 워크플로 입력은 `remote`.

### 6. 정할 것과 추천(구현 커밋이 ADR-0361과 정본에 적는다)

1. **적재기는 자체 적재기를 넓힌다(추천)**: 정본 §4.5의 '런타임 플러그인 `createScript`·`loadEntryError`·`errorLoadRemote`'는 `@module-federation/enhanced`의 이름이다. F-03-1이 webpack 5 내장 MF + 자체 적재기를 골랐으므로(ADR-0360 결정 6), 같은 순서(목록 → 판 → 무결성 스크립트 → 한 번 다시 → 대체)를 자체 적재기 한 곳이 하고, §4.5 글을 '적재기가 한다'로 고친다. 새 의존성이 없다('감독에게' 4).
2. **원격을 한 파일로(추천 (가), PoC)**: 지금 원격은 파일 다섯이라 진입 파일의 sha384가 위젯 덩어리를 덮지 못한다(원격 런타임이 받는 덩어리에는 무결성이 없다). (가) 원격 빌드에 `optimize.LimitChunkCountPlugin({ maxChunks: 1 })`과 공유 `import: false`(대체본 없음)를 걸어 `remoteEntry.js` 하나로 낸다. 원격이 작아(지금 위젯 둘 합쳐 원격마다 약 9kB) 늦게 싣기 이득이 거의 없다. (나) 원격 덩어리마다 해시를 걸려면 `webpack-subresource-integrity`(새 의존성, '감독에게' 4). 구현 담당이 (가)를 먼저 해 보고, 한 파일로 안 나오면 멈추고 감독에게 넘긴다.
3. **sha**: 경로의 `<sha>`는 원격을 빌드한 커밋 SHA 앞 12자(제안, 로컬은 `git rev-parse`, CI는 `GITHUB_SHA`)다. 원격 파일은 경로가 판마다 달라 긴 캐시(`immutable`)를 주고, `remotes.json`만 `no-cache`다.
4. **개발 서버의 목록(추천)**: 개발 서버는 원격을 메모리로 빌드하고 고쳐질 때마다 내용이 바뀐다. 개발 서버 미들웨어가 그 순간의 원격 바이트로 sha384를 계산해 `/remotes.json`을 내주면 운영과 같은 길(무결성 확인 포함)로 돈다. 무결성을 끄는 개발 전용 갈래는 두지 않는다.
5. **다시 받기와 실패 수**: 진입 파일 실패(무결성·네트워크·시간 초과·컨테이너 없음)는 한 번 다시 받는다. 판 불일치·목록 거절·정책 거절은 다시 받지 않는다. 수는 마지막 실패에 한 번 센다. 늦게 온 응답은 무시한다(칸은 이미 대체 카드).
6. **미리 받기 PoC의 답(예상)**: 미리 받기를 `<link rel=preload>`가 아니라 **같은 적재기 호출**(낮은 우선순위)로 하면 미리 받기도 무결성·정책·판 확인을 그대로 거친다. 그래서 정본 ADR-0091 결정 1의 '거치지 않으면 미리 받지 않는다'에 걸리지 않는다. T10이 위조 원격으로 이를 확인하고, 결과를 §6.3 '확인 필요' 표 1845행에 적는다.
7. **공유 싱글턴**: '감독에게' 8.
8. **숨긴 탭과 다시 보일 때 채우기**: 숨긴 지 30초가 되면 `WidgetStreams`가 키를 모두 빼되 구독자 목록은 멈춤으로 남기고, 다시 보이면 키마다 호스트가 위젯 조회(최근 15분 [가정])를 한 번 불러 같은 구독자에게 넘긴다(위젯은 자기가 보이는지 따지지 않는다, §4.5). 조회 값과 흐름 값의 모양이 같아(ADR-0360 결정 10) 위젯 코드는 바뀌지 않는다.
9. **그래프 쓰는 위젯이 지금 없다**: 실제 값으로 잇는 위젯 둘은 d5 설계에 그래프가 없다. 그래서 이 기능은 상한을 ds 부품 뒤에 두고 ds 시험(T17)으로 보며, 화면에서 처음 쓰는 것은 그래프 위젯의 원천 기능이다. 원격이 `chart.js`를 처음 가져오는 기능이 공유 싱글턴에 `chart.js`를 더한다(6-7의 규칙).

**소유자 결정이 필요할 수 있는 것**: (1) PoC가 실패해 새 의존성이 필요할 때(devops §4.4). (2) 공유 싱글턴 목록 좁히기를 방향 결정으로 볼 때('감독에게' 8). 둘 다 아니면 묻지 않는다.

## 구현 메모

- (구현 담당만 쓴다. 계획·정본과 다르게 한 곳과 다음 역할이 볼 것.)
- **PoC 결과(6-2·6-6)**: (가) 한 파일이 됐다. `LimitChunkCountPlugin({ maxChunks: 1 })`만으로는 원격의 공유 모듈 소비가 진입 덩어리 안 동기 소비가 되어 'Shared module is not available for eager consumption'에 걸린다(생성 코드로 확인). 그래서 호스트가 원격이 가져가는 react·react/jsx-runtime·계약 패키지를 `eager`로 내놓는다(react-dom은 원격이 쓰지 않아 eager 아님). 새 의존성 없음. 미리 받기는 같은 적재기(낮은 우선순위)라 무결성을 거친다. ADR-0361 결정 2·6, frontend §6.3에 적었다.
- **계획과 다르게 한 것**: ① 계약 패키지 판을 0.0.0 → 1.0.0으로 올렸다(strictVersion 범위 `^1.0.0`이 `CONTRACT_MAJOR`와 맞게, 결정 7). ② `WidgetProps`에 선택 콜백 `onCollapsedChange?(collapsed)`를 더했다(머리의 [접기]·접힌 줄 누르기를 호스트가 맡으려면 원격이 알려야 한다. 판 1 안 선택 칸, 결정 8, frontend §4.5 코드). ③ 원격 덩어리 크기 검사는 size-limit 대신 `remotes-manifest.mjs --check`(`node:zlib`)이고 §5.8 관제 줄 도구 칸을 고쳤다. ④ 위젯 흐름의 떠난 키는 10초에 목록에서 빠지고 1초 묶기 뒤(떠난 뒤 11초) 새 흐름이 열린다(정본 '10초 뒤 뺀다' + '바뀌면 1초 묶어 다시 연다'를 그대로 이음). ⑤ 미리 싣기는 이미 마지막에 실패한 원격을 다시 받지 않는다(브라우저 확인에서 2초 미리 싣기가 실패한 원격을 다시 받아 실패 수를 한 번 더 세는 것을 보고 고쳤다. 다시 받기는 [다시 시도]만, 결정 5). ⑥ 원격 sha는 커밋 앞 12자이되 원격 폴더·계약 패키지에 커밋 안 한 변경이 있거나 `.git`이 없으면(Docker 빌드) 원천 내용 해시다(같은 경로에 다른 바이트가 나가 오래 캐시와 무결성이 어긋나지 않게, 결정 3). ⑦ 실패 수는 첫 실패 뒤 1초 묶어 보내고 숨길 때·떠날 때 남은 것을 보낸다(route는 `/dashboard` 고정). ⑧ `tools/ci/changes.mjs` web 규칙에 `packages/console-contract/`와 `build-remote.yml`을 더했다(원격 빌드 잡이 돌게), `tools/ci/brief.mjs` 잡 표에 `web / remotes`와 잡 수 글(열셋)을 고쳤다. ⑨ 접은 위젯 줄('접은 위젯 n개 · [모두 펼치기]')은 실제 값 화면에 아직 없다(보드 줄은 퍼블리싱). 원격의 '받지 못함'(원천 없음)·'불러오는 중' 그림은 접힘을 따르지 않는다(원격 팀 몫).
