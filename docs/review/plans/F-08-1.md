# 기능 계획: F-08-1(경로별 번들 예산·좌석맵 랩·web-vitals p75)

- **진행**: 계획·시험·구현·소규모 실측(2026-11-25, 동결 로컬 갈래). 이 기능은 v1 배포 범위 밖(`frozen-local`)이고 `freeze/lane4-F-08-1` 가지에서만 개발한다(ADR-0373·ADR-0386 결정 4). 20회 정식 랩 판정은 이 계획의 도구로 따로 돌린다(아래 8절·14절).
- **무엇**: BUILD_ORDER '기능 단위 계획' F-08-1(갈래 4, 등급 B, LCH-200, WBS 3.00일)의 작업 목록이다. 판정 문장은 "경로별 번들 예산·좌석맵 랩·web-vitals p75가 된다 판정: FE-T10, docs/frontend.md"이고, 장부 범위는 `FE-T10` 하나로 좁혔다(5절). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **쉬운 말**: ① 화면마다 "처음 받는 자바스크립트가 몇 KB까지인지"를 경로 단위로 빠짐없이 정해 두고, 새 경로가 생겼는데 예산이 없으면 시험이 멈추게 한다. ② 5만 석 좌석맵을 메인 스레드 Canvas로 그리는 길과 Worker로 그리는 길을 같은 조건에서 20번씩 재어, 조작 반응(INP)·첫 그림·긴 작업이 목표 안인지 본다. ③ 그때 브라우저가 실제로 잰 INP·LCP·CLS·긴 작업·긴 애니메이션 프레임(LoAF)을 모아 **p75**(20번 가운데 75%가 이 값 이하)로 보고한다. p75는 "가운데 값"이 아니라 "나쁜 쪽에서 네 번째로 나쁜 값"에 가깝다.
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-08-1`, 가지 `freeze/lane4-F-08-1`, 기준 `origin/develop` `1d10d6da3`(2026-11-25 최신). 계획 담당은 Docker·kind·측정을 돌리지 않았고, 이 동결 갈래에서는 계획·시험·구현을 한 세션이 맡는다(감독 지시, 15절 담당 표에 적었다).
- **한 줄 결론**: 지금 있는 `tools/web-checks/budgets/`는 대표 경로 14개의 첫 JS를 막고 Lighthouse 8개 주소를 다섯 번씩 재지만, ① 소비자 웹 경로 전부가 §5.8 행에 매인다는 보장이 없고 ② 좌석 화면 Worker 60KB 예산은 아무도 막지 않으며 ③ 좌석맵 Canvas/Worker 비교와 web-vitals p75를 한 번에 내는 랩 하네스가 없다. 이 셋을 `tools/web-checks` 안에서 만들고, 20회 정식 판정은 이 PC의 로컬 Playwright/Chromium으로 돌린다.

## 2. 감독에게

1. **장부 범위를 FE-T10 하나로 좁힌다** — BUILD_ORDER F-08-1 줄의 장부 범위 칸을 `FE-T10, docs/frontend.md`에서 `FE-T10`으로 바꾼다. `docs/frontend.md` 전체를 범위로 두면 다른 기능의 빈칸 12개가 이 동결 기능에 딸려 온다. 판정은 FE-T10 하나이므로 `--require`의 빈칸은 0이 된다.
2. **v0는 다시 재지 않는다(동결 로컬 조건)** — 이 갈래는 Docker·kind를 쓰지 않는다는 지시를 받았다. v0 좌석맵은 kind 위 모놀리스라 로컬에서 띄울 수 없으므로, v0 값은 `docs/verification.md` §3.10의 2026-11-03 K5 실행(INP p75 88ms·그리기 p75 471ms·긴 작업 31)을 **문서 인용**으로 쓰고 다시 재지 않는다. 랩의 'Canvas'는 실제 v0 코드가 아니라 `@peaket/seatmap`의 **메인 스레드 대체 길**(`env: {}`)이다. 그래서 이 랩은 "v0 대 v1"이 아니라 **Canvas(메인 스레드) 대 Worker** 비교이고, 보고서에 그렇게 적는다. 힙 감축률(v0 대비 70%)은 보조 숫자라 판정에 쓰지 않고, v0 힙과의 비교는 '잴 수 없음'으로 남긴다.
3. **p75 정의를 못박는다** — `p75`는 오름차순 정렬 뒤 `ceil(0.75 × n) − 1`번째 값(최근접 순위, 보간 없음)으로 한다(추천 적용, 2026-11-25). 20회면 15번째로 작은 값이다. K5 PoC의 옛 헬퍼는 `floor(n × p)`라 20회에서 16번째를 골랐으므로, 이 기능의 새 도구는 최근접 순위로 통일하고 옛 값과 섞지 않는다. 판정에 쓰는 회차 수는 §5.8의 20회 [가정]을 정본에서 읽는다.
4. **정식 판정은 20회, 로컬 확인은 작게** — 20회×2모드(Canvas·Worker)는 이 PC에서 수 분이 걸린다. 구현 확인은 회차를 줄여 먼저 돌리고(계획 13절), 보고서에는 20회를 채웠는지와 줄였다면 그 까닭을 적는다. 20회를 못 채운 값은 `잠정`으로 표시하고 '랩 판정 통과'로 세지 않는다.
5. **네트워크 흉내는 로컬에서 선택** — §5.8의 중급 모바일은 CPU 4배·왕복 150ms·내려받기 1.6Mbps다. CPU 4배는 CDP로 건다. 망 흉내(`Network.emulateNetworkConditions`)는 5만 석 배치 파일(83KB brotli)과 화면 청크에 걸리는데, 로컬 서버가 같은 PC라 값이 실제보다 낙관적이다. 정식 판정 때는 켜고, 켰는지·껐는지를 `lab.json`에 적는다. 껐으면 'CPU만' 표시를 붙이고 정식 랩 판정으로 부르지 않는다.
6. **Worker 몫 보정은 PoC 방식을 그대로 쓴다** — CDP CPU 느리게 하기는 메인 스레드에만 걸린다(2026-11-04 확인, `seatmap/RESULT.md`). Worker에서 도는 첫 그림·풀기 몫은 ×4 보정값을 함께 적고, 보정하지 않은 값은 참고로만 둔다. INP는 메인 스레드 사건이라 보정하지 않는다.
7. **좌석 Worker 60KB를 실제로 막는다** — §5.8 좌석 화면 행의 `+ Worker 60KB [가정]`은 지금 아무 검사도 보지 않는다. 좌석 화면 데모를 브라우저로 열어 Worker 스크립트를 잡아 gzip으로 재는 검사를 `budgets` 잡에 더한다. Worker를 못 찾거나 화면이 안 열리면 **건너뛰지 않고 실패**한다(조용한 통과 금지).
8. **새 패키지 의존성은 더하지 않는다** — web-vitals 계측은 `tools/web-checks`의 새 의존성 대신, 브라우저 표준 `PerformanceObserver`로 LCP·CLS·INP·LoAF·longtask를 모으는 작은 수집기를 시험 페이지에 주입한다(`@peaket/telemetry`·제품 RUM은 건드리지 않는다). p75 집계는 순수 함수로 두고 `node --test`로 시험한다.
9. **보고서 자리** — 측정 결과는 `docs/review/measurements/F-08-1.md`에 표로 남기고, `docs/review/ledger-notes.md` FE-T10 줄이 그 파일을 가리키게 한다. 20회 정식 판정 전에는 '잠정' 표시와 남은 몫을 적는다.

## 3. 범위

### 3.1 하는 것

**① 경로별 번들 예산(소비자 웹 전 경로 + 좌석 Worker)**

- 소비자 웹의 경로 원천(`apps/web/src/_app/security/page-headers.ts`의 `ROUTES`)을 읽어 **모든 화면 경로**가 §5.8의 어느 경로 묶음 행에 매이는지 표로 만든다(`budgets/routes.mjs`). 처리기 경로(`handler(...)`, HTML이 아니다)는 표에서 빼되 왜 뺐는지 남긴다.
- 매이지 않은 화면 경로가 하나라도 있으면 시험이 실패한다(새 경로가 예산 없이 들어오는 것을 막는다). 경로 묶음 이름이 §5.8에 없어도 실패한다.
- 표는 경로마다 `첫 JS 예산·CSS 예산·(좌석이면) Worker 예산`을 정본에서 읽어 낸다. 기준선이 있는 경로는 기존 규칙(`jsLimit`: 기준선 + 1kB)을 그대로 쓴다.
- §5.8 좌석 화면 행의 Worker 60KB를 `budgets/worker.spec.mjs`가 실제 Worker 스크립트(gzip)로 막는다. 첫 JS 예산은 기존 `js.spec.mjs`가 계속 막는다(중복 판정이 아니라 서로 다른 파일을 잰다).
- `budgets/report.mjs`에 경로 예산 표를 더해, 측정이 없어도 "이 경로는 이 행·이 예산" 표를 낼 수 있게 한다.

**② 좌석맵 랩(5만 석·Canvas/Worker)**

- 실제 `@peaket/seatmap` 패키지를 쓰는 `tools/web-checks/seats/` 하네스에 `?main=1`(메인 스레드 대체 길)을 더한다. 같은 페이지·같은 5만 석 배치·같은 시나리오를 두 모드로 돈다.
- 시나리오(중급 모바일 412×823·배율 2.625, CPU 4배, 회마다 새 문맥): 첫 그림(ready) → 계측 비우기 → 휠 확대 3번 → 구역 초점(`focusSection`) → 캔버스에서 좌석 10개 누르기 → 1초 기다림 → 값 읽기. '홀드 버튼'은 하네스에 없으므로 누르지 않고, 그 사실을 보고서에 적는다(제품 화면의 홀드는 다른 기능 몫).
- 회마다 잰다: 첫 그림까지(내비게이션 시작→`ready.firstPaintAt`), INP·LCP·CLS, 긴 작업 수·합, LoAF 수·가장 긴 5개, 메시지 처리 p95, GC 뒤 힙(Worker는 Worker 대상, 메인은 페이지). 20회 [가정]으로 p75를 낸다.
- 판정은 FE-T10: 첫 그림 p75 ≤ 1,000ms, INP p75 ≤ 200ms, LCP p75 ≤ 2,500ms, CLS ≤ 0.1, 조작 경로 긴 작업 0, 메시지 처리 p95 ≤ 2ms. 힙은 보조 숫자다.
- Worker 모드의 첫 그림·풀기 몫은 ×4 보정값을 함께 적는다(6절). Canvas 모드는 메인 스레드라 CPU 4배가 그대로 걸린다.

**③ web-vitals p75 수집·보고**

- 브라우저 표준 `PerformanceObserver`만으로 LCP·CLS(세션 창)·INP(사건 상호작용별 최대의 p98)·LoAF·longtask를 모아 `window.__peaketVitals`(v0와 같은 모양)에 두는 수집기를 만든다. 페이지 스크립트보다 먼저 주입한다.
- 회차마다 `window.__peaketVitalsReset()`으로 비우고 시나리오 뒤에 읽는다. `status`가 `ready`가 아니거나 INP 표본이 0이면 그 회차는 **무효**다(0건을 통과로 세지 않는다).
- p75 집계는 순수 함수(`lib/vitals.mjs`)로 두고, 회차 수·무효 수·p75·최댓값·판정을 JSON과 Markdown으로 낸다. 20회를 못 채우면 `잠정`으로 표시한다.
- 보고서 `docs/review/measurements/F-08-1.md`에 모드별 표(첫 그림·INP·LCP·CLS·긴 작업·LoAF·메시지 p95·힙)와 판정, v0 문서 인용, 무효 회차와 까닭을 적는다.

## 6. 측정 설계(측정 전에 못박는다)

### 6.1 프로필과 무대

- 이 PC의 Playwright Chromium(로컬, Docker 없음). 화면 412×823 CSS px, 기기 배율 2.625, `isMobile`·`hasTouch`(Lighthouse 모바일 기본값).

- 회마다 새 브라우저 문맥을 만들고 서버는 `tools/web-checks/seats/server.mjs`(가짜 실시간 서버)를 쓴다. 서버는 회차 사이에 `GET /__seats/reset`으로 기록을 비운다.
- 회차 수 기본 20(§5.8 [가정], `lib/canon.mjs`가 문서에서 읽는다). `PEAKET_LAB_REPS`로 줄일 수 있고, 줄이면 결과에 `reps`와 `provisional: true`를 남긴다.

### 6.2 시나리오

1. 새 문맥·페이지. `addInitScript`로 vitals 수집기를 페이지 스크립트보다 먼저 넣는다.
2. `/`(Worker) 또는 `/?main=1`(Canvas)로 이동한다. 페이지는 `@peaket/seatmap`의 실제 `createSeatMap`을 쓴다.
3. `ready`를 기다린다. `seatCount`가 50,000, `sectionCount`가 25가 아니면 그 회차는 무효다.
4. 첫 그림 시각 = `ready.firstPaintAt − performance.timeOrigin`. `null`·음수면 무효.
5. `window.__peaketVitalsReset()` 뒤 50ms 쉰다.
6. 휠 확대 3번(화면 가운데, `mouse.wheel(0, -300)`) → `focusSection` 0 → `pointer` 사건이 실제로 나가도록 캔버스를 10번 누른다(좌석 단계에서, 화면 안 서로 다른 점). 누를 때마다 `hit` 또는 `selection` 메시지가 오는지 확인하고, 하나도 안 오면 그 회차는 무효다.
7. 1초 기다린 뒤 `window.__peaketVitals`와 `window.__seats`에서 값을 읽는다. `status !== 'ready'`면 무효.
8. GC를 한 번 돌리고 힙을 읽는다(Worker는 Worker 대상, Canvas는 페이지). 못 재면 `null`(판정에 쓰지 않는다).

### 6.3 판정과 p75

- p75 = 정렬한 값의 `ceil(0.75n) − 1`번째(최근접 순위). n=20이면 15번째, n=5면 4번째, n=1이면 그 값.
- **INP 표본 0의 뜻**: Event Timing은 16ms 이상 사건만 보고한다. 좌석을 눌렀는데(`clicks.hits ≥ 1`) 표본이 0이면 모든 조작이 16ms 미만이라는 뜻이라 INP를 0으로 적고 유효 회차로 센다. 표본이 있는데 INP가 비는 것은 무효다.
- 무효 회차는 계산에서 빼고, 무효 수와 까닭을 보고서에 적는다. 무효를 뺀 유효 회차가 20 미만이면 `잠정`이고 '랩 판정 통과'로 세지 않는다.
- 합격(랩 판정): 첫 그림 p75 ≤ 1,000ms · INP p75 ≤ 200ms · LCP p75 ≤ 2,500ms · CLS p75 ≤ 0.1 · 조작 경로 긴 작업 합 0 · 메시지 처리 p95 ≤ 2ms. 힙 감축률은 보조 숫자로만 적는다(ADR-0096).
- Worker 모드의 첫 그림 보정: `ready`까지의 구간을 메인 몫(문서·스크립트·init 전송)과 Worker 몫(받기·풀기·그리기·첫 프레임)으로 나눌 수 없으면, PoC `judgeK5`가 재는 단계 3·5의 ×4 보정값을 함께 적고 첫 그림 판정에는 **보정값이 있는 쪽(PoC)**을 보수적 근거로 쓴다. 두 값을 섞어 하나의 p75로 만들지 않는다.
- 같은 회차에서 Canvas와 Worker를 번갈아 돌리지 않는다(한 모드 20회를 끝낸 뒤 다른 모드). 모드 사이에 서버를 다시 띄우지 않는다.

### 6.4 멈춤 규칙

- `ready`가 30초 안에 오지 않거나 오류 메시지가 오면 그 회차를 무효로 하고 3회 연속이면 멈춘다.
- 좌석 수가 50,000이 아니거나 Worker 모드인데 `mode`가 `worker`가 아니면(OffscreenCanvas 없음) 멈춘다. 미지원을 건너뛰고 통과로 세지 않는다.
- vitals 수집기 상태가 `error`이거나 INP 표본이 없으면 3회 연속 무효일 때 멈추고 수집기를 고친다.
- 측정 도중 코드·설정을 바꾸지 않는다. 바꿔야 하면 멈추고 이 계획에 바꾼 때와 까닭을 적는다.

| Worker 스크립트를 못 찾음/화면이 안 열림 | spec 실패(건너뛰기 없음) | 하네스·빌드를 고친다. '없음'을 통과로 세지 않는다 |
| 랩 회차가 20 미만 | `provisional: true`, 판정 `unknown` | 정식 20회를 채우거나 '잠정'으로 보고한다 |
| vitals 수집기가 값을 못 냄 | `status`·INP 표본 0 → 무효 | 수집기·시나리오를 고치고, 3회 연속이면 멈춘다 |
| 캔버스 누르기가 좌석을 못 맞힘 | `hit`/`selection` 0 → 무효 | 좌표·배율을 고친다. 조용히 0건 통과 금지 |
| OffscreenCanvas가 없어 Worker 길이 안 돎 | `mode !== 'worker'` → 멈춤 | 미지원 브라우저를 통과로 세지 않는다. Windows WebKit 같은 대체는 FE-T15 몫 |
| CPU 4배가 Worker에 안 걸림 | 보정값과 원값이 크게 다름 | 보정값을 판정 근거로 쓰고 원값은 참고로 적는다 |
| 네트워크 흉내를 안 켬 | `lab.json`의 `network: 'off'` | 'CPU만' 표시, 정식 랩 판정으로 부르지 않는다 |
| 20회 중 한두 번 튐 | p75는 15번째라 두 번까지는 안 움직인다 | 그래도 한도 근처면 최댓값·LoAF 원인을 보고서에 적는다 |

## 10. 자주 놓친 결함(시험·구현 지시문에 넣는다)

- p75를 평균·중앙값·마지막 값으로 대신하지 않는다. `n=20`에서 15번째인지 시험이 본다.
- 0건·SKIPPED·`null`을 통과로 세지 않는다. 무효 회차는 빼되 수와 까닭을 남긴다.
- 경계값은 양쪽을 둔다: 첫 그림 1,000/1,001, INP 200/201, LCP 2,500/2,501, CLS 0.1/0.101, 메시지 2/2.001, 긴 작업 0/1.
- 같은 규칙을 두 곳에서 겹쳐 지키지 않는다(예: 첫 그림을 p75와 '모든 회차'로 동시에 판정하지 않는다). 판정 규칙은 한 곳(`lab-judge.mjs`)에만 둔다.
- Worker 보정값과 원값을 섞지 않는다. 보정은 Worker 스레드 몫에만 곱한다.
- 시험 값이 코드 상수를 그대로 가져오지 않게 한다. 단언 값은 정본(FE-T10·NFR-012)에서 적는다.
- `worker.spec.mjs`는 Worker를 못 찾으면 실패다. '찾은 Worker가 좌석맵 Worker인지' 표지(예: `seatmap` 문자열)도 확인한다.
- 경로 표는 `page-headers.ts`를 읽어 실제 경로와 대조한다. 표만 있고 원천과 안 맞으면 새 경로를 놓친다.

## 12. 크기와 차례

- **크기 어림**: 약 1.5일(계획 0.25, 시험 0.3, 구현 0.5, 로컬 확인·보고 0.45). 20회 정식 랩을 돌리면 +0.25일.
- **차례**: 계획 → 시험(기준 트리 실패 확인) → 구현 → 단위 시험 → 작은 회차 브라우저 확인 → 정식 20회(가능하면) → 보고서 → 게이트 → 커밋 셋(`docs(plan)`·`test(web-checks)`·`feat(web-checks)`).
- **줄일 곳**: ① 로컬 확인 회차를 3~5로 ② 네트워크 흉내를 끔 ③ Canvas/Worker 한 모드만 20회. ②③을 줄이면 보고서에 '잠정'과 까닭을 적는다.

## 13. 완료의 정의

1. `docs/review/plans/F-08-1.md`(이 파일)가 있고, `BUILD_ORDER` F-08-1 줄의 장부 범위가 `FE-T10`으로 좁혀져 있다.
2. `F081-01`~`F081-10` 시험이 있고, 기준 트리에서 실패를 본 기록이 14절에 있다.
3. 경로 표가 소비자 웹 화면 경로를 모두 §5.8 행에 매기고, 빠진 경로가 있으면 실패한다. 좌석 Worker 60KB 검사가 있다.
4. Canvas/Worker 랩 하네스가 5만 석·중급 모바일·CPU 4배로 돌고, INP·첫 그림·LCP·CLS·긴 작업·LoAF·메시지 p95·힙을 회차별로 남긴다.
5. `docs/review/measurements/F-08-1.md`에 모드별 표·p75·판정·무효·한계(네트워크 흉내 여부, 회차 수, v0 문서 인용)가 있다. 20회를 못 채웠으면 '잠정'이다.
6. `ledger-notes.md` FE-T10 줄이 보고서를 가리키고, `ledger --batch F-08-1 --require`가 빈칸 0으로 통과한다.
7. 8절 게이트가 통과하고, 커밋 셋이 꼬리말(`Batch: F-08-1`·`Feature: F-08-1`·`Role: ...`·`Agent-Session`·`Agent-Model`)을 달고 `freeze/lane4-F-08-1`에만 있다.
8. `develop`·`release/1.0.0`에 합치지 않았고, 다른 갈래의 미완 변경을 건드리지 않았다.

## 18. 동결 로컬 범위

- 이 기능은 `frozen-local`이고 v1 릴리스 계약에 들어가지 않는다(`docs/release/v1-scope.json`). `develop`·`release/1.0.0`에 합치지 않고, 릴리스 가지·`main`에 체리픽하지 않는다.
- 바꾸는 파일은 `tools/web-checks/`(검사 도구)·`docs/review/`(계획·측정)·`docs/BUILD_ORDER.md`의 F-08-1 범위 칸·`docs/review/ledger-notes.md`뿐이다. `deploy/`·`services/*/migrations`·출시 플래그를 바꾸지 않는다.
- 이 가지가 출시 뒤 `develop`과 충돌하면 출시 태그 기준으로 다시 쌓는다. 출시된 코드를 이 가지로 되돌리지 않는다.
