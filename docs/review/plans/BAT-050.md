# BAT-050 계획 — ticket-svc 최소 발권(HOT-160)

- 작성: 2026-11-13
- 묶음: BAT-050(HOT-160, 갈래 1, 구간 2, **A등급**, 1일)
- 장부 범위: `P-T15`, `P-T39`, `I-T26`, `I-T43`, `docs/security/asvs/payment.md`
- 선행: BAT-090(HOT-080·BOT-100)이 `develop`에 합쳐졌다. BAT-050은 HOT-160 발권만 하고 HOT-090(realtime-gw)은 BAT-052로 보류한다.

## 1. 목표

- `services/ticket-svc` 골격: 플랫폼 `createService`(health/management HTTP), 업무 gRPC 포트, Drizzle DB 마이그레이션.
- `ticket.proto` 최소 계약: `IssueTickets`(주문 단위 멱등 발권), `CancelTickets`(취소·키 폐기·취소표), `ListTickets`(월렛 목록).
- 같은 주문을 두 번 발권하지 않는다(`ticket_issue`의 `(order_id, issue_generation)` 기본 키). 재요청은 처음 티켓을 그대로 주고 키 원문은 다시 싣지 않는다.
- 티켓 키(32바이트 base64url, DB에는 SHA-256만)와 공개 QR 포인터(`PEAKET1:<ticket_id>`)를 만든다.
- 취소는 결제자=보유자·양도 요청 없음·입장 전/후를 행 잠금 안에서 보고 `REFUND_NOW`/`REFUND_AFTER_CLOSE`로 키를 폐기하며 취소표를 남긴다. `transfer_pending`·`fraud_lock_case_id`는 양도·부정 예매 잠금이 붙을 자리만 둔다.
- payment-svc 결제 확정 뒤 발권 호출은 `TicketIssuer` 포트·gRPC 어댑터·재시도 분류 시험까지 넣는다. 실제 Saga 실행기 연결은 후속(PRF-170 실행기).

## 2. 구현

- `domain/ticket.ts`: 입력 검사·멱등 지문·티켓 키/해시·QR·월렛 커서·상태.
- `domain/ports.ts`: `TicketStore`.
- `application/ticket-service.ts`: 발권 후보 생성(키 원문 포함), 취소·목록 위임.
- `adapters/memory-ticket-store.ts`: 단위 시험용. 같은 주문·세대 경합을 한 맵으로 모으고 취소표를 `(cancellation_id, ticket_id)`로 남긴다.
- `adapters/db/schema.ts`·`drizzle-ticket-store.ts`: `ticket_issue`·`ticket`·`ticket_cancellation`. 발권은 `ON CONFLICT DO NOTHING` + 재조회, 취소는 `FOR UPDATE`.
- `inbound/ticket.grpc.ts`: `IssueTickets`·`CancelTickets`·`ListTickets` 처리기. `TicketInputError`→`INVALID_ARGUMENT`, `TicketConflictError`→`FAILED_PRECONDITION`.
- `migrations/0000_ticket.sql`: 위 세 표·CHECK·유일/월렛 인덱스.
- payment-svc: `domain/ticket-issuer.ts`(재시도 분류), `adapters/ticket-grpc-issuer.ts`(2초 데드라인, `UNAVAILABLE`·`DEADLINE_EXCEEDED`·`RESOURCE_EXHAUSTED`만 재시도), `test/ticket-issuer.test.ts`. `start.ts`에는 아직 물리지 않는다.

## 4. 알려진 차이·다음

- 실제 Saga 연결(PRF-170 `TicketIssueRunner`가 `TicketIssuer`를 부르는 일), CS `TICKET_NOT_ISSUED` 건, 보상(T20)은 후속.
- `gate_zone`은 좌석 배치 연결 전이라 빈 값이다. 기기 키 등록·회전 QR(ADR-0025)도 후속.
- `VoidTickets`·`OperatorCancelTickets`·`CheckReviewEligibility`·`ListHeldTickets`·`ScannerDeviceService` 등 기존 proto의 나머지 RPC는 이 최소 서버에서 `UNIMPLEMENTED`다.
- DB test-int(실제 PostgreSQL)는 heavy gate에서 `0000_ticket.sql`·DrizzleTicketStore·발권 멱등·취소표·키 폐기·FOR UPDATE 경합을 9건으로 확인했다.
