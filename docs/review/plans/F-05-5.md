### 3. 공개 인터페이스(이름은 이대로)

```ts
// packages/platform (index.ts에서 내보냄)
export type ScannerAuthRejection = DpopRejectReason | 'proof_missing' | 'token' | 'session' | 'role' | 'device_unregistered' | 'device_revoked' | 'unavailable';
export const SCANNER_AUTH_REJECTIONS: readonly ScannerAuthRejection[]; // 18개, 차례는 offline-gate §6.1 'GAT-170 마감 규칙'
interface ScannerAuthWiring { /* 기존 칸 */ onRejected?: (reason: ScannerAuthRejection) => void }
export const SCANNER_PWA_ORIGIN_ENV = 'PEAKET_SCANNER_PWA_ORIGIN';
export function scannerPwaOriginFromEnv(env?: Record<string, string | undefined>): string; // 없거나 빈 값이면 'https://scanner.peaket.example'
export function assertScannerOrigin(origin: unknown, expected: string): void; // 정확히 같을 때만 통과, 아니면 ProblemError 403 'scanner-origin-forbidden'

// services/ticket-svc
export interface EnrollmentCodeStore {
  put(i: { codeHash: string; deviceId: string; ttlMs: number }): Promise<void>;
  take(codeHash: string): Promise<{ deviceId: string; expiresAtMs: number } | undefined>; // 한 번만, 원자적(§10의 5)
  restore(i: { codeHash: string; deviceId: string; expiresAtMs: number }): Promise<boolean>; // 만료됐거나 그 기기의 지금 코드가 다르면 false
}
export class ScannerEnrollmentUnavailable extends Error {} // application/scanner-devices.ts
// config.ts: TicketServiceConfig.scannerPwaOrigin: string

// apps/scanner/src/api/enrollment-link.ts
export function enrollmentCodeFromHash(hash: string): string | undefined; // §10의 4
export function stripEnrollmentFragment(loc: { pathname: string; search: string; hash: string }, replace: (url: string) => void): void;
export function enrollScreenEntry(o: { live: boolean; hash: string }): { live: boolean; initialCode: string }; // §10의 4
```

- 이유 사상: 증명 헤더 없음 → `proof_missing`, `DpopRejected(r)` → `r`(둘 다 401 `invalid_dpop_proof`). 신원 없음·토큰 모양·`X-User-Jkt` 없음·`X-User-Ath` 불일치·기기 전용 경로에 토큰·mTLS 비밀 불일치·자격 종류 불일치 → `token`, 세션 `valid:false`·역할 없음 → `session`(둘 다 401 `invalid_token`). 허용 역할 밖 → `role`(403). 미등록 → `device_unregistered`, ACTIVE 아님 → `device_revoked`(403). 원장·세션·`jti` 저장소에 닿지 못함·세션 확인 기한 넘김 → `unavailable`(503, `Retry-After: 1`). 통과는 부르지 않는다.
- `enroll`: `ScannerDeviceKeyConflict` → 409 소모·실패 셈, `bindCredential`이 `null` → 410 소모, 그 밖에 던지면 `restore`(만료 시각 = `take` 값) → `ScannerEnrollmentUnavailable`, `limiter.failed` 안 부름. Redis `restore`: 남은 ms ≥ 1이고 `scanner:enroll-device:{deviceId}`가 없거나 같은 해시일 때만 두 키를 `SET … PX <남은 ms>`.
- 화면(SCR-036 `/enroll`): '기기 등록'(입력 칸 초깃값 `initialCode`), '등록하는 중', 오류 글, 성공이면 `/login?live=1`. 코드를 어떤 저장소에도 쓰지 않는다.

### 5. 실제 서버 연결

### 10. 시험 리뷰 1 뒤 정본 결정(추천 적용, 2026-11-23)

시험 리뷰 1이 넘긴 정본 빈칸 다섯이다. 정본에 썼고 여기서는 시험이 볼 값만 적는다.

1. **세션 확인 기한**(offline-gate §6.2 '스캐너 세션 확인', authz-matrix §5.2): `CheckScannerSession` 호출은 1초 [가정]와 남은 처리 시간 가운데 짧은 쪽에서 끊는다. 기한 안에 답이 없거나 연결이 거절되면 503 `scanner-auth-unavailable`(`Retry-After: 1`), 이름표 `unavailable`, 행 0. 답하지 않는 대역으로 걸린 시간이 1,000ms 이상이고 1,400ms 미만인지 본다(TR-03). 기기 상태는 캐시하지 않는다(TR-05: 폐기 직전 통과 → 폐기 → 곧바로 403).
2. **동시 실행**(O-T37 ⑩, O-T42 ⑥, `Promise.all`, 실제 Valkey·PostgreSQL): 같은 증명 업로드 둘 → 200 하나·401(`invalid_dpop_proof`, 이름표 `jti`) 하나, 기록 한 묶음. 같은 코드로 다른 키 둘이 등록 → 201 하나·410 하나, 묶인 키는 201 쪽, 진 쪽은 실패 1로 셈.
3. **출처 거부는 등록 실패로 세지 않는다**(offline-gate §6.1 마감 규칙): 출처 확인이 IP 한도 확인·코드 꺼내기보다 먼저다. 틀린 출처 11번 뒤에도 같은 IP의 맞는 등록이 201이고 코드도 살아 있다.
4. **등록 QR 조각**(§6.1 마감 규칙 마지막 줄): `enrollmentCodeFromHash`는 `#`를 뗀 조각을 `&`로 나눠 첫 `code=` 칸만 읽고 `decodeURIComponent`한다. 깨진 인코딩(`#code=%E0%A4%A`)·빈 값·풀린 값 65자 이상 → undefined, 던지지 않는다. `#code=KDTW-BMQX-HLRP&x=1` → `KDTW-BMQX-HLRP`. `stripEnrollmentFragment`는 `code` 칸이 있으면(값이 깨져도) `replace(pathname + search)`를 한 번, 없으면 0번. `enrollScreenEntry({ live, hash })`는 `live`가 참이거나 `code` 칸이 있으면 `live: true`, `initialCode`는 읽은 코드나 `''`. 화면은 이 함수로 진입을 정한다(TR-01의 화면 시험: 입력 칸 값, `location.hash` 빔, 저장소 셋에 코드 없음, 등록 요청 본문의 코드, 실패 뒤 칸 값 남음).
5. **코드 꺼내기의 틈**(§6.1 마감 규칙): `take`는 한 키에 대한 원자 동작이다. 한 Lua 스크립트로 값·`PTTL`·지우기를 함께 하는 쪽을 권하고, `PTTL` 뒤 `GETDEL`도 받는다(`PTTL`이 음수면 없음으로 본다). 시험은 명령 이름을 단언하지 않는다(TR-09). `expiresAtMs`는 처음 발급 시각 + 10분을 넘지 않는다. Valkey에서 `restore`와 `put`(새 코드 발급: 옛 코드 지우기와 두 키 쓰기)도 서로 끼어들지 못하게 각각 원자적으로 한다(각각 한 Lua 등. 묶음 Redis면 두 키가 같은 슬롯에 오게 한다). 되살림·새 코드 겨룸 시험(20회)이 이것을 본다 (추천 적용 2026-11-23, F-05-5 시험 리뷰 2 TR-16).
