# 묶음 계획: BAT-202(BAS-011 보안 검사 게이트의 외부 도구)

- **무엇**: 묶음 하나를 시작할 때 계획 담당이 지시서로 만든 작업 목록이다(docs/architecture.md §8.6 4의 1, ADR-0256 결정 10). 검토 기록이고 규범이 아니다. 정본 값은 옮겨 적지 않고 자리(문서:줄)만 가리킨다. 정본과 다르면 정본이 이긴다. 다만 2장의 고정 값은 이 계획이 처음 찾은 값이라 그대로 적는다(정본 자리는 ADR-0263 결정 1).
- **바탕**: 가지 `feature/BAT-202-security-scan-tools`, 커밋 78dceb8f(origin/develop). 지시서는 작업 폴더 밖 `brief-BAT-202.md`(`node tools/ci/brief.mjs --batch BAT-202`, 같은 커밋)다. 2026-11-10 작성.
- **등급**: 묶음 B(docs/BUILD_ORDER.md:68). A등급 대상(돈·좌석·대기 순번)에 닿는 항목은 없다. 그래서 실패 증명은 실패 상황 시험, 틀린 구현 표본 20개 [가정](6장), 판정 기준 대조 표본이다.
- **용어**: 비밀 탐지는 커밋 이력에서 키·토큰 꼴 글자를 찾는 검사, 정적 분석(CodeQL)은 코드를 실행하지 않고 값이 흘러가는 길을 따라 약점을 찾는 검사, 설정 검사(Trivy `config`)는 인프라 코드·매니페스트·Dockerfile의 위험한 설정을 찾는 검사다. SARIF는 이런 도구가 결과를 담는 표준 JSON 꼴이고, 다이제스트는 컨테이너 이미지 내용으로 만든 고정 지문(`sha256:…`)이다.
- **소유자 결정**: OPEN[31](2026-11-10 "모두 추천대로"). gitleaks CLI·CodeQL 액션·Scorecard 액션(`publish_results` 끔)·Trivy(다이제스트 고정 이미지, 액션 안 씀)는 받고 Semgrep은 받지 않는다. gitleaks 커밋 전 검사는 두지 않는다.
- **읽은 정본 자리**(줄 번호는 78dceb8f 기준): docs/BUILD_ORDER.md:68·417, docs/adr/0259 결정 10~12(26~35), docs/devops.md §3.1(173~211)·§4.4(299~354)·§4.5(356~367)·§9.1·§9.3(689~716)·§14 D-T12(872), docs/security/asvs/delivery.md 머리(1~41)·V13(68~85)·V15(102~119)·L3(141~152), docs/architecture.md §8.3 SQL 주입 행(1062)·§8.6(1083~1141)·§8.7(1158~)·§11(1553~1557), docs/security/secrets-and-keys.md:13, docs/security/threat-model.md:118, docs/security/internal-management-plan.md:64, `.github/workflows/security-scan.yml`·`ci.yml`·`build-image.yml`·`iac-check.yml`, `tools/ci/check-workflows.mjs`·`ledger.mjs`(코드 영역 260~332)·`check-lint-disables.mjs` 머리·`image-smoke.mjs` 머리·`vuln-deadline.mjs` 머리, `packages/config/eslint/service-security.mjs` 머리, `eslint.config.mjs`, `infra/stacks/global/github/actions.tf`·`variables.tf`.

## 1. 장부 범위

### 1.1 지금 칸이 맞는지

지금 칸 `delivery:v5.0.0-13.3.1, delivery:v5.0.0-15.3.6`은 이 묶음이 하는 일의 반쯤이다. 단계 줄(BUILD_ORDER:417)의 'Trivy 이미지 검사'에 이미지 안 소스 관리 폴더 검사(asvs/delivery 13.4.1 '이미지 검사에서 `.git` 디렉터리가 나오면 검사가 실패한다')가 들고, 새 서드파티 액션을 처음 더하면서 허용 목록을 저장소와 맞추는 일이 D-T12(devops §14, 지금 빈칸)에 닿는다. 13.1.1(외부 통신 목록)은 글만 고치므로 범위에 넣지 않는다.

## 3. 막힌 부분

- 막는 선행은 없다. 조직 설정(7장 1번)이 늦어도 Scorecard 잡(예약·수동 실행만)만 실패하고 PR CI는 영향이 없다.
- 이 PC에서는 gitleaks·CodeQL을 돌리지 못한다(응용 프로그램 제어). Trivy는 Docker 이미지라 로컬에서 돌릴 수 있다. 그래서 첫 비밀·정적 분석 결과는 `develop` 푸시 뒤 CI가 낸다(ADR-0263 결정 11, 4.1의 11).
- §8.7 실패 목록 셋: 해당 없음. 이 묶음은 서비스 실행 경로의 경합·외부 호출·자원 한도를 더하지 않는다(CI 도구다). CI 쪽 실패 동작(받기 실패·결과 없음 → 막음)은 devops §4.4 '외부 보안 검사 게이트'에 적었다.
- 화면이 바뀌지 않아 브라우저 확인(§8.6 4의 9)은 없다. Lua·빠른 경로를 바꾸지 않아 성능 비교(4의 7)도 없다. '실제 서버 연결'(4의 4)은 첫 CI 실행이 대신한다.

## 4. 작업 목록

### 4.1 차례

1. **정본 빈칸 먼저**: 5장은 이 계획과 함께 이미 정본에 썼다(커밋 전). 구현 담당은 BUILD_ORDER '장부 범위' 칸(1.2)과 notes 줄(1.4)을 더한다.
2. **고정 표와 받기**: `tools/ci/scan-tools.mjs`(고정 표, gitleaks 받기와 SHA-256 맞추기, gitleaks·Trivy 실행 인자 만들기, 하위 명령 `fetch-gitleaks`·`gitleaks`·`trivy-config`·`trivy-image`)와 시험. 받기는 Node 내장 `fetch`와 `node:crypto`만 쓴다(`tools/spec-check/fetch-tools.mjs` 모양). 압축에서 `gitleaks` 실행 파일 하나만 푼다.
3. **판정 도구**: `tools/ci/scan-gate.mjs`(SARIF 읽기, 막는 규칙, 예외, 닫힘 실패, 잡 요약)와 예외 파일 `tools/ci` 아래의 `scan-exceptions.json`(처음엔 빈 목록)과 시험. 날짜 계산·만료 규칙은 `vuln-deadline.mjs`의 것을 가져다 쓴다(같은 한국 시각 달력 날짜, 만료일 그날 끝까지 유효).
4. **gitleaks 설정**: `tools/ci/gitleaks.toml`(`[extend] useDefault = true`, 허용 목록은 까닭이 든 `description`과 좁은 경로·꼴), `tools/ci/gitleaks-ignore`(처음엔 머리 주석만). 미끼 비밀은 실행 때 `$RUNNER_TEMP` 아래에 만든다.
5. **Trivy**: `trivy-config`·`trivy-image` 인자, Trivy 비밀 규칙 설정 `tools/ci` 아래의 `trivy-secret.yaml`(허용 규칙만, 처음엔 비었을 수 있다). 로컬 Docker로 `trivy-config`를 한 번 돌려 높음 이상을 분류한다(고치기 또는 30일 예외).
6. **이미지 소스 관리 폴더**: `tools/ci/image-smoke.mjs`에 검사 셋째를 더한다(ADR-0263 결정 9).

### 4.3 워크플로 잡 모양

공통: 맨 위 `permissions: contents: read`, 체크아웃마다 `persist-credentials: false`, 잡마다 `timeout-minutes`, 사용자가 고칠 수 있는 값은 식에 쓰지 않는다(`tools/ci/check-workflows.mjs` 규칙 1~6). 이미지는 `docker run`으로만 띄우고 다이제스트는 `tools/ci/scan-tools.mjs`에서 읽는다(워크플로에 이미지 글을 두지 않는다).

| 잡 | 언제 | 권한 | 단계 | 남기는 것 |
| --- | --- | --- | --- | --- |
| `dependencies`(있음) | 그대로(예약·수동 실행에서는 입력이 없어 라이선스 목록을 건너뛰고 취약점 판정만 한다) | `contents: read` | 그대로 | 그대로 |
| `secrets` | 늘 | `contents: read` | 체크아웃(`fetch-depth: 0`) → setup-node → `node tools/ci/scan-tools.mjs fetch-gitleaks --out "$RUNNER_TEMP/gitleaks"`(SHA-256이 다르면 실패) → `… gitleaks --sarif "$RUNNER_TEMP/gitleaks.sarif"`(미끼 먼저, 그다음 지금 커밋에서 닿는 전체 이력, `--redact`, 설정·무시 파일) → `node tools/ci/scan-gate.mjs --tool gitleaks --sarif … --report "$RUNNER_TEMP/secrets-gate.json"` | 판정 도구 보고서(규칙·파일·줄·커밋만, 비밀 조각 없음)를 산출물로 30일. 도구 원본 보고서는 올리지 않는다 |
| `codeql` | `inputs.sast`(PR은 `js`·`tools`·`ci` 범위가 바뀌었거나 범위를 못 골랐을 때, 푸시는 늘)와 예약·수동 실행 | `contents: read`, `security-events: write` | 체크아웃 → `github/codeql-action/init@9b3254085494b55a0f7c4c2b3d2d52cc712ce370 # v4.39.1`(`languages: javascript-typescript`, `build-mode: none`, `config-file: tools/ci/codeql-config.yml`, `trap-caching: false`, `tools`는 주지 않는다) → `…/analyze@` 같은 커밋(`category: /language:javascript-typescript`, `output: ${{ runner.temp }}/codeql`, `upload`는 PR이면 `never` 아니면 `always`. `github.event_name`만으로 고른다) → setup-node → `scan-gate.mjs --tool codeql` | `develop` 푸시·예약 실행은 코드 스캐닝. 판정 보고서를 산출물로 30일 |
| `iac-config` | 늘 | `contents: read` | 체크아웃 → setup-node → `scan-tools.mjs trivy-config --sarif …`(`docker run --rm --network none`, 저장소를 읽기 전용으로, `config --skip-check-update`, 대상은 ADR-0263 결정 7) → `scan-gate.mjs --tool trivy-config` | SARIF와 판정 보고서를 산출물로 30일 |
| `scorecard` | `github.event_name`이 `schedule`·`workflow_dispatch`일 때만 | `contents: read`, `actions: read` | 체크아웃 → `ossf/scorecard-action@<커밋>`(2장 표의 40자리 커밋, 줄 끝 주석 `# v2.5.0`. 입력 `results_file`, `results_format: sarif`, `publish_results: false`) → `actions/upload-artifact`(있는 고정 SHA) | SARIF를 산출물로 30일. 막지 않는다 |
| `build-image.yml` `build`(있음) | 그대로 | 그대로 `contents: read` 하나(규칙 7) | `image-build.mjs`(스모크에 소스 관리 폴더 검사가 든다) 뒤에 `scan-tools.mjs trivy-image --input image-out/<이름>-<arch>.oci.tar --sarif …`(`--scanners secret`, `--skip-db-update`·`--offline-scan`·`--skip-check-update`, 네트워크 없음) → `scan-gate.mjs --tool trivy-secret` | 판정 보고서를 그 잡의 산출물과 같이 7일 |

- 트리거: `on:`에 `schedule`(`0 0 * * 1`, 월요일 09:00 KST)과 `workflow_dispatch`를 더한다. 이 파일을 예약 실행할 때는 `ci.yml` 밖이라 `ci-summary`가 보지 않는다. 실패는 GitHub 기본 알림에 기댄다(8장 7번).
- `ci.yml` 잡 `security-scan`: `permissions: { contents: read, security-events: write }`를 잡에 두고(부른 워크플로의 잡 권한 상한이다), `with: sast: ${{ needs.changes.result != 'success' || needs.changes.outputs.js == 'true' || needs.changes.outputs.tools == 'true' || needs.changes.outputs.ci == 'true' || github.event_name == 'push' }}`. `licenses`는 그대로.
- 명령줄 플래그 이름(gitleaks `git`·`dir` 하위 명령, `--log-opts`, `--gitleaks-ignore-path`, `--exit-code`, Trivy `--skip-check-update`·`--offline-scan`, `image --input`이 OCI 묶음 tar를 받는지)은 [가정]이다. gitleaks는 v8.30.1 태그의 README(`gh api repos/gitleaks/gitleaks/contents/README.md?ref=v8.30.1`)로, Trivy는 로컬 `docker run … <다이제스트> --help`로 확인하고 다르면 맞춘다. `image --input`이 OCI 묶음을 못 읽으면 묶음을 OCI 폴더로 푼 뒤 그 폴더를 준다.

### 4.6 구현 지시문에 넣을 '자주 놓친 결함'(docs/architecture.md:1129~1141)의 이 묶음 판

- **비밀 꼴 글자를 저장소에 두지 않는다**: 미끼·시험의 키는 실행 때 조각을 이어 만든다(`'gh' + 'p_' + …`). 그대로 쓰면 이 묶음의 gitleaks가 저장소를 막는다.
- **정확한 값까지 단언한다**: 막음·통과만 보지 말고 판정 보고서의 막은 결과 수, 규칙 ID, 경로, 종료 코드를 본다. gitleaks 인자는 목록 전체를 견준다.
- **경계 양쪽**: 보안 등급 7.0·6.9, 만료일 당일·다음 날, 만든 날 + 한도·한도 + 1일, 결과 0개·1개.
- **시험 값은 상수와 다르게**: 예외 한도는 인자로 30이 아닌 값(예: 12)도 넣어 본다. 판 비교가 있으면 두 자리(8.9 → 8.10) 판을 넣는다.
- **겹친 가드는 하나씩 빼 본다**: 비밀은 gitleaks 종료 코드와 판정 도구의 결과 수 두 곳에서 막는다. 하나씩 뺀 판(종료 코드만 보고 SARIF를 안 봄, SARIF만 보고 종료 코드를 안 봄)을 각각 잡는 시험을 둔다. 프로토타입 오염도 ESLint와 CodeQL 두 겹이라 서로 가리지 않게 따로 시험한다.
- **조립을 따로 본다**: 워크플로 YAML(권한·조건·`uses:` 고정)은 도구 시험과 따로 `security-scan-workflow.test.mjs`가 실제 파일을 읽어 본다. ESLint 규칙도 규칙 시험과 뿌리 설정 연결 시험을 나눈다.
- 정본 시험 표에 세부 번호를 더할 때는 '연결: …' 앞에 둔다(D-T12는 그렇게 썼다).

## 7. 소유자에게 알릴 것(조직·저장소 설정. PROGRESS에는 적지 않는다)

1. **조직 Actions 허용 목록에 Scorecard 액션 더하기**: 이 묶음이 `infra/stacks/global/github/variables.tf`의 `actions_patterns_allowed` 기본값에 `"ossf/scorecard-action@*"`을 더한다. 소유자 PC의 그 스택에서 `terraform plan`으로 바뀌는 것이 조직 Actions 정책 하나뿐인지 본 뒤 `terraform apply`를 한다(상태는 소유자 PC에만 있다, infra 안내서). `github/codeql-action`은 이미 'GitHub 소유 액션 허용'으로 된다(2026-11-10 조직 API: `github_owned_allowed: true`, 목록 `hashicorp/setup-terraform@*`뿐, `sha_pinning_required: true`). 적용 전에는 예약·수동 실행의 Scorecard 잡만 실패한다.
2. **D-T12 ② 한 번 확인**: 적용 뒤, 태그로 액션을 부른 시험 워크플로가 조직 정책으로 실패하는지 한 번 본다(방법은 소유자가 고른다. 저장소 밖 가지 푸시는 소유자 몫이다). 보면 notes 줄을 '사람 확인'으로 바꾼다.
3. **코드 스캐닝 기본 설정은 끈 채로 둔다**: 지금 '설정 안 됨'이다(2026-11-10 API). 켜면 워크플로의 CodeQL 업로드와 겹친다 [가정](GitHub는 기본 설정과 고급 설정을 함께 받지 않는다).
4. **저장소 라이선스 파일이 없다**: CodeQL 이용 조건은 오픈소스 코드 분석을 허용하는 꼴이라, 라이선스가 없는 공개 저장소가 거기에 드는지 소유자가 확인한다 [가정]. Scorecard의 'License' 점검도 0점이 된다.
5. **(선택) GitHub 비밀 검사·푸시 보호**: 공개 저장소에서 무료이고 지금 꺼져 있다(2026-11-10 API `secret_scanning`·`secret_scanning_push_protection` disabled). 켜면 커밋 전 검사가 없는 빈틈 일부를 푸시 순간에 막는다. OPEN[31] 결정 밖이라 따로 정한다.
6. **Scorecard 'Branch-Protection' 점검**: 관리자 읽기 토큰이 없으면 일부만 본다. 이 묶음은 비밀을 두지 않는다(추천). 다 보고 싶으면 토큰을 따로 정한다.
