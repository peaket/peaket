- **읽은 정본 자리**: docs/review/plans/BAT-157.md §1·§8.2 ③·§8.3, ADR-0261 결정 1~13, ADR-0267, docs/design/d5-screen-blueprint.md §6.7, docs/features/queue-admission.md §3·Q-T36 ⑦, openapi `getPartnerSalePolicy`·`putPartnerSalePolicy`·판매 자격 명단 세 경로, docs/security/asvs/catalog-review.md 8.2.1·16.3.2.
- **장부 범위**: `Q-T36 ⑦`. 화면 자체의 시험 ID는 정본에 없어 브라우저 확인과 단위 시험으로 덮고, 웨이브 끝 장부는 Q-T36 ⑦ 하나를 `--require`로 본다.
- **선행**: BAT-157의 판매 정책·명단 서버(이미 develop에 있음).

## 1. 작업 목록

1. **대기열 Redis 사본 어댑터(Q-T36 ⑦)**: `QueueSaleEligibilityCopy`. `PEAKET_QUEUE_REDIS_URL`이 있으면 core-svc가 `q:{event:E}:elig:{listKey}` SET과 `:v` 판을 직접 쓴다. 임시 키에 1만 개씩 넣고 Lua로 판이 클 때만 RENAME, 수명은 `destroy_due_at`, 지우기는 그 판 이하만. 주소가 없으면 지금처럼 `UnwiredSaleEligibilityCopy`(경고 지표).
2. **SCR-024 라이브 모드**: 소문자 UUID 공연이고 `?state=`가 없으면 `LiveSalePolicy`. 규칙 목록·종류별 폼(선예매·등급 판매 여부·취소 공제율)·JSON 읽기 전용·시뮬레이션·판매 자격 명단 올리기/지우기.
3. **시험**: `test/queue-sale-eligibility-copy.test.ts`(1만 개 배치·판 비교·빈 명단·지우기 판·수명). 화면 모델의 규칙 요약·종류 판별은 컴포넌트 안 순수 함수로 두고 웨이브 끝 브라우저 확인으로 덮는다.
4. **웨이브 끝**: Valkey 통합 시험(Q-T36 ⑦), 4관점 리뷰, 브라우저 확인(SCR-024), CI.

## 2. 정한 값(ADR-0261 결정 12~13)

- Redis 사본은 core-svc가 직접 쓴다. 주소가 없으면 늘 실패하는 어댑터로 시작하고 지표로 드러낸다.
- 화면은 규칙을 폼으로만 고치고 JSON은 읽기 전용·복사만. 시뮬레이션은 서버와 같은 `@peaket/validation/sale-policy` 함수.
- 저장은 `If-Match` 판, 412·403·409·422를 나눠 보인다. 명단 올리기는 `X-Requested-With`·8MB.

## 3. 남기는 한계

- Q-T36 ⑦의 실제 Valkey 통합 시험은 웨이브 끝에 한 번(현재는 단위 시험만).
- 규칙 폼은 1판 문법의 세 종류만 다룬다. 조건 중첩 편집기(깊이 2~3)는 d5의 후속 화면 개선으로 남긴다.
- 판매 자격 명단의 법적 성격·수집 출처 통지는 BAT-157 계획의 확인 필요 그대로다.
