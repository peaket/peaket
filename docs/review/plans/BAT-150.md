## 3. HOT-220 작업 목록

### 3.1 차례

1. 정본 빈칸은 이 계획과 함께 썼다(5장). 구현 중 새 세부가 나오면 ADR-0264에 결정을 더한 뒤 코드를 쓴다.

3. 순수 함수부터(시험과 함께 쓴다. 불변식이 아니라 업무 규칙·계산이라 함께 써도 되지만 6의 틀린 구현 검사로 모두 실패를 본다): 문서 변환(불러오기 응답 ↔ 저장소 ↔ 저장 본문, 골든 파일), 도형 수학(사각형 회전·부채꼴 꼭짓점·대칭·격자·안내선 맞춤), 채우기·다듬기 계산, 내보내기 셋, 가져오기 앞 검사, 저장 답 처리 표.
4. 저장소와 명령·되돌리기 → Worker 껍데기(요청 ID·취소·시간 한도) → Konva 층(CMP-051 폴더) → 화면 조각(도구 막대·트리·속성 패널·가격 등급·대화상자·배너) → 라이브 경로(`?state=` 없을 때) → proxy matcher.

6. 실제 서버 연결(3.4 '실제 서버까지') → 관점 넷 리뷰 → 틀린 구현 표본 검사(3.8) → 게이트(3.5) → 브라우저 확인(3.6) → 기록과 커밋.
7. 묶음 끝에 wbs 2.9.2 설명 칸의 HOT-220 실측(시간·토큰)을 적는다(ADR-0260 결정 14와 같은 꼴).

### 3.3 인터페이스

- **HTTP(화면 → gw-partner → core-svc)**: `GET`·`PUT /v1/partner/productions/{productionId}/seatmap`(docs/api/openapi.yaml:4660~4663), `POST …/seatmap-imports`(4664~4665). 답과 화면 동작은 ADR-0264 결정 8·9. 이 계획이 더한 계약 칸: `SeatMapShape.arc`·`SeatMapShapeArc(Input)`(openapi.yaml:1917~1931), `SeatMapLayout.geometryLocked`(1961), `SeatMapLayout.warnings`·`SeatMapWarning`(HOT-230, 2113). 저장 본문은 `SeatMapLayoutInput`(닫힘)이라 응답 전용 칸을 실으면 400이다.
- **저장소**: 문서(캔버스·무대·구역 표·구역 차례·구역별 좌석 배열·가격 등급), 판(`ETag`), 화면 상태. 명령 목록과 되돌리기 규칙은 ADR-0264 결정 4. 캔버스는 React 밖에서 구독해 바뀐 구역의 노드만 고친다(frontend §3.9).
- **Worker 메시지**: ADR-0264 결정 5. `ToWorker`·`FromWorker`는 Zod로 모양을 본다(`@peaket/seatmap`의 protocol.ts 꼴). 계산 함수는 `model/fill.ts`·`refine.ts`·`export.ts`이고 Worker는 그것을 부르기만 한다.
- **Konva 층**: ADR-0264 결정 3. 좌석 층은 구역마다 `Shape` 하나, 듣지 않음. 좌석 찾기는 `@peaket/seatmap`의 `buildGrids`·`hitTest`(packages/seatmap/src/grid.ts).
- **미리보기**: 편집 문서를 `SeatMapColumns`로 바꾸는 함수(모델, core-svc `fanFile`과 같은 규칙: services/core-svc/src/modules/catalog/domain/seatmap-layout.ts:238)를 두고 `decodeLayout`(packages/seatmap/src/layout.ts:79)을 지난 값을 그리기 엔진(`SeatMapEngine`, 메인 스레드)에 준다. `createSeatMap`은 파일 주소를 받아 `blob:` 주소가 CSP `connect-src`에 걸리므로 쓰지 않는다 [확인 필요].

- 확인 못 할 것: 파일 대화상자를 거치는 실제 파일 고르기(HOT-190과 같다, Playwright가 본다), 공연 이름 머리(HOT-260 전), 운영 게이트웨이·로그인(BOT-132 전).
- 콘솔·요청 오류와 Trusted Types 보고(`/_t/csp`로 가는 보고 머리)를 함께 남긴다. Konva의 `innerHTML = ""`가 보고되면 frontend §5.6 '확인 필요' 줄에 결과를 적는다.

### 3.7 구현 지시문에 넣을 '자주 놓친 결함'(docs/architecture.md:1129~1141)의 이 묶음 판

- 저장·불러오기 답은 정확한 값까지 단언한다: 판(`ETag`), 서버 색인, 서버 좌석 ID로 갈아끼운 뒤의 좌석 수·좌표, 변경 수 0, 되돌리기 기록 0. 채우기는 좌석 수·첫 행 좌표·번호 차례를 정확히 본다.
- 지우는 명령(지우기·통로 만들기·지우고 채우기·문서 바꾸기)은 건드린 구역의 좌석 배열과 고른 것·격자 색인·트리 줄을 모두 다시 본다.
- 경계 양쪽: 되돌리기 200·201, 가격 등급 16·17, 본문 12MiB 정확히·1바이트 넘음, 가져오기 파일 10MB 정확히·1바이트 넘음, Worker 9,999ms·10,000ms, 배율 0.02·8, 빈 구역 하나, 좌석 0인 문서 저장.
- 계정 대조를 뺀 요청: 실무자의 승인 뒤 저장(403)과 다른 테넌트 공연(404)을 화면이 서버 답대로 보이는지. 화면이 역할을 짐작해 단추를 숨기는 것으로 끝내지 않는다(서버가 최종).
- 화면의 저장값: 저장 실패(412·409·422·503) 뒤 문서·변경 수·되돌리기 기록이 그대로이고, 새로고침하면 떠나기 확인을 거친다. 브라우저 저장소에는 아무것도 남지 않는다.
- 첫 JS 예산을 로컬 운영 빌드에서 잰다(⑬, R-439).
- 시간 한도(Worker 10초)는 가짜 시계로 한도 − 1ms와 한도를 재고, 단언 값은 정본(ADR-0264 결정 5)의 값을 적는다.
- 겹친 가드는 하나씩 빼 본다: 화면의 잠금 끄기와 서버 409(화면이 잠금을 놓쳐도 서버가 막는지), 화면의 12MiB·10MB 검사와 서버 413(화면 검사를 빼도 서버 답을 문구로 보이는지), 화면의 등급 검사와 서버 `TIER_UNKNOWN`.
- 시험 값은 상수와 다르게: 판 번호는 9 → 10을 지나게, 가격 등급 수·채우기 목표는 기본값과 다르게.
- core-svc의 `geometryLocked`·`arc` 조립은 운영 시작 파일(`dist/main.js`)로도 한 번 띄워 본다(BAT-195).
- 정본 시험 표에 세부 번호를 더하면 '연결: …' 앞에 둔다(이 계획의 FE-T38·FE-T46·S-T40은 그렇게 썼다).

## 6. 물을 것과 감독에게 넘길 것

### 6.1 물을 것(정하지 않았다, 또는 확인)

1. **나누기**: 1장 추천(BAT-150 = HOT-220, BAT-151 = HOT-230). 더 작게면 1.1 끝의 BAT-153 안.
2. **(확인) 자동 임시저장을 없앤 것**(G1): frontend §3.9·§5.6의 추천 적용을 바꿨다. 소유자가 자동 임시저장을 꼭 원하면 대안은 브라우저 임시저장(IndexedDB)인데, 파트너 로그아웃 때 지우는 길(FE-T13)이 아직 없어 인증 뒤 받은 배치를 브라우저에 남기게 된다(asvs/frontend.md 14.3.1). 되돌릴 조건은 ADR-0264 '결과'.
3. **(확인) 작업 공간 의존 더하기**: HOT-220은 `apps/partner` → `@peaket/seatmap`, HOT-230은 `apps/partner` → `@peaket/validation`(하위 경로 `./seatmap-checks`)이다. 외부 패키지가 아니고 BAT-157·HOT-180과 같은 꼴(잠금 파일 importers 손질, 접합점)이라 허락을 전제로 계획했다. 안 되면 미리보기·격자 색인을 파트너 안에 새로 쓰고(중복), 경고 검사기를 화면·서버에 두 벌 둔다(같은 검사기 규칙 ADR-0257 결정 8을 어긴다).
4. **(확인) 계약 깨짐 예외 한 줄**: `SEAT_OUTSIDE_SHAPE`를 가져오기 응답 열거에 더한 것은 oasdiff가 깨짐(ERR)으로 본다. 예외 파일에 이유를 적어 검사는 통과하지만, README대로면 PR에는 `breaking-approved` 라벨 몫이다(develop 직접 푸시 흐름에서는 커밋 본문에 적는다).
