### 7. 차례

1. 구현 ①: 계약 고침과 생성물(contracts·api-client gen) → identity-svc 서버 몫(0038, 스캐너 세션 두 경로, 초대 고침) → `pnpm --filter @peaket/identity-svc typecheck`·`test`.
2. 구현 ②: 웹 공용(`staff-fragment`, `event-summary`) → 세 스태프 화면 → 설정 화면 스태프 줄 → 게이트웨이 대역 → `pnpm --filter @peaket/web` 타입 검사·`test`, `pnpm lint`.
3. 시험(구현을 맡지 않은 담당): §6 표, 기존 I-T21 ⑫ 단언 고침, §8 연결 시험.
4. 리뷰(짧은 대조, B 짧은 고리) → 검증(틀린 구현 표본 최소 6개, §9) → 게이트(§10) → 기록.
- 커밋마다 `Role`·`Agent-Session`·`Batch: F-05-7`(모델을 알면 `Agent-Model`). 구현 커밋은 시험 파일을 바꾸지 않는다. 시험 결과로 드러난 구현 결함은 구현 커밋, 시험 결함은 시험 커밋으로 고친다.

### 8. 실제 서버 연결(§8.6 4의 4)

가짜 API로 끝내지 않는다. 앞선 예(`services/payment-svc/test-int/purchase-path-e2e.int.test.ts`의 웹 스크립트 동적 가져오기, `services/core-svc/test-int/local-partner-stack.int.test.ts`의 게이트웨이 대역·`PEAKET_LOCAL_STACK=1`, BAT-200 계획 §3.4)를 따른다.

- **파일**: 새 `services/identity-svc/test-int/staff-screens-wiring.int.test.ts`(시험 담당). identity-svc 통합 시험이라 CI `ci-node.yml`의 `pnpm --filter @peaket/identity-svc test:integration`에서 돈다.
- **띄우는 것**: 실제 PostgreSQL 18(`test-int/postgres.ts`, 마이그레이션 0038까지), 실제 Valkey(`test-int/valkey.ts`, 기기 승인 요청 저장소), identity-svc HTTP 앱(시험 조립, 실제 Drizzle·Redis 어댑터. 기기 원장 조회만 대역), 웹의 로컬 게이트웨이 대역(`apps/web/scripts/local-fan-gateway.mjs`를 `/* @vite-ignore */ new URL(…)`로 동적 가져오기, identity 앱 주소·공개키 묶음 주소를 준다).
- **화면 쪽**: 웹 흐름 모듈(`apps/web/src/features/staff-invitation/flow.ts`·`staff-approval/flow.ts`·`device-sessions/flow.ts`, `entities/staff-assignment`의 배지 계산)을 같은 방식으로 동적 가져와, 팬 액세스 쿠키(시험이 만든 팬 토큰 키로 서명)를 실은 `fetch`로 게이트웨이 대역을 부른다. identity-svc의 tsconfig가 `.ts` 확장자 가져오기를 받지 않으므로 정적 `import`를 쓰지 않는다.
- **씨앗**: 계정·본인확인 기록·초대 두 건(토큰 해시)·승인 요청(Valkey, `RedisDeviceAuthorizations.save`)을 시험이 넣는다. 재인증 토큰은 시험의 팬 토큰 키로 `op` `SCANNER_SESSION_END`를 실어 만든다(재인증 검증기와 같은 규칙).
- **대본**: 초대 조회 → 수락 → 내 배정 `ASSIGNED`(I-T91 ⑥) → 다른 초대 거절 → DB `EXPIRED`·이메일 없음(I-T91 ⑥) → 승인 조회 → 승인 → `scanner_session` 하나·`device_name`(I-T92 ④) → 내 배정의 `activeScannerDeviceName`·배지(I-T93 ④, 해제한 배정은 해제) → 스캐너 세션 목록 한 줄 → 끝내기 → `CheckScannerSession` 거절(I-T90 ⑤).
- **실제가 아닌 것(커밋 본문·검증 절에 적는다)**: 회차 공개 요약 `GET /v1/events/{eventId}`는 core-svc 공개 데이터라 이 시험에서는 게이트웨이 대역의 `fallbackUrl`로 가짜 API(`apps/web/scripts/mock-api.mjs`)가 답한다(씨앗 회차 ID는 가짜 API에 있는 회차). 기기 원장(ticket-svc gRPC)은 대역이다. Kafka 발행은 Outbox 행까지 보고, 이 PC에서는 Kafka 통합을 돌리지 못한다(갈래 메모: 네이티브 모듈 차단, CI 몫).
- **브라우저 확인용**: 같은 파일을 `PEAKET_LOCAL_STACK=1`로 돌리면 스택을 띄운 채 두고 주소와 씨앗 링크(`/staff/invitations#token=…`, `/staff/approve#code=…`)를 찍는다(core-svc 지역 스택 시험과 같은 꼴). 컨테이너 이름 머리는 `lane3-f057-`, 끝나면 `docker rm -f -v`.

### 9. 틀린 구현 표본(검증 담당, B는 표본으로 실패를 본다)

최소 6개, 관련 시험만 돌리고 `git checkout -- <파일>`로 되돌린다. 후보:
1. 끝내기가 재인증보다 먼저 세션을 찾아 404일 때 토큰을 쓴 것으로 적음(I-T89 ⑤).
2. 끝내기가 `op`를 보지 않음(`SESSION_END` 토큰 통과, I-T89 ③).
3. 목록이 `expires_at >= now`를 살아 있다고 봄(정각 경계, I-T89 ②).
4. 사건을 트랜잭션 밖에서 쓰거나 사유를 다르게(I-T89 ④).
5. 고지 판을 옛 값으로 두거나 화면이 고정 문구를 보임(I-T91 ①⑤).
6. 회차 공개 요약 실패에도 [수락]이 켜짐(I-T91 ③).
7. 배지 계산의 `<`/`<=` 뒤바꿈(I-T93 ①).
8. 조각을 지우지 않거나 `next`에 조각을 실음(I-T47).
9. 스캐너 범위 표시가 `DELETE /v1/identity/sessions/…`로 감(I-T90 ③).
10. 게이트웨이 대역이 스태프 경로를 넘기지 않음(연결 시험 전체).

### 13. 남는 위험
