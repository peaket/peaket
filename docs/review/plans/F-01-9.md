- **무엇**: 기능 F-01-9(docs/BUILD_ORDER.md:54)의 작업 목록이다(docs/architecture.md §8.6 4의 1·2, ADR-0354). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다. 정본 값은 옮겨 적지 않고 자리(문서:줄, 이 커밋 기준)만 가리킨다.

## 감독에게

막는 물음은 없다. 1은 동결 범위 확인, 2~5는 알림이다.

1. **[확인] 동결 로컬 범위.** F-01-9는 v1 출시 범위 밖이다(ADR-0386). 이 계획은 로컬 설정·단위 시험·Docker 통합 시험까지다. `deploy/`의 출시 환경 값·Helm 차트·Argo CD·클라우드 배포는 건드리지 않고, `docs/release/v1-scope.*`의 분류도 바꾸지 않는다(BUILD_ORDER 상태 `동결` 유지).
2. **[알림] 장부 범위는 V-T50 ⑧⑨ 둘이다.** 이미 F-01-4가 범위를 그 둘로 좁혀 두었다. `docs/review/ledger-notes.md`의 'F-01-4에서 뗀 몫' 표 두 줄(다른 단계)은 이 기능이 가져가므로 지운다(계획 커밋). 시험이 생기면 둘 다 자동 시험이 된다.
3. **[알림] 남는 한계 둘.**
   - 게이트웨이를 지나는 진입 경로(gw-queue)의 머리 표본 trace에는 exemplar를 달지 않는다. 정본 F-01-4 계획 '감독에게' 1이 정한 세 조건(정상 표본에 든 요청·5xx·SLO 지연 초과)만 따른다. 머리 표본을 더하려면 V-T50 ⑧의 판정 기준을 먼저 고친다.
   - 로컬 Grafana에는 Tempo·Loki가 없어(tools/local/cluster.mjs는 datasources.yaml만 싣는다) exemplar·로그 연결이 로컬 화면에서 닿지 않는다. 연결 설정의 정적 검사와 Docker 통합 시험이 그 자리를 대신한다.
4. **[알림] 게이트웨이 수집기의 클러스터 이름 원천.** 에이전트가 붙이는 자원 속성 다섯(§2 '신호 연결')에는 클러스터 이름이 없다. 그래서 게이트웨이 수집기가 환경 변수 `PEAKET_CLUSTER`를 `cluster` 라벨 값으로 쓴다(배포가 넣는다, INF-020). 로컬 Docker 시험은 이 변수를 넣어 값을 단언한다. 정본 §1 Loki 줄과 수집기 README에 적는다.
5. **[알림] F-01-3·F-01-4의 고정 시험은 고치지 않는다.** `tools/ci/collector-config.test.mjs`·`tools/ci/observability-stores.test.mjs`의 단언은 그대로 두고, 새 규칙은 도구의 `--check`에 더한다. 새 시험은 새 파일(`packages/platform/test/exemplar.test.ts`, `packages/platform/test-int/prometheus-exemplars.int.test.ts`, `packages/platform/test-int/gateway-loki-labels.int.test.ts`, `tools/ci/observability-signals.test.mjs`)에 둔다. 기존 `metrics.test.ts`의 `/metrics` content-type 단언 한 줄만 OpenMetrics로 바꾼다(정본 §2가 이미 OpenMetrics 노출을 적고 있다).

## 계획

### 1. 범위

- **E1 서비스 템플릿 exemplar**: `packages/platform`의 지연 히스토그램(`http_server_request_duration_seconds`)에 OpenMetrics exemplar(`traceId`·`spanId`)를 단다. 조건은 정본이 정한 셋뿐이다: 정상 표본에 든 요청(`peaket.sample.keep` 참), 5xx, SLO 지연 초과(`peaket.slo.exceeded` 참). 표본에 들지 않은 정상 요청에는 달지 않는다. 지표 노출은 OpenMetrics 형식으로 바꾼다(§2 'SLI 실시간 산출').
- **E2 로컬 Prometheus exemplar 저장**: `deploy/local/observability.yaml`의 Prometheus 인자에 `--enable-feature=exemplar-storage`가 있는지 시험이 견준다(이미 켜져 있다. 회귀를 막는 것이 이 몫이다).
- **E3 게이트웨이 수집기의 Loki 라벨 넷**: `deploy/platform/observability/collector/gateway.yaml`의 로그 파이프라인에 `transform/loki-labels` 처리기를 더해 자원 속성 `k8s.namespace.name`→`namespace`, `service.name`→`service`, `deployment.environment`→`env`, 환경 변수 `PEAKET_CLUSTER`→`cluster`를 복사한다. 2차 마스킹 뒤·묶기 앞에 둔다. 로컬 판은 내보내기만 바꾸므로 처리기 목록은 운영 판을 그대로 쓴다.
- **E4 Loki↔Tempo 연결**: `deploy/platform/observability/grafana/provisioning/datasources-platform.yaml`의 Loki 데이터 소스에 traceId 파생 필드 → Tempo, Tempo 데이터 소스에 `tracesToLogsV2` → Loki(같은 traceId)를 더한다.
- **정적 검사**: `tools/ci/collector-config.mjs --check`에 E3 규칙, `tools/ci/observability-stores.mjs --check`에 E4 규칙을 더한다. 새 도구·새 CI 단계는 만들지 않는다(이미 tools-check에 두 단계가 있다).
- **어림**: 구현 0.75일 [가정](E1 0.35, E2 0.05, E3 0.15, E4 0.1, 정적 검사 0.1)과 시험 0.5일로 1.25일 안팎이다. BUILD_ORDER의 어림과 같다.

### 3. 바른 동작과 근거(값은 정본에서 읽는다)

- **exemplar를 다는 조건**(docs/verification.md:671 V-T50 ⑧, docs/observability.md:138, F-01-4 계획 '감독에게' 1): 요청이 끝날 때(응답을 보낸 뒤) 그 요청의 지연 히스토그램 관측에만 붙는다. 붙이는 조건 셋은 ⑴ `sample.thresholdKeep`가 참(정상 표본, ADR-0125 결정 3) ⑵ 응답 상태 5xx ⑶ 그 경로의 SLO 지연 초과(`peaket.slo.exceeded`, F-01-3이 `onSend`에서 서버 span에 다는 것과 같은 판정). 조건 밖(표본에 들지 않은 2xx·3xx·4xx)에는 붙이지 않는다.
- **exemplar 값**: 라벨 이름은 `traceId`·`spanId`(docs/observability.md:138·:671, §8 표준 칸 목록과 같은 문서). `traceId`는 요청 맥락의 trace ID(32자리 16진수), `spanId`는 OTel 서버 span이 있을 때 그 값(16자리). 서버 span이 없으면 `traceId`만 단다(빈 spanId 라벨을 만들지 않는다).
- **노출 형식**: `@prometheus-io/client` 0.16.1의 exemplar는 OpenMetrics 형식에서만 나온다(README 'Exemplars'). 그래서 서비스 지표 레지스트리의 content type을 OpenMetrics로 두고, 관리 포트 `/metrics`가 그 content type을 그대로 알린다. 지표 이름·라벨·칸은 바꾸지 않는다. Prometheus는 OpenMetrics를 그대로 긁는다(§2가 이미 '지표는 OpenMetrics로 낸다'고 적는다).
- **로컬 Prometheus**: `deploy/local/observability.yaml`의 인자에 exemplar 저장을 켜는 `--enable-feature=exemplar-storage`가 있어야 한다(docs/observability.md:290 '보존은 2일, exemplar 저장을 켠다').
- **게이트웨이 Loki 라벨**(docs/observability.md:124·:578, ADR-0076 결정 7): Loki가 색인하는 자원 속성은 `namespace`·`service`·`env`·`cluster` 넷뿐이다. 그 값을 다는 쪽은 게이트웨이 수집기다. 에이전트가 붙이는 자원 속성 다섯 가운데 셋을 그대로 복사하고, 클러스터 이름은 에이전트에 없으므로 게이트웨이 수집기의 환경 변수 `PEAKET_CLUSTER`를 쓴다. 처리기는 로그 파이프라인에만 두고, 차례는 `memory_limiter → transform/pii → transform/loki-labels → … → batch`다(2차 마스킹이 끝난 값을 색인한다). 추적 파이프라인에는 두지 않는다(Loki로 가지 않는다).
- **Loki↔Tempo**(docs/observability.md:127·:140): Loki 데이터 소스의 파생 필드 하나가 로그 줄의 `traceId`를 정규식으로 뽑아 Tempo 데이터 소스로 잇는다. Tempo 데이터 소스는 `tracesToLogsV2`로 같은 trace ID의 로그를 Loki에서 찾는다. 둘 다 같은 조직(orgId 1)의 데이터 소스를 가리켜야 한다. 로그 줄 꼴은 정규 로그 줄(§7)의 Pino JSON `traceId` 필드다.
- **정적 검사가 막는 것**: 라벨 처리기가 없거나·넷 밖 라벨을 더하거나·원천 속성이 틀리거나·클러스터 이름 변수가 빠지거나·로그 파이프라인 차례가 틀리면 `collector-config --check`가, Loki 파생 필드나 Tempo 로그 연결이 없거나 다른 데이터 소스를 가리키면 `observability-stores --check`가 막는다. 막음 줄은 `<파일>: <까닭>` 하나씩이다.

### 5. 공개 인터페이스(시험 담당이 이 모양으로 시험을 먼저 쓴다. 구현은 이 이름을 그대로 쓴다)

- **서비스 지표**: 관리 포트 `/metrics`의 content type은 `application/openmetrics-text`로 시작한다. `http_server_request_duration_seconds_bucket` 줄 뒤에 exemplar 줄이 붙을 수 있고, exemplar 라벨 이름은 `traceId`·`spanId`다(둘째는 서버 span이 있을 때만). 새 공개 함수는 없다. `PlatformMetrics.requestDuration`은 exemplar를 켠 히스토그램이다.
- **수집기 처리기 이름**: `transform/loki-labels`. 로그 파이프라인 처리기 목록은 `[memory_limiter, transform/pii, transform/loki-labels, batch]`다. 처리기 안의 문장은 넷이고, 각각 `set(resource.attributes["<라벨>"], resource.attributes["<원천>"])` 꼴이다. `cluster`만 `set(resource.attributes["cluster"], "${env:PEAKET_CLUSTER}")`다.
- **Grafana 설정 키**: Loki `jsonData.derivedFields`의 항목 하나에 `name: traceId`, `matcherRegex: '"traceId":"([0-9a-f]{32})"'`, `datasourceUid: tempo`. Tempo `jsonData.tracesToLogsV2`에 `datasourceUid: loki`, `filterByTraceID: true`, `tags: [{ key: service.name, value: service }, { key: k8s.namespace.name, value: namespace }]`.
- **시험 도우미(시험 담당이 고친다)**: `packages/platform/test-int/collector.ts`의 `startGateway`에 `extraConfig?: string`(마지막 `--config`로 넣을 글)·`env?: Record<string,string>`(컨테이너 환경 변수)를 더한다. `packages/platform/test-int/observability-stores.ts`의 `startLoki(configText, network?, alias?)`에 셋째 인자(네트워크 별칭)를 더하고, `startContainer`에 `runArgs?: string[]`(`docker run`의 `--add-host` 같은 플래그)를 더한다. 기존 호출은 그대로 돈다.

### 9. 자주 놓친 결함(docs/architecture.md §8.6 4의 목록에서 고름, 시험·구현 지시문에 넣는다)

- 허용 목록은 목록 밖 값마다 본다: Loki 라벨은 하나 더함·하나 뺌·원천 속성 바꿈을 따로 단언하고, 파생 필드·로그 연결도 uid를 바꾼 경우를 둔다.

- 설정 원천과 실제 판이 다르면 원천이 이긴다: 로컬 판은 운영 판의 처리기·한도를 덮지 않는다(기존 시험이 본다).

### 11. 범위 밖과 막힘

- **배포**: Mimir·Loki·Tempo·Grafana·수집기의 실제 배포, `PEAKET_CLUSTER` 환경 값, Loki 메시 정책, 로컬 클러스터 반영은 INF-020·INF-040이다(ADR-0331 결정 9). 동결 가지는 클라우드·`deploy/envs` 출시 값을 건드리지 않는다.
- **로컬 Grafana의 Tempo·Loki**: `tools/local/cluster.mjs`는 `datasources.yaml`만 싣고 Tempo·Loki를 로컬에 띄우지 않는다. 그래서 exemplar 연결·로그 연결은 로컬 화면에서 눌러 보지 못한다. 정적 검사와 Docker 통합 시험이 그 몫을 대신한다.
- **머리 표본 진입 경로의 exemplar**: 감독에게 3.
- **F-01-8(접근 로그 두 갈래)**: 동결이라 이 기능은 일반 로그 꼴만 다룬다. 게이트웨이 접근 로그 줄의 `traceId` 파생 필드는 같은 설정으로 닿지만 실제 파일 수집은 F-01-8 몫이다.
- **알림 규칙**: exemplar·Loki 라벨의 경보는 F-01-5·F-01-10(동결) 몫이다. 이 기능은 규칙을 더하지 않는다.
