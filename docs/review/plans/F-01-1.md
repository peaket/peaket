## 감독에게

막는 물음은 없다. 아래는 추천대로 정본에 적었다. 다르게 정하면 이 계획과 그 정본 줄을 고친다.

1. **[확인] 시간 단가를 49,538원으로 고정했다**(perf-ledger.md:707). 한국소프트웨어산업협회 '2025년 적용 SW기술자 평균임금'(2024-12-04 공표)의 전체 평균 일평균임금 ÷ 8시간이다. 2026년 적용 공표는 금액 원문을 찾지 못해 쓰지 않았고, 운영 직무(정보시스템운용자) 값은 월평균만 확인돼 쓰지 않았다. 소유자가 다른 기준(예: 운영 직무 값, 2026년 값)을 원하면 그 줄 하나만 바꾸면 된다. 판정은 4.8.2에서 0.5~1.5배 민감도와 함께 하므로 이 기능의 시험은 값 자체가 아니라 '§11.5에서 읽은 값을 쓴다'를 본다.
2. **[결정 요청, 범위 밖] 인시던트 선언을 수집기에 보내는 쪽이 없다.** ADR-0070 결정 1은 인시던트 선언도 수집 계기로 두지만, 선언은 관제 콘솔(ops-svc)에서 한다. 수집기는 경보 이름 `IncidentDeclared`를 받으면 모든 대상을 뜨게 만들어 두고(observability.md:423), ops-svc가 선언 때 그 꼴로 보내는 연결은 인시던트 선언을 만드는 기능(관제 쪽, ADR-0373으로 동결된 F-03-4 감사 화면 근처일 수 있다)에 붙여야 한다. 맡을 기능을 정해 그 행 비고에 한 줄 더해 달라.
3. **[알림] 배포 몫은 INF-020으로 넘긴다**(ADR-0331 결정 9, ADR-0373 결정 1). 기록 커밋에서 INF-020 줄 끝에 넘긴 것을 적어 달라: 증거 버킷(공개 차단·버전 관리·SSE-KMS·`lifecycle.json`을 그대로 싣기)과 태그 없는 쓰기를 거부하는 버킷 정책, 서비스 역할의 객체 태그 쓰기 권한, 수집기 배포(플랫폼 네임스페이스·복제 1·NetworkPolicy는 delivery.md:96 그대로)와 `pg_monitor` 역할·Redis 세 명령 사용자, Alertmanager 수신 설정(웹훅 주소·Bearer 토큰, SEV1·원인 SEV2만 보내는 경로), 배포 뒤 확인(observability.md:259~260 마지막 칸). 경보 규칙 둘(수집 실패·거절, :259)은 F-01-5(OPS-100), 증거 수집기 패널은 F-01-4(OPS-080) 비고에 한 줄씩 더해 달라.
4. **[알림] `packages/platform`을 고친다**(증거 저장소에 보존 태그와 바이트 올리기). node 잡이 전체를 돈다(지시서 §6). 바꾸는 것은 더하기뿐이라 다른 서비스의 동작은 같고, 기존 진단 수집(D-T18 ①)이 올리는 객체에도 태그가 붙는다.

## 계획

### 1. 범위

- **P1 증거 수집기(새 서비스 `services/evidence-collector`)**: Alertmanager 웹훅을 받아 고른 경보의 의존성(PostgreSQL·Redis) 순간 상태를 떠 진단 증거 저장소에 올린다. 동작은 observability.md:422~426.
- **P2 진단 증거 보존 규칙**: 수명 주기 규칙 원천 `infra/modules/evidence-bucket/lifecycle.json`, 그 원천이 §9 행과 같은지 보는 정적 검사 `tools/ci/evidence-retention.mjs`, 올리는 쪽이 모든 객체에 보존 태그를 다는 것(`packages/platform`). 동작은 observability.md:592. 실제 버킷은 만들지 않는다(클라우드 계정 없음, INF-020).
- **P3 직접 운영 시간 기록(새 파일은 이 기능에서 만들 예정)**: 기록 파일 `docs/perf-ledger/ops-hours.csv`(머리 줄만으로 시작), 검사·요약 `tools/perf-ledger/ops_hours.py`, 시간 단가 고정. 형식은 perf-ledger.md:707~708.

### 3. 바른 동작과 근거(값은 정본에서 읽는다)

- **웹훅**: `POST /internal/v1/alerts`, Alertmanager 기본 웹훅 형식(판 4: `version`·`status`·`alerts[]`의 `status`·`labels`·`annotations`·`startsAt`·`fingerprint`), `Authorization: Bearer <PEAKET_EVIDENCE_WEBHOOK_TOKEN>`, 바로 202, 수집은 답한 뒤(observability.md:422). 토큰 비교는 `@peaket/platform`의 `constantTimeEqual`(공용 `InternalTokenGuard`는 거절을 남기지 않으므로 수집기는 자기 가드를 둔다). 401·400은 플랫폼 Problem 응답 꼴. 처리기는 `@Roles(['public'])`이라 제어 토픽 소비(`startServiceControlSync`)가 없어도 듣는다(packages/platform/src/service.ts:341).
- **고르기·간격**: :423. 라벨 값은 소문자 `sev1`·`sev2`(deploy/platform/observability/alerts/realtime-gw.yaml:22 꼴), `kind`는 observability.md §5의 값. 간격 10분은 대상마다, 겹침 없음, 메모리에만.
- **뜨기**: :424. PostgreSQL 세 질의는 읽기 전용 트랜잭션 하나, `statement_timeout`, 자기 세션 뺌, 클라이언트 주소 칸 없음. Redis는 세 명령만(그 밖의 명령을 보내면 제한 사용자로 실패한다). 한 가지 실패는 `partial`, 접속 실패는 `failed`이고 `manifest.json`만 올린다(devops.md:949 ⑥).
- **올리기**: :425. 객체 이름 꼴, 파일 목록, `manifest.json`에 실을 것과 싣지 않을 것(경보 설명 글), 보존 태그. 수집기 접두사는 `evidence-collector/`(서비스는 자기 접두사에만 쓴다, observability.md:592).
- **신호**: :426과 운영 확인 표 :259. 지표 라벨 `target`은 설정한 대상 이름뿐이라 개수가 묶여 있다(§8 카디널리티).
- **보존 규칙**: :592. 원천 파일은 S3 `PutBucketLifecycleConfiguration`의 JSON 꼴(`{"Rules":[…]}`, AWS CLI `--lifecycle-configuration file://`이 받는 꼴)이다. 규칙 셋: `standard` 태그 → §9의 보존 일수, `hold` 태그 → §9의 연장 일수, 빈 앞머리(`{"Prefix": ""}`) → 이전 판 지우기·남은 조각 지우기·남은 삭제 표시 치우기. 모두 `Enabled`. 다른 저장 등급으로 옮기는 규칙(`Transitions`·`NoncurrentVersionTransitions`)은 두지 않는다.
- **보존 태그**: 플랫폼 증거 저장소가 `put`·`putBytes` 모두 `Tagging`(머리 `x-amz-tagging`)에 §9의 `standard` 태그를 싣는다. 태그 문자열은 플랫폼 상수 하나에 두고 수집기·진단 수집이 같은 저장소를 쓴다.
- **운영 시간 기록**: perf-ledger.md:708(열·값 범위·검사 명령), 시간 단가 :707. 기록이 없으면 '기록 없음'이고 비용을 0원으로 내지 않는다(verification.md:666 ②).

### 5. 공개 인터페이스(시험 담당이 이 모양으로 시험을 먼저 쓴다. 구현은 이 이름을 그대로 쓴다)
