# 기능 계획: F-08-3(MSR-030·MSR-080 — M6 블로그·용량 산정서·비용 리포트·DORA 추세)

- **진행**: 계획·시험(측정 대조) 끝(2026-11-26). 다음은 새 세션 리뷰다. 구현·문서 작성은 리뷰 지적을 반영한 뒤에 시작한다. 이 세션은 리뷰를 받을 준비에서 멈춘다.
- **무엇**: BUILD_ORDER '기능 단위 계획' F-08-3(갈래 4, 등급 B, MSR-030·MSR-080, WBS 3.50일, 단계 줄 `MSR-030 wbs 6.1.2`·`MSR-080 wbs 6.4.1`, 측정 창 4)의 작업 목록이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **쉬운 말**: 이 기능은 새로 부하를 걸지 않는다. 이미 끝난 두 측정(F-08-2의 100만 외삽·진입 서버 비례, F-08-8의 K1·K2·K7 After)을 읽어서 ① 기술 블로그 M6 한 편의 초안, ② 용량 산정서, ③ 비용 리포트, ④ DORA 추세 보고서를 만든다. 새 숫자를 만들지 않고, 잰 것과 못 잰 것을 구분해 적는 것이 핵심이다.
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-08-3`, 가지 `freeze/lane4-F-08-3`, 출발 `origin/feature/lane4-F-08-2-refresh` = `19b33ba85`(F-08-2 측정 보고서 포함). 동결 트랙이라 `develop`·`release/1.0.0`에 합치지 않는다(ADR-0386 결정 4).
- **차례**: F-08-3은 B등급이지만 이번 동결 트랙에서는 소유자 지시로 **계획 → 시험(측정 대조) → 리뷰(새 세션) → 지적 반영 → 구현/문서 → 기록**으로 돈다. ADR-0373의 B등급 차례(계획 → 시험 → 구현)에 리뷰를 더한 것이다. 리뷰 담당은 계획·시험·구현을 맡지 않은 새 세션이고, 구현 담당은 시험을 고치지 못한다.
- **한 줄 결론**: 이 기능의 일은 새 측정이 아니라 **인용과 경계 짓기**다. F-08-2·F-08-8 보고서와 정본의 설계 목표를 한 곳(사실 대장)에 모으고, 그 값만 보고서에 쓰게 하는 정적 시험을 먼저 만든다. 새 수치 주장·Docker·kind·k6는 없다.

## 2. 감독에게(정할 것과 이 계획의 답)

1. **새 측정을 하지 않는다(이 계획의 답)** — F-08-3은 '측정 창 4'에 적혀 있지만, 실제로는 이미 끝난 창 1·2의 결과를 읽어 보고서를 쓰는 기능이다. Docker·kind·k6·Docker 잠금을 쓰지 않는다. 새 측정이 필요하면 그건 F-08-2·F-08-8·F-08-4의 몫이거나 새 창이다.
2. **산출물은 정본이 아니라 검토 기록에 둔다(추천)** — 용량·비용·DORA 보고서는 `docs/review/measurements/`에, M6 초안은 `docs/blog/`에 둔다. `docs/infra.md` §11·`docs/infra-handover.md` §9·`docs/verification.md`의 정본 값은 고치지 않고, 보고서 안에 '동결 해제 뒤 정본에 반영할 제안'으로만 적는다. 동결 트랙에서 정본을 고치면 출시 뒤 `develop`과 충돌하고, ADR-0386 결정 4의 '출시된 코드를 동결 가지로 되돌리지 않는다'에 어긋나기 쉽다.
3. **DORA는 '추세 판단 불가'가 정직한 답이다(정할 것)** — DORA 값은 GitHub Deployment 기록(Argo CD 알림)에서 나온다. 이 동결 로컬 트랙에는 배포 기록이 없고, GitHub API를 부르지 않는다. 그래서 주별 표를 `자료 없음`으로 채우고 '추세 판단 불가'라고 적는다. 0으로 채우거나 잠정 추세선을 그리지 않는다. 감독이 실제 배포 기록 파일을 주면 그때 값으로 바꾼다.
4. **비용은 전부 [추정]이다(이 계획의 답)** — 단가는 `docs/infra.md` §11의 2026-10-28 표만 쓴다. 새 가격 조회·AWS 청구서·Cost Explorer·OpenCost는 이 트랙에 없다. CloudFront 요청 단가처럼 정본에 단가가 없는 항목은 계산하지 않고 '단가 없음: 미계산'으로 적는다.
5. **200만은 설계 목표이지 측정값이 아니다(이 계획의 답)** — NFR-021·architecture §9.5의 200만·250만·300만, 합산 동시 입장 1만·1.25만·1.5만은 설계 목표다. F-08-2의 100만 외삽을 2배 하는 식으로 '200만 외삽'을 새로 만들지 않는다. 200만은 '한 공연 100만 + 중형 50만 × 2'라는 여러 공연 합산 시나리오이고, 공연 하나의 진입 폭주(20만 RPS)와 다른 축이다.
6. **M6는 F-08-7의 숫자 카드 다섯 개만 쓴다(이 계획의 답)** — M6 초안은 F-08-7 계획 §6.3의 카드 1~5 밖의 숫자를 쓰지 않는다. 카드에 값이 없으면 '판정 못 함'·'미달'·'무효'로 적고 숫자를 만들지 않는다.
7. **블로그 게시는 소유자 몫(정본 규칙)** — 이 기능은 초안과 상태 줄까지만 한다. 게시·공유·주소 기재는 하지 않는다.
8. **리뷰에서 멈춘다(소유자 지시)** — 이 세션은 계획과 시험, 기준 실패 확인까지만 한다. 리뷰 담당이 새 세션으로 계획·시험을 보고, 지적을 반영한 뒤 구현/문서를 시작한다.

## 3. 범위

### 3.1 하는 것

- **사실 대장(새 파일, 구현 몫, 예정)** — `docs/review/measurements/F-08-3-facts.json`. F-08-2·F-08-8 보고서와 정본의 설계 목표에서 인용한 값만 담는다. 값마다 `id`·`value`·`unit`·`label`(실측(PC)·외삽·문서 인용·설계 목표·[추정]·계산)·`source`·`anchor`(원천 파일에서 그 값을 찾을 수 있는 글)·`status`(무효·판정 못 함·자료 없음·부분)·`usedIn`(이 값을 쓰는 보고서)을 단다. 외삽은 목표·측정 최대·외삽 배수를, 실측은 반복 횟수와 편차를, [추정]은 단가 기준일을 함께 적는다.
- **M6 블로그 초안(MSR-030, 예정)** — `docs/blog/m6-100m-without-measuring.md`(파일 이름은 구현 때 정하되 `m6-`로 시작한다). F-08-7 목차의 M6 자리('100만을 재지 않고 말하는 법')를 채운다. ① 왜 한 번에 재지 않나, ② 무엇을 나눠 재나, ③ 실제로 잰 것, ④ 설계 식과 외삽, ⑤ 주장하지 않는 것, ⑥ 숫자를 읽는 법, ⑦ 근거와 한계. `docs/blog/README.md`의 M6 상태 줄만 '초안(2026-11-26), 게시 전'으로 고친다.
- **용량 산정서(MSR-080, 예정)** — `docs/review/measurements/F-08-3-capacity.md`. ① 입력과 표시 규칙, ② 100만(한 공연), ③ 200만(여러 공연), ④ 1~3년 전망, ⑤ 병목과 여유, ⑥ 가정·한계, ⑦ 사실 대장 인용. F-08-2의 진입 설계 식 결과를 **그대로 인용**하고 다시 계산하지 않는다.
- **비용 리포트(MSR-080, 예정)** — `docs/review/measurements/F-08-3-cost.md`. ① 입력과 단가 기준일, ② 상시 기본 비용, ③ 온세일 1회 비용, ④ 1~3년 전망, ⑤ 줄일 후보, ⑥ 한계, ⑦ 사실 대장 인용. `docs/infra.md` §11의 표를 원천으로 쓰고, 새 단가를 만들지 않는다.
- **DORA 추세 보고서(MSR-080, 예정)** — `docs/review/measurements/F-08-3-dora.md`와 `dora.mjs`가 만든 주별 산출물 `docs/review/measurements/F-08-3-dora-<월요일>.md`·`.json`. 최소 두 주(2026-11-16, 2026-11-23)를 빈 배포 기록으로 돌려 `자료 없음`을 확인하고, '추세 판단 불가'와 다음에 필요한 데이터를 적는다.
- **정적 시험(시험 몫)** — `tools/ci/f083-reports.test.mjs`. 위 파일이 생기기 전에는 읽기 실패로, 생긴 뒤에는 사실 대장·수치 주장·경계·DORA `자료 없음`·릴리스 범위를 대조해 통과한다. 시험 이름에 `MSR-030 ①`·`MSR-080 ①`처럼 ID와 세부 번호를 단다.

### 판정과 넘김

- **높음 3건(TR-01~03)과 통과 기준 6건(TR-04~08, TR-10)은 구현 전에 계획·시험 작성 담당이 고친다.** 고친 뒤 이 절에 `Fix-By: test` 커밋과 반영 확인을 적고, 구현 담당은 그 다음에 시작한다.
- **중간·낮음 가운데 통과 기준이 아닌 TR-09·TR-11~14는 `docs/lanes/lane4-cleanup.md`로 넘긴다.** 다만 TR-09(비용 수량 입력)는 구현 전에 계획에 한 줄로 정하지 않으면 보고서가 새 숫자를 만들 수 있으므로, 구현 담당은 WAF 1회 비용을 `docs/infra.md` §11의 기존 [추정] 인용으로 두고 1~3년 비용은 '미계산'으로 남기는 쪽을 기본으로 한다.
- **보안 지적은 없다.** 새 외부 호출·비밀·개인정보가 없고, 시험은 `dora.mjs --input`과 로컬 파일만 읽는다.
- **동결 경계는 지켜졌다.** 리뷰 시점 diff는 계획·시험뿐이고 `docs/release/v1-scope.*`·`docs/BUILD_ORDER.md`·정본은 바뀌지 않았다. 가지도 `freeze/lane4-F-08-3`뿐이다.

### 작성으로 넘길 준비

- TR-01~08, TR-10을 고친 뒤 시험이 고정된다. 구현 순서는 사실 대장 → 용량 → 비용 → DORA → M6 → 블로그 README M6 행이다.
- 구현 전에 `node --test tools/ci/f083-reports.test.mjs`가 다시 8/8 '산출물 없음'으로 실패하는지, `node --test tools/ci/dora.test.mjs`가 5/0인지, lint·doc-check·ledger·release-scope가 그대로인지 확인한다.
- **남은 위험**: 100만 외삽은 재지 않았고 V-T4는 '판정 못 함'이다. DORA는 배포 기록이 없어 추세를 말할 수 없다. 비용은 `docs/infra.md` §11 단가의 [추정]이고 CloudFront·S3·NLB 교차 전송 단가는 없다. F-08-4·F-08-5·F-08-6·F-08-9·F-08-10은 동결이라 병목을 재지 않았다.
