- 기능 F-06-11(고객·CS·법정), 등급 B, 단계 `GAT-254`(wbs 5.6.7), WBS 2.5일 [가정]. 상태 **동결**(ADR-0373, 2026-11-26 등록).
- 장부 범위: `N-T35`, `N-T36`, `N-T37`(`node tools/ci/ledger.mjs --batch F-06-11`).
- 정본: [notify.md](../../features/notify.md) §4.12, [ADR-0391](../../adr/0391-notification-template-review-and-activation.md), openapi `/v1/ops/notification-templates*`, data.md `notification_template`·`notification_template_event`, d5 §7.20·d3 SCR-073, planning/04 SCR-073, authz-matrix §3.2.
- 선행: F-06-9(Solapi 어댑터). 외부 계정·채널·카테고리·심사는 소유자 몫이다.

## 끝내는 것

1. `notification_template`·`notification_template_event`를 만들고 `(kind, locale, version)`·`(provider, template_code)`·`(provider, provider_template_id)` 유일, `(kind, locale)`마다 `ACTIVE` 하나(부분 유일 인덱스)를 건다.
2. 코드에 있는 판을 `POST /v1/ops/notification-templates`로 등록해 `DRAFT`를 만든다. 본문·문자 대체·버튼·변수 목록의 `content_sha256`과 `git_sha`를 남기고, 코드에 판이 없거나 해시를 만들 수 없으면 422다.
3. 내부 검토: `cs_lead`가 `POST .../internal-review`로 C1~C10을 모두 확인해야 `READY`다. 반려는 사유 필수, `DRAFT`로 되돌린다. 등록자≠검토자, 제출자≠활성자(2인 규칙).
4. 제공자 제출: `operator`가 `POST .../submissions`로 Solapi `POST /kakao/v2/templates`에 `channelId`·`name`·`content`·`categoryCode`·`buttons`·`messageType=BA`·`emphasizeType=NONE`·`securityFlag=false`를 보내고, 이어 검수 요청을 보낸다. 등록만 되고 검수 요청이 실패하면 검수 요청만 다시 한다.
5. 상태 확인: `PENDING`·`INSPECTING`은 `SUBMITTED`, `APPROVED`는 `APPROVED`, `REJECTED`는 `REJECTED`. 10분 [가정] 폴링·[상태 새로 고침], 3영업일 [가정] 경보. 반려 `comments`는 `CONTENT_PROHIBITED`·`AD_UNDECLARED`·`VARIABLE_INVALID`·`LINK_INVALID`·`LENGTH`·`DUPLICATE`·`PROVIDER_TEMPORARY`·`OTHER`로 옮긴다.
6. 활성·폐기: `commander`가 `APPROVED`만 활성하고 제출자와 같으면 403. 새 `ACTIVE`를 만들고 옛 판을 `RETIRED`로 내리며 옛 `templateId`를 24시간 [가정] 런타임 매핑에 남긴다. `emergency` 폐기는 즉시 알림톡을 멈추고 문자 대체로 보낸다.
7. 정합: 15분 [가정]마다 `ACTIVE`·`SUBMITTED`의 제공자 상태를 읽어 정지·삭제는 `SUSPENDED`·SEV2, 장부와 제공자가 다르면 `notify_template_reconcile_mismatch_total`을 올린다.
8. 화면 SCR-073 `/notifications/templates`: 목록·상세, 본문 미리보기(변수 강조), 문자 대체, C1~C10, 이전 판 비교, 제공자 시간선, 역할별 버튼, 반려 사유, 위험 안내. sm은 읽기만.
