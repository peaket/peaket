## 1. 이 기능이 끝내는 것과 넘기는 것

### 1.1 끝내는 것

1. **관제 `/investigations`(SCR-070) 실제 연결**: 회차 머리(기록 고정 판·늦은 적재·후보 계산 상태·다시 돌리기 가능), 회차 요약 4칸, 후보 묶음 목록(점수 범주만, 점수 원값·가중치 없음), 사건 목록(상태 거르기·담당·소명 기한·취소 마감), 외부 게시물 등록·목록을 실제 ops API로 읽고 쓴다. `?state=` 보드 미리보기는 개발 빌드에만 남기고, 운영 경로는 실제 API만 부른다.
2. **관제 `/investigations/:caseId`(SCR-071) 실제 연결**: 사건 상세·사건 기록·계정별 소명·연결 그래프·증거 묶음 목록·관리 연속성·내보내기를 실제 API로 읽는다. 조사관은 사건 고치기(메모·의견·계정 빼기·소명/이의 판단), 소명 요청, 조치 요청, 정상 종료, 증거 묶음 만들기, 보존 이유/끝, 내보내기를 할 수 있다.
3. **연결 그래프와 IP 원문 열기**: 그래프는 서버가 준 가린 IP(`/24`·`/48`)와 가명 앞 8글자만 그린다. 원문은 점을 골라 사유(5~500자, 한 번에 50개까지)를 적고 연 뒤에만 화면 메모리에 두고, 화면을 떠나거나 [원문 숨기기]를 누르면 지운다. 원문은 접속기록·로그·브라우저 저장소에 남기지 않는다. 점 2,000개 초과(`truncated`)면 '묶음을 나눠 보세요'를 보인다.
4. **승인 업무 SCR-046의 사건 요약**: `FRAUD_ACTION` 승인 상세의 `fraudCaseSummary`(사유 범주·계정 수·대상 표 수·구매 수 대 한도·공유 속성 종류·근거 신호 범주·계정별 소명 결과의 수·조사관 의견·고정 판 해시·취소 마감)를 읽기 전용으로 보인다. 계정 ID·실명·연락처·IP·결제 수단 값·연결 그래프는 보이지 않는다. 요약을 처음 연 시각을 서버 값으로 보이고, 열기 전에는 승인 단추가 이유와 함께 비활성이다. 판단 이유는 필수(1~1,000자)이고 대상 줄('계정 1·2…')을 꺼 범위를 줄일 수 있으며, 한 번에 한 승인 업무만 승인한다.
5. **소명 제출 SCR-042(부정 예매)**: 팬이 `GET /v1/fraud-appeal-requests`로 자기 부정 예매 소명 요청(사유 범주·기한·잠긴 표·잠금 최대 기한·소명 상태·조치 결과·이의 창/결과·우선 구매 권리)을 읽고, `POST /v1/appeals`(kind `FRAUD_CASE`, targetId 사건 ID)로 소명을 낸다. 받은 사람(`party` `HOLDER`) 변형은 사유 범주·잠긴 표·잠금·이용 제한·이의·우선 구매 없이 가진 표와 기한, 표마다의 취소 결과만 보인다. 소명 본문은 2,000자까지이고 화면·브라우저 저장소에 남기지 않는다.
6. **core-svc support 모듈(부정 예매 소명 최소)**: `POST /v1/appeals`·`GET /v1/appeals`·`GET /v1/appeals/{appealId}`·`GET /v1/fraud-appeal-requests`를 받는다. 소명은 core DB `appeal`에 두고, `FRAUD_CASE`만 ops-svc 내부 `POST /internal/v1/fraud-cases/{caseId}/appeals`로 이어 붙인다. ops-svc가 돌려준 결과가 `INVALID`·`EXPIRED`이면 소명을 닫고, 화면용 사본은 판 번호가 클 때만 바꾼다. `FraudAppealViewService.SetFraudAppealView` gRPC를 받아 `sup:far:{account}`에 사본을 쓴다.
7. **ops-svc 화면용 사본·사건 상세 보완**: 소명 요청을 보낼 때 결제자(`PAYER`) 사본(사유 범주·기한·잠긴 표·잠금 최대 기한·`lockActive`)과 받은 사람(`HOLDER`) 사본(가진 표·기한만)을 쓴다. 소명 인정·기각·기한 경과·잠금 풀림·조치 결과 때 사본을 다시 쓴다. 사건 상세의 `evidenceBundleIds`를 실제 증거 묶음 ID로 채우고, 승인 상세의 `fraudCaseSummary`에 `caseId`·`eventId`·`reasonCategory`·`ticketCount`·`appealCounts`·`snapshotHash`를 더하며, 요청자 본인에게는 `canApprove`를 거짓으로 준다.
8. **목업 제거**: SCR-070·071·046(부정 예매 조치)·042(부정 예매)의 운영 경로는 `entities/fraud-case` 목업·`entities/appeal` 목업을 가져오지 않는다. 목업은 `__PREVIEW__`·`?state=` 보드 미리보기에만 남는다. 화면 시험은 실제 호출 함수·서버 값만 쓰는지 소스와 모델로 확인한다.

## 2. 정본 빈칸과 이번에 정한 것(추천 적용 2026-11-26)

1. **support 모듈의 범위**: `docs/data.md`는 `appeal` 네 종류를 정하지만 F-06-4가 아직 없다. 이 기능은 `FRAUD_CASE`의 저장·조회·ops 연결·화면 사본만 닫고, `RESTRICTION`·`RECLAIM`은 `POST /v1/appeals`가 201로 저장만 하며 대상 연결은 `UnavailableAppealTargets`(닫힌 대역)로 둔다. `GET /v1/appeals`·`GET /v1/appeals/{appealId}`는 세 종류 모두 자기 것만 준다. 닫힌 대역은 `docs/lanes/lane6-cleanup.md`에 남긴다.
2. **support의 저장 위치**: core DB `appeal`(0000 계열 공유 클러스터의 core 논리 DB)에 둔다. 칸은 `docs/data.md` `appeal` 그대로다. `case_id`(CS 처리함 건)는 F-04-15에서 채우지 않고 null로 둔다(§1.2).
3. **support 화면용 사본**: `sup:far:{account}`는 Redis 해시다. 필드는 `caseId`, `eventId`, `party`, `reasonCategories`, `dueAt`, `lockedTicketIds`, `heldTicketIds`, `excludedTicketIds`, `lockActive`, `lockExpiresAt`, `state`, `objectionDueAt`, `objectionState`, `objectionNote`, `actionResult`, `priorityPurchases`, `version`이다. `version`은 사건 판(`fraud_case.version`)이고, 같은 계정·사건의 사본은 더 큰 판만 덮는다(작은 판은 버린다). Redis가 없는 local·ci는 메모리 사본을 쓴다.
4. **`SetFraudAppealView` gRPC 서버**: core-svc `main.ts`가 `PEAKET_SUPPORT_GRPC_PORT`(없으면 `PEAKET_GRPC_PORT`+1)로 `FraudAppealViewService`를 연다. 내부 토큰(`InternalTokenGuard`와 같은 머리)을 확인하고, `party`가 비면 `PAYER`, `HOLDER`면 `reasonCategories`·`lockedTicketIds`·`priorityPurchases`·`lockExpiresAt`·`objectionDueAt`·`restrictedUntil`을 비우고 `lockActive=false`로 저장한다. HOLDER의 `heldTicketIds`는 그대로 둔다.
5. **`POST /v1/appeals`의 멱등**: `Idempotency-Key`가 있으면 core `idempotency_record`에 같은 키의 처음 응답을 둔다. 같은 키·같은 본문은 처음 응답(201)을 재생하고, 같은 키·다른 본문은 422 `idempotency-key-reused`다. 키가 없으면 400 `idempotency-key-required`다(팬 쓰기 공통, `docs/api/guidelines.md`).
6. **`GET /v1/fraud-appeal-requests`의 범위**: 자기 계정의 사본만 준다. 열린 요청과 결정된 지 30일 [가정] 안의 요청만 준다. 사본의 사건 상태가 `CLEARED`면 빈 목록이다. 사건의 다른 계정·점수·근거 신호·기록은 싣지 않는다.
7. **소명 본문 검증**: NFC 정규화 뒤 코드 포인트 1~2,000자다. 앞뒤 공백은 지우고, 제로 폭 문자·제어 문자는 지운 뒤 센다. 이모지는 코드 포인트 하나를 한 자로 센다(1,001개는 201, 2,001개는 400). 민감정보를 적지 않아도 된다는 안내는 화면 문구이고 서버는 내용을 검사하지 않는다.
8. **화면의 사건 ID 판별**: `/my/appeals/{id}`는 `id`가 `apl-`로 시작하거나 `?state=`가 있으면 퍼블리싱 보드, UUID면 실제 부정 예매 소명 화면이다. 실제 화면은 `GET /v1/fraud-appeal-requests`에서 `caseId`가 같은 항목을 고른다. 없으면 404 화면이 아니라 '내 소명 요청이 아닙니다' 404 문구다.
9. **사건 작업대의 증거 묶음**: 사건 상세 `evidenceBundleIds`가 비어 있으면 `GET /v1/ops/evidence-bundles?eventId=`를 불러 `caseId`가 같은 줄만 골라 보인다. 목록은 `EvidenceBundleSummary`(ID·상태·묶음 해시·보존 이유·만든 시각)만 보이고, 파일 목록·관리 연속성은 상세 `GET`에서만 본다. 상세 `GET`은 `VIEWED`를 남기므로 화면은 사용자가 [묶음 열기]를 누를 때만 부른다.
10. **내보내기 화면**: 양식 셋(`AUTHORITY`·`PROMOTER`·`COMPLAINT`)과 사유(1~1,000자)를 받는다. `AUTHORITY`는 자료 요청 번호(UUID)가 필수이고, 응답의 `documentId`가 있으면 '자료 요청에 붙였습니다'를 보인다. `PROMOTER`는 `text/csv`, `COMPLAINT`는 `application/json`을 파일로 내려받는다. 파일 이름은 서버 `Content-Disposition` 이름을 쓰고, 없으면 d5·기존 규칙의 `complaint-<caseId>.json`·`promoter-report-<caseId>.csv`·`authority-<documentId>.json`을 쓴다. 화면이 임의 이름을 만들지 않는다.
11. **외부 게시물 등록**: `multipart/form-data`다. 화면은 주소·수집 시각·게시 시각(선택)·출처·신고 CS 건(출처 `REPORT`일 때)·적힌 좌석·캡처·가림 상자·확인 칸 셋을 보낸다. 주소는 `http`·`https`만이고 화면에서 누르는 링크로 만들지 않는다. 캡처는 PNG·JPEG·PDF, 10MB [가정]까지이고 확장자·매직 바이트를 함께 본다(서버가 다시 본다). 가림 상자는 캡처 크기에 대한 0~1 비율이고 최대 20개다. 확인 칸 셋을 모두 체크해야 등록 단추가 켜진다.
12. **가림 상자 고르기**: 캡처 미리보기 위에서 끌어 상자를 만들고, 키보드로는 x·y·w·h(0~1)를 넣는다. 상자는 캡처 밖으로 나가지 않게 자르고, 0 크기 상자는 버린다. OCR·자동 연락처 대조는 하지 않는다.
13. **보기용 사본**: `GET /v1/ops/external-posts/{postId}/capture`가 `image/png`를 주면 `<img>`로만 그린다. `viewAvailable`이 거짓이면 '검사 중'·'보기용 사본 없음(PDF)'을 보이고 내려받기 단추를 두지 않는다. 원본 캡처(PDF 포함)는 이 화면에서 내려받지 않는다.
14. **IP 원문 열기**: 응답은 `no-store`이고 화면 상태에만 둔다. `sessionStorage`·`localStorage`·`IndexedDB`·URL·로그에 남기지 않는다. 화면을 떠나면 지운다. 원문을 연 점의 가린 값은 '가림'으로 바꾸고 `aria-live`로 알린다.
15. **사건 요약의 계정 표현**: 승인 업무 요약의 `targets`는 `accountId`를 받지만 화면은 '계정 1·2…'로만 부른다. `ApprovalDecisionBody.excludeAccountIds`·`excludeTicketIds`에는 서버가 준 ID를 그대로 싣고, 화면에는 ID를 보이지 않는다.
16. **승인 가능 판정**: 화면은 서버가 준 `canApprove`를 그대로 쓴다. 서버 `canApprove=false`이면 화면 조건이 맞아도 승인 단추를 켜지 않고 이유를 보인다. 서버 `true`여도 요청자 본인·가명정보 취급자·비 commander·요약 미열람·상태 아님은 화면이 한 번 더 막는다(방어 깊이). 서버가 `409 fraud-summary-not-viewed`를 주면 요약을 먼저 열라는 안내와 [요약 열기]를 보인다.
17. **화면 시험의 경계**: 화면 모델 시험은 서버 응답 모양(openapi)만 넣고, React를 그리지 않는다. 실제 호출·목업 제거는 소스 배선 시험이 본다. 서버는 HTTP 경계 시험이 본다.
18. **계약**: 이번 단계는 `docs/api/openapi.yaml`을 고치지 않는다. 필요한 호출·스키마는 이미 있다(`investigations`·`support`·`ops`). 구현에서 계약을 고칠 일이 생기면 계획을 먼저 고치고 `packages/contracts`·`packages/api-client` 생성물을 함께 낸다.

## 3. 계약과 생성물(이번 단계는 고치지 않는다)

- 새 경로·스키마 없음. `GET /v1/fraud-appeal-requests`, `POST /v1/appeals`, `GET /v1/appeals`, `GET /v1/appeals/{appealId}`, 조사 API, 증거 묶음 API, 승인 상세는 이미 계약에 있다.
- 구현에서 `support` 모듈이 새 Problem type을 만들지 않는다. 쓰는 type은 `invalid-body`·`idempotency-key-reused`·`not-found`·`dependency-unavailable`·`fraud-case-state`·`investigator-required`·`precondition-failed`·`evidence-disposed`·`evidence-not-sealed`·`external-post-scan-pending`·`external-post-view-unavailable`·`export-rate-limited`·`data-request-required`·`data-request-not-approved`·`data-request-event-mismatch`·`data-request-not-found`·`approval-reason-required`·`fraud-summary-not-viewed`·`approval-scope-invalid`·`cancel-deadline-passed`·`restriction-too-long`뿐이다.
- `@peaket/api-client`의 `investigations`·`support`·`ops` 생성 호출을 그대로 쓴다. 새 생성물은 이번 단계에 없다.

- `support/index.ts`는 `MemorySupportAppealStore`·`MemoryFraudAppealViews`·`normalizeFraudAppealView`·`applyFraudAppealView`를 내보낸다(시험이 문자열 동적 import로 부른다). `MemorySupportAppealStore.findIdempotent`는 같은 `key`의 `requestHash`를 바이트로 견줘 같으면 `replay`, 다르면 `reused`, 없으면 `none`을 준다. `MemoryFraudAppealViews.set`은 들어온 `updatedAtMs`가 있으면 그 값을, 없으면 `nowMs`를 쓴다(시험이 30일 경계를 만들 수 있게).
- `services/core-svc/migrations/0048_support_appeal.sql`: `appeal` 표·`kind`/`status`/`result`/`char_length(body) <= 2000` 검사·`(account_id, submitted_at)`·`(target_id)` 인덱스·`core_app` 권한.
- `AppModule.register`의 두 갈래에 `support?: SupportWiring`을 더한다. `main.ts`는 `PEAKET_SUPPORT_GRPC_PORT`가 있으면 gRPC 서버를 열고, `PEAKET_REDIS_URL`이 있으면 Redis 사본 저장소를 쓴다. 없으면 local·ci는 메모리다.
- 시험은 `AppModule.register({ memory: true, support: {...} } as never)`로 띄우고 HTTP로만 본다. 구현 전에는 `support`를 모르는 옵션이라 라우트가 404다.

## 8. 실패 시나리오와 엣지 케이스

1. **API 설정 없음**: 관제 `__OPS_API_ORIGIN__`이 비면 '관제 API 주소가 설정되지 않았습니다'와 설정 안내를 보이고 호출하지 않는다. 팬 `ORIGINS.api`가 비면 '지금은 소명을 볼 수 없습니다'를 보인다.
2. **권한 없음**: 조사 경로는 `FRAUD_INVESTIGATOR` 지정이 없으면 403 `investigator-required`이고 화면은 '권한 없음(지정 없음)'이다. 승인 상세는 요청자·승인 자격자 밖이면 404다(존재 여부를 숨긴다).
3. **없는 사건·묶음·게시물**: 404 `not-found`이고 목록으로 돌아가는 링크를 보인다. 원천 만료는 410 `investigation-source-expired`이고 '원천 만료' 안내와 증거 묶음 링크만 보인다.
4. **상태 충돌**: 사건 고치기 `412 precondition-failed`면 최신 사건을 다시 읽고 '다른 조사관이 먼저 고쳤습니다'를 보인다. 사건 만들기 `409 fraud-case-exists`면 그 묶음의 사건으로 가는 링크를 보인다.
5. **소명 요청 기한**: 기한이 지금+24시간보다 짧거나 입장 시작 뒤면 422, 사건 상태가 `DECISION_PENDING`·`CLEARED`·`REVERSED`면 409다. 화면은 보내기 전에 같은 규칙으로 막고, 서버가 거절하면 문구를 보인다.
6. **조치 요청**: 소명 `SUBMITTED`·`PENDING` 계정, 취소 마감 뒤, 열린 승인 업무가 있으면 409다. 이용 제한 끝이 1년을 넘으면 422 `restriction-too-long`, 사유가 없으면 400 `invalid-body`다.
7. **IP 원문**: 사유가 5자 미만·50개 초과·그 사건의 IP 점이 아니면 422, 하루 200개 초과면 429다. 화면은 사유를 먼저 받고, 429면 '오늘은 더 열 수 없습니다'를 보인다. 원문은 응답을 받은 화면 상태에만 둔다.
8. **그래프 큼**: `truncated=true`면 '묶음을 나눠 보세요'를 보이고 점을 더 그리지 않는다.
9. **게시물 등록**: 확인 칸 셋이 모자라면 단추 비활성, `REPORT`에 신고 건이 없으면 422, 캡처가 10MB 초과면 413, 형식이 틀리면 415, 화소 상한이면 422다. 등록 중에는 단추를 막고 `aria-busy`를 준다.
10. **캡처 검사**: `PENDING`은 '검사 중', `THREAT`은 '위협'과 SEV2 안내, `CLEAN`이고 보기용 사본이 있으면 [보기]가 켜진다. PDF는 [보기]가 없고 'PDF는 보기용 사본이 없습니다'를 보인다.
11. **가림 상자**: 20개 초과·0 크기·1.0 밖 좌표는 거절하고, 캡처 밖은 자른다. 상자가 없어도 등록은 된다(가리지 않은 사본).
12. **소명 제출**: 기한 전 `OPEN`이면 201, `SUBMITTED`·`ACCEPTED`·`REJECTED`·`EXPIRED`면 막는다. `HOLDER`는 가진 표가 없거나 사건 계정이면 409다. 같은 키 재전송은 처음 응답을 재생한다.
13. **받은 사람**: 사유 범주·잠금·이의·우선 구매를 보이지 않고, 가진 표와 기한만 보인다. 결제자·다른 계정·사건 내용은 보이지 않는다.
14. **우선 구매**: `priorityPurchases`가 비어 있으면 아무것도 보이지 않는다. `OFFERED`이고 기한 전일 때만 산다. 기한이 지나면 '기한 지남'이고 구매 단추가 없다.
15. **사건 요약**: `fraudCaseSummary`가 없으면 '사건 요약이 아직 실리지 않았습니다'이고 승인 단추가 이유와 함께 비활성이다. 요약을 열면 `summaryViewedAt`을 서버에서 다시 읽어 보인다.
16. **승인**: 요청자 본인·비 commander·`PSEUDONYM_HANDLER`·요약 미열람·상태 아님은 막는다. 승인 본문은 이유 1~1,000자, 뺀 계정·표는 대상 안에서만, 모두 빼면 422다.
17. **내보내기**: 봉인 전 409 `evidence-not-sealed`, 파기 410 `evidence-disposed`, 해시 불일치 409, 하루 20회 초과 429, AUTHORITY 자료 요청 없음 422, 승인 아님·다른 회차 409다. 화면은 서버 문구를 그대로 쓴다.
18. **관리 연속성**: 목록은 `VIEWED`를 만들지 않고, 상세를 열 때만 `VIEWED`가 붙는다. 파기 뒤 목록에는 `DISPOSED`로 남고 상세는 410이다.
19. **화면 이탈**: IP 원문·게시물 캡처 미리보기·소명 본문은 화면을 떠나면 지운다. 브라우저 저장소에 쓰지 않는다.
20. **서버 시간**: 화면은 브라우저 시계로 기한을 판정하지 않고 서버가 준 `dueAt`·`cancelDeadlineAt`·`objectionDueAt`과 응답의 `serverTimeMs`(있으면)만 쓴다. 없으면 기한을 '지남'으로 단정하지 않는다.
21. **접속기록·감사**: 화면은 접속기록을 직접 만들지 않는다. 서버가 `invAccess`·`admin_data_access`에 남긴 값을 화면에 보이지 않는다. 화면 로그에 IP·연락처·계정 ID를 싣지 않는다.
22. **동시성**: 사건 고치기는 `If-Match`(사건 `version`/ETag)를 싣는다. 412면 다시 읽는다.
23. **목업**: `__PREVIEW__`가 꺼진 빌드에는 `entities/fraud-case`·`entities/appeal` 목업이 운영 경로 번들에 들어가지 않는다.
24. **소명 본문 저장**: support는 본문을 core DB에만 두고, ops-svc 내부 호출에는 본문을 싣지 않는다(해시·위치만 증거 묶음에).
25. **사본 판**: 작은 판의 `SetFraudAppealView`는 무시한다. HOLDER 사본은 잠금·사유·우선 구매를 비운다.

## 9a. 구현 전 실제 단언 실패 확인(architecture §8.6 4의 3·7)

- 파일·모듈이 없어 시험 파일이 실행조차 안 되는 실패는 '실패 증명'으로 세지 않는다. 구현 담당은 구현 **첫 커밋 전에** 커밋하지 않는 임시 껍데기로 한 번 돌려 실제 단언 실패를 확인한다.
- 절차:
  1. `git status`가 깨끗한 것을 확인한다.
  2. 시험이 부르는 새 모델·모듈 이름만 껍데기로 만든다(예: `mapOverview`가 입력을 그대로 돌려주는 함수, `MemorySupportAppealStore`가 `replay`만 돌려주는 저장소). 제품 동작을 만들지 않는다.
  3. 새 시험 파일을 하나씩 돌려 **파일 부재가 아닌 단언 실패**의 시험 이름·메시지를 적는다.
  4. 껍데기를 지우고 `git status`가 다시 깨끗한 것을 확인한 뒤 구현 첫 커밋을 만든다.
  5. 실행 결과(실패 시험 이름·메시지)를 이 파일 §7.13·§9에 덧붙인다.
- 껍데기는 어느 커밋에도 넣지 않는다. 껍데기를 넣은 채 구현을 시작하면 안 된다.

## 14. 동결 로컬 범위

- `freeze/lane6-F-04-15` 가지와 `D:/ticketpass-freeze-F-04-15` 워크트리에서만 개발한다. `develop`·`release/1.0.0`에 합치지 않고, 릴리스 가지·`main`에 체리픽하지 않는다(ADR-0386 결정 4).
- 마이그레이션 `0048`(core-svc)은 로컬·CI 무대만이다. 출시 `develop`이 같은 번호를 쓰면 동결을 풀 때 다시 매긴다(ADR-0386 결정 5). ops-svc `0040`·ticket-svc `0026`은 쓰지 않는다(§5).
- `deploy/`·릴리스 플래그·출시 환경 값을 건드리지 않는다. 계약은 이번 단계에서 고치지 않고, 구현에서 필요하면 `docs/api`와 `packages/contracts`·`packages/api-client` 생성물을 함께 고친다.
- `develop`에 쌓인 다른 기능의 코드를 되돌리지 않는다. 이 기능이 바꾸는 파일은 `apps/console-host`, `apps/web`, `services/core-svc`, `services/ops-svc`, 시험·문서뿐이다.
