## 2. 감독에게(정할 것과 이 계획의 답)

### 6.1 창 3g

| 창 | 무엇 | 어림 |
| --- | --- | --- |
| 3g | K8 10행 읽기·판정, K9 실행 읽기·판정, OPS-510 로컬 양·운영 시간 입력 확인, 후보별 비용·민감도·순위, 구성 요소 표, 보고서 | 약 10시간 |

- **합계 약 10시간 = 1.25일(8시간/일)**이다. 다른 역할 2.0일(계획 0.5·시험 0.5·리뷰 0.25·구현 0.5·기록 0.25 = 16시간)과 합계 **3.25일(26시간)**이다. 35시간 상한은 쓰지 않는다.
- **잠금**: 이 기능은 Docker를 쓰지 않으므로 잠금을 잡지 않는다. 써야 할 일이 생기면 멈추고 감독에게 묻고, 허락을 받아도 `docker lane4-F-08-14` 한 자리만 쓴다(`docker-all` 금지). 창은 감독이 연다.
- **시작 전 확인**: 입력 보고서·계획 JSON·`ops-hours.csv`를 읽을 수 있는지, 로컬 관측 양이 있는지, 가격표 조회 날짜가 있는지, 호스트 디스크 15GB 이상인지 본다. 사전 점검은 판정에 넣지 않는다.
- **이번 턴**: 창을 열지 않는다. 3g의 입력·규칙·표만 만든다.
- **계산 예**: OPS-510 요청 기록 저장소 (다) X-Ray는 테스트 입력(2,000,000 trace·5,000,000 조회/월, 운영 50시간)에서 저장 9.50 + 조회 2.00 = 월 11.50, 연 138달러이고, 운영 50시간 1,769.21을 더하면 **1,907.21달러**다(§6.5).

### 6.2 무대

- **이 기능은 새 무대를 만들지 않는다.** 로컬 demo·v1 무대도 띄우지 않는다. 기존 산출물(문서·JSON·CSV)만 읽는다.
- **없는 부품을 있는 것처럼 적지 않는다.** Mimir·Loki·Tempo·관측 Kafka·Alertmanager·AWS·Datadog·X-Ray는 이 가지에 없다. 로컬은 Prometheus·Grafana만 있다.
- **기대 경보는 문서 대조로만 본다.** 로컬 Prometheus에 경보 규칙이 없고 Alertmanager도 없어 `ALERTS`·알림 수신을 잴 수 없다. K8 입력은 F-08-6·F-08-12가 남긴 `timeline.csv`·보고서 표뿐이다.
- **되돌리기**: 계산은 상태를 바꾸지 않으므로 되돌릴 것이 없다. 출력 폴더와 보고서만 남기고, 새 측정을 하지 않았음을 manifest에 적는다.

- **계산**: `judgeK8`은 T0·T1·T1p·T2·T3를 받아 `탐지(초) = (T1 − T0) ÷ 1000`, `전파(초) = (T3 − T2) ÷ 1000`을 직접 계산한다. 이미 계산된 초를 받지 않는다. `T1`은 기대 알림이 처음 도착한 때(Alertmanager 웹훅 수신 로그)이고, `T1p`는 Prometheus `ALERTS{alertstate="firing"}`의 첫 표본이다. `T1 − T1p`는 묶음 대기·전달이다. K8은 `T1`로 판정한다(`docs/perf-ledger.md` §8).
- **G-07 T1 대체**: G-07은 판매 중 탭 신선도 경고 색이 탐지라 Alertmanager `T1`이 없을 수 있다. G-07에 한해 `T1`이 `null`이고 `T1p`(신선도 경고 색 첫 표본)가 있으면 `T1p`로 탐지 시간을 계산하고 `usedT1p:true`로 표시한다. 다른 ID는 `T1`이 없으면 `판정 못 함`이다. G-07에 `T1p`도 없으면 `미측정`이다.
- **경계**: 60.000초는 통과, 60.0005초는 미달. 59.9999초는 통과. 3.000초는 통과, 3.0005초는 미달, 2.9999초는 통과. 소수 셋째 자리 아래를 반올림하지 않고 원값으로 판정한다.
- **탐지율**: 분모는 **10**이다. 측정한 행만의 분모로 100%를 만들지 않는다. 입력이 하나도 없으면 탐지율은 `null`이고 `0%`로 적지 않는다. 측정률 `measuredRate = 측정 행 ÷ 10`은 0행일 때 `0`이다(탐지율과 다르다). 탐지율 `detectionRate = 탐지 행 ÷ 10`은 0행일 때 `null`이다.
- **전파 시간**: `T3 − T2`. `T2`는 운영 명령의 최종 승인 완료, `T3`는 대상 파드의 적용 ack다. 명령이 있는 행만 판정하고, 3.000초는 통과·3.0005초는 미달이다. 명령이 없는 행은 `—`다. 전파 입력이 하나도 없으면 전파 판정은 `미측정`이고, K8 전체는 `판정 못 함`이다(탐지만 통과로 적지 않는다).
- **실행 증거**: 각 행은 `runId`·`runExists:true`·`manifest:true`·`timeline:true`가 있어야 한다. 하나라도 없으면 `판정 못 함`이고 `통과`로 적지 않는다. `manifest.json`·`timeline.csv`는 `docs/perf-ledger/runs/<실행 ID>/`에 있어야 한다.
- **간격**: 행마다 `intervals`를 받아 `F0814_K8_INTERVALS`와 같아야 한다. G-01~G-06은 긁기 5초·평가 5초·묶음 대기 5초·`for` 0, G-07은 15·5·5·0, G-08~G-10은 15·5·5·30이다. 다르거나 없으면 `무효`이고 K8 판정에 쓰지 않는다.

### 6.4 K9 — HPA 파드 확장 시간

- **정본**: `docs/verification.md` §3.10 K9 표. K1의 1만·10만 실행에 `--hpa-timeline`을 붙이고, 앱 복제 1에서 시작(`--settle`)해 부하 시작부터 HPA가 복제를 늘린 시각, 새 파드가 준비된 시각을 쿠버네티스 사건·파드 상태에서 읽는다. 목표는 부하 시작 → 늘린 파드 준비 **60초 미만**이다.
- **경계**: 60.000초는 통과, 60.0005초는 미달, 59.9999초는 통과. `확장(초) = 첫 확장 시각 − 부하 시작`, `준비(초) = 첫 새 파드 준비 시각 − 부하 시작`으로 둘 다 적는다. 판정은 `준비(초)`로 한다.
- **유효 실행**: `valid:true`, `replicasBefore=1`, `replicasAfter>1`, `settle:true`, 세 시각이 모두 있고 `부하 시작 ≤ 첫 확장 ≤ 파드 준비`(등호 허용), 실행 ID·`runExists:true`·`manifest.json`·`timeline.csv`가 있다. 실행 증거가 없으면 `판정 못 함`, `replicasBefore≠1`·`replicasAfter=1`·시각 뒤집힘·`settle:false`·`valid:false`면 `무효`다.
- **입력**: F-08-8 계획은 K9/HPA를 범위 밖으로 두고 HPA를 껐다. K1 실행도 §3.10의 1만·10만 `--settle` 실행이 아니므로 K9 유효 실행이 없다. `readK9Summary`로 읽고, 파일이 없거나 실행이 0개면 `미측정`이다. F-08-8의 K1 1천 1/3·2천~1만 미달은 K9 입력이 아니며, K9 통과로 바꾸지 않는다.
- **노드 기동**: K9의 노드 기동 시간은 `문서 인용`이다. AWS는 노드 기동 시간을 보장하지 않으므로, 이 기능은 파드 준비 시간만 재고 노드 기동은 실측으로 주장하지 않는다(`docs/verification.md` §5.3).
- **v0 값**: `2026-11-03-v0-*`의 19~51초는 `version: v0`, `verdict: baseline` 인용이다. v1 통과가 아니다.

### 6.5 OPS-510 — 관측 백엔드 비교 계산

- **이름 정리**: 정본 K9는 파드 확장 시간이고, 이 절은 OPS-510이다. 지시문의 'K9(관측 백엔드 비교)'는 OPS-510을 가리키는 것으로 읽는다. 보고서에서는 `K9(파드 확장)`과 `OPS-510(백엔드 비교)`을 나눠 적는다.
- **후보 셋**(ADR-0068 결정 5): ① 직접 운영(지금 구성: Prometheus·Mimir·Loki·Tempo·Pyroscope·Grafana + S3), ② AWS 관리형(AMP가 Mimir 자리, AMG가 Grafana 자리. 로그·요청 기록·프로파일은 직접 운영), ③ Datadog(인프라·APM·지표·로그를 맡김). 어느 후보든 클러스터 안 Prometheus는 남는다(ADR-0068 결정 2).
- **요청 기록 저장소 세 안**(ADR-0077, `docs/observability.md` §1): (가) Tempo 마이크로서비스 + 관측 전용 MSK, (나) Tempo 모놀리식 + 꼬리 표본 상한, (다) AWS X-Ray. 세 안 모두 연간 비용·3등급(내구성)·오픈 피크 쓰기량·판정·`chosen`을 계산한다. 3등급 기준과 오픈 피크를 만족하는 안 가운데 연간 총비용이 가장 낮은 안을 고르고, 10% 안이면 지금 구성을 둔다. 관측 전용 MSK 가격은 정본 가격표에 없으므로 입력으로 받고, 없으면 (가)는 `미측정`이다. X-Ray는 월 10만 trace·100만 조회 무료를 빼고 계산한다. 테스트 입력(2,000,000 trace·5,000,000 조회/월, 운영 50시간)에서는 저장 9.50달러 + 조회 2.00달러 = 월 11.50달러, **연 138달러**이고, 운영 50시간 1,769.21달러를 더하면 **1,907.21달러**다.
- **구성 요소 비교**(`docs/observability.md` §9): Prometheus(로컬 15일), Mimir(원본 90일·5분 집계 13개월, S3), Loki(30일, S3), Tempo(14일, S3+관측 Kafka), Pyroscope(7일, S3). 표에 보존·저장량(GB)·연간 USD·쿼리 언어·운영 부담(직접/관리형)을 적는다. Mimir 저장량은 `metricStorageGB + aggStorageGB`(테스트 입력에서 160GB)로 AWS AMP 저장량과 같은 정의를 쓴다.
- **로컬에서 세는 양**(`docs/perf-ledger.md` §11.2): 활성 시계열 수, 초당 수집 샘플, 로그 GB/일, 요청 기록 GB/일·span/초, 서버(노드) 수, 화면 사용자 수. 여기에 저장량 계산을 위해 `metricStorageGB`·`aggStorageGB`·`profileGBPerDay`·`querySamplesPerYear`를 입력으로 더한다. 정본 §11.2에 없는 입력은 [가정]이 아니라 '빠진 입력'으로 표시하고, 없으면 `미측정`이다.
- **가격표**(`docs/perf-ledger.md` §11.3, 조회 날짜를 함께 적는다): AMP(2026-10-14), AMG(2026-10-20), Datadog(2026-10-19), X-Ray(2026-09-11), S3(2026-10-15). AMP 수집 2단계(20억·2,500억), X-Ray 무료 10만 trace·100만 조회, Datadog 로그 수집 GB당 0.10달러를 포함한다. 새 가격을 조회하지 않는다.
- **계산식**(월 → 연간 ×12):
  - `samples/month = samplesPerSecond × 2,592,000`(30일).
  - AMP 수집: 4천만 무료, 20억까지 1천만 샘플당 0.90달러, 다음 2,500억까지 1천만 샘플당 0.35달러.
  - AMP 저장: `metricStorageGB + aggStorageGB`에서 10GB를 뺀 GB·월 0.03달러(테스트 입력 160GB → 연 54달러). AMP 조회: 처음 2천억 무료, 10억 샘플당 0.10달러.
  - AMG: 활성 Editor 월 9달러, Viewer 월 5달러.
  - Datadog: 인프라 Pro 서버당 월 15달러, APM Enterprise 서버당 월 40달러, 서버당 지표 100개 포함·초과 100개당 월 5달러, 로그 수집 GB당 0.10달러.
  - S3: GB·월 0.025달러. Loki 저장량 = `logGBPerDay × 30`, Tempo = `traceGBPerDay × 14`, Pyroscope = `profileGBPerDay × 7`, Mimir = `metricStorageGB + aggStorageGB`, Prometheus = 로컬(0). AWS 후보의 S3는 Loki·Tempo·Pyroscope만 센다(377GB).
  - 운영 시간: `시간 × 49,538원 ÷ 환율(원/달러)`. 0.5·1·1.5배 민감도. 환율은 값·출처·기준일을 모두 적고, 하나라도 없으면 `미측정`.
  - 연간 총비용 = 서비스 요금 + 저장소·전송 비용 + 운영 시간 × 시간 단가(ADR-0068 R2).
- **판정 규칙**:
  - **R3(국외 이전)**: 직접 운영·AWS 관리형(서울)은 통과, Datadog은 요건을 먼저 갖춰야 한다. 기본은 Datadog 제외이고 `candidates`·민감도 `ranking`에서 아예 뺀다. 입력 `r3.datadog:true`일 때만 후보에 넣는다.
  - **R1(장기 조회)**: AMP는 쿼리 기간 최대 95일·QueryMetrics 초당 300건이다. 13개월 비교는 AMP만으로 안 되므로, AWS 후보는 `장기 조회 조건부`로 표시하고 13개월 몫을 Mimir/S3에 남기는지 적는다. 조건을 못 채우면 `판정 못 함`이다.
  - **R2(비용)**: R1·R3를 통과한 후보 가운데 1배 연간 비용이 가장 낮은 후보를 고른다. 1위가 직접 운영이면 그대로 고른다. 1위가 다른 후보이고 직접 운영과의 차이가 10% 이내면 `tie:true`로 두고, 직접 운영이 1.5배에서도 1위일 때만 직접 운영을 고른다. 1위가 직접 운영인데 1.5배에서 1위가 바뀌면 `opsSensitive:true`로 표시하고 1.5배 1위를 고른다. 판정은 1배 값으로 한다.
- **샘플 예산**(`docs/perf-ledger.md` §11.4): `보낼 샘플 = 시계열 수 × 86,400 ÷ 긁기 간격(초) × 보낼 날수`. 합이 4천만(AMP 무료 등급)을 넘지 않게 한다. 이 기능은 **보내지 않는다**. 예산 계산만 표에 남긴다.
- **입력 없음**: 여섯 양 가운데 하나라도 없거나 유한하지 않거나 `fxSource`·`fxDate`·`priceDate`가 없으면 후보 합계를 내지 않고 `미측정`이다. 일부 후보만 계산되면 `판정 못 함`이고, 계산된 후보와 빠진 입력을 함께 적는다. 0으로 채우지 않는다. 입력 파일은 `readOpsHours`로 읽고, 파일이 없거나 0행이면 운영 시간은 `미측정`이다. `traceStoreCosts`도 `krwPerUsd`·`fxSource`·`fxDate`·`priceDate`를 모두 요구하고, 하나라도 없으면 `미측정`·`missing`이다.
- **외부 전송 금지**: AWS·Datadog 계정을 만들지 않고, 자료를 보내지 않고, 유료 등급을 쓰지 않는다. 가격표·문서 인용만 한다.
- **온세일 1회·티켓 1,000장당 비용**: OPS-500의 나머지 몫이다. 이 기능은 백엔드 연간 비용에서 온세일 1회 몫을 나누는 식만 적고, 실제 온세일 1회 비용은 F-08-2·F-08-8의 유효 실행이 없어 `미측정`이다.
