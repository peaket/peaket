## 1. 묶음 나누기(추천: 나눈다)

**추천**: BAT-155 = HOT-240만, 새 묶음 **BAT-157** = HOT-250. HOT-250은 BAT-157을 시작할 때 다시 나누기를 권한다(1.2).

### 1.1 근거

- **크기**: HOT-240 하나가 새 표 넷(마이그레이션·행 보안 포함), 저장·불러오기 경로 둘, 판 예약과 두 트랜잭션, 회차마다 파일 게시, 오픈 뒤 잠금 비교, 승인 이력의 대기 판, 회차 더하기 고침, 공연 상세 칸, S-T38 ①~⑩(A등급, 항목마다 틀린 구현 1~2개)이다. WBS 2.25일이 이미 빠듯하다.
- **HOT-250은 서비스 넷에 걸친다**: 규칙 문법과 평가 함수(`@peaket/validation`, 화면·서버 공용), core-svc 규칙 저장과 정렬 설정 고치기 경로(`updatePartnerEvent`, 아직 구현이 없다), 명단 올리기·잠금·파기, 회원 코드 → 계정 변환(identity-svc에 RPC가 없다), 대기열 Redis 사본 쓰기, queue-svc 진입·로비 대조와 입장 토큰 명단 키, purchase-svc 규칙 한도, SCR-024 화면(wbs 2.9.3은 화면을 포함한다). 한 턴(WBS 5일 [가정])에 둘을 함께 끝낼 수 없다.
- **다른 갈래가 같은 폴더를 고치는 중**: 갈래 3 BAT-200(BOT-090)이 queue-svc 입장 확정·추가 검증을, 갈래 1 BAT-020(PRF-203·210)이 purchase-svc를 고친다. 이 묶음에서 그 폴더를 고치면 합칠 때 겹친다(4장 물을 것 ②).
- **HOT-240이 먼저여야 하는 것**: HOT-230(템플릿)은 HOT-240 뒤이고(BUILD_ORDER BAT-150 비고), HOT-250의 규칙 `grade` 사실과 공연 상세의 등급별 요약은 HOT-240의 가격 등급을 쓴다.

## 3. HOT-240 작업 목록

### 3.1 차례

1. 정본 빈칸은 이 계획과 함께 썼다(6장). 구현 중 새 세부가 나오면 ADR-0260에 결정을 더한 뒤 코드를 쓴다. BUILD_ORDER 줄 고침(6.3)은 감독이 한다.
2. **불변식 시험 먼저 쓰고 실패를 본다**(A): 색인 규칙(S-T38 ①), 판 번호 다시 쓰지 않기·두 트랜잭션 사이 경합(③), 게시 실패에 판이 오르지 않음(④), 잠금(⑤), 대기 판(⑥).
3. 마이그레이션 `0007`(표·제약·행 보안·권한) → drizzle 스키마 → 저장소 어댑터.
4. 순수 함수(색인 매기기, 등급 검사, 잠금 비교, 팬 파일 만들기, 라벨 기본값) → 사용 사례(불러오기, 저장) → 처리기 → 회차 더하기 고침 → 공연 상세 `priceTiers`.
5. 공용 파일 저장 포트와 어댑터 둘, 시작 파일 조립(`PEAKET_PUBLIC_FILE_DIR`).
6. 실제 서버 연결(3.4) → 관점 넷 리뷰 → 틀린 구현 검사(3.7) → 게이트(3.5) → 기록과 커밋. 화면이 없어 브라우저 확인은 하지 않는다. Lua를 바꾸지 않아 성능 비교도 없다.
7. 묶음 끝에 wbs 2.9.2 설명 칸의 남은 일수를 이 묶음 실측으로 다시 적는다(ADR-0260 결정 14).

### 3.3 인터페이스

- **HTTP**: `GET`·`PUT /v1/partner/productions/{productionId}/seatmap`(docs/api/openapi.yaml:4352~4353), 회차 더하기의 새 503(4293). 새 오류 이름 `seatmap-publish-unavailable`(210). 본문 칸 `SeatMapLayoutInput.priceTiers`(1881)·응답 `SeatMapLayout.priceTiers`·`fanFilePublished`(1851), `SeatMapPriceTier`(1943), `EventPublicSummary.priceTiers` 설명(1079). 규칙은 ADR-0260 결정 3~13.
- **포트**: `PublicFileStore`(쓰기 `put(key, bytes, { contentType, cacheControl })`, 지우기 `delete(key)`. 키는 `v1/events/{uuid}/seatmap-layouts/{정수}.json` 모양만 받는다. 로컬 폴더 어댑터는 키 모양을 다시 보고 폴더 밖 경로를 만들지 않는다). 배치본 저장소 포트는 트랜잭션 ①(판 예약)·②(판 확인 뒤 커밋)를 나눠 낸다(ADR-0260 결정 5).
- **표**: docs/data.md:569(`venue`)·589(`section`)·653(`seat`)·668(`price_tier`)·436(관계선)·2590(§5 줄). 행 보안은 `production_image`와 같은 꼴(0006)이고, `core_partner`에 `event.venue_id` 고치기 권한과 `venue`의 판·대기 판 칸 고치기 권한이 더 필요하다(지금 0004는 `production`의 두 칸만 준다). TEMPLATE 행(`promoter_id` NULL)은 공개된 것만 파트너가 읽는다.
- **gRPC·Kafka·Redis**: 없다.

### 3.6 구현 지시문에 넣을 '자주 놓친 결함'(docs/architecture.md:1129~1140)의 이 묶음 판

- 저장 응답은 정확한 값까지 단언한다: 서버가 매긴 `seatIndexRange`·`index`, `ETag`의 판, 파일 바이트(이긴 판 파일이 진 저장 뒤에도 같은지), 회차별 `venue_id`.
- 지우기: 게시 실패 때 그 판에 이미 쓴 파일을 모두 지웠는지, 커밋 뒤 앞 판 파일만 지우고 승인된 판 파일은 남겼는지 폴더를 세어 본다.
- 경계값 양쪽: `open_at` = 지금(잠김)과 1ms 전, 가격 등급 16·17개, 구역 하나 65,536·65,537석, 가격 1·10,000,000·0·10,000,001, 본문 12MiB 정확히·1바이트 넘음, 빈 구역 하나.
- 소유 대조를 뺀 요청: 다른 테넌트 공연, 실무자의 승인 뒤 저장, 다른 공연의 회차를 본문에 섞기(받지 않는 칸이라 400).
- 겹친 가드는 하나씩 빼 본다: 앱의 테넌트 조건과 행 보안, 트랜잭션 ①·②의 `If-Match` 확인, ①·②의 잠금 확인. 둘 사이에 다른 저장·오픈 시각 넘기기를 끼워 넣는 시험으로 각각을 잡는다.
- 시험 값은 상수와 다르게: 동시 게시 수·전체 시한은 환경 값이나 주입으로 바꿔 보고, 판 번호는 9 → 10을 지나게 해 글자 비교(`"10" < "9"`) 결함을 잡는다.
- 시작 파일 조립(`main.ts`의 파일 저장소·폴더)은 시험 조립과 따로 띄워 본다.
- 장애 주입은 끊는 자리를 셋으로 둔다: 파일 몇 개를 쓴 뒤 실패, 트랜잭션 ② 커밋 실패(판은 버린 번호가 되고 파일이 지워진다), 커밋 뒤 앞 판 지우기 실패(응답은 200이고 기록이 남는다). 끊긴 사례가 실제로 일어났는지 단언한다.

### 6.1 물을 것(방향을 바꾸는 결정, 정하지 않았다)

2. **Q-T36 ①②③을 다른 갈래 새 단계로 둘지**: queue-svc 로비·진입 대조와 입장 토큰 명단 키는 갈래 3, purchase-svc 규칙 한도는 갈래 1. 이 묶음(갈래 2)이 그 폴더를 고치지 않는 것을 추천한다(갈래 3 BAT-200·갈래 1 BAT-020이 같은 폴더를 고치는 중이고, 진입 Lua·입장 확정·홀드 Lua는 그 갈래가 만든 A등급 핵심이다).
3. **대기열 사본 `q:{event:E}:elig:{listKey}`를 쓰는 쪽**(open-items 102 ⑹, 소유자 결정 몫): 추천은 회차 일정 사본 `q:{event:E}:cfg`를 쓰는 판매 승인 경로(LCH-080)와 같은 '사본 쓰기' 길로 core-svc가 명단을 잠글 때 쓰고, 수명을 파기 시각에 맞춘다. 다른 안은 queue-svc 내부 gRPC로 넘기기다(queue-svc가 자기 Redis만 쓴다).
4. **회원 코드 → 계정 ID 변환**: identity-svc에 일괄 변환 RPC(예 `ResolveMemberCodes`, 한 번에 1만 개 [가정])가 없다. 갈래 3 영역(identity.proto·identity-svc 서버)이라 누가 만들지 정해야 한다.
5. **판매 정책 평가기를 둘 패키지**: d5 §6.7은 `@peaket/validation`이다. core-svc·apps/partner(그리고 purchase-svc·queue-svc)가 새 작업 공간 의존을 가져야 하고, pnpm이 막혀 잠금 파일을 손으로 고치고 링크를 손으로 만들어야 한다(외부 패키지는 아니다. HOT-180의 search-normalize가 같은 꼴로 잠금 파일 27줄을 고쳤다). validation은 지금 TS 원본만 내보내 서비스용 빌드도 더해야 한다. 허락할지.
6. **(확인) 가격 등급의 단위와 `event_seat_price`**: open-items 101 ⑴·102 ⑴은 '소유자 결정'으로 남아 있었다. 위저드·ADR-0093을 근거로 '공연(배치본) 단위, `event_seat_price`는 만들지 않음'으로 정본에 썼다(ADR-0260 결정 2, 되돌릴 조건 포함). 회차마다 가격이 달라야 하면 HOT-240 구현 전에 알려 달라(바뀌는 곳: data.md·openapi `priceTiers`·결정 2·4·12).
