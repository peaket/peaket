# 묶음 계획: BAT-355(ops-svc 명령 수명주기·2인 승인·dry-run·명령 4 보호 대역, 감사 체인의 키 건 mac·5분 앵커·검증 잡)

- **무엇**: BUILD_ORDER 145행 BAT-355(갈래 4, 구간 3, 등급 B, 4.25일, OPS-260·OPS-270, 단계 줄 543·544행)의 작업 목록이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **쉬운 말**: 운영자의 명령(입장 목표 바꾸기, 판매 멈추기, 대역 차단 등)이 '사유 → 사전 모의(dry-run, 실행하면 무엇이 바뀌는지 미리 세고 내다본 값) → 승인 → 전달 → 확인 → 되돌리기·만료'의 정해진 길만 걷게 한다. 그 기록은 덧붙이기만 하는 감사 로그에 남고, 키를 건 해시(mac, 비밀 키가 있어야 만들 수 있는 위조 확인 값)로 줄줄이 묶여 DB에서 몰래 고치면 다음 검증에서 드러난다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane4`, 가지 `feature/lane4-BAT-355`, 출발 `origin/develop` `de4d6a67e`. 계획 담당은 제품·시험 코드를 쓰지 않았고 시험·Docker를 돌리지 않았다.
- **차례**: B 정방향 짧은 고리(ADR-0281 결정 5, ADR-0283 결정 2, ADR-0331): 계획 → 구현 → 시험 → 리뷰 → 리뷰 반영 → 검증 → 기록. 계획 커밋에 `Batch-Order: impl-first`.
- **한 줄 결론**: 접수·2인 승인·재인증·해시 체인·체크포인트는 있다. 비어 있는 것은 DRY_RUN 단계와 실행 뒤 비교, 승인 기한, 되돌리기·연장·자동 만료, 멱등, 사람 칸의 가명 참조, 명령 4 조건, mac 전체(키·작업자·경보·앵커·검증 잡)다. dry-run 센 값의 원천 경로와 HOT-050이 넘긴 두 가지는 '감독에게'로 올리고 그 부분만 빼고 계획했다.

## 2. 감독에게

정하지 않고 올리는 것이다. 이 계획은 그 부분만 빼고 끝냈다. 답이 늦으면 구현은 포트·ops 쪽부터 한다.

1. **dry-run 센 값의 원천(C-T6 ①)과 회차 결제사 상한.** 정본은 센 값이 '같은 시각의 원천(대기열 Redis·purchase DB·게이트웨이 집계)에서 직접 센 값과 같다'고만 한다. ops-svc에서 닿는 읽기 길이 없다(`control.proto`는 `ApplyControl`뿐, 세 서비스에도 없다). 다른 서비스 계약을 바꾸는 구조 결정이다.
   - **(가, 추천)** `ControlReceiver`에 읽기 전용 `PreviewControl`(범위·종류 → 센 값·원천·센 시각, 리더는 결제사 상한도)을 더하고 받는 쪽은 같은 갈래 BAT-365(OPS-300)에서 만든다. C-T6 ①은 BAT-365 범위로 옮긴다. 명령 4의 '대역별 최근 5분 요청 수'는 원천이 정본에 없어 OPS-310 때 정한다.
   - (나) 이 묶음에서 세 서비스에 읽기 경로를 더한다(다른 갈래 코드, 약 1.5일 [추정] 늘어 5일을 넘는다). (다) Prometheus 지표로 센다(정본과 달라 C-T6 ①을 고쳐야 한다).
   - 어느 쪽이든 이 묶음은 `DryRunSource` 포트·기록·예측·비교까지 하고 어댑터는 비워 둔다(센 값은 `unavailable`). 명령 1 목표는 절대 상·하한(8,000·1,000)만 거른다(admission-ctrl도 적용 때 묶는다).
2. **HOT-050이 넘긴 두 가지.**
   - (a) 셔플 커밋 공시를 SYSTEM 감사 기록으로: ops 쪽 받는 경로(ADR-0341 결정 7)는 이 묶음이 만든다. **추천**: queue-svc 쪽(`ShuffleDisclosures` 어댑터 하나와 조립, 다른 갈래 코드)도 이 묶음 구현 담당이 그 두 곳만 고친다(포트 그대로, 실패해도 공시를 막지 않고 같은 `eventKey`로 3번 [가정] 다시 보낸 뒤 지금의 로그 줄). 다른 안: queue-svc를 맡은 갈래로 넘긴다.
   - (b) 셔플 검증 정보 사본을 시드 공개 때 불변 저장소에: ops-svc와 무관한 admission-ctrl·queue-svc·결과 객체 저장소(ADR-0232) 일이다. **추천**: 새 단계(예 'HOT-05x 셔플 검증 정보 사본', 0.75일 [추정])로 뗀다. 다른 안: 이 묶음에서 하고 4.25일을 넘긴다.
3. **(알림) 보안 사고 기록 서버를 만드는 단계를 찾지 못했다.** C-T27 ②(FR-063)와 §9 법정 조치의 서버 몫(docs/data.md `security_incident`)이다(OPS-400은 화면, OPS-100은 기한 경보). **추천**: 구간 마무리 때 단계를 더한다. 이 묶음은 SEV2와 `AUDIT_CHAIN_MISMATCH` 기록까지 하고 C-T27 ②를 뺐다.

결정(감독이 정한 넷):
- 1은 (가)다. `PreviewControl` RPC(proto)와 받는 쪽은 BAT-365(OPS-300)가 만들고, C-T6 ①은 BAT-365로 옮긴다(ADR-0340 결정 11, docs/review/ledger-notes.md '다른 단계', BUILD_ORDER BAT-365 장부 범위). 이 묶음은 `DryRunSource` 포트·기록·예측·비교와 `unavailable` 어댑터까지다(감독 결정 2026-11-21).
- 2(a)는 이 묶음이 queue-svc 쪽도 한다. 다만 조립 두 줄(ops-svc `src/main.ts`의 지표 등록, queue-svc `src/start.ts`의 `opsAudit` 칸)은 갈래 1 BAT-059가 합친 뒤로 미룬다(감독 결정 2026-11-21).
- 2(b)는 새 단계를 더하지 않는다. `docs/lanes/coord.md` 'SEG 때 정할 범위 늘어남' 후보로 두고, 기록 커밋에서 감독 세션이 적는다(감독 결정 2026-11-21).
- 3도 새 단계를 더하지 않는다. 같은 후보 목록에 두고 기록 커밋에서 감독 세션이 적는다(감독 결정 2026-11-21).

## 8. 공개 인터페이스

### 8.1 바깥 REST(openapi, 구현 커밋이 계약·생성물을 함께)

- `POST /v1/ops/commands`는 `Idempotency-Key` 필수, `dryRun`은 기록. 새 `POST /v1/ops/command-dry-runs`(200 `CommandDryRun`). `…/approvals`·`/rejections`는 `REVERT_PENDING`도 받고 기한 뒤 409. `…/reversions`(200·202·409·502)·`…/extensions`(200·409·502). 상세는 `dryRun`·`expiresAt`·`approvalExpiresAt`·대응 표로 푼 `requestedBy`·`approvals`·`canApprove`. 응답 코드와 새 Problem type 셋(`command-out-of-range` 422, `command-not-revertible` 409, `command-dispatch-failed` 502)의 정본은 ADR-0340 결정 2·5·7·9다.

## 13. 자주 놓친 결함(시험·구현 지시문에 넣는다)

- 저장소 응답은 정확한 값까지(상태, 사건 종류·차례, 표마다 행 수, 첫 어긋난 seq).
- 경계는 양쪽(10분 − 1ms·정각, 60,000·60,001ms, /16·/15, /48·/47, 5분 비교). 시간은 가짜 시계, 단언 값은 정본 값.
- 허용·거부 목록은 목록 밖 값마다(명령 유형, `AUTO_ACTION` 유형, `recordType`, 봇 강도, 대역 꼴).
- 겹친 가드는 하나씩 뺀다: 응용 층 요청자 검사와 `command_actor` 유일 제약, 원본 행 대조(`sourceMatches`)와 mac. C-T27 변조 시험은 원본 행과 키 없는 해시를 모두 맞춰 mac만 잡게 한다.
- 판정 함수만 말고 부르는 쪽이 쓰는지: `approvalModeOf(type, params)`가 재인증 요구와 첫 상태를 바꾸는지 HTTP 경계에서 본다.
- 빈 결과가 통과로 새지 않게(검증 `ERROR`, dry-run·비교의 `unavailable`). 장애 주입은 끊긴 사례가 실제로 있었는지 단언한다.
- 재인증 토큰의 계정·세션 대조를 뺀 요청이 거절되는지 본다.
- `main.ts` 조립은 따로 띄워 본다: 운영 환경에 키 ID·넘길 리전·버킷이 없으면 시작하지 않는다.
- 시험의 간격·바퀴 크기는 코드 상수와 다른 값으로 넣어 본다.

### 15.3 막는 지적과 재현

막는 지적(높음·보안·통과 기준)은 RV-01~RV-05 다섯이고 이 묶음에서 고친다. RV-01~03은 시험 담당이 재현 시험을 먼저 쓰고 구현 담당이 고친다. RV-04·05는 게이트 명령이 재현이다.

- RV-01: `test-int/audit-chain-mac.int.test.ts`의 C-T27 ① 흐름에서 첫 VALID 뒤 seq 2를 키 없이 고치고 `update audit_chain set created_at = created_at - interval '26 hours'`를 더한 뒤 1시간 뒤 검증 → MISMATCH(seq 2)를 단언한다(지금은 VALID, fromSeq 5).
- RV-02: 실행기를 붙인 1인 명령을 실행한 뒤 `audit_checkpoint.actor_ref`(메모리 조립이면 체크포인트 저장소 `entries[].actorRef`)에 요청자·실행자 관리 계정 ID가 없음을 단언한다.
- RV-03: `ACKED`인 `DEGRADED_MODE`를 commander가 `X-Reauth-Token` 없이 `/reversions` → 403 `reauth-required`, 되돌리기 사건·감사·실행 포트 호출 0을 단언한다.
- RV-04: `node tools/ci/gateway-routes.mjs --check` 끝 코드 0.
- RV-05: `node tools/ci/contract-breaking.mjs --target origin/develop` 통과(또는 승인된 깨짐 예외).

중간·낮음(RV-06~RV-13)은 구간 끝 정리 목록으로 간다.
