# 기능 계획: F-02-5(설정형 명령 5·8·9의 설정 사건과 적용 확인, `PreviewControl` 사전 모의 센 값, 온세일 로그 표본 생산)

- **진행**: 2026-11-25 동결 로컬 재개. 계획·시험 완료, **시험 리뷰 지적(TR-01~05) 반영 대기**. 구현은 시험 리뷰와 고정 뒤에 시작한다(A등급 차례, ADR-0372·ADR-0381, 동결 지시 2026-11-25).
- **무엇**: BUILD_ORDER '기능 단위 계획' F-02-5(등급 A, OPS-300, WBS 2.00일, 단계 줄 `OPS-300 wbs 4.4.2 ①`의 나머지)의 작업 목록이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **쉬운 말**: 봇 판정 강도(명령 5), 로그 자세히 남기기(명령 8), 부가 기능 끄기(명령 9)는 카프카(사건을 나르는 우편함)의 '설정 게시판'(압축 토픽, 키마다 마지막 글만 남는 게시판) `control.settings`로 퍼진다. 이 길에는 "받았다"는 답(ack)이 없다. 그래서 관제 서버(ops-svc)가 30초 동안 지표 저장소(Prometheus)를 보고 "받는 서비스의 모든 파드가 그 판을 적용했다"를 확인한다(적용 확인). 또 명령을 내리기 전에 보여 주는 사전 모의(dry-run, 실행하면 무엇이 바뀌는지 미리 세어 보는 것)의 '센 값'을, 원천을 가진 서버(입장 제어 리더·구매 서버·대기열 서버)가 직접 세어 주는 읽기 전용 호출 `PreviewControl`로 채운다. 끝으로 온세일(판매 시작) 구간에 정상 로그를 100줄에 1줄만 남기도록 ops-svc가 `LOG_SAMPLING` 설정 사건을 낸다.
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-02-5`, 가지 `freeze/lane2-F-02-5`, 출발 `1d10d6da3`(2026-11-25 최신 develop). 기존 계획·미완 시험은 `D:/ticketpass-lane4-F-02-5` 가지 `feature/lane4-F-02-5`의 커밋 넷(`e668b2e58`, `371ea460a`, `5c30c5080`, `de5e2c5b0`)만 가져와 최신 develop에 맞췄다. F-02-2 시험 커밋 등 다른 커밋은 가져오지 않았다.
- **동결 로컬 범위**: 이 기능은 ADR-0373으로 7일 완성 범위 밖이다. `develop`·`release`에 합치지 않고 `freeze/lane2-F-02-5` 가지만 푸시한다. 게이트는 로컬에서 돌리고, Docker가 필요하면 `tools/local` 잠금(`lock.sh take|drop docker lane2-F-02-5`)을 잡고 `docker-all`은 쓰지 않는다. 다른 동결 작업과 겹치면 기다린다.
- **차례(A등급, ADR-0372·ADR-0381, 동결 지시 2026-11-25)**: 계획 → 시험 → **시험 리뷰(새 세션)** → 시험 고정 → 구현 → **구현 리뷰(새 세션)** → 지적 반영 → 고친 곳 다시 보기 → 게이트. 이번 턴은 계획·시험을 끝내고 시험 리뷰를 받을 준비에서 멈춘다. 구현은 시험 리뷰 고정 뒤에 시작한다.
- **한 줄 결론**: 지금은 설정 사건이 명령 12 한 종류만 나가고, 적용 확인·센 값은 비어 있으며(늘 `unavailable`), 온세일 로그 표본 사건은 없다. 빈칸은 ADR-0365 결정 13~20으로 정했다(새 ADR 번호 없음). 명령 7의 purchase-svc 몫은 F-03-5로 넘어갔고, trust-svc 강도 반영·core-svc 후기 가드·`control.settings` 압축 토픽 선언·`LOG_SAMPLING` 생산은 이 기능이 한다. 마이그레이션은 ops-svc 0026 하나(0025 다음 0028이라 0026·0027이 비어 있다). 어림 약 4.5일 [가정](WBS 2.00보다 크나 5일 상한 안).

## 2. 감독에게

감독이 2026-11-23에 답했고, 2026-11-25 동결 로컬 재개를 지시했다. 이 계획은 그대로 따른다. ADR-0365 결정 13~20이 그 결정대로 쓰였다.

1. **크기** — 나누지 않는다. 다시 잰 어림은 약 4.5일 [가정]: 설정 사건 0.5, 적용 확인 1.0, `PreviewControl` 받는 쪽 셋과 ops 원천 1.0, core-svc 후기 가드(C-T51) 0.5, trust-svc 강도 반영 0.5, 온세일 로그 표본 0.75, 토픽 선언 0.25, 겹침 rebase·gen 0.25. WBS 일수 고치기는 감독 몫이라 행의 2.00은 그대로다.
2. **명령 7의 purchase-svc 사건** — 승인. purchase-svc 사건(`LobbyBannerValue {templateId}`)과 그 적용 확인은 승인된 공지 템플릿 저장소를 만드는 F-03-5(갈래 2, OPS-410)로 간다. 이 기능의 완료 정의는 '설정형 명령 5·8·9'로 맞췄다. F-03-5 행(장부 범위·완료 정의에 그 몫, 선행에 F-02-5)은 기록 커밋이 고친다('기록에 할 것').
3. **명령 5의 trust-svc 읽는 쪽** — 이 기능 안에서 한다. 정본(bot-defense §4.4 '설정 읽기')이 적용법을 이미 적었다. 코드에는 규칙 묶음의 `setIntensity`(주석 'control.settings 연결은 뒤 단계다')와 요청마다 강도를 한 번 읽는 `ScoreRisk`가 있고, `main.ts`는 이미 `startServiceControlSync(service, env, { sessions: false })`를 켠다(로그 레벨·표본 설정을 받는 길). 남은 빈칸은 계약 강도 이름(`STANDARD`·`AGGRESSIVE`)과 비공개 규칙 파일 이름(`BASE`·`STRICT`)의 잇기, 값 없음의 기본, 재평가 모드를 누가 읽느냐뿐이라 ADR-0365 결정 19로 정했다(약 0.5일). 재평가 작업자(`trust-reassess`)는 아직 없어 `reassessMode`는 설정 저장소에 남기만 한다.
4. **C-T51의 core-svc 읽는 쪽** — 승인. core-svc 새 파일 하나(후기 기능 플래그 가드)와 등록 한 줄(ADR-0365 결정 17). core-svc 마이그레이션은 없다.
5. **`control.settings` 압축 선언** — 저장소에서 토픽을 만드는 곳은 로컬·CI kind 무대의 `tools/local/v1-objects.mjs`(`V1_KAFKA_TOPICS`·`kafkaTopicArgs`, `kafka-topics.sh --create`)뿐이다. Strimzi(`deploy/local/kafka.yaml`)는 자동 토픽 만들기를 끄고 `KafkaTopic`을 두지 않으며, Helm 차트·Terraform에도 토픽 선언이 없다. 통합 시험은 시험마다 `createTopic`으로 설정 없이 만든다. 그래서 이 기능이 그 목록에 `control.settings`를 더하고 `cleanup.policy=compact`·`min.compaction.lag.ms=86400000`·`delete.retention.ms=604800000`을 싣는다(ADR-0365 결정 20). 운영 MSK(Terraform)는 구간 5이고, F-09-3 행 비고 한 줄은 기록 커밋 몫이다('기록에 할 것'). `control.sessions-terminated`도 그 목록에 없으나 이 기능 범위 밖이라 정리 목록 후보로 둔다.
6. **번호** — 새 ADR 없음(ADR-0365 보충 13~20). 마이그레이션 ops-svc **0026**(`command_apply_check`, Outbox `sent_at` 읽기 권한). 0025 다음이 0028이라 0026·0027이 비어 있다. purchase-svc **0034**는 5분 세기에 색인이 꼭 필요할 때만(14절 3). admission-ctrl·queue-svc는 Redis만, core-svc·trust-svc·payment-svc 마이그레이션 0개.
7. **차례와 겹침** — F-02-1 → F-02-2 → 이 기능. F-02-1의 `ControlDispatcher`·`ControlTargets`·`control_version`·`command-view.ts`의 `delivery`·admission-ctrl 제어 서버를 쓴다. F-02-2와 겹치는 곳: `control.proto`(F-02-2는 종류 9, 이 기능은 RPC 하나), ops-svc `execute-command.ts`(ACKED 트랜잭션의 사건)·`settings-outbox.ts`·`domain/ports.ts`·`main.ts`·`app.module.ts`, contracts 생성물, BUILD_ORDER 이웃 행. 뒤에 합치는 이 기능이 rebase 뒤 contracts·api-client `gen`을 다시 돌린다(동결이라 지금은 하지 않는다). payment-svc는 고치지 않는다(명령 12 적용 확인은 지표만 읽는다).
8. **갈래 2 F-03-1·F-03-4가 이미 합쳐진 develop 위** — F-03-1이 `modules/live/`, F-03-3이 readiness·판단 위젯, F-03-4가 명령 카드를 합쳤다. 이 기능이 고치는 ops-svc 파일: `docs/api/openapi.yaml`(`Command.params` 설명), `packages/api-client` 생성물(합칠 때 gen), `modules/commands/**`(7절), `app.module.ts`(손잡이 둘), `main.ts`(환경 값·조립), `migrations/0026`과 journal. `modules/alerts/`는 공개 면만 쓴다. 명령 카드 글('보냄 · 전파 대기', "카프카가 돌아오면 이어 보냅니다…", 못 미친 파드 표시)은 F-03-4 몫이다.
9. **ADR-0365를 두 가지가 고친다** — F-02-1 기록 커밋이 '확인' 절을, 이 계획 커밋이 결정 13~20·상태·관련 ID·결과를 고쳤다. 줄이 달라 rebase로 풀린다.
10. **넘겨받은 것 확인** — BAT-355 RV-10(낮음, 자동 조치 판정을 센 값과 견줌)과 '명령 5 승인 역할(정본보다 엄격)은 BAT-365'는 범위 밖이라 정리 목록 후보로 둔다. BAT-360 `settings-outbox.ts`의 '지우는 표시는 BAT-365가 정한다'는 결정 13(내지 않는다)으로 닫는다. `docs/review/ledger-notes.md` C-T6 ① '다른 단계' 줄은 이 기능의 시험 커밋이 지웠다. BAT-215가 넘긴 `LOG_SAMPLING` 내기·C-T75 ①④는 이 기능 시험 커밋이 생산 쪽 시험으로 받았다.

## 3. 범위

### 3.1 하는 것

- **설정 사건 내기(ADR-0365 결정 9·13)**: 명령 5·8·9 실행에서 `ACKED`와 같은 트랜잭션에 사건 하나, 명령 8 만료(정비 바퀴의 `AUTO_EXPIRED`)와 되돌리기·명령 5·9 되돌리기의 새 사건, 명령 8·9 `params` 닫기(목록 밖 422), 설정 판을 원장으로 매기기(명령 12 포함), 적용 확인 행을 같은 트랜잭션에.
- **적용 확인(결정 10·14·15)**: 정비 바퀴 5초·1분, Outbox `sent_at` 보기, Prometheus 즉시 질의 어댑터, 상태 다섯과 경계, SEV3 열기·닫기, `delivery`(`APPLY_CHECK`), `PEAKET_PROMETHEUS_URL` 조립(운영과 같은 환경에서 없으면 시작 실패).
- **`PreviewControl`(결정 11·16)**: proto RPC·메시지와 생성물, admission-ctrl 리더 주기 값, purchase-svc 세션 수·Paying 수·5분 홀드·접수 속도, queue-svc 대기 인원, ops-svc `DryRunSource` 어댑터(명령 1·3), 받은 값 검사.
- **C-T51 읽는 쪽(결정 17)**: core-svc 후기 경로의 플래그 가드.
- **trust-svc 명령 5 적용(결정 19)**: `controlSync.sync.settings`의 `PLATFORM:BOT_LEVEL:` 바뀜 → 규칙 묶음 강도. 시작 때 설정을 읽기 전에는 준비 아님(플랫폼이 이미 그렇게 한다).
- **온세일 로그 표본 생산(C-T75 ①④, ADR-0334 결정 1·3)**: ops-svc가 1분 바퀴로 대형·중형 회차 오픈 −10분부터 +60분까지 `LOG_SAMPLING`(`PLATFORM`, `*`, `oneIn` 100, `expiresAt` = 걸친 윈도우 끝)을 `control.settings`로 낸다. core-svc에서 앞으로 2시간 안의 오픈(회차·오픈 시각·규모)을 읽는 포트와 내부 HTTP 경로를 더한다. 복제 둘이 같은 끝을 내도 같은 `commandId`·`eventKey`로 한 번만 적용된다.
- **토픽 선언(결정 20)**: kind 무대 토픽 목록에 압축 `control.settings`.

## 8. 공개 인터페이스(시험이 이 이름·꼴을 그대로 쓴다)

F-02-1·F-02-2가 이미 내놓은 이름(그 계획들의 '구현 메모 > 시험 담당에게')을 그대로 쓰고 더하기만 한다. 구현이 이름을 바꿔야 하면 구현 전에 이 절을 고치는 계획 커밋을 먼저 낸다. '새'가 붙은 것만 이 기능이 만든다.

### 8.1 계약

- **`control.proto`**(새 RPC, 종류 1~9는 그대로): `rpc PreviewControl(PreviewControlRequest) returns (PreviewControlResponse)`. `PreviewControlRequest{string scope = 1; ControlKind kind = 2; repeated string keys = 3;}`, `PreviewCount{string key = 1; double value = 2; string source = 3; google.protobuf.Timestamp measured_at = 4;}`, `PreviewUnavailable{string key = 1; string reason = 2;}`, `PreviewControlResponse{repeated PreviewCount counts = 1; repeated PreviewUnavailable unavailable = 2; string pod_name = 3;}`. `kind`는 `CONTROL_KIND_ADMISSION_TARGET`(admission-ctrl)·`CONTROL_KIND_SALE_PAUSE`(purchase-svc·queue-svc)만, 그 밖은 `UNIMPLEMENTED`. `scope`가 소문자 UUID가 아니거나 `keys`가 0개·17개 이상이면 `INVALID_ARGUMENT`(상수 `PREVIEW_MAX_KEYS` = 16). admission-ctrl 비리더는 `UNAVAILABLE`, 메시지 `not-leader`(F-02-1의 `NOT_LEADER`).
