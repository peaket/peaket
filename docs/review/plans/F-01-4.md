- **설정 자리와 겹치기**: observability.md:115~116. Loki·Tempo는 설정 파일을 하나만 읽는다. 그래서 `--render`가 운영 판(`config.yaml`) 위에 로컬 판(`local.yaml`)을 깊게 합친다. 표(매핑)는 키마다 합치고, 목록과 값은 뒤 파일이 통째로 바꾼다. 로컬 판에만 있는 키도 더한다. 결과는 YAML 한 문서이고, 같은 입력이면 같은 바이트다.
- **Mimir**: :117. 인제스터 링 `replication_factor` 3, `zone_awareness_enabled` 참. 값 3은 :112의 '3중 복제'에서 읽는다. 로컬 판은 없다(Mimir는 규칙 확인과 G-26에서만 띄운다, :112).
- **Loki**: :118과 §7 :518, §9 :594, ADR-0125:56.
  - 운영 판: 복제 3, 영역 인식, 보존(`limits_config.retention_period`)은 §9 '정형 로그' 행의 30일, 컴팩터의 보존 지우기 켬. 한도 넷(`ingestion_rate_mb`·`ingestion_burst_size_mb`·`per_stream_rate_limit`·`per_stream_rate_limit_burst`)은 ADR-0125:56의 값. `auth_enabled` 거짓.
  - OTLP 받기: `limits_config.otlp_config.resource_attributes`에서 기본 색인 목록을 끄고(`ignore_defaults`), 색인 라벨로 둘 자원 속성을 `namespace`·`service`·`env`·`cluster` 넷으로만 적는다. 그 밖은 구조화 메타데이터다. `discover_service_name`은 빈 목록. 설정 이름은 고른 Loki 판에서 구현 담당이 확인한다(판은 3.x [가정]).
  - 로컬 판: 단일 프로세스, 메모리 링, 복제 1, 파일 저장소, 영역 인식 끔. 한도·라벨·보존은 운영 판 그대로다(덮지 않는다). 그래서 Docker 시험이 운영 판의 한도와 라벨을 그대로 본다.
- **Tempo**: :119, §6 :509, §9 :595, ADR-0078 결정 3.
  - 운영 판: 쓰기 큐 `ingest.kafka`의 주소는 `${PEAKET_OBS_KAFKA_BROKERS}`(환경 변수 펼침), 블록 보존은 §9 '분산 트레이스' 행의 14일(336h). metrics-generator 처리기는 서비스 그래프 하나(`service-graphs`)이고 span 지표 처리기는 켜지 않는다. 연결 지표를 켠다 [확인 필요, 감독에게 5]. 원격 쓰기는 하나뿐이고 머리 `X-Scope-OrgID: raw`, 주소는 Mimir(`deploy/platform/observability/prometheus/remote-write.yaml`의 `mimir-raw`와 같은 주소).
  - 로컬 판: 모놀리식, Kafka 쓰기 끔, 블록은 컨테이너 안 파일, 원격 쓰기 주소는 Docker 네트워크 별칭 `peaket-prom:9090`의 `/api/v1/write`(테넌트 머리는 운영 판 그대로 남는다). Tempo 3 모놀리식에서 metrics-generator가 Kafka 없이 도는지는 시험 담당이 고정한 이미지로 먼저 확인한다. 안 되면 로컬 판에 Kafka를 더하고(`packages/platform/test-int/containers.ts`의 Kafka 꼴) 그 사실을 '시험 결과'에 적는다.
- **exporter**: :120, §8 :552·:572~573.
  - postgres_exporter 원천: `{ image, args }`. 인자는 쿼리 통계 수집기 켬, 쿼리 문장 싣기 끔, 상위 20(§8 :552의 '상위 20개'). 인자 이름은 고른 판에서 구현 담당이 확인한다(쿼리 통계 수집기의 `limit`·`include_query` 꼴 [가정]). 접속 사용자는 `pg_monitor` 역할만 가진 모니터링 계정이다(F-01-1 증거 수집기와 같은 꼴).
  - YACE 원천: 작업 둘. ① CloudFront 배포 전부의 `Requests` 1분 합계(지역 us-east-1) ② 태그로 고른 queue·api 두 배포만 `502ErrorRate`·`504ErrorRate`·`Requests`, `delay` 300초(5분). 그 밖의 지표는 없다(§8 :572~573의 조회 요금 근거).
  - ClickHouse 포트 9363·`/metrics` [가정]은 정본에만 적고 설정 파일은 INF-020이 만든다(이 저장소에 ClickHouse 서버 설정 파일이 없다).
- **Grafana 연결**: :121, §2 :132·:134.
  - 클러스터 Prometheus(`datasources.yaml`, uid `prometheus`)와 Mimir 원본(`datasources-platform.yaml`, uid `mimir-raw`)의 `jsonData.exemplarTraceIdDestinations`에 이름 `traceId`(§2 :132의 exemplar 라벨 이름)·`datasourceUid: tempo` 하나.
  - Tempo(uid `tempo`)의 `jsonData.serviceMap.datasourceUid: mimir-raw`, `nodeGraph.enabled: true`, `tracesToProfiles.datasourceUid: pyroscope`.
  - 가리키는 uid는 두 파일을 합친 목록에서 같은 `orgId`에 있어야 한다. 제한 조직의 PostgreSQL 데이터 소스를 가리키는 연결은 F-01-2 검사가 이미 막는다.
- **정적 검사가 막는 것**: :122. 어긋남마다 `막음: <파일>: <까닭>` 한 줄. 운영 판의 '로컬 값'은 `inmemory` 링, 복제 1, 파일 저장소(`filesystem`·`local` 백엔드), Tempo의 Kafka 끔이다.
- **Loki 한도 시험의 부하(V-T30 ④)**: ADR-0125:56의 '표본 뒤 진입 2xx 1%는 초당 약 1MB, 진입 오류가 10%로 오르면 gw-queue 스트림 하나에 초당 약 10MB'와 :11의 줄 하나 약 500바이트. gw-queue 스트림 하나(라벨 넷 고정)에 초당 10MB를 20초 [제안] 넣는다. 그동안 Loki 기본 한도(스트림 3MB·순간 15MB, 테넌트 4MB·순간 6MB, ADR-0125:11)였다면 거절이 생길 양이다. PC가 초당 10MB를 내지 못하면 시험은 실패로 끝나고 도달한 속도를 적는다(통과로 꾸미지 않는다).
- **대시보드**: :267·:269와 §5 :457~466. uid `peaket-observability-pipeline`, 제목 '관측 파이프라인', platform 폴더. 첫 행은 네 신호 규칙(§3 규칙 1)의 대상이 아니다(서비스 대시보드가 아니다). 세 행과 패널:
  - 증거 수집기: 대상·결과별 수집 수(`evidence_collections_total` `target`·`result`), 경보 고른 결과(`evidence_webhook_alerts_total` `decision`), 거절 까닭(`evidence_webhook_rejected_total` `reason`).
  - OTel 수집기: 판정 전 버림(`otelcol_processor_tail_sampling_sampling_trace_dropped_too_early`), 보내기 실패(`otelcol_exporter_send_failed_*`, 내보내기별), 큐 사용률(`otelcol_exporter_queue_size ÷ otelcol_exporter_queue_capacity`), 받기 거절(`otelcol_receiver_refused_*`).
  - Loki: 받은 바이트(`loki_distributor_bytes_received_total`), 까닭별 거절(`loki_discarded_samples_total` `reason`).
  - 집계 창은 기존 생성기와 같은 `$__rate_interval`, 데이터 소스는 uid `prometheus`.
