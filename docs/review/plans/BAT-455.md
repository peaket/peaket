### 1. 먼저 바로잡는 것 — GAT-270의 정본 범위

지시서는 GAT-270을 '알림 설정·수신 거부·발송 기록'으로 적었지만, `docs/BUILD_ORDER.md` 595행과 `docs/wbs/wbs.md` 5.6.3의 GAT-270은 **파트너 웹훅 발송(Standard Webhooks 서명·비밀 교체 겹침, 웹훅 이벤트 8종과 구독 거르기, 발송 원장)**이다. 알림 설정·수신 거부·발송 기록은 GAT-250(5.6.1)의 범위다. 이 계획은 정본을 따른다.

- GAT-270은 BAT-610 잔여(R-588)가 코드를 넣었다: 등록·조회·고치기·비밀 재발급·발송 이력·다시 보내기, `webhook_endpoint`·`webhook_delivery`(0015), Standard Webhooks 서명(옛 비밀 24시간 겹침), 이벤트 8종 구독 거르기, 1분·5분·30분·2시간·6시간·12시간 재시도, DEAD, FAILING 비활성화, DNS 재검사·리디렉션 거부. 이 묶음은 수용 기준을 시험으로 다시 확인하고, 밖에서 막히는 몫(Secrets Manager/KMS, 파트너 콘솔 알림함·이메일, 분당 다시 보내기 상한, Kafka Outbox 소비자, 발송 파드의 나가는 443 제한 V-T34)을 '운영 전'으로 적는다.
- 그래서 이 묶음의 **개발 몫은 GAT-250**이다: 메일 대행사 포트·파일 대역, 발송 원장·워커, 재시도·실패 처리, 신청 설정·웹 푸시 구독·한 번 누름 수신 거부, 로그인 수단 변경 안내(I-T34), 계정 병합 때 설정 옮기기(POL-034).

**이 묶음이 닫지 못하는 것(이유)**

- **운영 메일 대행 계약**: 대행사가 정해지지 않았다(open-items 57). 파일 대역·포트·계약·시험까지 하고 실제 발송은 `PEAKET_NOTIFY_MAIL_DIR`(local·ci)로만 본다. 운영 값이 없으면 워커가 `FEATURE_UNAVAILABLE`로 남기고 503이 아니라 발송을 미룬다.
- **VAPID 운영 키·문자·알림톡**: OPEN[10] 소유자 결정(2026-11-02, ADR-0180)대로 서버 개인키는 Secrets Manager에서 메모리로 읽는 몫이다. 이 묶음은 `PEAKET_VAPID_PRIVATE_KEY`(JWK)·`PEAKET_VAPID_PUBLIC_KEY`를 환경으로 받고, local·ci는 고정 시험 키를 쓴다. 문자·알림톡은 대행 계약 뒤다(ADR-0060 결정 13).
- **POL-034 두 계정 이메일 완료 통지**: `identity.accounts-merged`에 흡수 계정 주소가 없고, 병합 확정 트랜잭션은 흡수 계정 이메일을 지운다. 주소를 Kafka에 싣는 것은 개인정보 최소화에 어긋난다. 이 묶음은 대표 계정 이메일과 흡수 계정의 남은 웹 푸시 구독으로 통지하고, 흡수 계정 이메일 통지는 identity와 계약(짧게 보관하는 암호화 사본 또는 내부 통지 입구)을 정한 뒤 후속으로 남긴다.
- **대량 발송(오픈·취소표 조각 원장)**: `notification_broadcast`·`notification_broadcast_chunk`와 계획 작업은 GAT-260(5.6.2 화면·대량 발송)의 몫이다. 이 묶음은 받는 사람 한 명짜리 낱건 원장·워커와 신청 설정까지다.
- **Kafka `trade.orders` 소비자**: R-592의 내부 입구를 원장으로 바꾸고, Kafka 소비자는 기존 core 소비자 틀에 얹을 수 있는 입구까지 만든다. 실제 Kafka 통합 시험은 Docker·Kafka 무대가 필요해 이 묶음은 단위·HTTP 시험과 소비자 배선 확인까지 한다(후속 위험).

### 4. 표·계약·설계

**마이그레이션 0046**(손으로 쓴 SQL, 파티션 표라 생성기를 쓰지 않는다)

- 칸 권한은 ADR-0351과 같은 꼴이다. `core_notify`는 원장에 넣고 집은 행의 결과 칸만 고치며, 본문·대상·계정·중복 키는 고치지 못한다. 팬 신청 표는 `sent_count`·`status`·`end_reason`·`night_push`·`updated_at`만 고친다. 파티션 부모의 기본 권한이 `core_notify`에 자동으로 붙지 않게 `ALTER DEFAULT PRIVILEGES`는 건드리지 않는다.
- 첫 `notification_delivery` 파티션은 마이그레이션 뒤 정비 함수(`ensureMonthlyPartitions`)가 만들고, `core-svc` 정비 일에 'notification-delivery-partitions'를 더한다(날짜를 박은 첫 파티션은 배포 날짜와 어긋난다, ADR-0114).

**발송 워커**

- due 행을 20개 [가정]까지 `FOR UPDATE SKIP LOCKED`로 집어 임대 2분을 걸고 커밋한 뒤 보낸다. 잠금을 쥔 채 바깥으로 나가지 않는다.
- 만료(`expires_at <= now`)는 `EXPIRED`, 재시도 한도(6회)를 넘으면 `DEAD`다. DEAD는 SEV3 로그·지표(`delivery_dead_total{kind}`)로 남긴다. 예매·결제·발권 표는 건드리지 않는다.
- 이메일 재시도: 1분·5분·30분·2시간·6시간·12시간 [가정], 지터 ±10%. 429·5xx·시간 초과는 재시도. 400·413은 즉시 DEAD. 결과 모름은 신청 알림·광고를 재시도하지 않고, 돈·보안·법정 통지(`REFUNDED`, `REFUND_FAILED`, `EVENT_CANCELLATION_CONFIRMED`, `EVENT_POSTPONED`, `FRAUD_*`)만 같은 중복 키로 한 번 더 보낸다.
- 신청 알림 job은 보내기 직전에 신청 행이 ACTIVE인지 다시 본다(끄면 건너뜀). 밤 웹 푸시는 `night_push`가 참일 때만 보낸다. 판정을 읽지 못하면 보내지 않고 다음 시도로 미룬다.
- 이메일 받는 주소·언어·상태는 identity-svc `RecipientQueryService.BatchGetRecipients`로 읽는다(포트 `RecipientDirectory`, 시험은 메모리). MERGED·DELETED·주소 없음은 이메일을 보내지 않는다(이메일은 재시도, 주소 없음은 기한까지).
- 웹 푸시: 계정의 구독마다 RFC 8291로 암호화하고 VAPID ES256 JWT(`aud`=구독 출처, `exp`=12시간)와 TTL·Urgency·Topic을 붙인다. 404·410·403(VAPID 불일치)은 구독을 지우고, 429·5xx는 남은 TTL 안에서 재시도한다. local·ci는 `FilePushTransport`가 보낼 봉투를 JSONL로 남긴다(파일 대역).
- 지표: `notify_suppressed_total{reason}`, `notify_push_responses_total{service,code_class}`, `delivery_job_due_backlog{kind}`. 계정·구독 주소·이메일은 라벨에 쓰지 않는다.

**I-T34와 POL-034**

- 내부 입구 `POST /internal/v1/notify/identity-events`(내부 토큰)가 `LOGIN_METHOD_CHANGED`와 `ACCOUNT_MERGED`를 받는다. Kafka `runKeyedConsumer`는 같은 유스케이스를 부른다(소비자 배선은 단위 시험).
- 연결·해제: `{kind}:{eventKey}:{accountId}:EMAIL`·`:WEB_PUSH` 중복 키로 한 번. 문안 '로그인 수단을 연결했습니다/해제했습니다'. 밤에는 웹 푸시를 보내지 않고 이메일만 보낸다(거래·안전).
- 병합: 흡수 계정의 `notification_subscription`을 대표 계정으로 옮기고 `(account_id,event_id,kind)`가 겹치면 하나만 남긴다(보낸 횟수는 큰 쪽). `push_subscription`도 옮기고 endpoint가 겹치면 대표 계정 행을 남긴다. 대표 계정 이메일로 완료 통지 한 통, 흡수 계정의 남은 푸시 구독으로 웹 푸시 한 번. 흡수 계정 이메일 통지는 §2의 막힌 몫이다.

### 확인한 것(지적 아님)

- **수신 거부**: 토큰은 `base64url(신청 ID ‖ HMAC 앞 16바이트)`이고 상수 시간 비교, 틀리거나 없어도 같은 200, GET 없음, 로그에 토큰 원문 없음. `List-Unsubscribe`·`List-Unsubscribe-Post` 머리는 신청 알림 이메일에만 붙는다.
- **재시도·실패**: 이메일·푸시 모두 쓸모 기한·최대 6회·지수 간격을 지키고, 400·413은 DEAD, 결과 모름은 신청 알림·광고를 다시 보내지 않는다. 알림 작업·기록만 바꾸고 예매·결제·발권 표를 부르지 않는다.
- **개인정보**: 작업 `vars`는 종류별 허용 목록만 받고 이메일·전화번호 꼴 값과 금지 키를 거부한다. 받는 주소는 보낼 때 identity에서 읽고 기록 표에는 넣지 않는다. 로그는 dedupKey·건수·사유만 남긴다.
- **권한**: `core_notify`는 신청의 다섯 칸, 구독 SELECT·DELETE, 원장 INSERT·상태 칸만 갖는다. `core_app`은 팬 경로 전체다. 파티션 부모의 기본 권한은 `core_notify`에 자동으로 붙지 않는다.
- **계약**: 새 경로는 기존 openapi 여섯 경로와 같은 모양이고 `gen:check`가 통과한다. opt-out form 본문은 `@AcceptFormUrlEncoded()`를 단 경로만 받고 다른 경로는 415다.
- **밤 규칙**: 판정은 보내는 순간의 KST이고, 신청 알림 웹 푸시만 `nightPush`를 본다. 이메일과 거래·안전 알림은 제한하지 않는다.
