# F-04-12 계획 — FRAUD_INVESTIGATOR 권한·사건 상태·조사 API·소명 요청 (동결 로컬)

- **무엇**: 기능 표 F-04-12(LCH-260)의 동결 로컬 트랙 계획이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **등급**: A(`Batch-Grade: A`). 차례는 계획 → 시험(구현 전) → 시험 리뷰(새 세션) → 시험 고정 → 구현 → 구현 리뷰(새 세션) → 지적 반영 → 고친 곳 다시 보기 → 게이트다(ADR-0372·0373·0381). 구현 담당은 고정된 시험을 고치지 못한다. 이번 턴은 계획·시험·기준 트리 실패 확인·게이트·푸시에서 멈추고 시험 리뷰를 기다린다.
- **동결 로컬 범위**: v1 출시 범위 밖이다(ADR-0373 결정 2, ADR-0386 결정 4·5, `docs/release/v1-scope.md` F-04-12). `freeze/lane6-F-04-12` 가지와 `D:/ticketpass-freeze-F-04-12` 워크트리에서만 개발하고 `develop`·`release/1.0.0`에 합치지 않는다. 출시 마이그레이션·릴리스 플래그·`deploy/` 값을 건드리지 않는다.
- **바탕**: `01f122860`(F-04-11 가지 끝, 2026-11-25). F-04-11이 만든 `services/inv-forensics`의 `SnapshotRecord`·`ClusterResult`·`verifySnapshot`을 입력으로 쓴다.
- **정본**: `docs/features/forensic-replay.md` §6.2·§6.7.1~§6.7.8·§8·§9, `docs/data.md` '부정 예매 사후 조사의 표', `docs/features/settlement.md`(부정 예매 취소 환급 경계), `docs/security/asvs/forensic-replay.md`, `docs/api/openapi.yaml` 태그 `investigations`, ADR-0171·0172·0173·0373·0381·0386.

## 1. 이 기능이 끝내는 것과 넘기는 것

### 1.1 끝내는 것

1. `FRAUD_INVESTIGATOR` 지정 확인을 조사 경로마다 요청 시점에 한다(캐시 없음). 지정이 없거나 `PSEUDONYM_HANDLER`를 함께 가진 계정은 403 `investigator-required`다(§6.2, FX-T16, C-T63 ①).
2. 사건 상태 C1·C3·C4·C14를 구현한다: 후보 묶음에서 사건 만들기, 소명 요청, 소명 판단으로 모두 인정되면 정상 종료, 계정 더하기·빼기(§6.7.4).
3. 조사 API 아홉 경로: 후보 묶음 목록·상세, 회차 머리, 후보 계산 다시 돌리기, 사건 만들기·목록·상세·고치기, 소명 요청(§6.7.8).
4. ops DB 표 `fraud_snapshot`·`fraud_cluster_run`·`fraud_cluster`·`fraud_cluster_member`·`fraud_case`·`fraud_case_event`의 마이그레이션과 저장소(DB·메모리). F-04-11 결과 JSON을 그 표에 옮기는 입구를 둔다.
5. 후보 계산 실패의 자동 세 번 재시도 판단·시도 행·다시 돌리기 경로(409 `fraud-run-retrying`·`fraud-run-in-progress`·`fraud-run-not-failed`, 410 `investigation-source-expired`). 실행기는 시도마다 `fraud_cluster_run` 행을 남기고, 네 번째 실패에 SEV3를 낸다.
6. `ops_event` `FRAUD_SNAPSHOT`·`FRAUD_CLUSTER_RUN` 줄. 하루 한 번, **열린 사건이 있는 회차**의 기록 검증이 불일치를 내면 SEV2 경보·보안 사고 기록 대상 표시·그 판을 쓰는 증거 묶음 내보내기 차단 상태를 남긴다.
7. 소명 요청의 양도 잠금(ticket-svc `SetTransferLock` 포트), 받은 사람 알림(사유 범주 없음), 잠금 최대 기한(첫 요청 + 14일, 연장 없음), 계정 빼기·모두 인정 때 잠금 풀기.
8. 조사 경로 조회·거절의 접속기록(`invAccess`/`admin_data_access` 상당) 남기기.

### 1.3 정본 빈칸과 이번에 정한 것(추천 적용 2026-11-25)

1. **C2 경로 없음**: §6.7.4 C2는 정상 종료를 말하지만 §6.7.8 PATCH는 "상태는 이 경로로 직접 바꾸지 못한다"고만 적고 경로를 주지 않는다. F-04-12는 C2를 구현하지 않고 F-04-13에 넘긴다. F-04-13은 계약에 `POST /v1/ops/fraud-cases/{caseId}/clearance`(본문 `{reason, outcomeLabel: HUMAN|NONE}`)를 더하는 안을 먼저 정본에 쓴다. 이 계획 커밋은 계약을 고치지 않는다.
2. **`fraud_snapshot` 검증 칸**: §6.7.2는 하루 검증·SEV2·내보내기 차단을 말하지만 `docs/data.md` 표에는 결과를 둘 칸이 없다. `fraud_snapshot.verify_status`(`OK|MISMATCH`)·`verified_at`을 더한다(§1.4). 내보내기 차단은 `verify_status = 'MISMATCH'`인 판을 쓰는 묶음으로 판정한다.
3. **`ops_event` 검증 줄**: 새 사건 이름을 만들지 않고 `FRAUD_SNAPSHOT`에 `stage` `VERIFIED|VERIFY_FAILED`를 붙인다. 후보 계산은 `FRAUD_CLUSTER_RUN`에 `stage` `STARTED|DONE|FAILED`를 붙인다.
4. **자동 재시도 수**: 처음 시도 1 + 자동 재시도 3 = 최대 시도 4다. `FAILED` 시도 N의 남은 자동 재시도는 `max(0, 3 − (N − 1))`이다. 판 4가 실패하면 0이고 SEV3다.
5. **다시 돌리기 조건**: 마지막 시도가 `FAILED`이고 남은 자동 재시도가 0이며 원천 보존이 살아 있을 때만 같은 생성 판의 새 시도(`attempt + 1`, `trigger MANUAL`)를 만든다. `RUNNING`은 409 `fraud-run-in-progress`, 남은 재시도가 있으면 409 `fraud-run-retrying`, 마지막이 `DONE`이면 409 `fraud-run-not-failed`다.
6. **소명 요청 응답의 `appealRequestId`**: 별도 표가 없으므로 요청의 `Idempotency-Key`를 그대로 쓴다. 같은 키 재요청은 같은 값을 돌려준다.
7. **잠금 최대 기한**: 계정마다 `처음 소명을 요청한 시각 + 14일`이다. 응답 `lockExpiresAt`은 이 요청으로 **처음** 잠긴 계정들의 기한이고, 처음 잠긴 계정이 없으면 null이다. 계정별 값은 사건 상세 `members[].lockExpiresAt`이다. 계정을 묶음에서 뺐다가 다시 더해도 이미 정한 `lockExpiresAt`은 지우지 않는다(같은 계정의 첫 요청 + 14일을 유지).
8. **소명 요청 순서**: 검증 → ticket-svc 잠금 → 저장(사건 상태·계정·사건 기록)이다. 잠금이 실패하면 저장하지 않고 503 `dependency-unavailable`이다. 저장이 실패하면 잠근 계정을 풀어 보상한다.
9. **조사 접속기록**: 모든 조사 경로가 허용·거절마다 `관리 계정 ID, 경로 이름, 회차·사건·묶음 ID, 행 수, 결과`를 남긴다. IP 원문·연락처·가명 값은 남기지 않는다. 기본 어댑터는 관제 감사 체인에 `recordType: 'ADMIN_DATA_ACCESS'`로 넣는다(C-T63이 말하는 `admin_data_access`의 이 저장소 판).
10. **조사관 판정**: `FRAUD_INVESTIGATOR`가 있고 `PSEUDONYM_HANDLER`가 없을 때만 통과한다. 둘 다 있으면 403 `investigator-required`다(정상 경로에서는 identity-svc가 지정을 거절하지만, 이미 그런 상태가 된 계정을 조사 경로에서도 막는다).
11. **원천 보존 끝**: 회차의 판매 종료(`saleEndsAtMs = 공연 시작 − 24시간`)에 24시간 + 30일을 더해 구한다(`sourceExpiresAtMs = saleEndsAtMs + 31일`). 이 시각이 지나면 다시 돌리기는 410이다.
12. **사건 판 동시 수정**: `PATCH`는 `If-Match` 필수(없으면 428 `precondition-required`, 다르면 412 `precondition-failed`)이고 저장소가 `version` 조건부 갱신으로 한 번만 성공한다. 사건을 바꾸는 경로(사건 만들기 뒤의 소명 요청·계정 더하기·빼기·소명 판단)는 성공할 때마다 판을 하나 올린다. 사건 기록은 `(case_id, seq)` 덧붙이기만 한다.
13. **사건 만들기의 담당**: 요청한 조사관이 담당(`assigneeId`)이 된다. 같은 묶음에 사건이 있으면 409 `fraud-case-exists`다.
14. **받은 사람 알림**: `SetTransferLock` 결과의 보유자 계정마다 한 번 알린다(같은 사람이 여러 표를 가져도 한 번). 알림 본문에 결제자의 사유 범주·계정·다른 사건 계정을 싣지 않는다. 응답 `notifiedHolderCount`는 알린 사람 수다.
15. **후보 저장**: F-04-11 `ClusterResult.clusters` 가운데 `candidate: true`만 `fraud_cluster`에 넣는다. `cluster_count`는 그 수다. `result_fingerprint`는 16진 64자 SHA-256을 bytea로 넣는다.
16. **감사·경보 포트**: 접속기록은 `InvestigationAccessLog`, SEV2 경보는 `FraudAlerts`, ops_event는 `FraudOpsEventSink` 포트로 둔다. 기본 어댑터는 서비스 로거·감사 체인을 쓴다. 시험은 가짜로 호출을 센다.

### 1.4 정본에 함께 쓰는 것(이 계획 커밋)

- `docs/data.md` `fraud_snapshot`에 `verify_status`·`verified_at` 두 칸을 더한다(§1.3 2). 표·칸 이름의 정본은 그대로 `docs/data.md`다.
- `docs/BUILD_ORDER.md` F-04-12 장부 범위를 `FX-T12, FX-T15, FX-T16, FX-T18`로 좁힌다(§1.5).

### 1.5 장부 범위를 좁힌다

- 원래 범위는 `docs/features/forensic-replay.md, FX-T12, FX-T15, FX-T16, FX-T18, C-T63, R-T33, docs/features/settlement.md, docs/security/asvs/forensic-replay.md`였다. 장부 도구는 정본 문서 경로가 있으면 그 문서의 판정 항목을 모두 끌어와 F-04-12와 닿지 않는 항목까지 **349개**로 잡았다(빈칸 51).
- 이 기능이 만드는 것의 판정은 FX-T12·FX-T15·FX-T16·FX-T18이다. C-T63 ①은 후보 목록·연결 그래프·리플레이 내보내기 세 경로를 함께 보는데, 이 기능은 그 가운데 후보 목록의 지정 확인·접속기록만 만들고 연결 그래프·리플레이 내보내기는 F-04-14·F-04-16이 붙인다. 그래서 C-T63 ①은 이 기능의 장부 범위로 잡지 않고, 지정 확인·접속기록은 FX-T16 ②·⑦이, 나머지 두 경로는 F-04-14·F-04-16이 닫는다. R-T33은 F-04-13, 나머지 FX-T와 ASVS 행은 각 기능의 추적 표가 맡는다. §8.6 3의 "장부 범위가 넓어 그 기능과 닿지 않는 항목이 들면 기능을 시작할 때 범위를 좁힌다"에 따라 범위를 네 항목으로 좁힌다. 정본 문서는 '완료 정의'의 판정 칸에 그대로 남는다.
- 상태(`동결`)·분류(`frozen-local`)는 바꾸지 않으므로 `node tools/ci/release-scope.mjs --check`의 대조에 영향이 없다.

## 2. 목표와 비목표

**목표**

1. 지정 조사관만 조사 경로를 쓰고, 모든 요청이 접속기록에 남는다. 지정을 거두면 다음 요청부터 403이다.
2. 후보 묶음에서 사건을 만들고, 소명을 요청하고, 소명 판단으로 정상 종료하며, 계정을 더하고 뺄 수 있다. 상태·판·사건 기록이 정본 규칙을 따른다.
3. ops DB에 여섯 표가 생기고 F-04-11 결과가 저장된다. 같은 입력을 다시 저장해도 판·시도·묶음이 중복되지 않는다.
4. 실패한 후보 계산의 자동 세 번 재시도와 조사관의 다시 돌리기가 정해진 409·410으로 갈린다.
5. 하루 검증 불일치가 SEV2·내보내기 차단으로 이어진다.
6. 소명 요청이 계정별 잠금 기한을 지키고, 받은 사람에게 사유 범주 없이 알린다.

**비목표(이번 턴에 하지 않는다)**

- 화면(SCR-070·071), 브라우저 확인, `apps/console-host` 변경.
- C2·C5~C13·C15~C17, 승인 업무 `FRAUD_ACTION`, 표 취소·환급·이용 제한·이의·정답 라벨 BOT.
- 연결 그래프·IP 원문·리플레이 파일·증거 묶음·내보내기 셋.
- 실제 ticket-svc gRPC·core-svc 팬 사본·notify 발송 연결(포트와 가짜 시험까지).
- 후보 계산 스케줄러·1시간 판 더하기·T+60분 고정 자동화.
- FX-T22 용량 측정.

## 3. 공개 인터페이스(시험이 이 이름을 쓴다)

## 5. 실패 시나리오와 엣지 케이스

1. **모듈이 없다**: 시험 첫 실행은 모듈을 찾지 못한다. 이 실패는 세지 않는다. 빈 껍데기를 두고 단언 실패를 본 뒤 구현한다.
2. **지정 없음/철회**: 지정이 없는 commander·cs_lead는 403 `investigator-required`. 지정을 거두면 다음 요청부터 403(캐시 없음). identity가 답하지 못하면 503 `authz-unavailable`이고 통과하지 않는다.
3. **두 지정**: `FRAUD_INVESTIGATOR`와 `PSEUDONYM_HANDLER`가 함께 있으면 403. 한쪽만 있으면 통과.
4. **판 경합**: 같은 판 두 번 PATCH → 첫 번째 200(version+1), 두 번째 412. If-Match 없음 428. 사건 기록 seq는 1부터 빈틈없이 붙는다.
5. **사건 중복**: 같은 묶음에 사건을 두 번 만들면 409 `fraud-case-exists`. 다른 묶음이면 된다.
6. **기한 경계**: due = now + 24시간은 통과, 24시간 − 1ms는 422. due = 입장 시작은 422, 입장 시작 − 1ms는 통과. 지금이 입장 시작과 같거나 뒤면 409 `entry-started`.
7. **취소 마감 경계**: 공연 시작 − 26시간과 같으면 마감이고 − 26시간 + 1ms는 아직이다. 소명 기한 기본값은 `min(now+3일, 취소마감−6시간)`이 `now+24시간`보다 이르면 `now+24시간`이다.
8. **잠금 기한**: 처음 요청 + 14일과 같으면 그대로이고 늘리지 않는다. 다른 계정은 자기 첫 요청 + 14일을 따로 받는다. 다시 요청해도 기존 값이 있으면 바꾸지 않는다.
9. **잠금 실패**: ticket-svc 포트가 던지면 503이고 사건 상태·계정 소명 상태·사건 기록이 바뀌지 않는다. 저장이 실패하면 잠근 계정을 풀어 보상한다.
10. **대상 계정**: 사건에 없거나 이미 뺀 계정은 422. 빈 목록·100개 초과·중복은 400(본문 스키마, openapi `FraudAppealRequestCreate`). `APPEAL_PENDING`에서는 조사관이 더한 `NOT_REQUESTED` 계정만 다시 요청할 수 있고, 이미 요청한 계정은 409다.
11. **사유 범주**: 다섯 밖의 값, 빈 목록, 중복 값은 400(본문 스키마). 점수·가중치·다른 계정은 응답·알림에 없다.
12. **롤백(계정 빼기)**: 뺀 계정의 잠금을 풀고 `MEMBER_REMOVED`를 남긴다. 활성 계정이 0이 되거나 남은 활성 계정이 모두 `ACCEPTED`면 CLEARED·HUMAN·잠금 해제다.
13. **소명 판단**: `SUBMITTED`가 아닌 계정, 중복 계정, 없는 계정은 422. 인정은 그 계정의 잠금을 바로 풀고, 불인정은 잠금을 유지한다.
14. **재시도**: 실패 1·2·3·4의 남은 자동 재시도는 3·2·1·0이다. 0이 아니면 다시 돌리기는 409 `fraud-run-retrying`. 실행 중 409 `fraud-run-in-progress`, 성공 409 `fraud-run-not-failed`, 원천 만료 410. 다시 돌리기는 같은 생성 판의 `attempt + 1`·`MANUAL`이다.
15. **실패 사유**: 시간 초과는 `TIMEOUT`, 원천 읽기 오류는 `SOURCE_READ_FAILED`, 그 밖은 `OTHER`. 원문 오류 문구는 저장·응답에 넣지 않는다.
16. **검증 불일치**: 표 해시 하나나 판 해시가 다르면 `SEV2`, `exportBlocked: true`, `verify_status = 'MISMATCH'`, 경보 한 번. 같으면 `OK`, 차단 없음.
17. **저장 경계**: `fraud_snapshot` 기본 키 `(event_id, version)`, `fraud_cluster_run` 기본 키 `(event_id, generation, attempt)`, `fraud_cluster_member` 기본 키 `(cluster_id, account_id)`, `fraud_case.cluster_id` UNIQUE다. 같은 행을 다시 넣으면 던진다.
18. **원천 보존**: `now = sourceExpiresAt`이면 만료다(경계 포함). 그 전이면 다시 돌릴 수 있다.
19. **개인정보**: 접속기록·사건 기록·응답·알림에 IP 원문·연락처·결제 수단 값·가명 원문이 없다. 받은 사람 알림에 사유 범주가 없다.
20. **순수성**: 도메인 함수는 입력을 바꾸지 않고 시계·난수를 직접 쓰지 않는다. 시각은 받은 `nowMs`만 쓴다.

  2. **실행기·검증기·스케줄러**: `FraudClusterRunService`와 `VerifyDailySnapshots`는 시험·호출 단위로 있고, 실제 `inv-forensics` 실행기와 하루 검증 스케줄러는 main에 조립하지 않았다(둘 다 `Unavailable`이라 판정하지 않는다).
  3. **알림·라벨·경보**: `Logging*` 어댑터만 있다. notify 모듈 발송·trust-svc 라벨·ops 경보 표 연결은 F-04-13·F-04-15·F-04-19 몫이다.
  4. **F-04-11 결과 적재**: 변환기와 저장소 입구까지다. 고정·후보 실행이 끝난 결과를 ops DB에 자동으로 옮기는 작업은 스케줄러와 함께 F-04-19가 붙인다.
  5. **플랫폼 시험 흔들림**: `packages/platform` 전체에서 grpc-server·metric-rules 두 시험이 병렬 실행 때 흔들리고 홀로 돌리면 통과한다. 이 기능 변경(clock 음수 복원·빈 JSON 본문)과 직접 관련 없는 기존 시험이다.
  6. C2·C5~C13·C15~C17·R-T33·graph·replay-export·증거 묶음은 계획대로 F-04-13·F-04-14·F-04-16 몫이다.

1. **C2 경로**: F-04-13이 계약에 정한다. 그 전에는 조사관이 잘못 만든 사건을 정상 종료할 수 없다. 동결 로컬이라 운영에 나가지 않는다.
2. **실제 외부 연결**: ticket-svc `SetTransferLock` gRPC·core-svc 팬 사본·notify 발송은 포트까지다. F-04-13·F-04-15가 실제 어댑터를 붙인다.
3. **스케줄러**: T+60분 고정·1시간 판 더하기·자동 재시도 실행 루프는 F-04-19다. 이 기능은 판단·시도 행·다시 돌리기 경로까지다.
4. **원천 보존 파기**: `inv-partition-purge`는 F-04-19/파기 작업 몫이다. 이 기능은 `sourceExpiresAt` 계산과 410만 한다.
5. **증거 묶음 내보내기 차단**: `verify_status='MISMATCH'`를 저장하는 데까지다. 실제 내보내기 경로가 그 값을 보는 것은 F-04-14다.
6. **후보 계산 실행기**: F-04-11 CLI를 부르는 어댑터는 구현하되 실제 ClickHouse를 시험에서 띄우지 않는다. F-04-11 통합 시험이 계산을 이미 본다.
7. **ASVS**: 이 기능이 닿는 행만 시험 태그로 닫는다. 표 전체의 나머지 행은 각 기능 추적 표가 맡는다.
8. **동결 마이그레이션 번호**: `0035`는 로컬 전용이다. 출시 `develop`이 같은 번호를 쓰면 동결을 풀 때 다시 매긴다(ADR-0386 결정 5).
