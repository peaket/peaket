# ADR-0354 기능 단위 전환 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 2026-11-22 전환점 뒤의 남은 일을 2~5일 수직 기능 87개로 다시 묶고, `docs/BUILD_ORDER.md`·`docs/architecture.md`·`docs/PROGRESS.md`·갈래 파일을 그 규칙에 맞춘다.

**Architecture:** 옛 `BAT-` 묶음 표는 기록으로 동결하고, 같은 `묶음`·`장부 범위` 머리를 쓰는 새 `F-` 기능 표를 더한다. 새 표는 `brief.mjs`·`ledger.mjs`가 그대로 읽고, `records.mjs`는 기존 단계 줄을 계속 센다. 전환점에 이미 시작한 묶음만 옛 규칙으로 끝내고, 새 작업은 기능 가지 하나에 역할 커밋을 쌓은 뒤 기능이 끝날 때 `develop`에 한 번 합친다.

**Tech Stack:** Markdown 정본, Node CI 도구(`tools/ci/brief.mjs`·`ledger.mjs`·`records.mjs`), Python 문서 점검(`tools/doc-check/check_all.py`).

**Spec:** `docs/adr/0354-feature-vertical-slices-after-cutover.md`

## Global Constraints

- 문서와 답변은 한국어로 쓴다. 도메인 지식이 없는 사람도 읽게 쓰고, 전문 용어는 처음 나올 때 풀어 쓴다.
- `docs/`가 정본이다. 정본의 값(임계값·표·시험 ID)을 새 표에 옮겨 적지 않고 위치만 가리킨다.
- 옛 `BAT-` ID와 단계 줄은 지우지 않는다. 커밋·ADR·계획 파일이 그 ID를 가리킨다.
- 새 기능 ID는 `F-<영역>-<번호>`다(예: `F-05-2`). 영역은 ADR-0354 결정 4의 열한 영역을 따른다.
- 기능 하나는 2~5일 [가정] 수직 조각이다. 화면이 있으면 화면·API·DB·시험·브라우저 확인까지 한 기능에 든다.
- 기능 하나는 기능 가지 하나(`feature/<갈래>-<기능 ID>`)에 역할 커밋(계획·시험·구현·리뷰·검증)을 쌓고, 기능이 끝날 때 `develop`에 한 번 합친다.
- 한 기능 안에서 서버와 화면을 다시 나누지 않는다. 5일을 넘으면 독립적으로 시험·합치기 가능한 기능 둘로 나눈다.
- 부분 단계는 기존 '일부 구현(R-…): 끝낸 몫. 남은 것: …' 규칙을 쓴다. 단계 줄은 마지막 몫이 끝날 때 체크한다.
- 다른 세션이 스테이징한 파일(`docs/walkthrough/**`, `services/purchase-svc/migrations/meta/_journal.json`)과 미추적 사용자 파일은 건드리지 않는다. 커밋은 이 계획이 만든 파일만 골라 한다.
- 무거운 시험·Docker·측정은 이 계획에서 하지 않는다. 문서·표만 고치고, 검증은 문서 점검과 도구 실행으로 한다.

## Review Focus

- **단계 누락**: 체크되지 않은 154개 단계가 새 기능 표 또는 전환점·마일스톤에 정확히 한 번씩 들어가는가. 하나라도 빠지면 그 일은 영원히 안 보인다.
- **이미 끝난 일**: 코드가 `develop`에 있는데 단계 줄만 열려 있는 단계(OPS-280·290, BAS-150, GAT-210·220 등)를 새 기능으로 다시 잡지 않는가. 먼저 확인해 체크해야 한다.
- **부분 단계**: 일부만 끝난 단계(GAT-140·160·180, LCH-080·100·110 등)의 남은 몫이 기능에 정확히 들어가고, 단계 줄을 일찍 체크하지 않는가.
- **도구 호환**: 새 표의 머리가 `| 묶음 | … | 장부 범위 | … |`를 유지해 `brief.mjs`·`ledger.mjs`가 `F-` 행을 찾는가.
- **옛 기록 보존**: 옛 `BAT-` 표와 단계 줄이 삭제·개명되어 다른 문서의 링크가 깨지지 않는가.

- [ ] **Step 3: `장부 범위`를 채운다**

각 기능의 `장부 범위`는 옛 묶음 표에서 그 단계를 맡던 행의 `장부 범위`에서 시작해, 기능의 `완료 정의`에 닿는 항목만 남긴다. 새 값을 만들지 않는다.
- `docs/features/<영역>.md`, `docs/security/asvs/<영역>.md`, 해당 시험 ID(예: `Q-T2`, `P-T1`, `S-T12`), 요구사항 ID(예: `NFR-009`)를 쓴다.
- 뽑을 정본이 없는 운영·문서 기능은 `-`로 둔다.
- 기능을 시작할 때 `node tools/ci/ledger.mjs --batch <기능 ID>`로 항목 수를 보고, `--require`가 빈칸·`ID만` 없이 통과하는지 확인한다.
- `완료 정의`가 여러 단계에 걸치면 `장부 범위`도 그만큼 넓힌다. 단, 다른 기능의 몫은 넣지 않는다.
