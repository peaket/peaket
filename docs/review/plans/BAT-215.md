# 묶음 계획: BAT-215(OPS-010·OPS-020 관측 코드 몫 — 온세일 로그 표본 신호의 계약·소비, 바깥 호출·지표 라벨 검사, 로그 줄 점검)

- **무엇**: OPS-010(wbs 4.1.1 ①)·OPS-020(②③) 줄의 코드 몫을 하는 B 등급 정방향 묶음의 작업 목록이다(docs/architecture.md §8.6 4의 1·2, ADR-0270 '계획'). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다. 정본 값은 옮겨 적지 않고 자리(문서:줄, 이 커밋 기준)만 가리킨다. OPS-030(wbs 4.1.1 ④)은 감독 결정으로 BAT-216(docs/BUILD_ORDER.md:118)이 한다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane1`, 가지 `feature/lane1-BAT-215`, 출발점 `746ff42c`(지시서 `node tools/ci/brief.mjs --batch BAT-215`, 같은 커밋). 2026-11-22 계획 담당 `bat215-plan-eec48d28`(claude-opus-5-5)가 썼고 시험·제품 코드는 쓰지 않았다.
- **등급**: B(docs/BUILD_ORDER.md:117). 구현 전 트리의 실패 확인은 하지 않고 §8의 틀린 구현 표본 10개로 대신한다(ADR-0331 결정 2·3). 짧은 고리(ADR-0283 결정 2): 리뷰 반영 계획 커밋을 따로 두지 않는다.
- **차례**: 정방향(이 계획 커밋에 `Batch-Order: impl-first`). 계획 → 구현 → 시험 → 리뷰 → (높음·보안 지적만) 재현 시험 → 고침 → 검증 → 기록.

## 감독에게

방향을 바꾸는 결정은 정하지 않았다. 처음 계획은 1 (가)·2 (가)로 썼고, 아래 '감독 판정'대로 고쳤다.

**감독 판정(2026-11-22)**: 1은 (가)(나눈다), 2는 (나)(생산을 미룬다, 전체 감독 동의). BAT-215 줄을 OPS-010·OPS-020과 그 장부 범위로 좁히고 WBS를 3.75로, 새 줄 BAT-216(OPS-030, WBS 1)을 더했다(docs/BUILD_ORDER.md:117~118). C-T75 ①④의 정할 곳은 **BAT-365(OPS-300, 갈래 4)**다: ops-svc `control.settings` Outbox 표·릴레이는 갈래 4 BAT-360이 만들고, 온세일 구간의 `LOG_SAMPLING` 내기와 C-T75 ①④ 판정은 BAT-365가 한다(ledger-notes, ADR-0334 상태 줄). 아래 1·2는 판정 전 원문이다.

## 계획

### 1. 범위

- **P1 LOG_SAMPLING 계약**: ADR-0334 결정 1대로 asyncapi·Avro·README를 고치고 생성물을 만든다.
- **P2 소비(공용 서버 패키지)**: `startControlSync`의 설정 처리에 `LOG_SAMPLING`을 더한다(결정 2). 설정을 읽는 시작 작업이 없는 trust-svc·realtime-gw·admission-ctrl도 설정 읽기를 켠다(asyncapi:210 '모든 서비스의 모든 파드'). 세 서비스는 신원 처리기가 없어 종료 세션 목록은 켜지 않는다(ADR-0333 결정 1).
- **P3 생산은 하지 않는다**(감독 판정 2 (나)): core-svc 내부 조회, ops-svc 윈도우 판단·주기 작업·Outbox는 BAT-365가 ADR-0334 결정 3대로 만든다. ops-svc·core-svc는 이 묶음에서 건드리지 않는다.
- **P4 바깥 호출 점검**: 공용 린트 규칙 하나와 허용 목록, 걸린 곳 고침(결정 5). 화면 앱 서버 코드는 확인만 하고 싣는 곳이 있으면 고친다(§4).
- **P5 지표 라벨 검사**: `listen` 때 레지스트리 검사(결정 6).
- **P6 로그 줄 점검**: AC-T7 ④의 '로그에 SHA-1과 앞 5자 0건'을 정규 로그 줄·서비스 로거까지 넓혀 본다. 16.2.2(시각 오프셋)·16.2.4(JSON·`traceId`·`version`)에 시험 태그를 단다.

### 10. 자주 놓친 결함(docs/architecture.md:1166~1180에서 고름, 시험·구현 지시문에 넣는다)

- 시간 경계는 직전(−1ms)과 경계를 가짜 시계로 잰다. 단언 값은 정본(POL-028의 10분·60분)에서 적고 코드 상수를 가져오지 않는다. 시험의 설정 값은 기본 10과 다르게 고른다.

- 판정 함수만 보지 말고 부르는 쪽이 결과를 쓰는지 본다: `setSampleOneIn`만이 아니라 실제 줄의 `sampleRate`.
- 겹친 가드(새 파드의 만료 무시와 실행 중 만료 되돌리기)는 하나씩 빼 본다(M4).
- `main.ts` 조립(세 서비스의 설정 읽기)은 시험 조립과 따로 띄워 본다.
- 빈 결과가 통과로 새지 않게 한다: 지표 검사가 등록 지표 0개를 받으면 실패로 본다.
