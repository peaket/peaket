# F-04-17 계획 — SCR-069 리플레이 화면·타임라인·비트마스크·키보드 조작(동결 로컬)

- **무엇**: 기능 표 F-04-17(LCH-220)의 동결 로컬 트랙 계획이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **등급**: B. 이번 동결 기간(2026-11-23~12-03)의 가벼운 절차(ADR-0373)에서는 B·C 기능의 시험 리뷰를 생략하지만, 감독이 이 기능에 한해 **계획 → 시험 → 시험 리뷰(새 세션) → 반영 → 구현 → 기록**을 지시했다. 이번 턴은 계획·시험·기준 트리 실패 확인·게이트·푸시에서 멈추고 시험 리뷰를 기다린다. 구현은 시험 리뷰 뒤에 시작한다.
- **동결 로컬 범위**: v1 출시 범위 밖이다(ADR-0373 결정 2, ADR-0386 결정 4·5, `docs/release/v1-scope.md` F-04-17). `freeze/lane6-F-04-17` 가지와 `D:/ticketpass-freeze-F-04-17` 워크트리에서만 개발하고 `develop`·`release/1.0.0`에 합치지 않는다. 출시 마이그레이션·릴리스 플래그·`deploy/` 값을 건드리지 않는다.
- **바탕**: `de5dd3a55`(`origin/freeze/lane6-F-04-16`, F-04-16 완료 포함, 2026-11-27). F-04-9~F-04-16이 만든 사건 열 형식·검증·체크포인트·합성 생성기·운영 빌드·`replay-export` 받기·`validateDecodedReplay` 경계를 입력으로 쓴다.
- **정본**: `docs/features/forensic-replay.md` §2.1~§2.3·§3.4~§3.5·§4.1~§4.4·§7.1·§8(FX-T4·FX-T8·FX-T21), `docs/security/asvs/forensic-replay.md`(v5.0.0-1.1.1·1.4.1·1.4.2·1.5.2·14.3.3), `docs/frontend.md` §5.19, `docs/design/d5-screen-blueprint.md` §7.17, `docs/lanes/lane6.md`, ADR-0080·0171·0173·0372·0373·0386.
- **감독 지시문과 정본의 차이**: 지시문의 '비트마스크'는 정본 §3.5의 교차 필터 `Uint32Array` 비트마스크다. 지시문의 'Arrow 열 해독'은 F-04-16이 남긴 `validateDecodedReplay` 경계에 Arrow 표를 넘기는 일이고, 실제 IPC 바이트 읽기는 `apache-arrow`가 맡는다. 정본에 없는 새 배지·새 화면 상태를 만들지 않는다.

## 1. 이 기능이 끝내는 것과 넘기는 것

### 1.1 끝내는 것

1. **Arrow 표 해독 경계**: `apache-arrow`의 `tableFromIPC`로 받은 표를 사건 열 16개·메타데이터로 옮긴다. 스키마(열 이름·형·순서)·압축·사전 표시와 원천별 메타데이터를 **열 값을 읽기 전에** 검사하고, 통과한 뒤 한 번만 읽는다. null은 `seat=0xFFFFFFFF`·`entropy=NaN`·나머지 0으로 채운다.
2. **원천·규칙 검증 연결**: 해독한 `ReplayFileInput`을 F-04-16의 `replayFileValidation`(=`validateDecodedReplay`)에 넘겨 원천 대조·시간 순서·좌석 범위·원천별 칸 규칙·일관성 규칙을 적용한다. 파일 거절이면 아무것도 그리지 않고 danger 띠를 보인다.
3. **일관성 규칙에서 버린 사건**: `keep` 배열로 압축하고, 버린 수를 warning 띠 "규칙에 맞지 않는 사건 {n}건을 빼고 보입니다"로 보인다. 0건이면 띠가 없다.
4. **좌석 상태 재구성 연결**: F-04-9의 `buildCheckpoints`·`reconstructAt`을 재생 세션에 붙여, 재생 위치의 좌석 상태(빈 좌석·홀드·결제 중·판매·경합 표시)를 만든다. 체크포인트 간격은 정본 §3.4의 32MB 규칙을 그대로 쓴다.
5. **타임라인(CMP-039 `scrub`)**: 재생·일시정지, 배속 ×1·×10·×60, 판매 시작 기준 시각(로비는 음수), 끌어서 구간 고르기, 초당 대기열 진입·홀드 시도·경합·판매 막대(CMP-033). 숫자 입력으로도 시작·끝을 넣는다.
6. **키보드 조작(FX-T8)**: ←→ 1초, Shift+←→ 10초, Space 재생·일시정지, Home·End 처음·끝, `[`로 구간 시작·끝 잡기, `Esc`로 지우기. 타임라인은 `role="slider"`와 `aria-valuemin`·`aria-valuemax`·`aria-valuenow`를 쓴다.
7. **교차 필터 비트마스크(FX-T4)**: 시간 범위·구역·결과·사건 종류·봇 등급·네트워크 유형·기기 묶음·묶음 계정 여부 차원마다 `Uint32Array` 마스크를 두고, 조건이 바뀐 차원만 다시 만든다. 요약 값(홀드 시도·경합 패배율·홀드 → 판매 전환·후보 비율 또는 묶음 계정 수)은 정본 §2.1의 집계 정의를 따른다.
8. **표로 보기(FX-T8)**: 타임라인 막대·요약·조사 원천 기준선마다 같은 집계를 표로 보인다. 표 값은 그림 집계와 같은 함수에서 나오고, 시험은 전 행을 도는 기준 구현과 대조한다.
9. **조사 원천 기준선 데이터**: `member=0` 여정의 단계별 걸린 시간(판매 시작 → 대기열 진입 → 입장 확정 → 첫 홀드 → 결제 시도 → 판매)과 1·50·99 백분위(가장 가까운 순위)를 계산해 표로 보인다. 그림(CMP-083)은 F-04-18이 그린다.
10. **운영 화면 연결**: F-04-16의 `OperatingApp`이 파일을 받은 뒤 `ReadyMain`(재생 준비) → 해독 → 검증 → `ReplayMain`(재생) 순서로 잇는다. 실패는 F-04-16의 `ProblemMain`·파일 거절 문구를 그대로 쓴다.
11. **화면 메모리 경계 유지**: 받은 파일·해독 결과·재생 세션은 React 상태·ref에만 둔다. `localStorage`·`sessionStorage`·`IndexedDB`·쿠키·URL·`console.*`·내려받기를 쓰지 않는다. 화면을 떠나면 `AbortController.abort()`·`setFile(null)`·`setSession(null)`.

## 2. 정본 빈칸과 이번에 정한 것(추천 적용 2026-11-27)

- **정본 반영(F-04-17)**: 아래 1~5는 이번 계획 커밋에서 `docs/features/forensic-replay.md` §2.1·§2.3·§4.2에 **먼저** 적었다. 이 계획은 그 정본을 가리키고, 정본과 다르면 정본이 이긴다.

1. **집계 정의**: 시간 범위는 `[시작, 끝)`이고, 초당 막대는 시간창 시작을 0초로 둔다. 경합 패배율·홀드 → 판매 전환·후보 비율·묶음 계정 수의 분모와 0 처리, 기준선 백분위의 가장 가까운 순위(`ceil(p/100 × n)`)를 §2.1에 적었다.
2. **키보드 구간 고르기**: `[` 두 번으로 구간의 두 끝을 잡고 `Esc`로 지운다. 두 끝이 같으면 구간이 아니다. §2.3에 적었다.
3. **숫자 입력 꼴**: `T+MM:SS`·`T−MM:SS`·`MM:SS`·`-MM:SS`·정수 초. §2.3에 적었다.
4. **메타데이터 키**: `schema`·`source`·`seatCount`·`sectionCount`·`saleStart`와 원천별 값의 이름, 수·시각의 문자열 꼴, null 채움 규칙을 §4.2에 적었다.
5. **해독 순서**: 열 이름·형·순서·압축·사전 표시를 먼저 보고 통과한 뒤 열 값을 읽는다. §4.2에 적었다.
6. **Arrow 표 포트**: `ArrowTableLike`는 `apache-arrow`의 `Table`이 구조적으로 만족하는 좁은 모양이다. `apache-arrow` import는 `arrow-ipc.ts` 한 파일에만 두고, 나머지 순수 모듈은 이 포트만 받는다. 그래서 시험은 실제 라이브러리 없이 표 값을 만들 수 있고, 실제 바이트 읽기는 `미실행`으로 남긴다.
7. **IPC 실패의 코드**: `tableFromIPC`가 던지면 `RejectCode`에 `arrow-ipc`를 더해 파일 거절로 끝낸다. 화면 문구는 F-04-16의 danger 띠 제목·이유 한 줄을 그대로 쓴다.
8. **0행 파일**: 정본 §4.2가 0행을 유효하게 본다. 재생 화면은 빈 좌석·빈 타임라인·0 요약으로 열고 파일 거절이 아니다.
9. **재생 시작 위치**: 시간창 시작(합성은 T−10:00)에서 재생 중으로 시작한다. 끝에 닿으면 멈춘다.
10. **버린 사건**: `compactColumns`로 압축한 열로 모든 집계를 하고, 원본 행 수·유지 수·버린 수를 세션에 남긴다. 버린 사건은 어떤 차원에도 들어가지 않는다.
11. **`ReadyMain`의 자리**: F-04-16의 `ReadyMain`은 받은 뒤 해독 전 준비 상태로 남기고, 해독·검증이 끝나면 `ReplayMain`으로 바꾼다. `ReadyMain` 파일과 `role="status"`는 F-04-16 시험이 요구하므로 지우지 않는다.
12. **`OperatingApp`의 순서**: `replayOperation` → `replayHeadersIssue` → `arrayBuffer` → `replayEnvelopeOf` → `replayFileIssue` → `decodeArrowIpc` → `validateDecodedReplay` → `prepareReplay`. F-04-16 시험이 요구하는 `replayFileValidation(`·`setFile(null)`·`AbortController` 문자열을 유지한다.
13. **F-04-18 경계**: 후보 산점도·2D 대체·후보 패널 그림·정밀도/재현율·성능 측정은 F-04-18이다. F-04-17은 기준선 데이터·표와 재생 화면의 뼈대까지다.
14. **F-04-19 경계**: 연구 내보내기 `POST`·감사·`pseudonymization_log`·`an_forensic_reader`는 F-04-19다. F-04-17은 F-04-16이 받은 `RESEARCH` 파일을 해독해 재생할 뿐이다.
15. **계약**: `docs/api/openapi.yaml`·`packages/contracts`·`packages/api-client`를 고치지 않는다. `package.json`에는 `apache-arrow` 의존만 더한다(구현 단계. 계약 변경 아님).
16. **데모 정적 보드**: 시험·시연 빌드의 정적 보드 3개는 그대로 둔다. 실제 생성 데이터 재생 연결은 F-04-18의 몫이다. 운영 빌드의 재생 화면은 이 기능이 실제 파일로 돌린다.

## 4. 공개 인터페이스(시험이 이 이름을 쓴다)

### 4.1 Arrow 표 해독(`apps/forensics/src/lib/replay/arrow.ts`, 순수)

```ts
import type { EventColumns, ForensicMeta, Reject, SchemaColumn } from '../forensics/events.ts';
import type { ReplayEnvelope, ReplayFileInput } from '../replay-export.ts';

export interface ArrowFieldLike {
  name: string;
  /** apache-arrow DataType의 글자. 예 'Int32'·'Uint8'·'Float32' */
  type: string;
  dictionary?: boolean;
}
export interface ArrowVectorLike {
  readonly length: number;
  get(index: number): unknown;
}
export interface ArrowTableLike {
  readonly numRows: number;
  readonly schema: {
    readonly fields: readonly ArrowFieldLike[];
    readonly metadata: ReadonlyMap<string, string> | null;
  };
  getChild(name: string): ArrowVectorLike | null;
}

export type DecodedReplay =
  | { ok: true; file: ReplayFileInput }
  | { ok: false; reject: Reject };

export function arrowTypeName(arrowType: string): string;
export function arrowMetadata(metadata: ReadonlyMap<string, string> | null): ForensicMeta;
export function decodeReplayTable(table: ArrowTableLike, envelope: ReplayEnvelope): DecodedReplay;
```

- `arrowTypeName`은 `Int32`→`int32`, `Uint8`→`uint8`, `Uint16`→`uint16`, `Uint32`→`uint32`, `Float32`→`float32`로 바꾸고, 모르는 글자는 그대로 돌려준다(스키마 검사가 거절한다).
- `arrowMetadata`는 정본 §4.2의 키를 읽는다. 수는 `Number`로 바꾸고 정수가 아니면 `NaN`으로 둬 `validateMeta`가 거절하게 한다. `source`는 글자 그대로 넘긴다. 없는 선택 키는 `undefined`다.
- `decodeReplayTable` 순서: ① `schema.fields`를 `arrowTypeName`으로 옮겨 `validateSchema` ② `arrowMetadata`→`validateMeta` ③ `validateEventCount(table.numRows)` ④ 16개 열을 `getChild`로 한 번씩 읽어 `EventColumns`를 채운다. ①~③ 가운데 하나라도 거절이면 `getChild`를 **한 번도 부르지 않는다**. 열이 없거나 길이가 `numRows`와 다르면 `row-count`다.
- null·`undefined`는 `seat=0xFFFFFFFF`, `entropy=NaN`, 나머지 0으로 채운다. 값은 이미 검사한 형의 형식 배열에 넣는다.

### 4.2 Arrow IPC 읽기(`apps/forensics/src/lib/replay/arrow-ipc.ts`)

```ts
import { tableFromIPC } from 'apache-arrow';
export function decodeArrowIpc(bytes: Uint8Array, envelope: ReplayEnvelope): DecodedReplay;
```

- `tableFromIPC(bytes)`를 정확히 한 번 부르고, 던지면 `{ ok: false, reject: { ok: false, code: 'arrow-ipc', message: 'Arrow 파일을 해독하지 못했습니다' } }`다.
- 표를 `ArrowTableLike`로 옮긴다. `fields`는 `{ name, type: String(field.type), dictionary: field.type instanceof Dictionary }`이고, `getChild(name)`은 `table.getChild(name)`을 그대로 준다. `schema.metadata`는 `table.schema.metadata`다.
- 실제 `apache-arrow` `Field`에는 압축 표시가 없다. 몸통 압축은 `tableFromIPC`가 풀지 못하면 위 `arrow-ipc`로 끝나고, 이 기능은 표에서 압축 표시를 검사하지 않는다. 실제 LZ4·ZSTD IPC 파일로 확인하는 시험은 `미실행`이다(§13.2). 그래서 `ArrowFieldLike`에 `compressed`를 두지 않고, `schema-compressed`는 이 경계의 시험으로 세지 않는다.

### 4.4 재생 상태·키보드(`apps/forensics/src/lib/replay/playback.ts`, 순수)

```ts
import type { ReplayBounds } from './session.ts';

export type Speed = 1 | 10 | 60;
export interface PlaybackRange { fromMs: number; toMs: number }
export interface PlaybackState {
  playing: boolean;
  speed: Speed;
  playheadMs: number;
  range: PlaybackRange | null;
  anchorMs: number | null;
}
export interface TimelineKey { key: string; shiftKey?: boolean }
export interface TimelineAria { min: number; max: number; now: number; text: string }

export function initialPlayback(bounds: ReplayBounds): PlaybackState;
export function timelineKey(state: PlaybackState, key: TimelineKey, bounds: ReplayBounds): PlaybackState;
export function advancePlayback(state: PlaybackState, elapsedMs: number, bounds: ReplayBounds): PlaybackState;
export function setSpeed(state: PlaybackState, speed: Speed): PlaybackState;
export function timelineAria(state: PlaybackState, bounds: ReplayBounds): TimelineAria;
export function formatOffset(ms: number): string;
export function parseOffset(text: string): number | undefined;
export function rangeFromInput(from: string, to: string, bounds: ReplayBounds): PlaybackRange | undefined;
```

- `initialPlayback`은 `{ playing: true, speed: 1, playheadMs: bounds.fromMs, range: null, anchorMs: null }`이다.
- `timelineKey`: `ArrowLeft`/`ArrowRight`는 `shiftKey`면 10,000ms, 아니면 1,000ms를 빼거나 더하고 `[fromMs, toMs]`로 자른다. `' '`(Space)는 `playing`을 뒤집는다. `Home`은 `fromMs`, `End`는 `toMs`. `[`는 `anchorMs`가 없으면 지금 위치를 잡고, 있으면 두 값 가운데 작은·큰 값을 `range`로 만든 뒤 `anchorMs=null`이다. 두 값이 같으면 `range=null`, `anchorMs=null`. `Escape`는 `range=null`, `anchorMs=null`. 그 밖의 키는 상태를 그대로 돌려준다(새 객체를 만들지 않아도 된다).
- `advancePlayback`: `playing=false`이거나 `elapsedMs<=0`이면 그대로. `playheadMs + elapsedMs*speed`를 `toMs`로 자르고, 끝에 닿으면 `playing=false`다.
- `setSpeed`: 1·10·60만 받고 그 밖은 `TypeError`다.
- `timelineAria`는 `{ min: bounds.fromMs, max: bounds.toMs, now: state.playheadMs, text }`다. `text`는 재생 위치의 `formatOffset`이고, 구간이 있으면 `${formatOffset(playhead)} · 구간 ${formatOffset(from)}~${formatOffset(to)}`다. `ReplayTimeline`은 이 값을 `aria-valuemin`·`aria-valuemax`·`aria-valuenow`·`aria-valuetext`에 그대로 쓴다.
- `formatOffset`: `T+MM:SS`·`T−MM:SS`(U+2212). 음수는 0 쪽으로 자른 초를 쓴다(`-1500`→`T−00:01`). 분은 두 자리 이상, 초는 두 자리다.
- `parseOffset`: `T+MM:SS`·`T−MM:SS`·`MM:SS`·`-MM:SS`·정수 초. 초는 0~59, 분은 0~1,799. 그 밖은 `undefined`다. `T` 뒤에 ASCII 하이픈을 쓰는 `T-MM:SS`는 정본에 없으므로 받지 않는다.
- `rangeFromInput`: 두 값을 `parseOffset`으로 읽고, 둘 다 있고 `fromMs < toMs`이며 `[bounds.fromMs, bounds.toMs]` 안이면 `{fromMs, toMs}`를, 아니면 `undefined`를 준다. 뒤집힌 입력은 작은·큰 값으로 정리한다. 키보드로 `[`를 두 번 눌러 만든 구간과 같은 값을 내야 한다.

### 4.5 교차 필터 비트마스크(`apps/forensics/src/lib/replay/crossfilter.ts`, 순수)

```ts
import type { EventColumns } from '../forensics/events.ts';
import type { ReplayBounds } from './session.ts';

export interface ReplayFilter {
  fromMs?: number; // 시작 이상
  toMs?: number;   // 끝 미만
  sections?: readonly number[];
  results?: readonly number[];
  kinds?: readonly number[];
  botTiers?: readonly number[];
  netTypes?: readonly number[];
  deviceGroups?: readonly number[];
  member?: 0 | 1; // 1이면 묶음 계정만, 0이면 묶음 밖만, 없으면 모두
}
export interface ReplaySummary {
  rows: number;
  sessions: number;
  holdTries: number;
  conflictRate: number;
  holdToSaleRate: number;
  candidateRate: number;
  memberSessions: number;
}
export interface TimelineBucket {
  atMs: number;
  queueEnter: number;
  holdTry: number;
  conflict: number;
  sale: number;
}

export function maskWords(rowCount: number): number;
export function selectionMask(columns: EventColumns, keep: Uint8Array, filter?: ReplayFilter): Uint32Array;
export function summarize(columns: EventColumns, keep: Uint8Array, filter?: ReplayFilter): ReplaySummary;
export function timelineSeries(columns: EventColumns, keep: Uint8Array, bounds: ReplayBounds, filter?: ReplayFilter): TimelineBucket[];
```

- 마스크는 `maskWords(n) = ceil(n/32)`개의 `Uint32Array`다. 비트 i는 행 i가 조건을 만족하면 1이다. `keep[i]===0`인 행은 어떤 마스크에서도 0이다.
- 빈 배열(`sections: []`)은 '아무것도 고르지 않음'이 아니라 '그 차원에서 아무것도 통과하지 않음'이다(교차 필터에서 체크를 모두 끄는 것과 같다). 시험이 이 경계를 고정한다.
- `summarize`는 정본 §2.1의 집계 정의를 그대로 센다. `candidateRate`는 `bot_tier>0` 세션 수 / 세션 수, `memberSessions`는 `member=1` 세션 수다. 세션이 0이면 두 비율은 0이다.
- `timelineSeries`는 `bounds.fromMs`를 0초로 두고 1초 칸을 만든다. 칸 수는 `ceil((toMs-fromMs)/1000)`이고, `atMs = fromMs + i*1000`이다. `bounds` 밖 사건은 세지 않고, `filter`가 있으면 여덟 차원과 `filter.fromMs`·`toMs`도 함께 본다. `bounds`는 막대의 시간축이고 `filter`는 고른 범위·조건이다.

### 4.6 표 보기와 기준선(`apps/forensics/src/lib/replay/table.ts`, 순수)

```ts

  | 'saleToQueue'
```

- `summaryRows`는 d5 §7.17의 이름(`홀드 시도`·`경합 패배율`·`홀드 → 판매 전환`·`후보 비율` 또는 `묶음 계정 수`)과 정확한 값을 낸다. 비율은 0~1 소수 넷째 자리까지 자른다(`Math.round(x*10000)/10000`).
- `timelineRows`는 칸마다 `{ second: formatOffset(atMs), queueEnter, holdTry, conflict, sale }`를 낸다.
- `baselineRows`는 단계 이름(`판매 시작 → 대기열 진입`·`대기열 진입 → 입장 확정`·`입장 확정 → 첫 홀드`·`첫 홀드 → 결제 시도`·`결제 시도 → 판매`)과 1·50·99·`n`을 낸다.
- `journeys`는 세션마다 종류별 첫 사건 시각을 모은다. `QUEUE_ENTER`·`ADMIT`·`HOLD_TRY`·`PAY_TRY`·`SALE`만 본다. `keep=0` 행은 보지 않는다.
- `stageDurations`는 앞 단계 시각에서 다음 단계 시각을 뺀 값이다. 두 시각이 모두 있어야 하고, 음수면 그 단계는 없다.
- `seatLegend`는 좌석 상태 4개의 이름과 무늬를 돌려준다(d2 CMP-021·CMP-023, tokens.json `pattern.seat.*`): 빈 좌석 `solid`, 홀드 `diagonal-hatch`, 결제 중 `solid-with-check`, 판매 `cross-hatch`. `SeatReplay`는 색과 이 무늬를 함께 쓰고, 시험은 네 값과 `SeatReplay`의 `seatLegend(` 사용을 본다.
- `percentile`은 오름차순 정렬한 값에서 `rank = ceil(p/100*n)`(1부터)의 값을 준다. 빈 배열은 `NaN`이다.
- `stageBands`는 `member`가 같은 여정만 모아 단계마다 `n`·1·50·99를 낸다. 조사 원천 기준선은 `member=0`으로 부른다.

## 8. 실패 시나리오와 엣지 케이스

1. **IPC 해독 실패**: 매직은 맞는데 flatbuffer·메시지가 깨졌다. `tableFromIPC`가 던지고 `arrow-ipc` 파일 거절이다. 아무것도 그리지 않는다.
2. **스키마 불일치**: 열 이름·형·순서가 다르거나 모르는 열·사전 열이 있다. 열 값을 한 번도 읽지 않고 `schema-columns`·`schema-dictionary`다. 압축 몸통은 표에서 볼 수 없어 이 경계에서 `schema-compressed`를 만들지 않는다(라이브러리 거절, `미실행`).
3. **메타데이터 없음**: `schema`·`source`·`seatCount`·`sectionCount`·`saleStart`가 없거나 수가 정수가 아니다. `meta` 거절이다. 원천별 필수 값(합성 시드/부하 ID, 연구 회차·시간창, 조사 사건·고정 판)도 같다.
4. **원천 불일치**: 사건 작업대 탭에 연구 파일, 연구 탭에 조사 파일이 오면 `source-mismatch`다. 양쪽 방향을 거절한다.
5. **원천별 칸 규칙**: RESEARCH에 `entropy`·`net_type`·`asn`·`device_group`·`member`·`post_seat` 값이 있거나, SYNTHETIC에 `member`·`post_seat`, INVESTIGATION에 `bot_tier` 또는 묶음 밖 행의 기기·망·행동 값이 있으면 `source-rule`이다.
6. **시간 범위**: `t_ms`가 로비 10분 앞보다 이르거나, 시간창 밖이거나, 내림차순이면 파일 거절이다. 고른 시간 범위(`[from,to)`)와 파일 시간창은 다르다.
7. **좌석·구역 범위**: `seat >= seatCount`이거나 `section >= sectionCount`면 파일 거절이다. `seat=0xFFFFFFFF`(좌석 없음)는 허용한다.
8. **일관성 규칙**: 홀드 없이 홀드 끝, 결제 시도 없이 판매, 받은 사람 없이 양도 같은 행은 그 사건만 버리고 warning 띠를 보인다. 파일 전체를 거절하지 않는다.
9. **버린 사건의 집계**: 버린 행은 좌석 상태·타임라인·교차 필터·기준선 어디에도 들어가지 않는다. 0건이면 띠가 없다.
10. **0행 파일**: 유효하다. `prepareReplay`가 0행 세션을 만들고 `replayScreenState`가 `'replay'`를 준다. 빈 좌석·빈 타임라인·0 요약으로 열고 파일 거절이 아니다.
11. **행 수 상한**: 3,000,000행 정확히는 허용, +1은 `event-limit`이다. 배열을 만들기 전에 거절한다.
12. **열 길이 불일치**: 열마다 행 수가 다르면 `row-count`다. 형식 배열을 다른 길이로 만들지 않는다.
13. **null 값**: `seat`는 좌석 없음, `entropy`는 NaN, 나머지는 0이다. null 때문에 파일을 거절하지 않는다.
14. **시간 경계**: 시작과 같은 시각의 사건은 들고, 끝과 같은 시각의 사건은 뺀다. 끝이 시작보다 이르거나 같으면 구간이 아니다.
15. **키보드 경계**: 처음에서 ←, 끝에서 →는 값이 그대로다. Home·End는 시간창 밖으로 가지 않는다. 모르는 키는 상태를 바꾸지 않는다.
16. **구간 두 끝이 같음**: `[`를 같은 자리에서 두 번 누르면 구간을 만들지 않는다. `[`를 한 번만 누른 상태에서 `Esc`는 잡아 둔 끝을 지운다.
17. **숫자 입력**: 초 60 이상, 분 1,800 이상, 빈 글자, `T+`만, 소수, `T` 뒤 ASCII 하이픈(`T-01:30`)은 `undefined`다. 범위 밖·뒤집힘은 `undefined`이고 화면은 이전 구간을 유지한다.
18. **재생 끝**: 끝에 닿으면 재생이 멈춘다. 일시정지 중에는 시간이 흘러도 재생 위치가 그대로다.
19. **격리 없음**: `crossOriginIsolated=false`여도 복사 방식으로 돈다. F-04-16의 상태 띠가 그대로 보인다.
20. **화면 이탈**: 해독·재생 중에 화면을 떠나면 `AbortController.abort()`, `setFile(null)`, `setSession(null)`, `cancelAnimationFrame`이다. 저장소·URL·로그에 남기지 않는다.
21. **큰 파일**: 200MB·300만 행 경계는 F-04-16 봉투 검사와 이 기능의 행 수 검사가 막는다. `MAX_EVENTS` 정확히는 허용하고 +1은 거절한다. 실제 200MB 파일은 만들지 않고 값으로 본다.
22. **`apache-arrow` 없음**: 시험·시연 빌드는 `arrow-ipc`를 가져오지 않는다. 운영 묶음에만 들어간다(정적 import 그래프 시험).
23. **번들**: `apache-arrow`는 운영 묶음에만 들어간다. 크기 측정은 F-04-18이다.
24. **좌석 배치 없음**: 리플레이 파일에 좌석 기하가 없어 F-04-17은 좌석 번호 격자로 그린다. 실제 회차 좌석맵 판 연결은 남은 위험이다.
25. **화면 고르기**: 파일 거절·오류면 `replayScreenState`가 `'problem'`이고 `ProblemMain`만 그린다. 받는 중이면 `'receiving'`, 해독·검증을 마치면 0행도 `'replay'`다.
26. **좌석 상태 구분**: 좌석 상태 네 가지는 색과 `pattern.seat.*` 무늬를 함께 쓰고, `seatLegend()`가 그 이름과 무늬를 낸다(색만으로 가르지 않는다).

1. **실제 Arrow 파일**: 실제 운영 Arrow 파일·S3·영상은 `미실행`이다. 시험은 표 모양과 바이트 경계를 값으로 본다. `apache-arrow` 실제 해독은 구현 뒤 로컬에서 한 번 확인하되, 이번 턴은 하지 않는다.

6. **데모 정적 보드**: 시험·시연 빌드의 보드 3개는 정적 그림 그대로다. 실제 생성 데이터 재생 연결은 F-04-18이다.
