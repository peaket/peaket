- **무엇**: 동결 로컬 트랙의 기능 작업 목록이다(docs/architecture.md §8.6 4의 1, ADR-0354·ADR-0386). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-07-4`, 가지 `freeze/lane5-F-07-4`, 출발 `11c3cd689`(F-07-3 가지 끝). 2026-11-25 작성.
- **동결 범위**: 이 기능은 ADR-0373으로 v1 완성 범위 밖이고 ADR-0386으로 `frozen-local`이다. **`develop`·`release/1.0.0`에 합치지 않고, release에 체리픽하지 않는다.** 이 가지에서만 커밋하고 `freeze/lane5-F-07-4`로 원격에 둔다. 마이그레이션·플래그는 로컬에만 둔다(ADR-0386 결정 4·5). `docs/BUILD_ORDER.md`의 F-07-4 상태 `동결`은 그대로 두고 release-scope manifest도 고치지 않는다.
- **등급**: B다(docs/BUILD_ORDER.md F-07-4). 돈의 계산·전이를 새로 만들지 않는다. 다만 판매 승인 때 결제사 지정을 고정하는 일은 회차의 결제 경로와 동시 입장 상한을 정하는 값이라, 승인 전후 값이 조용히 바뀌면 안 된다. 그래서 재현·회귀 시험을 먼저 쓰고 기준 트리에서 실패를 본다(작업 지시, ADR-0372).

## 3. 이번에 하는 것

구현 담당 할 일은 넷이다(I-01~I-04). 차례: I-01 → I-02 → I-03 → I-04. 시험은 구현 전에 쓴다.

1. **I-01 승인 때 결제사 지정 고정**: `sale-approval.ts`의 `SaleApprovalInput`에 `pgDefaults?: { primary: 'TOSS'|'PORTONE'; fallback?: 'TOSS'|'PORTONE' }`를 더하고, `applyApproval`이 회차마다 `pgPrimary`가 비어 있을 때만 기본값을 채운다(첫 승인은 모든 회차, 재승인은 새로 더한 회차). `sale-ports.ts` `SaleEventRow`에 `pgPrimary`·`pgFallback`을 더한다. `approve-sale-review.ts`가 플랫폼 기본값을 승인 입력에 넘기고, 채널이 꺼져 있으면 422 `sale-review-pg-unavailable`, 읽지 못하면 503으로 닫는다. `catalog.module.ts`에 `pgDefaults` 옵션과 `PG_DEFAULTS` 토큰을 더하고 `main.ts`가 `PEAKET_PG_DEFAULT`(비면 `TOSS`)·`PEAKET_PG_FALLBACK`(비면 `PORTONE`, `none`이면 없음)을 읽는다. core 0049가 `event.pg_primary`·`pg_fallback`과 CHECK·`core_ops` UPDATE 권한을 더한다. `drizzle-sale-store.ts`의 읽기·쓰기와 `memory-sale-store.ts`를 맞춘다. `ops-sale-review.controller.ts`의 상세 회차에 `pgPrimary`·`pgFallback`을 더하고 openapi를 고친 뒤 `contracts gen`·`api-client gen`을 돌린다.
2. **I-02 휠체어석 서버 재계산**: `packages/validation`의 좌석맵 검사기에 `wheelchairSummaryOf(sections)`를 더해 전체 좌석 수·휠체어석 수·기준 수·위치 확인 좌석 수·온라인 판매 가능 휠체어석 수를 낸다. `request-sale-review.ts`가 `SEATMAP_LAYOUT_STORE`로 그 공연의 지금 배치본을 읽어 요약을 만들고, `SaleTx.requestReview(body, now, accessibleSeating)`가 파트너 확인·부족 이유와 요약을 `production.accessible_seating_check` jsonb에 쓴다. core 0049가 그 칸을 jsonb로 바꾸고(object CHECK, 기존 boolean은 `{confirmed:true}`/`{}`로 옮긴다), `schema.ts`·Drizzle·메모리 저장소·`production.ts`를 맞춘다. `sale-review.ts`의 `OpsSaleReviewDetail`에 `accessibleSeating` 요약을 더하고 `accessibleSeatingCheck`는 호환 boolean으로 유지한다. SCR-048은 수·기준·위치 확인·온라인 판매 수·파트너 확인·이유를 한 줄로 보인다.
3. **I-03 R-T18 회귀 고정**: `services/core-svc/test/sale-review-r18.http.test.ts`를 더해 ① 승인 뒤 회차 고치기·가격/정책 변경이 `SUBMITTED`로 가도 `GET /v1/events/{eventId}` 공개 요약과 승인본 값이 그대로이고, ② 변경 취소가 마지막 승인본으로 돌며 기다리던 변경분을 비우고, ③ 재승인이 새 값을 반영하는지 본다. 제품 코드는 바꾸지 않는다(이미 동작). 이 시험은 기준 트리에서 통과하는 회귀임을 계획에 적는다.
4. **I-04 SCR-048 수요 예측·규모 올리기 배선**: `apps/console-host/src/pages/sale-review/model/sale-review.ts`에 `mapDemandForecast`, `scaleRaiseIssues`, `scaleChangeBody`를 더한다. 화면은 승인 전 확인 패널의 회차 줄에 예측(구독 수·중앙·상단·표본·기본 비율·제안)을 보이고, 승인된 공연에서는 지금 규모보다 큰 값만 고를 수 있는 [규모 올리기] 대화상자(사유 필수)를 둔다. api-client의 `getOpsEventDemandForecast`·`createOpsEventScaleChange`를 부른다. 409 `open-interval-conflict`는 commander 재인증 안내, 422·403·503은 다른 문구로 보이고 성공·실패 뒤 서버를 다시 읽는다. 판매 중지·재개 요청 단추의 화면 모델(`saleSuspensionCommand`)과 시험은 이번에 쓰되, 실제 단추 배선은 다음 동결 몫으로 넘긴다(§11).

## 11. 남은 몫(동결 로컬)

- **SCR-048 판매 중지·재개 단추**: 화면 모델(`saleSuspensionCommand`)과 시험은 이번에 둔다. 실제 단추·사유 코드 대화상자·SCR-046 승인 업무로 이어지는 배선은 다음 동결 몫이다. 서버 2인 승인·집행은 이미 있다.
- **재개 뒤 오픈 시각을 바꾼 회차의 판매 중지 표시 풀기**: 재승인 때 purchase·queue의 `sale_control.suspended`를 그 회차만 푸는 길이 필요하다. 재승인 경로와 함께 다음 동결 몫으로 둔다.
- **수요 예측 실제 원천(C-T43)**: `notification_subscription`의 오픈 30분 전 구독 수와 지난 회차 실제 진입 인원을 읽는 어댑터, SEV3/SEV2 경보, 변경 동결 달력 재계산, 간격 예외 재인증·감사는 LCH-100·운영 묶음이다. 이번 장부 범위 밖이다.
- **브라우저 확인**: 측정 창 뒤 `docs/review/browser-check/` 대본으로 SCR-048의 예측·규모 올리기·휠체어 수 표시를 누른다.
- **전체 `pnpm typecheck`**: 이 기능이 닿는 다섯 작업 공간은 15/15 통과했다. 뿌리 전체는 이 기능 밖의 `@peaket/identity-svc` `scripts/seed-demo.mjs`가 자기 `dist` 모듈을 찾지 못해(빌드 전) 실패한다(39/47, 2026-11-25). identity-svc `build`를 먼저 하거나 동결 트랙 정리 목록에서 다룬다.

## 12. 동결 기록

- 이 기능은 ADR-0373(7일 완성 범위 밖)·ADR-0386(`frozen-local`)에 따라 `develop`·`release/1.0.0`에 합치지 않는다. release 체리픽 금지. 마이그레이션 core 0049는 로컬·CI 전용이며 release 마이그레이션 목록에 넣지 않는다.
- 측정 창이 시작되면 Docker 잠금을 잡지 않고, 긴 통합 시험을 새로 시작하지 않는다. 안전한 체크포인트에서 커밋·push하고 감독 보고 뒤 측정 뒤에 재개한다.
