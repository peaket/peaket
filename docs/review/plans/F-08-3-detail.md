- `label`은 `실측(PC)`·`외삽`·`문서 인용`·`설계 목표`·`[추정]`·`계산` 가운데 하나다. `status`는 `무효`·`판정 못 함`·`자료 없음`·`부분`·`미달`·`실패` 가운데 하나이거나 없을 수 있다.
- `source`는 `sources`의 키다. `anchor`는 그 원천 파일에 실제로 있는 글이다(시험이 `includes`로 확인한다).
- `usedIn`은 `m6`·`capacity`·`cost`·`dora` 가운데 하나 이상이다. 그 보고서의 '사실 대장 인용' 표에 `id`가 있어야 한다.

### 6.2 보고서 공통

- 머리: 제목, 작성일, 상태(초안/검토 대기), 기준 커밋 `19b33ba85`, '이 문서는 정본이 아니다' 한 줄.
- **표와 본문의 숫자마다** 사실 대장 `id`를 같은 행이나 각주에 단다. 시험은 숫자 토큰이 있는 줄에 ID가 없으면 실패한다(날짜·절 번호·ID 자체·`1~3년` 같은 기간 표기는 제외).
- '사실 대장 인용' 절에 쓴 `id`와 값·표시를 다시 적는다.
- '한계' 절에 이번에 재지 않은 것(F-08-4·F-08-5·F-08-6·F-08-9·F-08-10 등 동결)을 적는다.
- '주장하지 않는 것' 절에 30,000건/초·100만·K1/K2/K7의 새 주장이 없음을 적는다.

### 6.3 M6 초안

- 제목: `M6: 100만을 재지 않고 말하는 법`(또는 같은 뜻).
- 상태: `초안(2026-11-26), 게시 전`.
- 절: `## 1. 왜 한 번에 재지 않나`·`## 2. 무엇을 나눠 재나`·`## 3. 실제로 잰 것`·`## 4. 설계 식과 외삽`·`## 5. 주장하지 않는 것`·`## 6. 숫자를 읽는 법`·`## 7. 근거와 한계`.
- '숫자 카드' 표: F-08-7 §6.3의 카드 1~5와 같은 다섯 행. 행마다 위 §6.1의 카드별 ID를 모두 단다. 카드 1은 `F082-VT4`(100만 외삽 판정 못 함)이고 250대를 쓰지 않는다. 카드 2는 `F082-X1`·`F082-N250`, 카드 3은 K1 1천·1만·10만의 p99·오류율과 상태, 카드 4는 K2 r2·r3 p99·오류율, 카드 5는 K7 ② 0건·불변식·실행 무효다.
- 카드 밖 숫자(200만·250만·300만, 합산 동시 입장 1만·1.25만·1.5만, 250대·800/s 등)를 본문에 쓰지 않는다. '주장하지 않는 것' 절과 인용문만 예외다.
- '주장하지 않는 것'에 30,000건/초, 100만 외삽, K1·K2·K7 통과를 명시한다.
- '근거'에 `docs/review/measurements/F-08-2-msr020.md`·`F-08-8-after.md`와 장부 실행 ID(정확한 ID 또는 접두)를 적는다. 새 실행 ID를 만들지 않는다.
- `docs/blog/README.md` M6 행만 '초안(2026-11-26), 게시 전'으로 고친다. 다른 아홉 행은 건드리지 않는다.

### 6.4 용량 산정서

- 절: `## 1. 입력과 표시 규칙`·`## 2. 100만(한 공연)`·`## 3. 200만(여러 공연)`·`## 4. 1~3년 전망`·`## 5. 병목과 여유`·`## 6. 가정과 한계`·`## 7. 사실 대장 인용`.
- 100만 절: **MSR-010(100만 외삽) 보고서가 없고 V-T4는 '판정 못 함'**임을 `F082-VT4`로 적는다. 250대는 200,000 RPS 진입 설계 식(MSR-020)의 외삽(`F082-N250`)이며 100만 외삽 값이 아니라고 구분한다. `외삽(측정 범위의 4배 초과)`·`비례 전제 확인 못 함`을 그대로 적고, 필요한 대수를 '확정'으로 쓰지 않는다.
- 200만 절: NFR-021·architecture §9.5의 여러 공연 합산 시나리오를 `설계 목표`로 적는다. `NFR-021`·`§9.5`를 인용하고, 100만 외삽을 2배(`×2`) 해서 '200만 외삽'이나 '500대'를 만들지 않는다. "100만 외삽의 2배가 아니다" 같은 부정 문장은 허용한다.
- 1~3년 절: NFR-021·architecture §9.5의 표를 `설계 목표`로 인용한다. 새 성장률을 만들지 않는다.
- 병목 절: F-08-2의 진입 비례 미확인, F-08-8의 K1 진입 병목·K2/K7 무효, F-08-4(정렬)·F-08-5(장시간)·F-08-6(Game Day)·F-08-9(장애 주입)·F-08-10(서비스 분리) 동결을 적는다.

### 6.5 비용 리포트

- 절: `## 1. 입력과 단가 기준일`·`## 2. 상시 기본 비용`·`## 3. 온세일 1회 비용`·`## 4. 1~3년 전망`·`## 5. 줄일 후보`·`## 6. 한계`·`## 7. 사실 대장 인용`.
- 단가 기준일은 `docs/infra.md` §11의 2026-10-28을 그대로 쓴다. 새 가격 조회를 하지 않는다.
- 모든 금액에 `[추정]`을 붙인다. '실측'·'청구액'이라고 쓰지 않는다.
- 상시 기본 비용표는 `docs/infra.md` §11의 행을 인용하고, 값을 바꾸지 않는다. 합계를 다시 계산하면 반올림 규칙(§11 계산 줄)을 따른다.
- **WAF 1회 비용은 `docs/infra.md` §11의 기존 [추정]을 문서 인용하고 다시 계산하지 않는다.** 요청 수는 §11이 적은 [가정]만 쓰고 새 요청 수를 만들지 않는다.
- **1~3년 비용은 '미계산'을 기본으로 한다.** 계산하려면 §9.5의 성장 시나리오와 §11의 단가만 쓰고, 부품별 확장 배수를 새로 만들지 않는다. 배수를 쓰면 그 근거를 같은 표에 적는다.
- CloudFront·NLB 교차 전송·S3·볼륨은 정본에 단가가 없으므로 `단가 없음: 미계산`으로 적는다.
- 진입 서버 비용 민감도: `F082-N250`(200,000 RPS 설계 식 외삽, 확정 아님)과 측정 최대 대수를 비교하는 표를 둘 수 있다. `[추정]`·`F-08-2 외삽, 확정 아님`을 붙이고, 생산 견적이나 100만 외삽 값처럼 쓰지 않는다.
- 1~3년 전망: NFR-021의 성장 시나리오별 비용을 `[추정]`으로만 적거나, 위 원칙대로 `미계산`으로 둔다. 실제 청구·절감률을 주장하지 않는다.

### 6.6 DORA 추세 보고서

- 절: `## 1. 데이터 원천과 기준`·`## 2. 주별 표`·`## 3. 추세 판단`·`## 4. 한계와 다음`.
- 기준은 `데모 환경 기준`이다(docs/devops.md §13). 운영 기준과 한 추세선에 잇지 않는다.
- 주별 표는 최소 `2026-11-16`(완료)·`2026-11-23`(진행 중, 2026-11-26 기준) 두 주. 표에 `상태` 칸을 두고, 배포 수는 0(배포 기록 없음), 리드타임·변경 실패율·복구 시간·재작업률 네 칸은 모두 `자료 없음`이다. 0을 비율·기간의 값으로 쓰지 않는다.
- `0`으로 채우지 않는다. `추세 판단 불가`라고 적고 추세선을 그리지 않는다.
- `node tools/ci/dora.mjs --input <빈 기록> --week <월요일> --out docs/review/measurements`로 만든 `dora-<월요일>.md`·`.json`을 `F-08-3-dora-<월요일>.md`·`.json`으로 둔다. 커밋한 산출물은 같은 입력으로 다시 돌린 `dora.mjs` 출력과 `basis`·`services`·`all`·`week`가 같아야 한다. GitHub API를 부르지 않았다고 적는다.
- 다음에 필요한 것: Argo CD 알림의 GitHub Deployment, 승격 PR 제목, `hotfix/` 라벨, 주간 워크플로 실행. 출시 뒤 실제 값이 생기면 그때 바꾸고, 과거 주를 소급해 채우지 않는다.

| `MSR-080 ④` | 비용 리포트가 있다. 단가 기준일 2026-10-28과 `docs/infra.md` §11을 가리킨다. 금액 줄마다 `[추정]` 또는 `문서 인용`이 있다. WAF 1회는 §11 [추정] 인용이고, 1~3년은 `미계산`이 기본이다. `실측`·`청구액` 주장이 없다. CloudFront 단가 없음을 적는다 | 비용 리포트가 없다 |
| `MSR-080 ⑤` | DORA 보고서가 있다. 2026-11-16(완료)·2026-11-23(진행 중) 표의 네 지표 칸이 **모두** `자료 없음`이고 `0%`·`0시간`·`0.00`이 없다. `추세 판단 불가`가 있다. `dora.mjs`를 같은 입력으로 돌린 JSON과 커밋한 JSON의 `basis`·`services`·`all`·`week`가 같다 | DORA 보고서·주별 산출물이 없다 |
| `MSR-080 ⑥` | 보고서의 모든 사실 ID가 대장에 있고 `usedIn`이 맞다. 장부 실행 ID는 `docs/perf-ledger/runs/`의 실제 디렉터리와 정확히 또는 접두로 맞는다. `v1-scope.json` F-08-3이 `frozen-local`, BUILD_ORDER가 `동결`, `release-scope --check` 통과. `git diff 19b33ba85..HEAD`에 정본·릴리스 노트·manifest 변경이 없다 | 보고서가 없다 |

- 시험은 원천 파일을 읽어 기대값을 뽑는다. 예를 들어 `F-08-2-msr020.md`의 `X₁(1 vCPU) = 800`과 `필요한 대수 250`을 정규식으로 읽고, 사실 대장의 `F082-X1`·`F082-N250`과 견준다. K2 p99·오류율과 K7 ② `PASS <수>`도 원천 표에서 읽는다. 원천이 바뀌면 시험이 실패해 사실 대장을 다시 맞추게 한다.
- **숫자마다 ID**: M6와 용량 산정서의 본문·표에서 숫자 토큰이 있는 줄에 사실 ID가 없으면 실패한다. 날짜·절 번호·ID 자체·`1~3년` 같은 기간 표기는 뺀다. '주장하지 않는 것' 절과 코드 블록은 뺀다.
- **금지 문형은 긍정 서술만**: `30,000건/초`·`초당 30,000건`·`30,000 RPS`, `100만 … 달성/가능/확인/통과`, `K1/K2/K7 … 통과/pass/달성`을 잡되 `확인하지 않`·`확인 못`·`미확인`·`1/3`·`일부`·`부분`·`미달`·`무효`·`판정 못 함`이 같은 줄에 있으면 허용한다.
- 시험은 네트워크·Docker·kind·k6를 쓰지 않는다. `dora.mjs`는 `--input`으로 빈 기록을 받아 자식 프로세스로 돌린다.
- 실패 문구에는 어느 파일·어느 사실 ID가 어긋났는지 적는다. '읽기 실패'와 '값 불일치'를 구분한다.
- 시험 값은 코드 상수와 다르게 고르지 않는다. 이 기능은 새 판정 상수를 만들지 않고, 원천 파일의 값을 그대로 대조한다.
