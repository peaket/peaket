# F-04-16 계획 — `/forensics` 운영 빌드·COEP/COOP·원천 배지·replay-export (동결 로컬)

- **무엇**: 기능 표 F-04-16(LCH-320)의 동결 로컬 트랙 계획이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **등급**: B. 이번 동결 기간(2026-11-23~12-03)의 가벼운 절차(ADR-0373)에서는 B·C 기능의 시험 리뷰를 생략하지만, 감독이 이 기능에 한해 **계획 → 시험 → 시험 리뷰(새 세션) → 반영 → 구현 → 기록**을 지시했다. 이번 턴은 계획·시험·기준 트리 실패 확인·게이트·푸시에서 멈추고 시험 리뷰를 기다린다. 구현은 시험 리뷰 뒤에 시작한다.
- **동결 로컬 범위**: v1 출시 범위 밖이다(ADR-0373 결정 2, ADR-0386 결정 4·5, `docs/release/v1-scope.md` F-04-16). `freeze/lane6-F-04-16` 가지와 `D:/ticketpass-freeze-F-04-16` 워크트리에서만 개발하고 `develop`·`release/1.0.0`에 합치지 않는다. 출시 마이그레이션·릴리스 플래그·`deploy/` 값을 건드리지 않는다.
- **바탕**: `f7c253b4c`(`origin/freeze/lane6-F-04-15`, F-04-15 완료 포함, 2026-11-27). F-04-9~F-04-15가 만든 `apps/forensics` 합성 데모(사건 열 형식·검증·체크포인트·시드), `packages/api-client`의 `getOpsFraudCaseReplayExport`·`getOpsResearchExport` 생성 작업, `packages/config`의 묶음 G 헤더를 입력으로 쓴다.
- **정본**: `docs/features/forensic-replay.md` §2.1~§2.3·§3.3·§4.2~§4.3·§6.3·§6.5·§6.7.1·§6.8·§7.1·§9, `docs/security/asvs/forensic-replay.md`, `docs/frontend.md` §5.14.1·§5.19, `docs/design/d5-screen-blueprint.md` §7.17, `docs/api/openapi.yaml` `getOpsFraudCaseReplayExport`·`getOpsResearchExport`, `docs/api/guidelines.md` §10~§12, `docs/lanes/lane6.md`, ADR-0080·0171·0173·0372·0373·0386.
- **감독 지시문과 정본의 차이**: 지시문의 '원천 배지(라이브/녹화/재생)'는 정본 CMP-082·d5 §7.17·`docs/features/forensic-replay.md` §2.1의 **조사·연구·합성 데이터**와 다르다. 이 기능은 정본 이름을 따르고, 운영 빌드에는 `조사`·`연구`만 둔다. '라이브/녹화/재생'이라는 새 배지를 만들지 않는다(§2.3).

## 1. 이 기능이 끝내는 것과 넘기는 것

### 1.1 끝내는 것

1. **빌드 갈래 둘**: `PEAKET_FORENSICS_MODE=operating`이면 운영 빌드(`operating.html` → `src/operating/main.tsx`, 기반 경로 `/forensics/`), 없거나 `demo`면 시험·시연 빌드(`index.html`, 기반 경로 `/`)다. 모르는 값은 빌드 첫 단계에서 거절해, 오타가 조용히 공개 데모를 만드는 일을 막는다.
2. **운영 원천 해석**: 운영 빌드는 `?case=`(사건 작업대가 넘긴다)이면 조사, `?export=`(연구 메뉴가 넘긴다)이면 연구다. `?source=`는 읽지 않는다. 둘 다 있거나 둘 다 없으면 화면을 열지 않고 안내한다. 회차(`?event=`)는 필수이고, 사건·내보내기 ID는 계약의 UUID 꼴만 받는다.
3. **원천 배지**: 운영 빌드의 머리에 CMP-082 `조사`·`연구` 배지를 늘 보이고 화면 안에서 바꾸지 못한다. 배지는 연 길이 정하며, 연 길과 파일 원천이 다르면 파일 거절이다(§4.2).
4. **replay-export 받기**: 조사는 `GET /v1/ops/fraud-cases/{caseId}/replay-export`, 연구는 `GET /v1/ops/research-exports/{exportId}`를 `api-client`의 `fetch` 경로로만 받는다. 주소창·링크로 열지 않고, `Content-Disposition`·내려받기 단추를 만들지 않으며, 받은 바이트는 화면 메모리에만 둔다.
5. **응답 계약 확인**: 200은 `application/vnd.apache.arrow.file`, `Cache-Control: no-store`, `Content-Disposition` 없음이어야 한다. 하나라도 어긋나면 파일 거절이다. 401·403·404·409·410·422·503은 정본 문구로 가른다.
6. **파일 계약 확인**: 앞뒤 `ARROW1` 매직, 200MB 경계, 스키마 열 이름·형·순서, 압축 버퍼·사전 열, 원천 대조를 읽기 전·해독 전에 본다. 열 해독 자체는 F-04-17 몫이다(§1.2).
7. **COOP/COEP·격리**: 시험·시연 빌드는 묶음 G(`COOP: same-origin`, `COEP: require-corp`), 운영 빌드는 콘솔 묶음 C에 `COEP: require-corp`를 더한 헤더를 쓴다. 개발·미리보기 서버도 같은 COOP/COEP를 걸어 `crossOriginIsolated`를 로컬에서 확인할 수 있게 한다. 격리가 없어도 복사 방식으로 돌고, 상태 띠에 `공유 메모리 켜짐`·`복사 방식`을 보인다.
8. **운영 화면의 받기·실패 상태**: d5의 `받는 중`, `파일 거절`, `원천 만료`, `권한 없음(지정 없음)`, `재생`과 기존 `source.ts`의 `오류 · pseudonymization-review-pending`을 쓴다. 409 `research-export-not-ready`는 받는 중 화면의 인라인 안내('연구용 내보내기를 아직 만드는 중입니다')다. 실제 좌석맵·타임라인 그리기는 F-04-17 몫이다.
9. **화면 메모리 경계**: 받은 파일·사건 값·원천 원문을 `localStorage`·`sessionStorage`·`IndexedDB`·쿠키·URL·로그에 쓰지 않는다. 화면을 떠나면 `AbortController`로 받기를 멈추고 파일 상태를 지운다.
10. **A-T24의 화면 쪽**: 조사 원천 화면 모델은 계정 ID·사건 ID·계정끼리 견주는 행동 값(엔트로피·유사도·순위)을 표시 값으로 만들지 않는다. 파일 안 번호(세션·기기 묶음)만 쓴다.
11. **헤더 정본의 한 자리**: `packages/config`에 콘솔 주소 아래 `/forensics` 경로의 헤더 생성기(`consoleForensicsHeaders`)를 더한다. 배포(`deploy/`)는 동결 범위라 건드리지 않고, 동결을 풀 때 그 생성기를 쓴다.

## 2. 정본 빈칸과 이번에 정한 것(추천 적용 2026-11-27)

- **정본 반영(2026-11-27, RV0416-10)**: 아래 1~4의 주소 키·빌드 환경 변수·`?source=` 무시는 이번 review-fix에서 `docs/features/forensic-replay.md` §6.8, `docs/design/d5-screen-blueprint.md` §7.17, `docs/frontend.md` §4.1 route 표·§5.19에 **먼저** 적었다. 이 계획은 그 정본을 가리키고, 정본과 다르면 정본이 이긴다.

1. **빌드 갈래 이름**: `PEAKET_FORENSICS_MODE=operating` 하나로 가른다. 값이 없으면 `demo`, `demo`·`operating`만 허용하고 그 밖의 값은 `TypeError`다. `import.meta.env.DEV`나 `?source=`로 갈래를 바꾸지 않는다. 정본: feature §6.8·frontend §5.19.
2. **운영 빌드의 원천**: `?case=`가 있으면 조사, `?export=`가 있으면 연구다. 둘 다 있으면 `both-branches`, 둘 다 없으면 `open-path`다. `?event=`는 필수다. `case`·`export`는 UUID(`^[0-9a-f]{8}-...$`)만 받고, `event`는 기존 `parseOpened`의 ID 꼴(`[A-Za-z0-9][A-Za-z0-9-]{0,63}`)을 쓴다. d5의 목업 사건 번호(`CASE-2610-0007`)는 운영 빌드에서 쓰지 않는다. 정본: feature §6.8·d5 §7.17.
3. **배지와 합성 spec 분리**: 운영 빌드는 `조사`·`연구`만 있다. 합성 데이터·시나리오·시드·[다시 만들기]·[파일 불러오기]·[이 시나리오 내려받기]·공유 주소 복사는 운영 묶음에 없다. 배지는 `ReplaySourceBadge`(CMP-082)를 그대로 쓰고, 원천을 화면 안에서 바꾸는 링크를 두지 않는다. 운영 묶음에 `source.ts`의 `SPECS.synthetic`이 남지 않게 `source-specs/{investigation,research,synthetic}.ts`로 나누고, 시험·시연만 셋을 모두 가져온다(RV0416-04).
4. **`?source=`**: 시험·시연 빌드는 지금처럼 `?source=조사|연구`로 원천을 고른다. 운영 빌드는 이 값을 읽지 않는다. 누군가 주소에 붙여도 연 길의 원천을 바꾸지 못한다. 정본: feature §6.8·d5 §7.17·frontend §5.19.
5. **헤더**: 시험·시연 빌드는 묶음 G(`Referrer-Policy: no-referrer`, `COOP: same-origin`, `COEP: require-corp`, `Permissions-Policy` 전부 끔)를 쓴다. 운영 빌드는 콘솔 묶음 C(CSP `connect-src`에 `ops-api`)에 `COEP: require-corp`를 더한다. 개발 서버는 HMR 때문에 CSP를 걸지 않고 COOP/COEP/Referrer/Permissions만 건다. 미리보기 서버는 빌드 갈래의 전체 헤더를 건다.
6. **응답 계약**: 200의 `content-type`은 `application/vnd.apache.arrow.file`로 시작해야 하고(파라미터 허용), `cache-control`에 `no-store`가 있어야 하며, `content-disposition`은 없어야 한다. `content-length`가 200MB를 넘으면 본문을 읽기 전에 거절한다. 200이 아닌 응답은 `replayProblem`이 상태·Problem type으로 가른다. 연구 내보내기의 409 `research-export-not-ready`는 `Retry-After`를 따르고 화면은 '연구용 내보내기를 아직 만드는 중입니다'를 보인다.
7. **파일 봉투와 해독의 경계**: 이 기능은 `ARROW1` 앞뒤 매직·200MB·스키마 열 목록·압축/사전 표시·원천 대조까지 본다. 실제 Arrow IPC 해독과 열 배열 만들기는 F-04-17이다. `replayFileValidation`은 `{ envelope: ReplayEnvelope, meta, schema, columns }`(`ReplayFileInput`)를 받아 내부에서 `Envelope`로 바꾼다. 확장자 검사는 응답 파일 이름이 아니라 내부 고정 이름 `replay.arrow`로만 한다(화면은 파일 이름을 만들지 않는다).
8. **파일 거절 문구**: danger 띠 제목은 '이 파일은 열 수 없습니다(형식이 다릅니다)'이고, 이유 한 줄은 `Reject.message`를 그대로 쓴다. 매직·크기·원천 불일치·압축·사전·스키마 위반은 모두 같은 띠로 끝나고 아무것도 그리지 않는다.
9. **오류 문구의 두 층**: 전체 화면 상태는 d5 §7.17의 `받는 중`·`재생`·`파일 거절`·`원천 만료`·`권한 없음(지정 없음)`을 쓰고, 연구 검토 전은 기존 `source.ts`의 `오류 · pseudonymization-review-pending`을 그대로 쓴다. `내보내기 준비 중`은 d5 상태가 아니라 받는 중 화면 안의 인라인 안내다. 인라인 Problem은 openapi의 Problem title을 쓴다. 예: 403 `investigator-required`는 전체 화면에서 '이 화면을 볼 권한이 없습니다', 인라인에서 '부정 거래 조사관만 할 수 있습니다'.
10. **내려받기 없음**: 리플레이 파일은 `fetch`로 받아 `ArrayBuffer`/`Uint8Array`로만 다룬다. `<a download>`·`window.open`·`URL.createObjectURL`·`new Blob`·`showSaveFilePicker`·`Content-Disposition`을 만들지 않는다. 화면은 파일 이름을 만들지 않고, 검증기 안의 고정 이름 `replay.arrow`만 쓴다(ASVS 5.4.1의 서버 쪽 판정은 F-04-14·F-04-15가 이미 닫았다).
11. **화면 메모리**: 받은 파일과 검증 결과는 React 상태·ref에만 둔다. `localStorage`·`sessionStorage`·`IndexedDB`·`document.cookie`·`navigator.storage`·`caches`·`history.pushState`·`document.title`·`location.*`·`console.*`에 쓰지 않는다. 화면을 떠날 때 `AbortController.abort()`와 `setFile(null)`로 지운다. 시험은 `OperatingApp` 한 파일이 아니라 `src/operating`의 모든 `.ts`·`.tsx`를 본다.
12. **A-T24의 경계**: 이 기능은 화면 모델이 계정 ID·사건 ID·계정별 엔트로피/유사도/순위·기기/망 값을 표시 값으로 만들지 않는 것까지다. 분석 저장소의 `slv_trust_label`·`brz_ops_fraud_summary`·R3 리포트 판정은 F-04-19 몫이다.
13. **연구 원천의 열기**: 연구 메뉴가 `POST /v1/ops/research-exports`로 만든 `exportId`를 `?export=`로 넘긴다. `POST`·감사·`pseudonymization_log`는 이 기능이 부르지 않는다. `PSEUDONYM_HANDLER` 지정이 없으면 서버 403을 받아 `권한 없음` 화면이 된다(화면이 지정을 미리 알 수 없으므로 서버 판정을 그대로 쓴다).
14. **운영 화면의 재생 자리**: 이 기능은 파일을 받아 검증한 뒤 d5의 `재생` 상태와 파일 요약(원천·바이트 수·사건 수는 해독 뒤 F-04-17)까지 보인다. 좌석맵·타임라인은 F-04-17이 붙인다. 그래서 이 기능의 완료 정의는 '운영 빌드가 열리고, 배지·헤더·받기·파일 계약·실패 상태가 정본대로 돈다'이다.
15. **계약**: `docs/api/openapi.yaml`·`packages/contracts`·`packages/api-client`를 고치지 않는다. 필요한 두 작업은 이미 생성물에 있다. 구현에서 `apps/forensics`의 `dependencies`에 `@peaket/api-client`를 더한다(계약 변경 아님).

## 3. 계약과 생성물(이번 단계는 고치지 않는다)

- 새 경로·스키마 없음. `getOpsFraudCaseReplayExport`(`GET /v1/ops/fraud-cases/{caseId}/replay-export`, 쿼리 `fromMs`·`toMs`), `getOpsResearchExport`(`GET /v1/ops/research-exports/{exportId}`)가 이미 `packages/api-client/src/gen/operations.ts`에 있다.
- `docs/api/openapi.yaml`의 200 응답은 `application/vnd.apache.arrow.file`, `Cache-Control: no-store`이고 `Content-Disposition`이 없다. 403 `investigator-required`·`pseudonym-handler-required`, 404, 409 `research-export-not-ready`, 410 `investigation-source-expired`, 422 시간창 초과가 이미 있다.
- `gen:check`는 계약과 생성물이 같은지만 본다. 이번 단계에 바뀌는 계약은 0줄이다.

## 4. 공개 인터페이스(시험이 이 이름을 쓴다)

### 4.1 운영 원천 모델(`apps/forensics/src/lib/operating.ts`, 순수)

```ts
import type { SourceSpec } from './source-spec.ts';
import type { EventRow } from './forensics/events.ts';

export type BuildMode = 'demo' | 'operating';
export type OpenedSource = 'INVESTIGATION' | 'RESEARCH';
export interface OpenTarget {
  source: OpenedSource;
  sourceLabel: 'investigation' | 'research';
  eventId: string;
  caseId: string | null;
  exportId: string | null;
}
export type OpenResult =
  | { ok: true; target: OpenTarget }
  | { ok: false; code: 'open-path' | 'both-branches' | 'event-id' | 'case-id' | 'export-id'; message: string };

export interface ReplayRowView {
  sessionNo: number;
  kind: number;
  seat: number;
  section: number;
  result: number;
  member: boolean;
  postSeat: boolean;
  atMs: number;
}

export function resolveOpen(search: string | URLSearchParams): OpenResult;
export function operatingBadge(t: OpenTarget): '조사' | '연구';
export function operatingSpec(t: OpenTarget): SourceSpec;
export function consolePathFor(t: OpenTarget): string;
export function isolationLabel(crossOriginIsolated: boolean): '공유 메모리 켜짐' | '복사 방식';
export function replayRowView(row: EventRow, t: OpenTarget): ReplayRowView;
```

- `resolveOpen`은 `?source=`를 읽지 않는다. `case`와 `export`가 모두 있으면 `both-branches`, 모두 없으면 `open-path`, `event`가 없으면 `event-id`, UUID 꼴이 아니면 `case-id`·`export-id`다.
- `operatingBadge`는 `INVESTIGATION` → `조사`, `RESEARCH` → `연구`다. `합성 데이터`를 돌려주지 않는다.
- `operatingSpec`은 `source-specs/investigation.ts`·`source-specs/research.ts`의 spec을 `sourceSpec`과 같은 모양으로 돌려준다. 정본 문구를 복사하지 않고, 운영 묶음에는 `source-specs/synthetic.ts`·`source.ts`가 들어가지 않는다(RV0416-04).
- `consolePathFor`는 조사면 `/investigations/{caseId}`, 연구면 `/dashboard`다. 운영 빌드는 콘솔과 같은 출처라 절대 주소를 만들지 않는다.
- `isolationLabel`은 `crossOriginIsolated` 참·거짓만 받는다. 재생은 이 값과 무관하게 복사 방식으로 돈다(§3.3). `OperatingHead`가 이 값을 읽어 상태 띠에 쓰고, `OperatingApp`은 이 값으로 받기·재생을 막지 않는다.
- `replayRowView`는 파일 행에서 화면에 필요한 숫자·불리언만 꺼낸다. `accountId`·`caseId`·`entropy`·기기/망 값·유사도·순위를 넣지 않는다. 값 매핑은 `atMs ← t_ms`, `sessionNo ← session`, `kind`·`seat`·`section`·`result`, `member ← member !== 0`, `postSeat ← post_seat !== 0`이다.
- `source-specs/{investigation,research,synthetic}.ts`는 `source.ts`가 쓰던 `SourceSpec`을 셋으로 나눈 것이다. `source.ts`는 시험·시연용으로 셋을 모두 가져오고, 운영은 앞 둘만 가져온다.

### 4.2 replay-export 모델(`apps/forensics/src/lib/replay-export.ts`, 순수)

```ts
import type { EventColumns, ForensicMeta, SchemaColumn, Validation } from './forensics/events.ts';
import type { OpenTarget, OpenedSource } from './operating.ts';

export const ARROW_MAGIC: 'ARROW1';
export const REPLAY_MEDIA_TYPE: 'application/vnd.apache.arrow.file';
export const REPLAY_WINDOW_MS: 1_800_000;
export interface ReplayEnvelope { byteLength: number; head: string; tail: string }
export interface ReplayFileInput {
  envelope: ReplayEnvelope;
  meta: ForensicMeta;
  schema: readonly SchemaColumn[];
  columns: EventColumns;
}
export interface ReplayWindow { fromMs?: number; toMs?: number }
export interface ReplayProblem {
  kind: 'auth' | 'denied' | 'review-pending' | 'reauth' | 'not-found' | 'not-ready' | 'expired' | 'invalid' | 'limited' | 'unavailable' | 'error';
  message: string;
  retry: boolean;
}
export interface ReplayOperation {
  operationId: 'getOpsFraudCaseReplayExport' | 'getOpsResearchExport';
  params: Record<string, string>;
  query: Record<string, number>;
}

export function replayEnvelopeOf(bytes: Uint8Array): ReplayEnvelope;
export function replayFileIssue(e: ReplayEnvelope): string | undefined;
export function replayHeadersIssue(status: number, headers: Headers | Record<string, string>): string | undefined;
export function replayFileValidation(file: ReplayFileInput, t: OpenTarget): Validation;
export function replayProblem(status: number, type: string | null | undefined, source: OpenedSource): ReplayProblem;
export function replayOperation(t: OpenTarget, w?: ReplayWindow): ReplayOperation;
export function replayWindowIssue(w: ReplayWindow): string | undefined;
```

- `replayEnvelopeOf`는 `byteLength`와 앞뒤 6글자를 꺼낸다. 0바이트·12바이트 미만도 빈 문자열·짧은 문자열로 돌려준다. `replayFileIssue`는 200MB 초과와 `ARROW1` 불일치를 문구로 준다.
- `replayHeadersIssue`는 200일 때만 본다. `content-type`이 `application/vnd.apache.arrow.file`로 시작하는지(파라미터 허용), `cache-control`에 `no-store`가 있는지, `content-disposition`이 없어야 하는지(빈 값도 거절), `content-length`가 200MB 이하인지 본다. 200이 아니면 `undefined`를 주고 `replayProblem`이 맡는다. `Record<string,string>`은 키를 소문자로 바꿔 읽는다.
- `replayFileValidation`은 `ReplayFileInput`을 받아 내부에서 `Envelope`(`fileName: 'replay.arrow'`, `byteLength`, `magicHead: head`, `magicTail: tail`)로 바꿔 `validateFile({ ..., openedSource: t.source })`를 부른다. 응답 파일 이름은 쓰지 않는다. 파일 원천과 연 길이 다르면 `source-mismatch`, 압축·사전·모르는 열은 `schema-compressed`·`schema-dictionary`·`schema-columns`다.
- `replayProblem`은 401 `auth`, 403 `denied`·`review-pending`·`reauth`, 404 `not-found`, 409 `not-ready`(retry 참), 410 `expired`(조사 `investigation-source-expired`), 422 `invalid`, 429 `limited`, 503 `unavailable`(retry 참), 그 밖 `error`로 가른다. 연구 GET 계약에는 410이 없으므로 연구 만료는 404로 다룬다.
- `replayOperation`은 조사면 `{ operationId: 'getOpsFraudCaseReplayExport', params: { caseId }, query: { fromMs?, toMs? } }`(없는 값은 빼고 `{}` 가능), 연구면 `{ operationId: 'getOpsResearchExport', params: { exportId }, query: {} }`다. 연구에 시간창을 넘기면 `TypeError`다(연구는 만들 때 정한다).
- `replayWindowIssue`는 시작·끝을 함께 적어야 하고, 끝이 시작보다 뒤이며, 차이가 30분 이하이고, 밀리초 정수여야 한다.

### 4.4 운영 화면(`apps/forensics/src/operating/`)

- 파일은 `main.tsx`, `OperatingApp.tsx`, `OperatingHead.tsx`, `ReceivingMain.tsx`, `ProblemMain.tsx`, `ReadyMain.tsx` 여섯이다. 시험은 이 이름이 모두 있는지 보고 `src/operating`의 모든 `.ts`·`.tsx`를 스캔한다.
- `main.tsx`: `createRoot`로 `OperatingApp`을 그린다. `src/styles.css`를 먼저 가져온다.
- `OperatingApp.tsx`: `useSearch`로 `resolveOpen`, `useEffect`에서 `AbortController`를 만들고 `replayOperation` → `api-client.request` → `replayHeadersIssue`(Content-Length 사전 검사 포함) → `arrayBuffer` → `replayEnvelopeOf`·`replayFileIssue` → `replayFileValidation` 순서로 받는다. 파일은 `useState`/`useRef`에만 둔다. 정리 함수에서 `abort()`와 `setFile(null)`을 부른다. `localStorage`·`sessionStorage`·`indexedDB`·`document.cookie`·`navigator.storage`·`caches`·`document.title`·`location.*`·`console.*`·`<a download>`·`window.open`·`createObjectURL`·`new Blob`·`showSaveFilePicker`·`sendBeacon`을 쓰지 않는다.
- `OperatingHead.tsx`: `ReplaySourceBadge`(조사·연구), 회차, 사건(조사), `consolePathFor` 링크, `crossOriginIsolated`를 읽어 `isolationLabel`로 그리는 격리 상태 띠(`role="status"`/`aria-live`), 화면 제목 `h1`.
- `ReceivingMain`·`ProblemMain`·`ReadyMain`: 정본 문구와 `role="status"`·`aria-live`. 실제 재생 화면은 F-04-17이 `ReadyMain` 자리에 붙인다.
- `src/operating/`은 `src/lib/source.ts`·`src/lib/source-specs/synthetic.ts`·`src/screen/`(합성 보드)·`lib/forensics/scenario.ts`·`prng.ts`·`cdf.ts`·`inv-cdf-table.ts`를 가져오지 않는다. 정적 import와 동적 `import()` 둘 다 시험이 따라간다.

## 8. 실패 시나리오와 엣지 케이스

1. **빌드 값 없음·오타**: 없으면 시험·시연, `operating`만 운영, `prod`·`Operating`은 빌드 실패. 오타가 공개 데모를 만들지 않는다.
2. **연 길 없음**: `?event=`만 있으면 `open-path` 안내. 사건 작업대·연구 메뉴에서 다시 열라는 문구.
3. **두 갈래 동시**: `?case=`와 `?export=`가 함께 있으면 `both-branches`로 열지 않는다. 한 화면에서 두 원천을 잇지 않는다(§6.6).
4. **ID 꼴**: 사건·내보내기는 UUID만, 회차는 기존 ID 꼴만. `CASE-2610-0007` 목업 번호·`apl-1`은 운영에서 거절.
5. **`?source=` 주입**: 운영에서 `?source=연구`를 붙여도 조사 탭은 조사로 남는다. 배지를 URL로 바꾸지 못한다.
6. **권한 없음**: 403 `investigator-required`·`pseudonym-handler-required`는 '이 화면을 볼 권한이 없습니다'와 지정 안내. 403 `reauth-required`는 '다시 인증해 주세요'. 감사 기록은 서버가 남긴다.
7. **가명처리 검토 전**: 403 `pseudonymization-review-pending`은 '가명 처리 검토 중입니다'와 보호책임자 안내. 받을 기록이 없어 아무것도 그리지 않는다.
8. **원천 만료**: 410 조사는 '이 회차의 조사용 기록은 보존 기간이 지났습니다. 증거 묶음만 볼 수 있습니다'. 연구 GET 계약에는 410이 없으므로 없는 내보내기는 404로 가고, 연구 원천의 90일 만료 문구는 `source.ts`의 기존 문구로 안내한다(계약 밖 방어). 받기 전에 멈춘다.
9. **없는 사건·내보내기**: 404는 '찾을 수 없습니다'와 관제 콘솔 링크.
10. **준비 중**: 409 `research-export-not-ready`는 '연구용 내보내기를 아직 만드는 중입니다'와 `Retry-After` 뒤 다시 시도. 화면은 자동으로 돌지 않고 사용자가 다시 연다.
11. **시간창**: 시작만·끝만·끝≤시작·30분 초과·소수가 아닌 값은 422로 가고 화면은 보내기 전에 같은 규칙으로 막는다.
12. **응답 형식**: 200인데 JSON·HTML이면 파일 거절. `content-type` 파라미터는 허용하고, `cache-control`에 `no-store`가 없거나 `content-disposition`이 있으면(빈 값 포함) 파일 거절. `Headers`와 `Record<string,string>` 둘 다 같은 규칙이다.
13. **매직·크기**: `content-length`가 200MB를 넘으면 본문을 받기 전에 거절하고, 앞뒤 `ARROW1`이 없거나 받은 바이트가 200MB를 넘으면 해독 전에 파일 거절. 200MB 정확히는 허용.
14. **원천 불일치**: 사건 작업대 탭에 연구 파일, 연구 탭에 조사 파일이 오면 `source-mismatch`. 양쪽 방향을 모두 거절하고 파일을 그리지 않는다.
15. **압축·사전·모르는 열**: `schema-compressed`·`schema-dictionary`·`schema-columns`로 거절. 풀기 전에 멈춘다.
16. **연구 파일의 조사 칸**: RESEARCH 파일에 `member`·`post_seat`·`entropy`·`device_group`·`net_type` 값이 있으면 `source-rule`. 화면은 연구 원천 문구로 거절한다.
17. **200MB 경계**: `MAX_FILE_BYTES` 정확히는 허용, +1은 거절. 큰 파일을 실제로 만들지 않고 봉투·`content-length` 값으로 본다.
18. **격리 없음**: `crossOriginIsolated=false`여도 재생은 복사 방식으로 돈다. 상태 띠는 '복사 방식'이고 경고가 아니다.
19. **격리 켜짐**: `true`면 '공유 메모리 켜짐'. `OperatingHead`가 이 값을 읽어 띠에 쓰고, `OperatingApp`은 이 값으로 받기·재생을 막지 않는다. 공유 시계는 F-04-17의 더할 조건 전에는 켜지 않는다.
20. **화면 이탈**: 받는 중에 화면을 떠나면 `AbortController.abort()`, 파일 상태를 `null`로 지운다. `src/operating`의 모든 파일이 브라우저 저장소·URL·로그에 남기지 않는다.
21. **내려받기 시도**: 리플레이 파일에는 내려받기 단추·`Content-Disposition`·`createObjectURL`·`new Blob`·`showSaveFilePicker`·`sendBeacon`이 없다. 화면은 파일 이름을 만들지 않는다.
22. **503**: '잠시 뒤 다시 시도해 주세요'와 retry. 자동 재시도는 `api-client` 정책을 따르고 화면이 무한 반복하지 않는다.
23. **합성 누출**: 운영 묶음 import 그래프(정적·동적)에 `source.ts`·`source-specs/synthetic.ts`·`scenario.ts`·`prng.ts`·`cdf.ts`·`inv-cdf-table.ts`·`screen/`이 없다. 시험·시연 묶음에 `@peaket/api-client`·`operating/`이 없다.
24. **A-T24**: 화면 모델에 계정 ID·사건 ID·엔트로피·기기/망 값·유사도·순위가 없다. 파일 안 세션 번호·기기 묶음 번호만 쓰고, `atMs`·`seat`·`member`·`postSeat`는 실제 값으로 매핑한다.
25. **그래프**: F-04-15가 남긴 운영 `FraudGraphSource` 빈 목록은 이 기능이 채우지 않는다. 리플레이 파일과 그래프를 같은 `Promise.all`로 묶지 않는다(리플레이가 그래프 실패에 막히지 않게).
26. **계약 없음**: 새 경로·스키마·Problem type을 만들지 않는다. 409·410·422의 기존 type만 쓴다.

## 15. 미룬 것과 남는 위험

1. **Arrow 열 해독·재생**: 이 기능은 파일 봉투·스키마·원천 대조까지다. 실제 열 배열·체크포인트·좌석 상태·타임라인은 F-04-17이다. 그래서 운영 화면은 d5의 `재생` 상태에서 멈추고, F-04-17이 그 자리에 재생 화면을 붙인다.
2. **운영 그래프 원천**: F-04-15 IR-01이 남긴 `FraudGraphSource` 빈 목록은 이 기능이 채우지 않는다. F-04-17의 화면이 그래프를 그리려면 별도 원천 배선이 필요하다. 이 계획은 그 경계를 명시하고 F-04-16 범위에서 뺐다.
3. **연구 내보내기 서버**: `POST /v1/ops/research-exports`, 감사 기록, `pseudonymization_log`, `an_forensic_reader` 권한, 적정성 검토 결과서 판은 F-04-19다. 이 기능은 이미 만들어진 `exportId`를 받아 오는 화면 쪽만 닫는다.
4. **배포 헤더**: `deploy/`의 CloudFront 응답 헤더 정책에 `consoleForensicsHeaders`를 연결하는 일은 동결 밖이다. 그 전까지 실제 배포에서는 COEP가 빠질 수 있고, ASVS 3.4.8·3.5.4는 '생성기·개발·미리보기까지'로만 판정한다.
5. **실제 S3·영상**: 실제 리플레이 파일·영상·S3 경로는 `미실행`이다. 이번 시험은 봉투·스키마·응답 계약만 본다.
6. **브라우저 확인**: `crossOriginIsolated`·배지·받기 상태는 실제 브라우저에서 확인하지 않았다. F-04-17·검증 단계에서 `peaket-browser-check`로 본다.
7. **`apache-arrow` 의존**: 이 기능은 라이브러리를 넣지 않는다. F-04-17이 넣을 때 번들 크기(§7.1 첫 JS 200KB [가정])를 잰다.
8. **Redis·서버 시험**: 이 기능은 서버 코드를 바꾸지 않는다. ops-svc·core-svc의 replay-export 서버 판정은 F-04-14·F-04-15·F-04-19가 맡는다.
9. **수치 주장**: 30k/s·100만·K1/K2/K7 0 같은 수치는 이 기능이 재지 않는다. 실제 영상·S3·브라우저는 `미실행`/[가정]으로 남긴다.
