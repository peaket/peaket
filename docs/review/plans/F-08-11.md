# 기능 계획: F-08-11(런북 41종·인시던트 기준·색인, 동결 로컬 트랙)

- **진행**: 계획·시험(문서 계약) 끝, 기준 트리 실패 확인, **리뷰 준비에서 멈춤**(2026-11-27). 런북 본문·정본 반영·기록은 다음 역할이 한다. 실제 인시던트·Game Day·장애 주입·측정은 모두 `미실행`이다.
- **무엇**: BUILD_ORDER '기능 단위 계획' F-08-11(갈래 4, 등급 B, OPS-450, WBS 2.75일, 단계 줄 `OPS-450 wbs 4.7.1 ①`)의 작업 목록이다. 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.
- **쉬운 말**: 장애가 났을 때 무엇을 보고, 누구에게 알리고, 어떤 순서로 되돌리는지를 적은 절차서(런북) 41개를 파일로 만든다. 지금은 `docs/infra.md` §10에 41줄 목차만 있고 실제 절차 파일은 없다. 함께 ① 장애를 인시던트로 선언하는 기준(심각도·탐지 경로·에스컬레이션·포스트모템), ② 서비스와 증상으로 런북을 찾는 색인, ③ 원인 유형 9가지로 찾는 색인을 만든다. **장애를 실제로 내 보거나 인시던트를 겪은 기록을 만드는 일은 이 기능이 하지 않는다.**
- **바탕**: 작업 폴더 `D:/ticketpass-freeze-F-08-11`, 가지 `freeze/lane4-F-08-11`, 기준 `origin/freeze/lane4-F-08-10` `c895b63dd`(F-08-10 구현·기록 포함). 계획·시험 담당은 Docker·kind·k6·브라우저·클러스터를 하나도 쓰지 않았고 Docker 잠금도 잡지 않았다.
- **차례(감독 지시 2026-11-27)**: 계획 → 시험(정적·문서 계약) → 리뷰(새 세션) → 반영 → 구현/문서 → 기록. ADR-0373의 B등급 차례는 계획 → 시험 → 구현 → 시험 통과면 합침이고 시험 리뷰가 없다. 이 기능은 **'목차만 있고 절차가 없는 상태'가 완료로 새지 않는가**와 **색인이 41종을 빠짐없이 찾게 하는가**가 핵심이라 감독이 리뷰를 한 번 더 붙였다. 리뷰는 코드가 아니라 문서 계약·시험·경계를 본다. 이번 동결 트랙은 계획과 시험을 한 세션이 맡았다(감독 지시). 역할 꼬리말은 `Role: plan`·`Role: test`로 나눠 남긴다.
- **동결 로컬 범위**: ADR-0373·ADR-0386에 따라 `freeze/lane4-F-08-11` 가지와 이 워크트리에서만 만든다. `develop`·`release/1.0.0`에 합치지 않고, 릴리스 가지·`main`에 체리픽하지 않는다. 마이그레이션·릴리스 플래그를 만들지 않고, `deploy/`의 출시 환경 값도 고치지 않는다. 이 기능의 결과는 v1 출시 계약의 근거로 쓰지 않는다.
- **수치**: 이 파일과 시험은 정본의 목표·판정 값을 **인용만** 한다. 실제 인시던트·Game Day·장애 주입·부하 측정은 `미실행`이므로 이 기능이 내는 값은 전부 `미실행` 또는 `미정`이다. `30k/s`·`100만`·`K1`·`K2`·`K7`의 달성값을 주장하지 않는다. 정본에 없는 새 수치(목표 시간·탐지 시간·복구 시간)를 만들지 않는다. 새 목표 시간이 필요하면 `미정`으로 두고 왜 정하지 못했는지 적는다.
- **한 줄 결론**: 목차 41줄과 산문 기준은 있지만, 41개 절차 파일·서비스×증상 색인·인시던트 기준 문서·문서 계약 시험이 없다. `docs/runbooks/`(예정)에 41개 파일과 읽기 안내·색인·기준·틀을 만들고, `docs/infra.md` §10 표를 파일 링크로 바꾸며, 정적 시험 10개로 빠진 런북·빈 절차·색인 누락·수치 주장을 막는다.

## 2. 감독에게

1. **41종을 파일 41개로 나눈다** — `docs/infra.md` §10의 한 줄 목차를 그대로 두고, `docs/runbooks/RB-01.md`~`RB-41.md`(예정)에 절차를 쓴다. 한 파일에 41개를 몰아넣지 않는다. 경보 `runbook_url`이 지금 `docs/infra.md#10-…`을 가리키므로, 파일이 생겨도 경보 규칙 URL은 이 기능에서 바꾸지 않는다(배포 설정 변경은 동결 로컬 범위 밖이고, F-08-11은 문서 기능이다). 찾는 길은 `docs/infra.md` §10 표와 새 색인이다. **감독 확인 필요.**
2. **인시던트 기준은 값을 복사하지 않는다** — `docs/runbooks/incident-criteria.md`(예정)는 SEV1~3의 발생 상황·수치를 다시 적지 않고 `docs/observability.md` §5를 가리킨다. 대신 운영자가 바로 쓰는 **선언 확인 목록 7개**, 탐지 경로 3가지, 역할(IC·OL·CL), 포스트모템 48시간·원인 유형 9가지, 공지 경로를 적는다. 시험이 정본과 목록의 핵심 낱말이 같은지 본다. **감독 확인 필요.**
3. **색인은 서비스×증상×런북이다** — `docs/runbooks/index.md`(예정)에 ① 서비스·영역별(10개 서비스 + 게이트웨이·관측·배포·플랫폼·보안·법정·공통·운영), ② 증상 분류 8가지, ③ 원인 유형 9가지, ④ 41종 전체 표를 둔다. 서비스·영역별 표는 41종이 모두 한 번 이상 나오고 모든 행이 비지 않아야 하며, 41종 전체 표는 41종이 정확히 한 번씩 나와야 한다. **감독 확인 필요.**
4. **런북마다 담당 역할과 목표 시간을 적는다** — `docs/infra-handover.md` 465행이 요구한다. 담당은 정해진 역할 목록 가운데 하나다(서비스 담당·온콜·IC·OL·CL·보안 담당·플랫폼 담당·DBA·릴리스 담당). 목표 시간은 정본에 있는 값만 인용하고, 없으면 `미정`으로 둔다. 새 숫자를 만들지 않는다. **감독 확인 필요.**
5. **`inv-ref-key` 회전은 RB-26 안에 둔다** — WBS는 별도 런북처럼 적지만 41종을 42로 늘리지 않는다. RB-26 '비밀 유출 대응'의 한 절로 `docs/security/secrets-and-keys.md`의 회전 절차 ①~⑧을 가리키고, 색인에 '조사 가명 키 회전' 증상으로 찾을 수 있게 한다. **감독 확인 필요.**
6. **HOT-010이 넘긴 두 길을 RB-05·RB-11에 넣는다** — RB-11에 queue-svc의 대기열 Redis 보류(`q:{held:<토픽>}:…`)를 위치로 다시 넣는 길, RB-05 뒤 `identity.accounts-withdrawn`의 queue-svc 소비자 그룹 위치를 장애 전환 시각 − 20분 [가정]으로 되돌려 다시 읽는 길(ADR-0214 결정 6·7). 두 길 모두 **절차만** 쓰고 실행 기록을 만들지 않는다. **감독 확인 필요.**
7. **경계** — F-08-6(Game Day 전체 재실행·포스트모템·SLO/KPI ADR), F-08-9(장애 주입 기록 검사·검색 측정), F-08-10(서비스 분리 비교·M2), F-08-12·F-08-13(Game Day 로컬·모의 진행)은 `미실행`이다. 이 기능은 절차·기준·색인만 만든다. 실제 인시던트도 0건이다. **감독 확인 필요.**
8. **장부** — F-08-11의 장부 범위 `docs/observability.md`는 장부 항목이 0개다(`node tools/ci/ledger.mjs --batch F-08-11` → 항목 0). OPS-450은 장부 ID가 아니라 WBS 작업 ID라 자동으로 세지 않는다. 그래서 `--require`는 '검사할 항목 없음'으로 통과하고, 진짜 판정은 이 계획의 문서 계약 시험 10개다. `docs/review/ledger-notes.md`는 고치지 않는다. **감독 확인 필요.**
9. **리뷰** — 새 세션이 계획·시험만 보고 본다. 보는 곳: 41종 파일·색인·기준이 서로 맞는가, 목차만 있고 절차가 빈 런북이 통과하지 않는가, 정본 값을 복사해 어긋나지 않는가, 수치·실행 주장이 새지 않는가, F-08-6·F-08-9·F-08-10을 침범하지 않는가, `docs/infra.md` §10 표와 파일이 같은가. 지적은 시험 담당이 고치고(`Fix-By: test`), 리뷰 담당이 확인한다. 번호는 `RV0811-NN`으로 적는다.
10. **정할 것** — 13절. 추천대로 정하고 구현 전에 이 파일에 적는다.
