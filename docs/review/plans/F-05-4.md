### 1. 끝내는 것과 넘기는 것

- **끝내는 것**
  1. B5: SCR-034가 카메라 → `BarcodeDetector` → 판정 10단계 → 스캔 큐(strict) → 화면으로 실제 판정한다(지금은 고정 상태 미리보기).
  2. 회차 목록을 기기 저장소 `peaket-scanner`에 두고 변경분 여덟 종류를 반영한다. 다시 받아도 아직 올리지 않은 이 기기 입장 상태를 잃지 않는다.
  3. B7: 판정 뒤 5초 묶음·500건 즉시 업로드, 연결 복귀·화면 복귀 즉시, 401 `invalid_token`이면 토큰을 지우고 기기 인증만으로 다시(O-T21 ③), `invalid_dpop_proof`면 새 증명, 로그아웃 전 큐 비우기(7.4.4).
  4. B8: 입장·퇴장 모드 전환(`PLACEMENT` 반영)과 ticket-svc가 core-svc 재입장 정책 바뀜을 `POLICY` 변경분으로 적기(O-T15).
  5. 서버 잔손: `KEY_REGISTERED` 변경분에 `publicKey`, 지표 `scanner_scans_received_total`·`scanner_policy_changes_total`, 로그 줄 `scanner.policy-changed`.
  6. GAT-160 버전 벡터 동시 스캔: 두 기기가 같은 티켓을 오프라인 통과시키고 동시에 올리면 기록 둘·'중복 입장' 표시 하나(판정 때 벡터·`knownSeq`·`deviceSeq`가 실린다).
- **이미 있는 것**(그대로 쓴다): §2 표와 근무 준비·준비 보고 API, 스캔 큐(strict), 버전 벡터 비교, 서버 판정 표·멱등 수신·세션 밖 기록, `PLACEMENT`·`SESSION_TERMINATED` 적기, 신선도 SEV2.
- **넘기는 것 → F-05-10**(BUILD_ORDER 새 행, 번호는 감독 확인): B9 새 앱 판은 근무 준비 때만(C1-15, `minAppVersion`)과 스캐너 서비스 워커, 판정 Worker·zxing-wasm 대체(3.5.5), 일회성 Background Sync 예비(O-T11), F-05-5가 넘긴 O-T37 ⑧ 서비스 워커 업로드, 판정 소리·진동·화면 낭독(O-T14), `marks.scan_judge_ms` 보내기, O-T20 현장 책임자 알림.
- **다른 기능 몫 그대로**: '몰랐음/알고도 통과'를 앞 기록 번호와 견주기(C1-03)·입장 기록 마감은 GAT-180(F-05-6). 양도 뒤 옛 QR(O-T7)은 양도 단계(F-05-2) 뒤. 부스·재인증 키 등록은 GAT-190·GAT-020.
- 정본에 쓴 것은 §3. 새 ADR 없음(방향을 바꾸지 않는 세부, ADR-0373 결정 3). 0377·0378은 쓰지 않았다.

### 10. 자주 놓친 결함(§8.6 4에서 고름)

- 경계 양쪽은 §6 표의 정본 값으로 적는다(코드 상수를 가져오지 않는다). 저장 응답은 정확한 값까지(`acceptedIds`, 행 수, 지표 값, 저장된 `known_seq`), 지우는 연산은 건드린 저장소 전부(큐·입장 상태·토큰 둘).
- 판정 함수만이 아니라 부르는 쪽(큐 쓰기 뒤에만 '통과', `acceptedIds`만 지움)을 바깥 경계에서 보고, 장애가 실제로 났는지(끊긴 횟수, 트리거가 던진 횟수) 단언한다.
- 짝 가짜(메모리 저장소·큐)는 같은 계약 시험을 진짜(IndexedDB, §8)에도. 겹친 가드(서버 멱등과 앱 `acceptedIds`)는 앱 쪽만 빼도 잡히게 '받지 않은 기록은 남는다'를 따로 본다.
