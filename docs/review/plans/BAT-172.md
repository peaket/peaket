# BAT-172 계획(CSP 3.6.1 같은 출처 스크립트 SRI: `/seed-color-mode.js` integrity와 건너뛰기 해소)

- **무엇**: BAT-171이 까닭 `BAT-172(OPEN[51], HOT-391)`을 달아 건너뛴 CSP 시험 `[ASVS v5.0.0-3.6.1]`을 되살린다. 지금은 공연 상세·추가 검증·결제 세 화면에서 같은 출처 `script[src]` 24·16·14건(공통 10건)에 `integrity`가 없어 실패한다. 이 묶음은 ① 우리 문서가 직접 싣는 같은 출처 스크립트 `/seed-color-mode.js`에 빌드 때 만든 SHA-256 `integrity`를 달고 ② Next.js가 넣는 `/_next/static/` 덩어리는 브라우저 `integrity`를 강제하는 대신 같은 빌드의 SRI 표와 받은 바이트를 시험으로 대조하며 ③ 시험의 건너뛰기를 지운다.
- **쉬운 말**: SRI(하위 자원 무결성)는 스크립트 태그에 파일의 지문(해시)을 적어, 받은 파일이 바뀌었으면 브라우저가 실행하지 않게 하는 장치다. 그런데 Next.js는 화면을 그리며 나중에 넣는 덩어리(클라이언트 부품·`import()`)에 지문을 달지 않는다. 이 덩어리들은 같은 빌드가 만든 내용 주소(`/_next/static/chunks/<해시>.js`)이고, 빌드가 SRI 표(`server/subresource-integrity-manifest.json`)에 해시를 남긴다. ASVS 3.6.1이 말하는 대상은 '외부에 둔 자산'이라, 우리 빌드 덩어리 전체에 브라우저 지문을 강제하는 것은 요구보다 넓다. 대신 시험이 그 표와 실제 바이트를 대조해 변조를 잡는다. 우리가 직접 쓰는 주소 고정 스크립트(`/seed-color-mode.js`)에는 진짜 `integrity`를 단다.
- **바탕**: 작업 폴더 `D:/ticketpass-lane2`, 가지 `feature/lane2-BAT-172`, 출발 `develop` `c540446e7`. 계획 담당 `ses_pending_plan_bat172`(deepseek-v4.1-flash), 2026-11-20. 제품·시험 코드는 쓰지 않았고 빌드·브라우저 시험을 새로 돌리지 않았다. 읽은 것: `docs/BUILD_ORDER.md` 95·463행, `docs/review/ledger-notes.md` 113행, `docs/review/plans/BAT-171.md` §1 F8·§2·'정할 것' 1·'F8 멈춤', `tools/web-checks/csp/web.spec.mjs` 315~339행, `tools/web-checks/playwright.csp.config.mjs`, `tools/web-checks/csp/pages.mjs`, `apps/web/next.config.ts` 16·68행, `apps/web/src/_app/layouts/RootDocument.tsx`, `apps/web/server/csp-hash-server.mjs`, `apps/web/scripts/hide-source-maps.mjs`, `apps/web/scripts/build-color-mode.mjs`, `apps/web/src/_app/theme/color-mode.test.mjs`, `docs/frontend.md` §5.14.1·§5.14.2·§6.3, `docs/security/asvs/frontend.md` 3.6.1, `docs/architecture.md` §8.6, ADR-0193·ADR-0283, `docs/PROGRESS.md` OPEN[51]. 26건 분류는 BAT-171 2차 CI(실행 44361082574) 기록과 이 폴더의 기존 운영 빌드 산출물(`apps/web/.next/server/app/search.html`, `apps/web/.next/server/subresource-integrity-manifest.json`)을 읽어 세웠다.
- **등급**: B(`docs/BUILD_ORDER.md:95`). 돈·좌석 홀드·대기 순번의 핵심 로직을 바꾸지 않는다. CSP 시험과 루트 문서의 스크립트 태그 하나, 빌드 보조 스크립트만 바꾼다. WBS 0.25일.
- **차례**: 정방향(`Batch-Order: impl-first`, ADR-0281 결정 5, `docs/architecture.md` §8.6 '정방향 묶음'). **선행: OPEN[51] 결정.** 계획 → (결정 뒤 정본·ADR 먼저) → 구현 → 독립 시험(구현 전 트리에서 실패 확인) → 리뷰 → 검증 → 기록. B 묶음 짧은 고리(ADR-0283 결정 2)라 리뷰 반영 계획 커밋을 따로 두지 않고, 다시 리뷰 대신 검증 담당이 고친 곳을 본다.
- 이 파일은 역할마다 자기 절만 쓴다: 계획(아래 '계획'·'정할 것'), 실패 확인·시험 결과(시험), 시험 이의(구현), 리뷰, 검증, 담당 표·기록(감독). 검토 기록이고 규범이 아니다. 정본과 다르면 정본이 이긴다.

## 감독에게

1. **OPEN[51]이 이 묶음의 문이다.** 소유자가 (가)(시험 범위를 좁힌다)를 고르면 아래 계획대로 0.25일 안에 끝낼 수 있다. (나)(실행 중 덩어리에도 브라우저 해시를 단다)나 (다)(건너뛰기를 유지한다)면 이 묶음은 멈추고 HOT-391을 체크하지 않는다.
2. **(가)의 범위를 한 가지 더 좁히자고 제안한다.** OPEN[51] (가)는 "HTML 응답에 실린 같은 출처 태그는 모두 integrity"라고 적었다. 그런데 Next.js는 클라이언트 참조·화면 데이터 덩어리를 HTML에 `<script src async>`로 넣으면서 `integrity`를 달지 않는다(아래 2의 증거). 이 태그들까지 브라우저 `integrity`를 강제하려면 요청 화면의 HTML을 앞 서버가 모아 고치거나 스트리밍으로 다시 써야 해서, 0.25일이 아니라 0.5~1일+ 성능 측정이 든다. 그래서 **추천은 ① 우리 문서가 직접 싣는 같은 출처 스크립트(지금은 `/seed-color-mode.js` 하나)에는 `integrity`를 달고 ② `/_next/static/` 덩어리는 같은 빌드의 SRI 표와 바이트를 시험으로 대조한다**이다. 이 좁힘을 소유자가 승인해야 ADR 0326을 쓸 수 있다.
3. **제품 변경은 `/seed-color-mode.js` 하나다.** Next.js 판을 고치거나 앞 서버에 HTML 다시 쓰기를 넣지 않는다. CSP 정책(`script-src`)·nonce·응답 때 인라인 해시는 그대로다.
4. **새 ADR 0326**(현재 마지막 0320)로 ADR-0193 결정 6을 보충한다. 제목·번호가 겹치면 감독이 다음 빈 번호로 바꾼다.
5. **정본을 아직 쓰지 않았다.** 방향을 바꾸는 결정(OPEN[51])이라 계획 커밋에는 BUILD_ORDER 행과 이 계획만 넣었다. 결정이 오면 계획 담당이 ADR 0326과 `docs/frontend.md`·ASVS 문장을 먼저 쓰는 커밋을 하나 더하고 구현을 시작한다.
6. **0.25일은 빠듯하다.** 제품 3파일(빌드 보조 1·생성 상수 1·루트 문서 1), 시험 3파일, 문서(ADR·`frontend.md` 3자리·ASVS), 장부 정리 하나다. `web / budgets`의 CSP 단계가 세 엔진이라 CI 시간이 늘고, 바이트 대조로 시험이 몇 초 길어진다. 0.25일을 넘길 것 같으면 구현 담당이 멈추고 감독에게 올린다.

### 2. 지금 상태와 원인

- **실패하는 시험**: `tools/web-checks/csp/web.spec.mjs:319~337`. 세 화면 `/events/<DETAIL_EVENT>`·`/queue/<EVENT>/verify`·`/booking/<EVENT>/checkout`, 세 엔진(Chromium·WebKit·Firefox). `page.goto(..., waitUntil: 'networkidle')` 뒤 `document.querySelectorAll('script[src]')`를 모두 세고, 같은 출처 태그에 `integrity`가 없으면 `integrity 없는 같은 출처 스크립트`로 실패한다.
- **건너뛰기 지점**: 같은 파일 322행 `test.skip(true, 'BAT-172(OPEN[51], HOT-391): 같은 출처 외부 스크립트 SRI')`. 시험은 지우지 않았고 까닭이 붙어 있다.
- **BAT-171 2차 CI(실행 44361082574)의 수**: 공연 상세 24·추가 검증 16·결제 14건, 세 엔진이 같다. 세 화면 공통 10건은 `/seed-color-mode.js` 1 + `_next/static/chunks` 9다.
- **이 폴더의 운영 빌드 산출물로 본 증거**: `apps/web/.next/server/app/search.html`에는 같은 출처 `script[src]` 12개 가운데 5개 `/_next/static/chunks/*.js`와 `/seed-color-mode.js`에 `integrity`가 없고, 그 5개 모두 `server/subresource-integrity-manifest.json`에 `sha256-…` 값이 있다. `apps/web/.next/server/app/index.html`은 6개 + `/seed-color-mode.js`다. 즉 Next.js는 SRI 표에 해시를 만들어 두고도 일부 태그에는 달지 않는다.
- **Next.js 코드에서 본 자리**: `next/dist/compiled/next-server/app-page.runtime.prod.js`의 `rg(...)`(클라이언트 참조·`injectedJS`)가 `<script src async nonce>`를 만들면서 `integrity`를 넣지 않는다. `getRequiredScripts`(`rn`)는 루트 시작 파일(`rootMainFiles`)에만 SRI 표의 `integrity`를 단다. 그래서 시작 덩어리 4개는 통과하고, 화면별 클라이언트 덩어리·실행 중 `import()` 덩어리가 실패한다.
- **인라인·서드파티·모의는 26건이 아니다**: Turbopack 시작 코드와 `self.__next_f.push` 화면 데이터는 `src`가 없어 시험이 세지 않고, 요청 화면은 nonce, 캐시 화면은 응답 때 인라인 해시가 맡는다(ADR-0193). Cloudflare Turnstile·토스페이먼츠·포트원은 다른 출처라 `foreign` 검사로만 보고 §5.14.2 표에 결정이 있다. `stubFanApi`는 팬 API에 503으로 답할 뿐 스크립트를 넣지 않는다.

### 13. 범위 밖

- **Next.js 판 올림·패치**: 지금 판(16.4.6) 그대로. `rg(...)`에 `integrity`를 넣는 패치는 다음 판 올림 뒤에도 별도 결정이다.
- **요청 화면 HTML 재작성**: 앞 서버가 요청 화면 HTML을 모아 `integrity`를 채우는 일은 성능(TTFB·스트리밍)·2MB 상한·HTML 파싱 위험이 있어 별도 묶음이다. 소유자가 모든 HTML 태그의 브라우저 SRI를 요구하면 그 묶음을 계획한다.
- **실행 중 `import()` 덩어리에 브라우저 SRI**: Next 실행 코드·화면 데이터 직렬화를 고쳐야 해서 이 묶음에서 하지 않는다.
- **서드파티 SRI**: Turnstile·토스·포트원은 버전 없는 주소라 붙일 수 없다. §5.14.2 표의 결정을 그대로 둔다.
- **CSP 정책·nonce·인라인 해시**: `script-src`, `proxy.ts`, `csp-hash-server.mjs`를 바꾸지 않는다.
- **다른 CSP 시험**: FE-T35·FE-T30·13.4.7, 첫 JS·Lighthouse. `web / budgets`의 다른 판정도 그대로다.
- **장부 범위 넓히기**: `frontend:v5.0.0-3.6.1` 밖의 ASVS 행은 이 묶음이 닫지 않는다.
- **브라우저 확인**: 화면이 바뀌지 않는다(스크립트 태그 속성 하나). §8.6 9단계를 하지 않는다.

## 정할 것

1. **OPEN[51] (가)와 위 2의 좁힘 승인**: 이것이 이 묶음의 선행 조건이다. 승인 없이는 ADR 0326을 쓰지 않고 구현도 시작하지 않는다.
2. **(가)를 "모든 HTML 태그에 브라우저 integrity"로 넓힐지**: 넓히면 앞 서버 HTML 재작성이 필요해 0.25일로 끝나지 않는다. 별도 묶음과 성능 측정을 추천한다.
3. **ADR 0326 번호·제목**: 0320 다음 번호. 겹치면 감독이 바꾼다.
4. **`seed-color-mode-sri.ts` 생성 방식**: 빌드 보조 스크립트가 쓰는 생성 파일(추천). 런타임에 파일을 읽는 방식은 standalone 산출물에 `public/`이 없을 수 있어 쓰지 않는다.
5. **`web / reflow` 회귀 포함**: 속성 하나라 영향은 없지만, 13분짜리 잡을 게이트에 넣을지 감독이 정한다. 넣지 않으면 `web / budgets`와 단위 시험만 본다.
6. **바이트 대조 범위**: `/_next/` 고유 URL마다 한 번씩 받아 센다(추천, 26개 안쪽). 시험 시간이 60초를 넘으면 표 키 대조만 남기고 바이트 대조를 줄일지 감독이 정한다. 줄이면 V172-06이 잡히지 않는다.

## 감독 결정(2026-11-20)

1. **OPEN[51] (가)를 좁혀 승인한다.** 우리 문서가 직접 싣는 같은 출처 스크립트(`/seed-color-mode.js`)는 `integrity` 필수, Next.js `/_next/static/` 덩어리는 같은 빌드 SRI 표와 받은 바이트 SHA-256 대조로 본다. 모든 HTML 태그에 브라우저 `integrity`를 강제하는 안은 별도 묶음으로 미룬다.
2. **ADR은 0326**으로 한다. 0321~0323은 BAT-045, 0324는 그 경보 자리, 0325는 BAT-086이 쓴다.
3. **0.25일을 지킨다.** 넘길 것 같으면 구현 담당이 멈추고 보고한다.
4. **`web / reflow`는 게이트에 넣지 않는다.** `web / budgets`·단위·CSP 시험만 본다.
5. **바이트 대조는 `/_next/` 고유 URL마다 한 번(26개 안쪽)** 한다. 60초를 넘으면 SRI 표 키 대조만 남기고, 그 한계를 기록한다(V172-06이 잡히지 않는다).
6. `seed-color-mode-sri.ts`는 빌드 보조 스크립트가 쓰는 생성 파일로 한다(런타임 파일 읽기 금지).
