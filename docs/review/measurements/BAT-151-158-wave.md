## 4. 4관점 리뷰

- **높음 1**: 겹침 검사가 좌석 간격 상한 없이 같은 좌표를 짝지어 견줘 비정상 배치에서 O(n²)이 될 수 있었다. R-490에서 간격 1,000cm 상한·같은 좌표 묶음·비교 100만 회 상한으로 고쳤다.
- **높음 2**: SCR-024 라이브 모드가 `parseSalePolicy`에 규칙 배열이 아니라 `{ rules }`를 넘겨 폼 적용·시뮬레이션이 늘 실패했다. 브라우저 확인에서 찾아 R-492에서 고쳤다.
- **중간(고침)**: 명단 업로드 뒤 서버가 정한 명단 키가 폼에 반영되지 않던 문제(R-491), 오류 낭독 `role="alert"`·템플릿 목록 `role="group"`(R-491), `docs/data.md`·schema가 없는 템플릿 DB 칸을 정본처럼 적던 문제(R-491), 409 `existingSeatCount` 시험 누락(R-489).
- **중간(남김)**: 에디터 요약 줄의 경고 계산이 드래그 중 문서가 바뀔 때마다 메인 스레드에서 돈다. FE-T33(LCH-200) 성능 측정 때 Worker `check`로 옮긴다.
- **낮음(남김)**: 템플릿 변형 값은 계약대로 검증만 하고 정적 도형에는 아직 반영하지 않는다. core-svc 운영 이미지에 `seed/seatmap-templates/`를 넣는 일은 배포 단계다.
- 보안·권한·개인정보: 템플릿 만들기는 저장과 같은 테넌트·역할·잠금 검사를 쓰고, 명단 사본은 계정 ID만 `destroy_due_at`까지 두며 로그에 남기지 않는다. 새 문제는 찾지 못했다.

## 5. 남은 문제

1. 실제 GitHub Actions 전체 매트릭스는 푸시 금지로 돌리지 못했다. 로컬 동등 게이트는 통과했다.
2. 병렬 `turbo test`에서 trust-svc·platform 시험이 시간 초과로 한 번씩 실패했다(각각 단독 재실행·순차 전체 실행은 통과). CI 러너에서 같은 흔들림이 나면 시험 시간 한도를 다시 본다.
3. 에디터 요약 경고 계산은 FE-T33에서 Worker로 옮긴다.
4. 템플릿 변형 도형과 core-svc seed 배포 이미지 넣기는 다음 템플릿 정교화·배포 단계다.
5. `PEAKET_QUEUE_REDIS_URL`이 있는데 Redis에 붙지 못하면 core-svc가 시작하지 못한다(대기열 Redis는 보조 경로인데 카탈로그 전체가 내려간다). 주소가 없을 때만 늘 실패하는 어댑터로 떨어지는 지금 동작을, 연결 실패에도 떨어뜨릴지 다음 웨이브에서 정한다.
6. SCR-024 명단 올리기의 실제 identity 연동은 로컬 스택에 없어 성공 경로를 브라우저로 보지 못했다(통합 시험이 덮는다).
