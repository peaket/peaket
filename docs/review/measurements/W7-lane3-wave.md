# 웨이브 7 갈래 3 보고서 — 웨이브 6 남은 결함 가운데 코드 몫(W7-audit)

- **독자와 용도**: 갈래 3이 웨이브 7(2026-11-16)에 한 일, 역할 나누기(ADR-0270)를 지켰는지, 게이트와 남은 위험을 적는다. 결함 하나하나의 계획·시험·리뷰·검증은 [계획 파일](../plans/W7-audit.md)이 정본이다.
- **가지**: `wave/lane3-w7`(기준 `origin/develop`, 합치기 직전에 다시 올림). 감독은 갈래 3 데스크톱 세션이고, 계획·시험·구현·리뷰·검증을 하위 에이전트로 따로 띄웠다. 모든 담당 모델은 Opus 5.5(`claude-opus-5-5`)다. 리뷰·검증은 구현과 같은 모델의 새 맥락이다(OPEN[40] 결정 전, ADR-0270 결정 6).

## 1. 한 일

| 결함 | 고친 것 | 남은 것 |
| --- | --- | --- |
| A2-17 예매자 명단 짧은 페이지 절단 | 명단 원천 포트를 `{items, nextCursor}` 페이지로 바꾸고 `nextCursor`가 null일 때만 끝으로 본다(짧은 페이지·0건 페이지도 계속). 같은 커서 되풀이·빈 문자열 커서·모양 틀린 응답은 503 `dependency-unavailable`(오류 목록 제목, `Retry-After` 30초 [가정], openapi 두 연산에 503). 부르는 곳 없던 `DrizzleMerchOrderStore`의 `limit*10`·`slice` 명단 메서드를 지웠다 | 내려받기 전체 시간 한도·요청 끊김 취소(K7), 쪽 수 상한(R7) |
| A2-19 명단 조회 접속기록 누락 | 명단 보기도 접속기록(`action LIST`, 조건 `limit`·`cursor`, 보인 행 수)을 남기고, 행위자가 없거나 기록이 실패하면 명단을 주지 않는다(fail-closed). 내려받기 이력과 접속기록을 한 트랜잭션에 쓴다. 보존 끝은 달력으로 2년. 접속지 정보는 요청의 클라이언트 IP 원문(`source_ip inet`, 리뷰 R2) — 응답·이력·로그에 싣지 않는다. 마이그레이션 core 0021(칸만 더하고 검사는 `NOT VALID`, 배포 중·되돌림에 안전, 리뷰 K1·K6) | 접속지 NOT NULL 좁히기는 다음 출시(넓히기/좁히기, devops §7.1). 저장소·해시 체인·FR-064 점검은 OPEN[43] |
| R-628 회귀 시험 공백 | `InternalToken401Guard`의 운영 무토큰 시작 차단(`onModuleInit`)과 상수시간 비교 시험(SEC-06R ①~⑤). 처음부터 통과(이미 있는 동작)였고 검증 담당의 틀린 구현으로 실패를 봤다 | 길이가 다르면 바로 끝나는 비교(S4, 낮음) |
| COV2-06 탈퇴 뒤 후기 익명화 연결 | core-svc가 `identity.accounts-withdrawn`을 `peaket.core-svc.<환경>` 그룹으로 받아 계정·주문 참조를 끊는다(pid는 읽지도 남기지도 않음, 읽지 못한 사건은 pid 없이 `held_event`에 보류). 운영에서 브로커 설정이 없으면 시작하지 않는다. 시험 담당이 찾은 계획 빈칸으로 `core_app`에 후기·보류 표 쓰기 권한이 없던 결함(지금 운영의 후기 쓰기·신고·정비 일도 실패)을 core 0022(코드가 쓰는 칸·동작만)로 고쳤다. `review(account_id)` 색인과 소비자 전용 `core_app` 풀(최대 2, 리뷰 K2) | 파기 vs 익명화는 OPEN[42], 탈퇴 직후 15분 창은 OPEN[44] |

- BAT-045(BOT-132·BOT-140·BOT-152·BOT-161)는 건너뛰었다. 선행이 develop에 없다: BOT-132는 HOT-400(저장소에 Gateway·HTTPRoute 매니페스트 없음), BOT-140은 AWS 계정·HOT-400·OPS-260, BOT-152는 OPS-260과 관리 계정 초대 수락 경로(wbs 0.2.3, docs/features/identity.md §13 대기), BOT-161은 BAS-140과 ZAP 이미지 허락(OPEN[46]).
- OPEN 번호(42~46)는 메인 감독 세션이 PROGRESS '미해결'에 넣었다.

- 차례: 계획 → 시험(실패 확인) → 계획 보충(시험이 찾은 빈칸, 첫 구현 전) → 구현 → 대조 리뷰 → 리뷰 반영(시험 → 구현, 지적마다 `Finding:`) → 다시 보기 → 검증 → 웨이브 끝 관점 리뷰 → 리뷰 반영 → 다시 보기 → 검증 2단계 → 기록.
- 손으로 본 것과 `node tools/ci/roles-check.mjs --base origin/develop --head HEAD`(develop R-643에서 들어옴): 합치기 직전 결과는 커밋 본문에 적는다. 중간에 걸린 것 둘을 고쳤다. ① 구현 뒤 계획 보충 커밋 둘에 단 `Finding:` 꼬리말(규칙은 review-fix에만) — 메인 감독 결정으로 두 커밋 메시지만 고쳐 본문 '고친 지적'으로 옮겼다(트리는 그대로, 고치기 전후 끝 커밋의 차이 없음 확인). ② 계획 커밋에 섞인 api-client 생성물 — 계획 담당이 자기 커밋에서 빼고 구현 담당이 다시 만들었다.
- 같은 지적 R2에 `Fix-By: test`가 구현 뒤 한 번 더 있다(구현 담당의 시험 이의를 시험 담당이 받아들여 시험 도우미가 접속지를 버리던 것을 고침).
