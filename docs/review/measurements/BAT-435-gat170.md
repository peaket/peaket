### 4관점 리뷰에서 고친 것

1. **높음 — 파트너 배치의 회차 소유 확인**: 파트너가 자기 기기를 다른 파트너의 회차에 배치할 수 있었다. core-svc 판매 설정 사본의 `promoterId`를 `ScannerEventPolicy`에 실어 파트너 경로에서 호출자 테넌트와 대조하고, 정책을 모르면 503으로 닫는다. `scanner-shift-http.test.ts`에 다른 파트너 회차 403 시험을 더했다.
2. **중간 — 기기 전용 스캔 업로드의 회차 묶기**: 스태프 세션이 없을 때 아무 회차나 올릴 수 있었다. 그 기기가 그 회차에 배치된 적이 있어야 받도록 `ScannerGate`에 배치 확인을 더했다(배치 없으면 403). 시험을 더했다.
3. **중간 — live 모드 무한 로딩**: IndexedDB 토큰 읽기가 멈추면 화면이 계속 '준비 중'에 머물렀다. 2.5초 뒤 로그인 안내 오류로 닫는 시간 한도를 더했다.
4. **중간 — test-int 누락**: 새 표·준비 보고·IP 제한·기기 인증만 스캔·세션 종료 Outbox를 실제 PostgreSQL·Valkey로 보는 시험을 더했다.
5. **중간 — `SESSION_TERMINATED` 변경분**: identity가 세션을 끝내도 ticket-svc `scanner_change`에 `SESSION_TERMINATED`를 적지 않는다. 다른 스캐너의 변경분으로는 세션 종료를 알 수 없다. identity→ticket 내부 gRPC가 없어 이번에는 남은 막힘으로 적었다.
6. **낮음 — `x-forwarded-for` 신뢰**: 등록 IP 제한은 게이트웨이가 출발지 IP로 덮어쓴 첫 값을 쓴다는 전제다. 게이트웨이 설정은 이 저장소 밖이라 문서로 남겼다.
7. **낮음 — 등록 코드 재발급 경합**: 같은 기기의 두 재발급이 겹치면 옛 코드 키가 남을 수 있다. 관리자 경로의 드문 경합이라 후속으로 적었다.

## 4. 남은 막힘

1. **mTLS 선택지**: 관리형 Android 기기·사설 CA·`AutoSelectCertificateForUrls`·`cnf.x5t#S256`·`mtls_authenticated` 정책·선택 PoC(§6.1 O-T36)가 배포 환경에 없어 구현하지 않았다. 기본안(기기 키 + DPoP)만 동작한다.
2. **ops-svc 이관**: ops-svc에 스캐너 기기 모듈이 없고, ticket-svc에 `ScannerDeviceService` gRPC 서버가 없다. 현재 `/v1/ops/scanner-devices*`는 ticket-svc가 직접 받는다. 옮기려면 (a) ticket-svc `ScannerDeviceService` gRPC 서버(List·Register·Revoke·ReissueEnrollmentCode), (b) ops-svc HTTP 컨트롤러·감사 기록·gRPC 클라이언트, (c) 게이트웨이 경로를 ops-svc로 바꾸는 배포 변경이 함께 필요하다. 이번에는 경계만 문서화했다.
3. **SCR-036 로그인 화면**: scanner 앱은 스태프 토큰을 IndexedDB/세션 저장소에서 읽는다. 기기 승인 로그인 화면(SCR-036)이 그 토큰을 저장하는 연결은 아직 없다. 실제 연결은 `?live=1`과 미리 저장한 토큰으로 확인할 수 있고, 화면 로그인 흐름은 후속이다.
4. **회차 이름**: `GET /v1/scanner/shift`는 회차 ID만 준다. SCR-033은 회차 공개 요약(`GET /v1/events/{eventId}`)을 아직 부르지 않아 화면에 `회차 <앞 8자>`로 보인다. 공연명 연결은 후속이다.
5. **O-T20 관제 신선도 경보**: 준비 보고·package 나이는 응답에 실었지만, 2분 경보·SEV2·현장 책임자 알림은 ops-svc 관제 경보 몫이라 넣지 않았다.
6. **`SESSION_TERMINATED` 변경분**: identity 세션 종료를 ticket-svc 변경분으로 전달하는 내부 경로가 없다.
7. **파트너 배치의 core-svc 의존**: 파트너 배치는 core-svc 판매 설정 사본(`PEAKET_CORE_HTTP_URL`)이 없으면 503으로 닫는다. 근무 준비는 창을 비우고 계속 동작한다.
