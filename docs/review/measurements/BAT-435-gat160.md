## 1. 구현 범위

### ticket-svc

- scanner package·changes에 `versionVector` 추가:
  - `eventId`, `seq`(전체 마지막 일련번호), `ticketSeq`(TICKET_STATUS), `keySeq`(KEY_REGISTERED·KEY_REVOKED), `policySeq`(POLICY), `placementSeq`(PLACEMENT), `flagSeq`(FLAG), `issuedAt`, `maxOfflineMs`.
  - package는 REPEATABLE READ 스냅샷 안에서 `scanner_change` 종류별 `max(seq)`를 함께 읽는다.
  - changes도 같은 벡터를 주며, `nowMs`는 생략하면 현재 시각을 쓴다.
- `maxOfflineMs` 기본 24시간 [가정], `PEAKET_SCANNER_MAX_OFFLINE_MS`로 바꾼다.
- 스캔 업로드의 `versionVector`를 검사한다. 회차가 다르거나 모양이 틀리면 400이다.
- `issuedAt`이 허용 시간을 넘긴 기록은 버리지 않고 `STALE_VERSION` 이상 표시를 만들며, 응답에 `resyncRequired`·`staleIds`를 싣는다.
- 마이그레이션 `0004_scanner_version_vector.sql`:
  - `scanner_change(event_id, kind, seq desc)` 인덱스.
  - `scan_event.flag`·`gate_flag.kind` CHECK에 `STALE_VERSION` 추가.
- OpenAPI에 `ScannerVersionVector`·`ScannerPackage.versionVector`·`ScannerChanges.versionVector`·`ScanEvent.versionVector`·`GateFlag.kind` `STALE_VERSION`·스캔 응답 `resyncRequired`/`staleIds`를 더하고 contracts/api-client를 다시 만들었다.

### 클라이언트

- `apps/scanner/src/storage/version-vector.ts`:
  - 벡터 저장·불러오기(깨진 값은 버린다).
  - `compareVersionVectors`(same/ahead/behind/diverged).
  - `isSnapshotStale`: 받은 시각 또는 `issuedAt`이 `maxOfflineMs`를 넘겼는가. 경계값(같음)은 신선하다.
  - `needsResync`: 낡음·서버가 뒤처짐·갈라짐이면 전체 재동기화, 서버가 앞서면 변경분만 받는다.
- `apps/web` 월렛 `WalletMeta.versionVector`와 `isWalletSnapshotStale`을 같은 규칙으로 둔다.

## 5. 4관점 리뷰

- **높음 0.**
- **중간 4(고침 2, 문서화·후속 2).**
  1. **고침**: changes의 `lastSeq`와 종류별 max를 서로 다른 읽기로 구해 경합 때 벡터가 어긋날 수 있었다. REPEATABLE READ 읽기 트랜잭션 하나로 묶었다.
  2. **고침**: 클라이언트 `loadVersionVector`가 `issuedAt` 문자열 모양만 보고 날짜인지 확인하지 않았다. `Date.parse` 검증을 더했다.
  3. 서버의 `STALE_VERSION` 판정은 클라이언트가 보낸 `versionVector.issuedAt`을 믿는 부분이 있다. 악의적·버그 클라이언트는 최신 시각을 보내 표시를 피할 수 있다. 실제 차단은 클라이언트 신선도 규칙이 하고, 서버 표시는 보조 지표다. 후속으로 서버가 `scannedAtDevice`·`knownSeq`와 현재 seq의 격차를 함께 본다.
  4. SCR-033·SCR-035가 아직 목업이라 저장한 벡터를 실제 스캔 화면이 쓰지 않는다. GAT-170 잔여에서 연결한다.
- 낮음: 기기 시계가 틀리면 `syncedAt` 기준 신선도가 과소·과대 판정될 수 있다(issuedAt 보조), `STALE_VERSION`은 벡터를 보내는 새 클라이언트에만 붙는다(옛 클라이언트 호환), O-T20 관제 경보는 아직 없다.
