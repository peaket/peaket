## 2. S-T13 — 버전 갭 자가 치유 3,000번

시험: `[ASVS v5.0.0-4.4.1] S-T13 3,000번 버전 갭에서 30초 안에 그 구역 스냅샷으로 회복하고 실패 0번이다`(`packages/seatmap/test/s-t13-gap.test.ts`).
명령: `pnpm --filter @peaket/seatmap exec vitest run test/s-t13-gap.test.ts --reporter=verbose`

| 값 | 측정 | 판정 기준 |
| --- | --- | --- |
| 갭 횟수 | 3,000 | 3,000번 이상 |
| 실패 | 0 | 0번 |
| 가장 느린 회복 | 2,650ms | 30,000ms 이하 |
| 503 주입 | 21번(149번에 1번) | 복구 경로 장애 포함 |
| 응답 지연 주입 | 150~450ms(회차마다) | — |
| 정확 이항 단측 95% 상한 | **0.0998%** | 0.0999% 이하 |
| 스냅샷 요청 | 3,021번(갭 3,000 + 503 재시도 21) | 갭마다 한 번, 같은 구역 동시 요청 없음 |

- 시험은 실제 `createSeatConnection`+`createDeltaSync`+`SeatMapEngine`을 가짜 시계·소켓·스냅샷으로 돌린다. 갭은 `version=current+2`인 델타를 클라이언트 경계에서 떨어뜨린 것과 같다.
- 실패가 0이므로 정확 이항 상한은 `1 − 0.05^(1/3,000) = 0.0998%`다. 시험은 근사를 쓰지 않고 0.000999와 견준다.
- **한계**: 실제 `tc netem` 망 드롭이 아니다. 클라이언트 경계 시뮬레이션이며 실제 망 드롭은 HOT-460 측정 창 몫이다(감독 결정 2).

## 3. RV-01·RV-05 — 5초 되풀이와 4,999ms 경계

### 3.1 RV-01: 5초마다 전체 스냅샷이 세 번 이상 도는가

- 단위 시험 `[FE-T11] 전체 보기는 5초마다 전체 스냅샷을 다시 받는다`(`packages/seatmap/test/stream-worker.test.ts`)가 **처음 + 5초 + 10초 + 15초**를 세어 `기준 +3`을 단언한다. 통과.
- 검증용 일회용 가짜 시계 프로브(커밋하지 않고 지움)로 같은 경계를 다시 쟀다:

| 시각 | 전체 스냅샷 누적 | 기대 |
| --- | --- | --- |
| 4,999ms | 기준 +0 | 0 |
| 5,000ms | 기준 +1 | 1 |
| 10,000ms | 기준 +2 | 2 |
| 15,000ms | 기준 +3 | 3 |

- 브라우저 시험은 축소 뒤 5초에 한 번만 보고 10초를 기다리지 않는다(계획 T10의 '한 번 이상' 단언). 5초 되풀이 자체는 단위 시험이 고정한다.

### 3.2 RV-05: 4,999ms 경계의 충실도

- 브라우저 시험은 축소 시각 `fitAt` 뒤 **4,999ms까지 기다린 뒤**, `at < fitAt + 4,999`인 전체 스냅샷이 0인지 보고, 첫 전체 스냅샷이 `fitAt + 4,900` 이상인지 본다. 이번 실행은 4,999ms 이전 전체 스냅샷 0으로 통과했다.
- 정확한 4,999/5,000 경계는 위 가짜 시계 프로브로 확인했다. 구현은 `SNAPSHOT_REFRESH_MS=5_000`으로만 타이머를 잡는다.
- **남은 빈틈**: 브라우저 시험은 1ms 해상도를 네트워크 너머로 재지 못하고, 필터가 `< 4,999`라 정확히 4,999ms에 도착한 요청은 잡지 않는다. 계획 RV-05가 요청한 **가짜 시계 단위 시험(4,999에 0·5,000에 1)**은 저장소 시험으로 들어가지 않았다. 이번 검증은 일회용 프로브로만 확인했으므로, 상시 회귀는 아직 아니다. (남은 정리 RV-05)

## 4. S-T21·S-T31 ⑥ — 5만 석 화면 시나리오

시험: `cd tools/web-checks && pnpm run seats` (3/3 통과, 44.1초, Chromium 1엔진).
측정마다 같은 시나리오를 새로 돈다: 전체 보기 → 0구역 확대(1,000ms 머묾) → 델타 100번 → 30번 끌어 1구역으로 이동 → 전체 보기로 축소 → 5초 뒤 → dispose.

| 값 | 1회차 | 2회차 | 3회차 | 판정 기준 |
| --- | --- | --- | --- | --- |
| p99(표본 100) | 20.1ms | 20.0ms | 44.6ms | 300ms 이하 |
| Long Task | 0 | 0 | 0 | 0 |
| 전체 보기 구독 | [] | [] | [] | 0개 |
| 확대 A 구독 | [0] | [0] | [0] | 1개 |
| 이동 B 구독 | [1] | [1] | [1] | 1개(A 빠짐) |
| 축소 뒤 구독 | [] | [] | [] | 0개 |
| 최대 구독 | 1 | 1 | 1 | 16개 이하 |
| 서버가 닫은 횟수 | 0 | 0 | 0 | 4403·4429·1013·1009 0 |
| `TimeSync` | 1 | 1 | 1 | 연결당 1(60초마다) |
| `BatchInterval` | 100만 | 100만 | 100만 | 100(정상) |
| 구역 스냅샷 | [0,1] | [0,1] | [0,1] | 정상 경로 재요청 0 |
| 전체 스냅샷 | 2(처음+축소 5초 뒤 1) | 같음 | 같음 | 5초마다 |
| 구독 집합 기록 | `[[0],[1],[]]` | 같음 | 같음 | 아래 참고 |

- **구독 집합 기록의 흔들림**: 주입 전 첫 실행(41.1초)은 `[[0],[],[1],[]]`로 A→B 사이에 빈 집합이 한 번 있었고, 최종 실행(44.1초)은 `[[0],[1],[]]`로 없었다. 좌석 화면을 30번 끌어 옮기는 동안 두 구역이 모두 화면 폭 1/3 미만인 순간이 생기면 빈 집합이 나갈 수 있다. 정본 S-T21의 '보이는 구역만 구독·축소하면 해제'와 상한에는 맞지만, 계획 T9가 그린 'A에서 B로 한 번에'와 다를 수 있고 시험은 중간 빈 집합을 단언하지 않는다.
- **전체 보기 5초**: 축소 뒤 4,999ms 안에는 전체 스냅샷이 0, 5,000ms 뒤에 1. 브라우저 시험은 `firstFullAfterFitMs >= 4,900`만 단언한다. 5초 되풀이는 §3.1의 단위 시험이 본다.
- **닫힘**: 화면을 떠날 때(`dispose`) 1000으로 닫는 것은 정상이고, 서버가 4403·4429·1013·1009로 닫은 적은 0이다.
- **`TimeSync`**: 연결 직후 1번, 다음은 60초 뒤라 41~44초 시나리오에서는 1번이다. 시험은 간격이 1,000ms 이상인지만 본다.
- **한계**: p99는 Worker가 `metrics.deltaE2eMs`로 알린 **그리기 명령 직전까지** 값이다. 화면 합성(컴포지터) 뒤 픽셀을 잰 값이 아니고, 하드웨어·GPU·다른 탭의 영향을 받는다. 5만 석 좌석맵은 운영 편집기 산출물이 아니라 `layout.mjs`가 만든 같은 크기 파일이다. 화면은 제품 `SeatsLive`가 아니라 같은 부품을 쓰는 시험 페이지다. Chromium 1엔진뿐이고 WebKit·Firefox·iOS 실기기는 범위 밖이다.
- **이전 실행**: 주입 전 첫 실행은 p99 14.3~36.6ms(41.1초), 최종 실행은 20.0~44.6ms(44.1초)였다. 두 실행 모두 판정 기준(300ms) 안이다.

## 5. 한계와 남은 정리

1. **대역**: 서버는 Docker 없는 realtime-gw 대역이다. 바이트·하위 프로토콜·4429/4403은 같지만 실제 realtime-gw·Valkey·JWKS 연결이 아니다. 서버 상한·프레임·Pub/Sub은 BAT-052 시험이 본다(감독 결정 3).
2. **Chromium 1엔진**: WebKit·Firefox·iOS 실기기는 이 묶음 범위 밖이다(감독 결정 1).
3. **`tc netem` 미실시**: S-T13은 클라이언트 경계 델타 드롭 시뮬레이션이다. 실제 망 드롭은 HOT-460이다.
4. **화면 합성 뒤 픽셀 아님**: S-T21 p99는 Worker의 그리기 명령 직전 값이다.
5. **시험 페이지**: 제품 React 화면(`SeatsLive`)의 운영 빌드가 아니라 같은 `@peaket/seatmap` 부품을 쓰는 Vite 시험 페이지다. 화면이 `stream`·`connection`·배너를 실제로 잇는지는 소스 시험(T8)이 본다.
6. **RV-05 상시 회귀 없음**: 4,999/5,000 경계는 일회용 가짜 시계 프로브로만 확인했고 저장소 시험에는 없다. 브라우저 시험은 `< 4,999`까지만 본다.
7. **S-T21 중간 빈 구독이 실행에 따라 나타난다**: 첫 실행은 `[[0],[],[1],[]]`(A→B 사이 빈 집합 1번), 최종 실행은 `[[0],[1],[]]`였다. 상한·최종 상태·닫힘에는 문제가 없지만, 계획 T9의 'A에서 B로 한 번에'와 다를 수 있으므로 기록 담당·구현 담당이 판단해야 한다.
8. **S-T21 구역 상태 변화 미단언**: 시험은 5초 뒤 전체 스냅샷 **요청**을 세지만, 그 스냅샷이 구역 색을 실제로 바꿨는지는 단언하지 않는다. `applyFullSnapshot`이 받은 판을 반영하는 코드는 있으나 화면 값 변화는 이번에 재지 않았다.
9. **M8 재현 메모**: 제품 코드를 10,000ms로 바꾼 뒤 처음 돌린 `pnpm run seats`는 이미 만들어 둔 `seats/dist`(5,000ms 판)를 써서 통과했다. `seats/dist`를 지우고 다시 묶은 뒤에는 5,000ms 전체 스냅샷 시간 초과로 실패했다. 브라우저 시험은 준비 단계가 `dist`를 강제로 다시 묶지 않으므로, 변이 측정 때는 `seats/dist`를 지워야 한다.
