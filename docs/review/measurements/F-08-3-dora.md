## 1. 데이터 원천과 기준

- **기준**: 출시 전에는 운영 배포가 없으므로 `docs/devops.md` §13과 `docs/planning/02-requirements.md` NFR-023에 따라 **데모 환경 기준**으로 산출한다. 운영 배포가 시작되면 운영 기준으로 전환하되, 데모 환경 기준과 운영 기준을 한 추세선에 잇지 않는다.
- **실행 방식**: 이 동결 로컬 트랙에는 GitHub Deployment 기록이 없고, 네트워크·GitHub API(`--from-github`)를 부르지 않는다. 대신 빈 배포 기록 파일(`{"deployments":[]}`)을 만들어 `node tools/ci/dora.mjs --input <임시 파일> --week <월요일> --out <임시 폴더>`로 두 주(2026-11-16, 2026-11-23)를 실행했다.
- **빈 값 규칙**: `tools/ci/dora.mjs`와 `docs/devops.md` §13은 분모가 0이거나 표본이 없을 때 `0`으로 꾸미지 않고 `자료 없음`을 내며(`0이 아니라 자료 없음`), JSON에서는 해당 지표를 `null`로 둔다.

## 3. 추세 판단

- **추세 판단 불가**: 두 주 모두 데모 환경 GitHub Deployment 기록이 0건이고 네 지표가 모두 **자료 없음**이므로, 개선·악화 추세를 판단할 수 없다. 추세선이나 임의의 목표선을 그리지 않는다(NFR-023의 "인위적인 수치 목표 금지" 및 기록 부재 원칙).

## 4. 한계와 다음

- **현재 한계**: Argo CD 알림과 GitHub Deployment 기록이 이 동결 로컬 트랙에 연결되어 있지 않다. 2026-11-23 주는 작성일(2026-11-26) 기준 **진행 중**인 주다.
- **다음에 필요한 데이터**:
  1. Argo CD 알림 설정(`deploy/platform/argocd/notifications.yaml`)이 데모 환경(`demo/<서비스>`) 배포마다 GitHub Deployment와 `success`·`failure` 상태를 기록한다.
  2. 승격 PR 제목 규칙(`chore(promote): <환경> <태그>`)과 `hotfix/` 가지·라벨 이력을 유지해 리드타임과 재작업률을 계산할 수 있게 한다.
  3. 주간 워크플로(`.github/workflows/dora-weekly.yml`)를 실제 저장소에서 실행해 주별 산출물을 쌓는다.
  4. 출시 뒤 실제 배포 기록이 생길 때부터 새 주를 기록하며, 기록이 없던 과거 주는 소급해 채우지 않는다.
- **주장하지 않는 것**: 이 보고서는 `30,000건/초`(`30,000 RPS`), 단일 공연 `100만` 달성·외삽 통과, `K1`·`K2`·`K7` 통과 또는 DORA 지표 개선 추세를 주장하지 않는다.
