# BAT-038 결과 — 결제 접수 전용 HTTP 칸막이

- 날짜: 2026-11-13

- 장부 범위: `P-T1`, `P-T23`
- 선행: BAT-037(HOT-471, R-508). 공유 `purchase-write` 칸막이 기본 64.

## 1. K7 r1 귀속

메인 구간 번들 로그(429 전수, 성공 표본):

| 경로 | 429 | 칸막이 즉시(<10ms) | 핫풀 200~400ms | 성공 p50/p99 |

| 주문 | 544 | 535 | 9 | 394.76 / 711.38ms |
| 결제 시작 | 130 | 117 | 6 | 378.25 / 931.87ms |

- 접수 429 158 = 칸막이 즉시 106 + 핫풀·기타 52.
- 128·192는 칸막이 즉시 0이 됐지만 핫풀 429가 늘어 429 2.67%·3.47%, p99 3,831·3,977ms로 더 나빠졌다. R-508 기본값은 64로 유지한다.

## 2. 고른 수정

- 접수 경로만 `purchase-accept`라는 별도 `@Bulkhead`를 쓴다. 주문·결제 시작은 `purchase-write`(64) 그대로다.
- 접수 칸막이 기본 64, `Retry-After: 1`, `PEAKET_PURCHASE_ACCEPT_BULKHEAD_LIMIT`(1~1,024).
- 주문 폭주가 접수 몫을 먹지 않게 하는 가장 작은 수정이다.
- (나) 접수 전용 DB 풀은 r1 접수 핫풀 429가 52/9,326 = 0.56%라, (가)가 즉시 106건을 없애면 1% 아래가 될 수 있어 다음 후보로 둔다. (다) 공유 칸막이 우선순위는 더 복잡하고 풀 429를 없애지 못한다.
