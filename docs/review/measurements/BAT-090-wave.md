## 4. S-T16 ② 구매 세션 확인 1ms

하네스: `services/purchase-svc/test-int/measure-purchase-verify.int.test.ts`

3회 반복(각 5,000표본, 예열 500)의 중앙값이다. 괄호는 3회 p99 범위다.

| 경로 | 표본 | p50 | p95 | p99 | 최대 | 1ms 초과 | 판정 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 전체: Valkey HMGET + 서버 ECDH/HKDF + MAC + 일련번호 Lua | 5,000 | 2.1276ms | 6.4127ms | 9.7101ms(9.4192~9.9969) | 60.9432ms | 4,632/5,000 | **미달** |
| Redis 제외: 메모리 세션 + ECDH/HKDF + MAC + 일련번호 | 5,000 | 0.6205ms | 2.3546ms | 3.8070ms(3.6766~5.1016) | 16.7681ms | 780/5,000 | **미달** |
| MAC만: Redis·ECDH 제외 | 20,000 | 0.1700ms | 0.3663ms | 1.1281ms(1.0930~1.4999) | 24.9996ms | 219/20,000 | **미달** |

- 판정: **미달**. 3회 반복 모두에서 전체 경로 p99가 9.4ms를 넘었고, Redis를 뺀 ECDH/HKDF+MAC 경로도 p99 3.68~5.10ms로 1ms를 넘었다. MAC만 남긴 경로도 p99 1.09~1.50ms로 예산을 넘었다. 단일 실행에서 p99 0.9ms가 나온 적이 있지만, 반복하니 재현되지 않았다(로컬 PC의 GC·이벤트 루프·컨테이너 부하가 섞인다).
- 탈취 재현 경로(서명 변조·재전송·다른 세션 키)는 `test/purchase-session-theft.test.ts` 6건이 고정하며 trace-check에서 통과했다.
- 다음 수: 1ms 예산을 "검증 연산"으로 좁히더라도 MAC-only p99가 1.1ms라 추가 최적화(요청 파싱·타이밍 비교·할당 줄이기)가 필요하다. 종단은 세션 조회를 파이프라인·로컬 캐시로 줄이는 별도 작업이 필요하다. 지금은 **미달**로 남긴다.

## 5. S-T19 자동 배정 1,000건 동시

하네스: `services/purchase-svc/test-int/measure-auto-s19-s20.int.test.ts`

### 5.1 문자 그대로 1,000건 동시(5,000석, 1인 2매)

| 항목 | 값 |
| --- | --- |
| 요청 | 1,000 |
| 성공 | 0 |
| 거절 | 1,000(`STORE_UNAVAILABLE`) |
| 수동 전환 | 0 |
| 잡은 좌석·중복 | 0·0 |
| 지연 p50·p95·p99·최대 | 242.7410ms·335.2162ms·345.7102ms·348.4971ms |

- 판정: **미달(무대 한계)**. 로컬 단일 Valkey·단일 연결에서 1,000건이 한꺼번에 몰리면 좌석 Redis 호출의 기본 100ms 마감을 넘겨 전부 503이 된다. 자동 배정 로직이 중복을 만들거나 좌석을 잘못 잡은 것이 아니라, 이 무대가 그 동시성을 100ms 안에 소화하지 못한 것이다.
- 이 실행에서 완료된 Lua가 남긴 홀드는 0이었다. 다만 마감 뒤에 완료되는 Lua가 있으면 503을 받은 요청의 홀드가 남을 수 있다. 같은 멱등 키로 다시 보내면 `IDEM_REPLAY`로 같은 좌석을 재생하므로, 클라이언트는 503 뒤에도 **같은 멱등 키**로 재시도해야 한다.

### 5.2 100 동시×10묶음(같은 회차, 새 5,000석)

| 항목 | 값 |
| --- | --- |
| 요청 | 1,000 |
| 성공 | **1,000** |
| 거절 | 0 |
| 수동 전환 | **0** |
| 잡은 좌석·고유·중복 | 2,000·2,000·**0** |
| 비트 수·`auto_cur` | 2,000·1,999 |
| 지연 p50·p95·p99·최대 | 124.9451ms·194.7385ms·240.7881ms·250.5323ms |

- 판정: **통과(기능 기준)**. 같은 조건의 1,000건이 모두 자동 배정되었고, 중복 홀드와 수동 전환이 0이다. 100 동시를 10번 이어 보낸 것은 로컬 무대에서 소화 가능한 동시성으로, 1,000건 전체의 배정 규칙·커서·중복 방지를 확인하는 데 충분하다.
- 초기 측정에서 4페이지(128묶음)일 때 324~360건이 `MANUAL_SELECTION_REQUIRED`로 떨어졌다. 공유 `auto_cur`가 앞서 나가면 늦게 시작한 요청이 빈 블록을 건너뛰는 문제였다. NEXT가 공유 커서를 쓰지 않고, OK만 앞으로 쓰며, NEXT가 `max(페이지 끝, 공유 커서)`로 따라가고, 페이지를 32(1,024묶음)로 늘려 0으로 만들었다.

### 5.3 1순위 매진

| 항목 | 값 |
| --- | --- |
| 요청 | 50(1인 2매, 1순위 R 100석을 미리 채움) |
| 성공 | 50 |
| 2순위 `SECOND` | 50 |
| 잡은 좌석·고유·중복 | 100·100·0 |

- 판정: **통과**. 1순위가 매진되면 2순위 S로 넘어가고, 중복 없이 100석을 배정했다.

### 5.4 연석 부족

| 조건 | 결과 |
| --- | --- |
| 분리 미허용 | 409 `manual-selection-required`(HoldError: 희망 조건에 맞는 좌석이 없다) |
| 분리 허용 | 201 `FIRST_SPLIT`, R0002·R0004 |

- 판정: **통과**. 한 칸씩 띄운 10석에서 연석 2매는 불가능하고, 분리를 허용하면 빈 좌석을 앞에서부터 골라 2매를 잡는다.

## 8. 4관점 리뷰

- **높음 3(고침)**
  1. **Lua `keyPos` off-by-one**: 실제 Valkey에서 자동 배정 Lua가 홀드 키를 한 칸 밀어 읽어 홀드 해시가 `null`이었다. `keyPos = 11 + #flat + 1`로 고치고 실제 Valkey 5건으로 확인했다.
  2. **첫 홀드가 구매 세션을 열지 않음**: 자동 배정 공연은 스냅샷이 없어 구매 세션이 없는데, 첫 홀드에서 `openFirstUse`를 부르지 않아 인증이 막혔다. `start.ts`와 `StoredPurchaseSessions`에 첫 사용 열기를 연결하고 시험을 더했다.
  3. **공유 커서 굶주림**: NEXT가 공유 `auto_cur`를 페이지 끝으로 옮겨 동시 요청이 빈 블록을 건너뛰었다. NEXT는 공유 커서를 쓰지 않고, OK만 앞으로 쓰며, NEXT는 `max(페이지 끝, 공유 커서)`로 따라가게 고쳤다. 페이지를 32로 늘렸다.
- **중간 4(고침)**
  1. `autoCursor` 읽기의 좌석 Redis 장애가 500으로 새지 않게 `STORE_UNAVAILABLE`(503)로 전파하고 시험을 더했다.
  2. `openFirstUse`의 좌석 Redis 장애를 401로 숨기지 않고 503으로 올린다.
  3. 자동 배정 후보 캐시에 상한(8조건)을 두어 조건을 바꿔 메모리를 채우지 않게 했다.
  4. 커서 칸 이름을 등급 문자열 조합에서 멱등 지문(`autoFingerprint`)으로 바꿔 특수 문자·칸 충돌을 피했다.
- **낮음 2(남김)**
  1. 503 마감 뒤 완료된 Lua의 홀드는 남을 수 있다. 같은 멱등 키 재시도가 `IDEM_REPLAY`로 흡수하지만, 클라이언트 재시도 규약을 문서에 더 분명히 적을 필요가 있다.
  2. `s:{event:E}:auto:{tier}:{n}` Redis 후보 목록과 `s:{event:E}:auto_back:{tier}` 돌아온 좌석 우선은 LCH-080 판매 열기·해제 경로에서 붙인다.
- **보안**: 새 PII·권한 경로는 없다. 구매 세션 키 교체는 현재·옛 키를 함께 허용하고, jti를 훔쳐도 키가 없으면 MAC 불일치·재전송은 replay로 거절하는 단위 시험 6건이 고정한다.

## 9. 남은 문제

1. **S-T16 ② 1ms 미달**: 3회 반복 중앙값에서 Valkey 포함 p99 9.7101ms, Redis 제외 p99 3.807ms, MAC만 p99 1.1281ms다. 1ms 예산을 어디까지로 볼지와 무관하게 지금은 미달이다. **재개 조건**은 (1) 운영과 같은 다중 샤드·연결 풀·실기에서 다시 재고, (2) Redis 근접 측정(같은 AZ·노드, 파이프라인, 로컬 세션 캐시)으로 왕복을 줄인 뒤 같은 3경로를 다시 재고, (3) 그래도 1ms가 어려우면 1ms 예산을 '검증 연산(ECDH/HKDF+MAC)'으로 조정할지 소유자가 정한다. 정본 `docs/verification.md` §3.11.
2. **S-T19 문자 그대로 1,000건 동시 미달**: 로컬 단일 Valkey·100ms 마감에서 전부 503. 100 동시×10묶음에서는 1,000/1,000 성공·중복 0이다. 실제 1,000 동시를 판정하려면 다중 샤드·연결 풀·입장 제어가 있는 무대가 필요하다.
3. **503 뒤 부분 홀드**: 마감 뒤 완료된 Lua가 홀드를 남길 수 있다. 같은 멱등 키 재시도로 흡수되지만, 클라이언트가 새 키로 재시도하면 좌석이 묶인 채 남는다. 재시도 규약을 API 문서에 명시한다.
4. **자동 후보 목록의 Redis화**: `auto_back`·`auto:{tier}:{n}`은 LCH-080에서 붙인다.
5. **전역 ledger**: `ledger --check`는 기존 전역 빈칸(1,115)·ID만(1,120)으로 여전히 실패한다. 이 묶음 범위(`--batch BAT-090 --require`)는 통과한다.
6. **브라우저 확인**: 화면 변경이 없어 생략했다.
