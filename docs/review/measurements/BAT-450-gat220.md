## 1. 구현 범위

### identity-svc

- RFC 8628 기기 승인 시작: `POST /v1/scanner/device-authorizations`
  - 기기 키 DPoP 증명(jkt)과 스캐너 PWA Origin 확인.
  - 기기 코드 CSPRNG 256비트, 서버에는 SHA-256만 저장. 5분·1회용.
  - 사용자 확인 코드 8자(4-4, RFC 8628 §6.1 문자 집합).
  - 기기당 시간당 10회 발급 제한.
- 토큰 폴링: `POST /v1/scanner/token`
  - `authorization_pending`·`slow_down`·`access_denied`·`expired_token` 구분.
  - 승인 뒤 `typ at+jwt`·`aud scanner`·`cnf.jkt`·회차·세션을 묶은 현장 스태프 토큰. 만료는 역할 유효 끝. 역할은 토큰에 싣지 않는다(ADR-0172).
  - 토큰 발급 때 ticket-svc 기기 원장을 한 번 더 보고, 폐기 기기는 403.
- 승인 화면·승인: `POST /v1/device-approval-lookups`·`/v1/device-approvals`
  - 그 기기의 배정 파트너 회차의 유효 배정만 보인다. 파트너가 다르면 `other-partner-device`, 시간 밖이면 `outside-staff-hours`, 배정이 없으면 `staff-assignment-missing`.
  - 승인하면 같은 기기·같은 계정의 이전 스캐너 세션을 끝내고 새 세션을 만든다(교대).
  - 대리 승인은 `gate_lead` 배정만 되고 세션 역할은 `gate_staff`로 낮춘다.
  - 계정당 10분 5회 승인 시도 제한.
- `staff_assignment.promoter_id`(마이그레이션 0032)와 `scanner_session`의 기기별 활성 세션 유일 인덱스.
- `CheckScannerSession`이 유효 세션의 `last_seen_at`을 갱신한다.
- Redis 저장소: `id:devauth:*`(기기 승인), `id:devcode:*`(확인 코드 색인), `id:devrate:*`(한도), `scanner:dpop:*`(jti). 로컬·시험은 메모리.

### ticket-svc

- gRPC `ScannerDeviceLookupService.GetScannerDeviceByCredential` 서버.
  - DEVICE_KEY 지문(jkt)으로 기기 ID·상태·이름·배정 파트너를 준다.
  - 미등록·다른 자격 종류·지문 누락은 `found=false`.
- 스캐너 요청마다 `scanner_device.last_seen_at` 갱신(platform `ScannerGuard`의 touch, 실패해도 요청은 막지 않음).

### packages/platform

- `ScannerAuth` 옵션 `token: 'required' | 'none' | 'optional'`.
  - `none`: 기기 증명만 본다. 사용자 토큰을 붙이면 401.
  - `optional`: 토큰이 있으면 세션까지, 없으면 기기 증명만.
- `AuthGuard`가 기기 전용 스캐너 역할(`scanner_device`)에서 사람 신원 머리 없이 통과시키고, 판정은 `ScannerGuard`가 한다.
- 기기 찾은 뒤 `touch`(마지막 연락 시각).

### 계약·문서

- OpenAPI 문제 유형: `assignment-required`(422), `proxy-approval-forbidden`(403), `scanner-origin-forbidden`(403), `scanner-login-rate-limited`(429).
- contracts/api-client 생성물 재생성.
- `docs/data.md` `staff_assignment.promoter_id`, `docs/features/identity.md`·`offline-gate.md`, ASVS 6.3.3·8.2.2·10.3.5, BUILD_ORDER·PROGRESS·lane1·00-summary·consistency-review 갱신.

## 5. 4관점 리뷰

- **높음 0.**
- **중간 6(고침 1, 문서화·후속 5).**
  1. **고침**: 승인 저장소가 승인을 거절했을 때 이미 만든 스캐너 세션이 남을 수 있었다. `endScannerSession`으로 되돌리게 했다.
  2. `staff_assignment.promoter_id`를 파트너 초대 생성이 아직 채우지 않는다. 지금은 값이 없는 배정을 승인할 수 없다(안전한 쪽). 파트너 초대 생성(GAT-210 후속)이 채워야 한다.
  3. 같은 기기 동시 승인은 `scanner_session_device_active_key` 유니크 위반으로 500이 될 수 있다. 승인 충돌을 409/`ALREADY_HANDLED`로 바꾸는 후속이 필요하다.
  4. 승인 화면 조회도 승인 시도 한도(계정당 10분 5회)를 함께 쓴다. 화면을 여러 번 열면 승인 버튼이 잠시 막힌다. 조회와 승인 한도를 나누는 후속.
  5. `last_seen_at`을 스캐너 요청마다 갱신한다. 플랫폼 가드의 5초 세션 캐시로 완화되지만, DB 쓰기 증폭을 줄이는 묶음 갱신은 후속.
  6. 기기 폐기 때 identity `scanner_session` 행을 즉시 끝내지 않는다. 다음 스캐너 요청의 기기 상태 확인(403)으로 막지만, 행 정리는 후속.
- 낮음: 승인 화면의 오래된 배정(`promoter_id` 없음)이 `other-partner-device`로 보이는 문구, 조회/승인 감사 로그, 등록 시도 IP 제한·SEV3, mTLS 선택지.
