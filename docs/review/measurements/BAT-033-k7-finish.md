# BAT-033 K7 마무리 결과

- 날짜: 2026-11-12
- 묶음: BAT-033(HOT-467, 갈래 1, A등급), 장부 범위 `P-T1`, `P-T47`
- 선행: BAT-032(HOT-466, R-477, OPEN[38])
- 결론: **K7 결제 확정 p99(confirmMs)는 3회 모두 3초 안에 들었지만, 공식 `payment_p99_3000ms` 경로 점검은 3회 모두 미달이다. K2는 p99 50ms 안이지만 발생기 dropped_iterations가 0이 아닌 실행이 많아 A/A를 성립시키지 못했다. 홀드는 k6 p99가 50ms를 넘고 서버 `hot_path` p99는 50ms 안이다(OPEN[39]).**

- 홀드는 k6 p99 199~224ms로 50ms를 넘고, 서버 `hot_path` p99는 r6에서 9.84ms로 50ms 안이다. BAT-032의 서버 값 43.4ms보다 좋아졌다. 50ms 게이트 기준은 **OPEN[39]**로 남긴다.

- 발생기 CPU는 31~35%, 메모리는 29~32%로 자원 고갈은 아니었다. v1 합본 메모리를 1.5Gi로 낮춘 조건과 대상 상태가 원인 후보이다. 다음 측정에서는 2Gi 합본·3복제를 유지하면서 발생기 메모리를 1Gi로 맞출 수 있는 노드 여유를 먼저 확보해야 한다.

## 5. 남은 문제

1. **공식 K7 점검 미달**: `confirmMs` p99는 3초 안이지만 `payment_p99_3000ms`는 9%대로 fail. 끝 상태가 아닌 답을 줄이거나 점검 정의를 정본에서 다시 정해야 한다.
2. **K2/A/A 미완**: p99는 50ms 안이나 dropped_iterations가 0인 실행을 3회 채우지 못했다. A/A는 성립하지 않았다.
3. **OPEN[39]**: 홀드 50ms를 k6로 볼지 서버 `hot_path`로 볼지 정본 결정이 필요하다. 서버 r6 9.84ms·k6 199~224ms.
4. **K7 서버 홀드 p99**: r4·r5는 클러스터를 제거하기 전에 Prometheus 값을 수집하지 못했다. r6만 9.84ms를 남겼다.
5. 다음 웨이브는 감독이 이 결과를 보고 지시한다. 이 배치에서는 다음 웨이브를 시작하지 않는다.
