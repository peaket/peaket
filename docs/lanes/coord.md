# 전체 감독 — 바퀴 기록

- **독자와 용도**: 갈래 다섯(ADR-0286)을 맞추는 전체 감독 세션이 바퀴마다 번호 나누기, 갈래 배치, 잰 값을 적는다. 갈래 세션은 번호를 받을 때와 다른 갈래 일을 옮기고 싶을 때 이 파일을 본다. 공용 턴 규칙은 [docs/PROGRESS.md](../PROGRESS.md), 묶음 배치는 [docs/BUILD_ORDER.md](../BUILD_ORDER.md) '기능 묶음' 표가 정본이다.
- **감독이 하는 일**: 구간 마무리(SEG), 공용 기록 표 맞추기(`node tools/ci/records.mjs` → `docs(records)` 커밋), ADR·마이그레이션·OPEN 번호 나누기, 합치기 줄 지키기, 사용량 확인(주간 80% [가정]를 넘으면 갈래 4·5 멈춤), 소유자 보고. 코드와 시험은 쓰지 않는다.

## 바퀴 기록
- 첫 바퀴: 갈래 다섯이 묶음을 하나씩 합칠 때까지. 끝나면 갈래마다 벽시계·토큰·커밋 수·합치기 기다림·충돌 수를 여기에 적고, ADR-0286 결정 7대로 갈래 6(측정 창 전담)을 열지 정한다.
- 2026-11-18 23:2x 사고: 갈래 2 BAT-166 시험 담당이 Docker 잠금 `mkdir` 실패를 못 보고 시험을 돌린 뒤 갈래 5가 쥔 `D:/ticketpass-locks/docker`를 지웠다(갈래 2가 스스로 알림). 그 사이 시험은 겹쳤을 수 있어 두 갈래가 다시 돌림. 모든 갈래 하위 담당 지시문에 "mkdir 실패면 기다림, 자기 owner.txt가 든 잠금만 지움"을 넣게 함. 갈래 4도 23:20 무렵 owner.txt를 보지 않고 같은 폴더를 지웠다고 스스로 알림(그 전 23:17~23:19 시험은 잠금을 쥔 채). 23:42부터 잠금은 손 `mkdir`/`rm -rf` 대신 PC의 도우미 `bash D:/ticketpass-locks/lock.sh take|drop|who <docker|merge> <갈래-묶음>`로만 잡고 놓는다(놓기는 owner.txt 첫 줄이 같을 때만). 되돌릴 조건(충돌로 되돌린 커밋)에는 아직 걸리지 않음.
