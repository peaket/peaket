# 갈래 5 — 진행 상태

- **독자와 용도**: 갈래 5(병렬 세션)가 다음에 할 일과 진행 로그를 적는다. 공용 턴 규칙과 미해결(소유자에게 물을 것)은 [docs/PROGRESS.md](../PROGRESS.md), 단계의 차례와 체크는 [docs/BUILD_ORDER.md](../BUILD_ORDER.md) '기능 묶음' 표가 정본이다(ADR-0286).
- **맡은 일**: BUILD_ORDER '기능 단위 계획' 표의 F-07(정산·커머스·파트너), F-08(출시·측정)을 맡는다. 커머스·정산·지급·법정 조치(LCH-010~170, BAT-600~635)와 결과를 남기는 측정(측정 창 2~4)을 맡는다. 주로 고치는 곳은 굿즈·정산 쪽 서비스와 `loadtest/`다. payment-svc는 갈래 1·3도 고치므로 마이그레이션 번호는 전체 감독에게 미리 받는다.
- **측정 창**: 측정 창 묶음은 그 측정이 재는 단계가 모두 `develop`에 들어간 뒤에만 한다(ADR-0286 결정 1). 측정 창이 열리면 하던 커머스 묶음을 끝낸 다음 측정을 먼저 한다. 정밀 측정이 도는 동안 다른 갈래는 이 PC에서 시험을 돌리지 않으므로, 시작과 끝을 전체 감독에게 알린다.
- **작업 폴더**: git worktree `D:/ticketpass-lane5`(처음이면 `git worktree add`로 만든다). 기능마다 최신 `origin/develop`에서 `feature/<갈래>-<기능 ID>` 가지를 따고, 기능이 끝나면 합치기 줄(PROGRESS 턴 규칙 '갈래'의 합치는 법, ADR-0286 결정 3)로 한 번 합친다.
- **이 갈래가 고치는 기록**: 이 파일, BUILD_ORDER의 자기 줄 체크, 커밋 본문의 정합 점검 행이다. R 표·요약 §4·wbs 상태 칸은 고치지 않는다(전체 감독이 맞춘다). 구간 끝 정리 목록은 이 폴더의 lane5-cleanup.md(처음 적을 때 만든다)에 쓴다.
- **ADR 번호(첫 바퀴)**: 0299~0301. 모자라면 전체 감독에게 더 받는다(`docs/lanes/coord.md`).
