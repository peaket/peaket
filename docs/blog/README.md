# 기술 블로그 초안

PEAKET 측정을 마칠 때마다 쓰는 기술 블로그의 초안을 둔다(docs/planning/01-overview.md §3.3 '지식 전파', ADR-0128 중간-006). 블로그는 면접 전에 밖에서 볼 수 있는 증거라, 무엇을 왜 바꿨는지가 흐려지기 전에 그 측정 직후에 쓴다.

- **규범이 아니다**: 이 폴더의 글은 정본(docs/verification.md, 성능 장부 docs/perf-ledger/ 등)을 풀어 쓴 것이다. 새 결정이나 새 숫자를 담지 않는다. 글과 정본이 다르면 정본이 맞고, 글을 고친다.
- **숫자 표시**: 숫자는 정본과 성능 장부에서만 가져오고 실측(PC)·실측(클라우드)·외삽·문서 인용·설계 목표·하한선 가운데 하나를 붙인다(ADR-0057 결정 9, docs/planning/02-requirements.md §3.1). 근거로 쓴 장부 실행 ID를 글 끝에 적는다.
- **쓰는 말**: 기획 문서와 같은 쓰기 규칙을 따른다(docs/planning/03-policies-glossary.md §5). 전문 용어는 글마다 처음 나올 때 푼다.
- **게시**: WBS의 블로그 작업은 담당이 소유자다. 루프는 BUILD_ORDER의 블로그 단계(예: BSL-100 '초안(게시는 소유자 몫)')대로 초안까지 쓴다. 밖에 게시하는 일(블로그 플랫폼에 올리기, 공유)은 외부 게시라 소유자가 한다(docs/architecture.md §8.6). 게시하면 아래 표의 상태 칸에 날짜와 주소를 적는다.
