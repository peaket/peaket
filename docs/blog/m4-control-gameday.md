# M4 ① 관제 명령과 Game Day — 초안

- **상태**: 초안(2026-11-28, 게시 전)
- **근거**: F-08-14(K8 미측정), F-08-13 계획의 예정 판정(현재 인용은 미측정)
- **숫자 표시**: 측정값은 모두 미측정이다.
- **게시**: 소유자 몫(publish: owner, draft)

## 1. 무엇을 설명하나

관제 명령이 2인 승인을 거쳐 대상 파드에 닿는 과정과, Game Day에서 장애를 주입했을 때 경보·대응·복구가 제때 도는지 확인하는 방법(K8)을 설명한다. 관측 스택과 로컬 경보 규칙이 없는 동안 무엇을 판정하지 못하는지도 함께 적는다.

## 2. 설계

- 관제 명령은 접수·승인·전파·적용 ack를 나눠 기록한다. 2인 승인과 재인증을 거친 명령만 실행한다.
- Game Day는 T0(주입) → T1p(Prometheus `ALERTS` firing) → T1(Alertmanager 웹훅) → T2(명령 접수) → T3(파드 반영) → T4(서비스 정상) 시간선을 남긴다.
- K8은 주입한 장애 10종의 탐지율과 장애마다의 탐지 시간(60초 이내, 최댓값), 명령 전파 시간(3초 이내, 최댓값)을 본다.
- 긁기·평가·묶음 대기는 운영과 같은 값이어야 한다. 줄인 간격으로 잰 실행은 판정에 쓰지 않는다.
- 정본 위치는 `docs/observability.md` §12와 `docs/perf-ledger.md` §8이다. 값을 옮겨 적지 않는다.

## 3. 측정 근거

- F-08-14 K8은 **미측정**이다. 이 글은 새 측정을 하지 않는다.
- F-08-13은 **계획의 예정 판정**이며, 이 가지에는 구현·시험이 없고 측정 보고서도 아직 없다. 측정 보고서가 생기기 전까지는 `미측정`으로 인용한다.
- F-08-6의 33종 전체와 SLO/KPI ADR은 이 글의 근거가 아니다. K8 개념과 10종 설명에만 참고한다.
- 측정하지 않은 값은 `미측정`으로 적는다.

## 4. 한계

- 로컬에는 Alertmanager와 관측 저장소 부품이 없어 T1(웹훅 도착)과 기대 경보 수신을 잴 수 없다.
- F-08-13의 모의 진행은 실제 주입이 아니므로 통과 근거가 될 수 없다.
- 이 글은 설계 목표와 판정 계약을 설명할 뿐, K8 달성을 주장하지 않는다.
