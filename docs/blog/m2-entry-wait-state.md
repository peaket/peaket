# M2 ① 진입과 대기 상태 파일 — 초안 뼈대

- **상태**: 초안(2026-11-27, 게시 전). 마일스톤 M2, BUILD_ORDER HOT-510(F-08-10). 게시는 소유자 몫이다.
- **근거**: F-08-2(진입 서버 비례·MSR-020)와 F-08-8(K1)의 측정 보고서·실행 ID. 이 글은 새 측정을 하지 않는다.
- **숫자 표시**: F-08-2·F-08-8의 `실측(PC)` 값을 인용할 자리만 둔다. 이 글을 쓰는 시점의 값은 `미측정`이며, 확인 전에는 수치를 적지 않는다.

## 1. 무엇을 설명하나

티켓 오픈 때 한꺼번에 몰리는 진입 요청을 대기열이 어떻게 받고, 대기 상태를 어떤 파일로 내보내 화면이 읽게 하는지 설명한다. 진입 서버를 늘릴 때 처리량이 어떻게 늘어나는지(비례)와, 한 대가 지키는 진입 지연 목표도 함께 다룬다.

## 2. 설계

- 진입 서버(queue-svc)와 대기 상태 파일의 역할을 나눈다.
- 대기 상태 파일은 화면이 자주 읽는 작은 조각으로 두고, 원본 대기열 저장소와 분리한다.
- 진입 서버를 늘릴 때 공유 저장소의 한 키가 상한이 된다는 점을 적는다.
- 이 절은 `docs/features/queue-admission.md`와 `docs/verification.md` §3.3·§3.8을 가리킨다. 정본 값을 옮겨 적지 않는다.

## 3. 측정 근거

- F-08-2 MSR-020: 1 vCPU 진입 서버의 X₁과 0.5 vCPU N=1의 무효를 인용한다. 실행 ID는 `2026-11-24-msr020-n1-c1-r1..r3`(유효)와 `2026-11-24-msr020-n1-c05-r1..r3`(무효)다.
- F-08-8 K1: 진입·대기 상태·입장 확정 경로의 실행 ID와 결과를 인용한다. 값은 `docs/review/measurements/F-08-8-after.md`에서 확인한다.
- 측정하지 않은 값은 `미측정`으로 적는다.

## 4. 한계

- 로컬 PC 한 대의 값이라 운영 규모를 직접 대신하지 않는다.
- 0.5 vCPU N=1은 무효이므로 그 값으로 비례를 주장하지 않는다.
- 진입 최대 도착률은 queue-svc만 켠 무대의 값이며, 다른 서비스를 함께 켠 무대와 같다고 주장하지 않는다.
