# RB-41: 인증서 만료

- **서비스·영역**: 게이트웨이
- **증상 분류**: 가용성
- **증상**: 인증서 갱신 예정 시각을 넘겼는데 새 인증서가 없거나 외부 합성 점검의 TLS가 실패할 때
- **탐지 경로**: 경보
- **심각도**: SEV2
- **발동 신호**: 인증서 갱신 예정 시각을 넘겼는데 새 인증서가 없거나 외부 합성 점검의 TLS가 실패할 때 — [관측 §5](../observability.md)
- **담당**: 플랫폼 담당
- **목표 시간**: [인프라 §9](../infra.md)

## 즉시 조치

1. 게이트웨이 인증서(cert-manager, ACME)를 강제로 갱신하고 상태를 확인한다.
2. CloudFront 시청자 인증서(ACM, us-east-1) 상태를 확인하고, 필요하면 ACM에서 다시 발급받는다.
3. 이미 만료됐으면 TLS 단계에서 실패해 판매 일시 중단 화면도 보이지 않으므로 상태 페이지에 공지한다.

## 에스컬레이션

- 플랫폼 담당이 맡고, 판매 경로가 막히면 IC·CL을 부른다.
- DNS·CloudFront 변경은 소유자 확인을 받는다.

## 복구 확인

- 게이트웨이·CloudFront 인증서가 유효하고, 합성 점검 TLS가 정상이며, 만료·갱신 경보가 꺼졌다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
