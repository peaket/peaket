# 런북 41종

- **독자와 용도**: 온콜 담당·운영자·서비스 엔지니어가 장애 때 따라 하는 절차서다. 심각도·선언 기준은 [인시던트 기준](incident-criteria.md), 서비스·증상·원인별 찾기는 [런북 색인](index.md)을 본다.
- **읽는 순서**: ① 경보·사람·외부 가운데 탐지 경로를 확인한다. ② 심각도를 정하고 [인시던트 기준](incident-criteria.md)의 선언 조건에 드는지 본다. ③ 색인에서 런북을 고른다. ④ 즉시 조치·에스컬레이션·복구 확인 순서로 움직인다. ⑤ 선언한 인시던트는 [RB-17](RB-17.md)로 포스트모템을 연다.
- **담당과 목표 시간**: 각 런북의 `담당`은 9개 역할 가운데 하나다. `목표 시간`은 정본에 있는 값만 인용하고, 없으면 `미정`·`미측정`으로 둔다. 새 숫자를 만들지 않는다.
- **고치는 법**: `docs/infra.md` §10의 목차·발동 신호와 이 폴더의 파일을 함께 고친다. `_template.md`를 복사하고, 정본 링크·색인·시험을 같은 커밋에서 맞춘다.
- **경계**: 실제 인시던트 대응·포스트모템 작성·Game Day·장애 주입·측정은 **미실행**이다. F-08-6(Game Day·SLO/KPI), F-08-9(장애 주입·검색 측정), F-08-10(서비스 분리 비교·M2), F-08-12·F-08-13(Game Day 로컬·모의 진행) 몫이며, 이 문서는 절차·기준·색인만 만든다.
- **수치**: `30k/s`·`100만`·`K1`·`K2`·`K7` 수치는 주장하지 않는다. 정본에 없는 목표 시간·탐지 시간·복구 시간도 만들지 않는다.
- **연습**: 모든 런북의 `## 연습`은 `미실행`이다. '연습으로 검증됨'을 주장하지 않는다.
