# RB-28: 변경 동결 달력 장애와 창 누락

- **서비스·영역**: 배포·플랫폼
- **증상 분류**: 변경·배포
- **증상**: 변경 동결 달력이 30분 넘게 갱신되지 않거나 T-30분 점검의 동결 창 적용이 실패했을 때
- **탐지 경로**: 경보
- **심각도**: SEV2
- **발동 신호**: 변경 동결 달력이 30분 넘게 갱신되지 않거나 T-30분 점검의 동결 창 적용이 실패했을 때 — [관측 §5](../observability.md)
- **담당**: 릴리스 담당
- **목표 시간**: 미정

## 즉시 조치

1. 달력 생성기 상태와 마지막 성공 시각을 확인한다.
2. 수동으로 `argocd proj windows add`와 Karpenter 예산을 적용한다.
3. 달력을 복구하고, T-30분 점검의 동결 항목을 다시 확인한다.

## 에스컬레이션

- 동결 창을 수동 적용하지 못하면 릴리스 담당과 IC를 부르고, 온세일 중 변경을 멈춘다.

## 복구 확인

- 달력이 신선하고, 동결 창·Karpenter 예산이 저장소와 같으며, T-30분 점검이 통과한다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
