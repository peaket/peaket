# RB-11: Kafka 컨슈머 Lag 급증 및 브로커 노드 손실 대응, 보류 사건 다시 처리

- **서비스·영역**: 공통·운영
- **증상 분류**: 오류·정합성
- **증상**: 거래 토픽 소비 지연이 30초를 1분 넘게 넘거나 보류 사건이 1건 이상일 때
- **탐지 경로**: 경보
- **심각도**: SEV2
- **발동 신호**: 거래 토픽 소비 지연이 30초를 1분 넘게 넘거나 보류 사건이 1건 이상일 때 — [관측 §5](../observability.md)
- **담당**: 서비스 담당
- **목표 시간**: 미정

## 즉시 조치

1. 소비자 그룹·파티션·오프셋·브로커 상태를 보고, 멈춘 파티션과 보류 표 `held_event`를 확인한다.
2. 원인을 고친 뒤 보류 행을 차례로 다시 넣고, queue-svc의 `q:{held:<토픽>}:…` 보류는 위치로 다시 넣는다.
3. 이미 반영된 사건은 `eventKey`로 건너뛰고, 다시 처리한 행의 삭제 시한을 기록한다.

## 에스컬레이션

- 결제·주문 토픽 보류가 1건이라도 있으면 IC를 부르고, 5분 넘게 파티션이 멈추면 의존성 SEV2로 올린다.
- 브로커 손실이면 RB-39와 함께 본다.

## 복구 확인

- 소비 지연이 기준 아래로 돌아오고, 보류 행과 멈춘 파티션이 0이며, 같은 키의 순서가 유지된다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
