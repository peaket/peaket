# RB-02: 프리워밍 실패 대응

- **서비스·영역**: 게이트웨이
- **증상 분류**: 포화·용량
- **증상**: T-30분 점검에서 목표 최소 복제본 수에 못 미치고 T-20분까지 회복하지 못할 때
- **탐지 경로**: 경보
- **심각도**: SEV2
- **발동 신호**: T-30분 점검에서 목표 최소 복제본 수에 못 미치고 T-20분까지 회복하지 못할 때 — [관측 §5](../observability.md)
- **담당**: 플랫폼 담당
- **목표 시간**: 미정

## 즉시 조치

1. KEDA ScaledObject·Karpenter 노드 풀·보류 중 파드·자원 할당을 확인한다.
2. 노드와 게이트웨이 복제본을 수동으로 늘리고, 이미지 받기·자원 부족·스케줄 제약을 가른다.
3. T-20분까지 회복하지 못하면 입장 일시정지(명령 2)로 오픈을 시작하고 commander에게 알린다.

## 에스컬레이션

- 복제본이 목표의 절반 아래면 인시던트 지휘관(IC)과 플랫폼 담당을 부른다.
- 오픈 지연이 확정되면 기록·대외 공지 담당(CL)이 대기실 공지를 준비한다.

## 복구 확인

- 목표 최소 복제본이 10분 이상 유지되고, 새 파드가 준비 상태가 되며, 스케줄 실패가 0이다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
