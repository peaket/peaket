# RB-26: 비밀 유출 대응

- **서비스·영역**: 보안·법정
- **증상 분류**: 보안·법정
- **증상**: gitleaks 탐지·비밀 사용 이상·외부 제보로 비밀 노출이 의심될 때
- **탐지 경로**: 경보·사람·외부
- **심각도**: SEV1
- **발동 신호**: gitleaks 탐지·비밀 사용 이상·외부 제보로 비밀 노출이 의심될 때 — [관측 §5](../observability.md)
- **담당**: 보안 담당
- **목표 시간**: 미정

## 즉시 조치

1. 노출된 비밀을 즉시 폐기·재발급하고 사용 이력을 조사한다.
2. 저장소 이력·이미지·로그에서 같은 값을 지우고, 보안 사고 해당 여부는 RB-20으로 판단한다.
3. `inv-ref-key` 회전 절차는 [비밀·키 관리](../security/secrets-and-keys.md)의 회전 절차 ①~⑧을 따르고, 진행 중인 판매가 없는 정비 시간에만 한다.

## 에스컬레이션

- 보안 담당과 IC가 함께 지휘하고, 개인정보 유출 가능성이 있으면 즉시 RB-20으로 넘긴다.

## 복구 확인

- 폐기·재발급·이력 정리가 끝나고, 옛 비밀로 성공한 접근이 0이며, 재발 방지·회전 기록이 남았다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
