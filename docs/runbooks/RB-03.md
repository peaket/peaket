# RB-03 대기열 진입 Degraded Mode 자동 전환 확인과 해제(명령 6)

- **발동 신호(정본 인용)**: 대기열 진입 지연 p99 > 150ms가 2분 [가정] 이어짐, 또는 Redis CPU 사용률 > 75%(`docs/infra.md` §10 RB-03).
- **정본**: `docs/features/control-tower.md` §3 명령 6, §5 '제어 상태', `docs/features/queue-admission.md` §4·§9, ADR-0223 결정 1·8, ADR-0234 결정 5, ADR-0365 결정 2·6.
- **전제**: 실제 AWS·CloudFront·WAF·S3 호출은 이 동결 트랙에서 `미실행`이다. 이 런북은 포트·정본 계약과 관제 콘솔 절차를 적고, 실제 배포·권한은 F-09-4가 잇는다.

## 1. 자동 전환이 켜졌는지 확인

1. 관제 콘솔에서 대기열 진입 p99와 Redis CPU를 본다. 위 발동 신호가 2분 [가정] 이상 이어졌는지, 다른 배포·장애가 함께 있는지 확인한다.
2. 엣지 저장소의 `mode:entry` 값을 읽는다. 꼴은 `{"on": true, "expireAtMs": <밀리초>}`이고, `on`이 참이면 진입 Degraded가 켜진 것이다. `expireAtMs`가 지났으면 엣지 함수는 그 기능을 건너뛰므로 값이 남아 있어도 켜진 상태가 아니다. 켜져 있으면 아래 2절의 해제(되돌리기) 절차로 간다.
3. 운영 명령 6의 `ENTRY_DEGRADED` 행을 찾는다. 자동 조치(`AUTO_ACTION`)로 만들어졌으면 행위자가 `system`이고 감사 기록에 `mode: ENTRY_DEGRADED`, `transition: ON`, `scope: PLATFORM`이 남는다. 수동이면 `PENDING_APPROVAL` 뒤 승인·실행 사건을 본다.
4. 상태 조회 Degraded도 함께 켰는지 본다. `q:{event:E}:notice`(전체는 `q:{event:PLATFORM}:notice`)의 `stateDegraded`가 `1`이면 상태 조회 Degraded가 켜진 것이고, 대기 상태 파일의 `pollHintMs`가 그 구간 주기의 2배가 된다. `stateDegradedRev`·`stateDegradedCmd`로 마지막 판·명령을 확인한다.

## 2. 해제(되돌리기) 절차

1. 원인이 사라졌는지 먼저 확인한다. 진입 지연 p99와 Redis CPU가 발동 신호 아래로 돌아왔고, `mode:entry`의 `expireAtMs`가 지나 자동으로 꺼졌는지 본다. 자동으로 꺼졌으면 명령 행은 `ACKED`로 남아 있으므로 되돌리기를 하지 않아도 된다. 다만 감사 확인을 위해 명령 6 행과 감사 기록은 남긴다.
2. 자동으로 꺼지지 않았으면 commander가 명령 6의 `ENTRY_DEGRADED` 행에 되돌리기를 요청한다. 되돌리기는 `mode:entry`에 `{"on": false, "expireAtMs": <지금>}`을 쓰고, 명령은 `REVERTED`가 된다. 되돌리기는 재인증이 필요한 commander 1인 실행이다(ADR-0340 결정 5, ADR-0223 결정 1).
3. `STATE_DEGRADED`를 켰으면 같은 종류·범위의 새 판으로 `{"stateDegraded": false}`를 보내 `stateDegraded`를 `0`으로 쓴다. 전체 범위는 한 번, 회차 범위는 회차마다 보낸다. 대기 상태 파일의 `pollHintMs`가 원래대로 돌아왔는지 확인한다.
4. 엣지 저장소와 notice의 값이 바뀌었는지, 되돌리기 감사 기록에 `mode`, `transition: OFF`, `scope`가 남았는지 확인한다. 화면이 여전히 Degraded면 CDN·S3 사본 쪽 문제인지 RB-04를 함께 본다.

## 3. 감사 기록 확인

1. 명령 6의 `COMMAND_CREATED`·`COMMAND_APPROVED`·`COMMAND_EXECUTION_STARTED`·`COMMAND_ACKED`·`COMMAND_REVERT_STARTED`·`COMMAND_REVERTED` 감사 기록에 `mode`, `transition`(`ON`/`OFF`), `scope`가 있는지 본다. 자동 조치는 `COMMAND_AUTO_ACTION`과 `DISPATCHED` 사건 `detail`에 같은 값이 남는다.
2. 같은 `eventKey`의 자동 조치가 두 번 만들어지지 않았는지 명령 ID로 확인한다(같은 `eventKey`는 한 번만 만든다).
3. 해제 뒤에도 명령 행이 `ACKED`로 남아 있는 것은 정상이다. `ENTRY_DEGRADED`는 엣지 키의 `expireAtMs`가 끝내고, 명령 행은 자동 만료 대상이 아니다. `STATE_DEGRADED`·`STATE_MIRROR_FIXED`·`SOLD_OUT_STATIC`도 해제 명령 전까지 유지된다.
