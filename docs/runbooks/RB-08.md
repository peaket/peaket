# RB-08: ops-svc 장애 시 비상 런북 가동

- **서비스·영역**: ops-svc
- **증상 분류**: 가용성
- **증상**: ops-svc 파드가 멈추거나 관제 채널이 끊겨 30초 넘게 준비된 파드가 0일 때
- **탐지 경로**: 경보
- **심각도**: SEV1
- **발동 신호**: ops-svc 파드가 멈추거나 관제 채널이 끊겨 30초 넘게 준비된 파드가 0일 때 — [관측 §5](../observability.md)
- **담당**: 온콜
- **목표 시간**: 미정

## 즉시 조치

1. 비상 역할로 `ops-breakglass` 런북 Job을 만들고, commander 두 명의 KMS 서명을 받는다.
2. 제어 gRPC 포트로 같은 제어 상태를 판 번호와 함께 넣고, 명령 결과를 감사 기록에서 확인한다.
3. ops-svc가 돌아오면 런북 Job을 지우고 관제 콘솔과 경보 패널을 다시 본다.

## 에스컬레이션

- IAM Identity Center가 함께 멈췄으면 RB-37, 서울 KMS가 멈췄으면 도쿄 복제 키를 쓴다.
- IC가 인시던트를 선언하고 CL이 공지를 맡는다.

## 복구 확인

- ops-svc 준비 파드가 1 이상이고, 제어 상태 판이 모든 파드에 적용되며, 감사 체인이 이어진다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
