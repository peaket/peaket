# RB-08 ops-svc 장애 시 비상 런북

- **독자와 용도**: ops-svc가 모두 멈춰 관제 콘솔로 명령을 낼 수 없을 때, 온콜 운영자가 비상 Job의 `peaket-runbook`으로 제어 명령을 내고 결과를 확인한다. 정본은 [docs/features/control-tower.md](../features/control-tower.md) §5 '제어 평면 Degraded Mode'·§14 C-T13·C-T28, [docs/infra.md](../infra.md) §9 '비상 런북 통제'다.
- **전제**: 제어 포트(`<서비스>-control`, 50061)는 메시 신원으로 `ops-svc`와 `ops-breakglass`만 받는다. 실제 KMS·S3 Object Lock·Job·Kyverno·IAM은 구간 5다. 이 문서는 local·CI에서 포트·가짜로 확인한 경로와 운영 절차를 함께 적는다.

## 1. 시작

1. ops-svc 준비 파드 0이 30초 [가정] 지속되거나 외부 합성 점검 3곳 중 2곳이 실패하면 SEV1(`kind` control)이다. 인시던트를 선언한다.
2. IAM Identity Center가 멀쩡하면 비상 역할로, 멈췄으면 RB-37 비상 접근 계정으로 `ops-breakglass` 네임스페이스에 Job을 만든다. Job은 고정 이미지·메시 신원만 쓴다.
3. 운영자 공개키 목록(`PEAKET_RUNBOOK_COMMANDER_KEYS`)은 배포에 든다. 운영은 commander 둘 이상이 없으면 서비스·Job이 시작하지 않는다.

## 2. 명령 묶음 만들기

```bash
peaket-runbook draft sale-pause --event <회차 ID> --reason "<사유>" --command-id <UUIDv7> --out bundle.json
```

- 판매 일시정지(명령 3) 정지: commander **1명** 서명. 판매 재개: 서로 다른 commander **2명**. 그 밖(명령 2·6·11): 서로 다른 운영자 **2명**.
- 묶음은 `{v:1, commandId, kind, scope, version(=issuedAt), reason, issuedAt, expiresAt, requests}`이고 5분 유효다. `requests`는 받는 서비스마다 바라는 상태다.

## 3. 서명

```bash
peaket-runbook sign --in bundle.json --signer <운영자 ID>
```

- 두 번째 서명자는 `서명할 내용` 줄에서 kind·scope·사유·서비스별 `requests`를 확인한 뒤 서명한다.
- KMS 키는 `--key`, 키 목록의 `kmsKeyArn`, `PEAKET_RUNBOOK_SIGNING_KEY`, 서명자 ID 차례로 고른다. KMS가 실패하면 파일을 바꾸지 않고 6으로 끝난다.

## 4. 보내기

```bash
peaket-runbook run --in bundle.json
```

1. 보내기 전에 공개키 목록으로 정규화·모양·요청 대조·서명·역할·5분 창을 다시 본다. 틀리면 3, 전송 0.
2. 감사 sink에 intent를 먼저 쓴다. 쓰지 못하면 보내지 않는다(fail closed).
3. `requests`의 서비스마다 제어 포트로 `ApplyControl`을 보낸다. 받는 쪽은 같은 검사를 한 뒤 적용하고, 적용한 commandId를 기억한다. 주소는 Job 환경의 `PEAKET_PURCHASE_CONTROL_GRPC_ADDRS`·`PEAKET_ADMISSION_CONTROL_GRPC_ADDRS`·`PEAKET_QUEUE_CONTROL_GRPC_ADDRS`·`PEAKET_PAYMENT_CONTROL_GRPC_ADDRS`(쉼표 목록)에서 읽는다.
4. 결과를 감사 sink에 쓴다. 결과 쓰기가 실패하면 적용됐을 수 있으므로 commandId를 남기고 6으로 끝난다. 감사 sink는 local·CI에서 `PEAKET_RUNBOOK_AUDIT_DIR`, 운영에서 `PEAKET_RUNBOOK_AUDIT_BUCKET`(S3 Object Lock, 현재 `미실행`)이다.
5. 이전 결과가 있으면 다시 보내지 않는다. `APPLIED`는 0, `PARTIAL`·`FAILED`는 4, `REJECTED`는 5다.

## 5. 결과 확인

- `PEAKET_RUNBOOK_AUDIT_DIR`(local·CI) 아래 `<commandId>/intent.json`·`result.json`을 본다. 운영은 S3 Object Lock 앵커 버킷이 정본이며 현재 `미실행`이다.
- 받는 쪽 거부 사유는 `result.json`의 `failed[].reason`에 `rejected:bad-signature`처럼 `rejected:` 접두로 남는다. 재생·충돌은 `replayed`·`conflict`, 닿지 못한 곳은 `send-deadline`·`unavailable:<사유>`·`send-failed`다.
- ops-svc가 복구되면 감사 결과를 감사 체인에 넣고 받는 쪽 판 번호와 원장을 대조한다(구간 5·후속).

## 6. 사후

- commander 1명이 서명한 판매 정지는 사후 검토 보고서 할 일(48시간)이 생긴다.
- 인시던트 포스트모템에 런북 명령·사유·결과·한계를 적는다.
- 서울 KMS가 응답하지 않으면 도쿄 복제 키로 서명한다. 두 리전 KMS를 함께 쓰지 못하면 이미 받은 5분 재인증 토큰으로만 낼 수 있다.
