# RB-17: 장애 종결 후 48시간 이내 포스트모템 작성 및 보고서 배포

- **서비스·영역**: 공통·운영
- **증상 분류**: 오류·정합성
- **증상**: 인시던트 공식 종료를 선언했을 때
- **탐지 경로**: 사람
- **심각도**: SEV1~SEV3
- **발동 신호**: 인시던트 공식 종료를 선언했을 때 — [관측 §5](../observability.md)
- **담당**: 기록·대외 공지 담당(CL)
- **목표 시간**: [관측 §5](../observability.md)

## 즉시 조치

1. 첫 증상·첫 경보·사람이 안 시각과 탐지 경로를 모은다.
2. 주 원인 유형 9가지 가운데 하나와 구성 요소 하나, 기여 원인·영향·쓴 명령·런북을 적는다.
3. 재발 방지 실행 항목과 런북 개정을 GitHub Issues로 만들고, 48시간 안에 보고서를 배포한다.

## 에스컬레이션

- P0 후속 조치가 필요하거나 같은 원인이 분기 예산의 20%를 넘으면 IC와 commander가 우선순위를 정한다.

## 복구 확인

- 48시간 안에 비난 없는 포스트모템이 배포되고, 실행 항목마다 담당·기한이 있으며, 런북 개정이 연결됐다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
