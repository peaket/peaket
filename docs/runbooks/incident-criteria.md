# 인시던트 기준과 대응

- **독자와 용도**: 온콜 담당·운영자·인시던트 지휘관이 장애를 인시던트로 다룰지 정하고, 역할·에스컬레이션·포스트모템·공지를 같은 방식으로 하게 한다. 심각도 발생 상황과 수치는 [관측가능성·SLO·알림](../observability.md) §5와 POL-022가 정본이고, 이 문서는 운영 체크리스트다.

## 심각도

- **SEV1**: 전면 결제 마비, 좌석 오버셀·이중 결제 의심, 결제-발권 불일치, 차례 전 입장, 셔플 비콘 상한 초과, 관제 콘솔 상실, 보안 사고, 거래·제어 MSK 오프라인 파티션. 온콜 엔지니어를 즉시 호출하고 인시던트 채널을 연다.
- **SEV2**: 온세일 예산 3배 소진과 결제 확정 임박 원인, 발권 지연·보상 영구 실패, 외부 의존 이상, 핵심 여정 Degraded, 법정 기한 임박, 처리량 급감, Outbox 릴레이 밀림, admission-ctrl 리더 부재, 거래 토픽 소비 지연, Redis 메모리 85% 초과. 콘솔 경고와 메신저 운영 채널로 알린다.
- **SEV3**: 28일 예산 경고, 검색·사전·법정 점검·백업·인증서 갱신·CSP·자원 누수·관측 저장소·스트림 작업자·결제 결과 당기기·설정형 명령 적용 확인 등. GitHub Issues 티켓으로 다음 업무일에 처리한다.

값과 발생 상황의 정본은 [관측가능성·SLO·알림](../observability.md) §5다. 이 문서에 수치를 복사하지 않는다.

## 탐지 경로

- **경보**: Prometheus·Alertmanager·SLO 규칙이 먼저 잡은 경우다.
- **사람**: 운영자가 콘솔·대시보드에서 먼저 본 경우다.
- **외부**: 고객 문의·SNS·파트너가 먼저 알린 경우다.
- 사람이나 외부가 먼저 잡았으면 감시 실패로 보고, 포스트모템에서 경보를 고친다.

## 인시던트 선언

다음 가운데 하나라도 해당하면 인시던트로 선언한다(POL-022, [관측 §5](../observability.md)).

1. SEV1이 발생했다.
2. 불변식 위반 의심이 1건이라도 있다.
3. 명령 2·3·6을 실행한 경우(No-Go로 시작한 명령 2 포함).
4. SEV2가 15분 [가정] 넘게 풀리지 않는다.
5. 온세일 예산 50% 이상을 사용했다.
6. 상시 기능에서 사고 하나가 28일 예산의 20%를 넘게 썼다.
7. 경보보다 사람이나 외부가 먼저 발견했다.

명령 1은 일상 조작이라 선언 기준에 넣지 않는다. 선언하면 IRM 인시던트와 Slack 인시던트 채널을 열고(SEV1은 자동), 선언한 사람이 넘길 때까지 인시던트 지휘관을 맡는다.

## 역할과 에스컬레이션

- **인시던트 지휘관(IC)**: 우선순위·명령·역할을 정하고, 선언·종료를 판단한다.
- **운영 실행자(OL)**: 런북의 즉시 조치·복구 확인을 실제로 실행하고 결과를 IC에 알린다.
- **기록·대외 공지 담당(CL)**: 타임라인·결정·공지·상태 페이지를 맡는다.
- 가상 온콜 순번표에 따라 교대로 맡고, SEV1·SEV2는 온콜 호출, SEV3는 티켓으로 처리한다.
- 역할이 비었거나 15분 넘게 진전이 없으면 IC가 다음 역할을 부르고, 필요하면 commander를 부른다.

## 포스트모템

- 인시던트를 선언했으면 종료 뒤 48시간 안에 비난 없는 포스트모템을 쓴다. 정본은 [관측 §5](../observability.md)와 [RB-17](RB-17.md)이다.
- 초안에는 첫 증상·첫 경보·사람이 안 시각, 탐지 경로, 주 원인 유형 9가지 가운데 하나와 구성 요소 하나, 기여 원인, 영향, 쓴 명령·런북, 후속 조치(P0 여부)를 적는다.
- 같은 종류의 장애가 분기 예산의 20%를 넘게 쓰면 P0 후속 조치를 하나 이상 둔다.

## 원인 유형

포스트모템의 주 원인 유형은 다음 9가지다. 정본은 [정책·용어집](../planning/03-policies-glossary.md) §4다.

- 변경
- 외부 의존
- 내부 저장소·메시징
- 용량·포화
- 코드 결함
- 데이터
- 보안
- 운영 조작
- 기반

## 공지

- **상태 페이지(Upptime)**: 클러스터 밖에서 볼 수 있는 전체 상태·예정·복구 공지.
- **대기실 비상 공지 배너**: 미리 승인한 표준 안내 문구로 대기실 위쪽에 띄운다.
- **파트너 긴급 팝업**: 파트너 콘솔에 띄우고, 형식은 POL-022를 따른다.
- 공지 문구에는 이용자 식별값·내부 주소·비밀을 싣지 않는다. CL이 문안을 확인하고 IC가 낸다.

## 경계

- 실제 인시던트·Game Day·장애 주입·측정은 **미실행**이다. F-08-6·F-08-9·F-08-10·F-08-12·F-08-13 몫이며, 이 문서는 기준과 절차만 정한다.
- `30k/s`·`100만`·`K1`·`K2`·`K7` 수치는 주장하지 않는다. 정본에 없는 목표 시간도 만들지 않는다.
