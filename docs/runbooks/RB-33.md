# RB-33: 처리량 급감

- **서비스·영역**: 공통·운영
- **증상 분류**: 가용성
- **증상**: 오류 없이 처리량이 급감했거나 퍼널의 다음 단계 전환이 평소보다 크게 줄었을 때
- **탐지 경로**: 경보
- **심각도**: SEV2
- **발동 신호**: 오류 없이 처리량이 급감했거나 퍼널의 다음 단계 전환이 평소보다 크게 줄었을 때 — [관측 §5](../observability.md)
- **담당**: 온콜
- **목표 시간**: 미정

## 즉시 조치

1. 퍼널에서 막힌 단계와 그 화면의 Sentry 새 오류·CSP 위반·결제 SDK 로드 실패를 본다.
2. 최근 프런트 배포가 원인이면 RB-23으로 되돌리고, 결제 단계면 결제사 상태와 명령 6을 검토한다.
3. 원인을 모르면 명령 2로 들어오는 사람을 멈추고 엔지니어를 부른다.

## 에스컬레이션

- IC가 지휘하고, 15분 넘게 풀리지 않으면 인시던트 선언 기준을 본다.
- CL이 대기실 공지를 준비한다.

## 복구 확인

- 퍼널 전환율이 평소로 돌아오고, 새 오류·CSP 위반·SDK 실패가 0이며, 입장 목표가 안정됐다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
