# RB-32: 느린 쿼리·긴 트랜잭션 끊기

- **서비스·영역**: 공통·운영
- **증상 분류**: 지연
- **증상**: 잠금 대기로 핫패스 p99가 오르거나 긴 트랜잭션이 DB를 붙잡을 때
- **탐지 경로**: 경보
- **심각도**: SEV2
- **발동 신호**: 잠금 대기로 핫패스 p99가 오르거나 긴 트랜잭션이 DB를 붙잡을 때 — [관측 §5](../observability.md)
- **담당**: DBA
- **목표 시간**: 미정

## 즉시 조치

1. `pg_stat_activity`·`pg_blocking_pids()`로 막는 세션과 쿼리를 찾는다.
2. `pg_cancel_backend`로 쿼리만 취소하고, 10초 뒤에도 남으면 `pg_terminate_backend`로 세션을 끊는다.
3. 앱 풀이 다시 연결되는지, 핫패스 p99가 돌아오는지 본다.

## 에스컬레이션

- DBA가 맡고, 같은 쿼리가 반복되면 서비스 담당과 IC를 부른다.
- 데이터 손상이 의심되면 RB-10을 검토한다.

## 복구 확인

- 잠금 대기와 긴 트랜잭션이 0이고, 핫패스 p99가 기준 아래이며, 앱 풀이 정상이다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
