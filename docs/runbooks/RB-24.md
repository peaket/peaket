# RB-24: DB 마이그레이션 실패와 잠금 대기

- **서비스·영역**: 배포·플랫폼
- **증상 분류**: 변경·배포
- **증상**: PreSync 마이그레이션 잡이 실패하거나 `lock_timeout`이 반복될 때
- **탐지 경로**: 경보
- **심각도**: SEV2
- **발동 신호**: PreSync 마이그레이션 잡이 실패하거나 `lock_timeout`이 반복될 때 — [관측 §5](../observability.md)
- **담당**: DBA
- **목표 시간**: 미정

## 즉시 조치

1. 실패한 단계와 부분 적용 여부, 잠금 대기 세션을 확인한다.
2. 재시도할지 중단할지 정하고, 트랜잭션 밖 단계를 정리한다.
3. 앞으로만 가는 새 마이그레이션으로 고치고, 서비스 판과 스키마 판을 맞춘다.

## 에스컬레이션

- 부분 적용이 데이터에 닿았으면 DBA 리드와 IC를 부르고, 필요하면 RB-10 시점 복원을 검토한다.

## 복구 확인

- 마이그레이션 잡이 성공하고, 부분 적용·잠금 대기가 0이며, 서비스가 새 스키마로 정상 동작한다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
