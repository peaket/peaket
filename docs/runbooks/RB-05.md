# RB-05: 대기열 Redis 마스터 페일오버 후속 조치

- **서비스·영역**: queue-svc
- **증상 분류**: 데이터 손상·복구
- **증상**: 대기열 Redis 클러스터 장애 조치 이벤트를 받거나 진입이 503 `queue-recovering`으로 멈췄을 때
- **탐지 경로**: 경보
- **심각도**: SEV2
- **발동 신호**: 대기열 Redis 클러스터 장애 조치 이벤트를 받거나 진입이 503 `queue-recovering`으로 멈췄을 때 — [관측 §5](../observability.md)
- **담당**: 서비스 담당
- **목표 시간**: 미정

## 즉시 조치

1. 세대 키와 `pend` 상태, 복제본 연결·지연, 리더의 RB-05 복제 확인 대기를 본다.
2. 자동 건너뛰기가 붙은 `q:{event:E}:skipped` 구간과 진입 재개를 확인한다.
3. 장애 전환 중 `identity.accounts-withdrawn`의 queue-svc 소비자 그룹 위치를 잃었으면, 장애 전환 시각 − 20분으로 되돌려 다시 읽는다.

## 에스컬레이션

- 복제 확인이 10분 넘게 끝나지 않으면 서비스 담당과 Redis 담당을 부른다.
- 순번이 어긋난 정황이 있으면 IC가 RB-36을 검토한다.

## 복구 확인

- 진입이 다시 열리고 `q:{event:E}:skipped` 밖의 번호가 단조로우며, `queue-recovering` 503이 0이다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
