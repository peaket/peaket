# RB-10: Aurora PostgreSQL 장애 조치 검증 및 PITR 시점 복원 집행

- **서비스·영역**: 공통·운영
- **증상 분류**: 데이터 손상·복구
- **증상**: Aurora 장애 조치 알림을 받거나 대규모 논리 손상이 확인될 때
- **탐지 경로**: 경보
- **심각도**: SEV1
- **발동 신호**: Aurora 장애 조치 알림을 받거나 대규모 논리 손상이 확인될 때 — [관측 §5](../observability.md)
- **담당**: DBA
- **목표 시간**: 미정

## 즉시 조치

1. 장애 조치 대상과 읽기·쓰기 엔드포인트, 애플리케이션 연결 풀을 확인한다.
2. 시점 복원이 필요하면 복원 클러스터를 만들고, 복원 시점 뒤의 파기를 파기 감사 로그로 다시 적용한다.
3. 서비스에 붙이기 전에 파기 건수와 감사 기록을 맞추고, 읽기·쓰기 시험을 한다.

## 에스컬레이션

- 복원이 30분을 넘으면 IC와 DBA 리드를 부르고, 법정 보존 영향이 있으면 보안 담당을 부른다.
- 데이터 손실 범위는 CL이 공지 문안에 반영한다.

## 복구 확인

- 복원 클러스터의 파기 재적용 건수가 기록과 같고, 서비스 연결·읽기·쓰기·불변식 검사가 정상이다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
