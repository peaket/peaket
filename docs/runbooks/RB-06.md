# RB-06: 좌석 Redis 페일오버 대응

- **서비스·영역**: purchase-svc
- **증상 분류**: 데이터 손상·복구
- **증상**: 좌석 Redis 클러스터 장애 조치 이벤트를 받거나 `seat_store_unavailable`이 30초를 넘을 때
- **탐지 경로**: 경보
- **심각도**: SEV2
- **발동 신호**: 좌석 Redis 클러스터 장애 조치 이벤트를 받거나 `seat_store_unavailable`이 30초를 넘을 때 — [관측 §5](../observability.md)
- **담당**: 서비스 담당
- **목표 시간**: 미정

## 즉시 조치

1. 그 회차 구매 요청이 503 `seat-store-unavailable`로 미뤄지는지, 세대가 올라갔는지 확인한다.
2. 클러스터가 비었으면 DB의 `seat_sale`·홀드 원장으로 비트맵을 다시 만들고 세대를 쓴 뒤 재개한다.
3. 재개 뒤 홀드·결제 접수가 정상인지, 좌석 중복 판매 의심이 없는지 본다.

## 에스컬레이션

- 클러스터가 10분 안에 돌아오지 않으면 서비스 담당과 DBA를 부른다.
- 오버셀 의심이 생기면 즉시 RB-36으로 넘긴다.

## 복구 확인

- 새 세대에서 홀드가 정상이고, 503 미루기가 사라지며, 불변식 검사에서 오버셀 의심이 0이다.

## 포스트모템

- 인시던트로 선언하면 [RB-17](RB-17.md)에 따라 48시간 안에 비난 없는 포스트모템을 쓴다. 선언 기준에 들지 않으면 이슈로 남긴다.
